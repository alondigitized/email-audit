# Get your entryway ready for summer
**Score:** 8/10 · **Type:** Email audit · **2026-07-14**

- Article's July 14 entryway send is a clean, focused editorial — organized around three product subcategories (hall trees, benches, mirrors) with its own CTA per section. Coming four days after the well-executed "New arrivals just landed" reset on July 10, this one continues the post-sale editorial cadence without a discount, which is a deliberate brand choice Article has been making since the Memorial Day sale. ## What's weak

- **No offer visible anywhere** — no price, no %, no "starting at," no member pricing. This email asks for a click with nothing to pull the wallet out.
- **"Radiant reflections" section feels tonally out of place** — the mirror photography is warmer and more abstract than the clean product-first sections above it, creating a minor aesthetic inconsistency.
- **Hero copy is soft** — "The entrance is easier, inviting, organization and functionality to introduce summer guests to your home" is functional but generic; it reads like a brief, not a lure.
- **No social proof anywhere** — a star rating, a review pull-quote, or a "best seller" badge on any one product would reduce friction without requiring a redesign.

### 3. Rendering & Accessibility

**Bug 1 — Unclosed `@media` block (critical):**

```css
@media(prefers-color-scheme:dark){
  ...
  a .link{color:#fff!important}
</style>   ← media query never closed with }
```

The `}` closing the media query block is absent. In strict CSS parsers (Apple Mail, newer WebKit), everything inside the block is dropped; in lenient parsers, subsequent sibling `<style>` rules may be swallowed into the query. The `[data-ogsc]` block is in a separate `<style>` tag so it survives, but `@media` dark mode is effectively non-functional.

**Bug 2 — Trailing comma in selector:**

```css
h1,h2,p,{color:#fff!important}   /* inside @media prefers-color-scheme */
```

`p,{` is an invalid selector. The rule is dropped by all conformant parsers. `h1` and `h2` dark-mode text color will not apply.

**Bug 3 — Semicolon before `!important`:**

```css
a{color:#fff;!important}   /* inside @media prefers-color-scheme */
```

`!important` must be inside the declaration value, not after a semicolon. This declaration is invalid and ignored — link color in dark mode falls back to whatever the client default is.

**Bug 4 — Empty `<title>` tag:**

```html
<title></title>
```

Apple Mail and some screen readers announce the `<title>` when rendering. An empty title causes a blank announcement; should be set to the subject line or brand name.
