### 3. Rendering & Accessibility

**Issue 1 — Empty `<title>` tag (confirmed)**
```html
<title></title>
```
Several screen readers and some email clients (notably VoiceOver on iOS Mail) announce the `<title>` element. An empty title degrades accessibility. Set it to match the subject line or a meaningful description.

**Issue 2 — CSS syntax error: trailing comma in dark mode selector (confirmed)**
```css
@media(prefers-color-scheme:dark){
  ...
  h1,h2,p,{color:#fff!important}
```
The trailing comma before `{` is invalid CSS. The rule will be dropped entirely by conforming parsers. In dark mode, `h1`, `h2`, and `p` text may render as the inherited dark color against a black (`#000`) background — potentially invisible text.

**Fix:** `h1,h2,p{color:#fff!important}`

**Issue 3 — CSS syntax error: semicolon before `!important` (confirmed)**
```css
a{color:#fff;!important}
```
A semicolon terminates the declaration; `!important` outside a value is invalid and will be ignored. Link color override will fail in dark mode, leaving anchor text potentially unreadable.

**Fix:** `a{color:#fff!important}`

**Minor — `@media` missing space (low severity)**
```css
@media(prefers-color-scheme:dark)
```
The CSS spec requires a space: `@media (prefers-color-schemes: dark)`. Most clients tolerate the omission, but it's non-conformant.
