# ⭐⭐⭐⭐⭐ Bestsellers & new arrivals from Nuna!
**Score:** 5/10 · **Type:** Email audit · **2026-06-23**
## Executive summary

- This is Crate & Kids' Nuna brand spotlight — a co-branded editorial send that pivots hard from the 4th of July Warehouse Sale drumbeat. Nuna is a premium stroller/car seat/high chair brand with devoted parents who track drops, so the brand name in the subject line is doing real targeting work. The hero image (high chair + toddler in a stylized loft setting) is clean, and the grid layout beneath it organizes several Nuna SKUs logically. The overall composition communicates "premium baby gear, multiple categories, no deep discount."
- The problem: there's no offer. No percentage off, no free shipping hook (compare to the June 23 Crate & Kids free-shipping send that scored an 8), no urgency mechanism, no price callouts visible in the grid. For a premium brand known for high ticket prices, just saying "bestsellers" and "new arrivals" without surfacing a reason-to-buy-now isn't enough. This is pure editorial, which can work — but only when paired with brand-building investment or a hook the copy isn't delivering here.
- Verdict: a competent brand spotlight that will satisfy Nuna fans who are already in-market, but will get scrolled past by anyone not actively shopping baby gear right now. Medium-floor, medium-ceiling email.

## What's working

- **Co-brand name-drop in subject is strong.** Parents shopping Nuna specifically will recognize it and open; it's one of the few premium baby brands with genuine brand equity.
- **Hero image is high-production and clean.** The lifestyle shot (dark high chair with toddler in modern interior) communicates quality immediately without clutter.
- **Multi-category grid is well-organized.** High chair, car seat, rocker, stroller — distinct product shots with visible labels, easy to scan.
- **Visual hierarchy is readable.** The Nuna logo sits directly under the C&K header, making the co-brand relationship clear before any copy.
- **No render bugs.** Images load, text is legible, layout is intact — no visual errors visible.

## What's weak

- **Zero offer mechanics.** No price, no discount, no shipping incentive, no member pricing — nothing gives the reader a reason to act today vs. tomorrow.
- **"Bestsellers & new arrivals" is doing double duty and delivering neither.** These are opposite signals (trusted vs. fresh) and the email doesn't commit to one — it just lists products with no editorial point of view.
- **CTA copy is generic.** "Shop Now" or equivalent generic button — no noun attached, no specific pull toward a category.
- **No urgency.** In the context of an aggressive summer sale calendar (the June 21–23 sends were all urgency-forward), dropping a zero-deadline editorial feels flat.
- **No social proof surfaced.** Despite the subject leading with five stars (⭐⭐⭐⭐⭐), no reviews, ratings, or bestseller badging are visible in the product grid itself — the stars are in the subject line only, which is a missed amplification.

## Recommendations

- 1. **Pick one anchor: bestseller OR new arrival — not both.** If it's bestsellers, lead with a "most-loved" editorial frame and badge the top SKU with a rating count. If it's new arrivals, lean into "just landed" scarcity language. The current dual message dilutes both.
- 2. **Add one offer hook.** Even a soft one — "free shipping on Nuna" or "Nuna members save 10%" — gives the reader a functional reason to click today. The June 23 free-shipping send proved this brand can move on shipping alone.
- 3. **Make the five stars in the subject line payoff inside the email.** Drop a visible review pull-quote or rating count under the hero product. Right now the stars exist only in the subject line and then disappear.
- 4. **Sharpen the primary CTA.** Replace generic "Shop Now" with "Shop Nuna High Chairs" or "See the Full Nuna Collection" — something with a noun that tells the scanner exactly where they land.
- 5. **Add a soft deadline.** Even "new arrivals, in limited quantities" or a member-preview framing adds urgency without a manufactured sale.

### 3. Rendering & Accessibility

**`<title>` brand mismatch**
```html
<title>Crate & Barrel</title>
```
Sending brand is "Crate & Kids"; title reflects the parent brand. This surfaces in tab titles on webmail clients (Gmail, Outlook.com) and in screen reader announcements.

**Unfilled template placeholder with typo**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
A developer comment with a typo ("IMPUT" → "INPUT") was left in production HTML. If a custom font was intended, it was never injected. Low rendering risk, but confirms the template was sent without a final QA pass on the `<head>`.

**`maximum-scale=1` blocks pinch-zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from zooming on mobile. Violates WCAG 1.4.4 (Resize Text, Level AA). Remove `maximum-scale=1`.

**Global `text-size-adjust: none`**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
Applied to every element via the universal selector. Overrides the `body`-level `100%` value set two lines earlier and suppresses browser text scaling globally. Should be scoped to `body` only, and set to `100%`, not `none`.

**Conflicting `img` max-width media queries (ordering bug)**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }  /* declared first */
@media only screen and (min-width: 640px) { img { max-width: 640px } }  /* declared second */
```
At viewports ≥ 768px both queries match; the later declaration wins, so desktop images are capped at 640px — wider than the 600px email container. The `min-width: 768px` rule is effectively dead. Intended behavior is ambiguous; if container width is 600px, reorder so the 768px rule is last and authoritative.

**Duplicate `format-detection` meta tags**
`telephone=no`, `address=no`, and `date=no` each appear twice (once in a combined tag, once individually). Not harmful, but indicates template merging without deduplication.

**Dark mode not declared**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Only `light` is declared. Apple Mail will attempt auto-dark-mode inversion on unsupported color schemes. No issue if dark mode was deliberately tested and excluded, but it should be documented.
