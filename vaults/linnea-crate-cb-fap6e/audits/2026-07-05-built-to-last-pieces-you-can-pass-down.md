# Built-to-last pieces you can pass down
**Score:** 5/10 · **Type:** Email audit · **2026-07-05**
## Executive summary

- This is Crate & Kids' fourth editorial email in three days — following "Soft new bedding you've gotta see" (July 3), "★★★★★ furniture for every kind of kids' room" (July 4), and "Beautiful beds that work in any room" (July 5 earlier today). The "built-to-last, pass it down" positioning is a genuine brand differentiator for a furniture retailer, and the copy angle is more emotionally resonant than a straight catalog scroll. But the email doesn't close the loop: there's no anchor price, no concrete offer, and no single hero CTA that converts the feeling into an action.
- The creative is clean — well-shot lifestyle photography, visible color swatches on multiple SKUs, consistent brand aesthetic throughout. The problem is structural: this reads like a lookbook, not an email. Multiple product vignettes compete for attention, the eye never lands anywhere specific, and on July 5th — a clearance-heavy inbox day — there's no reason to click now versus never.
- The fourth consecutive editorial send from the same brand is also a cadence red flag. Crate & Kids is burning goodwill without offering a reason to buy. This email needed either a real offer or a dramatically shorter, more focused creative to break through.

### 3. Rendering & Accessibility

**`<title>` brand mismatch (confirmed):**
```html
<title>Crate & Barrel</title>
```
Email sender is "Crate & Kids" (`crateandkids@mail.crateandbarrel.com`). The `<title>` tag surfaces in some clients' tab/window UI and in screen reader announcements. Should read "Crate & Kids."

**Viewport blocks user zoom (WCAG 1.4.4 violation):**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
`maximum-scale=1` prevents pinch-to-zoom. Should be removed or set to `maximum-scale=5`.

**Overly broad `text-size-adjust: none` on `*`:**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; ... }
```
Applied globally — overrides user browser/OS font scaling preferences. Should be scoped to `body` or `table` only.

**Conflicting `img` max-width media queries (cascade bug):**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
The 640px query appears **after** the 768px query in source. On screens ≥768px, both match and equal specificity means the last declaration wins — images cap at 640px, not 600px. If 600px was the intended desktop max, the 640px rule overrides it silently. Reorder or consolidate.

**Duplicate `format-detection` meta tags (x3):**
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
Three redundant single-attribute tags follow the combined one. Not harmful but indicates sloppy template assembly.

**Global `line-height: 100%` on `*`:**
```css
* { ... line-height: 100%; }
```
`100%` is relative to the element's own font-size. On nested elements this collapses line spacing. Should use a unitless value (e.g. `1.4`) scoped to `body`.
