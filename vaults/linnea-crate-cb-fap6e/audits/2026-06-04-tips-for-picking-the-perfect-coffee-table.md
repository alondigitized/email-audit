### 3. Rendering & Accessibility

**Conflicting image `max-width` media queries (head `<style>`):**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
The 768px rule appears *after* the 640px rule in source order, so at viewports ≥768px both rules apply and the 600px cap wins (cascade order). The intent appears to be a 640px wide container but images are capped at 600px on desktop — a 40px discrepancy that will produce right-side gaps or unexpected image scaling.

**Viewport blocks user zoom:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
`maximum-scale=1` prevents pinch-to-zoom in iOS Mail and some Android clients. This is an accessibility failure (WCAG 1.4.4 — Resize Text). Remove `maximum-scale=1`.

**Global `-webkit-text-size-adjust: none`:**
```css
* { -webkit-text-size-adjust: none; ... }
```
Applied to every element via the universal selector. The standard recommendation is `-webkit-text-size-adjust: 100%` on `body` only; `none` on `*` can suppress legitimate OS-level text scaling for users with visual impairments.

**No dark mode support:**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Dark mode is explicitly opted out. This is a deliberate choice but worth flagging — Apple Mail and Gmail Android will force-invert colors on images and backgrounds, which may produce unexpected visual artifacts despite the opt-out.
