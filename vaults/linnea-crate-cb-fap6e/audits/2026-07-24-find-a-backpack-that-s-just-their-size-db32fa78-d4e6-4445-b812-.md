# Find a backpack that’s just their size →
**Score:** 7/10 · **Type:** Email audit · **2026-07-24**
## Executive summary

- This is a category drill-down email designed to slot into Crate & Kids' live Back-to-School Sale — yesterday's "STARTS NOW: Up to 20% off" send opened the campaign; this one funnels that momentum toward a specific purchase decision: backpacks, framed by size. That editorial sequencing is smart. But the execution leans catalog over conversion — a grid of many options, no dominant hero, and no visible sale price or deadline to pull a warm browser into a buyer.
- The sizing angle ("just their size") is the most distinctive idea here. For a parent who's done this before, the pain of buying a toddler-scale bag for a kindergartner is real. If the email had organized its grid around that insight — Toddler / Little Kid / Big Kid lanes — it would have been genuinely useful. Instead it's a flat product mosaic that makes the shopper do their own filtering.
- Competent execution, but it relies on the recipient already being in buying mode. For anyone not already mid-consideration, there's nothing here to close the loop.

## What's working

- **Timing is exactly right**: late July is peak intent for back-to-school gear; this email lands when parents are actively shopping, not early or late.
- **Size framing is differentiated**: "just their size" is a real parental anxiety — bags are notoriously mis-sized. Naming it gives this email a point of view that the broader sale send lacked.
- **Product variety is legible**: the grid communicates range (solids, patterns, different silhouettes) in a way that suits a first-look browse session.
- **Clean layout, no render breaks**: no broken images, overlapping text, or obvious layout failures visible in the render.

## What's weak

- **Sale pricing is absent from the hero**: the Back-to-School Sale (20% off) is presumably still live, but no prominent price or discount badge is visible at the top — the single strongest conversion accelerant is invisible.
- **No urgency signal anywhere**: nothing tells me the deal expires, stock is limited, or I need to act today vs. next weekend. This email has the same conversion pressure as a catalog page.
- **Grid without hierarchy**: too many backpacks shown at equal weight. No "Staff Pick," no "#1 Bestseller" badge, no editorial narrowing — choice paralysis sets in before a click happens.
- **No social proof**: no review counts, star ratings, or popularity signals on any individual product visible in the render.

## Recommendations

- 1. **Put the sale price in the hero**: A single headline — "Back-to-School Sale: backpacks up to 20% off" — before the grid. Don't make subscribers remember what yesterday's email said.
- 2. **Add a hard deadline**: "Sale ends Sunday" or a visual countdown. Without it, clicking "later" is identical to clicking "now" — so most people click never.
- 3. **Reorganize the grid by size lane**: Three columns, one per age band (Toddler / Little Kid / Big Kid), with one hero pick each and a two-sentence "why this one." Filters the choice; makes the email feel like a recommendation, not a shelf.
- 4. **Add a bestseller signal to one or two products**: A simple "Most-Loved" or "Top Pick" badge reduces abandonment mid-browse by giving the undecided a default.
- **Subject Alt A:** `Back-to-School Sale: backpacks sized for every grade (20% off)`
- **Subject Alt B:** `The right-sized backpack — and it's on sale this week`
- **Preheader Alt A:** `Toddler to big kid — shop by size before the first bell rings.`
- **Preheader Alt B:** `Up to 20% off. Sorted by size so you're not guessing.`

### 3. Rendering & Accessibility

**Template placeholder comments shipped in production**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
<!---->
```
Both are raw template scaffolding. The typo ("IMPUT" vs "INPUT") confirms this block was never replaced. These are visible in raw source and clutter deliverability analysis tools.

**`<title>` brand mismatch**
```html
<title>Crate & Barrel</title>
```
Sender is "Crate & Kids." Screen readers and some preview panes surface `<title>`; this creates a brand inconsistency and may trigger spam heuristics that compare envelope sender to document title.

**`maximum-scale=1` blocks user zoom (WCAG 1.4.4)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Disabling pinch-zoom fails WCAG Success Criterion 1.4.4. Remove `maximum-scale=1`.

**`-webkit-text-size-adjust: none` on `html` element**
```css
html { -webkit-text-size-adjust: none; }
```
`none` disables iOS automatic text scaling entirely. The body correctly uses `100%`, but this `html`-level override takes precedence in WebKit. Change to `100%`.

**Universal selector applies `-webkit-text-size-adjust: none` to every element**
```css
*{ -webkit-text-size-adjust:none; ... }
```
Compounding the above — this blanket rule suppresses size adjustment on all elements. Replace `none` with `100%`.

**Conflicting and redundant `img` max-width breakpoints**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
At ≥768px both rules match; the 640px query (declared last) wins via cascade, rendering the 768px rule dead code. This is harmless in practice but masks intent and will confuse future maintainers. Remove the 768px block if 640px is the canonical desktop cap.

**Duplicate `<meta charset>` declarations**
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta charset="utf-8">
```
Redundant but harmless. Keep only the `http-equiv` form for maximum client compatibility.

**Duplicate `format-detection` meta tags**
`format-detection` appears once omnibus (`telephone=no,address=no,email=no,date=no,url=no`) and then again individually for `date`, `address`, and `telephone`. No functional impact but adds ~200 bytes of dead markup per send.
