# The Sonos Match-Day Sweepstakes is here! Enter to win →
**Score:** 6/10 · **Type:** Email audit · **2026-06-11**
## Executive summary

- This is Crate & Barrel's Sonos sweepstakes launch email — a brand partnership activation dressed up as a "Match Day" tie-in. The hero is a lifestyle shot of a well-appointed living room leading into a prominent Sonos speaker image with a clean "Enter to win" CTA. The sweepstakes mechanic is clear and the creative is on-brand, but the sports metaphor ("Match Day") is tonal whiplash for a furniture and home retailer. C&B's recent run has been all editorial education — rug materials, sofa discovery, bedroom themes — so this sweepstakes departure is noticeable and a bit jarring.
- Below the fold, the email pivots into a product shop (Sonos speakers) and then into completely unrelated cross-sells: outdoor furniture, dining, home goods. The structure becomes a kitchen-sink scroll — the sweepstakes hook earns the open but the email then asks the reader to do too many different things at once.
- Net verdict: a competent sweepstakes send that dilutes itself by tacking on a full catalog cross-sell below. The Sonos partnership angle is interesting; the execution is average.

## What's working

- **Clean CTA hierarchy** — the "Enter to win" button is dark, prominent, and appears early in the scroll. No confusion about the primary action.
- **Lifestyle hero earns the Sonos tie-in** — opening with a living room setup before revealing the speaker keeps the context grounded in home, not just consumer electronics.
- **Sweepstakes mechanic is low-friction** — no purchase required implied, enter-to-win is an easy yes from the inbox.
- **Sonos product shop section is a smart upsell** — showing multiple speaker options below the sweepstakes is a good hedge: readers who won't enter might still buy.

## What's weak

- **"Match Day" is unexplained and off-brand** — C&B is not a sports brand, and the email never pays off the metaphor. It reads like borrowed framing that doesn't belong.
- **Below-the-fold cross-sell is unfocused** — after the Sonos block, the email dumps outdoor furniture, dining, and assorted home goods. The reader has no thread to follow.
- **No deadline on the sweepstakes** — "is here!" implies urgency but the email never specifies when it ends, which kills the time-pressure that makes sweepstakes emails work.
- **Subject line is over mobile-safe length** — at ~55 characters, "The Sonos Match-Day Sweepstakes is here! Enter to win →" will truncate on most phones before the call to action.
- **No social proof or winner history** — sweepstakes perform better with even minimal credibility signals ("Last month's winner took home…").

## Recommendations

- 1. **Add a hard deadline to the sweepstakes** — "Enter by June 15" creates a real reason to act now. Without it, the "is here!" urgency is empty.
- 2. **Cut the below-fold catalog cross-sell to one focused block** — keep Sonos shop, drop the outdoor dining and unrelated home goods. The reader came for a sweepstakes, not a browse session.
- 3. **Explain or drop "Match Day"** — either commit to the sports metaphor with actual copy ("Every room deserves a home-field advantage") or replace it with something that lands for a C&B subscriber.
- 4. **Shorten the subject and front-load the prize** — lead with what you win, not with the sweepstakes name.
- **Subject Alt A:** `Win a Sonos speaker from Crate & Barrel →`
- **Subject Alt B:** `Enter to win: Sonos home audio setup`
- **Preheader Alt A:** `Match Day sweepstakes — no purchase necessary. Ends June 15.`
- **Preheader Alt B:** `Your room. Better sound. Enter for a chance to win Sonos.`

### 3. Rendering & Accessibility

**`[HIGH]` Development placeholder shipped to production**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
"IMPUT" is a typo for "INPUT." This is an unfilled template comment that reached subscribers — a production hygiene failure.

**`[MEDIUM]` Conflicting desktop `img` max-width media queries**
Two desktop breakpoints both set `img { max-width }` with overlapping ranges:
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
The 768px rule is declared first and then the 640px rule is declared second. Because both fire at ≥768px and specificity is equal, the **last rule wins** — meaning images on screens ≥768px get `max-width: 640px`, not 600px. The ordering should be reversed (largest breakpoint last) or merged into a single rule.

**`[MEDIUM]` `maximum-scale=1` blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
WCAG 1.4.4 requires content to be zoomable to 200%. `maximum-scale=1` prevents this on iOS. Remove or raise to `maximum-scale=5`.

**`[LOW]` Global `-webkit-text-size-adjust: none` override**
```css
* { -webkit-text-size-adjust: none; ... }
```
This overrides the body's `100%` value and disables the browser's automatic text scaling for small fonts — a regression for low-vision users on mobile.

**`[LOW]` Duplicate `format-detection` meta tags**
`telephone=no`, `address=no`, and `date=no` are each declared twice — once in a combined tag and once individually. Harmless, but signals template drift.

**`[LOW]` Dark mode not supported**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Email explicitly opts out of dark mode with no `prefers-color-scheme: dark` override. No issue if intentional, but Apple Mail and Gmail on iOS will not adapt.

### 5. Compliance (CAN-SPAM, Unsubscribe, Authentication)
