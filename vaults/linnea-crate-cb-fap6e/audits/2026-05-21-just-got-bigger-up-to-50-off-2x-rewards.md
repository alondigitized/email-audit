# JUST got bigger! Up to 50% off + 2x Rewards!
**Score:** 7/10 · **Type:** Email audit · **2026-05-21**
## Executive summary

- This is essentially the same send as the 7/10 "Just got BIGGER" email already in the brand history from today — same dresser hero, same Memorial Day creative, same 2x Rewards mechanic, same "up to 50% off" offer. The subject line swap ("JUST got bigger!" vs "Just got BIGGER:") is a textbook A/B subject-line test on the same underlying campaign, likely a resend to non-openers. The creative holds up in isolation but arrives at the tail end of a punishing cadence: this is the fifth or sixth Crate & Kids/Crate & Barrel email in roughly 48 hours.
- The hero is clean — a styled sage-green dresser in a well-lit room, offer copy above the fold, "Shop Now" CTA legible. The "Just made for you" personalized product strip mid-email is a genuine bright spot, suggesting the brand has some behavioral data working for them. TheDesignDesk editorial block at the bottom is a complete non-sequitur in a sale email and wastes real estate.
- Judgment: a competent, unremarkable promotional execution buried under its own brand's volume. The creative does nothing to distinguish this resend from the prior send. A subscriber who opened the 9am version will delete this on sight.

## What's working

- Hero image is polished — styled room with sage dresser reads premium and on-brand for the audience
- "Just made for you" personalized strip is the best element: three curated product cards signal the brand knows something about your browse/purchase history
- Offer numerics ("up to 50% off" + "2x Rewards") appear together in the hero, so value is legible in the first scroll
- 2x Rewards reinforcement is well-placed across multiple breakpoints — not just the hero

## What's weak

- This is an obvious A/B resend of the already-audited "Just got BIGGER" email from today — zero creative differentiation for a subscriber who already opened
- TheDesignDesk editorial block appended to a sale email is dead weight; it dilutes the conversion focus at exactly the wrong moment
- "Shop Now" appears four or five times but never directs to a specific category (rugs? cribs? dressers?) — the prior 5/20 sends were better for narrowing to a product line
- No deadline copy visible anywhere — "Memorial Day" is assumed but the date is never called out, so urgency bleeds off
- The app promo block is another momentum-killer mid-email on an already long scroll

## Recommendations

- 1. **Commit to one category** — the 5/20 Crate & Kids furniture and rugs sends (both in brand history) outperformed this because they had a defined product focus; this resend should have done the same (e.g., "Up to 50% off cribs + nursery furniture")
- 2. **Kill the TheDesignDesk block** — editorial belongs in a separate campaign; in a sale email it reads as filler and splits attention
- 3. **Add a hard deadline** — "Ends Monday" or "Sale ends May 26" inside the hero converts significantly better than an implied holiday
- 4. **Differentiate from the morning resend** — if this is a resend to non-openers, the creative should change enough to feel new (different hero product, new lead copy angle)
- 5. **Subject Alt A:** `Ends Monday: Up to 50% off + Double Rewards`
- 6. **Subject Alt B:** `Your Memorial Day sale: nursery furniture up to 50% off`
- 7. **Preheader Alt A:** `Cribs, dressers, rugs — all on sale through the weekend.`
- 8. **Preheader Alt B:** `2x Rewards ends soon. Shop the pieces made for you.`

### 3. Rendering & Accessibility

**`<title>` brand mismatch — confirmed bug**
```html
<title>Crate & Barrel</title>
```
Email sender is "Crate & Kids SALE." Screen readers (NVDA, JAWS, VoiceOver) announce the document title on load. This surfaces the parent brand instead of the sending sub-brand.

**Conflicting `img` max-width media queries — confirmed cascade bug**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
Because the `640px` query is declared *after* the `768px` query and both match at `≥768px`, the cascade gives `640px` the win on all desktop viewports. The intent appears to be 600px on desktop — this rule is never applied.

**`maximum-scale=1` blocks user zoom — WCAG 1.4.4 violation**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from zooming text on mobile. Fails WCAG 2.1 SC 1.4.4 (Resize Text, Level AA).

**`-webkit-text-size-adjust: none` in global `*` selector**
```css
* { -webkit-text-size-adjust: none; ... }
```
Applied globally, not scoped to layout elements. Overrides the `<body>`-level `100%` value set two rules earlier and can suppress iOS dynamic type adjustments across all text nodes.

**Duplicate `format-detection` meta tags**
`telephone=no`, `date=no`, and `address=no` each appear in both a combined tag and standalone tags. Redundant; harmless in practice but indicates stale template hygiene.

**Unflushed developer placeholder comments**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
<!---->
```
Both comments survived to production send. The first has a typo (`IMPUT` → `INPUT`) confirming it was a fill-in directive, not intentional markup.
