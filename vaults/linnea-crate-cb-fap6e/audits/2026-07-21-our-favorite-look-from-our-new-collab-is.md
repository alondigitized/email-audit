### 3. Rendering & Accessibility

**[ISSUE] `maximum-scale=1` blocks user zoom (WCAG 1.4.4)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. WCAG 2.1 SC 1.4.4 failure. Remove `maximum-scale=1`.

**[ISSUE] Conflicting `img` max-width media queries**
```css
@media only screen and (min-width: 640px) { img {max-width: 640px} }
@media only screen and (min-width: 768px) { img {max-width: 600px} }
```
Both fire on viewports ≥768px. Source order gives the 768px rule (`max-width: 600px`) precedence, silently overriding the 640px rule. If the intended max is 640px on desktop, the 768px block is incorrect. If 600px is correct, the 640px rule is dead code.

**[ISSUE] `-webkit-text-size-adjust: none` on `html`**
```css
html { -webkit-text-size-adjust:none; }
```
Disables OS-level text scaling on iOS. Accessibility concern for low-vision users; prefer `-webkit-text-size-adjust: 100%`.

**[ISSUE] Dark mode disabled with no fallback**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Forces light-only rendering. Apple Mail and Outlook dark mode will either invert colors or render the email with poor contrast. No `@media (prefers-color-scheme: dark)` override is present in the visible CSS.

**[MINOR] Duplicate style rules across two `<style>` blocks**
`.ReadMsgBody`, `.ExternalClass`, and `table td { border-collapse }` are declared in both the first and second style blocks. No rendering breakage, but increases parse overhead and complicates maintenance.
