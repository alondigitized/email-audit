### 3. Rendering & Accessibility

**3a. Title tag / brand mismatch**
```html
<title>Crate & Barrel</title>
```
Sender identity is "Crate & Kids"; the `<title>` resolves to the parent brand. While invisible in most clients, some assistive technologies and tab previews surface this value. Should read `Crate & Kids`.

**3b. Duplicate `format-detection` meta tags**
The combined declaration appears once, then each attribute is re-declared individually — four total declarations for three attributes:
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
...
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
Redundant. Consolidate to one tag.

**3c. Conflicting `img` max-width breakpoints**
Two media queries set conflicting constraints:
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
At viewport widths 640–767px, only the 640px rule fires (max-width: 640px). At 768px+, the 768px rule (max-width: 600px) overrides it — images shrink by 40px as the viewport *widens*. Likely unintentional; resolve by consolidating to a single desktop breakpoint.

**3d. `*` selector overrides**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; max-height: 1000000px; ... }
```
`max-height: 1000000px` on `*` is a Gmail clip-prevention hack but is applied universally rather than scoped to the outer wrapper. `-webkit-text-size-adjust: none` (not `100%`) on `*` will suppress text scaling in WebKit browsers even when desirable.

**3e. `maximum-scale=1` in viewport**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents user pinch-to-zoom. Fails WCAG 1.4.4 (Resize Text). Remove `maximum-scale=1`.

**3f. Duplicate CSS blocks**
`.ReadMsgBody` and `.ExternalClass` rules are declared in both the first `<style>` block and the desktop CSS `<style>` block. Not harmful but increases file weight and makes maintenance error-prone.

**3g. Dark mode**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Dark mode explicitly disabled. Apple Mail and some Android clients will force-invert; no `@media (prefers-color-scheme: dark)` override is present to control the fallback appearance.

**3h. Image alt attributes — not verifiable from truncated source.** Confirm all `<img>` tags carry descriptive `alt` values (not empty strings for content images).
