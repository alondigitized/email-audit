## Technical Audit

## 1. Technical Summary
The email uses a standard table-based XHTML template with a mobile media-query layer. The QA run found no hard failures (57% pass rate, 0 issues, 3 warnings), but ~60 images lack alt attributes. The viewport meta also blocks zoom, and the headers and links that matter for compliance and tracking could not be verified from the captured data.

## 2. Link & Tracking Issues
- **Unverified links:** 105 tracking/click-redirect links were skipped from HTTP probing, so none were checked for destinations, status codes or redirect chains.
- **Third-party pixels:** `https://sr.rlcdn.com/448796.gif?s=dbe8da71…&n=1` through `n=5` fire five times. These are LiveRamp (rlcdn) pixels, apparently one per placement. They add third-party requests, and they will be blocked or fail in clients that restrict remote content.
- **First-party pixels:** The open pixel `mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif?mi_u=…` and `dv.crateandbarrel.com/o/1d06d63b-…?mi_cid=…&mi_mid=…` are standard tracking pixels and are expected.
- **Per-recipient hash:** The `mi_u=dbe8da71…` hash appears in image URLs. This is a per-recipient identifier embedded in image requests, and it is an observation rather than a defect.

## 3. Rendering & Accessibility
- **Missing alt text:** The QA check flagged about 60 `<img>` elements.
  - 46 are content images on `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/…` (e.g. `bbf6f9d4-86cc-437a-aa80-391067b74306.png`, `61581a40-….gif`, `971aa10f-….jpg`).
  - 7 are `mi.crateandbarrel.com/p/rp/*.png` images.
  - The other ~7 are tracking pixels (`rlcdn` ×5, `o.gif`, `dv…`). These should carry `alt=""`.
  - With images blocked, or in a screen reader, the content images have no text equivalent. If these are product tiles, the product, offer and link context is lost.
- **Zoom blocked:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` disables pinch-zoom (WCAG 1.4.4).
- **Text scaling disabled:** `*{-webkit-text-size-adjust:none}` and the `html`/`body` rules set `-webkit-text-size-adjust:none` in places. This blocks user text-size scaling in WebKit clients.
- **Markup hygiene:**
  - `<title>Crate & Barrel</title>` has an unescaped `&` under an XHTML 1.0 Transitional doctype, which is invalid XHTML.
  - The `<meta charset>` and `http-equiv` Content-Type declarations are redundant, and `format-detection` is declared three times.
  - A template placeholder comment, `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->`, is still in the source.
  - None of these is likely to break rendering.
- **Truncated source:** The HTML was cut off, so I can't assess the body's structure (role="presentation", link text, heading semantics) or Outlook/VML fallbacks beyond the `<head>`.

## 4. Personalization & Merge Tokens
No issues found. No unrendered merge tokens (`{{…}}`, `%%…%%`, `[FIRST_NAME]`) appear in the captured source or subject. The visible HTML is truncated, so the body is unchecked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe and List-Unsubscribe-Post:** Both are reported missing. The QA tool notes the AgentMail relay may strip them, so this is not confirmed as a sender fault. Gmail and Yahoo bulk-sender rules expect both RFC 8058 headers, so the sender's raw headers should be checked.
- **Authentication-Results:** Not found, so SPF, DKIM and DMARC status is unknown. The tool attributes this to the relay. The From domain `mail.crateandbarrel.com` aligns with the image and tracking subdomains, which is consistent but not proof.
- **Footer unverified:** The footer (visible unsubscribe link, physical postal address) falls outside the truncated source, so I can't confirm either.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not assessable. The 105 links were skipped from probing, and the captured source shows no destination URLs or UTM parameters. The tracked redirect domains hide the final landing URLs, so destination alignment and parameter preservation are unverified.

## 7. Recommendations
1. Add descriptive `alt` text to all content images (product, offer and CTA tiles). Set `alt=""` explicitly on the tracking pixels (`rlcdn`, `o.gif`, `dv…`).
2. Remove `maximum-scale=1` from the viewport meta. Replace `-webkit-text-size-adjust:none` with `100%` to allow text scaling.
3. Escape the title as `Crate &amp; Barrel`. Remove the leftover `IMPUT HERE CLIENT FONT IMPORT` placeholder and the duplicate meta tags.
4. Check the raw (pre-relay) headers for `List-Unsubscribe`, `List-Unsubscribe-Post` and SPF/DKIM/DMARC results before treating the compliance warnings as real.
5. Resolve a sample of the redirect links in a browser or with a redirect-following probe. Confirm final URLs, status codes and UTM presence.
6. Capture the full HTML so the footer, unsubscribe link and body markup can be audited.
