# STARTS NOW! Up to 60% off The Memorial Day Event + 2x Rewards!
**Score:** 8/10 · **Type:** Email audit · **2026-05-14**
## Executive summary

- This is a textbook Memorial Day sale send from Crate & Barrel — handsome lifestyle photography, a strong headline discount (up to 60% off), and a loyalty kicker (2x Rewards) that gives members a concrete reason to act now. The visual execution is clean: no broken images, no obvious layout collapse, and the hero lands the offer immediately. For anyone in the C&B universe, it's genuinely actionable.
- The problem is the email tries to do too much. By the time you get past the hero, you're hit with a Double Rewards explainer, a TheDesignDesk consultation pitch (twice), a multi-product grid, and an app download prompt. Each module competes for attention and the cumulative weight risks the reader bouncing before reaching the products. The subject line's ALL-CAPS opener and the 62-character length push into inbox noise territory for mobile.
- Bottom line: a strong offer buried slightly by module sprawl and a subject that oversells the urgency. Would convert with existing C&B loyalists; misses a chance to pull in lapsed or new subscribers.

## What's working

- **Hero clarity:** "Starts Today! Up to 60% Off The Memorial Day Event" is unambiguous — the offer reads in under two seconds.
- **Loyalty double-dip:** Pairing the 60% discount with 2x Rewards is a genuine value-stack for members; it's visible in both subject and body.
- **Photography:** The lifestyle hero image is high quality with a seasonal coastal feel — appropriate for May and consistent with C&B's brand aesthetic.
- **Clean render:** No broken images, no overlapping text, no lorem ipsum. Layout holds up in the screenshot.
- **Product grid:** Showing actual merchandise below the fold gives multiple click entry points without requiring users to land on a category page.

## What's weak

- **Module overload:** Hero → Double Rewards → TheDesignDesk → product grid → TheDesignDesk (again) → app promo is five distinct asks. The email doesn't know what it wants you to do most.
- **TheDesignDesk appears twice:** Back-to-back placements of the same service feel like a production error or over-indexing on a low-conversion service in a high-discount moment.
- **Subject line ALL CAPS opener:** "STARTS NOW!" reads like inbox noise — it's the kind of signal that trained users to ignore or spam-flag.
- **"Up to 60% off" hedge:** The "up to" qualifier is standard but, combined with no anchor product or minimum savings shown, the offer feels slightly soft compared to what the subject promises.

## Recommendations

- 1. **Cut the email to three modules:** Hero → product grid (4–6 hero items on sale) → loyalty/rewards callout. Drop TheDesignDesk to a footer text link — it's a conversion-killer in a sale email.
- 2. **Rewrite the subject — drop the ALL CAPS:** The urgency is already in the content; the caps are friction, not acceleration.
- **Subject Alt A:** `Memorial Day starts now — up to 60% off + 2x Rewards`
- **Subject Alt B:** `60% off starts today: The Crate & Barrel Memorial Day Event`
- 3. **Add a real preheader:** The preview text appears to be leaking non-copy content. Use it to anchor a specific category or product to create a content bridge from subject to open.
- **Preheader Alt A:** `Shop sofas, dining, outdoor — ends Memorial Day weekend.`
- **Preheader Alt B:** `Your 2x Rewards window is open. Ends Monday.`
- 4. **Anchor one hero product:** Instead of a pure lifestyle hero, overlay one featured item with its sale price. Converts the image from mood board to purchase prompt.
- 5. **Add a deadline:** "Memorial Day Event" implies an end date but doesn't state it. A visible "ends May 26" line would sharpen click urgency.

### 3. Rendering & Accessibility

**Confirmed issues:**

**3a. `maximum-scale=1` in viewport meta — accessibility violation**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom. WCAG 2.1 SC 1.4.4 (Resize text) violation. Remove `maximum-scale=1`.

**3b. Conflicting desktop image max-width media queries**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
At viewport widths ≥768px, both rules apply. Because the `640px` breakpoint is declared *after* the `768px` one, it wins via cascade — images cap at `640px` even on wide viewports. The `768px` rule is effectively dead. Consolidate to a single rule.

**3c. `.showmobile` hardcoded to `414px`**
```css
.showmobile { width: 414px !important; }
```
Hardcodes to iPhone X/11/12 width. On small Android devices (360px wide), this causes horizontal overflow. Use `100%` or `calc(100vw - 40px)` instead.

**3d. Dark mode explicitly disabled**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Apple Mail and Gmail on iOS will attempt an auto-invert that may distort the `#e6e7e8` background and image assets. Either add a tested dark-mode media query or accept the rendering risk — but the current opt-out with no fallback leaves dark mode clients unstyled.

**3e. Wildcard `line-height` override**
```css
* { line-height: 100%; }
```
Applies to every element including `<td>`, `<img>`, and `<span>`. Can collapse line-height on multi-line text blocks. Scope this to specific selectors.

**Alt text:** Cannot assess — image tags not present in truncated source. Full-source review should confirm every `<img>` has a non-empty `alt` attribute.
