### 3. Rendering & Accessibility

**Confirmed issues:**

- **`maximum-scale=1` in viewport meta** blocks pinch-to-zoom on mobile. Violates WCAG 1.4.4 (Resize Text). Selector: `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />`

- **`-webkit-text-size-adjust: none` applied universally** via `*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none;}`. Should be `100%`, not `none`. This suppresses OS-level text scaling for visually impaired users.

- **`line-height: 100%` on `*`** — `*{ line-height: 100% }` collapses line-height to equal font-size on every element. Multi-line text blocks will have no leading, causing lines to collide on some clients.

- **Conflicting desktop image `max-width` media queries:**
  - `@media (min-width: 768px) { img { max-width: 600px } }`
  - `@media (min-width: 640px) { img { max-width: 640px } }`
  At 640–767px viewport width, the 640px rule applies — but if the container is 600px wide, images will be constrained by the container anyway. At ≥768px, the 600px rule overrides. The 640px query is effectively dead code and creates false confidence about image sizing.

- **`dark-mode` explicitly disabled** — `<meta name="color-scheme" content="light">` and `supported-color-schemes: light` opt out of dark mode rendering entirely. Recipients using dark-mode email clients will see a forced light background; no dark-mode fallback is provided.

- **`appleLinksBlack` class color mismatch** — `.appleLinksBlack a { color:#989898 }` applies medium gray, not black. The naming is misleading and could cause incorrect class application in future templates.

- **Alt text on images: unverifiable** — source is truncated before any `<img>` tags.
