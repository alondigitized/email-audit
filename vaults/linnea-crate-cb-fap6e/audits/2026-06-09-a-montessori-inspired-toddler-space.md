### 3. Rendering & Accessibility

**[HIGH] Dead CSS rule — conflicting `img max-width` media queries**
Two `min-width` blocks appear back-to-back and conflict:
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
The `640px` block appears *after* the `768px` block. Equal specificity, last-rule-wins: on screens ≥768px both fire and the `640px` rule wins. The `768px / max-width: 600px` rule is dead code and never applies. Images will render at 640px max on desktop, not 600px as likely intended.

**[MEDIUM] `maximum-scale=1` blocks pinch-to-zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from zooming on mobile. WCAG 1.4.4 violation.

**[MEDIUM] Global `text-size-adjust: none` on `*` selector**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```
Disables OS-level text scaling for all elements, not just the `<body>`. Affects users with low vision who rely on system font scaling.

**[MEDIUM] Title/brand mismatch**
```html
<title>Crate & Barrel</title>
```
Sender identity is "Crate & Kids"; the `<title>` reads "Crate & Barrel". Affects screen reader announcement and browser tab if the email is viewed in a web version.

**[LOW] Duplicate `format-detection` meta tags**
The same directives are declared three times across separate tags:
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
...
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
Redundant; no functional breakage but adds parse overhead.

**[LOW] Duplicate charset declaration**
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta charset="utf-8">
```
Both are present. The HTML5 `charset` form is sufficient; the `http-equiv` form is legacy XHTML. Not harmful, but inconsistent with "no redundant markup."

**[LOW] Global `p { text-align: center; }` rule**
All `<p>` elements default to centered text. Any plain-text paragraphs in the footer (physical address, legal copy) will also be centered unless explicitly overridden.
