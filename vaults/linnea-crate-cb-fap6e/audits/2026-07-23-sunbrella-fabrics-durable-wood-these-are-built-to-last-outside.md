### 3. Rendering & Accessibility

**Conflicting desktop `img` max-width breakpoints (confirmed bug):**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }  /* line ~65 */
@media only screen and (min-width: 640px) { img {max-width: 640px} }  /* line ~69 */
```
On screens ≥ 768px both rules fire; the second rule wins by source order, capping images at 640px, not 600px. The 600px rule is dead on all desktop clients. This is likely unintentional.

**`maximum-scale=1` in viewport meta (accessibility):**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocks user pinch-zoom on mobile. Violates WCAG 1.4.4 (Resize Text, Level AA).

**Dark mode explicitly disabled:**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Apple Mail and iOS Mail will force light rendering and suppress dark-mode overrides. This is a deliberate choice but will produce uncontrolled color inversions on clients that ignore these hints (e.g., older Gmail Android).

**`-webkit-text-size-adjust: none` applied globally** via `*{}` selector. This suppresses OS-level text scaling for low-vision users across WebKit clients.

**Duplicate `format-detection` meta tags:** The directive appears 4 times — once combined (`telephone=no,address=no,email=no,date=no,url=no`) and then three separate declarations for `date`, `address`, and `telephone`. Redundant; no functional harm but signals template hygiene issues.

**Duplicate charset declaration:**
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta charset="utf-8">
```
Both present. Redundant; harmless in practice.
