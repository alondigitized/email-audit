## Technical Audit

## 1. Technical Summary
The email's markup basics are sound (`lang="en"`, XHTML doctype, MSO conditionals, preheader-safe resets). About 52 `<img>` tags have no `alt` attribute, and the QA harness couldn't confirm the compliance or authentication headers. The HTML source was truncated, so body-level checks (footer, unsubscribe link, UTMs) were not possible.

## 2. Link & Tracking Issues
- **96 tracking/click-redirect links were not probed.** They were skipped as tracking domains, so destination validity, redirect chains and 404s are unverified. This is a coverage gap, not a confirmed defect.
- **Third-party pixel stack.** The QA data shows these tracking images:
  - `https://sr.rlcdn.com/448796.gif?s=dbe8da71…&n=1` through `n=5`. These are five identical LiveRamp pixels, differing only by `n`.
  - `https://mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif?mi_u=…`, the open pixel.
  - `https://dv.crateandbarrel.com/o/226ed0f0-…?mi_cid=…&mi_mid=…`, a second open/view beacon.
- Five repeated `rlcdn.com` calls and two open beacons add requests without adding signal. The `s=` hash and `mi_u=` identifier are per-recipient values placed in image URLs. Proxy or privacy-preserving clients, such as Apple Mail Privacy Protection, will fetch them regardless of whether a human opened the email.

## 3. Rendering & Accessibility
- **~52 images flagged for missing `alt`.**
  - **Content images (38):** `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/*.jpg|png|gif`, e.g. `bbf6f9d4-…png`, `bf3053a9-…jpg`, `971aa10f-…jpg`. The QA data doesn't show whether any of these carry the primary messaging. If they do, this is a real accessibility and images-off failure.
  - **Product/recommendation images (7):** `mi.crateandbarrel.com/p/rp/*.png`.
  - **Tracking pixels (7):** the `rlcdn.com`, `o.gif` and `dv.` beacons. These should carry `alt=""`, which is a minor fix. A missing attribute is read differently from an empty one by screen readers.
- **`<meta name="viewport" content="…maximum-scale=1">`** disables pinch-zoom, an accessibility issue (WCAG 1.4.4).
- **Conflicting `format-detection` metas.** There are three declarations: `telephone=no,address=no,email=no,date=no,url=no`, then separate `date=no`, `address=no` and `telephone=no`. They are redundant, and clients typically honor only the first.
- **Dead CSS rule.** `@media (min-width:768px){img{max-width:600px}}` is followed by `@media (min-width:640px){img{max-width:640px}}`. Both match at ≥768px with equal specificity, so the later 640px rule wins and the 600px rule never applies.
- **Unescaped `&` in `<title>Crate & Barrel</title>`.** This is invalid XHTML under the declared doctype. It is cosmetic in practice.
- **Leftover template comment:** `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->`. It is harmless, but it exposes template scaffolding and has a typo.

## 4. Personalization & Merge Tokens

- Recipient-specific identifiers are present in URLs (`mi_u=dbe8da71…`, `mi_mid=…`). They are resolved, not broken.
- The body was truncated, so tokens further down can't be ruled out.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) not found.** The QA tool states these may be stripped by the AgentMail relay, so this is **unconfirmed**. Treat it as a capture limitation, not proof of non-compliance. Gmail and Yahoo bulk-sender rules require both headers.
- **`Authentication-Results` not found.** SPF, DKIM and DMARC status is unknown, again because of the relay. Verify against the raw message at the original receiving MTA if this matters.
- Footer physical address and in-body unsubscribe link are not visible in the truncated source and are unverified.
- The From domain `mail.crateandbarrel.com` is consistent with the image host `image.mail.crateandbarrel.com`, so no domain mismatch is visible.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- UTM parameters and landing-page destinations **could not be verified**. All 96 links were skipped as tracking redirects and the truncated source shows no resolved hrefs.
- The click-through URLs are wrapped in a redirect domain (`mi.crateandbarrel.com` / `dv.crateandbarrel.com`). That's standard ESP behavior, but final-destination alignment with the "Durable, stylish, elegant" dinnerware subject remains untested.

## 7. Recommendations
1. Add descriptive `alt` text to the 38 `image.mail.crateandbarrel.com` content images and the 7 `mi.crateandbarrel.com/p/rp/` product images. Use `alt=""` on the tracking pixels.
2. Remove `maximum-scale=1` from the viewport meta.
3. Consolidate the five `sr.rlcdn.com/448796.gif` calls into one, and the duplicate `format-detection` metas into a single declaration.
4. Reorder or remove the conflicting `img{max-width}` media queries.
5. Escape the title as `Crate &amp; Barrel` and strip the `[IMPUT HERE …]` comment.
6. For the audit pipeline itself:
   - Capture the raw headers (`List-Unsubscribe`, `List-Unsubscribe-Post`, `Authentication-Results`) before the relay, or flag these three checks as "indeterminate" rather than WARN.
   - Resolve redirect chains for a sample of the 96 tracking links so UTM and landing-page checks can run.
   - Pass the full, untruncated HTML so footer, unsubscribe and token checks are possible.
