### 3. Rendering & Accessibility

**Confirmed issues:**

**A. `maximum-scale=1` blocks user zoom (WCAG 1.4.4 violation)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Accessibility failure — users with low vision cannot zoom content.

**B. Global `text-size-adjust: none` overrides user accessibility settings**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```
Applied to the universal selector `*`. This suppresses browser/OS font scaling for all elements, not just table cells. Conflicts with user accessibility preferences.

**C. Conflicting `img max-width` rules across two media queries**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
At viewport widths ≥ 768px, both rules apply. The 768px query (600px) is declared later, so it wins — but that means images on wide desktop viewports are constrained to 600px while the container is 640px. This likely causes a 40px gap or forces a fallback. One of these breakpoints is redundant; the 768px rule should probably be removed or aligned to 640px.

**D. `line-height: 100%` on universal selector**
```css
*{... line-height: 100%}
```
A `line-height` of `100%` (relative to font-size) can clip descenders in some Outlook and Samsung Mail versions. Should use unitless values like `1.2` or explicit `px`.

**E. Dark mode not supported**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Only `light` is declared. In Apple Mail and Outlook on iOS with dark mode enabled, no overrides are provided — clients may invert colors unpredictably. A `@media (prefers-color-scheme: dark)` block is absent.

**No issues found:** `lang="en"` present on `<html>`, charset declared, VML namespace present for Outlook.
