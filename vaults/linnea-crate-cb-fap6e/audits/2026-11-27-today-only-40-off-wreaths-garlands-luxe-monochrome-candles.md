## Technical Audit

## 1. Technical Summary
The email is a table-based XHTML Transitional build on Marigold/Mapp-style infrastructure (`image.mail.`, `mi.`, `dv.` subdomains). The automated checks found 0 hard failures. The main code-level problems are widespread missing `alt` attributes (at least 39 images), many third-party tracking pixels, and compliance headers the relay didn't capture. The HTML was truncated, so the footer, unsubscribe link and body links couldn't be inspected.

## 2. Link & Tracking Issues
- **79 tracking links were not probed.** The QA tool skipped them as click-redirect domains, so none of the destination URLs or redirect chains are verified. The QA data can't confirm the links resolve.
- **Five identical LiveRamp pixels.** `https://sr.rlcdn.com/448796.gif?s=dbe8da71…&n=1` through `n=5` are the same pixel with an incrementing counter, and none has `alt`. Five third-party calls for one ID sync add render weight and a privacy surface.
- **Per-recipient identifier in image URLs.** The `mi_u=dbe8da718e2997cce014546f16c5722eaa3c322f28d40f0a8386f8fd101…` parameter appears on `mi.crateandbarrel.com/p/rp/*.png` and `/p/up/50c75a732e99b42a/o.gif`. The same hash appears as `s=` in the rlcdn pixels, so one user ID is shared with a third party. It is also the likely reason the `rp/*.png` images (dynamic recommendations) are 7 separate per-user requests.
- **Open-tracking pixels.** `o.gif` (mi.) and `https://dv.crateandbarrel.com/o/ef03845b-…?mi_cid=…&mi_mid=…` serve as the tracking beacons. The `dv.` URL is cut off in the report, so its full query string is unverified.

## 3. Rendering & Accessibility
- **Missing alt text on at least 39 images (the QA output looks truncated).**
  - 25 are content images on `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/…` (`.jpg`, `.gif`, `.png`).
  - 7 are `mi.crateandbarrel.com/p/rp/*.png`, which are dynamic product-recommendation images.
  - The rest are the 5 rlcdn pixels, `o.gif`, and the `dv.` beacon.
  - With images off, or in a screen reader, the email's offer content is likely inaccessible. Tracking pixels should use `alt=""` and not be left with no `alt` attribute at all.
- **Zoom is disabled.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` blocks pinch-zoom, a WCAG 1.4.4 concern.
- **Text resizing is disabled.** `-webkit-text-size-adjust:none` appears in the global `*{…}` rule and in `body`. It also conflicts with `-webkit-text-size-adjust:100%` set elsewhere in the same stylesheet.
- **Invalid markup.** `<title>Crate & Barrel</title>` has an unescaped `&`, which is invalid under the XHTML 1.0 doctype. The head also has duplicate `<meta name="format-detection">` tags (3 variants) and both `<meta http-equiv="Content-Type" …>` and `<meta charset="utf-8">`.
- **Template artifact left in the source.** `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->` (note the typo) is an unpopulated placeholder.
- **Broad CSS reset.** `*{… line-height:100%}` and `p{margin:0 auto; text-align:center}` apply to every element and can cause inheritance surprises in Outlook/Gmail.
- **Responsive breakpoints.** `.mobile{width:460px}` and `.showmobile{width:414px}` use fixed pixel widths, and the only mobile breakpoint is `max-width:460px`. Between 461px and 640px there is no adaptive rule. This can't be confirmed as a defect without the rendered body.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens (`{{…}}`, `%%…%%`, `[FIRST_NAME]`) appear in the visible source. The only visible placeholder is the template comment noted above.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **No `List-Unsubscribe` header.** The QA tool flags it as "may not be captured by AgentMail relay". This is a capture limitation and can't be treated as a sender defect.
- **No `List-Unsubscribe-Post` header (RFC 8058).** The same relay caveat applies. A sender this size would normally publish it, since Gmail and Yahoo require one-click unsubscribe for bulk senders.
- **No `Authentication-Results` header.** SPF, DKIM and DMARC alignment are unknown. The From domain `mail.crateandbarrel.com` matches the image host, which is a good sign, but this isn't verified.
- **Footer not inspected.** The HTML was truncated before the footer, so the visible unsubscribe link and physical postal address could not be checked.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not verifiable. All 79 links were skipped as redirect domains, and the visible source has no resolved destination URLs, so UTM parameters and landing-page alignment can't be assessed. The subject promises "40% off wreaths, garlands & luxe Monochrome candles", and there's no way to confirm that the click targets match it.

## 7. Recommendations
1. Add descriptive `alt` text to all content images, starting with the `image.mail…/m/1/*.jpg|gif|png` set and the `mi…/p/rp/*.png` recommendations. Use `alt=""` on the tracking pixels.
2. Reduce the five `sr.rlcdn.com/448796.gif` pixels to one, or confirm each is needed.
3. Remove `maximum-scale=1` from the viewport meta tag and drop `-webkit-text-size-adjust:none`.
4. Escape the `&` in `<title>`, remove the duplicate meta tags, and delete the leftover `[IMPUT HERE CLIENT FONT…]` comment.
5. Verify `List-Unsubscribe` and `List-Unsubscribe-Post` against the raw MIME message from a direct inbox, not the relay.
6. Pull `Authentication-Results` from a direct copy of the email to confirm SPF, DKIM and DMARC.
7. Re-run the audit with the full, untruncated HTML and a redirect-following link resolver. That would cover the footer, the postal address, the UTM parameters and the landing-page match.
