### 3. Rendering & Accessibility

**[HIGH] `maximum-scale=1` in viewport meta disables user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Violates WCAG 2.1 SC 1.4.4 (Resize Text). Some email clients honor this; others ignore it. Remove `maximum-scale=1`.

**[MEDIUM] Conflicting desktop image `max-width` media queries — 600px rule is dead**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }  /* fires at 768px+ */
@media only screen and (min-width: 640px) { img {max-width: 640px} }  /* fires at 640px+, overrides above */
```
At viewports ≥768px both rules match; the 640px block appears last in the stylesheet so `max-width: 640px` wins. The 600px rule is effectively unreachable. If the intended desktop cap is 600px, reverse the order or combine into a single `min-width: 640px` rule.

**[LOW] Duplicate `format-detection` meta tags (4 instances)**
A combined version plus three individual overrides for `date`, `address`, and `telephone` are all present. Redundant; no functional impact but adds unnecessary bytes.

**[LOW] Duplicate `charset` declaration**
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta charset="utf-8">
```
Both present. XHTML Transitional requires the http-equiv form; the HTML5 shorthand is harmless but redundant noise.

**[LOW] `color-scheme: light` / `supported-color-schemes: light` — dark mode explicitly suppressed**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Apple Mail and some Android clients will not offer dark mode adaptation. Intentional or oversight — confirm with design team.
