## 3. Rendering & Accessibility

**Confirmed issues:**

- **`maximum-scale=1` in viewport meta** blocks user zoom on mobile.
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
  ```
  Violates WCAG 1.4.4 (Resize Text, Level AA). Remove `maximum-scale=1`.

- **Conflicting desktop image `max-width` rules.** Two back-to-back media queries both fire at ≥ 768px; the cascade resolves to the wrong value:
  ```css
  @media only screen and (min-width: 768px) { img { max-width: 600px } }
  @media only screen and (min-width: 640px) { img { max-width: 640px } }  /* wins */
  ```
  At 768px+ viewports, images cap at 640px instead of the intended 600px. Either remove the 640px rule or reorder and scope it to `max-width: 767px`.

- **`-webkit-text-size-adjust: none` on `html` element** (client stylesheet) overrides the `100%` set on `body` in the general stylesheet. `none` completely disables text scaling on iOS Safari — use `100%` consistently.

- **No dark mode declarations.** `color-scheme` and `supported-color-schemes` are both set to `"light"` only. Clients that force dark mode (Gmail Android, Outlook) may invert colors unpredictably. Add `dark` to both if dark mode styles are not intentionally suppressed.

- **`.showmobile` hardcoded to `width: 414px`** — device-specific (iPhone 6/7/8). Phones with narrower viewports will overflow this. Use `width: 100%` with a `max-width`.
