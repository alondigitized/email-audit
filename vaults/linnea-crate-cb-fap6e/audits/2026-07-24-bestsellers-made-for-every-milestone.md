# Bestsellers made for every milestone
**Score:** 5/10 · **Type:** Email audit · **2026-07-24**
## Executive summary

- This is a milestone-journey editorial email — Crate & Kids walking the subscriber through developmental stages from crib to big-kid bed, with product pairings anchored to each stage. The concept is legitimate and brand-consistent, fitting the long-term Finn Collection thread they've been building since the July 23 collection intro. The photography is clean, the layout is tidy, and the brand voice lands.
- The critical problem: there is an active Back-to-School Sale running — up to 20% off, launched yesterday — and this email makes zero mention of it. Not in the hero, not in a banner, not in a footer callout. A subscriber who opened yesterday's "STARTS NOW" email and comes back to this one expecting sale continuity gets an editorial shrug instead of a conversion path. That's a budget and a momentum wasted.
- The "bestsellers" framing implied by the subject is also soft. There's no bestseller badge, review count, or social proof visible in the render. It reads more like a curated editorial than a true bestseller signal.

## What's working

- Visual hierarchy is clean — the hero crib-to-bed sequence is the dominant visual element and draws the eye immediately.
- The milestone-stage structure is an ownable concept for this brand; it reinforces the "grow with them" positioning from the Finn Collection send.
- No render bugs or layout breaks visible — the email renders correctly across the visible sections.
- Crate & Kids sender identity is immediately recognizable; no spam signals in subject or layout.

## What's weak

- The active 20% off Back-to-School Sale is completely absent — no banner, no callout, no urgency hook anywhere in the email.
- "Bestsellers" is asserted in the subject but never proved in the body — no star ratings, review counts, or "top seller" badges are visible.
- No single hero product takes center stage; the multi-section layout fragments attention and dilutes the click path.
- Subject lacks any specificity or urgency — "made for every milestone" is pleasant but forgettable, especially competing in a busy July inbox.

- 1. **Add a sale banner or sticky header.** Drop a "Back-to-School Sale — Up to 20% Off" strip at the top. The sale is live; this email is driving traffic to the same products. Not connecting them leaves conversion on the table.

- 3. **Pick a hero.** The milestone framework works editorially, but lead with one iconic product — the flagship convertible crib — as a named, linked hero before going multi-section.
- 4. **Sharpen the subject.** The current line is a positioning statement, not an inbox hook.

### 3. Rendering & Accessibility

**[HIGH] Viewport `maximum-scale=1` blocks pinch-zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from zooming in. WCAG 1.4.4 (Resize Text, AA) violation. Remove `maximum-scale=1`.

**[MEDIUM] Conflicting `img` max-width breakpoints**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
Source order puts the 768px rule first, so at ≥768px viewports the 600px rule is overridden by the later 640px rule (640px wins). Between 640–767px, images are allowed to render at 640px — wider than the 600px email container. Reorder: 640px rule first, 768px rule second.

**[MEDIUM] Universal `line-height: 100%` reset**
```css
* { line-height: 100%; }
```
Collapsing line-height to `100%` on every element can cause multi-line text to overlap in certain clients (Samsung Mail, some Webmail renderers). Scope to `table td` or specific selectors rather than `*`.

**[LOW] `<title>` brand mismatch**
```html
<title>Crate & Barrel</title>
```
Sender is "Crate & Kids"; title should match. Shown in some email clients as the tab or preview label.

**[LOW] `format-detection` meta declared four times**
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
Redundant — the combined declaration on line 1 covers all cases. The three duplicates are dead weight; remove them.

**[LOW] `charset` declared twice**
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta charset="utf-8">
```
Redundant but harmless. The `http-equiv` form is for legacy clients; both can coexist, but the duplicate is unnecessary noise.

**[LOW] Dark mode not supported**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
No `prefers-color-scheme: dark` media query present. Apple Mail and iOS Mail will force-invert unprotected colors. If dark mode styles aren't intentionally omitted, `color-scheme` should be `light dark` with matching CSS.
