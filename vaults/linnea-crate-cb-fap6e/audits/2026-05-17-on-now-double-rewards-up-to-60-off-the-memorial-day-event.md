# ON NOW! Double Rewards + up to 60% off The Memorial Day Event!
**Score:** 9/10 · **Type:** Email audit · **2026-05-17**
## Executive summary

- This is Crate & Barrel's Memorial Day escalation send — the offer ceiling has been pushed to 60% off (up from the 40–50% range that dominated the past 72 hours), and the "ON NOW!" opener signals a peak-urgency posture. The cinematic dark-ocean hero is the best creative this family has run all week: bold, high-contrast, impossible to miss. But the email body undercuts itself almost immediately. A "Welcome at the touch of a button" section appears mid-email with no obvious connection to a Memorial Day sale, and an app download block competes with the primary conversion goal. For a subscriber who has received nine or ten emails from this family since Friday, this is the one that should have closed the loop — and instead it sprawls.
- The dual-brand structure (Crate & Barrel hero → Crate&Kids product grid) also splits attention. If you came for furniture, the nursery/kids imagery sends you looking for your category. If you came for kids, the hero didn't speak to you. Neither audience is served cleanly.
- The 60% headline is the strongest hook in this send window. The execution doesn't honor it.

## What's working

- **Hero is the best creative of the series** — the dark coastal scene with white-on-dark text creates genuine visual impact and the 60% off claim lands without ambiguity.
- **Offer escalation is the right call** — moving from 40–50% to 60% gives this send a legitimate reason to exist after an extremely dense send week.
- **"We love these for you" personalized product section** shows CRM maturity; the implicit segmentation signal that this email knows something about you.
- **Double Rewards + discount stacking** is a concrete dual-value prop — two reasons to buy now, not one.
- **No visible render bugs** — the email loads cleanly, images render, layout holds.

## What's weak

- **"Welcome at the touch of a button" section is dead weight** — mid-email, in the middle of a sale event, it's jarring and contextually orphaned. Unclear what action it's asking for.
- **App download block splits the conversion goal** — a subscriber primed to shop the Memorial Day event is now being asked to also download an app. One CTA or the other, not both.
- **Subject line opens with "ON NOW!" in all-caps** — spam-adjacent, and at 62 characters it's over the mobile clip threshold, meaning the event name may truncate in most inboxes.
- **No explicit deadline visible** — "ON NOW!" implies urgency but the end date of the Memorial Day Event is never surfaced; a subscriber can rationalize clicking away and coming back.
- **After 10 sends in ~72 hours, 60% off reads as desperation, not celebration** — the escalating offer trains subscribers to always wait for the peak, and the peak is now.

## Recommendations

- 1. **Surface an explicit deadline in the hero** — "Ends Monday at midnight" or a countdown timer turns the urgency from implied to credible. This is the single highest-lift change.
- 2. **Cut the "Welcome at the touch of a button" section entirely** — it serves no sale purpose and interrupts the scroll.
- 3. **Move app download to the footer** — or save it for a non-sale send where it can be the hero ask.
- 4. **Pick one sub-brand per send** — either Crate & Barrel or Crate&Kids; the dual-brand structure dilutes category relevance for both audiences.
- 5. **Replace "ON NOW!" with something credible and under 50 chars** — specificity earns opens; shouting costs them.

- **Preheader Alt A:** `Furniture, rugs, bedding, outdoor — everything in the Event ships free over $49`

### 3. Rendering & Accessibility

**FAIL — Zoom blocked:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
`maximum-scale=1` prevents pinch-to-zoom. WCAG 2.1 SC 1.4.4 violation.

**FAIL — Global text-size override:**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
Applied on the wildcard selector — overrides user OS accessibility font-size settings across all elements, not just the body.

**WARN — Dark mode suppressed:**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Explicitly disables dark mode rendering. Background `#e6e7e8` set on `body` will remain in dark-mode clients that respect these declarations; images without dark-mode variants will likely clash.

**WARN — Conflicting `img` max-width breakpoints:**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
The `640px` rule is declared *after* the `768px` rule. On screens ≥768px, both fire and the later cascade wins (`640px`), making the `768px` rule a dead rule. Likely unintentional; images on large viewports get 640px cap instead of the intended 600px.

**WARN — Global paragraph center-align:**
```css
p { margin: 0 auto; text-align: center; }
```
Forces center alignment on every `<p>` in the document. Any left-aligned body copy in `<p>` tags will be overridden unless explicitly overridden inline.

**INFO — Duplicate `format-detection` meta tags:**
`telephone=no`, `address=no`, and `date=no` each appear twice (once in the combined declaration, once standalone). Harmless but indicates copy-paste without cleanup.

**INFO — Vestigial MSO conditional block:**
```html
<!--[if !mso]><!--> <!--<![endif]-->
```
Empty no-op conditional. Dead code from template.
