**Unfilled template placeholder comment in production HTML**

Two artifacts: (1) a production-visible template instruction with a typo ("IMPUT" vs "INPUT"), (2) a dangling empty comment immediately after. Neither causes rendering failure but indicates the send template was not cleaned before deployment.

**`maximum-scale=1` blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents accessibility zoom in supporting clients (some iOS mail clients honor this). WCAG 1.4.4 failure risk.

**Conflicting `text-size-adjust` rules**
```css
/* body rule */
body { -webkit-text-size-adjust: 100%; -ms-text-size-adjust: 100%; }

/* universal selector overrides body */
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
The `*` selector's `none` value overrides the `body` rule on all descendants, disabling text scaling entirely across all elements. Likely unintentional.

**Conflicting `img` max-width media queries**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
At ≥768px, both queries match. Cascade order makes the 600px rule (declared later) win, capping images at 600px on desktop despite the 640px query existing. If 640px is the intended desktop container width, the order should be reversed.

**Duplicate `format-detection` meta tags**
Four declarations total: one combined, then three individual — `date=no`, `address=no`, `telephone=no`. Redundant; no rendering impact, but adds parse weight.
