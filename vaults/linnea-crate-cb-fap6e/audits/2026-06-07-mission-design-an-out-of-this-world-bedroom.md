### 3. Rendering & Accessibility

**`<title>` brand mismatch**
```html
<title>Crate & Barrel</title>
```
The sending brand is "Crate & Kids" but the document title is "Crate & Barrel." Screen readers and some email clients surface the `<title>` tag; this is a brand accuracy issue that also affects accessibility for AT users.

**Conflicting `img max-width` media queries**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
The 640px breakpoint is declared *after* the 768px rule. On screens 768px+ both rules apply; the 640px rule wins via cascade order, overriding the intended 600px cap. Images will render at 640px max on desktop, not 600px as intended.

**Duplicate `format-detection` meta tags**
Three separate `format-detection` declarations are present: one combined and two redundant single-attribute repeats:
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
No functional harm but signals copy-paste assembly error in the template head.

**Global `*` reset includes `max-height:1000000px`**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; max-height:1000000px; ...}
```
Applying `max-height` to every element globally is a Gmail clipping workaround hack that can interfere with dynamic content blocks and animated GIFs in some clients.
