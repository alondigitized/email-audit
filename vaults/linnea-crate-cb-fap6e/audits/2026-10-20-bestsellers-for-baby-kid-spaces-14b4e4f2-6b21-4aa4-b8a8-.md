## Technical Audit

## 1. Technical Summary
The email is a Movable Ink–built XHTML template with 108 click-tracking redirects and around 65 images missing alt text. The truncated source and the relay-stripped headers leave unsubscribe, authentication and UTM handling unverifiable. QA result: 50% pass, 0 errors, 4 warnings.

## 2. Link & Tracking Issues
- **Click links unprobed:** all 108 links go through tracking/redirect domains, and the QA probe skipped them. Destination status, redirect chains and final URLs are unverified.
- **Duplicate third-party pixels:** the same LiveRamp pixel `https://sr.rlcdn.com/448796.gif?s=dbe8da71…&n=1` through `n=5` loads five times. Only `n` differs, and the hashed `s` value is identical each time. This adds 5 third-party requests to the render and the same identifier is sent to LiveRamp five times.
- **Subscriber identifier in image URLs:** `mi_u=dbe8da718e2997cc…` appears in `mi.crateandbarrel.com/p/rp/f3c0d22992a01946.png` (6 instances) and `o.gif`. Each Movable Ink dynamic-content image therefore carries a per-recipient hash. This is standard for the platform, but it means the images can't be cached or proxied as static assets.
- **Inconsistent image hosts:** assets come from `image.mail.crateandbarrel.com`, `s7d5.scene7.com`, `mi.crateandbarrel.com`, `dv.crateandbarrel.com` and `sr.rlcdn.com`. If any host is blocked or slow, parts of the email break.

## 3. Rendering & Accessibility
- **Missing alt text:** about 65 `<img>` tags are flagged. Most are product and content images on `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/*.jpg`. Examples:
  - `bbf6f9d4-86cc-437a-aa80-391067b74306.png`
  - `CK%5FH26%5FKidsHolidayMagic%5F24x13%5FEdit3%5FTert` (scene7)
  - `25%5FMI%5FBottom%5FSpacer%5F40px%5FWhite` (scene7, twice)

  With images blocked, the email is largely empty. Screen readers may announce filenames or URLs instead. Spacers and tracking pixels should carry `alt=""`. Content images need descriptive alt text.
- **Viewport blocks zoom:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` disables pinch-zoom on mobile, which fails WCAG 1.4.4.
- **Invalid markup under the XHTML 1.0 Transitional doctype:**
  - `<title>Crate & Barrel</title>` has an unescaped `&`; it should be `&amp;`.
  - `<meta charset>` is declared twice (once via `http-equiv`).
  - `format-detection` is declared three times with conflicting values (`telephone=no,address=no,email=no,date=no,url=no`, then `date=no`, `address=no`, `telephone=no`).
- **Template leftovers:** the source contains `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->` and empty `<!--[if !mso]><!-->` blocks. These are harmless but show the template wasn't cleaned.
- **Conflicting `img` max-width rules:** `@media (min-width:768px) { img {max-width:600px} }` and `@media (min-width:640px) { img {max-width:640px} }` overlap. Above 768px, source order decides the winner. This is a fragile cascade.
- **Universal selector:** `*{… line-height:100%}` and `-webkit-text-size-adjust:none` override text-resize preferences.
- **Subject glyphs:** `★★★★★` is likely read as "black star" five times by screen readers.
- **Title element:** `<title>` is generic ("Crate & Barrel") and doesn't match the subject.

## 4. Personalization & Merge Tokens
No issues found. No unresolved tokens (`{{ }}`, `%%…%%`, `[FIRST_NAME]`) appear in the visible source. The source is truncated, so the full body was not checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` not found:** the QA check notes the header "may not be captured by AgentMail relay". This is unconfirmed, and the sender may well send it.
- **`List-Unsubscribe-Post` not found (RFC 8058):** same caveat. Gmail and Yahoo require one-click unsubscribe for bulk senders, so verify it on the original message.
- **`Authentication-Results` not found:** SPF, DKIM and DMARC status is unknown. The cause is the relay, not evidence of a failure. The From domain `mail.crateandbarrel.com` is a dedicated subdomain and aligns with the image host `image.mail.crateandbarrel.com`.
- **Footer unverified:** the physical address and in-body unsubscribe link are not in the truncated source, so they cannot be confirmed.
- **Plain-text part is mostly URLs:** 21,315 of 29,392 characters (72.5%) are URLs, over the 70% threshold. The long tracking URLs dominate the text part, which can raise spam-filter scores and makes it hard to read.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
No confirmed issues. All 108 destinations are wrapped in tracking redirects that were not probed, so UTM parameters, landing-page status and campaign-to-page alignment are unverifiable from the available data.

## 7. Recommendations
1. Add descriptive `alt` to all content images (the ~46 `image.mail…/m/1/*.jpg` and scene7 hero images). Set `alt=""` on spacers and on pixels (`o.gif`, `448796.gif`, `f3c0d22992a01946.png`).
2. Remove `maximum-scale=1` from the viewport meta.
3. Escape the title as `Crate &amp; Barrel`, and remove the duplicate `charset` and `format-detection` metas and the leftover template comment.
4. Remove the five duplicate `sr.rlcdn.com/448796.gif` pixels, or consolidate them into one.
5. Check the raw message headers for `List-Unsubscribe`, `List-Unsubscribe-Post: List-Unsubscribe=One-Click`, and SPF/DKIM/DMARC `Authentication-Results`. Don't treat the relay warnings as sender defects until you have.
6. Resolve a sample of the tracking redirects with a real follow-through (not an HTTP HEAD probe) to confirm the final URLs and UTM parameters.
7. Shorten the plain-text part, for example by using shorter redirect URLs or fewer links, to get the URL share below 70%.
