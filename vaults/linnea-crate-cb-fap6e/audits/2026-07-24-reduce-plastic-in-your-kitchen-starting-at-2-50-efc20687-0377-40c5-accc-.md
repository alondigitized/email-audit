### 3. Rendering & Accessibility

**[HIGH] Conflicting `img` max-width media queries — dead rule**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
The `640px` query is declared *after* the `768px` query. At viewport widths ≥ 768px both match; the later declaration wins, making `max-width: 600px` unreachable. The `768px` rule is dead CSS. Either reverse the order or use `min-width: 768px` / `max-width: 767px` pairing.

**[HIGH] `maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Disables pinch-to-zoom. Violates WCAG 1.4.4 (Resize Text). Remove `maximum-scale=1`.

**[MEDIUM] `-webkit-text-size-adjust: none` on universal selector**
```css
* { -webkit-text-size-adjust: none; ... }
```
The `body` rule correctly sets `100%`, but the wildcard `*` selector overrides it on all child elements, suppressing mobile text scaling entirely. Change to `-webkit-text-size-adjust: 100%` on `*`, or remove it from `*` and rely on the `body` rule.

**[MEDIUM] `line-height: 100%` on universal selector**
```css
* { line-height: 100% }
```
A unitless `100%` line-height equals `1em`, which clips descenders on large fonts in some clients. Prefer `line-height: normal` on `*` and set explicit values per element.

**[LOW] Duplicate `format-detection` meta tags** — declared four times (once combined, then three individual). Redundant but harmless; clean up to one declaration:
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
```
