# 400+ NEW DEALS ADDED! Up to 60% off The Memorial Day Event + Earn 2x Rewards
**Score:** 7/10 · **Type:** Email audit · **2026-05-21**
## Executive summary

- This is Crate & Barrel's "deal refresh" email — the "we added more items" move designed to re-engage subscribers who already saw the initial Memorial Day blast. The hook is smart in theory: "400+ NEW DEALS ADDED" signals newness and gives a fatigued subscriber a reason to open again. But the execution undercuts it. The body reads as a catch-all category dump — cookware, rugs, furniture, bedding — with no editorial throughline and no clear answer to "what specifically is new vs. what was already on sale?" The campaign is now at least seven emails deep in three days, and that frequency is working against the brand.
- The visual presentation is clean and competent: no render bugs, strong product photography, consistent brand color usage. But competent layout can't compensate for message blur at this stage of a heavy-rotation campaign. A subscriber who already bought in on sofas or rugs has no reason to click back through a generic grid.
- Verdict: mechanically fine send; strategically an over-reach on an already exhausted list.

## What's working

- **"400+ NEW DEALS ADDED" hero headline** is the single strongest creative choice — it creates a reason to re-engage beyond just restating the same sale
- **Product photography is high-quality** — the cookware, rugs, and furniture shots are aspirational and on-brand
- **Up to 60% off** is a concrete, anchored discount that's visible in the hero without scrolling
- **Clear visual hierarchy** — the hero leads the eye, product tiles follow in a logical grid
- **No render bugs** — clean layout, no broken images, no overlapping text

## What's weak

- **Subject ALL-CAPS spam signal** — "400+ NEW DEALS ADDED!" uses both caps and an exclamation mark, which looks aggressive in-inbox and burns goodwill
- **Category scatter** — cookware, rugs, sofas, bedding, and serveware all appear with equal weight; no single category is elevated as "what's new"
- **2x Rewards not visible in the hero body** — it's in the subject line but the in-email rewards mention is buried lower, diluting the loyalty hook for people who skim
- **Cadence fatigue is real** — this is the seventh Memorial Day email in roughly 72 hours; the "new deals" framing doesn't feel credible when the sale has been running this long
- **No deadline or end-date visible** — Memorial Day is the implied deadline but no explicit "ends Monday" language creates urgency

## Recommendations

- 1. **Anchor one "new" category hero** — pick the single highest-demand category added to the sale (e.g., outdoor, bedding) and make that the exclusive hero message. "Bedding just joined the sale" converts better than 400 undifferentiated items.
- 2. **Remove the ALL CAPS from the subject** — "400+ new deals added" in sentence case reads as a human message, not a blast
- 3. **Add explicit deadline copy in the hero** — "Ends Monday" above or below the CTA button converts fatigued subscribers who need a push
- 4. **Surface 2x Rewards in the hero block** — not just the footer or subject; a "Members earn double through Monday" line under the CTA is a loyalty trigger worth repeating
- 5. **Reduce category tiles to 3 max** — a grid of 6+ categories reads as a catalog, not a curated recommendation
- **Subject Alt A:** `New items just added: up to 60% off through Memorial Day`
- **Subject Alt B:** `Bedding & rugs just joined the sale — up to 60% off`
- **Preheader Alt A:** `Ends Monday — earn double rewards on everything`
- **Preheader Alt B:** `400+ items added, including [category] — see what's new`

### 3. Rendering & Accessibility

**[HIGH] Global `text-size-adjust: none` applied via wildcard selector**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; ... }
```
Disabling text-size adjustment on `*` (not just `body`) overrides user agent accessibility preferences globally. WCAG 1.4.4 violation risk. Should be scoped to `body` only.

**[MEDIUM] `maximum-scale=1` in viewport meta blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-zoom on mobile. WCAG 1.4.4 (Resize Text) failure on iOS. Remove `maximum-scale=1`.

**[MEDIUM] Dark mode explicitly suppressed**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Forces light rendering in Apple Mail and other dark-mode-capable clients. If the email's images have transparent backgrounds or hard-coded light backgrounds, this is correct — but it should be intentional and documented, not a default. No dark mode fallback CSS is present.

**[MEDIUM] Conflicting image `max-width` breakpoints**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
At viewport ≥768px, the 600px rule overrides the 640px rule due to cascade order (768px block appears last). Images are constrained to 600px on desktop despite the container apparently being 640px wide. Either consolidate to a single breakpoint or reorder so the more-specific rule wins.

**[LOW] Global `line-height: 100%`**
```css
* { line-height: 100%; }
```
`100%` on `*` computes relative to font-size, which is fine for text but can collapse spacing on elements with no font-size set. Scope this to `td, p, span` instead.

**[LOW] Duplicate `<meta charset>` declarations**
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta charset="utf-8">
```
Both are present — redundant but not harmful. Keep only `<meta charset="utf-8">`.

**[LOW] Triplicate `format-detection` tags**
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
The first tag already covers all values. The three subsequent tags are redundant template artifacts. Remove lines 2–4.
