- **Sustainability angle is asserted, not proven:** The subject promises a "reduce plastic" angle but from the render it's unclear whether the framing carries through with meaningful callouts (material specs, plastic-saved claims, certifications) or just vague product photos.

### 3. Rendering & Accessibility

**`maximum-scale=1` in viewport meta** — prevents pinch-to-zoom on mobile. Violates WCAG 1.4.4 (Resize Text, AA). Evidence:
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

**Universal selector text-size-adjust disabled** — `*{-webkit-text-size-adjust:none;-ms-text-size-adjust:none;}` suppresses OS-level font scaling for all elements, compounding the zoom issue for low-vision users.

**Conflicting image `max-width` media queries** — the 768px breakpoint fires _after_ the 640px one, silently capping images at 600px on screens ≥768px (smaller than the 640px cap below it):
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
Cascade order should be largest-breakpoint-last, or the 768px rule should be removed/merged.

**Duplicate `format-detection` meta tags** — `format-detection` appears four times across two separate `<meta>` declarations with overlapping/redundant attributes. Not harmful but indicates sloppy template hygiene.

**Duplicate charset declaration** — `Content-Type` http-equiv and bare `charset="utf-8"` both present; redundant but harmless.

**`color-scheme: light` / `supported-color-schemes: light`** — hard-coded to light mode. Dark mode inboxes (Apple Mail, Gmail app on iOS) will render with no dark-mode adaptation. Flag if dark-mode support is a requirement.
