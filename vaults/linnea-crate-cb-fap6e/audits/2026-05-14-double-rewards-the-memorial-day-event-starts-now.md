# Double Rewards & The Memorial Day Event starts…NOW!
**Score:** 7/10 · **Type:** Email audit · **2026-05-14**
## Executive summary

- This is a competently produced loyalty + sale email from Crate & Barrel riding the Memorial Day window. The central mechanic — Double Rewards — is a smart hook for members because it reframes spending as earning rather than discounting. The email leans heavily into aspirational lifestyle photography across living, dining, and outdoor categories, which is C&B's brand bread-and-butter and executed cleanly here.
- The problem is breadth: the email tries to be everything at once — sofas, outdoor, dining, entertaining, food styling — and lands as a catalog blast rather than a curated event. The "starts NOW" urgency in the subject competes with the leisurely pace of the body, where there's no countdown, no hard-end date visible in the hero, and no single destination to anchor the click. You're invited to a party but handed a 40-room map at the door.
- Verdict: a solid mid-tier loyalty send. Members with recent C&B purchase intent will find it useful. Everyone else will appreciate the photography and close the tab.

## What's working

- **Double Rewards is front and center** — the loyalty mechanic is the hero, not buried in fine print. That's the right call; members will feel seen.
- **Photography quality is excellent** — room vignettes are aspirational but livable, consistent with the brand. No mismatched stock art.
- **Memorial Day timing is on-point** — outdoor and entertaining sections feel seasonally appropriate, not repurposed evergreen content.
- **Clean render** — no broken images, no overlapping text, no lorem ipsum visible anywhere in the scroll.
- **Multiple category entry points** — living, outdoor, dining are all represented, which broadens relevance across a diverse subscriber base.

## What's weak

- **No hard deadline visible in the body** — "starts NOW" promises urgency but the email never closes the loop with an end date or countdown; the event end is invisible.
- **CTA copy is generic throughout** — every button appears to be "Shop Now" or equivalent. None are tied to the specific category they're sitting below.
- **No single hero product** — the email is a grid of many rooms and categories; there's no one thing to want. Desire diffuses fast when everything is featured equally.
- **Double Rewards mechanics unexplained** — the offer is prominent but the email doesn't answer "double of what?" or "how long?" for non-power members who don't know the base earn rate.
- **No social proof** — no ratings, no "top seller" badges, no review counts on any featured product.

## Recommendations

- 1. **Add a hard end date to the hero** — "Earn Double Rewards through May 26" closes the urgency loop the subject line opens. Without it, "starts NOW" reads as hype.
- 2. **Make CTA copy category-specific** — swap "Shop Now" for "Shop Outdoor Furniture," "Shop Dining," etc. Specificity lifts click rate; generic verbs waste the context built by the surrounding image.
- 3. **Pick one hero product** — lead with a single aspirational piece (e.g., the sectional or the outdoor lounge set) and link directly to its PDP. Let the rest of the email support, not compete.
- 4. **Explain the Double Rewards rate** — one line: "Base 10 pts/$ → 20 pts/$ through May 26" tells members exactly what they're getting and gives non-members a reason to sign up.
- 5. **Add a "Best Sellers" social-proof rail** — even star ratings on 3-4 featured items would meaningfully reduce purchase hesitation.

- **Subject Alt B:** `Your rewards just doubled — shop the Memorial Day Event`
- **Preheader Alt A:** `Double points on furniture, outdoor, dining & more through May 26.`
- **Preheader Alt B:** `Shop now and earn 2× rewards — event ends Monday.`

### 3. Rendering & Accessibility

**[HIGH] Inverted image `max-width` breakpoints**
Two desktop media queries fire in sequence:
```css
@media only screen and (min-width: 640px) { img { max-width: 640px } }
@media only screen and (min-width: 768px) { img { max-width: 600px } }
```
At viewports ≥ 768px both rules apply; the 768px rule (declared later) wins, capping images at **600px on larger screens but 640px on smaller ones**. If the container is 600px this is harmless, but the ordering means images are allowed to be wider on a narrower viewport than on a wider one — likely unintentional.

**[MEDIUM] `maximum-scale=1` blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from zooming in on text, which fails WCAG 1.4.4 (Resize Text, Level AA).

**[MEDIUM] Wildcard `-webkit-text-size-adjust: none` overrides body**
```css
* { -webkit-text-size-adjust: none; ... }
body { -webkit-text-size-adjust: 100%; }
```
The `*` rule sets `none` on all child elements; `body`'s `100%` only applies to the `body` selector itself. All descendant elements inherit `none`, suppressing WebKit's automatic text size adjustment.

**[LOW] Unfilled font import placeholder left in send**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
Template comment with a typo ("IMPUT") shipped in the rendered HTML. No functional breakage, but exposes the ESP template structure.

**[LOW] Duplicate `format-detection` meta tags**
Four `format-detection` declarations appear: one combined and three individual (`date=no`, `address=no`, `telephone=no`). Redundant — only one combined declaration is needed.

**[LOW] Bare `&` in `<title>`**
```html
<title>Crate & Barrel</title>
```
`&` should be encoded as `&amp;` per XHTML rules. Most parsers handle this gracefully, but it is technically malformed.
