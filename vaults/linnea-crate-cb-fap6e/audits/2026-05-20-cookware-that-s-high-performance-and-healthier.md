### 3. Rendering & Accessibility

**Issue 3a — `maximum-scale=1` blocks user zoom (WCAG 1.4.4)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users with low vision from pinch-zooming. Remove `maximum-scale=1` or replace with `maximum-scale=5`.

**Issue 3b — Global `-webkit-text-size-adjust:none` overrides system accessibility settings**
```css
* { -webkit-text-size-adjust:none; -ms-text-size-adjust:none; ... }
```
Applied to the wildcard selector, this overrides user/OS font size preferences. Should be scoped to `body` only, and the value should be `100%` (not `none`).

**Issue 3c — Conflicting desktop image `max-width` media queries**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
Both queries match at ≥768px. Because the `640px` query appears later in the stylesheet it wins the cascade, capping images at 640px on desktop — the `600px` rule is dead. Either reorder (768px last) or consolidate into one rule.

**Issue 3d — No dark mode support**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Dark mode is explicitly disabled. Apple Mail, Outlook, and Gmail dark-mode users will see the forced light background without any adaptation. At minimum, add a `@media (prefers-color-scheme: dark)` block or change the value to `light dark`.

**Issue 3e — Duplicate `format-detection` meta tags**
The same directives appear in a combined tag and then repeated individually:
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
Not a rendering breakage, but indicates template debt — three of the four directives are duplicated.
