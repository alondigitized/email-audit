# Last chance! Up to 30% off bestselling furniture + 2x Rewards ends TOMORROW!
**Score:** 7/10 · **Type:** Email audit · **2026-05-25**
## Executive summary

- This is the "last chance" closer on Crate & Barrel's Memorial Day furniture push — and the most confusing version of it yet. The subject promises "up to 30% off bestselling furniture," but five days ago Crate & Barrel was advertising up to 60% off and 35% off brand-name kitchen electrics. Running a lower headline discount on the final-day urgency email is backwards psychology: the subscriber who's been watching all week will wonder if they missed the real sale. The 2x Rewards mechanic sits only in the subject line — it never gets amplified in the hero block where it belongs.
- The email body itself is structurally fine: the Memorial Day hero leads, a product grid follows, lifestyle imagery fills the middle. But then The Design Desk — a free interior design service pitch — intrudes mid-scroll, fragmenting what should be a tight sale-close into two separate asks. On the last day of a sale, you want one funnel, not a fork.
- The net read: technically competent, strategically muddled. A subscriber who missed earlier sends sees a decent furniture sale email. A subscriber who's been engaged all week sees a step-down offer with mixed signals on the final push.

## What's working

- Clear brand identity and consistent Crate & Barrel visual language throughout.
- Memorial Day context is legible immediately — no ambiguity about the campaign hook.
- Product grid gives concrete furniture examples with visible pricing, which is better than a pure lifestyle-only send.
- "Shop" CTA appears in the hero without fighting for attention.
- Lifestyle imagery of a styled living room is aspirational and on-brand.

## What's weak

- "Up to 30% off" as the last-chance headline is a step down from "up to 60% off" (5/24 Crate & Barrel send) — creates subscriber confusion about what the actual offer has been all week.
- 2x Rewards is buried in the subject but doesn't appear as a visible, prominent promise in the email body hero.
- The Design Desk free-design-service block mid-email hijacks a sale-close with a service pitch — two competing asks dilute both.
- Subject line is 76 characters — far over the mobile-friendly ~50-char threshold; likely truncated in most inboxes.
- "Last chance!" + "TOMORROW!" stacks urgency signals that, by day five of the same campaign, read as cry-wolf rather than credible deadline.

## Recommendations

- 1. **Restore the stronger discount framing.** If the actual sale cap is 30% for "bestselling" vs. 60% for clearance, lead with the category distinction — not a smaller number with no explanation. "Our most-wanted pieces — now 30% off" frames it correctly rather than looking like a downgrade.
- 2. **Bring 2x Rewards into the hero block.** The loyalty kicker is the differentiator for members; it should appear as a visual badge or callout directly under the hero image, not only in a 76-char subject line.
- 3. **Cut The Design Desk from this send.** Last-day close emails should have zero competing CTAs. Move the Design Desk to a standalone send or a post-purchase follow-up.
- 4. **Trim and restructure the subject.** The current structure tries to do everything; split the load.
- **Subject Alt A:** `Last chance: 30% off our bestselling furniture`
- **Subject Alt B:** `Sale ends tonight — shop our most-wanted pieces`
- **Preheader Alt A:** `Plus earn Double Rewards on every purchase through midnight.`
- **Preheader Alt B:** `Double Rewards + up to 30% off — this is the final day.`

### 3. Rendering & Accessibility

**`maximum-scale=1` blocks zoom (WCAG 1.4.4 violation)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from scaling text, breaking accessibility for low-vision readers. Remove `maximum-scale=1`.

**Global `-webkit-text-size-adjust:none` via wildcard selector**
```css
* { -webkit-text-size-adjust: none; ... }
```
Applied to every element. The safe pattern is `body { -webkit-text-size-adjust: 100%; }`. The `none` value on `*` suppresses iOS auto-sizing entirely, which can make small text unreadable without the ability to zoom (compounded by the above).

**Global `line-height: 100%` via wildcard selector**
```css
* { line-height: 100%; ... }
```
Sets line-height to 1.0× font-size on every element. For body-copy paragraphs this is below the WCAG 1.4.12 minimum of 1.5×. Requires element-level overrides throughout, and any missed elements will render with cramped leading.

**Conflicting image `max-width` media queries**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
The 640px rule is declared after the 768px rule. At viewport widths ≥ 768px both queries match; cascade order means `max-width: 640px` wins, overriding the intended 600px desktop constraint. Swap declaration order or use a `min-width: 768px` / `max-width: 767px` split.

**Duplicate `format-detection` meta tags**
Three separate `<meta name="format-detection">` tags declare overlapping values (`telephone=no` appears twice, `address=no` twice). Consolidate to one: `content="telephone=no,address=no,email=no,date=no,url=no"`. Harmless but indicates template hygiene gap.

**No dark mode declared despite `color-scheme` meta**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Explicitly locks to light mode — acceptable if intentional. If the design was tested only in light mode, this is correct; if dark-mode rendering was expected, the CSS media query (`prefers-color-scheme: dark`) is absent.
