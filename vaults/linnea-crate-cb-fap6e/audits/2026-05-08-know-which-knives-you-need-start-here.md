# Know which knives you need? Start here →
**Score:** 8/10 · **Type:** Email audit · **2026-05-08**
## Executive summary

- This is a content-marketing editorial from Crate & Barrel — a knife-selection guide designed to educate rather than convert on a discount. The design is clean, the subject question is genuinely useful, and the product-education format gives browsers a reason to click. The main weakness: there is no price offer, no urgency, and no visible loyalty hook, which caps click motivation for anything beyond casual browsing. For a kitchen-curious persona this is a solid, trustworthy send — just don't expect conversion numbers a promo email would hit.

## What's working

- **Subject question hooks immediately.** "Know which knives you need? Start here →" is conversational and self-selecting — people who don't know raise their hand and open it.
- **Editorial structure earns trust.** Multiple knife-type sections (appears to cover chef's, bread, paring, shears, etc.) position C&B as an authority, not just a retailer.
- **Visual density is well-managed.** Each knife gets its own image tile with supporting copy; the grid doesn't feel cluttered.
- **Brand aesthetic is consistent.** White backgrounds, tight typography, professional product photography — unmistakably C&B.
- **Lower-funnel hook near the bottom.** The email appears to widen into complementary home-goods categories, giving cross-sell surface without distracting from the knife guide upfront.

## What's weak

- **No price signal anywhere.** Without a MSRP, sale price, or even a "from $X" anchor, click motivation is curiosity-only — the highest-intent shoppers need a reason to act now.
- **No urgency mechanism.** Nothing timed, no inventory signal, no event tie-in (e.g., Mother's Day gifting, which is days away as of this send).
- **Multiple products dilute focus.** Showing every knife type in one send is comprehensive but unfocused — a single hero knife with deep editorial (specs, use case, comparison) would drive stronger single-click conversion.
- **Cross-sell at the bottom feels disconnected.** The home-goods modules (vases, tabletop items) late in the scroll aren't bridged by any editorial logic — they read as padding.
- **No social proof.** No star ratings, no "bestseller" badge, no number-of-reviews visible. For a high-consideration category like cutlery, this is a missed opportunity.

## Recommendations

- 1. **Tie to Mother's Day — it's right now.** A single line — "Still searching for a Mother's Day gift? These last." — would convert this from evergreen content into a timely send without rebuilding the email.
- 2. **Anchor one hero knife with a price.** Even "$79" next to the chef's knife gives the browser a concrete decision point and lifts click intent significantly.
- 3. **Add a "bestseller" badge or review count** to two or three knife tiles. This is the highest-ROI trust signal for cutlery purchases.
- 4. **Cut or contextualize the cross-sell modules.** Either drop the non-knife bottom section or bridge it with copy ("Complete the block with these") so it reads as intentional, not filler.
- 5. **A/B a version with urgency copy.** "Ships in time for Sunday" or "Order by [date]" in the hero would test whether this educational audience also responds to deadline framing.

### 3. Rendering & Accessibility

**Conflicting desktop image max-width rules (confirmed bug):**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
At viewports ≥768px, both queries match. The `640px` rule appears later in the stylesheet and wins by cascade, making the `600px` rule unreachable. Images will cap at 640px on all screens ≥640px. If the intent was 600px on large screens, the rule order must be reversed or the 768px block must use `min-width: 641px`.

**`maximum-scale=1` in viewport meta blocks user zoom:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Preventing zoom fails WCAG 2.1 SC 1.4.4 (Resize Text). Remove `maximum-scale=1`.

**Overly broad `-webkit-text-size-adjust: none`:**
```css
* { -webkit-text-size-adjust: none; }
```
Applied to every element, this disables system-level text scaling on iOS/Safari for users with accessibility settings enabled. Scope this to `body` only, or use `100%` instead of `none`.

**Duplicate `format-detection` meta tags (3 redundant declarations):**
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
Lines 2–4 are fully covered by line 1. Remove the duplicates.

**No dark mode declarations:**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Dark mode is explicitly disabled. Apple Mail, Gmail app, and Outlook 2019+ will force-invert unless `light dark` is declared and a `@media (prefers-color-scheme: dark)` block is provided. Acceptable if intentional; flag for stakeholder sign-off.
