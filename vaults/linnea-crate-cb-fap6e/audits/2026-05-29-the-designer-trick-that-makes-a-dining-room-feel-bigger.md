### 3. Rendering & Accessibility

**Conflicting image `max-width` media queries** — two overlapping rules are declared in the wrong order:

```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }  /* declared after → wins at ≥768px too */
```

At viewport widths ≥768px the `640px` rule wins because it is declared last, overriding the intended `600px` cap. The `768px` breakpoint is effectively dead.

**`maximum-scale=1` on viewport** — `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` blocks user pinch-zoom. WCAG 1.4.4 (Resize Text) requires content to be zoomable to 200%; this attribute prevents it on iOS Safari.

**Aggressive global `line-height`** — `* { line-height: 100% }` in the MI base styles applies to every element including block containers. This overrides per-element line-height and can cause tightly stacked or illegible text blocks. Line-height should be set per component, not via a universal selector.

**Light-mode only** — `<meta name="color-scheme" content="light">` and `<meta name="supported-color-schemes" content="light">` suppress dark-mode rendering. No `@media (prefers-color-scheme: dark)` block is present. Images with white backgrounds will look correct, but forced-light suppresses the OS-level dark adaptation that many Apple Mail users rely on.

**Duplicate/redundant meta declarations:**
- `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` and `<meta charset="utf-8">` both declare charset — redundant but harmless.
- `format-detection` is declared **four times** (once as a combined value, then three individual attributes). Only the first occurrence is parsed by most clients; the rest are noise.
