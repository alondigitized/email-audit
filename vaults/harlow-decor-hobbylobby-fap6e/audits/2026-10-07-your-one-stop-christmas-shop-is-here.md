## Technical Audit

## 1. Technical Summary
The email's markup is mostly standard ESP-generated table HTML, but the CSS has several malformed declarations and a very narrow responsive breakpoint. The QA run produced 4 warnings and 0 hard failures. Two of the warnings (missing auth headers and missing List-Unsubscribe) come from the AgentMail relay and can't be confirmed as sender defects. The HTML source was truncated, so footer and body checks are limited.

## 2. Link & Tracking Issues
- **Plain-text URL density:** 15,071 of 17,971 plain-text characters (about 84%) are URLs, over the 70% threshold. This points to long tracked redirect URLs on `link.hobbylobby.com` dominating the text part. It can raise spam-filter scoring and makes the text version hard to read.
- **Probe coverage is partial:** 12 material links were probed and 40 were skipped, so link health is unverified for most of the email. The QA data shows no failures among the probed links.
- **Tracking domain:** The tracking and image host is `link.hobbylobby.com`, a branded subdomain of the sending brand. That is good for reputation, with no mismatch seen.

## 3. Rendering & Accessibility
- **Missing alt text:** `https://link.hobbylobby.com/mo/eORqXTkAb7_837015858_139077_697445_148456.gif` has no `alt`. The `/mo/` path and the `.gif` extension suggest an open-tracking pixel, which would make this low impact. Even so, it should carry `alt=""` so screen readers skip it. If it is actually content, it needs descriptive alt text.
- **Invalid CSS in the `<style>` block:**
  - `.lhp2 {... verticl-align:middle;}` is a typo for `vertical-align`, so the declaration is ignored.
  - `.ctacr1 {color:; ... -moz-border-radius:px; -webkit-border-radius:px; border-radius:px;}` has empty values. The CTA gets no text color or border radius from this class and falls back to inherited values.
  - `.ctacr1` also declares `background-color:#013088` with `color:` empty, so text contrast depends on inheritance.
- **Responsive breakpoint:** `@media only screen and (max-width:300px)` is visible in the source. Almost no phone viewport is that narrow, so the stacking rules (`.fl`, `.fw`, `.image`, and so on) likely never fire on mobile. The source was truncated, so a later, wider breakpoint may exist. If not, the email renders at desktop width on phones.
- **Viewport meta:** `content="initial-scale=1, user-scalable=yes"` omits `width=device-width`. This is minor given the breakpoint issue.
- **Doctype and namespaces:** The doctype is HTML 4.01 Transitional, but the `<html>` tag carries `xmlns` attributes and a non-standard `e-locale` attribute. It is harmless in practice.
- **Outlook (MSO) handling:** Conditional comments are present and well-formed, with `OfficeDocumentSettings` and table resets. No issues found there.

## 4. Personalization & Merge Tokens
No issues found. The visible source shows no unrendered tokens (`{{ }}`, `%%`, `[[ ]]`). The footer was truncated, so it was not checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe not found:** The QA tool flagged this as possibly not captured by the AgentMail relay, so it can't be confirmed as a sender omission. The audit mailbox should verify it against the raw message headers.
- **List-Unsubscribe-Post (RFC 8058) not found:** The same caveat applies. If the header really is absent, Gmail and Yahoo's bulk-sender rules require one-click unsubscribe, and `noreply@create.hobbylobby.com` is clearly a bulk sender.
- **Authentication-Results not found:** SPF, DKIM and DMARC status is unknown. This is expected via the relay and can't be judged from this data.
- **Unsubscribe link and physical address:** The QA note says an unsubscribe link is always probed, and no failure was reported. The postal address couldn't be confirmed because the source is truncated.
- **From address:** `noreply@create.hobbylobby.com` is a no-reply address on a subdomain. It is not a violation, but replies are unmonitored.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- UTM parameters and final landing URLs couldn't be verified. Links route through the `link.hobbylobby.com` redirect tracker, and the redirect chains weren't exposed in the QA data. No broken or mismatched destinations were reported among the 12 probed links.
- Landing-page alignment with the "One-Stop Christmas Shop" subject can't be assessed from the available data.

## 7. Recommendations
1. Fix the CSS typos and empty values: `verticl-align` → `vertical-align`, and give `.ctacr1` explicit `color` and `border-radius` values.
2. Add a real mobile breakpoint, such as `max-width:480px` or `600px`. Add `width=device-width` to the viewport meta.
3. Add `alt=""` to the tracking GIF, or descriptive alt text if it is content.
4. Check the raw headers for `List-Unsubscribe` and `List-Unsubscribe-Post`, and for SPF, DKIM and DMARC results. Don't treat these as sender defects until confirmed.
5. Shorten or reduce the tracked URLs in the plain-text part, or use fewer links, to bring URL density under 70%.
6. Re-run the audit with the untruncated HTML and a higher probe limit, so the footer, UTM parameters and redirect destinations can be checked.
