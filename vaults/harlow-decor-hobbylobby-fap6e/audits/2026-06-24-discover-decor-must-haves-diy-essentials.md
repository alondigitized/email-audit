# Discover Decor Must-Haves & DIY Essentials
**Score:** 7/10 · **Type:** Email audit · **2026-06-24**
## Executive summary

- This is Hobby Lobby's generic weekly circular format — the same product-tile grid stacked top to bottom that appeared in the June 18 "Up To 75% Off" and June 21 "Hello Summer" sends. The subject promises curated focus ("Decor Must-Haves & DIY Essentials") but the email delivers an assortment that spans charger plates, foam bricks, a balloon helium tank, glue guns, AA batteries, and iron-on vinyl. That's not a curated decor send — it's a clearance shelf photo dump.
- The email's core claim is "New Lower Prices!" displayed in red above the product grid. No comparison prices are shown, no original price crossed out — so the claim lands as unsupported assertion rather than a compelling offer. "We give you our best price everyday" in the same breath undercuts any urgency: if the price is always best, why act now?
- The cadence context makes this worse. This is the seventh email from Hobby Lobby in nine days. A subscriber who's already seen the Spring Shop 50% off on June 17, June 21's "Hello Summer" mega-digest, and June 23's "Add A Burst Of Color" send has little reason to treat this differently. This one will blur into the noise.

## What's working

- **Free shipping threshold is visible upfront** — "$59 or More" is a clear, actionable offer at the top.
- **Clean product photography** — individual product tiles are legible, consistently lit, and show price prominently.
- **No render bugs** — the grid renders without broken images, overlapping text, or layout collapse.
- **Subject stays under 50 chars** — "Discover Decor Must-Haves & DIY Essentials" (42 chars) is mobile-friendly.
- **Prices are honest and direct** — no fine print asterisks, no "up to X% off" bait without specifics; every item has an actual dollar price.

## What's weak

- **Subject promise vs. email reality mismatch** — "Decor Must-Haves" implies curation; a helium balloon tank and AA batteries do not say "decor."
- **"New Lower Prices!" is a hollow claim** — no before/after price is shown, so there's nothing to validate it against.
- **Zero visual hierarchy below the banner** — every product tile is the same size, same weight; the eye has no anchor point.
- **CTA is a detour, not a destination** — "Click Here to View Our Weekly Ad" sends the reader away from the email to a separate ad view, adding friction with no payoff.
- **Cadence fatigue is real** — at seven emails in nine days, each without meaningful differentiation, a subscriber is primed to skip-and-unsubscribe.

## Recommendations

- 1. **Lead with one hero product and a specific, verifiable discount.** Pick the single best "New Lower Price" item in the decor category — say the Grapevine Wreath at $4.99 — show the old price struck through, and make that the hero. Everything else is secondary.
- 2. **Validate "New Lower Prices!" with at least one before/after price pair** — even one crossed-out original price turns an assertion into proof.
- 3. **Replace the "View Our Weekly Ad" CTA** with a direct "Shop Decor Deals" button that lands on a filtered category page, not a print-circular viewer.
- 4. **Cut the product count in half** — 20 tiles is a browse session, not an email. Eight tightly curated items converts better.
- 5. **Rethink cadence** — a subscriber who already opened the June 23 Spring Shop email does not need another promo 24 hours later with the same template.

### 3. Rendering & Accessibility

**Three confirmed CSS defects in the `<style>` block:**

**a) Malformed border-radius on `.ctacr1` (CTA button)**
```css
.ctacr1 {
  -moz-border-radius:px;      /* ← missing number */
  -webkit-border-radius:px;   /* ← missing number */
  border-radius:px;           /* ← missing number */
}
```
All three declarations are invalid and silently dropped. The CTA button will render with square corners in all clients regardless of intended design.

**b) Empty `color` property on `.ctacr1`**
```css
.ctacr1 { color:; ... }
```
Invalid value — property is ignored. Button text color falls through to inherited/default value, which is unpredictable across clients.

**c) Typo in `.lhp2`**
```css
.lhp2, .lhp2 font { verticl-align:middle; }
/*                   ^^^^^^ missing 'a' */
```
`verticl-align` is not a valid CSS property — silently ignored. Intended vertical centering will not apply.

**d) Responsive breakpoint is non-functional**
```css
@media only screen and (max-width:300px) { ... }
```
Modern smartphones have a minimum viewport width of ~360px (Android) or 375px (iPhone). This breakpoint will **never fire** on any current mobile device. The email has no effective responsive reflow — it will render at full desktop width on all mobile clients that support media queries, requiring horizontal scrolling.

**e) `<meta name="viewport">` missing `width=device-width`**
```html
<meta name="viewport" content="initial-scale=1, user-scalable=yes">
```
Without `width=device-width`, mobile WebKit-based clients (Gmail app, Apple Mail) will not set the viewport to device width. Combined with the broken breakpoint, this compounds mobile rendering failure.

**f) DOCTYPE is HTML 4.01 Transitional**
Industry-standard for legacy email clients; not a defect, but noted.
