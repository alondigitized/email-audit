# For you: code EXTRA20 🥹
**Score:** 9/10 · **Type:** Email audit · **2026-06-12**
## Executive summary

- Carter's returns with the EXTRA20 code three days after the June 9 "EXTRA 20% off 🥳 Code: EXTRA20" send — same code, different emoji, soft "For you" wrapper swapped in to signal freshness. The hero is cleanly executed: teal block, 60% + Extra 20% offer, code front-and-center, single "Shop Now" CTA. Structurally sound. The problem is what follows — the "HANDPICKED FOR YOU" header sits above what's visibly a generic category product grid, and the gap between that promise and that delivery is the loudest single thing in this email.
- The back half stacks three separate content sections (baby essentials editorial, a "TOP TIPS FOR PARENTS" content hub, and a red 70% OFF markdown banner) — creating two competing discount narratives in one send. - The teal hero block is instantly scannable; the offer stacks ("60% off + Extra 20%") register in under two seconds.
- "THE LATEST NEW BABY ESSENTIALS" editorial section adds content equity beyond a pure promo blast.

## What's weak

- "HANDPICKED FOR YOU" headlines a visibly generic product grid — the curation claim collapses on contact with the merch.
- 🥹 (pleading/tearful face) in the subject creates tonal confusion — it reads as neither urgency nor delight for a baby clothing sale.
- The red 70% OFF footer banner introduces a competing offer event with its own visual weight, splitting hierarchy with the hero.
- "Code EXTRA20 today" is a hollow urgency signal for anyone who watched this code run on June 9.
- The "TOP TIPS FOR PARENTS" content block interrupts the purchase funnel between the product grid and the footer CTA.

## Recommendations

- 1. **Make "handpicked" real or kill the label.** Replace "HANDPICKED FOR YOU" with a specific category ("SUMMER OUTFITS UNDER $15" or "NEW ARRIVALS FOR BABY") or surface actual purchase-history-driven picks. The subject sets a personal expectation the body can't cash.
- 2. **Give the two offers a clear hierarchy.** The EXTRA20 code should be the lead; the 70% markdown should be a supporting beat ("AND — new markdowns up to 70% off"). Right now the red footer block reads as a second email inserted inside the first.
- 3. **Address code fatigue.** EXTRA20 was "today" on June 9. Subscribers know. Frame this as an extension ("EXTENDED through Sunday") or swap to a new code. Repeating "today" on a multi-day code erodes trust faster than it creates urgency.
- 4. **Replace 🥹 with an on-emotion emoji.** 🛍️, ☀️, or 🎉 lands better for a summer baby clothing discount than a tearful pleading face.

- **Preheader Alt A:** `Shop the summer styles we picked — plus up to 70% off new markdowns.`

### 2. Link & Tracking Issues

**Dual open-tracking pixels — conflicting attribution**

Two independent open pixels fire on load:
- Attentive: `https://carters.attentivemail.com/ss/o/u001.6x9r1fsrCn5_kOCShC5EZg/4rf/...ho.gif`
- Secondary: `https://mi.carters.com/p/up/745a17bbb73445ad/o.gif?mi_u=1150794179&mi_ecmp=06_12_2026_CAR_FRI_STO_ENGAGERS`

Both pixels count independently, so open rate data will be double-counted in whichever system is not the master. The `mi.carters.com` pixel passes `mi_u=1150794179` — a numeric subscriber identifier — as a plaintext URL parameter. Depending on the platform's data classification, this may constitute transmission of PII in a non-hashed form.

**No standard UTM parameters on any CTA**

All links use Attentive's `ss/c/` click-redirect and append `cm_mmc` (Salesforce Marketing Cloud attribution format), not `utm_source/utm_medium/utm_campaign`. Example from a clearance CTA:

```
https://carters.app.link/PH7Wo9mJBTb?cm_mmc=ec.car.us.purchase.06_12_2026_car_fri_sto_engagers.20260612.campaign.attn.multi..CAR_EVERGREEN_SECONDARY_1_clearance
```

Google Analytics / GA4 will not credit these sessions to the email channel; they will land as direct or unattributed unless a server-side `cm_mmc` → `utm` translation is in place.

**Branch.io app deep links (`carters.app.link`)**

Multiple clearance-section CTAs route through Branch.io short links (`PH7Wo9mJBTb`, `6f5Sy9mJBTb`, etc.) before resolving to the Carter's app. Web-only visitors who don't have the app installed will fall through Branch's deferred deep-link fallback — confirm the fallback URL is the correct `carters.com` page and not the app store root.

**Three empty `<a href>` anchors in the footer (line 170)**

Three consecutive `<a href="...attentivemail.com/ss/c/..."></a>` tags wrap zero visible text. These are tracked redirect links with no label, producing invisible click targets that inflate click counts and are completely inaccessible.

### 3. Rendering & Accessibility

**Empty `<title>` tag**

`<title></title>` is blank. Screen readers (NVDA, JAWS) announce "untitled document." Should be `Carter's — Extra 20% off select styles`.

**Google Fonts loaded via `<link>` in `<head>`**

`League Spartan` is loaded via `<link href="https://fonts.googleapis.com/...">` inside `<!--[if !mso]><!-->`. Gmail (web + Android), Yahoo Mail, and Outlook.com all strip `<head>` `<link>` tags. The fallback stack `font-family:'League Spartan',Arial,sans-serif` is correctly specified inline throughout the body, so rendering will degrade gracefully to Arial — no crisis, but the font will drop silently in the majority of email clients.

**Preheader padding: dual invisible character sets**

The preheader uses ~150 U+034F (Combining Grapheme Joiner) characters followed by ~200 U+00AD (soft hyphen) characters to suppress preview bleed. Functionally effective. This adds approximately 700 bytes of invisible content to raw HTML size.

**`lang="en"`, `role="presentation"`, viewport, Apple/Outlook link overrides** — all present and correct.

### 6. Email-to-Site Continuity

Unless a Salesforce Marketing Cloud connector or GTM variable translates `cm_mmc` into `utm_` parameters client-side, GA4 will count this traffic as direct. Confirm GA4 session attribution for this campaign shows `email` channel before treating open/click data as reliable conversion signal.

The clearance-section CTAs use Branch deep links without a visible `$fallback_url` parameter in the query string. If Branch routes a non-app user to a generic fallback (e.g., the App Store listing), the conversion path breaks entirely for web visitors clicking those buttons.
