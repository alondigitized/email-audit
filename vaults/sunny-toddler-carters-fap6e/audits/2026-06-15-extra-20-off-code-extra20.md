### 3. Rendering & Accessibility

**Google Fonts via `<link>` tag will not render in most email clients.**
The League Spartan import is correctly gated behind `<!--[if !mso]><!-->`...`<!--<![endif]-->` to avoid Outlook errors, but Gmail, Yahoo, and Outlook.com all strip `<link>` tags from email `<head>`. No explicit fallback font stack is declared in the visible CSS. Clients that strip the link will fall back to the browser/OS default (typically Times New Roman or serif), which may break the intended layout.

```html
<link href="https://fonts.googleapis.com/css2?family=League+Spartan:..." rel="stylesheet" type="text/css">
```
**Fix:** Add a safe font stack inline on all text elements, e.g. `font-family: 'League Spartan', Arial, Helvetica, sans-serif`.

**`#MessageViewBody a` suppresses all link decoration:**
```css
#MessageViewBody a { color: inherit; text-decoration: none }
```
This targets the Gmail message body wrapper and removes underlines on every anchor. Functional links will be visually indistinguishable from surrounding text unless explicitly styled with color on the `<a>` element itself. Accessibility risk: fails WCAG 1.4.1 (use of color) if links are not otherwise distinguished.

**Empty `<title>` tag:**
```html
<title></title>
```
Some email clients (notably Apple Mail and Samsung Mail) surface the title in tab/notification UI. An empty title degrades accessibility for screen readers that announce the document title on load.

**Alt text on content images:** Could not verify — image blocks (`row-3`, `row-8`, `row-10`) are in the truncated section.

**Accessibility positives confirmed:**
- `lang="en"` on `<html>` — correct
- `role="presentation"` on all layout tables — correct
- `-webkit-text-size-adjust:none` set intentionally — correct for email
