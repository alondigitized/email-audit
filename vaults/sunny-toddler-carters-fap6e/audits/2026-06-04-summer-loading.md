# Summer loading...
**Score:** 8/10 · **Type:** Email audit · **2026-06-04**
## Executive summary

- "Summer loading..." is the weakest subject Carter's has written this week — a vague ellipsis-teaser hiding a perfectly competent 50%-off send. The email itself is structured fine: a teal hero with a concrete offer, a nine-item product grid, a Skip•Hop cross-brand insert, and a clearance escalation at 70% buried below the fold. The problem is that the 70% clearance — which is the more aggressive ask — is the *second* offer, not the first, and the subject line surfaces neither.
- The Skip•Hop module breaks the week's monotony in a meaningful way. It's the only original structural element in an otherwise paint-by-numbers discount execution that has now run the same 50%-off template, the same teal hero, and the same "summer" hook on at least three of the last seven sends. A subscriber who opened May 28, May 30, and June 2 has already seen this email.
- The clearance section with filterable gender/age tabs is the most actionable thing in the body — but it's positioned last, receives the smallest hero treatment, and is likely to be scrolled past. Flip the order, and this becomes a different email.

## What's working

- **70% clearance tab strip** — gender/age filters (Baby Boy, Toddler Boy, Girl) are a genuine usability win; this is more structured than the usual category grid.
- **Skip•Hop cross-brand module** — the play gym photo and developmental angle ("Encourage Milestones at Play") breaks cadence fatigue and adds perceived value beyond discount.
- **Clean rendering** — no broken images, no layout shifts, no overlapping text across all sections.
- **Carter's Rewards footer** — program logo is present and visible for members.

## What's weak

- **Subject buries the offer entirely** — "Summer loading..." doesn't mention 50% off, clearance, or any specific product; after a week of heavy discounting, this brand has to earn the open.
- **70% off buried below the fold** — the sharper offer is the *third* section down, after the hero and the product grid.
- **Three competing modules with no clear winner** — 50% off summer, Skip•Hop milestones, and 70% clearance each want to be the CTA, and none of them wins.
- **"Shop Now" on the hero is generic** — the button copy doesn't tell the reader *what* they're shopping for; the hero copy does the work, but the CTA doesn't reinforce it.
- **Cadence strain visible** — this is structurally the fourth near-identical summer/discount send this week; there's no new hook to justify sending again.

## Recommendations

- 1. **Lead with the 70% clearance in the hero** — "New Markdowns" signals freshness; the upgrade from 50% to 70% is the story worth telling. Swap module order: clearance hero → product grid → Skip•Hop.
- 2. **Surface the discount in the subject** — "Summer loading..." is a squandered opportunity when you have 50% or 70% off to work with. The subject should carry the number.
- 3. **Sharpen the hero CTA** — change "Shop Now" to "Shop Summer Sale" or "Shop Clearance" so the button earns its real estate.
- 4. **Give the product grid a price anchor** — "MADE FOR EVERY MOMENT" has no offer attached. One line like "From $9.99" or "Under $15" would convert browsers.
- 5. **Differentiate the send if cadence can't slow** — if this email must go out, lead with the Skip•Hop module as the hero variation; it's the one thing subscribers haven't already seen three times.

## Technical Audit — Carter's "Summer loading..." Email

### 1. Technical Summary

The email is built on Attentive's platform using standard MSO/VML conditionals and a 640px fixed container with a 660px responsive breakpoint. One confirmed structural issue (tracking pixel suppressed by its own wrapper) and one typography degradation risk (web font with no verified fallback) are the primary findings.

---

### 2. Link & Tracking Issues

**Open-pixel suppressed by parent `display:none`**

```html
<div class="pixel-wrapper" style="display:none;...max-height:0px;max-width:0px;opacity:0;overflow:hidden;">
  <img src="https://carters.attentivemail.com/ss/o/.../ho.gif" width="1" height="1" ...>
</div>
```

The Attentive open-tracking GIF is nested inside a `display:none` wrapper. In email clients that fully respect CSS visibility (Apple Mail, recent Outlook for Mac), the pixel will not load, resulting in under-reported open rates. The pixel itself is correctly sized to 1×1 with `alt=""`, but the wrapping div negates it in compliant renderers. The pixel should sit in a visible-but-zero-dimension container (e.g., `height:0;overflow:hidden;` without `display:none`) or be placed bare in the `<body>` before the layout table.

**CTA links** — source is truncated; UTM parameters could not be verified (see §6).

---

### 3. Rendering & Accessibility

**Web font loaded but likely to fail silently**

```html
<!--[if !mso]><!-->
<link href="https://fonts.googleapis.com/css2?family=League+Spartan:wght@400;500;600;700&display=swap" ...>
<!--<![endif]-->
```

League Spartan is conditionally loaded for non-Outlook clients, but Gmail (all surfaces), Yahoo Mail, and AOL block external `<link>` requests. If inline styles on headings/CTAs specify `font-family: 'League Spartan', <fallback>` with a web-safe fallback, this is acceptable; if no fallback is defined, those elements will render in the client's default sans-serif with unpredictable sizing. The truncated source prevents confirming fallback declarations — verify all `font-family` rules include a web-safe second value.

**Empty `<title>` tag**

```html
<title></title>
```

Several email clients (Samsung Mail, some Outlook builds) display the `<title>` as the tab or window label. Empty is better than wrong, but a value like `"Carter's Summer Sale"` improves accessibility for screen reader users who navigate by document title.

**MSO conditionals and `role="presentation"`** — correctly applied on all layout tables visible in the source. No issues.

**Responsive breakpoint** — set at `660px`, which is wider than the 640px container. This is intentional (column stacking triggers before the container hits edge), consistent with the builder's pattern. No issue.
