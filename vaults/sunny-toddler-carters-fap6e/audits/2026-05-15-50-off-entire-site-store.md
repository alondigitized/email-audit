- **Two identical "LOWEST PRICES OF THE SEASON" headers** back-to-back looks like a production error.

### 2. Link & Tracking Issues

**[HIGH] Open-tracking pixel suppressed by `display:none` wrapper**

The Attentive open pixel is placed inside a div styled `display:none; max-height:0px; max-width:0px; opacity:0; overflow:hidden;`:

```html
<div class="pixel-wrapper"
     style="display:none;...max-height:0px;max-width:0px;opacity:0;overflow:hidden;">
  <img src="https://carters.attentivemail.com/ss/o/u001.6x9r1fsrCn5_kOCShC5EZg/
             4qn/lHJubJ2pSOCAu942q3ekfQ/ho.gif" ...>
</div>
```

Gmail does not load images inside `display:none` nodes; most other clients behave the same. This will suppress opens across the majority of clients, not just Apple MPP. If the intent is MPP evasion, `display:none` is the wrong mechanism — it also kills real opens. The pixel should be placed in a visible-but-invisible-to-human element (1×1px, absolute positioned, or inline in the body flow).

### 3. Rendering & Accessibility

**[MEDIUM] Global link style reset in Gmail**

```css
#MessageViewBody a { color: inherit; text-decoration: none }
```

This strips color and underline from every `<a>` in the Gmail-rendered view. If in-email link styles do not explicitly re-declare color and decoration, links are visually indistinguishable from body text for sighted users and may confuse screen-reader heuristics that rely on decoration cues.

**[LOW] Google Fonts `<link>` loaded unconditionally for non-MSO clients**

```html
<!--[if !mso]><!--><link href="https://fonts.googleapis.com/css2?family=League+Spartan..."><!--<![endif]-->
```

MSO guard is correct. However, corporate proxies and some privacy-focused clients (Hey, Fastmail) block third-party font requests. Fallback `font-family` stack in the CSS could not be verified due to truncation — confirm a safe-serif/sans-serif fallback is declared.

**[LOW] Preheader padding uses mixed Unicode whitespace**

Preheader uses both U+034F (Combining Grapheme Joiner `͏`) and soft-hyphen (`­`) sequences. This is a common technique, but Apple Mail on macOS 14+ has been observed rendering soft hyphens as visible dashes in some build configurations. Monitor rendering on Apple Mail 16+.
