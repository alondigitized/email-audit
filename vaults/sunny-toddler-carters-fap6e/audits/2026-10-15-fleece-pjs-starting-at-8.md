## Technical Audit

## 1. Technical Summary
The HTML is a standard responsive table build with a hidden preheader, MSO conditionals, and a mobile media query at 660px. The QA run flags 11 tracked links returning 403, a 0-character plain-text part, and missing alt attributes on several images. Most of the link and header findings are probably probe or relay artifacts, and I note that where it applies.

## 2. Link & Tracking Issues
- **11 of the 12 probed links returned 403.** They are all Attentive click-tracking redirects on `carters.e.attentivemail.com/e/c/...`, covering the hero, the "Matching Sets", "Tops & Bottoms" and "FLEECE PJS FROM $8" blocks, brand tiles (osh kosh bigosh, little planet, Otter Avenue, Skiphop), and four product images.
- **The 403 is probably bot-blocking, not a dead link.** A uniform 403 on every redirect from one ESP domain usually means the probe's user agent or IP is being filtered. It does not show that recipients get an error. Re-probe with a browser-like UA, or check the redirect target in a real client, before treating these as defects.
- **48 links were skipped.** Footer, social, and utility links are unverified, so the audit cannot confirm the unsubscribe or preference links.
- **All destinations are hidden behind opaque redirect tokens.** Landing URLs can't be checked from the HTML.

## 3. Rendering & Accessibility
- **Empty `<title></title>`** in `<head>`. It is minor, but some clients and web-view renderers use it.
- **Missing alt text per QA:**
  - Four cloudfront banner images (`MzczMjo6U0VSVklDRVNfQkFOTkVSXzAx…` through `…BTk5FUl8wNF92My…`) look like services banners (shipping, returns, and similar) whose message is lost with images off.
  - `mi.carters.com/p/rp/264477f43986d8bb.png` is also flagged. Its role is unclear from the truncated source.
- **Probable false positives:** `ho.gif` is rendered with `alt=""` in the source (`<img src=".../ho.gif" alt="" width="1" height="1" …>`). That is valid for a decorative pixel. `mi.carters.com/.../o.gif` is a second tracking pixel and likely the same case.
- **Plain-text part is 0 chars.** There is no `text/plain` alternative, which hurts accessibility and deliverability scoring. The relay may have stripped it, so check the raw send.
- **Preheader padding** uses repeated `͏` and soft-hyphen characters. This is standard and fine.
- **Web font:** `League Spartan` loads from Google Fonts inside `<!--[if !mso]><!-->`, so Outlook falls back to its default font. That is acceptable if the CSS has fallback stacks, which I can't verify from the truncated source.

## 4. Personalization & Merge Tokens
- **No unresolved tokens** (`{{ }}`, `%%`, `[FIRST_NAME]`) in the visible source.
- **A numeric user ID is in the tracking-pixel URLs:** `mi_u=1150794179` on `mi.carters.com/p/up/745a17bbb73445ad/o.gif` and on `264477f43986d8bb.png`. It is an expected per-recipient token from the vendor, not a failed merge. It does mean per-recipient IDs appear in image URLs.

## 5. Compliance
- **`List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) were not found.** QA says the AgentMail relay may strip these headers. Verify on the original message before treating it as a defect. Gmail and Yahoo require one-click unsubscribe for bulk senders, so the check matters.
- **`Authentication-Results` is missing,** so SPF, DKIM, and DMARC status is unknown. Same caveat about the relay.
- **Unsubscribe link and physical address:** not visible in the truncated source, so I can't confirm either way.
- **Sender:** `carters.email@marketing.carters.com` is a branded subdomain, which is correct. The tracking host `attentivemail.com` differs from the sender domain, which is typical for ESP link wrapping.

## 6. Email-to-Site Continuity
- **UTM and landing alignment can't be assessed.** Every CTA is an opaque Attentive redirect and the 403s block resolution.
- **A campaign tag is visible only on the Monetate-style pixels:** `mi_ecmp=10_15_2026_CAR_THU_STO_ENGAGERS`. It matches the send date and an "engagers" segment, but it tells us nothing about UTM parameters on the landing pages.

## 7. Recommendations
1. Re-run link probing with a browser-like UA, or follow the redirects manually, to separate bot-blocking from real breakage. Then confirm the final URLs carry UTMs and land on matching pages.
2. Add descriptive `alt` text to the four cloudfront banners and the `264477f43986d8bb.png` image. Leave `alt=""` on the tracking pixels.
3. Fill in `<title>`, for example with the subject line.
4. Confirm the plain-text MIME part exists in the original send.
5. Check the raw headers for `List-Unsubscribe`, `List-Unsubscribe-Post`, and SPF/DKIM/DMARC results, since the relay may have dropped them.
6. Confirm the unsubscribe link and the postal address in the footer, which the truncated source and probe skipped.
