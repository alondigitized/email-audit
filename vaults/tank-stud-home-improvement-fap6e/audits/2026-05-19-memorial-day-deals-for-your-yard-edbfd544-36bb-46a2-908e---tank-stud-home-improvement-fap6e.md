### 3. Rendering & Accessibility

**Eight images missing `alt` text** (QA confirmed):

| Asset | Type | Risk |
|---|---|---|
| `c301e24e-…99.jpg` | Content image | Screen reader gap; broken image fallback shows no description |
| `ad569dc5-…05.png` | Content image | Same |

| 5× `sli.lowes.com/imp` | Impression pixels | Same as above — `alt=""` required, attribute absent |

The two content images are the meaningful failures. The tracking pixels need `alt=""` (empty, not missing) to suppress screen reader noise.

**Font loading — WOFF only, no WOFF2:**

```css
url('https://www.lowescdn.com/sffonts/Fellix-Regular.woff') format('woff')
```

All six `@font-face` declarations load `.woff` only. WOFF2 (30% smaller) is supported by every modern email client that supports web fonts. Minor bandwidth concern, not a rendering defect.

**Dual `<!--[if !mso]>` blocks** — the custom font CSS is split across two conditional comment blocks for no apparent reason. Functionally harmless but increases parse weight.

**Media query fragmentation** — two separate responsive breakpoints defined in distinct `<style>` blocks (`min-width: 375px and max-width: 600px` + `max-width: 480px`). These overlap at 480px. No confirmed rendering defect, but the overlap is a maintenance risk.
