## Technical Audit — Lowe's "July 4th Extra Big Deals" Email

### 1. Technical Summary

### 2. Link & Tracking Issues

**20 tracking links skipped (not probed).** All click-through URLs route through Lowe's ESP redirect infrastructure (`e.lowes.com`). No broken links confirmed, but destination URL UTM coverage cannot be verified — see §6.

**Impression pixels expose persona address** in query params:
```
https://sli.lowes.com/imp?s=1090834&e=cole-drywall-lowes-fap6e@etell.app&p=762026&lctg=410146703
```
The `e=` parameter encodes the recipient address in plain text in a GET request to a third-party pixel host. This is standard ESP behavior but means Lowe's has a copy of the etell persona address tied to campaign `p=762026`.

---

### 3. Rendering & Accessibility

**8 images missing `alt` attribute entirely:**

| Type | Evidence |
|---|---|
| Content image | `c301e24e-201b-46f9-8172-27b5acdcbf99.jpg` |
| Content image | `ad569dc5-361d-4d7d-8bc0-1ae6ec389f05.png` |
| Tracking pixel | `mi.lowes.com/.../o.gif?mi_u=410146703` |
| Impression pixels (×5) | `sli.lowes.com/imp?s=109083{4,4,5,7,8}...` |

The tracking pixels should carry `alt=""` (empty string, not omitted) — screen readers will read the filename or src URL when `alt` is absent entirely. Content images need descriptive alt text.

**Overlapping media query breakpoints:** Two separate query blocks target the 375–480px range simultaneously (`min-width:375px and max-width:600px` AND `max-width:480px`). Properties like `.container`, `.drop`, and `.mobile-hidden` are declared in both blocks with differing values. In a 375–480px viewport both blocks apply; cascade order resolves it, but it creates fragile override dependency.

**Font loading is correctly MSO-guarded.** Both `@font-face` blocks (Fellix, DIN Next) are wrapped in `<!--[if !mso]><!--> ... <!--<![endif]-->`, so Outlook Word-renderer clients won't attempt CDN font fetches — correct pattern, no issue.
