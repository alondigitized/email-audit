## Technical Audit — "Member Only Deals" / MyLowe's Rewards

### 1. Technical Summary

### 3. Rendering & Accessibility

**DOCTYPE parse error**
```html
<!DOCTYPE html PUBLIC"-//W3C//DTD XHTML 1.0 Transitional//EN" ...>
```
Missing space between `PUBLIC` and the quoted identifier. Correct form: `PUBLIC "-//W3C//DTD ...`. Some older parsers (Outlook rendering engine, certain webmail fallbacks) may drop into quirks mode as a result.

**Namespace URI uses HTTPS**
```html
<html xmlns="https://www.w3.org/1999/xhtml">
```
The canonical XHTML namespace is `http://www.w3.org/1999/xhtml` (no TLS). While most modern parsers are lenient, this is technically non-conformant and can trigger strict-mode failures in XML parsers.

**CDN version split on DIN Next fonts**
```
DIN Next Regular:  lowescdn.com/scaffold/1.4.4/fonts/din/din-next.woff
DIN Next Bold:     lowescdn.com/scaffold/1.2.0/fonts/din/din-next-bold.woff
DIN Next Black:    lowescdn.com/scaffold/1.2.0/fonts/din/din-next-black.woff
```
Regular loads from `1.4.4`; Bold and Black load from `1.2.0`. Version drift creates a latent risk: if `1.2.0` assets are ever evicted from CDN cache or purged, Bold/Black rendering falls back to system fonts while Regular continues loading correctly, producing a mixed rendering state.

**WOFF-only font declarations** — no WOFF2 sources. WOFF2 is supported in all current email clients that load web fonts. Missing it means slightly slower font load on supporting clients (minor, not blocking).

**Media query restricted to WebKit**
```css
@media screen and (min-width: 375px) and (max-width: 600px) and (-webkit-min-device-pixel-ratio:0) {
```
The 375–600px responsive breakpoint is gated behind `-webkit-min-device-pixel-ratio:0`, so it fires only in WebKit-based clients. Non-WebKit clients in that viewport range (e.g., some Android WebViews) fall through to the `max-width: 480px` query or desktop layout.

**Missing alt text confirmed by QA**
```
Image: a22207c1-63c7-47c0-9e00-61227828e1fe.jpg
src:   https://image.e.lowes.com/lib/fe9515707364027471/m/1/a22207c1-63c7-47c0-9e00-61227828e1fe.jpg
```
Alt text is empty or absent. Images-off rendering (common in B2B clients, corporate Outlook) will display a blank block for this asset with no fallback text.

### 5. Compliance

**List-Unsubscribe header absent** (QA: `[WARN]`)
RFC 2369 requires a `List-Unsubscribe` header on commercial bulk email. Gmail and Yahoo enforce this for senders above 5,000 messages/day and will route non-compliant mail to spam.

**List-Unsubscribe-Post header absent** (QA: `[WARN]`)
RFC 8058 one-click unsubscribe is now required by Gmail and Yahoo for high-volume senders. Absence does not immediately cause rejection but is a near-term deliverability liability as enforcement tightens.

*Note: Both headers may be present on the actual SMTP envelope and simply not captured by the AgentMail relay. This should be verified at the MTA level before treating as a confirmed gap.*

**Authentication-Results header not found** (QA: `[WARN]`)
SPF, DKIM, and DMARC pass/fail status cannot be confirmed from this capture. Sending domain is `e.lowes.com` (ESP subdomain). If DMARC alignment is not enforced on this subdomain, spoofing risk exists. Verify at relay/MTA.

**CAN-SPAM physical address** — not visible in truncated HTML. Must be present in the email body. Cannot confirm or deny from this excerpt.
