# Want to win $3,000 in concert gift cards?
**Score:** 6/10 · **Type:** Email audit · **2026-07-20**
## Executive summary

- Man, I'm getting déjà vu from that Messi fiasco on July 19th. I open my inbox expecting a sale on cordless power tool combos or maybe a lumber clearance, and instead Lowe's is asking me if I want to win three grand in *concert gift cards*. Concert gift cards. I'm a guy whose weekend highlight is figuring out which impact driver bit set is on clearance. I do not need Ticket Cash.
- To be fair, the email looks clean. The hero section is actually well-designed — big crowd shot, bold prize callout, clear "Enter to win" button. And the MyLowe's Rewards perks section below (complimentary lawn chair rentals? Two-for-one tickets?) at least connects to the loyalty program I actually use. But this is two off-brand entertainment swings in two days after a streak of genuinely useful appliance and patio emails. If this is a deliberate sweepstakes season pivot, fine — but it's not for me.
- I'd mark this as read and move on. I wouldn't click, I wouldn't forward. If my wife wants concert tickets, she can find her own sweepstakes.

## What's working

- **Recognizable sender.** MyLowe's Rewards in the from field — I know this brand, I'm a loyalty member, I opened it.
- **Prize amount is concrete.** $3,000 is a specific number that earns a second glance before you realize it's for concerts you'll never attend.
- **CTA is clean and unambiguous.** "Enter to win" button sits right below the hero — no guessing what they want me to do.
- **Email renders without bugs.** No broken images, no overlapping text, layout holds up cleanly on mobile view.
- **Loyalty perks section is a nice touch.** Mentioning member-specific benefits (lawn chair rentals, 2-for-1 tickets) at least reminds me there's a program I'm part of.

## What's weak

- **Completely wrong category for me.** Nothing in this email — not the hero, not the perks, not the CTA — has anything to do with tools, lumber, plumbing, or any project I'm planning.
- **No purchase offer or discount.** After last week's patio savings and appliance deals, this is a dead-end email with no financial upside unless I win.
- **Demographic mismatch.** The concert crowd imagery skews young and festival-y. This doesn't feel like it was designed for a 49-year-old who checks the lumber rack on weekends.
- **No urgency or deadline visible.** I can't see a "sweepstakes ends [date]" anywhere above the fold. No reason to enter now versus never.

## Recommendations

- 1. **Tie the sweepstakes to a purchase incentive.** "Spend $100+, get a sweepstakes entry" would've gotten a click from me. As-is, it's just a raffle I stumbled into.
- 2. **Segment this away from project-focused shoppers.** Someone who bought patio furniture last month or clicked the concert perks teaser should get this. I should get a drill bit email.
- 3. **Show the sweepstakes end date above the fold.** A visible deadline creates urgency — without it, the email feels indefinite and easy to skip.
- 4. **Hero copy needs a value hook for the tool-aisle crowd.** If you're going to blast this broadly, something like "Win concert cash — plus, deals on the gear you actually need" bridges the gap.
- **Subject Alt A:** `Tank, you've got a shot at $3,000 — enter before it closes`
- **Subject Alt B:** `Enter to win $3,000 — plus your MyLowe's perks this weekend`
- **Preheader Alt A:** `Sweepstakes closes [date] — one entry, no purchase required`
- **Preheader Alt B:** `More Ticket Cash™ prizes up for grabs — your member entry is waiting`

### 3. Rendering & Accessibility

**Missing alt text (confirmed by QA):**
```
src: https://image.e.lowes.com/lib/fe9515707364027471/m/1/a22207c1-63c7-47c0-9e00-61227828e1fe.jpg
```
Image renders as a blank rectangle in image-off contexts (Outlook default, some corporate environments) and is invisible to screen readers. This appears to be a hero or promotional image given the file path pattern.

**Malformed DOCTYPE — missing space:**
```html
<!DOCTYPE html PUBLIC"-//W3C//DTD XHTML 1.0 Transitional//EN"
```
Should be `PUBLIC "-//...` (space before the quoted string). Technically non-conformant; major clients parse it anyway, but it signals template hygiene debt.

**Duplicate `<!--[if !mso]>` font blocks:** Two separate conditional comment wrappers are used to load `@font-face` declarations — one for the Fellix family, one for DIN Next. These can be merged into a single block with no functional difference, reducing parse overhead.

**Font format — `.woff` only:** All six `@font-face` declarations reference only `.woff`, not `.woff2`. `.woff2` provides ~26% smaller file size where supported (Apple Mail, Samsung Mail). Low priority given limited email font support generally, but worth noting.

**CDN version inconsistency — DIN Next:**
- `DIN Next Regular`: `scaffold/1.4.4/fonts/din/din-next.woff`
- `DIN Next Bold` / `DIN Next Black`: `scaffold/1.2.0/fonts/din/...`

Bold and Black variants are pinned to an older CDN path than Regular. If `1.2.0` is ever purged, those weights break silently.

**Legacy Gmail `.mobilehide` hack present** (`.mobilehide { display: none; color: #fff; }`). Functional but outdated — modern Gmail (2019+) supports `display:none` directly in `<style>` blocks. Not a bug, just legacy debt.

### 5. Compliance

**`List-Unsubscribe` header — not found (WARN)**
Required for Gmail and Yahoo bulk sender compliance (enforced February 2024 for senders >5k/day). Absence risks increased spam folder placement. The QA note indicates this may be a relay capture gap rather than a genuine omission — confirm against raw SMTP headers via a seed inbox test (e.g., Mail-Tester, GlockApps).

**`List-Unsubscribe-Post` header — not found (WARN)**
RFC 8058 one-click unsubscribe. Gmail surfaces a native "Unsubscribe" button in the UI only when this header is present alongside `List-Unsubscribe`. Its absence degrades the unsubscribe path for Gmail users and is now a bulk sender requirement.

**`Authentication-Results` — not found (WARN)**
SPF/DKIM/DMARC pass/fail status is unknown through the AgentMail relay. The sending domain `e.lowes.com` is a Salesforce SFMC subdomain; DKIM is almost certainly configured, but this cannot be confirmed from captured headers. Validate via seed inbox inspection or MXToolbox DKIM check against `e.lowes.com`.
