### 2. Link & Tracking Issues

**Redirect chain opacity — 21 links unverified**
All 21 click links pass through a Lowe's click-redirect domain. The QA probe correctly skipped these, so destination URL health, UTM presence, and landing page alignment are entirely unverified this run.

**Recipient address exposed in pixel query strings**
Five `sli.lowes.com/imp` tracking pixels include the subscriber address in plain text via the `e=` parameter:

This is standard ESP behavior but means the address is visible in any proxy/CDN log along the pixel request path. Not exploitable in isolation, but worth noting for data-minimization posture.

### 3. Rendering & Accessibility

**8 images missing `alt` text (QA-confirmed)**

| Image | URL fragment | Severity |
|---|---|---|
| Hero/content | `c301e24e-...jpg` | High — content image needs descriptive alt |
| Content | `ad569dc5-...png` | High — content image needs descriptive alt |
| Open pixel | `o.gif` | Low — should be `alt=""` (decorative) |
| 5× impression pixels | `sli.lowes.com/imp?...` | Low — should be `alt=""` (decorative) |

Tracking pixels require `alt=""` (empty, not absent) to be valid per WCAG 1.1.1. Content images need meaningful alt text for screen readers and image-blocked rendering.

**Overlapping media query breakpoints**
Two `@media` blocks cover overlapping ranges:
- `@media screen and (min-width: 375px) and (max-width: 600px)` 
- `@media only screen and (max-width: 480px)`

Both fire on 375–480px viewports (most iPhones). Rule conflicts in this range (e.g., `.drop`, `.container`, `.no-padding`) will resolve by source order, which may not match intent.

**`woff2` absent from all `@font-face` declarations**
Fellix and DIN Next font stacks only declare `woff`. All modern clients support `woff2` (30% smaller). Not a breakage, but a performance gap.

**CDN version mismatch in DIN Next**
```
DIN Next Regular: /scaffold/1.4.4/fonts/din/din-next.woff
DIN Next Bold:    /scaffold/1.2.0/fonts/din/din-next-bold.woff
DIN Next Black:   /scaffold/1.2.0/fonts/din/din-next-black.woff
```
Regular references a newer scaffold version than Bold/Black. If `1.2.0` is deprecated, Bold and Black could 404 on CDN cache eviction.

### 5. Compliance

**`List-Unsubscribe` header missing — HIGH**
QA warning: `List-Unsubscribe header not found`. The AgentMail relay is not capturing this header. Gmail has required `List-Unsubscribe` for bulk senders (>5k/day) since February 2024; without it, Gmail may display a less prominent unsubscribe path or classify the message as promotional in ways that hurt placement.

**`List-Unsubscribe-Post` (RFC 8058) missing — HIGH**
QA warning: `List-Unsubscribe-Post header not found`. This header enables one-click machine-readable unsubscribe. Also a Gmail bulk sender requirement since February 2024. Absence does not mean Lowe's isn't sending it — the relay isn't forwarding it.

**Authentication-Results not captured**
QA warning: `Authentication-Results header not found`. SPF, DKIM, and DMARC pass/fail for `e.lowes.com` cannot be confirmed from the captured message. This is a relay pipeline gap, not confirmed as a sending failure. The sender domain (`e.lowes.com`) is a standard ESP subdomain that should have its own DKIM and SPF records.
