### 1. Technical Summary

Table-based XHTML 1.0 Transitional email with custom web fonts and two overlapping responsive breakpoints. QA surfaced three compliance gaps and two deliverability signals that require investigation before the next send.

---

### 2. Link & Tracking Issues

**28 click-redirect links skipped by HTTP probe** — all tracked through `e.lowes.com` redirect domain. Destination URLs, UTM presence, and link rot cannot be confirmed without bypassing the redirect or using Lowe's internal click-stream tooling.

**Plain-text body is 79% URLs** (3,572 / 4,504 chars). Spam filters (notably Gmail and SpamAssassin) penalize plain-text parts where the majority of content is raw URLs rather than readable copy. The plain-text version should mirror readable content with URLs appended, not be auto-generated from raw link dumps.

**No issues found** with dead-link detection on non-redirect URLs in the truncated source.

---

### 3. Rendering & Accessibility

**Missing alt text — one image confirmed:**
```
src: https://image.e.lowes.com/lib/fe9515707364027471/m/1/a22207c1-63c7-47c0-9e00-61227828e1fe.jpg
```
Alt attribute is absent. Renders as a broken-image icon in image-blocked clients and fails WCAG 2.1 SC 1.1.1.

**Conflicting media query breakpoints.** Two queries overlap on devices 375–480px wide:

```css
/* Query A — fires at 375–600px */
@media screen and (min-width: 375px) and (max-width: 600px) and (-webkit-min-device-pixel-ratio:0) { ... }

/* Query B — fires at ≤480px */
@media only screen and (max-width: 480px) { ... }
```

Both fire simultaneously on WebKit devices at 375–480px (e.g., iPhone SE, standard iPhone). Rules in Query B for `.container`, `.drop`, `.photo` conflict with Query A declarations for the same selectors. Last-declaration-wins resolves in favor of Query B, but this is likely unintentional and should be validated on an iPhone SE viewport.

**Font CDN version mismatch.** DIN Next Regular loads from scaffold `1.4.4`; Bold and Black load from `1.2.0`:

```
https://www.lowescdn.com/scaffold/1.4.4/fonts/din/din-next.woff        ← Regular
https://www.lowescdn.com/scaffold/1.2.0/fonts/din/din-next-bold.woff   ← Bold
https://www.lowescdn.com/scaffold/1.2.0/fonts/din/din-next-black.woff  ← Black
```

If `1.2.0` assets are ever purged during CDN cleanup, Bold and Black weight rendering will silently fall back to system fonts.

**WOFF only, no WOFF2.** All six `@font-face` declarations specify only `format('woff')`. WOFF2 is supported by 97%+ of email clients that honor web fonts and compresses ~30% smaller. Not a blocker, but increases load time on slower connections.
