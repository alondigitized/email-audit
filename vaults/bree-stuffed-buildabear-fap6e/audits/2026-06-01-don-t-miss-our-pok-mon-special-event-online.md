# Don’t Miss Our Pokémon Special Event Online!
**Score:** 8/10 · **Type:** Email audit · **2026-06-01**
## Executive summary

- This is a Pokémon event roundup — an umbrella email collecting multiple Pokémon bundles under a "ENDING SOON / SPECIAL EVENT!" hero, with dedicated modules for Sylveon and Jolteon below. The Jolteon reveal is the best thing in this email and is buried in the bottom half. Sylveon, meanwhile, just had its own dedicated send four days ago (May 28, "Pokémon Fans: Sylveon Is Back!" — 9/10), and re-featuring it here as if it's still the headline news blunts both emails simultaneously.
- The "ACTION-PACKED SAVINGS" hero copy promises a discount that never materializes with a specific number. "ENDING SOON" fires urgency without a date. Together these two moves make the email feel like a promo wrapper around products the brand wanted to move, rather than a genuine event with real stakes.
- The layout is clean, there are no render bugs, and the Pokémon IP still has pull — but this send leans too hard on the May 28 playbook without delivering anything new enough to justify the replay so soon.

## What's working

- **Jolteon module is genuinely new news** — "BOLT INTO ACTION: JOLTEON'S BACK!" is a strong hook for Pokémon fans and hasn't appeared in any recent send in the brand history.
- **"ENDING SOON" in the hero** creates real urgency at the top of the email, even without a specific deadline.
- **No render bugs** — product images load cleanly, CTAs are clearly styled, the 2x2 grid is organized.
- **Pokémon x Build-A-Bear color palette** (red hero on blue background) is on-brand for both IPs and the email looks intentional.
- **Four specific product bundles in the grid** give multiple landing targets, reducing the zero-match risk.

## What's weak

- **Sylveon recycled 4 days after its own headline email** — subscribers who opened the May 28 send already know Sylveon is back; re-featuring it as a primary module makes this email feel like a resend.
- **No concrete savings number visible** — "ACTION-PACKED SAVINGS" in the hero is empty without a % or $ value anywhere in the scroll.
- **"ENDING SOON" has no end date** — the urgency signal exists but evaporates without a specific deadline; a sophisticated subscriber treats this as decoration.
- **Product grid leads with the Teddy Bear Party Bundle** — the least Pokémon-iconic item in the set; a Pikachu or Jolteon lead would pull harder.
- **Subject line doesn't name the character or the offer** — "Special Event" tells you nothing that "Pokémon" didn't already imply.

## Recommendations

- 1. **Lead with Jolteon in the hero and subject** — Jolteon is the new character in this send; it should be the headline, not buried below a Sylveon recap.
- 2. **Show a concrete savings figure** — "Save up to 20%" or "Bundles from $XX" replaces "ACTION-PACKED SAVINGS" with a reason to click.
- 3. **Add a deadline to the urgency** — "Ends June 4" next to "ENDING SOON" turns a soft nudge into a real trigger.
- 4. **Reorder the product grid** — put Pikachu or Jolteon bundles first; the Teddy Bear Party Bundle should be last or removed.
- 5. **Retire the Sylveon standalone module** — it doesn't need its own section; keep it in the grid only. The full module feels like a May 28 replay.
- **Subject Alt A:** `Jolteon Is Back — Pokémon Event Ends Soon`
- **Subject Alt B:** `New Pokémon Arrivals: Jolteon's Back, Savings Ending Soon`
- **Preheader Alt A:** `Jolteon bundles, Sylveon, Pikachu and more — shop before the event closes.`
- **Preheader Alt B:** `Action-packed Pokémon bundles are ending soon — grab yours before they're gone.`

### 3. Rendering & Accessibility

**Issue — Invalid CSS property casing:**
```css
p { Margin: 0px !important; Padding: 0px !important; }
```
`Margin` and `Padding` with capital first letters are non-standard. CSS properties are technically case-insensitive per spec, but some strict parsers (older Outlook rendering engines, certain sanitizers) may drop these declarations silently. Correct to lowercase `margin` / `padding`.

**Issue — Missing `lang` attribute on `<html>`:**
```html
<html xmlns="..." xmlns:v="..." xmlns:o="...">
```
No `lang="en"` (or appropriate locale). Screen readers default to the OS language, which may mispronounce content for multilingual recipients. Add `lang="en"` (or `lang="en-US"`).

**Issue — Trailing space in viewport meta value:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0 " />
```
Trailing space before the closing `"` is technically malformed. Benign in most parsers, but worth cleaning.

**Minor — Redundant dual declaration in `.gmailfix`:**
```css
.gmailfix { display: none; display: none !important; }
```
Intentional Gmail hack pattern, but the non-`!important` declaration is dead code. Not a bug, low priority.

**Minor — Dual preheader suppression:**
The preheader `<div>` carries both a CSS class (`display: none !important`) and a redundant inline `style="... display: none !important;"`. Redundant but harmless; keep only the inline for maximum client coverage or the class for maintainability — not both.

**Dark mode:** `color-scheme` and `supported-color-schemes` meta tags are present — correct practice. Cannot verify whether actual dark-mode CSS overrides exist further in the document.
