# NEW Jumping Spider! 🤎
**Score:** 7/10 · **Type:** Email audit · **2026-08-08**
## Executive summary

- This is Build-A-Bear introducing a new "Jumping Spider" plush for Halloween season, but the hero creative doesn't back up the promise — the featured image is a round, big-eyed brown plush in a purple beanie with no visible legs, web, or any spider signifier, so the subject and headline set an expectation the artwork doesn't pay off. It's otherwise a clean, well-organized send: color-blocked sections (green hero, orange bat panel, purple kitty panel), a "Most Loved" grid, and a "More to Explore" module all render without bugs, and every block has an unambiguous "SHOP NOW" CTA.
- This follows the exact pattern the brand has run at least four times in two weeks — new plush, cute framing, zero discount (Silly Goose 8/4, Cow Cuddles 8/2, Halloween Friends launch 8/6). That cadence, combined with a hero image that doesn't match its own subject line, keeps this in the same middling 6-7 band as its recent siblings rather than pushing it higher.
- Judgement: solid production quality, weak creative-to-copy alignment, no incentive to act now. Ships fine, converts modestly.

## What's working

- Clean, bug-free render — no overlapping text, broken images, or placeholder copy across the full length of the email.
- Every product block (hero, Batty bat, Batty Kitty, grid items, explore items) carries its own clear "SHOP NOW" button, so intent is never ambiguous.
- Strong color-blocking (green → orange → purple) keeps a long scroll visually varied instead of monotonous.
- Footer nav (Find a Workshop / Shop Best Sellers / Plan a Party) gives non-buyers a path to engage besides "shop now."

## What's weak

- The hero image doesn't read as a spider at all — no legs, no web, no spider cues — directly undercutting the subject line and headline's promise.
- No discount, price, or loyalty incentive anywhere — pure "cute new product" messaging, the same play run on 8/4 and 8/2 with no escalation.
- The subject's brown heart emoji (🤎) is an odd choice for a spider/Halloween product — reads like a teddy-bear cue, not spooky or spider-specific.
- The "eight times the hugs" copy claim has no visual payoff (no fanned-out legs/arms) to make good on it.

## Recommendations

- 1. Fix the hero image so the product actually looks like a spider — visible legs or a web motif, or at minimum a name badge on the shot — so the creative matches the subject's promise. This is the single biggest lift; right now subject and hero disagree.
- 2. Add a real incentive. The brand's own highest recent score (7/10, 8/1 "50% Off GIANT Furry Friends") came from a discount-led send — pure product intros like this one are capping at 6-7.
- 3. Swap the subject emoji to something Halloween/spider-coded instead of 🤎, which reads off-brand-for-the-moment.
- 4. Add real preheader copy — none is rendering here, which wastes the inbox real estate next to the subject line.

## 1. Technical Summary
The email renders using a standard MSO/VML-conditional responsive table layout, but fails on deliverability and compliance basics (empty plain-text part, missing unsubscribe headers) and all four sampled product links return HTTP 403.

## 2. Link & Tracking Issues
- **4 of 4 probed product links return 403 Forbidden** (all "SHOP NOW" CTAs):
  - `/red-rose-kitty-stuffed-animal/034272.html`
  - `/timeless-teddy-bear/026518.html`
  - `/spooky-kitty-stuffed-animal/034053.html`
  - `/chummy-shark-stuffed-animal/034604.html`
  All four share the same query string, so this is likely a systemic block (WAF/bot-protection on `buildabear.com`, or the QA prober's UA/IP being blocked) rather than four independently broken URLs — worth confirming with a manual browser fetch before treating each as a dead link.
- UTM parameters are present and consistent across all four CTAs: `utm_source=Campaign&utm_medium=Email&utm_campaign=HalloweenSpiderGIF&utm_term=US-US_Testing_Hot-20260808&utm_content=Promo&utm_id=2786909`.
- 23 additional links use tracking/click-redirect domains and were skipped by the automated prober — their final destinations are unverified and should be spot-checked manually.

## 3. Rendering & Accessibility
- Doctype is XHTML 1.0 Transitional with MSO/VML conditional comments (`<!--[if gte mso 9]>`) — appropriate for Outlook desktop compatibility.
- Media queries are defined for two breakpoints (481–639px and ≤480px, plus a ≤350px override), indicating an intended mobile-responsive layout.
- **4 images missing `alt` text**, all product images served from the Demandware/SFCC CDN (`dw820854e2`, `dwae8c6c2a`, `dwfc05d237`, `dwac6db04b` asset paths). This fails WCAG 1.1.1 and degrades the experience for screen-reader users and when images are blocked by default (a common state in Outlook/Gmail).
- Preheader is implemented correctly via hidden `div.preheader` + zero-width-joiner/nbsp padding hack, with `display:none !important` fallback — standard, no issue.

## 4. Personalization & Merge Tokens
No merge tags, personalization placeholders (e.g. `{{first_name}}`, `%%FIRSTNAME%%`, AMPscript, Handlebars), or dynamic-content blocks are present in the visible HTML source. No issues found in the truncated content — note the source was truncated, so tokens further down the template were not inspected.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` header not found.** Note the QA tool flags this may be an artifact of the AgentMail relay not capturing the header rather than the sender omitting it — needs confirmation against raw source headers, not just the relayed copy.
- **`List-Unsubscribe-Post` header not found** (RFC 8058 one-click unsubscribe) — same caveat re: relay capture.
- **Plain-text MIME part is empty (0 chars).** A missing/functionally absent text alternative is a CAN-SPAM/deliverability risk (multipart/alternative with no usable text part) and will actively hurt inbox placement with providers that weight plain-text presence.
- **`Authentication-Results` header not found** — SPF/DKIM/DMARC pass/fail status could not be verified through this relay.
- No footer/unsubscribe link content was present in the truncated HTML sample to confirm an in-body unsubscribe mechanism exists — recommend checking the untruncated source.

## 6. Email-to-Site Continuity
- UTM taxonomy is internally consistent across all four sampled CTAs (same `utm_campaign`, `utm_id`, `utm_source`, `utm_medium`).
- Continuity cannot be fully assessed because **all four landing pages return 403**, blocking verification of message-to-page alignment (promo terms, product availability, creative match).
- Sending domain is `ebuildabear.com` rather than `buildabear.com` — confirm this is an intentional, authenticated ESP subdomain (with its own SPF/DKIM) rather than a domain-alignment gap, since `Authentication-Results` could not be verified (see §5).

## 7. Recommendations
1. Manually verify the 4 flagged product URLs in a browser (outside the automated prober) to distinguish a real outage from bot-protection blocking the QA tool's requests.
2. Populate the plain-text MIME part — it is currently empty and should not be.
3. Add `alt` text to the 4 unlabeled product images (Red Rose Kitty, Timeless Teddy, Spooky Kitty, Chummy Shark).
4. Confirm `List-Unsubscribe` / `List-Unsubscribe-Post` headers are present in the raw send (re-check against original ESP headers, not the AgentMail-relayed copy) and that RFC 8058 one-click unsubscribe is supported.
