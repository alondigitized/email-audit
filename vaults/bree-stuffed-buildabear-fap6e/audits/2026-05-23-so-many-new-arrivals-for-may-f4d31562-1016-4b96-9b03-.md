# So Many NEW Arrivals for May!
**Score:** 7/10 · **Type:** Email audit · **2026-05-23**
## Executive summary

- This is a catalog-dump "new arrivals" send — six distinct product categories crammed into one email with no unifying narrative beyond "new stuff exists." The hero graphic is clean and the blue-on-pink Build-A-Bear palette is on-brand, but the email has no offer, no discount, no deadline, and no reason to click *today* versus tomorrow. It reads like a CMS export, not an editorial decision.
- The timing is also bruised. Build-A-Bear has sent six emails in the five days prior — including a dedicated Hello Kitty Ice Cream Shop send on May 18, a Grogu send on May 19, and a broad summer collection launch on May 22. All three product categories that anchor this email already had their own featured send this week. To a subscriber paying attention, this feels like a greatest-hits recap, not genuine news.
- Bottom line: competent execution of a weak brief. If the goal was awareness, it'll do fine. If the goal was conversion, it has almost nothing working in its favor.

## What's working

- Hero hierarchy is clean — "NEW ARRIVALS" lands first, the sub-copy is short and readable, and the SHOP NOW button is impossible to miss.
- Four individual product cards each carry their own SHOP NOW button, which is better than a single homepage CTA.
- The Grogu section smartly rides the theatrical release window (May 22 film drop), adding a time-peg the rest of the email lacks.
- The Summer Bag Charms module introduces a genuinely new product type (accessories) that hasn't appeared in prior sends, giving subscribers at least one fresh hook.
- No render bugs — images load, text is legible, layout holds on mobile.

## What's weak

- Zero price incentive — no % off, no BOGO, no free shipping — in a send where the sole pitch is "it's new." Without a reason to buy now, most readers will defer and forget.
- Scented Hello Kitty plush and Grogu both had dedicated feature emails this week; reprising them here without new framing dilutes both the prior sends and this one.
- "SHOP NOW" repeated identically across every CTA is lazy — it gives the subscriber no directional signal about *what* they'd be shopping for.
- The Summer Bag Charms module is undersized — one image, three lines of copy — for what could be an interesting new product line with broader gifting appeal.
- Seven emails in six days is fatigue-level cadence for this brand; this send will open into a mentally exhausted subscriber.

## Recommendations

- 1. **Add one offer.** Even "free shipping on new arrivals through Sunday" changes the behavioral calculus completely — right now there is no urgency to act over browsing.
- 2. **Feature Bag Charms as the hero.** It's the only genuinely new product type in the email; give it the spotlight instead of another Hello Kitty reprise.
- 3. **Differentiate the CTAs.** "Shop Bag Charms," "Build Your Grogu," "See the Ice Cream Collection" each pulls a different buyer intent; generic "SHOP NOW" serves none of them.
- 4. **Cut the Grogu and Hello Kitty modules or reframe them.** If they stay, lead with something like "Just added: Bubblegum Scent" — give the subscriber a reason to revisit even if they saw the May 18 send.
- 5. **Ease the weekly cadence.** Six prior emails in five days means the marginal open rate on this one will be materially lower than May 18–19 sends.

### 3. Rendering & Accessibility

**Missing `lang` attribute on `<html>`:**
```html
<html xmlns="..." xmlns:v="..." xmlns:o="...">
```
No `lang="en"` present. Screen readers will not know the document language; some clients default incorrectly.

**Capitalized CSS property names on `<p>`:**
```css
p { Margin: 0px !important; Padding: 0px !important; }
```
`Margin` and `Padding` are non-standard casing. The CSS spec is case-insensitive for property names, but several legacy email client parsers (older Outlook WebApp, Lotus Notes) treat them as unknown properties and ignore the declaration.

**Trailing space in viewport `content` value:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0 " />
```
The trailing space before `"` is benign in most clients but is a malformed attribute value and may cause strict XML parsers to reject the document.

**Dark mode meta tags declared without implementation:**
```html
<meta name="color-scheme" content="light dark">
<meta name="supported-color-schemes" content="light dark">
```
No `@media (prefers-color-scheme: dark)` rules appear anywhere in the stylesheet. Declaring dark mode support without providing dark-mode overrides means Apple Mail and iOS Mail will attempt automatic color inversion — which can produce unintended contrast changes on images and colored backgrounds.

**`<style>` block inside `<body>`:**
```html
<body ...><style type="text/css"> div.preheader { display: none !important; } </style>
```
Gmail, Yahoo Mail, and several other webmail clients strip `<style>` tags that appear in the body. This rule is redundant (the preheader `<div>` already has an inline `display:none`) but the pattern is a reliability risk if relied upon for other rules in other sends.

**Duplicate declaration in `.gmailfix`:**
```css
.gmailfix { display: none; display: none !important; }
```
First declaration is overridden by the second; dead code. No functional impact.

**`&shy;` (soft hyphen) in preview-text padding div:**
The spacer div uses hundreds of `&shy;` entities. While widely used as a preview-text filler hack, `&shy;` can render as visible hyphens in Outlook 2019+ when the containing element's `overflow:hidden` is stripped, producing artifact characters at the top of the rendered email.
