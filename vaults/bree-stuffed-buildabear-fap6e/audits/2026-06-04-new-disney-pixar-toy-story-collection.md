# NEW Disney & Pixar Toy Story Collection!
**Score:** 8/10 · **Type:** Email audit · **2026-06-04**
## Executive summary

- This is a clean, IP-forward product launch announcing Build-A-Bear's Toy Story collection — Woody, Buzz Lightyear, and Jessie each get dedicated character modules against a yellow/gold backdrop that's a sharp visual match to the franchise palette. The layout is the same proven character-spotlight grid Build-A-Bear has deployed successfully all week, most recently on the Dadalorian send (June 3, 8/10) and the Bluey push (May 31, 9/10).
- The structural problem is pricing silence. This email asks for a purchase commitment across three character modules, a Celebrate Disney milestone callout, and a Stitch cross-sell without a single price anchor anywhere. - Toy Story IP is strong enough to carry the email on nostalgia alone, but the lack of pricing and the diluted story keep this well below the Bluey benchmark. Competent execution, unrealized potential.

### 3. Rendering & Accessibility

**Issue 1 — Attribute typo on X-UA-Compatible meta tag (definitive bug)**
```html
<meta http-equiv="X-UA-Compatible" Aontent="IE=edge" />
```
`Aontent` is not a valid attribute name; this should be `content`. The IE/Edge compatibility directive is silently ignored, meaning legacy Outlook WebView instances may not render in edge mode.

**Issue 2 — Malformed MSO conditional XML (duplicate closing tags)**
```xml
<o:PixelsPerInch>96</o:PixelsPerInch></o:PixelsPerInch>
</o:OfficeDocumentSettings></o:OfficeDocumentSettings>
```
Both tags are closed twice. This is invalid XML inside the MSO conditional comment block; Outlook's XML parser may discard the entire `<o:OfficeDocumentSettings>` block, which disables PNG alpha transparency support and the 96 DPI pixel density hint.

**Issue 3 — Incomplete `border` shorthand on `#table-container`**
```css
#table-container { border: 10px; border-radius: 20px 20px 20px 20px !important; overflow: hidden; }
```
`border: 10px` specifies a width but no style (e.g., `solid`) and no color. Per CSS spec, a border without a style value defaults to `none` and will not render. This is likely a leftover value from a template variable that was never set.

**Issue 4 — Trailing whitespace in viewport meta value**
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0 " />
```
The trailing space before `"` is technically invalid. Most parsers handle this, but it's worth correcting to avoid edge cases in strict email clients.

**Issue 5 — Redundant `display:none` declaration in `.gmailfix`**
```css
.gmailfix { display: none; display: none !important; }
```
Two identical declarations — harmless, but indicates template sloppiness.
