# NEW Moodicorn Unicorn! 🦄🖤
**Score:** 6/10 · **Type:** Email audit · **2026-07-14**
## Executive summary

- This is a product-launch awareness email introducing the Moodicorn Unicorn — a goth/emo-aesthetic stuffed unicorn in black with skull motifs. Build-A-Bear is clearly leaning into the alternative aesthetic trend here, and the hero copy nails the tone: "Adorable angst and an emo imagination." The pink-plus-black color contrast in the hero is eye-catching and brand-consistent. The product name alone has novelty pull.
- What's missing entirely is any price signal. After yesterday's "Ends Soon! Bag Charms 2 for $30" deal email, this send asks subscribers to click purely on product curiosity — no discount, no urgency, no member pricing. For a deal-conditioned BAB subscriber list, that's a meaningful gap. The secondary modules (Beardusa, Hooked on Hugs, Most Loved Stuff This Week) dilute the Moodicorn moment rather than deepening it.
- Net judgement: solid concept, thin execution. The Moodicorn deserves a tighter, more focused send rather than a multi-product catalog tacked below it.

## What's working

- **Hero concept is sharp.** "Adorable angst and an emo imagination" is genuinely fun copy that matches the product's visual identity — a rare case where BAB's tone lands exactly right.
- **Subject line intrigue.** "NEW Moodicorn Unicorn! 🦄🖤" is short, specific, and the black-heart emoji signals the emo angle without over-explaining.
- **Visual hierarchy is clean.** The eye goes immediately to the oversized product image and yellow "MOODICORN UNICORN" headline — no competition from surrounding noise.
- **Beardusa module is a small delight.** "Don't Worry, Beardusa Won't Turn You to Stone!" is a clever pun; it earns a secondary click without being forced.
- **No render bugs.** Layout is clean, images load, text doesn't overlap anywhere visible.

## What's weak

- **No price anchor anywhere.** Zero $, zero %, zero "starting at." For a subscriber list trained on 50%-off urgency emails (see June 24), asking for a click on vibes alone is a tough ask.
- **The secondary modules undercut the hero.** Dropping Beardusa, Hooked on Hugs, and a 4-product "Most Loved" grid right below the Moodicorn hero fragments attention. This product deserved a single-focus email.
- **"Most Loved Stuff This Week" feels like filler.** Four small thumbnails with generic product names and no prices or reviews — adds scroll without adding value.
- **No urgency signal.** "NEW" implies novelty but not scarcity. No "limited run," no launch-window pricing, nothing to motivate action now over next week.
- **Daily send cadence is showing.** This is the fifth email in five days from BAB. The diminishing-returns effect on opens is real by this point in the week.

## Recommendations

- 1. **Add a price or launch-week incentive.** Even "Shop the New Moodicorn — Free Shipping This Week Only" gives subscribers a reason to act now. Without it, this is a catalog browse.
- 2. **Cut the secondary modules.** Give Moodicorn the full email. Show multiple colorways, the outfit accessories, or a "Build Your Moodicorn" CTA that links directly to the customizer — not just a generic SHOP NOW.
- 3. **Rewrite the CTA button.** "SHOP NOW" is inert. "Meet Moodicorn" or "Build Your Moodicorn" is specific and matches the product's personality.
- 4. **Move "Most Loved" to a separate weekly digest.** It has no business being in a launch email.

### 3. Rendering & Accessibility

**Non-standard CSS property casing — confirmed:**
```css
p { Margin: 0px !important; Padding: 0px !important; }
```
`Margin` and `Padding` with capital M/P are technically non-standard CSS (spec requires lowercase). Most clients parse them anyway, but strict CSS processors (some webmail renderers, CSS inlining tools) may silently drop these rules, causing paragraph spacing to revert to browser defaults.

**Viewport meta trailing whitespace — confirmed:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0 " />
```
Trailing space before the closing quote. Harmless in current clients but should be cleaned up.

**Duplicate CSS declaration — confirmed:**
```css
.gmailfix { display: none; display: none !important; }
```
Redundant first `display: none` with no `!important`. One declaration is sufficient.

**Two overlapping media query breakpoints — confirmed:**
- `min-width:481px and max-width:639px` (tablet)
- `max-width: 480px` (mobile)

There is a 1px gap at exactly `481px` where neither query matches. Clients that land exactly on 481px width will get neither set of overrides. Standard practice is to use `max-width:600px` as a single mobile breakpoint, or to ensure the ranges are contiguous.
