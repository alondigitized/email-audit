# Comin’ in HOT: New Summer Collection!
**Score:** 8/10 · **Type:** Email audit · **2026-05-22**
## Executive summary

- Build-A-Bear opens with "the SUMMER stuff you love." and delivers exactly that: a clean, colorful multi-category catalog laid out across at least six distinct product sections. The render is tight, the palette is vivid and season-appropriate, and the scrolling layout has genuine visual rhythm — each section gets its own accent color, which keeps the eye moving. On those terms, the email executes well.
- The problem is context. This is the sixth Build-A-Bear email in roughly seven days, and it's the most generic of the batch. After yesterday's focused Lightning Bug single-product launch (8/10), a collection-overview catalog feels like a step backward. There is no discount, no deadline, no event hook, no urgency anywhere in the visible email — just a parade of "SHOP NOW" buttons. For a May 22 send with Memorial Day weekend directly ahead, that's a real missed opportunity.
- The summer timing is right, the brand voice is consistent, and the layout gives subscribers multiple entry points. But this is awareness spend dressed up as a conversion email, and without a promotion or hero-product focus, it's unlikely to move the needle on sales.

## What's working

- Each product section uses its own background color (pink, teal, yellow, coral) — creates rhythm and prevents the catalog scroll from becoming visually monotonous.
- "The SUMMER stuff you love." hero copy is clean, confident, and on-brand — no strained puns.
- "Most Loved Stuff This Week" editorial module at the bottom is a light social-proof layer that rewards scrollers.
- Product breadth across six categories (beach plush, summer friends, new bears, bag charms, style, favorites) gives multiple interest vectors.
- No render bugs — layout is structurally clean at mobile width.

## What's weak

- No discount, no promotion, no event hook — the email sends on the eve of a holiday weekend and asks nothing of the subscriber but vague browsing.
- Six emails in seven days is aggressive; by email six the marginal open probability has dropped materially.
- Every CTA across six sections reads "SHOP NOW" — identical copy for wildly different products signals low creative investment.
- The hero plush (an appealing crab or lobster character) is given no name, no personality, no story — just dropped into a hero image like stock art.
- A "Bear Weekend Event" appears to be referenced in a mid-email module but is visually buried — if there is an actual in-store event this weekend, it should be leading this email.

- 1. **Lead with a Memorial Day offer** — even 15% off or free shipping converts awareness into action. The timing is screaming for it and the email doesn't use it at all.
- 2. **Name and story the hero plush** — "Meet Crabby: Build-A-Bear's newest beach buddy" turns an anonymous catalog image into a character introduction, which is exactly what this brand does best and what the Lightning Bug send executed sharply.
- 3. **Differentiate the CTAs** — "Build Your Crab," "Shop Beach Friends," "Shop Charms" instead of five identical "SHOP NOW" buttons. Each section has a distinct audience; the copy should reflect that.
- 4. **Promote the weekend event to hero** — if there is genuinely an in-store Bear Weekend event happening May 23–25, it deserves the hero slot, not a buried mid-email module.
- 5. **Pull back cadence** — this collection overview could have been held until a sale or event email next week instead of being sent as email six of seven.

## Technical Audit — Build-A-Bear "Summer Collection" Email

### 1. Technical Summary
The template contains several malformed HTML/CSS constructs that will silently degrade rendering in Outlook and some mobile clients; the most critical is a broken IE-compatibility meta tag and invalid VML XML in the Outlook conditional block.

If SPF/DKIM/DMARC are not aligned to `ebuildabear.com`, inbox providers may downgrade deliverability or display a "via" mismatch in Gmail. ---

### 3. Rendering & Accessibility

**Critical — broken X-UA-Compatible meta:**
```html
<meta http-equiv="X-UA-Compatible" Aontent="IE=edge" />
```
Attribute `Aontent` is a typo for `content`. The directive is ignored; IE/legacy Edge will not use edge rendering mode.

**Critical — malformed VML XML (Outlook conditional block):**
```html
<o:PixelsPerInch>96</o:PixelsPerInch></o:PixelsPerInch>
</o:OfficeDocumentSettings></o:OfficeDocumentSettings>
```
Both closing tags are doubled. This produces invalid XML inside the `<!--[if gte mso 9]>` block; Outlook's XML parser may reject or partially ignore the VML settings, potentially breaking Outlook image rendering.

**Invalid CSS shorthand — `#table-container` border:**
```css
#table-container { border: 10px; border-radius: 20px 20px 20px 20px !important; }
```
`border: 10px` omits the required `style` value (e.g., `solid`). Per CSS spec, the shorthand sets `border-style: none` as default, so no border renders despite the `10px` width.

**Non-standard CSS property casing:**
```css
p { Margin: 0px !important; Padding: 0px !important; }
```
`Margin` and `Padding` with capital first letters are invalid CSS identifiers. Most parsers normalize these, but strict engines (some webmail clients) will drop the rules, causing paragraph spacing bleed.

**Redundant duplicate rule in `.gmailfix`:**
```css
.gmailfix { display: none; display: none !important; }
```
Harmless but signals a template editing artifact; lint should catch this.

**Mobile-only `.shop-now-button` definition:**
The `.shop-now-button` class is defined only inside `@media screen and (max-width: 480px)`. If this class appears on any element in desktop markup, it will be completely unstyled at desktop widths.

**`<title>` has trailing whitespace:**
```html
<title>Build-A-Bear </title>
```
Minor — strip the trailing space.
