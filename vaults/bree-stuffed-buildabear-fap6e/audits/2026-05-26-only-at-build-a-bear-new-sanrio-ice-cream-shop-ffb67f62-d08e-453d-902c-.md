# Only at Build-A-Bear: NEW Sanrio® Ice Cream Shop!
**Score:** 8/10 · **Type:** Email audit · **2026-05-26**
## Executive summary

- The Sanrio® partnership is the strongest IP Build-A-Bear has deployed this week, and this email mostly respects it. "AN EXTRA SCOOP OF FUN" lands cleanly in the hero, the four-character product grid is organized and thematically coherent, and ice cream + late May is a calendar layup. For a Sanrio fan on the list, this is an easy open.
- The miss is familiar: no price, no urgency mechanism, and copy that coasts on the IP rather than earning the click. Compare to the Lightning Bug launch (2026-05-21) — "This is kind of a bug deal" showed personality; "AN EXTRA SCOOP OF FUN" is adequate wordplay, but the Sanrio characters are doing all the heavy lifting. Add the fact that non-Sanrio products (a Pooh-style bear, a black plush) appear below the grid after the subject promises an exclusive Sanrio drop, and the send loses coherence at the scroll.
- For a Sanrio collector, this opens and converts. For a casual Build-A-Bear subscriber with no character allegiance, the "new thing exists, click to buy at unknown price" loop doesn't close.

## What's working

- **"Only at Build-A-Bear" in the subject** — genuine exclusivity signal that separates this from department-store Sanrio and creates a real reason to open.
- **Four named character cards** — "Bubblegum Ice Cream Chococat," "Strawberry Ice Cream Fluffy" — character fans can immediately see if their pick is in the drop; the flavor-naming reinforces collection coherence.
- **Candy-stripe awning + pastel ice cream palette** — the visual theme is end-to-end unified; the hero, the grid backgrounds, and the product styling all read as the same world.
- **Clean render** — no broken images, no overlapping text, no layout breakage; this is not guaranteed across the brand history and earns points here.
- **Late-May timing** — ice cream subject matter plus summer palette is exactly right seasonally.

## What's weak

- **Zero price points across six CTAs** — every product card says "SHOP NOW" with no "$XX" visible; a subscriber on the fence has to click into the site just to learn the price, which many won't.
- **Uniform "SHOP NOW" copy** — using the identical CTA six-plus times is a missed opportunity; character-specific copy ("Adopt Chococat," "Shop Cinnamoroll") would pull fans directly and cost nothing.
- **No scarcity or urgency signal** — "Only at" communicates exclusivity but not scarcity; Sanrio collabs sell out, and nothing in the email says so.
- **Non-Sanrio products below the fold break the promise** — the subject delivers "NEW Sanrio® Ice Cream Shop"; a Winnie-the-Pooh-style bear and a black plush appearing below the Sanrio grid undercut the exclusive-drop narrative.

## Recommendations

- 1. **Show at least one price per product card.** "$34" next to "SHOP NOW" is the single highest-leverage copy change — it lets budget-aware subscribers self-select in, reduces click hesitation, and signals value before the tap.
- 2. **Add a scarcity line to the hero.** One sentence: "Limited quantities — while supplies last." Sanrio collabs historically run short; name that reality.
- 3. **Character-specific CTA copy.** Replace the sixth identical "SHOP NOW" with "Shop Cinnamoroll," "Adopt Chococat," etc. — the smallest rewrite with meaningfully higher expected CTR.
- 4. **Cut or sequester non-Sanrio products.** If the email subject promises an exclusive Sanrio drop, keep the full scroll Sanrio. Separate sends for Pooh; don't dilute the exclusive framing.
- 5. **Hero subhead should name the characters.** One line beneath "AN EXTRA SCOOP OF FUN": "Cinnamoroll, Chococat, and friends — exclusively at Build-A-Bear." Fans who skim the image grid still see what's here.
- **Subject Alt A:** `Cinnamoroll & Chococat just dropped: Sanrio® Ice Cream Shop`
- **Subject Alt B:** `Limited: Sanrio® Ice Cream Shop — Only at Build-A-Bear`
- **Preheader Alt A:** `Cinnamoroll, Chococat, and friends. Four flavors. Zero calories.`
- **Preheader Alt B:** `Four new ice cream characters — adopt them before they're gone.`

### 3. Rendering & Accessibility

**3a. Malformed MSO conditional — duplicate closing tags (HIGH)**
```html
<o:PixelsPerInch>96</o:PixelsPerInch></o:PixelsPerInch>
</o:OfficeDocumentSettings></o:OfficeDocumentSettings>
```
Both `</o:PixelsPerInch>` and `</o:OfficeDocumentSettings>` appear twice. This produces invalid XML inside the `<!--[if gte mso 9]>` block. Outlook's XML parser will reject or silently ignore the entire `OfficeDocumentSettings` block, which can disable PNG rendering and cause DPI scaling issues on Windows Outlook 2016–2021.

**3b. Typo in `X-UA-Compatible` meta tag — attribute name broken (MEDIUM)**
```html
<meta http-equiv="X-UA-Compatible" Aontent="IE=edge" />
```
`Aontent` is not a valid attribute name. The correct attribute is `content`. This meta tag is a no-op — IE/legacy Edge compatibility mode will not be set. Low practical impact today but indicates a copy-paste defect in the template.

**3c. `.shop-now-button` class only defined inside mobile media query (MEDIUM)**
```css
@media screen and (max-width: 480px) {
  .shop-now-button { background-color: #0046c8; ... }
}
```
If any element in the body uses `class="shop-now-button"`, it will render with no background color, no padding, and no border-radius on desktop clients. Desktop clients that strip `<style>` blocks entirely (e.g., Gmail web) would also strip the mobile-only rule. Verify whether this class appears in the body; if so, add a base (non-media-query) rule.

**3d. `border: 10px` on `#table-container` — missing border-style (LOW)**
```css
#table-container { border: 10px; border-radius: 20px 20px 20px 20px !important; overflow: hidden; }
```
CSS `border` shorthand with only a width value and no style (`solid`, `none`, etc.) is invalid — the declaration is dropped by conforming parsers. If a visible or hidden border is intended, the style value must be specified (e.g., `border: 10px solid transparent`). Also, `overflow: hidden` has no effect on `<table>` elements in most email clients.

**3e. Trailing space in viewport meta (LOW)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0 " />
```
Trailing space inside the `content` value. Technically invalid; benign in practice but indicates template hygiene issues.

**3f. Capitalized CSS property names (LOW)**
```css
p { Margin: 0px !important; Padding: 0px !important; }
```
CSS property names are case-insensitive per spec, but some older email rendering engines (notably older Lotus Notes and some Android clients) parse them with case-sensitive rules. Use lowercase `margin` / `padding`.
