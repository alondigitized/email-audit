### 3. Rendering & Accessibility

**`lang="und"` on `<html>` element — confirmed issue.**
```html
<html dir="auto" lang="und" ...>
```
`und` is the ISO 639-3 code for *undetermined* language. Screen readers (NVDA, JAWS, VoiceOver) use this attribute to select a speech synthesis language; `und` causes a fallback to the OS default, which may mispronounce content in multilingual environments. **Fix:** `lang="en"` (or `en-US`).

**Global scrollbar suppression — confirmed accessibility concern.**
```css
@media only screen and (min-width:320px){
  body::-webkit-scrollbar{display:none!important}
}
```
Hiding the scrollbar on the email body inside a webmail renderer (Gmail, Outlook.com) can suppress the *page-level* scrollbar in some clients, trapping keyboard-only users. Remove or scope this rule to a specific container class rather than `body`.

**`<title>` is generic.**
```html
<title>REI</title>
```
Several clients (notably some versions of Outlook and Apple Mail) surface `<title>` as a tooltip or fallback preview string. A descriptive title (`REI Outlet – Up to 50% Off, 3 Days Only`) improves accessibility and disambiguation in multi-tab webmail.

**`dir="auto"` with `lang="und"`** compounds the language detection problem above. `dir="auto"` infers text direction from Unicode bidi characters; combined with an undetermined language, bidirectional text processing is ambiguous. Set `dir="ltr"` explicitly alongside `lang="en"`.
