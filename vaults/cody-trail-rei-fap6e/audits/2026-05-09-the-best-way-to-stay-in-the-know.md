### 3. Rendering & Accessibility

**Duplicate `color-scheme` meta — inconsistent values:**
```html
<meta name="color-scheme" content="light dark">   <!-- line 1 -->
<meta name="color-scheme" content="light, dark">  <!-- line 2 (duplicate) -->
```
The comma-separated format (`"light, dark"`) is non-standard for the `color-scheme` meta tag. One of these should be removed; the space-separated form (`"light dark"`) is correct per spec.

**`REIStuart-Bold` `@font-face` has conflicting `font-weight` declarations:**
```css
font-weight: 600;
font-weight: bold;   /* overrides to 700 — contradicts "Bold" = 600 intent */
```
The second declaration overwrites the first. If the intended mapped weight is 600, remove `font-weight: bold`.

**`maximum-scale=1.0` blocks user zoom:**
```html
<meta name="viewport" content="... maximum-scale=1.0" />
```
This prevents pinch-to-zoom in mobile browsers, which fails WCAG 1.4.4 (Resize Text). This is a common pattern in email templates but remains an accessibility defect.

**Preview text `<span>` blocks placed before `<head>`:**
The hidden preview-text spans appear in the document stream before the `<head>` element — technically malformed XHTML. Email clients tolerate this and some parsers require it to capture preview text early, but it should be documented as an intentional deviation from spec.

**`color:#ffffff` applied to hidden preview text:**
```html
<span style="... color:#ffffff;">Your special gift is almost over...</span>
```
White text on white background is a known spam-filter signal. The `display:none` + `max-height:0` approach already hides the text; the explicit white color is redundant and adds filter risk.
