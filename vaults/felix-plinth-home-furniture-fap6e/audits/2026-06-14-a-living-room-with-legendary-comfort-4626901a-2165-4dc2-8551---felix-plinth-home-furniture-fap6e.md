- The logo and sender read instantly — no "who is this?" friction

## What's weak

- Same-day sofa collision is a real problem: "bestselling sofas" already fired from this address on June 14, making "legendary comfort" feel like an outtake from the same shoot
- Zero offer signal — Pottery Barn dropped "100+ new sale styles UP TO 70% OFF" this week with actual numbers attached; C&B is sending pure editorial with no price hook, and that asymmetry makes me feel like I'm being sold *atmosphere*
- "Legendary comfort" is adjective soup — it tells me nothing I can act on; Article manages to do lifestyle copy that still has a specific tension ("summer hosting made simple" at least anchors to a use case)
- No quick-ship callout despite the renovation context — they sent a dedicated quick-ship email same day, but nothing in this email connects comfort to "available now" or "arrives by summer"
- The app download block near the footer is a distraction in a product-forward email and signals this template wasn't trimmed for this specific message

### 3. Rendering & Accessibility

**[HIGH] Conflicting `img` max-width media queries — confirmed overflow bug:**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
At viewports ≥ 768px both queries match. Declaration order gives the `640px` rule priority (declared later in the same `<style>` block), so desktop images are hard-capped at 640px rather than the intended 600px container — images will overflow a 600px layout container by 40px.

**[MEDIUM] `maximum-scale=1` on viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocks user pinch-zoom. Fails WCAG 1.4.4 (Resize Text, Level AA). Remove the attribute or raise to `maximum-scale=5`.

**[MEDIUM] Over-broad `-webkit-text-size-adjust` suppression:**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
Universal selector applies suppression to every element, not just `body`. Can override user accessibility font-scaling settings in WebKit mail clients. Scope to `body` only.

**[LOW] No dark mode support:** `color-scheme: light` / `supported-color-schemes: light` opts out of dark mode entirely. Apple Mail and Gmail will apply their own dark inversions unpredictably since no `@media (prefers-color-scheme: dark)` override is provided.

**[LOW] Duplicate `format-detection` declarations:** The combined meta tag (`telephone=no,address=no,email=no,date=no,url=no`) is re-declared individually three times. Harmless but adds template noise.

**[LOW] Duplicate charset declaration:** Both `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta charset="utf-8">` are present. Safe in practice.
