This is a build-time scaffolding comment that was never removed. The adjacent empty `<!---->` suggests the font import step was skipped entirely. Reveals template structure to source inspectors; indicates broken build/QA process.

**[HIGH] `<title>` brand mismatch:**
```html

```
Sender is "Crate & Kids" (`crateandkids@mail.crateandbarrel.com`). The `<title>` was not updated from the parent-brand template. Affects screen-reader announcements and some email client tab labels.

**[MEDIUM] `maximum-scale=1` disables pinch-to-zoom:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from zooming in on mobile — an accessibility failure for low-vision readers. WCAG 1.4.4 (Resize Text) requires content to be zoomable to 200%. Remove `maximum-scale=1`.

**[MEDIUM] Conflicting image `max-width` media queries:**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
Both fire at ≥768px; cascade order means `600px` wins at 768px+ (last rule loses to the earlier one since both match — actually the 768px block is declared first, so at ≥768px both apply and the later `640px` rule wins). Between 640–767px only the `640px` rule fires. At ≥768px: `600px` declared first, `640px` declared second → **640px wins**, which contradicts the intent of the 768px block. Either consolidate into one rule or swap declaration order.

**[LOW] `*{-webkit-text-size-adjust:none}` on universal selector:**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```
Applied globally rather than to `body` only. Can suppress iOS accessibility font scaling for users with visual impairments. Scope this to `body` or `table`.

**[LOW] Duplicate `format-detection` meta declarations:**
`format-detection` is declared four times — once with comma-separated values, then three more individual entries. Harmless but indicates copy-paste template drift.

**[INFO] `<!--V2-->` in opening `<html>` tag:**
Version marker is exposed in the rendered source. Use deployment metadata or email service provider template versioning instead of inline comments.
