## Technical Audit

## 1. Technical Summary
The visible markup is a standard Movable Ink/ESP table layout with no hard failures: the automated QA found 0 errors and 3 warnings, with a 57% pass rate. The main confirmed issues are widespread missing alt attributes, accessibility-hostile viewport and text-size meta settings, and an unescaped `&` in the `<title>`. Compliance and authentication could not be verified because the headers were not captured.

## 2. Link & Tracking Issues
- **Destinations unverified:** 97 tracking links were skipped by the HTTP probe because they sit on click-redirect domains. Link health and final destinations are therefore unconfirmed.
- **Third-party pixels:** five `https://sr.rlcdn.com/448796.gif?s=dbe8da71…&n=1` to `&n=5` beacons (LiveRamp) are embedded. Each carries the same hashed identifier in the `s=` parameter. Five identical calls per open is redundant.
- **Per-recipient tokens in image URLs:** `mi.crateandbarrel.com/p/rp/f3c0d22992a01946.png?mi_u=dbe8da71…` appears six times. `mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif` and `dv.crateandbarrel.com/o/6928c3cd-…?mi_cid=…&mi_mid=…` are the open and tracking pixels. They resolve as designed, but the images depend on live per-recipient rendering.
- **Image hosts:** assets load from `image.mail.crateandbarrel.com` and `s7d5.scene7.com`. The probe did not test them, so availability is unconfirmed.

## 3. Rendering & Accessibility
- **Missing alt text:** about 45 `<img>` warnings. Content images such as `…/m/1/f9756180-d90b-4a43-ba8b-f03ddd5d87b8.jpg` and `CK_H26_KidsHolidayMagic_24x13_Edit3_Tert` carry no alt. With images blocked, the email's product and offer content is unreadable to screen readers.
- **Decorative images:** the scene7 spacers (`25_MI_Bottom_Spacer_50px_White`, `…_40px_White`) and the tracking pixels (`o.gif`, `448796.gif`, `dv.crateandbarrel.com/o/…`) should carry an explicit `alt=""`. Some of the warnings may be false positives if `alt=""` is already present, since the checker doesn't distinguish.
- **Zoom disabled:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` blocks pinch-zoom.
- **Text resizing disabled:** `*{-webkit-text-size-adjust:none}` and `html{-webkit-text-size-adjust:none}` disable user text scaling in WebKit. The same stylesheet also sets `body{-webkit-text-size-adjust:100%}`, so the rules conflict.
- **Invalid markup:** `<title>Crate & Barrel</title>` has an unescaped `&`, which is invalid under the declared XHTML 1.0 Transitional doctype. It should be `&amp;`.
- **Template hygiene:**
  - Both `<meta http-equiv="Content-Type">` and `<meta charset>` are present.
  - `format-detection` is declared three times.
  - A leftover placeholder comment, `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->`, remains. This is harmless but shows an unfinished template.
- **Breakpoints:**
  - The mobile breakpoint is only `max-width:460px`, so mid-size viewports get the desktop layout.
  - `img{max-width:600px}` (≥768px) and `img{max-width:640px}` (≥640px) overlap, and the later rule wins.
- **Title:** `<title>` is the generic "Crate & Barrel". It does not match the subject line.
