### 3. Rendering & Accessibility

**[HIGH] `<title>` brand mismatch and invalid XHTML entity**
```html
<title>Crate & Barrel</title>
```
The sending brand is "Crate & Kids" but the `<title>` reads "Crate & Barrel" — wrong entity. In XHTML 1.0 Transitional (declared DOCTYPE), `&` must be encoded as `&amp;`. This produces invalid markup.

**[MEDIUM] `maximum-scale=1` blocks pinch-zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from zooming on mobile. WCAG 1.4.4 (Resize Text) violation; particularly harmful for low-vision readers in mobile email clients.

**[MEDIUM] Conflicting `img` max-width media queries — cascade inversion**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
On viewports ≥768px both rules fire, but the 640px query is declared later, so it wins the cascade — images are capped at **640px on desktop**, overriding the intended 600px container. The 768px rule is effectively dead code.

**[LOW] Duplicate `format-detection` meta tags**
`format-detection` is declared three times: once as a combined rule and then again individually for `date=no` and `address=no`. The `telephone=no` declaration appears both in the combined tag and as a standalone. Redundant but harmless.

**[LOW] `*{line-height: 100%}` applied globally**
A `line-height` of `100%` (equivalent to `1em`) on all elements — including headings — collapses leading to near-zero visual spacing. This is intentional in some email resets but causes readability issues if not overridden per-element in the body.
