### 3. Rendering & Accessibility

**`<title>` brand mismatch (confirmed):**
```html
<title>Crate & Barrel</title>
```
Sender is "Crate & Kids." This title surfaces in browser-tab email viewers and some VoiceOver/screen reader contexts. Should read "Crate & Kids."

**Zoom prevention — WCAG 1.4.4 violation (confirmed):**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
`maximum-scale=1` blocks user-initiated pinch-to-zoom. Violates WCAG 1.4.4 (Resize Text, Level AA).

**Global text-size-adjust suppression (confirmed):**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```
Applying this to the universal selector prevents OS-level accessibility text scaling on mobile. Scope should be `body` only, with value `100%` rather than `none`.

**Conflicting image max-width breakpoints (confirmed):**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
The 640px rule appears *after* the 768px rule in source, so at ≥768px both fire and the 640px rule wins via cascade order — images cap at 640px not 600px on desktop. If the container is 600px wide, images will overflow it. Rule order should be inverted or the 768px breakpoint dropped.

**Duplicate `format-detection` meta tags (confirmed, low severity):**
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
...
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
Three redundant single-attribute tags duplicate the omnibus tag above. Harmless but adds noise.
