# JUST got bigger! Up to 50% off + 2x Rewards!
**Score:** 8/10 · **Type:** Email audit · **2026-05-21**
## Executive summary

- Twenty-two. That number is not going away. This is — by my best count — somewhere around the twenty-second email from some configuration of the Crate & Barrel family since Sunday, and the thing that makes this one uniquely maddening is that I've already seen a Crate & Kids version of this *exact* send today. Different subject casing, same creative bones, same 50% off Memorial Day hook. I'm not imagining it — I audited an earlier Crate & Kids send this morning that hit a 9 on my own scale and had nearly identical hero copy.
- The email itself is clean. Sage-and-cream palette, readable hierarchy, that two-drawer dresser hero looks nice — genuinely nice. The 2x Rewards ribbon is visible, the "Shop Deals" CTA is unambiguous, and the product photography is the kind of soft-natural-light stuff that works well on mobile. If I needed children's furniture, this would be a solid send.
- I do not have children. The "just what you need for your growing family" section is doing a lot of heavy lifting for an audience I am apparently not part of. I'm renovating two *adult* homes simultaneously and Crate & Kids just served me cribs and changing tables. I'm going to mark this as read and feel a low-grade irritation for the rest of the morning.

## What's working

- The sage/cream color palette is genuinely on-trend and consistent with Crate & Kids' visual brand — cleaner than Wayfair's patriotic emoji flag from earlier this week.
- Up-front offer math: 50% off AND 2x Rewards in the hero without hunting for it. Article ran a similar Memorial Day push and buried the % below the fold — this doesn't do that.
- "Double Rewards to the Max — One More Day" section adds a credible time constraint that doesn't feel manufactured.
- The dresser in the hero is ambiguous enough that it briefly read as adult furniture — momentary visual hook before the "growing family" body copy killed it.
- No broken images, no lorem ipsum, no overlapping text. After the CB2 "Find your favorite new thing" mystery-product send from a few days ago, basic execution competence is actually notable.

## What's weak

- "Just what you need for your growing family" — I don't have a growing family. This is the hardest possible demographic miss, delivered at high confidence in the copy.
- This is a duplicate send. I audited a Crate & Kids version of this campaign earlier today. Same brand, same offer, same creative framework. Pottery Barn has been doing 18 sends in a row but at least they're cycling *different* products.
- The ALL-CAPS "JUST" in the subject is a low-grade spam signal that erodes the inbox trust I'd otherwise give a brand I recognize.
- The TheDesignDesk app section at the bottom feels like it belongs to a different email — it's a nice service but it's dropped at the tail end of a promotional blast for kids furniture. No connection to anything above it.
- Two "Shop Deals" CTAs in close vertical proximity with no product differentiation between them. One should have been product-specific.

## Recommendations

- 1. **Segment this list.** If I have never browsed or purchased children's products, the "growing family" send should never reach me. Pottery Barn's design-services email this week knew I was in a renovation context — this email has no idea who it's talking to.
- 2. **Kill the duplicate.** One Crate & Kids Memorial Day send per day, maximum. If the offer "just got bigger," suppress the prior version or send a one-line update, not a full creative re-blast.
- 3. **Make one CTA specific.** Replace one of the "Shop Deals" buttons with a linked product category — "Shop Cribs & Nursery" if you know I have kids, "Shop Dressers & Storage" if you're going adult. The Article send this week did this well with a specific product anchor.
- 4. **Lose the "JUST" all-caps.** Write it "Just got bigger!" — same urgency, less inbox-spam aesthetic.
- 5. **Preheader should lead with the deadline** — something like "Ends Monday: up to 50% off + earn double rewards."
- **Subject Alt A:** `Memorial Day sale ends Monday — 50% off + 2x Rewards`
- **Subject Alt B:** `Last day for double rewards: up to 50% off kids furniture`
- **Preheader Alt A:** `Ends Monday. Dressers, cribs, and bedding — up to half off with double rewards.`
- **Preheader Alt B:** `One more day to earn 2x Rewards on everything in the Memorial Day Event.`

### 3. Rendering & Accessibility

**`<title>` brand mismatch — confirmed bug**
```html
<title>Crate & Barrel</title>
```
Email sender is "Crate & Kids SALE." Screen readers (NVDA, JAWS, VoiceOver) announce the document title on load. This surfaces the parent brand instead of the sending sub-brand.

**Conflicting `img` max-width media queries — confirmed cascade bug**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
Because the `640px` query is declared *after* the `768px` query and both match at `≥768px`, the cascade gives `640px` the win on all desktop viewports. The intent appears to be 600px on desktop — this rule is never applied.

**`maximum-scale=1` blocks user zoom — WCAG 1.4.4 violation**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from zooming text on mobile. Fails WCAG 2.1 SC 1.4.4 (Resize Text, Level AA).

**`-webkit-text-size-adjust: none` in global `*` selector**
```css
* { -webkit-text-size-adjust: none; ... }
```
Applied globally, not scoped to layout elements. Overrides the `<body>`-level `100%` value set two rules earlier and can suppress iOS dynamic type adjustments across all text nodes.

**Duplicate `format-detection` meta tags**
`telephone=no`, `date=no`, and `address=no` each appear in both a combined tag and standalone tags. Redundant; harmless in practice but indicates stale template hygiene.

**Unflushed developer placeholder comments**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
<!---->
```
Both comments survived to production send. The first has a typo (`IMPUT` → `INPUT`) confirming it was a fill-in directive, not intentional markup.
