# Crafted to love & last
**Score:** 5/10 · **Type:** Email audit · **2026-06-05**
## Executive summary

- Fifty. We're at fifty C&B family emails in my inbox, and this one comes from the kids sub-brand — which is a tell before I even scroll. I'm renovating two homes right now, neither of which is a nursery. The hero is a softly lit kids' bedroom with natural wood beds and neutral bedding — genuinely beautiful photography, and if I had a six-year-old, I might have paused. But I don't, and the subject "Crafted to love & last" gave me zero signal that this was children's furniture. That's the core problem: the subject reads like a quality-positioning statement for any furniture, so I opened expecting clearance on a sofa or a dining table and landed in a kid's room.
- The email itself is clean and well-photographed. Multiple product sections, consistent warm palette, readable CTAs. Crate & Kids does a better production job here than most of the CB2 sale emails I've been wading through this week — there's no lorem ipsum, no layout breaks, no screaming "60% OFF" in a bolded header. But pretty doesn't solve the targeting miss. This is a well-dressed email that arrived at the wrong address.
- I'd mark as read without clicking. I wouldn't forward it — nobody on my current project has kids either.

## What's working

- **Photography quality is legitimately good** — the hero bedroom is aspirational in the way C&B does well, and the natural wood palette is consistent throughout.
- **No visual noise** — after a week of clearance emails with stacked discount callouts, the restrained layout is a relief. This reads like a brand email, not a fire sale.
- **Multiple product sections with clear CTAs** — the scroll-through structure gives me a few different entry points, so if something had matched my project, the path to click would've been obvious.
- **Subject line length is fine** — 22 characters, reads clean on mobile without truncation.
- **Consistent brand voice** — "Crafted to love & last" is a real positioning line, not filler copy.

## What's weak

- **Wrong sub-brand for my segment** — I'm on the main C&B list because I buy sofas and dining tables. Crate & Kids hitting my inbox means their segmentation is either off or nonexistent. Pottery Barn at least separates Pottery Barn Kids from the main send.
- **Subject is genre-agnostic** — "Crafted to love & last" tells me nothing about product category, offer type, or who this is for. Article's recent outdoor email — "Elevate your outdoor space" — is four words that close the brief. This could be a mattress brand tagline.
- **No offer in the subject or visible hero** — the Pottery Barn Summer Warehouse Sale email from this week had the deal front and center. Here I have to scroll before I find any price signal, and when I'm in fast-inbox mode I've already bounced.
- **Fifty emails** — I have to say it. The C&B family has sent so many promotional emails in the past week that I'm reading every one of them with a hand on the archive button. The cadence is eroding trust at a real rate.

## Recommendations

- 1. **Segment by life stage or purchase history** — if I've never bought a crib or a bunk bed from C&B, don't route me into the kids sub-brand sends. Pottery Barn Kids keeps its list clean; this should too.
- 2. **Put the category in the subject line** — even "kids' bedroom furniture, built to grow with them" tells me who it's for and saves me the wrong-open.
- 3. **Add a visible offer in the hero** — a "members save 10%" line or a free shipping threshold gives me a reason to scroll. Right now the hero is all mood and no hook.
- 4. **Dial back cadence** — one fewer email per week from the C&B family would make each send feel like less of a ticket to the archive.

### 3. Rendering & Accessibility

**`<title>` brand mismatch** (confirmed)
```html
<title>Crate & Barrel</title>
```
Sender identity is "Crate & Kids" but the document title reflects the parent brand. Screen readers and some email clients expose this value; it should match the sub-brand.

**`maximum-scale=1` blocks user zoom** (confirmed)
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Violates WCAG 1.4.4 (Resize Text). Remove `maximum-scale=1`.

**Conflicting `text-size-adjust` rules** (confirmed)
Three declarations are in scope simultaneously:
```css
/* block 1 — general settings */
* { -webkit-text-size-adjust: none; }

/* block 2 — client styling */
html { -webkit-text-size-adjust: none; }
body { -webkit-text-size-adjust: 100%; }
```
`body` overrides `*` for body text, but the `*` rule still applies to elements outside `body` and creates undefined behavior across clients. Standardize to `body { -webkit-text-size-adjust: 100%; }` only.

**Conflicting `img` max-width media queries** (confirmed)
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
At ≥768px both queries fire; the 600px rule wins due to source order, unintentionally capping images 40px narrower than the template width on desktop. The 768px block should be removed or set to `max-width: 640px`.

**Duplicate `format-detection` meta tags** (confirmed)
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
The first tag covers all suppression targets. The three subsequent tags are redundant dead weight; remove them.

**Duplicate charset declaration** (confirmed)
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta charset="utf-8">
```
Both are present. Keep the `http-equiv` form for Outlook compatibility; the `meta charset` shorthand is redundant here.

**Hard dark-mode opt-out** (confirmed)
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Forces light rendering in Apple Mail/iOS Mail even for users with system dark mode enabled. Apple Mail dark-mode inversion can produce worse results than a designed dark-mode alternative. Consider adding `dark` if a dark-mode variant exists, or accept Apple Mail's auto-inversion rather than hard-blocking it.

**Leftover template artifact** (confirmed)
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
<!---->
```
`IMPUT` is a typo for `INPUT`. The empty comment immediately after suggests a font block was removed but the placeholder comment was not cleaned up. No web font `@import` or `<link>` is present in the `<head>`, so the email falls back to system fonts — verify this is intentional.
