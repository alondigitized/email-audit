The "vintage beauty, modern performance" angle is actually a smart one-two punch: I want something that looks like it has a story but won't disintegrate under kids and dogs. ## 2. What stood out

The photography is doing the real work here. The living room and bedroom vignettes are styled well — that's the Crate & Barrel visual language I recognize and trust. The rugs read as genuinely new: the patterns have that distressed vintage look that's everywhere right now, and the color palette (warm taupes, dusty blues, ivory grounds) is current without being trendy-weird. If I'm being honest, the hero image is the best thing in this email; it made me slow down for a second and actually want to see more.

What pushed me back: the email runs long with no editorial spine. It's a scroll of vignette → product grid → vignette → product grid with nothing to anchor me. There's no clear "this is the one" hero product, no pricing visible, and no offer that gives me a reason to click now versus bookmark the site later. I'm also not seeing any signal that C&B knows I'm a customer — no "based on what you've been browsing" or member pricing callout. The app download module at the very bottom feels like an afterthought bolted on from a boilerplate template. And I'll admit — I've seen variations of the medallion-plus-neutral-ground rug in three brands' emails this week. That sameness is a Felix-specific annoyance: when Wayfair, Pottery Barn, and C&B all push nearly identical product aesthetics simultaneously, it erodes the "curated" premium feel that justifies C&B's prices.

### 3. Rendering & Accessibility

**`maximum-scale=1` blocks pinch-to-zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from zooming on mobile. Violates WCAG 1.4.4 (Resize Text). Remove `maximum-scale=1`.

**Conflicting `img` max-width media queries (wrong cascade order)**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }  /* declared second */
@media only screen and (min-width: 640px) { img { max-width: 640px } }  /* declared first */
```
At viewport ≥ 768 px, both rules match. Because the 768 px block is declared *after* the 640 px block, it wins the cascade — images cap at 600 px on wider screens rather than 640 px. Reverse declaration order or consolidate into one rule.

**Wildcard `-webkit-text-size-adjust: none` overrides user accessibility settings**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
Applying `none` on `*` prevents browsers from adjusting text size even when the user has configured larger default fonts. Scope this to `body` only, or use `100%` instead of `none`.

**Duplicate `charset` declarations**
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta charset="utf-8">
```
Redundant but harmless in practice. Remove the `http-equiv` form (XHTML legacy); keep the HTML5 `<meta charset>`.

**Duplicate `format-detection` declarations**
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
Three redundant single-value tags duplicate the first combined tag. No rendering impact, but indicates template hygiene issues.

**Unfired developer comment left in send**
```html

<!---->
```
Typoed placeholder (`IMPUT` → `INPUT`) was not removed before deployment. Signals this send went out with an unfinished template slot and an empty comment node.
