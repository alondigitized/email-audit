# 3 DAYS LEFT! Up to 60% off is going, going... nearly gone!
**Score:** 8/10 · **Type:** Email audit · **2026-07-05**
## Executive summary

- After five — maybe six — C&B sends on the Fourth alone, all pounding the same red "FINAL WEEKEND for up to 50% off" banner, I almost reflexed past this one entirely. What stopped me: the discount moved. 50% yesterday, 60% today. That's actual new information, not a reskinned hero. And the countdown timer in the dark-navy hero section is the first genuinely different creative element I've seen from this brand all weekend.
- But the subject line nearly torpedoed it. "3 DAYS LEFT!" in all-caps followed by "going, going... nearly gone!" is a real estate agent doing a clearance event — not a brand I've spent real money with. Article pulled a 9/10 from me on July 3rd by letting the deadline do the talking cleanly. Pottery Barn dropped an hourglass emoji and still felt more restrained than this. C&B wrote a sentence with three urgency devices in it and somehow made the offer feel more suspicious.

## What's working

- **The countdown timer is finally here** — after days of static "FINAL WEEKEND" copy, a live clock in the hero makes the deadline feel real. This is the move.
- **60% vs. 50% is a genuine escalation** — not the same offer repackaged. I noticed. That's a reason to look again at what I skipped yesterday.
- **Dark navy hero breaks the visual pattern** — after Tuesday's all-red, all-caps banners, this actually registers differently. The eye stops.
- **Product grid is well-organized** — I can see furniture categories laid out cleanly: living, dining, outdoor. Both of my renovations touch at least two of those.
- **Clean render throughout** — no broken images, no overlapping elements. C&B's layout discipline holds even at high send volume.

## What's weak

- **"Going, going... nearly gone!" is embarrassing copy** — the ellipsis drama does nothing except signal panic. The countdown timer already communicates urgency; this line just undercuts it.
- **All-caps + exclamation in the subject is a near-spam signal** — Pottery Barn ran "ONLY 48 HOURS LEFT TO SAVE ⏳" the same day and somehow felt more trustworthy. The emoji did more work than the all-caps screaming here.
- **This is email number six in 48 hours** — even with a better offer, the cadence is eroding trust. I'm not filtering yet, but this weekend moved me meaningfully closer to it.
- **Zero personalization visible** — I have purchase history and cart abandons with this brand. Showing me the same grid as a cold prospect wastes the relationship entirely.

## Recommendations

- 1. **Kill "going, going... nearly gone!" and replace with the actual deadline date** — "Sale ends July 8" does more work with zero melodrama. The countdown clock is already doing the urgency lift.
- 2. **Drop the all-caps in the subject** — the 60% number and "3 days" are strong enough. Caps just read as desperation.
- 3. **Make the countdown timer a direct link to "What's still 60% off"** — a live clock is a hook; send me to a curated landing page of what's actually in stock at the top tier, not the full sale homepage.
- 4. **Pull one personalized category into the hero subhead** — Article does this. If I've browsed outdoor dining in the last 30 days, lead with outdoor dining at 60% off. That's one hero, one click, one conversion.

### 3. Rendering & Accessibility

**Issue 3a — Duplicate `format-detection` meta tags (redundant, not harmful)**
The combined tag appears first, then three individual tags repeat the same directives:
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
This is harmless but adds ~160 bytes of dead markup. Template cleanup recommended.

**Issue 3b — Conflicting `text-size-adjust` rules**
Three competing declarations exist across two `<style>` blocks:
- MI block: `*{-webkit-text-size-adjust:none;}` (global wildcard)
- Client block: `html { -webkit-text-size-adjust:none; }`
- Client block: `body { -webkit-text-size-adjust:100%; }`

The body rule (`100%`) is the correct value for preventing iOS zoom on tap, but the wildcard `none` applied earlier overrides it. On some iOS clients this can cause unexpected zoom behavior on text-heavy sections.

**Issue 3c — Dead desktop media-query rule**
Two min-width breakpoints set `img { max-width }`, but their cascade order inverts the intent:
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }  /* declared first */
@media only screen and (min-width: 640px) { img { max-width: 640px } }  /* declared second — wins for ALL ≥640px */
```
For screens ≥768px, both rules match but the `640px` rule wins due to source order. The `600px` rule is effectively dead. If the 600px cap was intentional for wide viewports, the breakpoints need to be swapped or the 768px rule placed after.

**Issue 3d — `maximum-scale=1` in viewport**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents user-initiated zoom. WCAG 1.4.4 (Resize Text, AA) requires text be resizable to 200% without loss of content. Most email clients ignore this meta, but WebKit-based clients (Apple Mail, iOS Mail) respect it. Low-risk in practice for email, but worth removing.

**Issue 3e — Dark mode explicitly disabled**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
The email opts out of dark mode entirely. Apple Mail and Outlook on macOS will not apply automatic dark-mode inversion. This is a deliberate choice but means users in forced dark-mode environments will see the light background (`#e6e7e8`) unchanged, which may reduce readability depending on image content.
