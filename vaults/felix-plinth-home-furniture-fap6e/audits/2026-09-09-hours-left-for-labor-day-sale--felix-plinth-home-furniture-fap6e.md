## Technical Audit

1. Technical Summary
The email is a standard ESP-generated (CB2/mail.cb2.com) HTML campaign with heavy MSO/legacy support, but automated QA flags missing unsubscribe/authentication headers and multiple legacy HTTP ad-tracking pixels alongside widespread missing alt text.

2. Link & Tracking Issues
- 61 tracking/click-redirect links were present but skipped from HTTP probing (unable to confirm destination validity).
- Multiple legacy ad-network tracking pixels served over plain HTTP instead of HTTPS: `http://login.dotomi.com/ucm/UCMController?...`, and `http://ads.dotomi.com/cookieredir/2437/pub1.php` through `pub10.php`. Non-HTTPS resources are commonly blocked by mail clients (e.g., Outlook, Gmail image proxy) and may fail to fire, undercounting tracked conversions/attribution.
- Standard MI/CB2 open-tracking pixels (`mi.cb2.com/p/up/...`, `dv.cb2.com/o/...`) are HTTPS — no issue there.

- 8 content images missing `alt` text: `65deb545...gif`, `721de791...jpg`, `b034ce98...jpg`, `6b110dac...jpg`, `9bc8850d...jpg`, `d77f47da...jpg`, `2759d1db...jpg`, `3b5bafb0...jpg`, `3a0a3ed0...png`. This degrades accessibility for screen-reader users and leaves no fallback text when images are blocked (common default in Outlook/Gmail).
- Tracking pixels (UCMController, pub1–10.php, o.gif, dv.cb2.com/o/...) also lack alt text, which is standard/acceptable for invisible tracking pixels — not a real accessibility concern.
- Markup includes broad legacy MSO conditional comments and font-fix classes, indicating intentional Outlook/desktop-client support; no rendering-breaking issues surfaced in the QA data.

4. Personalization & Merge Tokens
No merge tokens or personalization placeholders were visible in the truncated source, and QA findings did not flag any unresolved tokens (e.g., `{{first_name}}`, `%%FIELD%%`). No issues found based on available evidence.
