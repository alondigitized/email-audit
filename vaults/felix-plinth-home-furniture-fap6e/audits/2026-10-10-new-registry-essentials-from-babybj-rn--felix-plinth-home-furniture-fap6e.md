## Technical Audit

## 1. Technical Summary
Table-based XHTML 1.0 Transitional email with mobile media queries and a lang attribute, sent from the `mail.crateandbarrel.com` subdomain. The QA run flagged missing alt text on about 40 images and could not capture the authentication or unsubscribe headers. The HTML was truncated, so the footer and link hrefs could not be inspected.

## 2. Link & Tracking Issues
- **Link validation not possible:** 82 links were skipped as tracking or click-redirect domains, so no destination status, redirect chain or 404 data exists. This is a coverage gap, not a confirmed defect.
- **Third-party pixels:** the source includes five `https://sr.rlcdn.com/448796.gif?s=…&n=1` to `n=5` beacons (LiveRamp). It also includes six repeats of `https://mi.crateandbarrel.com/p/rp/f3c0d22992a01946.png?mi_u=…`, an open pixel at `mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif`, and `dv.crateandbarrel.com/o/c3986fc4-…?mi_cid=…&mi_mid=…`.
  - The duplicate pixels add requests with no extra signal. The `rlcdn` beacons are third-party, which is relevant for privacy-focused clients and Apple Mail Privacy Protection.
  - These URLs carry a per-recipient hash (`mi_u=56aaa2787a…`) in the query string. This is normal for the ESP, but the hash is a stable identifier that is exposed to any proxy or log.
- **Animated assets:** the `scene7.com` assets `…HeroAnimationOnly…` and `…BOUNCERVIDEO_01…` appear to be animated or video-derived images. Check them for file weight and for fallback frames in Outlook, which shows only the first frame of a GIF.

## 3. Rendering & Accessibility
- **Missing alt text (QA-confirmed):** about 40 images have no alt attribute.
  - **Content images:** these include the hero animation (`2026%5F0916%5FCBK%5FBabybjorn%5FHeroAnimationOnly…`), the bouncer animation (`…BOUNCERVIDEO%5F01…`) and roughly 25 images under `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/*.jpg|gif|png`. With images blocked or a screen reader in use, the content is unavailable.
  - **Pixels and spacers:** the `rlcdn`, `mi.crateandbarrel.com`, `dv.crateandbarrel.com` and `25%5FMI%5FBottom%5FSpacer%5F40px%5FWhite` images are decorative or tracking. They should use `alt=""` so screen readers skip them. Absent alt can lead screen readers to read out the filename.
- **Viewport:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` sets `maximum-scale=1`, which blocks pinch-zoom. This is a WCAG 1.4.4 concern.
- **Title:** `<title>Crate & Barrel</title>` uses an unescaped `&`, which is invalid under the XHTML doctype (it should be `&amp;`). It is also generic: it is neither the subject nor the Kids brand.
- **Duplicate and conflicting markup:**
  - `<meta charset>` appears twice (once as `http-equiv` Content-Type and once as the HTML5 form).
  - `format-detection` is declared three times with conflicting values: the combined `telephone=no,address=no,email=no,date=no,url=no` and then separate `date=no`, `address=no` and `telephone=no` entries.
  - `*{line-height:100%}` and `p{margin:0 auto; text-align:center}` are global resets that can override inline styles in some clients.
- **Overlapping media queries:** `@media (min-width:768px){img{max-width:600px}}` is followed by `@media (min-width:640px){img{max-width:640px}}`. The later rule wins at equal specificity, so the 600px cap is dead code at ≥768px.
- **Template leftover:** the source still contains the placeholder comment `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->`. It is harmless but shows an unfinished template.
- **Positives:** `lang="en"`, the VML/Office namespaces and the MSO `PixelsPerInch` fix are present.
