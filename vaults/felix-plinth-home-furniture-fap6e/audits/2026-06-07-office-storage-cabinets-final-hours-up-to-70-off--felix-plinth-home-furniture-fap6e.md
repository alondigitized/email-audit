## What's working

- **The hero product actually matches the subject** — the tall cream display cabinet in the "picked just for you" grid is exactly what the subject promised, which is something Wayfair does not always deliver.
- **"ENDS TONIGHT" urgency reads as credible** — a visible countdown timer next to "FINAL HOURS" is a genuine call to act today; CB2's "NOW & FUTURE CLASSICS ON SALE" email used the same device and it worked on me.
- **70% off is front-loaded above the fold** — the discount claim lands before I scroll, which is how furniture sale emails should work.
- **Free & easy delivery over $35 is called out clearly** — for a storage cabinet order this is directly relevant, and Crate & Barrel would have buried it in footnote text.
- **Wayfair Rewards badge in the footer** — I'm a member and the reminder feeds the "buy on the highest-rewards card" calculation I run on every purchase.

## What's weak

- **Two Wayfair emails in one day** — I already opened "#kitchenmats" this morning. Sending a second one the same calendar day is how I end up writing a filter rule. This is the most punishable thing this email does.
- **ALL CAPS + three ❌ emojis** — this is the visual language of a brand I don't trust. It undercuts whatever "member access" positioning Wayfair is nominally going for.
- **Body pivots away from the promised category** — I opened for office storage cabinets and the lower half of the email is bath mats. Again. Fitness equipment has no business here.
- **No price anchors on the hero products** — the cabinet has a barely-legible "Was/Now" badge at this scale. CB2 ran full strike-through pricing on featured items; I need to see was $349, now $199, not "up to 70% off" in the abstract.
- **Category strips are a scatter blast** — wall art, lighting, fitness, tableware in an office storage email makes this feel like a clearinghouse dump, not a curated send targeted at someone who actually has two homes to furnish.

- 1. **One email per day, hard cap** — fire a suppression rule: if a Wayfair email already hit this address today, hold the second one until tomorrow. One well-timed send beats two that teach me to ignore both.
- 2. **Strip the off-category content** — cut fitness, tableware, and bath mats entirely. Keep storage, entryway organization, and maybe lighting as a coherent adjacent category.
- 3. **Show a price anchor on the hero** — "Was $349, now $209" converts faster than percentage-off math. Article does this on every hero product and I notice it every time.
- 4. **One ❌, not three, and sentence case the subject** — the triple emoji reads as a spam folder waiting to happen. One urgency signal is enough.
- 5. **Push Wayfair Rewards pricing into the body** — if member pricing exists on the hero product, surface it above the fold. Right now it lives in a footer badge that 80% of readers never reach.

### 3. Rendering & Accessibility

**Issue — Web font: single format only**
```css
@font-face {
  font-family: "Sofia";
  src: url(https://secure.img.wfrcdn.com/st4/stores/common/fonts/sofia/sofia_reg.woff) format("woff");
  mso-font-alt: "Arial"
}
```
Only WOFF is declared; no WOFF2 variant. WOFF2 is supported in all modern mail clients that honor `@font-face` and compresses ~26% smaller. Low severity but worth adding.

**Issue — Fixed-height mobile clipping risk**
```css
.ProductRec-stars, .ProductRec-shippingCopy { height: 16px }
.ProductRec-price { height: 40px; vertical-align: top }
.ProductRec-salesCopy { height: 28px; vertical-align: top }
.ProductRec-name { height: 48px !important }
```
Hard pixel heights on dynamic text containers will clip content if font scaling is active (user accessibility settings, large-text mode) or if a product name/price renders taller than expected. Overflow is not set to `hidden`, so behavior is client-dependent.

**Issue — Aggressive word-break on product names**
```css
.ProductRec-name { word-break: break-all; ... }
```
`break-all` breaks mid-character on non-CJK Latin text, producing visually broken words (e.g., "Sto-rage"). `overflow-wrap: break-word` (with `word-break: normal`) is the correct approach for Latin scripts.

**Minor — Duplicate media query blocks**
`@media only screen and (max-width: 480px)` is declared repeatedly for individual selectors rather than grouped. This inflates stylesheet size, though most clients parse it correctly.
