### 3. Rendering & Accessibility

**Confirmed issues:**

**a. Conflicting `img` max-width media queries**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
Both rules apply above 768px, but cascade order means the 768px rule (600px cap) wins over the 640px rule. For viewports 640–767px only the 640px cap applies. This is almost certainly unintentional — the 768px block should declare 640px or the rules should be consolidated.

**b. Wildcard `text-size-adjust: none`**
```css
* { -webkit-text-size-adjust:none; -ms-text-size-adjust:none; }
```
Applying `text-size-adjust:none` globally via `*` suppresses OS-level font scaling for users with accessibility needs. Should be scoped to `body` only, not `*`.

**c. `maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocks pinch-to-zoom on iOS/Android — an accessibility failure for low-vision users. Remove `maximum-scale=1`.

**d. `line-height: 100%` on wildcard selector**
```css
* { line-height: 100%; }
```
A computed value of 100% resolves to the element's own font-size, not the standard 1.5× reading default. This collapses line spacing on multi-line text blocks. Should be removed from the wildcard and set explicitly per text element.

**e. Duplicate `format-detection` meta tags**
The combined tag already covers all cases:
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
```
Three subsequent single-value tags (`date=no`, `address=no`, `telephone=no`) are redundant noise. Remove the duplicates.

**f. `<title>` mismatch**
```html
<title>Crate & Barrel</title>
```
Sender brand is "Crate & Kids" (`crateandkids@mail.crateandbarrel.com`). Title should read `Crate & Kids` to match the sub-brand and avoid confusion in screen readers / tab labels.

**g. Unfilled template placeholder comment**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
Developer scaffold comment with a typo ("IMPUT") was not removed before send. Harmless but indicates incomplete template cleanup.

**h. `color-scheme` locked to `light` only**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
No dark-mode CSS is declared. Apple Mail and Gmail dark mode will force-invert or re-color elements unpredictably. Intentional if dark mode was out of scope, but should be a documented decision.
