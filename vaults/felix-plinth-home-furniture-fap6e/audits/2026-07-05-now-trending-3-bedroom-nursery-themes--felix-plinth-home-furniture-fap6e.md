### 3. Rendering & Accessibility

**`<title>` brand mismatch — confirmed bug:**
```html
<title>Crate & Barrel</title>
```
Sender is "Crate & Kids" but the title tag says "Crate & Barrel". This surfaces in PDF saves, browser-rendered email previews, and some screen readers.

**Conflicting `img max-width` media queries:**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
Both rules fire at ≥768px. CSS cascade order means the 640px rule (declared last) wins at that breakpoint — images render 40px wider than the apparent intended 600px container cap on large displays.

**Duplicate `format-detection` meta tags:**
`telephone=no, address=no, email=no, date=no, url=no` appear once in a combined meta and then `date=no`, `address=no`, `telephone=no` repeat as individual metas. Redundant; no functional harm but signals sloppy templating hygiene.

**Viewport `maximum-scale=1`:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Disables pinch-to-zoom on mobile — fails WCAG 1.4.4 (Resize Text, AA). Common in email but worth flagging if accessibility compliance is a concern.

**Mobile breakpoint at 460px:**
```css
@media only screen and (max-width: 460px)
```
Standard breakpoint is 480px or 600px. At 461–479px (e.g., some Android devices), the layout falls through to desktop rules — possible layout break on mid-size phones.
