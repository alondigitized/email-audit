## Technical Audit

## 1. Technical Summary
The source is a table-based XHTML 1.0 Transitional email with dark-mode support and click tracking on SparkPost-style redirect domains. The confirmed defects are malformed dark-mode CSS, an empty `<title>`, and three images without alt text. The header-based compliance checks could not be verified (see section 5), and the HTML was truncated, so footer and body checks are incomplete.

## 2. Link & Tracking Issues
- **Wrapped links.** Links go through `post.spmailtechnol.com/q/.../AAQVbhA~/...` and `links.email.article.com/s/eo/...`. These are two different tracking hosts, and `spmailtechnol.com` is a third-party domain that doesn't match the sender domain `email.article.com`. This is a minor reputation and alignment concern, not a break.
- **Probe coverage gap.** Only 12 of 35 links were probed and 23 were skipped as footer, utility or social. No probe failures were reported, so no broken links are confirmed.
- **Destination URLs.** Because every link is redirect-wrapped, the final destinations can't be read from the source.

## 3. Rendering & Accessibility
- **Missing alt text.** The QA check flagged three `<img>` elements with no alt text:
  - `post.spmailtechnol.com/q/_ehWPlRwHLpfKh6kjLErpA~~/AAQVbhA~/kLP96f...`
  - `links.email.article.com/s/eo/dwYgSDhE70hx...`
  - `post.spmailtechnol.com/q/Rk7iJAxQ25BVgLdRY1AKsA~~/AAQVbhA~/2DIiThV...`

  Some of these may be tracking pixels, which should carry `alt=""` explicitly. The truncated source doesn't show their dimensions, so I can't tell.
- **Empty title.** `<title></title>` is empty. Screen readers and some clients use it, and it should hold the subject or preheader text.
- **Malformed dark-mode CSS** in the `@media(prefers-color-scheme:dark)` block:
  - `h1,h2,p,{color:#fff!important}` has a trailing comma. That makes the selector invalid, so the whole rule is dropped and headings and paragraphs don't get white text in dark mode.
  - `a{color:#fff;!important}` has a misplaced `!important`. The `color:#fff` still applies, but without the intended priority, so it can lose to inline styles.
  - The `@media` block is never closed. The source ends it with `a .link{color:#fff!important}</style>`, which closes the rule but not the media query. Browsers recover at the end of the style tag, but some clients may drop or mis-parse the block.
- **Inconsistent dark-mode overrides.** The `[data-ogsc]` block does correctly define `h1,h2,p` and `a`, so the Outlook.com dark-mode path is intact. The standard `prefers-color-scheme` path is the broken one.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens (`{{...}}`, `%%...%%`, `*|...|*`) appear in the visible source. The remainder of the HTML was truncated, so this only covers the visible portion.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe and List-Unsubscribe-Post** were not found. The QA note attributes this to the AgentMail relay possibly stripping them, so it can't be confirmed as a sender-side defect. Gmail and Yahoo bulk-sender rules require both headers (RFC 8058), so verify against the raw message from the original ESP.
- **Authentication-Results** was not found, so SPF, DKIM and DMARC are unknown. The QA note again attributes this to the relay. It's inconclusive and not evidence of failure.
- **Footer.** The footer, physical address and unsubscribe link are not in the truncated source, so I can't verify them. The QA tool says an unsubscribe link is always probed and reported no failure.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not verifiable. All links are redirect-wrapped, so the UTM parameters and final landing URLs aren't in the supplied source. No probe data on redirect destinations was provided.

## 7. Recommendations
1. Fix the dark-mode CSS:
   - Change `h1,h2,p,{` to `h1,h2,p{`.
   - Change `a{color:#fff;!important}` to `a{color:#fff!important}`.
   - Add the missing closing `}` for the `@media(prefers-color-scheme:dark)` block.
2. Add a meaningful `<title>`.
3. Add `alt=""` to the tracking and decorative images, and descriptive alt text to any content images, for the three flagged images.
4. Confirm `List-Unsubscribe` and `List-Unsubscribe-Post` and the SPF/DKIM/DMARC results on the raw original message. This is not a confirmed defect. Consider a custom tracking domain on `article.com` instead of `spmailtechnol.com`.
5. For the QA tooling, capture the full HTML and resolve redirect chains so UTM and landing-page checks can run. The reported 57% pass rate is mostly driven by the header warnings, which are relay artifacts and not email defects.
