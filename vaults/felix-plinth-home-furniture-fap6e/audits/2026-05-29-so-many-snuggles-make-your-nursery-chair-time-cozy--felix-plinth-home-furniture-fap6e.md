- **Offer surfaced immediately.** The 15% off callout is above the fold — I didn't have to hunt for it, which is more than I can say for half the Pottery Barn emails I've opened this week.

## What's weak

- **Complete persona mismatch.** I'm renovating a primary home and a second home simultaneously — neither has a nursery. Crate & Barrel has purchase history on me for adult furniture; this sub-brand segmentation bled into the wrong inbox.
- **Twelfth email this week from the C&B family — this is the one that tips into fatigued.** The earlier "60% off clearance" sends today from main C&B were actually relevant; this one resets me back to unsubscribe territory.
- **No adult crossover angle.** Article recently ran a "complete your home with new decor" email that was general enough to feel relevant even when I wasn't shopping a specific category. This email makes zero attempt to bridge to my actual context — not even a "shop all seating" link.

- 3. **Fix the subject line for any parent segment it does hit.** "So many snuggles" is soft and generic; a parent shopping for a glider wants to know the specific category and offer before they open.
- 4. **Surface the offer more concretely in the subject.** CB2 ran "NOW & FUTURE CLASSICS ON SALE" last week — still vague, but at least I know it's a sale. Lead with the number.

### 3. Rendering & Accessibility

**`maximum-scale=1` blocks user zoom (WCAG 1.4.4 violation)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Remove `maximum-scale=1`.

**Conflicting `img { max-width }` media queries**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
The 768px rule is declared after the 640px rule, so on viewports ≥768px the effective max-width is 600px — narrower than at 640–767px. Images will visually shrink on wider screens. The 768px rule should be removed or the order swapped.

**Dark mode not supported**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Explicitly opts out of dark mode. No `@media (prefers-color-scheme: dark)` block present. Text/image legibility on iOS/Apple Mail dark mode is unverified.

**Global `*` text-size-adjust suppression**
```css
* { -webkit-text-size-adjust: none; }
```
Applied to all elements, not just `body`. Can interfere with AT (screen readers, dynamic text scaling) on Android WebView clients.
