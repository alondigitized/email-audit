### 3. Rendering & Accessibility

**Issues found:**

| # | Issue | Evidence |
|---|-------|----------|
| 1 | **Viewport blocks user zoom** | `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` — `maximum-scale=1` prevents pinch-zoom; WCAG 1.4.4 failure |
| 2 | **Conflicting desktop `img` max-width rules** | Two `@media` blocks both set `img { max-width }` — `min-width: 768px` sets `600px`, `min-width: 640px` sets `640px`. At 640–767px viewport width both fire; cascade order determines outcome, likely unintentionally |
| 3 | **`line-height: 100%` on universal selector** | `* { ... line-height: 100% }` — overrides inline `line-height` on any element, including buttons and headings. Known to collapse text in some clients |
| 4 | **`-webkit-text-size-adjust: none` on `*`** | Forces no text scaling globally, not just on body. Prevents user accessibility overrides |
| 5 | **`showmobile` hardcodes `width:414px`** | `.showmobile { width:414px !important }` — device-specific pixel value; breaks on Plus/Pro/Max iPhone sizes and Android flagships |
| 6 | **No dark mode CSS** | `color-scheme: light` declared but no `@media (prefers-color-scheme: dark)` block. Will invert poorly in Apple Mail dark mode |
| 7 | **Duplicate `format-detection` meta tags** | `telephone=no`, `address=no`, and `date=no` each appear twice across two separate `<meta name="format-detection">` tags — redundant but harmless; indicates template sloppiness |
