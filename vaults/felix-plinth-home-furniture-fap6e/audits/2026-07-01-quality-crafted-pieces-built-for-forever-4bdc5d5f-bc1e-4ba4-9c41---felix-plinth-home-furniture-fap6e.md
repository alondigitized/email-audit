### 3. Rendering & Accessibility

**Conflicting `img` max-width media queries (confirmed bug)**
Two desktop MQs are declared in source order:
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }  /* declared first */
@media only screen and (min-width: 640px) { img { max-width: 640px } }  /* declared second */
```
At any viewport ≥768px both rules match; the later 640px rule wins the cascade, capping images at **640px, not 600px**. The 768px rule is effectively dead. Intended behavior is unclear but the ordering is wrong regardless.

**`maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents user pinch-zoom on mobile. Violates WCAG 1.4.4 (Resize Text, AA). Remove `maximum-scale=1`.

**Global `-webkit-text-size-adjust: none` on `*`**
```css
*{ -webkit-text-size-adjust:none; -ms-text-size-adjust:none; }
```
The `none` value (not `100%`) on a universal selector disables all automatic text scaling in WebKit clients. Should be scoped to `body` and set to `100%`.

**`<title>` brand mismatch**
```html
<title>Crate & Barrel</title>
```
Sender is "Crate & Kids"; some clients (Gmail web, Apple Mail) surface the document title in the tab or preview. Should read "Crate & Kids".

**Dark mode: light-only declared**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
No `dark` value declared. Dark-mode clients (Apple Mail, iOS Mail) may auto-invert colors unpredictably instead of respecting authored styles.

**Duplicate `format-detection` meta tags**
The combined declaration and three individual declarations of `format-detection` are redundant. Harmless but indicates template hygiene issues.
