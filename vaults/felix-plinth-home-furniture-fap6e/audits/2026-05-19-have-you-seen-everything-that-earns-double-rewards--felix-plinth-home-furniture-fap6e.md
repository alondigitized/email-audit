# Have you seen everything that earns Double Rewards?
**Score:** 7/10 · **Type:** Email audit · **2026-05-19**
## Executive summary

- I've lost count. This is either the twelfth or thirteenth email from the Crate & Barrel family in the last 48 hours, and it's from Crate & Kids — again. I don't have children. I have two homes I'm renovating simultaneously, both of which could genuinely use Crate & Barrel product right now, and instead I'm looking at bunk beds, toddler bedding, a child perched in a loft, and what appears to be a playroom styled to look like an adult living room. Double Rewards is the hook — and fine, I'm a member, I care about that — but the entire visual catalog is pointed at a life stage I'm not in.
- What kills me is that the earlier Crate & Kids send today — the "1000s of items on sale" one — already burned this exact creative on me: toddler imagery, Memorial Day scaffolding, kids' furniture framed as a rewards opportunity. This is the follow-up to a send I already didn't click. If the algorithm knew I was in the Double Rewards program, it had every opportunity to show me a sectional or a dining table. It showed me a loft bed instead.
- I'll mark it read. I won't click. I won't forward it — unless it's to a parent friend as a "hey, C&K is running double rewards," which is word-of-mouth for *them*, not for me.

### 3. Rendering & Accessibility

**`maximum-scale=1` in viewport meta restricts user-initiated zoom:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
This blocks pinch-to-zoom on mobile, which is an accessibility failure (WCAG 1.4.4). While common in legacy email templates, it is flagged here because several major email clients (iOS Mail, Samsung Mail) now honor this restriction.

**Conflicting responsive image breakpoints — potential clipping on desktop:**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
Both rules fire on viewports ≥ 768px. The 768px rule (`max-width: 600px`) is declared first and the 640px rule (`max-width: 640px`) declared second — cascade order means 640px+ screens get `max-width: 640px`, but 768px+ screens also get `max-width: 640px` (the second rule wins due to source order). If the intended desktop container is 600px, images will render up to 640px wide on all screens ≥ 640px, potentially overflowing the 600px wrapper.

**Dark mode suppression with no fallback:**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Forcing light mode only without any dark mode style block means Apple Mail and supported clients will either reject dark mode or forcibly invert colors. Not a bug per se, but confirm this is intentional — if dark mode color inversion is occurring in QA screenshots, adding a minimal `@media (prefers-color-scheme: dark)` block would fix it.
