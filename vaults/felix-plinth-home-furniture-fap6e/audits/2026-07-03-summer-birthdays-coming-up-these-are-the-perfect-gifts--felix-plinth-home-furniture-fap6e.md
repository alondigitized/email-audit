### 3. Rendering & Accessibility

**`maximum-scale=1` in viewport meta** blocks user zoom on mobile — an accessibility regression:
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Remove `maximum-scale=1` or replace with `initial-scale=1` only.

**Conflicting desktop image constraints** — two `min-width` media queries both fire at ≥768px, and the later-declared (lower) value wins:
```css
@media only screen and (min-width: 640px) { img {max-width: 640px} }  /* declared first */
@media only screen and (min-width: 768px) { img {max-width: 600px} }  /* overrides at 768px+ */
```
At 768px and above, images are capped at 600px, not 640px. If the template is 640px wide, this clips content in some desktop clients. Consolidate to one rule.

**Duplicate `format-detection` meta tags** — `telephone=no`, `address=no`, and `date=no` are declared twice: once in the combined tag and again individually. Redundant but harmless; clean up to reduce parse noise.

**Image `alt` text** — cannot verify from truncated source. Must confirm all `<img>` tags carry non-empty `alt` attributes.

**`<title>` tag mismatch** — the document title reads `Crate & Barrel`, not `Crate & Kids`. Some email clients surface `<title>` in tab labels or accessibility trees:
```html
<title>Crate & Barrel</title>
```
