## What's working

- **60% is a real number.** Yesterday's 30% was a decent offer; 60% is the kind of discount that opens a browser tab with actual purchase intent behind it.
- **Double Rewards is front and center.** I'm always running the rewards stack math — C&B Rewards on top of my card multiplier is tangible savings, and it's right there in the subject.
- **Multi-category layout fits a renovator's shopping mode.** Cookware, living room, bedroom all in one scroll mirrors how I'm actually buying right now across two houses. Accidental but useful.
- **Clean render throughout.** No broken images, no orphaned blocks, no lorem ipsum. Technically solid. Compared to some of the Wayfair rug emails this week, which had visual hierarchy that collapsed on mobile, this holds up.
- **"Ends Tonight" urgency is earned.** It's Memorial Day close — this is true, not manufactured, and I know it.

## What's weak

- **The offer escalation erodes trust in the whole week.** 30% yesterday, 60% today — Pottery Barn ran at 60% all weekend and let the deadline do the urgency work. C&B's ratcheting approach makes me wonder what tomorrow looks like if I wait.
- **No product hero.** This is a department-store catalog email. I've clicked C&B product pages this week. They know what I looked at. A "that sectional you saved is now 60% off tonight" email would absolutely convert. Instead I get everything and nothing.
- **Decision paralysis from the multi-section scroll.** Cookware, outdoor, bedroom, living room — CB2's "NOW & FUTURE CLASSICS ON SALE" at least committed to an aesthetic POV. This is the kitchen sink.
- **Demographic targeting is completely generic.** The lifestyle imagery reads aspirational-neutral. Nothing here signals "we know you're a 36-year-old guy actively making renovation decisions on two properties." Treated like a stranger.

## Recommendations

- 1. **Lead with behavioral personalization.** If they know what I browsed — and they do — the hero should be that specific piece at 60% off with a single CTA. One product, one price, one button.
- 2. **Flatten the discount narrative across the week.** Start at 60% on Thursday and let "Ends Tonight" do the work on Monday. Poker-style escalation from 30% to 60% in 24 hours trains subscribers to ignore early sends.
- 3. **Give the Rewards message teeth.** "Double Rewards" means nothing without my balance or tier context. "You're 400 points from [tier] — tonight's 60% off gets you there" would make me feel like a known customer instead of a broadcast target.
- 4. **Rethink the cadence.** ~50 emails from the C&B family since Sunday. This email would score meaningfully higher if my inbox weren't this saturated.

### 3. Rendering & Accessibility

**`maximum-scale=1` blocks user zoom (accessibility failure)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users with low vision from pinching to zoom on mobile. WCAG 1.4.4 violation. Remove `maximum-scale=1`.

**Dead CSS rule — `min-width: 768px` image constraint never fires**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
At any desktop width (≥768px), both queries match. The later `min-width: 640px` rule wins via cascade, pinning images at 640px. The 600px rule is dead code. Either intended behavior is 640px (remove the 768px block) or it's inverted and should be `max-width: 600px` in the 640px block.

**Dark mode not declared**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Light-only declaration forces light rendering in Apple Mail and iOS Mail dark mode via forced inversion, which can make white backgrounds appear black and invert image colors. If dark mode styles are not included in the body, this is the correct defensive choice — but should be documented as intentional.

**Duplicate `format-detection` meta tags**
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
...
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
Three individual declarations repeat values already set in the combined tag. Harmless but adds ~200 bytes of dead markup per send.

**Overly broad `*` selector in CSS**
```css
* { -webkit-text-size-adjust:none; -ms-text-size-adjust:none; max-height:1000000px; mso-line-height-rule:exactly; line-height: 100% }
```
`line-height: 100%` applied globally can collapse multi-line text to single-line in certain clients. `line-height` should be scoped to specific selectors, not `*`.
