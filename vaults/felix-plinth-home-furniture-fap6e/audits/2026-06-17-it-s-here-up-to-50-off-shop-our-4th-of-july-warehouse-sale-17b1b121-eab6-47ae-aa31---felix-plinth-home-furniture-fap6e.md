### 3. Rendering & Accessibility

**Confirmed issues:**

- **`<title>` brand mismatch** — `<title>Crate & Barrel</title>` in a *Crate & Kids* send. Screen readers announce this as the document title; it also appears in some email clients' tab bars.

- **Unstripped template placeholder** — Raw scaffolding comment survived into production:
  ```html
  <!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
  ```
  The typo ("IMPUT") confirms this is unreplaced boilerplate, not intentional. Any font import that was supposed to go here was omitted.

- **Conflicting desktop image breakpoints** — Two `@media` rules both set `img { max-width }` for desktop, in the wrong order:
  ```css
  @media only screen and (min-width: 768px) { img { max-width: 600px } }
  @media only screen and (min-width: 640px) { img { max-width: 640px } }
  ```
  At `≥768px` both rules match; cascade order means the *second* rule (640px) wins — images are allowed up to `640px` at desktop widths. At `640–767px` only the second rule applies, also `640px`. The `768px` rule is effectively dead. Likely intended to be the other way around (larger screens, wider images), or the `768px` rule is vestigial.

- **`maximum-scale=1` on viewport** — `<meta name="viewport" content="..., maximum-scale=1" />` blocks user-initiated zoom. WCAG 1.4.4 (Level AA) requires content to be resizable up to 200% without loss of content. Some email clients strip this, but Apple Mail and some WebKit-based clients honor it.

- **Duplicate `format-detection` declarations** — The combined declaration appears first, then individual ones for `date=no`, `address=no`, and `telephone=no`. No functional impact but is dead markup.

- **Duplicate `charset` declaration** — Both `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` and `<meta charset="utf-8">` are present. Redundant; harmless.

- **Dark mode not supported** — `<meta name="supported-color-schemes" content="light">` opts out entirely. No `@media (prefers-color-scheme: dark)` block visible. Apple Mail and some Android clients will force-invert without explicit dark styles.
