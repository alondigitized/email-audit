# Refresh their room & earn Double Rewards →
**Score:** 8/10 · **Type:** Email audit · **2026-05-22**
## Executive summary

- Twenty-seven. I'm pretty sure this is twenty-seven from the Crate & Barrel family since Sunday, and it lands in my inbox maybe forty minutes after "All the things to finish their dream room" — which itself had nearly identical subject architecture: "Refresh their room" versus "all the things to finish their room." Same brand, same day, same rewards hook, same room. At this point the Double Rewards carousel has lapped itself.
- Here's the category problem: I don't have kids. I'm running two simultaneous renovations — sectionals, dining chairs, kitchen hardware, outdoor furniture — and Crate & Kids is a brand I know and respect, but it is not where I'm spending this season. If my purchase history skews adult furniture across Crate & Barrel and CB2, this email should not be reaching me on loop. Article ran a single "Up to 40% off ends Monday" send last week and outperformed this entire Tuesday cadence for a reason: one clear message, one deadline, done.
- The execution itself is cleaner than it has any right to be given the circumstances. "Get upgrades in days, not weeks" is genuinely good renovation-era copy — delivery lead times are a real anxiety right now — and the visual hierarchy works. But clean execution in the wrong category, on the fourth send of the day, is a dead end. I'm marking this read.

## What's working

- "Get upgrades in days, not weeks" in the hero is the best line in the email — delivery speed is a live purchase signal for anyone mid-project and it actually landed for me even though the products aren't mine right now.
- Visual hierarchy is solid: hero leads, product grid follows, rewards callout mid-email, app push at the bottom — eye follows without friction.
- No render bugs, no broken images, no layout collapse — this renders cleanly at mobile width.
- Double Rewards is visible and prominent; it reads as a real benefit, not buried fine print the way some loyalty programs are handled.
- Crate & Kids brand identity is consistent throughout — photography, palette, and logo treatment are all on-model.

## What's weak

- Fourth C&B family email today, and the subject rhymes structurally with the one sent a few hours prior — "All the things to finish their dream room" and "Refresh their room" are the same brief in two fonts.
- "Their room" assumes I have a child. No behavioral signal on my account should suggest that, and sending a kids catalog in volume to adult-furniture buyers is segmentation malpractice.
- The Double Rewards pitch has appeared on at least three C&B family emails today; CB2 paired an actual discount with its program benefit in "NOW & FUTURE CLASSICS ON SALE" and it landed cleaner because there was a concrete anchor.
- No specific percentage off visible — "earn Double Rewards" is a loyalty multiplier, not a savings offer. Pottery Barn's "Extra 20% off select styles" from earlier this week told me exactly what I was getting.
- The cadence has eroded the trust signal entirely. Even a good offer stops reading as urgent when it arrives four times in one day.

## Recommendations

- 1. **Kill the fourth send.** This email shouldn't exist separately. Consolidate the day's Crate & Kids sends into one email with a real deadline and a clear product hero. The cadence problem is the root cause — nothing downstream fixes it.
- 2. **Lead with a specific dollar or percentage off.** Double Rewards is not a discount. Article's "Up to 40% off ends Monday" is the benchmark this week — number, deadline, done. Tell me what the rewards multiplier is worth in dollars or pair it with a base sale percentage.
- 3. **Make "get upgrades in days, not weeks" the preheader, not a buried hero aside.** That line is doing real work — move it to where it gets read before the open, not after.
- 4. **Segment on purchase behavior, not brand family proximity.** If I've never bought from Crate & Kids, route me to the adult catalog. If there's a kids-purchase signal, use it. If not, don't guess.
- **Subject Alt A:** `Kids' room refresh: ships in days + Double Rewards`
- **Subject Alt B:** `New arrivals, fast delivery — plus earn 2x Rewards`
- **Preheader Alt A:** `No waiting weeks — kids' room upgrades arrive fast, plus earn Double Rewards on every order.`
- **Preheader Alt B:** `Up to [X]% off + earn 2x Rewards. Fast shipping, no guessing on lead times.`

### 3. Rendering & Accessibility

**[HIGH] `maximum-scale=1` blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. WCAG 2.1 SC 1.4.4 (Resize Text) failure. Many accessibility scanners flag this automatically. Remove `maximum-scale=1` or replace with `maximum-scale=5`.

**[MEDIUM] Conflicting `text-size-adjust` declarations**
The first `<style>` block sets:
```css
body { -webkit-text-size-adjust: 100%; -ms-text-size-adjust: 100%; }
```
A later rule in the same block overrides it globally:
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
The `*` selector wins. The `body` rule is dead code. In some clients this can cause text to render at unexpected sizes. Consolidate to one intentional value on `body` and remove from `*`.

**[MEDIUM] Desktop image `max-width` media queries conflict**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
Source order means the 768px rule overrides the 640px rule for viewports ≥768px. Result: images cap at 640px on tablets (640–767px) but shrink to 600px on full desktop (≥768px). This is almost certainly inverted intent. Swap the source order or set the 768px rule to `max-width: 640px` if 640px is the intended maximum.

**[LOW] Duplicate `format-detection` meta tags**
`telephone`, `address`, and `date` suppression appear twice each (once in the combined tag, once individually). Harmless but indicates template drift between the boilerplate block and the client-added block.

**[LOW] `line-height: 100%` on `*` selector**
```css
* { line-height: 100%; }
```
Applied globally, this collapses line-height to font-size for every element. Clients that don't support `mso-line-height-rule: exactly` may render text tighter than designed. Consider scoping to `table td` instead of `*`.
