### 3. Rendering & Accessibility

**Issue — Conflicting `img` `max-width` media queries (confirmed):**

```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```

Both rules match viewports ≥ 768px. CSS cascade applies the 600px rule (declared later), overriding the 640px rule. On desktop clients that honor both blocks, images are constrained to 600px even inside a 640px container, potentially causing right-side clipping or misalignment.

**Issue — `maximum-scale=1` in viewport meta (confirmed):**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

Blocks user-initiated zoom. Fails WCAG 1.4.4 (Resize Text, Level AA). Some mobile clients ignore this, but it is a confirmed accessibility defect.

**Issue — Light-mode only (confirmed):**


Email explicitly opts out of dark mode. No `@media (prefers-color-scheme: dark)` override is present. Text and image assets will not adapt; confirmed risk of low-contrast rendering in Apple Mail and Gmail dark mode on iOS/Android.
