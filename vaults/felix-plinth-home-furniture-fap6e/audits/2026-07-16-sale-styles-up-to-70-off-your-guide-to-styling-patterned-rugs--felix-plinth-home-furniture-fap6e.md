### 3. Rendering & Accessibility

**PHP `header()` calls rendered as raw CSS text**
```html
<style>
  ...
  header('Content-Type: image/jpeg');
  header("Cache-Control: no-store, no-cache, must-revalidate, max-age=0");
  header("Cache-Control: post-check=0, pre-check=0", false);
  header("Pragma: no-cache");
</style>
```
These are PHP server-side directives that were never executed — they landed verbatim in the `<style>` block. They parse as invalid CSS selectors and will generate CSS parse errors in strict clients. This is a template/build pipeline defect.

**Empty `<title>` tag**
- `<title></title>` — blank. Some clients (notably Gmail web) display the title in tab/window labels; this is a missed surface.

**`maximum-scale=1` in viewport meta**
- `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` — suppresses user zoom. This fails WCAG 1.4.4 (Resize Text) and is flagged by accessibility auditors.

**38 images missing `alt` text**
Notable missing alt instances:
- `F26_TOP_SummerSalePartC_NoUrgency.jpg` — hero banner (primary CTA surface)
- All 12 `slices_01.jpg`–`slices_12.jpg` in the rugs editorial section
- All 18 footer slices (`Email-Footer/slices_01.jpg` through `slices_18.jpg`)
- Product images: `farmhouse-platform-bed-l.jpg`, `hydrocotton-quick-dry-towel-l.jpg`, `belgian-flax-linen-duvet-cover-2-l.jpg`, etc.
- `F26_Bottom_NewArrivals.jpg`, `S26_Bottom_UpTo60OffOutdoor.jpg`

Clients with images disabled will render blank for the entire email body and footer.

**3 HTTP (non-HTTPS) image sources**
These may be blocked by security-conscious clients (Gmail, Outlook.com):
- `http://edm.westelm.com/we/evergreen/spacer_0.gif`
- `http://edm.potterybarn.com/pb/thekey/CC_Banner/PB/Foot_NonMem_PB.jpg`

The HTTP open-tracking pixel is particularly high-risk: if blocked, open-rate data for this send will be undercounted.
