### 3. Rendering & Accessibility

**[HIGH] `maximum-scale=1` prevents pinch-to-zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocks user-initiated zoom in mobile browsers. WCAG 1.4.4 failure. Remove `maximum-scale=1`.

**[MEDIUM] Conflicting desktop image breakpoints**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
The 768px rule is declared *after* 640px but targets a larger minimum — on screens ≥768px both rules apply and specificity is equal, so the last declared wins (600px). This likely silently caps desktop images 40px narrower than intended. Reorder or consolidate into a single breakpoint.

**[MEDIUM] Blanket `*` line-height override**
```css
* { line-height: 100% }
```
Applied universally, this flattens line-height on all elements including headings and body copy. Known to collapse multi-line text in Outlook. Should be scoped to specific elements.

**[LOW] Hardcoded mobile width in `.showmobile`**
```css
.showmobile { width: 414px !important; }
```
Hardcodes iPhone 6/7/8 portrait width. Devices narrower than 414px (SE 1st gen = 320px) will overflow or clip this element.

**[LOW] Alt text not assessable** — HTML truncated before `<img>` tags. Verify all product images have descriptive `alt` attributes; decorative spacers should have `alt=""`.
