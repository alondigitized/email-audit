### 3. Rendering & Accessibility

**Issue — Conflicting desktop `img max-width` media queries (cascade collision):**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }  /* declared first */
@media only screen and (min-width: 640px) { img {max-width: 640px} }  /* declared second — wins at ≥640px */
```
At viewports ≥768px, both rules fire. Cascade order means the 640px breakpoint rule wins, capping images at 640px even on wide desktops — overriding what appears to be intentional 600px sizing for a mid-range breakpoint. These should either be separated with non-overlapping ranges or the 768px rule should be declared last.

**Issue — `maximum-scale=1` blocks user zoom:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Violates WCAG 1.4.4 (Resize Text, Level AA).

**Issue — Aggressive `text-size-adjust: none` on wildcard selector:**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
Later overridden to `100%` on `html` only, but the `*` rule still applies to all child elements in some WebKit clients, suppressing browser-initiated text scaling entirely.

**Issue — No dark mode support declared:**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Opt-out of dark mode is intentional here, but with background `#e6e7e8` hardcoded on `body`, content may render with low contrast in clients that force dark mode regardless (Apple Mail on macOS).

**No issues found** — duplicate `format-detection` meta tags (telephone, address, date declared twice) are redundant but harmless.
