### 3. Rendering & Accessibility

**Brand/title mismatch (confirmed):**
```html
<title>Crate & Barrel</title>
```
The sender is "Crate & Kids" but the document `<title>` reads "Crate & Barrel". This surfaces in Gmail's web view tab title and any webview-based email client.

**Duplicate `format-detection` meta tags (confirmed):**
The first meta already suppresses all detectors, but three additional single-attribute versions follow — redundant and inconsistent:
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<!-- then separately: -->
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```

**Conflicting `img max-width` media queries (confirmed):**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
The 640px block appears *after* the 768px block in source. At viewports ≥768px, the 640px rule wins (cascade order), capping images at 640px instead of the intended 600px.

**`maximum-scale=1` blocks user zoom (confirmed):**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Fails WCAG 1.4.4 (Resize Text, Level AA). Users who rely on browser zoom to read small text cannot do so.

**Aggressive universal selector resets (confirmed):**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; max-height:1000000px; line-height: 100%}
```
Applying `line-height: 100%` to `*` is known to break list rendering in Outlook and Apple Mail. The `max-height` hack and text-size-adjust suppression should be scoped to `body` or `table td`, not `*`.

**Dark mode explicitly disabled (confirmed):**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Intentional, but will force a white background in Apple Mail dark mode rather than adapting — confirm this is deliberate.
