### 3. Rendering & Accessibility

**[HIGH] `maximum-scale=1` blocks pinch-to-zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users (including those with low vision) from zooming in. Drop `maximum-scale=1`.

**[MEDIUM] Conflicting desktop `img` max-width rules — smaller breakpoint wins**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
Both rules match viewports ≥ 768 px. Because the 640 px rule is declared last, it overrides the 768 px rule everywhere on desktop — the intended 600 px cap is dead code. Either collapse to a single rule or swap declaration order.

**[MEDIUM] Global `* { line-height: 100% }` and `* { -webkit-text-size-adjust: none }`**
```css
*{ -webkit-text-size-adjust:none; ... line-height: 100% }
```
Applying `line-height: 100%` to `*` collapses multi-line text in several Outlook versions and some Android clients. Scope these to `td, p, span` instead.

**[LOW] Duplicate `format-detection` meta tags**
`telephone=no`, `address=no`, and `date=no` each appear twice in `<head>`. Redundant but harmless; worth cleaning to avoid parser confusion.

**[LOW] `<title>` brand mismatch**
```html
<title>Crate & Barrel</title>
```
Sender is "Crate & Kids"; some clients (notably Gmail's web UI) display the `<title>` value. Should read `Crate & Kids`.
