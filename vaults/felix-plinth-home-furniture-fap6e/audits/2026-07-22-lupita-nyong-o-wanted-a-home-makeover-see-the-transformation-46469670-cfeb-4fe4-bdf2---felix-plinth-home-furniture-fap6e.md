### 3. Rendering & Accessibility

**`maximum-scale=1` in viewport meta** — prevents users from pinching to zoom. Fails WCAG 1.4.4 (Resize Text). This is the single most actionable accessibility defect visible in this source.
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

**`-webkit-text-size-adjust: none` applied globally** — the `*{}` rule disables browser text scaling system-wide, compounding the zoom issue above.
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```

**Dead `min-width: 768px` breakpoint** — the 768px img rule is always overridden by the 640px rule that follows it in source order. On screens ≥ 768px, both queries match and cascade gives 640px the win, making `max-width: 600px` unreachable.
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }  /* dead */
@media only screen and (min-width: 640px) { img {max-width: 640px} }  /* always wins */
```

**Dark mode not supported** — `color-scheme` is hard-coded to `light` only. Clients that force dark mode (Apple Mail, Outlook 2021+) may invert unintended elements.
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```

**Duplicate `format-detection` meta tags** — the combined tag already covers all values; the three individual tags below it are redundant (harmless but noisy).
