### 3. Rendering & Accessibility

**Confirmed issues:**

**Web font will not render in most clients.**
```css
@font-face {
  font-family: "Sofia";
  src: url(https://secure.img.wfrcdn.com/st4/stores/common/fonts/sofia/sofia_reg.woff)
  mso-font-alt: "Arial"
}
```
Web fonts are blocked in Gmail (all platforms), Outlook Windows, Yahoo Mail, and Samsung Mail — the majority of commercial email volume. The `mso-font-alt: "Arial"` fallback handles Outlook but is non-standard (should be inside `font-face` descriptor as `mso-generic-font-family`). Confirm all typography degrades acceptably to the system font stack.

**`<head>` `<style>` block stripped by Gmail.**
All responsive rules (`@media`, `.u-FullWidth`, `.u-HalfWidthBlock`, etc.) are in a `<head>` `<style>` block. Gmail web strips `<head>` styles entirely. The Gmail-specific hack (`u + .Gmail`) is present and correct but only patches a narrow subset of rules. Product grid, button padding, and font-size overrides at mobile widths will not apply for Gmail webmail users.

**`word-break: break-all` on `.ProductRec-name`:**
```css
.ProductRec-name { word-break: break-all; ... }
```
This breaks words at any character boundary, not just word boundaries. Can produce visually broken product names (e.g., "Kitchen Fauce-ts"). Prefer `overflow-wrap: break-word` or `word-break: break-word`.

**`@supports (-webkit-touch-callout: none)` in media query:**
iOS-only inline image override. Valid client-hack pattern; no issue beyond noting it targets only iOS Safari.

- Table `role="presentation"` on layout tables
