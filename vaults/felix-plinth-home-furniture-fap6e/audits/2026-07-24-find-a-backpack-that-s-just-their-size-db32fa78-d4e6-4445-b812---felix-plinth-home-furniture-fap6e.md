## Technical Audit — Crate & Kids Backpack Email

### 1. Technical Summary

### 2. Link & Tracking Issues

### 3. Rendering & Accessibility

**Template placeholder comments shipped in production**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
<!---->
```
Both are raw template scaffolding. The typo ("IMPUT" vs "INPUT") confirms this block was never replaced. These are visible in raw source and clutter deliverability analysis tools.

**`<title>` brand mismatch**
```html
<title>Crate & Barrel</title>
```
Sender is "Crate & Kids." Screen readers and some preview panes surface `<title>`; this creates a brand inconsistency and may trigger spam heuristics that compare envelope sender to document title.

**`maximum-scale=1` blocks user zoom (WCAG 1.4.4)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Disabling pinch-zoom fails WCAG Success Criterion 1.4.4. Remove `maximum-scale=1`.

**`-webkit-text-size-adjust: none` on `html` element**
```css
html { -webkit-text-size-adjust: none; }
```
`none` disables iOS automatic text scaling entirely. The body correctly uses `100%`, but this `html`-level override takes precedence in WebKit. Change to `100%`.

**Universal selector applies `-webkit-text-size-adjust: none` to every element**
```css
*{ -webkit-text-size-adjust:none; ... }
```
Compounding the above — this blanket rule suppresses size adjustment on all elements. Replace `none` with `100%`.

**Conflicting and redundant `img` max-width breakpoints**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
At ≥768px both rules match; the 640px query (declared last) wins via cascade, rendering the 768px rule dead code. This is harmless in practice but masks intent and will confuse future maintainers. Remove the 768px block if 640px is the canonical desktop cap.

**Duplicate `<meta charset>` declarations**
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta charset="utf-8">
```
Redundant but harmless. Keep only the `http-equiv` form for maximum client compatibility.

**Duplicate `format-detection` meta tags**
`format-detection` appears once omnibus (`telephone=no,address=no,email=no,date=no,url=no`) and then again individually for `date`, `address`, and `telephone`. No functional impact but adds ~200 bytes of dead markup per send.
