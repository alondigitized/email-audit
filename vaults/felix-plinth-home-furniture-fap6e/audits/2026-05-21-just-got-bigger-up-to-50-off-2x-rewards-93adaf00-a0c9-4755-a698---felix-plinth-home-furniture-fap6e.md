# JUST got bigger! Up to 50% off + 2x Rewards!
**Score:** 7/10 · **Type:** Email audit · **2026-05-21**
## Executive summary

- Twenty-three. Possibly twenty-four — I genuinely cannot keep track anymore. The Crate & Barrel family has been hammering my inbox all week, and now here's Crate & Kids with the **exact same subject line** I saw earlier today from what I assumed was the parent brand. Same "JUST got bigger" hook, same 50% off, same 2x Rewards. I opened it because "Crate & Kids SALE" is technically a different sender name and I wondered if there was something new in the creative. There isn't.
- The email itself is competently assembled: the sage-green dresser hero is a genuinely beautiful product shot, the Double Rewards banner is prominently placed in a dark navy block that actually catches my eye, and the overall layout is cleaner than what Wayfair has been running all week (the "🔴 CLEARANCE ⚪ MEMORIAL DAY 🔵" flag-emoji disaster still haunts me). But competent execution doesn't solve the core problem, which is that I've already mentally processed this deal at least twice. Article's Memorial Day blast — which I also got this week — had the same discount depth but felt like one deliberate send. This feels like someone forgot to suppress the sub-brand list.
- Would I click? No. Would I forward to a friend expecting a nursery? Maybe, but only because they might not be getting twenty-three of these themselves. More likely: marked read, archived.

## What's working

- The sage dresser hero is the right anchor — it's a genuinely desirable piece, the image is clean, and the offer overlay doesn't crowd the product.
- The "Double Rewards" navy banner is well-placed and prominent; I actually pay attention to rewards math because I'm routing everything through a high-cashback card anyway, and "2x" landing above the fold is a real hook.
- No visible render bugs — the layout holds, images loaded, text isn't stepping on itself anywhere.
- Crate & Kids branding is distinct enough from C&B proper that I didn't mistake it for a resend of the parent email — the sub-brand identity reads clearly.
- "We love these for you" personalization module exists, which at least signals intent even if execution is soft.

## What's weak

- This subject line appeared in my inbox earlier today from the parent brand. Sending the same headline from the sub-brand a few hours later reads as an automation handoff failure, not a coordinated campaign.
- I don't recall signing up for Crate & Kids specifically — this feels like the parent brand auto-opted me into a sub-brand list, and that's a quiet trust erosion.
- The personalized product thumbnails in "we love these for you" are so small they're doing no persuasion work; I can vaguely make out what might be a crib but I can't see a price or name without zooming.
- Kids furniture has soft relevance for me right now — both renovations I'm running are adult spaces, and neither hero image here speaks to that.
- No hard deadline visible anywhere. "Memorial Day" implies urgency but Pottery Barn's design-services email from earlier this week managed to make the same holiday feel more time-bounded with specific framing; this one just floats.

## Recommendations

- 1. **Suppress the sub-brand send when the parent brand already ran the same subject line same-day.** This is the single change that would save the most trust equity. CB2 made a similar sequencing blunder this week — sending a "Welcome to CB2" email the day *after* a sale email — and this rhymes with that.
- 2. **Put a hard deadline in the subject line.** "Ends Monday" converts. "Just got bigger" does not.
- 3. **Make the personalization module actually personal** — large product card, visible price, something I've browsed if possible. The current thumbnails are decorative noise.
- 4. **Segment adults-without-kids out of the Crate & Kids blast**, or at minimum use the hero to show adult-adjacent kids pieces (entry-room storage, guest-room dresser for a second home) that could cross over.
- 5. **Use the rewards angle harder in the preview/preheader** — the 2x Rewards is the most differentiated signal in this email and it's buried below the fold.
- **Subject Alt A:** `Sale ends Monday: 50% off + double rewards at Crate & Kids`
- **Subject Alt B:** `Up to 50% off kids furniture — Memorial Day ends Monday`
- **Preheader Alt A:** `The dresser everyone's adding to cart — now half price through Monday.`
- **Preheader Alt B:** `Earn double rewards on every purchase this weekend only.`

### 3. Rendering & Accessibility

**`<title>` brand mismatch — confirmed bug**
```html
<title>Crate & Barrel</title>
```
Sender is "Crate & Kids SALE." Screen readers (NVDA, JAWS, VoiceOver) announce the document title on load — this surfaces the parent brand, not the sub-brand.

**Conflicting `img` max-width media queries — confirmed cascade bug**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
The `640px` query is declared *after* `768px`. Both match at ≥768px viewport, so cascade gives `640px` the win on all desktop. The `600px` rule is never applied.

**`maximum-scale=1` blocks user zoom — WCAG 1.4.4 violation**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents mobile users from zooming text. Fails WCAG 2.1 SC 1.4.4 (Resize Text, Level AA).

**`-webkit-text-size-adjust: none` in global `*` selector**
```css
* { -webkit-text-size-adjust: none; ... }
```
Applied globally — overrides the `<body>`-level `100%` value set two rules earlier, and suppresses iOS dynamic type adjustments across all text nodes.

**Duplicate `format-detection` meta tags**
`telephone=no`, `date=no`, and `address=no` each appear in both a combined tag and standalone tags. Harmless, but signals stale template hygiene.

**Unflushed developer placeholder comments in production HTML**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
<!---->
```
The typo (`IMPUT`) confirms this was a fill-in directive, not intentional markup. Both survived to send.
