### 3. Rendering & Accessibility

**Issue — `<title>` tag mismatch:**
```html
<title>Crate & Barrel</title>
```
Sender is "Crate & Kids"; the title should match. Screen readers announce the `<title>` in some mail clients (e.g., Apple Mail accessibility mode).

**Issue — Duplicate `format-detection` meta tags:**
Three separate `<meta name="format-detection">` tags appear — one combined and two standalone — creating redundancy and a minor spec violation:
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
Consolidate to the single combined tag; the duplicates add parse overhead with no benefit.

**Issue — `maximum-scale=1` blocks user zoom:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
`maximum-scale=1` prevents pinch-to-zoom on mobile, which is an accessibility failure (WCAG 1.4.4). Remove the `maximum-scale` constraint or set it to `5`.

**Issue — `*` selector applies `-webkit-text-size-adjust: none` universally:**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```
Applying `text-size-adjust: none` to every element overrides the `body`-scoped `100%` value declared earlier in the same stylesheet and can cause unreadable text at certain zoom levels on Android WebKit. Scope this to `body` or `table td` only.

**Issue — Conflicting `img` `max-width` media queries:**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
At viewports ≥ 768px, both rules match; cascade order makes the 600px rule (768px block) win because it appears first in source — but the 640px block appears *after* it, so the 640px block actually wins. This means images render at 640px on all viewports ≥ 640px, which may clip or overflow on 600px-wide email clients (e.g., Gmail web). Reconcile to a single rule.

**Issue — Unfilled template placeholder comment:**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
<!---->
```
"IMPUT" is a typo for "INPUT." The placeholder and the empty comment below it are production artifacts from the template builder and should be stripped before send. No custom font is loaded, so if the design calls for a web font, it is missing.
