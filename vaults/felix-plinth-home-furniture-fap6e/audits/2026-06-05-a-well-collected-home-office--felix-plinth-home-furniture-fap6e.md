### 2. Link & Tracking Issues

**Cannot fully audit** — HTML is truncated before body links appear. From what is visible:

- **Cross-domain font dependency**: Four `@font-face` declarations load the `HNW05` font family from `https://www.crateandbarrel.com/webfonts/` (e.g., `1e07d600-3787-4517-bd3d-b140f9e54ec2.woff2`). - **Double-slash URL paths**: Multiple cb2.com font URLs contain a double slash in the path segment:
  ```
  https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2
  https://www.cb2.com//Styles/CB2/fonts/BrownRegular/lineto-brown-regular.woff2
  https://www.cb2.com//Styles/CB2/fonts/GTSectra/GT-Sectra-Display-Regular.woff2
  ```
  Most servers normalize this, but it adds a redirect hop and should be corrected.

---

### 3. Rendering & Accessibility

- **Leaked developer placeholder** — The following comment appears verbatim in the shipped `<head>`, with a typo ("IMPUT"):
  ```html
  <!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
  ```
  This is an unfilled template instruction that should have been removed pre-send.

- **Zoom blocked** — `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` prevents user-initiated zoom. This violates WCAG 2.1 SC 1.4.4 (Resize Text) and is flagged by Apple Mail and some ESPs as an accessibility defect.

- **Global text-size-adjust suppression** — `*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none;}` is applied universally. The intended target is `body`, not `*`; applying it globally can interfere with nested overrides.

- **Conflicting `@font-face` declarations** — "Lineto Brown Sub" is declared three times:
  1. `eot` + `woff2` + `woff` stack (no weight qualifier)
  2. `woff2` only, `font-weight: 400`
  3. `woff2` only, `font-weight: 600`

  The unweighted declaration shadows the weight-keyed ones in clients that process CSS sequentially, making weight resolution unpredictable.

- **Narrow mobile breakpoint** — `@media only screen and (max-width: 418px)` targets only the narrowest phones. Devices rendering at 420–767px CSS width (common Android flagships, many iPads in portrait) receive no responsive overrides and will likely render the desktop layout unconstrained.

- **`line-height: 100%` globally applied** — `*{line-height: 100%}` collapses line height to match font size on every element. This is often intentional in email resets but will clip descenders on multi-line text unless overridden per-element. Confirm all text blocks have explicit `line-height` declarations.
