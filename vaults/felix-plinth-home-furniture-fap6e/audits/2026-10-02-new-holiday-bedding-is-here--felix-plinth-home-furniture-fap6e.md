## Technical Audit

## 1. Technical Summary
The email's markup is standard ESP-generated XHTML 1.0 Transitional and has mobile media queries and Outlook (MSO) fallbacks. It has 44 flagged `<img>` tags with no `alt` attribute, plus a viewport setting that blocks pinch-zoom. Compliance and authentication headers couldn't be verified. The HTML source was truncated, so the footer and link `href`s weren't inspectable.

## 2. Link & Tracking Issues
- **Unverifiable links:** All 86 links point to tracking or click-redirect domains, so the HTTP probe skipped them. I can't confirm destinations, redirect chains, or broken links.
- **Third-party pixel with a recipient identifier:** Five `https://sr.rlcdn.com/448796.gif?s=dbe8da71…5a8&n=1` through `&n=5` calls load from LiveRamp's `rlcdn.com`. The `s=` value is a 64-character hex string. It matches the `mi_u=dbe8da71…` value on the first-party `mi.crateandbarrel.com` pixels. It is probably a hashed recipient identifier shared with a third party, but that isn't confirmed from the source.
- **Redundant pixels:** The same `mi.crateandbarrel.com/p/rp/f3c0d22992a01946.png` loads 6 times. The `rlcdn.com` pixel loads 5 times with `n=1..5`. Both add requests without adding data.
- **Other tracking images:** `mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif` and `dv.crateandbarrel.com/o/e2065408-…` are the open and view pixels. They have no file extension on the `dv` URL.

## 3. Rendering & Accessibility
- **Missing `alt` on 44 images.** They fall into three groups:
  - 28 creative images, such as `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/*.jpg` and `.gif`, and the hero `CK%5FH26%5FKidsBedding%5F4x5%5FPrimary.gif`. With images off, or in a screen reader, the email has no readable content.
  - 3 spacer and rule images: `25%5FMI%5FBottom%5FSpacer%5F40px%5FWhite` (×2) and `042025%5FCBK%5FKidsBeds1%5FRule%5FSpacer%5F40px`. These should have `alt=""`.
  - 13 tracking pixels, which should also have `alt=""`.
- **Pinch-zoom is blocked.** `<meta name="viewport" content="… maximum-scale=1">` stops mobile users from zooming. This fails WCAG 1.4.4.
- **Text resizing is disabled.** `-webkit-text-size-adjust:none` and `-ms-text-size-adjust:none` are set on `*` and `body`. `*{line-height:100%}` also overrides the per-element line-heights.
- **Invalid XHTML.** `<title>Crate & Barrel</title>` has an unescaped `&`, which is invalid under the declared XHTML 1.0 doctype. It should be `&amp;`.
- **Template cruft.** An unfilled placeholder comment, `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->`, is still in the source. There are also duplicate `<meta charset>` and `format-detection` tags. These are harmless but sloppy.
- **Conflicting media queries.** `@media (min-width:768px) { img {max-width:600px} }` is overridden by the later `@media (min-width:640px) { img {max-width:640px} }`, so the 600px cap never applies.
- **What's fine:** `<html lang="en">` is present, and `color-scheme` is declared as light only.

## 7. Recommendations
1. **`alt` text:** Add descriptive `alt` text to the 28 creative images, starting with the hero GIF and product tiles. Use `alt=""` on spacers and pixels.
2. **Viewport and text sizing:** Remove `maximum-scale=1` from the viewport meta tag. Drop `-webkit-text-size-adjust:none` and the `*{line-height:100%}` rule.
3. **Pixel consolidation:** Reduce the repeated `f3c0d22992a01946.png` and `448796.gif` pixels to one each.
4. **Third-party pixel disclosure:** Confirm that sharing the hashed identifier with `rlcdn.com` is covered by the privacy policy.
5. **Markup cleanup:** Escape `&` in `<title>`. Remove the leftover `IMPUT HERE` placeholder comment and the duplicate meta tags.
6. **Header verification:** Re-check `List-Unsubscribe`, `List-Unsubscribe-Post` and `Authentication-Results` against the raw message from the original sender, not the relay copy.
7. **Link resolution:** Resolve the tracking redirects (follow a sample with `curl -I -L`) to check UTM parameters and landing pages.
