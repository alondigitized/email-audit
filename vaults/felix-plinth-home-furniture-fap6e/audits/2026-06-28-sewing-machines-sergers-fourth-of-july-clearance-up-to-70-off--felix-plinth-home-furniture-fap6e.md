Only WOFF is declared. WOFF2 is supported by Apple Mail, Gmail (webmail), and Samsung Mail and would reduce font payload by ~30%. The `mso-font-alt` fallback only applies to Outlook on Windows; no standard CSS `font-family` fallback stack (`Arial, sans-serif`) is present for clients that ignore `mso-font-alt`.

**Issue — Fixed heights on mobile product components will clip content:**
```css

.ProductRec-price { height: 40px; vertical-align: top }
.ProductRec-salesCopy { height: 28px; vertical-align: top }
```
These hard-coded pixel heights are fragile. If a product name or price renders at a larger font size (system font substitution, user accessibility settings, or a longer price string), content will be clipped. `min-height` would be safer.

**Issue — `word-break: break-all` on product names:**
```css

```
`break-all` splits words at any character boundary, not just at natural break points. This produces visually broken strings ("Sew" / "ing") on narrow screens. `overflow-wrap: break-word` combined with `word-break: normal` is the correct approach for preventing overflow without aggressive mid-word splits.
