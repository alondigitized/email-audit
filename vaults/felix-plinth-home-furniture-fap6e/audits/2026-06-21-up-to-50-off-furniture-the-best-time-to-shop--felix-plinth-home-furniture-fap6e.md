### 3. Rendering & Accessibility

**`maximum-scale=1` blocks user zoom (WCAG 1.4.4 violation)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents low-vision users from pinching to zoom. Remove `maximum-scale=1`.

**Global `text-size-adjust: none` overrides user accessibility settings**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
Applied to `*` (not just `body`), this suppresses OS-level font scaling on mobile. Should be scoped to `body` only and set to `100%`, not `none`.

**Conflicting desktop `img` max-width rules — cascade order bug**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }  /* declared first */
@media only screen and (min-width: 640px) { img { max-width: 640px } }  /* declared second — wins at ≥768px */
```
At ≥768px both queries match; the second rule wins due to cascade order, so the 600px cap is dead code. Images on wide viewports render at 640px when 600px was likely intended. Reorder or consolidate.

**Global `line-height: 100%` risks text clipping**
```css
* { line-height: 100%; }
```
A unitless `100%` line-height collapses multi-line text in several email clients (notably older Gmail Android). Should be overridden with explicit pixel values on text-bearing elements.

**Duplicate `format-detection` declarations**
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
...
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
The combined declaration and three individual declarations are redundant. Harmless but increases parse overhead; remove the three individual repeats.

**Duplicate charset declarations**
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta charset="utf-8">
```
Both present; the HTML5 form (`<meta charset>`) is sufficient. Redundant but not harmful.
