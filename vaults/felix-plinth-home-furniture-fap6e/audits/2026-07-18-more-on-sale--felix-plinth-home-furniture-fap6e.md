- **No render bugs** — everything loads, layout holds, no broken image gaps.

## What's weak

- **"MORE ON SALE" is the laziest subject line of the month** — no category, no %, no hook. Pottery Barn this morning opened with "Up to 70% off + Layer your bed in color" and I knew exactly what I was opening. This tells me nothing.
- **Two competing hero offers dilute focus** — Summer Edit AND Outdoor Collection with different CTAs means I have to choose what this email is actually about.
- **The product grid is unreadable on mobile** — thumbnails are postage-stamp sized. I can't tell what I'm looking at or what I want to click.
- **No deadline anywhere** — "40% off" with no end date is how you train people to wait. Crate & Barrel's outdoor email at least gestured at seasonal urgency with "sunny days ahead."
- **Twenty-six emails in July** — whatever this email did right, the cadence context kills goodwill before the open.

- 1. **Put something specific in the subject line.** "40% off furniture" or "Outdoor: 50%+ off" — anything that signals what kind of sale this is. The current subject sounds like a sequel nobody asked for.
- 2. **Add a deadline to the hero offer.** Even "ends Sunday" or "this week only" gives me a reason to not defer the click to never.
- 3. **Make the virtual appointment block the only CTA** — or lead with it. It's the most differentiated thing in this email and it's buried in the middle. If CB2 wants to own the "design-help-bundled-with-sale" space, commit to it.
- 4. **Kill or enlarge the product grid** — the "MORE FOR YOU" tiles are too small to drive clicks. Show three featured items at full width instead of eight thumbnails I can't parse.
- 5. **Throttle the cadence** — this is a product note, not a copy change, but it's the highest-leverage thing CB2 could do this month.

## Technical Audit — CB2 "MORE ON SALE"

### 1. Technical Summary

Standard XHTML 1.0 Transitional ESP template with table-based layout. Several code-quality defects are present in the visible source: an unreplaced template placeholder, duplicate `@font-face` declarations with conflicting descriptors, and a cross-brand CDN dependency.

---

### 2. Link & Tracking Issues

**Cross-brand font CDN dependency**
Four `@font-face` declarations load `HNW05` webfonts from `https://www.crateandbarrel.com/webfonts/` (a sibling brand's domain), not from `cb2.com`. If that domain goes unreachable or changes its CORS policy, font load fails silently with no fallback declared.

```css
src: url("https://www.crateandbarrel.com/webfonts/1e07d600-3787-4517-bd3d-b140f9e54ec2.woff2")
```

**Double-slash font URLs**
Six font src values on `cb2.com` contain a double slash in the path (`//Styles/`), e.g.:

```
https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2
```

Most servers normalize this, but it is a defect in the template.

**UTM params** — Not assessable from the truncated source. Confirm all `<a href>` links include `utm_source`, `utm_medium`, and `utm_campaign` before send.

---

### 3. Rendering & Accessibility

**`maximum-scale=1` blocks user zoom (WCAG 1.4.4 failure)**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

This prevents users from pinch-zooming text, which fails WCAG 1.4.4 (Resize Text, Level AA). Some ESPs and accessibility auditors flag this automatically.

**Mobile breakpoint is too narrow**

```css
@media only screen and (max-width: 418px)
```

This targets only devices ≤418px wide. Most modern Android handsets (and many iPhones in landscape) are wider. The industry standard is 480px or 600px. Recipients on wider phones get the desktop layout with no responsive overrides applied.

**Conflicting `img` max-width rules**

```css
@media (min-width: 768px) { img { max-width: 100% !important } }
@media (min-width: 690px) { img { max-width: 690px } }
```

At 690–767px viewport, both rules match; the 690px rule (declared second in source order) wins over the `100% !important` rule. This is likely unintentional and can clip images on tablet-width email preview panes.

**`alt` attributes** — Truncated source; confirm all `<img>` tags carry descriptive `alt` text. Images are loaded from `cb2.com` so they will be blocked in several clients on first open.

---

### 4. Personalization & Merge Tokens

**Unreplaced template placeholder left in production source**

```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```

This is an authoring comment with a typo ("IMPUT" vs. "INPUT") that was not stripped before send. While invisible to end users, it is visible in raw source and indicates the template was not fully sanitized.

No dynamic merge tokens (`{{first_name}}`, `*|FNAME|*`, etc.) are visible in the provided portion. If personalization is intended, confirm token replacement ran before deployment.

### 5. Compliance

**Cannot fully assess from truncated source.** Verify the following are present in the full HTML:

- Physical mailing address (CAN-SPAM §5(a)(5)) — required in footer
- One-click unsubscribe link with functioning endpoint
- Sender domain (`mail.cb2.com`) has valid SPF, DKIM, and DMARC records — check with `dig TXT mail.cb2.com` and a DMARC lookup on `cb2.com`

The `From` header (`cb2@mail.cb2.com`) uses a subdomain mailer, which is correct practice for deliverability separation.

### 6. Email-to-Site Continuity

**Font `@font-face` declarations include a duplicate for "Lineto Brown Sub"** — the family is declared three times:

1. No weight/style discriminator (catches all weights)
2. `font-weight: 400` (overrides above for regular)
3. `font-weight: 600` (overrides above for semibold)

Declaration #1 subsumes all weights in clients that process `@font-face` sequentially. In Gmail Web and some Outlook versions, the fallback stack (`Helvetica, sans-serif`) may render instead of the intended weight variants.

**UTM continuity** — Truncated source prevents full assessment. Landing pages should carry matching `utm_campaign` values; mismatches break attribution in GA4/Adobe Analytics.
