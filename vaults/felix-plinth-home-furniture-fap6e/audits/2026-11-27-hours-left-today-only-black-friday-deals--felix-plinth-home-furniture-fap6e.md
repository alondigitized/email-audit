## Technical Audit

## 1. Technical Summary
The HTML is a table-based, image-slice SFMC send. The main problems are accessibility (linked slices with empty alt text), invalid CSS in a `<style>` block, mixed-content `http://` images, and the recipient address exposed in pixel and URL query strings. The compliance and authentication checks couldn't be verified from the captured data.

## 2. Link & Tracking Issues
- **70 click-tracking links not probed.** All sampled links are opaque SFMC redirects of the form `https://click.e.potterybarn.com/?qs=ABp7Im...`. Destinations can't be validated from this capture, so broken-link status is unknown rather than failed.
- **Recipient address in cleartext URLs.** Two URLs carry `lila-hearth-potterybarn-fap6e@etell.app`:
  - `https://www.potterybarn.com/customer-service/coreemail.html?email=...`
  - `https://svopn.potterybarn.com/?sv_cid=0053_00597&sv_emopen=true&sv_sveme=...`
  
  Putting the address in a query string exposes it to logs, proxies and referrers.
- **Third-party ad pixels.** `secure.leadback.advertising.com/adcedge/lb?site=695501...` and `d.turn.com/r/dd/id/.../cat/1` load from ad-tech domains. Any client that loads images will fire them.
- **Cross-brand asset dependency.** `https://edm.westelm.com/we/evergreen/spacer_0.gif` is hosted on a sister brand's domain. If West Elm changes or removes it, this email breaks.
- **Dead code shipped in the source.** A commented-out credit-card banner block contains live-looking URLs (`...cm_ite=PB_header_nonmember`). It is harmless but adds weight.

## 3. Rendering & Accessibility
- **Linked slices with no accessible name.**
  - The hero slices `slices_01`–`slices_03` and others are wrapped in `<a href="https://click.e.potterybarn.com/...">` and carry `alt=""`. The same applies to the footer, bottom-banner and product images.
  - A screen reader announces these links with no name, or reads the raw URL. QA flagged roughly 60 images.
  - Empty `alt` is only correct for non-linked decorative images.
- **Pixels with URL-as-alt.** `svopn.potterybarn.com/?sv_cid=...` is exposed with its URL as the image name. Tracking pixels should use `alt=""` and `width="1" height="1"`.
- **Invalid CSS in the second `<style>` block.** Leaked PHP lines sit directly before the `a[x-apple-data-detectors]` rule:
  - `header('Content-Type: image/jpeg'); header("Cache-Control: no-store..."); header("Pragma: no-cache");`
  - A CSS parser reads these as part of the next rule's selector, so the `x-apple-data-detectors` rule is likely dropped. Apple Mail would then auto-link and restyle dates, addresses and phone numbers.
- **Mobile media query likely doesn't apply.**
  - `table[class="wrapper"]` and `img[class="photo"]` target classes I could not find on any element in the visible source. The tables are fixed `width="650"` and the images fixed `width="650"` or `325`.
  - The source is truncated, so this could still match later in the document. If not, there is no responsive behavior below 650px.
- **Mixed content.** `http://edm.potterybarn.com/pb/thekey/CC_Banner/PB/Foot_NonMem_PB.jpg` and `http://edm.potterybarn.com/pb/2022/0311_Key_CC_Email_BrandBanner/slices_02.jpg` may be blocked or upgraded by some clients.
- **Document structure.**
  - ampScript comments (`<!-- begin dynamic ampScript slot -->`) sit before the DOCTYPE. This can trigger quirks mode in some clients.
  - The XHTML 1.0 Strict DOCTYPE is used with deprecated attributes (`bgcolor`, `align`, `border`, `<center>`), so the markup isn't valid against its own DOCTYPE.
- **Web font may not load.** The Google Fonts `<link>` (`Montserrat`) is unsupported in Gmail and Outlook. This is fine if the fallback fonts are intentional.
- **Image-only layout.** If images are blocked, the content is essentially absent, because the slices have no alt text. The hidden preheader text ("Hope you saved room for savings") is the only text fallback.

## 4. Personalization & Merge Tokens
No issues found. I saw no unresolved `%%...%%` or `{{...}}` tokens in the visible source. The empty ampScript comment slot at the top suggests server-side processing completed. Recipient identity is resolved in the pixel URLs (see section 2).

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) not found.** QA notes this may be an AgentMail relay capture limit. It is unverified, not confirmed missing. Gmail and Yahoo bulk-sender rules require both for senders at this volume.
- **`Authentication-Results` not found.** SPF, DKIM and DMARC alignment for `e.potterybarn.com` is unknown. The same relay caveat applies.
- **Footer not visible.** The in-body unsubscribe link and physical postal address are not in the truncated source, so I can't confirm or deny them. The `Email-Footer/slices_01`–`18` images are image-only, so if the unsubscribe link is one of those slices it has no alt text and is unreadable with images off.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **UTM and campaign params can't be verified.** All links are encoded `qs=` redirects with no visible `utm_*` or `cm_*` parameters, and the 70 tracking links were skipped by the HTTP probe. Landing-page alignment is unverified.
- **Visible exception.** The commented-out block shows `cm_ite=` and `marketingChannelCode=` params, which suggests the live links carry Coremetrics-style params inside the encoded payload. That is not confirmable here.

## 7. Recommendations
1. Add descriptive `alt` text to every linked slice (hero, bottom banners, footer, product tiles). Keep `alt=""` only for the spacer and tracking pixels.
2. Remove the leaked PHP `header(...)` lines from the `<style>` block so the `a[x-apple-data-detectors]` rule is parsed.
3. Check that `class="wrapper"` and `class="photo"` exist on the elements the media query targets, or fix the selectors. Otherwise there is no mobile layout.
4. Move the two `http://` images to HTTPS.
5. Stop putting the recipient email in cleartext in `coreemail.html?email=` and `sv_sveme=`. Use a hashed or opaque subscriber key.
6. Host `spacer_0.gif` on the sender's own domain, and move the ampScript comments after the DOCTYPE.
7. Confirm with a raw `.eml` capture that `List-Unsubscribe`, `List-Unsubscribe-Post` and `Authentication-Results` are present on the original message. Also confirm a text-based unsubscribe link and postal address exist in the footer.
8. For continuity, resolve one or more `click.e.potterybarn.com` redirects and record the final landing URL and its UTM and `cm_` params.
