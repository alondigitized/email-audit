### 3. Rendering & Accessibility

**Issue — Viewport `maximum-scale=1` blocks user zoom:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from pinching to zoom. Violates WCAG 1.4.4 (Resize Text, Level AA). Remove `maximum-scale=1`.

**Issue — Conflicting `img` max-width breakpoints produce inverted behavior:**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
Both blocks fire at ≥768px; the later-declared `600px` rule wins due to cascade order, so images are *narrower* on larger screens than on 640–767px screens. The 768px block should be removed or the values corrected (should be `640px` → `600px` in ascending order, not reversed).

**Issue — No dark mode support:**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
`light`-only is declared. In dark-mode email clients (Apple Mail, Outlook iOS), this forces light rendering but provides no dark-mode stylesheet. Images and white backgrounds may render poorly. Consider adding a `prefers-color-scheme: dark` media query or at minimum testing in dark mode.

**Issue — Aggressive global text-size suppression:**
```css
* { -webkit-text-size-adjust: none; }
```
The `none` value (vs. `100%`) completely disables browser text scaling. On mobile viewports this can render text unreadably small in some clients.

**Issue — Duplicate `format-detection` meta declarations (x4):**
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
...
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
The combined declaration on line 1 already covers all attributes. The three individual declarations are redundant. Not breaking, but adds payload weight.

**Issue — Redundant dual `charset` declaration:**
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta charset="utf-8">
```
Both are present; one is sufficient.
