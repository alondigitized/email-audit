### 3. Rendering & Accessibility

**[HIGH] Unfilled template placeholder left in production**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
<!---->
```
Both lines are template scaffolding that was never removed. "IMPUT" is also a typo of "INPUT". While comments don't render visibly, this is a QA failure indicating the template was not properly finalized before send.

**[MEDIUM] Duplicate `format-detection` meta tags**
The combined tag and three individual tags conflict and create redundancy:
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
`telephone=no`, `address=no`, and `date=no` are each declared twice. Per spec, only the last matched value is used in some clients; the extras are noise.

**[MEDIUM] `maximum-scale=1` locks pinch-to-zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from zooming in on content. WCAG 2.1 SC 1.4.4 (Resize Text) failure for users with low vision.

**[LOW] Global wildcard disables text-size-adjust**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```
The `*` selector applies `text-size-adjust:none` to all elements. This is more aggressive than the `body`-scoped version declared earlier in the same stylesheet and may override accessibility user-agent settings.

**[LOW] Conflicting `img` `max-width` rules**
Two separate `@media` blocks set `img { max-width }` with overlapping conditions:
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
At 768px+, both blocks apply; the 600px rule wins due to source order. This may unintentionally cap desktop images at 600px when the template container is 640px wide.
