# JULY 4TH SALE STARTS NOW
**Score:** 8/10 · **Type:** Email audit · **2026-06-25**
## Executive summary

- Forty. That is approximately where I am in the CB2 / Crate family email count since mid-May, and this one drops on June 25th — nine days before the holiday it's selling. The coral-red hero is punchy and I won't pretend "50% OFF" didn't register; I'm pricing out a sofa for the second house right now so this is genuinely the right message. But here's the problem: I've already seen the CB2 Warehouse Sale pitched, the "Now & Future Classics on Sale" push, "Private Sanctuaries," and the Crate & Kids version of this exact offer — all within the last four days. My brain has developed a CB2 callus.
- Still, "BETTER THAN FIREWORKS" made me smirk. That's the first bit of CB2 copy in weeks that felt like a human wrote it rather than a spreadsheet. The category strips — SHOP FURNITURE, SHOP RUGS, SHOP LIGHTING — map almost perfectly to what I'm actively buying, so the product logic is right even if the cadence is exhausting.
- I'd open this, probably click through to rugs or lighting, and not forward it to anyone because my friends are already getting their own CB2 deluge. Mark it filed, not deleted.

## What's working

- **"BETTER THAN FIREWORKS"** — genuinely funny one-liner that CB2 hasn't earned in a while; resets goodwill burned by volume
- **Coral hero with 50% OFF in the first viewport** — zero ambiguity, no scrolling required; Pottery Barn buried a comparable offer below two lifestyle images in their June 25th send and this lands cleaner
- **Category strip navigation (Furniture / Rugs / Lighting)** — these are exactly the three rooms I'm actively working on; it lets me self-sort immediately instead of hunting
- **Warehouse Sale upgrade at 60%+** — placing a deeper discount deeper in the email rewards the scroll; good architecture
- **Clean render, consistent palette** — no broken images, no lorem ipsum, no overlapping text; layout holds at mobile width

## What's weak

- **Cadence is the real problem** — this is the fifth CB2/Crate family email I've seen since June 20th; "JULY 4TH SALE STARTS NOW" would hit differently if I hadn't already been through two Warehouse Sale emails and a "Private Sanctuaries" drop this week
- **"SHOP GIFTS"** — I am not buying gifts right now; I'm buying furniture; that category slot is wasted on me and signals generic segmentation
- **Two discount levels, no logic given** — hero says 50%, Warehouse Sale banner says 60%+; as someone who does the rewards math before checking out, the discrepancy is mildly annoying without context (which items, which tier?)
- **"More for You" grid looks algorithmic, not curated** — hard to tell from the render whether those are genuinely based on my browse history or just filler; Article's "Bedroom storage essentials" send from this week felt more like a warm handpick even though it was probably the same recommendation engine

## Recommendations

- 1. **Slow the cadence before anything else** — no subject line rewrite fixes a subscriber who's seen 5 emails in 6 days; a suppression rule for opens within 48 hours would double the open rate on the next one
- 2. **Replace "SHOP GIFTS" with "SHOP OUTDOOR" or "SHOP BEDDING"** — more purchase-intent relevant for someone who's actually furnishing rooms vs. wrapping boxes
- 3. **Clarify the two discount tiers** — a single line like "Up to 60% off, starting at 50%" resolves the math; right now the hero and the Warehouse Sale banner feel like two different emails in one
- 4. **Personalize the hero subhead** — even just "Up to 50% off furniture, rugs + lighting" instead of the generic SALE framing; tell me the categories you know I browse

- **Preheader Alt A:** `Furniture, rugs, lighting — all marked down. No code needed.`

### 3. Rendering & Accessibility

**`maximum-scale=1` in viewport meta (line 6)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents user-initiated zoom on mobile. WCAG 1.4.4 failure. Many ESPs now flag this automatically.

**Blanket `-webkit-text-size-adjust: none` on `*` selector**
```css
*{-webkit-text-size-adjust:none;-ms-text-size-adjust:none; ... }
```
Applied globally rather than scoped to `body`. Overrides OS-level accessibility text scaling for all elements.

**Non-standard mobile breakpoint: `max-width: 418px`**
This targets the exact 414px iPhone width. Gmail's mobile webview clips at 480px; content between 419–479px gets neither desktop nor mobile styles applied. Standard safe breakpoint is `480px` or `600px`.

**Conflicting desktop image rules**
```css
@media only screen and (min-width: 768px) { img {max-width: 100% !important} }
@media only screen and (min-width: 690px) { img {max-width: 690px} }
```
The `690px` rule fires first as viewport widens, then the `768px` rule overrides it with `!important`. Between 690–767px, `max-width: 690px` applies; above 768px, `max-width: 100%` takes over. The `!important` on the wider breakpoint wins unintentionally — likely intended to cap images at `690px` on all desktop sizes.

**Double-slash URLs in `@font-face` declarations**
```css
src: url("https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2")
src: url("https://www.cb2.com//Styles/CB2/fonts/BrownRegular/lineto-brown-regular.woff2")
src: url("https://www.cb2.com//Styles/CB2/fonts/GTSectra/GT-Sectra-Display-Regular.woff2")
```
Three font `src` URLs contain `//` double slashes after the domain. Most servers normalize this via 301 redirect, adding a round-trip per font load. Confirm these resolve without redirect; fix to single slash.

**Duplicate `@font-face` for "Lineto Brown Sub"**
The family is declared three times: once for the legacy EOT/WOFF stack, then twice more for woff2-only weight variants (400 and 600). The redundancy is harmless but inflates `<head>` size.

**Template placeholder comment left in production HTML**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
This is an unresolved ESP template comment (also contains a typo: "IMPUT" → "INPUT"). It should have been removed or filled before send.
