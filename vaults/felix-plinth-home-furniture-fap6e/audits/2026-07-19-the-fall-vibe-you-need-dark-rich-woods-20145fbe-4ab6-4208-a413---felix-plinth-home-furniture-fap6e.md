### 3. Rendering & Accessibility

**`maximum-scale=1` on viewport** (WCAG 1.4.4 violation)
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from pinch-zooming. Remove `maximum-scale=1`.

**`text-size-adjust: none` applied globally**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```
Disables OS-level text scaling for all elements. This overrides user accessibility settings. Scope this to `body` or `table td` at most — never `*`.

**Conflicting desktop image max-width rules** — media query ordering bug:
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }  /* declared first */
@media only screen and (min-width: 640px) { img {max-width: 640px} }  /* declared last — wins at ≥768px */
```
At viewport widths ≥768px both queries fire; the second rule (640px) wins due to cascade order. Result: images cap at 640px on large desktop, not 600px as likely intended. Swap the declaration order, or use `min-width: 640px` only and handle 600px with a separate rule.

**Light-mode forced, no dark mode fallback**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Apple Mail and Gmail (Android) will not apply dark-mode overrides. Dark text on light backgrounds forced in the ESP will appear correctly, but any hardcoded light background colors in the (unseen) body may render poorly for users with OS-level dark mode enabled. At minimum, test in Apple Mail dark mode.

**Duplicate meta declarations** — minor but indicates template hygiene issues:
- `format-detection` declared 4 times (once combined, then individually for `telephone`, `address`, `date`).
- `charset` declared twice (`http-equiv` + standalone `meta charset`).
