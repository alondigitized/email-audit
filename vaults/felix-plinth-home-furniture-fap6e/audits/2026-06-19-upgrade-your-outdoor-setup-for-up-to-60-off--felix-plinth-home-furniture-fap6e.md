- The hero discount percentage is front and center — I don't have to scroll or squint to understand the offer before committing a click.

## What's weak

- Pottery Barn already threw 70% off at me this week. Sixty percent feels like second place when my inbox has the comparison sitting two rows up — and I shop both.
- Mid-email there's a pivot to what looks like festive/colorful outdoor entertaining items. The shift breaks the "outdoor furniture sale" flow — I came here for dining tables and lounge chairs, not a party supply editorial.
- No deadline is visible anywhere. "Up to 60% off" with no end date gives me zero reason to buy this weekend instead of waiting for a deeper cut. Article did this same thing and I never converted.
- This reads like a stranger's email. No name, no loyalty acknowledgment, no personalization hook. CB2's "NOW & FUTURE CLASSICS ON SALE" email from earlier this month had the same cold-stranger energy — at least that one had tighter editorial focus.

- 1. **Put a hard deadline in the subject or hero** — "Ends Sunday" or "Through June 22" would convert this from a passive save to an action item. That single change is worth more than any copy rewrite.
- 2. **Split the CTAs by outdoor zone** — Generic "Shop" buttons don't tell me whether I'm landing on dining, lounge, or accessories. "Shop Outdoor Dining" and "Shop Lounge Seating" side by side would get me to the right product faster.
- 3. **Cut the colorful entertaining pivot** — Pick a lane. Outdoor furniture sale *or* outdoor entertaining edit. Two missions in one email is half an email on each. Save the entertaining content for its own Thursday send.
- 4. **Surface my C&B rewards balance if I have one** — Pottery Barn telegraphs loyalty pricing better than C&B does. If I have points sitting idle, tell me. That's a real differentiator over Pottery Barn and C&B keeps leaving it on the table.
- 5. **Reframe the hero copy around the second-home use case** — "Setting up a summer home?" or "The second home needs a patio too." That's surgical for a customer in renovation mode and it's not a hard guess — C&B has my purchase history.

### 3. Rendering & Accessibility

**Confirmed issues:**

**a. Conflicting `img` max-width media queries (rendering regression risk)**
Two desktop breakpoint rules fight each other:
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
At viewports ≥ 768px the `600px` rule wins (later specificity is irrelevant; source order with equal specificity means the first declared wins — but here the 768px block appears *before* the 640px block, so 640px will actually win at ≥ 768px). Net result: images cap at 640px even on wide desktop, not 600px. Likely unintended.

**b. `maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Violates WCAG 1.4.4 (Resize Text, Level AA). Remove `maximum-scale=1`.

**c. Conflicting `-webkit-text-size-adjust` values**
```css
* { -webkit-text-size-adjust: none; }         /* aggressive global reset */
body { -webkit-text-size-adjust: 100%; }       /* contradicts above */
html { -webkit-text-size-adjust: none; }
```
The `*` selector sets `none` globally, then `body` overrides to `100%`. Behavior is undefined when these conflict across WebKit implementations. Consolidate to a single `html, body { -webkit-text-size-adjust: 100%; }` and remove the `*` override.

**d. `line-height: 100%` on `*` selector**
```css
* { line-height: 100%; }
```
This global reset suppresses inherited line-height overrides. Any element that needs a `line-height` value must explicitly re-declare it, or it collapses to `100%` of font-size. High risk of clipped descenders in text-heavy blocks.

**e. Duplicate `format-detection` meta tags**
The `format-detection` directive appears four times: once as a combined value, then three redundant single-value declarations. Not harmful but is dead markup weight.

**f. Mobile breakpoint: `max-width: 460px` defined twice**
Two separate `@media only screen and (max-width: 460px)` blocks exist across the two `<style>` elements. Cascade order is correct (second block wins on conflict) but this is a maintainability defect — one block should consolidate all mobile overrides.

**Alt text on images:** Unverifiable — `<img>` tags not present in the visible truncated source. Must be validated in the full source.
