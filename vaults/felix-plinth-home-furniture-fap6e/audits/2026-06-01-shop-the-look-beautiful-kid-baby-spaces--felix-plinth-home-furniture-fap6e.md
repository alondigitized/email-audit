### 3. Rendering & Accessibility

**Conflicting `img max-width` media queries (CSS bug):**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
At viewport widths ≥768px both rules match. Because the 640px rule is declared **after** the 768px rule, cascade order makes `max-width: 640px` win at desktop — overriding the intended 600px container cap. Images can overflow the 600px wrapper on desktop clients that respect media queries (Apple Mail, modern webmail).

**`maximum-scale=1` on viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocks pinch-to-zoom. Violates WCAG 1.4.4 (Resize Text, Level AA). Should be removed.

**`line-height: 100%` on `*` selector:**
```css
*{ line-height: 100% }
```
Applies to all elements globally. On body copy, computed line-height will collapse to font-size, producing cramped text and potential WCAG 1.4.12 (Text Spacing) failures. Should be scoped to layout elements only.

**`-webkit-text-size-adjust: none` on `*` selector:**
Also applied globally — overrides OS-level accessibility font scaling on iOS/Android for all elements, not just those needing it.

**Dark mode explicitly disabled:**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Deliberate but worth noting — Apple Mail and Gmail dark mode will attempt a forced inversion if no dark styles are provided, which can produce unintended color inversions on images and backgrounds.
