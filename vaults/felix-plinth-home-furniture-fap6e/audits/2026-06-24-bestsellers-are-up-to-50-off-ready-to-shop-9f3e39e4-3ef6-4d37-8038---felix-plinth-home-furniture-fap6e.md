### 3. Rendering & Accessibility

**Template placeholder not removed:**
```html

```
Developer instruction comment with a typo ("IMPUT" → "INPUT") is live in production. The empty `<!---->` after it confirms the font block was removed but the instruction comment was not. Leaks internal workflow notes to anyone who inspects source.

**Duplicate `format-detection` meta tags:**
Three attributes appear twice each — the combined declaration at the top is followed by three separate single-attribute declarations. Redundant; signals template hygiene issues.

**Conflicting desktop breakpoint rules:**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
At viewports ≥768px both rules match; the 640px query wins via cascade order, making `max-width: 600px` dead. One of these rules is incorrect.

**`maximum-scale=1` blocks pinch-zoom:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from zooming in on small text or fine print. Violates WCAG 1.4.4 (Resize Text, Level AA).

**Dark mode explicitly disabled:**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
No `@media (prefers-color-scheme: dark)` block present. Apple Mail and Gmail Android may auto-invert, breaking logo colors and text-on-image legibility.

**Internal system comments exposed:**
```html

<!----- MI styling start----->
<!----- CLIENT styling start----->
```
Template-system labels (appears to be Movable Ink origin) visible in delivered HTML. Reveals vendor and template structure.
