## Technical Audit

## 1. Technical Summary
The visible markup is a standard table-based XHTML Transitional template, with MSO conditionals and mobile media queries. 18 content images lack alt text, and the compliance and authentication checks were inconclusive because headers weren't captured. The HTML source was truncated, so footer, link and body checks are partial.

## 2. Link & Tracking Issues
- **66 tracking links were not probed.** The QA run skipped them as click-redirect domains, so destination status, redirect chains and landing-page validity are unverified.
- **Tracking pixels are present.** There are 5 `https://sr.rlcdn.com/448796.gif?...&n=1..5` pixels (LiveRamp, with a hashed identifier in the `s=` param), plus `https://mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif?mi_u=...` and `https://dv.crateandbarrel.com/o/96e0d6b9-...?mi_cid=...&mi_mid=...`. This isn't a defect. However, 5 identical third-party pixel calls add requests, and they are hosted outside the sending domain.
- The QA output was cut off, so more pixels may exist.

## 3. Rendering & Accessibility
- **18 content images have no alt text.** All are on `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/` or `/m/47/`, for example `bbf6f9d4-...png`, `592f13e9-...jpg` and `ac698ed7-...gif`. If these images are blocked, or a screen reader is used, the sale and promotion content is lost.
- **The animated GIF `ac698ed7-...gif` has no alt text.** Whatever it conveys, such as the offer, is lost when it doesn't render.
- **The tracking pixels have no alt text** (`448796.gif` ×5, `o.gif`, `dv...`). This is low severity, but they should use `alt=""` plus `width="1" height="1"`.
- **`<meta name="viewport" ... maximum-scale=1>`** blocks pinch-zoom, which is a WCAG 1.4.4 concern.
- **`-webkit-text-size-adjust:none` appears on `*` and `body`.** This disables iOS text scaling, which conflicts with the `100%` values set elsewhere in the same stylesheet.
- **`<title>Crate & Barrel</title>` has an unescaped `&`.** This is invalid under the XHTML doctype, though it's harmless in practice.
- **The `<meta name="format-detection">` tag is declared three times with conflicting values.** The first sets `telephone=no,address=no,email=no,date=no,url=no`, and two later tags repeat parts of it.
- **A template placeholder comment shipped:** `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->`. It's cosmetic, but it shows a QA gap.
- **Two overlapping `img` max-width rules** apply at `min-width:640px` (`640px`) and `min-width:768px` (`600px`). At 640 to 767px the image cap is wider than at 768px and above. This is probably unintended.

## 4. Personalization & Merge Tokens
No issues found in the visible source. I saw no unrendered merge tokens, though the truncated HTML means the body wasn't fully reviewed. I also saw no first-name or other personalization, so I can't confirm it either way.

## 5. Compliance
- **The `List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) headers were not found.** The QA tool notes the AgentMail relay may strip them, so this is **unconfirmed**. Gmail and Yahoo require both headers for bulk senders, so the original message should be checked.
- **The `Authentication-Results` header was not found, so SPF, DKIM and DMARC are unknown.** This is expected through the relay and isn't evidence of a failure.
- **The in-body unsubscribe link and physical postal address are not verifiable.** The footer is past the truncation point. The sender domain `mail.crateandbarrel.com` is a dedicated subdomain, which is good practice.

## 6. Email-to-Site Continuity
Not verifiable. The 66 tracking links were not resolved, so UTM parameters, final destinations and any mismatch with the "up to 50% off" subject couldn't be checked. The `mi_cid` and `mi_mid` params on the `dv.` pixel show campaign and message IDs are in use. The visible HTML doesn't show whether those IDs carry through to the site.

## 7. Recommendations
1. Add descriptive `alt` text to all 18 content images (the `/m/1/` and `/m/47/` assets). Use `alt=""` on the pixels.
2. Remove `maximum-scale=1` from the viewport tag, and drop `text-size-adjust:none`.
3. Pull the raw `.eml` from the sending ESP or an unrelayed seed inbox. Confirm `List-Unsubscribe`, `List-Unsubscribe-Post: List-Unsubscribe=One-Click`, and SPF, DKIM and DMARC alignment for `mail.crateandbarrel.com`.
4. Rerun link QA with a redirect-following probe (HEAD or GET with redirects) on a sample of the 66 tracked links. Check final URLs, UTM params and 4xx or 5xx responses.
5. Fix the `&` in `<title>`, consolidate the duplicate `format-detection` tags, and clean up the leftover `IMPUT HERE` placeholder comment.
6. Capture untruncated HTML for the next audit so the footer, unsubscribe link and postal address can be checked.
