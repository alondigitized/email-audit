### 3. Rendering & Accessibility

**`maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Accessibility failure (WCAG 1.4.4). Recommendation: remove `maximum-scale=1`.

**`-webkit-text-size-adjust:none` on `*` selector**
```css
*{-webkit-text-size-adjust:none; ...}
```
Applied globally, this overrides user font-size settings across all elements. More targeted than needed — should be scoped to `body` only.

**Conflicting image `max-width` breakpoints**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
The 640px rule appears after the 768px rule and has equal specificity. For viewports 640–767px, the cascade resolves to `max-width: 640px`, not `600px`. Whether intentional, this is likely a copy-paste error — the two rules conflict in the 640–767px range. Verify intended behavior and consolidate.

**Duplicate `format-detection` meta tags**
`telephone=no` and `address=no` are declared twice each (once combined, once individually). No functional impact, but indicates template hygiene issue.
