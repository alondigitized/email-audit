## Technical Audit

## 1. Technical Summary
The HTML is a Marketing Cloud-style (MI) table layout with `lang="en"` and a UTF-8 charset. The main confirmed problems are widespread missing `alt` attributes (53 images flagged), a zoom-blocking viewport tag, and 97 tracked links that couldn't be verified. Header-level compliance and authentication could not be confirmed because the relay didn't capture those headers.

## 2. Link & Tracking Issues
- **97 links were not probed.** They were skipped as tracking/click-redirect domains, so destination status, redirect chains and 404s are unverified. This is a coverage gap, not a confirmed defect.
- **Per-recipient identifiers appear in image URLs.**
  - `mi.crateandbarrel.com/p/rp/*.png?mi_u=56aaa278…` (7 images) and `mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif?mi_u=…` carry a recipient ID.
  - `dv.crateandbarrel.com/o/7bb8392e-…?mi_cid=…&mi_mid=…` carries campaign and message IDs.
  - `sr.rlcdn.com/448796.gif?s=56aaa278…&n=1` through `n=5` are five third-party (LiveRamp) pixels. They carry the same `s=` identifier, which looks like the `mi_u` value.
  - If the identifier is derived from the recipient's email, this is a privacy exposure. The five repeated `rlcdn` calls with `n=1..5` are redundant requests.
- **Third-party pixel count.** There are at least 7 beacons, 5 of them third-party. I could not confirm from the truncated source whether the footer discloses them.

## 3. Rendering & Accessibility
- **Missing alt text.** The QA run flagged 53 `<img>` elements with no `alt`.
  - About 39 are content images, for example `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/bf3053a9-….jpg` and `s7d5.scene7.com/is/content/Crate/00%5FEmail/2026/09%5FCore/…Thanksgiving…`.
  - These are likely hero, product and CTA images, so with images off or in a screen reader the email may be unreadable.
  - The rest are tracking pixels (`rlcdn`, `o.gif`, `dv.*`, probably the `mi…/rp/*.png` set). Those should use `alt=""` explicitly.
- **Viewport blocks zoom.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` prevents pinch-zoom (WCAG 1.4.4).
- **Text resizing disabled.** `-webkit-text-size-adjust:none` and `-ms-text-size-adjust:none` are set on `*`, `html` and `body`, which blocks user text scaling in some clients.
- **Narrow mobile breakpoint.** All responsive rules sit under `@media (max-width:460px)`. Viewports between roughly 461 and 640px get no responsive adjustments, and `.mobile{width:460px!important}` is a fixed width.
- **Duplicate meta tags.**
  - `format-detection` is declared four times with conflicting values (`telephone=no,address=no,email=no,date=no,url=no`, then `date=no`, `address=no` and `telephone=no` separately).
  - `charset` is declared twice (`http-equiv` and `<meta charset>`).
- **`<title>` source.** The source reads `<title>Crate & Barrel</title>` with an unescaped `&`, and the title doesn't match the subject line ("Le Creuset: Made for naturally cleaner cooking").
- **Leftover template comment.** `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->` is a template artifact. It is harmless but shows the template wasn't cleaned.
- **Global `*{max-height:1000000px; line-height:100%}`.** This is a broad reset that can cause line-height side effects, but I couldn't confirm any actual breakage.

## 4. Personalization & Merge Tokens
No issues found in the visible HTML. No unresolved tokens (`{{…}}`, `%%…%%`, `[FIRST_NAME]`) appear in the retrieved portion. The source was truncated, so the body and footer were not fully checked.

## 5. Compliance
- **List-Unsubscribe not found.** QA flagged `List-Unsubscribe` as missing. It notes this may be an AgentMail relay capture artifact, so treat it as unconfirmed.
- **List-Unsubscribe-Post not found.** The same applies to `List-Unsubscribe-Post` (RFC 8058, one-click). Gmail and Yahoo bulk-sender rules require one-click unsubscribe for senders of this volume. Verify against the raw message headers.
- **Authentication-Results not found.** SPF, DKIM and DMARC status is unknown. This is expected via the relay, and the sending domain `mail.crateandbarrel.com` is a dedicated subdomain.
- **Footer not visible.** The in-body unsubscribe link and physical postal address could not be verified because the source is truncated.

## 6. Email-to-Site Continuity
Not verifiable. UTM parameters can't be assessed because the 97 tracking links were wrapped in redirect domains and skipped, and no landing-page probes ran. The only direct URLs in the QA data are image hosts, not click destinations.

## 7. Recommendations
1. **Add `alt` text** to the ~39 content images, with descriptive text for product and CTA images. Set `alt=""` on all tracking pixels.
2. **Remove `maximum-scale=1`** from the viewport meta, and drop `text-size-adjust:none` (use `100%`).
3. **Check the raw message** (not the relay copy) for `List-Unsubscribe`, `List-Unsubscribe-Post` and `Authentication-Results`.
4. **Resolve the 97 wrapped links** by following the redirect chain to confirm final URLs return 200 and carry the expected UTMs.
5. **Review the recipient identifiers** (`mi_u`, `s=`) in image URLs and confirm they are non-reversible. Deduplicate the five `rlcdn` pixels.
6. **Clean the head.** Collapse the duplicate `format-detection` and `charset` metas, escape `&` in `<title>`, and remove the leftover placeholder comment.
7. **Add a breakpoint** between 461 and 640px, or raise the existing one, so mid-width phones aren't served the desktop layout.
8. **Re-run QA on the full HTML** to cover the footer and any merge tokens past the truncation point.
