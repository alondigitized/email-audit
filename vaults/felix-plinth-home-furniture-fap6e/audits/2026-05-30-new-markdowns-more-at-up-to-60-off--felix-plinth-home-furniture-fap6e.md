### 3. Rendering & Accessibility

**`<title>` brand mismatch.**
```html
<title>Crate & Barrel</title>
```
The title reflects the parent brand, not "Crate & Kids." Several clients (Apple Mail, some Android) surface the `<title>` value. Should be `<title>Crate & Kids</title>`.

**Conflicting `img` max-width media queries — cascade order bug.**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
At viewports ≥768px both rules match. The 640px rule appears *after* in source order, so it wins at equal specificity — the intended 600px desktop cap is never applied. Either remove the 640px rule or place it before the 768px block.

**Duplicate `format-detection` meta tags.** `telephone=no` and `address=no` each appear twice (once inline in the combined tag, once as standalone metas). Redundant but harmless; clean up to reduce parse noise.

**Double charset declaration.** Both `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta charset="utf-8">` are present. The HTTP-equiv form is sufficient for XHTML; the standalone form is the HTML5 pattern. Having both is not an error but is inconsistent with the XHTML doctype.

**Aggressive universal selector reset.**
```css
*{-webkit-text-size-adjust:none; line-height: 100%; max-height:1000000px; ...}
```
`-webkit-text-size-adjust:none` on `*` overrides the `body` declaration and suppresses zoom-based text scaling in VoiceOver/iOS contexts. Scope this to `body` only.

**Unusual mobile breakpoint.** `@media only screen and (max-width: 460px)` — the industry standard is 480px or 600px. At 460–479px viewport widths (e.g., older Androids at 480px with scaling), the mobile layout does not trigger.
