### 3. Rendering & Accessibility

**Conflicting image max-width media queries** — two rules apply to desktop with the larger breakpoint getting the tighter constraint:

```css
@media only screen and (min-width: 640px) { img { max-width: 640px } }  /* 640–767px */
@media only screen and (min-width: 768px) { img { max-width: 600px } }  /* 768px+ */
```

Images shrink at wider viewports. The 768px rule should be `max-width: 640px` or removed.

**`maximum-scale=1` in viewport meta** prevents user-initiated zoom, a WCAG 1.4.4 (Level AA) failure for users who need text scaling.

**Global `-webkit-text-size-adjust: none`** applied via the `*` selector overrides all elements. This suppresses OS-level font scaling for visually impaired users and conflicts with the `body` rule that correctly sets it to `100%`.

**`<meta name="supported-color-schemes" content="light">`** — dark mode explicitly suppressed. Not a bug, but OS-level dark mode will force-invert images in some clients (Apple Mail) since no dark-mode overrides are provided.

**Duplicate `format-detection` meta tags** — declared four times (one combined, three individual). Redundant; the combined declaration at the top is sufficient.
