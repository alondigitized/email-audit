# The Summer Clearance Event is here! Shop up to 60% off ☀️
**Score:** 8/10 · **Type:** Email audit · **2026-05-29**
## Executive summary

- Eleven. That's where I am with the Crate & Barrel family this week, and somehow I'm looking at the *second* "60% off clearance" email from C&B today. The "NEW MARKDOWNS! Shop up to 60% off" hit my inbox earlier this morning — I opened it, I actually liked it (scored it an 8), and now here comes the Summer Clearance Event branded version doing the exact same lifting with a different hero treatment. The offer is legitimately good — up to 60% on furniture clearance is real money when you're outfitting two houses simultaneously — but the déjà vu is real and it chips away at credibility. I'm not confused; I'm slightly annoyed.
- That said, the email itself is clean. The hero is immediate. The category grid — Outdoor, Dining, Lighting, More Furniture — is honestly useful for how I shop, because I'm not browsing randomly, I'm ticking rooms off a list. If I hadn't already opened the first send today, this version would've gotten more of my attention.
- The Crate & Kids cross-sell embedded mid-email is the other thing. I've flagged this before on C&K sends: I don't have kids, and every time that logo drops into a scroll I'm doing for a dining table, I feel like the segmentation fell asleep at the wheel. I'll mark as read — I won't forward, I won't click. I already handled this brand today.

## What's working

- **Hero offer is instant and legible** — "up to 60% off The Summer Clearance Event" reads in one pass; no creative ambiguity about whether this is a sale or just a brand moment
- **Category grid is genuinely functional** — Outdoor, Dining, Lighting, More Furniture as distinct tap targets maps directly to how I shop by room when I'm mid-reno; Pottery Barn's "Find a rug in a color you ❤️" pivot last week was cute, but this utilitarian grid is more useful to me right now
- **"Shop All Clearance" CTA is unambiguous** — green button, clear verb+noun, nothing clever that buries the action
- **Summer theming lands correctly** — the ☀️ and "Summer Clearance" language is seasonally appropriate; not stale promo copy recycled from March
- **Clean render, no broken images** — everything loaded, layout is intact, type is readable without zooming

## What's weak

- **Second 60%-off send today is a cadence mistake** — the "NEW MARKDOWNS" email from earlier this morning already claimed this territory; running two clearance-event emails same-day reads as disorganized, not urgent
- **Crate & Kids hijack mid-scroll** — the embedded C&K "we love these for you" section is a demographic misfire; I've had five C&K sends this week and none of them are for me
- **No time boundary on the offer** — "is here!" without a deadline ("ends Sunday," "48 hours left") kills the urgency; Wayfair's "under $99" area rug send and Article's "ends today" Memorial Day send both gave me a specific reason to act *now*; this doesn't
- **"Shop All Clearance" is the ceiling, not a floor** — after the category grid builds intent, landing me on the full clearance page instead of, say, a curated "Dining Room Clearance" or a specific hero piece leaves money on the table
- **No loyalty or rewards signal** — I buy on my highest-rewards card specifically because C&B doesn't remind me of any membership upside; even a one-liner about Design Desk savings or a rewards balance nudge would've moved me

## Recommendations

- 1. **Consolidate the two same-day sends into one** — pick the better creative (the "NEW MARKDOWNS" version earlier had better energy) and don't double-dip the same day; two clearance emails from the same parent brand in a single morning reads as a deployment error, not a strategy
- 2. **Add a hard expiration date** — even a "Clearance pricing through June 1" line in the hero converts fence-sitters; every brand in my inbox that moved me to click this week had a clock on it
- 3. **Kill the Crate & Kids cross-sell or gate it** — if segmentation knows I'm not shopping C&K, that real estate should be another furniture category or a deeper clearance call-out; CB2 runs a tight single-brand lane and it shows
- 4. **Deep-link the category tiles** — "Dining" should land on dining clearance, not the clearance homepage; the navigation promise should match the destination
- 5. **Surface a specific hero piece** — one sofa or dining table at the 60% price point in the hero would anchor the abstract "up to 60%" and give me something to react to

### 3. Rendering & Accessibility

**[HIGH] Zoom disabled via viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
`maximum-scale=1` prevents pinch-to-zoom. Violates WCAG 1.4.4 (Resize Text, Level AA). Remove `maximum-scale=1`.

**[HIGH] Wildcard text-size-adjust suppression**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```
`none` applied to `*` blocks OS-level font scaling system-wide, not just on `body`. Low-vision users relying on OS font size settings are affected. Change to `body { -webkit-text-size-adjust: 100%; }`.

**[MEDIUM] Inverted image max-width media queries**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
The `min-width: 640px` rule is declared **after** the `min-width: 768px` rule. At viewport ≥768px, both match; CSS cascade awards last-declared wins, so `max-width: 640px` overrides `600px` — the wider viewport gets the larger image max-width, which is logically inverted. Swap declaration order so the `768px` rule is last.

**[LOW] No dark mode support**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Explicitly opts out of dark mode. Apple Mail, Gmail app, and Outlook on macOS will not apply dark-mode adaptation — product images and backgrounds may invert unexpectedly for users with system dark mode enabled. Evaluate `content="light dark"` with tested overrides.

**[LOW] Duplicate `format-detection` meta tags**
The `format-detection` attribute appears four times: once as a combined declaration and then separately for `date`, `address`, and `telephone`. No functional breakage; consolidate to one tag.
