### 3. Rendering & Accessibility

**[HIGH] Viewport `maximum-scale=1` blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Violates WCAG 1.4.4 (Resize Text, Level AA). Remove `maximum-scale=1`.

**[MEDIUM] Conflicting desktop image `max-width` media queries — 768px rule is dead code**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }  /* declared first */
@media only screen and (min-width: 640px) { img {max-width: 640px} }  /* declared second — overrides at 768px+ */
```
At any viewport ≥768px, both queries match but the later 640px rule wins the cascade, making the 768px/600px rule unreachable. Images render at 640px max instead of the intended 600px on desktop. Remove or reorder these rules.

**[MEDIUM] Aggressive wildcard `line-height: 100%` and `max-height: 1000000px`**
```css
* { line-height: 100%; max-height: 1000000px; }
```
`line-height: 100%` on `*` means line-height is 100% of the element's font-size, not 100% of computed line-height — this causes text clipping in many clients. `max-height: 1000000px` is a Gmail clipping workaround but applied globally is unnecessarily broad.

**[LOW] Dark mode not supported**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Forces light mode only. Apple Mail and some Android clients will still invert or recolor; declaring only `light` without a dark stylesheet means C&B has no control over dark-mode rendering.

**[LOW] Duplicate `format-detection` meta tags**
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<!-- then repeated individually: -->
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
Three redundant declarations. No functional harm but indicates a template merge error.
