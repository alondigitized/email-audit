## Technical Audit

**1. Technical Summary**
The email is a table-based XHTML Transitional build with Outlook (MSO) fallbacks and a mobile breakpoint at 460px. The QA run found 3 warnings, none of them hard failures. The main confirmed issue is missing alt text on about 45 images. The header-related warnings may come from the AgentMail relay rather than from the sender.

**2. Link & Tracking Issues**
- 86 tracking links were skipped by the HTTP probe because they are click-redirect domains. Their destinations are unverified, so no broken-link claim can be made.
- Third-party pixels are in the body:
  - Five `https://sr.rlcdn.com/448796.gif?s=…&n=1` to `n=5` beacons (LiveRamp/RampID sync). All five have no alt text.
  - `https://mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif?mi_u=…` (open pixel).
  - `https://dv.crateandbarrel.com/o/e2065408-…?mi_cid=…&mi_mid=…` (tracking image).
- The `mi_u=` tokens are long per-recipient identifiers embedded in image URLs. Six identical `mi.crateandbarrel.com/p/rp/f3c0d22992a01946.png` images are repeated, which looks like a templated personalized or "rp" block. This is not a defect, but it adds image requests.
- Several decorative spacers load from `s7d5.scene7.com` (`25%5FMI%5FBottom%5FSpacer%5F40px%5FWhite`, `042025%5FCBK%5FKidsBeds1%5FRule%5FSpacer%5F40px`). Spacer images are fragile when images are blocked.
- The hero asset `CK%5FH26%5FKidsBedding%5F4x5%5FPrimary.gif` is an animated GIF with no alt text. Its first frame matters for Outlook desktop, which shows only that frame. The source does not show whether the first frame carries the key message.

**3. Rendering & Accessibility**
- **Missing alt text (QA-confirmed):** about 45 `<img>` elements are flagged. The content images are on `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/*.jpg|gif`, for example `bbf6f9d4-86cc-437a-aa80-391067b74306.png`, `eeb8adae-5b4e-4a30-bd6d-f75109be3722.jpg` and the hero GIF. Some of these may be product tiles or CTAs. With images blocked, or for screen-reader users, those blocks would be blank or read as filenames.
- Purely decorative images (spacers, tracking pixels) should use `alt=""`. The QA tool counts a missing attribute and an empty one differently, so the spacer and pixel warnings may be partly false positives. The source is truncated, so the actual attribute values can't be checked.
- `<title>Crate & Barrel</title>` has an unescaped `&`. It is not a rendering failure in practice, but it isn't valid XHTML under the declared XHTML 1.0 Transitional doctype.
- Duplicate `<meta name="format-detection">` tags appear three times with conflicting values (`telephone=no,address=no,email=no,date=no,url=no`, then `date=no`, `address=no`, `telephone=no` separately). The redundancy is harmless, but later tags can override earlier ones in some clients.
- `p{margin:0 auto; text-align:center;}` and `*{line-height:100%; -webkit-text-size-adjust:none}` are global rules. They can override intended per-element styling, and `-webkit-text-size-adjust:none` disables text scaling on iOS. The `*` selector also sets `max-height:1000000px`, a known Gmail font-size workaround.
- A placeholder comment, `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->`, is left in the markup. It is a template artifact, and "IMPUT" is a typo. It has no functional impact.
- `lang="en"` is set on `<html>`, which is correct. The viewport meta has `maximum-scale=1`, which blocks pinch-zoom (WCAG 1.4.4 concern).
- Dark-mode metas (`color-scheme: light`, `supported-color-schemes: light`) force light mode. This is deliberate, but clients may still apply their own inversion.

**4. Personalization & Merge Tokens**
No unresolved merge tokens (`{{…}}`, `%%…%%`, `[FIRSTNAME]`) are visible in the supplied excerpt. The HTML is truncated, so the body and footer could not be fully checked. The `mi_u` and `mi_mid` parameters are resolved per-recipient identifiers.

**5. Compliance (CAN-SPAM, unsubscribe, authentication headers)**
- **`List-Unsubscribe` not found [WARN]** and **`List-Unsubscribe-Post` (RFC 8058) not found [WARN].** The QA tool itself says these may not be captured by the AgentMail relay. These are unconfirmed rather than proven defects. If they really are absent, Gmail and Yahoo bulk-sender rules (≥5,000/day) require one-click unsubscribe.
- **`Authentication-Results` not found [WARN].** SPF, DKIM and DMARC status is unknown. The From domain `mail.crateandbarrel.com` is a dedicated sending subdomain, which is good practice, but alignment can't be confirmed from this data.
- The unsubscribe link and physical address are likely in the truncated footer, so they couldn't be verified. This is not flagged as a defect.

**6. Email-to-Site Continuity (UTM params, landing page alignment)**
- All 86 links go through tracking redirects, so final destinations and UTM parameters can't be confirmed. There is no evidence of UTM misalignment.
- The email's own tracking uses `mi_u`, `mi_cid` and `mi_mid` (Cheetah/Marigold-style identifiers). Site analytics attribution therefore depends on the redirector appending UTMs, which wasn't verified.

**7. Recommendations**
1. Add descriptive `alt` text to all content images, including the animated GIF hero and the product tiles. Use `alt=""` on spacers and tracking pixels.
2. Re-run the checks against the raw original message, not the relay copy, to confirm `List-Unsubscribe`, `List-Unsubscribe-Post` and `Authentication-Results`. If they are truly missing, add RFC 8058 one-click headers and confirm SPF, DKIM and DMARC alignment.
3. Resolve the redirect chains for a sample of the 86 tracked links to verify landing pages and UTM presence.
4. Remove `maximum-scale=1` from the viewport meta, escape `&` as `&amp;` in `<title>`, and delete the duplicate `format-detection` metas and the leftover "IMPUT HERE" comment.
5. Check the first frame of the animated GIF hero for Outlook desktop.
6. Review the 5 `rlcdn.com` third-party pixels. Confirm they are intended and covered by the privacy policy.
