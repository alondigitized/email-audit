## Technical Audit

## 1. Technical Summary
The email's HTML is table-based and has `lang="en"`, but the automated checks left key items unverified. These are the unsubscribe headers, authentication results, and the destinations of all 89 tracked links. About 57 images have no alt text, and the viewport meta tag blocks pinch-zoom. The QA run scored a 57% pass rate with 0 errors and 3 warnings.

## 2. Link & Tracking Issues
- **Link destinations unverified.** QA skipped the HTTP probe on 89 tracking links ("Tracking/click-redirect domains"), so redirect chains, status codes and final landing pages are unconfirmed.
- **Third-party pixel repeated 5 times.** `https://sr.rlcdn.com/448796.gif?s=dbe8da71…f5a8&n=1` through `&n=5` is a LiveRamp pixel. The `s=` value is a 64-character hex string, which looks like a hashed recipient identifier. Only `n` differs between the five calls, so they are redundant.
- **Per-recipient identifiers in image URLs.** `mi_u=dbe8da71…` appears on `mi.crateandbarrel.com/p/rp/*.png` (7 images) and on `mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif`. A matching `mi_cid` and `mi_mid` are on the `dv.crateandbarrel.com/o/04f7253c-…` image. These are Movable Ink dynamic-content and open-tracking calls. If the content service is down or slow, the images could fail to render, and I can't tell from the truncated source whether fallbacks exist.
- **Mixed image hosts.** Images load from `image.mail.crateandbarrel.com`, `s7d5.scene7.com`, `mi.crateandbarrel.com`, `dv.crateandbarrel.com` and `sr.rlcdn.com`. That is five hosts, each of which can fail or be blocked separately.
- **Video asset.** `2026%5F0914%5FCB%5FNFLCollection%5FSocial%5FVideo.` (Scene7) is served as an image, and its filename is truncated in the QA output.

## 3. Rendering & Accessibility
- **Missing alt text on about 57 images (the largest finding).**
  - Content images on `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/…` (about 40 `.jpg`, `.png` and `.gif` files, such as `6f9ddb32-…jpg` and `e5a45dc0-…gif`). If these are linked content images, screen readers and images-off clients get no description or link purpose.
  - Tracking and pixel images (`mi.crateandbarrel.com/p/rp/*.png`, `o.gif`, `448796.gif` ×5, `dv.crateandbarrel.com/o/…`). These should carry an explicit `alt=""` so screen readers skip them. QA doesn't say whether the attribute is absent or empty, so confirm which.
- **Zoom disabled.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` blocks pinch-zoom on some clients, which fails WCAG 1.4.4.
- **Text scaling disabled.** `*{-webkit-text-size-adjust:none; …}` and `body{-webkit-text-size-adjust:none}` prevent user text resizing in WebKit clients. This conflicts with `body{-webkit-text-size-adjust:100%}` earlier in the same stylesheet.
- **Redundant meta tags.** `format-detection` is declared 5 times (`telephone=no,address=no,email=no,date=no,url=no`, then `date=no`, `address=no` and `telephone=no` separately). `charset` is declared twice, once via `http-equiv` and once via `<meta charset="utf-8">`.
- **Leftover template placeholder.** `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->` is still in the head. It's harmless but shows the template wasn't cleaned.
- **Unescaped ampersand.** `<title>Crate & Barrel</title>` uses a raw `&` under an XHTML 1.0 Transitional doctype. This is invalid XML but is tolerated by mail clients.
- **Generic `<title>`.** It says "Crate & Barrel" rather than the subject line, which matters for the web-view version.
- **Dead CSS rule.** `@media (min-width:768px){img{max-width:600px}}` is overridden by the later `@media (min-width:640px){img{max-width:640px}}`, since both match at 768px and above. The 768px rule never applies.
- **Fixed-width mobile class.** `.mobile{width:460px !important}` and `.showmobile{width:414px}` are fixed pixel widths, so they can overflow on viewports narrower than 414px.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens such as `%%…%%`, `{{…}}` or `[FIRSTNAME]` appear in the visible HTML, but the source is truncated, so the full body isn't covered.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` not found** (QA WARN). The report attributes this to the AgentMail relay possibly not capturing the header, so this is unconfirmed rather than a proven defect.
- **`List-Unsubscribe-Post` (RFC 8058) not found** (QA WARN). Same caveat. One-click unsubscribe is a Gmail and Yahoo bulk-sender requirement, so verify it against the raw original message.
- **`Authentication-Results` not found.** SPF, DKIM and DMARC alignment are unknown through the relay. The From domain is `mail.crateandbarrel.com`, so alignment with the sending infrastructure should be checked on raw headers.
- **Footer not visible.** The visible HTML doesn't show the physical postal address or the unsubscribe link, so CAN-SPAM body requirements can't be confirmed from this excerpt.
- **Third-party identifier sharing.** The LiveRamp pixel's `s=` parameter appears to be a hashed identifier, so recipient data is likely passed to a third-party data broker on open. Confirm this is covered in the privacy disclosures.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not verifiable. Click-tracking links were not probed, so UTM parameters, redirect targets and landing-page alignment with the "tailgating / NFL collection" subject can't be confirmed. Image hosts (`s7d5.scene7.com/…/2026_0913_CB_NFLCollection/…`) do suggest NFL-collection assets, but that isn't proof of link destinations.

2. Resolve a sample of the 89 tracked links in a follow-up pass. Check the redirect chain, final status codes, UTM parameters and that each destination matches its creative.
3. Add descriptive `alt` text to the roughly 40 content images on `image.mail.crateandbarrel.com`. Add `alt=""` to the pixel and tracking images (`mi.`, `dv.`, `sr.rlcdn.com`).
4. Remove `maximum-scale=1` from the viewport meta tag. Remove `-webkit-text-size-adjust:none` from the universal selector and body.

6. Reduce the five identical `sr.rlcdn.com` pixel calls to one if they serve no distinct purpose. Confirm Movable Ink fallback images exist if `mi.crateandbarrel.com` fails.
