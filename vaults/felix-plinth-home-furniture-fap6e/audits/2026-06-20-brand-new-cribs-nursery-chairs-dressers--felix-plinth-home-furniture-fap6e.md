- **Zero personalization signals.** Pottery Barn's "On sale & ready-to-ship!" send felt like it knew I'd been browsing. This feels addressed to the zip code, not me.

### 3. Rendering & Accessibility

**Confirmed issues:**

- **Conflicting `img` max-width rules.** Two media queries overlap:
  - `@media only screen and (min-width: 640px)` → `img { max-width: 640px }`
  - `@media only screen and (min-width: 768px)` → `img { max-width: 600px }`

  At ≥768px, both fire; cascade order makes 640px win (it appears later in the `<style>` block), so desktop gets a wider cap than the 768px rule intends. This is inverted — the narrower desktop cap is overridden by the tablet rule. Result: images on desktop may render 40px wider than intended.

- **`maximum-scale=1` in viewport meta** blocks user-initiated zoom on mobile — a WCAG 1.4.4 (Resize Text) failure:
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
  ```

- **`line-height: 100%` on the `*` selector** (first style block) is extremely broad. This flattens line-height for all elements globally and may collapse multi-line text in some clients.

- **Duplicate `format-detection` declarations** — defined once as a combined value and then again as three separate tags:
  ```html
  <meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
  <!-- then individually: -->
  <meta name="format-detection" content="date=no">
  <meta name="format-detection" content="address=no">
  <meta name="format-detection" content="telephone=no">
  ```
  Redundant; no functional harm, but signals template hygiene issues.

- **Duplicate `charset` declaration:**
  ```html
  <meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
  <meta charset="utf-8">
  ```
  Harmless but redundant.

- **Duplicate `ExternalClass` rules** defined in both the MI and CLIENT `<style>` blocks — specificity risk if values diverge in a future edit.

- **Dark mode: not supported.** `<meta name="color-scheme" content="light">` with no dark mode CSS. Background is hardcoded `#e6e7e8`. No `@media (prefers-color-scheme: dark)` block. Apple Mail and Gmail dark-mode clients will auto-invert; no controlled override is in place.

- **Alt text cannot be confirmed** — source truncated before `<img>` tags. Must verify in full HTML.
