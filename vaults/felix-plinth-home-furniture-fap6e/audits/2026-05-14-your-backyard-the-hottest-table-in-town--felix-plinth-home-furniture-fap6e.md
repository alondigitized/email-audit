## What's weak

- "from $30" anchor is a mismatch — I'm budgeting for a full outdoor dining setup, not a single wine glass
- The colorful goblet grid right below the hero reads as younger and more casual than my dining situation — I'm outfitting for adult dinner parties, not a backyard kegger
- The email is punishingly long — grills, dining sets, outdoor kitchen, rugs, and an app promo is too many narratives competing for the same click
- CTA button copy is unclear or garbled (appears to read "Get all my easy now") — that's a trust break right when I'm warming up
- Zero personalization — I'm a returning Wayfair buyer with two active outdoor projects and this reads like it went to every address on the list

- 1. **Lead with dining sets, not glassware** — I'm in market for a table and chairs. The hero product that converts mid-funnel buyers should be above the fold, not a $30 glass grid that signals entry-level.
- 2. **Fix the CTA copy** — "Get all my easy now" is either a merge failure or just bad writing. "Shop Outdoor Dining" is boring but functional. "Build My Outdoor Setup" actually matches the renovator mindset and earns the click.
- 3. **Cut the email to one theme** — outdoor dining OR outdoor kitchen OR rugs. Pick one, own it, send the others in separate emails this week.
- 4. **Raise the perceived price anchor** — a $299 or $449 dining set as the hero signals quality. Lead with the aspirational piece; let the $30 glassware be the upsell at the bottom.
- 5. **Drop the app promo** — I already have the app, and it kills the outdoor entertaining narrative right as it was building momentum.

### 3. Rendering & Accessibility

**Media query breakpoint at 480px** is below the viewport width of many current flagship phones (e.g., iPhone 15 Pro Max renders at 430pt; many Android flagships exceed 480px). The `u ~ div { min-width: 100vw }` Gmail hack is correct but only compensates for Gmail's specific clipping behavior — it does not substitute for a wider breakpoint.

**`<style>` block in `<head>` only.** Gmail (webmail), Yahoo, and older Android clients strip `<head>` styles. All layout-critical properties (widths, display, padding) must also be present as inline `style=""` attributes. The utility class system (`.u-FullWidth`, `.u-HalfWidth`, etc.) is invisible to those clients unless duplicated inline.

**`.u-MobileHide { display: none !important }`** — suppressing content via media query is unreliable in clients that ignore `<style>` blocks. If hidden content is decorative, acceptable. If it hides functional copy or CTA fallbacks, this is a rendering risk.

**Alt text** — cannot verify from truncated HTML. All `<img>` tags must carry descriptive `alt` attributes; images-off rendering (common in Outlook) will show blank boxes otherwise.

**`@supports (-webkit-touch-callout: none)` block** used to target iOS Safari specifically for `.u-HalfWidthBlock img` — this is a recognized workaround and is correct, but should be tested against iOS 17+ where rendering behavior changed.
