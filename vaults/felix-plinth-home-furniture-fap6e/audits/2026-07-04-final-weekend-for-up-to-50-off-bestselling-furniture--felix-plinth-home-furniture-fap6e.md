### 3. Rendering & Accessibility

**Bug — conflicting desktop `img` max-width rules (media query ordering error):**

```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }  /* declared first */
@media only screen and (min-width: 640px) { img {max-width: 640px} }  /* declared second — wins */
```

At viewports ≥768px both queries match; CSS last-declaration-wins means the 640px rule (`max-width: 640px`) always overrides the 768px rule (`max-width: 600px`). The 600px cap never applies. If the container is 640px wide this is benign, but the intent appears inverted — the larger viewport rule should be declared last or the breakpoints should be restructured.

**Accessibility — `maximum-scale=1` in viewport meta:**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

Prevents user zoom. Violates WCAG 1.4.4 (Resize Text, Level AA). Remove `maximum-scale=1`.

**Accessibility — blanket `-webkit-text-size-adjust: none` on `*`:**

```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```

Suppresses browser text-size adjustment for all elements including body copy, not just layout containers. Use `-webkit-text-size-adjust: 100%` on `body` only.

**Dark mode not supported:**

```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```

Forces light rendering in Apple Mail and other dark-mode-aware clients. Acceptable if intentional, but should be documented as a known limitation since ~50% of Apple Mail users have dark mode enabled.

**Duplicate `format-detection` meta tags:**

Three separate `format-detection` declarations — one combined and two individual — for telephone, address, and date. Redundant; no functional bug but adds unnecessary bytes.

**`line-height: 100%` on `*` selector:**

```css
*{... line-height: 100%}
```

Applied universally via the `*` selector. Can produce visually compressed line heights on paragraph text in some clients. Scope this to layout containers only.
