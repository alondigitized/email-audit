- **Near-identical to June 13** — "100+ new items added to Warehouse Sale" and "NEW ITEMS ADDED: Warehouse Sale" are the same email with a trim haircut. If I'm paying attention, I've already seen this concept. Twice in four days is a pattern, not a strategy.
- **"STILL ONGOING: DESIGN LEGENDS SALE" banner** — they told me this was "ALMOST OVER" on June 13. Now it's still going? Either I'm being played or this is a calendar coordination failure between two campaigns running out of the same sender address.
- **"Leave a Review, Win $1000" module** — completely breaks purchase flow. It belongs in a post-purchase email or the footer. Not between a back-in-stock hook and the product grid.
- **No end date visible** — "up to 60% off" without a deadline is ambient furniture noise at this point. Crate & Barrel — same family — has trained me to assume the sale just rolls forward indefinitely.
- **No price anchor in the hero** — Crate & Kids ran "Up to 50% off: Shop our 4th of July Warehouse Sale" and showed specific product prices inline. This hero has a beautiful sofa and no number attached to it.

- 1. **Pull the Review module out of the flow** — footer, post-purchase trigger, or its own dedicated send. It's a full stop in the middle of a sale email.
- 2. **Show one price in the hero** — even "from $299" on the sofa. Tie the photography to a number that makes someone act.

### 3. Rendering & Accessibility

**[HIGH] Unresolved template placeholder in production HTML:**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
This is a vendor template comment left in the live send. It is misspelled ("IMPUT" → "INPUT") and indicates the font-import slot was never actioned or removed. No functional breakage, but it reveals internal tooling to anyone inspecting source.

**[HIGH] Double-slash path in multiple `@font-face` `src` URLs:**
```css
src: url("https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2")
src: url("https://www.cb2.com//Styles/CB2/fonts/GTSectra/GT-Sectra-Display-Regular.woff2")
```
RFC 3986 treats `//` after the authority as valid but CB2's web server may return 301/404 on the double-slash path depending on IIS/nginx config. If fonts fail to load, the fallback chain (`Helvetica, sans-serif`) kicks in silently — no client-visible error, but brand font rendering is lost.

**[MEDIUM] Conflicting `@font-face` declarations for "Lineto Brown Sub":**
The same `font-family` name is declared three separate times:
1. No `font-weight`/`font-style` descriptors (matches everything)
2. `font-weight: 400` with woff2 only
3. `font-weight: 600` with woff2 only

Declaration 1 has no discriminating descriptors, so it will match all weight requests before declarations 2 and 3 in some rendering engines, making the weight-600 bold variant unreachable. The 400/600 declarations should replace, not supplement, the unqualified declaration.

**[MEDIUM] `maximum-scale=1` in viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents user-initiated zoom. WCAG 1.4.4 (AA) requires content to be resizable up to 200% without loss of content. This fails for low-vision users on iOS Safari.

**[MEDIUM] Global text-size-adjust disabled:**
```css
*{-webkit-text-size-adjust:none;-ms-text-size-adjust:none;}
```
Applied to `*` (every element). This overrides the OS-level text size accessibility setting. Should be scoped to `body` and set to `100%`, not `none`.

**[LOW] Mobile breakpoint width is 418px:**
```css
@media only screen and (max-width: 418px) { .mobile { width:414px !important; } }
```
The breakpoint targets ≤418px but the inner width is hardcoded to 414px. This is clearly written for iPhone 14 (logical width 390px) or older iPhones (375px). Devices between 415–418px wide will enter this media query but get a 414px-wide container that overflows by 0–4px. Typical safe values are `375px` (smallest target) or `390px`.
