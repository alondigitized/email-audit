## Technical Audit

## 1. Technical Summary
The email is a table-based layout built from sliced images, sent through Salesforce Marketing Cloud click tracking. The main confirmed problems are widespread missing alt text (so hero and footer slices have no accessible name), mixed-content `http://` images, recipient email addresses in plaintext pixel URLs, and broken or inert CSS. The compliance headers could not be verified from the captured data.

## 2. Link & Tracking Issues
- **Destinations unverified.** 57 links were skipped because they go through `click.e.potterybarn.com/?qs=...`, so destinations and redirect health are unknown.
- **Linked images with `alt=""`.** The hero slices (`slices_01.jpg`, `slices_02.jpg`, …) are the only content inside their `<a>` tags and have `alt=""`. The links have no accessible name, and with images blocked they are blank, unlabeled click targets.
- **Third-party tracking pixels.** `secure.leadback.advertising.com/adcedge/lb?site=695501…` and `d.turn.com/r/dd/id/...` are ad-retargeting pixels. They add third-party requests and are usually blocked by Apple MPP and privacy tooling.
- **Leftover commented-out markup.** The credit-card banner block (`cm_ite=PB_header_nonmember`) is still in the production HTML.

## 3. Rendering & Accessibility
- **Broken CSS block.** The second `<style>` block contains stray PHP text: `header('Content-Type: image/jpeg'); header("Cache-Control: ...")`. The CSS parser will read this as part of the next selector's prelude. The `a[x-apple-data-detectors]` rule that follows is likely discarded, so Apple auto-linking styles won't apply.
- **Responsive rules don't match the markup.** The `@media (max-width:480px)` rules target `table[class="wrapper"]` and `img[class="photo"]`. In the visible source, the tables are fixed `width="650"` with no `class="wrapper"`, and the images have no `class="photo"`. On mobile the layout will not collapse. The source is truncated, so later sections could differ.
- **Missing alt text.** The QA run flagged about 45 images. This includes:
  - 12 hero slices, 18 footer slices, and the `H26_*` banners.
  - Product images such as `classic-velvet-stockings-l.jpg` and `faux-fur-ruched-throw-l.jpg`.
  - The tracking pixels, which should carry `alt=""`.
- **Mixed content.** Two images use `http://`: `http://edm.potterybarn.com/pb/thekey/CC_Banner/PB/Foot_NonMem_PB.jpg` and `http://edm.potterybarn.com/pb/2022/0311_Key_CC_Email_BrandBanner/slices_02.jpg`. Some clients block these. The second path is from 2022, so it is a stale reused asset.
- **Content before the DOCTYPE.** The AMPscript comment slot sits before `<!DOCTYPE ...>`, which can push some clients into quirks mode.
- **Document-level gaps.** `<html>` has no `lang` attribute, there is no `<title>`, and layout tables lack `role="presentation"`.
- **Cross-brand asset.** `spacer_0.gif` is loaded from `edm.westelm.com`. If that host changes, this email depends on another brand's infrastructure.

## 4. Personalization & Merge Tokens
No unresolved merge tokens or AMPscript were visible in the captured source. The recipient address resolved correctly in the pixel URLs.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe and List-Unsubscribe-Post:** Both were not found. The QA tool notes that the AgentMail relay may strip them, so this is unconfirmed rather than a proven defect. RFC 8058 one-click support can't be assessed from this data.
- **Authentication-Results:** Not captured. The QA tool says SPF/DKIM/DMARC status is unknown, and this is likely a relay artifact.
- **Footer visibility:** The footer (`Email-Footer/slices_01–18.jpg`) is entirely sliced images with no alt text. Any unsubscribe link or physical address inside it would be invisible when images are off. The truncated source doesn't show whether text versions exist, so confirm in the full HTML.
- **PII in URLs:** The recipient's plaintext email appears in query strings:
  - `https://www.potterybarn.com/customer-service/coreemail.html?email=lila-hearth-potterybarn-fap6e@etell.app`
  - `https://svopn.potterybarn.com/?sv_cid=0053_00597&sv_emopen=true&sv_sveme=lila-hearth-potterybarn-fap6e@etell.app`

  Email addresses in image and pixel URLs end up in proxy and CDN logs and in Referer headers. A hashed or opaque ID would avoid this.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
This can't be assessed. All 57 links are wrapped in redirects, so UTM parameters and landing pages are not visible. The only readable first-party URL is in the commented-out block (`cm_ite=PB_header_nonmember`), and that block is not live. Pottery Barn appears to use `cm_*` campaign parameters rather than UTMs. Resolving a sample of `click.e.potterybarn.com` links would be needed to verify this.

## 7. Recommendations
1. Remove the stray `header(...)` lines from the `<style>` block so the Apple data-detector rule applies.
2. Add descriptive `alt` text to all linked images (hero, banners, products, footer). Use `alt=""` plus `width="1" height="1"` on tracking pixels.
3. Switch the two `http://` images to `https://`, and drop or replace the stale 2022 banner.
4. Replace plaintext emails in `coreemail.html` and `svopn` URLs with an opaque subscriber key.
5. Make the mobile CSS match the markup: add `class="wrapper"` and `class="photo"`, or switch to fluid `max-width` tables.
6. Move the DOCTYPE to the first line. Add `<html lang="en">`, a `<title>`, and `role="presentation"` on layout tables.
7. Remove the commented-out credit-card block and host `spacer_0.gif` on the brand's own domain.
8. Check the raw `.eml` for `List-Unsubscribe`, `List-Unsubscribe-Post`, and `Authentication-Results`, since the relay may have dropped them. Also confirm the footer has live-text unsubscribe and address.
9. Resolve a sample of tracked links to check landing pages and campaign parameters.
