## Technical Audit

## 1. Technical Summary
The email is a large, template-built XHTML 1.0 Transitional message with 78 click-tracked links. QA found no hard failures, but 20 content images have no alt text and the viewport meta tag blocks pinch-zoom. The compliance and authentication checks couldn't be verified, because the headers weren't captured and the HTML source was truncated.

## 2. Link & Tracking Issues
- **78 tracking links were not probed.** QA skipped them as click-redirect domains, so destination status, redirect chains, and broken links are unverified. This is a coverage gap, not a confirmed defect.
- **Several third-party pixels are embedded.** All appear in the QA output:
  - 6× `https://mi.crateandbarrel.com/p/rp/f3c0d22992a01946.png?mi_u=…` (the same URL repeated)
  - 5× `https://sr.rlcdn.com/448796.gif?s=…&n=1` through `n=5` (the LiveRamp/RLCDN pixel)
  - `https://mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif`
  - `https://dv.crateandbarrel.com/o/5e081145-…`
- **Pixel volume.** Thirteen tracking pixels in one message is a lot. Each is an extra request, and several are duplicates. This is a performance and privacy-surface observation.

## 3. Rendering & Accessibility
- **20 content images have no alt text.** They are on `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/…`. Examples:
  - `bbf6f9d4-86cc-437a-aa80-391067b74306.png`
  - `ec997ddd-48db-4d16-bffd-48b5b834d0f5.jpg`
  - `94703e82-4091-436e-b22b-b9245cde305b.gif`
  - `971aa10f-db11-4b79-b1d6-d95ad4507a7c.jpg`

  With images blocked, or in a screen reader, those blocks are blank or announced by filename.
- **13 tracking pixels also have no `alt` attribute.** Their `alt` should be `alt=""` (decorative), because a missing attribute makes some screen readers read the URL aloud.
- **Viewport meta blocks zoom.** The `<meta name="viewport" … maximum-scale=1 />` tag prevents pinch-zoom. This is a WCAG 1.4.4 concern.
- **Markup hygiene problems in the `<head>`:**
  - The `<title>` contains a raw `&` (`Crate & Barrel`), which is invalid under the declared XHTML 1.0 Transitional doctype and should be `&amp;`.
  - The `<title>` is the generic brand name, not the subject line.
  - `format-detection` is declared three times with conflicting values (`telephone=no,address=no,email=no,date=no,url=no`, then `date=no`, `address=no` and `telephone=no` separately).
  - Both `<meta http-equiv="Content-Type" … charset=utf-8>` and `<meta charset="utf-8">` are present.
- **Leftover template text.** The `<head>` contains the comment `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->`. It is harmless to rendering but shows an unfinished template.

## 4. Personalization & Merge Tokens
No issues found in the visible source. The HTML was truncated, so the body wasn't checked for unrendered tokens. The `mi_u=` and `mi_cid=` parameters on the pixel URLs look like resolved per-recipient identifiers, not leaked merge tags.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) were not found.** QA notes the relay may strip these, so this can't be confirmed as a sender-side defect. If the headers are really absent, Gmail and Yahoo bulk-sender rules for one-click unsubscribe are not met.
- **`Authentication-Results` was not found.** SPF, DKIM, and DMARC status is unknown. The QA tool attributes this to the AgentMail relay. The From domain, `mail.crateandbarrel.com`, is aligned with the image and tracking subdomains, but alignment is not proof of authentication.
- **Body footer not verified.** The footer, with the unsubscribe link and physical postal address, is past the truncation point, so CAN-SPAM body requirements can't be confirmed.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Unverifiable. All 78 links go through tracking redirects (not probed), and the visible source doesn't show final destination URLs or UTM parameters. QA performed no landing-page check.

## 7. Recommendations
1. Add descriptive `alt` text to the 20 content images, listed above. Add `alt=""` to all 13 tracking pixels.
2. Remove `maximum-scale=1` from the viewport meta (use `width=device-width, initial-scale=1`).
3. Escape the title ampersand (`&amp;`), set the title to the campaign subject, and remove the duplicate `charset` and `format-detection` meta tags and the stray `IMPUT HERE` comment.
4. Consolidate the duplicated `mi.crateandbarrel.com` (6×) and `rlcdn` (5×) pixels where the platform allows.
5. Re-run QA with the full headers (raw `.eml`, or an AgentMail setting that preserves them). Then confirm `List-Unsubscribe`, `List-Unsubscribe-Post`, and SPF/DKIM/DMARC.
6. Resolve a sample of the 78 tracked links to the final URLs to check for 4xx/5xx responses, redirect-chain length, and UTM parameters. Also confirm the footer unsubscribe link and postal address, using the untruncated HTML.
