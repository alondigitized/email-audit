### 3. Rendering & Accessibility

**Issue — Empty `<title>` tag:**
```html
<title></title>
```
Apple Mail renders the `<title>` value as a secondary preview line in some view modes. An empty title degrades that surface. Screen readers in some clients also announce it on focus.

**Issue — CSS syntax error (invalid selector, dark mode media query):**
```css
@media(prefers-color-scheme:dark){
  h1,h2,p,{color:#fff!important}   /* trailing comma → invalid selector */
```
The trailing comma after `p` makes the selector list unparseable. Most CSS engines will drop the entire rule block. Dark-mode `h1`/`h2`/`p` text will not be forced to `#fff` in clients that honor `prefers-color-scheme` (Gmail Android, Apple Mail, iOS Mail).

**Issue — CSS syntax error (value-level, dark mode media query):**
```css
a{color:#fff;!important}   /* semicolon before !important → invalid declaration */
```
The semicolon terminates the declaration before `!important` is parsed. The `color` rule is accepted, but the `!important` flag is lost, making it ineffective against specificity conflicts. (The `[data-ogsc]` Outlook block correctly writes `color:#fff!important` — the media query block appears to have been edited independently and diverged.)

**Note:** The `[data-ogsc]` block targeting Outlook dark mode does not share these errors and should function correctly in Outlook clients.
