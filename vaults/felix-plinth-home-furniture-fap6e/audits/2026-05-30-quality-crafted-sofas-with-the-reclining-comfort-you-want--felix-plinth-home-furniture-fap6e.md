- Fifteen. That's where the Crate & Barrel family count sits in my inbox this week, and if there was one send I was actually waiting for, this might be it. Sofas. Living room seating. - "Quality-crafted" is generic hang-tag copy that a mid-tier DTC brand would be embarrassed to use — C&B is better than this subject line and it doesn't reflect it
- The reclining framing skews slightly too functional/comfort-suburban for the visual tone the email is actually setting; the photography says premium living room, the subject says sectional showroom at a strip mall
- No price anchor, no offer, no deadline — this lands as a browse email, not a buy email, and by email fifteen from the family this week I need a reason to act today rather than wishlist-and-forget
- The app download module at the bottom treats me like a new customer; I've had the app for two years; this slot should be "find this sofa in a showroom near you" if they want to close the loop on a high-consideration purchase

### 3. Rendering & Accessibility

**[HIGH] `maximum-scale=1` in viewport meta prevents pinch-to-zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
iOS VoiceOver and low-vision users cannot zoom. WCAG 1.4.4 failure. Remove `maximum-scale=1`.

**[MEDIUM] Conflicting `img` max-width rules across overlapping media queries**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
At viewport ≥768px both queries fire; the 768px block appears last in source and wins (600px). The 640px rule is effectively dead on desktop. This is likely a residual from a template merge. Consolidate to a single rule.

**[MEDIUM] Global `line-height: 100%` via `*` selector**
```css
* { ... line-height: 100%; }
```
Applied universally, this collapses multi-line text in several clients (Gmail Android, older Samsung Mail). Should be scoped to `td, p` only, not `*`.

**[LOW] Unescaped ampersand in `<title>` (invalid XHTML)**
```html
<title>Crate & Barrel</title>
```
XHTML 1.0 requires `&amp;`. Technically invalid; benign in practice but fails strict validators.

**[LOW] `.ReadMsgBody` declared twice** — once in the "MI styling" block and again in the "CLIENT styling" block. Redundant; no functional impact.

**[LOW] `format-detection` meta declared three times** (combined form + two individual `date=no` / `address=no` repetitions). Pure redundancy.
