### 3. Rendering & Accessibility

**Bug 1 — Unclosed `@media` block (critical):**

```css
@media(prefers-color-scheme:dark){
  ...
  a .link{color:#fff!important}
</style>   ← media query never closed with }
```

The `}` closing the media query block is absent. In strict CSS parsers (Apple Mail, newer WebKit), everything inside the block is dropped; in lenient parsers, subsequent sibling `<style>` rules may be swallowed into the query. The `[data-ogsc]` block is in a separate `<style>` tag so it survives, but `@media` dark mode is effectively non-functional.

**Bug 2 — Trailing comma in selector:**

```css
h1,h2,p,{color:#fff!important}   /* inside @media prefers-color-scheme */
```

`p,{` is an invalid selector. The rule is dropped by all conformant parsers. `h1` and `h2` dark-mode text color will not apply.

**Bug 3 — Semicolon before `!important`:**

```css
a{color:#fff;!important}   /* inside @media prefers-color-scheme */
```

`!important` must be inside the declaration value, not after a semicolon. This declaration is invalid and ignored — link color in dark mode falls back to whatever the client default is.

**Bug 4 — Empty `<title>` tag:**

```html
<title></title>
```

Apple Mail and some screen readers announce the `<title>` when rendering. An empty title causes a blank announcement; should be set to the subject line or brand name.
