### 3. Rendering & Accessibility

**[HIGH] `<title>` brand mismatch**
```html
<title>Crate & Barrel</title>
```
Sender is "Crate & Kids" — the `<title>` value is surfaced in some clients (e.g., Apple Mail tab label, screen reader page title). Should read `Crate & Kids`.

**[MEDIUM] `maximum-scale=1` blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-zoom on mobile. Accessibility issue (WCAG 1.4.4). Remove `maximum-scale=1`.

**[MEDIUM] Dead CSS rule — desktop image cap overridden**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }  /* declared first */
@media only screen and (min-width: 640px) { img { max-width: 640px } }  /* declared second — wins on all screens ≥640px */
```
On any viewport ≥768px, both queries match at equal specificity; the 640px rule wins via cascade. The 600px rule is effectively dead code. Intended cap is likely 600px for the container width; swap declaration order or merge into one rule.

**[LOW] Duplicate `format-detection` meta tags — 4 declarations**
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<!-- then individually: -->
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
Redundant; no functional harm but adds noise and byte weight. Consolidate to the single combined declaration.

**[LOW] Dark mode not declared**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Explicitly opts out of dark mode. Fine as a deliberate choice, but if dark mode rendering is untested, this hard-blocks it rather than letting clients gracefully adapt. Confirm this is intentional.

**[LOW] `line-height: 100%` applied globally**
```css
* { line-height: 100%; }
```
Can cause text clipping on descenders in some clients. Standard practice is to apply to specific containers, not `*`.
