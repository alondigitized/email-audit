### 3. Rendering & Accessibility

**CSS syntax error — invalid trailing comma in selector:**
```css
/* prefers-color-scheme block */
h1,h2,p,{color:#fff!important}
```
The trailing comma before `{` is invalid CSS. Strict parsers (some webmail renderers) will drop the entire rule, leaving `h1`/`h2`/`p` text invisible in dark mode.

**CSS syntax error — semicolon before `!important`:**
```css
a{color:#fff;!important}
```
`color:#fff;!important` is malformed — the semicolon terminates the declaration before `!important` is parsed. Correct form: `color:#fff!important`. Links may not override to white in dark mode on affected clients.

**Empty `<title>` tag:**
```html
<title></title>
```
Some clients (notably older Android Gmail) surface the `<title>` as a preview snippet fallback. An empty value is harmless but a missed opportunity; not a rendering defect.

**`supported-color-schemes` meta/CSS property:** Used both as a `<meta>` tag and in CSS (`:root` block). `supported-color-schemes` is a legacy Apple Mail hint; the current standard is `color-scheme`. Both are present, which is correct defensive practice — no defect.
