### 3. Rendering & Accessibility

**`maximum-scale=1` blocks user zoom (WCAG 1.4.4 violation)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-zoom on mobile. This is a WCAG 1.4.4 (Resize Text) failure.

**Global `text-size-adjust: none` applied via `*` selector**
```css
*{-webkit-text-size-adjust:none;-ms-text-size-adjust:none; ...}
```
Applied to every element, not just `body`. This overrides assistive technology text scaling globally.

**Conflicting `img` max-width breakpoints**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
Both rules target desktop. The 640px rule fires first but is then overridden at 768px+ by the 600px rule. On tablet viewports (640–767px), images render up to 640px — wider than the 600px container — which may cause horizontal overflow on certain email clients. The 640px rule appears to be dead code for the intended 600px container.

**`<title>` does not match sender brand**
```html
<title>Crate & Barrel</title>
```
Sender is "Crate & Kids SALE." The tab title shows the parent brand. Low impact but inconsistent; some clients surface the `<title>` in preview panes.

**Duplicate `<meta name="format-detection">` declarations**
Four separate format-detection tags are present — one omnibus declaration plus three redundant single-attribute declarations:
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
Harmless but indicates copy-paste accumulation across template versions.

**Duplicate `charset` declaration**
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta charset="utf-8">
```
Both are present. Redundant; not harmful.
