### 3. Rendering & Accessibility

**`maximum-scale=1` blocks zoom (WCAG 1.4.4 violation)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from pinching to zoom. Remove `maximum-scale=1`.

**Conflicting `img` max-width media queries — wrong cascade order**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
At ≥768px both rules match; the 640px rule wins (declared later), setting images to 640px instead of the intended 600px. Swap declaration order or restructure breakpoints.

**Aggressive `*` line-height reset will flatten text**
```css
*{line-height: 100%; mso-line-height-rule:exactly;}
```
Applies `line-height: 100%` to every element globally. Multi-line text (paragraphs, legal copy) will collapse unless every instance uses `!important`. High risk of overlapping text in Outlook.

**Duplicate `format-detection` meta tags (4 declarations)**
`telephone=no`, `address=no`, and `date=no` are declared individually after already being set in the combined tag on line 1. Redundant noise; benign but sloppy.

**Duplicate charset declarations**
Both `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` and `<meta charset="utf-8">` are present. Harmless but should be consolidated.

**Unencoded `&` in `<title>`**
```html
<title>Crate & Barrel</title>
```
XHTML 1.0 Transitional requires `&amp;`. Will cause XHTML parse errors in strict validators; benign in practice but technically invalid per the declared doctype.

**No dark mode support**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Forces light rendering in Apple Mail/supported clients. Dark mode users get no adaptation. Not a bug, but a rendering limitation worth flagging.
