## Technical Audit

## 1. Technical Summary
The email is built on a Movable Ink/Salesforce-style template with 63 redirect-tracked links, about 29 images with no `alt` attribute, and a few CSS and markup defects. Header-based compliance and authentication checks could not be verified. The relay likely stripped those headers, and the HTML source was truncated before the footer.

## 2. Link & Tracking Issues
- **Unverified links:** 63 links were skipped by the QA probe because they use tracking or click-redirect domains. Destination status, redirect chains and expiry are unconfirmed. This is a coverage gap, not a defect.
- **Duplicate third-party pixels:** `https://sr.rlcdn.com/448796.gif?s=56aaa278…&n=1` through `n=5` is the same LiveRamp pixel fired five times with an incrementing counter. This adds requests and third-party data sharing. It has no functional benefit visible in the source.
- **Recipient identifier in image URLs:** The `mi_u=56aaa2787a6773d0f164733102dce5192f75df7c634bb941bb640686964…` token appears on `mi.crateandbarrel.com/p/rp/*.png`, on `…/p/up/50c75a732e99b42a/o.gif` and on the `dv.crateandbarrel.com/o/30cafb78-…` open pixel. The `s=` value on the rlcdn pixel appears to be the same hash. This is a stable per-recipient ID exposed in image URLs. It is normal for the platform, but it is a privacy consideration.

## 3. Rendering & Accessibility
- **Missing `alt` (about 29 images):**
  - 15 content images on `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/…` (jpg/gif) and `/m/47/bbf6f9d4-…png`. If they carry offer or product information, that information is lost with images blocked or in a screen reader.
  - 7 `mi.crateandbarrel.com/p/rp/*.png` images. They are probably dynamic content blocks, so they may also be content.
  - 7 tracking pixels (5 rlcdn, `o.gif`, `dv.crateandbarrel.com/o/…`). These should have `alt=""`. An absent attribute makes some screen readers read out the filename or URL.
- **Zoom disabled:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` blocks pinch-zoom on mobile, which is a WCAG 1.4.4 concern.
- **Conflicting `img` max-width rules:** `@media (min-width:768px){img{max-width:600px}}` and `@media (min-width:640px){img{max-width:640px}}` both match at 768px and above. The later rule wins, so the 600px rule is dead code and images cap at 640px.
- **Markup nits:**
  - `<title>Crate & Barrel</title>` has an unescaped `&`, which is invalid under the declared XHTML 1.0 Transitional doctype.
  - `<meta charset="utf-8">` is not self-closed, which is also invalid XHTML.
  - `format-detection` is declared three times (combined and split).
  - A template placeholder comment, `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->`, is left in the shipped source.
- **Global `p{margin:0 auto; text-align:center}`:** This forces centered paragraphs everywhere and can override intended left-aligned copy unless each case is overridden inline.
- **Positives:** `lang="en"` is set, MSO conditional blocks are present, and `color-scheme` is pinned to light.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens such as `{{…}}`, `%%…%%` or `[FIRST_NAME]` appear in the visible source. The truncated remainder is not covered.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058):** Both are reported missing. The QA tool itself notes the AgentMail relay may not capture them, so this is unconfirmed rather than a confirmed sender defect. Gmail and Yahoo require one-click unsubscribe for bulk senders, so check the raw message headers.
- **`Authentication-Results`:** Not found, so SPF, DKIM and DMARC status is unknown. This is expected via the relay. The From domain, `mail.crateandbarrel.com`, matches the image host `image.mail.crateandbarrel.com`, which is consistent with aligned sending, but alignment is not verified.
- **Footer:** The physical address and the in-body unsubscribe link are not visible in the truncated source, so they cannot be confirmed.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
No confirmable issues. No destination URLs or UTM parameters appear in the provided source, and the 63 tracked links were not resolved. Whether the redirects land on the sale or markdown pages promised in the subject ("New markdowns on furniture, decor & more") is unverified.

## 7. Recommendations
1. Add descriptive `alt` text to the 15 `image.mail…` content images and check whether the 7 `mi…/p/rp/*.png` images carry content. Set `alt=""` on all tracking pixels.
2. Remove `maximum-scale=1` from the viewport meta tag.
3. Collapse the five identical rlcdn pixel calls into one, or confirm each is needed.
4. Re-run QA against the raw `.eml`. This would confirm `List-Unsubscribe`, `List-Unsubscribe-Post` and `Authentication-Results`, and would cover the footer address and unsubscribe link.
5. Resolve the 63 redirect links with a follow-redirects check to verify landing URLs, status codes and UTM parameters.
6. Clean up the template: escape `&` in `<title>`, remove the placeholder comment, de-duplicate `format-detection`, and fix the conflicting `img` max-width media queries.
