### 3. Rendering & Accessibility

**Confirmed issues:**

- **`maximum-scale=1` in viewport meta** prevents pinch-to-zoom. This is an accessibility violation (WCAG 1.4.4 — Resize Text). Remove this attribute.
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
  ```

- **Conflicting image `max-width` media queries** — the 768px breakpoint overrides the 640px one incorrectly due to cascade order:
  ```css
  @media only screen and (min-width: 768px) { img {max-width: 600px} }  /* declared last */
  @media only screen and (min-width: 640px) { img {max-width: 640px} }  /* declared first */
  ```
  At viewports ≥768px, `600px` wins (last declared). At 640–767px, `640px` applies. The intent appears reversed — larger viewport gets smaller max-width. Swap declaration order or consolidate.

- **`*{-webkit-text-size-adjust:none}` global rule** suppresses system-level text scaling for users with accessibility needs. Scope this to `body` only, not the `*` wildcard.

- **Duplicate `format-detection` meta tags** — appears 4 times total (once combined, then three individual overrides). Redundant; the combined tag already covers all three signals:
  ```html
  <meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
  <meta name="format-detection" content="date=no">     <!-- redundant -->
  <meta name="format-detection" content="address=no">  <!-- redundant -->
  <meta name="format-detection" content="telephone=no"> <!-- redundant -->
  ```
