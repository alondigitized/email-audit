## Technical Audit

**1. Technical Summary**
The email's HTML is heavily templated and mobile-aware, but the automated checks turned up gaps in accessibility, an insecure (HTTP) tracking-pixel family, and header data missing from the capture. The QA run reports a 57% pass rate with 0 errors and 3 warnings. Most link probes were inconclusive because of rate limiting.

**2. Link & Tracking Issues**
- **Probe coverage is incomplete.** 12 links were probed and 63 were skipped. 4 more product links were not checked because the 70s time budget ran out. These are the `wayfair-product-L37-K~W002846587.html` and `wayfair-product-L54-K~W112490693.html` URLs, each appearing twice. They are neither pass nor fail.
- **Every probed link returned HTTP 429.** Examples are `https://www.wayfair.com/daily-sales?...`, `https://www.wayfair.com/?...`, the `wayfair-product-L6364-K~W117486328.html` PDP, and the `wayfairapp.onelink.me/2420802157` app link. A 429 is a rate limit from the probe's request rate. It does not show the links are broken, so I can't confirm any link is valid or invalid.
- **Insecure tracking pixels.** 20 `<img>` beacons use plaintext HTTP, for example `http://li.wayfair.com/imp?s=124126000&sz=2x1&m=false&p=b8dd1c6b-...`. The `s=` values run from 124126000 to 124126019. Clients that block mixed or non-HTTPS content may drop them, which undercounts impressions.
- **Per-link tracking IDs are unique to this recipient.** Each URL carries `_emr=b8dd1c6b-...` and a distinct `_eml=` value. This is expected for tracking, but it makes URL-based deduplication and caching impossible. It is not a defect.
- **The `t.wayfair.com/b.php?x=...` open pixel has no alt text.** This is a WARN in the checks (see section 3). Its base64 payload includes `eventType=EmailOpen`.

**3. Rendering & Accessibility**
- **Missing alt text on content images.** These images have no alt text:
  - the hero banner `0929_bigfurnituresale_skinnyhero-general.jpg`
  - the header `email-sku-headers_test-06.jpg`
  - several product/lifestyle images (`wfusca_jt800_batch11_livingroom_dogbeds_s...`, `wfus_jt800_minibahn_singleclass_dressers_...` ×3, `020124_galacticrefresh_tile_product_headb...`, and others)
  - 8 instances of `stars_10.png`

  Two of these are wrapped in links: the hero (`sltid=4`) and the header (`sltid=5`). The link text is then reported as the filename, e.g. `[image: 0929_bigfurnituresale_skinnyhero-general]`. With images blocked or on a screen reader, those links have no meaningful label.
- **Star-rating images (`stars_10.png`) are inside the product link** (`sltid=5`, sku `FMCR1779`). Without alt text they read as a filename to assistive tech, and the rating is not conveyed as text.
- **Tracking `<img>` elements (`b.php`, `imp`) lack alt.** These are decorative 1×1 or 2×1 beacons. They should use `alt=""` so screen readers skip them, but this is low severity.
- **Stale or test asset names.** `email-sku-headers_test-06.jpg` ("test" in the filename) and `0728_Outd%oorClearance_SkinnyHero-VP.jpg` are in the send. The second is from a July outdoor clearance and sits in a late-September email. Its filename also has a malformed percent-escape (`%oo`), which is not a valid `%XX` sequence. Whether it loads depends on the CDN and the client. The probe did not test it.
- **Responsive CSS is present.** The `@media (max-width: 480px)` block and the `u ~ div` and `u + .Gmail` Gmail fixes are in place. Nothing in the visible source is broken. The HTML was truncated, so the rest of the markup is unverified.

**4. Personalization & Merge Tokens**
No issues found. No unresolved merge tokens (`{{...}}`, `%%...%%`, `[FIRST_NAME]`) appear in the visible source or in the probed URLs. The truncated HTML means this covers only the portion provided.

**5. Compliance (CAN-SPAM, unsubscribe, authentication headers)**
- **`List-Unsubscribe` was not found.** The check notes the header may not be captured by the AgentMail relay. That makes this a capture limitation, not confirmed sender non-compliance.
- **`List-Unsubscribe-Post` (RFC 8058) was not found.** This has the same caveat. One-click unsubscribe support is unconfirmed. Gmail and Yahoo bulk-sender rules require it.
- **`Authentication-Results` was not found.** SPF, DKIM and DMARC status are unknown. The From domain is `members.wayfair.com`. Alignment and pass status need to be checked against the raw message headers.
- **Body unsubscribe link and physical address.** The QA note says an unsubscribe link is always included in probing. The truncated HTML doesn't show the footer, so I can't confirm the body unsubscribe link or a postal address.

**6. Email-to-Site Continuity (UTM params, landing page alignment)**
- **No standard UTM parameters.** Links use Wayfair's own scheme instead: `source=graymatter_batch`, `batchid=15`, `varid=2`, `csnid=`, `sltid=`, `refid=MKTEML_121675`, `emlid=101`, `maiid=16371`, `mdlid=`. Nothing carries `utm_source`, `utm_medium` or `utm_campaign`. This is a gap only if the analytics setup expects UTM tags.
- **The app link differs from the web links.** It uses `c=Triggered` and `pid=Email` on the `wayfairapp.onelink.me` link (AppsFlyer) although the send is a batch campaign (`source=graymatter_batch`). `c=Triggered` is a campaign label that doesn't match the batch source, which could misattribute installs in AppsFlyer.
- **The subject and destinations don't line up.** The subject is "HOLIDAY ACCENTS — our top picks." The probed links go to `/daily-sales`, the homepage, and a party-supplies PDP (`How to Train Your Dragon Birthday Party Supplies`). The hero image is `0929_bigfurnituresale_skinnyhero-general`. The destinations are generic, and no link visibly goes to a holiday-accents landing page. Landing-page alignment can't be verified from the 12 probed links, because no destination content was fetched.
- **Two different image links go to the homepage** (`sltid=2` and `sltid=5`, both to `https://www.wayfair.com/?...`), one of them the product-header image. Header images that resolve to the homepage instead of a category or PDP add friction.

**7. Recommendations**
1. Move the 20 `li.wayfair.com/imp` beacons to HTTPS, and set `alt=""` on all beacons (`b.php`, `imp`).
2. Add descriptive alt text to the hero, header, product and lifestyle images. Give `stars_10.png` a text equivalent such as `alt="5 out of 5 stars"`. Any image that is the only content of a link needs alt text that describes the destination.
3. Remove test-named and out-of-season creative (`email-sku-headers_test-06.jpg`, `0728_Outd%oorClearance_SkinnyHero-VP.jpg`), and fix the malformed `%oo` in that filename.
4. Check the raw headers for `List-Unsubscribe`, `List-Unsubscribe-Post: List-Unsubscribe=One-Click`, and `Authentication-Results` (SPF, DKIM, DMARC pass, aligned to `members.wayfair.com`). Do not treat the current warnings as confirmed failures.
5. Re-run link probing with lower concurrency or backoff, and a longer budget, to clear the 429s and cover the 4 unprobed product links.
6. Point the header/hero links at destinations that match the campaign, and confirm the `c=Triggered` label on the app link.
7. Consider adding `utm_*` parameters if downstream analytics needs them.
