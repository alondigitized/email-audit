### 3. Rendering & Accessibility

**`maximum-scale=1` blocks user zoom (mobile)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-zoom on iOS/Android. This is an accessibility barrier for low-vision users and also violates WCAG 1.4.4.

**Conflicting desktop `max-width` media queries**
```css
@media only screen and (min-width: 640px) { img { max-width: 640px } }
@media only screen and (min-width: 768px) { img { max-width: 600px } }
```
The 768px rule overrides the 640px rule on wider viewports, so images are *narrower* on 768px+ screens than on 640–767px screens. Both rules should target the same breakpoint or the 768px value should be ≥ 640px.

**Aggressive universal selector**
```css
* { line-height: 100%; max-height: 1000000px; }
```
`line-height: 100%` on `*` can collapse line-height on nested elements that need a larger value (buttons, headings). This is a common hack but is known to break rendering in certain Outlook builds.

**Duplicate meta declarations**
- `format-detection` is declared 4× (once combined, then individually for `date`, `address`, `telephone`)
- `charset` is declared twice (`http-equiv="Content-Type"` and bare `meta charset`)
These are harmless but indicate a poorly maintained template base.
