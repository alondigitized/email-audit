### 3. Rendering & Accessibility

**Conflicting `img` max-width media queries (CSS rendering defect):**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }  /* declared after */
```
At viewports ≥768px, both rules apply; the 640px rule wins by cascade order, making the 600px rule dead code. Images render at 640px on desktop, not 600px as apparently intended.

**Viewport `maximum-scale=1` disables user zoom:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Violates WCAG 1.4.4 (Resize Text). Should be removed or set to `maximum-scale=5`.

**Global `text-size-adjust: none` is overly broad:**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none;}
```
Applied to every element via `*` selector, not just `body`. Can suppress OS-level accessibility font scaling across all text nodes.

**Duplicate `format-detection` meta tags (4 redundant declarations):**
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<!-- then separately: -->
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
The combined declaration on line 1 is sufficient. The three individual repeats are redundant and add noise to the `<head>`.

**Forced light-mode only:**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Dark-mode clients (Apple Mail, Gmail app) will not apply dark-mode adaptations. Acceptable as a deliberate choice, but note it may reduce readability for dark-mode users.
