## Technical Audit

## 1. Technical Summary
The HTML is a standard Marketo-style ESP template that is structurally sound but has widespread missing `alt` attributes (about 40 flagged images). Header-level compliance and authentication could not be verified, and all 84 tracked links were skipped, so continuity could not be checked. The QA run scored a 57% pass rate with 0 errors and 3 warnings. The HTML source was truncated, so footer and body checks are limited.

## 2. Link & Tracking Issues
- **Link destinations are unverified.** 84 links go through tracking or click-redirect domains and were skipped by the HTTP probe. Final destinations, redirect chains and 404s are unconfirmed.
- **Third-party pixel repetition.** `https://sr.rlcdn.com/448796.gif?s=…&n=1` through `n=5` are five separate LiveRamp (rlcdn) pixel calls.
- **First-party pixels:**
  - `https://mi.crateandbarrel.com/p/rp/f3c0d22992a01946.png?mi_u=…` appears 6 times.
  - `https://mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif` is the open pixel.
  - `https://dv.crateandbarrel.com/o/2ce714ee-…?mi_cid=…&mi_mid=…` is a further tracker.
- **Redundant pixels.** Repeating the same `f3c0d22992a01946.png` six times adds requests without adding data.
- **Subscriber ID shared with a third party.** The `s=` value on the rlcdn pixels (`56aaa2787a6773d0f164733102dce5192f75df7c634bb941bb6406869640cfd8`) matches the `mi_u` value on the mi.crateandbarrel.com pixels. The same persistent identifier appears to be sent to a third party, which is worth checking against the privacy policy.

## 3. Rendering & Accessibility
- **Missing alt text (about 40 images, per QA).**
  - Content images (`.jpg` under `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/`) have no `alt`, for example `3930ebb6-…jpg`, `1cce28bd-…jpg` and `b369fa96-…jpg`.
  - Animated GIFs also lack alt: `024feb9f-…gif`, `2417c77e-…gif`, `d24f24c6-…gif`, `9c5d35f4-…gif`, and the scene7 `…ezgif2.` asset.
  - If images are blocked, the content is lost and screen readers fall back to filenames.
- **Spacers and pixels need empty alt.** Spacers (`25%5FMI%5FBottom%5FSpacer%5F40px%5FWhite`, `042025%5FCBK%5FKidsBeds1%5FRule%5FSpacer%5F40px`) and tracking pixels should carry an explicit `alt=""`. The QA flagged them as missing alt, which suggests the attribute is absent entirely.
- **Zoom is restricted.** `<meta name="viewport" … maximum-scale=1>` blocks pinch-zoom on mobile. This is a WCAG 1.4.4 concern.
- **Text resizing is disabled.** `*{-webkit-text-size-adjust:none;…}` and `html{-webkit-text-size-adjust:none}` disable text-size adjustment globally.
- **Generic `<title>`.** `<title>Crate & Barrel</title>` has an unescaped `&`, which is invalid under the declared XHTML 1.0 Transitional doctype. It also doesn't describe the email.
- **Doctype mismatch.** The doctype is XHTML 1.0 Transitional, but unclosed `<meta charset="utf-8">` is HTML5 syntax. `charset` is also declared twice (http-equiv plus meta).
- **Dead CSS rule.** `@media (min-width:768px){img{max-width:600px}}` is followed by `@media (min-width:640px){img{max-width:640px}}`. At 768px and above both match, and the later rule wins, so the 600px cap never applies.
- **Leftover template placeholder.** `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->` is still in the head. It is harmless but shows an unfinished template.
- **Line-height override.** The universal `*{line-height:100%}` rule may compress text.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens (`%%…%%`, `{{…}}`, `[FIRST_NAME]`) appear in the visible source. The `mi_u` and `mi_cid`/`mi_mid` values are populated. Because the HTML was truncated, later sections were not checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe not found (WARN).** This is not confirmed as a sender defect, because QA notes the header may be stripped by the AgentMail relay.
- **List-Unsubscribe-Post not found (WARN).** Same caveat. If it is really absent, RFC 8058 one-click unsubscribe isn't supported. Gmail and Yahoo require it for bulk senders.
- **Authentication-Results not found (WARN).** SPF, DKIM and DMARC status is unknown. The sender domain `mail.crateandbarrel.com` is aligned with the From address, but this can't be confirmed from the data.
- **Footer not assessable.** The visible source doesn't include the footer, so the physical address and the unsubscribe link can't be verified.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not verifiable. All 84 links were skipped as tracking redirects, so UTM parameters and landing pages could not be checked. No issues are confirmed.

## 7. Recommendations
1. **Add `alt` text to every content image and GIF.** Use `alt=""` on spacers and tracking pixels. This is the largest confirmed issue.
2. **Remove `maximum-scale=1` from the viewport meta.** Drop the global `text-size-adjust:none` where possible.
3. **Re-run header checks against the original message.** Use raw `.eml` headers rather than the relay copy, and confirm `List-Unsubscribe`, `List-Unsubscribe-Post` and SPF/DKIM/DMARC pass.
4. **Resolve tracked links in a headless client.** Capture final URLs and UTMs, then check destination status and parameter consistency.
5. **Consolidate duplicate pixels.** In particular the six `f3c0d22992a01946.png` and five rlcdn `448796.gif` calls.
6. **Template cleanup:**
   - Escape `&` in `<title>` and set a meaningful title.
   - Reorder or remove the conflicting `img max-width` media queries.
   - Remove the "IMPUT HERE" placeholder comment and the duplicate `format-detection` and `charset` declarations.
