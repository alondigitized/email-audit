## What's weak

- **"NEW COLLECTION" as a subject line is the minimum viable effort.** Article's July 14 entryway editorial led with "Get your entryway ready for summer" — a specific room, a specific season, a reason to open. CB2 sent me two words that tell me nothing about what's in the collection, in all caps.
- **No hero product.** I can see multiple vignettes but I can't identify a single item being positioned as the launch centerpiece. Even Wayfair's annoying "KITCHEN MATS under $30" email told me exactly what I was clicking for.
- **No offer, no urgency, no reason this is a today problem.** The editorial tone is fine but it needs to commit. Article commits. The "WHY SLIP INTO..." section I caught lower in the scroll wants to be storytelling but reads like it ran out of room.
- **Cadence is destroying the signal.** This is the third CB2 email in roughly 48 hours. "GET IT ON SALE" on July 13, the gallerist piece on July 12, and now a new collection drop. By the time I see "new collection" I'm already treating it like background noise.

- 1. **Rewrite the subject line — this is the highest-leverage fix.** Name a product category, a material, a price anchor, anything that tells me what's new. The body earns it; the subject doesn't.
- 2. **Lead with one hero product, not a lifestyle tableau.** Give me a specific sofa or floor lamp that's new to the line, link it directly, show the price. Article does this even in pure editorial sends — there's always one piece you can click for.
- 3. **Add a social proof signal.** "Just dropped" is fine. "The piece we've been designing since winter" or even a single quote earns more trust than a mood board.
- 4. **Treat this like a launch, not a broadcast.** A collection drop deserves first-look framing — even Pottery Barn does "shop before it sells out" as a signal of value, not inventory scarcity.
- 5. **Pull the cadence back.** Two sends in 48 hours on different creative tracks (sale, editorial) reads as one undifferentiated firehose. The gallerist email on July 12 was good. This could have been good with breathing room.

### 3. Rendering & Accessibility

**Critical — Global `text-size-adjust: none`:**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
Applied to every element via the `*` selector. This suppresses OS-level font scaling for visually impaired users and violates WCAG 1.4.4 (Resize Text). The correct value is `100%`, not `none`.

**Mobile breakpoint mismatch:**
The single responsive breakpoint fires at `max-width: 418px` targeting a `.mobile` class set to `width: 414px`. This misses common viewport widths between 419px–767px — the email will render as desktop layout on mid-size phones (e.g., iPhone Plus/Pro Max in landscape).

**Font-face collision — three declarations for the same family:**
```css
@font-face { font-family: "Lineto Brown Sub"; src: url("...eot"); ... }
@font-face { font-family: "Lineto Brown Sub"; src: url("...woff2"); font-weight: 400; }
@font-face { font-family: "Lineto Brown Sub"; src: url("...woff2"); font-weight: 600; }
```
The first declaration omits `font-weight`, creating an ambiguous cascade. In practice, the latter two override it correctly, but the first block is dead weight that adds parse cost.

**"Lineto Brown Light Sub" missing woff2:**
```css
@font-face { font-family: "Lineto Brown Light Sub"; src: url("...lineto-brown-light.woff"); }
```
Only `.woff` is declared — no `woff2` format. All modern clients will download the larger `.woff` file unnecessarily.

**Cross-brand font dependency (HNW05 from crateandbarrel.com):**
Four `@font-face` blocks load `HNW05` from `https://www.crateandbarrel.com/webfonts/...`. A DNS or CDN issue on the sibling brand's domain directly degrades CB2 email rendering. These should be mirrored to CB2's own CDN or served from a shared static asset host.

**`max-height: 1000000px` on all elements:**
```css
* { max-height: 1000000px; }
```
This is a known Gmail clipping workaround but is applied globally via `*`. It can interfere with layout in clients that respect it literally. Scope it to `body` or the wrapper table only.
