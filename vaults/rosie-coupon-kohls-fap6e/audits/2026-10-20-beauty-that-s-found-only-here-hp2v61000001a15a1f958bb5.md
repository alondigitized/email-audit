- The "ONLY AT SEPHORA" hero is bold and on-subject, with a strong pink block and a clear "SHOP NOW" button.

- The top of the email leads with two unrelated promos, 4X Points on moisturizers and a free sample bag, so the "only here" hero doesn't come first.

# Technical Audit: "Beauty that's found only here ❤️" (Sephora Insider)

## 1. Technical Summary
The HTML is a table-based XHTML 1.0 Transitional email with responsive media queries. The one hard QA failure is an empty plain-text part (0 chars). Header-based compliance and authentication checks are inconclusive because the AgentMail relay may strip those headers. The HTML source was truncated, so the body links, footer and unsubscribe block were not available to inspect.

## 2. Link & Tracking Issues
- **Probe coverage is partial.** 12 material links were probed and 43 were skipped, so about 78% of links are unverified. The QA output gives no per-link status codes, so I can't confirm any broken or redirecting links.
- **Open-tracking image:** `https://app.sephora.com/O/AQEAAZcF2gAndjYxMDAwMDAxYS0x...` is a long opaque token path on `app.sephora.com`. It looks like a tracking pixel or open beacon and is missing alt text (see section 3).
- **Third-party image host:** assets are served from `images.harmony.epsilon.com/ContentHandler/images/de0a3226-...`. This is normal for an ESP and needs no action. Any outage there would break every image.
- No other link or tracking defects are confirmed.

## 3. Rendering & Accessibility
- **Plain-text fallback is missing (QA FAIL).** The text version is 0 chars, so this is multipart with an empty text part or HTML-only. That hurts accessibility, text-only clients and spam scoring.
- **Three images have no alt attribute (QA WARN):**
  - `2021_Navs_Header_06.jpg` (`images.harmony.epsilon.com/.../2021_Navs_Header_06`)
  - `US_4XHYDRATE_Barcode.jpg` (`.../US_4XHYDRATE_Barcod...`)
  - The `app.sephora.com/O/AQEAAZcF...` image
  - If the first two carry content, the missing alt text matters, and the barcode is likely functional. If the third is a tracking pixel, it should have `alt=""`.
- **Zoom is blocked:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />`. `maximum-scale=1` prevents pinch-zoom, which is a WCAG 1.4.4 concern.
- **Text resizing is disabled:** the CSS sets `-webkit-text-size-adjust: none; -ms-text-size-adjust: none; -moz-text-size-adjust: none; text-size-adjust: none` on `div, a, tr, table, body, span, img, strong, td`. Users can't enlarge text on some clients.
- **Invalid meta value:** `<meta name="robots" content="no index" />` has a space. The valid token is `noindex`, so the directive is likely ignored. The impact is minor.
- **Generic `<title>`:** `<title>Sephora</title>` doesn't describe the message. This is a minor point for web-view and screen-reader use.
- The `<!-- US shell snippet -->` comment is a leftover template comment. It's harmless.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens (`%%…%%`, `{{…}}`, `[FNAME]`) appear in the visible source or the subject. The truncated body could not be checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)

Verify against the raw original message before treating them as defects. If the headers really are absent, Gmail and Yahoo bulk-sender rules require one-click unsubscribe.
- **`Authentication-Results` not found (WARN).** SPF, DKIM and DMARC alignment are unknown. The sender is `shop@beauty.sephora.com`, but nothing here confirms authentication passes.
- **In-body unsubscribe link and physical address:** an unsubscribe link is always included in link probing, but its result isn't in the QA output. The postal address is not visible in the truncated source. Neither could be confirmed.
