## Technical Audit

## 1. Technical Summary
The email has a broken personalization slot (`Hi ,`) and no plain-text part. Its table layout is fixed at 700px, and the `<style>` block contains malformed CSS. The QA pass rate is 38%, with 2 FAIL and 3 WARN. The HTML source was truncated, so footer, unsubscribe and physical-address markup could not be inspected.

## 2. Link & Tracking Issues
- **Opaque redirect wrapping:** Links go through `https://app.sephora.com/T/v61000001a1cb0152a2c04fe0369fea47bc/.../?__dU__=...`. The final destination and any UTM parameters cannot be verified from the source.
- **Probe coverage:** Only 12 of 60 links were probed and 48 were skipped (footer, utility and social links are deprioritized), so those are unverified. The unsubscribe link is always probed, but the QA data does not report its result.
- **Tracking pixels missing `alt`** (QA WARN, the same two images):
  - `https://app.sephora.com/O/AQEAAZcF2g...` is hidden with `display:none; max-height:0; mso-hide:all`, so the missing `alt` has little practical effect.
  - `https://mi.sephora.com/p/up/f6716d0a0f52104e/o.gif?mi_u=4970269939971072&mi_ecmp=20261111_Exclusive_Gifts` carries a numeric user ID (`mi_u`) in the query string.
- **Structured data:** The JSON-LD block has `"@type": "DiscountOffer", "discountCode": ""` (empty value) and a bare `"@type": "PromotionCard"` with no properties. This is incomplete markup that will be ignored or flagged by clients that parse it.

## 3. Rendering & Accessibility
- **Malformed CSS:** `<!--[if mso]> img.mso-size {...} <![endif]-->` sits inside the `@media only screen and (max-width:480px)` block in `<style>`. Conditional comments are not valid in CSS, so parsers may drop or mis-parse the rules that follow it (`.mobileHeaderTierRouge`, `.mobileHeaderTierVIB`, `.mobileHeaderTierBI`, `.mobileIcon`, `.mobileBelong`, `.footerBanner`, `.mobileDisc`).
- **Fixed-width layout:** The wrapper is `<table width="700" style="min-width:700px; width:700px">`. The media query only adjusts font sizes and image dimensions, so the 700px table will not reflow on narrow viewports.
- **Zoom disabled:** `<meta name="viewport" content="... maximum-scale=1">` blocks pinch-zoom, which is a WCAG 1.4.4 concern.
- **Invalid robots value:** `<meta name="robots" content="no index">` should be `noindex`. The impact is minor.
- **No `lang` attribute:** `<html xmlns=...>` has no `lang`.
- **Layout tables:** The visible tables carry no `role="presentation"`.
- **Generic title:** `<title>Sephora</title>` does not identify the message.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** The greeting renders as `Hi ,`, so the first-name merge field resolved to an empty string with no fallback.
- The Epsilon redirect wrapping can mask other unresolved tokens. None were visible in the truncated source.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **[WARN] `List-Unsubscribe` not found** and **[WARN] `List-Unsubscribe-Post` (RFC 8058) not found.** The QA note says AgentMail may not capture these headers. Treat them as unverified, not confirmed missing.
- **[WARN] `Authentication-Results` not found:** SPF, DKIM and DMARC status is unknown for the same relay reason. The From domain `beauty.sephora.com` is a subdomain, but alignment cannot be confirmed from the data given.
- **[FAIL] Plain-text part is 0 chars.** A missing text/plain alternative is a deliverability and accessibility defect. Some spam filters penalize HTML-only mail.
- The physical address and the visible unsubscribe link were not visible in the truncated source, so they could not be assessed.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **UTMs not verifiable:** Tracking is carried by the `__dU__` token in the redirect, and no `utm_*` parameters are visible in the source or the QA data.
- **Landing page alignment:** The landing page was not captured, so it cannot be checked.
- **Campaign ID vs. subject:** The pixel's campaign ID `20261111_Exclusive_Gifts` differs in wording from the subject "Exclusive beauty you'll have on rotation". This is a naming observation, not a defect.

## 7. Recommendations
1. **Add a fallback for the empty `Hi ,` greeting.** Use a default such as "Hi there," or drop the greeting when the name field is empty (highest priority, FAIL).
2. **Add a multipart text/plain alternative** (FAIL).
3. **Move the `<!--[if mso]>` block out of the `@media` rule** into a standalone conditional `<style>` so the later mobile rules parse.
4. **Make the layout fluid.** Use `max-width:700px; width:100%` instead of `min-width:700px`, and remove `maximum-scale=1` from the viewport meta.
5. **Add `lang="en"` and `role="presentation"`** to layout tables, and set `alt=""` on the tracking pixels.
6. **Fix or remove the JSON-LD stubs** (`discountCode: ""` and the empty `PromotionCard`), and change `no index` to `noindex`.
7. **Capture raw headers.** Re-test from a source that preserves `List-Unsubscribe`, `List-Unsubscribe-Post` and `Authentication-Results` before drawing compliance conclusions.
8. **Re-run the link probe** with a higher cap or include footer links, and record the final redirect destinations and any UTMs.
