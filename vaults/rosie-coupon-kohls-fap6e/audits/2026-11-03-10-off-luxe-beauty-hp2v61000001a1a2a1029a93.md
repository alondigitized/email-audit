## Technical Audit

## 1. Technical Summary
The email has a confirmed empty-name greeting ("Hi ,"), a 0-character plain-text part, and a malformed `<style>` block. Header-based checks (List-Unsubscribe, SPF/DKIM) could not be verified because the relay didn't capture the headers. The QA pass rate was 38%.

## 2. Link & Tracking Issues
- **Link health:** 12 material links were probed and 47 were skipped (footer, utility and social links are deprioritized). The QA data reports no failures among the probed links. The unprobed links are unverified.
- **Tracking pixels:** There are two.
  - `https://mi.sephora.com/p/up/f6716d0a0f52104e/o.gif?mi_u=4970269939971072&mi_ecmp=20261103_Oct_Luxe_MBC_Lite_Dedicated_BI`
  - `https://app.sephora.com/O/AQEAAZcF2g…` (open pixel in the preheader, hidden with `display:none`)
- **Per-recipient ID:** `mi_u=4970269939971072` is a per-recipient identifier in a URL, which is normal for ESPs.
- **Campaign label:** `mi_ecmp` reads `20261103_Oct_…`. The "Oct" label doesn't match a Nov 3 send date. This is a minor naming inconsistency, not a functional fault.
- **UTM parameters:** The truncated HTML doesn't include the CTA hrefs, so I can't assess click-tracking parameters.

## 3. Rendering & Accessibility
- **Alt text:** The QA warning on `o.gif` looks like a false positive. The source has `alt="" aria-hidden="true"`, which is correct for a decorative pixel. The preheader pixel (`app.sephora.com/O/…`) has no `alt`. It is hidden with `display:none`, so the impact is minimal, but adding `alt=""` would be cleaner.
- **Malformed CSS:** The `<style>` block has `<!--[if mso]> img.mso-size {…}<![endif]-->` inside the `@media only screen and (max-width:480px)` block. Conditional comments are not valid there. Browsers will probably treat `<!--[if mso]> img.mso-size` and `<![endif]--> .mobileHeaderTierRouge` as invalid selectors and drop those rules. This would break mobile sizing for `.mobileHeaderTierRouge` (and the intended MSO `img.mso-size` rule). This is inferred from CSS parsing rules, not tested in a client.
- **Fixed width:** The wrapper table has `width:700px; min-width:700px`. The only mobile overrides are the font and image classes in the media query. The layout may force horizontal scrolling on narrow clients that ignore those overrides.
- **Viewport meta:** `maximum-scale=1` disables pinch zoom, which is a WCAG 1.4.4 concern.
- **Robots meta:** `<meta name="robots" content="no index">` is invalid. The valid token is `noindex`.
- **Structured data:** The JSON-LD has `"discountCode": ""` and `@type: "PromotionCard"`, which isn't a schema.org type. Most clients strip `<script>` tags anyway, so this is low severity.
- **Plain-text part:** The text version is 0 chars (QA FAIL). Multipart/alternative has no usable text part, which hurts accessibility and deliverability.

## 4. Personalization & Merge Tokens
- **Empty greeting (FAIL):** The greeting renders as "Hi ," because the first-name slot is empty. The greeting should have a fallback value, or the greeting should be suppressed when the name is missing. I can't see the source of the greeting in the truncated HTML, so this rests on the QA check.
- **Discount code:** `"discountCode": ""` in the JSON-LD is empty, which may be intentional for a no-code promotion.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe and List-Unsubscribe-Post:** Both are reported as not found. The QA note says the AgentMail relay may not capture these headers, so this is unconfirmed. Without RFC 8058 one-click unsubscribe, the email would not meet Gmail and Yahoo bulk-sender requirements.
- **Authentication-Results:** This header wasn't found, so SPF, DKIM and DMARC status is unknown. It is a relay limitation, not a confirmed failure.
- **Footer:** The footer (unsubscribe link and physical address) is outside the truncated source. An unsubscribe link was included in the link probe, but its result isn't itemized.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
No issues can be confirmed. The CTA hrefs are not in the truncated source, and the QA data has no landing-page comparison. The promo is a "10% OFF LUXE BEAUTY" offer with an empty `discountCode`, so landing-page alignment needs a manual check.

## 7. Recommendations
1. **Fix the greeting:** Add a fallback for the empty name slot, or suppress the greeting when the name is missing. This is the only confirmed broken-experience issue.
2. **Add a text part:** Generate a multipart/alternative plain-text version.
3. **Fix the `<style>` block:** Move the MSO conditional out of the `@media` block. This restores the `.mobileHeaderTierRouge` rule and `img.mso-size`.
4. **Allow zoom:** Remove `maximum-scale=1` from the viewport meta.
5. **Add `alt=""`:** Put it on the preheader pixel, and correct the `robots` meta to `noindex`.
6. **Check headers at the source:** Pull the raw message headers to confirm List-Unsubscribe, List-Unsubscribe-Post and SPF/DKIM/DMARC. The relay doesn't expose them.
7. **Probe the skipped links:** Probe the 47 unprobed links, especially the unsubscribe and footer links.
8. **Align the campaign label:** Make the `mi_ecmp` campaign label match the send date.
