# Epic Deals are still going strong 🏋️
**Score:** 5/10 · **Type:** Email audit · **2026-09-23**
## Executive summary

- This is the same "EPIC DEALS" category-blitz layout Kohl's has now run at least four times in the past week (09-20, 09-21 twice, and now 09-23), just with the deal tiles reshuffled — carter's clothing, food storage, kitchen appliances, decor, jewelry, bras, sweaters, bath towels, toys. Nine-plus separate deal tiles stacked vertically means there's no single hero offer to land on; the eye has nowhere to rest before scrolling into a wall of red banners.
- The "Picked with you in mind" personalization block at the bottom is a nice touch in theory, but it's just more product tiles in the same visual language, so it doesn't actually feel personalized. Subject line "still going strong" is honest about the fatigue — it reads like Kohl's own copywriters know this promo has overstayed its welcome.
- Judgement: functional but exhausting. This is the fourth near-identical send in a week and it's starting to actively erode open rates rather than build urgency.

## What's working

- Clear "EPIC DEALS" hero banner with the "Shop Now" CTA visible immediately at the top, no render bugs.
- 3x Kohl's Cash rewards banner is prominent and ties in loyalty benefit visibly.
- Deal tiles are legible with clear percentage-off callouts (50%, 40%, 60%, 30%) and real product photography, no broken images or lorem ipsum.
- Coupon codes and barcodes at the bottom are legible for in-store use.

## What's weak

- This is the fourth "EPIC DEALS" blitz in about a week (09-20, 09-21 x2, now 09-23) with no new creative — pure fatigue risk.
- No single hero product or offer — nine-plus competing deal tiles create decision paralysis instead of a clear primary CTA.
- Subject line "still going strong" telegraphs staleness rather than urgency — it reads as an admission the sale has run too long.
- "Picked with you in mind" section is generic re-merchandising, not real personalization — same visual treatment as everything above it.
- Layout requires heavy scrolling on mobile before any category resolves into an actual product decision.

## Recommendations

- 1. Cut the tile count from nine-plus down to 3-4 and lead with the single best offer (60% off fine/silver jewelry is the strongest %) as the true hero, not buried mid-scroll.
- 2. Retire the "EPIC DEALS" wall format — it's been run four times in a week; rotate in a genuinely different layout (flash countdown, single-category spotlight) to reset fatigue.
- 3. Replace "still going strong" framing with a real deadline callout since Sept. 27 end-date already exists in the fine print — surface it in the subject/hero instead of vague continuity language.
- 4. Make the "Picked with you in mind" section feel distinct (different background/border) so it reads as personalized, not another deal tile row.

- **Subject Alt B:** `Your Epic Deals picks, ending Sept. 27`
- **Preheader Alt A:** `Plus 3x Kohl's Cash through Sept. 21 — shop before deals reset`
- **Preheader Alt B:** `Fine jewelry, kids' clothing, and toys — up to 60% off`

## Technical Audit

1. Technical Summary
The email is a Kohl's promotional send (Coherent Path ESP platform) with heavy tracking instrumentation; automated QA flags gaps in unsubscribe/authentication headers and widespread missing alt text on tracking pixels and product images.

2. Link & Tracking Issues
- Open/click tracking uses multiple redundant pixels/domains: `click.chp.kohls.com` (1x1 open beacon), `mi.kohls.com/p/up/...` (1x1 gif), `click.s.kohls.com/open.aspx` (1x1 open pixel), and `kohls.demdex.net/event` (Adobe Audience Manager). Three separate open-tracking mechanisms firing for a single send is redundant and increases external HTTP calls per open.
- 72 tracking/click-redirect links were skipped by the automated HTTP probe (click.s.kohls.com redirect wrapper) — link destinations are unverified; cannot confirm no dead/broken redirects exist downstream.
- Primary anchor sampled (`click.s.kohls.com/?qs=ABB7InYiOjEsImQiOjUwMDh9...`) uses an opaque encoded payload typical of Coherent Path redirect wrapping — not independently verifiable from HTML alone.

3. Rendering & Accessibility
- 9 images confirmed missing `alt` text per QA output, including the primary content image `57746756_2_2x` (a real product/creative image, not just a tracking pixel) — screen reader users get no fallback text for visible content.
- Tracking pixels (`o.gif`, `event`, `up/...`) also lack `alt`, though these are non-visual and lower priority; the `event` pixel should carry `alt=""` with `role="presentation"`/`aria-hidden="true"` explicitly rather than relying on missing-attribute default (only one pixel, the `open.aspx` beacon, has `aria-hidden="true"` set — inconsistent treatment across pixels).
- Malformed markup: `<img ... aria-hidden="true" /></custom>` — a stray closing `</custom>` tag with no matching opening tag, inside a `<div>`. This is invalid HTML and may cause unpredictable DOM handling in strict-parsing clients.
- `<title></title>` is empty — no fallback subject/title text for clients that render it (e.g., some webmail tabs or accessibility tooling that reads document title).
- MSO/Outlook conditional comments and responsive `@media (max-width:500px)` block are present, indicating standard multi-client scaffolding — no structural issues found there.

4. Personalization & Merge Tokens
- No visible unresolved merge tags (e.g., `{{first_name}}`, `%%FIELD%%`) in the truncated source.
- `mi_cid`, `mi_mid`, `mi_ecmp`, `mi_u`, `mi_kc_redm_end_dte`, `mi_kc_event_pe` query params are populated (some, like `mi_kc_redm_end_dte`, appear empty — e.g. `mi_kc_redm_end_dte=&mi_kc_event_pe`), suggesting an unpopulated personalization/redemption-end-date token feeding the tracking pixel. Low impact since it's a tracking param, not customer-facing content, but worth flagging as an empty merge field.

5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- List-Unsubscribe header not detected — required for one-click unsubscribe support in Gmail/Yahoo bulk sender rules; risks deliverability penalties if truly absent (note QA caveat: may be a relay-capture limitation rather than the sender's actual header).
- List-Unsubscribe-Post (RFC 8058) not detected — same caveat applies.
- No physical mailing address detected in the truncated HTML — CAN-SPAM requires one; not confirmed absent since content is truncated, but flagged by QA as not found in the scanned portion.
- Authentication-Results header not found — SPF/DKIM/DMARC pass/fail status unknown from this scan; cannot confirm authentication posture.
- Recommend re-verifying these four items against raw, untruncated headers/HTML directly from the source MTA rather than the relay-captured copy, since QA explicitly flags relay-capture as a possible cause of the missing headers.

6. Email-to-Site Continuity (UTM params, landing page alignment)
- No standard `utm_source`/`utm_medium`/`utm_campaign` params observed in the sampled link; instead the ESP uses proprietary `mi_ecmp` (e.g., `1022305_2026923`), `mi_cid`, `mi_mid` campaign identifiers and an opaque `qs=` payload on `click.s.kohls.com`. This is consistent with Coherent Path's own attribution scheme rather than GA-style UTMs — not a defect, but means cross-platform (e.g., GA4) attribution depends on server-side redirect mapping, which is unverifiable from this HTML alone (72 links unresolved).
- Cannot assess landing page alignment — all destination URLs are wrapped in click-tracking redirects that were skipped by the probe; no final landing URLs are available for comparison.

7. Recommendations
- Add `alt` text to the `57746756_2_2x` product image at minimum (content-bearing image); set explicit `alt=""` + `aria-hidden="true"` uniformly on all tracking pixels for consistent screen-reader handling.
- Remove the stray `</custom>` tag near the `open.aspx` pixel `<div>`.
- Populate `<title>` with the subject line or brand name.
- Confirm List-Unsubscribe / List-Unsubscribe-Post / Authentication-Results directly from raw SMTP headers at the source (not via relay) to rule out a relay-capture artifact before treating as a real compliance gap.
- Confirm a physical mailing address exists in the (untruncated) footer to satisfy CAN-SPAM.
- Investigate the empty `mi_kc_redm_end_dte` param — likely an unpopulated personalization token in the redemption-tracking pixel.
- Consider consolidating the three separate open-tracking mechanisms if they're serving duplicate purposes, to reduce per-open network overhead.
