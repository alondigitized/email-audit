# ENDS TODAY‼️Up to 50% off select beauty.
**Score:** 9/10 · **Type:** Email audit · **2026-05-26**
## Executive summary

- This is the second Sephora "Stacking Weekend" send on May 26 — the brand already pushed near-identical creative this morning under "LAST CHANCE 🥺 Get up to 50% off select beauty—plus earn 500 bonus points with $75 min. spend." (scored 8/10 in brand history). The dual-incentive hero — 50% off + 500 bonus points — is intact, the visual hierarchy is clean, the SHOP NOW CTA is unambiguous, and Beauty Insider scaffolding is present throughout. Execution is solid.
- The strategy is not. Subscribers who opened this morning's "LAST CHANCE" push are getting the same deal again with a slightly different subject. The "ENDS TODAY‼️" treatment with ALL CAPS and a double-exclamation emoji reads as desperate rather than urgent, and it undersells the points hook that was the sharpest line in the earlier subject. Same-day repeats on the same creative are the fastest way to burn Sephora's hard-won sender reputation.
- The email would perform well as a standalone deadline send. As the second push in eight hours on an already-fatigued Stacking Weekend arc, the incremental lift it drives will be modest against the unsubscribe and spam-flag risk it carries.

## What's working

- **Dual-incentive hero is immediately legible** — 50% off badge and 500-point badge both visible above the fold, no scrolling required.
- **"LAST CHANCE to Save on These Must-Haves" product grid** adds browse depth for subscribers already warming to a purchase.
- **rhode Limited-Edition placement mid-scroll** is smart — high-demand collaboration gives a non-deal reason to keep scrolling.
- **Auto-Replenish 15% offer** is a well-placed LTV play; feels additive, not distracting.
- **Render is clean** — no broken images, no overlapping text, no empty placeholder fields.

## What's weak

- **Same-day fatigue is the headline problem** — "LAST CHANCE" this morning, "ENDS TODAY" this afternoon on the same deal strips the urgency of credibility.
- **Subject drops the bonus points** — the prior send named "500 bonus points with $75 min. spend" explicitly; this subject collapses to just "50% off select beauty," losing the dual-incentive hook that differentiates the offer.
- **"ENDS TODAY‼️" ALL CAPS opener + ‼️** reads as shouting and risks Gmail Promotions tab ranking penalties.
- **No name personalization** — Sephora has "Rosie" in their data (used in May 14 and May 20 triggered sends) but this blast omits it entirely.
- **Email length dilutes urgency** — auto-replenish pitch, color launch, store locator, and Beauty INSIDER editorial all compete with the single-minded "buy before midnight" message.

## Recommendations

- 1. **Suppress for morning openers.** Anyone who opened the "LAST CHANCE" send should not receive this. Retarget only the non-openers with a shorter, tighter version.
- 2. **Put the bonus points back in the subject.** "50% off + 500 points" is the dual hook — never drop one half.
- 3. **Cut to hero + product grid only.** Strip auto-replenish, color launch, and store locator for a final-hour send. One action, one scroll depth.
- 4. **Add the name token.** Sephora has it; use it. "Ends tonight, Rosie" converts materially better than "ENDS TODAY‼️."
- 5. **Swap ‼️ for ⏰ or nothing.** Clock emoji reads as credible urgency; double exclamation reads as spam.
- **Subject Alt A:** `⏰ Ends tonight, Rosie: 50% off + 500 bonus points`
- **Subject Alt B:** `Last hours: Stacking Weekend closes tonight`
- **Preheader Alt A:** `Your 50% off + 500 bonus points disappear at midnight — shop before it's gone.`
- **Preheader Alt B:** `500 points with a $75 spend. 50% off select beauty. Ends tonight.`

### 3. Rendering & Accessibility

**`maximum-scale=1` on viewport meta — confirmed issue**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents user zoom on mobile. Fails WCAG 1.4.4 (Resize Text, Level AA). Should be removed or replaced with `initial-scale=1` only.

**Duplicate `display` declarations on `.show` and `.appear` — minor**
```css
*[class=show], .show { display: block!important; display: table!important; }
*[class=appear], .appear { display: block!important; display: table!important; }
```
The first `display: block` is immediately overridden by `display: table` in the same rule block. Likely intentional for cross-client compatibility, but the `block` declaration is dead weight.

**`<title>` is bare "Sephora"** — acceptable for email, not an issue.
