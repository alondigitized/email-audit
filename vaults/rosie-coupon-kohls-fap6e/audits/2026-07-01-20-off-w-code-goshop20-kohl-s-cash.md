# 20% off w/code GOSHOP20 + Kohl's Cash 🎊
**Score:** 8/10 · **Type:** Email audit · **2026-07-01**
## Executive summary

- This is Kohl's pressing the reset button after a brutal nine-day stretch: twelve Deal Days emails, a clearance pivot on June 29, and back-to-back 40%-off urgency blasts on June 30. Today, July 1, they're relaunching with a fresh discount code (GOSHOP20, 20% off), Kohl's Cash as the loyalty hook, and a 4th of July creative frame that actually earns its place three days before the holiday. The email is clean, competently assembled, and visually coherent — red/white/blue palette carries the patriotic theme without being garish.
- The problem is the discount regression. Yesterday this brand was screaming 40% off TODAY ONLY. Today it's 20% with a code. Any subscriber paying attention will notice the step-down, and the code-based mechanic introduces friction (remember the code, type it at checkout) that the one-click 40%-off stack did not. The buried clearance section — "Up to 70% off" in a high-contrast orange block — is actually the stronger offer, yet it sits below the fold where most mobile readers never reach.
- Verdict: competent creative, correct seasonal timing, but structurally punished by its own cadence history. The discount looks worse because of what just ran, and the best offer is in the wrong place.

## What's working

- **Code specificity in the subject** — GOSHOP20 is explicit, removes ambiguity, and trained deal-hunters will recognize a real code vs. a "click to see discount" tease.
- **4th of July framing lands on schedule** — Arriving July 1 with patriotic product imagery (red/white/blue apparel, americana-adjacent styles) hits the right prep window before the holiday.
- **Kohl's Cash prominently surfaced** — The loyalty reward mechanic appears in both the header and a dedicated mid-email block; this is the brand's strongest retention tool and they're using it correctly.
- **Clean render, no visible bugs** — Layout is intact, images load, no overlapping elements, no broken sections.
- **Clearance block has strong visual contrast** — The orange "CLEARANCE Up to 70% off" band would stop a scroll if subscribers got that far.

## What's weak

- **Discount regression from yesterday is jarring** — Going from "40% off TODAY ONLY" (June 30) to "20% off with a code" (July 1) is a visible value cut that bargain-hunters will clock immediately.
- **Best offer is below the fold** — The clearance 70% off is buried; most mobile readers never reach it, so the headline offer defaults to the weaker 20% code.
- **"Shop Now" CTAs throughout are generic** — Every section uses the same verb-neutral button; nothing pulls a specific category or urgency trigger.
- **Serta mattress insert breaks the seasonal story** — A mattress 20%-off block dropped into a patriotic party-essentials email reads like a revenue insertion, not editorial coherence.
- **No visible deadline on the 20% code** — Without a stated expiry, the urgency floor is zero; nothing compels action today vs. tomorrow.

## Recommendations

- 1. **Flip the offer hierarchy** — Lead the email with "Up to 70% off clearance + 20% off with GOSHOP20" in the hero. Let clearance be the hook and the code be the upgrade path. The 70% is the more compelling number; it should be above the fold.
- 2. **Add a code expiry** — Even "Code valid through July 4" dramatically lifts click urgency without being dishonest. Right now the code floats timelessly, which kills the now-or-never impulse.
- 3. **Make at least one CTA category-specific** — "Shop Women's Red, White & Blue" or "Shop Patriotic Styles" beats "Shop Now" for both CTR and segmentation signal.
- 4. **Cut or relocate the Serta block** — Move mattresses to a standalone email or a footer module; it disrupts the holiday narrative and competes for attention with no seasonal justification.
- 5. **Lean into the cadence reset in preheader** — Use the preview text to signal this is a new campaign, not more Deal Days noise.
- **Subject Alt A:** `4th of July styles + 20% off w/ GOSHOP20 — code expires July 4`
- **Subject Alt B:** `Up to 70% off + extra 20% — stock up before the 4th 🎆`
- **Preheader Alt A:** `Party picks, patriotic styles, and clearance you haven't seen yet.`
- **Preheader Alt B:** `New code, new sale — 70% off clearance starts now. Code: GOSHOP20.`

## Technical Audit — Kohl's "20% off w/code GOSHOP20" (2026-07-01)

### 1. Technical Summary

HTML structure is standard retail ESP output (MSO conditional comments, table-based layout, Google Fonts) with no catastrophic rendering issues. Primary concerns are missing alt text on tracking pixels, unresolved compliance header capture via AgentMail relay, and a malformed custom HTML tag.

---

### 2. Link & Tracking Issues

- **22 tracking/click-redirect URLs skipped** by HTTP probe — all routed through `click.s.kohls.com` and `click.chp.kohls.com`. Destination URLs and response codes unverified.
- **Three distinct pixel vendors** detected in the same send:
  - `click.chp.kohls.com` — CoherentPath behavioral pixel
  - `mi.kohls.com` — Marigold (Campaign Monitor) open/render pixels
  - `kohls.demdex.net` — Adobe Audience Manager DMP pixel
  - This is expected for enterprise ESP stacks but adds ~3 external DNS lookups on open.
- **Malformed closing tag** in open-pixel block: `</custom>` appears as the closing tag for a `<div>` — invalid HTML that will cause a parse error in strict renderers:
  ```html
  <img src="https://click.s.kohls.com/open.aspx?..." width="1" height="1" alt=""></custom>
  ```

---

### 3. Rendering & Accessibility

- **10 images missing `alt` text** (confirmed by QA). Affects:
  - The CoherentPath behavioral pixel (`49687762...`)
  - The Marigold open-tracking GIF (`o.gif`)
  - The Adobe DMP pixel (`event`)
  - Six `mi.kohls.com/p/rp/*.png` render-tracking images
  - Tracking pixels should carry `alt=""` plus `aria-hidden="true"` (pattern used on `o.gif` but not others). Screen readers will announce raw filenames for the unfixed images.
- **`user-scalable=0` in viewport meta** — disables pinch-to-zoom, which is an accessibility violation (WCAG 1.4.4). Modern iOS ignores this but Android WebView respects it.
- **`<title>` element is empty** — minor but causes "Untitled" to appear in some preview panes.
- **Google Fonts loaded three ways** (two `<link>` tags + two `@import` rules for the same families) — redundant requests, no rendering impact but wasteful.
- **MSO conditional VML namespace declared** (`xmlns:v`) but no VML shapes present in the truncated source — likely vestigial boilerplate.

---

### 4. Personalization & Merge Tokens

- No unresolved merge tokens (`{{`, `%%`, `[%`, etc.) visible in the provided HTML — tokens appear to have rendered correctly.
- Marigold pixel URLs carry `mi_u=604230016` (subscriber ID) and `mi_ecmp=1016327_202671` (campaign ID) — both appear populated, not placeholder values.
- `mi_kc_redm_end_dte=` and `mi_kc_event_pen` parameters on one pixel end with empty values — suggests Kohl's Cash redemption date and event pending fields were not populated for this recipient (expected if the subscriber has no active Kohl's Cash balance).

---

### 5. Compliance

- **`List-Unsubscribe` header not captured** (QA WARN) — relay may have stripped it; cannot confirm one-click unsubscribe is functional from header inspection alone. ESP-side verification needed.
- **`List-Unsubscribe-Post` (RFC 8058) not detected** — required for Gmail and Apple Mail auto-unsubscribe UI. If missing at the SMTP layer (not just relay capture), this will suppress the native unsubscribe button in Gmail for high-volume senders.
- **No physical mailing address detected in HTML** — CAN-SPAM §5(a)(5) requires a valid postal address in the body. Not visible in the truncated source; may appear below the fold. Must be verified against full HTML.
- **`Authentication-Results` header absent** — SPF/DKIM/DMARC pass/fail status unknown through AgentMail relay. Sending domain is `s.kohls.com` (subdomain); alignment with `kohls.com` DMARC policy unverified.
- **`<meta name="referrer" content="no-referrer">`** — suppresses HTTP `Referer` header on link clicks, which will cause UTM attribution to drop if any landing pages rely on referrer rather than query params. Intentional but worth noting.

---

### 6. Email-to-Site Continuity

- All destination URLs are wrapped in `click.s.kohls.com` redirects — cannot inspect UTM params on final URLs without resolving the redirect chain (skipped by probe).
- The `mi_ecmp=1016327_202671` parameter in pixel URLs references campaign `1016327` — if click-redirect URLs carry a different campaign ID, attribution will be split across two campaign records in analytics.
- `email_name=260701_DG_Email_Wednesda` (truncated at 25 chars in pixel params) — the campaign name parameter is cut off. If this value is passed through to landing page analytics it will appear as an incomplete identifier in reporting.
