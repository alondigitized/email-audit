# 👕 $6 TEES & $5 TANKS + an extra $10 off orders $75+
**Score:** 7/10 · **Type:** Email audit · **2026-05-16**
## Executive summary

- This is Old Navy's second send on May 16 — the earlier "...are yours for the taking" version of the same $6 tees / $5 tanks deal already went out today and scored a 7. This version adds the $10 off $75+ stacking offer, which is a genuine upgrade in value, but it doesn't solve the underlying problem: subscribers who already saw the first email today are now looking at the same hero, same urgency badge, same products — in what feels like a follow-up blast rather than a distinct campaign. The cadence is the biggest drag on this email's effectiveness.
- Inside the email, the creative is solid Old Navy. The "2 DAYS ONLY" hero is clean, price-forward, and the visual hierarchy works — your eye lands on the deal immediately. The secondary modules (50% Off Deals, accessories, Disney collection carryover) are standard Old Navy stacking and don't hurt the render, but they do dilute focus from the $10 off threshold offer, which is buried in the subject line rather than anchored in its own hero module.
- **Verdict:** A functionally well-executed deal email that's undermined by same-day cadence overlap and an underworked threshold-incentive. The "$10 off $75+" hook deserved its own moment, not a "+an extra" tack-on.

## What's working

- **Hero urgency is immediately legible** — "2 DAYS ONLY" badge with price points reads fast, even on a small mobile screen.
- **Price points are aggressive and visible** — $6 and $5 are specific enough to stop a scroll.
- **Stacking offer is real value** — $10 off $75+ on top of already-low prices is a meaningful basket-building incentive; it's just underplayed.
- **Render is clean** — no broken images, overlapping text, or empty content blocks visible across the full scroll.
- **50% Off Deals module** adds a secondary deal layer that gives non-basics shoppers a reason to stay.

## What's weak

- **Second email same day as the near-identical "...are yours for the taking" send** — subscribers who opened the first one will feel pestered, not motivated.
- **$10 off $75+ is treated as a footnote** — the subject buries it after a "+" and it gets no dedicated visual in the hero; it's the best mechanic in the email and it's invisible.
- **Disney module at the bottom feels recycled** — it launched 3 days ago in its own send (May 13) and its reappearance here as a tail module signals content reuse, not fresh relevance.
- **Multiple competing deal blocks** (hero pricing, 50% Off Deals, clearance) split click intent and make it harder for the subscriber to know what action to take.

## Recommendations

- 1. **Dedicate the $10 off $75+ to its own hero module** — "Stack it: $6 tees + $5 tanks + $10 off when you hit $75" is a clear basket narrative. Right now the threshold incentive is invisible in the body.
- 2. **Kill the same-day resend or make it clearly additive** — if the $10 off is new, lead with that as the reason for a second email, not a rehash of the same price points.
- 3. **Retire the Disney tail module** — it ran its own send three days ago; carrying it forward here reads as list fatigue, not cross-sell strategy.
- 4. **Consolidate the deal modules** — choose one secondary hook (50% Off Deals OR clearance, not both) to reduce decision paralysis.
- **Subject Alt A:** `$6 tees, $5 tanks — plus $10 off when you hit $75`
- **Subject Alt B:** `Stack it: 2 days, $6 tees + $10 off your cart`
- **Preheader Alt A:** `The math is easy: buy a few, save even more.`
- **Preheader Alt B:** `$10 off kicks in at $75 — that's like 12 tanks for free.`

### 2. Link & Tracking Issues

**[FAIL] Broken ConvertPipe redirect**
The QA probe on the ConvertPipe tracking pixel resolved to a relative URL rather than an absolute destination:
```
Probed:   https://cp.oldnavy.com/o/91049900-241e-4740-9012-5fec7a6bb6ac?mi_mid=...
Resolved: /g/91049900-241e-4740-9012-5fec7a6bb6ac?txn=39569980-517b-11f1-88f4-4e61e507eb6e
Error:    unknown url type
```
The `/o/` → `/g/` path rewrite is producing a relative URL, which means the redirect chain is broken. This pixel sits in a `display:none` preheader div, so it is invisible to recipients but the failed request will register as an error in ConvertPipe logs and silently drop engagement attribution for any client that follows the redirect.

**[WARN] 23 click links not probed**
All outbound CTAs route through `click.email.oldnavy.com`. These were skipped by the HTTP probe. UTM integrity and destination validity cannot be confirmed without a manual spot-check of at least the primary hero CTA.

### 3. Rendering & Accessibility

**[WARN] Missing alt text on tracking pixel**
The ConvertPipe pixel image has no `alt` attribute:
```
src: https://cp.oldnavy.com/o/91049900-241e-4740-9012-5fec7a6bb6ac?mi_mid=...
```
While invisible by design, screen readers will announce this as an unlabeled image. Add `alt=""` explicitly (not missing the attribute — an empty string signals decorative intent to assistive tech).

**[WARN] Duplicate responsive utility class definitions**
In the `@media (max-width: 639px)` block, `.MspaceTop` and `.MspaceBot` are each defined twice with conflicting values:
```css
.space-top5, .MspaceTop {padding-top: 5px;}   /* line ~70 */
.space-top10, .MspaceTop {padding-top: 10px;}  /* line ~76 — overwrites above */
.space-bot5,  .MspaceBot {padding-bottom: 5px;}
.space-bot10, .MspaceBot {padding-bottom: 10px;} /* overwrites above */
```
Any element using `.MspaceTop` alone will always get 10px, never 5px. Elements intended to have 5px spacing will silently render at 10px on mobile.

**[WARN] Outlook global `line-height:0px` override**
Inside the `[if gte mso 9]` conditional:
```css
td { line-height:0px; mso-line-height-rule:exactly }
```
This is a global reset applied to every `td` in Outlook 2013+. Any `td` that relies on inherited or default line-height for text readability (rather than an explicit inline style) will collapse line height to zero. This is a known pattern but must be compensated with explicit `line-height` on every text-bearing `td`.

### 5. Compliance

**[FAIL-RISK] Physical mailing address unconfirmed**
CAN-SPAM §5(a)(5) requires a valid physical postal address. The QA checker found none in the captured content. The full HTML is truncated and the address typically appears in the footer — this must be verified against the full source. If omitted, it is a CAN-SPAM violation.

**[WARN] List-Unsubscribe header absent from relay capture**
The `List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) headers were not found. These may be present in the original SMTP envelope but were not forwarded by the AgentMail relay. Gmail and Apple Mail use `List-Unsubscribe` to surface native unsubscribe UI — absence increases user-reported spam rates. Confirm these headers exist on the sending MTA; if not, add them.

**[WARN] One-click unsubscribe (RFC 8058) not confirmed**
Without `List-Unsubscribe-Post: List-Unsubscribe=One-Click`, Gmail's bulk sender requirements (enforced since Feb 2024 for >5k/day senders) are not met. Old Navy volume virtually guarantees they exceed this threshold.

**[WARN] Authentication-Results header missing**
SPF and DKIM status are unknown from the relay-captured version. Cannot confirm DMARC alignment. This should be verified via the original message headers.
