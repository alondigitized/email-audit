# $5 TANKS INSIDE + an extra 20% off everything*
**Score:** 6/10 · **Type:** Email audit · **2026-07-14**
## Executive summary

- This is Old Navy's second swing at the same $5 tanks / extra 20% off campaign — yesterday's July 13 send told the same story and scored 5/10 here. The material difference today is the "2 DAYS ONLY!" urgency block in the hero, which is a legitimate reason to resend a promotional campaign (deadline push), but the subject line buries that urgency entirely. A subscriber who already deleted yesterday's email will feel déjà vu, not FOMO.
- The email itself is reasonably well-executed for a multi-offer promotional blast. The hero lands the price point immediately, clearance from $3.99 adds a value anchor, and the "Short Story" shorts module extends the hot-weather narrative. But the content is dense enough that the editorial thread (summer simplicity) gets lost between the stacked modules.
- The cadence problem is real but defensible here — brands routinely resend with a deadline nudge. What's not defensible is a subject line that doesn't mention the deadline. That's the single biggest miss.

## What's working

- **"2 DAYS ONLY!" hero urgency** is bold, high-contrast, and visible immediately on load — this is the email's best asset.
- **$5 TANKS** price point is rendered in large type; eye goes straight there.
- **Clearance from $3.99** provides a secondary hook for deal-seekers; the red/orange module creates enough visual contrast to stand out.
- **"Short Story" shorts section** anchors a seasonal narrative and adds category depth beyond the lead offer.
- **No visible render bugs** — layout is clean across the full scroll.

## What's weak

- **Subject line hides the deadline** — "2 DAYS ONLY!" is the entire justification for resending today; it's nowhere in the subject or (likely) preheader.
- **"TANKS" all-caps in subject** brushes against spam-signal territory; borderline on aggressive subject formatting.
- **Repeat campaign fatigue** — this is functionally the same email a subscriber already received yesterday; without a clear deadline signal from the inbox view, many will skip.
- **No social proof or reviews anywhere visible** — for a value-priced category like tanks, a quick "4.6★ from 12K reviews" badge does real work.
- **Asterisk-heavy "everything\*"** — experienced Old Navy subscribers know this means clearance included only sometimes; trust is slightly undermined.

## Recommendations

- 1. **Lead the subject with the deadline** — "2 DAYS ONLY!" is doing nothing if it never reaches the inbox view. This is the single change that lifts open rate on a repeat send.
- 2. **Drop the asterisk or own the exclusion** — either "extra 20% off everything" (if true) or "extra 20% off, Clearance included" (if that's the hook). The asterisk creates micro-friction.
- 3. **Add a review badge to the $5 tanks hero** — one line, "Over 50K sold — grab yours before Sunday" earns the click.
- 4. **Consolidate the "Discover More" bottom module** — it diffuses click energy; if the goal is tanks + shorts, don't scatter to six other categories below the fold.
- **Subject Alt A:** `2 DAYS ONLY: $5 tanks + extra 20% off everything`
- **Subject Alt B:** `Offer ends Sunday — $5 tanks + 20% off sitewide`
- **Preheader Alt A:** `Clearance from $3.99 too — this weekend only.`
- **Preheader Alt B:** `$5 tanks, $4 deals, and clearance from $3.99. Ends Sunday.`

### 1. Technical Summary

The email passes basic rendering requirements but has one broken link that will cause a dead-end click, and several compliance gaps (unsubscribe headers, physical address, SPF/DKIM visibility) that create CAN-SPAM and deliverability exposure.

---

### 2. Link & Tracking Issues

**[FAIL] Broken tracking pixel URL — `/g/` redirect returns unknown URL type**

The Content Passport pixel in the preheader div resolves to a `/g/` redirect that the checker cannot follow:

```
https://cp.oldnavy.com/o/9e64fab6-e70f-4427-96d8-865e90dd8a9f
  ?mi_mid=019f5fda-c280-7000-b1a9-4149ef58af61
  &cp_tp=v3.eJyFks...
  → Error: unknown url type: '/g/9e64fab6-...'
```

This is likely a Movable Ink / Content Passport pixel with a malformed or expired redirect chain. While it won't break visible links, it means impression/open data from this pixel may be silently dropped.

**[INFO] 23 click-redirect links skipped** — all routed through `click.email.oldnavy.com`. No direct destination errors detected, but final-destination validation was not performed.

---

### 3. Rendering & Accessibility

**[WARN] Missing `alt` text on tracking pixel**

```html
<img src="https://cp.oldnavy.com/o/9e64fab6-..." width="1" height="1" alt="">
```

Empty `alt=""` is present, which is acceptable for decorative/tracking pixels per WCAG. However, the open-tracking pixel also has `alt=""`:

```html
<img src="https://click.email.oldnavy.com/open.aspx?..." width="1" height="1" alt="">
```

Both are technically compliant but noted for completeness.

**CSS duplicate selectors** — `.MspaceTop` and `.MspaceBot` are each defined twice in the responsive block (conflicting `padding-top: 5px` and `padding-top: 10px` for `.MspaceTop`). Last-rule wins in CSS, so mobile spacing will apply the 10px value regardless of intent for the 5px variant.

**MSO Outlook line-height conflict** — The Outlook conditional sets `td { line-height: 0px; }` globally, then tries to restore with `mso-line-height-rule: exactly` per-element. This is a known pattern but aggressive; any `td` without an explicit line-height override will collapse to 0px in Outlook 2013+.

---

### 4. Personalization & Merge Tokens

No unresolved merge tokens (e.g., `{{first_name}}`, `[FNAME]`) visible in the truncated source. Personalization appears to be handled via the Content Passport payload (`cp_tp=v3.eJy...` base64 blob) and `mi_mid` / `mi_cid` audience IDs — consistent with a Movable Ink deployment. No issues found.

---

### 5. Compliance

**[WARN] `List-Unsubscribe` header not detected**

The QA relay did not capture a `List-Unsubscribe` header. Gmail and Apple Mail use this to surface one-click unsubscribe UI. Its absence (or relay-layer stripping) degrades inbox placement and risks the email being flagged under Gmail's bulk sender policies (required for senders >5k/day since Feb 2024).

**[WARN] `List-Unsubscribe-Post` (RFC 8058) not detected**

Required for Gmail's native one-click unsubscribe button. Without it, users must click through to a landing page — Google treats this as non-compliant for high-volume senders.

**[WARN] No physical mailing address detected in truncated source**

CAN-SPAM §5(a)(5) mandates a valid physical postal address. The source is truncated so this may appear in the footer — but the QA check flagged it as absent. Needs manual footer verification.

**[WARN] SPF/DKIM/DMARC authentication status unknown**

`Authentication-Results` header was not captured by the AgentMail relay. Cannot confirm SPF pass for `email.oldnavy.com` or DKIM signature validity. This is likely a relay capture issue, not an actual auth failure, but should be verified via a direct header inspection.

---

### 6. Email-to-Site Continuity

**UTM parameter coverage** — All 23 click links route through `click.email.oldnavy.com` before redirecting to oldnavy.com destinations. UTM injection at the click-redirect layer is standard for Gap Inc. ESP setups and is consistent with this pattern. Cannot confirm UTM values without following the redirect chain, but no raw `oldnavy.com` links without click-wrapping are visible.

**Tracking pixel domain mismatch** — The open pixel uses `click.email.oldnavy.com` while the Content Passport pixel uses `cp.oldnavy.com`. Both are expected for this stack (Salesforce Marketing Cloud + Movable Ink), but the `/g/` redirect error on the `cp.oldnavy.com` pixel (see §2) means that open event may not be attributed correctly if Movable Ink is the source-of-truth for impression data.
