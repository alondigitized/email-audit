- **Subject Alt B:** `Your workout wardrobe: half off this weekend only`

### 3. Rendering & Accessibility

**[WARN] Tracking pixel missing `alt` attribute**

```html
<img src="https://cp.oldnavy.com/o/b5c3e8e3-..." width="1" height="1">
```

The pixel has no `alt=""`. While invisible by design, screen readers may announce the src URL. Add `alt=""` (empty string) to suppress it explicitly.

**CSS class duplication — low risk, note for maintainability**

`.MspaceTop` and `.MspaceBot` are each defined twice in the responsive block with different property values (5px and 10px respectively). The second declaration wins, silently overriding the first. This is a CSS authoring bug; any template component relying on the 5px variant will silently render at 10px on mobile.

**Outlook line-height override is aggressive**

The MSO conditional sets `td { line-height: 0px; mso-line-height-rule: exactly }` globally, then relies on per-component overrides to restore correct spacing. This is a known pattern but increases fragility — any new content block added without an explicit `line-height` will collapse in Outlook 2013+.

**XHTML 1.0 Transitional doctype**

The document declares `XHTML 1.0 Transitional`, which is the correct historical choice for broad email client compatibility and not an issue per se — but `<meta>` elements inside `<div>` (the Schema.org block) are invalid in this doctype and may be dropped by strict parsers.

### 5. Compliance

**[WARN] `List-Unsubscribe` header absent**

The QA relay did not capture a `List-Unsubscribe` header. Gmail and Yahoo Mail (since February 2024 bulk sender requirements) require this header for senders at volume. Its absence — even if present on the originating MTA but stripped by the AgentMail relay — means the one-click unsubscribe button in Gmail will not render, increasing spam complaint rate.

**[WARN] `List-Unsubscribe-Post` header absent (RFC 8058)**

Required for Gmail's native one-click unsubscribe UI. Without it, Gmail degrades to a redirect-based flow, which has significantly lower completion rates and does not satisfy the 2024 bulk sender mandate for >5k/day senders.

**[WARN] No physical mailing address detected**

CAN-SPAM §5(a)(5) requires a valid physical postal address in every commercial email. The truncated source does not show a footer address block. If absent from the full HTML, this is a CAN-SPAM violation. If present but not captured in the truncated source, flag as unverified.

**Note on header absence:** All three compliance warnings may be artifacts of the AgentMail relay stripping headers before QA inspection rather than the originating send lacking them. Verify against raw SMTP headers from the MTA, not the relay-processed copy.
