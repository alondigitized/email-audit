# SANTOS BRAVOS goes live at 12pm PST
**Score:** 4/10 · **Type:** Email audit · **2026-08-18**
## Executive summary

- This is H&M turning a livestream promo into the entire email — "LIVE FROM LOS ANGELES" and a boy-band group shot for an "exclusive acoustic performance by SANTOS BRAVOS" streaming at 12pm PST. It's the second Santos Bravos tie-in this stretch after the 8/14 back-to-school send bolted a livestream plug onto the bottom; here it's promoted to the full hero, which at least commits to the bit instead of feeling tacked-on. But there's zero shopping motivation — no discount, no product, no urgency beyond a time stamp, just "MORE INFO" and a category grid.
- For a subscriber who came for clothes, this reads as a content/entertainment push wearing a retail newsletter's clothes. It's well-executed within its own narrow goal (drive stream attendance) but does nothing for basket size, and unlike the 8/15–8/16 "15% or 20% off" sends this offers no reason to buy anything today.

## What's working

- Clean, uncluttered layout — single hero image, one clear headline, no competing sections above the fold.
- Copy is specific about time and mechanism ("acoustic performance," "12pm PST," "streaming live from Los Angeles") rather than vague hype.
- "MORE INFO" CTA button is visible and unambiguous for what it wants you to do.
- No render bugs — image, type, and button all display cleanly.
- "SHOP BY" category grid gives a fallback path to browse even though the hero isn't selling anything.

## What's weak

- No offer of any kind — no %/$ off, no free shipping, nothing transactional; pure content marketing.
- Primary CTA ("MORE INFO") is vague — doesn't say what happens (watch stream? RSVP? buy merch?).
- Demographic mismatch — five young men in a moody studio shot skews toward a niche fandom audience, not a general H&M shopper.
- Time-sensitive send with no countdown/urgency treatment — "12pm PST" is just stated, not visually emphasized, so a later-opening subscriber has already missed it.
- No product tie-in at all — if Santos Bravos has a capsule collection or merch, it's not shown; the email doesn't monetize the tie-in.

## Recommendations

- 1. Tie the stream to an actual purchase path — link a Santos Bravos capsule or the outfits shown, or at minimum add "Shop the look" under the hero. Content-only sends have no revenue mechanism.
- 2. Replace "MORE INFO" with an action-specific CTA like "WATCH LIVE" or "SET A REMINDER" so the click intent is unambiguous.
- 3. Add urgency treatment (countdown, "starts in X hours") since this is a live, time-boxed event — right now it reads as static as any other send.
- 4. Segment this send to fans/subscribers who've engaged with music content before; general shoppers will bounce off it.
- **Subject Alt A:** `Santos Bravos live acoustic set — 12pm PST today`
- **Subject Alt B:** `Watch Santos Bravos perform live from LA at noon`
- **Preheader Alt A:** `An exclusive acoustic session, streaming for a limited time.`
- **Preheader Alt B:** `Tune in before the set goes offline.`

## Technical Audit

## 1. Technical Summary
This H&M campaign email fails to render or function correctly: all 12 probed material links return HTTP 403, and the ESP relay is missing required unsubscribe/authentication headers.

## 2. Link & Tracking Issues
- **12/12 probed links return 403 Forbidden**, including all CTAs ("Shop now" ×2), the logo link, both hero images, both "MORE INFO" links, "Women", "Men", both "Find store" links, and the **Unsubscribe link itself**. All routes through the `t19.email.hm.com/r/?id=...` redirector (Salesforce Marketing Cloud tracking domain) — the redirector is rejecting requests, not the destination pages.
- Link text on the two "Shop now" CTAs contains stray zero-width/BOM characters (`‌  ﻿Shop now`), suggesting a templating/encoding artifact in the source HTML that could affect screen-reader pronunciation and any text-based link auditing.
- Tracking parameters (`did`, `rid`, `erid`, `p1`–`p5`) are present and consistently formatted across links, so the tracking schema itself looks intact — the issue is redirector availability, not parameter structure.

## 3. Rendering & Accessibility
- 4 `<img>` elements are missing `alt` text, including both hero/product images (`cq5dam.web.1400.1400.jpeg`, `cq5dam.web.750.750.jpeg`) and 2 tracking pixel images served from `t19.email.hm.com/r/`.
- Extensive mobile-responsive CSS (`.is-hidden-mobile`, `.image-mobile`, `@media (max-width:699px)`) is present and structured normally — no issues found in the responsive rules themselves.
- Client-specific hacks present and correctly scoped (`#MessageViewBody` for Outlook.com, `@media screen yahoo` for Yahoo Mail) — no issues found.

## 4. Personalization & Merge Tokens
- The `application/ld+json` schema.org block has multiple **empty merge fields**: `"subjectLine":""`, `"discountCode":""`, `"availabilityEnds":""`, `"image":""`, `"url":""` under the `PromotionCard`/`DiscountOffer` types. These are unpopulated at send time — likely broken Gmail Promotions markup (annotations won't render if required fields are blank).
- `"availabilityStarts":"2018-12-31T18:59:59-05:00"` is a stale/leftover date (2018) inconsistent with the 2026 send — indicates this JSON-LD block is a stale reused template fragment, not dynamically populated for this campaign.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Unsubscribe link returns 403** (same redirector failure as all other links) — functionally, this is a broken unsubscribe mechanism at time of audit.
- `List-Unsubscribe` header not detected — QA flags this may be an artifact of the AgentMail relay not capturing/forwarding the header rather than the sender omitting it; cannot confirm sender-side compliance from this data alone.
- `List-Unsubscribe-Post` (RFC 8058 one-click unsubscribe) not detected — same caveat re: relay capture.
- `Authentication-Results` header (SPF/DKIM/DMARC) not detected — same caveat; SPF/DKIM pass/fail status is unknown from available data, not confirmed failing.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- Cannot assess destination-page/UTM alignment — every material link 403s at the redirector layer before reaching any landing page, so no destination URLs or UTM parameters are observable in this dataset.
- Plain-text alternative is 87% URL content by character count (522/600 chars), i.e. minimal readable copy — spam-filter risk factor and poor fallback experience for plain-text clients.

## 7. Recommendations
1. **Priority 1:** Investigate the `t19.email.hm.com` redirector — a 403 on 100% of probed links (including Unsubscribe) indicates a systemic ESP/tracking-domain issue (auth token expiry, bot-protection false-positive, or misconfigured campaign ID) rather than isolated bad links. This blocks compliance (unsubscribe) and all click-through, so treat as send-blocking.
2. Add `alt` text to the 2 hero/product images and audit the JSON-LD template for the 2 tracking-pixel images.
3. Strip stray zero-width/BOM characters from the "Shop now" anchor text.
4. Populate or remove the empty JSON-LD `PromotionCard`/`DiscountOffer` fields (`subjectLine`, `discountCode`, `availabilityEnds`, `image`, `url`) and correct the stale 2018 `availabilityStarts` date.
5. Reduce plain-text URL density; add descriptive copy so the plain-text version isn't dominated by raw links.
6. Re-verify `List-Unsubscribe`/`List-Unsubscribe-Post`/`Authentication-Results` directly against raw SMTP headers outside the AgentMail relay, since this data can't confirm whether they're actually absent or just not captured.
