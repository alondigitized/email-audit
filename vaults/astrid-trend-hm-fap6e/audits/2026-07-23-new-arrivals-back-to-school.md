# New arrivals: Back to school
**Score:** 6/10 · **Type:** Email audit · **2026-07-23**
## Executive summary

- H&M pivots hard from five consecutive sitewide-sale blasts to a full-price new-arrivals editorial — no discount, no urgency, just product. The back-to-school timing is actually right (late July is exactly when the consideration window opens), and the varsity-jacket-plus-basketball hero reads the season immediately. But H&M has spent the past week training subscribers to expect 50% off, and this email offers nothing to bridge that conditioning. Walking from "last day: 50% off sitewide" directly into "here are new things at full price" is a harder ask than the creative acknowledges.
- The second problem is message discipline: midway through the email, a completely unrelated "Golden Summer" editorial appears — warm tones, totally different aesthetic, a second "SHOP NOW" CTA. It's not a complementary section; it's a separate campaign bolted on. The email ends up saying two things to no one in particular.
- The execution is clean — no sale-banner clutter, products are legible, layout holds — but clean without an offer reads as "nothing for me" to deal-trained eyes. This needed either a promotional hook or ruthless focus. It has neither.

- "Golden Summer" section below the fold is a completely different campaign; dual message dilutes the seasonal focus and wastes scroll depth
- Both CTAs read "SHOP NOW" — generic, non-directional, same copy on two competing sections

## Technical Audit — H&M "Back to School" Email

### 1. Technical Summary

The email uses a standard table-based layout with Gmail Promotions tab JSON-LD annotations and responsive CSS. Several JSON-LD fields contain stale or empty values, and two `@import` calls for external fonts will silently fail in the majority of email clients.

### 3. Rendering & Accessibility

**`@import` for external fonts will be blocked**
```html
<style>
  @import url(https://fabric.hmgroup.com/fabric-fonts/0/northstar/css/fonts.css);
  @import url(https://s1-cdn.hm.com/global/hm-fonts/4.0.1/oces.css);
</style>
```
`@import` inside `<style>` is stripped or ignored by Outlook (all versions), Yahoo Mail, and several mobile clients. If the CSS cascade doesn't fall back to a declared `font-family` stack, text will render in the client's default serif/sans. Confirm that inline `font-family` fallbacks exist on all text elements.

**Missing `lang` attribute on `<html>`**
```html
<html style="border:0;margin:0;outline:0;padding:0">
```
No `lang="en"` (or locale-appropriate value). Screen readers cannot infer the content language; WCAG 2.1 SC 3.1.1 failure.

**`display:inline` on `.is-hidden-desktop` at mobile breakpoint**
```css
.is-hidden-desktop { display: inline !important; ... }
```
Using `display:inline` to un-hide block-level elements (tables, `<td>`) produces unpredictable layout in email clients. The pattern should use `display:block` or `display:table` depending on the element type.

**Positive findings:**
- `<meta name="x-apple-disable-message-reformatting"/>` present — correct
- `<meta content="telephone=no" name="format-detection"/>` present — correct
- `<meta name="viewport" content="width=device-width"/>` present — correct
- `charset=UTF-8` declared — correct

---

### 4. Personalization & Merge Tokens

**Stale hardcoded date in JSON-LD**
```json
"availabilityStarts": "2018-12-31T18:59:59-05:00"
```
This date is ~7.5 years in the past. It appears to be a leftover default from template creation. Gmail uses this field to render Promotions tab deal cards; an expired `availabilityStarts` with no `availabilityEnds` may suppress the annotation or display incorrect deal timing.

**Multiple empty JSON-LD fields that should be populated or omitted**
```json
{ "@type": "EmailMessage", "subjectLine": "" }
{ "@type": "DiscountOffer", "discountCode": "", "availabilityEnds": "", "description": "" }
{ "@type": "PromotionCard", "image": "", "url": "" }
```
- `subjectLine` should match the actual subject (`"New arrivals: Back to school"`) or be omitted.
- `PromotionCard.url` and `PromotionCard.image` are empty strings — Gmail will ignore or reject the annotation. If this email is not intended to carry a deal card, the `DiscountOffer` and `PromotionCard` blocks should be removed entirely rather than left as empty shells.
- Empty `discountCode` and `description` on `DiscountOffer` will prevent Gmail from rendering a deal badge.
