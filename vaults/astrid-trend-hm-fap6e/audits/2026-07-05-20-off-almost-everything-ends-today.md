#  20% off almost everything ends today
**Score:** 10/10 · **Type:** Email audit · **2026-07-05**
## Executive summary

- H&M closes its July 4th run with its most mechanically clean execution of the week: "LAST DAY" followed immediately by "20% OFF SITEWIDE," a blue-print summer dress hero, then the 70% sale red band as a secondary pull. The hierarchy is textbook — urgency text, hero, category nav, secondary offer, infrastructure. No creative risks, none needed. On "last day" you need clarity, not hooks, and the email delivers.
- The fatal miss is the preheader. Instead of pushing urgency into the inbox preview slot, H&M burns that real estate on member recruitment copy ("BECOME A MEMBER, GET 10% OFF YOUR FIRST PURCHASE + VIP PERKS!") aimed at people who are already subscribers. For a send where "ends today" is the entire proposition, that's a squandered injection.
- Context matters here: yesterday's send (July 4, "The main event: 20% off 'til tomorrow") already fired the "main event" gun. This is the follow-through — and it lands well mechanically, but as a fifth email in five days on an identical offer, it is reaching a fatigued list. The email works; the cadence is doing damage.

## What's working

- "LAST DAY" + "20% OFF SITEWIDE" above the fold with zero scanning required — the hierarchy is the offer.
- Clean two-layer value stack: member 20% off leads, 70% sale closes — gives fence-sitters two reasons to click.
- The hero caption ("The holiday may be over, but the glow-up isn't. Keep the energy going with peak summer picks.") pivots cleanly off July 4th into evergreen summer without belaboring the holiday.
- Render is completely clean — images load, no broken elements, text sits correctly throughout.
- "LAST DAY" framing sharpens urgency without resorting to exclamation stacking or spam triggers.

## What's weak

- Preheader is the member recruitment banner — "BECOME A MEMBER, GET 10% OFF YOUR FIRST PURCHASE + VIP PERKS!" — which undercuts the "ends today" urgency signal entirely at the inbox level.
- Subject says "almost everything," body says "SITEWIDE" — a small but real contradiction that erodes trust; the dense fine print at the bottom is where the actual exclusions live.
- Both primary CTAs read "SHOP NOW" — generic for a last-chance send; no category pull, no product hook, no specificity that moves a waverer.
- No individual product hero: same sitewide framing as the prior four sends, so there's nothing new to click toward even if you're already familiar with the offer.
- The member recruitment banner at the top of a "last day" email is an odd priority inversion — existing members (the intended audience for the 20% off) don't need acquisition copy.

## Recommendations

- 1. **Rewrite the preheader to reinforce the deadline.** This is the single highest-leverage change. Swap the member acquisition copy for urgency: "Your 20% closes at midnight — here's what to grab before it's gone." That's what a subscriber sees next to "ends today" in the inbox.
- 2. **Sharpen the CTAs.** Replace "SHOP NOW" with "CLAIM 20% OFF" or "SHOP BEFORE IT'S GONE" — verb plus specific payoff, not generic browse framing.
- 3. **Align "almost everything" vs. "SITEWIDE."** Pick one and use it consistently. "Almost everything" is more honest; carry it into the hero headline and drop the fine-print whiplash.
- 4. **Introduce one product hero.** "The dress everyone grabbed this week — now 20% off today only" gives a concrete action to fence-sitters who've already ignored four prior sends.
- 5. **Suppress or relocate the member recruitment banner** for the existing subscriber segment — move it to the footer or hide it for confirmed members so prime inbox preview real estate goes to urgency.
- **Subject Alt A:** `Last call: 20% off closes at midnight`
- **Subject Alt B:** `Today only — your 20% off almost everything`
- **Preheader Alt A:** `The summer picks worth grabbing before the discount disappears tonight`
- **Preheader Alt B:** `20% off every member pick — ends today, not tomorrow`

## Technical Audit — H&M "20% off almost everything ends today"

### 1. Technical Summary

Standard ESP-delivered HTML email with table-based layout and responsive CSS. The most significant technical issue is a partially-rendered JSON-LD schema block containing stale hardcoded dates and multiple empty merge fields that were never populated.

---

### 2. Link & Tracking Issues

HTML source is truncated before link `href` values are visible, so UTM coverage cannot be fully confirmed. One structural issue is observable:

- **JSON-LD `PromotionCard.url` is an empty string** (`"url":""`) — if Google uses this for promotional tab rendering, the card will have no destination.

Cannot audit individual link UTM parameters or click-tracking wrapper domains from the provided truncation. Full source required.

---

### 3. Rendering & Accessibility

**`@import` CSS stripped by Gmail:**
```css
@import url(https://fabric.hmgroup.com/fabric-fonts/0/northstar/css/fonts.css);
@import url(https://s1-cdn.hm.com/global/hm-fonts/4.0.1/oces.css);
```
Gmail (web and Android) strips `@import` rules entirely. Both font imports will silently fail, falling back to system fonts for all Gmail recipients. This is a known ESP limitation and standard fallback behavior, but worth confirming fallback stack is acceptable.

**`img.image + div { display: none !important; }`**
This rule hides any `<div>` immediately following an `.image` element. If any image has an adjacent accessibility or alt-text fallback `<div>`, it will be suppressed in all clients.

**Non-standard media query:**
```css
@media screen yahoo { .show-webkit-table { display: none; } }
```
`screen yahoo` is not a valid CSS media query. No client will evaluate it. If this was intended to target the Yahoo Mail rendering engine, it has no effect.

**Missing `lang` attribute:** The `<html>` tag has no `lang="en"` (or any language). Screen readers default to the OS language, which can misread content for international subscribers.

---

### 4. Personalization & Merge Tokens

The JSON-LD `DiscountOffer` block contains unfilled template fields sent in production:

```json
{
  "@type": "DiscountOffer",
  "discountCode": "",
  "description": "",
  "availabilityStarts": "2018-12-31T18:59:59-05:00",
  "availabilityEnds": ""
}
```

- **`discountCode` and `description` are empty strings** — these appear to be merge tokens that were not resolved before send.
- **`availabilityEnds` is empty** — required field for offer validity signaling.
- **`availabilityStarts` is hardcoded to `2018-12-31T18:59:59-05:00`** — this is 7+ years stale, indicating the schema template has never been updated. Google's Gmail Promotions tab uses this data; a 2018 start date may cause the offer to render as expired or be deprioritized.

Similarly in `EmailMessage`:
```json
{"@type":"EmailMessage","subjectLine":"","@context":"http://schema.org/"}
```
`subjectLine` is an empty string rather than the actual subject line, which should be `" 20% off almost everything ends today"`.
