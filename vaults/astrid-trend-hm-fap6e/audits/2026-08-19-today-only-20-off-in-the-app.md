# Today only: 20% off in the app
**Score:** 5/10 · **Type:** Email audit · **2026-08-19**
## Executive summary

- This is H&M running a legit sitewide-style discount — "TODAY ONLY, 20% OFF YOUR APP ORDER" — but burying the actual purchase behind an app-download wall. There's no discount code, no shop-now button tied to the offer, just two "DOWNLOAD IOS / DOWNLOAD ANDROID" buttons stacked under a moody model shot. Compare to 8/15's "15% OR 20% OFF ALL WEEKEND," which had the same size type but led straight into shoppable categories — this send asks for an app install before it asks for a purchase, which is a much bigger ask for a "today only" urgency play.
- The creative itself is clean — bold black sans-serif headline, single striking hero image, on-brand — but the whole email is structured as an app-acquisition funnel wearing a discount headline. Anyone who doesn't already have the app can't act on this offer from the email at all; they have to download, register, hunt for a code inside the app, then buy, all within one day. That's friction stacked on top of friction, and it directly contradicts the "today only" urgency.
- Net: strong subject, weak execution. The email will get opened on urgency + specificity, but the click-to-purchase path is broken for a huge share of recipients (anyone without the app already installed).

## What's working

- Clear, bold hero copy — "TODAY ONLY / 20% OFF YOUR APP ORDER" reads instantly, no scrolling needed on mobile.
- Single hero image with a real, in-category model shot (casual loungewear, matches general apparel persona) — no lorem-ipsum or broken renders.
- Fine print is unusually complete and specific — dated expiry (08/19/2026), exclusions, no vague "some restrictions apply."
- "THE H&M APP" section explains concrete value (Member Hub, Scan & Find, Visual Search) rather than a generic app plug.

## What's weak

- No visible discount code or in-line CTA that maps to the 20% offer itself — the only actionable buttons are app downloads, not "Shop Now."
- Primary path to redeem requires downloading an app, logging in, and finding a code — far too many steps for a same-day deadline.
- "SHOP NOW" and "SALE" exist only as tiny top-nav text links, not a prominent hero button — visual hierarchy sends the eye to the model image, not to any actionable next step.
- Offer excludes a long list of categories (MOVE, furniture, guest designer collabs, etc.) buried in fine print — reduces how honest the "20% off" headline feels once you read past the hero.

## Recommendations

- 1. Add a hero CTA button ("Get My Code" or "Redeem in App") directly under the headline — right now the only buttons are generic app-store downloads, disconnected from the offer.
- 2. For recipients who already have the app, deep-link the CTA straight into the app with the code pre-applied instead of making them hunt for it after opening.
- 3. Move the exclusions summary ("not valid on MOVE, furniture, collabs") up near the hero in one short line — it currently only shows up in dense fine print at the bottom, which reads as bait-and-switch once you compare headline to restrictions.
- 4. Shorten the redemption chain: if this is genuinely "today only," a one-tap mobile-web checkout with the code auto-applied would convert far better than a full app-download detour.
- **Subject Alt A:** `Today only: your 20% code is in the app`
- **Subject Alt B:** `20% off, but only until midnight`
- **Preheader Alt A:** `Open the app now — your code expires tonight`
- **Preheader Alt B:** `Exclusions apply. Redeem before 11:59pm.`

## Technical Audit

# Technical Email Audit — H&M "Today only: 20% off in the app"

**1. Technical Summary**
The email uses Adobe Campaign/H&M's t19.email.hm.com tracking redirector for all links; automated QA shows the redirector returning HTTP 403 on all 4 probed material links, including the unsubscribe link, and standard compliance/authentication headers are absent from the capture.

**2. Link & Tracking Issues**
- 4/4 probed links return **403 Forbidden** at the tracking redirector `https://t19.email.hm.com/r/?id=h114b7518-...`, affecting both CTAs ("Shop now" x2), "Scan & Find", and the Unsubscribe link. A 403 at this domain suggests either bot/UA blocking on the redirect service or an expired/invalid `id`/`rid` token set — this should be verified against a real client fetch before concluding it's broken for end users, since 403s on click-tracking redirectors are sometimes anti-bot false positives rather than true link failures.
- Link text for both "Shop now" CTAs contains embedded zero-width/invisible characters (`‌  ﻿Shop now` — ZWNJ/BOM-like characters), which is a common list-hygiene/engagement-tracking pattern but can interfere with screen readers and text-based link parsing.
- Only 12 of 69 total links were probed (57 skipped per QA scope), so link coverage is partial — footer/social links are unverified.

**3. Rendering & Accessibility**
- 4 images missing `alt` text, including two product images (`1347095005_202604_LB_0126.jpg` at 1400px and 750px variants) and two tracking-pixel/redirector images. Missing alt text on product imagery degrades screen-reader experience and breaks graceful degradation when images are blocked.
- Extensive Outlook/mso and mobile-media-query CSS present (`.is-hidden-mobile`, `.is-hidden-desktop`, mso-hide rules) indicating standard multi-client responsive handling — no issues found in the visible markup for this pattern.
- `application/ld+json` schema block has several empty required-looking fields (`"subjectLine":""`, `"discountCode":""`, `"image":""`, `"url":""`, `"availabilityEnds":""`), which will cause the structured data (Gmail annotations / promo card) to fail validation or simply not render the promo card.

**4. Personalization & Merge Tokens**
No unresolved merge tokens (e.g. `{{first_name}}`, `%%FIELD%%`) found in the truncated source. No issues found.

**5. Compliance (CAN-SPAM, unsubscribe, authentication headers)**
- Unsubscribe link is present in-body but **returns 403** per QA — a functionally broken unsubscribe mechanism is a CAN-SPAM concern if confirmed against real delivery (not just the automated probe).
- `List-Unsubscribe` header not found — QA notes this may be a capture limitation of the AgentMail relay rather than confirmation of absence; **cannot confirm** true header state from this data.
- `List-Unsubscribe-Post` (RFC 8058 one-click unsubscribe) not found — same caveat as above.
- `Authentication-Results` header (SPF/DKIM/DMARC) not found — same relay-capture caveat; authentication status is **unknown**, not confirmed failing.

**6. Email-to-Site Continuity (UTM params, landing page alignment)**
- Links use H&M's proprietary redirector params (`did`, `rid`, `erid`, `p1`–`p5`) rather than standard `utm_*` parameters — this is expected for Adobe Campaign-style tracking and not itself an issue, but means standard UTM-based attribution tooling won't parse these directly.
- Cannot verify final landing page alignment (product/category page vs. app deep link) since all redirects 403 before reaching a destination.

**7. Recommendations**
1. Re-verify the 4 broken-link findings with a manual/real-browser fetch (with a standard browser UA) to rule out bot-detection false positives at `t19.email.hm.com` before treating this as a true production outage.
2. If the unsubscribe link 403 is confirmed real, treat as high-priority — broken unsubscribe is a compliance risk.
3. Add `alt` text to the two product images and the two tracking pixel `<img>` tags.
4. Populate the empty `ld+json` fields (`subjectLine`, `discountCode`, `image`, `url`, `availabilityEnds`) or remove the schema block if not in use — currently non-functional.
5. Confirm `List-Unsubscribe`/`List-Unsubscribe-Post`/`Authentication-Results` header presence via raw header capture (e.g., direct MTA/API log) rather than relying on the AgentMail relay, since this QA pass could not confirm true absence.
