But there's no discount, no urgency, and no anchor price that makes "new in" feel like a reason to act now rather than later (or never). - **Zero urgency or offer** — "New in" is the only hook; there's no discount, deadline, or limited-quantity signal anywhere.
- **Category mismatch for the existing subscriber base** — H&M's email cadence has been 100% apparel and activewear for weeks; a tableware drop with no contextual bridge ("did you know H&M sells this?") feels like a wrong number.

- **No social proof, no editorial voice** — "Return to city life with a collection inspired by the timeless cafés and bakeries of France" is the only copy; it's thin and gives no reason this collection is special right now.

### 3. Rendering & Accessibility

**`@import` for web fonts is unsupported in most major email clients:**

```css
@import url(https://fabric.hmgroup.com/fabric-fonts/0/northstar/css/fonts.css);
@import url(https://s1-cdn.hm.com/global/hm-fonts/4.0.1/oces.css);
```

Gmail (all clients), Outlook desktop, and Samsung Mail all strip `<style>` tags or ignore `@import` inside them. Recipients on those clients will silently fall back to system fonts. This is industry-standard behavior — the email will render but branded typography will be absent for a significant share of recipients.

**Client-targeting selectors present and correct:**
- `#MessageViewBody` (Outlook Web App) — valid
- `@media screen yahoo` — valid Yahoo Mail hack
- `x-apple-disable-message-reformatting` meta tag — present

**Alt text:** Cannot verify from truncated source. Images are expected given the product-grid CSS classes (`.price-module-image-product-info`, `.stand-alone-product-grid-info`). All product images must carry descriptive `alt` attributes for accessibility and for clients with images disabled by default.

### 4. Personalization & Merge Tokens

No recipient-level merge tokens are visible in the rendered portion (no `{{first_name}}`, `*|FNAME|*`, or equivalent). This is consistent with a broadcast promotional email.

**JSON-LD merge fields are unfilled or incorrect:**

```json
{"@type":"EmailMessage","subjectLine":"","@context":"http://schema.org/"}
```

`subjectLine` is an empty string. It should match the actual subject: `"New in: Parisian-style tableware"`. Gmail uses this field for inbox annotations.

All three fields are empty strings. If no discount applies, the entire `DiscountOffer` object should be removed rather than sent as empty — empty structured data can trigger schema validation warnings and wastes annotation eligibility.
