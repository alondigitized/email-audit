# Up to 50% off sitewide ends tonight
**Score:** 7/10 · **Type:** Email audit · **2026-07-19**
## Executive summary

- This is H&M's second "last day" email on July 19 alone — the earlier send this morning ran the identical "Up to 50% off almost everything" offer with a "Last day" subject, and this one follows with "ends tonight." The creative is clean and competent: bold "LAST DAY / UP TO 50% OFF / ALMOST EVERYTHING" headline, a strong female model in transitional denim, and a tidy category-button grid. Nothing is broken. Nothing is inspired.
- The fundamental problem isn't execution — it's the story. H&M has now sent a sitewide 50%-off email every single day for at least a week, with two on July 19 alone. The urgency has been so thoroughly debased that "ends tonight" reads as noise. No subscriber who has watched this run believes the sale actually ends tonight.
- The email would work adequately as a one-off. As the seventh iteration in an unbroken chain, it's contributing to list fatigue faster than it's moving product.

## What's working

- **"LAST DAY" badge + deadline copy in the headline** — the visual hierarchy is tight; the eye goes banner → badge → percentage → model → category buttons in one clean sweep.
- **Free-shipping member benefit prominently top-billed** — the preheader banner surfaces a concrete perk that complements the discount without repeating it.
- **Model and creative match the offer** — transitional denim styling fits the "almost everything" breadth without feeling scattershot.
- **Subject line length** — 35 characters, well under the mobile cutoff, reads fast and clean.
- **No render bugs** — five category buttons, five "shop by" thumbnails, social row, app download block — all render correctly.

## What's weak

- **No single primary CTA button** — five equal-weight category buttons (WOMEN / MEN / BABY / KIDS / HOME) diffuse intent; a first-time opener has no clear next step beyond "pick one."
- **"Ends tonight" has zero credibility at this point** — this is the second "last day" message today and the sixth-plus sitewide sale email this week; the deadline is functionally decorative.
- **Body copy is generic** — "Bring your A-game to every look with modern transitional basics and feel-good prices" says nothing specific about the sale depth, a hero product, or a category anchor.
- **No product specificity** — unlike July 16's shorts-from-$12.49 send (which scored well partly because of the price anchor), this email gives no concrete example product or starting price beyond the headline percentage.
- **Fine print visible at the bottom** — the legal block is legible enough to undercut the "up to" framing, which invites skepticism about how many items actually hit 50%.

## Recommendations

- 1. **Kill the second send today** — two "last day" emails in one day is the single highest-impact change. It trains the list to ignore urgency signals permanently.
- 2. **Add a concrete price anchor in the hero** — "Jeans from $14.99" or "Tops from $7.99" next to the percentage turns "up to 50% off" from a ceiling claim into a tangible deal.
- 3. **Consolidate to one hero CTA** — "Shop Women's Sale" as a full-width button above the fold; move the other categories below. Every extra button costs click-through.
- 4. **Earn the deadline** — if this is genuinely the last day, show it: a countdown timer or "sale ends at midnight" copy. If it isn't, don't send the email at all.
- 5. **Category-specific subject for the second send** — if a second send was unavoidable, differentiate it: "Your last chance on these jeans" lands differently than a sitewide repeat.
- **Subject Alt A:** `Ends tonight: up to 50% off (for real this time)`
- **Subject Alt B:** `These jeans are $14.99 — but only until midnight`
- **Preheader Alt A:** `Free shipping for members + up to 50% off. Tonight only.`
- **Preheader Alt B:** `Stock is moving fast — grab your size before midnight.`

### 3. Rendering & Accessibility

**`@import` font loading will fail in most clients:**
```html
<style>
  @import url(https://fabric.hmgroup.com/fabric-fonts/0/northstar/css/fonts.css);
  @import url(https://s1-cdn.hm.com/global/hm-fonts/4.0.1/oces.css);
</style>
```
`@import` inside `<style>` blocks is stripped by Gmail (web), Outlook (all versions), and Yahoo Mail. These clients will fall back to system fonts. If the design depends on brand typography, fonts must be embedded via `@font-face` declarations directly in the `<style>` block, with system-font stacks as fallbacks.

**Viewport meta missing `initial-scale`:**
```html
<meta name="viewport" content="width=device-width"/>
```
Should be `content="width=device-width, initial-scale=1"`. Some Android WebView-based clients zoom out without `initial-scale=1`.

**Mobile breakpoint hardcoded to iPhone-specific width:**
```css
.footer-table{width:375px!important}
.header-menu-container{width:375px!important}
```
375px is the iPhone SE/8/X logical width. Samsung Galaxy S-series and most Android flagships are 360–412px. Elements will either overflow or show unexpected whitespace on non-Apple devices.

**Redundant/conflicting CSS declarations in media query:**
- `.department-title` declared twice with different `font-size`/`line-height` values (24px/30px first, then 16px/20px).
- `.set_font_heading_xlarge` declared three times in the same `@media (max-width:699px)` block with identical values — dead weight that increases parse time.
- `.cta-link-mobile-border-ns` and `.cta-link-mobile` each declared twice.

**Potential hidden-content accessibility issue:**
```css
img.image + div { display: none !important; }
```
This hides any `<div>` immediately following an `img.image` element. If that div contains alt-text fallback content or accessible descriptions, screen readers will skip it. Verify the hidden siblings are purely decorative.

**JSON-LD structured data has a 2018 hardcoded date — a confirmed bug:**
```json
{
  "@type": "DiscountOffer",
  "availabilityStarts": "2018-12-31T18:59:59-05:00",
  "availabilityEnds": "",
  ...
}
```
- `availabilityStarts` is `2018-12-31` — a template placeholder that was never updated. Gmail's Promotions tab uses this to display deal timing; a 2018 date will either suppress the annotation or display incorrect information.
- `availabilityEnds` is **empty string** — for an email whose subject line is "ends tonight," this field must contain tonight's UTC cutoff timestamp. Gmail cannot surface the deal card without it.
- `"subjectLine": ""` in the `EmailMessage` schema is also empty, preventing Gmail from matching it to the actual subject for annotation display.
- `"url": ""` in `PromotionCard` is empty — no destination URL for the Gmail Promotions card.
