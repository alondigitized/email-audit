# Enter if you dare, Leo
**Score:** 7/10 · **Type:** Email audit · **2026-08-07**
## Executive summary

- This is LEGO's Halloween teaser, and it opens well — purple hero, spooky-diamond haunted-house pattern, "Get into the spirit this Halloween" — but it never delivers on its own promise. The hero copy calls out "the haunted house, the scary skull, or the enchanting pumpkin," then the "Built to thrill" grid directly below shows Boba Fett, the Gustav Klimt art set, a Hanging Golden Pothos plant kit, and the Hubble Space Telescope. Not one Halloween set appears anywhere in the email. That's the email's whole problem in one screenshot.
- Compare this to the run of sends in the brand history: 8/2's Klimt "The Kiss" launch scored 8.00, and here's that same set recycled into a generic recommendation slot four days later — a rerun, not a follow-up. Subject line ("Enter if you dare, Leo") is a solid Halloween hook on its own, but it's cashing a check the body doesn't pay.
- Judgment: the top-of-funnel creative (hero banner) is genuinely good — best Halloween treatment I've seen from this brand — but the product grid is a copy-paste of a generic "trending" module that undercuts it. This reads like two teams' work stitched together without a final consistency pass.

## What's working

- Hero banner has real seasonal craft: purple palette, diamond haunted-house silhouette pattern, and a Halloween headline that's on-brand and legible at a glance.
- "Shop now" CTA button is high-contrast (orange on purple) and impossible to miss.
- Loyalty card at the footer (Insiders points, barcode, "Leo") reinforces membership status in a way that feels tactile, like an actual membership card.
- Piece counts and Insiders-points-earned are shown on every product tile, which is the detail a LEGO buyer actually wants before clicking.
- App download CTA (App Store / Google Play) is a clean secondary ask that doesn't compete with the primary Shop Now buttons.

## What's weak

- The product grid ("Built to thrill") shows zero Halloween sets despite the hero copy explicitly naming a haunted house, a skull set, and a pumpkin set — a direct promise/delivery mismatch that undermines trust in the email's premise.
- The Gustav Klimt "The Kiss" set is recycled from the 8/2 dedicated launch send into this generic grid slot — feels like filler, not a fresh recommendation.
- No actual offer or discount anywhere — this is pure browse-and-earn-points, which is a weaker pull than a %/$ promo.
- Halloween marketing landing in early August (today is 8/7, Halloween is 10/31) is nearly three months early and reads as premature/off-season for most subscribers.
- Category icon row (Star Wars, Ideas, LEGO Icons, LEGO City) adds navigation clutter right before the membership-app block, diluting focus rather than reinforcing it.

## Recommendations

- 1. **Fix the hero/grid mismatch first** — either swap in the actual Halloween haunted house / skull / pumpkin sets under "Built to thrill," or rewrite the hero copy to match what's really being merchandised. This is the single highest-impact fix; right now the email breaks its own promise before the first scroll ends.
- 2. Drop or replace the Klimt tile — it was the hero of a dedicated send five days ago; repeating it here reads as inventory padding rather than a curated pick.
- 3. Add a concrete incentive (e.g., "double Insiders points this weekend" or a bundle deal) — points-only framing is the weakest lever in the email; every other August LEGO send has had a stronger hook (early access, launch, event).
- 4. Hold Halloween creative until September — sending it in early August, three months out, costs it urgency and freshness.
- 5. Trim the category icon row — it's redundant with the main nav and just adds scroll before the app-download block.

- **Subject Alt B:** `Haunted house, skull, or pumpkin, Leo?`
- **Preheader Alt A:** `Three new Halloween builds, plus double points this weekend`
- **Preheader Alt B:** `Get spooky before the shelves do — new for October`

## Technical Audit

## Technical Audit: LEGO "Enter if you dare, Leo" (Halloween Reveal)

**1. Technical Summary**
Built on Salesforce Marketing Cloud (image.e.crm.lego.com, cl.s50.exct.net) using an MJML-derived responsive template; automated QA shows a 38% pass rate driven primarily by missing image alt text and unconfirmed authentication/unsubscribe headers (likely relay artifacts, not necessarily template defects).

**2. Link & Tracking Issues**
- 55 tracking/click-redirect links were skipped by the HTTP prober (expected behavior for SFMC-wrapped links, not a defect in itself — but means link destinations are unverified in this audit).
- One image loads over plain HTTP: `http://cl.s50.exct.net/LiveContent.aspx?qs=ABB7InYiOjEsImQiOjQ5NjF9...` ("Insider Barcode", appears twice). Non-HTTPS resources are commonly blocked or flagged by mail clients (Gmail/Outlook enforce HTTPS image proxying) and represent mixed-content risk in an otherwise HTTPS template.

**3. Rendering & Accessibility**
- 15+ `<img>` elements missing `alt` text, including both hero banners (`01_Halloween-Reveal-20260809-Hero-Banner-Standard_GIF.gif`, occurs twice), all four product shots (`75455`, `31221`, `11512`, `11382` set images), decorative/spacer assets (`GreyBrick.png`, `Footer-Products_GenericPoints_Colour.png`, each repeated ~5x), and footer nav art (`Footer_TopSeparator_Desktop_Member-Non-Member_Dark.png`, `Footer_Mobile_LegoInsidersLogo.png`). Screen-reader users and images-off clients get no fallback text on any of these.
- Head includes standard defensive markup for cross-client rendering: `x-apple-disable-message-reformatting`, MSO conditional comments, `color-scheme`/`supported-color-schemes` for dark mode, and mobile breakpoints at 599px — no issues found here.
- External `@import` and `<link>` webfont calls to fonts.googleapis.com (Noto Sans / Noto Sans Display) will silently fail in most email clients (Outlook desktop, many mobile clients strip remote `@import`/webfonts); the `body` font-family fallback stack (`LEGO Typewell, 'Noto Sans', Cera Pro, Arial, sans-serif`) mitigates this, so not flagged as a defect, but the two duplicate/near-duplicate `<link>` font requests (one for weight 700 only, one for 400;700) are redundant.

**4. Personalization & Merge Tokens**
- Subject line contains a resolved personalization token (`Leo`) with no visible fallback artifact (e.g., no literal `%%FirstName%%` or `{{first_name}}` leaking into the rendered subject) — token appears to have resolved correctly.
- The HTML body was truncated in this review, so merge-token resolution within the body/preheader could not be verified. Recommend re-running QA against the full DOM to confirm no unresolved AMPscript/token placeholders exist further down the template.

**5. Compliance (CAN-SPAM, unsubscribe, authentication headers)**
- `List-Unsubscribe` header not found — either genuinely absent or stripped by the AgentMail relay; cannot confirm which from this data.
- `List-Unsubscribe-Post` (RFC 8058, one-click unsubscribe) not found — same caveat.
- No physical mailing address detected in the captured content — CAN-SPAM requires this; note the footer was likely cut off by truncation, so this may be a detection gap rather than a true omission.
- `Authentication-Results` header not found, so SPF/DKIM/DMARC pass/fail status is unknown from this data — cannot confirm authentication posture.
- All four findings share the same root uncertainty: the AgentMail relay may not be surfacing/preserving original headers. Recommend verifying against raw source at the receiving MTA (not post-relay) before treating these as sender-side defects.

**6. Email-to-Site Continuity (UTM params, landing page alignment)**
- Truncated HTML source did not expose CTA `href` values, so UTM parameter presence/consistency could not be verified in this pass.
- Product image assets reference `www.lego.com/cdn/cs/set/assets/...` (production CDN) alongside `image.e.crm.lego.com` (ESP asset host) — both are legitimate first-party LEGO domains, no cross-domain leakage observed in what was visible.
- Recommend re-auditing with full (untruncated) HTML to confirm click-through URLs carry UTM/tracking params consistent with the landing pages (e.g., set PDPs for 75455/31221/11512/11382).

**7. Recommendations**
1. Add descriptive `alt` text to all product and hero images (or explicit `alt=""` for confirmed decorative assets like `GreyBrick.png`) to fix the 15+ accessibility warnings.
2. Replace the HTTP `LiveContent.aspx` barcode image reference with HTTPS to eliminate mixed-content/blocking risk.
3. Verify `List-Unsubscribe` / `List-Unsubscribe-Post` and `Authentication-Results` presence by checking raw headers at the receiving MTA rather than post-relay, since AgentMail may be the point of loss rather than the sender.
4. Confirm a physical mailing address is present in the (untruncated) footer to close out CAN-SPAM verification.
5. Re-run link/UTM continuity checks against the full HTML source, since 55 tracking links and all CTA `href`s were outside the truncated capture.
6. Consider consolidating the two near-duplicate Google Fonts `<link>` requests into one.
