# Extra 25% off🎉 Score select clearance deals NOW
**Score:** 7/10 · **Type:** Email audit · **2026-06-04**
## Executive summary

- This is at minimum the sixth execution of the "Extra 25% off select clearance" creative since May 30 — the June 3 "Best DEALS of the week" send (9/10) was DICK'S chance to pivot away from this exhausted playbook, and they did, briefly. Now they're right back with the same hero, same offer, same DSG activewear and golf modules. The cadence has crossed from aggressive into subscriber-hostile: six near-identical sends in five days from the Clearance sub-brand alone.
- Within the email itself, the execution is competent. The red hero banner lands the 25%-off message instantly, the multi-category layout gives shoppers entry points (shoes, tanks, golf), and the ScoreCard rewards module near the bottom adds a loyalty hook. But "competent" is doing a lot of work here when the brand already sent two clearance emails on June 3, including one that scored 9/10 by swapping in fresh creative. Returning to the exact same format the next morning signals the send calendar is on autopilot.
- The single biggest problem isn't the design — it's the lie of urgency. "NOW" in the subject means nothing when this same deal has been "NOW" for five straight days.

## What's working

- **Hero does its job immediately.** The red banner + "EXTRA 25% OFF" in oversized white type is visible before anything else; the offer is decoded in under a second.
- **Multi-category structure gives multiple entry points.** Shoes, DSG tanks/shorts, golf, Father's Day, and the summer gear grid mean there's at least one hook for most active shoppers.
- **Father's Day peg is timely.** The June 22 callout is the one seasonal anchor that actually adds new information not present in the prior five sends.
- **ScoreCard loyalty module present.** Earning 2X rewards on qualifying purchases gives a reason to buy via DICK'S rather than a competitor with a similar discount.

## What's weak

- **"NOW" urgency is burned.** Six days of the same offer destroys credibility — there is no urgency left in this word.
- **No single hero product.** The layout scatters attention across four or five separate deal zones; nothing is merchandised as the lead item worth clicking for.
- **"Select clearance" qualifier is doing heavy lifting with no help.** No visible category count, no "ends Sunday," no minimum threshold — the restriction feels fine-printy without a payoff.
- **The $28,200 savings callout (or similar large number visible mid-email) is unexplained.** Whether it's a cumulative savings claim or a product-level figure, it reads as noise without context.
- **Zero personalization.** Name, category, past purchase — nothing. On the sixth send of the same offer, even a light segmentation signal ("your last purchase was in Running") would have justified another touch.

## Recommendations

- 1. **Hard-stop the creative.** This subject line and hero have been sent six times. Retire it today; the June 3 "Best Deals" format already proved a content-led pivot lifts scores.
- 2. **Pick one hero product and lead with it.** A single hero SKU (e.g., a specific Nike or Under Armour shoe at 25%+ off) with real before/after pricing drives click conviction far better than a categorical claim.
- 3. **Add a credible deadline.** "Ends Sunday at midnight" or "while supplies last on these 200 styles" converts "NOW" from noise to action.
- 4. **Segment by purchase history.** Clearance emails sent to running buyers should lead with running clearance, not a DSG tank grid.
- **Subject Alt A:** `Extra 25% off ends Sunday — grab it before it's gone`
- **Subject Alt B:** `Your clearance picks: shoes, tanks & more — 25% extra off`
- **Preheader Alt A:** `Prices already slashed, now take another 25% at checkout — ends 11:59 PM Sunday.`
- **Preheader Alt B:** `Over 200 styles already marked down. Here's the extra 25% to close the deal.`

## Technical Audit — DICK'S Sporting Goods Clearance Email

---

### 1. Technical Summary

The email is built on Epsilon/Harmony ESP infrastructure with standard MSO conditional comments and responsive mobile overrides. Four confirmed code-level defects exist: invalid JSON-LD syntax, stale/empty structured data fields, a malformed MSO CSS rule, and a suspected `_dev`-path image asset in production.

---

### 2. Link & Tracking Issues

**Epsilon tracking redirects — correct pattern, no broken links visible**
All CTA links route through `https://app.dickssportinggoods.com/T/v610000019e92304217adf710f4bbe5be68/…` and the open-pixel through `/O/…`. This is expected Epsilon Harmony behavior. No naked/untracked links are visible in the truncated source.

**Suspected dev-tier image CDN in production**
The logo `src` resolves to:
```
https://dsg.images.harmony.epsilon.com/_phoenix/_dev/AEM/img/headers/brand-logo--dk…
```
The `/_dev/` path segment suggests the asset is being served from a development or staging origin. If this path 404s in production the logo renders broken. Confirm the live CDN path should be `/_prod/` or equivalent.

---

### 3. Rendering & Accessibility

**Malformed CSS in MSO conditional block**
```css
div {background-color:inherit; font-size:0; line-height:100%; margin:0; padding:0;"}
```
There is a stray `"` immediately before the closing `}`. This makes the rule invalid CSS inside the `<!--[if (gte mso 9)|(IE)]>` block. Outlook's parser may discard the entire `div` rule or corrupt subsequent rules, causing `div` elements to render with inherited browser defaults in Outlook 2016+.

**Duplicate `font-family` declaration**
```css
body{font-family:Archivo,Arial,sans-serif;font-family:Archivo,Arial,sans-serif!important}
```
The first declaration is overridden immediately by the `!important` version. Not a rendering defect, but dead CSS.

**Tracking pixel missing explicit dimensions**
```html
<img src='https://app.dickssportinggoods.com/O/…' style="display:none; max-height:0px; …"/>
```
`width` and `height` HTML attributes are absent. While `display:none` suppresses rendering in most clients, some older clients (Lotus Notes, certain Android native clients) ignore `display:none` and will attempt to size the element — missing explicit `width="1" height="1"` can cause a 1px gap. Low severity but worth standardizing.

**`<link rel="icon">` in `<head>`**
```html
<link rel="icon" type="image/x-icon" href="https://www.dickssportinggoods.com/…/favicon.ico"/>
```
Ignored by all major email clients. No rendering defect, but adds unnecessary request surface and markup noise.

---

### 4. Personalization & Merge Tokens

**Invalid JSON in `application/ld+json` block — JavaScript-style comments**
```js
{ // GIF & WEBP images are not supported…
  "@type": "PromotionCard",
  // DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!
  "image": ""
}
```
`//` comments are **not valid JSON** (RFC 8259). Gmail's structured data parser will reject or silently discard the entire `<script type="application/ld+json">` block when comments are present, meaning the PromotionCard and DiscountOffer Gmail inbox annotations will not render. Remove all comment lines before send.

**Stale hardcoded `availabilityStarts`**
```json
"availabilityStarts": "2020-03-06T06:00:00-04:00"
```
This date is from 2020. It appears to be a template default that was never updated. Gmail's structured data validator may surface this as an anomaly.

**Unfilled merge tokens — empty required fields**
```json
"description": "",
"discountCode": "",
"availabilityEnds": "",
"image": ""
```
Four fields in the JSON-LD structured data block are empty strings. These appear to be template placeholders that were not resolved before send. `discountCode` and `image` are the most consequential for Gmail inbox card rendering.
