# 📢 Up to 50% off this week's DEALS is yours!
**Score:** 7/10 · **Type:** Email audit · **2026-05-14**
## Executive summary

- This is a classic "weekly deals dump" from DICK'S Sporting Goods — a high-volume, broad-reach send designed to expose as many SKU categories as possible in one scroll. The hero is clean and punchy: bold "50% OFF" in yellow against a dark athletic backdrop with an unambiguous green "SHOP DEALS" button. That's the strongest part of this email. Everything after the fold is where it loses coherence — fan gear, men's shoes, tennis rackets, TaylorMade golf, outerwear, New Balance footwear, and a ScoreCard rewards multiplier all compete for attention in a tall, grid-heavy layout.
- The send feels seasonally current ("This Week's Deals" framing) and carries loyalty perks for ScoreCard members, which is a genuine differentiator for DSG. But the breadth of categories makes this feel like a circular rather than a campaign — it's speaking to everyone, which means it's speaking precisely to no one.
- Net judgement: functional but forgettable. The open is earned by brand recognition and a clear discount headline. The click is harder to earn because nothing after the hero is urgent or specific enough to compel action from a particular buyer type.

## What's working

- **Hero is immediately legible** — "50% OFF" in large yellow type on dark green reads at a glance, even at thumbnail size.
- **ScoreCard loyalty section is visible** — rewards multiplier (3X) and earn/redeem copy gives members an extra reason to act.
- **Green CTA button on hero has strong contrast** — "SHOP DEALS" is clearly clickable and above the fold.
- **Category breadth covers multiple buyer intents** — fan gear, shoes, tennis, golf, outerwear all in one send means something will land for someone.
- **No visible render bugs** — layout is clean, images load, no overlapping text or broken placeholders visible.

## What's weak

- **Subject line feels bloated and passive** — "is yours!" adds filler that dilutes the discount signal and the emoji-plus-ALL-CAPS "DEALS" combo flirts with spam aesthetics.
- **No single hero product or category anchors the email** — every section competes equally; there's no editorial spine pulling you toward one purchase decision.
- **CTA copy is generic throughout** — "Shop Now," "Shop Deals" appear repeatedly without category specificity ("Shop Men's Shoes," "Shop Tennis Gear" would do more work).
- **No personalization visible** — no name, no category preference signal, no "because you bought X" hook; the email reads as a mass blast.
- **Time pressure is vague** — "This Week's" implies a deadline but no specific date or countdown is shown, which softens urgency.

## Recommendations

- 1. **Anchor the email to one lead category** — pick the strongest deal (e.g., the 60% off men's shoes) and make it the hero; subordinate everything else. One sharp hook beats five broad ones.
- 2. **Rewrite the subject line** — remove the filler phrase "is yours!" and be specific about the lead category deal. The emoji can stay if it's the only formatting signal, not paired with ALL-CAPS.
- **Subject Alt A:** `Up to 60% off shoes + 3X rewards this week`
- **Subject Alt B:** `This week: 50% off fan gear, shoes, golf & more`
- 3. **Add a hard deadline** — "Deals end Sunday" or a visible date makes "This Week's" feel real and actionable.
- 4. **Make category CTAs specific** — swap "Shop Now" for "Shop Men's Shoes," "Shop Tennis," etc. so the click intent is clear.
- 5. **Surface the ScoreCard multiplier higher** — 3X rewards is a strong member hook; it's buried below multiple deal blocks where most recipients won't reach it.
- **Preheader Alt A:** `3X ScoreCard points + up to 60% off shoes this week only`
- **Preheader Alt B:** `Fan gear, golf, tennis, shoes — this week's best deals inside`

## Technical Audit — DICK'S Sporting Goods Promotional Email

### 1. Technical Summary

The email is built on Salesforce Marketing Cloud (SFMC) and follows standard MSO/responsive table architecture. Two blocking issues require immediate attention: invalid JSON in the structured-data block and a stale 2020 placeholder date embedded in Gmail schema markup.

---

### 2. Link & Tracking Issues

**Open tracking pixel** — `https://app.dickssportinggoods.com/O/v610000019e260ee002bb24cf6e96c660f0/...` uses the SFMC `/O/` endpoint. Functioning as expected.

**Click-redirect links** — All hrefs route through the SFMC `/T/` redirect endpoint (e.g., `https://app.dickssportinggoods.com/T/v610000019e260ee002bb24cf6e96c660f0/...`). Functioning as expected.

**No issues found** beyond the continuity note in section 6.

---

### 3. Rendering & Accessibility

**Preheader text exposed as bare text node** — The preheader string `+ Don't miss up to 50% off select Fan Shop gear***` sits as an unwrapped text node inside `<td id="ssl">`, mixed with the tracking pixel:

```html
<td id="ssl" ...>
  <img src="..." style="display:none; ..."/>
  <!--Replace/Paste SSL Here-->
  + Don't miss up to 50% off select Fan Shop gear***
</td>
```

It carries no `display:none` or font-size:0 wrapper of its own. Some rendering environments (plain-text fallback, certain accessibility tools) may surface this as visible body content. Best practice is to wrap it in a `<span style="display:none;max-height:0;overflow:hidden;">`.

**Duplicate `font-family` declaration in `<style>`:**

```css
body { font-family: Archivo, Arial, sans-serif; font-family: Archivo, Arial, sans-serif !important }
```

Redundant but harmless — no functional impact.

**Google Fonts hardcoded at `/v7/` path** — `fonts.gstatic.com/s/archivo/v7/...` pins to Archivo v7 WOFF2 files. If Google removes or redirects that version path, the custom font silently falls back to Arial. Low urgency, but worth updating to the current URL or a self-hosted copy.

**HTML is truncated** — Logo `<img id="logo">` alt attribute and full footer could not be verified. These should be confirmed in a full-source review.

### 4. Personalization & Merge Tokens

No SFMC `%%merge_tags%%` or AMPscript visible in the supplied HTML fragment — the content appears entirely static / non-personalized at this tier of the email. This is consistent with a broad promotional send, not a trigger or lifecycle email.

### 5. Compliance

**JSON-LD block contains JavaScript-style comments — invalid JSON** (blocking for Gmail Annotations):

```json
{ // GIF & WEBP images are not supported and will be filtered out.
  // Sample image is 538x138, 3.9 aspect ratio
  "@context": "http://schema.org/",
  "@type": "PromotionCard",
  // DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!
  "image": ""
}
```

`//` comments are illegal in JSON. Any JSON parser (including Gmail's schema processor) will reject the entire `<script type="application/ld+json">` block. The `PromotionCard` annotation will never display in Gmail.

**`DiscountOffer` schema contains a stale 2020 placeholder date:**

```json
"availabilityStarts": "2020-03-06T06:00:00-04:00",
"availabilityEnds": ""
```

`availabilityStarts` is over 6 years in the past — a template default that was never populated. `availabilityEnds` is an empty string. Both fields must be set dynamically per send or removed.

**`DiscountOffer` required fields are empty:**

```json
"description": "",
"discountCode": ""
```

Empty strings for required fields will cause the Gmail Annotation to be silently dropped even if the JSON were syntactically valid.

**`PromotionCard` image URL is empty:**

```json
"image": ""
```

No promotional image will surface in Gmail's Promotions tab carousel.

**Footer / physical address / unsubscribe** — HTML is truncated; cannot confirm presence of required CAN-SPAM elements (physical mailing address, unsubscribe mechanism). Must be verified against the full source. The sending domain `e.dcsg.com` is a dedicated ESP subdomain, which is standard.
