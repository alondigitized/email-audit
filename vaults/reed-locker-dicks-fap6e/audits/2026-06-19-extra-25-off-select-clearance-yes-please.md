# EXTRA 25% off select clearance? Yes, please! 🙌
**Score:** 7/10 · **Type:** Email audit · **2026-06-19**
## Executive summary

- This is the fifth (or possibly sixth) near-identical "EXTRA 25% OFF Select Clearance" send from the DICK'S Clearance sub-account in roughly 72 hours. The dark-red hero is pixel-identical to the June 16, 17, and 18 versions. At this point the creative is doing more to erode list trust than to drive incremental conversions — a subscriber who opened any of the previous three sends has already seen everything here.
- Inside the fold, the merchandising spread is genuinely broad: running shoes, women's apparel, golf clothing, Blackstone griddles, camping gear, and a $10 Bonus Rewards pull. That breadth confirms this is a clearance dump, not a curated send. The category variety isn't a flaw, but without a single hero product or a credible deadline the email gives no specific reason to click *now* versus later — or versus the one that landed yesterday.
- Bottom line: technically competent, render is clean, offer is real — but this send is running on fumes. The cadence fatigue from the prior week's stack of identical clearance blasts is the single biggest drag on every score here.

## What's working

- **Hero legibility is instant.** "EXTRA 25% OFF" on dark red reads at a glance even at thumbnail size in the inbox.
- **$10 Bonus Rewards module adds a stacking incentive** — a $10 reward on a $100 purchase is a real hook for an already-warm buyer and differentiated from the prior sends that didn't feature it.
- **Category breadth is an asset for a clearance email** — running, golf, camping, and griddles cover a wide swath of the list without obvious mismatch.
- **No render bugs.** Images load, text doesn't overlap, CTAs are visible throughout.

## What's weak

- **Creative is fatigued beyond repair.** This is the same dark-red "EXTRA 25% OFF" hero used on June 16, 17, and 18. A subscriber who opened any of those is looking at an identical email.
- **No deadline anywhere visible.** There's no "ends tonight," "48 hours only," or countdown clock — nothing converts browsing intent into urgency.
- **"SHOP NOW" CTAs are generic throughout.** Every module says the same thing; none tell you what specifically you're clicking into.
- **Subject line rhetorical device is weak.** "Yes, please! 🙌" reads like filler copy that pads length without earning a click.
- **Email is long without a payoff.** The scroll depth from hero to footer is significant, and the bottom "Must-have gear for an epic summer!" product grid feels disconnected from the clearance theme.

## Recommendations

- 1. **Retire this creative immediately.** The dark-red "EXTRA 25% OFF" block has now run four consecutive days. Even if the offer is extended, the hero needs to change — different color, different typography, different product in the image.
- 2. **Add a hard deadline.** A single line — "Offer ends Sunday at midnight" — would convert fence-sitters without requiring any structural change.
- 3. **Replace "SHOP NOW" with category-specific CTA copy.** "Shop Running Shoes," "Shop Golf Clearance," "Shop Camping Gear" — one line of work that meaningfully lifts click relevance.
- 4. **Anchor the subject on the deadline or the $10 Rewards hook**, not the discount that's been repeated all week.
- 5. **Surface the Bonus Rewards offer higher.** It's the only new variable vs. prior sends — it should be in the subject or at least immediately below the hero.
- **Subject Alt A:** `Clearance + a $10 Bonus Reward — ends Sunday`
- **Subject Alt B:** `New clearance drops: up to 75% off + earn $10 back`
- **Preheader Alt A:** `Stack your Extra 25% off before it's gone — select styles only.`
- **Preheader Alt B:** `Running, golf, camping gear marked way down. Offer ends this weekend.`

## Technical Audit — DICK'S Sporting Goods Clearance Email

---

### 1. Technical Summary

Email is built on Epsilon/Harmony ESP infrastructure with standard MSO conditional rendering guards. The primary technical defects are invalid JSON-LD structured data (which will suppress Gmail Promotions tab annotations) and stale/empty template fields that indicate the structured data block was never properly populated.

---

### 2. Link & Tracking Issues

**Open pixel** — `https://app.dickssportinggoods.com/O/v610000019edf7a1693c5986cf4bbc780a0/ed5e4ff14af5417000004c5a42963aa1` — rendered via hidden `<img style="display:none">`. Technically functional; Apple MPP will pre-fire this for all iOS 15+ recipients, inflating open rates. No fix available at send time — note for reporting interpretation.

**Click tracking** — All hrefs route through `https://app.dickssportinggoods.com/T/...?__dU__=<encoded>`. Pattern is consistent and correct for Epsilon. No bare/untracked links visible in the truncated source.

**UTM params** — Cannot confirm UTM parameters on destination URLs because they are encapsulated inside the ESP redirect. Verify that the ESP is appending UTM parameters post-redirect; if not, GA4 will attribute all traffic as direct.

---

### 3. Rendering & Accessibility

**Malformed CSS in MSO conditional** — The `<style>` block inside `<!--[if (gte mso 9)|(IE)]>` ends the `div` rule with a stray double-quote:

```css
div {background-color:inherit; font-size:0; line-height:100%; margin:0; padding:0;"}
```

The trailing `"` after the semicolon is invalid CSS. Outlook's CSS parser will likely drop the entire `div` rule, which could affect font-size and line-height resets in Outlook 2016–2021.

**`border-radius` on `<table>`** — `#header-non-sc-member` has `border-radius:8px 8px 0px 0px`. Outlook ignores CSS `border-radius` on table elements entirely; no VML fallback is provided. Corners will render square in all Outlook versions.

**`alt` attribute on logo** — The `<img id="logo">` src is truncated in the provided source; cannot confirm an `alt` value is present. If missing, screen readers will announce the raw filename or URL.

**Hidden tracking pixel** — `style="display:none; max-height:0px; font-size:0px; overflow:hidden; mso-hide:all"` — approach is standard, no issues.

**`lang="en"`** on `<html>` — present. `role="presentation"` on layout tables — present. `<meta charset="UTF-8">` and `viewport` meta — present.

---

### 4. Personalization & Merge Tokens

**JSON-LD structured data is entirely unpopulated and contains invalid syntax:**

```json
{
  "@type": "DiscountOffer",
  "description": "",
  "discountCode": "",
  "availabilityStarts": "2020-03-06T06:00:00-04:00",
  "availabilityEnds": ""
}
```

- `availabilityStarts` is hardcoded to **2020-03-06** — six years stale.
- `availabilityEnds`, `description`, `discountCode`, and `PromotionCard.image` are all empty strings — unfilled template slots.
- The block contains **JavaScript-style `//` line comments**, which are not valid JSON. Gmail's structured data parser will reject the entire `<script type="application/ld+json">` block, meaning no Promotions tab annotation (deal badge, offer expiry, promo image) will render.

Designer note embedded in source (`// DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!`) confirms this block was intentionally left as a template and not completed before send.

**Sender identity** — From name "DICK'S | Clearance" and domain `e.dcsg.com` (subdomain of `dcsg.com`) clearly identifies the sender. No deceptive header indicators visible.

**Authentication headers** — not visible in provided source (headers were not included). SPF/DKIM/DMARC status for `e.dcsg.com` should be confirmed via raw message headers before drawing conclusions. Epsilon-hosted sends typically have these configured, but cannot assert from HTML alone.
