# Lucky you! Up to 50% OFF our best deals of the week is a click away...
**Score:** 8/10 · **Type:** Email audit · **2026-05-18**
## Executive summary

- This is DICK'S running its familiar "Best Deals of the Week" template on the same day it sent a stronger Memorial Day Event email (scored 8/10 today). The result is two sends competing against each other in the same inbox, with the weaker one — this one — undermining the better creative. The "Lucky you!" subject opener is the defining problem: it's nine characters of hollow pseudo-personalization that signals clickbait and arrives on a subject line already bloated to 70+ characters. Recipients who already opened the Memorial Day send will feel nothing new here.
- Inside the email, the body does real work. The $20-and-under shoe section, 60% off DSG apparel, and a dense product grid give genuine reasons to click. Visual hierarchy is clean; the red 50% badge reads fast. But the email is structured as a category sweep — not a curated offer — which diffuses intent. There's no deadline, no countdown, no Memorial Day hook to explain why today is the day to act.
- Verdict: the body is 7/10, the subject line is 4/10, and the same-day cadence collision with a better send makes both worse. This email would read stronger if it were killed entirely and its offers rolled into the Memorial Day send as a secondary section.

## What's working

- **Real, specific in-body offers:** "$20 and Under Select Shoes" and "Up to 60% Off Select DSG Clothing for the Family" are concrete price anchors, not vague percentage ranges.
- **Clean visual hierarchy:** The red 50% OFF badge dominates the hero; the eye goes there first.
- **Category nav tabs** (Men's, Women's, Kids, Golf, Team Sports, Clearance) let a scanner self-select quickly.
- **Dense product grid with named brands:** HOKA, New Balance 550, Under Armour visible — real SKUs, not stock photography.

## What's weak

- **"Lucky you!" is hollow filler** — adds length to an already-long subject while delivering zero signal about the offer.
- **No seasonal or campaign frame:** The other DICK'S send today uses "Memorial Day Event"; this one reverts to generic "Best Deals of the Week," making it feel like inbox filler by comparison.
- **Subject is 70+ characters** — gets truncated hard on mobile, cutting off before the offer resolves.
- **No urgency mechanism:** No deadline, no "ends Sunday," no countdown anywhere in the body.
- **Same-day cadence collision:** Two sends in one day from the same brand — this one is the weaker sibling and pays the price.

## Recommendations

- 1. **Kill "Lucky you!" entirely** — start the subject with the offer. The opener adds length, removes trust, and signals spam filters.
- 2. **Adopt the Memorial Day frame** — every send this week should be anchored to the campaign name. "Best Deals of the Week" sounds evergreen; "Memorial Day Deals" sounds like a reason to act today.
- 3. **Add a deadline** — even "This week only" in the hero subhead converts browsers into buyers.
- 4. **Collapse into one send or make this the category-specific follow-up** — send men's deals to men, women's to women. The grid is too broad to feel personal.
- 5. **Shorten the subject line to under 50 chars** for clean mobile rendering.
- **Subject Alt A:** `Memorial Day: up to 50% off this week`
- **Subject Alt B:** `$20 shoes. 60% off apparel. Deals are live.`
- **Preheader Alt A:** `HOKA, New Balance, DSG — shop before Memorial Day weekend ends`
- **Preheader Alt B:** `Ends Sunday: $20 shoes, 60% off DSG clothing, and more`

## Technical Audit

## Technical Audit — DICK'S Sporting Goods Promotional Email

---

### 1. Technical Summary

The email uses Epsilon's redirect/tracking infrastructure correctly, but contains a fatally malformed `<script type="application/ld+json">` block (JavaScript comments inside JSON) that will silently break all Gmail structured-data annotations. Several schema fields are also stale or empty template defaults.

---

### 2. Link & Tracking Issues

**Epsilon redirect chain confirmed** — all CTA links route through `app.dickssportinggoods.com/T/v610000019e3cb8e8f19a43c6f4bbe5c7c0/...`. Tracking appears wired.

**Staging/dev asset path in logo URL (unconfirmed — source truncated):**
```
https://dsg.images.harmony.epsilon.com/_phoenix/_dev…
```
The `_dev` path segment in the image host is a red flag. If this resolves to a dev/staging CDN rather than production, images will 404 or serve stale assets in some inboxes. Needs verification against the full source.

**Tracking beacon:**
```
https://app.dickssportinggoods.com/O/v610000019e3cb8e8f19a43c6f4bbe5c7c0/cb322e1aff474e3b00004c5a42963aa1
```
Pixel is correctly hidden (`display:none; max-height:0px`). No issues.

---

### 3. Rendering & Accessibility

**Unencoded ampersand in preheader text:**
```html
<td id="ssl" ...>
  + $100 & under select shoes 💰
```
`&` should be `&amp;` in HTML. Some strict parsers (Outlook) may mangle this character.

**Logo `alt` attribute — unverifiable** (source truncated before the `<img>` closes). Flag for manual check.

**Font loading** — `@font-face` for Archivo is correctly scoped inside `@media screen`, preventing download in non-screen clients (Outlook). No issues.

**Table layout** — `border-collapse:separate` combined with `border-spacing:0` is intentional for border-radius support. Correct for this pattern.

**MSO conditional styles** — `<!--[if (gte mso 9)|(IE)]>` blocks present and syntactically valid.

---

### 4. Personalization & Merge Tokens

**`id="header-non-sc-member"`** implies a conditional block for non-ScoreCard members. The corresponding `header-sc-member` variant is not visible in the truncated source — cannot confirm whether dynamic content switching is implemented.

**`DiscountOffer.discountCode` is an empty string:**
```json
"discountCode": ""
```
If this field is meant to carry a personalized promo code, it was not populated. If intentional (no code for this send), the field should be omitted entirely rather than sent as empty.

---

### 5. Compliance

**CAN-SPAM / unsubscribe** — footer not visible in truncated source. Cannot confirm presence of physical address or unsubscribe link. Must verify manually.

**Sender domain:** `DSG@e.dcsg.com` — subdomain of `dcsg.com` (Dick's parent domain). Standard ESP sending domain; no issues assuming SPF/DKIM/DMARC are configured on `e.dcsg.com`. Authentication headers not available for inspection here.

---

### 6. Email-to-Site Continuity (UTM Params)

UTM parameters are not visible in the Epsilon redirect URLs shown. Epsilon's system typically appends them at redirect time or encodes them in the token. **Cannot confirm UTM pass-through from this source alone** — requires inspecting a live redirect response or the Epsilon campaign config.

The `availabilityStarts` date in the JSON-LD schema is a stale template default:
```json
"availabilityStarts": "2020-03-06T06:00:00-04:00"
```
This is 6 years old and will be ignored by Gmail's annotation engine, but it signals the template was not fully updated for this send.

---

### 7. Recommendations

**Critical — fix before any future send:**

1. **Remove all `//` comments from the `<script type="application/ld+json">` block.** JSON does not support line comments. The entire structured data array is currently invalid and will be rejected by every JSON parser, meaning Gmail promotional annotations will never render. Example of the breaking lines:
   ```json
   { // GIF & WEBP images are not supported and will be filtered out.
     // Sample image is 538x138, 3.9 aspect ratio
     ...
     // DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!
     "image": ""
   }
   ```
   Strip all `//` lines and populate `"image"` with the actual promo card URL before sending.

2. **Populate or remove the empty `PromotionCard.image` field.** An empty string fails schema validation. Either add the correct URL or omit the object.

3. **Update `availabilityStarts` / `availabilityEnds`** to reflect the actual campaign window.

**High — verify before send:**

4. **Confirm the logo image host** does not contain `_dev` in the production send path. Pull the full HTML source and inspect every `src=` attribute.

5. **Encode the ampersand** in the preheader: change `+ $100 & under` to `+ $100 &amp; under`.

6. **Verify UTM pass-through** by clicking a tracked link in the test send and confirming `utm_source`, `utm_medium`, and `utm_campaign` appear in the final destination URL.

7. **Manually confirm** CAN-SPAM footer (physical address + unsubscribe) is present — source was truncated before the footer.
