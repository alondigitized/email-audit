# *** App exclusive: spend $100+… get $20 off ***
**Score:** 5/10 · **Type:** Email audit · **2026-05-24**
## Executive summary

- This is — by my count — DICK'S seventeenth-plus promotional send in roughly a week, and the fifth distinct email built around the "Epic Memorial Day Sale" creative I've reviewed since Friday. The actual offer here is narrower than the daily 50%-off drumbeat: an app-exclusive $20-off-$100 stack, hero-imaged with a blue tiled grid of "$20 OFF" cards. That's a legitimate hook, but the subject line buries it under asterisk-spam (`*** App exclusive: spend $100+… get $20 off ***`) that reads like a deliverability red flag, not a deal.
- Below the fold, the email reverts to the same Memorial Day boilerplate — 50% hero band, Nike favorites, sandals, camping, basketball, ALL®. So the "app exclusive" framing is the only new beat, and it's not reinforced anywhere obvious in the body copy I can see. The render itself is clean: grid is tight, modular product blocks are intact, no broken images.
- Net: a real, differentiated mechanic (app-exclusive stackable coupon) wrapped in the brand's most spammy-looking subject of the week. The asterisks alone probably cost them opens.

## What's working

- The "$20 OFF" tiled hero is instantly legible and communicates the offer without needing to read.
- Clear secondary 50%-off Memorial Day band keeps the holiday context without overwhelming the app hook.
- Modular category grid (Nike, sandals, camping, basketball, ALL®) gives multiple click targets.
- Clean render — no layout breaks, broken images, or overlapping text.

## What's weak

- Triple-asterisk subject line `*** … ***` looks like spam-folder bait, not a premium retailer.
- The "app exclusive" angle isn't visually reinforced in the hero — no phone mockup, no QR code, no "open in app" CTA visible.
- Seventeen-plus sends in a week means subscribers are numbed; the Memorial Day creative below the hero is now repetitive.
- $20 off $100 is a weaker hook than the headline "up to 50% off" they've been blasting all week — risks feeling like a downgrade.
- No visible code, no visible expiry — terms of the app-exclusive offer aren't surfaced in the hero area.

## Recommendations

- 1. **Kill the asterisks.** The `*** … ***` framing is the single biggest open-rate drag here. Lead with the mechanic in plain English.
- 2. **Make the "app" part of the hero do work** — add a phone-frame visual or "Tap to open in app" button so the exclusivity feels real, not slapped on.
- 3. **Surface the code or auto-apply note** in the hero band so subscribers don't worry about whether it'll work at checkout.
- 4. **Add an expiry timestamp** ("ends 11:59 PM Monday") near the hero — Memorial Day urgency is the whole point.
- 5. **Demote the generic 50% band** — it competes with the app-exclusive story and confuses which deal is "the" deal.
- **Subject Alt A:** `App-only: $20 off your $100+ order`
- **Subject Alt B:** `Open the app — $20 off $100 through Monday`
- **Preheader Alt A:** `Stack it on Memorial Day deals. App users only, ends 5/26.`
- **Preheader Alt B:** `Your app unlock: $20 off $100+ for the holiday weekend.`

## Technical Audit

### 1. Technical Summary
The HTML uses a standard MSO-conditional table layout with Archivo web fonts and Epsilon (Harmony) link wrapping. Source is truncated, but several issues are observable in what was provided.

### 2. Link & Tracking Issues
- Logo `<img>` `src` is truncated mid-URL (`brand-logo--dk…`) — cannot verify image loads, but the host `dsg.images.harmony.epsilon.com/_phoenix/_dev/AEM/...` contains `_dev/` in the path, which is a red flag for a production send (suggests a non-prod AEM asset path).
- Tracking pixel and click-tracking are routed through `app.dickssportinggoods.com` (Epsilon Harmony). Pixel is correctly hidden (`display:none; max-height:0; mso-hide:all`). OK.
- No UTM parameters visible on the wrapped CTA link — Epsilon's `__dU__` token replaces them, so downstream attribution depends on Epsilon→GA stitching rather than standard `utm_source/medium/campaign`. Flag if GA4 reporting expects native UTMs.

### 3. Rendering & Accessibility
- `<img id="logo">` has no `alt` attribute in the visible source — fails WCAG 1.1.1 and degrades Outlook image-blocked rendering.
- `<title>` is generic ("DICK'S Sporting Goods") rather than mirroring the subject line — minor a11y/preview issue.
- No preheader text element visible in the truncated source; the first visible node after `<body>` is the SSL pixel cell, so inbox preview will fall through to body copy uncontrolled.
- MSO conditional CSS contains a syntax error: `padding:0;"}` — stray `"` inside the `div { ... }` block. Outlook may drop the rule.
- `font-family:Archivo,Arial,sans-serif;font-family:Archivo,Arial,sans-serif!important` is duplicated on `body`.

### 4. Personalization & Merge Tokens
- No merge tokens (`%%first_name%%`, `${...}`, etc.) found in the provided source. Subject line `*** App exclusive: spend $100+… get $20 off ***` contains literal asterisks — likely intentional ESP placeholders for A/B test markers, but if not stripped pre-send they will render in the inbox. Confirm with send platform.

### 5. Compliance
- Truncated source does not include the footer, physical address, or unsubscribe link — cannot verify CAN-SPAM compliance from the excerpt provided.
- JSON-LD `DiscountOffer` block has empty `description` and `discountCode` fields and an `availabilityStarts` of `2020-03-06` with no `availabilityEnds` — Gmail Promotions annotations will likely be rejected or ignored.
- JSON-LD `PromotionCard` has an empty `"image": ""` and contains JS-style `//` comments inside the JSON, which is invalid JSON-LD and will fail schema.org parsers.
- Authentication headers (SPF/DKIM/DMARC) not provided in the input; cannot audit.

### 6. Email-to-Site Continuity
- All links are Epsilon-wrapped, so final landing URL is not inspectable from source. UTM alignment with the DSG site cannot be verified without resolving a wrapped URL.
- `From:` domain `e.dcsg.com` is a known DSG sending subdomain; alignment with `dickssportinggoods.com` requires DMARC relaxed alignment — verify.

### 7. Recommendations
- Replace `_dev/` AEM asset path with the production CDN path before send.
- Add descriptive `alt` text to `<img id="logo">` (e.g., `alt="DICK'S Sporting Goods"`).
- Add a hidden preheader `<div>` immediately after `<body>` to control inbox preview text.
- Fix the stray `"` in the MSO `<style>` block: `padding:0;"}` → `padding:0;}`.
- Remove the duplicated `font-family` declaration on `body`.
- Fix JSON-LD: remove `//` comments, populate `image`, set a valid `availabilityEnds`, or remove the schema blocks entirely if unused.
- Resolve a wrapped Epsilon link in a test send to confirm landing URL + UTM parameters match site analytics expectations.
- Verify the `***` asterisks in the subject line are not unresolved ESP tokens.
