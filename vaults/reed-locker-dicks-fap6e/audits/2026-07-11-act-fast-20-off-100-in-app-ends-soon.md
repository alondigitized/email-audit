# Act fast! $20 off $100+ in-app ends soon ⏳
**Score:** 8/10 · **Type:** Email audit · **2026-07-11**
## Executive summary

- This is the fourth consecutive delivery of the same $20 off $100+ app-exclusive offer — July 10 debut, July 10 "expires TOMORROW," July 11 "ends TONIGHT," and now July 11 "Act fast… ends soon." The creative is functionally identical each time: dark green hero, countdown timer, GET OFFER button, secondary 60% off clearance banner. As a standalone email it's clean and well-executed. As the eleventh email in roughly two days from the same sender, it reads as a system stuck in a loop.
- The countdown timer and "Final Hours" framing are the emotional engine here — and they do their job. The hierarchy is legible: timer → $20 off hero → GET OFFER → clearance secondary. The product grid below the fold adds browse value and features women's CALIA items relevant to the persona. None of that helps when the inbox is already drowning in DICK'S sends and the urgency mechanic has cried wolf three times.
- Verdict: a technically competent email that has been deployed one — maybe three — sends too many times. The real cost isn't the creative; it's the credibility debt accumulated by treating "ends TONIGHT" as a revolving door.

## What's working

- Countdown timer + "Final Hours" framing is the strongest urgency hook DICK'S has run in this cycle — more visceral than text alone.
- "$20 OFF" hero is large, high-contrast, and unmissable — the offer parses in under a second.
- "No code needed" copy removes the friction of digging for a promo code.
- CALIA women's grid adds persona-relevant browse appeal below the hero.
- Secondary 60% clearance banner is visually distinct (red vs dark green) and doesn't cannibalize the primary offer.

## What's weak

- The "app exclusive" mechanic creates hard friction — any non-app user must download or open the app before redeeming, killing the click-to-conversion path.
- No ScoreCard+ loyalty acknowledgment — the paid membership upsell from the July 9 send is already forgotten.
- Urgency is completely hollowed out: "ends TONIGHT" yesterday, "ends soon" today — subscribers who opened the prior send know this deadline is elastic.
- The ** on the offer headline telegraphs exclusions without explaining them inline; forces the reader to scroll to fine print.
- Eleven emails in two days will be triggering unsubscribes and spam complaints that dwarf whatever incremental revenue this fourth trigger generates.

## Recommendations

- 1. **Stop.** This offer has now run four sends. If it hasn't converted by send three, send four is burning the list, not converting it. Cut the chain here.
- 2. **Retire the elastic urgency.** If the deadline is real, honor it. If it isn't, the credibility cost compounds with each send and permanently damages future urgency copy.
- 3. **Lock the hero to a specific women's product** — a CALIA legging, a running shoe — with a "shop now" link to that PDP. App-exclusive offers that link to a category page lose people who want one specific thing.
- 4. **Surface the ScoreCard+ angle** — if members get early access or stacking rewards on the app offer, say so. That's the only differentiation this send has that prior sends didn't.
- 5. **Reframe the app requirement as a benefit, not a gate** — "in the app" buried in the subject feels like a gotcha; "first look in the app" or "members get it first" reframes the exclusivity as reward.
- **Subject Alt A:** `Last call: $20 off $100+ in the app — for real this time`
- **Subject Alt B:** `CALIA, YETI, On — $20 off your pick (app only, Final Hours)`
- **Preheader Alt A:** `Countdown's real. No code, just tap GET OFFER before it's gone.`
- **Preheader Alt B:** `ScoreCard members: stack this with your points before midnight.`

## Technical Audit — DICK'S Sporting Goods: "$20 off $100+ in-app" Email

### 1. Technical Summary

Standard table-based Outlook-compatible layout with functional tracking infrastructure. Two critical defects: the JSON-LD block is syntactically invalid JSON (JS-style comments embedded), and a stale hardcoded date and multiple unfilled placeholder fields were shipped in the structured data block.

---

### 2. Link & Tracking Issues

**No blocking issues found** in the truncated source, but two items need follow-up:

- **Open pixel**: `https://app.dickssportinggoods.com/O/v610000019f52e396a1b092046e96638858/de20322dd843408700004c5a42963aa1` — standard 1×1 open tracker, correctly hidden.
- **Click redirect**: CTAs route through `app.dickssportinggoods.com/T/...` with a `__dU__` user identity token. This is expected for an ESP redirect. UTM parameters on the final destination URL cannot be verified from the provided source (link is truncated before the destination); see §6.
- **`<link rel="icon">` in `<head>`**: Has no effect in any email client. Harmless noise, but indicative of a desktop-web template being repurposed without email-specific cleanup.

---

### 3. Rendering & Accessibility

**CSS syntax error in MSO conditional block** (high severity for Outlook):

```html
<!--[if (gte mso 9)|(IE)]><style>
  div {background-color:inherit; font-size:0; line-height:100%; margin:0; padding:0;"}
```

There is a stray `"` before the closing `}` in the `div` rule. This is invalid CSS. Outlook's renderer may reject the entire rule block, causing `div` elements to render with default spacing/sizing in Outlook 2016–2021.

**Fix:** `padding:0;"}` → `padding:0;}`

Other rendering items:
- `role="presentation"` on layout tables: correct.
- `lang="en"` on `<html>`: correct.
- `a[x-apple-data-detectors]` override present: correct.
- Logo `<img id="logo">` HTML is truncated in the provided source — **`alt` attribute presence cannot be confirmed.** Must verify in full source; missing `alt` on the logo is a common audit failure.
- Tracking pixel hidden via `display:none; max-height:0px; overflow:hidden; mso-hide:all`: correct pattern.

---

### 4. Personalization & Merge Tokens

The `<script type="application/ld+json">` block has **multiple critical defects**:

**A. Invalid JSON — JS-style comments embedded (critical)**

```json
{ // GIF & WEBP images are not supported and will be filtered out.
  // Sample image is 538x138, 3.9 aspect ratio
  "@type": "PromotionCard",
  // DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!
  "image": ""
}
```

JSON does not support `//` comments. This block will throw a parse error in every JSON parser including Gmail's structured data extractor. The entire JSON-LD annotation is silently dropped. Designer/QA instructions were left in the production send.

**B. Empty placeholder fields shipped to subscribers**

| Field | Value | Impact |
|---|---|---|
| `DiscountOffer.discountCode` | `""` | No promo code surfaced in Gmail annotation |
| `DiscountOffer.description` | `""` | No offer description |
| `DiscountOffer.availabilityEnds` | `""` | Gmail cannot show offer expiry in Promotions tab |
| `PromotionCard.image` | `""` | No promo card image; Gmail Promotions tab shows blank |

**C. Stale hardcoded `availabilityStarts`**

```json
"availabilityStarts": "2020-03-06T06:00:00-04:00"
```

This date is over 6 years old. It should be the current campaign start date. A static value suggests this field was never wired to a merge variable.
