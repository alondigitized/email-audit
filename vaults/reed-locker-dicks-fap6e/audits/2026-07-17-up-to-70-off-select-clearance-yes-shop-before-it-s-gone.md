# Up to 70% off select clearance? YES! Shop before it's gone
**Score:** 8/10 · **Type:** Email audit · **2026-07-17**
## Executive summary

- This is the third iteration of DICK'S Summer Clearance 70%-off email in four days — structurally identical to the July 14 and July 16 sends: dark hero with the bold "UP TO 70% OFF" badge, category browse rail, a Nike sub-offer, and a dense product grid below. The only creative differentiation from the July 16 send is the subject line's question-mark + "YES!" hook. That novelty wears off in about two seconds.
- Taken cold, the email is competently executed: the hero is legible, the discount punches, the CTA hierarchy works. But the July 15 "Fresh Picks" reset (10/10) showed DICK'S knows how to break a repetitive discount loop — then they immediately snapped back into it. Sending this creative a third time erodes the credibility of the offer itself. If 70% off was so urgent on July 14 and July 16, why is it still here on July 17?
- Verdict: technically solid, strategically lazy. Subscribers who've been in their inbox this week have already decided if they wanted this clearance deal.

## What's working

- **Hero legibility is strong.** "UP TO 70% OFF" in oversized white type on a dark background is immediately scannable — zero ambiguity about what the email offers.
- **SHOP NOW button is high-contrast and well-placed** directly below the hero copy — no hunting required.
- **Nike sub-section adds a brand anchor.** The "$100 and Under Select Nike Favorites" block gives a concrete price ceiling and a recognizable brand name, which is stronger than a generic clearance bucket.
- **Scorecard loyalty signal is present** — the loyalty program is visible at the top, which is a subtle but meaningful trust signal for enrolled members.

## What's weak

- **Creative is on its third run this week.** The July 16 review already called this email "structurally identical to July 14." This July 17 version makes it three in a row, and cadence fatigue is now a real subscriber trust problem.
- **"Before it's gone" is a hollow deadline.** It doesn't name a date, a quantity, or an event — it's the email marketing equivalent of "hurry up." After three sends of the same offer, it reads as false urgency.
- **The product grid is too small to drive clicks.** The "Must-have gear for an epic summer!" section crams multiple SKUs into thumbnail-sized cells with barely readable labels — it's a catalog dump, not a curated recommendation.
- **Three competing "SHOP NOW" buttons dilute attention.** The main CTA, the Nike section, and the "top deals" row all use identical button copy, creating no click hierarchy.
- **"YES!" in the subject line is forced.** The question-and-answer construction ("Up to 70% off select clearance? YES!") feels like a copywriter trying to refresh stale creative without actually changing the creative.

## Recommendations

- 1. **Stop sending this creative.** The single highest-impact change isn't a rewrite — it's a content decision. Pull this template after two sends and pivot back to editorial (like the July 15 "Fresh Picks" send) or a category-specific angle (Running, Back to School, Trail Gear).
- 2. **Anchor the subject to a hard deadline.** "Before it's gone" is doing no work. Swap it for a specific end date so the urgency is falsifiable and credible.
- 3. **Give the hero a product.** A single hero image of a recognizable clearance item — a shoe, a cooler, a bike — outperforms a standalone discount badge for click intent.
- 4. **Consolidate to one CTA.** One "SHOP SUMMER CLEARANCE" button, no secondary "SHOP NOW" clones competing for attention.
- 5. **Upgrade the Nike block.** It's the strongest section — lead with it or give it a product image, not just a text headline.
- **Subject Alt A:** `Clearance hits 70% off — last call before sizes run out`
- **Subject Alt B:** `Final 48 hrs: summer clearance ends Sunday`
- **Preheader Alt A:** `Nike, Under Armour, adidas — limited sizes, real markdowns`
- **Preheader Alt B:** `The deepest cuts of summer. Don't say we didn't warn you.`

## Technical Audit — DICK'S Clearance Email

### 1. Technical Summary
The email has two confirmed infrastructure defects: an invalid JSON-LD block with JavaScript comments and stale/empty schema fields, and a stray character in the MSO conditional CSS that invalidates the `div` reset rule in Outlook. The rest of the structure is standard ESP-rendered HTML; the truncated source prevents full compliance verification.

---

### 2. Link & Tracking Issues

**Open pixel** — `https://app.dickssportinggoods.com/O/v610000019f71cab27f8ef1d8f4bbcfb920/...` — rendered with no `alt=""` attribute. Not exploitable (it's `display:none`), but technically malformed.

**ESP redirect chain** — all CTA links route through `app.dickssportinggoods.com/T/v610.../?__dU__=<base64>`. UTM attribution appears to be applied server-side at redirect time. Cannot confirm UTM presence from HTML alone (see §6).

No broken or suspicious domains detected in the visible link set.

---

### 3. Rendering & Accessibility

**MSO conditional CSS — stray `"` character (confirmed bug):**
```html
<!--[if (gte mso 9)|(IE)]><style type="text/css">
  ...
  div {background-color:inherit; font-size:0; line-height:100%; margin:0; padding:0;"}
</style><![endif]-->
```
The `div` rule ends with `padding:0;"` — an extra double-quote before `}`. This invalidates the entire `div` reset in Outlook/IE, potentially causing layout-breaking spacing in Outlook desktop.

**Positive signals:**
- `role="presentation"` on all tables — correct
- `lang="en"` on `<html>` — correct
- MSO `PixelsPerInch` and `AllowPNG` declarations present
- `@font-face` wrapped in `@media screen` — correctly keeps web fonts from breaking Outlook

**Cannot verify from truncated source:** alt text on product images, logo `alt` attribute.

---

### 4. Personalization & Merge Tokens

No visible unfilled merge tokens (`%%`, `{{`, `[%`, etc.) in the rendered HTML.

**JSON-LD schema fields are empty** (separate from visible body — see §2 in schema block):
- `"description": ""` on `DiscountOffer`
- `"discountCode": ""`
- `"availabilityEnds": ""`
- `"image": ""` on `PromotionCard`

These don't affect the visible email body but indicate the schema block was never populated for this send.

### 5. Compliance

**CAN-SPAM / physical address:** Not visible in the truncated source. Cannot confirm presence of required postal address or unsubscribe mechanism from the provided HTML.

**JSON-LD block contains JavaScript comments — invalid JSON (confirmed bug):**
```js
{ // GIF & WEBP images are not supported and will be filtered out.
  // DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!
  "@context": "http://schema.org/",
  "@type": "PromotionCard",
  "image": ""
}
```
JSON does not permit `//` comments. This will cause a parse error in any JSON-LD consumer (Gmail Promotions tab, schema validators). The entire `<script type="application/ld+json">` block is non-functional.

**Stale date in schema:** `"availabilityStarts": "2020-03-06T06:00:00-04:00"` — a 6-year-old timestamp, clearly a template default that was never updated.

**Authentication headers:** Not evaluable from HTML source. Requires inspection of raw email headers (DKIM, SPF, DMARC on `e.dcsg.com`).

---

### 6. Email-to-Site Continuity

All links pass through `app.dickssportinggoods.com/T/...` ESP redirects. UTM parameters (`utm_source`, `utm_medium`, `utm_campaign`) are not present in the HTML-side URLs — they must be injected at redirect time by the ESP.

**Risk:** If the ESP redirect is misconfigured or the campaign is not set up with UTM passthrough, all clicks from this send will land on the destination URL with no attribution. This is unverifiable from the HTML alone and should be spot-checked via a test click before send.
