# Up to 60% off select clearance? You got it!
**Score:** 6/10 · **Type:** Email audit · **2026-06-10**
## Executive summary

- This is the clearance sub-brand sender ("DICK'S | Clearance") stepping up its headline offer to 60% — a meaningful escalation from the 25–30% the main DICK'S account has been hammering for two weeks. The hero banner lands hard and clean: bold green, oversized "60% OFF," and a readable subhead. But the email makes a structural mistake that erodes trust: the product sections directly below the 60% hero are labeled **30% Off Sandals** and **30% Off Casual Apparel.** The subscriber who opens on the promise of 60% off scrolls into a wall of 30% deals. That gap is a credibility hit.
- The email is a catalog scroll — Father's Day section, bottles and coolers, golf balls, an XP rewards module — which means it's doing a lot of work for a clearance send. The volume dilutes the urgency the hero tried to build. "While They Last" scarcity is in the subhead but then disappears for twelve product rows.
- The send is serviceable but it undersells a genuinely good headline. With tighter product curation and a single clearance category up front matching the 60% claim, this email would perform noticeably better.

## What's working

- **60% hero banner is unmissable.** Green-on-black, bold display type, clear hierarchy — the eye lands here first without effort.
- **Subject line is under 50 characters (43)** and includes a hard number — "60% off" is concrete and mobile-friendly.
- **Father's Day hook is timely.** The "June 22" callout grounds the email in the current moment; right instinct 12 days out.
- **XP/rewards module present** — loyalty signals add stickiness for members even in a clearance context.
- **No visible render bugs.** Clean layout, images appear loaded, no broken gaps.

## What's weak

- **60% headline, 30% products.** The two product grids beneath the hero are labeled 30% off — a headline-to-body mismatch that reads as bait-and-switch, even if 60% items exist deeper in the scroll.
- **Catalog sprawl undermines urgency.** Sandals → apparel → bottles → golf → Father's Day → XP rewards — too many themes for a "clearance" send. Scarcity framing collapses when there's unlimited variety.
- **"You got it!" subject line closer is try-hard.** The conversational affirmation feels off-brand for a clearance push; it's neither urgent nor specific.
- **No visible deadline or countdown.** "While They Last" is written once in the subhead and never reinforced — the email needed a visible end date or SKU-scarcity signal.
- **Cadence wear.** This is at minimum the fourth clearance-themed DICK'S send in under two weeks (the June 7 Flash Sale, June 8 50%-off deals, June 9 up-to-40% clothing). The clearance drum is getting loud.

## Recommendations

- 1. **Lead with a 60% product, not a 30% one.** The first product grid must show actual 60%-off items. If none exist above the fold, the hero claim should say "starting at 30%, up to 60% off" — don't promise 60 and deliver 30.
- 2. **Collapse to two sections max.** Clearance + Father's Day is a coherent pair. Bottles, golf, and XP modules should be a separate send or footer-only.
- 3. **Add a visible deadline.** "Clearance pricing valid through Sunday, June 15" or a countdown module. "While They Last" does nothing without a date.
- 4. **Kill "You got it!" in the subject.** Replace with deadline or specificity language.
- **Subject Alt A:** `Clearance just hit 60% off — shop before it's gone`
- **Subject Alt B:** `Up to 60% off clearance — sale ends Sunday`
- **Preheader Alt A:** `Sandals, shoes & apparel — deepest cuts of the season`
- **Preheader Alt B:** `30–60% off select clearance styles while supplies last`

### 1. Technical Summary

The email infrastructure (ESP redirect chain, mobile CSS, MSO conditionals) is structurally sound, but the `<script type="application/ld+json">` block contains invalid JSON that will silently break Gmail Promotions tab rich-card rendering, and a designer placeholder comment was shipped in the production build.

**Open-tracking pixel** — present and correctly hidden:
```html
<img src='https://app.dickssportinggoods.com/O/v610000019eb103a9b3babd166e96c66058/...'
     style="display:none; max-height:0px; font-size:0px; overflow:hidden; mso-hide:all"/>
```

**Click-tracking** — all links route through `app.dickssportinggoods.com/T/` (Epsilon/Harmony). This is correct.

**Comment suggests an unfilled placeholder was shipped:**
```html

```
An SSL pixel is present above this comment, so the actual pixel fired — but the stale comment indicates the template was not fully cleaned before send.

**UTM coverage** — the HTML is truncated before destination URLs are visible. Recommend verifying that the Epsilon redirect chain appends `utm_source`, `utm_medium`, and `utm_campaign` to all landing page URLs. This cannot be confirmed from the provided source alone.

### 7. Recommendations

**P0 — Fix before next send:**

1. **Remove JavaScript-style comments from the JSON-LD block.** JSON does not support `//` comments — every line below is invalid JSON and will cause the entire structured-data block to fail silently:
   ```
   // GIF & WEBP images are not supported and will be filtered out.
   // Sample image is 538x138, 3.9 aspect ratio
   // DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!
   ```
   Gmail's Promotions tab rich-card renderer will drop the block entirely when it cannot parse the JSON.

2. **Populate or remove `PromotionCard.image`.** An empty `"image": ""` with a designer comment means this campaign will not render a rich promo card in Gmail. Either supply a valid 538×138 JPEG/PNG URL or remove the `PromotionCard` object entirely.

**P1 — Fix in template before next campaign:**

3. **Update `availabilityStarts` away from the 2020 hardcoded default.** The current value `"2020-03-06T06:00:00-04:00"` is six years stale — this is clearly a template default that was never overridden. Either populate it dynamically or remove the `DiscountOffer` schema block.

4. **Remove the `<!--Replace/Paste SSL Here-->` comment** from the production template. It signals incomplete template cleanup in rendered source.

5. **Audit UTM coverage** on all destination URLs post-redirect to confirm `utm_source=email`, `utm_medium=...`, and `utm_campaign=...` are consistently appended.
