# ~ Do you want to shop now? Up to 50% off Memorial Day deals ~
**Score:** 7/10 · **Type:** Email audit · **2026-05-20**
## Executive summary

- This is DICK'S fourth-plus Memorial Day-anchored send in roughly three days, following the May 18 "Memorial Day Event = Up to 50% OFF" email that scored 8/10 and was considered the campaign's legitimate anchor. The body is competent — clean Memorial Day hero, multi-category product grid, ScoreCard loyalty pull, no obvious render bugs. DICK'S knows how to build this template.
- The subject line is where this falls apart. The tildes (`~`) flanking the copy are an unusual formatting tick that reads as outsider spam, not polished retail email. "Do you want to shop now?" is a low-conviction question that buries the actual offer — the 50% off claim doesn't land until 30+ characters in, well past mobile truncation. A brand that opened Memorial Day with a clean imperative subject on May 18 has no business soft-pedaling with a permission-seeking question two days later.
- The body wins; the subject line loses. Net result: a capable email that most subscribers on DICK'S current pace will reflexively skip.

## What's working

- **Memorial Day hero is immediately legible** — event name, discount depth (50% off), and category breadth ("More Summer Essentials") read in one pass.
- **Multi-category product grid** covers running, basketball gear, golf, and camping — good coverage of different buyer intents in a single scroll.
- **ScoreCard loyalty block** is a smart anchor near the bottom; rewarding members within the send reduces churn.
- **Clean render** — no broken images, no overlapping text, no visible empty merge fields in the screenshot.
- **Sender display name** ("DICK'S | Memorial Day Event") reinforces campaign context rather than using a generic "DSG@..." label alone.

## What's weak

- **Tilde-framed question subject** ("~ Do you want to shop now? ~") reads as spam formatting and buries the 50% offer past mobile truncation.
- **No hard deadline visible** anywhere in the body — "Memorial Day" implies an end date but never states one; "Sale ends Monday, May 26" would create real urgency.
- **Email is extremely long** — running shoes, basketball, golf, camping, loyalty, and a product grid all compete; the shopper exits before reaching the bottom half.
- **Cadence fatigue** — this is the fourth-plus DICK'S send since May 18; no new creative hook distinguishes it from the near-identical body sent two days ago.
- **No single hero product** — everything links to category pages or the homepage; there's no "this week's star" to anchor a click.

## Recommendations

- 1. **Rewrite the subject** — the single highest-leverage change. Drop the tildes and the question. Lead with the event name and the offer, then add a deadline.
- **Subject Alt A:** `Memorial Day Sale Ends Monday — Up to 50% Off`
- **Subject Alt B:** `Up to 50% Off Running, Camping & More — Memorial Day Only`
- 2. **Add a deadline everywhere** — "Sale ends Monday, May 26" in the hero subhead, repeated in the footer CTA. Every section with a percentage off should state when it expires.
- 3. **Collapse the body to three hero deals** — pick the three highest-converting categories from prior sends (running shoes, camping, and one more), feature them with strong product imagery, and cut the rest to a single "Explore all deals →" link.
- 4. **Write a real preheader** that adds information the subject doesn't.
- **Preheader Alt A:** `Gear up for summer — deals on running, camping, golf and more through Monday.`
- **Preheader Alt B:** `ScoreCard members earn 20% back. Memorial Day pricing through May 26.`
- 5. **Slow the send cadence** — with three virtually identical emails landing in three days, a fourth send reinforces the unsubscribe impulse rather than conversion. One well-timed reminder (today, with a countdown) would outperform two generic repeats.

## Technical Audit — DICK'S Sporting Goods Memorial Day Email

---

### 1. Technical Summary

Table-based layout with MSO conditionals and Epsilon/Harmony click+open tracking infrastructure. Several JSON-LD structured data blocks contain invalid syntax and unfilled template fields that will cause the schema to be silently rejected by all parsers.

---

### 2. Link & Tracking Issues

**Open/click tracking domain confirmed active:** All links route through `app.dickssportinggoods.com/T/...` and the tracking pixel fires via `app.dickssportinggoods.com/O/...`.

**Preheader/subject mismatch (confirmed):**
- Subject: `Up to 50% off Memorial Day deals`
- Preheader text (hardcoded in `#ssl` td): `On now: Up to $150 off select golf electronics`

These describe different offers. Recipients on Outlook/Gmail preview pane will see the golf electronics preheader, not the Memorial Day 50% off message. This is a production content/template sync error with measurable open-rate impact.

**Tracking pixel missing `alt` attribute:**
```html
<img src='https://app.dickssportinggoods.com/O/v610...' 
  style="display:none; max-height: 0px; ..."/>
```
No `alt=""` present. While invisible, some strict validators flag this.

---

### 3. Rendering & Accessibility

**`border-collapse:separate` on wrapper table:**
```html
style="border-collapse:separate; border-spacing:0; ..."
```
`separate` with `border-spacing:0` is functional but non-standard for email. Most Outlook versions behave better with `border-collapse:collapse`. The MSO conditional stylesheet correctly overrides this for Outlook (`table {border-collapse:collapse}`), so no confirmed breakage — but the redundancy adds maintenance risk.

**Google Fonts loaded inline via `@font-face` inside `@media screen`:** Correct pattern for email — Outlook ignores it, webmail clients that support it will load Archivo. No issue.

**Logo `alt` attribute:** Source is truncated before the `<img id="logo">` close tag — unable to confirm presence of `alt`. Flag for manual verification.

---

### 4. Personalization & Merge Tokens

**No dynamic merge tokens visible** in the header block. The email appears to be a non-personalized broadcast (no `%%FIRST_NAME%%` or equivalent). This is fine if intentional.

**`DiscountOffer` JSON-LD block has three unfilled fields:**
```json
"description": "",
"discountCode": "",
"availabilityEnds": ""
```
Empty strings are technically valid JSON but semantically useless — Gmail's promotional annotation won't surface this offer in the Promotions tab without `description` and `availabilityEnds` populated.

**`availabilityStarts` contains a hardcoded stale date:**
```json
"availabilityStarts": "2020-03-06T06:00:00-04:00"
```
This is the template default from 2020, never updated. Gmail's parser will treat this offer as 6 years expired.

---

### 5. Compliance (CAN-SPAM, Unsubscribe, Authentication)

HTML is truncated before the footer — **unable to confirm** presence of:
- Physical mailing address
- Unsubscribe link
- Opt-out mechanism

These must be present. Flag for manual footer verification.

**Authentication headers** (SPF/DKIM/DMARC) are not visible in the provided source — these are envelope-level, not HTML-level. Sending domain is `e.dcsg.com`. Verification requires raw message headers.

---

### 6. Rendering & Accessibility — JSON-LD Validity (Critical)

**Invalid JSON in `<script type="application/ld+json">`:**

The block contains JavaScript-style `//` comments, which are **not valid JSON**:

```js
{ // GIF & WEBP images are not supported and will be filtered out.
  // Sample image is 538x138, 3.9 aspect ratio
  "@context": "http://schema.org/",
  "@type": "PromotionCard",
  // DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!
  "image": ""
}
```

JSON does not support `//` comments. Any conforming JSON parser (including Google's structured data extractor) will reject the entire `<script type="application/ld+json">` block as malformed. This means **all three schema objects** (`Organization`, `DiscountOffer`, `PromotionCard`) fail — including the organization logo used for Gmail sender branding.

Additionally, `"image": ""` is an unfilled designer placeholder that reached production.
