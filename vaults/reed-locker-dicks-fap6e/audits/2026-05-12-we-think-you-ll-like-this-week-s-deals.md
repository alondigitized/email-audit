# We think you'll like this week's deals
**Score:** 8/10 · **Type:** Email audit · **2026-05-12**
## Executive summary

- This is a textbook weekly deals digest from DICK'S Sporting Goods — wide surface area, seven category sections, one structural template repeated top to bottom. The "UP TO 50% OFF" hero is loud and effective; it earns the open immediately. From there, the email becomes a scrolling catalogue: clothing, golf, drinkware, team sports, outdoor, fan shop, fitness gear, each with the same left-image / right-copy / SHOP NOW pattern. Competent execution on a deliberately generic brief.
- The strategic bet here is breadth — DICK'S is counting on at least one category resonating per subscriber. That's a reasonable approach for a weekly digest, but it produces an email with almost no signal for the reader. A walker/runner will mentally wade through golf equipment and fan jerseys before landing on anything personally relevant, and the subject line gives zero help pre-open.
- Solid workhorse send. It'll hit base conversion rates. Anything above that was left on the table.

## What's working

- **Hero stops the scroll:** "UP TO 50% OFF" in large white type on a dark background lands within one second of opening — any opener knows immediately there's a discount.
- **Category filter chips** (GOLF, RUNNING, SWIM, TENNIS) near the top are a smart navigation affordance that rewards the engaged reader.
- **Consistent section layout** — each category block follows the same image/headline/button pattern; zero visual confusion about where to click.
- **"Check out these picks" personalized product row** at the bottom adds a product-level hook for anyone who scrolled past the category blocks.
- **Subject line length (38 chars)** is fully mobile-safe with no spam pattern triggers.

## What's weak

- **Subject is almost content-free:** "We think you'll like this week's deals" names no brand, no category, no specific discount — it reads like a pre-send placeholder that shipped.
- **Every section uses identical "SHOP NOW" copy:** Seven identical buttons with no destination signal; they become interchangeable visual noise by the third section.
- **No personalization in category ordering:** Golf leads regardless of whether the subscriber has ever touched a club; no evidence of browse/purchase-history sequencing.
- **No hard deadline:** "This week's deals" is soft — no explicit end date, no countdown, nothing that creates genuine now-or-never urgency.
- **Zero social proof:** No review snippets, no "bestseller" flags, no "X,000 sold" callouts anywhere in the email.

## Recommendations

- 1. **Rewrite the subject line to name a specific offer or category** — this is the single highest-leverage change in the entire email. A generic "deals" subject has no reason to beat the one above it in the inbox.
- 2. **Differentiate CTA copy per section** — "Shop Running Deals," "Shop Golf," "Shop Outdoor" each cost nothing to write and dramatically reduce decision friction at the point of click.
- 3. **Add an explicit sale-end date** in the hero or in a thin urgency banner below it. "Ends Sunday at midnight" turns passive awareness into an action trigger.
- 4. **Reorder category sections by subscriber segment** — if browse/purchase history skews running or fitness, that section should appear first, not fourth.
- 5. **Add one "bestseller" or "trending" callout** to the personalized picks row — even a simple badge converts it from a product grid into social proof.
- **Subject Alt A:** `Up to 50% off running, outdoor & more — this week only`
- **Subject Alt B:** `Your weekly deals: 50% off + picks we pulled for you`
- **Preheader Alt A:** `Shop running shoes, outdoor essentials, fan gear & more — sale ends Sunday`
- **Preheader Alt B:** `7 categories, up to 50% off — see the picks we picked for you`

### 1. Technical Summary

The email's JSON-LD structured data block contains fatal syntax errors (JavaScript-style comments inside JSON) and multiple unfilled template placeholders that will prevent Gmail promotional card rendering. All other infrastructure appears functional, though the preheader implementation has a conditional rendering risk.

### 2. Link & Tracking Issues

**Open pixel** confirmed at `https://app.dickssportinggoods.com/O/v610000019e1de8b667ae748b6e96c660a0/...` — standard, no issue.

**Click tracking** routes through `https://app.dickssportinggoods.com/T/v610000019e1de8b667ae748b6e96c660a0/...` with a `?__dU__=` parameter. UTM parameters on the final destination URL cannot be confirmed from the truncated source — recommend verifying the redirect chain appends campaign UTMs (`utm_source`, `utm_medium`, `utm_campaign`) before the landing page.

No issues with link protocol (all `https`).

---

### 3. Rendering & Accessibility

**Preheader text exposure risk.** The preheader string `+ Don't miss up to 40% off select clothing & shoes` is a bare text node inside `#ssl`, a TD styled with `height:0; font-size:0; line-height:0`. Those styles apply to the *cell*, not the text node itself. In clients that ignore cell-level font-size suppression (notably some versions of Samsung Mail), this text can render visibly above the header. Standard fix: wrap it in `<span style="display:none;max-height:0;overflow:hidden;mso-hide:all;">`.

**Archivo font pinned to `v7`.** `fonts.gstatic.com/s/archivo/v7/...` is an older version. Google has since released newer cuts of Archivo. Minor — renders correctly but won't benefit from upstream hinting improvements.

**Redundant `font-family` declaration on `body`:**
```css
body{font-family:Archivo,Arial,sans-serif;font-family:Archivo,Arial,sans-serif!important}
```
Duplicate property — harmless but indicates a template generation issue.

**`<link rel="icon">` in `<head>`.** Favicon links are ignored by all email clients and trigger an unnecessary external DNS/HTTP request. Remove.

No issues found with `role="presentation"` on layout tables or the Outlook conditional comment wrapper.

---

### 4. Personalization & Merge Tokens

**Critical: Invalid JSON in `<script type="application/ld+json">`.** The block uses JavaScript-style `//` line comments, which are not valid JSON:

```json
{ // GIF & WEBP images are not supported and will be filtered out.
  // Sample image is 538x138, 3.9 aspect ratio
  "@context": "http://schema.org/",
  "@type": "PromotionCard",
  // DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!
  "image": ""
}
```

JSON parsers (including Gmail's structured data renderer) will reject the entire `<script>` block. This silently disables all structured data features — promotional card, discount offer display in the Promotions tab.

**Stale hardcoded date.** `DiscountOffer.availabilityStarts` is set to `"2020-03-06T06:00:00-04:00"` — a 2020 date left over from a template. `availabilityEnds` is an empty string `""`.

**Unfilled template fields:**

| Field | Value |
|---|---|
| `DiscountOffer.description` | `""` |
| `DiscountOffer.discountCode` | `""` |
| `DiscountOffer.availabilityEnds` | `""` |
| `PromotionCard.image` | `""` |

All four are empty strings — the JSON-LD structured data would provide no promotional value even if the syntax were valid.

Without it, GA4/Adobe Analytics will attribute sessions to direct, obscuring campaign attribution.
