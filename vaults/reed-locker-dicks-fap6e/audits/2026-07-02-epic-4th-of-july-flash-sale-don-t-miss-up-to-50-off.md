# EPIC 4th of July Flash Sale⚡ Don't miss up to 50% off!
**Score:** 8/10 · **Type:** Email audit · **2026-07-02**
## Executive summary

- This is at minimum the tenth DICK'S send since June 26, and the creative machinery is showing its age. The "EPIC 4th of July Flash Sale" framing is a near-identical sibling to the June 27 launch (scored 8/10) and the June 29 continuation (scored 8/10) — same headline structure, same 50% off claim, same 4th of July hook. The word "Flash" is doing a lot of dishonest work here when subscribers have seen five variants of the same 50%-off message in a week.
- Inside the email, the visual execution is competent: the hero is punchy, the "EXTRA 30% OFF Summer Clearance" secondary block is cleanly stacked, and the product grid covers real categories (apparel, bikes, Adidas). However, something goes wrong mid-scroll: there is a large standalone text element — appearing to read "MOM" — sitting between product sections with no clear 4th of July thematic connection. Whether this is a misplaced content block or a layout artifact, it reads as a content assembly error and kills the patriotic momentum at exactly the moment the email needs to close.
- Verdict: the skeleton is fine but the cadence has beaten the concept into the ground, and a content anomaly mid-email undercuts an otherwise workmanlike send.

## What's working

- **Hero punches immediately.** "UP TO 50% OFF / Epic 4th of July Sale" lands in the first viewport with strong contrast — no ambiguity about the offer.
- **Dual-discount stacking.** The "EXTRA 30% OFF Summer Clearance" secondary module gives a logical escalation for clearance shoppers beyond the hero.
- **Category breadth is clear.** Bikes, apparel, Adidas — each section has a distinct headline with a specific discount amount, letting different shoppers self-select.
- **Seasonal framing is intact.** Red/white/blue color signals and the 4th of July branding are on-theme and visually coherent through the top two-thirds of the email.

## What's weak

- **"Flash Sale" is an empty label.** Subscribers have received 50% off 4th of July emails from DICK'S since June 27; calling today's "flash" doesn't create urgency, it creates cynicism.
- **"MOM" content block appears mid-email.** A large text element seemingly reading "MOM" appears between product categories with no apparent connection to a 4th of July flash sale — this looks like a template assembly error or content bleed from an unrelated campaign.
- **No deadline or countdown.** "Flash Sale" signals time pressure but no end date/time is visible anywhere; the urgency claim is unfalsifiable.
- **CTAs are generic.** Every "Shop Now" button leads to a category, not a curated hero product — the email functions as a department store directory, not a flash sale.
- **Sender name mismatch.** The from-name is "DICK'S | Weekend Savings Event" for what's labeled a Flash Sale — the naming is inconsistent and weakens trust at the inbox level.

## Recommendations

- 1. **Kill the "MOM" block or fix the assembly error.** Whatever is generating that element needs to be audited before the next send. It breaks narrative flow at the exact moment the email should be closing.
- 2. **Add a hard deadline.** "Flash Sale Ends Tonight at Midnight" or a visible countdown widget converts "flash" from a label into a real forcing function.
- 3. **Pick one hero product/deal.** Choose the single deepest-discounted item with a strong hero image and link it directly to that PDP. Use the grid for supporting offers, not as the lead.
- 4. **Rename the sender.** Change from "DICK'S | Weekend Savings Event" to "DICK'S Sporting Goods" — consistent naming builds recognition across cadence-heavy periods.
- 5. **Throttle the cadence signal.** The "USA Wins" email sent earlier today (July 2) was the right kind of reactive brief. This email landing on the same day as that one dilutes both.
- **Subject Alt A:** `Flash Sale: 50% off ends tonight — 4th of July`
- **Subject Alt B:** `Last chance: DICK'S 4th of July deals up to 50% off`
- **Preheader Alt A:** `Bikes, apparel, Adidas and more — shop before the sale ends.`
- **Preheader Alt B:** `Your July 4th gear is waiting. Up to 50% off select styles.`

## Technical Audit

## Technical Audit — DICK'S Sporting Goods "4th of July Flash Sale"

---

### 1. Technical Summary

The email infrastructure (SFMC/ExactTarget ESP, MSO conditionals, responsive CSS) is well-structured. However, the `application/ld+json` structured-data block contains critical authoring errors — invalid JSON syntax and unfilled template fields — that will silently break Gmail Promotions Tab annotations for this send.

---

### 2. Link & Tracking Issues

**Open pixel** — `https://app.dickssportinggoods.com/O/v610000019f22624c59c08d5df4bbcfb648/...`
Hidden via CSS only (`display:none; max-height:0px; overflow:hidden`). No `width="0" height="0"` attributes on the `<img>` element itself. CSS stripping in aggressive clients (Outlook 2003, some webmail) could cause the pixel to render visibly as a broken image sliver.

**Click-tracking** — All links route through `app.dickssportinggoods.com/T/...` (SFMC redirect). This is standard. UTM parameters are presumably appended post-redirect; cannot confirm from source alone — see §6.

**No issues with link structure itself** beyond the pixel attribute gap noted above.

---

### 3. Rendering & Accessibility

**`border-collapse:separate` on wrapper `<table>`** — Non-standard for email layouts. Intentional here (required for `border-radius` on child card tables), but it can cause unexpected 1–2px gaps between cells in Outlook 2016/2019. Acceptable if tested, but worth flagging.

**`<link rel="icon">` in `<head>`** — `https://www.dickssportinggoods.com/home/assets/icons/dsg/favicon.ico`. Email clients do not render favicons. This tag is a no-op and adds unnecessary bytes. Remove it.

**Double `font-family` on `body`** in `<style>`:
```css
body{font-family:Archivo,Arial,sans-serif;font-family:Archivo,Arial,sans-serif!important}
```
Redundant declaration. The `!important` version wins; the first can be dropped.

**Logo `<img>` alt text** — Truncated source prevents confirmation. Must verify `alt` attribute is present and descriptive (not empty) per accessibility best practice.

---

### 4. Personalization & Merge Tokens

**Critical — unfilled template fields in `application/ld+json`:**

```json
"@type": "DiscountOffer",
"description": "",
"discountCode": "",
"availabilityStarts": "2020-03-06T06:00:00-04:00",
"availabilityEnds": ""
```

- `availabilityStarts` is hardcoded to **March 6, 2020** — 6+ years stale.
- `availabilityEnds`, `description`, and `discountCode` are **empty strings** — unfilled merge fields.
- `PromotionCard.image` is also empty: `"image": ""` — the designer prompt comment is still in the production payload (see §5).

These are live in the sent email and indicate the structured-data block was not populated before send.

---

### 5. Compliance (CAN-SPAM, Unsubscribe, Authentication)

**Invalid JSON in `<script type="application/ld+json">`** — This is the highest-severity finding. The block contains JavaScript-style single-line comments, which are **not valid JSON**:

```javascript
// GIF & WEBP images are not supported and will be filtered out.
// Sample image is 538x138, 3.9 aspect ratio
// DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!
```

JSON does not support `//` comments. Any JSON parser — including Gmail's promotions-tab annotation engine — will reject the entire block. The `DiscountOffer` and `PromotionCard` schema annotations will not activate.

**Production designer comments left in send** — The comment `// DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!` shipped to recipients. This exposes internal template workflow in the raw source.

**CAN-SPAM physical address / unsubscribe** — HTML is truncated; footer not visible. Cannot confirm presence of physical mailing address and functional unsubscribe mechanism. Must verify in full source.

**Authentication headers (SPF/DKIM/DMARC)** — Not derivable from HTML. Sending domain is `e.dcsg.com`. Verify DKIM signature and DMARC alignment externally (e.g., mail-tester.com or header inspection).

---

### 6. Email-to-Site Continuity (UTM Params, Landing Page Alignment)

SFMC redirect links (`/T/...`) handle click tracking. UTM parameters are not visible in the source links themselves — they would need to be verified by following a redirect chain to confirm parameters like `utm_source=email&utm_medium=email&utm_campaign=...` are appended to the final destination URL.

**Cannot confirm UTM coverage from truncated source.** Recommend spot-checking 2–3 redirect chains in a test send before deployment.
