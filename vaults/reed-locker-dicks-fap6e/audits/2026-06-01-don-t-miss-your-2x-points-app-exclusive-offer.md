# Don't miss your 2X Points app-exclusive offer!
**Score:** 8/10 · **Type:** Email audit · **2026-06-01**
## Executive summary

- This is DICK'S second Mobile Monday email of the day — a "Final Hours" resend of the earlier "Earn 2X Points‼️ On app purchases with your ScoreCard" send, which already scored 7/10. The playbook is now familiar: launch the offer, blast the resend with countdown urgency. The creative is competent — the green ScoreCard hero with the 2X badge reads cleanly, the countdown is prominent, and the overall hierarchy is sound. But calling it fresh would be generous.
- The email inherits a real structural problem: the 2X Points offer is app-only, and anyone reading this in a desktop inbox has to context-switch to mobile before they can redeem. That friction sits at the center of the CTA without ever being resolved. The sprawling product grid below the hero — golf bags, camping tents, running shoes, casual clothing — doesn't sharpen the pitch; it dilutes it.
- Solid execution of a tired mechanic. Nothing broken, nothing inspiring.

## What's working

- **ScoreCard 2X hero is impossible to miss.** Green block, gold badge, phone mockup — the offer reads in under two seconds.
- **Countdown timer reinforces urgency.** "Final Hours: 07:59:46" is credible-looking and visible immediately below the header.
- **Subject line is tight and concrete.** 46 characters, no spam signals, "app-exclusive" adds just enough exclusivity framing.
- **Multiple specific price anchors.** $100-and-under, $120 off golf drivers, $135 off golf balls — real numbers give the browse section more pull than a generic % banner.

## What's weak

- **App-only offer creates friction for email readers.** The primary CTA is locked behind a channel switch (open app, log in, shop). No QR code, no deep link prominently displayed — just "SHOP NOW" into the web experience that doesn't redeem the points.
- **Product grid is incoherent.** Golf gear, camping equipment, athletic clothing, and footwear in the same scroll without any connective tissue. No persona is served here.
- **"Don't miss" urgency is hollow after the tenth identical resend this week.** DICK'S has cried Final Hours on clearance, flash sales, and now Mobile Monday — the phrase no longer creates real pressure for a subscriber who has seen it daily.
- **Asterisk on "2X Points\*" is never resolved above the fold.** The core offer is modified — terms/exclusions are buried — which makes it feel vaguer than the headline implies.

## Recommendations

- 1. **Add a QR code or app deep link in the hero.** The whole offer is app-exclusive. Either solve the channel switch with a scannable code, or surface a "Open in App" link directly below SHOP NOW. Without it, desktop readers bounce.
- 2. **Tighten the product grid to one lane.** The subscriber just opened a 2X Points email. Lead the scroll with the highest-margin, highest-conversion product category — don't give them golf balls and tents on the same screen.
- 3. **Retire "Don't miss" and "Final Hours" for at least a week.** The urgency language is spent. Try specificity instead: name the points ceiling ("Earn up to 500 bonus points today only") to create real stakes.
- 4. **Surface the points cap or minimum spend in the hero.** If there are conditions on the 2X offer, state them clearly — "on orders $50+" or "up to 500 points" — rather than hiding behind an asterisk. Transparency earns clicks.
- **Subject Alt A:** `Mobile Monday ends tonight — 2X Points in the app`
- **Subject Alt B:** `Last call: earn double points on every app purchase`
- **Preheader Alt A:** `Your ScoreCard earns double today only — tap to open in the app`
- **Preheader Alt B:** `2X Points on every purchase made in the DICK'S app before midnight`

## Technical Audit

## Technical Audit — DICK'S Sporting Goods "Mobile Monday / 2X Points" Email

---

### 1. Technical Summary

The email uses Epsilon/Harmony for delivery and rendering, with standard MSO conditional comments for Outlook. Three separate JSON-LD blocks in `<head>` are structurally broken and will fail Gmail Promotions tab parsing; additionally, a CSS syntax error in the MSO conditional block will degrade Outlook rendering.

---

### 2. Link & Tracking Issues

**Epsilon click-tracking present** — all outbound links route through `app.dickssportinggoods.com/T/v610000019e84d5b245a26ff7f4bbe5be68/...` with a `__dU__` personalization token appended. This is expected for the platform.

**Open pixel present** — `https://app.dickssportinggoods.com/O/v610000019e84d5b245a26ff7f4bbe5be68/09f0b6b6...` rendered as a hidden `<img>` in `td#ssl`. Standard.

**Unfilled template slot comment left in production HTML:**
```html
<!--Replace/Paste SSL Here-->
```
The tracking pixel img is already in the DOM above this comment; the comment itself is a raw workflow instruction that should have been stripped before send. Low severity but exposes internal process.

**No UTM parameters visible** on any outbound href in the provided source. If the Epsilon redirect targets do not append `utm_source`, `utm_medium`, and `utm_campaign`, campaign attribution in GA4/Adobe Analytics will be lost. Cannot confirm without inspecting redirect destinations.

---

### 3. Rendering & Accessibility

**CSS syntax error in MSO/IE conditional block** — the `div` rule has a stray `"` before the closing brace:

```css
div {background-color:inherit; font-size:0; line-height:100%; margin:0; padding:0;"}
```

The `"` makes this invalid CSS. Outlook's rendering engine will likely drop the entire rule, causing `div` elements to render with default font-size/line-height in all MSO clients. Actual impact depends on how many `div` elements are used vs. `td` elements in the layout.

**CDN image path contains `_dev` segment:**
```
https://dsg.images.harmony.epsilon.com/_phoenix/_dev/AEM/img/headers/brand-logo--dk…
```
If `_dev` is a literal path component (not an artifact of the truncation), the logo is being served from a development/staging asset path on the Epsilon CDN. This could break if the dev environment is rotated or rate-limited. Needs verification against the full, untruncated URL.

**`role="presentation"` on all layout tables** — correctly applied throughout. No issues.

**`lang="en"` on `<html>`** — present. No issues.

**Hidden tracking pixel** has no `alt` attribute in the visible source. Standard practice is `alt=""` to suppress screen-reader noise; confirm it is set in the full source.

---

### 4. Personalization & Merge Tokens

**JSON-LD `DiscountOffer` block has three unpopulated fields:**
```json
"description": "",
"discountCode": "",
"availabilityEnds": ""
```
These should be populated with the offer details or the block should be omitted if no structured discount is being surfaced.

**`availabilityStarts` is hardcoded to a stale date:**
```json
"availabilityStarts": "2020-03-06T06:00:00-04:00"
```
This is over six years in the past. This is clearly a placeholder value that was never updated — it will cause Gmail to render the offer as already expired in any Promotions tab card.

**`PromotionCard` image field is empty:**
```json
"image": ""
```
Gmail's Promotions tab card will not display without a valid image URL (538×138 recommended per the inline comment). The card will either be suppressed or render with a broken image slot.

**Editorial/designer comments left in production JSON-LD:**
```js
// GIF & WEBP images are not supported and will be filtered out.
// Sample image is 538x138, 3.9 aspect ratio
// DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!
```
**These are fatal.** JSON does not support `//` line comments. This makes all three JSON-LD blocks syntactically invalid JSON. Any parser (Gmail, Google Search) attempting to process this will throw a parse error and discard the entire structured data payload. The Gmail Promotions tab card, discount badge, and logo annotation will all fail silently.

Cannot verify without inspecting full redirect chain.
