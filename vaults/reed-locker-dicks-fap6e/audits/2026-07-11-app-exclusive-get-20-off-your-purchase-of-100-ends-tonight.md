# App exclusive! 📲 Get $20 off your purchase of $100+ (ends TONIGHT)
**Score:** 8/10 · **Type:** Email audit · **2026-07-11**
## Executive summary

- This is the **third consecutive delivery of the same $20 off $100+ app-exclusive offer** — July 10 debut, July 10 "expires TOMORROW," and now July 11 "ends TONIGHT." By any honest count, it's also the tenth DICK'S email in roughly 48 hours. The hero is technically competent: big green-on-dark "$20 OFF" block, clear minimum spend, visible CTA button. But any subscriber still paying attention has already seen this creative twice, and the only thing separating today's send from yesterday's is a clock update.
- The secondary content below the fold carries real deal weight — up to 60% off running shoes, Oakley, Walter Hagen golf shirts, and assorted clearance — and a price-sensitive shopper could find genuine value here. That's the strongest case for the click. Against it: the app-exclusive mechanic creates real friction, and a mid-page "SPORTS MOM" section is jarring in mid-July, landing two months after Mother's Day with no obvious seasonal anchor.
- Bottom line: technically clean execution on a strategically depleted concept. The urgency is real (it genuinely does end tonight), but DICK'S has burned the "same offer, new deadline" escalation ladder dry. This email exists because it has to, not because it earned its place in the inbox.

## What's working

- **Hero clarity is strong.** "$20 OFF / YOUR ORDER OF $100+" reads instantly at a glance on both desktop and mobile widths.
- **Legitimate urgency.** "Ends TONIGHT" is the final honest beat in a three-step countdown sequence — at this point the deadline is actually real.
- **Secondary deal depth.** 60% off running shoes, golf shirts, and select clearance give deal-seekers multiple exit ramps beyond the hero offer.
- **No render bugs.** Layout is clean, no broken images, no overlapping text.
- **Brand identity is consistent.** DICK'S logo, color palette, and deal format are exactly what subscribers expect.

## What's weak

- **Creative is a reprise of a reprise.** The July 10 "expires TOMORROW" send (6/10 in brand history) already flagged this exact fatigue problem; July 11 compounds it.
- **App-exclusive friction goes unaddressed.** The hero announces an app-exclusive discount but there's no visible "download the app" nudge or QR code for subscribers who haven't installed it yet.
- **"SPORTS MOM" section has no seasonal logic on July 11.** Mother's Day was May; nothing in the email anchors this to a current campaign. It reads as a template leftover.
- **Zero personalization.** No name, no sport, no category signal — just a blast to the full list.
- **Subject line is 66 characters** — well over mobile's ~50-char cutoff, so the "ends TONIGHT" deadline will clip on most phones where it matters most.

## Recommendations

- 1. **Compress the subject to force "ends TONIGHT" into mobile view.** The current subject buries the strongest signal past truncation. Drop "your purchase of" and the emoji to save space.
- **Subject Alt A:** `App exclusive: $20 off $100+ — ends TONIGHT`
- **Subject Alt B:** `Tonight only: $20 off in the app (min $100)`
- **Preheader Alt A:** `Shop running shoes, golf gear + 60% off clearance — only in the DICK'S app.`
- **Preheader Alt B:** `Your last chance — $20 off expires at midnight. Open the app to redeem.`
- 2. **Add a visible app CTA for non-app subscribers.** A secondary "Download the App" button or QR code immediately under the hero converts this from a reward for existing app users into an acquisition moment.
- 3. **Pull the "SPORTS MOM" block.** Replace with a category that's seasonally coherent for mid-July — back-to-school gear, summer sports camp equipment, or outdoor recreation. The current block reads like a scheduling error.
- 4. **Enforce a send cadence cap.** Ten emails in 48 hours — including three with the same offer — is the single biggest deliverability and unsubscribe risk here. Even at a tactical level, collapsing the three $20 off sends into one well-timed single send on the final day would have performed better.

### 5a. JSON-LD Structured Data — Critical Failures

The `<script type="application/ld+json">` block contains **multiple hard failures**:

**1. JavaScript comments inside JSON (invalid syntax):**
```json
{ // GIF & WEBP images are not supported and will be filtered out.
  // Sample image is 538x138, 3.9 aspect ratio
  // DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!
  "@type": "PromotionCard",
  "image": ""
}
```
JSON does not support `//` comments. This will cause the entire JSON-LD block to **fail parsing silently** — Gmail Promotions tab annotations will not render, and any rich snippet eligibility is lost.

**2. Stale `availabilityStarts` date — 6 years old:**
```json
"availabilityStarts": "2020-03-06T06:00:00-04:00"
```
This is clearly a template default that was never replaced with the current send date.

**3. Non-standard Schema.org types:**
- `"@type": "DiscountOffer"` — not a valid Schema.org type (correct type: `Offer`)
- `"@type": "PromotionCard"` — not a standard Schema.org type; Gmail's Promotions schema expects `PromotionCard` under the `http://schema.googleapis.com/` context, not `http://schema.org/`. The `@context` is wrong.

**4. Empty required fields:**
```json
"availabilityEnds": ""   // offer end time missing
"discountCode": ""       // discount code missing
"image": ""              // PromotionCard image missing
"description": ""        // offer description missing
```
All four are empty strings, not populated placeholders.
