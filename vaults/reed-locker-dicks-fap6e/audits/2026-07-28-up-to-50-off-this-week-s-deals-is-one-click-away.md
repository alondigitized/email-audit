# Up to 50% off this week's DEALS is one click away 👉
**Score:** 8/10 · **Type:** Email audit · **2026-07-28**
## Executive summary

- This is the same "UP TO 50%" paddleboard-at-sunset hero DICK'S ran on 2026-07-26 ("Up to 50% off is available in this week's deals," 8.00/10), which was itself a rerun of the 2026-07-24 send — this is now the third consecutive appearance of this exact visual and headline treatment. The subject swaps in "is one click away 👉" as a thin urgency hook, but nothing else has moved: same hero crop, same green SHOP NOW buttons, same 10-offer product dump below the fold.
- Execution is clean — no render bugs, the hero offer is unmissable, and ScoreCard membership is surfaced up top. But this send is pure volume, not strategy: 10 disconnected offers (clothing, golf, kayaks, gloves, fan shop, Peloton shoes, clearance) crammed into one email with zero curation, plus a second "UP TO 70% OFF" red block near the bottom competing with the hero for primary-offer status.
- Judgement: solid production quality dragging down a fatigued, uncurated creative. This is a send that will perform on autopilot with existing engaged subscribers and get ignored by everyone else.

## What's working

- Hero "UP TO 50% OFF" block is bold, high-contrast, and unmissable above the fold.
- Green SHOP NOW CTA buttons have strong contrast and appear consistently throughout.
- Category nav bar (Men's/Women's/Kids'/Shoes/Golf/Summer Shop) gives fast browse paths right under the hero.
- ScoreCard logo and points balance are visible at the very top for member recognition.
- Zero visible render bugs — all images load cleanly, no overlapping text or broken layout.

## What's weak

- Third consecutive use of the identical paddleboard-sunset hero (2026-07-24, 2026-07-26, now this send) — no creative differentiation at all.
- 10 unrelated offers stacked in one email (clothing, golf, kayaks, gloves, fan shop, Peloton, clearance) flattens hierarchy into a catalog dump rather than a curated pick.
- A second bold "UP TO 70% OFF" red block near the bottom duplicates the hero's exact visual language, diluting which offer is actually primary.
- No credible deadline — the only urgency cue is buried fine print ("Valid online only for a limited time. While quantities last.").
- Subject's "is one click away 👉" is filler urgency copy, not a concrete hook like the "Nike Deal Days" send used.

## Recommendations

- 1. Retire the paddleboard hero — reusing the identical image and headline block three sends in a row is the single biggest drag here; a fresh campaign identity (like "Nike Deal Days") outperformed this exact creative pattern earlier in the stretch.
- 2. Cut the offer count from 10 to 3-4 and let the rest live on a landing page — this send reads as a sitewide clearance table, not a curated pick.
- 3. Replace the vague "limited time" fine print with a real date ("Ends Sunday 8/2") to justify the frequency of these blasts.
- 4. Move the ScoreCard/loyalty angle into the subject line — it's a real differentiator DICK'S has used well before (2026-07-27, 9.00/10) and is buried here as just a header logo.

- **Preheader Alt A:** `10 deals, one cart — golf, kayaks, cleats, and more`

# Technical Audit — DICK'S Sporting Goods "Up to 50% off" Email

## 1. Technical Summary
Email is built on Epsilon Harmony ESP infrastructure with standard MSO/mobile responsive markup; QA shows a 43% pass rate driven by a broken unsubscribe link, missing authentication/compliance headers, and pervasive missing alt text.

## 2. Link & Tracking Issues
- **Broken unsubscribe redirect (confirmed FAIL):** `https://app.dickssportinggoods.com/U/v610000019fa836a068913689f4bbe5be50/7e3d52bd211e469f0000021ef3a0bcff` resolves to `/pc/Error/Error?aspxerrorpath=/pc/subscription` — the preference-center endpoint is misconfigured or the path was moved.
- All tracked links route through the Epsilon Harmony redirect domain (`app.dickssportinggoods.com/T/...`, `/O/...`, `/U/...`) with opaque tokenized paths and a `__dU__` deep-link parameter on the header logo link — consistent with expected Harmony link-wrapping, no anomaly there.
- QA probed 12 of 62 total links (material/high-click-likelihood links); footer/social links were deprioritized. Given the truncated source, CTA destination URLs beyond the header logo were not visible for direct review.

## 3. Rendering & Accessibility
- **11 images missing `alt` text**, including content-bearing product imagery (`clothes-shoes.png`, `kayak.jpg`, `gloves.png`, `fan-shop.png`, `peloton.jpg`, `mapbreak.gif`) and footer trust/value-prop icons (`icon-vc-sms.png`, `icon-value-sportsmatter--light.png`, `icon-vc-bpg.png`, `icon-vc-favorite.png`, `icon-location-2025.png`). This fails WCAG 1.1.1 and degrades screen-reader and image-blocked rendering.
- The tracking/open pixel (`.../O/.../7e3d52bd...`) also lacks `alt`, but this is expected/acceptable for a hidden 0×0 tracking image.
- Mobile breakpoint rules (`@media screen and (max-width:480px)`) and Outlook conditional comments (`<!--[if (gte mso 9)|(IE)]-->`) are present and correctly scoped — no issues found here.
- Web font (`Archivo`) is loaded via `@font-face` inside a `@media screen` guard with `font-display:swap` and an Arial/sans-serif fallback stack on `body` — correct defensive pattern for Outlook/non-webfont clients.

## 4. Personalization & Merge Tokens
- The `application/ld+json` block contains **unresolved/empty template fields**: `"description": ""`, `"discountCode": ""`, `"availabilityEnds": ""`, and `"image": ""` (PromotionCard). These appear to be merge tokens that were never populated for this send.
- **The JSON-LD block is invalid JSON** — it contains `//` line comments (`// GIF & WEBP images are not supported...`, `// DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!`), which is not legal JSON syntax. Any strict JSON-LD parser (including Google's structured data tooling) will fail to parse this block entirely.
- `"availabilityStarts": "2020-03-06T06:00:00-04:00"` is a stale hardcoded date carried over from a template and inconsistent with the campaign's actual send date (image paths reference `2026-0728`), indicating this merge field is not being refreshed per-campaign.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Unsubscribe link is broken** (see §2) — this is a CAN-SPAM compliance risk since the required functioning opt-out mechanism is not reachable.
- `List-Unsubscribe` header not detected — one-click unsubscribe visibility to mailbox providers cannot be confirmed (may be a relay/capture artifact rather than a true absence).
- `List-Unsubscribe-Post` header (RFC 8058) not detected — if genuinely absent, Gmail/Yahoo one-click unsubscribe compliance requirements (enforced since Feb 2024) would not be met.
- `Authentication-Results` header not detected — SPF/DKIM/DMARC pass/fail status could not be verified via this relay.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- Cannot fully assess: the truncated HTML source only exposes the header logo link, SSL/open pixel, and unsubscribe link — CTA/product-tile destination URLs (post-redirect) were not present in the provided source to check for UTM parameters or landing-page alignment.
- All observed links funnel through the Epsilon Harmony tracking domain rather than direct-to-site URLs, which is standard for this ESP and not itself an issue, but means UTM/landing-page validation must happen post-redirect (not verifiable from source alone).

## 7. Recommendations
1. Fix the unsubscribe endpoint immediately — `/pc/subscription` errors out; this is both a broken-link and CAN-SPAM compliance issue.
2. Remove the `//` comments from the `application/ld+json` block or convert them to valid JSON — as written, the structured data block will fail parsing.
3. Populate or remove empty JSON-LD merge fields (`description`, `discountCode`, `availabilityEnds`, `image`) and correct the stale `availabilityStarts` date.
4. Add descriptive `alt` text to all 11 flagged content/icon images.
5. Confirm with the sending platform/relay whether `List-Unsubscribe`, `List-Unsubscribe-Post`, and `Authentication-Results` are genuinely absent or simply not captured by the AgentMail relay — verify directly against raw SMTP headers if possible.
