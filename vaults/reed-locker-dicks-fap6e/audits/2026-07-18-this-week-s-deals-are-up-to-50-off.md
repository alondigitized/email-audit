# This week's deals are up to 50% off
**Score:** 5/10 · **Type:** Email audit · **2026-07-18**
## Executive summary

- This is the sixth "This Week's Deals / up to 50% off" email from DICK'S in roughly four days — and at this point it's a carbon copy. The dark hero badge with "UP TO 50% OFF" in white, the category browse rail, the multi-sport product grid — it's the same template the July 15 and July 16 sends used, and it was stale by then. The subject line ("This week's deals are up to 50% off") is barely distinguishable from "Up to 50% off is available now with this week's deals" (July 15, 5/10) or "Good news: up to 50% off the best deals of the week is waiting — shop now" (July 16, 8/10). The only direction this cadence is headed is unsubscribes.
- The creative itself is competent — the 50% badge reads cleanly, each category section (Clothing, Outerwear, Golf, Team Sports, Fitness) has a visible CTA — but the execution is buried under extreme fatigue. Nothing about this send differentiates today from yesterday. There's no escalating hook, no deadline, no new angle.
- The brand is burning down subscriber attention fast. A subscriber who opened the July 16 "Good news" version (8/10) got identical value from this one, and got nothing new. That's a bad trade.

## What's working

- **50% badge is immediately legible** — large white type on dark background, hero reads in under a second.
- **Category sectioning is clear** — Clothing & Shoes, Outerwear, Golf Equipment, Team Sports, Fitness Equipment, Pro Shop each get their own module with a CTA button.
- **Product photography is clean** — lifestyle shots are consistent in quality and render without gaps or broken images.
- **No layout bugs visible** — the email renders cleanly top to bottom, no overlap or truncation artifacts.

## What's weak

- **Cadence fatigue is the dominant problem** — this is the sixth near-identical 50%-off send; a real subscriber has seen this creative so many times it's invisible.
- **No deadline or urgency mechanism** — "this week's deals" is a soft window with no countdown, end date, or "ends Sunday" hook.
- **Subject is structurally identical to three prior sends** — opens will continue to erode; the inbox is pattern-matching this as noise.
- **No personalization or segmentation visible** — same broad category dump sent to everyone; no sport-specific hook that would make a runner or golfer feel targeted.
- **Hero says nothing new** — same dark-background 50%-off badge that appeared on July 15 and July 16; there is no creative evolution.

## Recommendations

- 1. **Kill the cadence or differentiate hard** — sending the same 50%-off template daily destroys open rates faster than any creative fix can recover. Either skip a day or force a completely different angle (e.g., a single-sport focus, a "last chance" final-day frame, or a specific product spotlight).
- 2. **Add a real deadline** — "Ends Sunday 11:59 PM" in the hero and subject converts far better than "this week." Make the urgency mechanical, not vague.
- 3. **Rotate the hero visual** — the dark badge template is recognizable as "another DICK'S deal email"; a bright, sport-specific hero (e.g., a runner, a golfer) would reset visual attention.
- 4. **Segment by category** — readers who clicked Golf last time should get a golf-lead version. The category grid buried below the fold only works if someone cared enough to scroll.

- **Preheader Alt A:** `Your category's deals, curated. Tap to see what made the cut this week.`

### 2. Link & Tracking Issues

**Open-tracking pixel — CSS-only hiding, no dimensional attributes**

```html
<img src='https://app.dickssportinggoods.com/O/v610000019f76e00b95a3760ff4bbe5c898/...'
     style="display:none; max-height: 0px; font-size: 0px; overflow: hidden; mso-hide: all"/>
```

No `width="1" height="1"` HTML attributes are set. CSS is stripped by several clients (Yahoo, some Outlook versions); without dimensional attributes the pixel may render as a broken-image icon in those environments. Fix: add `width="1" height="1"` as HTML attributes.

**No UTM parameters visible on click-tracked links**

The tracked click URL (`app.dickssportinggoods.com/T/...`) contains no `utm_source`, `utm_medium`, or `utm_campaign` parameters in the visible source. If the redirect server does not append UTMs, analytics attribution will be lost. Confirm in the redirect chain or flag for ESP configuration review.

### 3. Rendering & Accessibility

**Truncated image `src` attribute on logo**

```html
<img id="logo" src="https://s7d6.scene7.com/is/image/DSGAEMSites/brand-logo--dks-2?wid=248&hei=…
```

The `hei` query parameter is cut off. Whether this is truncation in the source provided or a genuine send defect is unverifiable from this extract — confirm against the live deployed HTML. A broken `src` will render a missing image in clients that do not cache prior sends.

**`alt` text on logo not confirmed**

The `<img id="logo">` tag is cut off before the `alt` attribute appears. Verify `alt` is present and non-empty (e.g., `alt="DICK'S Sporting Goods"`); missing `alt` breaks screen readers and renders blank in image-off clients.

**Outlook MSO conditionals — present and correct**

### 6. Email-to-Site Continuity

**JSON-LD structured data is syntactically invalid — Gmail annotations will not render**

The `<script type="application/ld+json">` block contains JavaScript-style single-line comments, which are not legal JSON:

```js
{ // GIF & WEBP images are not supported and will be filtered out.
  // Sample image is 538x138, 3.9 aspect ratio
  "@context": "http://schema.org/",
  "@type": "PromotionCard",
  // DESIGNER, ADD YOUR PROMO IMAGE URL BELOW!
  "image": ""
}
```

JSON has no comment syntax. Any JSON parser (including Gmail's structured data extractor) will reject the entire `<script>` block on encountering `//`. This means Gmail Promotions tab annotations (deal badge, logo, offer card) will not fire for this send regardless of whether fields were filled in.

**`http://` schema.org context vs `https://`**

`"@context": "http://schema.org/"` — schema.org redirects HTTP to HTTPS, but the canonical form in Google's structured data documentation is `https://schema.org/`. Low severity but worth standardizing.

**UTM continuity**

Covered in Section 2. If UTMs are absent end-to-end, GA4 / Adobe Analytics will attribute site sessions from this email to `(direct)` rather than the campaign, breaking ROI measurement.
