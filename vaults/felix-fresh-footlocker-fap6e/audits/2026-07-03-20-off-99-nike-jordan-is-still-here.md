# 20% off $99 Nike & Jordan is still here!
**Score:** 10/10 · **Type:** Email audit · **2026-07-03**
## Executive summary

- This is the day-after extension send for the July 2 debut that scored 9/10 here. Foot Locker swapped "starts today!" for "is still here!" and added "through the weekend" in the body — everything else is a pixel-for-pixel copy: the same hero shoe in the same dark burst graphic, the same oversized "20% OFF $99" typography, the same SAVES5 code, the same CURATED FOR YOU product grid. The offer itself is still tight and the July 4th weekend framing is natural, but the creative gives any subscriber who opened and didn't convert on July 2 exactly zero new reasons to act today.
- The geographic personalization is a quiet win — showing a specific Pasadena store address in the locator signals real CRM work, not a mass blast. The "Not Many Left" availability tag on the Nike Air Diamond is the strongest individual pull in the product grid. These details keep the email from feeling lazy even when the hero creative is recycled.
- Judgement: this send earns its place in the sequence — a 48-hour reminder on a strong Nike/Jordan offer is defensible — but it needed a new hero product, a "what's moving fast this weekend" module, or at minimum a different shoe. Without new visual content, it's a reminder dressed as a fresh send.

## What's working

- Hero visual hierarchy still fires immediately: oversized "20% OFF $99" over the burst graphic with the shoe is the strongest above-fold execution in Foot Locker's recent run
- Offer mechanics are fully visible above the fold — discount, spend threshold ($99+), code (SAVES5), and brand (Nike & Jordan) without scrolling
- "Through the weekend" body copy lands July 4th urgency without resorting to INDEPENDENCE DAY ALL-CAPS shouting
- Pasadena store address in the locator section is genuine geographic personalization — a trust signal a generic blast can't fake
- "Not Many Left" label on the Nike Air Diamond creates legitimate scarcity without manufactured pressure

## What's weak

- Creative is a direct copy of July 2's debut — same shoe, same layout, same code — giving previous openers nothing new to act on
- "CURATED FOR YOU" grid includes three adidas products against a Nike & Jordan subject line, breaking the brand-specific promise the moment the eye moves below the fold
- "SHOP THE SALE" CTA is generic — a shopper interested in Jordan doesn't know what page they're landing on or whether Jordan is even on sale at that link
- "is still here!" implies expiry without committing to a date; "Ends Sunday" would do far more persuasive work
- The top promo bar ("20% OFF $99+ | USE CODE: SAVES5 | SHOP SALE") is the likely preview text in most inboxes, which repeats the subject offer rather than adding new information

## Recommendations

- 1. **New hero product or a "selling fast" module** — the most impactful single change. July 2 introduced the offer; July 3 needs to make the case with a different shoe, a Jordan-only spotlight, or a grid of the top-5 units moving this weekend. Same image as 24 hours ago is zero new persuasion.
- 2. **Remove adidas from the CURATED FOR YOU grid** — every Nike & Jordan opener who scrolls into adidas product has to reorient. Replace with Jordan colorways or clearly separate it as "Also on sale."
- 3. **Sharpen the CTA** — "Shop Nike & Jordan Faves" or "Find My Jordan" maintains the brand promise through to the click; "SHOP THE SALE" throws it away.
- 4. **Name the deadline in the body** — replace "through the weekend" with "Offer ends Sunday, July 6" to convert fence-sitters doing deal math.
- 5. **Write a dedicated preheader** — the hidden preheader slot should add inbox-new information, not echo the promo bar.
- **Subject Alt A:** `Nike & Jordan 20% off — ends Sunday`
- **Subject Alt B:** `Code SAVES5 still works — grab your Jordan pair`
- **Preheader Alt A:** `Offer ends July 6 — top Nike & Jordan picks below $200`
- **Preheader Alt B:** `Use SAVES5 at checkout on select Nike & Jordan styles`

### 1. Technical Summary

The email has one confirmed deliverability failure (missing plain-text fallback), one CSS selector typo affecting mobile layout, and an incomplete Movable Ink personalization token. Compliance headers were not captured by the AgentMail relay, leaving SPF/DKIM status unverifiable.

---

### 2. Link & Tracking Issues

**Incomplete `mi_u` parameter on Movable Ink render pixel**
```
https://mi.footlocker.com/p/rp/fa53ea8871ffa0e2.png?mi_u=
```
`mi_u` is present but empty. If this is a subscriber-ID merge token that failed to resolve, the render-time personalization call will fail silently or return a fallback/broken image. Compare to the open pixel which carries a full value: `mi_u=9a78343cafd910a7eb199ae4b17875b7`.

**No issues with Bluecore redirect tracking** — `trk.bc.footlocker.com` wraps appear well-formed.

---

### 3. Rendering & Accessibility

**CSS selector typo — mobile column widths**
```css
/* In the <style> block */
.fluid-row .col-9, .md-fluid-row .col-8 { width: 74.25% !important; }
```
The second selector targets `.md-fluid-row .col-8` instead of `.md-fluid-row .col-9`. Effect: on mobile, `.md-fluid-row .col-8` is overridden to 74.25% (should be 66%), and `.md-fluid-row .col-9` gets no mobile width override at all. Any 9-column responsive block inside an `md-fluid-row` will break at <600px.

**Three images missing `alt` text (QA confirmed)**

| Image | URL |
|---|---|
| `ho.gif` | `https://trk.bc.footlocker.com/.../ho.gif` |
| `o.gif` | `https://mi.footlocker.com/p/up/.../o.gif` |
| `fa53ea8871ffa0e2.png` | `https://mi.footlocker.com/p/rp/fa53ea8871ffa0e2.png?mi_u=` |

The first two are open-tracking pixels and conventionally carry `alt=""`, but the value must be explicitly set — omitting the attribute causes screen readers to announce the filename. The third is the broken-token render pixel above.

**External font dependency**
```html
<link rel="stylesheet" href="https://partner-fonts.bluecore.com/footlocker/footlocker_fonts_1776712244.css">
```
Web fonts are blocked in Gmail (all clients) and Outlook (desktop). No issue if a system-font stack fallback is defined in the CSS — but worth confirming the stack degrades gracefully.
