### 3. Rendering & Accessibility

**`<html>` tag missing `lang` attribute.**
`<html>` has no `lang="en"` declaration. Screen readers will not announce the document language correctly. WCAG 3.1.1 failure.

**`-webkit-text-size-adjust: none !important` applied globally on mobile.**
```css
div,p,a,li,span,td { -webkit-text-size-adjust:none !important; }
```
This disables user-controlled text scaling on iOS. Violates WCAG 1.4.4 (Resize Text). Replace with `100%`, not `none`.

**CSS selector bug in fluid grid — `.md-fluid-row .col-9` is never defined.**
```css
.fluid-row .col-9,.md-fluid-row .col-8 { width: 74.25% !important; }
```
The second selector targets `.md-fluid-row .col-8` (a duplicate), not `.md-fluid-row .col-9`. Any 9-column element in a `md-fluid-row` receives no width override and will render at its inherited width. Likely a copy-paste error in the Bluecore template.

**External font loaded via blocking `<link>` tag.**
```html
<link rel="stylesheet" href="https://partner-fonts.bluecore.com/footlocker/footlocker_fonts_1776712244.css">
```
If `partner-fonts.bluecore.com` is unavailable or slow, font load fails silently and falls back to system fonts — no font-display fallback is possible in email context. Gmail and some clients strip `<link>` tags entirely, meaning this font will not render in Gmail web.

**Preheader technique is correct** — `display:none; max-height:0px; overflow:hidden` is standard and functional. No issue.
