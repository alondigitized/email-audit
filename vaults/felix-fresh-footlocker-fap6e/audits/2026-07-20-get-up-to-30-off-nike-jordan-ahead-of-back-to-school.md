### 3. Rendering & Accessibility

**Bug — CSS selector typo (confirmed):**
```css
.fluid-row .col-9, .md-fluid-row .col-8 { width: 74.25% !important; }
```
The `.md-fluid-row` side of this rule targets `.col-8` instead of `.col-9`. Any 9-column `md-fluid-row` layout will fall through to the wrong width rule. This is a copy-paste error in the responsive grid definition.

**Bug — external font link will fail silently in Outlook and many corporate clients:**
```html
<link rel="stylesheet" href="https://partner-fonts.bluecore.com/footlocker/footlocker_fonts_1776712244.css">
```
`<link>` stylesheet loading is stripped by Gmail (web), Outlook (all versions), and Apple Mail with remote content blocked. Font will fall back to client default — no crash, but typography degrades silently. Standard mitigation is inlining the `@font-face` declarations in a `<style>` block.

**`-webkit-text-size-adjust: none` applied too broadly:**
```css
div,p,a,li,span,td { -webkit-text-size-adjust: none !important; }
```
`none` prevents users from adjusting text size at all, including via OS accessibility settings. The correct value is `100%`, which prevents auto-inflate while preserving user control. This is an accessibility regression, particularly for low-vision users.

**`format-detection` meta only suppresses phone numbers:**
```html
<meta name="format-detection" content="telephone=no">
```
Email addresses and street addresses (visible in footers of most retail emails) will still be auto-linked by iOS Mail. Add `content="telephone=no, date=no, address=no, email=no"` if footer contains those fields.

**No dark mode `@media (prefers-color-scheme: dark)` rules present.** White `#ffffff` backgrounds will invert in Apple Mail dark mode, potentially making black text on white backgrounds render as white text on black — confirm in Litmus/Email on Acid dark mode previews before send.
