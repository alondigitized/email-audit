# You've still got time to get 20% off $99 Nike & Jordan!
**Score:** 7/10 · **Type:** Email audit · **2026-07-04**
## Executive summary

- This is the third consecutive Foot Locker send built around the same 20% off $99 Nike & Jordan offer — July 2 debut (9/10), July 3 extension (10/10), and now July 4 with a subject line shift to urgency-close mode: "You've still got time." The creative is effectively pixel-for-pixel identical to the July 3 send. Same navy sneaker hero, same fireworks burst motif, same "20% OFF $99" in giant type, same code SAVE$99, same "LOOKS YOU'LL LOVE" product grid below. The only meaningful change is the subject line — which does what it needs to do on July 4: signal that the clock is running out.
- The problem isn't the email itself — it's the third-send fatigue. By this point a subscriber has already seen this exact layout twice in 48 hours. The urgency framing in the subject is the one fresh lever, but the body doesn't reinforce it: there's no "ends tonight," no countdown, no explicit deadline in the hero. The code is still showing as SAVE$99 in the offer bar at top, which conflicts with the body copy that says "use code SAVE$99" — visually redundant but not broken.
- Solid, competent execution of a known-performing template. The real risk here is that this is the send that breaks the streak — subscribers who already converted on July 2 or 3 have no reason to click, and those who didn't are being pushed with urgency copy that the creative doesn't back up with a hard deadline.

- Third identical layout in three days; subscribers who've already seen this twice will feel déjà vu before the scroll.
- "Nike & Jordan Faves" headline is softer than the offer — the coupon code is the hook, not the editorial label.
- App download and Sign Up for SMS callouts in the footer add visual clutter on a send that should be laser-focused on close.
- Star ratings on the product grid are tiny and barely readable at this render size.

- 1. **Add a hard deadline in the hero.** "Ends tonight at midnight" or "Offer ends July 4" directly under the offer — this is the single highest-leverage fix. The subject primes urgency; the body must close it.
- 2. **Refresh at least one hero product or headline.** Swapping the sneaker image or the "Nike & Jordan Faves" label for something new (e.g., a limited July 4 colorway) gives returning eyes a reason to re-engage.
- 3. **Remove the footer app/SMS clutters or move them below the fold.** On a deadline-urgency send, every element below the CTA should accelerate the click, not branch it.

### 3. Rendering & Accessibility

**[HIGH] CSS selector typo — col-9 mis-mapped on `.md-fluid-row`**

```css
.fluid-row .col-9, .md-fluid-row .col-8 { width: 74.25% !important; }
```

The second selector is `.md-fluid-row .col-8` but should be `.md-fluid-row .col-9`. On any layout using `.md-fluid-row`, the 9-column cell will not receive 74.25% width, and the col-8 cell will be double-targeted. This is a broken responsive layout on tablets.

---

**[MEDIUM] External `<link>` stylesheet will be stripped by Gmail and most webmail clients**

```html
<link rel="stylesheet" href="https://partner-fonts.bluecore.com/footlocker/footlocker_fonts_1776712244.css">
```

Gmail and Yahoo strip `<head>` content including `<link>` tags. The font load will silently fail for a majority of recipients. Custom fonts should either be inlined via `@font-face` inside a `<style>` block, or the design must be validated with system-font fallbacks.

---

**[MEDIUM] Missing `lang` attribute on `<html>` element**

```html
<html>
```

No `lang="en"` (or equivalent). Screen readers cannot determine the document language, violating WCAG 2.1 SC 3.1.1. Required for accessibility compliance.

---

**[LOW] `-webkit-text-size-adjust: none` instead of `100%`**

```css
div,p,a,li,span,td { -webkit-text-size-adjust: none !important; }
```

`none` disables user-controlled text scaling entirely, which breaks accessibility for users who rely on browser/OS font size settings. Best practice is `100%`, which prevents automatic scaling while preserving manual user control.

---

**[LOW] Viewport meta missing `initial-scale`**

```html
<meta name="viewport" content="width=device-width">
```

Standard practice is `content="width=device-width, initial-scale=1"`. Some mobile clients may render at reduced scale without it.
