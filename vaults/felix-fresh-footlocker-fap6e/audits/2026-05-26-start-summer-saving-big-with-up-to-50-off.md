# Start summer saving big with up to 50% off.
**Score:** 9/10 · **Type:** Email audit · **2026-05-26**
## Executive summary

- This is the fourth creative execution of the same Summer Kickoff Sale — and it shows. The pool-party hero, the oversized yellow "50% OFF," the Nike Air Max floating on a blue background: all of it was fresh on May 21, tolerable on May 22, starting to wear by May 24, and now fully stale. The email is technically competent — clean render, correct hierarchy, visible FLX Rewards section — but it is doing zero incremental work for the subscriber. Nothing in the hero, headline, or CTA has changed in any meaningful way.
- The product grid underneath is the email's strongest element and goes largely underserved. Six products with real sale prices and star ratings give a subscriber something to act on, but the hero creative buries them behind a sale mechanic they've now seen four times.
- The send is punching below its weight. At this point in the cadence Foot Locker should be closing urgency (countdown, "ends tonight," final-hours framing) or rotating to a fresh creative angle — a specific brand spotlight, a product drop, last-chance inventory. Instead it's re-airing the launch email.

## What's working

- Product grid executes well — six SKUs with real sale prices, strikethrough originals, and star ratings give actual shopping signal.
- "SHOP THE SALE" is a clean, unambiguous CTA with good button contrast.
- FLX Rewards footer section gives members a reason to feel acknowledged.
- Render is clean — no broken images, no layout issues, no overlapping text.

## What's weak

- Hero creative is identical to May 21 and May 22 sends — full creative fatigue after four identical executions.
- No urgency mechanism anywhere — no countdown, no "ends Sunday," no inventory signal — on a sale that has now been running six days.
- Subject line ("Start summer saving big with up to 50% off.") adds nothing new; it's a slightly rephrased version of "Up to 50% off starts today!" and "The savings are heating up."
- Preview text appears to be leaking a utility/view-in-browser link rather than real marketing copy — wasted inbox real estate.
- No brand differentiation in the hero — the Nike Air Max floatie is generic and could be any athletic retailer's summer send.

## Recommendations

- 1. **Add a hard deadline to the hero.** "Sale ends Sunday" or a countdown badge on the 50% OFF treatment immediately changes this from a passive browse-when-you-feel-like-it email to an action signal. This is the single highest-lift change.
- 2. **Rotate the hero creative.** Swap the pool floatie for a specific franchise: "Jordan Week within the sale," "Birkenstock markdowns," or "Nike Dunks from $45." The product grid knows what's selling — pull one winner into the hero.
- 3. **Give the product grid more prominence.** Move the six-product grid above the fold or reduce hero height so products appear earlier on mobile scroll.
- 4. **Write a real preheader.** The preview text is leaking junk. Even "Nike Dunks, Birks, Reeboks — all on sale now" outperforms whatever is rendering there today.

## Technical Audit — Foot Locker "Start summer saving big" (2026-05-27)

### 1. Technical Summary

Bluecore-rendered promotional email with responsive table layout, dynamic product recommendation widgets, and an external font dependency. One confirmed CSS selector bug affects mobile column rendering; remaining issues are infrastructure/compliance gaps confirmable from available source.

---

### 2. Link & Tracking Issues

**External font stylesheet — single point of failure**
```
<link rel="stylesheet" href="https://partner-fonts.bluecore.com/footlocker/footlocker_fonts_1776712244.css">
```
This is a blocking external resource in `<head>`. If `partner-fonts.bluecore.com` is unreachable at render time, the fallback font stack silently takes over. No `<link rel="preload">` or timeout guard is present. Low risk in practice but worth noting for deliverability audits.

**Click-tracking domain**
All links route through `bc.footlocker.com` (Bluecore's click-tracking subdomain). Confirmable from the From header. UTM parameter coverage cannot be verified from the truncated source — see §6.

---

### 3. Rendering & Accessibility

**CSS selector bug — col-9 mobile width**
```css
.fluid-row .col-9, .md-fluid-row .col-8 { width: 74.25% !important; }
```
The second selector is `.md-fluid-row .col-8` instead of `.md-fluid-row .col-9`. This is a copy-paste error: `col-9` inside an `md-fluid-row` will receive no explicit mobile width, potentially collapsing or inheriting `100%` from the `#content-table` rule above it. If any `md-fluid-row` uses 9-column layouts, those cells will render incorrectly on mobile.

**Missing `lang` attribute**
```html
<html>
```
No `lang="en"` on the root element. Screen readers (JAWS, NVDA) and some translation engines rely on this for language detection. WCAG 2.1 §3.1.1 failure.

**`-webkit-text-size-adjust: none` on all elements**
```css
div, p, a, li, span, td { -webkit-text-size-adjust: none !important; }
```
Applying `none` (rather than `100%`) globally disables iOS font scaling entirely, including for users with accessibility zoom enabled. Should be `100%` to preserve automatic size adjustment while preventing unwanted scaling.

**Image alt text** — not verifiable from truncated source. Flag for full-source review; Bluecore product widgets frequently emit `alt=""` on product images.

---

### 4. Personalization & Merge Tokens

Two Bluecore recommendation widgets are present:
- `widget_7f0685d76ce802a8ea7df55efac0ec33` (footer/legal text region based on CSS — small font, 11px)
- `widget_ff2afdccb9b4b2ae4c549f2b135d888b` (product grid with name/gender_age/prod_color/price/rating_stars slots)

No unresolved Bluecore merge token syntax (e.g. `{{first_name}}`) is visible in the truncated source — consistent with Bluecore rendering tokens server-side before delivery.

**Fixed-height product attribute cells** (mobile overrides):
```css
#widget_ff2afdccb9b4b2ae4c549f2b135d888b .name { height: 24px !important; }
#widget_ff2afdccb9b4b2ae4c549f2b135d888b .gender_age { height: 25px !important; }
```
These heights have `min-height` overrides on the `<p>` inside, which is correct. However, if a product name exceeds one line at 11–12px on a narrow mobile screen, the container clips. This is a data-dependent rendering risk, not a static defect.

### 5. Compliance

**Sending domain**: `bc.footlocker.com` (Bluecore shared infrastructure subdomain).

SPF, DKIM, and DMARC alignment cannot be verified from HTML source alone — requires header inspection. Standard Bluecore deployments sign with `d=bluecore.com` for DKIM, which means DMARC alignment passes on SPF (`bc.footlocker.com`) but DKIM is misaligned with the `From:` domain (`footlocker.com`). If Foot Locker's DMARC policy is `p=reject` or `p=quarantine` and requires DKIM alignment, this is a deliverability risk. Verify with actual message headers.

**CAN-SPAM physical address and unsubscribe** — not visible in truncated source. These are legally required and typically appear in the footer widget (`widget_7f0685d76ce802a8ea7df55efac0ec33`). Must be present in full render.

---

### 6. Email-to-Site Continuity

UTM parameters on destination URLs are not visible in the truncated source. Bluecore can inject UTMs at click-track redirect time, which would not appear in the raw HTML. Confirm by inspecting a decoded tracking URL — expected pattern:
```
utm_source=email&utm_medium=email&utm_campaign=<campaign_id>&utm_content=<widget/block_id>
```
If UTMs are absent or inconsistent across CTA blocks vs. product widget links, attribution in GA4/Adobe will be fragmented.
