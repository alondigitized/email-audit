## Technical Audit

## Technical Audit — Skechers "Going, going..." (2026-07-23)

---

### 1. Technical Summary

All image assets are served over HTTP rather than HTTPS, exposing them to blocking or proxy-stripping in major clients (Gmail, Outlook.com). One third-party monitoring pixel has a missing URL protocol, making it a broken relative reference that will never load.

---

### 2. Link & Tracking Issues

**Protocol-missing Return Path pixel (critical)**
```html
<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1dbf0dcef79cbad82c12fe25342701e4499" />
```
No `http://` or `https://` prefix. Email clients treat this as a relative path — the request goes to `[current-domain]/pixel.app.returnpath.net/...` and 404s. Inbox placement monitoring via Validity/Return Path is broken for this send.

**26 click-tracked links unresolvable**
All CTAs route through `click.emails.skechers.com`. QA correctly skipped probing them, but UTM parameter presence on destination URLs cannot be confirmed (see §6).

**QA summary counter bug**
The automated check emitted 14 `[WARN]` lines but reported `0 warning(s)` in the summary. The warning tally is not being incremented — the summary line is misleading and should not be trusted.

---

### 3. Rendering & Accessibility

**All `image.emails.skechers.com` assets served over HTTP**
Affected: logo, product images, footer icons (App Store, Google Play, social icons, store locator, AfterPay). Gmail proxies HTTP image sources through its own CDN, stripping subscriber identity from image requests and potentially breaking any Movable Ink/dynamic content tied to user identity. Clients that enforce HTTPS-only (Outlook.com strict mode, some corporate proxies) will block these outright.

```
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-...png  (logo)
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/49468f73-...png  (missing alt)
```

**Ink1000 (Movable Ink) tracking pixel — HTTP + no alt**
```html
<img src="http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&..." />
```
HTTP source and missing `alt=""`. If this pixel drives dynamic content personalization (e.g. live countdown, personalized product swap), the HTTP load may be intercepted or proxied before Movable Ink can identify the subscriber.

**Missing `http-equiv` on charset meta**
```html
<meta content="text/html; charset=utf-8" />
```
Should be `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />`. Some legacy Outlook versions fall back to system default encoding without `http-equiv`, risking character corruption.

**`-webkit-text-size-adjust: none`**
Applied via `* { -webkit-text-size-adjust: none; }`. This globally disables user-initiated text scaling on iOS, which is an accessibility regression for low-vision users. WCAG 1.4.4 requires text to be resizable to 200% without loss of content.

**Duplicate responsive breakpoint blocks**
The 375px and 640px `@media` blocks contain identical rule sets. No functional bug, but adds ~800 bytes of redundant CSS.

Two missing alt attributes confirmed by QA:
- `o.gif` (Ink1000 pixel)
- `49468f73-4651-4af3-bea2-61d1ae5db486.png`

---

### 4. Personalization & Merge Tokens

The Kruxd SHA-256 pixel (`partner_uid=9153f33fe5...`) appears properly resolved — the hash format indicates a subscriber-level value was substituted.

The static Kruxd subid pixel (`partner_uid=121173391`) uses what appears to be a fixed integer. If this is a segment-level constant rather than a subscriber merge token, it is intentional and not a defect.

No unresolved merge token syntax (e.g. `%%TOKEN%%`, `{{token}}`, `[FIRST NAME]`) is visible in the available HTML. Preheader text is static: no first-name personalization.

---

### 5. Compliance

The HTML is truncated before the footer. Unsubscribe link and physical mailing address presence cannot be confirmed from the source fragment. The QA tool's `100% pass rate` claim is unreliable given the counter bug noted in §2 — do not treat this as confirmation of CAN-SPAM compliance.

No issues identifiable in the visible portion of the email.

### 6. Email-to-Site Continuity

Campaign identifier `MKG_US_NONPUR180_U_BEST_NONPURCH_EN_07232026` is present in both the Kruxd ad impression pixel and the Ink1000 pixel — consistent naming is good. Whether this value maps to UTM parameters on click-through URLs (`utm_campaign`, etc.) cannot be verified without resolving the `click.emails.skechers.com` redirects.
