### 3. Rendering & Accessibility

**Confirmed issues:**

- **Malformed `Content-Type` meta** (`<head>`, line ~8):
  ```html
  <meta content="text/html;" charset="utf-8" />
  ```
  Missing `http-equiv="Content-Type"`. Some legacy clients (Outlook 2007/2010) fall back to default encoding if this attribute is absent. Correct form:
  ```html
  <meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
  ```

- **Malformed `X-UA-Compatible` meta** (`<head>`, line ~10):
  ```html
  <meta content="IE=edge" />
  ```
  Missing `http-equiv="X-UA-Compatible"`. Without it, IE/Outlook rendering engine ignores the directive. Correct form:
  ```html
  <meta http-equiv="X-UA-Compatible" content="IE=edge" />
  ```

- **No dark mode support declared**: `color-scheme` and `supported-color-schemes` are set to `light` only. Apple Mail and iOS Mail will force-invert colors on recipients with dark mode enabled, potentially breaking background colors and image overlays. If dark mode variants are not designed, this should at minimum be acknowledged.

- **Redundant CSS declaration** (link rule block):
  ```css
  color:inherit !important; color:inherit;
  ```
  The non-`!important` duplicate is dead code. Harmless, but indicates template hygiene issue.

- **Image alt text** — cannot confirm from truncated source. All `<img>` tags must carry descriptive `alt` attributes for screen readers and image-blocked clients.

- **No `role="presentation"` on layout tables** — not visible in truncated source but expected for table-based layouts to suppress VoiceOver table navigation.
