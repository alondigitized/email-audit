### 3. Rendering & Accessibility

**[HIGH] Malformed `<meta>` tags — both non-functional**

```html
<meta content="text/html;" charset="utf-8" />
<meta content="IE=edge" />
```

Both are missing their required `http-equiv` attribute. Correct forms:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without `http-equiv`, neither tag signals anything to the rendering engine. The charset declaration is especially critical — some clients may fall back to a default encoding.

**[HIGH] CSS `!important` conflict kills Apple link color classes**

The global `a` selector at the bottom of the final `<style>` block:
```css
a, a:link, a:visited ... {
  color: inherit !important;
}
```
uses `!important`. The `.appleLinksWhite`, `.appleLinksGray`, and `.appleLinksBlack` class rules do **not** use `!important`:
```css
.appleLinksWhite a { color: #ffffff; text-decoration: none; }
```
In CSS, `!important` beats specificity, so `color:inherit !important` on the tag selector overrides all three class-based color overrides. These fixes are effectively dead in any client that parses `<style>` correctly (Apple Mail, Gmail web). The Apple autolink fix was the whole point of these classes; it is not working.

**[MEDIUM] Dark mode explicitly disabled — no fallback**

```html
<meta name="color-scheme" content="light" />
<meta name="supported-color-schemes" content="light" />
```

No `@media (prefers-color-scheme: dark)` block exists anywhere in the five `<style>` blocks. Opting out of dark mode entirely is valid, but Apple Mail and Gmail Android will still force-invert elements that lack explicit background colors. Any transparent or unset backgrounds risk dark text on dark surfaces.

**[MEDIUM] Five separate `<style>` blocks**

Gmail strips all but the last `<style>` block in some rendering modes. Styles in blocks 1–4 (the responsive media queries) may be silently dropped for Gmail web users. Consolidate into a single `<style>` block.

**[LOW] 12px minimum font size at mobile breakpoint**

```css
@media only screen and (max-width: 600px) {
  .responsive-text { font-size: 12px !important; }
}
```

12px falls below the WCAG 2.1 recommended 14px minimum for body text. Flagged for accessibility; not a hard compliance blocker.

**[LOW] `pointer-events: none` on tel/sms links**

```css
a[href^="tel"], a[href^="sms"] { pointer-events: none; cursor: default !important; }
```

Disables tap-to-call and tap-to-text on mobile. Appears intentional but should be confirmed — it is a friction point on the primary device type for this audience.
