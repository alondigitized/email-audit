# Boo-nus alert! Extra 10% off for members today only 👻
**Score:** 7/10 · **Type:** Email audit · **2026-10-31**
## Executive summary

- My first thought was that it's Halloween and Skechers wants me to buy something today. The black and orange banner is loud, and "EXTRA 10% OFF" with the code TREAT is easy to read, even on my phone. It's the first email in a while that has an actual offer. The last four I got from them this week were cart nags about a cart I never filled, like "Your cart expires soon!" and "Did you forget something?"
- But 10% off a "Mystery Sale" doesn't tell me what I'm buying. The shoes underneath are a sparkly women's sneaker, a bright orange runner and a kid's shoe with a velcro strap. None of it says cushion, arch support or slip-in, which is what I shop for. I'd glance at it, maybe tap Men's, and probably move on. I wouldn't forward it.

## What's working

- "EXTRA 10% OFF" is huge, and the "today only" deadline is clear. I know the deal at a glance.
- The code TREAT is in a bold pill, so I don't have to hunt for it.
- "Hi, Walker" and the "1000 points, enough for a $5 reward" line show they know I'm a member. It's a small touch, but I noticed it.
- The Halloween theme matches today's date, so it doesn't feel like a stale promo.
- The text is big and the buttons are wide, so they're easy to tap with my thumb.

## What's weak

- "Mystery Sale" tells me nothing. I'd want to see a price before I'd tap.
- Nothing on the shoes says comfort, cushioning or slip-in. The only men's shoe is a neon orange runner with no name, price or feature.
- The sparkly women's shoe is shown first, and there's no one who looks like me. No people at all, just three shoes.
- I'd have to enter a code at checkout. The fine print says it's online only, on select styles, with exclusions. That feels like a catch.
- I'm getting nearly daily emails from them. Another "today only" feels like noise.

## Recommendations

- 1. Lead with a men's comfort shoe, such as a Slip-ins walker, with its name and sale price. Put the "Shop Men's" button right under it, not third.
- 2. Say what the "Mystery Sale" covers, such as "Up to 40% off walking shoes", and apply the discount automatically so I don't need a code.
- 3. Add one line of comfort copy, like "Cushioned. Arch-supported. Hands-free." and a star rating.
- 4. Cut the cart nags. A real offer lands better when it isn't the fifth email in a week.
- 5. Shorten the subject so it fits on a phone screen.
- **Subject Alt A:** `Members: extra 10% off walking shoes today 👟`
- **Subject Alt B:** `Today only: 10% more off, code TREAT`
- **Preheader Alt A:** `Stacks with our Mystery Sale. Slip-ins and walking shoes included.`
- **Preheader Alt B:** `Your 1,000 points + 10% off today. Ends at midnight.`

# Technical Audit: "Boo-nus alert! Extra 10% off for members today only 👻"

## 1. Technical Summary
The email fails one automated check, an empty greeting slot (`Hi ,`). The source also has a scheme-less tracking pixel URL, two non-HTTPS images without alt text, and a viewport meta tag that blocks zoom. SPF/DKIM status and the footer/unsubscribe block can't be verified from the data provided.

## 2. Link & Tracking Issues
- **Scheme-less pixel URL (confirmed in source):** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…">` has no `https://`. Email clients resolve it as a relative path, so it won't load and the Return Path/Validity seed tracking is lost. It also has no `alt` attribute.
- **Non-HTTPS tracking pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=PRO_US_NA_U_SITEEXTRA_LOYL_EN_10312026` (QA WARN). Clients may block or rewrite it, and it exposes the subscriber ID `mi_u` in cleartext HTTP.
- **Identifiers in third-party beacons:** two `beacon.krxd.net/1x1_usermatch.gif` URLs pass a SHA-256 value (`partner_uid=9153f33f…ed00`) and a subscriber ID (`partner_uid=121173391`). This is a privacy-review item for a third-party DMP, not a functional bug.
- **Hidden-image markup is inconsistent:** the krxd pixels use `width="0" height="0"` with no `alt`, and the Return Path pixel has no `alt` either. The open pixel (`click.emails.skechers.com/open.aspx`) is correct.
- **Unverified links:** 30 tracking links were skipped by the HTTP probe because they are click-redirect domains. Destination validity is untested.

## 3. Rendering & Accessibility
- **Meta tags are malformed:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` both lack `http-equiv`, so neither declares anything. Use `<meta charset="utf-8">` or add `http-equiv="Content-Type"`.
- **Zoom is blocked:** the viewport meta has `maximum-scale=1`, which prevents pinch-zoom on mobile.
- **No `lang` attribute:** `<html xmlns=…>` has no `lang`.
- **Layout tables lack roles:** the visible tables (`<table cellpadding="0" cellspacing="0" border="0">`, `<table class="widthFull" width="640">`) have no `role="presentation"`.
- **Missing alt text (QA WARN):** `dde00662-169f-447d-b0e2-fc65f6c2290c.png`, served from `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/…`, has no alt text. If it is a content image, it is invisible to screen readers and to image-blocked clients. `o.gif` also lacks alt but is a pixel.
- **Mixed content:** the same PNG loads over `http://` from the Skechers image domain (QA WARN). Some clients block it, and the domain should serve HTTPS.
- **Text-size adjust:** `* { -webkit-text-size-adjust: none }` disables user text scaling in WebKit clients.
- **Title is generic:** `<title>Skechers®</title>` doesn't describe the message.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** the greeting renders as `Hi ,` because the first-name field was empty at send. This is a visible broken experience. It is not visible in the truncated HTML, so the QA check is the evidence.
- The data doesn't show whether a fallback value is defined in the template. A missing fallback (e.g. `%%=v(@firstname)=%%` with no default, since this is an SFMC send) would explain it.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication-Results not found (QA WARN):** this is expected through the AgentMail relay, so SPF/DKIM/DMARC status is **unverified**, not failed. Check the original headers at the receiving mailbox.
- **Unsubscribe and physical address:** the source is truncated before the footer, so the unsubscribe link, `List-Unsubscribe` / `List-Unsubscribe-Post` headers, and postal address can't be confirmed. No finding.
- **Sender:** `no-reply@emails.skechers.com` is a no-reply address. This isn't a CAN-SPAM violation, but it gives recipients no reply path.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- The campaign identifier `PRO_US_NA_U_SITEEXTRA_LOYL_EN_10312026` appears in the `ink1000` and `krxd` pixels. That is consistent with a 10/31 loyalty send.
- UTM parameters and landing-page alignment **can't be assessed**. The visible links go through `click.emails.skechers.com`, and the 30 tracked links were skipped by the probe, so final URLs weren't resolved. No finding.

## 7. Recommendations
1. **Fix the greeting.** Add a default fallback to the first-name merge (e.g. "Hi there,") or suppress the greeting when the name is empty. Add a pre-send test for empty-name records.
2. **Add `https://` to the Return Path pixel.** Change it to `https://pixel.app.returnpath.net/pixel.gif?r=…`.
3. **Move all images to HTTPS.** Cover the `ink1000.com` `o.gif` and the `image.emails.skechers.com` PNG. Serve the image domain over TLS and replace `http://` URLs.
4. **Add alt text.** Give `dde00662-…png` a descriptive `alt`, and add `alt=""` to the decorative pixels.
5. **Fix the head markup.** Use `<meta charset="utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`, drop `maximum-scale=1`, add `lang="en"` to `<html>`, and add `role="presentation"` to layout tables.
6. **Verify authentication from original headers.** Confirm SPF, DKIM and DMARC alignment for `emails.skechers.com` outside the relay.
7. **Run an unprobed-link check.** Resolve the 30 click-redirect URLs through a redirect-following pass to confirm final destinations and UTM carry-through. Also confirm the footer unsubscribe link and `List-Unsubscribe` header on the full source.
