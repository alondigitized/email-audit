# Here's $10 OFF!
**Score:** 5/10 · **Type:** Email audit · **2026-06-04**
## Executive summary

- Here we go again. DSW dangles "$10 off" in the subject — I bit, same as I bit this morning on the sandals wave email and twice earlier this week. And sure enough, the whole email is "WE EMBELLISHED A LITTLE" — bejeweled strappy heels, gold-chain sandals, a young woman draped in red accessories. - **Preheader is a mess.** "It's all about the little details this summer" is vague and feminine — "little details" reads as jewelry and embellishment, not comfort shoes. Then it trails into a long wall of invisible padding that wastes the second line of inbox real estate.
- **DSW fatigue is real.** This is effectively the fifth "$10 off" communication in two days. Even when the deal is genuine, the repeated cadence trains me to tune it out. I opened this one out of habit, not interest.

- 2. **Put the $10 off in the body hero.** The offer belongs above the fold with a visible code or button, not only in the subject. If I can't see the $10 off in the first screen, the promise broke.
- 3. **Give the preheader real work.** "Little details" is a women's fashion phrase. Replace it with something that names the offer or the category.
- 4. **Pull back the cadence.** Four $10-off emails in 48 hours dulls the urgency. Space them out or vary the angle.
- 5. **Lead with the wide-width / comfort line** when talking to men. The "SHOP WIDE WIDTH" button is buried; for a guy like me it should be the hook.

### 3. Rendering & Accessibility

**[HIGH] `Src:` capitalisation in all `@font-face` declarations**
CSS property names are technically case-sensitive per spec. All 10 `@font-face` blocks use `Src:` (capital S) instead of `src:`. Gecko-based clients (Thunderbird) will reject these rules entirely; other clients may silently accept them. Evidence — every `@font-face` block in the `<style>` tag:
```css
Src: url("https://braze-images.com/appboy/...woff") format('woff');
```
Fix: lowercase `src:` across all 10 declarations.

**[HIGH] All `@font-face` weights registered as `font-weight: normal`**
`Futura_PT_Bold`, `Futura_PT_Demi`, `Futura_PT_Medium`, `HelveticaNow_Bold`, `HelveticaNow_BoldItalic`, etc. are all declared with `font-weight: normal`. This means any CSS rule that applies `font-weight: bold` against these family names will not trigger the correct font file — it will either use the regular variant or fall back to the system font. Each variant must be registered with its matching `font-weight` descriptor:
```css
/* Fix example */
@font-face {
  font-family: 'Futura_PT_Bold';
  font-weight: bold; /* or 700 */
  src: url("...") format('woff');
}
```

**[MEDIUM] `-ms-text-size-adjust` conflict in `*` reset**
The reset block sets the property twice in the same rule — `100%` first, then immediately overridden to `none`:
```css
*{
  -ms-text-size-adjust: 100%;   /* set */
  ...
  -ms-text-size-adjust: none;   /* overrides to none */
}
```
`none` disables automatic text scaling in Windows Mobile / older Outlook Mobile, which can break responsive text behaviour. The `100%` declaration is dead. If the intent is to prevent auto-scaling, `none` is correct but the redundant `100%` should be removed; if `100%` is intended, remove the `none`.

**[LOW] `<meta charset>` missing `http-equiv` attribute**
```html
<meta content="text/html; charset=utf-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, some legacy MIME parsers may not honour the charset declaration. The `<title>` and body are ASCII-safe so the practical impact is low, but this is a well-known email HTML anti-pattern.

**[LOW] Invalid CSS property `supported-color-schemes` in `:root`**
```css
:root {
  color-scheme: light dark;
  supported-color-schemes: light dark;  /* not a valid CSS property */
}
```
`supported-color-schemes` is a `<meta>` tag attribute, not a CSS property. It is already correctly declared as `<meta name="supported-color-schemes" content="light dark" />` in the `<head>`. The CSS version is dead code and should be removed to keep the stylesheet clean.
