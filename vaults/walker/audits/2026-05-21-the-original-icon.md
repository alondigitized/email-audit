- I recognized adidas in the sender field and opened this one out of habit — hoping maybe they finally had something on sale that I'd actually want on my feet. What I got was the Superstar. Again. I already got an email called "The Superstar Returns" back on May 13th — same flat, canvas-sole fashion sneaker, now repackaged as "the original icon." Eight days later they're sending me the same shoe with different headline copy like I didn't notice. That's not a campaign, that's running out of ideas.
- There's a section near the bottom for a Strava x adiClub partnership that's mildly interesting — at least it's about staying active, and I do have an adiClub account. That's not me. That's not anyone I'm buying shoes for.
- I'm marking this read and moving on. Wouldn't click, wouldn't forward. If adidas wants my attention, they need to show me cushioning, arch support, or a real price break — not a legacy sneaker I've now been pitched twice this month.

### 1. Technical Summary

Two confirmed failures: a broken redirect link and a missing plain-text fallback. Eight HTTP (non-HTTPS) image sources are flagged and will be blocked by most modern email clients with image proxying enabled.

---

### 2. Link & Tracking Issues

**[FAIL] Broken redirect — malformed relative URL in click wrapper**

The QA probe resolved a click-tracking URL to a relative path, which is not a valid redirect target:

```
Resolved path: /g/7e07fb28-d2a5-4524-877f-17f4157e1d90?txn=5a442500-...
Tracking URL:   https://dv.adidas.com/o/7e07fb28-d2a5-4524-877f-17f4157e1d90?cp_tp=v3.eJzj...
```

The `dv.adidas.com` redirect service is returning a relative `/g/...` path instead of an absolute `https://` destination. Any subscriber who clicks this link reaches a broken page. This is the single highest-severity issue.

**[WARN] 36 click-tracking links skipped** — all routed through `click.comms.adidas.com` or `dv.adidas.com`. The broken redirect above may affect additional links using the same redirect service; manual spot-checking of other CTA destinations is warranted.

---

### 3. Rendering & Accessibility

**[WARN] HTTP image sources — 8 instances of the same asset**

The same arrow icon is embedded 8 times via HTTP:

```
src: http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg
```

Gmail, Outlook.com, and Apple Mail all proxy or block mixed-content images. This asset will render as a broken image in clients with HTTPS enforcement. Fix: serve from `https://`.

**[WARN] 1 additional HTTP image** via the click-tracking CDN:

```
src: http://click.comms.adidas.com/CI0/0102019e487f5f44-.../xgVCw7EzgftKrxR9kf-e8l3Qf...
```

Same mixed-content risk.

**[WARN] Missing `alt` text on 2 images** — the `dv.adidas.com` open-pixel and the `click.comms.adidas.com` tracking image both lack `alt=""`. Tracking pixels should carry `alt=""` (empty string) explicitly; omitting it leaves screen readers to announce the raw filename or URL fragment.

**Note on font declarations:** `AdihausDIN` and `AdineuePRO` are declared in three separate `@font-face` blocks with identical `src` stacks pointing only to local system fonts (Arial/Helvetica/Calibri). No remote `.woff2` sources are loaded. This is intentional for email compatibility but means the custom typeface never renders — fallback only.
