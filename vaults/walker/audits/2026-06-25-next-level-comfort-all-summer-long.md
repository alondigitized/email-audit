## Technical Audit

## Technical Audit — Skechers "Next-Level Comfort, All Summer Long"

---

### 1. Technical Summary

One broken personalization token produces a visible rendering defect ("Hi ,") that will reach every recipient. Additionally, all hosted images are served over HTTP, creating a systemic mixed-content risk across the email's visual payload.

---

### 2. Link & Tracking Issues

**26 click-redirect links** all route through `click.emails.skechers.com` (Salesforce Marketing Cloud). Probing was skipped for tracking domains — final destination URLs were not verified.

**Third-party pixel exposure:** Three distinct tracking pixels fire on open:
- `beacon.krxd.net` — Salesforce/Krux DMP user-match pixels (2 requests), one exposing a raw subscriber ID (`partner_uid=121173391`) in the query string.
- `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif` — third-party open tracker, served over **HTTP** (see §3).
- `pixel.app.returnpath.net/pixel.gif` — Validity (Return Path) inbox monitoring pixel. URL is missing the `https://` scheme prefix in the source (`pixel.app.returnpath.net/...` rather than `https://...`), making it a protocol-relative or broken reference depending on client behavior.

---

### 3. Rendering & Accessibility

**[FAIL — Systemic] All image assets served over HTTP.**

Every image hosted on `image.emails.skechers.com` uses `http://`. Gmail, Outlook.com, and Apple Mail proxy or block non-HTTPS image sources; these images will likely not render for a significant share of recipients.

Affected assets (representative):
```
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png  (Skechers logo)
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/49468f73-4651-4af3-bea2-61d1ae5db486.png
http://www.ink1000.com/p/up/7076d8b15a776085/o.gif  (third-party tracker)
```
All 10+ hosted images are affected.

**[WARN] Missing `alt` text on two images:**
- `o.gif` (ink1000 tracker) — no `alt` attribute.
- `49468f73-4651-4af3-bea2-61d1ae5db486.png` — no `alt` attribute. If this is a content image (hero/product), missing alt breaks screen readers and images-off rendering.

**[INFO] `-webkit-text-size-adjust: none`** is set globally. This suppresses iOS auto-sizing but also prevents user accessibility overrides. Low risk, but worth noting for accessibility standards compliance.

**[INFO] `maximum-scale=1`** in the viewport meta tag prevents pinch-to-zoom on mobile. This is a WCAG 1.4.4 violation.

---

### 4. Personalization & Merge Tokens

**[FAIL] Empty greeting — broken merge token.**

QA confirmed: the greeting block renders as **"Hi ,"** — the first-name merge field resolved to an empty string. The fallback value is either missing or the conditional logic (`IF firstname EMPTY THEN "there"` pattern) was not implemented.

This is a P1 defect: it is visible to every recipient whose first name is absent from the subscriber record, and it signals a data/template error to the reader.

No other merge tokens were detectable in the truncated HTML.

---

### 5. Compliance

**CAN-SPAM / Unsubscribe:** Not verifiable from the truncated HTML provided — the footer (physical address, unsubscribe link) was cut off. Requires review of the full source.

**Authentication headers:** Not available in the HTML source. DKIM, SPF, and DMARC alignment should be verified via received message headers (`Authentication-Results` header). `no-reply@emails.skechers.com` sending domain must be covered by a published SPF record and DKIM signing key for `emails.skechers.com`.

**Subscriber ID exposure:** `beacon.krxd.net` pixel includes `partner_uid=121173391` — a raw internal subscriber or segment ID in a GET request to a third-party domain. Confirm this is intentional and covered by the ESP's data processing agreement.

---

### 6. Email-to-Site Continuity

UTM parameters could not be verified because all 26 destination links are wrapped in the SFMC click-redirect domain and were not probed. **Before send, manually spot-check 2–3 CTA links** to confirm:
- `utm_source`, `utm_medium`, `utm_campaign` are present and correct.
- Campaign ID in pixels (`MKG_US_L90D_U_CATEGORY_ENGAGEDCLICK_EN_06112026`) matches the UTM `utm_campaign` value for attribution consistency.
- Landing pages resolve to the correct offer (BOGO 50% off / 20% off) and are not 404ing or redirecting to the homepage.

---
