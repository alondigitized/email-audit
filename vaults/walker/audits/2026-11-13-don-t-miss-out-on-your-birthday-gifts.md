## Technical Audit

# Technical Audit: "Don't miss out on your birthday gifts!"

## 1. Technical Summary
The email has one confirmed merge-token failure (an empty greeting) and a malformed tracking-pixel URL in the HTML source. It also has widespread `http://` image sources and four third-party Krux beacons, one of which appears to carry a hashed identifier. The HTML was truncated, so footer, unsubscribe and link-level findings are limited to what the QA data shows.

## 2. Link & Tracking Issues
- **Malformed pixel URL (source-confirmed):** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…">` has no scheme. It resolves as a relative URL and will 404 or never fire, so Return Path/Validity seed and inbox-placement tracking is lost. It also has no `alt` attribute.
- **Insecure tracking pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=TRG_US_EN_BDAYCAPTURE_3_07092026_B` loads over plain HTTP. Clients may block it or show a mixed-content warning. The QA "missing alt" flag on this image is a false positive, because the source shows `alt=""`, which is correct for a tracking pixel.
- **Unprobed links:** 30 tracking links on `click.emails.skechers.com` were skipped by the HTTP probe, so redirect health and final destinations are unverified.
- **Redundant hidden pixels:** There are 7 hidden or 1×1 images in total. These are the SFMC open pixel (`click.emails.skechers.com/open.aspx?qs=…`), 4 Krux beacons, the Return Path pixel and the ink1000 pixel. They add third-party requests, and some are only partly hidden: the Return Path and ink1000 pixels have no `display:none`.

## 3. Rendering & Accessibility
- **Invalid meta tags (source-confirmed):** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv`. The charset declaration is therefore ineffective, and `®` in `<title>` could mis-render in clients that don't default to UTF-8.
- **Missing alt text:** `49468f73-4651-4af3-bea2-61d1ae5db486.png` has no alt text, per QA. It is a content image, not a pixel.
- **Layout tables:** The visible tables (`<table cellpadding="0" cellspacing="0" border="0">` and the 1×1 table) have no `role="presentation"`. This is only confirmable for the truncated portion.
- **HTTP image sources:** 12 images on `image.emails.skechers.com` use `http://`, including the logo, app-store badges, AfterPay, Find a Store and the social icons. Most major clients proxy these, but some clients and security gateways flag or block them.
- **Hidden-content CSS:** The `.mobile-content` and `.desktop-content` toggle defaults are inverted around the 768px breakpoint. Between 641px and 767px the layout depends on the `640px` and `680px` rules, which could cause inconsistent rendering. This is unverified without the body markup.

## 4. Personalization & Merge Tokens
- **FAIL (QA-confirmed):** The greeting renders as `"Hi ,"` because the first-name field is empty. There is no fallback or default value. If the test subscriber was captured without a name, this is a missing-data case, and the template should handle it with a default such as `%%=IIF(Empty(@firstname),"there",@firstname)=%%` or by suppressing the greeting.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication:** `Authentication-Results` was not found, so SPF/DKIM/DMARC status is unknown. QA attributes this to the AgentMail relay stripping the header, so it is not a confirmed defect on the sender's side.
- **Unsubscribe and physical address:** The footer is not in the truncated source, and no `List-Unsubscribe` or `List-Unsubscribe-Post` headers were provided. No determination is possible.
- **Third-party data sharing:** `beacon.krxd.net/1x1_usermatch.gif?partner=LprH63a7_sfmc_100007688_sha25&partner_uid=9153f33f…ed00` carries a 64-hex value labelled `sha25…`, which is likely a SHA-256 hashed email address. A second beacon sends `partner_uid=121173391`, a subscriber ID. Passing hashed PII to an ad-tech partner via image URLs is a privacy and disclosure risk, because it is outside the ESP and can be logged by any proxy. The `from` address is `no-reply@`, which does not breach CAN-SPAM but gives recipients no reply path.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- No UTM parameters are verifiable. The 30 links are all wrapped in SFMC click redirects and were not resolved, so final URLs and landing pages could not be checked.
- The campaign ID `TRG_US_EN_BDAYCAPTURE_3_07092026_B` appears in the Krux and ink1000 beacons. It contains a date stamp of 07/09/2026, while the email was received 2026-11-13. This suggests a triggered or evergreen send reusing a July campaign ID. It is not an error, but it makes attribution harder.

## 7. Recommendations
1. Add a first-name fallback so the greeting never renders as `"Hi ,"`, and handle empty-name subscribers in the birthday-capture segment.
2. Fix the Return Path pixel to `https://pixel.app.returnpath.net/pixel.gif?r=…` and add `alt=""`.
3. Move all `image.emails.skechers.com` and `ink1000.com` references to `https://`.
4. Correct the meta tags to `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
5. Add descriptive alt text to `49468f73-…png`, and add `role="presentation"` to layout tables.
6. Review the Krux hashed-identifier beacons against the privacy policy and consent language, and consider removing the duplicates.
7. For the next audit, supply the full HTML including the footer and `List-Unsubscribe` headers. Resolve the click-tracking redirects to check UTM parameters and landing pages.
