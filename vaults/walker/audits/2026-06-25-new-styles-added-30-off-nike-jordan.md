### 3. Rendering & Accessibility

**Malformed `<meta http-equiv>` tags (confirmed):**

```html
<!-- Missing http-equiv="Content-Type" -->
<meta content="text/html;" charset="utf-8" />

<!-- Missing http-equiv="X-UA-Compatible" -->
<meta content="IE=edge" />
```

Both tags omit the required `http-equiv` attribute. The content-type meta also has an incomplete `content` value (`text/html;` instead of `text/html; charset=utf-8`). These will be silently ignored by most clients but are technically invalid and may cause issues in strict parsers.

**Style block precedes charset declaration:**
The first `<style>` block appears in the source *before* the `<meta charset>` tag. CSS should follow all `<meta>` declarations.

**Overlapping responsive breakpoints:**
Three breakpoints overlap in the 451–660px range:
- `max-width: 600px` — sets font sizes only
- `max-width: 660px` — sets layout (`.container`, `.drop`, `.show`/`.hide`)
- `max-width: 450px` — repeats some layout rules from the 660px block

The gap between 601px and 660px will receive layout rules from the 660px block but *not* the font-size rules from the 600px block. Verify this range renders correctly on mid-size Android phones (~Galaxy S series).

**Dark mode suppressed:**

```html
<meta name="color-scheme" content="light" />
<meta name="supported-color-schemes" content="light" />
```

Apple Mail on iOS/macOS will force light rendering. If any text colors are set assuming a white background and the background is overridden by a dark OS, text may become unreadable. This is an intentional trade-off, but it should be flagged.
