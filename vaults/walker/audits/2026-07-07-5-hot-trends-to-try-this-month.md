# 5 hot trends to try this month ❤🔥

## Executive summary

- I opened this one because yesterday's BOGO email had me curious whether DSW was going to keep that deal going. And sure enough, the BOGO banner is right there at the top. That part's fine. But then I scroll down and I'm staring at a lookbook built entirely around jelly sandals, minimalist strappy sandals, and floral picks. I'm a 62-year-old man. - The 40% OFF CLEARANCE block down near the bottom is the only thing that made me slow down. ## What's weak

- **Every single trend is aimed at young women** — Court sneakers on a college-age model, jellies, floral sandals. Not one signal this is for a guy like me.
- **"Summery Jellies"** — I had to Google what those even were. Jelly sandals. I haven't thought about those since my kids were in grade school.
- **"The Hotpants may be now" copy** — I read that line three times trying to figure out what it was selling. Lost me immediately.
- **Zero comfort or support language anywhere** — not one mention of cushioning, arch support, wide widths, or walkability. That's the whole game for me at this point.
- **Clearance section is buried** — the one thing I'd actually act on is at the very bottom, after I've already scrolled past five trend buckets that don't apply to me.

- 1. **Segment men vs. women** — this is the entire fix. A version of this email showing men's comfort or casual trends (retro sneakers for men, cushioned walking shoes, etc.) would actually get my click. Right now I'm collateral damage on a send built for someone else.
- 2. **Lead with the clearance** — or at minimum put a men's clearance teaser block higher up; don't make me find it after wading through a women's lookbook.
- 3. **Swap "5 hot trends" framing for something that lands for a broader audience** — the trend-editorial voice works for fashion shoppers; it doesn't work for a guy who wants to know if there's a good walking shoe on sale.
- 4. **"Retro Sneakers" is the one trend with potential for me** — pull that out, show it with a men's version, and you've got one section worth clicking. Right now it's one of five lost in the mix.

### 3. Rendering & Accessibility

**[HIGH] Invalid CSS property casing on all `@font-face` declarations**
All 10 `@font-face` blocks use `Src:` (capital S) instead of the valid `src:`. CSS property names are case-sensitive in standards-compliant parsers. This will cause font fallback to system fonts in strict CSS clients (e.g., some webmail renderers).

```css
/* Wrong — appears 10 times */
Src: url("https://braze-images.com/...") format('woff');

/* Correct */
src: url("https://braze-images.com/...") format('woff');
```

**[MEDIUM] `maximum-scale=1` blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
WCAG 1.4.4 (Level AA) requires text to be resizable up to 200%. Locking `maximum-scale` fails this criterion for users who zoom via system accessibility settings. Remove `maximum-scale=1`.

**[LOW] Missing `http-equiv` on charset meta**
```html
<meta content="text/html; charset=utf-8" />
```
Missing `http-equiv="Content-Type"`. Some legacy Outlook and Lotus Notes clients require this attribute to recognize the charset declaration. Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

**[LOW] `supported-color-schemes` inside CSS `:root` block is invalid**
```css
:root {
  color-scheme: light dark;
  supported-color-schemes: light dark;  /* not a valid CSS property */
}
```
`supported-color-schemes` is only valid as an HTML `<meta>` tag (already present in `<head>`). The CSS declaration is a no-op and should be removed to avoid parser warnings.

**[LOW] Near-black dark mode background uses `#00000F` (blue-tinted)**
```css
.dm-bg-black { background: #00000F !important; }
```
`#00000F` has a faint blue cast. If intentional for perceptual reasons, document it; if a hex typo for `#000000`, correct it.

**[INFO] Font payload: 10 web font files loaded**
Both Futura PT (4 weights, `.woff`) and HelveticaNow (6 weights, `.ttf`) families are declared. Most email clients block remote fonts anyway, but clients that do load them (Apple Mail, iOS Mail) will fetch up to 10 files. Trim to only the weights actually used in the template.
