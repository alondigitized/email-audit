### 3. Rendering & Accessibility

**Invalid `<meta>` attributes — two instances:**
- `<meta content="text/html; charset=utf-8" />` is missing `http-equiv="Content-Type"`. Should be `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />`.
- `<meta content="IE=Edge" />` is missing `http-equiv="X-UA-Compatible"`. Without the attribute, the pragma is silently ignored in Outlook/IE rendering engines.

**Invalid CSS property casing in all `@font-face` blocks:**
All ten `@font-face` declarations use `Src:` (capital S) instead of the spec-required `src:`. CSS property names are case-insensitive in practice, but strict parsers (some email preprocessors, AMP4EMAIL) may reject the rule, causing web-font fallback to system fonts for all recipients.

**Inconsistent font formats:**
Futura PT weights load `.woff` only; HelveticaNow weights load `.ttf` only (with cache-busting query strings: `?1755182939`). No `.woff2` is offered for either family. `.ttf` is larger than `.woff2` and loads slower on mobile; `.woff2` is supported by all modern email clients that support web fonts at all.

**`maximum-scale=1` in viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Disables user-initiated zoom. This is an WCAG 1.4.4 (Resize Text) violation and will trigger accessibility flags in automated scanners.

**Near-black color value `#000001`:**
```css
.border-top-black { border-top: 1px #000001 solid !important; }
```
Using `#000001` instead of `#000000` is a known workaround to prevent Gmail dark-mode color inversion. Functionally harmless but should be documented so it isn't "fixed" to `#000000` in a future template edit.
