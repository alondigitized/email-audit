# Extended: take $15 off in the app…
**Score:** 5/10 · **Type:** Email audit · **2026-10-13**
## Executive summary

- DSW again. I've now had this same CIDER $15/$20/$60 deal several times since the 8th, including this morning's "Get $15 OFF in the app!" and yesterday's "Your $15 Off Offer Is Ending Soon." Now it's "Extended," and the banner says the clock is at 12 hours and change. Dropping the "ends tonight" line from the preview only makes it more obvious they keep moving the finish line. I stopped believing the urgency a few sends ago.
- The email itself is clean and easy to read. The green countdown banner and the big $15 / $20 / $60 numbers are the first thing I see, and I understand the deal in about two seconds. But then the whole thing turns to women's fall browns, heels, and boots. There's nothing for a 62-year-old man looking for cushioned slip-ons. The "Men" link is a tiny underlined line buried under the banner. And the deal only works in the app, which is one more hoop for me.
- Would I click? No. Forward it? No. I'd mark it read and move on. If I wanted a comfortable walking shoe, I'd go straight to the Skechers or Brooks section on my own.

## What's working

- The big $15 / $20 / $60 tiers are easy to read on my phone, and I get the deal right away.
- The countdown banner at the top is large and clear.
- The nav and the black "Download the App" button are easy to see and tap.
- The "Shop by Size" block has big numbers, and the wide-width button is a nice touch for feet like mine.
- The footer shows free shipping and in-store pickup, which I'd actually use.

## What's weak

- Everything below the banner is women's fashion: handbags, boots, heels, a "Fall Browns" story. I'm not the target.
- "Shop Men" is a small underlined text link. It's easy to miss and a tough tap target for my thumbs.
- It's the umpteenth send of the same CIDER deal since the 8th, and "Extended" confirms the deadlines aren't real.
- The code only works in the app, so I have to download something before I can save $15.
- The VIP Shoebox Shuffle game is a gimmick and doesn't help me pick a shoe. I don't care about a points balance.
- The fine print is tiny and I'd have to zoom to read it. I can't see any comfort, cushion, or arch-support messaging anywhere.

## Recommendations

- 1. Segment by gender and category. Send me a men's comfort and walking hero, with slip-ons and cushioned brands like Skechers, Hoka, and Brooks, instead of women's trends.
- 2. Stop the daily repeats. One honest "extended" notice is fine, but a fifth near-identical send in a week trains me to ignore you.
- 3. Make the men's link a real button, at the same size as the women's buttons.
- 4. Say the app-only condition in the subject line or preheader, so I know before I open it.
- 5. Replace the game block with a "comfort picks under $100" row or a wide-width highlight.

## Technical Audit

## 1. Technical Summary
The email's source is mostly sound, but one probed CTA ("Opt-In to Texts Get 15% Off") returned HTTP 400. The plain-text part is 84% URLs, and there are a few accessibility and markup defects. Only 12 of 81 links were probed, and the HTML is truncated, so coverage is partial.

## 2. Link & Tracking Issues
- **Broken CTA (FAIL):** The link text is "Opt-In to Texts Get 15% Off". Its URL is `https://ablink.dsw.com/f/a/Mrx9EODLENkTSDOhOejemA~~/AAQRxRA~/e-VSIliwOwJbb…` (very long tracked redirect), and it returned **400**.
  - It is 1 of 12 probed links, and the only failure.
  - A 400 on a signed redirect can mean the tracking token is malformed or expired. It can also mean the redirector rejects automated probes. The QA data can't tell these apart, so verify it manually in a real client.
  - If it is genuinely broken, the SMS-opt-in CTA is dead for recipients.
- **Dual open-tracking pixels:**
  - `https://ablink.dsw.com/q/5bFrzAJv-pWxYX-MJd1Bbw~~/AAQRxRA~/…`
  - `https://mi.dsw.com/p/up/e6f23fb0…/o.gif?mi_u=225090073&mi_ecmp=20261013_P261451_V1_W-_Offer_Trend`
  - Both are expected for an ESP plus Movable Ink setup. Note that `mi_u` is a numeric user identifier carried in the pixel URL.
- **Coverage gap:** 69 links were skipped, so the rest of the tracked links are unverified.

## 3. Rendering & Accessibility
- **Missing alt text (WARN, confirmed):** Both images listed above lack `alt`. They are tracking pixels, so the fix is `alt=""` (plus `width="1" height="1"`). That keeps screen readers from announcing the raw filename (`o.gif`).
- **Pinch-zoom disabled:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">`. `maximum-scale=1` blocks user zoom on some clients, which is a WCAG 1.4.4 concern.
- **Malformed meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv`, so both are ignored by parsers. Charset normally comes from the MIME `Content-Type` header, so the impact is low.
- **No `lang` attribute:** The root element is `<html xmlns="http://www.w3.org/1999/xhtml">`, which hurts screen-reader pronunciation.
- **Other checks:** Dark-mode support (`color-scheme`, `prefers-color-scheme`) and the `x-apple-disable-message-reformatting` / `format-detection` metas are present and correct. Web fonts are served from `braze-images.com`.
- **Not assessable:** The HTML is truncated, so I can't evaluate table roles, button alt text or the body.

## 4. Personalization & Merge Tokens
No issues found in the visible source. No unrendered tokens (`{{ }}`, `%%`, `[FIRST_NAME]`) appear in the supplied portion, but the body is truncated.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)

- **Not verifiable from the supplied data:** SPF/DKIM/DMARC results, `List-Unsubscribe` / `List-Unsubscribe-Post` headers, and the physical postal address, which would be in the truncated footer.
- **Sender:** `dsw@e.dsw.com` is a dedicated subdomain, so there is no mismatch to report.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- Every link is wrapped in the `ablink.dsw.com` redirector, so final destinations and UTM parameters can't be seen without following the redirects. The only campaign identifier visible is `mi_ecmp=20261013_P261451_V1_W-_Offer_Trend`, on the pixel.
- The one confirmed continuity failure is the SMS opt-in CTA's 400. If real, a user who clicks lands on an error page rather than the opt-in flow.

## 7. Recommendations
1. Manually click the "Opt-In to Texts Get 15% Off" link from a real inbox. If it fails, regenerate the tracked link or fix the destination. If it works, whitelist the QA probe's user agent so it doesn't produce false positives.
2. Remove `maximum-scale=1` from the viewport meta.
3. Add `alt=""` to both tracking pixels, and add `lang="en"` to `<html>`.
4. Fix the meta tags: `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
5. Shorten tracked URLs or send a proper `multipart/alternative` text part. The plain text is 26,070 of 31,046 characters URLs (84%), which can trigger spam heuristics.
