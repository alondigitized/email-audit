### 3. Rendering & Accessibility

**`http-equiv` missing on two `<meta>` tags (malformed):**
```html
<meta content="text/html; charset=utf-8" />          <!-- missing http-equiv="Content-Type" -->
<meta content="IE=Edge" />                            <!-- missing http-equiv="X-UA-Compatible" -->
```
Without `http-equiv`, these meta declarations have no effect. Charset fallback and IE rendering hints are silently dropped.

**Invalid CSS property casing — `Src:` instead of `src:` in all 10 `@font-face` blocks:**
```css
@font-face {
  font-family: 'Futura_PT_Regular';
  Src: url("https://braze-images.com/.../original.woff") format('woff');  /* INVALID */
}
```
Capital `S` is not a valid CSS property. Strict parsers (including some webmail clients) will silently discard the declaration, causing all custom fonts to fail. All 4 Futura PT and all 6 HelveticaNow `@font-face` blocks are affected.

**Contradictory `text-size-adjust` declarations in the same rule:**
```css
* {
  -webkit-text-size-adjust: 100%;   /* allow normal scaling */
  text-size-adjust: none;           /* then disable it entirely */
}
```
`100%` and `none` conflict. Intended behavior is unclear; net effect varies by client. If the goal is to prevent iOS auto-scaling, the correct value is `100%` (not `none`) paired with the `-webkit-` prefix.

**`maximum-scale=1` in viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. WCAG 1.4.4 failure for users who require zoom. iOS 10+ ignores this restriction in browsers, but it is still a flagged accessibility issue.

**Font format coverage:**
- Futura PT variants: `.woff` only — no `woff2`.
- HelveticaNow variants: `.ttf` only — no `woff2`, no `woff`.

`woff2` has near-universal email client support where web fonts work at all; `ttf` loads are significantly larger. Not a rendering blocker but increases load time for clients that do honor web fonts (Apple Mail, some Android).
