# Technical Audit: HOKA "Arahi 9: Light, soft stability"

## 1. Technical Summary
The email has a 67% QA pass rate. It has no plain-text part, 13 content images with no alt text, and an unsubscribe link and a returns link that both returned 403 to the automated probe. The HTML also has template-rendering leftovers and conflicting meta tags.

## 2. Link & Tracking Issues
- **Unsubscribe link returned 403 (FAIL).**
  - Wrapper: `https://e.emails.hoka.com/c2/1664:...:1/d24c6bd3?jwtH=...`
  - The JWT payload decodes to `linkUrl: https://options.hoka.com/unsubscribe?cid=69e560485cc95da09e001cd9&utm_source=US_Broadcast&utm_medium=email&utm_campaign=H_US_BR_20261006_Arahi9_Spotlight_GWP_...&hmail=...&cordial_id=...`.
  - A 403 on a Cordial click-wrapper often means bot filtering, so this may be a false positive. The data doesn't show whether a real browser succeeds. Verify manually, because a failing unsubscribe is a compliance risk.
- **Returns link returned 403 (FAIL).**
  - Link text is `hoka.com/en/us/return-start/`, and the wrapper is `.../c2/.../513db86f?jwtH=...`.
  - The decoded target is `https://www.hoka.com/en/us/return-start/?utm_source=US_Broadcast&utm_medium=email&utm_campaign=H_US_BR_20261006_Arahi9_Spotlight_GWP_...`.
  - The same bot-filtering caveat applies, so a browser check is needed.
- **Probe coverage was partial.** Only 12 links were probed and 15 were skipped, so the remaining links are unverified.
- **Two open-tracking pixels:** `e.emails.hoka.com/o/p/1664:...` (Cordial) and `mg.emails.hoka.com/o/eJyM...` (a second sending-domain tracker). Two trackers can double-count opens. Neither pixel has alt text.

- **13 images have no alt text.** The QA run flagged `US_20261006_SneakerWeekPromo.jpg`, `US_20261006_SpotlightArahi9_a.jpg` through `_g.jpg`, `1006-C.jpg`, `1006-D.jpg`, `US_Q3_SMSCTA_DoubleAsterisk.jpg` and `LogoFooterPrimary.png`. The email appears to be image-based, so with images blocked it would render blank or unreadable and be unusable with a screen reader. The two tracking pixels also lack alt, which is minor.
- **Empty `<title></title>`.**
- **Malformed charset meta:** `<meta content="text/html; charset=utf-8" />` has no `http-equiv` attribute, so it declares nothing.
- **Duplicate viewport meta tags with conflicting values:**
  - `maximum-scale=1` blocks pinch-zoom.
  - `maximum-scale=1, user-scalable=yes` conflicts with it.
  - Clients will resolve these inconsistently, and the zoom restriction is an accessibility problem.
- **Unresolved template values in the CSS:**
  - `.nav_padding {padding-top:px !important;padding-bottom:px !important;}`
  - `.nav_border {border-top:px solid ;}`
  - These are invalid declarations that browsers and clients will drop.
- **Duplicate comment and class declarations:** `/* MOBILE SIDE PADDING */` appears twice. This is cosmetic.
- **Web fonts** (`TheFutureHOKA` via `@font-face` from `hoka.com`) are ignored by most clients. This is only an issue if the fallback font stack is missing, which the truncated source doesn't show.

## 4. Personalization & Merge Tokens
No issues found. The visible source shows no unresolved merge tags or tokens. The only unrendered values are in the CSS (see section 3), and the source is truncated, so the body copy wasn't fully checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **No plain-text part (FAIL).** QA reports "Text version is 0 chars". This hurts deliverability and accessibility, and some filters penalize HTML-only mail.
- **Unsubscribe link returned 403.** It is present, but see section 2. Functionality needs manual confirmation.
- **Not verifiable from the supplied data:** `List-Unsubscribe` and `List-Unsubscribe-Post` headers, SPF/DKIM/DMARC results, and the physical postal address. The source is truncated and no headers were provided.
- **Subject line** ends in a trailing invisible character (`stability ​`, likely a zero-width space). This is minor, but it indicates a template or copy-paste artifact.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **UTMs are present** on the decoded links: `utm_source=US_Broadcast`, `utm_medium=email`, and `utm_campaign=H_US_BR_20261006_Arahi9_Spotlight_GWP_STO_A60Day_365StabilityTag_...`.
- `utm_source` holds a send type ("Broadcast") rather than a platform or list, which limits attribution granularity.

- **Landing-page alignment** couldn't be checked, because only the `return-start` link was decoded and the Arahi 9 product links were not provided.

## 7. Recommendations
1. Add a plain-text alternative part.
2. Manually click the unsubscribe and `return-start` links in a real browser. If they fail there, fix the Cordial wrapper or the `options.hoka.com` endpoint. If they work, allowlist the QA user-agent.
3. Add descriptive `alt` text to every content image, and `alt=""` to the tracking pixels and any decorative images.
4. Remove the duplicate viewport meta. Keep one tag without `maximum-scale=1`.

6. Remove or populate the `.nav_padding` and `.nav_border` rules, and fix the template variable defaults.
7. Confirm both open-tracking pixels are intended, or drop one.
