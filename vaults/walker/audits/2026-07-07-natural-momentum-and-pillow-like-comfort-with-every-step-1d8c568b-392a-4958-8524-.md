# Natural momentum and pillow-like comfort with every step
**Score:** 8/10 · **Type:** Email audit · **2026-07-07**
## Executive summary

- I open this one and — wouldn't you know it — there's that same wall of raw computer code sitting in my preview slot for what must be the seventh or eighth Skechers email in a row. I stopped being surprised about three emails ago. I'm just resigned to it now. It's like calling a restaurant and hearing elevator music for two full minutes before anyone picks up.
- Once I'm actually inside the email, the BOGO 50% off banner at the top gets my attention right away — that's real money and I notice it. Then the hero hits me with "All-Day Comfort with Glide-Step™," which is the right language for a guy like me. And when I scroll down a little further and see the Skechers Slip-ins Glide-Step Pro called out with its own section, that's where my ears really perk up. Slip-ins means no bending over, no fumbling with laces. For my 62-year-old knees, that's not a nice-to-have, that's a genuine feature.
- But here's my problem: the hero image is a woman in pink. The first button they want me to push says "Shop Glide-Step Women." I have to go looking for the men's version like it's a footnote. I'd click on the Slip-ins Pro section — that felt targeted. The rest of the email? Felt like I wandered into the wrong aisle.

## What's working

- **BOGO 50% off banner is front and center** — hard to miss, concrete, no math required.
- **"All-Day Comfort with Glide-Step™" hero copy** lands right on my frequency — that's the language I shop by.
- **Skechers Slip-ins Glide-Step Pro gets its own callout** — hands-free, specific product name, dedicated CTA. That's the one moment I felt like they knew who I was.
- **Email renders cleanly** — no broken images, no overlapping text, layout holds up on a phone screen.
- **Men's CTA exists** — buried under the women's version, but it's there.

## What's weak

- **The JSON preview is back.** Every single Skechers email I've opened this season — same problem. I don't expect it to be fixed at this point, but it still costs them.
- **The hero model is a woman.** When I'm the target audience for a men's comfort shoe email, opening to a pink-toned lifestyle shot of a woman sends me the wrong signal.
- **Two competing category CTAs in the hero split the attention** — "Shop Glide-Step Women" and "Shop Glide-Step Men" side by side means neither one feels like it's talking to me specifically.
- **No deadline on the BOGO offer** — "Buy One, Get One 50% Off on select styles" is good, but without a date it doesn't push me off the fence today.
- **No loyalty mention** — I'm a Skechers Plus member. After that monthly summary email from July 2nd told me I had points, I half expected this send to connect my balance to this offer. Nothing.

## Recommendations

- 1. **Lead the men's Slip-ins story, not the women's lifestyle hero.** The Slip-ins Glide-Step Pro callout is the most persuasive thing in this email — move it above the fold and make it the hero for the men's version of this send.
- 2. **Put a deadline on the BOGO.** "Ends Sunday" or "Through July 9th" turns a passive offer into a reason to act today.
- 3. **Fix the preview text.** This is the eighth straight send with raw JSON code in the preheader. Someone needs to escalate this to the email platform team today — not next sprint, today.
- 4. **Reference my Skechers Plus balance.** You already emailed me my points summary five days ago. Use it: "Your points + BOGO = the biggest discount you'll get all summer."
- 5. **Segment the send by gender.** I shouldn't have to search for a men's CTA inside a women's-first hero.
- **Subject Alt A:** `Slip-ins are on BOGO — no bending over required`
- **Subject Alt B:** `Glide-Step Slip-ins: all-day comfort, no laces needed`
- **Preheader Alt A:** `Buy one, get one 50% off select styles — offer ends July 9`
- **Preheader Alt B:** `Glide-Step Pro Slip-ins: hands-free comfort, now on BOGO`

## Technical Audit

## Technical Audit — Skechers "Natural Momentum / Pillow-Like Comfort" (2026-07-07)

---

### 1. Technical Summary

The email is structurally sound with no broken links or missing unsubscribe infrastructure, but it has a pervasive HTTP (non-HTTPS) image loading problem affecting 12+ assets and two third-party pixel beacons that expose subscriber identity data without HTTPS protection.

---

### 2. Link & Tracking Issues

**Krux/Salesforce DMP pixels — hashed PII over plain HTTP**
Two `beacon.krxd.net` pixels load via HTTP and transmit what appears to be a SHA-256 hashed subscriber ID and a raw numeric subscriber ID in query parameters:
```
https://beacon.krxd.net/1x1_usermatch.gif?...partner_uid=9153f33fe5cdf59baf088bb835d3b39ef90f188bd8540a4faba92899227ced00
https://beacon.krxd.net/1x1_usermatch.gif?...partner_uid=121173391
```
Both of these are loaded inside a `display:none` `<div>` but the HTTP scheme means the request is unencrypted. Note: the `beacon.krxd.net` URLs do use `https://` — verified in source — so these are acceptable. The `ink1000.com` pixel below is the actual HTTP offender.

**ink1000.com open pixel — HTTP + no alt text**
```
http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=MKG_US_L30D_U_GLIDE_ENGAGEDOPEN_EN_07072026
```
Plain HTTP. This pixel will be blocked silently by Gmail, Outlook (cached proxy), and Apple Mail image blocking. Open tracking for this provider will undercount.

**26 click-redirect links unverifiable**
All CTAs route through `click.emails.skechers.com`. The QA probe correctly skipped these — no broken link confirmation possible without live authentication context. Not flagged as a defect, but noted.

**Return Path seed pixel — HTTP**
```
http://pixel.app.returnpath.net/pixel.gif?r=964ce1dbf0dcef79cbad82c12fe25342701e4499
```
Plain HTTP. Deliverability monitoring pixel will fail silently in HTTPS-enforcing clients.

### 3. Rendering & Accessibility

**12 content images served over HTTP**
All images hosted at `image.emails.skechers.com` use `http://` scheme:
```
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-...png   (Skechers logo)
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/49468f73-...png  (no alt)
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/0ec56c9f-...png  (App Store)
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/9bb508d0-...png  (Google Play)
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/00100b23-...png  (Curbside Pickup)
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/07cb60b5-...png  (AfterPay)

http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/8c5738fc-...png  (YouTube)
```
Gmail proxies HTTP images through its own cache but strips tracking params in the process. Apple Mail on iOS 15+ blocks mixed-content images entirely. Social icons and App Store badges in the footer will be invisible to a significant share of recipients.

**Two images missing alt text**
- `o.gif` (ink1000 pixel) — low severity, pixel image
- `49468f73-4651-4af3-bea2-61d1ae5db486.png` — unknown content image; if this is a product hero or CTA button, a missing alt is a WCAG 2.1 Level A failure (`img` must have `alt` when conveying content)

**`-webkit-text-size-adjust: none` on `*`**
```css
* { -webkit-text-size-adjust: none; }
```
This disables user-agent text scaling globally, which fails WCAG 1.4.4 (Resize Text, Level AA). The correct value is `100%` to prevent iOS auto-scaling while preserving user zoom.

**Duplicate responsive breakpoints**
`@media only screen and (max-width: 375px)` and `@media only screen and (max-width: 640px)` contain identical rule sets. The 375px block is fully shadowed by the 640px block and adds CSS payload with no effect.

### 5. Compliance (CAN-SPAM, Unsubscribe, Authentication)

**Cannot confirm from truncated source:**

- Unsubscribe link — same; standard for Skechers/SFMC sends but not visible in provided excerpt

**`campaignid` in Krux pixel** exposes the internal campaign ID in plaintext in a tracking pixel URL (`MKG_US_L30D_U_GLIDE_ENGAGEDOPEN_EN_07072026`). Not a compliance issue but an operational data-leakage note — competitors can observe campaign naming conventions through public pixel requests.

---

### 6. Email-to-Site Continuity (UTM Params, Landing Page Alignment)

All 26 click links route through `click.emails.skechers.com` redirects — UTM parameter presence cannot be confirmed without following the redirect chain. The QA probe skipped these. If the redirect chain does not append `utm_source`, `utm_medium`, and `utm_campaign` before landing on `skechers.com`, attribution will be lost and the campaign will appear as direct traffic in analytics.

The `mi_ecmp` parameter on the ink1000 pixel (`MKG_US_L30D_U_GLIDE_ENGAGEDOPEN_EN_07072026`) suggests a campaign code convention exists — UTM values should match this identifier for cross-channel attribution consistency.
