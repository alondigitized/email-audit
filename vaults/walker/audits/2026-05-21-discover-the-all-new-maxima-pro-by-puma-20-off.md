### 3. Rendering & Accessibility

**Issue 1 — Malformed charset meta:**
```html
<meta content="text/html;" charset="utf-8" />
```
The `http-equiv="Content-Type"` attribute is absent. As written, the `content` value is `"text/html;"` only — the charset is split off into a separate non-standard attribute. This meta is non-functional for content-type declaration. Correct forms:
- HTML5: `<meta charset="utf-8">`
- Legacy: `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">`

**Issue 2 — Malformed IE-edge meta:**
```html
<meta content="IE=edge" />
```
Missing `http-equiv="X-UA-Compatible"`. Non-functional as written. Correct form:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge">
```

**Issue 3 — `<head>` ordering:**
Two `<style>` blocks appear before the charset `<meta>`. The charset declaration must be the first tag in `<head>` (within the first 1024 bytes) to prevent encoding-based misparse. Current order: `<style>` → `<meta charset>`.

**Issue 4 — Dark mode not supported:**
```html
<meta name="color-scheme" content="light" />
<meta name="supported-color-schemes" content="light" />
```
Both are set to `light` only. Apple Mail and Outlook for Mac will attempt forced color inversion on light-only emails in dark mode, which can invert brand colors and make text unreadable. No `prefers-color-scheme: dark` media query is present in the visible CSS.

**Issue 5 — Four separate `<style>` blocks in `<head>`:**
Functional in major clients, but consolidating reduces parser surface and file size. Minor.
