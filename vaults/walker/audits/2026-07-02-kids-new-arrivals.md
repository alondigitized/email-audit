# Kids' new arrivals
**Score:** 7/10 · **Type:** Email audit · **2026-07-02**
## Executive summary

- I looked at this for about two seconds before I figured out what was happening. "Kids' new arrivals." The whole email — top to bottom — is kids' shoes and kids' hoodies. 990 Lace in little-kid sizing. A "Never too young for style" headline over a photo of children. Three CTAs: babies, little kids, big kids. Not one adult men's shoe in sight.
- Here's the thing: I've gotten six or seven New Balance emails in the last two weeks. They had me — actually had me — with that June 26th "Your feet just know" send, even if the hero model skewed young. I went back and looked, and I swear I saw a kids' send around June 11th too, based on what I noted in the June 20th email. So we're doing this again. Same wrong audience, same misfire.
- I am not clicking. I'm not forwarding this to anyone unless I'm showing a grandkid who needs sneakers. Straight to archive.

## What's working

- **The layout is clean and readable.** Even on a small phone screen, the shoe grid is easy to scan — big images, names underneath, nothing cluttered.
- **Free shipping threshold is visible right at the top.** "$75" is clear. That's the kind of upfront honesty I respect.
- **New Balance is a name I trust.** I'd never delete this sender, even when they miss like this.
- **No broken images, no overlapping text.** It rendered perfectly. The execution quality is fine; the problem is the targeting.

## What's weak

- **I am 62 years old. This email is for my grandchildren's feet, not mine.** There is not a single men's shoe anywhere in this email. Not in the nav, not in a footer cross-sell, nowhere.
- **"Styles you won't want to miss" as the preview.** Generic filler — same energy as "Now's your chance" back in June. After seven emails in two weeks, I'm running low on patience for lazy preview copy.
- **This is at minimum the second kids' email I've gotten from them this month.** The cadence is already heavy; sending me off-segment content on top of that is how you get unsubscribes.
- **No men's comfort content anywhere — not even a "while you're here" banner.** If you're going to send this to your whole list, at least throw a men's category link in the nav or footer for the people you accidentally included.

## Recommendations

- 1. **Segment this send to parents and households with kids — not to a list of adult men who buy men's shoes.** This is the highest-leverage fix. Nothing else matters if the list is wrong.
- 2. **If you must blast the full list, include a "Shop Men's" rescue banner** before the footer — one line, one button. Costs nothing, catches the stray.
- 3. **Rest the cadence.** Seven emails in two weeks, and one of them is kids' arrivals to a guy who wears a size 11D. Give it a few days.
- 4. **Preview text needs a job.** "Styles you won't want to miss" is a throwaway line I've seen a dozen times. If you must send a kids' email broadly, at least lean into the hook: something like "summer kicks for every kid on your list."

- **Preheader Alt A:** `Fresh arrivals in sizes toddler through big kid — shop before they sell out`
- **Preheader Alt B:** `Running, school, play — new kids' shoes for every occasion`

### 3. Rendering & Accessibility

**[HIGH] Unreplaced background image placeholder**
```css
.bgwhite { background-image: url('http://image.XXXXX.png'); }
```
`XXXXX` is an unfilled template token. Any element using `.bgwhite` will attempt a broken HTTP image request and fail silently or produce a broken background in clients that render it.

**[HIGH] `@font-face` declarations missing `src:` property**
All nine `@font-face` blocks declare `font-family` and weight/style but contain no `src:` value. Example:
```css
@font-face { font-family: proxima-nova,sans-serif; font-weight: 700; font-style: normal; }
```
Without `src:`, no custom fonts will load in any client. Fallback fonts (Arial, Times New Roman) will render everywhere. This appears to be a template wiring failure — the ESP font-hosting URLs were never injected.

**[MEDIUM] `.bg1` class defined twice with conflicting values**
```css
/* Definition 1 (line ~8): */
.bg1 { background-color: #ffffff; }

/* Definition 2 (later in stylesheet): */
.bg1 { background: #58546d; }
```
The second definition wins via cascade. `#58546d` (muted purple-gray) is inconsistent with the white-background template and likely an accidental import from a different template variant.

**[LOW] Malformed IE compatibility meta tag**
```html
<meta content="IE=edge" />
```
Missing `http-equiv="X-UA-Compatible"`. Should be:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Negligible impact today but reflects a template defect.

**[LOW] Duplicate `font-family` property in bold-italic `@font-face` block**
```css
@font-face { font-family: proxima-nova,sans-serif; font-weight: 700; font-style: italic; font-family: proxima-nova,sans-serif; }
```
Duplicated `font-family` property — second value overrides the first (same value here, so no functional impact, but signals copy-paste error in template).
