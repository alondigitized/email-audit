### 3. Rendering & Accessibility

**`maximum-scale=1` blocks user zoom (WCAG 1.4.4 violation)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents text scaling in mobile browsers. Affects users with low vision. Should be removed or changed to `maximum-scale=5`.

**`text-size-adjust: none` applied globally**
```css
* { -ms-text-size-adjust: none; text-size-adjust: none; }
```
The `none` value (vs `100%`) is non-standard and can cause unpredictable reflow in some mobile clients (Samsung Mail, older Android WebView). Change both to `100%`.

**`charset` meta missing `http-equiv` attribute**
```html
<meta content="text/html; charset=utf-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, the charset declaration is invalid in XHTML and may not be honored by Outlook's rendering engine.

**Capitalized `Src:` property in `@font-face` declarations**
All 10 `@font-face` blocks use `Src:` (capital S) instead of the spec-required lowercase `src:`. Most parsers tolerate this, but it is invalid CSS and will silently fail in strict parsers.
```css
/* Wrong */
Src: url("https://braze-images.com/...") format('woff');
/* Correct */
src: url("https://braze-images.com/...") format('woff');
```

**Futura_PT fonts served as `.woff` only — no `.woff2`**
Modern clients (2019+) prefer `.woff2` for ~30% smaller payloads. HelveticaNow correctly uses `.ttf` but Futura_PT has no format fallback within the declaration.

**Inconsistent cache-busting on font URLs**
HelveticaNow fonts include a cache-busting query string (`?1755182939`), Futura_PT fonts do not. This is a deployment consistency issue — if Futura_PT assets are updated, clients will serve stale cached versions.
