## Technical Audit

## 1. Technical Summary
The email renders from a shared template with leftover placeholder code (`<title>New Balance Template</title>`, a `http://image.XXXXX.png` background URL). QA shows 3 images with no alt attribute and a plain-text part that is almost entirely URLs. The HTML was truncated and no link-probe results were supplied, so the link, compliance and UTM checks below are limited.

## 2. Link & Tracking Issues
- **Probe coverage:** 12 material links were probed and 27 skipped. No probe failures were reported, so I found no broken links. The 27 skipped links (footer, social, utility) are unverified.
- **Plain-text part:** 13,188 of 14,933 characters (~88%) are URLs. This is above the 70% warning threshold and suggests the text alternative is mostly raw tracking links. That pattern is a spam-filter signal and reads poorly in text-only clients.
- **Redirect wrapper:** Assets and tracking are served from `link.email.newbalance.com`, including the `/mo/egR1f966kc_818512772_12590487_244758_23771396.gif` open pixel. I found no issue with the wrapper itself.
- **Placeholder URL:** `.bgwhite { background-image: url('http://image.XXXXX.png'); }` is in the stylesheet. It is a non-resolving, non-HTTPS placeholder, and any element using `.bgwhite` will request it. The truncated HTML doesn't show whether any element does.

## 3. Rendering & Accessibility
- **Missing alt (confirmed by QA):**
  - `ShippingIcons_06.png`
  - `ShippingBanner_DarkMode_03.png`
  - `egR1f966kc_…gif` (the open-tracking pixel). Give it `alt=""`, since it is decorative.
- **Reused welcome assets:** The two shipping images sit under `/custloads/818512772/NBUS/myNB_Welcome/UpdatedImages/`. They were likely reused from a welcome-series template. If the shipping banner carries offer or shipping terms, the missing alt text hides that content from screen readers and image-blocked clients.
- **Template defects in the `<head>`:**
  - `<title>New Balance Template</title>` is a placeholder. It is exposed in webmail tab titles and "view in browser" pages.
  - `<meta content="IE=edge" />` has no `http-equiv`, so it does nothing.
  - `.bg1` is declared twice with conflicting values (`#ffffff`, then `#58546d`). The later rule wins, which may not be intended.
  - Every `@font-face` block lacks a `src`, so no web fonts load. Text falls back to `Arial,sans-serif` and `Times New Roman,serif` for the Didot classes.
- **Doctype mix:** The doctype is HTML 4.01 Transitional but the `<html>` tag carries an `xmlns` attribute. This is harmless but inconsistent.
- **Dark mode:** `color-scheme` meta tags and a `prefers-color-scheme` block are present. I saw no issue in the visible portion.

## 4. Personalization & Merge Tokens
No issues found. The visible HTML contains no unresolved merge tokens. The `XXXXX` string is a template placeholder in CSS, not a personalization field.

The subject appears as `25% off your order of $125+ ends soon., 25% off your order of $125+ ends soon.`, with the string repeated. If this reflects the actual Subject header and not a capture artifact, it is a template or ESP concatenation bug. Confirm against the raw header.

## 5. Compliance
- **Authentication:** `Authentication-Results` was not found. The QA note attributes this to the AgentMail relay, so SPF, DKIM and DMARC are unverified. This is a limit of the test setup and not evidence of a sender failure.
- **Unsubscribe:** QA says an unsubscribe link is always probed, but no result or URL was supplied. The footer was beyond the truncated HTML, so I can't confirm the unsubscribe link, the physical address, or `List-Unsubscribe` / `List-Unsubscribe-Post` headers.
- **From address:** `newbalance@email.newbalance.com` is a branded subdomain.

## 6. Email-to-Site Continuity
Not assessable. No destination URLs or UTM parameters appear in the truncated source, and no landing-page probe results were provided. The links likely go through the `link.email.newbalance.com` redirect wrapper, so UTMs would only show after resolving it.

## 7. Recommendations
1. Remove or replace `http://image.XXXXX.png` and the unused `.bgwhite` rule, and set a real `<title>`.
2. Add `alt` to `ShippingIcons_06.png` and `ShippingBanner_DarkMode_03.png`, and `alt=""` to the tracking pixel.
3. Trim the plain-text part to a shorter, readable text alternative, or reduce the number of tracked URLs in it.
4. Fix `<meta http-equiv="X-UA-Compatible" content="IE=edge">` and remove the duplicate `.bg1` rule.
5. Add `src` to the `@font-face` blocks or drop them, since they currently do nothing.
6. Check the raw Subject header for the duplicated string.
