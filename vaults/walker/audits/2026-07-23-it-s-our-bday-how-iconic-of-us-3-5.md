### 3. Rendering & Accessibility

**`Src:` capitalization bug in all `@font-face` declarations — HIGH severity**

All 8 `@font-face` blocks use `Src:` (capital S) instead of the valid CSS property `src:`. CSS property names are case-sensitive in `@font-face` context. Every major email client (Apple Mail, Gmail, Outlook) will silently skip the invalid property and fall back to system fonts. Affects all four Futura PT variants and all six HelveticaNow variants:

```css
/* BUG — invalid property name, will be ignored */
Src: url("https://braze-images.com/appboy/communication/assets/font_assets/files/67dd7a3bf1de1d0066403c87/original.woff") format('woff');

/* CORRECT */
src: url("...") format('woff');
```

**Missing `http-equiv` on charset meta**

```html
<!-- Current — not standards-compliant -->
<meta content="text/html; charset=utf-8" />

<!-- Correct -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

Without `http-equiv="Content-Type"`, older Outlook and some webmail clients may not honor the charset declaration, risking character encoding display issues in the subject line (which contains multi-byte emoji).

**`maximum-scale=1` blocks user zoom**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

`maximum-scale=1` prevents pinch-to-zoom on mobile. This violates WCAG 1.4.4 (Resize Text, Level AA). Remove the `maximum-scale` constraint.

**No `lang` attribute on `<html>` element**

```html
<html xmlns="http://www.w3.org/1999/xhtml">
```

Missing `lang="en"` (or appropriate locale). Screen readers cannot determine language, affecting pronunciation and accessibility tools.

**Inconsistent `text-size-adjust` values**

```css
-webkit-text-size-adjust: 100%;  /* allows adjustment */
-ms-text-size-adjust: none;      /* disables adjustment entirely */
text-size-adjust: none;
```

`-ms-text-size-adjust: none` is more aggressive than the WebKit counterpart. On Windows IE/Edge mobile, this can cause text to render at unintended sizes. Standard practice is `100%` across all prefixes.

**HelveticaNow fonts load as `.ttf` only — no `.woff` or `.woff2`**

```
https://braze-images.com/.../original.ttf?1755182939
```

Futura PT loads as `.woff`; HelveticaNow loads as `.ttf` with no format fallback. `.ttf` has wider support than `.woff2` but larger file size. More importantly, the `Src:` bug above means none of these load regardless.
