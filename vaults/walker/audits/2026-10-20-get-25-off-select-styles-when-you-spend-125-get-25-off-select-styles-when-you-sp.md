## Technical Audit

## 1. Technical Summary
The email is a Salesforce Marketing Cloud-style template (tracking on `link.email.newbalance.com`) with leftover placeholder code, a malformed subject line and three images without `alt`. The HTML provided is truncated and there are no header or landing-page data, so the compliance and continuity checks are mostly unverifiable.

## 2. Link & Tracking Issues
- **No broken links found.** 12 material links were probed and no failures were reported. 26 were skipped as footer, utility and social links, so those are unverified.
- **Placeholder asset URL in CSS:** `.bgwhite {… background-image: url('http://image.XXXXX.png'); }` is an unresolved template placeholder. It is also plain `http://`, so it would trigger mixed-content blocking and a 404 for any element using `.bgwhite`.
- **Plain-text part is mostly URLs:** 12,348 of 14,078 characters (about 88%) are URLs. The long tracking-redirect URLs dominate the text part, which can raise spam scoring. It also makes the text version hard to read.
- **Open-tracking pixel:** `https://link.email.newbalance.com/mo/egR1f966kc_818512772_12476889_275037_23529351.gif` is a tracking pixel. That is expected, but see the `alt` issue below.

## 3. Rendering & Accessibility
- **Three images lack `alt` text:**
  - `ShippingIcons_06.png`
  - `ShippingBanner_DarkMode_03.png`
  - the tracking pixel `…/mo/egR1f966kc_….gif`
- **Decorative images need `alt=""`:** The pixel (and the icons, if purely decorative) should carry an explicit empty `alt`. `ShippingBanner_DarkMode_03.png` likely carries shipping-offer text. If so, the message is lost to screen readers and to clients that block images.
- **Template title not updated:** `<title>New Balance Template</title>` is a placeholder. It is exposed in some clients and web views.
- **Malformed meta tag:** `<meta content="IE=edge" />` has no `http-equiv` attribute, so it does nothing.
- **Doctype mismatch:** The HTML 4.01 Transitional doctype is paired with an `xmlns` attribute and self-closing tags. This is low risk in email clients.
- **Conflicting `.bg1` rules:** `.bg1` is declared twice in the stylesheet (`#ffffff`, then `#58546d`). The later rule wins, so any element using `.bg1` renders purple-grey in light mode unless it is inline-styled.
- **Web fonts have no source:** The `@font-face` blocks (`proxima-nova`, `linotype-didot`) shown have no `src`. They are no-ops, and rendering falls back to Arial or Times New Roman.
- **Dark-mode support is declared:** The email has `color-scheme` meta tags and a `prefers-color-scheme` block. Only the first part of that block was visible, so dark-mode coverage is unverified.

## 4. Personalization & Merge Tokens

The same string appears twice, joined by a stray ` ,` (space before the comma). This looks like a subject and preheader concatenation, or a merge field populated with the same value twice.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)

4. Update `<title>`, and fix the `<meta http-equiv="X-UA-Compatible" content="IE=edge">` tag.

7. Re-run the QA on the full HTML and the raw headers. Confirm SPF/DKIM/DMARC, `List-Unsubscribe`, the postal address, final landing URLs and UTM parameters.
