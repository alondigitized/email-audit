## Technical Audit

## 1. Technical Summary
The email's HTML carries leftover template artifacts (placeholder `<title>`, a placeholder background URL, a malformed meta tag) and has two images with no alt text. Link health, unsubscribe and authentication could not be verified from the data provided: the source is truncated, 11 of 12 links were not probed, and there is no Authentication-Results header.

## 2. Link & Tracking Issues
- **Link health is mostly unverified.** QA probed 1 of 12 material links and skipped 11, so destination status codes, redirect chains and CTA targets are unconfirmed.
- **Placeholder asset URL in CSS.** `.bgwhite {background-image: url('http://image.XXXXX.png');}` points to a non-existent host.
  - It is also plain `http://`, which triggers mixed-content/insecure-resource warnings in some clients.
  - It only matters if `.bgwhite` is actually applied in the body, which the truncated source can't confirm.
- **Image path from a different template.** `…/custloads/818512772/NBUS/myNB_Welcome/UpdatedImages/ShippingBanner_DarkMode_03.png` is hosted under a `myNB_Welcome` folder. This suggests a reused welcome-series asset. Confirm the asset is meant to be shared and won't be removed when that campaign is retired.
- **Tracking pixel.** `https://link.email.newbalance.com/mo/egR1f966kc_818512772_12645621_315753_23888754.gif` is the open-tracking pixel, and it has no alt text (see section 3).

## 3. Rendering & Accessibility
- **Missing alt text on 2 images (QA-confirmed):**
  - `ShippingBanner_DarkMode_03.png` is a content banner and needs a descriptive alt. With images blocked, the shipping message is lost.
  - `egR1f966kc_…gif` is the tracking pixel and should have `alt=""`.
- **Malformed meta tag.** `<meta content="IE=edge" />` has no `http-equiv="X-UA-Compatible"`, so it does nothing.
- **Placeholder `<title>`.** `<title>New Balance Template</title>` was never updated. Some clients and web-view versions surface it.
- **No `lang` attribute.** `<html xmlns="http://www.w3.org/1999/xhtml" style="color-scheme:light dark;…">` has no `lang`, which screen readers need to pick a pronunciation.
- **Doctype/namespace mismatch.** The HTML 4.01 Transitional doctype is paired with an XHTML `xmlns`.
- **`@font-face` blocks with no `src`.** The `linotype-didot`, `proxima-nova` and other declarations have no `src`, so they are invalid and never load a web font. The `fst10` and `fst12` styles on linotype-didot fall back to `Times New Roman`, and the `proxima-nova` styles fall back to Arial.
- **Duplicate `.bg1` rule.** It is defined as `background-color:#ffffff` and later as `background:#58546d`, so the last one wins.
- **Dark-mode link override.** `@media (prefers-color-scheme: dark) { a {color:#cf0a2c !important;} … }` forces red on every link. Contrast on the `#151415` dark background needs checking, though I can't confirm that from the truncated source.
