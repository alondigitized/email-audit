## Technical Audit

## 1. Technical Summary
The email has one confirmed broken-experience bug, an empty greeting slot (`Hi ,`). It also has several markup and infrastructure defects: a protocol-less tracking pixel URL, malformed `<meta>` tags, and plain-HTTP image sources. The source was truncated, so link, UTM and footer checks could not be completed.

## 2. Link & Tracking Issues
- **Broken pixel URL.** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…" width="1" height="1" />` has no scheme. Clients resolve it as a relative path, so the request never reaches Return Path and the seed/deliverability pixel is lost. It also has no `alt` attribute.
- **Plain-HTTP sources.**
  - `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=…&mi_ecmp=MKG_US_NA_U_COLOR_ENGAGEDL60D_EN_10042026`
  - `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png`
  - The second is a content image on the brand's own image domain. It may be blocked or rewritten by clients that enforce HTTPS, and it can trigger mixed-content handling.
- **Unverified links.** 29 tracking links were skipped by the HTTP probe (click-redirect domains). Their resolution and destinations are unconfirmed.
- **Many third-party pixels.** Four `beacon.krxd.net` pixels, `ink1000.com` and `returnpath.net` all sit in the hidden `display:none` block. Several have no `alt` attribute (the three krxd `1x1_usermatch`/`1x1_ad_impression` pixels and the returnpath pixel). Clients that load images regardless of `display:none` will fire them.

## 3. Rendering & Accessibility
- **Malformed meta tags.** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv` attribute, so neither declaration takes effect. The charset then depends solely on the transport header.
- **Zoom blocked.** `<meta name="viewport" content="…maximum-scale=1" />` blocks pinch-zoom (WCAG 1.4.4). `* { -webkit-text-size-adjust: none }` also stops iOS text resizing.
- **Focus outline removed.** `a { outline: none }` removes the focus indicator for keyboard and assistive-tech users.
- **Alt text.**
  - The QA flag on `o.gif` is a false positive: the source shows `alt=""`, which is correct for a tracking pixel.
  - The `dde00662-…png` image was flagged for missing alt, but its tag is truncated, so this can't be confirmed from the source shown.
  - The returnpath and krxd pixels have no `alt` at all.
- **Missing structure.** `<html>` has no `lang` attribute. The layout tables visible in the source (e.g. `<table class="widthFull" width="640" …>`) have no `role="presentation"`. The generic `<title>Skechers®</title>` doesn't describe the email.
- **Preheader.** `<div class="preheader" style="font-size:1px;display:none !important">` is present. No trailing whitespace padding is visible in the shown source, so body text may bleed into the inbox preview. This is unconfirmed because of truncation.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot.** The QA check found `Hi ,`, so the first-name merge field rendered empty and there is no fallback value. The source shown is truncated before the greeting, so only the QA result confirms it. A default such as `Hi there,` is needed.
- The subscriber-specific values in the pixels (`partner_uid=121173391`, `mi_u=8107766165`, the hashed `partner_uid=9153f33f…`) resolved, so those merge fields work.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Not verifiable.** The truncated source ends before the footer, so the unsubscribe link, physical postal address and sender identification could not be checked. No raw headers (SPF, DKIM, DMARC, `List-Unsubscribe`, `List-Unsubscribe-Post`) were provided.
- **Data-sharing disclosure.** `https://beacon.krxd.net/1x1_usermatch.gif?partner=LprH63a7_sfmc_100007688_sha25&partner_uid=9153f33f…ed00` sends what is labelled a SHA-256 hash, apparently of the subscriber's email, plus the subscriber ID to a third-party data platform (Krux/Salesforce). Confirm that the privacy policy and consent flow cover this.
- **From domain.** `no-reply@emails.skechers.com` is a no-reply sender. This is a deliverability and reply-handling note, not a violation.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- No issues could be confirmed. All 29 click links were unprobed and the visible source contains no destination URLs, so UTM parameters and landing-page alignment are unverified.
- The only campaign identifier in the source is `MKG_US_NA_U_COLOR_ENGAGEDL60D_EN_10042026`, in the krxd and ink1000 pixels. Check that the click links carry the same campaign ID.

## 7. Recommendations
1. **Fix the greeting.** Add a fallback to the first-name merge field (e.g. `%%=Iif(Empty(@firstName),"there",@firstName)=%%`), or drop the name when it is empty.
2. **Fix the returnpath pixel.** Use `https://pixel.app.returnpath.net/pixel.gif?r=…` and add `alt=""`.
3. **Switch to HTTPS.** Change `http://image.emails.skechers.com/…/dde00662-….png` and the `ink1000.com` pixel to `https://`. Confirm that the image domain serves a valid certificate.
4. **Repair the meta tags.** Use `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` and `<meta http-equiv="X-UA-Compatible" content="IE=Edge" />`.
5. **Fix accessibility.**
   - Remove `maximum-scale=1`.
   - Add `lang` to `<html>`.
   - Add `role="presentation"` to layout tables.
   - Add `alt=""` to the remaining pixels.
   - Restore a focus style on links.
6. **Re-run QA on the full HTML.** Include the footer and the raw headers, and probe the 29 tracking links with a click-domain-aware checker. This would confirm the unsubscribe link, postal address, `List-Unsubscribe`, authentication results and UTM consistency.
7. **Review the third-party pixel stack.** The krxd and ink1000 beacons add load and privacy exposure for little benefit if they aren't actively used.
