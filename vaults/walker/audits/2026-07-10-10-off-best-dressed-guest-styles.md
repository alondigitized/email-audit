### 3. Rendering & Accessibility

**`http-equiv` missing on two `<meta>` tags:**
- `<meta content="text/html; charset=utf-8" />` — missing `http-equiv="Content-Type"`. Some legacy clients (Outlook, older Yahoo) won't honor charset declaration without this attribute, risking encoding fallback to ISO-8859-1.
- `<meta content="IE=Edge" />` — missing `http-equiv="X-UA-Compatible"`. The IE conditional rendering directive has no effect without the `http-equiv` attribute.

**`text-size-adjust` inconsistency in reset:**
```css
*{
  -ms-text-size-adjust: 100%;
  -webkit-text-size-adjust: 100%;
  text-size-adjust: none       /* conflicts with prefixed 100% above */
}
```
Unprefixed `none` and prefixed `100%` are contradictory. In browsers that now support the unprefixed property (Firefox 116+), this disables user text-size adjustment entirely rather than capping it.

**`maximum-scale=1` accessibility violation:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents zoom on mobile. WCAG 1.4.4 (Resize Text, Level AA) requires text to be resizable to 200% without loss of content. This is a known accessibility failure mode, particularly for low-vision users on mobile.

**`supported-color-schemes` in `:root` CSS:**
```css
:root {
  color-scheme: light dark;
  supported-color-schemes: light dark;  /* not a valid CSS property */
}
```
`supported-color-schemes` is only valid as an HTML `<meta name>` attribute (already present in `<head>`), not as a CSS property. The CSS declaration is a no-op.

**Near-black color hack `#000001`:**
Used in `.dm-font-black` and mobile `.border-top-black`. This is an intentional workaround to prevent certain clients (Gmail dark mode) from auto-inverting pure `#000000`. Technically functional but worth noting as a known client-specific hack, not a standard pattern.
