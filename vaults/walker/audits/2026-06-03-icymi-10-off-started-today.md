### 3. Rendering & Accessibility

**DEFECT — Invalid `Src:` property in all 10 `@font-face` blocks.**
CSS property names are case-sensitive in spec. All font declarations use uppercase `Src:` instead of `src:`. Most modern clients are forgiving, but strict CSS parsers (some webmail, older Outlook rendering engines) will skip the declaration entirely, causing silent font fallback to the stack default.

Affected declarations: `Futura_PT_Regular`, `Futura_PT_Medium`, `Futura_PT_Demi`, `Futura_PT_Bold`, `HelveticaNow_Regular`, `HelveticaNow_Medium`, `HelveticaNow_MediumItalic`, `HelveticaNow_Bold`, `HelveticaNow_BoldItalic`, `HelveticaNow_Italic`.

**DEFECT — `maximum-scale=1` in viewport meta.**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocks pinch-to-zoom on iOS Safari. WCAG 1.4.4 (Resize Text, Level AA) requires that text can be resized up to 200% without loss of content. This fails that criterion.

**DEFECT — `text-size-adjust: none` in global reset.**
```css
* { -ms-text-size-adjust: none; text-size-adjust: none }
```
The `none` value (as opposed to `100%`) actively disables OS-level text scaling. The `100%` value is the correct fix — it prevents auto-inflation while still honoring user accessibility settings. `none` is a known WCAG failure pattern.

**Minor — inconsistent cache-busting on font URLs.**
HelveticaNow fonts include a timestamp query string (`?1755182939`); Futura PT fonts do not. If the Futura PT assets are ever updated at the same CDN path, recipients' clients may serve stale files indefinitely.
