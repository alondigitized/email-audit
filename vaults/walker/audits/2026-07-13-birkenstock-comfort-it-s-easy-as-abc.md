### 3. Rendering & Accessibility

**Confirmed issues:**

**A. Malformed charset meta tag**
```html
<meta content="text/html;" charset="utf-8" />
```
Missing `http-equiv="Content-Type"` (required for HTML 4.01 Transitional). The `content` attribute is also truncated — it should be `content="text/html; charset=utf-8"`. Current form mixes HTML5 shorthand (`charset=`) with HTML 4.01 doctype inconsistently.

**B. Malformed IE compatibility meta**
```html
<meta content="IE=edge" />
```
Missing required `http-equiv="X-UA-Compatible"` attribute. As written, this tag is a no-op.

**C. Charset declaration out of position**
The `<meta charset>` tag appears *after* the first `<style>` block. Per spec, charset must be declared within the first 512 bytes of the document and before any character-dependent content. This ordering risks encoding misinterpretation in some renderers.

**D. Light-mode forced, no dark mode support**
```html
<meta name="color-scheme" content="light" />
<meta name="supported-color-schemes" content="light" />
```
Dark mode is explicitly excluded. Apple Mail (iOS/macOS) and Outlook for Mac will not apply system dark mode. If images or backgrounds use white (`#FFFFFF`) as a base color, dark mode users may see inverted or clipped rendering. No `@media (prefers-color-scheme: dark)` block is present.

**E. Responsive breakpoint gap (601–660px)**
```css
/* Block 1 */ @media only screen and (max-width: 600px) { ... }
/* Block 3 */ @media only screen and (max-width: 660px) { ... }
```
Different rules target overlapping but non-identical ranges. The 601–660px band receives Block 3 rules but not Block 1 rules. This is a common window for landscape phone and small tablet viewports.

- `role="presentation"` on layout tables
- Heading hierarchy
