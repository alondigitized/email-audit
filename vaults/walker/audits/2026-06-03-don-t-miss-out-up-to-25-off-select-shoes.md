# Don't miss out – up to 25% off select shoes
**Score:** 8/10 · **Type:** Email audit · **2026-06-03**
## Executive summary

- Fourth or fifth time I've opened a "25% off select shoes" email from New Balance in the last few weeks. At this point my finger knows where the delete button is before the email finishes loading. The hero image is a stack of red shoe boxes — which is a nice visual but tells me absolutely nothing about whether any of those boxes contain something comfortable, wide, or easy to get on and off. "Don't delay" is the headline, and all I can think is: delay what, exactly? This is the same sale they've been running since late May.
- The email renders cleanly, the Men/Women/Kids shop buttons are easy to tap, and I did notice a "More to explore" section with actual shoe names — the Fresh Foam Arishi caught my eye because "Fresh Foam" at least hints at cushioning. But there's nothing here that feels like New Balance is talking *to me* versus blasting everyone on their list.
- I'll mark it as read. I won't click. And I won't forward it — my buddy Phil already got this email.

## What's working

- **Clean layout, no clutter.** Big image at top, simple "Shop the sale" block, then a few featured shoes — easy to scan on my phone without squinting.
- **Free shipping callout is right at the top.** That always catches my eye; $75 threshold is reasonable.
- **Specific shoe names in "More to explore."** 574 Core Lace, Fresh Foam Arishi v4 — at least I can see real product names, not just "shoes on sale."
- **Men | Women | Kids segmentation buttons** are large, easy to tap, and get me one click closer to a filtered view.
- **No broken images, no layout issues.** This one rendered fine.

## What's weak

- **Same sale, same subject line format, again.** I've received near-identical "25% off select shoes" emails multiple times this month. The brand goodwill from the 9060 and the '70s tech story emails is burning up fast.
- **Hero image is shoe boxes, not shoes.** Stacked red boxes look premium but tell me nothing about fit, comfort, or what's actually on sale. A single cushioned men's walking shoe would've done more work.
- **"Don't delay" headline is empty.** No specific date, no countdown — just vague urgency. The deadline (June 5) is buried in fine print I'd need to squint to read.
- **Zero comfort or fit language above the fold.** Nothing about cushioning, arch support, wide sizing, or slip-on options — the things that actually make me buy. I have to hunt for it.
- **"Log in or create an account" CTA mid-email is a stumbling block.** I'm browsing on my phone and that button just slows me down.

## Recommendations

- 1. **Rotate the hero to a specific comfort shoe and call out the fit.** "Men's Fresh Foam Arishi — now 25% off. Cushioned. Easy on." One shoe, one benefit, one price. That's the email.
- 2. **Name the deadline in the headline.** Change "Don't delay" to "Sale ends June 5" — I now have a reason to act, not just FOMO language that I've learned to ignore.
- 3. **Add a "Comfort & Wide Fit" shop button** alongside Men/Women/Kids. That's what I'm actually looking for in every email.
- 4. **Drop "Log in or create an account" from the body.** Push that to the cart page; mid-email it's friction.
- 5. **Retire the 25% off drumbeat for at least one more send.** Two product-story emails in a row (the 9060, the '70s tech one) built more interest than five sale repeats. Trust the product.

- **Subject Alt B:** `Sale ends Friday: your comfort picks are marked down`
- **Preheader Alt A:** `Men's cushioned styles included — shop before it's gone`
- **Preheader Alt B:** `Free shipping on $75+. Wide-fit options included.`

### 2. Link & Tracking Issues

The string `XXXXX` is an un-substituted template token. Any element using `.bgwhite` will 404 on the background image. Additionally, the URL uses `http://` — a mixed-content violation in clients that enforce HTTPS (Gmail strips insecure resource loads).

### 3. Rendering & Accessibility

**Duplicate `.bg1` class — conflicting definitions (MEDIUM)**

The stylesheet defines `.bg1` twice with different values:
```css
/* First declaration */
.bg1 { background-color: #ffffff; }

/* Second declaration — overrides the first */
.bg1 { background: #58546d; }
```
The second definition (a dark slate/purple) wins via cascade. Any element expecting a white background via `.bg1` will render dark. This is almost certainly unintentional.

**`@font-face` blocks have no `src:` property (MEDIUM)**

All nine `@font-face` rules declare `font-family`, `font-weight`, and `font-style`, but none include a `src:` URL:
```css
@font-face { font-family: linotype-didot,serif; font-weight: 400; font-style: normal; }
@font-face { font-family: proxima-nova,sans-serif; font-weight: 700; font-style: normal; }
/* ... same pattern for all nine */
```
These declarations are no-ops — no font file is referenced, so the browser/client has nothing to load. If fonts are loaded via an Adobe Fonts `<link>` elsewhere in the `<head>`, these declarations are redundant and can be removed. If they're the sole font-loading mechanism, custom fonts will silently fall back to `Arial` / `Times New Roman`.

**Malformed IE compatibility meta tag (LOW)**
```html
<meta content="IE=edge" />
```
Missing the required `http-equiv="X-UA-Compatible"` attribute. Should be:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Negligible impact today but technically malformed.

**Dark mode implementation** — Correctly declared via both `<meta name="color-scheme">` and `@media (prefers-color-scheme: dark)`. No issues in the visible portion.
