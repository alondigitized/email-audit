## 4. What's Weak

## Technical Audit

## Technical Summary

The Skechers mobile journey has three categories of issues: a bot-detection SDK in a rate-limit loop that blocks the cart page, a View Cart page missing fundamental HTML document metadata (title + lang), and an excessive third-party script payload that will suppress LCP/TTI on mobile. TTFB is healthy (25–34ms) everywhere except View Cart (120ms), which correlates with the 429 on `/cart/`.

---

## Accessibility

**16 violations across 3 pages.**

**Homepage (9 violations):**
- `aria-required-parent` [critical] — ARIA role used on an element not contained by its required parent. Likely a carousel or listbox component missing its wrapper role.
- `link-name` [serious] — One or more `<a>` elements have no discernible text. Common cause: icon-only links with no `aria-label`.
- `landmark-main-is-top-level`, `landmark-no-duplicate-main`, `landmark-unique` [moderate] — Multiple `<main>` elements detected, or `<main>` is nested inside another landmark. Indicates the page shell is wrapping content incorrectly.
- `heading-order` [moderate] — Heading levels skip (e.g., `<h1>` → `<h3>`).
- `aria-allowed-role` [minor] — Explicit role on element where it is redundant or invalid.

**View Cart (4 violations) — highest severity path:**
- `document-title` [serious] — `<title>` is empty or absent. This is a hard failure for screen readers and for Google's indexing of cart pages.
- `html-has-lang` [serious] — `<html>` has no `lang` attribute. Likely the cart renders as a client-side overlay or SPA shell that does not inherit or re-emit the lang attribute on route change.
- `landmark-one-main` + `page-has-heading-one` [moderate] — No `<main>` and no `<h1>`, confirming the cart view is not a real document but an injected UI layer with incomplete document semantics.

**Search results (3 violations):**
- Duplicate/nested landmark and uncovered content regions — same pattern as homepage.

---

## SEO

- **View Cart missing `<title>`** is a direct indexability defect. If Googlebot crawls `/cart/` (common for shared-cart or gift-link flows), it will receive an untitled page.
- LCP and CLS data was not captured for any step — these are Core Web Vitals and required for Google's page experience ranking signal. Instrumentation gap.
- `--vh: 6.640000000000001px` is set as an inline style on `<html>`. This is a floating-point artifact from `window.innerHeight / 100` without `toFixed()`. No SEO impact, but signals unmaintained JS.
- Protocol-relative URL `//se.monetate.net/js/2/...` in `<head>` — resolves to HTTPS in context, but is a legacy pattern and will emit a mixed-content warning if the page is ever served over HTTP.

## Mobile Optimization

- `--vh` custom property is used to fix the iOS 100vh issue, which is correct technique. However the value `6.640000000000001px` (= `innerHeight / 100` without rounding) introduces sub-pixel rendering imprecision. Use `Math.round()` or `(innerHeight / 100).toFixed(2)`.
- No `<meta name="viewport">` visible in the truncated HTML samples — not confirmed absent, but should be verified.
- WebFontLoader v1.6.28 loaded from Cloudflare CDN adds a synchronous font-check cycle. The `wf-*-active` classes on `<html>` confirm it is active and deferring text render until font confirmation. Consider `font-display: swap` at the CSS level instead.

## Console & Network Errors

**429 rate-limit loop — PerimeterX/HUMAN KPSDK fingerprinting:**

```
429 POST /149e9513-01fa-4fb0-aad4-566afd725d1b/2d206a39-8ed7-437e-a3be-862e0f06eea3/fp?x-kpsdk-v=j-1.2.381
```

This endpoint is the KPSDK (PerimeterX/HUMAN Security) browser fingerprinting call. It fired **5 times** and received 429 every time. The SDK retries on failure without backoff, creating a storm. Root causes: (1) the test session's fingerprint was flagged, triggering a challenge loop, or (2) the `/fp` endpoint has an aggressive per-session rate limit that the SDK itself violates through retries. Either way, the SDK is not handling its own 429 responses gracefully.

**Cart page 429:**

```
429 GET https://www.skechers.com/cart/
```

The cart page itself returned 429. This is a conversion-path blocker — a real user would see an error or empty cart state during a bot-protection trigger event. The KPSDK challenge and the cart 429 occurring in the same session suggests the bot detection is classifying the automated test session as a bot and blocking downstream requests.

**Stylitics CORS failure:**

```
Access to CSS stylesheet at 'https://web-assets.stylitics.com/style.css?...' blocked by CORS policy: No 'Access-Control-Allow-Origin' header
```

The Stylitics outfit-widget CSS is being fetched as a cross-origin stylesheet (likely via `@import` or a `<link>` injected by JS) and the Stylitics CDN is not returning the correct CORS header for `skechers.com`. The widget will render without its styles. This is a Stylitics CDN misconfiguration — needs an `Access-Control-Allow-Origin: https://www.skechers.com` header on the `style.css` response, or the fetch mode needs to change to `no-cors` if it doesn't need a credentialed read.

## Recommendations

**P0 — Cart 429 / KPSDK retry storm:**
The KPSDK fingerprint endpoint returning 429 and the cart page returning 429 in the same session is a bot-detection false-positive affecting real users. Audit KPSDK SDK version (`j-1.2.381`) against the HUMAN dashboard for known retry-loop bugs. Add exponential backoff on the client SDK retry or configure the `/fp` endpoint rate limit to be session-scoped rather than IP-scoped.

**P0 — View Cart document metadata:**
The cart view is missing `<title>` and `<html lang>`. If the cart is a client-side SPA transition, the framework (SFCC/Demandware) is not updating `document.title` or `<html lang>` on navigation. Add a `document.title` assignment and verify `<html lang="en">` persists through client-side cart renders.

**P1 — Stylitics CORS:**
File a ticket with Stylitics support to add `Access-Control-Allow-Origin: https://www.skechers.com` to the `style.css` CDN response. Until fixed, the outfit widget renders unstyled.

**P1 — Duplicate third-party script injections:**
Audit GTM for duplicate tag configurations. `creativecdn` and `ytc.js` firing twice doubles their payload and event emissions, which will corrupt attribution data.

**P2 — Accessibility: link-name and aria-required-parent:**
The `link-name` [serious] violation likely affects icon buttons in the navigation or product carousel — add `aria-label` attributes. The `aria-required-parent` [critical] violation needs a DOM audit of the carousel/listbox component to ensure the container role is present.

**P2 — LCP/CLS instrumentation:**
All 8 steps show `LCP=?` and `CLS=?`. The audit tooling is not capturing these vitals, likely because LCP fires after the measurement window or CLS attribution requires scroll interaction. Fix the Web Vitals capture to use the `PerformanceObserver` with `buffered: true` and capture on `visibilitychange`/`pagehide`.

**P3 — Script deduplication and `--vh` precision fix:**
Remove duplicate GTM tags. Fix `--vh` to `(window.innerHeight / 100).toFixed(3)` to eliminate floating-point noise.
