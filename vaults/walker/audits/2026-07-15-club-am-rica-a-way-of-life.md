## Technical Audit — adidas "Club América" (2026-07-15)

---

### 1. Technical Summary

One CTA click link is broken due to a relative-URL resolution failure inside the ESP's click-tracking wrapper. Plain-text fallback is entirely absent, creating a deliverability and accessibility gap.

---

### 2. Link & Tracking Issues

**[FAIL] Broken destination URL — click tracker received a relative path**

The QA probe returned `unknown url type: '/g/9e22c8fa-3f3e-45fb-a99e-21f2886a4dcc?txn=7f6d9380-802c-11f1-95bc-9e016bacd681'`. The `dv.adidas.com` click-redirect system resolved the destination as the relative path `/g/...` instead of an absolute `https://` URL. The outer wrapper is:

```
https://dv.adidas.com/o/9e22c8fa-3f3e-45fb-a99e-21f2886a4dcc?cp_tp=v3.eJzj...
```

The encoded `cp_tp` payload likely contains the malformed destination. Any recipient clicking this link lands on a broken page. Impact is proportional to how many CTAs share this same `9e22c8fa` destination token.

**[INFO] 22 tracking links — not probed**

All click-redirect domains (`click.comms.adidas.com`, `dv.adidas.com`) were skipped during HTTP probing. The broken link above was caught only because the redirect resolved before being skipped; remaining 22 links are unverified.

---

### 3. Rendering & Accessibility

**[FAIL] Four HTTP (non-HTTPS) image references — same asset repeated**

The arrow icon is loaded four times over plain HTTP:

```
http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg
```

Gmail, Outlook.com, and Apple Mail all block or warn on mixed-content HTTP images. The same file should be served at `https://image.link.adidas.com/...`.

**[WARN] Tracking pixel also served over HTTP**

```
http://click.comms.adidas.com/CI0/0102019f6504de55-9103819c-fa7c-4a72-8599-4d4b8dd644b1-000000/TJurMkFzN...
```

Open-tracking pixels blocked by HTTPS-enforcing clients will undercount opens.

**[WARN] Two images missing `alt` text**

- Hero/product image: `src` resolves to `https://dv.adidas.com/o/9e22c8fa-3f3e-45fb-a99e-21f2886a4dcc?...` — no `alt` attribute
- Tracking pixel `TJurMkFzN...` — no `alt=""` (should be empty string for decorative/invisible elements)

Screen readers will read the raw filename or skip silently; the hero image case is the meaningful accessibility gap.

**[WARN] Duplicate `@font-face` declarations**

`AdihausDIN` and `AdineuePRO` are declared twice across two separate `<style>` blocks with identical `src: local(...)` fallbacks. Neither block references an actual web font URL — both resolve to Arial/Helvetica. Duplication is harmless but indicates the template was assembled from two partial blocks without cleanup. Brand fonts will never render in any client.

**[WARN] Malformed charset meta tag**

```html
<meta content="text/html; charset=UTF-8" />
```

Missing `http-equiv="Content-Type"`. Correct form:

```html
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
```

Most clients tolerate this, but it is invalid HTML 4.01 and could cause charset fallback in legacy Outlook versions.

---

### 4. Personalization & Merge Tokens

No unresolved merge tokens visible in the source (`{{...}}`, `*|...|*`, `%%...%%`). Per-send IDs (`mi_mid`, `mi_cid`, `cp_cid`) appear to be resolved values, not placeholders. No issues found.

---

### 5. Compliance

**CAN-SPAM / unsubscribe:** Cannot fully verify from the truncated source, but adidas's standard templates include a physical mailing address and unsubscribe footer — flag for manual confirmation against the full render.

**`no-referrer` meta tag present:**

```html
<meta name="referrer" content="no-referrer" />
```

This suppresses the `Referer` header on any click-through, which is intentional for privacy but means server-side referrer-based attribution on landing pages will be blank for clients that respect this directive. Only relevant if the landing page team relies on HTTP referrer rather than UTM/click-ID params.

**Sender domain:** `us-news.comms.adidas.com` — a dedicated ESP subdomain. SPF/DKIM alignment cannot be assessed from HTML; verify that `comms.adidas.com` is covered in adidas's SPF record and that DKIM `d=` aligns to `adidas.com` or the sending subdomain.

---

### 6. Email-to-Site Continuity

**No standard UTM parameters visible in destination URLs.** The click-tracking system uses proprietary adidas parameters (`cp_tp`, `mi_cid`, `mi_mid`, `cp_cid`) encoded in the redirect payload. GA4/Adobe Analytics on the landing pages will only attribute correctly if the adidas ESP decodes these and appends UTM params at redirect time, or if the site has a custom integration. Confirm with the analytics team that campaign attribution is firing for this send.

**Broken CTA destination (see §2)** means at minimum one landing page is unreachable — the `/g/` path implies this may have been intended to route to a product grid or category page on adidas.com.
