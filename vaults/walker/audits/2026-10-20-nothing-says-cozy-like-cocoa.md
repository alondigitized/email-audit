## Technical Audit: "Nothing Says Cozy Like Cocoa☕" (Shoe Carnival)

### 1. Technical Summary
The email has an overall QA pass rate of 75% (0 issues, 2 warnings). The HTML source is truncated, so the body, footer and link markup could not be inspected. The confirmed findings are a likely unresolved `[UNIQUE]` placeholder in a tracking pixel, a malformed UTM query string, and a plain-text part that is mostly URLs.

### 2. Link & Tracking Issues
- **Click-tracking links not probed.** 32 links were skipped as tracking/redirect domains (`*.emltrk.com`). Destination status, redirect chains and final UTM values are unverified.
- **Unresolved placeholder in a pixel.** `https://0di86k1v.emltrk.com/v2/0di86k1v?d=[UNIQUE]` still contains a literal `[UNIQUE]`. This is probably a token the ESP did not replace, so the open pixel may not record a per-recipient ID. It could also be an intentional ESP macro, so confirm it against the raw MIME.
- **Malformed pixel URL.** `https://ieezzy5m.emltrk.com/v2/ieezzy5m?i=72180589&t=utm_campaign=SCA_20261020_espresso_color_story_AM` has two problems:
  - The `t` parameter contains a nested `=` (`t=utm_campaign=...`), so parsers will read the value as `utm_campaign=SCA_...` rather than a proper `utm_campaign` key.
  - The QA output shows a trailing zero-width character (U+200B) after `_AM`. That character would end up in the campaign value or URL.
- **Plain-text part is mostly URLs.** 6,332 of 8,844 characters (about 72%) are URLs, which exceeds the 70% threshold. This usually means long tracking URLs are inlined in the text/plain alternative, and spam filters may weigh it negatively.

### 3. Rendering & Accessibility
- **Missing alt text on two images.** Both are the tracking pixels above (`ieezzy5m`, `0di86k1v`). Because they are 1×1 pixels, the impact is low. Add `alt=""` and explicit `width="1" height="1"` so screen readers skip them.
- **Link styling removed.** The global rule `a, a:link, a:visited, ... { text-decoration:none !important; color:inherit !important; }` strips underline and colour from every link. Any inline text link that relies on default styling is then indistinguishable from body text, which fails WCAG 1.4.1.
- **Small mobile text.** `.responsive-text { font-size:12px !important; }` at `max-width:600px` sets text at 12px on mobile, below the common 14px minimum.
- **Malformed meta tags.** `<meta content="text/html;" charset="utf-8" />` and `<meta content="IE=edge" />` have no `http-equiv` attribute, so the second one has no effect. The doctype is HTML 4.01 Transitional but the root element carries `xmlns`. Neither is likely to cause a visible failure.
- `lang="en"` and the viewport meta tag are present.

### 4. Personalization & Merge Tokens
- `?d=[UNIQUE]` in the pixel `0di86k1v` is the only suspected unrendered token (see section 2).
- The visible source shows no other `%%…%%`, `{{…}}` or `[[…]]` tokens, but the body is truncated, so this is not a full check.

### 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication-Results header not found.** The QA note attributes this to the AgentMail relay stripping it. SPF, DKIM and DMARC status is therefore unknown and is not evidence of a sender problem. The sender domain is `email.shoecarnival.com`.
- **Unsubscribe and address not verifiable.** The footer, unsubscribe link, physical address and `List-Unsubscribe` / `List-Unsubscribe-Post` headers are outside the truncated source and were not provided. No violation is claimed.

### 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Campaign tag mismatch.** The only visible campaign tag is `SCA_20261020_espresso_color_story_AM`, but the subject line is about cocoa. This may be a reused or mislabelled campaign name, which would split reporting.
- **Landing pages unchecked.** Landing-page alignment and UTM propagation on the 32 tracked links could not be verified because the HTTP probe was skipped.

### 7. Recommendations
1. Check the raw MIME and send logs for `d=[UNIQUE]`. Confirm that the ESP resolves it per recipient, or fix the merge syntax.
2. Fix the pixel query string so UTMs are separate parameters (`&utm_campaign=...`, not `t=utm_campaign=...`), and strip the trailing U+200B from the campaign string.
3. Add `alt=""` and `width="1" height="1"` to both tracking pixels.
4. Re-add underline or a distinguishing colour to inline text links, and avoid `color:inherit !important; text-decoration:none !important` on all anchors.
5. Raise the mobile `.responsive-text` size from 12px to at least 14px.
6. Add `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"` to the two meta tags.
7. Shorten the text/plain tracking URLs, or reduce the number of links, to bring the URL ratio under 70%.
8. Capture the full headers (`Authentication-Results`, `List-Unsubscribe`) from the original message, not the relay copy, and re-run the compliance checks. Resolve the tracking redirects to confirm the landing URLs and UTMs.
9. Confirm the campaign name `espresso_color_story` against the actual send.
