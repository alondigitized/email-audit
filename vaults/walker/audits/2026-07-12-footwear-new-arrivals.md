# Footwear new arrivals
**Score:** 6/10 · **Type:** Email audit · **2026-07-12**
## Executive summary

- I see New Balance in the sender column and "Footwear new arrivals" in the subject and I honestly almost didn't open it. They've sent me ten-plus emails in the past two weeks — kids' shoes, back-to-school, the 530 model, extra 20% off markdowns — and now we're back to "new arrivals." No offer, no urgency, just a floating sneaker against wood paneling and some copy that says "Step into something new." The hero shoe looks stylish enough, but it reads young and fashionable, not cushioned and walkable. Then I scroll and find four product thumbnails I can barely read on my phone, followed by a whole section pitching athletic shorts and a sports bra under something called "The RC Collection." I'm 62. I don't need a bra.
- Would I click? Probably not. I'd tap "Shop now" out of habit if one of those grid shoes looked like something my feet would thank me for — but none of them are calling out arch support, cushioning, or slip-on convenience. They're just pictures with tiny labels. Would I forward this to a buddy? No. There's nothing here to share.

## What's weak

- **No offer whatsoever** — after the July 10th send that actually dangled "extra 20% off select markdowns," coming back with zero discount feels like a step backward. I was trained to expect something.
- **The RC Collection section is dead space for me** — athletic tees, shorts, a sports bra. I don't need performance apparel; I need a shoe that doesn't punish my arches after an hour at the hardware store.
- **Models skew young and athletic** — the RC section shows two people who look like they're in their late twenties training for a 10K. Not one image signals "this shoe works for a 62-year-old guy who walks a lot."
- **No product details where I need them** — those four grid shoes (9060, 880, 327L, Fresh Foam Hierro) are just images and names. No mention of cushioning level, wide width availability, or anything that would let me self-qualify.
- **Cadence fatigue is real** — this is the eleventh-ish email in two weeks. "New arrivals" with no hook doesn't give me a reason to stop the scroll.

- 4. **Attach a modest incentive given the cadence** — even "free shipping with no minimum today only" would justify another send this week. Right now there's nothing to differentiate this from the last three.
- 5. **Put a deadline on something** — even "new arrivals ship fast, sizes sell out" is better than a purely evergreen send that feels like it'll be there next Tuesday too.

## Technical Audit — New Balance "Footwear New Arrivals"

**Note:** HTML source is truncated; link inventory, unsubscribe block, and CTA UTM params cannot be fully verified. Issues below are confirmed from visible source only.

---

### 1. Technical Summary

The email has several CSS authoring defects — a duplicate class overriding a background color and `@font-face` blocks with no `src` declarations — that will silently break rendering across all clients. One background-image URL appears to be an unfilled placeholder served over HTTP.

---

### 2. Link & Tracking Issues

- **Unfilled placeholder URL** in `.bgwhite` background-image: `url('http://image.XXXXX.png')`. `XXXXX` is not a valid hostname; this image will 404 on every client.
- **HTTP (non-HTTPS) asset**: that same URL uses `http://` — mixed-content warnings on HTTPS mail clients (Gmail, Outlook.com) will block it even if the placeholder were resolved.
- Full link audit not possible — HTML is truncated before CTA and footer links are visible.

---

### 3. Rendering & Accessibility

**Duplicate `.bg1` class — cascade conflict (critical):**

```css
/* First declaration, line ~6 */
.bg1 { background-color: #ffffff; }

/* Second declaration, line ~60 */
.bg1 { background: #58546d; }  /* purple-gray */
```

The second rule wins the cascade. Any element using `.bg1` will render as `#58546d` (dark purple), not white. One of these declarations must be renamed or removed.

**`@font-face` blocks have no `src` — fonts will never load:**

All nine `@font-face` declarations are empty:

```css
@font-face { font-family: proxima-nova,sans-serif; font-weight: 700; font-style: normal; }
```

No `src:` property means the browser/client has no font file to fetch. `proxima-nova` and `linotype-didot` fall back to `Arial`/`Times New Roman` silently on every client. If these are Adobe Fonts / Typekit web fonts, the `@font-face` blocks are vestigial and should be replaced with a `<link>` to the Typekit CDN, or removed.

**Duplicate `font-family` property inside one `@font-face` block:**

```css
@font-face {
  font-family: proxima-nova,sans-serif;
  font-weight: 700;
  font-style: italic;
  font-family: proxima-nova,sans-serif;  /* repeated */
}
```

Authoring error; second `font-family` is redundant.

**Malformed IE compatibility meta tag:**

```html
<meta content="IE=edge" />
```

Missing `http-equiv="X-UA-Compatible"`. Should be:

```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```

Without the attribute, Outlook (which uses IE/Trident rendering) ignores this directive.

**Mixed doctype:**

```html
<!DOCTYPE html PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" ...>
<html xmlns="http://www.w3.org/1999/xhtml">
```

HTML 4.01 Transitional DOCTYPE combined with an XHTML namespace is contradictory. HTML 4.01 Transitional is the standard choice for broad email client support; the `xmlns` attribute is harmless but unnecessary and misleading for maintainers.
