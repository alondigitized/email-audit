- **"SHOP WIDE WIDTH" button** — that's the first thing in this whole email that felt like it was talking to me; wide widths matter to me and I appreciated seeing it called out.
- **Subject line urgency held up** — "[FINAL HOURS] $10 Off" at 21 characters is clean and punchy on a phone screen, and "This is it: your last chance" as the preheader is real copy, not unsubscribe junk leaking through.
- **DSW brand recognition** — I know this sender, I trust it enough to open.
- **VIP loyalty callout at the bottom** — at least they're reminding me my points exist, even if it's buried.

## What's weak

- **The $10 off doesn't appear in the email body** — the whole subject-and-preheader promise evaporates the second I open; that's a bait-and-switch, even if unintentional.
- **Every product in the hero reads as women's shoes** — heels, pointed mules, kitten pumps; I don't see a single men's casual or walking shoe in the grid.
- **Size grid is women's sizing** — 5, 5.5, 6, 6.5 tells me immediately this wasn't built for me.
- **"SHOP WIDE CALF" button** — that's a women's boot feature; it just reinforces I'm in the wrong send.
- **Eleven-ish emails in four days on the same $10 off** — even if I liked this one, the fatigue is real; "FINAL HOURS" lost some punch because I've read "last chance" three times this week already.

## Recommendations

- 1. **Put the $10 off visibly in the hero** — if the subject promises $10 off, the first thing I should see when I open is that offer with a deadline clock or at minimum a bold CTA. Don't bury it.
- 2. **Send the right creative to the right list** — this email is clearly a women's new-arrivals send; Walker shouldn't be on this list or the men's segment should get men's product in the hero.
- 3. **Add one men's comfort/walking shoe to the grid** — even one Hoka, New Balance, or Brooks-adjacent option signals "we know you shop here too."
- 4. **Consolidate the "FINAL HOURS" and new-arrivals campaigns** — either I'm getting the $10 urgency email or I'm getting the new arrivals email; sending a hybrid where neither story lands is worse than picking one.
- 5. **Rest the cadence** — after 11 sends in four days, any email from DSW reads as noise; a 2-3 day pause would reset my attention.

### 3. Rendering & Accessibility

**`<meta>` charset missing `http-equiv` attribute.**
```html
<!-- found -->
<meta content="text/html; charset=utf-8" />

<!-- correct -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv="Content-Type"`, Outlook and some legacy clients may not pick up the charset declaration, risking mojibake on special characters (e.g., the `$` and `°` symbols common in promo copy).

**Same issue on IE compatibility meta:**
```html
<!-- found -->
<meta content="IE=Edge" />

<!-- correct -->
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```

**`text-size-adjust: none` in reset.**
```css
*{ -webkit-text-size-adjust: none; text-size-adjust: none }
```
`none` disables user-initiated text scaling on mobile. The accessibility-safe value is `100%`, which prevents auto-scaling by the OS while preserving user zoom. This is already set as `-ms-text-size-adjust: 100%` elsewhere in the same rule — the `none` value is an inconsistency and an accessibility regression.

**Web fonts: no woff2 format declared.**
All Futura PT faces load `.woff` only; all HelveticaNow faces load `.ttf` only. woff2 offers ~30% smaller payloads and is supported in all modern email clients that support web fonts at all. The fallback stack (system fonts) will be hit in clients that block external font loading regardless.

**Off-black color values (`#000001`) used intentionally or in error.**
`.dm-font-black` and the mobile `border-top-black` rule both use `#000001` instead of `#000000`. This is a known ESP workaround to prevent certain clients from inverting "pure black," but it should be documented as intentional — if it was a copy-paste artifact it will produce near-invisible borders in some dark mode renderers.

**Image alt text and table structure unverifiable** — source truncated before `<body>`.
