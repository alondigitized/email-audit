# Found: sleek sandals + more
**Score:** 7/10 · **Type:** Email audit · **2026-05-05**
## Executive summary

- DSW sent me a summer sandals email and I'm a 62-year-old guy who wears slip-ons and New Balance. The headline says "Keep It Simple" and the whole email is women in strappy heels. Not one pair of men's shoes that I can see. I recognize DSW, I've got an account, and there's a real 25% off offer in there — but every image, every model, every product shot is aimed at someone else entirely. The bones of this email are fine; the targeting is completely wrong for me.

## What's working

- The 25% off deal is real and visible without a magnifying glass. DSW has earned some trust with me — I've bought there before — so I didn't immediately delete this. The layout is clean top to bottom. No broken images, no overlapping text, nothing that looks scrambled on my phone screen. The "Shop by Size" module near the bottom is actually a smart touch — I know my size, I want to cut straight to what fits, and that kind of shortcut is something I appreciate.

## What's weak

- **Everything about this email is aimed at women.** I'm looking at strappy heeled sandals, feminine styling, female models in sundresses. The headline is "Keep It Simple" — that sounds fine in the abstract, but the whole visual treatment says spring fashion spread for women in their 30s. There is nothing — not one product, not one image — that signals "hey, we've got comfortable men's shoes on sale too." I'm not the guy buying kitten-heel sandals for brunch.
- The preview text is also a problem. "The minimalist trend is the moment" — that doesn't make me feel like a known customer. That sounds like language from a fashion magazine. I'm not chasing trends, I'm chasing shoes that don't hurt my feet by 2pm.
- No loyalty perks visible either. I've shopped at DSW enough to have an account and I got nothing — no "member pricing" badge, no points reminder, no "as a VIP member" line. That's a missed opportunity to make me feel like they know who I am.

## Recommendations

- 1. **Route me to men's content.** Even a small "Men's picks from this sale →" block at the bottom would've given me a reason to click. I know the 25% sale probably covers men's too, but why make me go dig for it?
- 2. **Swap or add a hero that speaks to me.** A clean shot of a comfortable men's sandal or slip-on would've stopped my scroll. Right now I'm scrolling past this because nothing says "this is for you."
- 3. **Use my member status.** A one-liner like "Your VIP savings: 25% off this weekend" would've made this feel personal instead of mass blast.
- 4. **Drop "The minimalist trend is the moment."** That preview text means nothing to me. Try: "Men's sandals and slip-ons: up to 25% off this week" — now I know what I'm opening.

### 3. Rendering & Accessibility

**Bug — invalid CSS property casing in all `@font-face` blocks.**
Every `@font-face` declaration uses `Src:` (capital S) instead of the required lowercase `src:`. CSS property names are case-sensitive in spec; while lenient parsers may accept it, strict renderers (some webmail clients) will silently skip the font load, falling back to system fonts.

Evidence — repeated across all 10 declarations:
```css
@font-face {
  font-family: 'Futura_PT_Regular';
  Src: url("https://braze-images.com/...") format('woff');  /* ← invalid */
}
```

**Bug — `<meta>` tags missing `http-equiv` attribute.**
Two meta tags omit `http-equiv`, rendering them non-functional:
```html
<meta content="text/html; charset=utf-8" />          <!-- missing http-equiv="Content-Type" -->
<meta content="IE=Edge" />                            <!-- missing http-equiv="X-UA-Compatible" -->
```
The charset declaration in particular matters for Outlook rendering.

**Bug — `-ms-text-size-adjust` declared twice with conflicting values.**
In the reset block, the same property appears twice on the same rule:
```css
* {
  -ms-text-size-adjust: 100%;   /* set */
  ...
  -ms-text-size-adjust: none;   /* immediately overridden — first declaration is dead */
}
```
The `100%` declaration is dead code. The effective value is `none`, which is probably intentional, but the dead declaration should be removed to avoid confusion.

**Bug — `supported-color-schemes` used as a CSS property inside `:root`.**
```css
:root {
  color-scheme: light dark;           /* valid */
  supported-color-schemes: light dark;  /* not a valid CSS property */
}
```
`supported-color-schemes` is only valid as a `<meta name="supported-color-schemes">` tag (already correctly present in the `<head>`). The CSS declaration does nothing and can be removed.
