## Technical Audit — Crocs "Just Landed: The Mellow 2"

### 1. Technical Summary

The email is structurally sound with proper doctype, charset, and responsive breakpoints. The primary issues are mixed-content HTTP image sources in the footer and missing alt attributes on tracking/recommendation pixels.

---

### 2. Link & Tracking Issues

**30 click-redirect links skipped by probe** — all appear to route through Crocs' ESP click-tracking domain (standard). No broken destination URLs confirmed, but not verified by QA.

**Open pixel exposes recipient hash in plain URL:**
```
https://demandwarecrocs.demdex.net/event?...&d_dpuid=9153f33fe5cdf59baf088bb835d3b39ef90f188bd8540a4faba92899227ced00...
```
The `d_dpuid` is a hashed ID passed as a query parameter to Adobe Audience Manager. This is standard practice but the pixel is rendered as a visible `<img>` with `visibility:hidden;display:none` rather than a 1×1 transparent GIF inline — some aggressive image-blocking rules may strip it before the `display:none` is applied.

### 3. Rendering & Accessibility

**Missing alt text — 5 images flagged:**

| Image | Source |
|---|---|
| Open pixel | `demandwarecrocs.demdex.net/event?...` |
| Recs slot 1 | `recs.igodigital.com/.../1/walker@agentmail.to` |

No system font fallback is declared in the `@font-face` block itself — fallback depends on downstream `font-family` stacks in the body. If Cloudinary blocks the woff2 fetch, rendering degrades silently. Acceptable risk, but worth noting.

### 6. Email-to-Site Continuity

**UTM parameters:** The 30 tracked links are all wrapped in ESP click-redirect URLs — UTM presence on the destination URLs cannot be confirmed without resolving the redirects. The QA probe skipped all 30. If UTM params are appended by the ESP at redirect-time (common), this is fine; if they are missing from the destination URLs, attribution will break in GA4/analytics.

**`category=Recommended for You` in recs URLs:** The `category` query parameter contains an unencoded space character:
```
?category=Recommended for You
```
This is technically malformed (should be `Recommended+for+You` or `Recommended%20for+You`). Most servers will handle it, but it is a latent parsing risk.
