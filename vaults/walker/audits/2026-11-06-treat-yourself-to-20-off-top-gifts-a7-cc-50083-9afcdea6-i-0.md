## Technical Audit

## 1. Technical Summary
The email is a Braze-built template with SendGrid-branded click tracking (`ablink.dsw.com`) and a Movable Ink pixel (`mi.dsw.com`). The QA run found one failing CTA link, two images without alt attributes, and a text-heavy plain-text part. SPF/DKIM could not be checked, and the HTML was truncated, so footer and compliance elements could not be inspected.

## 2. Link & Tracking Issues
- **Broken CTA (HTTP 400):** the "Opt-In to Texts Get 15% Off" link returned 400. The URL is `https://ablink.dsw.com/f/a/al4CDEVKpkyGSa1SggSvnA~~/AAQRxRA~/44NnZhBq9CNt…`. It is a roughly 900-character tracked URL, and the QA label shows an empty link title. I can't confirm the cause from the data. It could be a malformed or expired tracking token, a destination that rejects the probe's user agent, or a non-HTTP target (such as an `sms:` URI) that was wrapped. It should be checked manually, because this is the SMS-acquisition CTA.
- **Plain-text part:** 22,372 of 28,410 characters (about 79%) are URLs. Long tracked URLs inflate the plain-text alternative and can hurt spam scoring and readability for text-only clients.
- **Probe coverage:** only 12 of 72 links were probed, so the 62% pass rate rests on a partial sample. The other 60 links (footer, utility, social) are unverified.
- **Tracking pixels:** `https://mi.dsw.com/p/up/e6f23fb0…/o.gif?mi_u=225090073&mi_ecmp=…` puts a per-recipient ID (`mi_u`) in a query string. That is normal for Movable Ink, but it means the pixel URL is unique per recipient.

## 3. Rendering & Accessibility
- **Missing alt attributes (2):**
  - `o.gif` (`mi.dsw.com`) is a tracking pixel.
  - The image `src` `https://ablink.dsw.com/q/CHbYN-tsBT4YaJeUzwN2bA~~/…` appears to be the ESP open pixel, based on the `/q/` path.
  - Both are probably non-content images, so severity is low. They should still carry `alt=""` so screen readers skip them, and the pixels should be `width="1" height="1"` with `display:none` or equivalent.
- **Viewport:** `<meta name="viewport" content="… maximum-scale=1" />` blocks pinch-zoom on some mobile clients, which is a WCAG 1.4.4 concern.
- **Malformed meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv` attribute, so the charset and compatibility declarations do nothing. The `Content-Type` header normally covers charset, so impact is low.
- **Dark mode:** the `color-scheme` and `supported-color-schemes` metas and `prefers-color-scheme` rules are present. I found no defect in the visible portion.

## 4. Personalization & Merge Tokens
No issues found. The visible HTML contains no unrendered tokens (such as `{{ }}` or `%%`). Only the first part of the source was available, so the body and footer were not checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication:** the `Authentication-Results` header was not found, so SPF, DKIM and DMARC alignment are unknown. The note says this is expected via the AgentMail relay, so it is a QA-environment limitation rather than a confirmed sender defect. `dsw.com` should be checked separately with a direct-delivery test or DNS lookup.
- **Unsubscribe and address:** the unsubscribe link is always probed, and no unsubscribe failure was reported. The postal address and `List-Unsubscribe` / `List-Unsubscribe-Post` headers could not be verified from the truncated source and headers provided.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Cannot be fully assessed. Every probed link goes through `ablink.dsw.com` redirects, and the final destination URLs and UTM parameters are not in the QA data. The only campaign identifier visible is the Movable Ink `mi_ecmp=20261106_P261661_V1_W-_Offer_Occas…`, which is truncated. The "Opt-In to Texts" CTA is the only link confirmed to fail, so landing-page alignment for that offer is unverified.

## 7. Recommendations
1. **High:** manually click the "Opt-In to Texts Get 15% Off" link. If it is a real 400, fix the tracking token or destination. If the probe caused it, document it as a false positive.
2. **Medium:** re-run the audit with a direct-delivery header capture to confirm SPF, DKIM and DMARC, and to check `List-Unsubscribe`.
3. **Medium:** log the resolved destination URLs and UTM parameters for the primary CTAs so continuity can be audited.
4. **Low:** add `alt=""` to the two tracking pixels, add `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"` to the metas, and remove `maximum-scale=1` from the viewport.
5. **Low:** shorten or simplify the plain-text part, for example with shorter tracked links or fewer duplicate URLs, to bring the URL ratio down.
