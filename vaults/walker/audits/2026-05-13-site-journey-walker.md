## Technical Audit

## Technical Summary

Skechers.com runs on Salesforce Commerce Cloud (SFCC/Demandware), with a heavy third-party script load managed via TrustArc's consent framework (`vice-managed-src` pattern). The View Cart step shows a degenerate HTML document (missing `<title>` and `lang`), likely rendered by a different template or partial SPA shell. The dominant issue across the journey is repeated 429 rate-limiting from Kasada bot-detection (`/fp?x-kpsdk-v=j-1.2.405`), which also caused a cart-page 429. LCP and CLS are unreported across all steps — likely dropped by the auditor rather than truly absent, but they must be treated as unknown.

---

## Accessibility

**15 violations across 3 pages.**

**Critical / Serious**
- `aria-required-parent` (Homepage, critical): ARIA role used on an element outside its required parent container. Common in carousels or custom listboxes.
- `document-title` (View Cart, serious): `<title>` element is empty or absent. Screen readers announce the page title on load; this silences that announcement entirely.
- `html-has-lang` (View Cart, serious): No `lang` attribute on `<html>`. Breaks screen reader language inference and fails WCAG 2.1 § 3.1.1.

**Moderate (structural / landmark)**
- `landmark-main-is-top-level`, `landmark-no-duplicate-main`, `landmark-one-main`: The `<main>` element is either nested inside another landmark or duplicated. Indicates a modal or drawer is being injected at the wrong DOM level.
- `landmark-complementary-is-top-level` (Homepage + Search): `<aside>` elements nested inside `<main>` or other landmarks. Must be top-level siblings.
- `landmark-unique` (Homepage + Search): Multiple landmarks of the same type without unique `aria-label` values.
- `region` (Homepage + Search): Content exists outside any landmark region — anything outside `<header>`, `<main>`, `<footer>`, `<nav>`, `<aside>` is invisible to landmark navigation.
- `heading-order` (Homepage): Heading levels skip (e.g., `<h1>` → `<h3>`), breaking outline hierarchy.
- `page-has-heading-one` (View Cart): No `<h1>` on the cart page.

**View Cart is the worst-offending page** — it appears to render a bare shell lacking foundational document structure.

---

## SEO

- **View Cart — missing `<title>`**: Googlebot will index the page with no title, producing garbage in SERPs. Cart pages should canonicalize to a non-indexable URL anyway (`<meta name="robots" content="noindex">`), but the missing title is a signal that the template is incomplete.
- **Duplicate/inconsistent script injection**: `tags.creativecdn.com/dhGobFICKSkk6J9nvQPw.js` loads **twice** on the Men category page. Redundant script tags inflate `<head>` parse time and may produce double-fired analytics events.
- **`s.yimg.com/wi/ytc.js` loaded twice** on Homepage and Log In pages — same issue.
- SFCC's `demandware.static` bundle is loaded synchronously-adjacent (async attr present, but it's a large monolithic bundle) — no critical SEO impact, but noted.

---

## Performance

TTFB is excellent across all steps (25–36ms) except **View Cart at 149ms** — a 5–6× spike relative to the rest of the journey. Likely causes: server-side cart session hydration, or the 429 from Kasada triggering a retry/fallback path that adds latency before the first byte.

LCP and CLS are missing from all steps. Without these values:
- LCP cannot be assessed. Given the volume of third-party render-blocking work (20+ async scripts in `<head>`), LCP is likely poor on first load.
- CLS cannot be assessed. The `--vh` CSS custom property trick (`style="--vh: 6.640000000000001px"`) suggests JavaScript-driven viewport height calculations, which can cause layout shifts if applied after paint.

**Third-party script count** on Homepage `<head>` (visible in truncated source): 20+ async scripts spanning GTM, TikTok pixel (×2 scripts), Pinterest, Reddit, Bing, Monetate (×2 scripts), Bloomreach, Impact, Quantum Metric, Tune, WebFontLoader, Pulse Insights, Snapchat (Men page), Taboola, Facebook, Nextdoor, Stape. This is an extreme tag load — even async, these consume main thread bandwidth during parse.

---

## Mobile Optimization

- **`--vh` custom property via JS**: `style="--vh: 6.640000000000001px"` is a mobile viewport height workaround for the `100vh` bug on iOS Safari. Acceptable approach but should be set before first paint to prevent reflow.
- **WebFontLoader for Mulish**: `wf-mulish-n3-active` through `wf-mulish-n8-active` — 6 font weights loaded via WebFontLoader. Each weight is a separate network request. On mobile this delays text rendering (FOIT/FOUT) unless `font-display: swap` is set in the `@font-face` declarations.
- No `<meta name="viewport">` visible in the truncated source samples — likely present but not captured in the truncation. If absent, the entire mobile layout would be broken.

## Console & Network Errors

**429 Rate Limiting (6 network + 5 console = high frequency)**

All 429s target the same Kasada fingerprinting endpoint:
```
/149e9513-01fa-4fb0-aad4-566afd725d1b/2d206a39-8ed7-437e-a3be-862e0f06eea3/fp?x-kpsdk-v=j-1.2.405
```
This is Kasada's browser fingerprinting probe. The 429 responses indicate the bot-detection system is rate-limiting the session — possibly because automated tooling was used for the audit (Playwright/Puppeteer). In real user sessions these should not 429, but if they do, Kasada's client SDK should handle retries silently. The fact that they surface as unhandled console errors suggests the SDK's error handler is not suppressing them. One additional 429 hit `/cart/` directly — the cart page itself was rate-limited, which explains the 149ms TTFB spike (the initial request was blocked, retried, or slowed by Kasada challenge resolution).

**CORS block on Stylitics**
```
Access to CSS stylesheet at 'https://web-assets.stylitics.com/style.css?...' blocked by CORS policy: No 'Access-Control-Allow-Origin' header
```
Stylitics is a product recommendation/styling widget. Their CDN is not returning the correct CORS headers for `www.skechers.com`. This is a **Stylitics-side misconfiguration** (or a version mismatch on the `?version=6d4ec9fabe` hash). The widget's styles will not load, leaving the component visually broken or invisible. Impact: outfitting/recommendation UI is non-functional.
