A motion party sounds like something my grandson would go to.
- The email is clean, I'll give it that. No clutter, loads fine. But from top to bottom this thing is aimed at somebody ten, fifteen years younger than me who tracks splits on Strava and buys hot-pink sneakers. The Bondi and the Clifton — those are shoes I've actually looked at for the cushioning — but they're shown here in neon orange and electric yellow. That's not the version I'd buy. ### 3. Rendering & Accessibility

**Duplicate `<meta name="viewport">` tag**
Two viewport declarations are present in `<head>`:
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
The second overrides the first. The values conflict (`maximum-scale=1` vs. `user-scalable=yes`). Remove one; keep the `user-scalable=yes` variant if pinch-zoom is intended.

**Malformed CSS — missing numeric values in `.nav_padding`**
```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
```
Unit without a number — both declarations are invalid and will be silently ignored. Affected elements will fall back to inherited or default padding.

**Malformed CSS — `.nav_border` incomplete declaration**
```css
.nav_border { border-top:px solid ; }
```
Missing border-width integer and color value. This rule is a no-op.

**Missing `http-equiv` on charset `<meta>`**
```html
<meta content="text/html; charset=utf-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, some older email clients (notably Outlook 2007–2016) may not recognize the charset declaration.

**Web font support**
`@font-face` for `TheFutureHOKA` and `TheFutureHOKAMono` is loaded from `https://www.hoka.com/on/demandware.static/...`. These fonts will not render in Gmail (any client), Outlook (Windows), or Yahoo Mail. The fallback font stack is not visible in the truncated source — verify a defined `font-family` fallback stack exists on body text elements, or rendering will defer to the client's default serif/sans-serif.
