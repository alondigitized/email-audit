- The boots offer is the same one from my last several DSW emails. The only new thing is the UGG theme.

- 4. Space out the boots reminders so I don't get one every day.

## Technical Audit

# Technical Audit: "UGG for you & yours 🎁" (DSW)

## 1. Technical Summary
The email's code is mostly standard for a Braze/ablink-wrapped template. The one confirmed failure is the SMS opt-in CTA, which returned HTTP 400 during probing. The HTML source was truncated and only 12 of 68 links were probed, so some checks below can't be confirmed.

## 2. Link & Tracking Issues
- **[FAIL] SMS opt-in CTA returned 400.** The link text is "Opt-In to Texts Get 15% Off", and the URL is `https://ablink.dsw.com/f/a/_OKIsBcaS8jq…HQ~~` (an `ablink.dsw.com/f/a/` redirect).
  - A 400 on a tracked redirect can mean a malformed or expired tracking token. It can also mean the redirector rejected the automated probe.
  - The probe doesn't say which, so verify manually from a real mobile client. If it is broken, the email's main acquisition CTA is dead.
- **Opaque click tracking.** All probed links go through `ablink.dsw.com`, so final destinations can't be checked from the source alone.
- **Probe coverage is low.** 56 of 68 links were skipped (footer, social and utility links were deprioritized). Only the unsubscribe link was guaranteed to be probed, and no result for it is reported.
- **Plain-text part is link-heavy.** 21,404 of 25,585 characters (about 84%) are URLs, which exceeds the 70% threshold. This is a likely side effect of long ablink URLs with encoded tokens. Heavy URL content in the text part is a mild spam-filter signal.

## 3. Rendering & Accessibility
- **Missing `alt` on a linked image.** The `src` is `https://ablink.dsw.com/q/u638mOdhL4aScU1FqSpAoA~~/…NAuTRJtVE8xTDHb45ZmTe4c0zqKxB_LamDvx1MBTUTvfd4euaZ…`.
  - Because it is a tracked `ablink` URL, it looks like content or a linked image.
  - If it is a CTA image, screen readers and image-blocked clients get no label.
- **Missing `alt` on `https://braze-images.com/…/6ae9ff99e0e4ab008ab20de2/original.gif`.**
  - I can't tell from the data whether it is decorative or content.
  - Add `alt=""` if decorative, or descriptive text if it carries content.
- **Missing `alt` on the open-tracking pixel `https://mi.dsw.com/p/up/e6f23fb0…/o.gif?mi_u=…&mi_ecmp=…`.** This is low severity. Add `alt=""` to prevent clients from announcing the filename.
- **Zoom is blocked.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` disables pinch-zoom, which conflicts with WCAG 1.4.4 (Resize Text).
- **Two inert `<meta>` tags.** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv` attribute, so browsers ignore them.
  - The charset is therefore not declared in the document. Rendering relies on the MIME `Content-Type` header, which is usually fine.
- **Generic `<title>`.** The title is just "DSW", which is minor.
- Web fonts (`braze-images.com` woff/ttf) are declared, but the visible CSS doesn't show the fallback font stacks, which were cut off by truncation.

## 4. Personalization & Merge Tokens
No issues found in the visible source. I saw no unrendered Liquid or Braze tokens (`{{ }}`, `{% %}`) in the non-truncated portion. The remainder of the body couldn't be checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication headers can't be checked.** `Authentication-Results` was not found, and the QA tool notes that the AgentMail relay may strip or omit it. This is a tooling limitation, not a confirmed SPF/DKIM/DMARC failure. Verify against raw headers from a direct-delivery inbox.
- **Unsubscribe link and header can't be confirmed.** No unsubscribe probe result, `List-Unsubscribe` header, or `List-Unsubscribe-Post` header (RFC 8058) appears in the data provided. The footer, where the postal address and unsubscribe link normally sit, was truncated.
- The sender is `dsw@e.dsw.com`, a subdomain that matches the `dsw.com` link domains, so there is no visible domain mismatch.

## 6. Email-to-Site Continuity
- **UTM parameters can't be verified.** All links are wrapped in `ablink.dsw.com` redirects, so the final landing URLs and any UTM parameters are not visible in the source. Resolve the redirect chain to check this.
- **Campaign ID is in the tracking pixel.** The pixel carries `mi_ecmp=20261114_P261695_V1_W-_Offer_Trend`, an internal campaign ID. It does not confirm that landing pages match the offer.
- **The SMS opt-in destination is unreachable (see §2).** The email-to-site path for the "15% off" opt-in is therefore unverified.

## 7. Recommendations
1. **Re-test the SMS opt-in link** (`ablink.dsw.com/f/a/_OKIsBcaS8jq…`) in a real browser and on mobile. If it is truly 400ing, fix or regenerate the Braze link and the SMS-capture landing page.
2. **Add `alt` text** to the linked `ablink.dsw.com/q/u638mOd…` image and to `original.gif`, and use `alt=""` on the `o.gif` pixel.
3. **Remove `maximum-scale=1`** from the viewport meta to restore pinch-zoom.
4. **Fix the two meta tags.** Use `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
5. **Shorten the plain-text part.** Use shorter link-tracking tokens and trim redundant links in the text version to lower the URL ratio.
6. **Verify authentication and unsubscribe handling from raw headers.** Check SPF, DKIM and DMARC alignment for `e.dsw.com`, and confirm `List-Unsubscribe` and `List-Unsubscribe-Post` are present.
7. **Re-run the audit with full source and a wider probe.** The goal is to resolve ablink redirects, check UTM presence, and cover the footer links.
