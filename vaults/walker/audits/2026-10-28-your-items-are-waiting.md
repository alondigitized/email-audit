- Four of the six "options we think you'll love" are women's styles, and one is a boy's Garage sneaker. That's sloppy targeting for a 62-year-old man.

- 2. Show men's comfort slip-ins first, and drop the kids' shoe from my row.

## Technical Audit

## 1. Technical Summary
The email renders from a standard Stensul/BEE-style table layout with Attentive click tracking. It has two confirmed deliverability and compliance risks: the unsubscribe link probe returned HTTP 400, and the plain-text part is empty (0 chars). It also loads 13 images over insecure `http://`.

## 2. Link & Tracking Issues
- **Unsubscribe link returned 400.** The probe of `https://skechers.attn.tv/p/dvm?token=ChQwME5H…&attn_macro=dW5zdWJzY3JpYmVMaW5r…` failed (link text "Unsubscribe"). The `attn_macro` value decodes to `unsubscribeLink`. A token-based endpoint may reject an unauthenticated probe, so verify manually before treating it as a hard break. If real, it is the highest-severity item in this audit.
- **CTA links could not be verified.** "Complete you Order" and "We noticed you noticing us... Your cart is still waiting..." both returned 429 on `skechers.e.attentivemail.com/e/c/…`. These are rate limits, not confirmed breakage.
- **Probe coverage was partial.** 12 of 44 links were probed and 32 were skipped (footer, social and utility links).
- **Link domains differ from the sender.** The From address is `msgs.skechers.com` and images come from `image.emails.skechers.com`. Links go through `skechers.e.attentivemail.com` and `skechers.attn.tv`. This is normal for Attentive but is a branded-domain mismatch.

## 3. Rendering & Accessibility
- **Insecure image sources.** 13 images use `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/…`, which can be blocked or flagged as mixed content. They include the logo (`dde00662-…png`), the hero CTA (`dfcc8fd7-…jpg`), `737031d9-…jpg`, `a6ec5198-…jpg`, the app-store badges, Curbside, Afterpay, Find a Store, and the Instagram, Facebook and YouTube icons. The same host serves HTTPS elsewhere (`…/m/21/021bd784-….gif`), so the fix is changing the scheme.
- **Missing alt text.**

  - `a6ec5198-5437-4eaa-8613-eacc775726f9.jpg`

- **Empty `<title></title>`.**
- **Ineffective charset declaration.** `<meta content="text/html; charset=utf-8" />` has no `http-equiv="Content-Type"` attribute, so clients ignore it.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Plain-text part is empty.** QA reports "Text version is 0 chars", so the message is HTML-only. That hurts spam scoring and accessibility.
- **Unsubscribe link may not work.** If the 400 is confirmed, it violates the CAN-SPAM requirement for a functioning opt-out. An unsubscribe link is present (`attn_macro=unsubscribeLink`).
- **Authentication is unverified.** There is no `Authentication-Results` header, because the message came through the AgentMail relay. SPF, DKIM and DMARC status is unknown, so this is not a confirmed failure.
- **Not evaluable from the data.** `List-Unsubscribe` / `List-Unsubscribe-Post` headers and the physical postal address are not in the supplied data or the truncated source.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
No issues confirmed, but nothing was verified either. Every CTA is wrapped in an Attentive redirect (`skechers.e.attentivemail.com/e/c/…`), so destination URLs and any UTM parameters are not visible in the source. The two 429 responses blocked resolving the cart-recovery CTAs. Follow the redirects with a throttled request to confirm that:
- the destination is the cart or checkout page;
- UTM parameters are present;
- items are restored.

## 7. Recommendations
1. Manually test the unsubscribe URL in a browser. If it still returns 400, fix the Attentive unsubscribe macro or token.
2. Generate a plain-text MIME part. This is likely a template or ESP setting.
3. Change all 13 `http://image.emails.skechers.com` image sources to `https://`.
4. Add descriptive alt text to `021bd784-…gif` and `a6ec5198-…jpg`, and use `alt=""` on the tracking pixel. Fix the "Complete you Order" typo and replace the "Text" alt.
5. Set a non-empty `<title>` and replace the charset meta with `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">`.
6. Re-run the link probe with backoff on the 429 CTAs. Capture the raw headers (`Authentication-Results`, `List-Unsubscribe`) from the original message, not the relay copy, to close the compliance gaps.
