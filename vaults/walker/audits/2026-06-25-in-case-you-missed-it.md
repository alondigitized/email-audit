# In case you missed it
**Score:** 5/10 · **Type:** Email audit · **2026-06-17**
## Executive summary

- I've seen "In case you missed it" in my inbox before and I know exactly what it usually means — they sent something, I didn't click, and now they're nudging me again. Fine, I get it. But when I see New Balance in the sender field these days, I'm already bracing myself. They've been hammering my inbox for weeks with stuff that wasn't for me — kids' styles, a pink edit, "footwear favorites" with couples half my age. So I opened this one with one eye half-closed.
- The top half almost got me. There's a solid grid of men's shoes — chunky retro styles, looks like six different models — and "Shop now" is right there. No hunting for the button. But then I scroll down and — there it is again — "Styles for all ages" with two kids center-frame and a "Shop kids'" CTA. At this point it feels like they buried a trap in every send. I've been down this road since June 9th. It's the same bait-and-switch every time.
- I'd mark it as read and move on. I wouldn't click, and I'd definitely not forward it to a buddy — none of my friends want kids' shoes either.

## What's working

- The men's shoe grid is the strongest thing in this email — six styles laid out cleanly, each with a model name underneath, easy to scan on a phone.
- "Shop now" button is right there above the fold, no hunting required — one tap and I'm in.
- Free shipping on orders $75+ is visible at the top, which at least tells me there's a threshold to clear, not a mystery.
- No layout breakage I could see — images loaded, text lined up, nothing looked busted.

## What's weak

- "In case you missed it" tells me absolutely nothing about what I missed — and the preview "Now's your chance" was literally the subject line on the June 11th email. They recycled the headline *and* the preview and just swapped which one goes where. That's lazy.
- The kids section halfway down the email kills whatever momentum the men's grid built. Two kids in bright NB gear, "Styles for all ages," a "Shop kids'" button — I don't have young kids at home, and this is at least the third time they've pushed that message at me this month.
- Not a single mention of comfort, cushioning, or fit — nothing that speaks to *why* I'd pick New Balance over Brooks or Hoka. It's all silhouettes and model numbers.
- Zero urgency or price break. Free shipping over $75 is table stakes; it's not a reason to act today versus next week.

## Recommendations

- 1. **Cut the kids section entirely or move it to a separate send.** If you're resending to men who didn't click last time, retargeting them with children's shoes is the wrong call. Segment it out.
- 2. **Put a real offer in the re-send.** "In case you missed it" re-sends exist to convert the fence-sitters — give me a reason now. Even "Free shipping, no minimum" or "Save $15 on your first order" beats nothing.
- 3. **Give the subject line something to hold onto.** Right now it's a slot machine with no payout.
- **Subject Alt A:** `Men's top styles — free shipping today only`
- **Subject Alt B:** `6 men's styles we think you'll like`
- 4. **Preheader should tell me what I missed, not just taunt me.**
- **Preheader Alt A:** `The 990, 9060, and more — still available in your size`
- **Preheader Alt B:** `Free shipping on orders $75+ — shop men's now`
- 5. **Add one comfort callout** — even a single line like "Cushioned midsole. All-day support." under the hero would do more for a guy like me than six model numbers I have to Google.

### 1. Technical Summary

The email uses a standard HTML 4.01 Transitional + XHTML namespace structure with dark mode support, but contains a broken background image reference, a critical `.bg1` CSS class conflict, and malformed `@font-face` declarations that serve no function. The source is truncated, so compliance and UTM sections are assessed only on what is visible.

---

### 2. Link & Tracking Issues

**Broken/placeholder background image URL** (confirmed in source):
```css
.bgwhite { background-image: url('http://image.XXXXX.png'); }
```
`XXXXX` is either an unreplaced template token or a CDN path that was redacted post-send. If this reached production as-is, the background image silently fails to load in all clients.

**HTTP (non-HTTPS) protocol on image URL**: The same URL uses `http://`, not `https://`. Gmail, Apple Mail, and Outlook.com proxy or block non-secure image assets. This compounds the broken URL problem.

---

### 3. Rendering & Accessibility

**`.bg1` class defined twice with conflicting values** (high severity):
```css
/* Definition 1 — line ~8 */
.bg1 { background-color: #ffffff; }

/* Definition 2 — line ~95 (later in same <style> block) */
.bg1 { background: #58546d; }
```
The second definition wins due to cascade order. Any element using `.bg1` renders as `#58546d` (dark purple-grey) in light mode — almost certainly unintentional given the surrounding white-background design system. The dark mode override then sets it to `#151415`, so light mode is the broken state.

**All `@font-face` blocks are missing `src:` descriptors**:
```css
@font-face { font-family: linotype-didot, serif; font-weight: 400; font-style: normal; }
/* no src — rule is invalid */
```
Nine `@font-face` declarations follow this pattern. Without a `src` descriptor, they are invalid CSS and do nothing. The fonts (`proxima-nova`, `linotype-didot`) must be loaded via an external `<link>` (Adobe Fonts / Typekit) not visible in the truncated source — these declarations are vestigial dead code that may cause parser warnings in strict clients.

**Duplicate `font-family` property in one `@font-face` rule**:
```css
@font-face {
  font-family: proxima-nova, sans-serif;
  font-weight: 700;
  font-style: italic;
  font-family: proxima-nova, sans-serif; /* duplicate — second value wins, first ignored */
}
```
A no-op since values are identical, but indicates copy-paste error in template authoring.

**`<meta content="IE=edge" />` is missing `http-equiv`**:
```html
<meta content="IE=edge" />
```
Should be `<meta http-equiv="X-UA-Compatible" content="IE=edge" />`. Without `http-equiv`, Outlook (which uses the IE/Word rendering engine) does not receive the compatibility directive.

**`supported-color-schemes` on `<html>` style attribute is not a valid CSS property**:
```html
<html style="color-scheme:light dark;supported-color-schemes:light dark">
```
`supported-color-schemes` has no effect as inline CSS. The valid property is `color-scheme` only. The `<meta name="supported-color-schemes">` tag in `<head>` is the correct mechanism, and that is present — this inline copy is noise.

**Dark mode media query is truncated** — cannot confirm whether all light-mode backgrounds and text colors have corresponding dark overrides. The visible portion overrides `body`, `a`, and `.bg1`.
