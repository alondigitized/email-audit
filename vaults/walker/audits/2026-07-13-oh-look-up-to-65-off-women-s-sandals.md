### 3. Rendering & Accessibility

**Issue: Two `<meta>` tags are missing their `http-equiv` attribute.**

```html
<!-- As coded — both missing http-equiv -->
<meta content="text/html; charset=utf-8" />
<meta content="IE=Edge" />

<!-- Correct form -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```

Without `http-equiv`, the charset declaration is inert in some mail clients (Outlook 2016 in particular), and the IE edge-mode hint has no effect. Low blast radius in 2026, but technically broken.

---

**Issue: `Src:` (capital S) in all 11 `@font-face` blocks.**

```css
@font-face {
  font-family: 'Futura_PT_Regular';
  Src: url("https://braze-images.com/...") format('woff');  /* ← invalid */
}
```

CSS property names are case-sensitive per spec. `Src` is not a valid CSS property; only `src` (lowercase) is. All 11 `@font-face` rules (Futura PT Regular, Medium, Demi, Bold; HelveticaNow Regular, Medium, MediumItalic, Bold, BoldItalic, Italic, Italic) are affected. Gecko and WebKit are forgiving here, but it is invalid CSS and will silently drop font loading in any strict parser. Fix: lowercase all `Src:` → `src:`.

---

**Issue: `text-size-adjust` conflict in `*` selector.**

```css
* {
  -ms-text-size-adjust: 100%;
  -webkit-text-size-adjust: 100%;
  text-size-adjust: none;         /* ← overrides the 100% above */
}
```

`text-size-adjust: none` disables browser/client text scaling entirely for all elements. The earlier `100%` declarations are overridden by the unprefixed `none`. This is an accessibility concern — users with browser zoom or OS text-size overrides will not get scaled text. The intended behavior is almost certainly `100%`, not `none`.
