### 3. Rendering & Accessibility

**Issue — malformed charset meta tag (HIGH)**
```html
<meta content="text/html; charset=utf-8" />
```
Missing the required `http-equiv="Content-Type"` attribute. Correct form:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without it, the charset declaration is non-functional. Outlook and some legacy clients may fall back to a default encoding, risking mojibake on special characters (e.g., the `💥` in subject).

**Issue — viewport meta missing `initial-scale` (LOW)**
```html
<meta name="viewport" content="width=device-width" />
```
Missing `initial-scale=1`. iOS Mail and some Android clients may not zoom-to-fit without it:
```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

**Issue — CSS selector typo in fluid grid (MEDIUM)**
```css
.fluid-row .col-9, .md-fluid-row .col-8 { width: 74.25% !important; }
```
The second selector should be `.md-fluid-row .col-9`, not `.col-8`. As written:
- `.md-fluid-row .col-9` has **no mobile width rule** — inherits the `width: 100% !important` from the blanket `.col-*` reset, collapsing any 9-column fluid layout on mobile.
- `.md-fluid-row .col-8` receives a **duplicate conflicting rule** (also set to `66%` two lines above).

**Alt text — cannot confirm.** Source truncated before `<img>` tags in body. If product images lack `alt` text, screen readers and image-blocked clients will show blank cells.
