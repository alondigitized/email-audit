## What's weak

- **Nothing in here is about shoes I'd wear** — an F1 signed jersey and an NBA player's sneaker are both for someone 30 years younger and with completely different hobbies.
- **Subject line is way too long for a phone** — I had to work to read the whole thing; by "May Newsletter" I was already tuned out.
- **No comfort footwear, no walking shoe, no discount** — I'm a loyalty member and there's not one signal that they know what I actually buy.

- **Cadence is becoming a problem** — eighth email in roughly two weeks, none of them have been for me. This is the kind of pattern that ends with me hitting unsubscribe.

- 2. **Add a men's comfort or walking shoe to the newsletter mix** — even one product block showing a walking-friendly style with a member price would give me a reason to scroll.
- 3. **Dramatically shorten the subject line** — 93 characters on a phone is brutal. Cut to under 50.
- 4. **Replace giveaway with a member discount** — a 20% off for adiclub members would pull me in far more than a sweepstakes for something I'd never use.

## Technical Audit — adidas May Newsletter (adidas x Mercedes-AMG PETRONAS Jersey)

---

### 1. Technical Summary

One confirmed broken link and a missing plain-text multipart fallback are the primary blockers; five HTTP image sources (four are the same repeated asset) introduce mixed-content risk in secure mail clients. The email is otherwise structurally sound for a table-based HTML send.

---

### 2. Link & Tracking Issues

**[FAIL] Broken click-redirect — relative URL as redirect target**
The QA probe found an `unknown url type` error on this redirect:
```
/g/0b14a5dd-0062-4a71-9f1a-635127ac2c6c?txn=56836c00-516b-11f1-aa8a-6e9b95041fa3
```
The outer click-tracker URL is:
```
https://dv.adidas.com/o/0b14a5dd-0062-4a71-9f1a-635127ac2c6c?cp_tp=v3.eJzj...
```
The `/g/` path inside the redirect payload is a bare relative URL — not an absolute HTTPS destination. If `dv.adidas.com` does not internally resolve `/g/` to a canonical product or promo page, this link is dead for recipients. **Needs ESP-side fix before next deploy.**

**[WARN] 26 tracking links not validated**
All 26 click-wrapper links were skipped by the HTTP probe (expected for redirect chains). UTM and final-destination correctness is unverified — see §6.

---

### 3. Rendering & Accessibility

**[FAIL] Five HTTP image sources — mixed content**
Gmail, Apple Mail, and Outlook block HTTP `<img>` sources when secure image loading is enforced. The same arrow asset is referenced four times over HTTP, plus one tracking pixel:

```
http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg  (×4)
http://click.comms.adidas.com/CI0/0102019e329af728-d14cc3f2-cd67-443e-8266-6fe6c35fb695-000000/h7cwNk88Ty6bU5Fr...
```

Both domains (`image.link.adidas.com`, `click.comms.adidas.com`) should support HTTPS — these are likely misconfigured asset references, not intentional downgrades.

**[WARN] Missing `alt` text on at least 2 images**
- Tracking/open-pixel image at `https://dv.adidas.com/o/0b14a5dd-0062-4a71-9f1a-635127ac2c6c?...` — no `alt` attribute
- HTTP click image `h7cwNk88Ty6bU5Fr...` — no `alt` attribute

Screen readers and image-off rendering environments will produce empty content at these positions.

**[WARN] Duplicate `@font-face` declarations**
`AdihausDIN` and `AdineuePRO` are declared twice in separate `<style>` blocks with near-identical rules. No rendering breakage, but the redundancy adds ~1KB to payload and can cause parse inconsistency in aggressive CSS-stripping clients.

**[WARN] Missing `http-equiv` on charset meta**
```html
<meta content="text/html; charset=UTF-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
```
Without `http-equiv`, the charset declaration is non-functional. Most clients infer UTF-8, but Outlook 2007–2016 on Windows may fall back to system locale encoding for special characters.

**[INFO] No `<title>` element**
Minor — some clients display the title in the tab or preview pane.

### 4. Personalization & Merge Tokens

No unfired or raw merge tokens (e.g., `{{first_name}}`, `*|FNAME|*`) are visible in the truncated source. No issues found from available HTML.

### 5. Compliance

**[WARN] Plain-text multipart body is absent**
```
Text version is 0 chars
```
CAN-SPAM does not explicitly require a plain-text alternative, but a `multipart/alternative` with an empty or missing text part:
- Raises spam filter scores (SpamAssassin `MIME_HTML_ONLY` rule)
- Prevents rendering in text-only clients (some corporate mail filters, accessibility tools)
- Is flagged as a best-practice violation by Gmail Postmaster and Microsoft SNDS

**[INFO] Unsubscribe link and physical address**
Not verifiable from the truncated HTML. Adidas EU/US sends are typically compliant, but the footer was cut off — full source review needed to confirm CAN-SPAM §5(a)(5) and GDPR Article 7(3) opt-out links are present and functional.

**[INFO] Authentication headers (SPF/DKIM/DMARC)**
Sending domain `us-news.comms.adidas.com` is a dedicated ESP subdomain, which is correct practice. Header values are not included in this audit payload — verify DKIM `d=` alignment and DMARC policy via a live header capture (`Authentication-Results` header in received mail).

---

### 6. Email-to-Site Continuity

**[WARN] `no-referrer` meta suppresses browser referrer**
```html
<meta name="referrer" content="no-referrer" />
```
When a recipient clicks a link, the browser sends no `Referer` header to the landing page. If any destination relies on server-side referrer for attribution (vs. UTM params baked into the URL), that attribution is lost.

**[WARN] UTM parameter presence unverified**
All 26 click links were skipped by the HTTP probe, so UTM params on final landing pages (`adidas.com/us/...`) cannot be confirmed. Given `no-referrer` is set, UTM params **must** be present in every click URL for campaign attribution to function. Manual spot-check of 3–5 representative links recommended.
