## Technical Audit — Skechers PLUS 25% Off Members Email (2026-07-22)

---

### 1. Technical Summary

The email has a protocol-broken third-party monitoring pixel that will silently fail to fire, plus 11+ images served over plain HTTP that modern clients will block or flag. Meta tag attribute errors are minor but indicate template sloppiness.

---

### 2. Link & Tracking Issues

**Critical — Return Path pixel has no protocol scheme:**
```html
<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1dbf0dcef79cbad82c12fe25342701e4499" />
```
The `src` is a bare hostname with no `https://` prefix. Email clients parse this as a relative path, so the pixel never fires. Return Path inbox monitoring data for this send is lost.

**HTTP tracking pixel (ink1000.com):**
```
src="http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=..."
```
Plain HTTP. Clients with HTTPS-enforcement (Gmail, Apple Mail on iOS 15+) will either block or silently upgrade — either way, attribution may be inaccurate.

**26 click-redirect links** all route through `click.emails.skechers.com` — destination UTM parameters cannot be audited from the source alone (see §6).

**Krux/Salesforce DMP pixels** (`beacon.krxd.net`) fire SHA256-hashed PII and a raw subscriber ID (`partner_uid=121173391`). Both use HTTPS — no technical issue, but worth confirming SFMC data-sharing consent covers Krux audience syncing.

---

### 3. Rendering & Accessibility

**11 images served over HTTP** from `image.emails.skechers.com` — every asset on that domain uses `http://` not `https://`. Gmail (default image loading), Apple Mail, and Outlook.com will either block or warn. Affected images include the Skechers logo, app store badges, social icons, and footer icons.

**Two images missing `alt` text:**
- `o.gif` (ink1000.com tracking pixel) — low impact, but alt="" should be explicit
- `49468f73-4651-4af3-bea2-61d1ae5db486.png` (`image.emails.skechers.com`) — unknown content; if this is a product/promo image, missing alt breaks screen readers and image-off rendering

**Malformed meta tags — missing `http-equiv` attributes:**
```html
<meta content="text/html; charset=utf-8" />         <!-- missing http-equiv="Content-Type" -->
<meta content="IE=Edge" />                           <!-- missing http-equiv="X-UA-Compatible" -->
```
Both are inert as written. Charset declaration failure can cause encoding fallback issues in older Outlook versions.

**`-webkit-text-size-adjust: none` in global CSS:**
This completely disables text scaling on iOS/Android. Violates WCAG 1.4.4 (Resize Text, AA). Should be `100%`, not `none`.

**`maximum-scale=1` in viewport meta:**
Prevents pinch-to-zoom on mobile. WCAG 1.4.4 failure for users who rely on zoom. Standard email practice is to omit `maximum-scale` or set it to `5`.

**Duplicate responsive breakpoint declarations:** The `@media (max-width: 375px)` and `@media (max-width: 640px)` blocks contain identical rule sets, and a third `@media (max-width: 480px)` block in a separate `<style>` tag duplicates `.show` and `.mobile-hidden`. No functional breakage, but adds ~300 bytes of dead CSS.

**Authentication headers** (SPF/DKIM/DMARC) are not included in the HTML source provided — these must be verified at the MTA/header level separately. Sending domain is `emails.skechers.com` (subdomain), so DMARC alignment depends on whether SPF/DKIM align to `skechers.com`.

The campaign string `PRO_US_NONPUR_U_SPENDMIN_NONPURCH_EN_07222026` is present in pixel tracking but it is unknown whether it also propagates as a `utm_campaign` value on landing pages.
