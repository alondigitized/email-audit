## Technical Audit

# 1. Technical Summary
Email renders via standard HTML table/media-query template with functional tracking and unsubscribe infrastructure, but ships zero plain-text fallback and multiple HTTP-only (non-HTTPS) image/link assets.

# 2. Link & Tracking Issues
- 17 tracking/click-redirect links (`click.comms.adidas.com` CI0 redirect pattern) were skipped by automated HTTP probing — expected behavior for redirect-wrapped ESP links, not itself a defect, but means click-through destinations are unverified in this audit.
- One click-tracking asset is served over plain HTTP: `http://click.comms.adidas.com/CI0/010201a09e189d1a-33c5fb10-eff8-4c7b-bb40-5db781286021-000000/JCGMNX8DNVsgCkdIlEbJDEFjr...` — this is a tracking pixel/redirect masquerading as an image `src`, not a standard content image.

# 3. Rendering & Accessibility
- **Non-HTTPS image source** (repeated 4x in source, same asset): `http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg` (alt="arrow"). Many mail clients (Outlook, some corporate proxies) block or flag mixed-content HTTP images, risking a broken arrow graphic.
- **Missing alt text** on two images:
  - `https://dv.adidas.com/o/d8c24b60-a116-4ca9-9d8c-0ba8f6e8c0af?cp_tp=...` (content/product image)
  - The HTTP click-tracking image noted above
- Template includes standard Outlook/Apple Mail reset rules (`.ReadMsgBody`, `.ExternalClass`, `x-apple-disable-message-reformatting`) and mobile breakpoints at 640/480/414/320px — no structural rendering issues found in the provided markup.

# 4. Personalization & Merge Tokens
No issues found — no unresolved merge tags (e.g. `{{first_name}}`, `%%FIELD%%`) or broken personalization syntax present in the truncated source.

# 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- `<meta name="ROBOTS" content="NOINDEX, NOFOLLOW">` and `<meta name="referrer" content="no-referrer">` present — standard ESP hardening, not a compliance issue.
- Truncated source does not include the footer/unsubscribe block or sender postal address, so unsubscribe-link presence and physical-address requirement (CAN-SPAM) cannot be verified from the given excerpt.
- Authentication headers (SPF/DKIM/DMARC) are not visible in the HTML body — these live in message headers, not the HTML source provided, so cannot be assessed here.
- Sending domain `us-news.comms.adidas.com` is a dedicated ESP subdomain, consistent with standard DKIM/domain-alignment practice, but this cannot be confirmed without raw headers.

# 6. Email-to-Site Continuity (UTM params, landing page alignment)
Cannot be assessed from the provided evidence — the 17 tracking links were skipped by the probe (redirect-wrapped), and no resolved destination URLs or UTM parameters are visible in the truncated source to compare against landing pages.

# 7. Recommendations
1. **Fix plain-text fallback (highest priority / FAIL)**: Text version is 0 chars — this hurts deliverability/spam scoring and breaks accessibility for text-only clients. Generate a proper `text/plain` MIME part.
2. Serve the "arrow" image over HTTPS instead of `http://image.link.adidas.com/...` to avoid mixed-content blocking.
3. Convert the HTTP click-tracking redirect (`http://click.comms.adidas.com/CI0/...`) to HTTPS.
4. Add `alt` text to the `dv.adidas.com` product image and the tracking image (or use `alt=""` if purely decorative/tracking-only, per accessibility best practice).
5. Provide full (non-truncated) HTML and raw headers in future audits to evaluate unsubscribe/CAN-SPAM footer compliance and SPF/DKIM/DMARC alignment, and resolve at least a sample of the 17 tracking links to verify UTM parameters and landing-page alignment.
