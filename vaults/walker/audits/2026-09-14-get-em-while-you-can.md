- "Shop Sale" is a plain, obvious button — I know where to tap if I want to look.

## What's weak

- Not a single shoe pictured anywhere in this email — for a shoe sale, that's a miss. I want to see what's actually marked down before I click anywhere.

- 3. Drop the free-hat banner or move it way down — leading with a hat instead of the shoe sale is backwards priorities for a shoe brand.

## Technical Audit

1. **Technical Summary**
The email renders via a standard MJML-style table layout with custom `@font-face` declarations, but automated QA flags two broken tracked links (403) and a missing plain-text MIME part; six images also lack `alt` attributes.

2. **Link & Tracking Issues**
- Both probed links resolve through a Cordial redirect wrapper (`e.emails.hoka.com/c2/1664:...`) with JWT-encoded destination (`jwtH`/`jwtP`/`jwtS` params) and returned **403** on automated probe:
  - Return-start link → decodes to `https://www.hoka.com/en/us/return-start/?utm_source=US_Broadcast&utm_medium=email&utm_campaign=...`
  - **Unsubscribe** link → decodes to `https://options.hoka.com/unsubscribe?cid=69e560485cc95da09e001cd9&utm_source=US_Broadcast&...`
- A 403 on an automated crawler is common for ESP click-trackers with bot/anti-scraping protection and does not necessarily indicate the link is broken for a real recipient click; however, the **unsubscribe link returning 403** is the higher-severity item since it's also a compliance-critical link (see §5) — recommend manual verification with a real inbox click, not just probe re-run.
- 7 of 19 total links were deprioritized/skipped by the probe (footer/social/utility) — no data on those.
- All tracked links correctly append `utm_source`, `utm_medium`, `utm_campaign`, plus `hmail` (hashed email) and `cordial_id` for attribution — no missing UTM params observed on probed links.

3. **Rendering & Accessibility**
- Six images missing `alt` text:
  - `US_20260910_NewColorsIntheFlowDrip2_h.jpg`
  - `US_20260914_Markdown_a.jpg`
  - `US_20260914_Markdown_b.jpg`
  - `LogoFooterPrimary.png`
  - Two tracking/open-pixel images (`e.emails.hoka.com/o/p/...`, `mg.emails.hoka.com/o/...`) — pixels don't strictly need alt text but should ideally use `alt=""` or `role="presentation"` to avoid screen readers announcing raw JWT/base64 strings as filenames.
  - The four content images (`NewColorsIntheFlowDrip2_h`, `Markdown_a`, `Markdown_b`, `LogoFooterPrimary`) should have descriptive `alt` attributes — currently a screen reader/blocked-image fallback will show nothing or the raw filename.
- Custom web fonts (`TheFutureHOKA`, `TheFutureHOKAMono`) are loaded via `@font-face` from `www.hoka.com/.../fonts/*.woff2`; most email clients (Outlook desktop, Gmail) strip `@font-face`/`<style>` font declarations, so these will silently fall back to system fonts in the majority of clients — not a bug, but worth noting no `font-family` fallback stack is visible in the truncated snippet to confirm graceful degradation.
- CSS includes several empty/malformed declarations that will no-op rather than break rendering: `.nav_padding {padding-top:px !important;padding-bottom:px !important;}` and `.nav_border {border-top:px solid ;}` — missing numeric values make these rules invalid CSS (ignored by parsers), effectively dead code.

4. **Personalization & Merge Tokens**
- No unresolved merge tags (e.g. `{{first_name}}`, `%%FIELD%%`) present in the visible HTML.
- Personalization is handled via the hashed `hmail` and `cordial_id` query params on links rather than inline token substitution — no issues found in the truncated source.

5. **Compliance (CAN-SPAM, unsubscribe, authentication headers)**
- Unsubscribe link is present and correctly targets `options.hoka.com/unsubscribe?cid=...`, but **QA flagged it as returning 403** — if this reflects real subscriber behavior (not just crawler blocking), it is a CAN-SPAM violation (non-functional opt-out mechanism). Recommend confirming with a live click test before shipping.
- Physical mailer address/postal footer and authentication headers (SPF/DKIM/DMARC) are not visible in the provided HTML truncation — cannot confirm or deny from source; these are typically header-level, not body-level, so flag as **not assessable** from this data rather than a failure.
- Sender domain (`emails.hoka.com`) is a dedicated subdomain, consistent with standard DKIM/SPF alignment practice — no issue observed, but not independently verified here.

6. **Email-to-Site Continuity (UTM params, landing page alignment)**
- Return-start link UTMs are consistent and well-formed: `utm_source=US_Broadcast&utm_medium=email&utm_campaign=H_US_BR_20260914_Markdowns_GWP_A60Day_270GWPTag_365SaleTag_SalePLPBrowse_AIPriceSensHigh`.

- Cannot confirm landing page alignment (whether `/return-start/` actually resolves and matches campaign intent) since the link itself 403'd on probe.
