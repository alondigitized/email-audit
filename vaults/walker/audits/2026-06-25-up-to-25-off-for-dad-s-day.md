### 3. Rendering & Accessibility

**Issue — Missing `http-equiv` on charset meta:**
```html
<meta content="text/html; charset=utf-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv="Content-Type"`, Outlook (MIME rendering path) may not honor the charset declaration, risking mojibake on special characters.

**Issue — Capitalized `Src:` property in all `@font-face` blocks:**
```css
Src: url("https://braze-images.com/appboy/...") format('woff');
```
CSS property names are case-sensitive in spec. `Src` is not a valid CSS property; `src` is. All 10 `@font-face` declarations share this defect. WebKit and Gecko are tolerant, but stricter parsers (some Outlook WebView paths) will silently drop the font load.

**Issue — `text-size-adjust` inconsistency in `*` reset:**
```css
-webkit-text-size-adjust: 100%;
-ms-text-size-adjust: 100%;
-ms-text-size-adjust: none;   /* overwrites the line above it */
text-size-adjust: none;
```
`-ms-text-size-adjust` is set to `100%` then immediately overwritten to `none` on the next line. The unprefixed `text-size-adjust: none` suppresses text scaling entirely on supporting clients rather than the conventional `100%`, which can harm readability on Windows Mobile/IE.

**Issue — `supported-color-schemes` declared in CSS `:root`:**
```css
:root {
  color-scheme: light dark;
  supported-color-schemes: light dark;  /* ← not a CSS property */
}
```
`supported-color-schemes` is only valid as an HTML `<meta>` tag (which is correctly present). Inside CSS it is a no-op and adds dead code.

**Issue — `maximum-scale=1` in viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Fails WCAG 1.4.4 (Resize Text, Level AA). Common in email but worth flagging.

**Issue — HelveticaNow fonts served as TTF only:**
All HelveticaNow variants (Regular, Medium, Bold, Italic, etc.) deliver `.ttf` format. Futura PT fonts correctly use `.woff`. TTF files are 2–3× larger than WOFF for equivalent quality, increasing load time in Apple Mail and iOS Mail (the only clients that render web fonts).
