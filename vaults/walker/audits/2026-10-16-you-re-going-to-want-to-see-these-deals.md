## Technical Audit

## 1. Technical Summary
The email shows no hard failures in the QA run (86% pass, 0 issues, 1 warning). The one confirmed defect is a literal `[UNIQUE]` placeholder in a tracking-pixel URL. The destination URLs, footer and headers couldn't be checked because the source was truncated and the links were skipped.

## 2. Link & Tracking Issues
- **Unresolved token in pixel URL:** `https://0di86k1v.emltrk.com/v2/0di86k1v?d=[UNIQUE]`. The `[UNIQUE]` value was never replaced by the ESP. That pixel likely can't attribute the open to a recipient. The square brackets are also not valid unescaped URL characters.
- **Malformed pixel query string:** `https://ieezzy5m.emltrk.com/v2/ieezzy5m?i=72180589&t=utm_campaign=SCA_20261016_friday_deals_AM​`.
  - The `t` parameter holds a nested `utm_campaign=...` key/value pair, which parsers may split or mis-decode.
  - The URL ends in a zero-width space (U+200B). It can be percent-encoded as `%E2%80%8B` and corrupt the campaign value.
- **Unverified links:** 32 links on `emltrk.com` click-redirect domains were skipped by the HTTP probe, so I can't confirm any destination, redirect chain or status code.

## 3. Rendering & Accessibility
- **Missing alt on both tracking pixels:** `ieezzy5m` and `0di86k1v`. Pixels should carry `alt=""`. This is low severity, since they are non-content images.
- **Links can't be told apart from body text:** the global rule `a, a:link, a:visited … { text-decoration:none !important; color:inherit !important; }` removes underline and color from every anchor. Any inline text links will be indistinguishable from surrounding text unless they are styled as buttons.
- **Small mobile text:** `.responsive-text { font-size: 12px !important; }` under 600px is below the common 14px accessibility minimum.
- **Malformed meta tags:**
  - `<meta content="text/html;" charset="utf-8" />` has no `http-equiv`.
  - `<meta content="IE=edge" />` has no `http-equiv="X-UA-Compatible"`.
  - Both are ignored by clients.
- **Doctype and namespace mismatch:** the HTML 4.01 Transitional doctype is combined with `xmlns="http://www.w3.org/1999/xhtml"`. This is harmless in most clients but inconsistent.
- **Inconsistent breakpoints:** the CSS uses 600px, 660px and 450px, so layout switches at different widths for different rules.
- **Not assessable:** the source is truncated, so I can't check the table structure, image `width`/`height` attributes or total size (Gmail's ~102KB clipping threshold).

## 4. Personalization & Merge Tokens
- **Unresolved token:** `d=[UNIQUE]` in `https://0di86k1v.emltrk.com/v2/0di86k1v?d=[UNIQUE]` is a confirmed merge failure. See section 2.
- No other tokens, such as `{{first_name}}` or `%%…%%`, appear in the visible source.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication-Results not found:** the QA note says it was expected via the AgentMail relay, so SPF/DKIM/DMARC status is unknown. This is a test-harness gap, not a confirmed sender defect.
- **Not verifiable:** the unsubscribe link, physical postal address and `List-Unsubscribe` / `List-Unsubscribe-Post` headers are not in the truncated source or QA data. No violation is asserted.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- The only campaign identifier visible is `SCA_20261016_friday_deals_AM`, inside the pixel's `t` parameter. It has a sensible date and name, but it's malformed (see section 2).
- Destination URLs and their UTM parameters are hidden behind the 32 skipped `emltrk.com` redirects. I can't verify UTM preservation, landing-page status or offer alignment.

## 7. Recommendations
1. Fix the ESP merge for the second pixel so `d=[UNIQUE]` resolves to a real recipient ID. Re-send a test to confirm.
2. Remove the zero-width space from the campaign string and encode `t=utm_campaign=…` properly, for example `t=utm_campaign%3D…`.
3. Add `alt=""` and explicit `width="1" height="1"` to both pixels.
4. Restore a visible affordance (underline or distinct color) for non-button text links, or confirm all links are styled as buttons.
5. Correct the meta tags with `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"`. Align the doctype with the namespace.
6. Raise mobile `.responsive-text` to at least 14px.
7. Re-run QA with the full HTML. Follow the redirects (or resolve them via the ESP's link report) to verify destinations and UTMs. Capture the raw headers (`Authentication-Results`, `List-Unsubscribe`) from a direct-delivery test instead of the AgentMail relay.
