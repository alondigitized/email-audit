### 3. Rendering & Accessibility

**`http-equiv` missing on two `<meta>` tags:**

```html
<!-- AS-IS (invalid) -->
<meta content="text/html; charset=utf-8" />
<meta content="IE=Edge" />

<!-- CORRECT -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```

Without `http-equiv`, both tags are no-ops. The charset declaration will be silently ignored by strict parsers, and the IE compatibility directive won't be applied.

**`Src:` (capital S) in all `@font-face` blocks:**

Every font declaration uses `Src:` instead of `src:`. CSS property names are technically case-insensitive per spec, but multiple email clients and older WebKit-based renderers apply strict parsing and will skip the `@font-face` rule entirely, causing fallback font cascade failure with no fallback stack defined.

Affected fonts: `Futura_PT_Regular`, `Futura_PT_Medium`, `Futura_PT_Demi`, `Futura_PT_Bold`, `HelveticaNow_Regular`, `HelveticaNow_Medium`, `HelveticaNow_MediumItalic`, `HelveticaNow_Bold`, `HelveticaNow_BoldItalic`, `HelveticaNow_Italic` — all 10 declarations.

**No fallback font stack on `@font-face` declarations:**

If the external font fails to load (blocked by corporate firewalls, Gmail image proxy, or the `Src:` bug above), there is no `font-family` fallback in the `@font-face` rule itself. Text will revert to the browser/client default serif, which may break layout.

**Conflicting `text-size-adjust` values in reset block:**

```css
* {
  -ms-text-size-adjust: 100%;   /* set first */
  -ms-text-size-adjust: none;   /* immediately overrides — wins */
}
```

The `none` value will suppress text scaling in older IE/Windows Mail clients. This is likely unintentional; the `100%` value is the standard safe reset.

**`maximum-scale=1` on viewport meta:**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

Prevents user-initiated pinch-zoom on mobile. Violates WCAG 1.4.4 (Resize Text, Level AA). iOS Safari 10+ ignores this, but Android WebView-based clients enforce it.
