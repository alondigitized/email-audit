# Up to 40% Off Select Shoes
**Score:** 7/10 · **Type:** Email audit · **2026-05-22**
## Executive summary

- Well, here's HOKA again — and I'll be straight with you, I almost didn't open this one. I just got the Clifton 10 markdown email yesterday, and now it's another sale send? My inbox is starting to feel like I signed up for the daily HOKA newsletter whether I wanted to or not. That said, "Up to 40% Off" in the subject is hard to ignore when you're a guy who watches what things cost.
- Once I'm in, the layout is clean and easy — big headline, four shoes laid out in a simple grid, one button. Nothing confused me, nothing made me squint. What's missing, though, is any reason to care beyond the number. I see the Clifton 10 from yesterday's email, which at least gives me some continuity. But there's no price shown anywhere on those four shoes. No "$89.99, was $139.99." Just "Up to 40% Off" and a "Shop Sale" button. That's asking me to click through on faith, and at my age I don't do a lot of impulse browsing just to find out the real number.
- I'd mark it as read, maybe bookmark it for later, but I'm not clicking right now. If there had been even one price callout on the Clifton 10 Men, I probably would.

## What's working

- **"Up to 40% Off Shoes" is direct and visible the second the email opens** — no mystery about what the offer is.
- **The Clifton 10 Men is in the grid** — I saw that shoe featured in yesterday's email, so there's some name recognition there; it doesn't feel like a stranger.
- **Layout is clean and phone-friendly** — two columns, large tap targets, no clutter; I could navigate this fine without my reading glasses.
- **"Summer Kickoff Sale" subtext adds seasonal context** — it at least explains why markdowns are happening, which makes the offer feel more legitimate.
- **No render issues** — everything loaded, nothing overlapped, no broken images.

## What's weak

- **No prices anywhere in the grid** — four shoes shown and not a single dollar figure; I can't make a buying decision without knowing if 40% off still lands at $120 or $80.
- **"Up to 40% Off" is hedge language** — "up to" means the best shoes in my size might be 15% off and the bargain bin stuff is 40%; I've been burned by that before.
- **Free Shipping section requires signing up for texts** — that's not a benefit, that's a trade; I don't want marketing texts, so that whole bottom module is dead space for me.
- **The action shot in the Free Shipping section looks like a 30-year-old runner training for a marathon** — nothing about that image speaks to my feet or my lifestyle.
- **Cadence fatigue is real** — this is the eighth email in roughly ten days; yesterday's was also about Clifton 10 markdowns; starting to feel like the sale never ends, which makes me trust the original prices less.

## Recommendations

- 1. **Put actual prices on the product tiles.** Even one product with "Was $140 → $89" would convert more than the current "shop to find out" approach. I'm not going to click through on four shoes to price-check each one.
- 2. **Drop the "up to" qualifier from the hero** — or own it by saying "Starting at 40% Off." Vague ceiling promises read as bait-and-switch to a careful shopper.
- 3. **Cut the SMS sign-up module or make the free shipping unconditional.** Tying shipping to a text opt-in feels like a gotcha at the end of an otherwise clean email.
- 4. **Swap the action-shot hero image for a comfort-forward lifestyle image** — a guy walking a trail or a park bench context would resonate a lot more with who's actually buying the Clifton 10.
- 5. **Back off the send frequency** — two markdown emails in 48 hours trains me to think the sale is always on, which kills urgency.

- **Subject Alt B:** `Your Size Is Still In: 40% Off Sale`
- **Preheader Alt A:** `Clifton 10, Skyflow, and more — prices just dropped.`
- **Preheader Alt B:** `Sale ends soon. Shop men's styles before your size sells out.`

### 3. Rendering & Accessibility

**Duplicate `<meta name="viewport">` tag** (lines 5–6 in `<head>`):
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
The second declaration also contradicts the first (`user-scalable=yes` vs. `maximum-scale=1` implying no scale). Some clients will use the last declaration; behavior is inconsistent across iOS Mail and Android Gmail.

**Malformed charset meta** — missing `http-equiv` attribute:
```html
<meta content="text/html; charset=utf-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, the charset declaration is a no-op in most parsers.

**Empty `<title>` tag:**
```html
<title></title>
```
Outlook on Windows uses the `<title>` value in the window titlebar and some tab previews. An empty value is not a rendering break but is a missed quality signal.

**CSS syntax errors in `@media (max-width: 480px)` block:**

`.nav_padding` has zero-length unit values — the numeric component is absent:
```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
```
This rule will be silently ignored by all CSS parsers, meaning any element using `.nav_padding` gets no mobile top/bottom padding override.

`.nav_border` has the same pattern plus a missing color value:
```css
.nav_border { border-top:px solid ; }
```
Both rules appear to be template variables that were never substituted (e.g., `{{navPadding}}px`). The nav row will render with its desktop spacing on all mobile viewports.

**Custom web font loading** — `TheFutureHOKA` and `TheFutureHOKAMono` are loaded via `@font-face` with `woff2`/`woff` sources. Gmail (web and Android), Outlook (all Windows versions), and Samsung Mail do not support `@font-face` in email. The fallback stack is not visible in the truncated source — verify that a system-safe fallback (e.g., `Helvetica Neue, Arial, sans-serif`) is declared on all `font-family` properties.

**Global `border: none` reset:**
```css
* { border: none; }
```
This strips borders from all elements including `<table>` and `<td>`, which is intentional but will override any inline `border` on images used as dividers. Confirm no spacer images rely on border for visual separation.

**`alt` text** — not visible in truncated source. Must be verified on full HTML; missing `alt` on hero/product images fails WCAG 2.1 AA and causes broken layout text in image-blocking clients (Outlook default, corporate proxies).
