### 3. Rendering & Accessibility

**3a. `<meta http-equiv>` attributes missing (breaks IE/Outlook rendering)**

```html
<!-- as written — broken -->
<meta content="text/html; charset=utf-8" />
<meta content="IE=Edge" />

<!-- correct -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```

Without `http-equiv`, neither tag is parsed by Outlook 2007–2016 (Word rendering engine). The charset declaration is ignored and the IE edge-mode directive is a no-op.

**3b. `@font-face` uses `Src:` (capital S) — non-standard**

All 10 `@font-face` blocks use `Src:` instead of `src:`. CSS property names are technically case-insensitive in the spec, but several email client parsers (Yahoo Mail, older Samsung Mail) apply stricter tokenization and will skip the rule, causing fallback fonts to render instead of Futura PT / Helvetica Now.

```css
/* as written */
Src: url("https://braze-images.com/.../original.woff") format('woff');

/* correct */
src: url("https://braze-images.com/.../original.woff") format('woff');
```

**3c. `maximum-scale=1` blocks user zoom — WCAG 1.4.4 violation**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

`maximum-scale=1` prevents users from pinching to zoom on mobile. This fails WCAG 1.4.4 (Resize Text, Level AA). Remove the `maximum-scale` constraint.

**3d. `text-size-adjust: none` applied globally**

```css
* { -ms-text-size-adjust: none; text-size-adjust: none }
```

The wildcard selector disables OS-level text scaling for all elements. This compounds the zoom issue above and can cause readability failures for low-vision users. Standard practice is `100%` not `none`.
