### 2. Link & Tracking Issues

### 3. Rendering & Accessibility

**IE-compatibility directive non-functional**
```html
<meta content="IE=edge" />
```
Missing required `http-equiv="X-UA-Compatible"` attribute. This renders the directive a no-op in Outlook/Word rendering engine. Correct form:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```

**Charset meta malformed**
```html
<meta content="text/html;" charset="utf-8" />
```
Mixes HTML5 shorthand (`charset="utf-8"`) with an incomplete HTML4 `content` value (`text/html;` omits `charset=utf-8` within the content string). Modern parsers handle this via the standalone `charset` attribute, but it will fail strict HTML4 validators and may misbehave in legacy Outlook MSO renderer. Correct HTML4 form:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

**Dark mode declared unsupported**
```html
<meta name="color-scheme" content="light" />
<meta name="supported-color-schemes" content="light" />
```
Explicitly opts out of dark mode. Apple Mail and Outlook for Mac will still force dark mode on some elements (backgrounds, images with transparency). Hardcoded color classes (`.appleLinksWhite`, `.appleLinksGray`, `.appleLinksBlack`) will not invert, risking low-contrast or invisible text for ~35–40% of mobile recipients.
