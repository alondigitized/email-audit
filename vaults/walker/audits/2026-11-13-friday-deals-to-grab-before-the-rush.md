## Technical Audit

## 1. Technical Summary
The visible source and QA data show no hard failures. They do show a malformed tracking-pixel URL, an unresolved `[UNIQUE]` placeholder, and missing alt attributes on content images. The HTML was truncated and 34 tracking links were not probed, so links, footer and compliance elements can't be verified.

## 2. Link & Tracking Issues
- **Malformed pixel URL:** `https://ieezzy5m.emltrk.com/v2/ieezzy5m?i=72180589&t=utm_campaign=SCA_20261113_friday_deals_AM​`
  - The `t=` parameter contains a nested `utm_campaign=...` key/value pair, so the value is `utm_campaign=SCA_...`. Parsers that split on `=` or `&` may mishandle it.
  - The URL ends with an invisible zero-width character after `_AM`. If it is not stripped, the campaign value will be recorded as `..._AM<U+200B>` and will not match `..._AM` in analytics.
- **Unresolved placeholder:** `https://0di86k1v.emltrk.com/v2/0di86k1v?d=[UNIQUE]`
  - `[UNIQUE]` is a literal, un-substituted token in the delivered HTML. Square brackets are also not valid unescaped URL characters.
  - If the ESP doesn't substitute it at request time, this pixel can't be matched to a recipient. Open tracking would be unreliable.
- **Unprobed links:** 34 tracking links were skipped because they are click-redirect domains. Destination status codes, redirect chains and final URLs are unverified.

## 3. Rendering & Accessibility
- **Missing alt on content images:**
  - `https://image.email.shoecarnival.com/lib/fe3311737164047d701077/m/1/23a03225-7c93-49fa-988c-8821675cac1b.jpg`
  - `https://image.email.shoecarnival.com/lib/fe3311737164047d701077/m/1/fe4e293c-bccf-488a-bbf7-db06bf5745de.jpg`
  - With images blocked or read by a screen reader, these show nothing or the raw filename.
- **Tracking pixels without alt:** both `emltrk.com` pixels lack alt. They should have `alt=""` plus explicit 1×1 dimensions so screen readers skip them.
- **Malformed meta tags:**
  - `<meta content="text/html;" charset="utf-8" />` has no `http-equiv`, so the content attribute does nothing.
  - `<meta content="IE=edge" />` also has no `http-equiv="X-UA-Compatible"`, so it has no effect.
  - The `charset="utf-8"` attribute still works.
- **Link styling:** the global rule `a, a:link, ... { text-decoration:none !important; color:inherit !important; }` removes default link styling. Inline text links may be indistinguishable from body text (WCAG 1.4.1) unless they are restyled inline, which I couldn't see in the truncated source.
- **Small mobile text:** `.responsive-text` is set to `font-size:12px !important` at `max-width:600px`. That is small for mobile reading.
- **Breakpoints:** the CSS uses 600px, 660px and 450px breakpoints. `.hide`, `.show`, `.pad20` and similar rules are duplicated across the 660px and 450px blocks, which makes layout shifts between 450px and 660px harder to predict. This is a maintainability risk, not a confirmed failure.
- **Doctype and namespace:** an HTML 4.01 Transitional doctype is paired with an `xmlns="http://www.w3.org/1999/xhtml"` attribute. This is harmless but inconsistent.
- **Present and fine:** `lang="en"` and a viewport meta tag.

- **No tokens elsewhere:** the subject line "Friday Deals to grab before the rush!" has none. No other tokens are visible in the truncated source.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Only UTM evidence:** the one visible UTM string is `utm_campaign=SCA_20261113_friday_deals_AM`, and it is attached to a tracking pixel, not a CTA link. The `20261113` date matches the send date.
- **Not verifiable:** the 34 click-tracking links were not resolved, so `utm_source`, `utm_medium`, landing-page match and destination health are unknown.

## 7. Recommendations
1. Fix the pixel URL: remove the zero-width character and pass the campaign value in a properly encoded parameter, for example `t=SCA_20261113_friday_deals_AM`.
2. Check why `[UNIQUE]` is not substituted. If the ESP is meant to resolve it, confirm the pixel fires with a real ID. Otherwise, correct the template merge syntax.
3. Add descriptive `alt` text to the two `image.email.shoecarnival.com` JPGs, and `alt=""` with `width="1" height="1"` to both tracking pixels.
4. Fix the meta tags: `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
5. Make sure inline text links keep a visible distinction (underline or colour) despite the global `text-decoration:none !important; color:inherit !important`. Consider raising the 12px mobile text size.
6. Re-run the audit with the full HTML and the raw headers. That would let us check the footer, unsubscribe link, `List-Unsubscribe` headers, SPF/DKIM/DMARC, and resolve the click-tracking links to confirm UTMs and landing pages.
