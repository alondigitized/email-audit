### 3. Rendering & Accessibility

**Issue 3a — Malformed `<meta>` tags (missing `http-equiv` attribute)**
Both of these meta declarations are invalid and will be silently ignored by compliant parsers:
```html
<!-- Missing http-equiv="Content-Type" -->
<meta content="text/html; charset=utf-8" />

<!-- Missing http-equiv="X-UA-Compatible" -->
<meta content="IE=Edge" />
```
Correct forms:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```
The charset omission is the higher-risk defect — if the email client doesn't detect UTF-8 another way, special characters can mojibake.

**Issue 3b — Invalid CSS property `Src:` (capital S) in all 10 `@font-face` blocks**
CSS property names are case-sensitive in the spec. All ten `@font-face` declarations use `Src:` instead of `src:`:
```css
/* Wrong — all 10 font-face blocks */
Src: url("https://braze-images.com/...") format('woff');
```
Most major email clients are forgiving, but Outlook desktop and some Android clients apply strict parsing. If fonts silently fail, fallback stacks (`Helvetica, Arial, sans-serif`) kick in — verify fallbacks are visually acceptable.

**Issue 3c — Non-standard `<meta name="supported-color-schemes">` tag**
```html
<meta name="supported-color-schemes" content="light dark" />
```
`supported-color-schemes` is not a valid meta `name` value. It is a CSS-only property. The valid meta equivalent is only `color-scheme` (already present on the line above). This tag will be ignored by all email clients; it is dead markup. No functional breakage, but it should be removed to reduce noise.

**Issue 3d — Inconsistent cache-busting on font assets**
Futura PT fonts have no cache parameter; HelveticaNow fonts all carry `?1755182939`:
```
# No param (Futura PT)
.../files/67dd7a3bf1de1d0066403c87/original.woff

# Has param (HelveticaNow)
.../files/689df75b1d1e1f00960f35f2/original.ttf?1755182939
```
Inconsistency suggests HelveticaNow was added/updated more recently. Not a breakage, but if Futura PT assets are ever replaced at the same path, cached copies will serve stale bytes with no way to bust them.
