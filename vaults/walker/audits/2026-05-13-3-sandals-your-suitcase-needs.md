### 3. Rendering & Accessibility

**Bug — conflicting `text-size-adjust` declarations (confirmed):**

In the `*` reset rule, `-ms-text-size-adjust` is set twice in the same declaration block:

```css
*{
  -ms-text-size-adjust: 100%;   /* line 1 */
  -webkit-text-size-adjust: 100%;
  -webkit-font-smoothing: antialiased;
  -ms-text-size-adjust: none;   /* overrides line 1 — bug */
  text-size-adjust: none        /* also disables standard property */
}
```

`-ms-text-size-adjust: none` wins by cascade order, disabling auto text-size adjustment on Windows Phone / IE Mobile entirely. `text-size-adjust: none` applies the same to any browser honoring the unprefixed property. The intent appears to be `100%` (prevent iOS auto-inflate), not `none` (disable scaling). This should be:

```css
-ms-text-size-adjust: 100%;
-webkit-text-size-adjust: 100%;
text-size-adjust: 100%;
```

**Non-standard CSS casing — `Src:` in `@font-face` blocks (confirmed):**

All ten `@font-face` declarations use `Src:` (capital S) instead of the correct lowercase `src:`. CSS property names are case-insensitive in most parsers, but this is non-conformant and will fail in any strict-mode parser or future CSS tooling.

**Font dependency on third-party CDN:**

Futura PT fonts are served from `braze-images.com`. HelveticaNow fonts (six variants) are also served from `braze-images.com` with cache-busting timestamps (`?1755182939`). Both families will silently fall back to system fonts if the CDN is unreachable. No system-font fallback is declared for `HelveticaNow_*` variants in the `@font-face` blocks — fallback behavior depends entirely on per-element inline `font-family` stacks elsewhere in the template.

**Malformed meta tags (confirmed):**

Two meta tags are missing required attributes:

```html
<!-- Missing http-equiv="Content-Type" -->
<meta content="text/html; charset=utf-8" />

<!-- Missing http-equiv="X-UA-Compatible" -->
<meta content="IE=Edge" />
```

Without the `http-equiv` attribute, both tags are no-ops. The charset declaration won't be recognized by IE/legacy renderers, and the IE compatibility flag won't apply. Correct form:

```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```
