# Save on fall faves with 20% off 🤭 
**Score:** 6/10 · **Type:** Email audit · **2026-10-08**
## Executive summary

- DSW again, and it's the same HAYRIDE 20% code I've now seen twice already today, once in "20% OFF?! You better be-leaf it 🍁" and once in "FYI: we've got 20% off right now." This is the third copy. The giant white "20% OFF*" on green is easy to read on my phone without my readers, and I'll give them that. But I've seen it, and I've got the code memorized.
- Then I scroll down and the shoes are a bunch of women's boots, a mary jane flat, and something that looks like a furry bag. Nothing here is built for a 62-year-old man looking for a cushioned slip-on. The "Shop Men" link is there, but the products shown aren't mine.
- Would I click? Probably not today. Would I forward it? No. I'd mark it read and maybe come back if I needed shoes before October 11.

## What's working

- The huge "20% OFF*" on green is readable at a glance, even without my glasses.
- The code HAYRIDE sits right under the number with a black "Claim 20% Off" button, so I know what to do.
- The nav (Women, Men, Kids, Brands, Clearance) is simple and the text is big enough.
- "Shop by size" with wide width listed is a nice touch for older feet. I like seeing wide widths called out.
- The barcode for in-store use is handy if I'd rather walk in than type a code on my phone.

## What's weak

- Every product shown is women's or fashion-forward. There's nothing in the grid for me, and "So new, so you" doesn't feel like me.
- This is the third email today with the same 20% code. After the BOGO barrage earlier this week, I'm tired of it.
- The "Hurry…this won't last long!" preheader is pushy. The fine print says the offer runs October 8-11, which is four days, so the urgency feels thin.
- "DSW on Location: Montana" is style inspiration for trendsetters. I don't care about it.
- The fine print is a wall of tiny text. It excludes sale items and lists the brands that qualify (Skechers is in there, good), but I have to scroll a long way to find out what's left out.
- Nothing mentions cushioning, arch support, or slip-on comfort anywhere.

## Recommendations

- 1. Use my browsing history. If I've looked at men's walking or slip-on shoes, show those in the grid instead of boots and flats.
- 2. Add comfort categories to the shop-by links: "Slip-Ons," "Arch Support," "Walking."
- 3. Stop sending the same code three times in one day. Pick one send and make it count.
- 4. Put the dates (Oct 8-11) up top instead of burying them in the fine print.
- 5. Put comfort brands in the grid: Skechers, Hoka, Brooks, New Balance.

## Technical Audit

## 1. Technical Summary
The email has one confirmed broken tracked link (the SMS opt-in CTA returns HTTP 400) and a plain-text part that is about 86% URLs. The visible HTML source shows no unrendered merge tokens. The source was truncated, so the footer, headers and most destination URLs could not be checked.

## 2. Link & Tracking Issues
- **Broken CTA (HTTP 400):** the link text is "Opt-In to Texts Get 15% Off". The URL is `https://ablink.dsw.com/f/a/ZEq-Map5KIiCw_MW29HJtQ~~/AAQRxRA~/4P-mfft3…` and is about 900 characters long.
  - The QA probe's failure label is empty, so the failure has no descriptive label.
  - A 400 from a click-tracking redirector usually means the encoded payload is malformed or expired. It can also mean the redirector rejects the probe's user agent. This is unconfirmed, so manually click the link from a real client.
  - If it is a real failure, the SMS-acquisition offer is dead for every recipient.
- **Plain-text part is URL-heavy:** 25,445 of 29,707 characters (about 85.7%) are URLs, which is a spam-filter risk. The long wrapped tracking URLs are the likely cause.
- **Coverage gap:** only 12 of 69 links were probed and 57 were skipped. Link health for the rest is unverified.

## 3. Rendering & Accessibility
- **Missing alt text (2 images):**
  - `https://ablink.dsw.com/q/IWdALMkEnIJ56QAICLYwNw~~/AAQRxRA~/w1mT7YpM2ncK…` (the `/q/` path suggests an open-tracking pixel)
  - `https://mi.dsw.com/p/up/e6f23fb0…/o.gif?mi_u=…&mi_ecmp=20261008_P261379_V1_WM-_Offer_Stan…` (a tracking pixel)
  - Both look like pixels, so impact is low. Add `alt=""` so screen readers skip them.
- **Invalid meta declarations:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` both lack the `http-equiv` attribute, so neither works as a directive. The charset then relies on the HTTP/MIME `Content-Type` header.
- **Zoom restriction:** `<meta name="viewport" content="… maximum-scale=1" />` blocks pinch-zoom, which is a WCAG 1.4.4 concern.
- **Text resizing:** the global `*{… text-size-adjust: none}` disables text-size adjustment in some clients.
- **Not verifiable:** the font fallback stacks and dark-mode behavior fall in the truncated section. The visible `@media (prefers-color-scheme: dark)` classes (`.dm-bg-*`, `.dm-font-*`) are syntactically valid.

## 4. Personalization & Merge Tokens
No issues found in the visible source. No unrendered tokens (`{{…}}`, `%%…%%`, `${…}`) appear in the visible HTML or in the QA output. The rest of the markup was truncated, so this is not a full check.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Unsubscribe:** the QA system always probes an unsubscribe link, and it reported no failure for it. I could not see the footer, the physical postal address or the `List-Unsubscribe` / `List-Unsubscribe-Post` headers, so none are confirmed.
- **Authentication:** no SPF, DKIM or DMARC results were supplied, so they cannot be assessed. The From domain (`e.dsw.com`) and the tracking domains (`ablink.dsw.com`, `mi.dsw.com`) share the `dsw.com` parent domain.
- No violations are evidenced.

## 6. Email-to-Site Continuity
- **UTM parameters:** every link is wrapped by the click tracker (`ablink.dsw.com/f/a/…`), so the final destinations and UTM parameters are opaque. Alignment between the "20% off" subject and the landing pages is unverified.
- **Campaign ID:** the only visible campaign identifier is `mi_ecmp=20261008_P261379_V1_WM-_Offer_Stan…`, from the `mi.dsw.com` pixel. It is truncated and gives no information about landing-page parameters.
- **SMS opt-in:** the "Get 15% Off" CTA fails, so that journey is blocked.

## 7. Recommendations
1. Manually test the SMS opt-in link at `ablink.dsw.com/f/a/ZEq-Map5…`. If it fails, regenerate the link and check whether the destination or the encoded payload is invalid.
2. Reduce the plain-text URL ratio by trimming the plain-text alternative to key links, or by shortening the tracked URLs.
3. Add `alt=""` to both tracking pixels.
4. Fix the meta tags to `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` and `<meta http-equiv="X-UA-Compatible" content="IE=edge" />`.
5. Remove `maximum-scale=1` from the viewport meta tag, and reconsider `text-size-adjust: none`.
6. Re-run QA on the full HTML and the raw headers (SPF/DKIM/DMARC, `List-Unsubscribe`) to cover the compliance and footer checks that were not possible here. Also resolve the redirects to verify UTM parameters and destinations.
