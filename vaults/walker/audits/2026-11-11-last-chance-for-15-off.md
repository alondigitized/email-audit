# LAST CHANCE FOR $15 OFF!
**Score:** 7/10 · **Type:** Email audit · **2026-11-11**
## Executive summary

- DSW again, and this is the second time today I've seen the same Veterans Day offer. The earlier one was "3 words: Early. Black. Friday." with the same $15/$20/$60 tiers and the same VETERANS code. Now it's "LAST CHANCE" in all caps with an exclamation point, and I've heard that tune all week. The big red block is easy to read on my phone, and the countdown clock (05:43:28) is a nice touch. The offer is clear: $15 off $49, $20 off $99, $60 off $199.
- But the shoes below the hero are all women's: a heel, two flats, a fuzzy boot and a pink sneaker. Nothing is cushioned, slip-on or made for a walking man. The extra 10% is only for veterans and active military, which I'm not. I'd skim it, maybe tap "Shop Men," and move on. I wouldn't forward it. Mark it read.

## What's working

- The hero offer is huge and readable without zooming. Three price tiers, no hunting.
- The countdown timer gives me a reason to hurry, and "Veterans Day only" makes the deadline believable.
- The "CLAIM $15 OFF" button is a clear target for my thumb.
- "Shop Men" sits right under the hero, so I can skip the women's stuff.
- "Shop by Size" with "Shop Wide Width" is useful. Fit matters more to me than a logo.

## What's weak

- Every product shown is a women's style. Not one comfort shoe or men's walker.
- The headline ($15 off) is for everyone, but the extra 10% is veterans only, and it's the part that really stands out. It feels like I'm being left out.
- I need a code (VETERANS) and a barcode for in-store use. That's more work than a simple discount.
- The fine print is a wall of tiny text with long brand exclusions. That makes me trust the "offer" less.
- The sale email arrives right after "3 words: Early. Black. Friday." and the UGG and TINSEL emails. The "LAST CHANCE" line has lost its punch.

## Recommendations

- 1. Show men's comfort shoes in the product grid. Think slip-on walkers, cushioned sneakers and arch-support styles from Skechers, Hoka and Brooks. That one change would do the most for me.
- 2. Put the code in the button copy, e.g. "Shop now, code VETERANS", so it takes fewer taps.
- 3. Send one Veterans Day email, not two, and don't use "LAST CHANCE" until it really is the last send.
- 4. Move the 10% military perk to a smaller banner so everyone else doesn't feel shut out.
- 5. Replace the dollar-off labels under each product with the real price.
- **Subject Alt A:** `Ends tonight: $15 off $49 at DSW`
- **Subject Alt B:** `Men's walking shoes, $15 off today only`
- **Preheader Alt A:** `Use code VETERANS. $20 off $99, $60 off $199. Ends tonight.`
- **Preheader Alt B:** `Slip-ons, sneakers and wide widths, all in the sale.`

## Technical Audit

# Technical Audit: DSW "LAST CHANCE FOR $15 OFF!"

## 1. Technical Summary
The email has one confirmed broken-experience failure: the SMS opt-in CTA tracked link returned HTTP 400. The rest are minor rendering and accessibility issues, plus several checks that couldn't be completed (SPF/DKIM, footer compliance, UTMs). The QA run passed 62% of checks.

## 2. Link & Tracking Issues
- **[FAIL] SMS opt-in CTA returned 400.** The link text is "Opt-In to Texts Get 15% Off". The URL is `https://ablink.dsw.com/f/a/YacmtQj5KpimhlsjjJ3ycg~~/AAQRxRA~/MMGPWwMxD4...` (SendGrid-style click-tracking wrapper). The probe returned no status text.
  - The prober may have been rejected by the click tracker, or the redirect may target an `sms:` or deep link that a bot can't follow. The 400 is therefore not proven to be user-facing, but it needs a manual check on a real device.
  - If it does fail for users, it is the highest-value broken link, since it carries the incentive for the text-message opt-in.
- **Probe coverage was partial.** 12 links were probed and 63 skipped (footer, utility and social links were deprioritized). Only the one failure above was recorded among the probed set.
- **Very long tracking URLs.** The plain-text part is 26,064 of 31,515 characters URLs (83%), which triggered the [WARN] "Plain-text is >70% URLs". Wrapped click-tracking tokens of roughly 600+ characters each are the cause. This hurts the plain-text version's readability and may add a spam-filter risk.

## 3. Rendering & Accessibility
- **Charset meta is malformed.** `<meta content="text/html; charset=utf-8" />` has no `http-equiv="Content-Type"`, so it declares nothing. The same applies to `<meta content="IE=Edge" />`, which has no `http-equiv="X-UA-Compatible"`. Rendering depends on the MIME header charset, which is usually fine but fragile.
- **Zoom is restricted.** The viewport meta sets `maximum-scale=1`, which blocks pinch-zoom (WCAG 1.4.4).
- **Two images lack alt text.**
  - `https://ablink.dsw.com/q/4fStJgQRwUqebgZQZMLgtA~~/AAQRxRA~/oicnO802...` is a tracking-pixel-style image.
  - `https://mi.dsw.com/p/up/e6f23fb024fdcb2cc855b9ed672710d4/o.gif` is an `o.gif` open pixel.
  - Both are probably non-content, so this is low severity. They should carry `alt=""` (and ideally `width="1" height="1"`) so screen readers skip them.
- **The HTML was truncated.** I could not check image dimensions, `role="presentation"` on layout tables, or the `lang` attribute beyond the head.

## 4. Personalization & Merge Tokens
No issues found. No unrendered tokens (`{{ }}`, `%%`, `[FIRST_NAME]`) appear in the visible source or QA output. The `mi_u=225090073` parameter on the `mi.dsw.com` pixel is a rendered Movable Ink user ID, not a leaked token.

## 5. Compliance
- **Authentication headers are unverified.** [WARN] No `Authentication-Results` header was found, because AgentMail relays the message. SPF, DKIM and DMARC status for `e.dsw.com` is unknown from this data. It is not evidence of failure.
- **Unsubscribe link:** the QA notes say an unsubscribe link is always probed, and no failure was reported for it. The `List-Unsubscribe` and `List-Unsubscribe-Post` headers, and the physical address, were not in the supplied data or the truncated HTML, so they can't be confirmed.
- **Sender identity:** From is `dsw@e.dsw.com`, a dedicated subdomain aligned with the brand. No issue found.

## 6. Email-to-Site Continuity
- **UTM parameters can't be evaluated.** All links are opaque `ablink.dsw.com` wrapped redirects, and the probe recorded no final destination URLs. Landing-page alignment and UTM presence are unverified.
- **Campaign ID:** the only visible campaign identifier is `mi_ecmp=20261111_P261648_V1_WM-_Offer_MI_C`, on the Movable Ink pixel. It is dated 2026-11-11, which matches today's send. There is a stray `-` in `WM-_Offer`, which looks like an empty template segment. That is cosmetic, but it suggests a naming-convention variable that rendered blank.

## 7. Recommendations
1. **Manually test the SMS opt-in link** on iOS and Android and from a browser. If it truly returns 400, fix the destination or the tracking-domain configuration before the next send. If it works, whitelist the QA prober's user-agent or switch the probe to a GET with browser headers to avoid false failures.
2. Add `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"` to the head meta tags.
3. Remove `maximum-scale=1` from the viewport meta.
4. Add `alt=""` to the tracking and open-pixel images.
5. Shorten the plain-text part by using a leaner link format, or reduce the number of wrapped links in it.
6. Re-run the check with the full HTML and raw headers (`Authentication-Results`, `List-Unsubscribe`) so that compliance and UTM continuity can be verified. Record the resolved redirect destinations during probing.
7. Check the `WM-_Offer` campaign-ID segment in the Movable Ink template for an empty variable.
