# Top styles on sale now

## Executive summary

- I saw "New Balance" in my sender column and "Top styles on sale now" in the subject and I thought — okay, at least it's not kids' shoes again. But then I noticed the preview: "Now's your chance." That's the same line New Balance used as their subject on June 20th and June 11th. At this point that phrase means nothing to me. It's wallpaper.

The 574 Core caught my eye — that's a classic I've looked at before. But the Fresh Foam 680v8 and Kaiha Road v3 are performance runners, not the comfort walkers I'm after. And I've been seeing this same 25% off deal in my inbox since at least June 3rd. At some point a "sale" that's been going for three weeks isn't really a sale anymore — it's just the price.
- I'd mark this as read, not click. I'm not forwarding it to anyone.

## What's working

- **"Shop men" CTA is right there.** After weeks of kids' shoes and women's styles, seeing a clear "Shop men" button up front without hunting is a relief.
- **25% off is concrete.** The offer is real and visible — code SUMMER26 is spelled out, and "through Wednesday" gives an actual deadline.
- **The 574 Core in the product grid** — that's a shoe I know, and it reads as a comfortable everyday walker. Its presence earns a second look.
- **Clean layout, no visual breaks.** The email renders neatly — no broken images, no overlapping text, easy to scan on my phone screen.
- **"Now through Wednesday" adds a real deadline** — that's more credible than "while supplies last" hand-waving.

## What's weak

- **"Now's your chance" has been used as a subject line twice already this month** (June 11, June 20). Recycling it as a preview feels sloppy and erodes credibility.
- **Zero comfort language.** No mention of cushioning, arch support, or walking fit anywhere in this email. That's the only reason I'd buy from New Balance over Hoka or Brooks right now.
- **The same 25% off offer has been running since at least June 3rd.** What's the urgency here? I've been ignoring this deal for three weeks. Why would Wednesday be different?
- **Coupon code friction.** I have to remember SUMMER26 and type it at checkout. Skechers just knocks the price off — I don't have to remember anything.
- **The hero model is cropped at the waist.** I can see dark pants and sneakers but nothing that tells me this shoe is for someone my age looking for all-day comfort.

## Recommendations

- 1. **Drop "Now's your chance" entirely** — it's been a subject line twice this month and is now meaningless to repeat subscribers. Pick something fresh.
- 2. **Put a comfort signal in the subject or hero** — even "top comfort styles" or "walking favorites" would tell me there's something here for me without scrolling.
- 3. **Pull the 574 Core or Fresh Foam 1080 into the hero** — one big shoe with explicit comfort copy ("all-day cushion," "wide widths available") beats a generic lifestyle shot.
- 4. **Lose the promo code or pre-apply it.** Make the discount automatic at checkout. Code friction is a drop-off point I don't need.
- 5. **If you're going to run a sale for weeks, escalate it** — give long-time subscribers a better tier. Seeing the same offer in my inbox for 22 days doesn't say "deal," it says "we gave up."

### 1. Technical Summary

The email renders from a well-structured HTML4 Transitional template with dark-mode support attempted, but contains a confirmed unreplaced template variable in a CSS background-image URL, two conflicting definitions of the same CSS class, and `@font-face` rules with no `src:` declarations that silently fail on all clients.

### 2. Link & Tracking Issues

**Unreplaced placeholder URL (high severity)**
```css
.bgwhite { background-image: url('http://image.XXXXX.png'); }
```
`XXXXX` is an unfilled merge token. This will 404 on send. Additionally, the URL uses `http://` — many ESPs and webmail clients (Gmail, Outlook.com) block or auto-upgrade mixed-content HTTP image requests.

Full links are not visible in the truncated source; UTM coverage cannot be fully assessed (see §6).

### 3. Rendering & Accessibility

**Duplicate `.bg1` class with conflicting values**
Two rules in the same `<style>` block define `.bg1`:
```css
/* First definition */
.bg1 { background-color: #ffffff; }

/* Later definition — overrides the first */
.bg1 { background: #58546d; }
```
The second declaration wins via cascade. Any element using `.bg1` expecting white will render as `#58546d` (dark purple-gray). This is almost certainly a copy-paste error from a component library.

**`@font-face` rules have no `src:` property**
All nine `@font-face` blocks (`proxima-nova`, `linotype-didot`, etc.) are empty — they declare `font-family`, `font-weight`, and `font-style` but no `src:`. Web fonts will never load; every client silently falls back to `Arial` or `Times New Roman`. If web fonts are intentional, the Adobe Fonts / Typekit embed URL must be added to each block.

**Single responsive breakpoint at 414px**
```css
@media only screen and (max-width:414px) { ... }
```
The industry standard for email is a 600px breakpoint to catch tablets and larger phones. Devices between 415–600px viewport width receive the desktop layout unmodified.

**Malformed IE compatibility meta tag**
```html
<meta content="IE=edge" />
```
Missing the required `http-equiv` attribute. Should be:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without it, older Outlook/IE rendering engines may not honor the directive.

**Partial dark mode implementation**
The `@media (prefers-color-scheme: dark)` block visible in the source only overrides `body` background and `a` color. CSS utility classes (`.bg1`, `.bgwhite`, `.bgcontent`, `.bgfooter`, etc.) have no dark-mode counterparts, meaning content areas will remain white-on-dark-background when the OS is in dark mode.
