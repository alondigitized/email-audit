## Technical Audit

## 1. Technical Summary
The email's tracked links have well-formed UTMs and per-recipient parameters, but the QA probe got 406/403 on all 12 probed links, and there is no plain-text part. Alt text is missing on every image, and the `<head>` has markup defects.

## 2. Link & Tracking Issues
- **All 12 probed links failed.** 11 returned 406 and the Unsubscribe link returned 403. They are all Cordial click-tracking redirects on `e.emails.hoka.com/c2/1664:…/<hash>?jwtH=…&jwtP=…&jwtS=…`.
  - Decoding the `jwtP` payload shows valid destinations. Examples: `https://www.hoka.com/en/us/best-sellers/?utm_…`, `https://www.hoka.com/en/us/return-start/?utm_…`, and `https://options.hoka.com/unsubscribe?cid=…`.
  - A uniform 406/403 across every link, including the unsubscribe link, points to bot-blocking of the probe's User-Agent. A broken template would not fail this uniformly.
  - **This is unconfirmed.** I can't say whether real recipients are affected, so treat these as unverified rather than confirmed broken.
- **The payload contains `"ce":86400`.** If this is a 24-hour link expiry, links would fail for recipients who open the email after a day. This is inferred from the field value only, not confirmed.
- **Two open-tracking pixels.** `https://e.emails.hoka.com/o/p/1664:…` and `https://mg.emails.hoka.com/o/eJyMzU…` both have no alt text.
- **Image links have no accessible text.** Their link text falls back to filenames, for example `[image: US_20261107_TrendingColors_a.gif]`.

## 3. Rendering & Accessibility
- **Alt text is missing on 15 images.** This covers all 13 content/logo images on `images.usw2.cordial.com/1664/…` (for example `US_Clifton11_TopLeft_1176573-FYGL.jpg` and `LogoFooterPrimary.png`) plus the 2 tracking pixels.
  - This email is image-heavy, so image-blocking clients will show an essentially blank body, and screen readers will read filenames.
- **Empty `<title></title>`.**
- **Invalid charset declaration.** `<meta content="text/html; charset=utf-8" />` has no `http-equiv` attribute, so it doesn't declare a charset.
- **Duplicate, conflicting viewport tags.** The first has `maximum-scale=1`, which blocks pinch-zoom. The second has `user-scalable=yes`. Remove the first.
- **Invalid CSS with empty values:**
  - `.nav_padding {padding-top:px !important;padding-bottom:px !important;}`
  - `.nav_border {border-top:px solid ;}`
- **Global reset `* {… outline:none …}`** removes keyboard focus indicators on links.
- **Plain-text part is missing.** The QA check reports "Text version is 0 chars", which is a rendering and deliverability fallback issue.

## 4. Personalization & Merge Tokens
No issues found. The visible source and the decoded link payloads show no unrendered merge tokens such as `{{…}}` or `%%…%%`. The HTML provided is truncated, so the body copy wasn't fully checked.

## 5. Compliance
- **Authentication can't be verified.** The `Authentication-Results` header is absent (QA WARN), so SPF/DKIM/DMARC status is unknown. The sender is `info@emails.hoka.com` with an `emails.hoka.com` tracking domain, which looks aligned, but that is an inference.
- **Unsubscribe link present but unverified.** It points to `options.hoka.com/unsubscribe?cid=…` and returned 403 to the probe (likely bot-blocking, as above). A manual click-through is needed to confirm it works.
- **`List-Unsubscribe` / `List-Unsubscribe-Post` headers and the physical postal address** can't be verified from the truncated HTML and the QA data provided.

## 6. Email-to-Site Continuity
- **UTMs are present and consistent.** Every decoded destination carries `utm_source=US_Broadcast`, `utm_medium=email` and the same `utm_campaign=H_US_BR_20261107_TrendingColors_STO_A30Day_90Purchasers_270BestSellersTag_HighLTV_AIPurchasePropensityHigh_0629Openers_WishListAdd`.
- **No `utm_content` or `utm_term`.** All 9 product and hero links share one campaign string, so link-level click attribution isn't possible in analytics.
- **Segment data in the query string.** The campaign string exposes audience criteria such as "HighLTV" and "AIPurchasePropensityHigh". Together with `hmail=<hash>` and `cordial_id=…`, these are visible to the recipient and to any third-party scripts on the landing page.
- **Destinations look aligned with the content.** Product links go to PDPs with a colour parameter, for example `clifton-11/1176573.html?dwvar_1176573_color=FYGL`. The hero links go to `/best-sellers/`. I couldn't load the landing pages to confirm that the colours are in stock.

## 7. Recommendations
1. Re-probe the Cordial links with a browser-like User-Agent, or allowlist the QA probe. Confirm the unsubscribe link works by hand. Check what `ce:86400` does and whether links expire after 24 hours.
2. Add descriptive `alt` text to all 13 content images, and `alt=""` to the 2 tracking pixels.
3. Generate a plain-text MIME part.
4. Fix the `<head>`:
   - Add `http-equiv="Content-Type"` to the charset meta.
   - Set a non-empty `<title>`.
   - Remove the first viewport tag so the page can zoom.
   - Delete or complete the empty-value CSS rules.
   - Restore focus styles for links.
5. Add `utm_content` per module for link-level attribution. Consider moving the audience descriptors out of `utm_campaign`.
6. Confirm the `Authentication-Results` and `List-Unsubscribe` headers on the raw message, since the relay path hides them here.
