# For all dad’s many miles
**Score:** 6/10 · **Type:** Email audit · **2026-06-08**
## Executive summary

- HOKA's going back to the Father's Day well, and honestly, they earned a second trip after that solid "Gifts for every dad" send two weeks ago. "For Every Father" lands big and bold at the top — I can read it without squinting, which is more than I can say for some of their recent emails. The layout is organized: Road, Trail, Race, Lifestyle, Travel. Clean sections, decent thumbnails.
- But here's my problem — this email is coded for runners, not comfort walkers. "Is dad pulling in the miles? Keep him going in our top styles for everyday running." I don't pull miles. I walk my neighborhood, run errands, and stand at the grill. The Road and Race sections are wasted real estate on me, and the apparel push at the bottom — young guy in a red top — feels like it was dropped in from a different email. And there's not a single price anywhere. Not a sale, not a range, not even a "from $X." For a gift guide where I'm supposed to be buying for someone else, I need numbers.
- I'd scroll down to Lifestyle and Travel before closing it. The Ora Recovery Walk in the Travel section is the kind of shoe that'd actually catch my attention — but I'd have to dig past three sections I don't care about to find it. Mark as read with maybe a tap on Lifestyle. Wouldn't forward this one.

## What's working

- **"For Every Father" hero copy** is big, readable, male-targeted — I see it the second the email opens, no hunting required.
- **Category navigation** (Road, Trail, Race, Lifestyle, Travel) is smart structural work — I can skip to what matters even without prices.
- **Lifestyle and Travel sections** actually have shoes I'd look at — the chunky recovery-looking silhouettes in those rows signal comfort without saying "old man shoe."
- **"Shop Father's Day" CTA** is a clean, unambiguous button — I know exactly where it takes me.
- **No render bugs** — images loaded, text didn't overlap, nothing looked broken.

## What's weak

- **Zero pricing anywhere** — this is a gift guide and I can't do any price math. Every shoe is just a name and a thumbnail. That's a missed opportunity.
- **"Everyday running" framing in the hero** pushes me away immediately — I'm not a runner, and leading with that language tells me this email isn't really for me.
- **Road and Race sections are filler** for someone like me — two full category blocks I'm skipping past.
- **The apparel section** at the bottom feels pasted on from a different campaign; young athlete in red performance gear is demographically irrelevant to me as a Father's Day recipient.
- **No comfort or fit language** anywhere visible — no "cushioned," no "arch support," no "wide fit" — the words I actually shop on are absent.

## Recommendations

- 1. **Lead the hero copy with comfort language**, not running language. "Comfort for every mile he walks" beats "everyday running" for a guy my age.
- 2. **Add prices** — even "from $89.95" under each shoe. Gift givers need a budget signal; remove that friction.
- 3. **Reorder the categories** — put Lifestyle and Travel first, Road second, move Race to the end or drop it for this audience.
- 4. **Cut the apparel section** or replace it with a comfort-accessory offer (insoles, recovery footwear) that fits the gift occasion.
- 5. **Add one specific podiatrist/comfort callout** like they did on the 5/28 "Comfort you can count on" send — that trust signal works on me.

- **Subject Alt B:** `The walking shoes dads actually want`

### 3. Rendering & Accessibility

**Three confirmed bugs:**

**a) Broken CSS values in mobile media query** (`@media only screen and (max-width:480px)`)
```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
.nav_border  { border-top:px solid ; }
```
Both declarations have missing numeric values — `px` with no number, and `border-top` missing both width and color. These rules parse as invalid and are silently dropped by all clients. Navigation spacing and border will not apply on mobile.

**b) Duplicate `<meta name="viewport">` tags**
Two viewport meta tags are present in `<head>`:
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
Browsers use the last declaration; these also conflict (`maximum-scale=1` vs `user-scalable=yes`). The second tag's `user-scalable=yes` contradicts `maximum-scale=1` on the first.

**c) Missing `http-equiv` on charset meta**
```html
<meta content="text/html; charset=utf-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, this tag has no effect. Charset declaration relies entirely on the HTTP `Content-Type` header or the `<html>` tag's implicit encoding.

**d) Empty `<title>` tag**
```html
<title></title>
```
Some email clients (Apple Mail, Outlook on macOS) display the `<title>` value as the window/tab label. Empty title is a minor but unnecessary gap.

**e) Custom font fallback stack not visible**
Five `@font-face` declarations load `TheFutureHOKA` and `TheFutureHOKAMono` from Demandware CDN. Web fonts are blocked by Gmail (all clients), Outlook (Windows), and Yahoo. The truncated source doesn't show inline `font-family` declarations with fallback stacks — if body copy specifies only `TheFutureHOKA` without a system-font fallback, text will render in client default (usually Times New Roman on Outlook/Windows). Cannot confirm fallback presence from truncated source.
