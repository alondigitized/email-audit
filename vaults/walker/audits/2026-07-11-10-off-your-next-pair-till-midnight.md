### 3. Rendering & Accessibility

**BUG — Conflicting `-ms-text-size-adjust` declarations (CSS reset block):**
```css
* {
  -ms-text-size-adjust: 100%;   /* set first */
  ...
  -ms-text-size-adjust: none;   /* overrides above */
}
```
The second declaration wins. Setting `text-size-adjust: none` breaks user-controlled text scaling in IE/legacy Edge and is an accessibility regression. The `none` value should be removed; keep `100%`.

**BUG — Invalid `Src:` capitalization in all `@font-face` blocks (8 instances):**
```css
Src: url("https://braze-images.com/...") format('woff');
```
CSS property names are case-insensitive per spec, but `Src:` is non-standard and will silently fail in stricter XHTML/CSS parsers (some Outlook rendering engines, Lotus Notes). Should be lowercase `src:`.

**MINOR — `supported-color-schemes` declared twice, in two different syntaxes:**
- `<meta name="supported-color-schemes" content="light dark" />` (Apple Mail legacy)
- `@media (prefers-color-scheme: dark) { ... }` with `:root { supported-color-schemes: light dark }` (non-standard CSS property)

Intentional for Apple Mail compatibility, but `supported-color-schemes` as a CSS property is not a W3C standard — only the `<meta>` form is recognized. No functional breakage expected in current clients.

### 5. Compliance (CAN-SPAM, Unsubscribe, Authentication)

**Cannot audit unsubscribe link or physical address** — truncated before body.

**BUG — Malformed `Content-Type` meta tag (missing `http-equiv`):**
```html
<meta content="text/html; charset=utf-8" />
```
Missing `http-equiv="Content-Type"`. Some legacy XHTML parsers will not recognize the charset declaration. Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

**BUG — Malformed IE compatibility meta tag (missing `http-equiv`):**
```html
<meta content="IE=Edge" />
```
Missing `http-equiv="X-UA-Compatible"`. The directive is ignored without it. Should be:
```html
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```
