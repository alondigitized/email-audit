## Technical Audit

## 1. Technical Summary
The email has one confirmed broken-experience bug, an empty greeting slot ("Hi ,"). The HTML also has a scheme-less tracking pixel URL, two `http://` images, malformed `<meta>` tags and several accessibility gaps. SPF/DKIM, unsubscribe and UTM handling can't be verified from the supplied data.

## 2. Link & Tracking Issues
- **Scheme-less pixel (real bug):** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…">` has no `https://`. It resolves as a relative URL, so the request fails or hits the wrong host. The Return Path/Validity seed-tracking pixel never fires. The tag also has no `alt`.
- **Insecure tracking pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=MKG_US_NA_U_MULTI_ENGAGEDL14D_EN_10182026` is plain HTTP. QA flags it as likely to be blocked or rewritten, which would drop the measurement.
- **Third-party beacons:** Four `beacon.krxd.net` pixels carry a `partner_uid` that looks like a SHA-256 hash (64 hex chars). The same pixels use `width="0" height="0"` with `display:none`. This is a data-sharing and privacy exposure, but it's valid markup.
- **Open pixel inside a hidden container:** `click.emails.skechers.com/open.aspx?…` sits in a `display:none !important` div. Some clients don't load images in hidden containers, so open counts may be understated.
- **Not probed:** QA skipped 37 tracking/click-redirect links, so destination validity and redirect chains are unverified.

## 3. Rendering & Accessibility
- **Malformed meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv`. The charset declaration is therefore ineffective. The content-type header normally covers it, but this is still invalid.
- **Missing alt text (QA-confirmed):** `o.gif` (ink1000) and `dde00662-169f-447d-b0e2-fc65f6c2290c.png`. The second image is hosted at `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/…` and looks like a content image, so it needs real alt text.
- **Insecure image source:** That same PNG is served over `http://`. This can trigger mixed-content blocking or proxy rewrites, and the image may fail to render.
- **Zoom disabled:** `<meta name="viewport" content="… maximum-scale=1">` blocks pinch-zoom (WCAG 1.4.4).
- **Focus outline removed:** `a { outline: none; }` removes keyboard focus indicators.
- **Text resize suppressed:** `* { -webkit-text-size-adjust: none; }` stops iOS text resizing.
- **Layout tables:** The visible tables (`<table cellpadding="0" cellspacing="0" border="0">`) have no `role="presentation"`.

- **Generic title:** `<title>Skechers®</title>` doesn't describe the email.
