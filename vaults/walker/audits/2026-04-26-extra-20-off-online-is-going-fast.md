### 3. Rendering & Accessibility

**Confirmed defects:**

**3a. Missing `http-equiv` on charset meta tag**
```html
<!-- ACTUAL (broken) -->
<meta content="text/html; charset=utf-8" />

<!-- CORRECT -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv="Content-Type"`, the charset declaration is inert in some legacy clients (Outlook 2007–2016 on Windows). Risk: mojibake on special characters (e.g., the `⏳` in the subject line may render as `?` in-body in affected clients).

**3b. Viewport meta missing `initial-scale`**
```html
<!-- ACTUAL -->
<meta name="viewport" content="width=device-width" />

<!-- CORRECT -->
<meta name="viewport" content="width=device-width, initial-scale=1" />
```
Omitting `initial-scale=1` can cause iOS Mail to render at a zoomed-out scale on first load before the user interacts.

**3c. CSS selector typo — `col-9` / `col-8` collision in `md-fluid-row`**
```css
/* Line in <style> block — md-fluid-row targets col-8, not col-9 */
.fluid-row .col-9, .md-fluid-row .col-8 { width: 74.25% !important; }
```
**Bug:** `.md-fluid-row .col-8` appears here AND in the `col-8` rule above it (66%). This creates a specificity conflict: on mid-width viewports, `col-8` elements inside `md-fluid-row` will receive 74.25% width instead of 66%, misaligning any 8-column fluid block. Meanwhile `.md-fluid-row .col-9` has no explicit rule, so col-9 elements fall back to the full-width `100%` override from the `.row .col-9` rule, which may or may not be the intended behavior.

**Correct version should be:**
```css
.fluid-row .col-9, .md-fluid-row .col-9 { width: 74.25% !important; }
```
