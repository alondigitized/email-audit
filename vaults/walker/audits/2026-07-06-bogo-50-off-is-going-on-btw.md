### 3. Rendering & Accessibility

**`Src:` capitalization in all 10 `@font-face` declarations (confirmed)**

Every `@font-face` block uses `Src:` (capital S) instead of the valid CSS property `src:`. Example:

```css
@font-face {
  font-family: 'Futura_PT_Regular';
  Src: url("https://braze-images.com/...") format('woff');
}
```

This is invalid CSS per spec. Most modern renderers are lenient and parse it anyway, but strict CSS parsers (some webmail clients) will silently skip the declaration, forcing fallback fonts for all 10 declared faces.

**`text-size-adjust: none` conflicts with vendor-prefixed `100%` values**

The global `*` reset block sets:
```css
-webkit-text-size-adjust: 100%;
-ms-text-size-adjust: 100%;
text-size-adjust: none;  /* ← conflicts */
```

`none` disables text size adjustment entirely; `100%` preserves it. The unprefixed property should be `100%` to be consistent, or omitted. This can cause unpredictable text scaling behavior on Android clients that support the unprefixed property.

**Font formats: no `woff2` for Futura PT; no `woff`/`woff2` for HelveticaNow**

- Futura PT: `.woff` only — `woff2` is ~30% smaller and supported in all modern email clients
- HelveticaNow: `.ttf` only — `.ttf` is the least compressed format; no `woff` or `woff2` fallback offered
