### 3. Rendering & Accessibility

**`<meta charset>` missing `http-equiv`**
```html
<!-- current (broken) -->
<meta content="text/html; charset=utf-8" />
<!-- correct -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv="Content-Type"`, Outlook and older clients may not honor the charset declaration.

**`Src:` capitalization in all `@font-face` blocks**
```css
Src: url("https://braze-images.com/appboy/...woff") format('woff');
```
CSS property names are case-sensitive in some parsers. All ten `@font-face` rules use the capitalized `Src:` — this is the most likely cause of Futura PT / HelveticaNow falling back to system fonts silently. Should be lowercase `src:`.

**No `woff2` format declared**
Futura PT fonts offer only `.woff`; HelveticaNow fonts offer only `.ttf`. All modern email clients that support web fonts (Apple Mail, Outlook iOS) prefer `woff2`. Missing format means larger download with no quality gain.

**`maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from zooming on mobile — WCAG 1.4.4 (Resize Text, AA) violation.

**`text-size-adjust: none` in reset**
```css
-ms-text-size-adjust: none; text-size-adjust: none;
```
`100%` is the correct safe value; `none` disables OS-level text scaling and is an accessibility regression beyond what email reset requires.
