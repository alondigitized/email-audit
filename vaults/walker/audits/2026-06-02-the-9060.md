# The 9060
**Score:** 7/10 · **Type:** Email audit · **2026-06-02**
## Executive summary

- I've been getting a lot of New Balance emails lately, and this one takes a different tack — no sale countdown, no percentage-off headline, just the shoe front and center. I'll give them credit for that. Yesterday's "'70s structure meets 2000s tech" send was a similar move, and I appreciated the change of pace then too. So I didn't immediately delete this one.
- But once I'm inside, this email is talking to someone younger and more fashion-forward than me. "Modern expressionism" — I don't even know what that means for a sneaker. The model is young, the styling is editorial, and I'm looking at a chunky shoe in what seems like multiple colorways. My questions — does it come in a wide? Is there any arch support? How does it feel after a two-hour walk at the outlet mall? — none of that gets answered.
- I'd mark this as read and move on. Wouldn't click, wouldn't forward. If a buddy asked me "hey what's New Balance sending these days," I'd tell him they're doing artsy product story emails now. That's about the sum of it.

## What's working

- **Clean visual hierarchy.** The hero shoe image hits first, the name "The 9060" is right below it, and my eye moves in a straight line down the page without getting lost.
- **No sale fatigue this time.** After four-plus "25% off select shoes" sends in a row, a product-focused email is genuinely refreshing. I actually paused to look at the shoe.
- **Free shipping callout at the top.** Small but useful — that $75 threshold is visible before I even scroll and it's the kind of practical detail I actually factor in.
- **Colorway grid is well laid out.** "More to explore" with all those 9060 options in a clean grid loads well and doesn't feel cluttered on a phone screen.
- **No render bugs.** Everything displays cleanly — no broken images, no layout collapse, text is legible.

## What's weak

- **"Modern expressionism" means nothing to me.** I'm 62, not an art school grad. If you want me interested in a shoe, tell me if my feet will hurt less after wearing it, not what movement it belongs to.
- **The model is not me.** Young, fashion-forward styling. I keep seeing myself compared to the editorial vision here and I'm not in the frame at all.
- **Zero comfort credentials.** No mention of cushioning, no Fresh Foam callout, no width options, no "designed for all-day wear." The 9060 might have great support — I genuinely don't know because the email doesn't tell me.
- **"Colorways for all ages" feels like a kids re-run.** Last week's kids email already got me wondering if NB thinks I'm shopping for grandkids. Seeing "for all ages" with what looks like another child-styled shot doesn't make me feel like a target.

## Recommendations

- 1. **Lead with one comfort/fit credential in the hero copy.** Even a single line — "Fresh Foam cushioning. All-day comfort." — changes who this email speaks to. Right now it's pure style; add one functional hook and you've got both audiences.
- 2. **Swap the model or add a secondary lifestyle shot.** Show someone my age actually wearing these out in the world — walking a park path, running errands. Editorial cool is fine but not if it's the only image in the email.
- 3. **Add width availability near the CTA.** "Available in standard and wide widths" is the kind of detail that gets me to click. I'm already half-interested; close the deal with specifics.
- 4. **Make the CTA more specific.** "Shop Now" is generic. "Shop The 9060" at minimum, or "Find My Size" if you want to push harder.

## Technical Audit — New Balance "The 9060" Email

### 1. Technical Summary

The email uses an HTML 4.01 Transitional doctype with XHTML namespace mixing and several CSS authoring defects. Dark-mode scaffolding is present but the source is truncated, preventing full compliance and link verification.

---

### 2. Link & Tracking Issues

**Placeholder URL in production CSS**
`.bgwhite` class contains a literal unreplaced token:
```css
background-image: url('http://image.XXXXX.png');
```
If this reached production as-is, the background image would 404. Confirms an ESP variable substitution failure in the stylesheet block.

**Unable to verify CTA link UTM coverage** — source truncated before `<body>`. Flag for full-source re-audit.

---

### 3. Rendering & Accessibility

**Duplicate `.bg1` class — value collision**
Defined twice in the same `<style>` block with conflicting values:
```css
.bg1 {background-color: #ffffff;}  /* first definition */
...
.bg1 {background:#58546d;}         /* overrides — purple/grey */
```
The second definition wins in all clients that parse standard CSS cascade. Any element using `.bg1` expecting white will render purple-grey.

**Malformed `<meta>` tag**
```html
<meta content="IE=edge" />
```
Missing required `http-equiv` attribute. Should be:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without it, the IE compatibility directive has no effect.

**Invalid `@font-face` block — duplicated `font-family` property**
The proxima-nova italic declaration contains a CSS authoring error:
```css
@font-face {
  font-family: proxima-nova,sans-serif;
  font-weight: 700;
  font-style: italic;font-family: proxima-nova,sans-serif;  /* duplicate */
}
```
The inline-concatenated duplicate property is invalid CSS. Minor in practice since all `@font-face` blocks lack `src:` URLs anyway (see below).

**All `@font-face` blocks missing `src:` declarations**
Nine `@font-face` rules are present with no `src:` value. They declare family names only and will never load. Proxima Nova and Linotype Didot require Adobe Fonts/Typekit JS injection, which email clients block universally. The fallback stack (Arial, Times New Roman) will always be used — the `@font-face` blocks are dead weight that inflate payload size.

**Doctype / namespace mismatch**
```html
<!DOCTYPE html PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" ...>
<html xmlns="http://www.w3.org/1999/xhtml" ...>
```
HTML 4.01 Transitional doctype with an XHTML namespace is contradictory. Gmail and Outlook strip doctypes anyway, but this inconsistency can trigger quirks-mode parsing in some webmail renderers.

**`charset` meta placement**
`<meta charset="UTF-8" />` appears after other `<meta>` tags. Spec requires it as the first element in `<head>` (within the first 1024 bytes) to prevent encoding sniffing before the declaration is parsed.

**Dark mode implementation** — partial credit: `color-scheme: light dark` on `<html>`, matching `<meta name="color-scheme">`, and a `@media (prefers-color-scheme: dark)` block are all present. Full assessment blocked by truncation.
