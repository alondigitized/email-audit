## Executive summary

- Soon as I opened this one, I could tell it wasn't aimed at me. The photography is dramatic — rocky trails, athletic poses, dramatic lighting — and it looks sharp. I'll give them that. But everything from the headline to the product names (Speedgoat? - **Zero offer.** No sale, no percent off, no free shipping. Just "go look at these." At my age I'm not clicking out of curiosity, I'm clicking because there's a reason to buy.

### 3. Rendering & Accessibility

**Duplicate `<meta name="viewport">` tags**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
The second tag resets `user-scalable=yes`, which contradicts `maximum-scale=1` on the first. Behavior is undefined when both exist. Remove the first; keep only the second (the more permissive one).

**Missing `http-equiv` on charset `<meta>`**
```html
<meta content="text/html; charset=utf-8" />
```
The `http-equiv="Content-Type"` attribute is absent. Spec-compliant form is `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />`. Some clients rely on this for charset negotiation.

**Blank `<title>` tag**
```html
<title></title>
```
Empty titles are penalized by some spam classifiers. Set a descriptive value (e.g., `HOKA® — Take on the terrain`).

**Malformed CSS rules in `@media (max-width: 480px)`**
```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
.nav_border  { border-top:px solid ; }
```
Both rules contain invalid CSS: numeric values are missing before `px`, and the `border-top` color token is empty. These will be silently dropped by all parsers. This is likely a template merge failure (tokens resolved to empty string).

**Web fonts unsupported in target clients**
`@font-face` for TheFutureHOKA/TheFutureHOKAMono is not honored by Gmail (web/app/AMP), Outlook (all versions), or Yahoo Mail — together representing the majority of email opens. The fallback font stack is not visible in the truncated source and must be verified. If no `font-family` fallback is declared, clients will default to Times New Roman.

**`font-display: swap` in `@font-face`**
This is a browser-rendering hint; it has no effect in any email client and adds dead markup weight.

**Overly broad CSS reset**
```css
* { -webkit-text-size-adjust: none; }
```
Applying `-webkit-text-size-adjust: none` via the universal `*` selector can cause text-sizing issues in WebKit-based clients. Scope this to `body` only.
