## Technical Audit — Skechers "Summer's Almost Official" Email

---

### 1. Technical Summary

The email has a significant mixed-content (HTTP vs HTTPS) problem across 12+ images and one third-party tracking pixel, plus a broken Return Path deliverability pixel caused by a missing URL protocol. The QA tool summary is also internally contradictory and should not be trusted as-is.

---

### 2. Link & Tracking Issues

**Broken Return Path pixel — missing protocol**
```html
<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db...">
```
No `http://` or `https://` prefix. This resolves as a relative URL and fires against the ESP's own domain — the deliverability monitoring pixel is silently broken.

**HTTP-only ink1000 tracking pixel**
```
src: http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=MKG_US_L30D_U_MULTI_ENGAGED_EN_06202026_B
```
Plain HTTP. Gmail and Apple Mail will block or proxy this, defeating the impression/open signal.

**26 click-redirect links unverifiable**
All outbound links pass through `click.emails.skechers.com`. The QA tool skipped all 26 — no confirmation that destination URLs resolve or that UTM parameters are attached (see §6).

**Third-party DMP pixel exposes subscriber identity**
Two Krux pixels pass subscriber data to `beacon.krxd.net`:
- SHA-256 hashed email: `partner_uid=9153f33fe5...ced00`
- Raw subscriber ID: `partner_uid=121173391`

This is an intentional integration but is worth confirming against current consent/privacy policy, especially for EU/CA recipients.

---

### 3. Rendering & Accessibility

**Mixed HTTP/HTTPS image sources — 12 images**

All images served from `image.emails.skechers.com` in the footer and lower body use `http://`:
- Skechers logo: `http://image.emails.skechers.com/.../dde00662-...png`
- App Store badge, Google Play badge, Curbside Pickup, AfterPay, Find A Store, Instagram, Facebook, YouTube icons — all HTTP

Gmail's image proxy will rewrite these to HTTPS, but Apple Mail on iOS/macOS, Outlook, and privacy-proxy clients may block or break them. The fix is to serve all assets over HTTPS at the CDN level.

**Missing alt text — 3 images**

| Image | URL |
|---|---|
| Ink1000 tracking pixel | `http://www.ink1000.com/.../o.gif` |
| Hero/product image | `https://image.emails.skechers.com/.../fad3dc53-...jpg` |
| Unknown content image | `http://image.emails.skechers.com/.../49468f73-...png` |

The hero image missing alt text is the highest priority — screen readers skip it entirely, and it shows no fallback text when images are blocked.

**`-webkit-text-size-adjust: none` applied globally**
```css
* { -webkit-text-size-adjust: none; }
```
The correct value is `100%`, not `none`. `none` prevents users from adjusting text size on mobile — a WCAG 1.4.4 failure. This also triggers known rendering bugs in certain WebKit clients.

**`maximum-scale=1` in viewport**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocks pinch-to-zoom. An accessibility concern; Apple removed enforcement of this in Safari but it remains an issue in other mobile environments.

**Duplicate media query blocks**
The 375px and 640px breakpoints define identical rule sets for `.hideme`, `.hidden`, `.mobile-hidden`, `.widthFull`, `.responsive-td`, etc. This is redundant dead weight but not a rendering defect.

**Two conflicting content-toggle systems**
The email uses both a `show`/`hidden` class pattern (show on mobile via media query) and a `mobile-content`/`desktop-content` class pattern (hide desktop via `display:none` in base CSS, reveal via `min-width: 768px` media query). These operate independently and could produce double-show or double-hide in certain clients that partially support media queries (e.g., Outlook 2019 on Windows).

### 6. Email-to-Site Continuity

All 26 outbound links are wrapped in `click.emails.skechers.com` redirects. UTM parameter presence cannot be confirmed without resolving those redirects. The QA tool skipped all of them.

Minimum expected UTM structure on destination URLs:
```
?utm_source=email&utm_medium=email&utm_campaign=MKG_US_L30D_U_MULTI_ENGAGED_EN_06202026_B&utm_content=[block-identifier]
```

This should be manually spot-checked on 3–5 destination links, including the primary CTA and the BOGO/20%-off landing page. Missing or inconsistent UTMs will break campaign attribution in GA4/Adobe Analytics.
