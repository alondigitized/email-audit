## Technical Audit

## 1. Technical Summary
The email is a Braze/SendGrid-style send with tracked redirects on `ablink.dsw.com`. The QA run found one probe failure (HTTP 400 on the SMS opt-in CTA), a pixel and a tracked image with no alt text, and a viewport setting that blocks zoom. The source is truncated and only 12 of 79 links were probed, so SPF/DKIM, the unsubscribe link and destination URLs could not be checked.

## 2. Link & Tracking Issues
- **[FAIL] SMS opt-in CTA returned 400.** The link text is "Opt-In to Texts Get 15% Off". The URL is `https://ablink.dsw.com/f/a/DeTzrImSPUwJOCh3TzhkhQ~~/AAQRxRA~/AUARootFFfATvilshufpsIXCoMeFs41…~`.
  - This is the only hard failure in the run, and the CTA is a conversion point.
  - A 400 from a click-tracking redirector can mean a truncated or malformed token. It can also mean the redirector rejects the probe's request, so a manual click test from a real client is needed to confirm.
  - The QA output shows an empty resolved-destination field (`Broken link (400): `), so the final landing page is unknown.
- **All links are wrapped in `ablink.dsw.com` redirects.** The final destinations and any UTM parameters cannot be verified from the HTML source.
- **Plain-text part is more than 70% URLs.** 29,603 of 35,419 characters are URLs, a result of long tracked-link tokens. It is a minor spam-score and readability risk for text-only clients.
- **Probe coverage is partial.** 12 links were probed and 67 were skipped. Link health for the rest is unknown.

## 3. Rendering & Accessibility
- **Zoom is disabled.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` blocks pinch-zoom in some clients, which conflicts with WCAG 1.4.4 (Resize Text).
- **Missing alt text on two images:**
  - `https://ablink.dsw.com/q/V2P_6iaRjjKCJGt7vcmIUQ~~/…`. Its role is unclear from the truncated data. If it is content, it needs descriptive alt text. If it is decorative, it needs `alt=""`.
  - The tracking pixel `https://mi.dsw.com/p/up/e6f23fb024fdcb2cc855b9ed672710d4/o.gif?…`. It should carry `alt=""` so screen readers skip it.
- **Meta tags are missing `http-equiv`.** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv` attribute, so the charset and compatibility declarations have no effect. The charset is likely set via the MIME Content-Type header anyway, so the practical risk is low.
- Dark-mode and `color-scheme` meta tags are present, and `@font-face` fallbacks could not be assessed in the truncated source.

## 4. Personalization & Merge Tokens
No issues found. No unrendered merge tokens (such as `{{ }}`, `%%`, or `[FIRST_NAME]`) appear in the visible source. The pixel URL carries a per-recipient ID (`mi_u=225090073`) and a campaign code (`mi_ecmp=20261124_P251285_V2_WM-_Offer_MI_C`), both rendered correctly.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **[WARN] No `Authentication-Results` header.** The QA notes this is expected via the AgentMail relay, so SPF/DKIM/DMARC status is unknown. This is a limitation of the test setup and not a confirmed sender defect. Verify with a direct-delivery test.
- **Unsubscribe and physical address could not be confirmed.** The footer is cut off in the truncated source, and no unsubscribe-link probe result was reported. I am not flagging a violation, but this needs a check against the full HTML. It should also include a `List-Unsubscribe` / `List-Unsubscribe-Post` header check.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Cannot verify.** Destinations are hidden behind `ablink.dsw.com` redirects, and the only resolved-destination result is the failed SMS link.
- **Tracking is campaign-coded.** The open pixel carries `mi_ecmp=20261124_P251285_V2_WM-_Offer_MI_C`, but no UTM parameters could be seen on any link.
- The 30%-off claim in the subject line cannot be matched to a landing page from the data provided.

## 7. Recommendations
1. Click-test the SMS opt-in link (`ablink.dsw.com/f/a/DeTzrImSPUw…`) from a real client. If it returns 400 there too, regenerate the tracked link or fix the destination in the ESP.
2. Remove `maximum-scale=1` from the viewport meta tag.
3. Add `alt=""` to `o.gif`. Add meaningful alt text to the `ablink.dsw.com/q/…` image, or `alt=""` if it is decorative.
4. Add `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"` to the two meta tags.
5. Re-run the audit against the full HTML and a direct-delivery copy, to confirm the unsubscribe link and `List-Unsubscribe` header, SPF/DKIM/DMARC alignment, and UTM presence on resolved destinations.
6. Raise probe coverage beyond 12 of 79 links, and add the plain-text part's URL-to-text ratio to the watch list.
