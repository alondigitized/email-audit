## Technical Audit

## Technical Audit — Adidas "Predator or F50" Email

### 1. Technical Summary

Two confirmed failures: a broken click link and a missing plain-text fallback. Additionally, four images are served over HTTP (not HTTPS) and two images lack alt text, both of which degrade deliverability and accessibility scores.

---

### 2. Link & Tracking Issues

**[FAIL] Broken redirect — unknown URL type**
The QA probe on the primary CTA resolves to a relative path instead of an absolute URL:
```
unknown url type: '/g/77c97694-5cb0-4d38-9c34-0f6a912da56c?txn=2c934e80-654b-11f1-b383-3efb318f62ec'
```
Entry URL: `https://dv.adidas.com/o/77c97694-5cb0-4d38-9c34-0f6a912da56c?cp_tp=v3.eJx9kD0s...`

The `dv.adidas.com` redirect chain is emitting a relative `/g/` path rather than an absolute destination. Recipients who click this link land nowhere. This is a critical broken-experience failure.

**[INFO] 24 tracking links skipped**
All click-redirect domains (`dv.adidas.com`, `click.comms.adidas.com`) were skipped during HTTP probing. Only the one above was flagged; the remainder are unverified.

---

### 3. Rendering & Accessibility

**[WARN] HTTP image sources — may be blocked by email clients**
The same arrow image is referenced four times via HTTP:
```
http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg
```
Gmail, Outlook (web), and Apple Mail proxy or block non-HTTPS image sources. All four instances of this src will likely render as broken images on those clients.

A tracking/open-pixel is also served over HTTP:
```
http://click.comms.adidas.com/CI0/0102019eb4da312d-4f3ae2c8-763a-4297-97d5-4b3b57ce58c1-000000/...
```
This will suppress open-tracking on clients that enforce HTTPS-only mixed-content rules.

**[WARN] Missing alt text on two images**
- `https://dv.adidas.com/o/77c97694-5cb0-4d38-9c34-0f6a912da56c?cp_tp=v3.eJx9kD0s...` — no `alt` attribute
- `http://click.comms.adidas.com/CI0/.../C_dk7C6VnLDnSIGB_cjEEY3Kd...` — no `alt` attribute

The first is a content image (not a pixel), so this is an accessibility gap for image-off and screen-reader rendering.

**[MINOR] Duplicate @font-face declarations**
`AdihausDIN` and `AdineuePRO` are each declared twice across two separate `<style>` blocks with slightly different fallback lists (`Calibri` / `Sans Serif` present in block 1, absent in block 2). The duplication adds ~800 bytes of dead CSS and creates an ambiguous cascade. One block should be removed.

**[MINOR] Malformed charset meta**
```html
<meta content="text/html; charset=UTF-8" />
```
Missing `http-equiv="Content-Type"`. Some legacy clients (Outlook 2007–2013) will not apply the charset declaration without it:
```html
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
```

---

### 4. Personalization & Merge Tokens

No issues found. No unresolved `{{token}}`, `*|MERGE|*`, or `%%variable%%` patterns are visible in the provided HTML source.

### 5. Compliance

**[FAIL] Plain-text fallback is absent**
QA reports 0 characters in the text/plain MIME part. CAN-SPAM does not mandate a plain-text part, but SpamAssassin and Gmail's filters apply a negative score to HTML-only messages. Most commercial ESPs require a non-empty text part as a send prerequisite. This is a deliverability risk and an ESP configuration gap.

**[INFO] Unsubscribe link not visible in truncated source**
The HTML was cut before the footer. CAN-SPAM §5(a)(5) requires a functional opt-out mechanism in every commercial message. Assumed present in the footer; should be verified in the full source.

**[INFO] `referrer: no-referrer` meta is set**
```html
<meta name="referrer" content="no-referrer" />
```
This is intentional (suppresses referrer leakage to landing pages), but it means web-version clicks will appear as direct traffic in GA4/Adobe Analytics rather than email-attributed sessions. UTM parameters on links are the only attribution signal.

---

**[FAIL] Primary CTA link is broken** (see §2) — no UTM evaluation is possible until the redirect chain is fixed.
