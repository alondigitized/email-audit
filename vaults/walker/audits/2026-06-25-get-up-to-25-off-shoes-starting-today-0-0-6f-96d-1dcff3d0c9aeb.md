# Get up to 25% off shoes, starting today.
**Score:** 8/10 · **Type:** Email audit · **2026-06-18**
## Executive summary

- I opened my inbox this morning and saw New Balance again — which, at this point, feels like Groundhog Day. Yesterday they were telling me the sale was "almost over." Today they're back telling me one is "starting today." Same twenty-five percent. I've been watching this same number bounce around my inbox since early June. At some point the urgency just stops working on me.
- That said — the email itself isn't a mess. The headline is clear, the Shop Now button is right there, and I can see specific shoes in the lower half: that Fresh Foam 680v8 actually caught my eye because that's the kind of walking shoe I'm looking for. But I had to scroll to find it. What I don't need is a t-shirt halfway down the email, or a Kids category taking up a third of the shop-the-sale block.
- I'd call this one a "save for later" — I might circle back Wednesday before the sale ends, but I'm not clicking right now. The brand burned through its credibility by crying wolf on the deadline too many times. I'm not forwarding this to anybody.

## What's working

- **25% off shoes is front and center** — the headline is big, clean, and I don't have to hunt for the offer.
- **Preview text earned its keep** — "Plus, up to 30% off select clothing and accessories" actually adds information the subject didn't cover, which is the right move.
- **Fresh Foam 680v8 in the product grid** — that's a real walking shoe, the kind of thing I'm actually shopping for. Happy to see it in there, even if it's buried.
- **Shop Now button is clear** — black button, simple text, hard to miss even on my phone screen.
- **Clean render** — no broken images, no overlapping text, everything loaded fine.

## What's weak

- **Yesterday the sale was "almost over." Today it's "starting."** Same 25%, same brand, back-to-back days. That's not a sale, that's a revolving door. I don't trust the deadline anymore.
- **Hero image is a stack of shoeboxes, not shoes.** I want to see what the shoe looks like on a foot, not in packaging. Boxes don't help me decide if something's going to fit my foot right.
- **Kids category takes up a third of the shop-the-sale section.** I'm 62. I'm not buying kids' shoes. That real estate is wasted on me.
- **A t-shirt in the product grid.** I'm here for shoes. The Athletics Cotton T-Shirt showing up in "More to explore" is a miss — I don't open New Balance emails to shop for tops.
- **No comfort callouts anywhere.** Nothing about cushioning, arch support, wide widths — the things that actually move me toward a purchase. The 680v8 is sitting there unlabeled.

## Recommendations

- 1. **Stop resetting the 25% sale the day after "almost over."** If the cadence is going to be weekly sales, at least change the percentage or the category so it doesn't feel like a con. The credibility erosion is real and cumulative.
- 2. **Lead with the shoe, not the box.** Replace the hero image with a side-profile shot of the Fresh Foam or a comparable walking shoe — something I can imagine on my foot.
- 3. **Pull the Kids tile and replace it with a Walking or Comfort category.** That's a targeting decision that would pay off immediately for someone in my demographic.
- 4. **Add one comfort descriptor to the product tile copy.** Even "Extra cushioning" or "Wide available" next to the Fresh Foam would stop me mid-scroll.
- 5. **The code requirement (SUMMER24) visible in the fine print should be surfaced higher** — I shouldn't have to squint at the bottom of the email to know I need to enter a code at checkout.
- **Subject Alt A:** `Your 25% off window opens today — men's shoes`
- **Subject Alt B:** `Fresh Foam 680v8 is 25% off. Ends Wednesday.`
- **Preheader Alt A:** `Comfort walkers, wide widths, and trail options — all in the sale.`
- **Preheader Alt B:** `Ends Wednesday. No code needed — discount applies at checkout.`

### 1. Technical Summary

HTML 4.01 Transitional template with dark-mode support; three confirmed code defects in the `<head>` alone (duplicate class conflict, broken IE meta directive, placeholder URL). Full link/compliance analysis is limited by HTML truncation.

### 2. Link & Tracking Issues

**Placeholder/broken background image URL**
`.bgwhite` class in `<style>`: `background-image: url('http://image.XXXXX.png')`
`XXXXX` is either an unfilled merge token or a redaction artifact. If the literal string shipped, this image 404s for every recipient.

**HTTP (non-HTTPS) asset reference**
Same URL uses `http://` not `https://`. Gmail, Outlook.com, and Apple Mail all strip or block mixed-content HTTP assets in an HTTPS-loaded message, silently removing the background.

*UTM/link-level tracking cannot be verified from truncated source — spot-check required on rendered output.*

---

### 3. Rendering & Accessibility

**`.bg1` class defined twice with conflicting values**
```css
/* declaration 1 — line ~5 */
.bg1 {background-color: #ffffff;}

/* declaration 2 — later in same <style> block */
.bg1 {background:#58546d;}   /* purple-gray */
```
The second rule wins in all clients. Any element using `.bg1` renders purple-gray (`#58546d`) instead of white. This is almost certainly a template merge error — a promotions block was dropped in and its overrides were not scoped or removed.

**`<meta>` IE compatibility tag missing `http-equiv` attribute**
```html
<meta content="IE=edge" />   <!-- as sent -->
<meta http-equiv="X-UA-Compatible" content="IE=edge" />   <!-- correct -->
```
Without `http-equiv`, the directive is silently ignored in Outlook/IE rendering engine.

**`@font-face` declarations carry no `src:` property**
All nine `@font-face` blocks (proxima-nova, linotype-didot, etc.) declare `font-family` and `font-weight` but omit `src:`. The rules are no-ops — fonts load only if the client already has them installed or if a separate stylesheet (e.g., Adobe Fonts embed) is loaded elsewhere. If that external load fails, fallback stacks (`Arial, sans-serif` / `Times New Roman, serif`) engage silently. Acceptable only if the Adobe Fonts link is confirmed present outside the truncated source.

**Duplicate `font-family` property inside one `@font-face` block**
```css
@font-face { font-family: proxima-nova,sans-serif; font-weight: 700; font-style: italic;
             font-family: proxima-nova,sans-serif; }   /* repeated */
```
No functional impact (same value), but indicates copy-paste slop in the template.

**`<title>` is "New Balance Template"**
Some clients (Yahoo Mail, older Lotus Notes) surface the `<title>` tag. Recipients would see the template name, not a branded string.
