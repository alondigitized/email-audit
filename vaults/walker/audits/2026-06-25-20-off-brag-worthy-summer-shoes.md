- **Every image and section screams women's fashion** — green sundress, colorful slides, heeled sandals, a "FANCY FÊTING AND PARTY CRASHING" section. I felt like a tourist who walked into the wrong store.
- **"Brag-worthy," "crowd surfing," "fancy fêting"** — that's not Boomer male vocabulary. That's not anyone over 50's vocabulary. Alienating before you even get to the product.

- **The "BACK IN STOCK" tease never resolved** — the preview hooked me, but nowhere in the email did I find a specific called-out product that was back. That's a broken promise.
- **This is the seventh-plus DSW email I've gotten this week** — after the June 14th "Last chance for 20% off!" and the barrage before it, the 20% offer has completely lost its urgency. It's wallpaper now.

- 4. **Kill two of the lifestyle sections** — "crowd surfing at a concert" and "fancy fêting" are burning screen real estate that could show me walking shoes, wide-width options, or arch-support callouts.

### 3. Rendering & Accessibility

**Critical — Invalid `@font-face` property name (all 11 declarations)**
Every `@font-face` block uses `Src:` (capital S) instead of the valid CSS property `src:`. CSS property names are case-sensitive in strict parsers. This causes font loading to fail silently and all text falls back to system fonts.

```css
/* Current (broken) */
Src: url("https://braze-images.com/.../original.woff") format('woff');

/* Fix */
src: url("https://braze-images.com/.../original.woff") format('woff');
```

**No WOFF2 format declared**
Futura PT fonts only list `woff`; Helvetica Now only lists `truetype` (`.ttf`). WOFF2 offers ~30% smaller payloads and is supported by all modern clients. Missing format means unnecessary load time when fonts do load.

```css
/* Recommended pattern */
src: url("...original.woff2") format('woff2'),
     url("...original.woff") format('woff');
```

**`-ms-text-size-adjust` conflict**
`html, body` sets `-ms-text-size-adjust: 100%`, then the `*` selector overrides it with `-ms-text-size-adjust: none`. `none` disables automatic text size scaling entirely in older Windows Phone IE — the `*` rule wins due to specificity tie-breaking and should be removed or set to `100%`.

**Missing `http-equiv` on charset meta**
```html
<!-- Current -->
<meta content="text/html; charset=utf-8" />

<!-- Correct -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, some older clients (Lotus Notes, older Outlook) may not honor the charset declaration.
