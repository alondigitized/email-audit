### 3. Rendering & Accessibility

**Confirmed issues:**

- **Invalid CSS property casing — `Src:` (capital S)** in every `@font-face` block:
  ```css
  Src: url("https://braze-images.com/appboy/...woff") format('woff');
  ```
  The correct property is lowercase `src:`. This is invalid CSS per spec. Most email clients ignore web fonts anyway, so practical impact is low, but it will cause the font declaration to silently fail in any client that does attempt to load it.

- **`maximum-scale=1` in viewport meta blocks user zoom:**
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
  ```
  This prevents users with low vision from pinching to zoom on mobile. It fails WCAG 1.4.4 (Resize Text, Level AA). Remove `maximum-scale=1`.

- **`text-size-adjust` conflict in reset:**
  ```css
  -ms-text-size-adjust: 100%;
  -webkit-text-size-adjust: 100%;
  text-size-adjust: none;
  ```
  The prefixed declarations set adjustment to `100%` (normal), while the unprefixed shorthand overrides to `none` (disables). This inconsistency will behave differently across rendering engines.

- **No `.woff2` format** in any `@font-face` declaration. Only `.woff` and `.ttf` are served. `.woff2` is universally supported and ~30% smaller. Minor — web fonts rarely load in email clients — but worth correcting if Braze templates are reused for web.

- **`<title>DSW`** — title tag is not closed: `<title>DSW</title>` appears syntactically correct in the snippet, but verify in the full source that it is not truncated, as some parsers will absorb subsequent head content into the title.
