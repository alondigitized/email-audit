### 3. Rendering & Accessibility

**Malformed `<meta charset>`**
```html
<meta content="text/html;" charset="utf-8" />
```
Mixes `Content-Type` content syntax with the HTML5 `charset` attribute while omitting `http-equiv="Content-Type"`. Should be one or the other:
```html
<meta charset="utf-8">
<!-- or -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Some older Outlook and Lotus Notes builds may misread character encoding.

**Malformed `<meta http-equiv="X-UA-Compatible">`**
```html
<meta content="IE=edge" />
```
Missing `http-equiv="X-UA-Compatible"` attribute. The directive has no effect as written.

**Dark mode explicitly blocked**
```html
<meta name="color-scheme" content="light" />
<meta name="supported-color-schemes" content="light" />
```
Forces light rendering in Apple Mail 13+ and clients that honor these tags. Intentional or oversight — confirm with design. No technical bug, but a deliberate capability gate.

**Breakpoint gap: 601px–660px**
Three breakpoints are defined: `600px` (font sizes only), `660px` (full layout reset), and `450px`. In the 601–660px range, `responsive-text` font sizes activate (14px) but layout classes (`.container`, `.photo`, `.drop`, etc.) are still in desktop mode. On tablets in portrait at ~640px this produces large text inside a fixed-width table — potential clipping.

**Dead CSS declaration**
```css
a, a:link, ... {
  color:inherit !important;
  color:inherit;   /* shadowed — dead */
}
```
The second `color:inherit` is unreachable due to the preceding `!important`. No rendering impact, but indicates copy-paste artifact in the stylesheet.

**`display:none` with `color` set**
```css
a.mobileshow, .mobilehide { display: none; color: #ffffff; }
```
`color` on a `display:none` element is never applied. Harmless but dead code.
