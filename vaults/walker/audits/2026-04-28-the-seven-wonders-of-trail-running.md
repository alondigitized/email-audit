### 3. Rendering & Accessibility

**3a. Duplicate, conflicting `<meta name="viewport">` declarations**

Two viewport tags exist with contradictory `user-scalable` values:

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<!-- then later: -->
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```

The second overrides the first in compliant parsers, but behavior varies across clients. Remove the first tag.

**3b. `maximum-scale=1` suppresses user zoom**

Both viewport tags include `maximum-scale=1`, which prevents pinch-to-zoom on mobile. This violates **WCAG 2.1 SC 1.4.4 (Resize Text)** and is specifically blocked by iOS 10+ Safari (ignored) but still affects Android WebView-based clients. Remove `maximum-scale=1` from the retained viewport tag.

**3c. Empty `<title>` tag**

```html
<title></title>
```

Some clients (Samsung Mail, browser fallback renders) display the title in the tab/preview pane. Should be set to a meaningful string matching the subject line, or omitted.

**3d. Malformed charset `<meta>` tag**

```html
<meta content="text/html; charset=utf-8" />
```

Missing the required `http-equiv="Content-Type"` attribute. Correct form:

```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

Some legacy clients (Outlook 2007–2010) fall back to their default encoding without it.

**3e. Stale Typekit font kit**

The CSS comment embedded in the font declaration reads:

```
/*{"last_published":"2022-03-23 22:26:23 UTC"}*/
```

The Typekit kit `hva0tmw` has not been republished in ~4 years. Web fonts do not render in Gmail, Outlook, or most native mobile clients regardless — but if HOKA's brand font stack has changed since 2022, the fallback stack embedded here may be misaligned. Verify the fallback `font-family` stack covers current brand-approved system fonts.

**3f. Aggressive universal CSS reset**

```css
* { margin-top:0px; margin-bottom:0px; padding:0px; border:none; outline:none; }
```

`border:none` on `*` strips table borders in some Outlook versions. This is a known pattern that can cause collapsed table cell rendering in Outlook 2016/2019. Scope the border reset to `img, a` rather than `*`.
