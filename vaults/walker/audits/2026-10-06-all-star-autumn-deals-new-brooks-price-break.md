## 2. Link & Tracking Issues
- **Unresolved placeholder in a pixel URL:** `https://0di86k1v.emltrk.com/v2/0di86k1v?d=[UNIQUE]` still contains a literal `[UNIQUE]`. The unique ID was not substituted at send time, so this pixel can't tie opens to a recipient. Literal brackets are also not valid in a query string.
- **Zero-width space in a URL:** `https://ieezzy5m.emltrk.com/v2/ieezzy5m?i=72180589&t=utm_campaign=SCA_20261006_nike_brooks_athletics_AM​` ends with a U+200B character, visible in the QA output as a trailing invisible character. Some clients and proxies will percent-encode it or treat it as part of the campaign value.
- **Malformed parameter:** The same URL passes `utm_campaign=...` as the value of a `t=` parameter (`&t=utm_campaign=SCA_...`), not as its own query parameter. Only the ESP tracker will parse this correctly.
- **Unverified links:** 23 tracking links were skipped by the HTTP probe because they are on click-redirect domains. Their destinations and status codes are unverified.

## 3. Rendering & Accessibility
- **Missing alt text:** Both tracking pixels (`ieezzy5m.emltrk.com`, `0di86k1v.emltrk.com`) have no `alt` attribute. Decorative or tracking images should use `alt=""` so screen readers don't announce the URL.
- **Malformed meta tags:** `<meta content="IE=edge" />` has no `http-equiv`, so it does nothing. `<meta content="text/html;" charset="utf-8" />` has no `http-equiv="Content-Type"`. The charset is still declared.
- **Doctype mismatch:** The HTML 4.01 Transitional doctype is combined with `xmlns="http://www.w3.org/1999/xhtml"` and self-closed tags (`/>`). This is a harmless mix in most clients but is inconsistent.
- **Link styling:** The CSS rule `a, a:link, ... { text-decoration:none !important; color:inherit !important; }` removes default link styling globally. Whether links stay distinguishable depends on inline styles in the truncated body, so I can't confirm it.
- **Language:** `lang="en"` is present, and a viewport meta tag and responsive media queries are included.
