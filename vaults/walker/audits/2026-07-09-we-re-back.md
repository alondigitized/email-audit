# We’re back.
**Score:** 7/10 · **Type:** Email audit · **2026-07-09**
## Executive summary

- New Balance showed up in my inbox again — eighth or ninth time in roughly two weeks if I'm keeping count right — and this one is pure back-to-school. The hero image is five kids in matching NB gear. The headline reads "Start the school year with new favorites." My youngest finished school a long time ago. Wrong guy.
- That said, "We're back." as a subject is just vague enough that I opened it wondering if maybe there was a real shoe drop in here for me. There isn't — not at the top, anyway. If I scroll deep enough I hit a "More to explore" grid and there's a FuelCell Hook & Loop in there, which is exactly the kind of slip-on I actually want. But it's fifth in a product row, buried below two full kid-photo sections. I almost missed it entirely.
- I'm marking this as read and moving on. The "Shop now" button tells me nothing about where I'm landing, and I am not clicking a back-to-school CTA to find out I'm on a kids' shoes page. If the FuelCell Hook & Loop had been the hero with a price on it, maybe. Buried where it is, no.

- **FuelCell Hook & Loop appears in "More to explore"** — slip-on, hook-and-loop closure, exactly the comfort category I care about. First useful product I spotted in the whole email.
- **Clean render on mobile** — loaded fast, no broken images, no garbled text, no overlapping elements. At least it works.
- **"Shop by gender" section includes Men** — they remembered I exist, even if the top half of the email forgot about me.
- **Back-to-school in early July is timely** — they're not running this campaign late, I'll give them that.

## What's weak

- **Completely wrong audience** — I'm 62, no school-age kids at home. The entire hero and headline is for parents shopping for children. This email should not have reached my segment.
- **No offer, no price, no discount** — compare this to the July 6 send ("up to 25% off select shoes"), which at least gave me a reason to click. This one is just "here are products." No hook.
- **"Shop now" CTA tells me nothing** — shop what? I need to know before I tap that it's taking me to men's shoes, not a kids' landing page.
- **Second kids-focused email in a week** — the July 2 "Kids' new arrivals" was the same territory. If I'm in an older male segment, two kids emails in eight days feels like a list segmentation problem, not a content problem.
- **Zero comfort copy anywhere** — cushioning, arch support, wide widths — nothing. The June 26 "Your feet just know." email at least gestured at that. This one doesn't try.

## Recommendations

- 1. **Segment this away from 60+ male subscribers** — or swap the hero block entirely for a men's comfort shoe. The kids campaign doesn't need to go to everyone on the list.
- 2. **Lead with a concrete offer** — even 15% off pulls me in, because then I start browsing everything. No offer means no reason to click.
- 3. **Rename the main CTA** — "Shop Men's Comfort Styles" tells me where I'm landing. "Shop now" tells me nothing.
- 4. **Put the FuelCell Hook & Loop above the fold** — it's exactly the slip-on comfort shoe I want. It should be the hero, not product number five.
- 5. **Rest the back-to-school creative for the 60+ segment** — after July 2's kids email, sending me another one a week later is just noise.

## Technical Audit — New Balance "We're back."

### 1. Technical Summary

The template has three confirmed code-level defects: a duplicate CSS class definition that creates a conflicting background color, an unreplaced template placeholder in a background image URL over HTTP, and a malformed `<meta>` tag that renders inert. The remaining items are lower-severity but worth tracking before send.

---

### 2. Link & Tracking Issues

**Unreplaced template token in background image URL**
```css
.bgwhite { background-image: url('http://image.XXXXX.png'); }
```
`XXXXX` is an unresolved merge token — the asset will 404. Additionally, the URL uses `http://` instead of `https://`, which triggers mixed-content warnings in modern clients (Gmail, Apple Mail) and may cause the image to be silently blocked.

**Full link inventory not auditable** — HTML is truncated before body links appear. UTM and click-tracking parameters cannot be verified from this excerpt (see §6).

---

### 3. Rendering & Accessibility

**Duplicate `.bg1` class with conflicting values**
The stylesheet defines `.bg1` twice:
```css
/* First definition — line ~9 */
.bg1 { background-color: #ffffff; }

/* Second definition — later in same <style> block */
.bg1 { background: #58546d; }  /* muted purple-gray */
```
The second rule wins due to cascade order. Any element using `.bg1` expecting white will render purple-gray. This is a confirmed rendering bug.

**`<meta>` IE compatibility tag is non-functional**
```html
<meta content="IE=edge" />
```
Missing `http-equiv` attribute. Correct form:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without `http-equiv`, this tag is ignored by all clients.

**Viewport meta missing `width=device-width`**
```html
<meta name="viewport" content="initial-scale=1, user-scalable=yes" />
```
Without `width=device-width`, mobile clients may not trigger responsive layout reflow. Standard form: `content="width=device-width, initial-scale=1"`.

**`@font-face` blocks lack `src:` declarations**
All nine `@font-face` rules (proxima-nova variants, linotype-didot, etc.) declare `font-family`/`font-weight`/`font-style` but include no `src:` property — technically invalid. If these fonts load via Adobe Fonts JS injected elsewhere this is acceptable, but there is no fallback `src:` for clients that block external JS. One block also contains a malformed duplicate property:
```css
@font-face {
  font-family: proxima-nova,sans-serif;
  font-weight: 700;
  font-style: italic;font-family: proxima-nova,sans-serif;  /* ← duplicate, malformed */
}
```

**Alt text** — Not auditable from truncated source. Should be verified on full HTML before send.
