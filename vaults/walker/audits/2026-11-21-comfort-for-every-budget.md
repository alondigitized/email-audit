- The price-tier tags ($50, $75, $100 and under) match how I compare value.

## What's weak

- Not one image or line mentions cushioning, arch support or slip-ins. That's the reason I'd buy.

## Technical Audit

## 1. Technical Summary
The email has one confirmed rendering/personalization defect (an empty greeting, "Hi ,") and several code-level problems visible in the HTML: a scheme-less tracking pixel, two `http://` images without alt text, malformed `<meta>` tags and a zoom-blocking viewport. The HTML was truncated, so footer, unsubscribe and CTA markup could not be inspected.

## 2. Link & Tracking Issues
- **Broken pixel URL.** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…" width="1" height="1">` has no `https://`. It resolves as a relative path, so the request goes nowhere useful and the Return Path/Validity seed or placement tracking never fires. It also has no `alt`.
- **Cleartext tracking pixel.** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=MKG_US_NA_U_PRICE_ENGAGEDL90D_EN_11212026` uses `http://`. It can be blocked or rewritten by image proxies and triggers mixed-content warnings. The URL carries a user identifier (`mi_u`) in cleartext.
- **Third-party beacons.** Three `beacon.krxd.net` pixels (`1x1_usermatch.gif`, `1x1_ad_impression.gif`) sit in the same hidden block. The `partner_uid=9153f33f…ced00` value is a 64-hex string, which looks like a SHA-256 hash of an identifier. That is inferred from the format, not confirmed.
- **Hidden open pixel.** The SFMC open pixel (`click.emails.skechers.com/open.aspx?qs=…`) sits inside `<div style="display:none !important">` within a `display:none` `<td>`. Some clients skip images in hidden containers, which could under-report opens.
- **Unprobed links.** 39 tracking links were skipped by QA because they are on click-redirect domains, so their destinations and status are unverified.

## 3. Rendering & Accessibility
- **Missing alt text (QA-confirmed).**
  - `o.gif` (ink1000.com)
  - `dde00662-169f-447d-b0e2-fc65f6c2290c.png` (`http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/…`)
  - The Return Path `pixel.gif` also has none (from the HTML).
- **HTTP image source.** The `dde00662…png` image uses `http://`, so it may be blocked or replaced with a broken-image icon. It is a content image, not a pixel, so the impact is higher.
- **Malformed meta tags.** `<meta content="text/html; charset=utf-8" />` lacks `http-equiv="Content-Type"`, so the charset is not declared. `<meta content="IE=Edge" />` lacks `http-equiv="X-UA-Compatible"`. Both are no-ops.
- **Zoom disabled.** `<meta name="viewport" content="…maximum-scale=1" />` blocks pinch-zoom on mobile, which is a WCAG 1.4.4 concern. `* { -webkit-text-size-adjust: none }` also disables text scaling in WebKit.
- **No language attribute.** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang`, which hurts screen-reader pronunciation.
- **Layout tables.** The layout tables (for example `<table cellpadding="0" cellspacing="0" border="0">`) carry no `role="presentation"`, so screen readers may announce them as data tables.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot (QA-confirmed).** The greeting renders as "Hi ," because the first-name field resolved to empty. The merge likely has no fallback value (for example an SFMC `%%=v(@firstName)=%%` or AMPscript `IIF(Empty(...))` default). The greeting itself was outside the truncated HTML, so this rests on the QA check alone.
- No unrendered `%%…%%` or `{{…}}` tokens were visible in the truncated source.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **[WARN] Authentication-Results header not found.** QA attributes this to the AgentMail relay stripping or not exposing the header. SPF/DKIM/DMARC status for `emails.skechers.com` is unknown, not failing. It is not a confirmed defect of the email itself.
- **Not verifiable.** The footer was cut off, so the unsubscribe link, `List-Unsubscribe`/`List-Unsubscribe-Post` headers and postal address could not be checked. No violation is claimed.
- **From address.** The sender is `no-reply@emails.skechers.com`. Replies are not possible, which is acceptable under CAN-SPAM if a working opt-out and physical address are present.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Not verifiable.** All 39 click links are SFMC redirects (`click.emails.skechers.com`) and were skipped, so final landing URLs and UTM parameters are unknown.
- **Campaign ID.** The only campaign identifier visible is `MKG_US_NA_U_PRICE_ENGAGEDL90D_EN_11212026` in the Krux and ink1000 beacons (`campaignid=` / `mi_ecmp=`). Confirm it propagates as `utm_campaign` on the destination URLs.

## 7. Recommendations
1. Add `https://` to the Return Path pixel (`https://pixel.app.returnpath.net/pixel.gif?r=…`) and an `alt=""`, or remove it if it is not in use.
2. Switch `www.ink1000.com` and `image.emails.skechers.com` image URLs to `https://`, and confirm both hosts serve valid TLS.
3. Add alt text to `dde00662…png` (descriptive if it is content) and `alt=""` to `o.gif` and the other tracking pixels.
4. Add a fallback to the first-name merge (for example "Hi there,") or suppress the greeting when the field is empty.
5. Fix the meta tags with `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"`. Remove `maximum-scale=1`, add `lang="en"` to `<html>`, and add `role="presentation"` to layout tables.
6. Move the SFMC open pixel out of the `display:none` wrapper (for example a 1×1 image with `style="width:1px;height:1px"`).
7. Review whether the hashed identifier in the Krux `partner_uid` and the `mi_u` value in the ink1000 URL are covered by the privacy policy and consent.
8. Re-run QA on the full, untruncated HTML plus raw headers, and resolve the click redirects to check UTM parameters, `List-Unsubscribe` and the unsubscribe link.
