- **From:** DSW | **Subject:** LAST DAY FOR $15 OFF >>> | **Date:** 2026-04-29

- **The discount math is dead simple.** Three tiers, spelled out cleanly. I don't need to decode anything — spend $49, save $15. That's the kind of deal I can act on.

- **The entire new arrivals section is women's product.** Six product images, every single one a women's heel, sandal, or espadrille. I don't care about any of that. It fills the most valuable real estate below the offer with content that has zero relevance to me.

- **The VIP section at the bottom is low-contrast and small.** That's where they're trying to upsell membership but it's the weakest-looking block in the email.

### 3. Rendering & Accessibility

**Confirmed issues:**

**A. `Src:` capitalization in all `@font-face` rules (critical)**
All 10 `@font-face` blocks use `Src:` (capital S), which is invalid CSS. Spec-compliant parsers (Outlook via Word engine, some older WebKit builds) will silently drop the rule, causing font fallback. Should be lowercase `src:`.

```css
/* Current (invalid): */
Src: url("https://braze-images.com/...") format('woff');
/* Correct: */
src: url("https://braze-images.com/...") format('woff');
```

**B. HelveticaNow fonts loaded as `.ttf` only**
All six HelveticaNow variants reference `.ttf` files (~3–4× larger than `.woff2`). No `.woff` or `.woff2` fallback format is declared. This increases email render weight and load time, particularly on mobile where these fonts are most likely to render.

**C. Futura PT fonts: `.woff` only, no `.woff2`**
The four Futura PT variants declare only `.woff`. Adding `.woff2` first in the `format()` stack would reduce file size ~25–30%.

**D. `maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
This blocks user zoom. WCAG 1.4.4 (Resize Text, AA) requires content to be resizable up to 200% without loss of functionality. Common iOS mail clients respect this restriction.

**E. `text-size-adjust: none` on `*` selector**
```css
*{...-ms-text-size-adjust: none; text-size-adjust: none}
```
Applying `text-size-adjust: none` globally (rather than to `body` only) suppresses browser-level text scaling for users who rely on system font size settings. Should be scoped to `html, body`.

**F. Charset meta missing `http-equiv`**
```html
<meta content="text/html; charset=utf-8" />
```
Without `http-equiv="Content-Type"`, this declaration has no normative effect in HTML parsers. Some legacy Outlook versions rely on this attribute to detect encoding. Correct form:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

**G. Dark mode color values use near-black, not pure black**
`#000001` and `#00000F` are intentional Apple Mail dark-mode inversion workarounds — this is a known technique, not a defect. Noted for completeness.
