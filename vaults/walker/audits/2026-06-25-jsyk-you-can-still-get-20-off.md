# JSYK, you can still get 20% off
**Score:** 7/10 · **Type:** Email audit · **2026-06-12**
## Executive summary

- My thumb went to this on pure reflex — DSW has trained that muscle memory well, and I've noted it in every audit since the June 12th send. ### 3. Rendering & Accessibility

**`Src:` (capital S) in all `@font-face` blocks — confirmed bug**

Every `@font-face` declaration uses `Src:` instead of the spec-required lowercase `src:`. Example:

```css
@font-face {
  font-family: 'Futura_PT_Regular';
  Src: url("https://braze-images.com/...original.woff") format('woff');
}
```

CSS property names are case-insensitive in the browser spec, but several email clients (particularly older Outlook WebView and Samsung Mail) do not normalize property names and will silently drop the `@font-face` rule, falling back to system fonts for all Futura PT and HelveticaNow usages.

**`text-size-adjust: none` (overly aggressive)**

```css
* { -webkit-text-size-adjust: 100%; -ms-text-size-adjust: none; text-size-adjust: none }
```

`-ms-text-size-adjust: none` and `text-size-adjust: none` disable auto-scaling entirely rather than pinning at 100%. This can cause text to render smaller than intended on high-DPI Windows and Android clients. Change both to `100%`.

**`maximum-scale=1` in viewport — accessibility violation**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

`maximum-scale=1` blocks pinch-to-zoom. This fails WCAG 2.1 SC 1.4.4 (Resize Text) and is flagged by accessibility auditors. Remove `maximum-scale=1` or replace with `maximum-scale=5`.

**Missing `http-equiv` on two `<meta>` tags**

```html
<meta content="text/html; charset=utf-8" />       <!-- missing http-equiv="Content-Type" -->
<meta content="IE=Edge" />                          <!-- missing http-equiv="X-UA-Compatible" -->
```

Without `http-equiv`, these tags are no-ops. The charset declaration in particular is inert, leaving character encoding to client heuristics. Fix:

```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```

**Mixed font formats without cross-format fallback**

- Futura PT weights load only `.woff` — no `.woff2` or `.ttf` fallback.
- HelveticaNow weights load only `.ttf` — no `.woff` fallback.

iOS Mail and some Android clients prefer `.woff2`; Outlook on Windows will ignore `.woff` and `.ttf` entirely. A format stack (`woff2`, `woff`, `truetype`) is standard practice.

**Dark mode near-black values**

```css
.dm-bg-black { background: #00000F !important; }
.dm-font-black { color: #000001 !important; }
```

`#00000F` and `#000001` are deliberate Gmail-link-detection workarounds (pure `#000000` can trigger auto-link styling). Intentional, but worth documenting so future editors don't "fix" them.
