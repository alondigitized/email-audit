### 3. Rendering & Accessibility

**`maximum-scale=1` blocks zoom (WCAG 1.4.4 violation)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Remove `maximum-scale=1` or replace with `maximum-scale=5`.

**`text-size-adjust: none` applied globally**
```css
*{-ms-text-size-adjust: 100%;-webkit-text-size-adjust: 100%;...
  -ms-text-size-adjust: none;text-size-adjust: none}
```
Two issues: `-ms-text-size-adjust` is declared twice with conflicting values (`100%` then `none`); the second wins and disables text scaling in IE/Outlook. The bare `text-size-adjust: none` on `*` also disables scaling in Firefox. These should both be `100%`.

**Invalid `Src:` property in all `@font-face` blocks**
```css
@font-face {
  font-family: 'Futura_PT_Regular';
  Src: url("https://braze-images.com/...") format('woff');
}
```
`Src:` (capital S) is invalid CSS. Browsers handle it via case-insensitive parsing, but it's a spec violation and may fail strict parsers. All 10 `@font-face` declarations are affected — should be lowercase `src:`.

**Missing `http-equiv` on two `<meta>` tags**
```html
<meta content="text/html; charset=utf-8" />   <!-- missing http-equiv="Content-Type" -->
<meta content="IE=Edge" />                     <!-- missing http-equiv="X-UA-Compatible" -->
```
Both tags are no-ops as written. Charset should use `<meta charset="utf-8">` (HTML5 form, widely supported in email) or the full `http-equiv` form.

**Font CDN dependency**
All 10 web fonts load from `braze-images.com`. If that origin is unavailable or blocked (corporate mail proxies), no fallback is specified in the `@font-face` blocks themselves beyond what the calling `font-family` stack provides in inline styles (not visible in truncated source — verify).

**`#000001` near-black color** — used in `.border-top-black` and `.dm-font-black`. This is a deliberate workaround to prevent Apple Mail from auto-styling black text as a link. Intentional, no action needed.
