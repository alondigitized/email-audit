## 3. Rendering & Accessibility
- **Invalid CSS property in all `@font-face` declarations:** each block uses `Src:` (capital S) instead of `src:` — e.g. `font-family: 'Futura_PT_Regular'; ... CSS properties are case-sensitive for parsing in most mail clients' stricter renderers; this will cause custom web fonts to silently fail to load in any client that doesn't lowercase/normalize the property, falling back to system fonts. This appears 9 times (Futura_PT_Regular/Medium/Demi/Bold, HelveticaNow_Regular/Medium/MediumItalic/Bold/BoldItalic/Italic).
- Standard Outlook/Gmail/dark-mode reset rules are present and well-formed (MSO table spacing resets, `x-apple-disable-message-reformatting`, `color-scheme`/`supported-color-schemes` dark mode block) — no issues found there.

The `o.gif` tracking pixel missing alt is expected/non-issue (1x1 tracking pixels are conventionally alt-less).
