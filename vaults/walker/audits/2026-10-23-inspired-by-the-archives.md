## Technical Audit

## 1. Technical Summary
The email has no plain-text alternative (QA FAIL, 0 chars), and several images load over `http://`, including the click-tracking pixel. The HTML source was truncated, so the unsubscribe link, footer and most link hrefs could not be checked.

## 2. Link & Tracking Issues
- **14 tracking links were not probed.** They are on click-redirect domains, so QA skipped them. Destination validity and redirect chains are unverified.
- **Insecure tracking pixel.** The image `EIXmwYKkYbh-L1sAXF9L-hgPVbaPtBUkIkgWG41RpF4=452` loads from `http://click.comms.adidas.com/CI0/010201a167601d63-9683d472-ca12-4ff5-8557-ca657d1e7219-000000/...`. It is plain HTTP on the click domain, so a client that blocks mixed or insecure content may not register the open. Open-rate data would then be undercounted. The path suggests this is an open pixel, but the truncated source doesn't confirm it.
- **Insecure image.** The `arrow` image (`b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg`) is served from `http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/...`. It appears twice, so it is probably used in two CTAs.

## 3. Rendering & Accessibility
- **Missing alt text on `https://dv.adidas.com/o/ea92342e-3ff1-475d-bbd7-bbf7d4a5841b?cp_tp=...`.** The QA check flags an absent `alt` attribute. If this is a content image, screen readers will announce the filename or URL, and nothing shows when images are blocked.
- **Missing alt text on the tracking pixel `...=452`.** This is low impact. A 1x1 pixel should still carry `alt=""` explicitly.
- **Malformed charset declaration.** `<meta content="text/html; charset=UTF-8" />` has no `http-equiv="Content-Type"` or `charset=` attribute, so it declares nothing. Clients that rely on the in-document charset could mis-decode non-ASCII characters. Whether the MIME header carries the charset can't be seen here.
- **Legacy markup.** The HTML 4.01 Transitional doctype is combined with XHTML-style self-closing tags (`<meta ... />`). This is tolerated by email clients and is not a defect.
- **Custom fonts.** `AdihausDIN` and `AdineuePRO` `@font-face` rules use `local('Arial')` and similar sources only, so no web font is loaded. The `mso-font-alt: Arial` fallback is present, and this is fine.
- **Duplicated CSS.** The same `@font-face` and media query blocks appear in two separate `<style>` blocks. This adds weight with no functional effect, and the HTML may be clipped earlier in Gmail.

## 4. Personalization & Merge Tokens
No issues found in the visible source. No unresolved tokens such as `%%...%%`, `{{...}}` or `[FIRSTNAME]` appear in the truncated portion, and the QA data reports none.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **No plain-text part (FAIL).** The text version is 0 chars. A multipart/alternative with a text part is expected for deliverability, and the lack of one can raise spam scoring. It also leaves nothing for text-only clients or assistive tools to fall back on.
- **Authentication unverified.** `Authentication-Results` was not found. The QA note attributes this to the AgentMail relay, so it is a limit of the test setup and not a confirmed sender-side failure. SPF, DKIM and DMARC alignment for `us-news.comms.adidas.com` could not be assessed.
- **Not verifiable.** The `List-Unsubscribe` and `List-Unsubscribe-Post` headers, the footer unsubscribe link and the physical postal address were all outside the supplied data.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not assessable. All 14 tracked links went through redirect domains and were skipped, so final destination URLs, UTM parameters and landing page alignment were not observed. The `cp_tp=` parameter on the `dv.adidas.com` image URL is an asset-delivery token and not a campaign parameter.

## 7. Recommendations
1. Add a plain-text MIME part. This is the only confirmed FAIL.
2. Switch `http://image.link.adidas.com/...b0c011a2-...jpg` and `http://click.comms.adidas.com/CI0/...` to `https://`. Confirm the ESP supports HTTPS on both domains with a valid certificate.
3. Add a descriptive `alt` to `dv.adidas.com/o/ea92342e-...`, or `alt=""` if it is decorative. Add `alt=""` to the tracking pixel.
4. Change the charset meta to `<meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />` or `<meta charset="UTF-8">`.
5. Merge the duplicate `<style>` blocks to reduce size.
6. Rerun QA against the full HTML and the raw message. This would cover the headers (`Authentication-Results`, `List-Unsubscribe`), the footer compliance elements, and the resolved redirect targets with their UTMs.
