## Technical Audit

**1. Technical Summary**
The email has a confirmed empty-name greeting ("Hi ,") and several tracking pixels with protocol or syntax errors. One pixel is malformed and will not load. Two images use insecure `http://`, and both lack alt text. The HTML source was truncated, so link-level checks, the footer and the headers could not be confirmed.

**2. Link & Tracking Issues**
- **Malformed pixel URL (confirmed):** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…">` has no scheme. Clients will resolve it as a relative path, so the request fails. The Return Path/Validity deliverability pixel never fires, which skews inbox-placement and read data.
- **Insecure tracking pixel (confirmed):** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=PRO_US_NA_U_SITE_FULL_EN_10122026` uses plain HTTP. Gmail's image proxy and some clients may block or rewrite it, so the open is not recorded reliably.
- **Third-party data-sync pixels:** Three `beacon.krxd.net/1x1_usermatch.gif` and `1x1_ad_impression.gif` calls carry a SHA-256 hash (`partner_uid=9153f33f…`) and a subscriber ID (`partner_uid=121173391`). These match the email identity to an ad-tech profile. Apple Mail Privacy Protection and similar features neutralize them, and they add third-party requests to every open.
- **Click tracking:** 31 tracking links were skipped by the QA probe (click-redirect domain), so their destinations are unverified. The truncated source also prevented checking them by hand.

**3. Rendering & Accessibility**
- **Missing alt text (confirmed):** `o.gif` (ink1000.com) and `dde00662-169f-447d-b0e2-fc65f6c2290c.png` (`http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/…`) have no `alt` attribute. The `o.gif` is a tracking pixel and low impact. The `.png` is a content image, so images-off and screen-reader users get nothing from it.
- **Insecure content image (confirmed):** The same `.png` is served over `http://`. Clients that block mixed content may not show it.
- **Markup:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv` attribute, so they do nothing. The charset is not declared effectively, which risks mis-encoded characters such as the `®` in the title in some clients. The `<html>` tag has no `lang` attribute.
- **Hidden pixels:** The pixel block is wrapped in `display:none`. Some pixels, such as the `returnpath` one, have no `alt`.
- **Viewport:** `maximum-scale=1` blocks pinch-zoom on mobile, which is an accessibility concern.

**4. Personalization & Merge Tokens**
- **Empty greeting slot (FAIL, confirmed by QA):** The greeting renders as "Hi ," with the first-name field empty. The fallback value is missing or not set. This breaks the personalization and looks like a defect.
- The preheader reads "Members take 25% off sitewide for 2 days only", so the audience is membership-targeted, but the greeting does not account for missing names.

**5. Compliance (CAN-SPAM, unsubscribe, authentication headers)**
- The visible HTML was truncated before the footer, so the unsubscribe link and the physical postal address could not be verified. This is not flagged as a defect.
- **Sender:** `no-reply@emails.skechers.com` is a no-reply From address. This is not a violation, but it gives recipients no reply path for opt-out requests. A `List-Unsubscribe` header is needed for Gmail and Yahoo bulk-sender rules, and the headers were not provided.
- SPF, DKIM and DMARC results were not provided.

**6. Email-to-Site Continuity (UTM params, landing page alignment)**
- The tracking-link destinations and UTM parameters could not be checked, because all 31 links were skipped by the QA probe. The campaign ID `PRO_US_NA_U_SITE_FULL_EN_10122026` appears in the pixels, which suggests the campaign is tagged. Whether it carries through to the landing URLs is unverified.
- The preheader promises "25% off sitewide". Landing-page offer alignment cannot be verified from the data given.

**7. Recommendations**
1. **Fix the empty greeting (highest priority):** Add a fallback in the template, for example `%%=IIF(Empty(@firstname),"there",@firstname)=%%`, or drop the name when it is empty. Suppress the greeting if the name field is blank. The Salesforce Marketing Cloud (SFMC) `click.emails.skechers.com` pixel suggests SFMC AMPscript is the right place.
2. **Fix the `returnpath` pixel:** Change `pixel.app.returnpath.net/pixel.gif?r=…` to `https://pixel.app.returnpath.net/pixel.gif?r=…`.
3. **Move to HTTPS:** Change `ink1000.com/…/o.gif` and `image.emails.skechers.com/…/dde00662-….png` to `https://`. Confirm the image host has a valid certificate.
4. **Add alt text:** Give the content `.png` a descriptive `alt`, and set `alt=""` on the tracking pixels.
5. **Fix the head markup:** Use `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` and `<meta http-equiv="X-UA-Compatible" content="IE=Edge" />`. Add `lang="en"` to `<html>`. Remove `maximum-scale=1`.
6. **Verify the unverified items:** Check the full HTML for the footer, the `List-Unsubscribe` and `List-Unsubscribe-Post` headers, and SPF/DKIM/DMARC alignment on `emails.skechers.com`. Manually sample the click-tracking redirects and the final URLs for UTM carryover.
