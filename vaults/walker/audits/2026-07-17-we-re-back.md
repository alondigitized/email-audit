# We're back.
**Score:** 4/10 · **Type:** Email audit · **2026-07-17**
## Executive summary

- "We're back." in my inbox from New Balance — and honestly, "we're back" to what? This is back-to-school for kids. Head-to-toe kids. A smiling boy in a polo shirt, three shop-by-age tiles labeled Toddlers, Little Kids, Big Kids, tiny sneakers on tiny feet. I'm 62. My grandkids are grown. There is not one thing in this email that has anything to do with my feet.
- What really stuck in my craw: the preview text. "Class in session." — I recognize that. That was the subject line from the email they sent me on July 14th. Two days ago. New Balance just recycled their old subject line as this email's preview. That's not a good look. It's the kind of thing that makes me wonder who's minding the store.
- This is thirteen, maybe fourteen emails from New Balance in about two weeks. I've been patient. I've even given some of them decent marks — the extra 20% off deal on the 10th was real money on a real offer. But this one? I'm marking it read and moving on. Wouldn't click, wouldn't forward. Not even close.

## What's working

- **New Balance is a name I trust** — I didn't hesitate to open, even knowing the cadence has been aggressive lately.
- **The email renders cleanly** — no broken images, no overlapping text, layout holds up on mobile.
- **Clear visual hierarchy** — hero image first, headline second, category tiles third; the eye knows where to go even if I don't care about the destination.
- **Back-to-school is seasonally correct** — the creative matches the time of year, which at least tells me someone is coordinating the calendar.

## What's weak

- **Not a single thing for me** — every image, every CTA, every category tile is aimed at parents buying for children. I'm not that person.
- **"We're back." tells me nothing** — vague subject for a vague email. Back from what? With what?
- **Preview text is recycled** — "Class in session." was the July 14th subject line. Seeing it again two days later as a preheader reads like a copy-paste mistake.
- **No offer anywhere** — no percent off, no dollar threshold, no deal. Just "Shop now" buttons into kids' category pages. After the extra 20% off email earlier this month, this feels like a step backward.
- **Cadence fatigue is real** — fourteen emails in two weeks and now one that has nothing to do with me? This is how people hit unsubscribe.

## Recommendations

- 1. **Segment me out of the kids emails.** If they know I'm a 62-year-old man who has never bought kids' shoes from them, don't send me the back-to-school push at all. Or send me a men's version with walking shoes and wide widths.
- 2. **Put an offer in.** "We're back" with no discount is a nothing-email. Even "Free shipping on first day styles" gives me a reason to care — or forward it to someone who might.
- 3. **Fix the preheader pipeline.** "Class in session." being recycled from the prior subject line is a production error. Audit whatever template or automation is pulling that copy.
- 4. **Give the subject line a hook.** "We're back" with a period is barely a sentence. Tell me what's back.
- **Subject Alt A:** `Back to school: kids' shoes starting at $XX`
- **Subject Alt B:** `New arrivals for their first day — shop by age`
- **Preheader Alt A:** `Toddlers through big kids — find the right fit before school starts`
- **Preheader Alt B:** `First day styles for every age, ready to ship`

### 1. Technical Summary

The email uses a standard HTML 4.01 Transitional table-based layout with dark mode support. Several CSS authoring bugs are confirmed in the `<head>` block; a full link and compliance audit is blocked by the truncated source.

### 2. Link & Tracking Issues

**HTTP background image URL (unresolved or redacted)**
```css
.bgwhite { background-image: url('http://image.XXXXX.png'); }
```
The URL uses `http://` (not `https://`) and contains what appears to be a redacted/placeholder domain (`XXXXX`). If this is a production send, the placeholder was never resolved — the background image silently fails. If it is a real HTTP URL, mixed-content policies in Gmail and Outlook will block it.

**Remaining links not auditable** — source is truncated before any `<a href>` tags appear. UTM parameter coverage, click-tracking domains, and affiliate redirect chains cannot be confirmed.

---

### 3. Rendering & Accessibility

**`bg1` class defined twice with conflicting values (bug)**
```css
/* First definition (line ~6 of inline styles) */
.bg1 { background-color: #ffffff; }

/* Second definition (later in same block) */
.bg1 { background: #58546d; }
```
The second rule wins in cascade order. Any element using `.bg1` expecting a white background will render as dark purple-gray. This is almost certainly unintentional.

**Malformed `@font-face` block — duplicate `font-family` property**
```css
@font-face {
  font-family: proxima-nova, sans-serif;
  font-weight: 700;
  font-style: italic;
  font-family: proxima-nova, sans-serif;  /* duplicate */
}
```
Duplicate property in the same rule; CSS parsers ignore the first occurrence. The rule is effectively valid but indicates a copy-paste error.

**All `@font-face` blocks have no `src:` declaration**
None of the nine `@font-face` blocks define a `src:` URL. Custom web fonts (`proxima-nova`, `linotype-didot`) will not load; all rendering falls back to Arial/Times New Roman. Intentional if the ESP injects `src` at send time — but if not, the type hierarchy collapses silently.

**IE compatibility meta tag missing `http-equiv` attribute**
```html
<meta content="IE=edge" />
```
Should be:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without `http-equiv`, Outlook desktop (which uses IE's rendering engine) ignores this tag.

**Dark mode CSS truncated** — the `@media (prefers-color-scheme: dark)` block cuts off mid-declaration (`…a {color:#cf0a2c !important;} .bg1…`). Cannot confirm all dark mode overrides are complete; the `.bg1` conflict above will affect dark mode rendering as well.

**Alt text coverage not auditable** — source truncates before `<img>` tags.
