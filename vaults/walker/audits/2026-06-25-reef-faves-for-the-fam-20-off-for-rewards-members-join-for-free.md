## Technical Audit

## Technical Audit — Famous Footwear: REEF Faves / Rewards Promo

### 1. Technical Summary

The email uses a legacy HTML 4.01 Transitional doctype with a Salesforce Marketing Cloud (ExactTarget) delivery stack. Core infrastructure is functional but has two active HTTP (non-HTTPS) image sources and pervasive missing alt text across product images.

---

### 2. Link & Tracking Issues

**31 tracking links unverified** — all hrefs route through `click.email.famousfootwear.com` with opaque `?qs=` encoded payloads. HTTP probing was skipped by the QA system, so broken destination URLs cannot be ruled out without manual spot-checking.

**Action required:** Spot-check at least the primary CTA links (logo, hero, "Join Rewards") against their intended landing pages to confirm redirect chains resolve correctly.

---

### 3. Rendering & Accessibility

**12+ images have empty `alt=""` or no alt attribute** — confirmed by QA findings. Affected images include the logo (`3b6a7dc1`), hero divider (`4ccff4ad`, repeated 4×), and all product/lifestyle shots. When images are blocked (common in corporate mail clients), these render as blank boxes with no fallback text.

- Logo: `alt=""` — should be `alt="Famous Footwear"`
- Product images: all missing descriptive alt text

**Two images served over HTTP (not HTTPS):**
```
http://cl.S7.exct.net/LiveContent.aspx?qs=... (id: 920205576257)
http://cl.S7.exct.net/LiveContent.aspx?qs=... (id: 920155576550)
```
These are LiveContent (dynamic/personalized) image blocks. Gmail, Outlook, and Apple Mail will block mixed-content HTTP images, causing broken image slots. The `S7.exct.net` domain supports HTTPS — this is a configuration error in the template, not a platform limitation.

**Viewport meta tag has `user-scalable=0`** — prevents pinch-zoom on mobile, which fails WCAG 1.4.4 (Resize Text) and is flagged as an accessibility defect by major auditors.

**`<meta content="text/html; charset=UTF-8" />` is missing the `http-equiv` attribute** — the charset declaration is malformed and will be ignored by some parsers:
```html
<!-- Current (broken) -->
<meta content="text/html; charset=UTF-8" />
<!-- Should be -->
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
```

---

### 4. Personalization & Merge Tokens

No unrendered merge tokens (e.g., `%%firstName%%`, `{{{name}}}`) are visible in the truncated source. Cannot confirm full template without complete HTML, but no obvious breakage detected in the provided excerpt.

### 5. Compliance

**Plain-text version is URL-heavy:** 71.7% of the plain-text body is URLs (6,707 of 9,356 chars). This ratio is a known spam-filter trigger (Spamhaus, Barracuda) and explains any deliverability degradation. The plain-text version should be a human-readable summary with a small number of key URLs, not a URL dump.

**Sender domain:** `email.famousfootwear.com` — consistent with From header. No authentication header data was provided to audit SPF/DKIM/DMARC alignment, but the subdomain pattern is standard for SFMC.

**Unsubscribe / CAN-SPAM:** Cannot verify from the truncated source. The full HTML must include a physical mailing address and a functional unsubscribe link. Flag for manual confirmation.

---

### 6. Email-to-Site Continuity

All destination URLs are wrapped in the SFMC click-tracking redirect (`click.email.famousfootwear.com`), which means UTM parameters, if present, are encoded inside the `?qs=` payload and not directly inspectable. Cannot confirm UTM attribution (`utm_source`, `utm_medium`, `utm_campaign`) is wired correctly without decoding a sample redirect chain.

**Recommended spot-check:** Decode one primary CTA link and confirm the final landing URL contains expected UTM params, e.g.:
```
utm_source=email&utm_medium=email&utm_campaign=reef-rewards-june2026
```
