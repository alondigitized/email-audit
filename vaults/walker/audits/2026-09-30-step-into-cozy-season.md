## Technical Audit

# Technical Audit: "Step into cozy season"

## 1. Technical Summary
The email has one confirmed personalization failure (empty greeting, "Hi ,") and one malformed tracking pixel URL with no scheme. It also has two non-HTTPS images without alt text and several small markup and accessibility gaps. The HTML was truncated, so the body, footer and all 33 tracked links could not be inspected.

## 2. Link & Tracking Issues
- **Malformed pixel URL:** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…" width="1" height="1" />` has no `https://` or `//`. Clients resolve it as a relative path, so the request fails and the Return Path/Validity seed-tracking pixel never fires. It also has no `alt`.
- **Insecure tracking pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=MKG_US_NA_U_COMF_PROD_EN_09302026` (QA WARN) is served over plain HTTP. Clients may block it or show a mixed-content warning. It also has no alt text, and the `mi_u` subscriber identifier is sent in the clear.
- **Hidden pixel wrapper:** Five pixels sit in `<div style="display:none !important">` inside a `<td>` with `font-size:0;line-height:0;display:none`. Some clients strip or ignore `display:none` content, so open and match tracking is unreliable there.
- **Unverified links:** 33 tracking links (`click.emails.skechers.com` redirects) were skipped by the QA probe. Their destinations and redirect health are unverified.

## 3. Rendering & Accessibility
- **Missing alt text (QA WARN):**
  - `o.gif` (ink1000)
  - `dde00662-169f-447d-b0e2-fc65f6c2290c.png` (`http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/…`)
  - The Return Path pixel
- **Insecure content image (QA WARN):** The `dde00662-…png` source is HTTP on the brand's own image host, so it may be blocked. Its missing alt text means nothing renders if it is blocked.
- **Zoom disabled:** `<meta name="viewport" … maximum-scale=1>` prevents pinch-zoom, and `* { -webkit-text-size-adjust: none }` disables text resizing. Both are WCAG 1.4.4 concerns.
- **Malformed meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` lack `http-equiv`, so they have no effect. Charset is not reliably declared in the head.
- **Missing language and table roles:** `<html xmlns="…">` has no `lang` attribute. The visible layout tables (`<table cellpadding="0" cellspacing="0" border="0">`) have no `role="presentation"`.
- **Preheader:** The `.preheader` div is hidden, which is fine. No padding or filler follows it, so body text may follow it in inbox previews. This could not be confirmed in the truncated source.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** The greeting renders as "Hi ," with the name field empty. There is no fallback value such as "Hi there," in the merge logic.
- The tracking URLs carry populated subscriber identifiers (`partner_uid=121173391`, `mi_u=8107766165`), so the ID fields resolve. Only the name field failed.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Not verifiable:** The unsubscribe link, physical postal address and List-Unsubscribe headers are not in the truncated HTML or the provided headers. No issue is claimed.
- **Third-party data sharing:** Two `beacon.krxd.net/1x1_usermatch.gif` pixels pass `partner_uid=9153f33f…ced00`, a 64-character hex value consistent with a SHA-256 email hash, and a subscriber ID (`121173391`). A third-party ad impression pixel (`1x1_ad_impression.gif?confid=so3yexmpm`) sits alongside them. This is data sharing with an ad-tech platform and should be covered by the privacy disclosure.
- **Sender:** `no-reply@emails.skechers.com` is a no-reply address. It does not violate CAN-SPAM but gives recipients no direct reply path. SPF, DKIM and DMARC results were not provided.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Campaign ID:** `MKG_US_NA_U_COMF_PROD_EN_09302026` appears consistently in the ad and ink1000 pixels, which is good for internal attribution.
- **Not verifiable:** UTM parameters and landing page destinations are behind SFMC redirects (`click.emails.skechers.com`) that were skipped by QA. No claim is made.

## 7. Recommendations
1. **Fix the greeting.** Add a fallback for an empty first name (for example, `%%=IIF(Empty(@firstName),"Hi there,","Hi "+@firstName+",")=%%`), or drop the name when it is missing.
2. **Fix the Return Path pixel URL.** Change it to `https://pixel.app.returnpath.net/pixel.gif?r=…` and add `alt=""`.
3. **Move all images to HTTPS.** This covers `http://www.ink1000.com/...o.gif` and `http://image.emails.skechers.com/.../dde00662-…png`.
4. **Add alt text.** Use `alt=""` on the tracking pixels, and a descriptive `alt` on the `dde00662-…png` content image.
5. **Fix the head and accessibility markup.** Change the metas to `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"`. Add `lang="en"` to `<html>` and `role="presentation"` to the layout tables. Remove `maximum-scale=1`.
6. **Reduce tracking clutter.** Consolidate the five hidden pixels and confirm that the Krux match pixels are covered in the privacy policy.
7. **Complete the audit on the full source.** Check the unsubscribe link, postal address, List-Unsubscribe headers, SPF/DKIM/DMARC results, UTM parameters and the redirect targets of the 33 skipped links.
