### 3. Rendering & Accessibility

**Confirmed issues:**

**A. Duplicate `.bg1` class — conflicting values**
```css
/* Declaration 1 — line ~12 */
.bg1 {background-color: #ffffff;}

/* Declaration 2 — line ~95 (later in same <style> block) */
.bg1 {background:#58546d;}
```
The second declaration wins due to cascade order. Any element using `.bg1` expecting white (`#ffffff`) will render as muted purple-gray (`#58546d`). This is almost certainly unintentional.

**B. `@font-face` rules missing `src:` property**
All nine `@font-face` blocks (`linotype-didot`, `proxima-nova` variants, `proxima-nova-extra-condensed`, `proxima-nova-condensed`, `ITC Garamond Book Condensed`) declare `font-family` and `font-weight` but have no `src:` URL. Email clients will never download these fonts; all text falls back to `Arial, sans-serif` / `Times New Roman, serif`. This is likely an ESP-stripping artifact or authoring error, but means the Didot headline treatment is invisible to all recipients.

**C. Malformed `@font-face` rule — duplicate `font-family` property**
```css
@font-face {
  font-family: proxima-nova,sans-serif;
  font-weight: 700;
  font-style: italic;font-family: proxima-nova,sans-serif;  /* ← duplicate on same line */
}
```
The inline duplicate is a syntax defect; parsers will either silently accept or drop the rule.

**D. `<meta>` tag missing `http-equiv` attribute**
```html
<meta content="IE=edge" />
```
Should be `<meta http-equiv="X-UA-Compatible" content="IE=edge" />`. Without `http-equiv`, this tag has no effect on IE/Outlook rendering engine selection.

**E. Dark-mode blanket `a` color override**
```css
@media (prefers-color-scheme: dark) {
  a {color:#cf0a2c !important;}
```
This applies `color: red !important` to every anchor in dark mode, overriding any inline link colors set on individual CTAs. If any button or nav link uses a non-red color in its inline style, it will be forced red in dark mode. Needs to be scoped to specific selectors.

**F. Responsive breakpoint — single breakpoint only**
```css
@media only screen and (max-width:414px) {
  .image1 {width:auto !important; height:auto !important; max-width:100% !important;}
}
```
Only one image class is made responsive. Any other fixed-width images outside `.image1` will overflow on narrow viewports. Cannot confirm scope without full source.
