- "SHOP WOMEN" is the very first CTA — that's not just irrelevant, it's a directional sign pointing me away

### 3. Rendering & Accessibility

**`Src:` capitalization in all 10 `@font-face` declarations (confirmed bug)**
CSS property names are case-sensitive per spec. All font-face rules use `Src:` (capital S) instead of `src:`. This is a violation across all 10 declarations:
```css
/* Incorrect — all 10 @font-face blocks */
Src: url("https://braze-images.com/appboy/...") format('woff');
```
Most major clients silently accept this, but it will fail in any strict CSS parser and is a latent breakage risk on future rendering engine updates.

**`maximum-scale=1` blocks zoom (accessibility issue)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Disabling user zoom violates WCAG 1.4.4 (Resize Text, Level AA). Users who need to zoom for readability cannot do so on iOS/Android.

**`text-size-adjust` conflict**
The global reset sets vendor-prefixed values to `100%` then immediately overrides with `none`:
```css
* {
  -ms-text-size-adjust: 100%;
  -webkit-text-size-adjust: 100%;
  text-size-adjust: none;   /* ← overrides the above on standards-compliant browsers */
}
```
On non-prefixed-aware browsers, text size adjustment is fully disabled rather than clamped to 100%.

**Charset meta missing `http-equiv`**
```html
<!-- Present -->
<meta content="text/html; charset=utf-8" />

<!-- Correct form -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, some older Outlook and Lotus Notes builds may not honor the encoding declaration.

**Invalid CSS property in dark mode block**
```css
:root {
  supported-color-schemes: light dark;  /* not a valid CSS property */
}
```
`supported-color-schemes` is only valid as an HTML `<meta name>` attribute (already present correctly). As a CSS property it is silently ignored — no functional impact, but indicates a copy-paste error from the meta tag.

**`dm-bg-black` and `dm-font-black` use near-black values**
```css
.dm-bg-black  { background: #00000F !important; }
.dm-font-black { color: #000001 !important; }
```
This is a known workaround to defeat Gmail's automatic dark mode color inversion (Gmail ignores exact `#000000`). Intentional — no issue, flagging for documentation only.
