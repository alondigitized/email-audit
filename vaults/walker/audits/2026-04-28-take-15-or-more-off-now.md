# Take $15 (or more!) off NOW!
**Score:** 4/10 · **Type:** Email audit · **2026-04-28**
## Executive summary

- I'm a 62-year-old guy who buys comfortable shoes — slip-ons, wide widths, nothing fussy. This DSW email landed in my inbox with a pretty decent deal up front, but the second I scrolled past the discount banner, the whole thing stopped being for me. Six product photos, all women's heels and sandals. A "Shop by Size" grid with sizes starting at 5.5. A "Wide Calf" button that's clearly for ladies' boots. I'm still not sure why DSW sent this to me at all. The offer is real, but I felt like I accidentally picked up someone else's mail.
- The tiered discount is the only thing that earns points here. Everything else — the product photography, the size module, the "So New, So You" section — completely misses my demographic. If I happened to be shopping for my wife, maybe this nudges me. For me personally, this is a near-total miss.

## What's working

- **The discount ladder is clear and immediate.** "$15 off $49, $20 off $99, $60 off $199" — I understood the deal in under five seconds. No guessing, no math. I appreciate that.
- **"2 DAYS ONLY!" gets my attention.** Urgency language works on me. I don't want to miss a sale.
- **Free shipping for VIPs and in-store returns** — those utility perks near the bottom are things I actually care about. Picking up in-store or returning without hassle matters at my age.

## What's weak

- **Every single product shown is women's shoes.** Strappy sandals. Block heels. Espadrilles. I'm a 62-year-old man. There's not one shoe in this email I'd ever buy for myself.
- **The "Shop by Size" grid starts at a women's 5.** Even the size module excluded me. And "Wide Calf" is not a men's category.
- **"How much will you save???" is three question marks too many.** That preview text reads like a teenager wrote it. It doesn't make me curious — it makes me roll my eyes.
- **No men's comfort tech, no slip-ins, no casual shoes anywhere.** DSW carries Skechers. I know this. But you'd never know it from this email.
- **The fine print under the offer is tiny.** On my phone, I can barely read it. I don't know if my purchase qualifies, and I'm not going to squint to find out.
- **DSW VIP vs. my Skechers Plus** — I'm already loyal somewhere else. The VIP pitch at the bottom doesn't connect to anything I care about here.

## Recommendations

- 1. **If you know I'm male, show me men's shoes.** Full stop. The product grid should be dynamically rendered by gender. This is basic segmentation.
- 2. **Lead with a men's comfort or wide-width hook.** Something like "Your next favorite slip-on is on sale" would stop my scroll.
- 3. **Drop the triple question marks.** "Save $15 on your next pair — today only" is more my speed. Treat me like an adult.
- 4. **Legible fine print or a "see details" link.** I want to know if my purchase qualifies without needing reading glasses and a magnifying glass.
- 5. **Size module should reflect men's sizing** — or skip it entirely if you're not going to personalize it.

### 3. Rendering & Accessibility

**[HIGH] `Src:` (capital S) in all 10 `@font-face` blocks — confirmed CSS parse error.**

CSS property names are case-sensitive in spec. Every `@font-face` block uses `Src:` instead of `src:`. Most browsers silently discard the invalid declaration, causing silent fallback to system fonts across all declared typefaces (Futura PT Regular/Medium/Demi/Bold, HelveticaNow Regular/Medium/MediumItalic/Bold/BoldItalic/Italic). This affects all 10 font-face declarations in the `<style>` block.

**[HIGH] `text-size-adjust: none` in universal reset — conflicts with earlier value in same rule.**

The `*` selector sets both `-ms-text-size-adjust: 100%` and then `text-size-adjust: none` in the same declaration block. The final `none` wins, disabling OS-level text scaling globally. This breaks user accessibility settings on mobile and violates WCAG 1.4.4 (Resize Text).

```css
/* Confirmed in source — same rule block, none overrides 100% */
*{-ms-text-size-adjust: 100%; -webkit-text-size-adjust: 100%; ... text-size-adjust: none}
```

**[MEDIUM] `maximum-scale=1` in viewport meta tag prevents pinch-to-zoom.**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

Locks zoom at 1×. Fails WCAG 1.4.4 and is blocked by Safari on iOS 10+ (ignored by browser), but remains a compliance flag.

**[LOW] `<meta content="text/html; charset=utf-8" />` missing `http-equiv` attribute.**

```html
<!-- Current (invalid) -->
<meta content="text/html; charset=utf-8" />

<!-- Correct -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

Without `http-equiv="Content-Type"`, the charset declaration is a no-op meta tag. Charset may be inferred correctly by modern clients from HTTP headers, but older clients (Outlook 2007–2016) rely on this tag.

**[LOW] `supported-color-schemes` declared as CSS property inside `:root {}` — not valid CSS.**

```css
:root {
  color-scheme: light dark;          /* valid */
  supported-color-schemes: light dark; /* not a CSS property — meta-tag only */
}
```

The meta tag equivalent is correctly present (`<meta name="supported-color-schemes" content="light dark" />`), so no functional impact, but this is dead/misleading code.

**[LOW] Futura PT fonts served as `.woff` only — no `.woff2` or `.ttf` fallback formats.**

HelveticaNow is served as `.ttf`. Futura PT lacks a `.woff2` variant (better compression, ~30% smaller) and a `.ttf` fallback for clients that skip `.woff`.
