## Technical Audit — adidas x Mercedes-AMG PETRONAS F1 Blue Wonder Collection

---

### 1. Technical Summary

The email has three confirmed failures: a broken destination URL, an unfired merge token, and a missing plain-text body. Six arrow-icon images and one tracking pixel are served over HTTP, risking silent blocking by Gmail and Outlook.

---

### 2. Link & Tracking Issues

**[FAIL] Broken destination link — unknown URL scheme**

The redirect chain resolves to a destination path using `/g/` instead of the expected `/o/` scheme used on all other adidas.com links in this send:

```
Destination resolved: /g/84f44469-a4eb-408b-9edf-13f411048c1e?txn=e7770680-79a8-11f1-b80e-764a3bc6abf2
Expected pattern:     /o/84f44469-a4eb-408b-9edf-13f411048c1e
```

This is a click-path failure for at least one CTA. The outer click-redirect URL is:
`https://dv.adidas.com/o/84f44469...` — the `/o/` wrapper resolves correctly, but the inner `txn`-parameterized target does not.

**[INFO] 29 tracking links not probed** — click.comms.adidas.com redirect URLs were excluded from HTTP validation. Destination health for those CTAs is unverified.

---

### 3. Rendering & Accessibility

**[WARN] 6 identical HTTP image URLs — same asset, repeated 6×**

All six instances reference the same arrow icon over HTTP:
```
src: http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg
```
Gmail (via proxy) and Outlook 365 will silently block non-HTTPS image sources. This asset should be served from `https://`.

**[WARN] 1 tracking pixel over HTTP**
```
src: http://click.comms.adidas.com/CI0/0102019f3a557863-2938e145-d378-4b45-abaf-14b911b7973b-000000/...
```
Open-tracking pixel served over HTTP. Same blocking risk; open-rate data will be undercounted in clients that enforce HTTPS-only image loading.

**[WARN] 2 images missing `alt` text**

- Dynamic product image: `https://dv.adidas.com/o/84f44469-a4eb-408b-9edf-13f411048c1e?cp_tp=v3...`
- Tracking pixel: `http://click.comms.adidas.com/CI0/...`

The product image alt omission degrades accessibility (screen readers, image-off clients). The pixel omission is lower priority but technically non-conformant.

**[INFO] Duplicate `@font-face` declarations**

`AdihausDIN` and `AdineuePRO` are each declared twice across two `<style>` blocks with slightly differing fallback lists (`local('Calibri'), local('Sans Serif')` present in block 1, absent in block 2). Redundant declarations; no rendering breakage expected, but adds ~300 bytes of CSS bloat.

**[INFO] Malformed `<meta>` charset tag**

```html
<meta content="text/html; charset=UTF-8" />
```
Missing `http-equiv="Content-Type"`. Some older clients may not parse charset from this tag. Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
```

**[INFO] `x-apple-disable-message-reformatting` missing `content` attribute**

```html
<meta name="x-apple-disable-message-reformatting" />
```
Apple Mail requires `content=""` to honor this directive.

### 4. Personalization & Merge Tokens

```
%%P_POS_SCS_PEF_MCLU_SEG%%
```

This Salesforce Marketing Cloud AMPscript/personalization token was not substituted before send. Depending on where it appears in the template (likely a conditional block or segmentation flag), subscribers may have received a visible raw token or a broken conditional rendering path. Exact placement in the HTML was not locatable in the truncated source — the full template should be audited to determine whether this token controls content visibility or is rendered inline.

### 5. Compliance

**[FAIL] Plain-text alternative body is 0 characters**

The multipart/alternative MIME structure contains an empty text part. CAN-SPAM does not mandate a plain-text part, but its absence:
- Increases spam score on Spamassassin and similar filters (missing `text/plain` part is a signal)
- Breaks display in text-only clients and accessibility tools entirely

A minimal plain-text version with the key offer, a destination URL, and the unsubscribe link should be present.

**[INFO] Unsubscribe and physical address presence not verifiable** from the truncated source, but the footer CSS classes (`mobile-footer-padding-block`, `net-footer-logo-v2`) are consistent with a standard adidas footer template that typically includes these elements.

---

### 6. Email-to-Site Continuity

The click-redirect URLs use Salesforce Marketing Cloud's proprietary tracking parameters (`cp_tp`, `cp_cid`, `mi_cid`, `mi_mid`) rather than standard UTM parameters. This means:

- **GA4 / site analytics will not attribute this traffic** to the campaign unless adidas has a server-side translation layer or the landing pages extract SFMC params and map them to `utm_*` dimensions.
- Standard `utm_source=email&utm_medium=email&utm_campaign=...` are not present in any visible destination URL.

If adidas relies on GA4 or a third-party analytics platform for email-to-purchase attribution, this is a measurement gap — clicks will land as direct/unattributed traffic.
