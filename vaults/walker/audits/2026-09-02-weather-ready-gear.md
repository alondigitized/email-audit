## Technical Audit

Technical Email Audit — HOKA "Weather-ready gear"

**1. Technical Summary**
The email uses Cordial ESP tracking-link wrapping and font-face/media-query responsive CSS; automated QA found broken outbound tracking redirects (including the unsubscribe link) and a missing plain-text MIME part.

**2. Link & Tracking Issues**
- Primary CTA link ("hoka.com/en/us/return-start/") returns **403** through the Cordial redirect wrapper: `https://e.emails.hoka.com/c2/1664:6a8cb680084572103300c319:ot:69e560485cc95da09e001cd9:1/75ed0119?jwtH=...`. Decoded `jwtP` payload resolves to `https://www.hoka.com/en/us/return-start/?utm_source=US_Broadcast&utm_medium=email&utm_campaign=H_US_BR_20260902_...`. The wrapper itself is failing, not necessarily the destination — indicates a tracking-domain/JWT issue on Cordial's side (`cd`, `ce`, `tk`, `mtlID` claims present in the JWT).
- 12 of 28 links were probed (16 skipped per click-likelihood ranking); no other broken material links reported.

**3. Rendering & Accessibility**
- 13 images missing `alt` text, including all content images (`US_20260902_GoreTexStyles_*`, `US_Clifton11GTX_*`, `US_Speedgoat7GTX_*`, `US_StravaChallenge_SingleAsterisk.jpg`) and the footer logo (`LogoFooterPrimary.png`). Screen readers and images-off clients will render no fallback text.
- Two invisible tracking assets also flagged for missing alt (`e.emails.hoka.com/o/p/...` open pixel, `mg.emails.hoka.com/o/...` — expected/benign for pixels, not a real defect).
- Custom `@font-face` (TheFutureHOKA family) loads from `www.hoka.com/on/demandware.static/...`; no fallback stack shown in the truncated CSS beyond family name — most email clients strip custom fonts anyway, low risk.
- Mobile CSS uses malformed values in two rules: `.nav_padding { padding-top:px !important; padding-bottom:px !important; }` and `.nav_border { border-top:px solid ; }` — missing numeric values make these declarations invalid CSS (dropped by parsers), so intended nav padding/border likely won't apply at ≤480px.

**4. Personalization & Merge Tokens**
No merge/personalization tokens visible in the truncated source. No issues found in the visible portion, but truncation limits confidence — body content wasn't fully inspected.

**5. Compliance (CAN-SPAM, unsubscribe, authentication headers)**
- **Unsubscribe link is broken (403)**: same Cordial wrapper failure as above — `https://e.emails.hoka.com/c2/.../5d786cc3?jwtH=...` decodes to `https://options.hoka.com/unsubscribe?cid=69e560485cc95da09e001cd9&utm_source=US_Broadcast&...`. - Plain-text MIME part is **0 chars** — effectively missing. This doesn't itself violate CAN-SPAM but increases spam-filter risk and removes the unsubscribe/physical-address fallback that plain-text parts typically carry for text-only clients.

- Cannot confirm landing page alignment (e.g., that `hoka.com/en/us/return-start/` renders correctly) since the redirect wrapper itself 403s before reaching the destination — this is a tracking-layer failure, not confirmed evidence of a broken landing page.
