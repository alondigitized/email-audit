### 1. Technical Summary

One confirmed broken-experience bug (empty personalization token) and one broken tracking pixel (protocol-relative src). Twelve content images are served over HTTP and will be blocked by clients that enforce HTTPS-only loading.

---

### 2. Link & Tracking Issues

**Broken tracking pixel — missing protocol**
The Return Path reputation pixel has no protocol prefix:

```html
<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1..." />
```

Email clients treat this as a relative URL, so the request never fires. Deliverability/reputation data from Return Path will be missing for this send.

**HTTP open/match pixels**
`ink1000.com` open pixel is served over plain HTTP:

```
http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=PRO_US_NA_U_SITEBUNDLE_FULL_EN_05112026
```

Gmail and Outlook proxy all images over HTTPS; HTTP-only pixels may be suppressed or reported inaccurately.

**Third-party data-match beacons**
Three `beacon.krxd.net` pixels fire on open for cross-device identity matching. No issue per se, but these should be disclosed in the privacy policy if not already.

**26 click-redirect links** all route through `click.emails.skechers.com` — standard ESP redirect pattern, no structural issue.

---

### 3. Rendering & Accessibility

**12 content images served over HTTP**

All `image.emails.skechers.com` asset URLs use `http://`. Gmail proxies these but strips query params; clients with strict mixed-content enforcement (Apple Mail with certain privacy settings) may block them entirely.

Affected images include the Skechers logo, App Store/Google Play badges, Curbside Pickup, AfterPay, Find A Store, Instagram, Facebook, and YouTube icons.

Fix: change `http://image.emails.skechers.com` → `https://image.emails.skechers.com` across all `src` attributes.

**Missing alt text on 2 images**

```
o.gif (ink1000.com open pixel) — alt=""  ✓ acceptable for tracking pixel
49468f73-4651-4af3-bea2-61d1ae5db486.png — no alt attribute at all
```

The second image (no alt attribute) will break screen reader flow. Add `alt=""` at minimum if decorative.

**`<meta>` charset missing `http-equiv`**

```html
<meta content="text/html; charset=utf-8" />
```

Should be:

```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

Without `http-equiv`, older Outlook and Lotus Notes clients may not honor the charset declaration, risking character encoding errors on accented characters (e.g., "Skechers®").

**`-webkit-text-size-adjust: none` applied globally**

```css
* { -webkit-text-size-adjust: none; }
```

`none` (not `100%`) disables all automatic font scaling on iOS. Small legal-copy text that renders below 11px will remain unreadable and cannot be enlarged. Change to `-webkit-text-size-adjust: 100%`.

**Duplicate media query blocks**

Identical CSS rules are declared twice — once for `max-width: 375px` and again for `max-width: 640px`. This doubles stylesheet weight without effect. Not a rendering defect but adds ~1.5 KB to payload.

---

### 4. Personalization & Merge Tokens

**[FAIL] Empty first-name merge token**

QA confirmed the greeting renders as `"Hi ,"` — the subscriber first-name field is unpopulated or the fallback value is absent. This is a broken experience for any subscriber with a missing first name in the contact record.

Fix: add a fallback value to the merge tag, e.g. (Salesforce Marketing Cloud syntax):

```
Hi %%=IIF(EMPTY(FirstName), "there", FirstName)=%%,
```

No other unrendered merge tokens visible in the truncated source.
