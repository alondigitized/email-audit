## Technical Audit

## 1. Technical Summary
The email's tracked links return 403 to the automated probe, including the unsubscribe link. It has no plain-text part, and 7 images have no alt attribute. The HTML head also has small markup defects. Most of the 403s are probably bot-blocking by the Cordial redirector, not real breakage.

## 2. Link & Tracking Issues
- **403 on two probed links.** Both are Cordial click-tracking redirects on `e.emails.hoka.com/c2/1664:6af3b6461b2402d5ee0d503c:ot:69e560485cc95da09e001cd9:1/…`:
  - `/86830078`, link text "hoka.com/en/us/return-start/". The JWT payload decodes to `https://www.hoka.com/en/us/return-start/?utm_source=US_Broadcast&utm_medium=email&utm_campaign=H_US_BR_20261123_AM_BFHeadStart_…`.
  - `/44190699`, link text "Unsubscribe". It decodes to `https://options.hoka.com/unsubscribe?cid=69e560485cc95da09e001cd9&utm_source=US_Broadcast…`.
  - The 403 comes from the redirector or WAF. I can't tell from the QA data whether a real browser would also be blocked. Treat both as **unconfirmed breakage**, not confirmed.
- **Possible 24-hour link expiry.** The JWT payload carries `"ce":86400` alongside `"iat":1795438165`. If `ce` is an expiry in seconds, every tracked link, including unsubscribe, dies about 24 hours after send. I couldn't confirm this from the data. Check it with the ESP.
- **Raw URL as link text.** The "hoka.com/en/us/return-start/" label is a bare URL, so the visible text may not match the real destination. The wrapper hides the destination in a JWT.
- **Coverage gap.** Only 12 links were probed and 7 were skipped, so the other links' status is unknown.

## 3. Rendering & Accessibility
- **Missing alt text on 7 images.** Five are content images on `images.usw2.cordial.com`:
  - `H_US_Hero_BFEA_3.jpg`
  - `H_US_Subcopy_Hero_BFEA_2.jpg`
  - `H_US_CTA_BFEA_1.jpg`
  - `US_NEWShoeFinder_20260623_Black.jpg`
  - `LogoFooterPrimary.png`

  The CTA and subcopy images probably carry the offer and call-to-action text. With images blocked, or in a screen reader, that text is lost. The other two are the open-tracking pixels (`e.emails.hoka.com/o/p/…`, `mg.emails.hoka.com/o/…`), which should use `alt=""`.
- **Plain-text part is empty.** The QA data shows "Text version is 0 chars", with no multipart/alternative text part. This can hurt spam scoring and leaves text-only clients and some assistive tools with nothing to read. It may be an artifact of the relay, so check the original send.
- **Charset declaration is ineffective.** `<meta content="text/html; charset=utf-8" />` has no `http-equiv="Content-Type"`, so it declares nothing.
- **Empty `<title></title>`.**
- **Conflicting viewport tags.** There are two `<meta name="viewport">` tags. One has `maximum-scale=1`, which restricts pinch zoom. The other has `user-scalable=yes`.
- **Invalid CSS.** `.nav_padding {padding-top:px !important;padding-bottom:px !important;}` and `.nav_border {border-top:px solid ;}` have unit-only values with no number, so the browser discards them. These are empty template tokens.
- **Web fonts.** `TheFutureHOKA` is loaded from `www.hoka.com/on/demandware.static/…`. Most email clients ignore `@font-face`, so they will use fallback fonts. Confirm the font stack has web-safe fallbacks. The truncated source doesn't show it.

No issues found. The truncated HTML shows no unrendered tokens (`{{…}}`, `%%…%%`, `[FNAME]`). I can't assess the part of the HTML that was cut off.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Unsubscribe link present.** It points to `options.hoka.com/unsubscribe`, but it returned 403 on probe (see section 2). If it fails for real users, that is a CAN-SPAM violation, so verify it in a real browser and mail client.
- **No List-Unsubscribe headers checked.** The QA data says nothing about `List-Unsubscribe` or `List-Unsubscribe-Post` (RFC 8058 one-click). Gmail and Yahoo require these for bulk senders.
- **SPF/DKIM/DMARC status unknown.** `Authentication-Results` was not found. This is a limit of the AgentMail relay, not evidence of a sender problem. The sender `info@emails.hoka.com` aligns with the tracking domains `e.emails.hoka.com` and `mg.emails.hoka.com`.
- **Physical address and footer.** These are not visible in the truncated source, so I can't verify them.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **UTMs are present** on the decoded links: `utm_source=US_Broadcast`, `utm_medium=email`, and a structured `utm_campaign` (`H_US_BR_20261123_AM_BFHeadStart_Launch_A180Day_HighestEngaged_HighLTV_460SaleTag_SaleBrowsers_SearchBondi_LY1123Openers_LYLLYAnniPurchasers_`). The campaign naming is consistent with a 2026-11-23 send.
- **Over-long `utm_campaign`.** It encodes audience segments and ends with a trailing underscore. It is valid, but it exposes internal segmentation in the URL.
- **Extra identifiers.** Both decoded links append `hmail=9153f33f…` (a 64-character hash) and `cordial_id=69e56048…` to the destination query string, and the unsubscribe URL also carries `cid=`. Check that the hashed email value is intended to reach site analytics and third-party scripts on hoka.com.
- **Unsubscribe link carries UTMs.** This is harmless but unnecessary.
- **Landing-page alignment.** The destination for the "return-start" link is `hoka.com/en/us/return-start/`, a returns page. This is the only destination I could decode, and I haven't checked whether it fits the Black Friday campaign.

## 7. Recommendations
1. Re-test the `return-start` and unsubscribe links with a real browser user-agent. If they still return 403, fix the redirector or WAF and treat unsubscribe as a P0.
2. Ask the ESP (Cordial) whether `ce:86400` limits link lifetime. If it does, extend it, and never let the unsubscribe link expire.
3. Add a plain-text multipart alternative.
4. Add descriptive `alt` text to the hero, subcopy, CTA and shoe-finder images, and `alt=""` to the tracking pixels. Make sure the offer text is also present as live text.
5. Fix the head: add `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">`, fill in `<title>`, keep a single viewport tag without `maximum-scale=1`, and remove the empty-value CSS rules.
6. Verify `List-Unsubscribe` and `List-Unsubscribe-Post` headers and SPF/DKIM/DMARC on the original message, since the relay hid them.
7. Review `hmail` and the segment-laden `utm_campaign` for privacy and hygiene.
