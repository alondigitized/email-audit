### 3. Rendering & Accessibility

**[HIGH] Duplicate `<meta name="viewport">`**
```html
<meta content="width=device-width; initial-scale=1.0; maximum-scale=1.0;" name="viewport" />
<meta name="viewport" content="width=device-width" />  <!-- line 2 overrides line 1 -->
```
The second tag silently overrides the first in most clients, discarding `initial-scale` and `maximum-scale`. Result: inconsistent zoom behavior across iOS Mail, Gmail app, and Android. Only one viewport meta should exist.

**[HIGH] Nested/unclosed `@media` blocks (invalid CSS)**
```css
@media screen and (max-width: 414px) { .padl10m { padding-left: 0px; }
@media screen and (max-width: 412px) { .padl10m { padding-left: 0px; }
@media screen and (max-width: 405px) { … }
```
The 414px block is opened but never closed before the 412px block begins. This cascades through seven consecutive breakpoints, all effectively nested — which is invalid CSS. Gecko and WebKit parsers handle this inconsistently; some clients will discard all rules from 414px downward. The `}` count in the excerpt does not balance the `@media` opens.

**[MEDIUM] `border-collapse` applied to `td`, not `table`**
```css
table td { border-collapse: collapse; … }
```
`border-collapse` is a `<table>` property. On `<td>` it is a no-op. This is a dead rule; the intended reset is not applied. Correct selector: `table { border-collapse: collapse; }`.

**[MEDIUM] `-webkit-text-size-adjust: none`**
Setting `none` (vs. `100%`) completely disables text-size adjustment, including user-initiated scaling on low-vision devices. WCAG 1.4.4 (Resize Text) concern. Change to `100%`.

**[LOW] `maximum-scale=1.0` in first viewport tag**
Prevents pinch-to-zoom on iOS. Redundant given the second viewport tag wins anyway, but confirms the original intent was to block zoom — which is an accessibility anti-pattern.

**[LOW] Missing `http-equiv` on charset meta**
```html
<meta content="text/html; charset=utf-8" />
```
`http-equiv="Content-Type"` attribute is absent. Most clients infer charset correctly anyway, but the declaration is non-conformant. Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

**[LOW] XHTML namespace uses `https://`**
```html
<html xmlns="https://www.w3.org/1999/xhtml" lang="en">
```
The canonical XHTML namespace URI is `http://www.w3.org/1999/xhtml` (HTTP, not HTTPS). Strict XML parsers treat this as an unrecognized namespace.
