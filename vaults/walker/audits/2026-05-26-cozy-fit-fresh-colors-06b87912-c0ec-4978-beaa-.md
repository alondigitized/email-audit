## Technical Audit

# Technical Audit — "Cozy Fit, Fresh Colors"

## 1. Technical Summary
Email renders on standard SFMC scaffolding but ships with a broken personalization token (empty greeting) and a fleet of `http://` image references that risk being blocked by Gmail/Outlook image proxies. No HTTPS for the primary CDN is the dominant infrastructure defect.

## 2. Link & Tracking Issues
- 27 tracking/click-redirect links present (`click.emails.skechers.com`) — skipped by automated HTTP probe, manual validation recommended.
- Multiple third-party tracking pixels firing in parallel: Salesforce Marketing Cloud (`click.emails.skechers.com/open.aspx`), Krux/Salesforce DMP (`beacon.krxd.net` — 3 separate calls), Return Path (`pixel.app.returnpath.net`), and Ink/Movable Ink (`ink1000.com/p/up/...o.gif`). Pixel sprawl is functional but worth auditing for duplicates.
- Return Path pixel uses a protocol-relative/bare URL (`pixel.app.returnpath.net/pixel.gif?...`) with no scheme — most clients will treat as relative and fail to load.

## 3. Rendering & Accessibility
- **Non-HTTPS image hosts** — at least 10 images served over `http://image.emails.skechers.com/...` and `http://www.ink1000.com/...`. Gmail's image proxy and Outlook.com routinely block or downgrade mixed-content images.
- **Missing `alt` attributes** on at least two images: `o.gif` (tracking, acceptable but should be `alt=""`) and `49468f73-4651-4af3-bea2-61d1ae5db486.png` (content image — accessibility failure).
- DOCTYPE is XHTML 1.0 Transitional — fine, but `<meta http-equiv="X-UA-Compatible" content="IE=Edge">` is malformed (missing `http-equiv` attribute on the IE=Edge meta).
- Duplicate media query blocks for `max-width:640px` and `max-width:375px` contain identical rule sets — bloats payload but not breaking.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot** — QA detected `"Hi ,"` indicating an unresolved first-name merge token. Either the data extension lacks a fallback or AMPscript `%%=v(@FirstName)=%%` was used without a default. Use `%%=IIF(EMPTY(@FirstName),"there",@FirstName)=%%` or equivalent.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- HTML source is truncated before the footer — unsubscribe link, physical postal address, and List-Unsubscribe headers cannot be verified from the supplied snippet.
- Sending domain `emails.skechers.com` is consistent with their known SFMC subdomain; DKIM/SPF/DMARC alignment not verifiable without raw headers.

## 6. Email-to-Site Continuity
- Cannot evaluate UTM parameters — all destination URLs are wrapped in `click.emails.skechers.com` redirects and the unwrapped targets are not in the truncated source. Recommend a follow-pass on resolved final URLs to confirm `utm_source/medium/campaign` are populated and consistent with the campaign code `MKG_US_NONPURCLICK_U_COZY_NONPURCH_EN_05232026`.

## 7. Recommendations
1. **Fix the empty greeting** — add a default-value fallback on the first-name merge field; this is a visible defect in the inbox.
2. **Force HTTPS on `image.emails.skechers.com`** — the CDN supports TLS; update the SFMC content block image references to `https://`. Same for the Ink tracking pixel.
3. **Add `alt=""` to tracking pixels** and meaningful `alt` text to content images (e.g. the `49468f73…` hero asset).
4. **Fix the Return Path pixel URL** — add the `https://` scheme.
5. **Repair the IE=Edge meta tag** — `<meta http-equiv="X-UA-Compatible" content="IE=Edge">`.
6. **Audit pixel stack** — confirm Krux, Return Path, and Ink are all still required; each adds load time and a potential failure point.
