## Technical Audit

# Technical Audit — Skechers "Red, White & BOGO 50% Off"

## 1. Technical Summary
Email is structurally sound XHTML 1.0 Transitional with responsive CSS, but ships a broken merge token in the greeting and serves nearly all images over plain HTTP, which will be downgraded or blocked by stricter mail clients.

## 2. Link & Tracking Issues
- 27 tracking/click-redirect links were skipped by the HTTP prober — none verified as resolvable end-to-end.
- Open-pixel beacons fire correctly: `click.emails.skechers.com/open.aspx` (SFMC), `beacon.krxd.net` (Krux/Salesforce DMP, 3 variants), Return Path (`pixel.app.returnpath.net` — note: missing `https://` scheme, rendered as a relative URL and will 404), and `ink1000.com/p/up/.../o.gif`.
- Return Path pixel `<img src="pixel.app.returnpath.net/pixel.gif?r=...">` has no protocol — browser/client will resolve it against the host page and fail to track.

## 3. Rendering & Accessibility
- **HTTP image hosts (13 instances)**: every asset on `image.emails.skechers.com/lib/...` and `ink1000.com` is served over `http://`. Gmail proxies and Apple Mail Privacy Protection commonly block or fail to upgrade these; expect broken images for a meaningful share of recipients.
- **Missing alt text**: `o.gif` tracking pixel (acceptable — decorative) and `49468f73-...png` (content image — accessibility regression).
- DOCTYPE is XHTML 1.0 Transitional — acceptable for email but `<meta content="IE=Edge" />` is missing the `http-equiv="X-UA-Compatible"` attribute, making the tag a no-op.
- First `<meta>` charset tag is also missing `http-equiv="Content-Type"`; technically invalid though clients tolerate it.
- Two near-duplicate `@media` blocks at `max-width: 375px` and `max-width: 640px` define identical rules — bloats payload, no functional issue.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot**: greeting renders as "Hi ," — the first-name merge variable resolved to an empty string and was not guarded with a fallback (e.g., `%%=IIF(EMPTY(@FirstName), "there", @FirstName)=%%` in AMPscript). This is a visible personalization failure to the recipient.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- HTML source is truncated before the footer; unsubscribe link, physical postal address, and List-Unsubscribe headers cannot be verified from the provided excerpt.
- From-address `no-reply@emails.skechers.com` is on a dedicated sending subdomain consistent with SFMC setups; SPF/DKIM/DMARC headers were not included in the audit payload and could not be verified.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- Cannot verify — all destination links are wrapped in `click.emails.skechers.com` redirects, and the prober skipped them. UTM params on the resolved landing URLs are not inspectable from this source.
- Campaign ID `PRO_US_NONPURCLICK_U_SITEBUNDLE_NONPURCH_EN_05252026` is present in tracking pixels, suggesting internal attribution is wired up even if standard `utm_*` params aren't.

## 7. Recommendations
1. **Fix the empty-name merge** — add an `IIF(EMPTY(...))` or `ISNULL` fallback to the greeting personalization string before next send.
2. **Migrate image hosts to HTTPS** — update `image.emails.skechers.com` and `ink1000.com` references to `https://` to prevent client-side blocking under Gmail image proxying and MPP.
3. **Fix the Return Path pixel** — prefix `pixel.app.returnpath.net/pixel.gif?...` with `https://` so the deliverability beacon actually fires.
4. **Add alt text** to `49468f73-...png` (and audit any other content images in the truncated portion).
5. **Repair the IE compatibility meta tag** — `<meta http-equiv="X-UA-Compatible" content="IE=Edge" />`.
6. **Have QA re-run the link prober with tracking domains followed** to validate the 27 skipped click-redirects end-to-end before next deploy.
