### 3. Rendering & Accessibility

**`<meta>` charset tag missing `http-equiv`**
```html
<meta content="text/html; charset=utf-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, charset declaration is ignored by some email clients (notably older Outlook versions), risking mojibake on special characters.

**`<meta http-equiv>` for IE missing attribute**
```html
<meta content="IE=Edge" />
```
Missing `http-equiv="X-UA-Compatible"` — the tag is a no-op as written.

**`@font-face` uses capitalized `Src:` (invalid CSS)**
All 10 `@font-face` blocks use `Src:` (capital S) instead of the valid lowercase `src:`. Technically malformed; most parsers tolerate it, but it fails strict validation and may silently drop on stricter CSS parsers.

**`maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocking zoom is a WCAG 1.4.4 (Level AA) violation and prevents low-vision users from enlarging content on mobile.

**Missing `lang` attribute on `<html>`**
```html
<html xmlns="http://www.w3.org/1999/xhtml">
```
No `lang="en"` — screen readers cannot determine language for correct pronunciation rules.

**Font format inefficiency**
- Futura PT fonts: served as `.woff` only — no `.woff2` fallback. Modern clients support woff2 (30% smaller).
- HelveticaNow fonts: served as `.ttf` (largest format). Should be `.woff2` or `.woff`. Each TTF file adds ~50–100 KB per weight, multiplied across 6 variants.

**Inconsistent `text-size-adjust` values**
```css
-webkit-text-size-adjust: 100%;
-ms-text-size-adjust: none;   /* different value */
```
`-ms-text-size-adjust: none` disables auto-sizing entirely on Windows Phone/IE, while `-webkit` is set to `100%`. Should be consistent: both `100%`.
