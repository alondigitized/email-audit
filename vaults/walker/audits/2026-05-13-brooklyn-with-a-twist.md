## Technical Audit

## Technical Audit — Crocs "Brooklyn, with a twist?" (2026-05-13)

---

### 1. Technical Summary

The email is structurally sound with no broken rendering blocks, but carries two categories of real risk: seven footer/social images served over plain HTTP that will be blocked in strict clients, and four personalization recommendation images that embed the recipient's raw email address as a URL query parameter — a PII exposure issue.

---

### 2. Link & Tracking Issues

**35 click-tracking links skipped by QA probe** — all links redirect through a click-tracking domain; destination URLs and UTM parameter presence could not be verified. This is expected behavior but means landing page alignment (Section 6) cannot be confirmed.

**Tracking pixel uses hashed subscriber ID** — `d_dpuid=9153f33fe5...` in `demandwarecrocs.demdex.net/event` appears to be a SHA-256 hash. No plaintext PII in the pixel itself. ✓

**Recommendation engine images expose raw email address in URL path:**
```
https://10745993.recs.igodigital.com/rr/v2/685c6ddd06fd7c003f1cd785/i/1/walker@agentmail.to?category=Recommended+for+You
```
The recipient address appears unencoded in the URL path segment (positions `/i/1/`, `/i/2/`, etc.) for all four recommendation images. Every HTTP request for these images transmits the plaintext email to igodigital's CDN and any intermediary proxy. This is a PII-in-logs risk.

---

### 3. Rendering & Accessibility

**7 images served over HTTP** — all in the footer block, sourced from `http://image.crocs-email.com`:

|---|---|
| App Store badge | `9c36c0ef-333c-4e6c-bec8-9e0ac799d475.png` |

| Facebook | `80f68cd8-0090-4258-b202-50e422ad1b5c.png` |

| YouTube | `1187ef58-07fe-4985-8349-93e338d86694.png` |

HTTP images are blocked by Outlook 2016+ (mixed-content), Apple Mail on iOS 15+ (default image loading is HTTPS-proxied), and some corporate gateways. All seven should be `https://`.

**Malformed `<meta>` charset tag** — missing `http-equiv` attribute:
```html
<!-- actual -->
<meta content="text/html; charset=utf-8" />
<!-- correct -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, this tag is inert. Charset declaration falls back to browser/client heuristics.

**5 images missing `alt` text:**
- Tracking pixel (`demandwarecrocs.demdex.net`) — alt="" is acceptable here by convention, but the attribute is absent entirely.
- All 4 igodigital recommendation images — these are product images that should carry descriptive alt text for image-off rendering (Outlook default, many corporate environments).

**Dual preheader implementation** — a `.preheader` div is hidden via a `<style>` block placed inside `<body>` (non-standard), plus a second spacer div with zero-width Unicode characters. Both target the same preheader slot. Functional in practice but the in-body `<style>` tag for `.preheader { display: none }` is stripped by some clients (Gmail, Yahoo), leaving the preheader div potentially visible. The inline `style="font-size:1px;display:none !important"` on the div itself is the reliable fallback and appears present.

### 5. Compliance

Authentication headers (SPF, DKIM, DMARC) cannot be assessed from HTML source alone — requires raw message headers.

Unsubscribe link presence cannot be confirmed from the truncated HTML. CAN-SPAM requires a functional unsubscribe mechanism and physical mailing address in every commercial email.

`From` domain is `crocs-email.com` (ESP subdomain), not `crocs.com`. DMARC alignment requires SPF/DKIM pass on the `From` header domain; this should be verified against DNS records for `crocs-email.com`.

### 6. Email-to-Site Continuity

All 35 CTA links pass through a click-tracking redirect — destination URLs and UTM parameter completeness could not be confirmed by the QA probe. Manual spot-check of decoded redirect targets is needed to verify `utm_source`, `utm_medium`, and `utm_campaign` consistency with `us_20260513_collection_brooklyn_x`.
