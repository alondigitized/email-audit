## Technical Audit

## Technical Summary

Site runs on **Salesforce Commerce Cloud** (demandware.static). The dominant technical risks are: (1) Kasada bot-protection self-rate-limiting during automated traversal, causing the cart page to return 429 and likely rendering it non-functional; (2) an outsized third-party script payload with several duplicate loads; (3) two serious accessibility regressions on the View Cart template (missing `<title>` and `lang`). LCP and CLS were not captured, leaving the most impactful Web Vitals blind.

---

## Accessibility

**1 critical, 2 serious, 12 moderate violations across 3 pages.**

| Severity | Rule | Page |
|---|---|---|
| Critical | `aria-required-parent` | Homepage |
| Serious | `document-title` | View Cart |
| Serious | `html-has-lang` | View Cart |
| Moderate | `landmark-no-duplicate-main`, `landmark-main-is-top-level`, `landmark-unique`, `region`, `landmark-complementary-is-top-level`, `heading-order` | Homepage |
| Moderate | `landmark-one-main`, `page-has-heading-one` | View Cart |
| Moderate | `landmark-complementary-is-top-level`, `landmark-unique`, `region` | Search |

**Critical item:** The `aria-required-parent` violation means an element with an ARIA role (likely a `role="option"` or similar) is orphaned from its required container — screen reader navigation will break for that component.

**View Cart template failure:** Missing `<title>` and `html[lang]` on the cart page suggests the cart is either rendered in an iframe or via a partial-page swap that does not bootstrap a full HTML document. This is a fundamental template defect, not a configuration gap.

**Landmark soup on Homepage:** Duplicate `<main>` and improperly nested `<aside>` elements indicate multiple independently rendered widgets each emitting their own landmark structure without coordination.

- No canonical or hreflang issues visible in the truncated source, but the page class `g-local-en_US` confirms locale-scoped rendering is in place.

## Mobile Optimization

- `--vh: 6.640000000000001px` is a JS-computed viewport unit workaround for mobile browser chrome (100vh bug). This is a known pattern but creates a render dependency on JS execution before any `--vh`-sized element paints. A precision value like `6.640000000000001` suggests a raw `window.innerHeight / 100` calculation without rounding — cosmetically harmless but worth normalizing.
- LCP and CLS not captured — cannot assess image lazy-loading correctness, hero render path, or layout shift on scroll without these metrics. The audit is incomplete for mobile perf without them.
- WebFontLoader 1.6.28 (2018) loads via `<script async>` and triggers a FOUT cycle for Mulish across 5 weights. The `wf-active` class is present in the HTML, meaning fonts are injected client-side rather than via `<link rel="preload">`.

## Console & Network Errors

**Rate limiting (Kasada bot protection — 5x 429):**
```
/149e9513-01fa-4fb0-aad4-566afd725d1b/2d206a39-8ed7-437e-a3be-862e0f06eea3/fp?x-kpsdk-v=j-1.2.391
```
This UUID-path endpoint is the Kasada fingerprinting challenge. The automated browser is triggering Kasada's bot detection, causing the fingerprint endpoint to 429. This cascades into the `/cart/` 429 — Kasada blocks the cart request because the fingerprint was never successfully established. **The cart is functionally broken in this test environment.** Real user sessions would pass the challenge; automated audits will not without Kasada bypass handling.

**CORS failure (Stylitics outfit widget):**
```
https://web-assets.stylitics.com/style.css?base=hotspots&theme=skechers&version=11d3ae821d
```
The Stylitics CSS is blocked by CORS — the `stylitics.com` CDN is not returning `Access-Control-Allow-Origin: https://www.skechers.com`. This breaks the "Complete the Look" / outfit-hotspot feature wherever it appears. Either the Stylitics CDN configuration is wrong or a recent Stylitics version deploy changed the CORS headers. This is a live production bug affecting a revenue-contributing feature.

## Recommendations

**P0 — Fix now:**
1. **Stylitics CORS regression** — file a ticket with Stylitics or update the CDN configuration to emit the correct `Access-Control-Allow-Origin` header. The outfit feature is silently broken for all real users hitting that component.
2. **View Cart template** — audit the cart page render path for the missing `<title>` and `html[lang]`. If the cart renders inside a shell that strips the document head, that shell needs to re-inject these elements.

**P1 — Fix this sprint:**
3. **Capture LCP and CLS** — the audit cannot assess Core Web Vitals compliance without these. Run a Lighthouse or CrUX trace on a real mobile device (not a bot-triggering automated session).
4. **Deduplicate third-party tags** — remove the duplicate loads of `tags.creativecdn.com`, `s.yimg.com/wi/ytc.js`, and consolidate Monetate to a single version endpoint. These are measurable wasted bytes on every page load.
5. **Kasada bypass for synthetic monitoring** — configure the monitoring tool with a synthetic test user token or use Kasada's allowlisted IP range so cart-step testing reflects real user behavior.

**P2 — Backlog:**
6. **`aria-required-parent` (critical)** — identify which Homepage component emits the orphaned ARIA role and fix the markup hierarchy.
7. **Landmark architecture** — coordinate widget teams to avoid emitting `<main>` or `<aside>` inside widget templates; those landmarks belong to the page shell only.
8. **WebFontLoader → `<link rel="preload">`** — replace the JS-driven font load with `preload` + `font-display: swap` to eliminate the FOUT cycle and reduce LCP risk.
9. **Round `--vh` value** — `Math.round(window.innerHeight / 100 * 1000) / 1000` to avoid the floating-point artifact.
