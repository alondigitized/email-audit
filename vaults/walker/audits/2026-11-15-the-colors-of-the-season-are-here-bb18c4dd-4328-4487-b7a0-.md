## Technical Audit

## 1. Technical Summary
The email has one confirmed rendering and personalization failure (an empty greeting slot, "Hi ,"). It also has several tracking-pixel problems: a scheme-less `src`, `http://` image sources and missing `alt` attributes. The HTML provided was truncated and the Authentication-Results header was absent, so link destinations, UTM parameters, the footer and authentication could not be verified.

## 2. Link & Tracking Issues
- **Scheme-less pixel URL:** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…" width="1" height="1" />` has no `https://`. Clients resolve it as a relative path, so the request fails and the Return Path/Validity seed pixel never fires. It also has no `alt`.
- **Insecure pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=MKG_US_NA_U_COLOR_ENGAGEDL14D_EN_11152026` is served over plain HTTP, so clients may block it (QA WARN).
- **Third-party beacons:** Four `beacon.krxd.net` pixels (usermatch ×2, ad_impression) and the `click.emails.skechers.com/open.aspx` open pixel are inside `display:none` containers. Some clients strip or ignore these, so open and impression data can be undercounted.
- **Unprobed links:** 42 tracking links were skipped by the QA probe because they are click-redirect domains. Final destinations and redirect health are unverified.

## 3. Rendering & Accessibility
- **Empty greeting:** QA FAIL. The greeting renders as "Hi ," with an empty name field (see section 4).
- **Missing `alt`:** QA confirmed two images without `alt`. These are `o.gif` (ink1000.com) and `dde00662-169f-447d-b0e2-fc65f6c2290c.png`. The PNG is a content image, not a pixel, so screen readers or image-blocked clients get no description.
- **HTTP content image:** `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png` is non-HTTPS and may be blocked or flagged as mixed content.
- **Malformed meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv`, so both are inert. Charset is then only declared in the Content-Type header, if at all.
- **Zoom disabled:** `viewport` contains `maximum-scale=1`, which prevents pinch-zoom (WCAG 1.4.4).
- **Layout tables:** The visible layout tables (`<table cellpadding="0" cellspacing="0" border="0">`, `<table class="widthFull" width="640">`) have no `role="presentation"`.
- **Text size adjustment:** `* { -webkit-text-size-adjust: none; }` blocks user text resizing on iOS.

## 4. Personalization & Merge Tokens
- **Empty name slot:** QA FAIL. The greeting renders "Hi ," because the first-name field is empty and there is no fallback. This happened in the QA inbox, so the send-time AMPscript or data extension has no default value for blank names. The rendered output shows no unresolved `%%…%%` tokens in the visible HTML.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication-Results:** Not found. QA notes it is expected via the AgentMail relay, so SPF/DKIM/DMARC status is unknown. This is a test-harness limitation, not a confirmed sender defect.
- **Unsubscribe, physical address and List-Unsubscribe:** Not verifiable. The truncated HTML does not reach the footer, and headers were not supplied.
- **Hashed-email sharing:** The `beacon.krxd.net` usermatch pixel (`partner=LprH63a7_sfmc_100007688_sha25`) passes a 64-hex value in `partner_uid`, which appears to be a SHA-256 of the recipient identifier. A second pixel passes `partner_uid=121173391`, apparently the SFMC subscriber ID. Both go to a third-party DMP on open. This is not a CAN-SPAM violation, but it should be covered by the privacy policy and consent handling.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
No issues confirmed. The campaign ID `MKG_US_NA_U_COLOR_ENGAGEDL14D_EN_11152026` appears in the ink1000 and Krux pixels. UTM parameters and landing page alignment could not be checked because the click links were skipped and the HTML was truncated.

## 7. Recommendations
1. **Add a first-name fallback:** Use an AMPscript `IIF(Empty(@firstName), "Hi there,", Concat("Hi ", @firstName, ","))` or similar. This is the highest-impact fix.
2. **Fix the Return Path pixel:** Change it to `https://pixel.app.returnpath.net/pixel.gif?r=…` and add `alt=""`.
3. **Use HTTPS:** Serve `o.gif` and `dde00662-….png` over HTTPS, and add `alt=""` to the tracking pixel and a descriptive `alt` to the PNG.
4. **Correct the meta tags:** Use `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
5. **Allow zoom:** Remove `maximum-scale=1` from the viewport meta, and add `role="presentation"` to the layout tables.
6. **Re-run QA with fuller data:** Use the full HTML, raw headers (Authentication-Results, List-Unsubscribe) and click-redirect resolution. That would let it check the unsubscribe link, the postal address, UTM parameters and landing page continuity.
