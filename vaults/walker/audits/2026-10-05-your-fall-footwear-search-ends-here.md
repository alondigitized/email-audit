## Technical Audit

## 1. Technical Summary
The email fails one QA check: an empty personalization slot renders "Hi ,". The visible source also shows a malformed tracking-pixel URL and plain-HTTP image sources. The HTML is truncated, so the footer, unsubscribe link and headers could not be checked.

## 2. Link & Tracking Issues
- **Broken pixel URL:** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…">` has no scheme. Clients resolve it as a relative path, so it never reaches Return Path and deliverability or seed tracking fails silently. It also has no `alt`.
- **35 tracking links not probed:** the QA run skipped them as click-redirect domains (`click.emails.skechers.com`). Their destinations are unverified.
- **Third-party pixels in a hidden block:** `beacon.krxd.net/1x1_usermatch.gif` (two calls) and `1x1_ad_impression.gif?confid=so3yexmpm&advertiserid=100007688`. These are legitimate DMP calls, but they add external requests and depend on the container's `display:none`.
- **Open pixel:** `click.emails.skechers.com/open.aspx?…&d=100223&bmt=0` is correctly formed over HTTPS.

## 3. Rendering & Accessibility
- **Mixed content:** two images load over `http://`, which QA flagged as possibly blocked:
  - `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=MKG_US_NA_U_BEST_ENGAGEDL14D_EN_10052026`
  - `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png`
  - The `.png` is on Skechers' own image host, so the fix is to serve it over HTTPS.
- **Alt text:**
  - `dde00662-…png` is missing `alt` (QA-confirmed). I couldn't see its tag in the truncated source.
  - The QA "missing alt" flag on `o.gif` looks like a false positive. The source shows `alt=""`, which is correct for a decorative pixel.
  - `returnpath` `pixel.gif` has no `alt` attribute at all.
- **Malformed meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv`, so they do nothing. The charset declaration is not applied.
- **No document language:** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang` or `xml:lang`, which hurts screen-reader pronunciation.
- **Layout tables:** the visible layout tables (`<table cellpadding="0" cellspacing="0" border="0">`, `class="widthFull"`) have no `role="presentation"`.
- **Redundant CSS:** `.hideme, .hidden, .mobile-hidden` are declared identically in two media queries. This is low impact.

6. **Add `lang="en"` and `xml:lang="en"` to `<html>`.** Add `role="presentation"` to the layout tables.
