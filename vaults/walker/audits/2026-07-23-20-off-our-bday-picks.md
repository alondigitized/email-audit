### 3. Rendering & Accessibility

**Issue 3a — Invalid `Src:` property in all `@font-face` blocks (confirmed)**

All 10 `@font-face` declarations use a capitalized `Src:` property:
```css
Src: url("https://braze-images.com/appboy/communication/assets/font_assets/files/67dd7a3bf1de1d0066403c87/original.woff") format('woff');
```
CSS property names are case-insensitive per spec, but some stricter email client parsers (notably older Samsung Mail, some Outlook WebView builds) will silently drop the rule. Fallback stack (`Helvetica`, `Arial`) will render instead — not broken, but web fonts may not load consistently.

**Fix:** Lowercase all `Src:` → `src:` across all `@font-face` blocks.

---

**Issue 3b — `text-size-adjust: none` overrides accessible scaling (confirmed)**

The CSS reset contains:
```css
* {
  -webkit-text-size-adjust: 100%;   /* allows scaling */
  -ms-text-size-adjust: none;       /* blocks scaling on IE/older Edge */
  text-size-adjust: none;           /* blocks scaling globally */
}
```
`text-size-adjust: none` (unprefixed) prevents OS-level text size adjustments. The `-webkit-` value correctly uses `100%` but is immediately overridden for standard/MS paths. This conflicts with WCAG 1.4.4 (Resize Text) and may trigger accessibility flags in inbox screening tools.

**Fix:** Change `text-size-adjust: none` and `-ms-text-size-adjust: none` to `100%`.

---

**Issue 3c — `maximum-scale=1` in viewport meta (confirmed)**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
`maximum-scale=1` prevents pinch-to-zoom on iOS Safari. Apple partially lifted this restriction in iOS 10+ for Safari, but it still applies in WKWebView-based apps (Gmail iOS, Outlook iOS). Users with low vision who rely on pinch-zoom will be blocked.

**Fix:** Remove `maximum-scale=1` or replace with `maximum-scale=5`.

---

**Issue 3d — No `woff2` format for any web font (confirmed)**

All Futura PT fonts declare only `format('woff')`; all HelveticaNow fonts declare only `format('truetype')`. No `woff2` source is provided. `woff2` is supported by all modern email clients that support web fonts at all (Apple Mail, Samsung Mail) and is 30–40% smaller.

**Fix:** Add `woff2` sources as the first `format()` entry in each `@font-face` block, with `woff`/`ttf` as fallbacks.

---

**Issue 3e — ⚠️ Image `alt` text unverifiable (source truncated)**

Standard check: all `<img>` tags must have `alt=""` (decorative) or descriptive `alt` text. Hero and product images with missing or empty `alt` on linked images will render as broken icon links in image-blocked clients (Outlook desktop default).
