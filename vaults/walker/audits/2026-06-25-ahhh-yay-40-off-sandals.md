### 3. Rendering & Accessibility

**Issue — `text-size-adjust: none` on `*` selector (confirmed):**
```css
* {
  -ms-text-size-adjust: none;   /* ← "none" disables resize entirely */
  text-size-adjust: none;
}
```
The rule above it sets `-webkit-text-size-adjust: 100%` correctly, then `text-size-adjust: none` overrides it for non-prefixed implementations. `none` prevents users from adjusting text size system-wide — a WCAG 1.4.4 violation. Should be `100%`.

**Issue — `maximum-scale=1` in viewport meta (confirmed):**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocks pinch-to-zoom on mobile. WCAG 1.4.4 (Resize Text, AA) requires content to be resizable up to 200% without assistive technology. Remove `maximum-scale=1`.

**Issue — Uppercase `Src:` in all `@font-face` blocks (confirmed):**
```css
@font-face {
  font-family: 'Futura_PT_Regular';
  Src: url("https://braze-images.com/...") format('woff');
}
```
All ten `@font-face` declarations use `Src:` (capital S). CSS property names are technically case-insensitive per spec, but some legacy email client CSS parsers (notably older Outlook WebView) reject non-lowercase property names and will silently drop the font load, falling back to system fonts. Should be `src:`.

**Minor — `.woff` only for legacy Futura fonts, `.ttf` for HelveticaNow:** No `.woff2` variant for any declared font. Not a breakage, but `.woff2` would reduce font payload ~30% for clients that support it.
