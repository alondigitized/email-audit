## Technical Audit

# Technical Audit: "Holiday Ready, from party to pajamas"

## 1. Technical Summary
The HTML is a standard SFMC table layout, but it has a failed personalization slot (`Hi ,`), a schemeless tracking pixel that won't resolve, and two `http://` images with no alt text. The `<head>` has malformed meta tags, and the HTML provided was truncated, so I couldn't check the footer, the unsubscribe link or the CTA URLs.

## 2. Link & Tracking Issues
- **Broken pixel URL (confirmed in source):** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…" width="1" height="1" />` has no `https://`. Clients resolve it as a relative path, so the Return Path/Validity open-tracking and inbox-placement pixel never fires.
- **Non-HTTPS images:**
  - `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=MKG_US_NA_U_SEASONAL_ENGAGEDL30D_EN_11192026`
  - `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png`
  - Clients may block or rewrite these. The second is a first-party content image on the sender's own domain, so it can be moved to HTTPS.
- **Many third-party beacons:** Five `<img>` tags sit in the hidden preheader wrapper: the SFMC open pixel, three `beacon.krxd.net` pixels and the Return Path pixel. A further `ink1000.com` pixel follows in the next table. Clients that don't fire `display:none` images won't load these, so the beacons will under-report.
- **Unverified links:** The QA run skipped HTTP probes on 33 tracking/redirect links. I can't confirm that any CTA resolves.

## 3. Rendering & Accessibility
- **Malformed meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv`, so neither declares anything. Rendering depends on the HTTP `Content-Type` header for the charset.
- **Zoom disabled:** `<meta name="viewport" content="… maximum-scale=1" />` blocks pinch-zoom, which fails WCAG 1.4.4.
- **Missing alt text:** The QA run flagged `o.gif` and `dde00662-….png` as having no `alt`. The `krxd.net` and `returnpath` pixels also have no `alt` attribute. The `dde00662` PNG is a content-sized image, not a spacer, so it needs real alt text or `alt=""`.
- **No language or table roles:** `<html xmlns="…">` has no `lang` attribute, and the layout tables in the visible markup have no `role="presentation"`.
- **Text-size adjust off:** `* { -webkit-text-size-adjust: none }` disables iOS text-size adjustment.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot (QA):** The greeting renders as `Hi ,`, so the first-name field was empty and there's no fallback. Add a default in the AMPscript (e.g. `%%=IIF(Empty(@firstName),"there",@firstName)=%%`) or remove the greeting for empty values. This is the only hard failure in the automated run.
- No unrendered `%%…%%` or `{{…}}` tokens appear in the visible HTML.

## 5. Compliance
- **Authentication headers:** `Authentication-Results` wasn't present. QA attributes this to the AgentMail relay, so SPF, DKIM and DMARC are unknown. This is a limit of the test setup, not a sender defect. The `From` domain `emails.skechers.com` needs to be checked on the raw message.
- **Unsubscribe / physical address / List-Unsubscribe:** I couldn't assess these because the HTML was truncated and no headers were supplied. I'm not flagging a defect.
- **Hashed identifier in a third-party beacon:** `beacon.krxd.net/1x1_usermatch.gif?…partner_uid=9153f33f…ced00` is a 64-character SHA-256 value, presumably of the subscriber's email. It is sent to a third-party DMP, so the privacy policy and consent basis should cover that sharing.

## 6. Email-to-Site Continuity
- **Campaign ID:** `MKG_US_NA_U_SEASONAL_ENGAGEDL30D_EN_11192026` appears in the `krxd` and `ink1000` pixels, which suggests an engaged-last-30-days segment.
- **UTM parameters and landing pages:** Not assessable. The CTA hrefs are click-tracked redirects (`click.emails.skechers.com`) that weren't probed or visible in the truncated source.

## 7. Recommendations
1. **Fix the greeting fallback** (`Hi ,`) so empty first names render a default.
2. **Add the `https://` scheme** to the `pixel.app.returnpath.net` pixel, or drop it if it isn't needed.
3. **Serve both flagged images over HTTPS** (`image.emails.skechers.com` and `ink1000.com`), and add `alt` text to them, including `alt=""` on the pure tracking pixels.
4. **Fix the head:** use `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`. Remove `maximum-scale=1`.
5. **Add `lang="en"` to `<html>`** and `role="presentation"` to the layout tables.
6. **Re-run QA on the full HTML and raw headers** to cover the footer, unsubscribe and `List-Unsubscribe`/`-Post`, SPF/DKIM/DMARC, and the UTM parameters on the redirect destinations.
