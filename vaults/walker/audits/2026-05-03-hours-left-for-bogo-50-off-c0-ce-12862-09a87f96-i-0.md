### 3. Rendering & Accessibility

**Malformed `<meta>` tags (missing `http-equiv`):**
```html
<!-- as sent — attribute missing -->
<meta content="text/html; charset=utf-8" />
<meta content="IE=Edge" />

<!-- correct form -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```
Without `http-equiv`, these tags are inert. The charset declaration will be ignored by some parsers; the IE compatibility hint will not be applied.

**Conflicting `-ms-text-size-adjust` in universal selector reset:**
```css
* {
  -ms-text-size-adjust: 100%;   /* set first */
  ...
  -ms-text-size-adjust: none;   /* overrides — wins */
}
```
The second declaration wins, effectively disabling text-size adjustment in legacy IE/Outlook. Intent appears to be `100%` (preserve scaling). Should be de-duplicated to a single `100%` value.

**`Src:` (capital S) in all `@font-face` blocks:**
```css
@font-face {
  font-family: 'Futura_PT_Regular';
  Src: url("https://braze-images.com/...") format('woff');
}
```
`Src` is not a valid CSS property name — the correct declaration is lowercase `src`. Most modern parsers are case-insensitive for property names, but this is technically invalid and will silently fail in strict parsers or future spec-compliant engines. Affects all 10 declared font faces.

**Single-format font declarations:** Each `@font-face` declares only `.woff` or `.ttf` — no fallback format. Not a defect, but reduces rendering reliability in environments where one format is unsupported.
