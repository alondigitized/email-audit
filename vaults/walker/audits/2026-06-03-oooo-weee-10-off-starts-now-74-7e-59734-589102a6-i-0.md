### 3. Rendering & Accessibility

**`Src:` capitalized in all `@font-face` declarations (10 instances)**
```css
Src: url("https://braze-images.com/...") format('woff');
```
`src` is a CSS descriptor, not a property — case sensitivity depends on the parser. Most desktop email clients tolerate this, but it is non-standard and will fail strict parsers.

**Duplicate, conflicting `-ms-text-size-adjust` values on `*`**
```css
*{
  -ms-text-size-adjust: 100%;   /* set first */
  ...
  -ms-text-size-adjust: none;   /* overrides above */
  text-size-adjust: none;
}
```
The second `-ms-text-size-adjust: none` overrides the `100%` reset, disabling text scaling entirely on IE/Windows Phone rather than normalizing it. Almost certainly a copy-paste error. `text-size-adjust: none` (unprefixed) similarly blocks OS-level text scaling for users who rely on it — accessibility risk.

**`supported-color-schemes` declared as a CSS property**
```css
:root {
  color-scheme: light dark;
  supported-color-schemes: light dark;  /* not a valid CSS property */
}
```
`supported-color-schemes` is only valid as a `<meta>` attribute. As a CSS property it is silently ignored by all email clients that parse `:root` dark mode rules, making this declaration dead code. The `<meta name="supported-color-schemes">` in `<head>` is correct and handles Apple Mail; the `:root` version does nothing.

**Font format coverage is incomplete**
- Futura PT: `.woff` only — no `.woff2`, no fallback `.ttf`
- HelveticaNow: `.ttf` only — no `.woff` or `.woff2`

`.woff2` is supported in all modern email clients and is 20–30% smaller. `.ttf` files are the largest format. Mixed strategies across the two typefaces suggest different template origins were merged.
