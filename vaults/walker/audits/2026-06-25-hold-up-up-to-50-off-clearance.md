### 3. Rendering & Accessibility

**`Src:` capital-S in all `@font-face` blocks — invalid CSS**

All 10 `@font-face` declarations use `Src:` instead of the lowercase `src:`. CSS property names are case-sensitive in some parsers. Gecko (Thunderbird) and strict WebKit implementations may silently skip these rules, causing font fallback to system fonts across the entire email.

```css
/* All 10 blocks — e.g.: */
Src: url("https://braze-images.com/...woff") format('woff');  /* ← invalid */
src: url("https://braze-images.com/...woff") format('woff');  /* ← correct */
```

**Missing `http-equiv` on two meta tags**

```html
<meta content="text/html; charset=utf-8" />           <!-- missing http-equiv="Content-Type" -->
<meta content="IE=Edge" />                             <!-- missing http-equiv="X-UA-Compatible" -->
```

Without `http-equiv`, both tags are no-ops in legacy Outlook and IE rendering engines, defeating their purpose.

**`text-size-adjust: none` overrides accessibility scaling**

The reset block sets vendor-prefixed properties to `100%` but then applies the unprefixed standard property as `none`:

```css
* {
  -ms-text-size-adjust: 100%;
  -webkit-text-size-adjust: 100%;
  text-size-adjust: none;   /* ← blocks user text-size preferences */
}
```

`none` disallows any browser text-size adjustment, breaking accessibility for users with custom font-size settings. Should be `100%`.

**`supported-color-schemes` as a CSS property in `:root`**

```css
:root {
  color-scheme: light dark;
  supported-color-schemes: light dark;  /* ← not a valid CSS property */
}
```

`supported-color-schemes` is a `<meta>` attribute, not a CSS property. The declaration is a no-op in all CSS engines. It's already correctly set as a `<meta>` tag in the `<head>` — the duplicate CSS declaration should be removed.

**Inconsistent font format and cache-busting strategy**

- Futura PT fonts: served as `.woff` with no cache-busting query param.
- HelveticaNow fonts: served as `.ttf` with `?1755182939` query param.

TTF is the least compressed web font format; WOFF2 would reduce payload. The inconsistency also suggests the HelveticaNow fonts were added in a separate deployment cycle — verify they are intentional replacements, not accidental duplicates of the Futura stack.
