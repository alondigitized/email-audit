### 3. Rendering & Accessibility

**[HIGH] Contradictory `text-size-adjust` in the `*` selector**
```css
*{-ms-text-size-adjust: 100%; ... -ms-text-size-adjust: none; text-size-adjust: none}
```
`-ms-text-size-adjust: 100%` is immediately overridden by `-ms-text-size-adjust: none` in the same rule — the first declaration is dead code. `-webkit-text-size-adjust` remains at `100%` while the standard property and IE vendor prefix both land at `none`. Inconsistent cross-client behavior; the `-ms-` duplicate should be removed.

**[HIGH] Invalid `Src:` property in all 10 `@font-face` declarations**
```css
Src: url("https://braze-images.com/appboy/...") format('woff');
```
CSS property names are technically case-insensitive per spec, but several webmail parsers (Gmail, Outlook.com) apply strict tokenization and will silently drop `@font-face` blocks containing `Src:`. All 10 declarations are affected. Should be lowercase `src:`.

**[MEDIUM] `<meta>` tags missing `http-equiv`**

Two meta tags omit the required attribute:
```html
<meta content="text/html; charset=utf-8" />
<meta content="IE=Edge" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```
Without `http-equiv="Content-Type"`, encoding declaration is advisory-only; some legacy clients (Lotus Notes, older Android mail) may fall back to ASCII.

**[MEDIUM] `maximum-scale=1` prevents user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocking zoom is an accessibility failure (WCAG 1.4.4, Level AA). Remove `maximum-scale=1`.

**[LOW] Font format gaps**

Futura_PT variants serve only `.woff`; no `.woff2` fallback. HelveticaNow variants serve `.ttf` with hardcoded cache-busting timestamps (`?1755182939`). Apple Mail and iOS Mail — the clients most likely to render web fonts — strongly prefer `.woff2`. Serving `.ttf` as the primary format increases transfer size by ~30% vs `.woff2`.

**[LOW] Dark mode `.dm-bg-white` maps to `#ffffff`**
```css
.dm-bg-white { background: #ffffff !important; }
```
This preserves a white background in dark mode rather than inverting it. Likely intentional to protect image rendering, but any text-on-white region using this class will have poor contrast for dark-mode users.
