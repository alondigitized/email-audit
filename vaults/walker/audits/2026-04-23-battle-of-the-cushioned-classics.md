### 3. Rendering & Accessibility

**`<meta>` charset missing `http-equiv`**
```html
<!-- Current (incorrect) -->
<meta content="text/html; charset=utf-8" />

<!-- Required for email -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv="Content-Type"`, older Outlook and Lotus Notes builds may misinterpret encoding.

**Duplicate `<meta name="viewport">` with conflicting values**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
`maximum-scale=1` (first tag) conflicts with `user-scalable=yes` (second tag). Last-declared wins in most parsers, but behavior is undefined across Apple Mail, Gmail, and Samsung Email.

**`-webkit-text-size-adjust: none` on the `*` selector**
```css
* { -webkit-text-size-adjust: none; }
```
This suppresses iOS font scaling for every element. The `body` rule correctly sets `100%` — the wildcard `none` overrides it and breaks accessibility for users with large-text system settings.

**Empty `<title>` tag**
`<title></title>` — some clients (Outlook desktop, Samsung Email) surface the title string in notifications or window chrome. Empty string degrades to generic fallback text.
