## Technical Audit

## Technical Audit — Shoe Carnival Skechers Sale (SCA_20260719_skechers_AM)

### 1. Technical Summary
Five of six tracked link failures share a common root cause: a Unicode zero-width space (U+200B) is embedded at position 70–72 of every `emltrk.com` redirect URL, corrupting the query string before it reaches the tracker. A separate tracker pixel domain (`0di86k1v.emltrk.com`) timed out entirely, suggesting a dead or misconfigured second tracking domain.

---

### 2. Link & Tracking Issues

**Critical — Zero-width space in tracking URLs**
Every `ieezzy5m.emltrk.com` redirect URL contains a U+200B character appended to the campaign token:
```
utm_campaign=SCA_20260719_skechers_AM​  ← invisible char after "AM"
```
This breaks URL parsing at the ASCII codec level. Affected link types: `rd` (redirect), `rl` (link), `p` (pixel open), `f` (forward), and the raw impression pixel. All click and open tracking for this campaign is effectively non-functional. Root cause is almost certainly a copy-paste from a Unicode-aware editor (Notion, Google Docs, etc.) that injected the ZWSP.

**Critical — Tracker pixel timeout**
```
https://0di86k1v.emltrk.com/v2/0di86k1v?rd&d=[UNIQUE]
```
This URL timed out. The `[UNIQUE]` token is also unexpanded — it appears to be an unfilled merge token from a second ESP or tracking layer, suggesting this pixel was added but its substitution was never wired up. Any dedupe or deliverability tracking relying on this domain is broken.

**Info — 24 tracking links skipped**
Redirect domains were not probed for final destination reachability. Destination landing page validation was not performed.

### 3. Rendering & Accessibility

**Missing alt text — 4 images**
All four images with missing `alt` attributes:
- `9521013e-7444-4804-9257-f83e6db7b8bc.jpg` — content image (likely product/hero)
- `a97db5d3-cfac-4b76-923a-ca38510bf3a6.jpg` — content image
- `ieezzy5m` tracking pixel — alt="" acceptable here but not present
- `0di86k1v` tracking pixel — same

Content images without `alt` text fail WCAG 1.1.1 and will render as broken image icons in image-blocking clients (Outlook desktop default, many corporate environments). Screen readers will announce the filename or skip silently.

**HTML 4.01 Transitional doctype**
```html
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" ...>
```
Combined with `xmlns` and `lang="en"`, this is a mixed-doctype pattern. Functional for major clients but technically inconsistent. Not a blocking issue.

**`color-scheme: light` only**
```html
<meta name="color-scheme" content="light" />
<meta name="supported-color-schemes" content="light" />
```
Dark mode is explicitly disabled. No dark mode overrides in CSS. Recipients in dark-mode clients (Apple Mail, Outlook for Mac) will see the forced-light render. This is a deliberate choice but worth flagging as a known trade-off.

**Legacy client hacks present**
`.ReadMsgBody`, `.ExternalClass`, Hotmail line-height fixes, and `[class="ii"]` Gmail overrides are all included. These target clients that are effectively extinct (Hotmail 2010-era, pre-2013 Gmail). No harm, just dead weight.
