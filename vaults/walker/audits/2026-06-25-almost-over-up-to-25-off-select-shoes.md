# Almost over: up to 25% off select shoes
**Score:** 6/10 · **Type:** Email audit · **2026-06-24**
## Executive summary

- I opened this one because "almost over" in the subject did its job — I hate missing a sale end. But the second I'm in the body, I'm looking at a tower of red shoeboxes like I'm browsing a clearance warehouse. There's nothing here that says "Walker, here's the walking shoe with cushioning you need." It's a blanket sale email. The price-bucket grid (Under $50, $50–$100, $100–$150, +$150) tells me nothing about which of those shoes actually fit a 62-year-old who's on his feet all day.
- The bigger problem — and this one genuinely bothers me — is the fine print. When I squint at the small text under the hero, the sale dates appear to run through June 24, 2026. Today is June 25. So "almost over" isn't almost over. It's done. If I'd clicked "Shop now" expecting to find 25% off and discovered the deal was gone, I would've felt like I got played. That's the kind of thing that makes you unsubscribe.
- On top of that, this is the same 25% off I've seen from New Balance on June 3rd, June 7th, and June 13th. Fool me once. I'm not clicking. I'm marking this read and moving on.

## What's working

- **"Almost over" is smart urgency** — it created a real pull to open, even for a repeat offer
- **Free shipping banner up top** — free shipping on $75+ is the first thing I see, and that matters to me; I don't like paying to ship shoes I haven't tried on
- **Fresh Foam 680v8 in the product grid** — buried near the bottom, but that's a walking/running shoe I might actually wear; glad it's in there
- **Clean, uncluttered layout** — the email renders perfectly, no broken images, the text is legible on my phone without zooming
- **Preview adds new info** — "Plus, up to 30% off clothing and accessories" extends the offer without repeating the subject, which is the right call

## What's weak

- **Possible expired sale** — the fine print under the hero appears to show a June 24 end date; sending "almost over" a day late turns urgency into a broken promise
- **Hero image is red shoeboxes, not shoes** — I can't see what I'm buying; a stack of boxes doesn't help me imagine fit or comfort
- **Not one mention of comfort, cushioning, or walking** — New Balance makes excellent walking shoes; none of that language appears anywhere in this email
- **Price buckets are useless for how I shop** — I don't filter by price, I filter by fit and feel; "Under $50" doesn't tell me if any of those are arch-supported slip-ons
- **Fourth time I'm seeing 25% off this month** — at this point it reads like the regular price, not a deal

## Recommendations

- 1. **Verify the sale is still live before it sends** — an "almost over" email that arrives after the sale ends is actively harmful to the brand; add a deployment window check or adjust the end date to accommodate send delay
- 2. **Swap the hero from shoeboxes to an actual shoe** — specifically a walking or Fresh Foam shoe that speaks to the comfort buyer; the boxes are an art director choice that doesn't sell anything
- 3. **Add one comfort headline** — something like "Cushioned walkers, up to 25% off" would have me in the CTA immediately
- 4. **Replace the price-bucket grid with a category row** — Walking / Running / Casual lanes would let me self-select faster than price brackets
- 5. **Rotate out of "25% off select shoes"** — I've seen it five times this month; even a "save $30 on the 680v8 today" would feel fresher

## Technical Audit — New Balance "Almost over: up to 25% off select shoes"

### 1. Technical Summary

The email is built on HTML 4.01 Transitional with functional dark mode declarations and a proxima-nova/linotype-didot web font stack. Two confirmed issues in the `<head>` require fixes before send: an unresolved template placeholder in a CSS background-image URL, and a malformed `<meta>` tag.

---

### 2. Link & Tracking Issues

**Unfilled template variable — background image URL (high severity)**
```css
.bgwhite { background-image: url('http://image.XXXXX.png'); }
```
The string `XXXXX` is an unresolved placeholder, meaning this background image will 404 for every recipient. Additionally, the URL scheme is `http://` rather than `https://`, which triggers mixed-content warnings in Gmail and Outlook web and may be silently blocked.

**Unable to fully audit click-tracking links** — the HTML body is truncated. Verify that all `<a href>` values carry consistent UTM parameters and point to `https://` destinations.

---

### 3. Rendering & Accessibility

**Missing `http-equiv` on IE compatibility meta tag**
```html
<meta content="IE=edge" />
```
Should be:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without `http-equiv`, the tag is ignored; Outlook 2007–2019 (Word renderer) will not trigger edge-mode rendering.

**Empty `@font-face` rules — no `src` declarations**
All nine `@font-face` blocks declare `font-family`, `font-weight`, and `font-style` but omit `src`. This is invalid CSS. Email clients will silently skip these rules and fall back to the system font stack (Arial/Times New Roman), which is the intended fallback — but it means proxima-nova and linotype-didot will only render if loaded via a separate external stylesheet (e.g., Adobe Fonts CDN `<link>`), which is not visible in the truncated source. Confirm that stylesheet link is present in the full `<head>`.

**Duplicate `font-family` property in proxima-nova italic `@font-face`**
```css
@font-face {
  font-family: proxima-nova,sans-serif;
  font-weight: 700;
  font-style: italic;
  font-family: proxima-nova,sans-serif; /* duplicate */
}
```
Not rendering-breaking, but indicates a copy-paste error in the template.

**Dark mode support: present and structurally correct**
`<meta name="color-scheme" content="light dark">` and `@media (prefers-color-scheme: dark)` are both declared. Spot-check that the dark-mode overrides (truncated at `background:#151415`) cover all background and text color classes — particularly `.bgwhite`, `.fc3`, and `.fc6`.

**Alt text and image accessibility** — cannot audit from truncated source. Confirm all `<img>` tags carry non-empty `alt` attributes.
