### 3. Rendering & Accessibility

**Issue 1 — Duplicate conflicting `viewport` meta tags**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```

Two `<meta name="viewport">` declarations with conflicting `user-scalable` values. The first implicitly disables user scaling; the second explicitly enables it. Browsers take the last declaration; some email clients (Samsung Mail, older Android webviews) may behave unpredictably. One declaration should be removed.

**Issue 2 — Web fonts loaded via `@import` + `@font-face` (Typekit)**

```css
@import url("https://p.typekit.net/p.css?s=1&k=hva0tmw...");
```

`@import` inside `<style>` is blocked by Gmail (strips `<style>` blocks entirely in some contexts), Outlook (all versions), and most Android clients. No confirmed fallback font stack is visible in the truncated CSS. If the fallback degrades to serif or Times New Roman, layout metrics for the font-sized table cells will shift. Verify a safe fallback stack (`Arial, sans-serif` or similar) is declared on all `font-family` rules.

**Issue 3 — Near-black / near-white color values**

```css
a { color: #000001; }
.footer_text a { color: #fffffe; }
```

`#000001` and `#fffffe` are 1-step off from pure black/white — a documented technique to evade content filters that scan for `#000000`/`#ffffff`. These values will fail WCAG contrast checks under certain high-contrast or forced-color rendering modes (Windows High Contrast, some accessibility overlays). Use `#000000` / `#ffffff` directly; spam filter evasion via color encoding is a deliverability risk if detected by modern filters (SpamAssassin, Proofpoint).

**Issue 4 — Stale template metadata timestamp**

```css
/*{"last_published":"2022-03-23 22:26:23 UTC"}*/
```

This Typekit CSS comment indicates the font kit was last published in March 2022. Typekit kits can expire or have font license changes. Verify the kit `hva0tmw` is still active in Adobe Fonts and that font licensing covers email use (Typekit web licenses typically do **not** cover embedding in email; see ToU at `http://www.adobe.com/products/eulas/tou_typekit`).
