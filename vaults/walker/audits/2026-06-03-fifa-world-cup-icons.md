## What's weak

- Zero connection to footwear comfort, arch support, or anything I actually buy from adidas — this email could have been sent to a 22-year-old soccer obsessive and made perfect sense; it makes no sense for me

## Technical Audit

## Technical Audit — adidas "FIFA World Cup™ Icons"

---

### 1. Technical Summary

Two hard failures: a broken click-redirect URL and a completely absent plain-text MIME part. Additionally, a repeated HTTP image asset will be blocked by most modern email clients with image-load security enabled.

---

### 2. Link & Tracking Issues

**[FAIL] Broken click-redirect — `/g/` path fragment unresolvable**
The QA checker reports `unknown url type: '/g/3e9b4806-236c-4ed2-8488-2cf3a6ffef40'`. The underlying destination resolves to `dv.adidas.com/o/3e9b4806-...` (a dynamic content/personalization beacon), but the `/g/` variant used as the click-href does not follow the same redirect pattern and cannot be resolved. Any CTA that wraps this URL will silently fail for recipients whose client follows the raw href before the redirect chain resolves.

**[WARN] 36 tracking links skipped**
All click-redirect links route through `dv.adidas.com` or `click.comms.adidas.com`. QA did not probe these (expected behavior for redirect domains), so destination URL health is unverified. Manual spot-check of sampled CTAs is recommended post-send.

**[WARN] Referrer suppressed**
`<meta name="referrer" content="no-referrer" />` is set in `<head>`. Any click-through that does not carry UTM parameters will arrive at adidas.com with no referrer signal, defeating session attribution for non-tracked links.

---

### 3. Rendering & Accessibility

**[FAIL] HTTP image asset — will be blocked**
The arrow icon (`b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg`) is referenced **8 times** via plaintext HTTP:
```
src: http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-...jpg
```
Gmail (HTTPS-proxied images), Apple Mail (strict HTTPS), and Outlook.com will either block or proxy-substitute this image. Since it appears to be a repeated UI element (navigation arrow), its absence will degrade layout fidelity at scale.

**[WARN] Missing alt text on 3 images**
- `ec93a4e0-ec25-4fb9-9aaf-abcc6b5afec5.png` — no `alt` attribute
- `3e9b4806-236c-4ed2-8488-2cf3a6ffef40` (dynamic beacon/image) — no `alt`
- `R5Ps-GpPIZWL4-_cDh_8H1OEe...` (tracking pixel via `http://click.comms.adidas.com`) — no `alt`

The first two affect screen readers and images-off rendering. The third is a tracking pixel; `alt=""` (empty string, not absent) is the correct fix there.

**[INFO] Duplicate `@font-face` declarations**
`AdihausDIN` and `AdineuePRO` are each declared twice across two separate `<style>` blocks with identical `src: local(...)` fallback chains. No web font URLs are loaded — the custom faces resolve entirely to system fallbacks (Arial/Helvetica). This is functional but wasteful; it adds ~1 KB of redundant CSS and increases parse time.

**[INFO] `<meta charset>` missing `http-equiv`**
```html
<meta content="text/html; charset=UTF-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
```
Without `http-equiv`, older Outlook and some legacy webmail clients may not honor the declared charset.

### 5. Compliance

**[FAIL] Plain-text MIME part absent**
QA reports the text/plain alternative is 0 characters. CAN-SPAM does not mandate a plain-text part, but its absence is a deliverability signal used by spam filters (SpamAssassin, Proofpoint, Microsoft Defender). Best practice and most ESPs require a non-empty `text/plain` part. This should be treated as a send-blocking defect.

**[INFO] ROBOTS meta present**
`<meta name="ROBOTS" content="NOINDEX, NOFOLLOW" />` is correctly set, preventing search engine caching of the email HTML if it is mirrored on the web.

**[INFO] Unsubscribe and physical address**
Not visible in the truncated source. Assumed present in footer — confirm `List-Unsubscribe` header is set at the envelope level by the ESP (not just in-body link).

---

### 6. Email-to-Site Continuity

36 click-redirect links are wrapped through `dv.adidas.com` / `click.comms.adidas.com`. UTM parameter decoration cannot be confirmed from the HTML alone since parameters are embedded in the opaque redirect payloads. The suppressed referrer (`no-referrer` meta) means any link that loses its UTM chain mid-redirect will produce dark traffic in GA4/Adobe Analytics. The broken `/g/` URL (see §2) represents a confirmed gap in the redirect chain for at least one CTA.
