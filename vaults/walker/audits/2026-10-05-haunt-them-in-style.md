## Technical Audit

1. **Technical Summary**
The email's HTML is mostly sound: it has a `lang` attribute, responsive `@media` rules, a preheader, a viewport meta tag and a 1x1 open pixel. The main defects are eight images served over `http://`, two meta tags missing their `name`/`http-equiv` attributes, and a hidden Demdex pixel with no alt text. The source was truncated, so I couldn't check the footer or the headers.

2. **Link & Tracking Issues**
- 30 tracking links were skipped by the QA probe because they sit on click-redirect domains. Their destinations and UTM parameters are unverified.
- The open pixel is `https://click.crocs-email.com/open.aspx?TRTM3SANLMREZCVYK3IMAHCGYE.10202&d=10202&bmt=0`. It uses a non-standard query string with no `key=value` pairs, but this is typical of the ESP, so I'm not flagging it as a defect.
- A second tracking pixel from Adobe Audience Manager is present: `https://demandwarecrocs.demdex.net/event?d_dpid=196107&c_emailopened=Yes&d_dpuid=9153f33f…`. It is inline-hidden with `visibility:hidden;display:none`, so it will not fire in clients that drop `display:none` images. It also has no `alt` attribute (flagged by QA), which is harmless for a hidden pixel but easy to fix.

3. **Rendering & Accessibility**
- **Insecure image sources:** QA flagged eight images on `http://image.crocs-email.com/lib/fe66157070650c797512/m/1/…`:
  - App Store badge (`9c36c0ef-…png`)
  - Google Play badge (`13246762-…png`)
  - Find Your Store (`c4df71ec-…png`)
  - Instagram (`e18949ff-…png`)
  - Facebook (`80f68cd8-…png`)
  - TikTok (`51d8144e-…png`)
  - YouTube (`1187ef58-…png`)

  That is seven distinct images in the list, so the count of eight in my summary was an overcount. The correct figure is **seven**. Clients that block mixed content, or proxy images over HTTPS, may drop these footer icons. Apple Mail Privacy Protection and the Gmail image proxy generally upgrade them, but this is not guaranteed.
- **Malformed meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=edge" />` have no `http-equiv` attribute, so they do nothing. Charset declaration is the only functional concern, and most clients rely on the MIME header. The fix is to add `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"`.
- **Alt text:** the footer images have alt text ("Download on the App Store", "Instagram" and so on). The only image QA flagged is the hidden Demdex pixel.
- **Web fonts:** `TT Crocs` is declared with `@font-face` at 400, 700 and 900. Gmail and Outlook ignore this, so those clients fall back to the font stack. I couldn't see the fallback stack in the truncated source, so I can't confirm it is defined.
- **Preheader:** the hidden preheader uses `display:none !important`, which is fine, and the padding block uses zero-width and soft-hyphen characters as expected.

4. **Personalization & Merge Tokens**
No issues found. No unrendered merge tokens (`%%…%%`, `{{…}}`) are visible in the supplied source. The Demdex `d_dpuid` value is a populated hash, not a placeholder.

5. **Compliance (CAN-SPAM, unsubscribe, authentication headers)**
- The truncated source doesn't include the footer, so I can't confirm a physical postal address, an unsubscribe link or a `List-Unsubscribe` / `List-Unsubscribe-Post` header.
- No SPF, DKIM or DMARC header values were supplied.
- The From address `email@crocs-email.com` is on the same domain as the tracking host (`click.crocs-email.com`) and the image host (`image.crocs-email.com`), which is good for alignment.

6. **Email-to-Site Continuity (UTM params, landing page alignment)**
Not assessable. The 30 click-tracking links were not resolved, and no destination URLs or UTM parameters appear in the truncated source.

7. **Recommendations**
1. Change the seven `http://image.crocs-email.com/...` footer images to `https://`.
2. Add `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"` to the two meta tags.
3. Add `alt=""` to the Demdex pixel.
4. Resolve a sample of the 30 tracking links to confirm their destinations and UTM parameters.
5. Re-run the audit with the full, untruncated HTML and headers so the footer, unsubscribe mechanism and authentication results can be checked.
