### 3. Rendering & Accessibility

**`Src:` (capital S) in every `@font-face` block — 10 instances**
CSS property names are case-sensitive per spec. `Src:` is technically invalid; it parses in most browsers due to forgiving tokenization, but behavior in email client CSS parsers (particularly WebKit-based mail views) is undefined. Should be lowercase `src:`.

```css
/* current — invalid */
Src: url("https://braze-images.com/...") format('woff');
/* correct */
src: url("https://braze-images.com/...") format('woff');
```

**`supported-color-schemes` used as a CSS property — invalid**
In the `:root` block:
```css
:root {
  color-scheme: light dark;
  supported-color-schemes: light dark;  /* ← not a valid CSS property */
}
```
`supported-color-schemes` is only valid as an HTML `<meta name="supported-color-schemes">` attribute (already correctly present in `<head>`). The CSS rule is a no-op and should be removed to keep the stylesheet clean.

**`-ms-text-size-adjust: none` in `*` selector overrides earlier `100%` declaration**
The reset block sets `-ms-text-size-adjust: 100%` inline, then the `*` universal selector sets `-ms-text-size-adjust: none`. The `none` value fully disables text resizing in Windows Mail / Outlook.com on mobile, which can break accessibility for users with large text settings. Should be `100%` consistently.

**10 web font files loaded with no woff2 variant**
- 4× Futura PT (`.woff` only)
- 6× HelveticaNow (`.ttf` only)

Gmail, Outlook (desktop), and most Android clients do not render web fonts at all — system fallbacks apply. Apple Mail and some iOS Mail builds do support them, but both Futura PT and HelveticaNow lack `woff2` declarations. woff2 offers ~30% better compression and is the format modern web-font-capable email clients prefer. Serving `.ttf` cold to a mobile Apple Mail client is the slowest possible delivery format.

**No `role` or `aria-label` on decorative images visible in excerpt** — cannot confirm alt text coverage without full HTML.
