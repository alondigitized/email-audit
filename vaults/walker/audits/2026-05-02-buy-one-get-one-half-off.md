### 3. Rendering & Accessibility

**`Src:` capitalization in all `@font-face` blocks (invalid CSS)**
All ten `@font-face` rules use `Src:` (capital S), which is invalid per the CSS spec. Strict parsers (Apple Mail, some Outlook versions) will silently drop the declaration, causing font-load failures and fallback to system fonts.
```css
/* present in source — all 10 @font-face blocks */
Src: url("https://braze-images.com/...") format('woff');
/* correct */
src: url("https://braze-images.com/...") format('woff');
```

**Contradictory `text-size-adjust` values on `*`**
The reset stylesheet sets `-ms-text-size-adjust: 100%` and then immediately overrides it with `-ms-text-size-adjust: none` on the same `*` selector. `none` disables user text-scaling (accessibility concern) and the two declarations conflict. Only `100%` should be present.
```css
*{-ms-text-size-adjust: 100%; ... -ms-text-size-adjust: none; text-size-adjust: none}
```

**Malformed `<meta>` tags (missing `http-equiv`)**
Two meta tags are missing required `http-equiv` attributes and will be ignored by parsers:
```html
<!-- source -->
<meta content="text/html; charset=utf-8" />
<meta content="IE=Edge" />
<!-- correct -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```

**`supported-color-schemes` used as CSS property**
```css
:root { supported-color-schemes: light dark; }
```
`supported-color-schemes` is only valid as an HTML `<meta>` attribute, not a CSS property. It should be removed from the `:root` block; the `<meta name="supported-color-schemes">` in `<head>` is sufficient.

**No `.woff2` format declared for any web font**
Futura PT fonts declare only `format('woff')`; HelveticaNow declares only `format('truetype')`. Omitting `.woff2` means larger payloads and slower rendering in modern clients that prefer woff2.

**Near-black color hack (`#000001`, `#00000F`) — informational**
`border-top-black`, `dm-font-black`, and `dm-bg-black` use off-black hex values rather than true `#000000`. This is an intentional dark-mode inversion workaround and is functionally correct; no action needed unless future tooling flags it as a color mismatch.

**Font migration mid-campaign (informational)**
Futura PT (woff, no cache buster) and HelveticaNow (ttf, timestamp `?1755182939`) are both declared. If this is a mid-send font swap, templates that cached the old stylesheet may render with Futura PT while new renders use HelveticaNow. Confirm whether both font families are actively used in the body or if Futura PT declarations are dead weight.
