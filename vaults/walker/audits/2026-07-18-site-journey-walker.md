## 1. Executive Summary

Skechers knows how to say the right words — "Hands Free Slip-ins," "Comfort Technologies," "Arch Fit" — but the actual shopping experience undercuts all of it. The homepage sells energy drinks to 24-year-olds. The cart page loaded as a completely blank white screen. And when I searched "comfort shoes," the first results they handed me were Women's. I'm logged in. They know I'm a man. None of that information seems to matter. The bones of a decent experience are here — the men's menu is clean, the product page is readable, the Slip-ins category is well-organized — but three serious failures drag the whole visit down. Skechers left money on the table today the same way they did yesterday.

## Technical Audit

## Technical Summary

The skechers.com mobile journey runs on Salesforce Commerce Cloud (SFCC/Demandware), visible from `/on/demandware.static/Sites-USSkechers-Site/` paths. The audit captured 8 steps with full TTFB data but no LCP or CLS readings — likely because Kasada bot detection (the `fp` fingerprinting endpoint) blocked the automated testing agent mid-session, causing the cart page to return HTTP 429 and serve a challenge page instead of real content. That single fact invalidates all View Cart accessibility findings and skews the console/network error counts.

---

## Accessibility

**18 violations across 3 pages. Several are likely test-environment artifacts; the structural ones are real.**

**Homepage (10 violations):**
- `aria-required-parent` [critical] — ARIA roles used outside their required parent context. Likely a slider/carousel component with misstructured role hierarchy.
- `button-name` [critical] — One or more `<button>` elements have no accessible label (no text, no `aria-label`, no `aria-labelledby`). Common in icon-only buttons (close, hamburger menu).
- `link-name` [serious] — Same pattern: `<a>` elements with only image or icon children, no alt text or aria-label.
- `landmark-no-duplicate-main` / `landmark-main-is-top-level` [moderate] — Two `<main>` elements detected; one is nested inside another landmark. Points to a page-within-page overlay pattern or a partial-render injection from Monetate/personalization.
- `landmark-complementary-is-top-level` / `landmark-unique` [moderate] — `<aside>` elements nested inside `<main>` or other landmarks, and non-unique landmark roles. Cookie consent or sidebar widgets likely injecting markup outside the standard document structure.
- `heading-order` [moderate] — Heading level hierarchy is non-sequential (e.g., `<h1>` → `<h3>`, skipping `<h2>`).
- `region` [moderate] — Content exists outside any landmark region.
- `aria-allowed-role` [minor] — An element has a `role` attribute that's invalid for its tag type.

**View Cart (5 violations — artifact of 429 challenge page):**
- `document-title` [serious] and `html-has-lang` [serious] are absent. The real cart page almost certainly has these; the challenge/error page served by Kasada does not. These findings should be re-run against an authenticated, non-rate-limited session before filing as real bugs.
- `landmark-one-main` and `page-has-heading-one` — same root cause: challenge page has minimal HTML structure.

**Search page (4 violations):**
- `landmark-complementary-is-top-level`, `landmark-unique`, `region` — same structural pattern as homepage, suggesting a shared layout defect.
- `aria-allowed-role` [minor] — same as homepage.

**Confirmed real issues requiring fixes:** `button-name`, `link-name`, `aria-required-parent`, `heading-order`, duplicate `<main>` landmark, `landmark-complementary-is-top-level`.

---

## SEO

- **`document-title` and `html-has-lang` on cart:** If bot detection ever serves 429s to Googlebot (unlikely but not impossible with aggressive rate limits), the cart URL would be indexed without a title. Low risk in practice.
- **Heading hierarchy skip (`h1`→`h3`):** Directly impacts crawl quality for product/category pages.
- **Third-party scripts in `<head>` without `defer`:** Scripts like `us-skechers-prod.js` and several analytics tags load `async` which is correct, but Monetate loads two separate bundles (`/js/2/` and `/js/3/`) — one of which may be render-blocking if the async attribute is stripped at runtime.
- **No canonicalization or structured data visible** in the truncated HTML samples, but source is truncated — cannot confirm absence.

## Mobile Optimization

- **Viewport height JS hack:** `--vh: 6.640000000000001px` set as an inline style on `<html>`. This is a well-known workaround for the Safari mobile viewport height bug (where `100vh` includes the browser chrome). The floating-point value suggests it's calculated as `window.innerHeight / 100`. This pattern causes layout recalculation on scroll in mobile Safari and can contribute to CLS — though CLS was not captured to confirm.
- **No evidence of `viewport` meta tag** in truncated source samples, though it's almost certainly present further down `<head>`.
- **Script volume on mobile:** 25+ third-party scripts on a mobile connection degrades TTI (Time to Interactive) significantly beyond TTFB. Mobile CPUs parse and execute these serially even when fetched in parallel.
- **Salesforce Commerce Cloud architecture** is server-rendered, which is generally mobile-friendly for initial load, but the personalization layer (Monetate) adds client-side DOM manipulation after load.

## Console & Network Errors

**Root cause: Kasada bot detection is rate-limiting the audit session.**

The GUID path `/149e9513-01fa-4fb0-aad4-566afd725d1b/2d206a39-8ed7-437e-a3be-862e0f06eea3/fp` is the Kasada fingerprinting endpoint (`x-kpsdk-v=j-1.2.522`). It was 429'd **5 times**. When bot detection fails to fingerprint the client, it blocks subsequent requests — which is why `/cart/` also returned 429.

**Stylitics CORS failure:**
```
Access to CSS stylesheet at 'https://web-assets.stylitics.com/style.css?...' 
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header
```
Stylitics is a third-party "shop the look" / outfit widget vendor. Their CDN is not returning CORS headers for stylesheet requests, which breaks the widget for cross-origin contexts. This is a Stylitics-side configuration issue that Skechers should escalate to their account team. The widget will fail silently or render without styles on affected page loads.

**Error inventory:**
| Error | Count | Root Cause |
|---|---|---|
| 429 on Kasada `fp` endpoint | 5 | Bot detection rate-limiting the test agent |
| 429 on `/cart/` | 1 | Cascading block from Kasada failure |
| Stylitics CORS block | 1 | Missing `Access-Control-Allow-Origin` on Stylitics CDN |
| `net::ERR_FAILED` | 1 | Likely Kasada challenge blocking a subsequent request |

**All 6 network errors are attributable to bot detection triggering during automated testing.** They would not appear in a normal user session. The Stylitics CORS error may appear in real user sessions.

## Recommendations

**High priority:**
1. **Fix `button-name` and `link-name` violations** — add `aria-label` to all icon-only buttons (hamburger, close, search) and image-only links. These are WCAG 2.1 AA failures.
2. **Remove duplicate Monetate and Yahoo YTC script loads** — the duplicate Monetate v2/v3 loaders and duplicate Yahoo YTC tags are firing twice, doubling their tracking requests and parse cost. Audit GTM tag configuration.
3. **Escalate Stylitics CORS issue** — the missing `Access-Control-Allow-Origin` header breaks the outfit widget. Stylitics needs to configure their CDN to allow `https://www.skechers.com` as an origin for the stylesheet.
4. **Capture LCP and CLS** — re-run the audit in an authenticated, non-rate-limited browser session to get real Core Web Vitals. TTFB alone is insufficient for CWV assessment.

**Medium priority:**
5. **Investigate TTFB spike on Log In and Men category (412ms)** — profile the SFCC server-side rendering path for these pages; likely a session-resolution or personalization timeout.
6. **Fix duplicate `<main>` landmark on homepage** — indicates a layout injection (personalization overlay?) is adding a second `<main>` element. Use `<div>` or `<section>` for injected content containers.
7. **Fix heading hierarchy** — ensure `<h1>` → `<h2>` → `<h3>` sequence is maintained on category and product pages.
8. **Replace WebFontLoader with `<link rel="preload">`** — load Mulish directly with `font-display: swap` and preload the most-used weight to eliminate FOUT without the JS dependency.

**Low priority:**
9. **Replace `--vh` JS hack with CSS `dvh` units** — `height: 100dvh` is now supported in all modern mobile browsers and eliminates the JS-calculated custom property and its associated layout recalculation on scroll.
10. **Audit third-party script necessity** — 25+ third-party scripts is unusually high. Conduct a tag audit in GTM; consolidate redundant analytics where possible.
