# 25% off for America’s birthday 
**Score:** 8/10 · **Type:** Email audit · **2026-07-04**
## Executive summary

- Another DSW in my inbox — I've genuinely lost count this week, but I think we're at eight or nine now. I saw the subject, recognized the pattern, and opened mostly out of habit. The patriotic hook is fine — it's the Fourth, I get it. "25% OFF" is front and center and that's the right call; I don't have to hunt for the offer. But the moment I'm past the hero I'm in a women's shoe catalog with a small "For him" lane buried about a third of the way down. That SHOEMERGENCY bit made me feel like I walked into a TikTok. I'm 62, not 22.
- The clearance call-out — 40% off — actually grabbed me more than the hero. That's real money. I'd probably scroll to it and wonder whether any wide-width walking shoes are in the mix. Trouble is, nothing in this email tells me whether comfort styles or slip-ons are part of the deal. I'm not buying heels. No social proof, no fit callout, no cushioning mention — just a sea of colorful shoes aimed at everyone, which means aimed at nobody.
- I'd mark it read and maybe check the DSW app later if I'm already shopping. I would not forward this to a friend, and I would not click from the email itself.

## What's working

- **25% OFF is unmissable.** Big, bold, top of the page — I didn't have to squint to find the deal.
- **Promo code is visible.** SPANGLED25 is right there; I don't have to dig through fine print to find it.
- **Fourth of July hook is timely.** "Star-Spangled Savings" is a bit corny but it's seasonally honest — this isn't a random promo disguised as a holiday.
- **Clearance callout is genuinely compelling.** 40% off clearance is a better number than 25%, and it caught my eye on the scroll.
- **Layout is clean.** No broken images, no overlapping text, nothing weird. Just renders and I can read it.

## What's weak

- **Women dominate the visual story.** "For her" gets the big real estate; "For him" is a smaller row below the fold. As a man, I feel like an afterthought.
- **Zero comfort language.** Not one word about cushioning, arch support, slip-on, wide width — the things that actually drive my shoe decisions. It might as well be a fashion email.
- **SHOEMERGENCY is not my language.** Feels like a joke written for a 25-year-old. At my age, a shoe emergency is when the doctor says my plantar fasciitis is back.
- **Preview text leaked junk.** In my inbox, after "Happy birthday, America" there was a long trail of invisible spacer characters taking up the preview line. Looks sloppy.
- **DSW fatigue is real.** This is the continuation of the same 25% off deal I've seen pushed three or four times already this week. The well is running dry.

## Recommendations

- 1. **Put men's comfort shoes in the hero.** Even a half-and-half split — or a second hero block that speaks directly to walking shoes, cushioning, wide-width — would tell me this email has something for me.
- 2. **Add one line of fit copy near the CTA.** "Arch support styles included" or "Slip-ons, wide widths — all 25% off" is all it takes to get my thumb moving.
- 3. **Drop SHOEMERGENCY.** Replace with something more direct, like a second sale rail that just says "40% Off Clearance — Walking, Comfort, Casual."
- 4. **Fix the preview text.** "Happy birthday, America" is fine; cut the spacer padding that bleeds into the inbox preview.
- 5. **Set a visible deadline.** "Today only" or "Ends midnight July 4th" would push me off the fence. Right now I assume I have days.

### 1. Technical Summary

Braze-rendered promotional email with dark mode support and custom web fonts. Several CSS authoring errors and invalid meta tag attributes are present; the HTML is truncated so link and compliance sections are partially assessable.

---

### 2. Link & Tracking Issues

**Partially assessable — HTML truncated before body links appear.**

- Font assets load from `braze-images.com` CDN. No functional issue, but any CDN failure silently degrades rendering.
- HelveticaNow `.ttf` URLs include a cache-buster query string (`?1755182939`). This is benign but inconsistent — Futura PT `.woff` files have no such param. Not an issue unless the query string gets stripped by a proxy, preventing cache hits.

---

### 3. Rendering & Accessibility

**`http-equiv` missing on two `<meta>` tags:**
```html
<meta content="text/html; charset=utf-8" />           <!-- missing http-equiv="Content-Type" -->
<meta content="IE=Edge" />                             <!-- missing http-equiv="X-UA-Compatible" -->
```
Both tags are effectively inert as written. Charset declaration failure can cause encoding fallback in older Outlook.

**Invalid CSS property casing — `Src:` in all `@font-face` blocks:**
```css
Src: url("https://braze-images.com/.../original.woff") format('woff');
```
CSS property names are case-insensitive per spec, but certain email clients (Outlook on Windows, some older Android clients) run a stricter CSS parser. All 10 `@font-face` declarations are affected. Correct to lowercase `src:`.

**`text-size-adjust: none` applied globally:**
```css
* { -ms-text-size-adjust: 100%; -webkit-text-size-adjust: 100%; text-size-adjust: none }
```
The unprefixed `text-size-adjust: none` (as opposed to `100%`) can suppress text scaling in accessibility contexts. The prefixed variants correctly use `100%`. Align the unprefixed value to `100%`.

**Conflicting `Margin` (non-standard capitalized) alongside `margin: 0 !important`:**
```css
h1, h2, h3, h4, h5, h6, p, ul, li {
  margin: 0 !important;
  Margin: 0          /* ← invalid property name */
}
```
`Margin` (capital M) is not a valid CSS property. It is a no-op in compliant parsers and dead weight.

**TTF font format for HelveticaNow:**
All six HelveticaNow variants load as `.ttf`. TTF has significantly worse support in webmail clients than `.woff`/`.woff2`. If HelveticaNow is a required brand font, add a `.woff` source as the primary format with `.ttf` as fallback.

**`cursor: default !important` on `.linkfix a`:**
```css
a[x-apple-data-detectors], .linkfix a, .linkfix span {
  cursor: default !important;
}
```
If `.linkfix` wraps actual clickable links (not just suppressed auto-detected data), this hides interactivity from the user. Verify `.linkfix` is only applied to non-link spans.
