# Happening NOW! 20% Off w/ code FALL20
**Score:** 6/10 · **Type:** Email audit · **2026-10-13**
## Executive summary

- Okay, a big "20% OFF" in black on yellow. I can read that without my glasses, and I'll give them credit for it. The code FALL20 is plain, and the offer is the first thing I see. That's much better than Sunday's "Hey friend, start your week with THESE" send, where I had to dig for the deal.
- Then I scrolled to the products and my interest dropped. The best sellers are Converse high-tops, white Icebound clogs, a mushroom-colored bootie, a kid's cozy clog, and a women's running shoe. The only men's item is one Nike court sneaker. I'm a 62-year-old man who wants cushioned slip-ons, and nothing here says cushion or arch support. The "Fall Shop" banner is tall boots, flats and booties, which is another women's boots pitch like the 10/07 "Fall Boot Refresh." It's also the eighth or so Shoe Carnival email this week, and I'm tired of the orange coupon block.
- Would I click? Maybe, if I were already thinking about Nikes. I wouldn't forward it. The 20% is decent, but the fine print lists exclusions for Brooks, New Balance, Skechers-type comfort brands and Crocs. Those are the brands I actually cross-shop, so the headline overpromises for me. I'd skim it and mark it read.

## What's working

- The giant "20% OFF" with "CODE: FALL20" is easy to read on my phone and needs no zoom.
- "Limited Time, Online Only" tells me why to act now.
- Each shoe has a plain label with the gender and name, so I can tell what it is.
- The wallet barcodes ($10 off $74.98, $25 off $149.98) give me a second way to save in the store.
- The bottom nav has a Mens tab, so I can find my section quickly.

## What's weak

- Almost every product is for women, kids or teens. I counted one men's shoe and nothing in cushioned slip-ons or walking.
- The fall banner shows only tall boots, flats, clogs and booties. None of it is for me.
- The asterisk and the long exclusion list take out Brooks, New Balance, Crocs and other brands I'd shop. The headline then feels like bait.
- It's another near-identical promo this week with the same coupon block, so I'm numb to it.
- There's no comfort, cushioning or arch-support language anywhere, and no reviews.
- The tiny fine print can't be read on a phone without zooming.

## Recommendations

- 1. Segment by gender. For men 55+, lead with a row of men's comfort walkers and slip-ons, and say "cushioned" and "slip-on."
- 2. Put the exclusions up near the headline so the deal feels honest, or limit the code to brands people can really use it on.
- 3. Use one clear button, like "Shop Men's Comfort Shoes," instead of the plain "Shop Now" link.
- 4. Cut the cadence. One strong send beats eight similar ones.
- 5. Make the fine print larger, or link to it.

- **Preheader Alt A:** `Cushioned sneakers and easy slip-ons for fall. Online only.`

## Technical Audit

## 1. Technical Summary
The email is structurally sound: it has a viewport meta, `lang="en"`, and a layered responsive CSS setup. QA reports a 100% pass rate. Two tracking-pixel images lack `alt` attributes, and one pixel URL contains an unresolved `[UNIQUE]` placeholder. The HTML source was truncated, so footer, link, and header checks are limited.

## 2. Link & Tracking Issues
- **Unverified links:** 36 tracking links on `emltrk.com` were skipped by the HTTP probe, so redirect chains and landing-page status codes are unconfirmed.
- **Malformed pixel query:** `https://ieezzy5m.emltrk.com/v2/ieezzy5m?i=72180589&t=utm_campaign=SCA_20261012_20_off_sitewide`
  - The value of `t=` contains a second `=` (`t=utm_campaign=…`), so the UTM string is nested inside a single parameter. A strict parser may read it as `t="utm_campaign=SCA_…"` rather than as a campaign parameter.
  - The QA output shows a trailing zero-width character (U+200B) after `sitewide`. It can corrupt the campaign value in analytics.
- **Placeholder in a URL:** `https://0di86k1v.emltrk.com/v2/0di86k1v?d=[UNIQUE]`. The literal `[UNIQUE]` is a placeholder that was not replaced in the captured copy. If it also shipped unresolved, every recipient's pixel hits an identical, non-unique URL. Open tracking would then be unreliable and could be cached or de-duplicated.

## 3. Rendering & Accessibility
- **Missing alt text:** the two pixel images above (`ieezzy5m`, `0di86k1v`) have no `alt`. Tracking pixels should carry `alt=""` so screen readers skip them. This is low severity.
- **Link affordance removed:** `a, a:link, a:visited … { text-decoration:none !important; color:inherit !important; }` strips default link styling globally. Inline text links then depend on other cues to be identifiable as links, which is an accessibility risk (WCAG 1.4.1).
- **Small mobile text:** `.responsive-text { font-size: 12px !important; }` at `max-width: 600px` is small for body copy on mobile.
- **Malformed meta tags:**
  - `<meta content="text/html;" charset="utf-8" />` has no `http-equiv`.
  - `<meta content="IE=edge" />` has no `http-equiv="X-UA-Compatible"`, so it does nothing.
  - The charset attribute is still declared, so this is cosmetic.
- **Doctype mismatch:** the HTML 4.01 Transitional doctype is paired with an `xmlns` attribute on `<html>`. This is harmless in practice.
- **Breakpoints:** three different breakpoints (600/601, 660, 450) are in use. This is not a bug, but it increases the risk of inconsistent layouts between 600 and 660px.

## 4. Personalization & Merge Tokens
- One unresolved token is confirmed in the QA data: `d=[UNIQUE]` in `https://0di86k1v.emltrk.com/v2/0di86k1v?d=[UNIQUE]`. See Section 2.
- No other tokens (`%%…%%`, `{{…}}`) are visible in the truncated source.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
No issues found in the data provided. The truncated HTML does not include the footer, so the unsubscribe link and physical address could not be verified. Raw headers (SPF/DKIM/DMARC, `List-Unsubscribe`, `List-Unsubscribe-Post`) were not supplied. This category is unverified, not cleared.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- The only UTM visible is `utm_campaign=SCA_20261012_20_off_sitewide`, and it appears only in a pixel URL, in the nested form described above.
- `utm_source` and `utm_medium` are not visible in the provided data.
- Because 36 links were not probed, I could not check that the "FALL20" offer lands on a page that applies the code. Nothing was confirmed either way.

## 7. Recommendations
1. Confirm `[UNIQUE]` is substituted at send time. If it is not, fix the ESP merge syntax for the pixel URL.
2. Clean the pixel URL by splitting `t=utm_campaign=…` into proper parameters and removing the U+200B character from the campaign value.
3. Add `alt=""` to both tracking pixels, and set `width="1" height="1"` if they are missing.
4. Re-run the QA with the full HTML and raw headers. Check the unsubscribe link, `List-Unsubscribe`/`List-Unsubscribe-Post`, and SPF/DKIM/DMARC alignment for `email.shoecarnival.com`.
5. Probe a sample of the 36 `emltrk.com` links by following redirects, and verify the final landing URLs, UTM retention, and FALL20 handling.
6. Fix the two meta tags with `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"`.
7. Consider restoring underline styling on inline text links, and a mobile body font size of at least 14px.
