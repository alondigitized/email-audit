## Technical Audit

**1. Technical Summary**
The email is structurally sound for responsive rendering, and the automated QA run reports a 100% pass rate. However, 32 click-tracking links could not be verified, two tracking images have no `alt` attribute, and one tracking pixel URL contains a literal `[UNIQUE]` placeholder. The HTML source was truncated, so footer, header and link-level checks are limited.

**2. Link & Tracking Issues**
- **Unverified links:** 32 links were skipped because they use tracking and click-redirect domains (`*.emltrk.com`). The final destinations, HTTP status and redirect chains are not confirmed.
- **Possible unresolved token:** `https://0di86k1v.emltrk.com/v2/0di86k1v?d=[UNIQUE]` has a literal `[UNIQUE]` in the query string. If this is not a deliberate ESP macro that is resolved at send time, the pixel carries no unique ID and open tracking is degraded. Confirm against the raw sent message.
- **Stray character in pixel URL:** `https://ieezzy5m.emltrk.com/v2/ieezzy5m?i=72180589&t=utm_campaign=SCA_20261008_MWK_fall_is_ON_AM` ends with a zero-width space (U+200B) after `AM`. That character can be percent-encoded into the parameter value and corrupt the campaign string in reporting.
- **Malformed query:** `t=utm_campaign=...` nests a `key=value` pair inside another parameter's value. That is unconventional and may not parse as UTM data downstream.

**3. Rendering & Accessibility**
- **Missing alt text:** Both flagged images are tracking pixels (`ieezzy5m` and `0di86k1v`). They should carry `alt=""` so screen readers skip them. The QA check did not flag any content images, but I can't confirm that from the truncated source.
- **Links lose affordance:** The global rule `a, a:link, a:visited, ... { text-decoration:none !important; color:inherit !important; }` removes underlines and link color from every anchor. Unless the buttons or images are styled separately, inline text links won't be distinguishable. That is a WCAG 1.4.1 risk.
- **Malformed meta tags:**
  - `<meta content="text/html;" charset="utf-8" />` lacks `http-equiv="Content-Type"`. The `charset` attribute still sets the encoding.
  - `<meta content="IE=edge" />` lacks `http-equiv="X-UA-Compatible"`, so it does nothing.
- **Doctype mismatch:** The doctype is HTML 4.01 Transitional, but the `<html>` tag carries `xmlns="http://www.w3.org/1999/xhtml"`, and the markup uses self-closing `/>` tags. This is not breaking but is inconsistent.
- **Small mobile text:** `.responsive-text` is set to 12px at max-width 600px, which is below the commonly recommended 14px minimum for mobile body copy.
- **Positives:** The viewport meta tag, `lang="en"`, Apple and Samsung autolink fixes, and the 660px and 450px breakpoints are all present.

**4. Personalization & Merge Tokens**
- The only token-like artifact found is `d=[UNIQUE]` in the pixel URL (see section 2). No other unresolved merge tokens such as `{{...}}`, `%%...%%` or `*|...|*` appear in the visible source, though it is truncated.

**5. Compliance (CAN-SPAM, unsubscribe, authentication headers)**
- Not verifiable. The truncated HTML does not include the footer, so I can't confirm an unsubscribe link or a physical postal address. No headers were provided, so `List-Unsubscribe`, `List-Unsubscribe-Post`, SPF, DKIM and DMARC are unchecked.
- The sender is `shoecarnival@email.shoecarnival.com`, a dedicated subdomain, which is generally good practice. Authentication results still need confirming from the raw headers.

**6. Email-to-Site Continuity (UTM params, landing page alignment)**
- The campaign identifier `SCA_20261008_MWK_fall_is_ON_AM` appears only inside a tracking pixel URL. Click URLs are wrapped in `emltrk.com` redirects, so I can't confirm that UTM parameters survive to the landing page.
- The campaign name (`fall_is_ON`) doesn't obviously match the subject line (Nike 30% off). This may just be naming convention, but landing-page alignment can't be confirmed without resolving the redirects.
