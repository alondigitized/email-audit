Gmail proxies HTTP images but strips the original URL context; Apple Mail and Outlook.com may block mixed-content. All seven should be `https://`.

**[MEDIUM] Missing `http-equiv` on charset meta**

```html
<!-- As sent — no effect -->
<meta content="text/html; charset=utf-8" />

<!-- Correct -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

Without `http-equiv="Content-Type"`, this tag is inert. Outlook and older clients that rely on it for charset detection may fall back to a default encoding, risking mojibake on special characters (e.g., the `™` and `©` that likely appear in the footer).

**[LOW] Open-tracking pixel missing `alt=""`**

```html
<img style="visibility:hidden;display:none" height="1" width="1"
  src="https://demandwarecrocs.demdex.net/event?d_dpid=196107&...">
```

A hidden pixel should carry `alt=""` explicitly. Some screen readers and strict accessibility validators flag `<img>` without any `alt` attribute, even on hidden elements.
