## Technical Audit — Adidas "Adizero Dropset Pro" Email

**Sent:** adidas@us-news.comms.adidas.com | **QA pass rate:** 75% (2 hard failures)

---

### 1. Technical Summary

Two hard failures: a broken click destination with a relative URL scheme, and a completely absent plain-text MIME part. Supporting issues include six HTTP image assets, two images missing alt text, a malformed charset meta tag, and duplicated `@font-face` declarations.

---

### 2. Link & Tracking Issues

**[FAIL] Broken click URL — relative path used where absolute required**
QA flagged `unknown url type: '/g/8c37763f-c87a-47cd-a2c8-3b3c740c3388?txn=7ab4ae00-7e79-11f1-b422-4ec26c495bcf'`. A relative `/g/…` path cannot be resolved from within an email client; the link destination resolves to nothing. The corresponding image URL (`https://dv.adidas.com/o/8c37763f-c87a-47cd-a2c8-3b3c740c3388`) loads correctly, so this appears to be a click-wrapper that was built against a relative base path rather than the absolute `https://dv.adidas.com` origin.

**[WARN] 29 tracking links not resolvable**
All click redirects route through `click.comms.adidas.com`. QA skipped HTTP probing for these, so UTM integrity and final-destination health cannot be confirmed from this audit.

---

### 3. Rendering & Accessibility

**[FAIL] Six HTTP image assets — same file, six placements**
```
src: http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg
```
All six references are identical (the arrow icon). Gmail, Outlook.com, and Apple Mail block mixed-content images by default; these will render as broken placeholders in the majority of clients.

**[WARN] Tracking pixel also served over HTTP**
```
src: http://click.comms.adidas.com/CI0/0102019f59e01116-7fa8304d-…/CplarLodcZHH6764S3AC-KoKq…
```
Open-tracking will fail in clients that enforce HTTPS-only image loading, producing under-counted open metrics.

**[WARN] Two images missing alt text**
- Hero/product image: `8c37763f-c87a-47cd-a2c8-3b3c740c3388` (no `alt` attribute)
- Tracking pixel: `CplarLodcZHH6764S3AC-KoKq…` (should carry `alt=""` to suppress screen-reader noise)

**[WARN] Malformed charset meta tag**
```html
<meta content="text/html; charset=UTF-8" />
```
Missing `http-equiv="Content-Type"`. Without `http-equiv`, the tag is ignored by rendering engines. Correct form:
```html
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
```

**[WARN] Duplicate `@font-face` declarations**
`AdihausDIN` (400, 700) and `AdineuePRO` (400, 600) are declared twice across two separate `<style>` blocks. Beyond the redundancy, all `@font-face` rules reference only `local()` sources (Arial/Helvetica/Calibri) — the brand typefaces will never load from a web source; fallback fonts render in all clients.

---

### 4. Personalization & Merge Tokens

No issues found. No unresolved token placeholders visible in the provided source. The `txn=` parameter in the broken URL is a resolved send-time identifier, not a dangling merge field.

### 5. Compliance

**[FAIL] Plain-text MIME alternative is 0 characters**
QA confirmed the text part is empty. CAN-SPAM does not technically mandate a text part, but a missing or empty alternative is a significant spam-filter signal (SpamAssassin `MIME_HTML_ONLY` rule). Major ESPs recommend a minimum 20% text-to-HTML ratio by character count.

**No issues found** on: `ROBOTS: NOINDEX, NOFOLLOW` present; `referrer: no-referrer` present; `lang="en"` set on `<html>`; unsubscribe link assumed present (footer HTML truncated, standard in adidas sends).

Cannot verify UTM parameter coverage — all 29 destination links are wrapped in `click.comms.adidas.com` redirects that were not probed. The broken `/g/…` link is a zero-conversion dead end for whichever CTA it wraps; that product or section receives no traffic.
