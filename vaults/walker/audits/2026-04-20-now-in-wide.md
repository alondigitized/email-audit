## What's weak

- **Wrong brand for me, full stop.** I didn't sign up for HOKA. I'm a Skechers Plus member. This feels like it ended up in my inbox by accident.
- **Trail running imagery is alienating.** A person sprinting across rocky terrain? That's not my life. I need shoes for the grocery store and a walk around the block, not mountain descents.

- Show a price or a promotion above the fold. I need a reason to act, and "Wide sizes exist" isn't enough.

- The "Far and Wide" product grid is useful but the thumbnails are tiny on a phone — larger product cards with a visible price would help.

### 3. Rendering & Accessibility

**Duplicate, conflicting `<meta name="viewport">` tags (lines 5–6):**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
First tag disables pinch-to-zoom (no `user-scalable=yes`); second tag re-enables it. Behavior is browser/client-dependent when duplicated. One tag should be removed; retain the `user-scalable=yes` variant for accessibility.

**Malformed charset `<meta>` (line 2):**
```html
<meta content="text/html; charset=utf-8" />
```
Missing `http-equiv="Content-Type"`. Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, some legacy clients (Outlook 2007–2016) may not apply the declared charset.

**`-webkit-text-size-adjust: none` on universal selector:**
```css
* { -webkit-text-size-adjust: none; }
```
Setting this to `none` (rather than `100%`) prevents iOS Mail from adjusting small text on narrow viewports. Can cause illegible font sizes on mobile if any text is set below ~14px. Change to `100%` or remove from the universal selector.

**Web font `@import` blocked by major clients:**
```css
@import url("https://p.typekit.net/p.css?s=1&k=hva0tmw&...");
```
Gmail, Outlook (all versions), and Yahoo strip `@import` rules entirely. Futura PT will not render in those clients. Acceptable if fallback stack (typically Arial/Helvetica) is defined; confirm fallback is set on all text elements.

**Stale Typekit cache comment:**
```css
/*{"last_published":"2022-03-23 22:26:23 UTC"}*/
```
The Typekit kit (`hva0tmw`) has not been re-published since March 2022. If font weights or variants were updated on the Adobe Fonts side, this kit may be serving stale assets. Re-publish or verify kit currency.
