### 3. Rendering & Accessibility

**Duplicate conflicting `<meta name="viewport">` tags:**
```html
<!-- tag 1 -->
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<!-- tag 2 — conflicts -->
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
Tag 1 disables user scaling; tag 2 re-enables it. iOS Safari reads the first; behavior in other clients is undefined. Remove the duplicate — keep whichever policy is intended.

**CSS syntax errors in mobile media query (`@media only screen and (max-width:480px)`):**
```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
.nav_border  { border-top:px solid ; }
```
Both rules are missing numeric values before `px` and `border-top` is missing its color. Parsers will silently discard these declarations, breaking nav spacing on small screens.

**`-webkit-text-size-adjust: none` on `*` selector:**
```css
* { -webkit-text-size-adjust: none; }
```
Disables text resizing for all elements, including body copy. WCAG 1.4.4 (Resize Text) requires content to be resizable up to 200%. This conflicts with iOS accessibility settings.

**`<title>` is empty:**
```html
<title></title>
```
Some clients (Yahoo, older Outlook) expose the title in the tab or window. Low severity, but a descriptive value is preferred.

**`charset` meta is missing `http-equiv`:**
```html
<meta content="text/html; charset=utf-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, this tag has no effect in clients that don't recognize the shorthand form.
