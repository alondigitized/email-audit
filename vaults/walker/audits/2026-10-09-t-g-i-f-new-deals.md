## Technical Audit

## 1. Technical Summary
The automated QA run reports a 100% pass rate, but two of its warnings point to real defects in the tracking pixels: an unresolved `[UNIQUE]` placeholder and a hidden character in a campaign string. The HTML source was truncated, so I could only audit the `<head>`, and I could not verify the body, headers or landing pages.

## 2. Link & Tracking Issues
- **Unresolved token in a pixel URL:** `https://0di86k1v.emltrk.com/v2/0di86k1v?d=[UNIQUE]` still has the literal `[UNIQUE]`. This is probably a cache-buster or recipient ID that the ESP didn't substitute. If so, the open pixel may be cached or may not attribute to a recipient.
- **Hidden character in a pixel URL:** `https://ieezzy5m.emltrk.com/v2/ieezzy5m?i=72180589&t=utm_campaign=SCA_20261009_friday_deals_AM​` ends with an invisible zero-width space (U+200B) after `AM`. This can corrupt the campaign value in analytics (`..._AM%E2%80%8B`) and split reporting.
- **Malformed query string:** `t=utm_campaign=SCA_...` puts an unencoded `=` inside a parameter value. It probably works, but it is fragile.
- **Unprobed links:** 33 tracking links were skipped by the HTTP probe because they are click-redirect domains. Destination validity and redirect chains are unverified.
- **QA summary is inconsistent:** it says "0 warnings" while listing `[WARN]` lines.

## 3. Rendering & Accessibility
- **Missing alt text:** both `emltrk.com` images (`ieezzy5m`, `0di86k1v`) have no `alt`. They look like tracking pixels, so the impact is low. Adding `alt=""` would mark them as decorative.
- **Links are visually indistinguishable:** the global rule `a, a:link, … { text-decoration:none !important; color:inherit !important; }` removes underline and colour from every link. Any text link that has no other styling gets no visual cue, which is a WCAG 1.4.1 concern.
- **Tel links disabled:** `a[href^="tel"], a[href^="sms"] { pointer-events:none; }` makes phone and SMS links non-clickable on mobile.
- **Small mobile text:** `.responsive-text` is set to `font-size:12px !important` at ≤600px.
- **Malformed meta tags:**
  - `<meta content="text/html;" charset="utf-8" />` has no `http-equiv`.
  - `<meta content="IE=edge" />` has no `http-equiv`, so it has no effect.
- **Doctype mismatch:** the HTML 4.01 Transitional doctype is combined with `xmlns="http://www.w3.org/1999/xhtml"`, so the markup is inconsistent.
- **Positive:** `<html lang="en">`, a viewport meta tag and `color-scheme` meta tags are present.

## 4. Personalization & Merge Tokens
- The `[UNIQUE]` token in the `0di86k1v` pixel URL is unresolved (see section 2).
- No other unrendered tokens appear in the visible portion. The body was truncated, so this is unverified.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
Not verifiable. The footer was cut off, and no `List-Unsubscribe`, `List-Unsubscribe-Post`, SPF, DKIM or DMARC headers were provided. The sender (`shoecarnival@email.shoecarnival.com`) is on a dedicated subdomain, which is normal.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- The only UTM evidence is `utm_campaign=SCA_20261009_friday_deals_AM`, and it appears only inside a pixel URL. The campaign name matches the send date (2026-10-09).
- I could not confirm `utm_source` or `utm_medium`, or whether UTMs survive the redirect to the landing pages, because the 33 click links weren't probed.

## 7. Recommendations
1. Fix the `[UNIQUE]` substitution in the `0di86k1v` pixel, and check the ESP's dynamic-content settings.
2. Remove the zero-width space (U+200B) from the `utm_campaign` / `t=` value, and validate templates for invisible characters.
3. Add `alt=""` to the tracking pixels.
4. Restore a visible link affordance, such as an underline or colour, for inline text links. Scope the `color:inherit !important` rule so it only covers autolink fixes.
5. Add `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"` to the meta tags, and make the doctype match the markup.
6. Re-run QA on the full HTML and headers to cover unsubscribe, authentication and click-through destinations. Also fix the QA summary so warnings are counted.
