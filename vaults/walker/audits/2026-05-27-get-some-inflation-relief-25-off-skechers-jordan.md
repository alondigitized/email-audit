### 3. Rendering & Accessibility

**Issue 3a — Malformed charset meta tag**
```html
<meta content="text/html;" charset="utf-8" />
```
`content="text/html;"` is not a valid value when `charset` is also present. The correct forms are either:
- `<meta charset="utf-8">` (HTML5), or
- `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />`

As written, some parsers will treat the `content` attribute as overriding or conflicting. Low-risk in practice but technically malformed.

**Issue 3b — Charset declaration appears after two `<style>` blocks**

The charset `<meta>` tag is the third element in `<head>`, placed after two `<style>` blocks. Per the HTML spec and browser/email parser behavior, the charset declaration must appear within the first 1024 bytes of the document and before any content that could trigger encoding interpretation. Style blocks before the charset declaration may be parsed with the wrong encoding on edge-case clients.

**Issue 3c — Missing `http-equiv` on IE compatibility tag**
```html
<meta content="IE=edge" />
```
Without `http-equiv="X-UA-Compatible"`, this tag has no effect. It should be:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```

**Issue 3d — Dark mode explicitly disabled, no fallback**
```html
<meta name="color-scheme" content="light" />
<meta name="supported-color-schemes" content="light" />
```
Dark mode is hard-blocked. Apple Mail and Outlook on macOS will not apply any dark adaptation. This is a deliberate choice but means dark-mode users see a forced-white background with no OS-level fallback. If the design relies on white backgrounds for image blending, this is intentional and acceptable — flag for the content reviewer to confirm image assets have white backgrounds.

**Issue 3e — `pointer-events: none` on tel/sms links**
```css
a[href^="tel"], a[href^="sms"] {
  color: inherit !important;
  pointer-events: none;
  cursor: default !important;
}
```
This disables tap-to-call and tap-to-text for any `tel:` or `sms:` links in the email body. If the email contains a customer service phone number formatted as a `tel:` link, it will appear clickable but not respond. Confirm no `tel:` links exist in the body, or remove this rule.

**Issue 3f — Redundant duplicate CSS declaration**
```css
color:inherit !important; color:inherit;
```
Appears in the global anchor reset selector. Harmless but indicates copy-paste artifact in the template.
