# GET $10 OFF NOW(!)
**Score:** 4/10 · **Type:** Email audit · **2026-06-06**
## Executive summary

- Eighth DSW email in four days. My thumb was already on autopilot when I tapped it open. "GET $10 OFF NOW(!)" — the exclamation point in parentheses is an odd quirk, almost like they're apologizing for yelling. I didn't hate the subject, but by now the $10-off hook from DSW is like background noise; I've heard it every single day this week.
- Once I was inside, the layout said everything I needed to know in about two seconds: young woman, pink fashion sneakers, "KICK IT UNDER $80" as the hero headline. That's not my world. I'm 62 and I want cushioning, arch support, and something that doesn't require a shoehorn. The whole creative is aimed squarely at a 25-year-old sneakerhead who wants to look cool at a rooftop bar. The "Must Haves Under $60" grid below it is more of the same — chunky colorful kicks that I'd never pull on.
- I marked it read and moved on. I'm not forwarding this to anyone I know. The tiered savings offer is real and visible, but the shoe selection underneath makes it irrelevant to me.

## What's working

- **Tiered savings ladder is clear** — $10/$20/$60 off thresholds are spelled out across the top banner; I knew the deal before I scrolled an inch.
- **"Under $80" price anchor** — for a value shopper like me that's a useful filter even if the shoes underneath aren't my style.
- **No render bugs** — images loaded cleanly, text didn't overlap, layout held together on mobile.
- **Concrete offer front-and-center** — no ambiguity, no "up to X% off" weasel language; the dollar amounts are right there.

## What's weak

- **Every model is a young woman in fashion sneakers** — zero demographic signal for a 62-year-old guy; feels like I accidentally opened someone else's email.
- **"KICK IT" hero language** — that's not how I talk, and it's not what motivates me; I'm not trying to "kick it," I'm trying to walk 18 holes without my knees aching.
- **No comfort signals anywhere** — cushioning, arch support, wide width, slip-on — none of those words appear in what I can see.
- **$10 off fatigue is real** — same offer, same format, seventh or eighth time this week; the urgency has completely worn off for me personally.
- **Preview text leaks padding characters** — all those spaced dots after the real copy look like technical garbage in my inbox.

## Recommendations

- 1. **Segment men vs. women** — or at minimum rotate the hero creative so men's comfort shoes get equal real estate. One men's walking shoe in the "Under $80" grid would've kept me scrolling.
- 2. **Retire the $10-off hook for this send** — after seven uses in four days, swap in a product story: "Our best-cushioned shoes, all under $80." That's new information.
- 3. **Drop one comfort keyword into the hero** — something like "KICK BACK UNDER $80" or "WALK ALL DAY UNDER $80" signals to me that this might actually apply.
- 4. **Fix the preheader** — strip the invisible spacer characters; they render as visual noise on some clients.

- **Preheader Alt A:** `Cushioned walkers, slip-ons, and wide widths — shop now`

### 3. Rendering & Accessibility

**`http-equiv` missing on charset meta tag**
```html
<meta content="text/html; charset=utf-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, some legacy email clients (Outlook 2007–2016) may not honor the charset declaration, causing encoding fallback issues with special characters (the subject line includes `!`).

**CSS property capitalization errors in `@font-face` blocks**
All 10 `@font-face` declarations use `Src:` (capital S) instead of `src:`. While most parsers are forgiving, this is non-conforming CSS and may cause web font load failure in stricter parsers (e.g., Samsung Email, some Outlook versions).
```css
/* Incorrect — found in all 10 @font-face blocks */
Src: url("https://braze-images.com/...") format('woff');
```

**Redundant / mixed-case `Margin` in heading resets**
```css
h1, h2, h3, h4, h5, h6, p, ul, li { margin: 0 !important; Margin: 0 }
```
Both `margin` and `Margin` are declared. The uppercase form is non-standard and should be removed.

**`supported-color-schemes` used as a CSS property (invalid)**
```css
:root {
  color-scheme: light dark;
  supported-color-schemes: light dark;  /* not a valid CSS property */
}
```
`supported-color-schemes` is only valid as a `<meta name>` value, not a CSS property. It has no effect here and is noise in the stylesheet.

**Font format efficiency**
- Futura PT fonts are served as `.woff` only — no `.woff2` fallback. WOFF2 compresses ~30% smaller.
- HelveticaNow fonts are served as `.ttf` — significantly larger than WOFF/WOFF2 equivalents.
- Neither issue breaks rendering (email clients that support web fonts accept both), but contributes to load time.
