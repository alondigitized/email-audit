# WHOA! This deal starts…NOW!
**Score:** 3/10 · **Type:** Email audit · **2026-04-27**
## Executive summary

- **Email:** "WHOA! This deal starts…NOW!" | DSW | April 27, 2026
- I opened this one mostly out of habit — DSW is a store I recognize. But the second I saw that hero, I felt like this email was written for somebody else entirely. A button that says "CLICK TO REVEAL THE DEAL." That's it. No deal shown. No product shown. No price. They want me to click just to find out what they're selling. - **DSW brand is recognizable.** I know the logo, I trust the store. That's the only reason I didn't delete this immediately.
- **"ONE DAY ONLY" does create some pressure.** Urgency messaging is something I respond to when I'm already interested — a sale ending today would matter to me if I knew what was on sale.
- **"Free Shipping for $35+" banner** near the bottom is genuinely useful. I always check shipping costs before buying, so that caught my eye even if it was small.

## What's weak

- **No product, no price, no category.** The entire email is a teaser. As a guy browsing on my phone, I'm not going to click a button to find out what the deal even is. Show me men's shoes. Show me a price. Give me a reason.
- **That hero image is not for me.** A young woman looking shocked — that's not my world. I shop men's casual, walking shoes, comfort brands. Nothing here signals this email was meant for Walker Miles.

- **No men's content anywhere.** No men's shoes, no comfort tech, no Slip-ins mention, nothing aimed at me.

- 4. **Make the fine print readable.** If there are exclusions or conditions on the deal, I want to know them, but I can't read six-point text on a phone screen.

### 3. Rendering & Accessibility

**Malformed `<meta>` attributes (two instances):**
```html
<meta content="text/html; charset=utf-8" />         <!-- missing http-equiv="Content-Type" -->
<meta content="IE=Edge" />                           <!-- missing http-equiv="X-UA-Compatible" -->
```
Both are parsed as no-ops in strict renderers. The charset declaration in particular should be `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` for reliable Outlook/older client behavior.

**Viewport blocks user zoom (WCAG 1.4.4 failure):**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
`maximum-scale=1` prevents pinch-to-zoom on mobile, which fails WCAG 2.1 SC 1.4.4 (Resize Text). Remove or raise to `maximum-scale=5`.

**`text-size-adjust: none` is overly aggressive:**
```css
* { -ms-text-size-adjust: none; text-size-adjust: none; }
```
The `-webkit-text-size-adjust` is correctly set to `100%`, but the non-prefixed `text-size-adjust: none` and the `-ms-` variant are set to `none`, which disables user-agent text scaling entirely. Change all three to `100%`.

**Non-standard CSS property capitalization in all `@font-face` blocks:**
```css
@font-face { Src: url("...") format('woff'); }   /* capital S */
```
CSS property names are case-insensitive per spec, but `Src:` (capital S) is non-standard. Older MSO/WordEngine parsers may reject it. Normalize to lowercase `src:`.
