# $10 OFF STARTS NOW, BTW!
**Score:** 7/10 · **Type:** Email audit · **2026-07-09**
## Executive summary

- Well, the BOGO circus finally closed up shop. After getting hammered with "final hours" warnings twice on July 8th alone, I half-expected DSW to go quiet for a few days and let me breathe. Instead I woke up to a brand-new deal — $10 off with a code called POOLDAY. At least it's something different.
- Here's my problem though: I open this thing and the first thing staring back at me is a bunch of women's heeled shoes and Mary Janes. "SO NEW, SO YOU," it says. Well, that "you" isn't me. I'm a 62-year-old man looking for something cushioned I can slip on without bending over, and the hero of this email is showing me kitten heels. I had to go looking for the SHOP MEN link in the nav bar like I'm hunting for the bathroom in a hotel lobby.
- The $10-off offer is real and the code is right there — I'll give them that. The wide-width shortcut buttons buried in the size section are actually useful for me. But I'm not clicking the primary CTA on an email that spent its whole hero section ignoring men. I'd mark this as read, maybe circle back later if I remember the code.

## What's working

- **$10 off with code POOLDAY is visible and specific** — I don't have to dig, the dollar amount and the code are right there below the headline.
- **SHOP WIDE WIDTH and SHOP WIDE CALF buttons** — this is the first DSW email in this whole BOGO run that acknowledged I might need a wider shoe. That actually matters to me.
- **DSW VIP perks are front and center** — free shipping for VIPs, visible without having to hunt. I care about that.
- **Clean render, no broken images** — the email loaded fast and nothing looked busted on my phone, which at my age is the bare minimum I expect.

## What's weak

- **Hero imagery is all women's shoes** — heels, Mary Janes, dressy flats. None of that is me. When the first thing I see is products I'd never buy, the email already feels like it was sent to the wrong address.
- **"BUY MORE, SAVE MORE" headline is misleading** — that phrase tells me there are tiers (spend X, save Y; spend more, save more). But the offer is just flat $10 off. That's bait-and-switch framing, even if unintentional.
- **No end date visible** — BOGO had deadlines baked in everywhere; that's actually what drove me to open those emails. This one says "STARTS NOW" but won't tell me when it ends. If I don't click today, when does the deal go stale?
- **"BTW" cadence is wearing thin** — they used the casual voice on the "BOGO is going on, btw" send too. It was charming once. Now it's a verbal tic.
- **Grammar error in the preview** — "Which mean shopping also starts now" — "mean" should be "means." Small thing, but sloppy from a retailer trying to act like my trusted source.

## Recommendations

- 1. **Lead the hero with a men's comfort product** — or at minimum split the "SO NEW, SO YOU" section by gender. Show me a Skechers slip-on or a walking shoe with cushioning in that first scroll. If DSW has my purchase history, they know I'm not buying kitten heels.
- 2. **Fix the headline to match the offer** — "BUY MORE, SAVE MORE" sets up a tiered expectation. Either show the tiers, or swap the headline to something like "YOUR $10 OFF IS READY."
- 3. **Add a clear expiration** — "Offer ends July 13" or whatever the date is. Urgency has driven opens all week; dropping it now is a mistake.
- 4. **Fix the preview typo** — "Which mean" → "Which means." Takes ten seconds.
- 5. **Afterpay placement** — that section is more relevant for a younger buyer financing a $200 sneaker. For me it's noise; push it below the fold or drop it.

- **Subject Alt B:** `New offer: $10 off with code POOLDAY (while it lasts)`
- **Preheader Alt A:** `Use POOLDAY in stores or online — offer ends soon`

### 3. Rendering & Accessibility

**`Src:` property capitalized in all `@font-face` blocks (confirmed bug)**
Every `@font-face` declaration uses `Src:` (capital S) instead of the spec-required lowercase `src:`. CSS property names are technically case-insensitive in the spec, but some strict email client CSS parsers (notably older Samsung Mail and some WebKit builds) will silently skip unrecognized property names. Affects all 10 font declarations.

```css
/* Bug — all 10 @font-face blocks */
Src: url("https://braze-images.com/...") format('woff');
```

**`-ms-text-size-adjust` declared twice with conflicting values (confirmed bug)**
The wildcard reset declares `-ms-text-size-adjust` twice — first `100%`, then `none`. The second declaration wins, disabling automatic text scaling in IE/legacy Edge entirely rather than the intended 100% normalization.

```css
/* In the * reset */
-ms-text-size-adjust: 100%;   /* set */
...
-ms-text-size-adjust: none;   /* then immediately overridden — wrong */
```

**Missing `http-equiv` attributes on two `<meta>` tags**
Both tags are missing the required attribute and will be silently ignored by some clients:
- `<meta content="text/html; charset=utf-8" />` → needs `http-equiv="Content-Type"`
- `<meta content="IE=Edge" />` → needs `http-equiv="X-UA-Compatible"`

**`supported-color-schemes` in CSS `:root` is not a valid CSS property**
The `:root` block includes `supported-color-schemes: light dark;` — this only belongs in the `<meta>` tag, not as a CSS declaration. The meta tag version is present and correct; the CSS version is a no-op but indicates a copy-paste error.

**HelveticaNow fonts served as `.ttf`, not `.woff`**
The four Futura faces use efficient `.woff`; the six HelveticaNow faces use `.ttf` with cache-buster query strings (`?1755182939`). TTF files are ~40% larger than WOFF and have no meaningful browser-support advantage in 2026. Increases load time for HelveticaNow recipients.
