# Technical Audit — Shoe Carnival "FINAL DAY DEALS"

## 1. Technical Summary
Three tracking URLs contain a zero-width space (`\u200b`) appended to the `utm_campaign` value, causing encoding failures and likely broken clicks. Several tracking pixels and one content image lack alt text, and the document still ships as legacy HTML 4.01 Transitional.

## 2. Link & Tracking Issues
- **Broken URLs — invisible Unicode in query string.** Three `emltrk.com` redirector links end with `…SCA_20260519_sandals_crocs_skechers_AM​` where the trailing character is U+200B (zero-width space). Any strict URL parser (or downstream analytics ingestion) will reject these:
  - `https://ieezzy5m.emltrk.com/v2/ieezzy5m?rd&i=72180589&t=utm_campaign=SCA_20260519_sandals_crocs_skechers_AM\u200b`
  - `…?rl&i=72180589&t=utm_campaign=…\u200b`
  - `…?p&i=72180589&t=utm_campaign=…\u200b`
- **Malformed `t=` parameter.** The tracker's `t=` value contains an unencoded `=` (`t=utm_campaign=SCA_…`). The `=` inside the value should be percent-encoded (`%3D`) to avoid ambiguous parsing.
- 26 click-redirect links were not HTTP-probed (expected for tracking domains) — destinations cannot be verified from source alone.

## 3. Rendering & Accessibility
- **Legacy DOCTYPE**: `HTML 4.01 Transitional` with XHTML namespace. Functional in email clients but outdated; some accessibility tooling will skip semantic checks.
- **Missing `alt` attributes**:
  - Content image `fcf7c998-c6f2-4f06-82af-785f6595003d.jpg` — visible hero/product image with no alt text, fails WCAG 1.1.1.
  - Tracking pixels `ieezzy5m` and `0di86k1v` — should have `alt=""` (empty) to mark as decorative; missing attribute entirely causes screen readers to announce the filename.

- UTM strategy is inconsistent: only `utm_campaign` is present (`SCA_20260519_sandals_crocs_skechers_AM`). No `utm_source`, `utm_medium`, or `utm_content` — landing-page analytics will bucket this traffic incorrectly or as "(direct)".

## 7. Recommendations
1. **Strip U+200B from campaign string at template-build time.** Add a sanitizer that rejects/normalizes non-ASCII whitespace in URL query values before send.
2. **Fix `[UNIQUE]` token substitution** on the `0di86k1v` open-tracking pixel — verify the ESP's merge syntax matches the placeholder.
3. **Percent-encode the `t=` parameter value** so `=` inside it becomes `%3D`.
4. **Add `alt` attributes**: descriptive alt on the hero JPG; explicit `alt=""` on tracking pixels.
5. **Add full UTM set** (`utm_source=email`, `utm_medium=promotional`, distinct `utm_campaign` per send date) and verify the campaign ID matches the actual send date.
6. **Fix the dead `IE=edge` meta** by adding `http-equiv="X-UA-Compatible"`, or drop it entirely.
7. Consider adding `dark` to `supported-color-schemes` once dark-mode renders have been QA'd.
