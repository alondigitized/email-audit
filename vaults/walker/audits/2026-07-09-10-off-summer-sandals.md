# $10 OFF: Summer Sandals >>>
**Score:** 7/10 · **Type:** Email audit · **2026-07-09**
## Executive summary

- I already heard about this ten-dollar deal this morning — DSW's "$10 OFF STARTS NOW, BTW!" landed before I finished my coffee. So when I opened this one and saw the same code, same offer, I felt like I was being followed around the store by the same salesperson. The "Summer Edit" creative is fine — it's July, sandals make sense — but when I tap it open, the first person I see is a woman in a sun hat. Then comes LADIES content, then GENTS, then KIDDOS. I had to scroll to find myself in this email, and that's backwards.
- That said, a couple of things pulled me back. The SHOP WIDE WIDTH button is exactly the kind of detail that signals somebody over there knows who's actually buying comfort shoes. And the SHOP MEN'S SANDALS button is clean and specific. There's what looks like a Birkenstock-style sandal in the Gents section — that's the kind of thing I'm actually hunting for.
- Would I click? Probably — one tap on SHOP WIDE WIDTH, maybe SHOP MEN'S SANDALS. But I'm not energized about it. This is DSW's second $10 off email today and probably their seventh this week. I'd mark it read and come back if I have a few minutes. Wouldn't forward to a friend unless he specifically mentioned sandals.

## What's working

- **SHOP WIDE WIDTH button** — That single button does more for me than all the lifestyle copy combined. Wide-width comfort options are hard to find; naming them earns a tap.
- **$10 off + code POOL5AY visible right at the top** — "BUY MORE, SAVE MORE / GET YOUR $10 OFF" is front and center before I scroll anywhere. Clean, no hunting.
- **SHOP MEN'S SANDALS button** — Specific verb + noun, goes where I want to go. No "Discover" or "Shop Now" vagueness.
- **SHOP BY SIZE grid** — Practical. I know my size, I don't need to fish for a filter.
- **Email renders cleanly** — No broken images, no overlapping text, loads fine on my phone.

## What's weak

- **Hero is a woman in a summer hat** — I'm 62 and shopping for my own feet. A female model isn't a dealbreaker by itself, but leading with her as the first human in the email signals that I'm not the primary audience here.
- **LADIES leads, GENTS is second, KIDDOS is third** — That hierarchy tells me exactly where men fall on DSW's priority list for this send.
- **"Get something new for the whole fam"** — I live alone and shop for myself. The family-shopping frame puts me in the wrong mental mode before I even open the body.
- **Second $10 off email today** — The morning version already announced this deal. Sending again same-day with a fresh creative doesn't add value; it just runs up the fatigue counter.
- **"Flip-flop shoes" and zero comfort language** — Not a word about arch support, cushioning, or anything I actually evaluate when buying footwear. "Flip-flop" signals fashion-first, comfort-second — the opposite of what wins my foot.

## Recommendations

- 1. **Segment by gender and serve men's content first** — Basic A/B by customer gender. Walker shouldn't have to scroll past Ladies to find GENTS. Men's hero first, men's CTA above the fold.
- 2. **Swap "flip-flop shoes" for comfort language** — Something like "finally, sandals with real support" or "weekend-ready and actually comfortable" speaks to why I buy, not just what season it is.
- 3. **Name the "LOOK WHO'S BACK IN STOCK" product** — If it's a Birkenstock, a Hoka Ora, a Crocs Classic — say it. A brand name in that slot would stop my scroll cold. Vague curiosity doesn't hook a Boomer who wants specifics.
- 4. **Pull the preview off the family angle** — "Whole fam" reads like a Target ad. Lean into the comfort/men's positioning instead.
- 5. **Rest the $10 off one send before re-blasting** — The morning email broke the news. This one should either add a new incentive (free shipping stacked, extra clearance discount) or wait until tomorrow.

### 3. Rendering & Accessibility

**[HIGH] Missing `http-equiv` on charset `<meta>` tag**
```html
<!-- Current (broken) -->
<meta content="text/html; charset=utf-8" />

<!-- Required -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv="Content-Type"`, the charset declaration is a no-op. Outlook and some webmail clients will not apply UTF-8 encoding from this tag alone.

**[HIGH] `Src:` (capital S) in every `@font-face` block**

All 10 `@font-face` declarations use `Src:` instead of lowercase `src:`. CSS property names are case-sensitive in non-IE parsers. This is a systemic bug across the entire font stack — Futura PT and HelveticaNow will silently fail to load in any client that enforces spec-compliant CSS parsing.

```css
/* Current (invalid) */
Src: url("https://braze-images.com/.../original.woff") format('woff');

/* Correct */
src: url("https://braze-images.com/.../original.woff") format('woff');
```

**[MEDIUM] Missing `lang` attribute on `<html>` element**
```html
<html xmlns="http://www.w3.org/1999/xhtml">
```
No `lang="en"` (or locale-appropriate value). Screen readers and translation tools cannot determine the document language. Required for WCAG 2.1 Level A (Success Criterion 3.1.1).

**[MEDIUM] Conflicting `text-size-adjust` values in reset**
```css
*{
  -webkit-text-size-adjust: 100%;   /* sets to 100% */
  -ms-text-size-adjust: none;       /* sets to none */
  text-size-adjust: none;           /* overrides unprefixed */
}
```
`-webkit-text-size-adjust: 100%` (correct, prevents iOS zooming) is immediately contradicted by `text-size-adjust: none` on the same rule. Modern Chromium-based clients apply the unprefixed property, which disables all text scaling — a WCAG 1.4.4 violation and an accessibility failure for users with low vision.

**[LOW] Font assets served over `.ttf` without `woff2`**

The HelveticaNow variants are served exclusively as `.ttf` with no `woff` or `woff2` fallback format. `.ttf` is 20–40% larger on the wire. No functional breakage, but adds transfer weight for every open.
