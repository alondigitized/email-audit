# ADIZERO Evo SL EXO: Feel fast.
**Score:** 7/10 · **Type:** Email audit · **2026-06-22**
## Executive summary

- Another adidas email, another performance shoe pitched at me like I'm training for a 5K. "Feel fast" — I'm 62. I want to feel comfortable at the end of a day on my feet, not fast. The Adizero Evo SL Exo sounds like something a twenty-something would wear in a half-marathon, not what I'm reaching for at DSW or browsing on New Balance's site. The shoe photography is sharp and the email renders clean, I'll give them that. But nothing in the hero copy is talking to me.
- What caught my eye was lower in the email — the big "SPEND LESS GET MORE / SAVE $30 ON ORDERS $100+" block. That math I can do in my head. Problem is, I'm almost certain adidas ran this exact same dollar-off offer on June 19th. Now they've wrapped it around a different product and resent it. That feels like a rerun, and when I can't tell if the code is fresh or recycled, I hesitate.
- I'd mark this one read and move on. Not forwarding it. If I were already in the market for something adidas, I might click through just to use the coupon on a comfort shoe — but not for the Adizero.

## What's working

- The $30 off $100 offer is plain-English math I can hold in my head — no percentage gymnastics.
- "FIND YOUR SIZE" button is a useful specific CTA; sizing is exactly the kind of thing I think about before committing.
- Clean render — images loaded, no overlapping text, nothing confusing to navigate on my phone.
- The shoe photography is premium and the two-section layout (product hero → deal block) reads clearly even at a glance.

## What's weak

- "Feel fast" is the wrong hook for me entirely — I want cushioning, arch support, all-day comfort. Speed is someone else's problem.
- The Adizero line is a performance/competition shoe. I cross-shop Brooks, Hoka, New Balance for walking. This product isn't in my universe.
- I'm almost certain this is the same $30-off-$100 offer from the June 19th email, just repackaged. Feels stale.
- The product description text in the body is tiny — I would need to zoom in on my phone to read it, and I'm not going to do that.
- Seven adidas emails in ten days. I'm starting to auto-filter this brand before I even read the subject.

## Recommendations

- 1. Lead the product copy with a comfort/support hook even if the shoe leans performance — even something like "cushioned for every mile" would pull me closer than "feel fast."
- 2. If the $30 off code is newly refreshed or extended, say so explicitly. "Code DEAL is back — fresh offer, same great deal" gives me a reason to act instead of wondering if this is the same old email.
- 3. Add a second product block below the hero in a casual/comfort category — let me browse even if the Adizero doesn't land.
- 4. Bump up the product description font size. If I can't read it without pinching to zoom, I'm not reading it.

### 1. Technical Summary

One confirmed broken redirect link will silently fail for affected recipients; a zero-length plain-text fallback creates deliverability risk with spam filters. Remaining issues are HTTP asset leaks and missing alt attributes.

---

### 2. Link & Tracking Issues

**[FAIL] Broken redirect — invalid relative URL in click-tracking chain**

The QA prober followed the click-redirect at:
```
https://dv.adidas.com/o/b6055490-8d92-4646-a473-bfc625127fb6?cp_tp=v3...
```
and the redirect target resolved to a relative path:
```
/g/b6055490-8d92-4646-a473-bfc625127fb6?txn=b96ff900-706f-11f1-8770-aea38baf8e0c
```
A bare `/g/…` path is not a valid absolute URL. The prober logs this as `unknown url type`. Recipients clicking this link will land on an error page or a broken destination depending on how `dv.adidas.com` handles the malformed redirect. The affected `txn` ID is `b96ff900-706f-11f1-8770-aea38baf8e0c`.

**[WARN] 18 tracking links not probed** — click-redirect domains were excluded from HTTP verification, so additional broken destinations cannot be ruled out.

---

### 3. Rendering & Accessibility

**[WARN] Two images served over HTTP (not HTTPS)**

Both will be blocked by Gmail, Outlook.com, and Apple Mail by default under mixed-content policies:

| alt | src |
|---|---|
| `"arrow"` | `http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg` |
| *(tracking pixel)* | `http://click.comms.adidas.com/CI0/0102019eee23f141-32c89937-d550-4d31-8485-91acb84097ae-000000/…` |

The arrow image appears to be referenced twice — same `src`, same `alt` — suggesting a template duplication bug.

**[WARN] Two images missing alt text**

- `https://dv.adidas.com/o/b6055490-…` — appears to be a content image (not decorative); empty or descriptive `alt` is required.
- `http://click.comms.adidas.com/CI0/…` — likely an open-tracking pixel; `alt=""` is the correct value and is absent.

**Duplicate `@font-face` declarations**

`AdihausDIN` (weights 400, 700) and `AdineuePRO` (weights 400, 600) are each declared twice across two separate `<style>` blocks, with slightly different local-font fallback stacks (`'Calibri', 'Sans Serif'` in block 1 vs. only `'Arial', 'Helvetica'` in block 2). The second block overrides the first. This is dead weight that inflates HTML size and introduces inconsistent fallback behavior depending on parse order.

**Missing `http-equiv` on charset meta**

```html
<meta content="text/html; charset=UTF-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
```
Without `http-equiv`, some legacy clients (Outlook 2007–2016) ignore the charset declaration entirely, risking mojibake on non-ASCII characters.

### 5. Compliance

**[FAIL] Plain-text alternative is 0 characters**

QA reports the `text/plain` MIME part is empty. This violates CAN-SPAM best practice (ISPs treat HTML-only sends as a spam signal) and is blocked outright by some corporate mail gateways that require multipart/alternative. A minimal plain-text version reflecting the key links and unsubscribe URL must be present.

Unsubscribe link and physical address were not visible in the truncated HTML, but the footer CSS classes (`.mobile-footer-padding-block`, `.net-footer-logo-v2`) suggest a standard footer block exists below the truncation point — those elements should be verified against CAN-SPAM §5(a)(3) requirements (physical postal address) and §5(a)(4) (clear opt-out mechanism).
