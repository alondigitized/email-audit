### 1. Technical Summary

### 2. Link & Tracking Issues

### 3. Rendering & Accessibility

**`<meta content="IE=edge" />` is missing `http-equiv` attribute.**
```html
<!-- found -->
<meta content="IE=edge" />
<!-- required -->
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without `http-equiv="X-UA-Compatible"`, the tag is a no-op and IE/Outlook rendering mode is not forced.

**All nine `@font-face` blocks have no `src:` declaration.**
Every `@font-face` rule declares `font-family`, `font-weight`, and `font-style` but omits the `src:` property entirely. The rules are syntactically incomplete and will never load the custom fonts (`proxima-nova`, `linotype-didot`). System fallbacks (Arial, Times New Roman) will render instead. Example:
```css
@font-face {
  font-family: proxima-nova, sans-serif;
  font-weight: 700;
  font-style: normal;
  /* no src: — font will not load */
}
```

**`.bg1` class is defined twice with conflicting values.**
```css
.bg1 { background-color: #ffffff; }   /* line ~6 — white */
...
.bg1 { background: #58546d; }          /* line ~82 — dark purple */
```
CSS cascade means the second definition wins globally. Any element using `.bg1` expecting a white background will render dark purple. The first definition is unreachable dead code.

**Blanket dark mode anchor override will break CTA buttons.**
```css
@media (prefers-color-scheme: dark) {
  a { color: #cf0a2c !important; }
}
```
This applies to every `<a>` tag, including buttons with inline color styles or `.cta1a`/`.cta1b` classes that use `color:#ffffff`. The `!important` flag means white button text becomes red in dark mode regardless of per-element overrides.
