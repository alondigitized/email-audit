# 25% OFF TODAY 🎉
**Score:** 4/10 · **Type:** Email audit · **2026-04-21**
## Executive summary

- DSW is trying to get me in the door with a one-day 25% off deal, and honestly the number itself is big and clear enough that I noticed it. But then I looked at the rest of the email and it's basically a women's shoe catalog. Heels, strappy sandals, skinny little kitten things — none of that is me. They've got a "SHOP MEN" link tucked in there but it's about the size of fine print. I'm a DSW shopper when I need to, but this email treated me like it had no idea who I am. - **Shop by Size module is useful.** If I knew there were men's shoes somewhere in here, that size grid would actually help me navigate. Wide width option noted — that matters to guys like me.
- **Price-match promise banner** is a nice trust signal. I like knowing they'll meet competitors.

## What's weak

- **Product grid is almost entirely women's shoes.** I counted the products in "So New, So You" — heels, strappy sandals, more heels, stilettos, a loafer that might be unisex at best. There is nothing in that grid that makes me think "that's for me." That's a hard stop for a 62-year-old guy.

- **The "SHOP MEN" link is tiny.** It's right there in the nav below the hero, but on a phone it's small enough that I nearly missed it. If you know I'm a guy, lead with men's content.
- **DSW isn't Skechers.** I'm loyal to Skechers. DSW has to work harder to get my attention, and showing me women's shoes on a one-day deal isn't the play.
- **The preview text is a mess.** It starts okay — "It's a good day to get new shoes" — but then it's just a wall of blank space characters filling up my inbox preview. Looks broken.
- **Tiny product images on mobile.** That 3x3 grid of shoes is going to be postage-stamp sized on my phone. I can't tell what I'm looking at without zooming in, and I'm not going to bother.

### 3. Rendering & Accessibility

**`http-equiv` missing on two `<meta>` tags** — both will be ignored by some parsers:

```html
<!-- Present (broken) -->
<meta content="text/html; charset=utf-8" />
<meta content="IE=Edge" />

<!-- Required -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```

**Duplicate, conflicting `-ms-text-size-adjust` in the `*` reset:**

```css
* {
  -ms-text-size-adjust: 100%;   /* declared first */
  -ms-text-size-adjust: none;   /* overrides to none — effective value */
}
```

The `none` value wins in cascade. In Outlook/IE this disables automatic text scaling entirely, which can break readability on high-DPI Windows displays.

**`Src:` capitalized in all `@font-face` blocks** — CSS property names are technically case-insensitive per spec, but several email client CSS parsers (notably older Gmail Android, Samsung Mail) handle `@font-face` strictly and may silently drop the font load:

```css
/* All 10 @font-face blocks have this: */
Src: url("https://braze-images.com/...") format('woff');
/* Should be: */
src: url("https://braze-images.com/...") format('woff');
```

**No `.woff2` format declared** for any font — `.woff` only for Futura_PT, `.ttf` only for HelveticaNow. `.woff2` is ~30% smaller and supported in all clients that support web fonts in email. Minor bandwidth issue.

**`<title>DSW</title>`** — minimally descriptive; some clients (Apple Mail, Thunderbird) surface this as the tab/window label. Low priority.

**Alt text on images**: Cannot audit — body is truncated before `<img>` tags.
