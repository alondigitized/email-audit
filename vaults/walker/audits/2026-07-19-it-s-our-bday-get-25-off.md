# IT’S OUR BDAY: GET 25% OFF 🥳
**Score:** 9/10 · **Type:** Email audit · **2026-07-19**
## What's working

- **25% off is actually a step up.** After six or seven straight 20%-off emails this week, this one moves the number — that registers immediately on a guy like me who's been trained to look for the discount first.
- **The discount is the hero and it lands fast.** Big blue circle, "25%" front and center — I don't have to hunt for it or read fine print to know what I'm getting.
- **Code is right there and it's memorable.** CANDLES. Birthday themed, easy to type, not buried. I didn't have to click through just to find out what the code was.
- **"TODAY ONLY" badge gives the urgency real footing.** Especially after all the "ends tonight!!!" subject lines that clearly didn't end tonight — the badge combined with "1-Day Only" in the sender name actually feels like it means something this time.
- **Wide Width and Wide Calf buttons in the size section** — that's the first time in this week's DSW barrage that I've seen something that feels like it was put there for someone with my foot shape. Good instinct, just buried too deep.

## What's weak

- **The whole design reads female, not male.** Pink balloons, confetti, birthday-party pastels — nothing about this visual palette says "we're talking to a 62-year-old guy shopping for walking shoes." The MEN tab is in the nav but there's no male signal anywhere in the creative.
- **Zero comfort language.** Not one word about cushioning, arch support, memory foam, slip-resistant outsoles — nothing that maps to why I actually buy shoes at DSW versus buying them at a department store.
- **The birthday charity section feels disconnected.** I appreciate a brand that gives back, genuinely. But "round up at in-store checkout" doesn't help me at all — I'm clicking from my phone, I'm not driving to a store. It's a nice thought dropped in the wrong channel.
- **No product imagery at all.** The whole above-the-fold section is typography and a balloon illustration. After seven emails from DSW this week, I've never seen a single shoe they actually sell. Show me what I'm buying.
- **Cadence fatigue is still real.** Even a better email can't fully undo what seven near-identical sends in one week did to my goodwill toward this brand.

## Recommendations

- 1. **Show me a shoe.** Put one or two actual men's comfort shoes in the hero — something with visible cushioning or wide-width callout. I don't need a party graphic; I need to see what I'm buying at 25% off.
- 2. **Add one comfort-specific line under the offer.** Something like "Works on wide-width walkers, memory foam, and our best arch-support styles." That one sentence would have me scrolling faster than any balloon.
- 3. **Move Wide Width higher.** The Shop by Size section is great — Wide Width especially — but it's buried below the charity ask. For a guy like me that's the first question I have about any shoe. Lead with it.
- 4. **Drop the sender name gimmick.** "DSW 1-Day Only" as the sender name is fine once; after the fifth email this week from a fake "1-Day Only" sender, I'm reading it as noise. Use the real sender name and let the subject carry the urgency.
- 5. **The charity ask belongs in a dedicated send.** The DSW Foundation $20,000 goal is a good story. Wedging it between a discount CTA and a size grid makes both feel cheap.
- **Subject Alt A:** `DSW turns 35: Take 25% off today only`
- **Subject Alt B:** `Birthday sale — 25% off, code CANDLES, one day`
- **Preheader Alt A:** `Biggest discount of the week — grab it before midnight`
- **Preheader Alt B:** `25% off men's, women's, and wide-width styles today`

### 3. Rendering & Accessibility

**[HIGH] `Src:` capital-case in all 10 `@font-face` declarations**
All font-face blocks use `Src:` instead of the spec-required lowercase `src:`. While most CSS parsers are case-insensitive, this is non-standard and will fail any strict validator or linter, and may cause font-load silently dropping in edge-case email clients.

```css
/* All 10 blocks — example: */
@font-face { font-family: 'Futura_PT_Regular'; Src: url("https://braze-images.com/...") }
```

**[MEDIUM] Invalid CSS property `supported-color-schemes` in `:root`**
```css
:root {
  color-scheme: light dark;
  supported-color-schemes: light dark;  /* not a CSS property — silently ignored */
}
```
`supported-color-schemes` is an Apple proprietary `<meta name>` value, not a CSS property. The declaration does nothing in any email client. The corresponding `<meta name="supported-color-schemes">` tag is correct. Remove the CSS line.

**[MEDIUM] HelveticaNow fonts served as TTF, not WOFF**
Futura PT fonts use `.woff` (compressed). All 6 HelveticaNow fonts use `.ttf` — roughly 2–3× larger, adding unnecessary load time per file.

```
https://braze-images.com/.../original.ttf?1755182939
```

**[LOW] Cache-busting timestamps on HelveticaNow font URLs**
The `?1755182939` query string means fonts bypass HTTP cache on each deploy if the timestamp changes. If Braze regenerates these per-send, fonts will re-download every email open.

### 5. Compliance (CAN-SPAM / Authentication)

**[HIGH] Two `<meta>` tags missing their `http-equiv` attribute**

```html
<!-- Missing http-equiv="Content-Type" -->
<meta content="text/html; charset=utf-8" />

<!-- Missing http-equiv="X-UA-Compatible" -->
<meta content="IE=Edge" />
```

Without `http-equiv`, neither declaration is semantically meaningful to the parser. The charset declaration may not be recognized by some older clients, risking encoding failures. The IE compatibility target is fully disabled without it.

Correct forms:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```
