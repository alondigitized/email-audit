### 3. Rendering & Accessibility

**`@font-face` declarations have no `src:` property**
All nine `@font-face` blocks are structurally invalid — they declare a family name but provide no font file source. Custom typefaces (`proxima-nova`, `linotype-didot`, etc.) will never load. Clients will silently fall back to `Arial` / `Times New Roman`.

```css
@font-face {
  font-family: proxima-nova, sans-serif;
  font-weight: 700;
  font-style: normal;
  /* no src: — invalid */
}
```

**Duplicate `.bg1` definition with conflicting values**
```css
/* declaration 1 — near top of <style> */
.bg1 { background-color: #ffffff; }

/* declaration 2 — later in same <style> block */
.bg1 { background: #58546d; }
```
The second declaration wins by cascade order. Any element using `.bg1` expecting white (`#ffffff`) will render as dark purple (`#58546d`).

**Malformed IE compatibility meta tag**
```html
<meta content="IE=edge" />
```
Missing the required `http-equiv="X-UA-Compatible"` attribute. This directive is silently ignored by all rendering engines.

**Mixed DOCTYPE + XHTML namespace**
```html
<!DOCTYPE html PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" ...>
<html xmlns="http://www.w3.org/1999/xhtml" ...>
```
HTML 4.01 Transitional with an XHTML namespace is an inconsistent combination. Some parsers enter quirks mode; the safest fix is `<!DOCTYPE html>`.
