## Technical Audit

## 1. Technical Summary
Email renders via a standard responsive HTML table/media-query template with correct MSO/Outlook and Gmail-specific resets; primary technical issues are mixed-content (HTTP) asset sources and missing alt attributes, both confirmed by QA output.

## 2. Link & Tracking Issues
- Open-tracking pixel present and correctly formed: `https://click.crocs-email.com/open.aspx?HJ6ZBHEJWHREFO72IGIKDYGHAQ.10198&d=10198&bmt=0` (1x1, hidden via `height:1px;overflow:hidden`).

Using both `display:none` and `visibility:hidden` on a tracking pixel is redundant but not a functional bug.
- QA flagged 34 tracking/click-redirect links as skipped from HTTP probing (info-level, expected behavior for redirect domains — no destination validation was possible from this pass).

## 3. Rendering & Accessibility
- 7 images missing `alt` text or served over plain HTTP:
  - `demandwarecrocs.demdex.net` tracking pixel — missing `alt` (acceptable; decorative/tracking-only).
  - 4x recommendation images (`10745993.recs.igodigital.com/rr/v2/.../i/1-4/...`) — missing `alt` text, meaning screen-reader users get no context for recommended products.
  - App Store, Google Play, Find Your Store, Instagram, Facebook, TikTok, YouTube icons (6 images) served via `http://image.crocs-email.com/...` — non-HTTPS sources risk being blocked by mail clients enforcing mixed-content/TLS policies (e.g., Outlook, some webmail), which would leave the footer nav/app-badge icons broken for a subset of recipients.

## 4. Personalization & Merge Tokens
- No unresolved merge tags (e.g., `{{first_name}}`) found in the visible/truncated markup.
- The 4 recommendation-block image URLs embed the recipient's raw email address in plaintext as a URL path segment (`.../i/1/walker@agentmail.to?category=Recommended for You`). This transmits PII unhashed in a GET request/image src, which will also appear in server logs, browser history, and any CDN/proxy along the path — recommend hashing or tokenizing the identifier instead of sending raw email addresses in image URLs.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- Truncated HTML does not include the footer, so unsubscribe link and physical mailing address cannot be confirmed — flag for manual verification against the full source rather than treated as a defect.
- No SPF/DKIM/DMARC header data was provided in this payload, so authentication cannot be assessed from available evidence.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- All CTA/product links route through `click.crocs-email.com` redirect infrastructure (consistent with the 34 skipped tracking links); actual destination UTM parameters and landing-page alignment cannot be verified without following redirects, which QA intentionally skipped.

## 7. Recommendations
1. Add descriptive `alt` text to the 4 `igodigital.com` recommendation images (e.g., product name) for screen-reader accessibility — currently null/absent per QA.
2. Migrate the 6 HTTP-only asset URLs (app badges, social icons, store-locator icon) on `image.crocs-email.com` to HTTPS to prevent client-side blocking.
3. Replace raw email address in recommendation-image URLs with a hashed/opaque subscriber ID to avoid transmitting PII in plaintext GET requests.
4. Obtain and review the full (non-truncated) HTML footer to confirm unsubscribe link and CAN-SPAM postal address are present before sign-off.
