## Technical Audit — Shoe Carnival "Fresh Deals on All Things SPRING" 

### 1. Technical Summary

### 2. Link & Tracking Issues
**Cannot fully assess** — source is truncated before any `<a href>` tags with destination URLs appear. Flag for full-source re-audit.

**Potential concern (from CSS):** The global rule `a, a:link, a:visited, a:hover, a:active { color:inherit !important; }` overrides all link colors unconditionally. If click-tracking redirects rely on standard `:visited` state or any JS-side color signal, this suppresses it silently.

---

### 3. Rendering & Accessibility

**Issue — Malformed charset meta tag:**
```html
<meta content="text/html;" charset="utf-8" />
```
`content="text/html;"` is incomplete (truncated MIME type with no charset value in the `content` attribute). The standalone `charset="utf-8"` attribute is an HTML5 construct but is being mixed with an XHTML/HTML4 legacy pattern. Use one or the other:
- HTML5: `<meta charset="utf-8">`  
- Legacy: `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">`

**Issue — Missing `http-equiv` on IE meta tag:**
```html
<meta content="IE=edge" />
```
Without `http-equiv="X-UA-Compatible"`, this tag is inert. Outlook 2007–2016 will not receive the edge-rendering directive.

**Issue — `<title>` element absent.** Required by HTML spec; some spam filters flag its absence.

**Issue — Dark mode explicitly blocked:**
```html
<meta name="color-scheme" content="light" />
<meta name="supported-color-schemes" content="light" />
```
Apple Mail and newer Outlook versions respect this and will not apply dark-mode overrides. If the email has white-on-white or light-background sections with no dark-mode fallback, this is intentional and acceptable — but it should be a documented decision, not a default.

**Minor — Four separate `<style>` blocks** in `<head>`. Not broken, but some older webmail clients cap the number of parsed style blocks. Consolidation reduces risk.
