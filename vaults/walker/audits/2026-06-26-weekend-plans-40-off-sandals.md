### 3. Rendering & Accessibility

**`<meta>` charset missing `http-equiv`**
```html
<!-- Current (invalid) -->
<meta content="text/html; charset=utf-8" />

<!-- Required -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv="Content-Type"`, Outlook and older WebKit clients may not honor the charset declaration, risking mojibake on special characters (e.g., the `🤝` in the subject line or any accented brand names).

**`@font-face` uses `Src:` (capital S) — invalid CSS**
All 10 `@font-face` blocks declare `Src:` instead of `src:`. CSS property names are case-sensitive in strict parsers. Gmail's CSS inliner and some Lotus Notes clients will silently drop the rule, falling through to system fonts earlier than intended.

**`text-size-adjust` conflict in global reset**
```css
* {
  -ms-text-size-adjust: 100%;
  -webkit-text-size-adjust: 100%;
  text-size-adjust: none;   /* ← contradicts the two lines above */
}
```
The unprefixed `text-size-adjust: none` disables auto-resizing entirely, which can make body copy unreadably small on mobile clients that honor the unprefixed property (modern Firefox, some Samsung Mail builds) while the prefixed `100%` values are overridden.

**Font format coverage is narrow**
- Futura PT: `.woff` only — no `.woff2`. Modern clients prefer `.woff2`; `.woff` is the fallback.
- HelveticaNow: `.ttf` only — no `.woff`/`.woff2`. TTF loads slower and is blocked by some corporate proxies.

Neither set provides a `format()` fallback chain, so a client that can't parse the single declared format gets no custom font at all.

**`<title>` is generic**
```html
<title>DSW</title>
```
Some webmail clients (Yahoo Mail, Outlook.com) surface the `<title>` as a tooltip or tab label. A subject-aligned title (e.g., `40% Off Sandals — DSW`) improves accessibility for screen reader users opening the email in a browser.

**Near-black color values (`#000001`, `#00000F`)**
These are intentional — a well-known Apple Mail dark-mode inversion workaround. Not a bug.
