### 3. Rendering & Accessibility

**Issue 1 — `maximum-scale=1` blocks zoom (WCAG 1.4.4)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
This prevents pinch-zoom on mobile, failing WCAG 1.4.4 (Resize Text). Should be removed or changed to `maximum-scale=5`.

**Issue 2 — Invalid CSS property casing in all `@font-face` blocks**
```css
Src: url("https://braze-images.com/...") format('woff');
```
`Src:` with a capital `S` is invalid CSS. Most browsers auto-correct it, but strict parsers (some older Outlook WebView instances) will drop the declaration entirely, causing silent font fallback. All 10 `@font-face` blocks are affected. Should be lowercase `src:`.

**Issue 3 — Duplicate conflicting `text-size-adjust` declarations**
```css
*{
  -ms-text-size-adjust: 100%;   /* set first */
  ...
  -ms-text-size-adjust: none;   /* immediately overrides */
  text-size-adjust: none;
}
```
The first `-ms-text-size-adjust: 100%` declaration is dead code — overridden two properties later in the same rule. Net effect is `none` on all three vendor variants, which is the intent but the redundant declaration adds confusion and should be cleaned up.

**Issue 4 — `supported-color-schemes` used as a CSS property (invalid)**
```css
:root {
  color-scheme: light dark;
  supported-color-schemes: light dark;   /* not a valid CSS property */
}
```
`supported-color-schemes` is only valid as an HTML `<meta>` name attribute (already correctly present in the `<head>`). As a CSS property it is silently ignored by all browsers. This is dead code.

**Issue 5 — Web fonts served via third-party CDN with no fallback versioning**
All font files (`braze-images.com/appboy/communication/assets/font_assets/...`) are hosted on Braze's CDN. The Futura PT files have no cache-busting query strings; the HelveticaNow files do (`?1755182939`). Inconsistency aside, any CDN availability issue at `braze-images.com` silently falls back to system fonts — acceptable but worth noting as a dependency.
