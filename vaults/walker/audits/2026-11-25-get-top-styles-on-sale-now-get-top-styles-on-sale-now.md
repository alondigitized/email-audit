## Technical Audit

## 1. Technical Summary
The email renders from a reusable template with a few leftover template artifacts (placeholder background URL, generic `<title>`, a duplicated subject phrase). The automated QA run found 0 hard failures and 2 warnings. Several items can't be verified, because the HTML was truncated and the headers weren't captured.

## 2. Link & Tracking Issues
- **Placeholder asset in CSS:** `.bgwhite {background-image: url('http://image.XXXXX.png');}` points to a non-existent host over plain `http://`. Any element using `.bgwhite` will request a dead URL, and some clients will flag it as mixed or insecure content.
- **Probe coverage:** 12 links were probed and 23 were skipped, and no failures were reported. Footer, utility and social links weren't checked, so their health is unconfirmed.
- **Tracking pixel:** `https://link.email.newbalance.com/mo/egR1f966kc_818512772_12734076_127910_24046257.gif` is a standard open-tracking pixel. It is not a defect, but see its missing alt text in section 3.

## 3. Rendering & Accessibility
- **Missing alt text (3 images, from QA):**
  - `ShippingIcons_06.png`
  - `ShippingBanner_DarkMode_03.png`
  - the tracking GIF `egR1f966kc_…gif`

  The two shipping images likely carry content (shipping offer and icons), so screen readers and image-blocked clients get nothing. The tracking pixel should have `alt=""`.
- **Template path reuse:** The shipping images come from `/custloads/818512772/NBUS/myNB_Welcome/UpdatedImages/`, a welcome-program asset folder. Stale or shared assets can break if that folder is reorganized.
- **`<title>`:** It reads "New Balance Template", an unpopulated placeholder. It shows in the web-view and browser tab and in some accessibility tools.
- **Invalid meta tag:** `<meta content="IE=edge" />` has no `http-equiv`, so it does nothing.
- **CSS issues:**
  - `.bg1` is defined twice, first as `#ffffff`, later as `#58546d`. The later rule wins, which is probably unintended.
  - Many `@font-face` blocks have no `src`, so they are no-ops. Web fonts (`proxima-nova`, `linotype-didot`) will fall back to Arial or Times New Roman in clients without the system fonts.
  - The HTML 4.01 Transitional doctype is paired with an `xmlns` attribute, which is a mismatch.
- **Dark mode:** `color-scheme` meta tags and a `prefers-color-scheme` block are present, which is correct. The source is truncated, so the rest of the dark-mode rules couldn't be audited.
