## Technical Audit

## 1. Technical Summary
The email builds and tracks its links correctly (Cordial-wrapped, UTM-tagged, JWT-signed), but the probe flagged all 12 links tested as failed, and it has no plain-text part, 16 images with no alt, and several malformed head and CSS declarations. The uniform 406/403 pattern points to the link checker being blocked, not to 12 separately broken pages.

## 2. Link & Tracking Issues
- **Probe failures:** 11 of 12 links returned **406**, including the logo, all 3 hero banners, 6 product tiles and the `hoka.com/en/us/return-start/` link. The Unsubscribe link (`/c2/…/edbbbd82`) returned **403**. Every failing URL is on `e.emails.hoka.com/c2/1664:…`. Because the status is the same across all of them, this looks like a WAF or user-agent block on the tracking domain, not a dead destination. The final landing pages were not verified, so treat these as unconfirmed, not confirmed breakage.
- **Token validity unconfirmed:** the JWT payload (`jwtP`) decodes to `{"iat":1792711785,"cd":".emails.hoka.com","ce":86400,"tk":"hoka",…}`. I can't tell from the data whether `ce` is a 24-hour link expiry. If it is, links would fail after one day.
- **Redundant links:** hero banners `_a`, `_b` and `_c` all resolve to `https://www.hoka.com/en/us/walking-shoes/` with identical parameters. The wrapped links have different IDs (`a8ef9472`, `a0801063`, `d5ecd9bc`), so clicks are tracked separately by ID. They can't be told apart in downstream analytics, though, because there is no `utm_content`.
- **Coverage gap:** 16 links were skipped by the prober (footer and social), so they are unverified.

## 3. Rendering & Accessibility
- **Alt text:** 16 images have no alt (`WARN`).
  - Content images: `US_20261022_WalkingFallFavorites_a/b/c/d.jpg`, the 6 product tiles, `US_20261026_IDme_d.jpg`, `US_Q3_ShoeFinder_Blue.jpg` and `LogoFooterPrimary.png`.
  - Because the product and hero images are the link content, screen readers get only the filenames as link names (the checker shows `[image: …jpg]`).
  - The two tracking pixels (`e.emails.hoka.com/o/p/…` and `mg.emails.hoka.com/o/…`) should carry `alt=""`.
- **Duplicate viewport tags:** there are two `<meta name="viewport">` tags with conflicting values: `maximum-scale=1` and `user-scalable=yes`. `maximum-scale=1` restricts pinch-zoom, which is a WCAG 1.4.4 concern.
- **Charset declaration:** `<meta content="text/html; charset=utf-8" />` has no `http-equiv="Content-Type"` or `charset=` attribute, so it declares nothing.
- **Empty title:** `<title></title>` is empty.
- **Invalid CSS:** the `.nav_padding` and `.nav_border` rules contain empty values (`padding-top:px`, `padding-bottom:px`, `border-top:px solid ;`). They look like template variables that never resolved. Clients ignore them.
- **Focus outline:** the global reset `* {…outline:none}` removes focus outlines, which hurts keyboard navigation in clients that support it.

## 4. Personalization & Merge Tokens
- The visible portion shows no unresolved `{{ }}` or `%%` tokens.
- The empty-valued CSS above (`padding-top:px`) suggests an upstream variable substitution that returned blank.
- The HTML was truncated, so body and footer tokens could not be fully checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Plain-text part (FAIL):** the text version is 0 characters, so there is no `text/plain` alternative. This is a deliverability and accessibility issue.
- **Authentication:** SPF, DKIM and DMARC status is unknown (`Authentication-Results` not found; the relay strips or doesn't expose it). This is a tooling gap, not a confirmed failure.
- **Unsubscribe:** an Unsubscribe link exists and points to `options.hoka.com/unsubscribe?cid=…`, per the decoded `linkUrl`. The prober got a 403, which is most likely bot-blocking. Whether a `List-Unsubscribe` or one-click header is present can't be verified from the supplied data.
- **Physical address:** not visible in the truncated source, so it is unverified.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **UTM structure:** every decoded `linkUrl` carries `utm_source=US_Broadcast`, `utm_medium=email` and `utm_campaign=H_US_BR_20261022_Walking_FallFavorites_STO_A120Day_180Purchasers_270WalkingTag_AIPurchasePropensityHigh_AIAOVHigh_AIUnsubLow`. There is no `utm_content` or `utm_term`, so you can't tell which banner or tile drove a click.
- **Segmentation in the URL:** the campaign string exposes audience logic (purchaser windows, AI propensity and AOV tiers, "AIUnsubLow") to anyone who sees the landing URL.
- **Hashed email in the URL:** each URL also carries `hmail=9153f33fe5cdf59baf088bb835d3b39ef90f188bd8540a4fabа92899227ced00` (a 64-character hex value, likely a SHA-256 of the email address) and `cordial_id=69e560485cc95da09e001cd9`. A hashed email in a visible query string is a privacy concern, because it can be matched against known emails.
- **Landing pages:** the banners go to `/en/us/walking-shoes/`. The product tiles go to PDPs: Arahi 9 `1176570`, Arahi SR `1168712` (`dwvar_…_color=ARDD`), Clifton 11 `1176573` (`BNNN`, `Regular`), Clifton 11 GTX `1176574` (`VYBR`) and Bondi 9 `1162012` (`WKP`) / `1162011` (`FDNV`). The color and width variants are pre-selected, which is correct.
- **Category paths:** the paths are inconsistent: Arahi 9 and Clifton 11 use `…-everyday-running-gear/…`, while Bondi 9 uses `…-everyday-running-shoes/…`. Confirm these resolve and aren't redirecting.

## 7. Recommendations
1. Re-probe the tracking URLs with a browser-like user agent, or resolve the `linkUrl` destinations directly, to separate probe blocking from real failures. Confirm what `ce:86400` means for link lifetime.
2. Add a `text/plain` alternative with the key links and the unsubscribe URL.
3. Add descriptive alt text to the content images (for example "Arahi 9 in …") and `alt=""` to the tracking pixels and any decorative images.
4. Remove the duplicate viewport tag and drop `maximum-scale=1`. Fix the charset tag (`<meta charset="utf-8">`), fill in `<title>`, and remove or default the empty CSS values.
5. Add `utm_content` per slot (hero_a, hero_b, tile_arahi9, and so on). Consider dropping segmentation details from `utm_campaign` and the `hmail` parameter from landing URLs.
6. Verify `List-Unsubscribe` / `List-Unsubscribe-Post` headers, SPF/DKIM/DMARC alignment on `emails.hoka.com`, and the physical address on the full, untruncated message.
