## What's weak

- **Hero image is wrong for me.** Two lavender-toned women's sneakers, shot overhead. I'm a dude. I kept scrolling looking for men's shoes.
- **Subject line isn't for me.** I'm retired. "Teachers & students" doesn't register as anything but a message addressed to someone else. I'd never open this.
- **No prices visible anywhere.** I'm price-conscious. Show me a number — even a rough discount percentage — so I know whether it's worth my time.

- **I don't have a relationship with HOKA.** This email treats me like I already love the brand. I don't. There's no "here's why HOKA is for you" moment anywhere.

### 3. Rendering & Accessibility

**`outline:none` on wildcard selector** — `* { outline:none; }` in the global reset removes focus rings from all interactive elements, including links and buttons. This breaks keyboard navigation and violates WCAG 2.1 SC 2.4.7.

**Duplicate `<meta name="viewport">` declaration** — Two viewport tags present in `<head>`:
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
The second tag contradicts the first (`user-scalable=yes` vs implicit `no`). Some clients apply the last declaration; behavior is inconsistent. Consolidate to one.

**Malformed charset meta** — Missing `http-equiv` attribute:
```html
<!-- Found -->
<meta content="text/html; charset=utf-8" />
<!-- Should be -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, older Outlook and Lotus Notes versions may ignore the charset declaration.

**Empty `<title>` element** — `<title></title>` renders as blank in Apple Mail's subject preview and is announced as empty by screen readers. Should contain a meaningful string (e.g., the subject line).

**Adobe Typekit fonts will not load in major clients** — The `@import` from `p.typekit.net` and all `@font-face` declarations loading from `use.typekit.net` are blocked in Gmail (strips `<style>` blocks), Outlook for Windows (ignores web fonts entirely), and Samsung Mail. No system font fallback stack is visible in the truncated source. If the fallback is not explicitly declared, clients will fall back to Times New Roman or serif defaults.

**Typekit kit last_published date is 2022-03-23** — The embedded comment `{"last_published":"2022-03-23 22:26:23 UTC"}` indicates the font kit has not been refreshed in ~4 years. Typekit kits with stale publish dates can break silently if Adobe rotates CDN URLs or the kit is deactivated.
