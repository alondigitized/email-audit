## Technical Audit

## Technical Summary

The skechers.com mobile journey has three overlapping problem clusters: (1) Kasada bot-protection rate-limiting that is blocking real user cart requests, (2) 17 axe violations including two critical/serious structural ARIA failures and a fully broken View Cart document, and (3) an extreme third-party script payload that will destroy LCP/TTI despite good TTFB numbers. The cart page returning HTTP 429 is the most immediately business-critical issue.

---

## Accessibility

**Critical**
- `aria-required-parent` (Homepage): ARIA roles requiring a parent container role (e.g., `option`/`listbox`, `row`/`rowgroup`) exist outside that parent. This breaks screen reader interaction model entirely for the affected widget.

**Serious**
- `aria-hidden-focus` (Homepage): Elements with `aria-hidden="true"` remain in the tab order. Keyboard users land on content that is announced as invisible — creates a disorienting no-op focus trap.
- `link-name` (Homepage): One or more `<a>` elements have no accessible name (no text content, no `aria-label`, no `aria-labelledby`). Likely icon-only nav links.
- `document-title` (View Cart): The cart view is served or rendered without a `<title>`. This indicates either a bare SPA shell, an iframe without its own `<title>`, or a server-side template omitting the element.
- `html-has-lang` (View Cart): `<html>` has no `lang` attribute on the cart page — same root cause as above; cart is rendering a structurally different document.

**Moderate**
- `heading-order` (Homepage): H-level sequence is non-linear (e.g., H1 → H3 → H2). Likely caused by component-driven layout where heading levels are hardcoded per component rather than derived from document position.
- `landmark-main-is-top-level` / `landmark-no-duplicate-main` / `landmark-unique` (Homepage): Multiple `<main>` elements present. Indicates deeply nested components injecting their own landmarks, or a CMS/personalization layer (Monetate) injecting page fragments with landmark elements.
- `landmark-complementary-is-top-level` (Homepage, Search): `<aside>` elements nested inside `<main>` or other non-top-level containers.
- `landmark-one-main` / `page-has-heading-one` (View Cart): Cart page has no `<main>` and no `<h1>`. Reinforces that the cart renders as a structurally skeletal document.
- `region` (Homepage, Search): Content exists outside any landmark region.

---

## SEO

- **View Cart missing `<title>`**: A cart URL indexed without a title will surface as untitled in SERPs. Low crawl priority but worth fixing for canonical cleanliness.
- **View Cart missing `lang`**: Hreflang inference and language detection by crawlers will fail for this URL.
- **`G-1234567890` GA property ID** firing in production alongside real IDs (visible in HTML source): This is a test/placeholder Google Analytics property ID (`G-1234567890`). It will pollute no real dataset but signals a GTM misconfiguration — a stale tag that should be removed before it's reused for something unintended.
- **Duplicate script tags** on Men category: `https://tags.creativecdn.com/dhGobFICKSkk6J9nvQPw.js` appears twice. Yahoo `ytc.js` (`vice-managed-src`) loads twice on multiple pages. Duplicate tag firing inflates analytics event counts and wastes render-blocking budget.
- **Heading hierarchy**: Non-sequential heading order on Homepage affects crawlers' ability to infer content structure.

---

## Performance

**TTFB** is excellent across most steps (26–32ms), indicating strong CDN edge caching. The exception is **View Cart at 141ms** — a 4–5× spike vs. other pages, consistent with the observed 429 on `/cart/` triggering a retry cycle or fallback path before serving the page.

**LCP and CLS were not captured** — the most impactful Web Vitals are missing from this audit. TTFB being fast does not indicate good LCP; script parse time dominates.

**Third-party script payload (homepage `<head>`)** — partial count from truncated source:

| TikTok pixel | 3 (events.js + identify + main chunk) |

Conservative estimate: **20–30 third-party script fetches** on first load, many from cold origins not covered by the two `dns-prefetch` hints (`d.monetate.net`, `sb.monetate.net`). This will produce significant LCP delays on mobile regardless of TTFB.

**WebFontLoader (v1.6.28 from cdnjs)**: Loads Mulish via JavaScript, which delays font availability until script executes. Standard `@font-face` with `font-display: swap` and preload hints would be faster and remove the cdnjs dependency.

**`--vh` custom property**: Set inline on `<html>` via JavaScript (`--vh: 6.640000000000001px`). This is a known mobile Safari viewport height workaround. The value is correct in principle but the fractional precision (`6.640000000000001`) indicates a raw floating-point division without rounding — harmless functionally but signals the calculation isn't sanitized.

---

## Mobile Optimization

- **`--vh` JS viewport fix**: The pattern is necessary for iOS Safari dynamic toolbar compatibility, but the implementation triggers a JS execution + style recalculation before first paint. A CSS-native approach (`svh`/`dvh` units, now supported in iOS 16+) would eliminate the JS dependency for modern devices.
- **No viewport-specific resource hints**: Only two `dns-prefetch` entries present (`monetate.net`). Given 20+ third-party origins, mobile connections (higher latency) will incur repeated DNS lookups. Critical origins (GTM, TikTok, Bloomreach) have no prefetch or preconnect.
- **Font loading on mobile**: WebFontLoader blocks on script execution. On a slow 4G connection this adds measurable FOIT/FOUT delay.

## Console & Network Errors

**429 Rate Limiting — Kasada bot fingerprint endpoint (5 hits):**
```
https://www.skechers.com/149e9513-01fa-4fb0-aad4-566afd725d1b/
  2d206a39-8ed7-437e-a3be-862e0f06eea3/fp?x-kpsdk-v=j-1.2.386
```
This is the Kasada bot protection challenge endpoint (`/fp` = fingerprint probe). Getting 429s here means Kasada's own challenge script is being rate-limited by itself or a WAF layer sitting in front of it. The JS SDK retries automatically, generating additional 429s — a self-amplifying loop. This does not block page loads directly, but it degrades Kasada's ability to issue a valid session token.

**429 on `/cart/` — conversion-critical:**
```
429 https://www.skechers.com/cart/
```
The cart page itself returned 429 during this audit session. This means real users can be blocked from viewing their cart by bot-protection misclassification. Given the Kasada fingerprint failures above, Kasada may have failed to validate this session as human, causing the WAF to block the cart request. This is a direct checkout conversion blocker.

**CORS — Stylitics stylesheet blocked:**
```
Access to CSS stylesheet at 'https://web-assets.stylitics.com/style.css?...'
blocked by CORS policy: No 'Access-Control-Allow-Origin' header
```
Stylitics is the outfit/look-builder widget. Their CDN is not sending the required CORS header for cross-origin stylesheet fetches. The widget will render unstyled or fail silently. This is a Stylitics-side configuration issue but skechers.com's integration team needs to escalate it.

**`net::ERR_FAILED`**: One unattributed resource load failure — likely cascades from the Kasada or Stylitics failures above.

## Recommendations

**P0 — Fix immediately (revenue impact)**
1. **Kasada + cart 429**: Audit the WAF rule ordering. Kasada's `/fp` endpoint should be explicitly excluded from rate-limit rules, and the cart endpoint (`/cart/`) needs a whitelist for sessions that have a valid Kasada token. Work with Kasada support to diagnose why the SDK is self-rate-limiting.

**P1 — Serious (accessibility compliance + broken functionality)**
2. **View Cart document structure**: The cart page must emit a valid `<html lang="...">`, `<title>`, `<main>`, and `<h1>`. If the cart loads via an SPA shell or iframe, ensure those elements are present in the outer document or the frame document respectively.
3. **`aria-required-parent`**: Audit the homepage component rendering ARIA roles out of hierarchy context. Fix the parent container roles or restructure markup so role/child relationships are valid.
4. **`aria-hidden-focus`**: Audit modal/overlay/carousel components. Elements with `aria-hidden="true"` must also have `tabindex="-1"` and must not contain focusable children.
5. **`link-name`**: Add `aria-label` to all icon-only links in navigation.

**P2 — High (performance)**
6. **Remove duplicate scripts**: Remove the second instance of `tags.creativecdn.com` on category pages and the duplicate Yahoo `ytc.js`. Audit GTM for stale/redundant tags including `G-1234567890`.
7. **Add `preconnect` hints** for high-priority third-party origins: GTM, TikTok Analytics, Bloomreach, Quantum Metric. Replace `dns-prefetch` with `preconnect` where connections are made immediately.
8. **Replace WebFontLoader** with native `@font-face` + `<link rel="preload" as="font">` for Mulish. Eliminates a cdnjs dependency and a JS-gated font load.
9. **Capture LCP/CLS**: Re-run this audit with Web Vitals instrumentation active. TTFB is healthy but tells nothing about render performance given the script payload.

**P3 — Medium (mobile)**
10. **Migrate `--vh` to CSS viewport units**: Use `dvh` (dynamic viewport height) with a `svh` fallback for iOS 16+, eliminating the JS-computed inline style. Keep the JS fallback for iOS 15 and below only.
11. **Escalate Stylitics CORS to vendor**: The missing `Access-Control-Allow-Origin` on `web-assets.stylitics.com` must be fixed on Stylitics' CDN configuration. Verify the Stylitics integration version is current.
