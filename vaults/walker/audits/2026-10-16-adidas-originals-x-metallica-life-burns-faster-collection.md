## Technical Audit

## 1. Technical Summary
The email has no plain-text alternative (0 chars, QA FAIL). It also loads several images over `http://` and has a malformed charset meta tag. SPF/DKIM/DMARC and the final landing URLs can't be verified from the supplied data.

## 2. Link & Tracking Issues
- **22 tracking links were not probed** (QA WARN). They go through click-redirect domains such as `click.comms.adidas.com/CI0/...`. Destination status, redirect chain and final URLs are unverified.
- **Insecure tracking-pixel candidate:** `http://click.comms.adidas.com/CI0/010201a143c21f6b-.../qskZUOR2-pQjqIAd7lf38PWeQ8vNrWyg4u8I3N-eSmo=452` loads over plain HTTP and has no alt text. This is likely the open-tracking pixel. Clients that block mixed or insecure content will not fire it, so open counts may be understated.
- **Insecure asset host:** `http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg` ("arrow") appears 6 times over HTTP. It is a single asset, so one fix covers all six.
- `<meta name="referrer" content="no-referrer">` is in the head. Most email clients ignore it. In web-view or browser rendering it would strip the referrer on click-throughs.

## 3. Rendering & Accessibility
- **Plain-text part missing (FAIL).** This hurts deliverability and leaves no fallback for text-only clients and screen readers.
- **Missing alt text:**
  - `https://dv.adidas.com/o/dd18c03f-8f0e-4623-ae9c-3fa1e078a27c?cp_tp=...` has no alt. If it is content, it needs descriptive text. If it is decorative, it needs `alt=""`.
  - The tracking pixel above has no alt. It should have `alt=""`.
- **Decorative arrow:** the "arrow" image has `alt="arrow"` and is repeated 6 times, so screen readers announce it each time. It should probably be `alt=""` if it sits next to link text.
- **Charset declaration is ineffective:** `<meta content="text/html; charset=UTF-8" />` has no `http-equiv="Content-Type"`, so it declares nothing. The `‘ ’` characters in the subject and body rely on the transport-level charset.
- **Duplicated CSS:** there are multiple `<style>` blocks, and the `@font-face` and `@media (max-width:640px)` rules are repeated almost verbatim. This adds weight and risks clipping in Gmail, which has a size limit.
- **Media query breakpoints are inconsistent:** the source uses 768px, 640px and 639px. `img {max-width:600px}` applies at `min-width:640px`, while the mobile rules start at `max-width:639px`, so behavior at exactly 640px is untested.
- The `@font-face` rules for AdihausDIN and AdineuePRO use only `local('Arial'/'Helvetica')` sources. They fall back to system fonts and are never actual webfonts.

## 4. Personalization & Merge Tokens
No issues found in the visible HTML. No unrendered tokens (`{{ }}`, `%%…%%`, `[FNAME]`) appear, but the source is truncated.

## 5. Compliance
- **Authentication:** the `Authentication-Results` header is missing (QA WARN). This is expected from the AgentMail relay, so SPF/DKIM/DMARC alignment for `us-news.comms.adidas.com` is unconfirmed.
- **Unsubscribe and address:** the truncated source and QA data show no unsubscribe link, `List-Unsubscribe` / `List-Unsubscribe-Post` headers or physical postal address, so none could be assessed. Footer CSS classes exist, but their content isn't visible.
- **Plain-text omission** also counts against bulk-sender best practice.

## 6. Email-to-Site Continuity
Not verifiable. Every click goes through a redirect domain that wasn't probed, and the truncated HTML shows no UTM parameters or destination URLs. Landing-page alignment with the Originals x Metallica collection can't be confirmed.

## 7. Recommendations
1. **Add a text/plain MIME part** with the main CTAs and the unsubscribe link.
2. **Serve all images over HTTPS.** Move `image.link.adidas.com` assets, including `b0c011a2-…jpg`, and the `click.comms.adidas.com` pixel to `https://`.
3. **Fix alt attributes:** use `alt=""` for the pixel and the arrow (or a single meaningful label), and add proper alt text to `dd18c03f-…` if it carries content.
4. **Correct the charset tag** to `<meta http-equiv="Content-Type" content="text/html; charset=UTF-8">`.
5. **Merge the duplicate `<style>` blocks** and unify the breakpoints.
6. **Re-run QA with the full HTML and raw headers.** That would let the audit check unsubscribe and `List-Unsubscribe` headers, SPF/DKIM/DMARC, and UTM parameters on the 22 tracked links by following their redirects.
