### 3. Rendering & Accessibility

**Confirmed bugs:**

**a) Duplicate, conflicting `<meta name="viewport">` tags**
```html
<!-- tag 1 -->
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<!-- tag 2 — conflicts on user-scalable -->
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
Behavior is client-defined when two viewport tags are present; the second tag's `user-scalable=yes` contradicts the intent of the first. Remove one; keep only the second (with `user-scalable=yes` for accessibility).

**b) Malformed CSS — missing values in mobile rules**
```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
.nav_border  { border-top:px solid ; }
```
Both rules have bare `px` with no number, and `border-top` has no color. These declarations are invalid and will be silently dropped by the parser. Any element using `.nav_padding` or `.nav_border` will render without the intended mobile spacing/border.

**c) Empty `<title>` tag**
```html
<title></title>
```
Not harmful, but some clients (Samsung Mail, Outlook Web) display the `<title>` value in the tab or preview pane. A descriptive value improves deliverability signals slightly.

**d) Missing `http-equiv` on charset meta**
```html
<meta content="text/html; charset=utf-8" />
```
The `http-equiv="Content-Type"` attribute is absent. Correct form:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without it, a subset of older Outlook/Lotus clients may not honor the declared charset.

**e) Dead CSS — `font-display: swap` in `@font-face`**
No email client supports the `font-display` descriptor. It is harmless but adds dead bytes across five `@font-face` blocks.

**f) Alt text on images — cannot verify (truncation)**
No `<img>` tags are visible in the supplied excerpt. All product and hero images must carry descriptive `alt` text; decorative spacer images should have `alt=""`.
