# Did you miss it? 20% off select styles
**Score:** 4/10 · **Type:** Email audit · **2026-05-02**
## Executive summary

- Well, I'll be honest — I don't remember signing up for New Balance emails, but here one is. It's a welcome email with a 20% off offer, which is decent, but the whole thing feels like it was built for a 28-year-old track athlete, not me. The dark, moody hero image, the fashion-forward product tiles, the tiny text — none of it says "Walker, we've got something for your feet." I'm a Skechers guy at heart, but I'd at least poke around if they showed me a comfortable walking shoe. Instead they're showing me woven shorts and a sneaker called the "NB Numbers Tunga Lemon 1010." I don't even know what that means.
- There's a real offer here — 20% off — but the execution buries the hook under aspirational athletic branding that doesn't speak to me. For a welcome email, this should be the moment they earn my loyalty. They didn't.

## What's working

- **The offer is clear.** "20% off select styles" and a "Shop now" button — I got the point without squinting too hard. Simple and direct, which I appreciate.
- **The layout isn't cluttered.** It's clean. One hero, four products below, a footer. I know where to look.
- **"Thanks for signing up"** is a friendly, low-pressure opener. No hype, no screaming. I respect that.

## What's weak

- **Not for me, visually.** The hero is a dark, dramatic close-up of athletic gear. That's not how I think about shoes. I want to see a shoe that looks like it won't kill my feet by noon.
- **The product tiles are tiny.** Four small images stacked two-by-two on my phone screen. I can barely make out what the RC42 looks like. My eyes aren't what they were.
- **No comfort angle anywhere.** Not one mention of cushioning, support, wide widths, or anything that tells me New Balance makes shoes for real walking. I know they do — I just can't find it here.
- **The "NB Numbers Tunga Lemon 1010" name.** That means nothing to me. What kind of shoe is it? Is it comfortable? Is it a running shoe? A lifestyle shoe? I'd need to already know their lineup to care.
- **Woven Shorts in a shoe email.** Why are shorts the second product recommendation? I'm not buying shorts from an email. I opened this because of a shoe offer.
- **The fine print is very small.** There's a wall of gray legal text at the bottom. I can read it if I zoom in, but I shouldn't have to.

## Recommendations

- 1. **Show a comfort-forward shoe in the hero.** If they know I signed up (they do — they said thanks), they should show me something welcoming. A cushioned everyday walker, not an athletic editorial shot.
- 2. **Drop the apparel from the product tiles.** Shorts don't belong here. Replace with men's walking or casual shoes that look comfortable.
- 3. **Add a comfort callout.** One line — "Built for all-day comfort" or "Fresh Foam cushioning inside" — would do a lot. I need permission to believe the shoes are worth $100+.
- 4. **Make the "Shop now" button bigger.** It's readable but a little small on a phone. I've got big thumbs and I'd rather not misclick.
- 5. **Use the product names I understand.** "860 X" and "RC42" tell me nothing. Add a short descriptor line under each tile — "Everyday trainer," "Walking shoe," etc.

### 3. Rendering & Accessibility
**CSS class collision — `.bg1` defined twice with conflicting values**
```css
/* First definition */
.bg1 { background-color: #ffffff; }

/* Later definition (overrides) */
.bg1 { background: #58546d; }  /* purple-gray */
```
The second rule wins in standard cascade order, rendering any `.bg1` element purple-gray instead of white. If the first definition is intentional for a specific module, use a more specific selector or a separate class name.

**Malformed IE compatibility meta tag**
```html
<meta content="IE=edge" />
```
Missing the required `http-equiv` attribute. Correct form:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without `http-equiv`, this tag is a no-op and does not trigger IE edge rendering mode.

**`@font-face` declarations have no `src:` property**
All nine `@font-face` blocks declare `font-family`, `font-weight`, and `font-style` but omit `src:`. These rules are non-functional as written — fonts render only via fallback stack. If proxima-nova and linotype-didot are loaded via a separate `<link>` (Adobe Fonts / Typekit), that's acceptable but should be confirmed. If not, font loading is silently broken.

**Duplicate property in proxima-nova italic `@font-face`**
```css
@font-face {
  font-family: proxima-nova,sans-serif;
  font-weight: 700;
  font-style: italic;font-family: proxima-nova,sans-serif;  /* stray duplicate */
}
```
Stray `font-family` property appended after `font-style`. Harmless in most parsers but indicates a template authoring error.

**`<title>` is generic**
```html
<title>New Balance Template</title>
```
Some email clients (Apple Mail preview pane, certain accessibility tools) surface the `<title>`. This should match the subject line or campaign name, not the template placeholder.
