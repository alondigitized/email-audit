### 3. Rendering & Accessibility

**Confirmed issues:**

**Duplicate `<meta name="viewport">` tags** — Two conflicting viewport declarations in `<head>`:
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
They conflict on `user-scalable` (omitted vs. `yes`). The second tag wins in most parsers but behavior is undefined across clients. Keep one.

**Malformed mobile CSS rules** — Two rules in `@media only screen and (max-width:480px)` have missing values:
```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
.nav_border { border-top:px solid ; }
```
Both are invalid — the numeric value before `px` is absent, and `border-top` is also missing its color. CSS parsers silently discard invalid declarations, so these rules have zero effect. This is a template authoring bug, not a rendering crash, but nav spacing/borders may be broken on mobile.

**Missing `http-equiv` on charset meta** — `<meta content="text/html; charset=utf-8" />` lacks the required `http-equiv="Content-Type"` attribute. Outlook and older MSHTML-based clients use this attribute to detect encoding; without it they may fall back to system default encoding:
```html
<!-- Current (broken for Outlook) -->
<meta content="text/html; charset=utf-8" />

<!-- Correct -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

**Empty `<title>` tag** — `<title></title>` — Some clients (Samsung Mail, older Android) render the document title in preview; leaving it blank is a missed opportunity, and a few clients show "Untitled" as preview text.

**Web font fallback not confirmed** — `TheFutureHOKA` is declared via `@font-face` from `hoka.com/on/demandware.static/...`. Gmail (web + Android), Outlook (Windows/Mac), and Yahoo Mail do not support custom web fonts. The truncated source does not show fallback font stacks on body copy — confirm `font-family` declarations include safe system fallbacks (e.g., `"TheFutureHOKA", Arial, Helvetica, sans-serif`).

**`-webkit-text-size-adjust: none` on `*` selector** — The global reset applies `none` to all elements, which can suppress user-agent font scaling on iOS for non-body elements. `body` correctly overrides with `100%`, but nested tables/cells may inherit `none` and resist scaling on older iOS WebKit.
