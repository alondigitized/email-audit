### 3. Rendering & Accessibility

**[HIGH] `@font-face` — incorrect `font-weight` on all named weight variants**

Every variant — Medium, Demi, Bold, BoldItalic, MediumItalic — is declared with `font-weight: normal`:

```css
@font-face {
  font-family: 'Futura_PT_Bold';
  font-weight: normal;   /* ← should be bold / 700 */
  Src: url("...original.woff") format('woff');
}
```

The browser/webmail font-matching algorithm uses `font-weight` to select the correct face. Declaring all variants as `normal` means elements styled with `font-weight: bold` will never load `Futura_PT_Bold` or `HelveticaNow_Bold` — they will fall back to the system font. This affects all webmail clients that support web fonts (Gmail, Apple Mail, etc.).

**[MEDIUM] `@font-face` — non-standard `Src:` property (capital S)**

All 10 `@font-face` blocks use `Src:` instead of `src:`. CSS property names are case-sensitive per spec. Most rendering engines are forgiving in `<style>` blocks, but this is invalid CSS and can fail in stricter parsers.

```css
Src: url("https://braze-images.com/...original.woff") format('woff');
/* should be: */
src: url("...") format('woff');
```

**[MEDIUM] HelveticaNow fonts declared as `.ttf` only**

The Futura PT family provides `.woff` (reasonable email fallback). The newer HelveticaNow family provides only `.ttf`:

```
.../689df75b1d1e1f00960f35f2/original.ttf?1755182939
```

`.ttf` has worse email client support than `.woff`. Cache-bust timestamp `?1755182939` suggests these were added recently. Should add `.woff` variants or reference existing WOFF assets.

**[LOW] `<meta>` tags missing `http-equiv` attribute**

Two meta tags omit `http-equiv`, making them semantically inert:

```html
<meta content="text/html; charset=utf-8" />
<!-- should be: <meta http-equiv="Content-Type" content="text/html; charset=utf-8" /> -->

<meta content="IE=Edge" />
<!-- should be: <meta http-equiv="X-UA-Compatible" content="IE=Edge" /> -->
```

The charset issue is mitigated by the `<!DOCTYPE>` declaration, but both are technically broken tags that waste payload bytes and may cause unexpected behavior in edge cases.

**[LOW] Futura PT fonts: `.woff` only, no `.woff2`**

`.woff2` offers ~30% better compression. Not a rendering failure, but increases load time for clients that fetch web fonts.
