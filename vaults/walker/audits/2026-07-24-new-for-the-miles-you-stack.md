# New for the miles you stack
**Score:** 7/10 · **Type:** Email audit · **2026-07-24**
## Executive summary

- Another HOKA, another Clifton PRO. I clocked it the second I saw the hero — same shoe that's been bouncing around my inbox since July 9th. At least "Just landed" gives it a new frame, and credit where it's due: the hero copy actually says "ultra-cushioned support" this time, which is the exact language that gets my attention. For a brief moment the email felt like it was talking to me.
- Then I scrolled and hit the apparel section. Some young guy with a six-pack flexing in a black tank top. Zero to do with me. I'm 62, I want comfortable shoes, and that section belongs in a different inbox entirely. The product grid is also split men's-women's with no obvious label hierarchy — I had to work a little to figure out which shoes were even for me. The Clifton PRO men's and the Mach 7 are my only options, and the Mach 7 is a speed shoe.

## What's weak

- "Miles you stack" in the subject is runner speak — I don't stack miles, I look for comfortable shoes to get through the day
- The apparel block is dead weight for a 62-year-old shoe shopper; a young athlete in a performance tank doesn't represent me at all
- The Bondi 9 is shown women's-only in the grid — the shoe I'd actually care about for cushioning has no men's representation
- Free shipping requires signing up for texts — there's a hoop to jump through, and that asterisk makes me wonder what the fine print says
- HOKA fatigue is real: this is roughly the seventh email in ten days, and the Clifton PRO has appeared in most of them

- 1. **Lead the subject with comfort, not mileage** — "miles you stack" is runner positioning; try language that matches why comfort shoppers buy HOKA
- 2. **Pull the apparel section out of this send entirely** — or move it to a separate email; it breaks the shoe-focused narrative and wastes scroll space on someone like me

### 3. Rendering & Accessibility

**[HIGH] Invalid CSS values in mobile media query:**
```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
.nav_border  { border-top:px solid ; }
```
Both rules are missing the numeric value before `px`. These will be silently discarded by CSS parsers — any element relying on `.nav_padding` for mobile spacing or `.nav_border` for a divider will render incorrectly on narrow viewports.

**[MEDIUM] Duplicate `<meta name="viewport">` tags with conflicting values:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
The first omits `user-scalable`; the second sets `user-scalable=yes`. Behavior when a client encounters duplicate viewport metas is undefined — some ignore the second, some merge. Remove one; the canonical version should be the second (with `user-scalable=yes` for accessibility compliance).

**[MEDIUM] Empty `<title>` element:**
```html
<title></title>
```
Several email clients (Samsung Mail, some Outlook versions) use the `<title>` tag as preview or tab text. Screen readers also surface it. Should be set to a meaningful string (e.g., the subject line).

**[LOW] Universal `border:none` CSS reset:**
```css
* { border:none; }
```
Applying `border:none` to every element globally can strip table borders used for layout spacers or dividers in Outlook. Standard practice is to scope border resets to `img, a, table, td` rather than `*`.

**[LOW] Near-black link color with no underline:**
```css
a { text-decoration: none; color: #000001; }
```
`#000001` is visually indistinguishable from black body text. With `text-decoration: none`, sighted users cannot identify links without hovering. CTA buttons typically override this inline, but any plain-text anchor in the body (e.g., footer links) will be invisible as links.
