### 3. Rendering & Accessibility

**Duplicate `<meta name="viewport">` tag** — Two viewport declarations are present:
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
The second declaration also contradicts the first (`user-scalable=yes` vs. implicit no). Browsers will use the last one encountered; the conflict is benign in most clients but indicates a template assembly error.

**Empty `<title>` tag:**
```html
<title></title>
```
Some email clients (Gmail web, Apple Mail) surface the `<title>` in tab labels or preview panes. An empty title is a missed branding touch but not a rendering blocker.

**Missing `http-equiv` on charset meta:**
```html
<meta content="text/html; charset=utf-8" />
```
Should be `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />`. Without `http-equiv`, some older Outlook/Lotus clients may not honor the encoding declaration, risking character corruption on special characters (e.g., the ® symbol in the sender name).

**Aggressive CSS reset — `border:none` on `*`:**
```css
* {margin-top:0px; margin-bottom:0px; padding:0px; border:none; outline:none; ...}
```
Applying `border:none` universally can strip visible focus indicators and button borders in clients that render interactive elements (e.g., Gmail's AMP or interactive email). Low risk for a static promotional email, but a known fragility.

**Conflicting `-webkit-text-size-adjust`:**
- `*` selector: `-webkit-text-size-adjust: none`
- `body`: `-webkit-text-size-adjust: 100% !important`

The `body` rule overrides for body text (correct behavior), but the `*` rule may affect nested elements in some WebKit clients if specificity resolves differently. The `none` value on `*` is the problematic one — `100%` is the recommended value.

**Stale Typekit kit:**
```css
/*{"last_published":"2022-03-23 22:26:23 UTC"}*/
```
The Typekit kit `hva0tmw` was last published March 2022. If the kit has since been revoked, renamed, or the associated Adobe account lapses, web font loading will silently fail and fall back to system fonts — no breakage, but worth auditing the kit's active status.
