- No render bugs — email loaded clean, images came in, text didn't overlap anything.

## What's weak

- Back-to-school notebooks in the hero image — I'm 62, New Balance, you know this. This is the same mismatch they tried on July 14th ("Class in session.") and July 17th ("We're back."). Third time I'm seeing it, still not my lane.
- Subject says "25% off your order when you spend $150+" — sounds sitewide. Fine print inside says "up to 25% off select shoes." That qualifier matters and it's not up front.
- "More to explore" gives me a skate shoe (NB Numeric Tiago Lemos), a fleece jogger, and shorts. Not one slip-on or walking shoe in plain sight.
- Seventh email in eleven days. At some point the discount stops feeling like urgency and starts feeling like wallpaper.

## Recommendations

- 1. **Swap the back-to-school hero for a comfort/walking image.** A Fresh Foam X or 1080 on a wide-load male foot, no notebooks. If the sale is real, the savings sell themselves — you don't need to dress it up as something I have zero use for.
- 2. **Make the subject and body match.** If it's "select shoes," say that in the subject. "25% off select shoes thru July 30 — shop your size" is honest and still clickable.
- 3. **Surface one specific men's comfort pick above the fold.** A single shoe card — Fresh Foam X, 860v14, anything with cushion language — with its own "Shop now" tap target. Don't make me navigate to find what's actually for me.
- 4. **Pull the price-bucket rail above "More to explore."** That's the smartest bit of navigation in the email and it's buried mid-scroll.
- 5. **Rest the list for a few days.** July has had more NB emails than I've had cups of coffee. The discount fatigue is real.

## Technical Audit

## Technical Audit — New Balance "25% off $150+" Email

---

### 1. Technical Summary

The email is built on HTML 4.01 Transitional with modern dark mode extensions and a large inline stylesheet. At least one unresolved template placeholder exists in the visible source, and a CSS class collision will silently override an intended white background with dark purple on all email clients.

---

### 2. Link & Tracking Issues

**Unresolved placeholder URL (high severity):**
`.bgwhite` contains `background-image: url('http://image.XXXXX.png')`. The `XXXXX` string is an unfilled template token. Any element using this class will render a broken background. Additionally, the scheme is `http://` — mixed-content blocking in Gmail and some clients will silently drop HTTP asset references.

**UTM parameters:** Not visible in the truncated source. Cannot confirm tracking is instrumented on CTA links. Verify before send.

---

### 3. Rendering & Accessibility

**`.bg1` class collision (high severity):**
The class is defined twice with conflicting values:
- Definition 1 (line ~10): `background-color: #ffffff`
- Definition 2 (line ~90): `background: #58546d` (dark purple/gray)

The cascade applies the second definition. Any element using `.bg1` expecting a white background will render dark purple.

**Malformed IE meta tag:**
```html
<meta content="IE=edge" />
```
Missing `http-equiv="X-UA-Compatible"`. Outlook ignores this tag without it. Correct form:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```

**Empty `@font-face` blocks:**
All `@font-face` declarations lack `src:` URLs. Without source references, these rules are no-ops — web fonts load via a separate TypeKit link tag (not present in visible source) or fall back silently to system fonts. The empty declarations add parse overhead with no benefit.

**Invalid CSS property in `:root`:**
```css
:root { supported-color-schemes: light dark; }
```
`supported-color-schemes` is a `<meta>` tag value, not a CSS property. It will be ignored. The valid CSS property is `color-scheme`, which is already correctly declared above it.

---

### 4. Personalization & Merge Tokens

`http://image.XXXXX.png` (see §2) is the only unfilled token visible in the provided source. No other unresolved merge variables (`%%`, `{{`, `*|`, etc.) are visible in the truncated HTML.

---

### 5. Compliance

**Cannot confirm from truncated source:**
- Unsubscribe link presence and placement
- Physical mailing address (CAN-SPAM §5(a)(5))
- One-click list-unsubscribe header (RFC 8058, now enforced by Gmail/Yahoo for bulk senders)

These likely exist in the unshown footer. Verify the unsubscribe link is functional and the physical address is present in plain text (not image-only).

**Sender authentication:** `email.newbalance.com` is a standard ESP subdomain — SPF/DKIM/DMARC alignment cannot be assessed from HTML source. Confirm via MX Toolbox or header inspection post-send.

---

### 6. Email-to-Site Continuity

UTM parameters are not visible in the truncated source. Confirm all CTA links carry at minimum:
- `utm_source=email`
- `utm_medium=email`
- `utm_campaign=<campaign-id>`

Confirm the landing page surfaces "25% off $150+" prominently and applies the discount automatically or via the expected promo code — offer/landing-page mismatch is the most common drop-off point for threshold-based promotions.
