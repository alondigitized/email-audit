# Full speed. The Speedgoat 2 is back.
**Score:** 5/10 · **Type:** Email audit · **2026-07-10**
## Executive summary

- I see "Full speed." in big white text over a dark hero, a product shot of a very aggressive-looking trail shoe in neon green and blue, then a guy on a dirt bike. That's the email. That's all I need to know about whether this was built for me.
- I'm 62. I walk three miles before breakfast. I need cushioning, arch support, and a shoe I can get on without sitting down. The Speedgoat 2 partnering with Simms and a motocross lifestyle — that's not my life. I don't know what Simms is in this context, and I don't need to, because the whole thing reads like an ad for someone a third my age who spends weekends on trails and weeknights watching off-road racing clips. The feature callouts — "Grip Without Compromise," "Legendary Trail Heritage," "Built to Last" — are fine things if you're running Moab. I'm not.
- On top of that, HOKA sent me "Just Landed: Clifton PRO" yesterday and I gave it a 6 because the creative felt young and fast. Now they've followed it with something even more extreme. I'm going to mark this read and move on. No click. Definitely not forwarding it.

- **HOKA brand recognition:** I know the name, I trust the shoe quality — that still counts for something even when the creative misses.
- **CTA button is clear:** "Shop Speedgoat 2" appears twice, it's a dark button on a light background, easy to tap even on my phone.
- **Product is specific:** They named the shoe, not just a category. I know exactly what they're selling, even if I don't want it.
- **No render bugs:** The layout loaded clean, text sat where it should, nothing overlapping or broken.
- **Free Expedited Shipping section at bottom:** At least they put something concrete at the end, even if it required a signup I wasn't expecting.

## What's weak

- **"Full speed" hero copy is completely wrong for me:** I'm a comfort walker, not a trail racer. That headline actively signals this email isn't mine.
- **Moto/dirt-bike imagery:** Two images of a motorcycle rider in desert terrain. That's a 30-year-old influencer's aesthetic, not mine. It pushed me away immediately.
- **Zero cushioning or support language:** Not a single mention of arch support, foam stack, or comfort — the three things that would get me to click on a HOKA shoe.
- **The Simms collaboration is unexplained:** I see the name in small text but I have no idea what it means in this context. It doesn't add anything for me.
- **Free shipping buried and conditional:** The shipping offer requires signing up for something — that's in fine print at the bottom. Don't bury the best offer.

## Recommendations

- 1. **Swap the hero for the Speedgoat's trail-to-everyday story** — if this shoe has cushioning and can be worn casually, lead with that. "Built for the trail. Works everywhere else." sells it to more of us.
- 2. **Pull the free expedited shipping offer to the top** — make it the reason I open, not a reward for surviving the scroll. Right now it reads like an afterthought.
- 3. **Replace the moto imagery with something I can see myself in** — a guy hiking a moderate trail or just walking a paved path. Not a dirt bike.
- 4. **Add one comfort spec in the feature callouts** — just tell me the foam stack or that it has a roomy toe box. Something that connects trail performance to walking comfort.
- 5. **Drop "Simms" from the hero if it needs explanation** — collaborations are only interesting when I know both names.

### 3. Rendering & Accessibility

**Confirmed issues:**

**a) Duplicate, conflicting `<meta name="viewport">` tags**
Two viewport tags appear back-to-back with contradictory values:
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
The first blocks zoom (`maximum-scale=1`); the second re-enables it (`user-scalable=yes`). Behavior is client-dependent. `maximum-scale=1` alone violates WCAG 1.4.4 (Resize Text, Level AA). The second tag should be the sole declaration, and `maximum-scale` should be removed.

**b) Malformed CSS in `@media (max-width: 480px)` block**
Two rules have missing numeric values, producing invalid CSS that will be silently dropped:
```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
.nav_border  { border-top:px solid ; }
```
The pixel values and border color are both absent. Mobile nav spacing/borders will not render as intended.

**c) Missing `http-equiv` on charset meta tag**
```html
<meta content="text/html; charset=utf-8" />
```
Without `http-equiv="Content-Type"`, older Outlook and Lotus Notes builds may not apply the charset declaration. Correct form:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

**d) Empty `<title>` tag**
`<title></title>` is blank. Some spam filters and accessibility tools penalize missing titles. Set to the subject line or a descriptive value.

**e) `mso-line-height-rule: exactly` applied globally to all `td`**
```css
td { mso-line-height-rule: exactly; }
```
Applied without an accompanying explicit `line-height` value, this setting causes Outlook to clip text that exceeds the inferred line height. Scope this only to cells where tight line control is intentional.

**f) Web font fallback risk**
`TheFutureHOKA` loads via `@font-face` from `hoka.com`. Gmail (web, Android), Outlook desktop (all versions), and Samsung Mail will not render it. The declared `font-family` stacks should be confirmed to include a robust generic fallback (`sans-serif` at minimum) in every inline style that references the custom font.
