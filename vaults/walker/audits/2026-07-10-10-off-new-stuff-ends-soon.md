# $10 off new stuff ends soon ⏲️
**Score:** 9/10 · **Type:** Email audit · **2026-07-10**
## Executive summary

- Fourth "$10 off" pitch in two days, and this time DSW decided to fill the entire email with women's heels, ballet flats, and ankle boots. I'm not kidding — scrolled the whole thing and couldn't find a single men's shoe. The hero says "Hey, what's new?" and I'm asking myself the same question, because everything I see is stilettos and strappy sandals. The "shop by category" row at the bottom? Heels, Athletic & Fashion, Sandals, Women's Shoes. The size strip? Tops out at women's sizing. I'm invisible in this send.
- To be fair, the email itself isn't broken. It's clean, loads fine, the $10 off code is right there at the top where I can see it. But DSW knows I'm a 62-year-old guy — I've been shopping their clearance rack for walking shoes for years. Sending me a women's new arrivals blast is the kind of slip that makes me wonder if anybody's actually looking at my account.
- I'd mark this read without clicking. Not going to forward it — my wife doesn't need my shoe discount code. If the $10 off applies to men's too, I'd have to go hunting for that on my own, and at my age I'm not doing extra homework for a ten-dollar coupon.

## What's working

- **Offer is front and center.** "$10 off" with the code sits at the very top — I didn't have to dig for it.
- **Subject is short and honest.** Thirty-ish characters, no caps-lock screaming, no triple exclamation points — reads clean on my phone.
- **No broken images or layout junk.** Everything loaded, nothing overlapped, the grid looks sharp.
- **Preview text did its job.** "Don't miss this one in stores & online" — tells me I can use this in a physical store too, which I actually prefer for shoes.

## What's weak

- **Wrong gender, full stop.** Every single product in this email — every hero image, every grid tile, every category label — is women's footwear. This isn't close; it's 100% miss.
- **"New stuff" tells me nothing.** I already know DSW has new arrivals. Tell me if there's something in men's comfort or walking styles that's worth my time.
- **Fourth $10 off email in two days.** The deal was fresh on July 9th. By the fourth send it's wallpaper. I'm tuning it out.
- **No comfort or fit signals.** Not one mention of cushioning, arch support, wide widths, or anything that tells me this shoe is built for a guy on his feet all day. That's all I care about.

## Recommendations

- 1. **Segment this correctly.** If DSW has my purchase history and gender on file, there's no excuse for a men's subscriber getting a women's-only new arrivals blast. Fix the audience filter first — nothing else matters until this is solved.
- 2. **Add a men's module.** Even if the campaign is women's-first, drop a "Men's New Arrivals" block at the bottom. Give me one reason to scroll.
- 3. **Name a comfort benefit in the hero.** "New styles with all-day cushioning" or "New arrivals, built for comfort" would stop my thumb from moving on.
- 4. **Retire the $10 off subject line for a day.** After four sends, rotate to something fresher — the offer fatigue is real.

### 3. Rendering & Accessibility

**`maximum-scale=1` blocks user zoom (WCAG 1.4.4)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Violates WCAG 1.4.4 (Resize Text). Should be removed or replaced with `maximum-scale=5`.

**`@font-face` uses invalid CSS property casing (`Src:` instead of `src:`)**
All 10 `@font-face` blocks use capital-S `Src:`. Technically invalid per CSS spec; email clients with strict parsers will silently skip these, causing fallback fonts to load. Not a crash, but font loading reliability is degraded.

**Contradictory `-ms-text-size-adjust` values in same rule**
```css
* {
  -ms-text-size-adjust: 100%;   /* set first */
  ...
  -ms-text-size-adjust: none;   /* overrides above */
}
```
The `none` value wins. This disables text-size adjustment on Windows Phone/older IE, which may cause small text to become unreadable. Likely unintentional — one of the two values should be removed.

**HelveticaNow fonts serve only `.ttf`, no `.woff`**
Futura PT variants serve `.woff`; the newer HelveticaNow variants (6 faces) serve `.ttf` only. Email clients that support web fonts (Apple Mail, iOS Mail) prefer `.woff`. Fallback system fonts will render for most clients regardless, but this is an inconsistency.

**Missing `http-equiv` attributes on two meta tags**
```html
<meta content="text/html; charset=utf-8" />         <!-- missing http-equiv="Content-Type" -->
<meta content="IE=Edge" />                           <!-- missing http-equiv="X-UA-Compatible" -->
```
These work in most modern clients due to loose parsing, but are malformed per spec.
