## Technical Audit — HOKA "Going, going, gone" Email

### 1. Technical Summary
Email uses Cordial ESP tracking redirects and Cordial-hosted images; automated QA shows a 67% pass rate with 3 hard failures — two 403'd tracked links and a missing plain-text MIME part — plus six images lacking alt text.

### 2. Link & Tracking Issues
- **[FAIL] Broken redirect (403)** — CTA link "hoka.com/en/us/return-start/" resolves through the Cordial click-tracker (`e.emails.hoka.com/c2/1664:...`) and returns HTTP 403. Decoded `jwtP` payload confirms the intended destination is `https://www.hoka.com/en/us/return-start/?utm_source=US_Broadcast&utm_medium=email&utm_campaign=...`. The tracking wrapper itself is failing, not necessarily the destination — this needs ESP-side verification.
- **[FAIL] Broken redirect (403)** — The **Unsubscribe** link (`e.emails.hoka.com/c2/1664:.../f72dc9bc?...`) also 403s. Decoded target is `https://options.hoka.com/unsubscribe?cid=69e560485cc95da09e001cd9&utm_source=US_Broadcast&...`. A non-functional unsubscribe link is both a UX and compliance risk (see §5).
- All probed links route through Cordial's `c2` click-tracking domain with JWT-encoded destination/params (`jwtH`/`jwtP`/`jwtS`) — standard ESP redirect pattern, no structural issue with the mechanism itself, only the 403 responses above.
- 12 material links probed, 6 skipped (footer/social/utility, deprioritized by design) — no failures reported among skipped links since they weren't tested.

### 3. Rendering & Accessibility
- **[WARN] Missing `alt` text** on 6 images, including content-bearing creative:
  - `US_HOKAHeader_Black.jpg` (header/nav)
  - `US_20260907_NewCTAAsset.jpg` (primary CTA asset)
  - `US_20260907_LaborDayPromo_b.jpg` (promo banner)
  - `LogoFooterPrimary.png` (footer logo)
  - Two tracking-pixel-style images (open-tracking pixel URL and `mg.emails.hoka.com` MailGun open pixel) — these are likely tracking pixels, so missing alt is low-severity, but the four content images above should have descriptive `alt` for screen readers and image-blocked clients.
- Responsive CSS includes malformed mobile rules: `.nav_padding {padding-top:px !important;padding-bottom:px !important;}` and `.nav_border {border-top:px solid ;}` — missing numeric values make these declarations invalid CSS (`px` with no digit), so they'll be dropped by parsers rather than applying any padding/border at the 480px breakpoint.
- Font loading uses `@font-face` with `font-display: swap` pointing to `www.hoka.com/.../fonts/*.woff2` — cross-origin font requests in email are unreliable (most clients strip `@font-face` entirely), acceptable as progressive enhancement but shouldn't be relied on for critical text legibility.

### 4. Personalization & Merge Tokens
No merge tokens (e.g. `{{first_name}}`) observed in the visible/truncated markup. No issues found.

### 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Unsubscribe link is broken (403)** — see §2. This is a functional CAN-SPAM risk: the mechanism must be operable, not merely present. Recommend immediate fix/re-test.
- **Plain-text MIME part missing** — QA reports the text/plain fallback is 0 chars. This affects deliverability scoring (many filters/ISPs penalize HTML-only multipart messages) and also means any client rendering plain text shows a blank email, including no visible unsubscribe instructions in that fallback.
- No SPF/DKIM/DMARC header data was included in the provided source/QA output, so authentication cannot be assessed from this audit — recommend pulling raw headers separately to confirm.
- Sender `info@emails.hoka.com` and unsubscribe host `options.hoka.com` are on separate subdomains from the primary `hoka.com` — consistent with typical ESP subdomain delegation, not itself an issue.

### 6. Email-to-Site Continuity (UTM params, landing page alignment)
- Destination URL carries a full UTM set: `utm_source=US_Broadcast&utm_medium=email&utm_campaign=H_US_BR_20260907_LDWMarkdown_FinalHours_MemberPromo_AllMembers_A60Day_460SaleTag_LDWAnniPurchasers_AIPriceSensHigh`. Params are present and structurally valid (no encoding errors in the decoded query string).
- Cannot confirm landing-page alignment (whether `hoka.com/en/us/return-start/` is the correct/expected page for this promo, or whether it renders correctly with these UTMs) since the destination itself is unreachable in this audit (403 via tracker). Flag for manual re-check once the redirect issue is resolved.
- Unsubscribe URL also carries `cid` and UTM params appended (`options.hoka.com/unsubscribe?cid=...&utm_source=...`) — functionally fine, just note the UTM params are unnecessary on an unsubscribe target.

### 7. Recommendations
1. **Priority:** Investigate why the Cordial `c2` tracking redirect is returning 403 for both the primary CTA and the Unsubscribe link — this is likely an ESP-side link-signing/expiry or domain-config issue affecting the whole send, not just these two links. Confirm with a live click-through test before next send.
2. Add a non-empty plain-text MIME alternative (should include unsubscribe text/link at minimum).
3. Add descriptive `alt` attributes to the four content images (header, CTA asset, promo banner, footer logo); tracking pixels can remain `alt=""`.
4. Fix malformed CSS values (`padding-top:px`, `border-top:px solid`) in the `@media (max-width:480px)` block — likely a template variable that failed to interpolate.
5. Re-verify the `return-start` landing page renders correctly with the passed UTM string once the redirect 403 is resolved.
