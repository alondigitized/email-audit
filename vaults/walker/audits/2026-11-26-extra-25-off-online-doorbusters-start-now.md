## Technical Audit

## 1. Technical Summary
The visible source is largely standard ESP boilerplate (responsive CSS, client-fix rules). The QA data shows two real defects, both in the tracking pixels: an unresolved `[UNIQUE]` token and a malformed pixel URL. The HTML was truncated, so most body-level checks (links, unsubscribe, footer) could not be verified.

## 2. Link & Tracking Issues
- **Unresolved token in a pixel URL:** `https://0di86k1v.emltrk.com/v2/0di86k1v?d=[UNIQUE]` still contains the literal `[UNIQUE]`. The per-recipient identifier was not substituted, so that open or click-tracking beacon cannot attribute to a recipient.
- **Malformed pixel URL:** `https://ieezzy5m.emltrk.com/v2/ieezzy5m?i=72180589&t=utm_campaign=SCA_20261126_thanksgiving_AM - 20261124_143955​`
  - The `t=` parameter holds a nested `utm_campaign=` assignment.
  - The value has raw spaces (` - `), which are not percent-encoded.
  - It ends in an invisible zero-width character (U+200B) after `143955`.
  - Strict parsers or proxies may truncate or reject this URL, which would drop the open event.
- **Unverified links:** 32 tracking links were skipped from the HTTP probe because they are redirect domains. Their resolution, status codes and destinations are unverified, not confirmed broken.

## 3. Rendering & Accessibility
- **Missing alt on both `emltrk.com` images:** these look like tracking pixels, so `alt=""` is acceptable. The attribute should still be present and empty rather than omitted. Low severity.
- **Malformed meta tags:**
  - `<meta content="text/html;" charset="utf-8" />` has no `http-equiv`.
  - `<meta content="IE=edge" />` has no `http-equiv="X-UA-Compatible"`, so it does nothing.
  - Both are harmless but invalid.
- **Doctype mismatch:** the HTML 4.01 Transitional doctype is combined with an `xmlns` attribute on `<html>`. This is non-critical.
- **Link styling removed globally:** `a, a:link, … { text-decoration:none !important; color:inherit !important; }` strips default link affordance. Inline-text links will not be distinguishable unless they are styled inline, which I can't confirm in the truncated source.
- **Small mobile text:** `.responsive-text { font-size: 12px !important; }` at max-width 600px is below the common 14px minimum for readability.
- `lang="en"` and the viewport meta are present, so those are fine.

## 4. Personalization & Merge Tokens
