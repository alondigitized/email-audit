## Technical Audit

## 1. Technical Summary
The email has one confirmed rendering and personalization defect: an empty first-name slot that renders as "Hi ,". The source also has a scheme-less tracking pixel URL, `http://` image sources, malformed `<meta>` tags, and missing alt text. The HTML was truncated and the click URLs were redirect-wrapped, so the footer, unsubscribe link, and UTM parameters could not be checked.

## 2. Link & Tracking Issues
- **Scheme-less pixel URL (confirmed in source):** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…">` has no `https://`. Clients resolve it as a relative path, so the request fails and the Return Path / Validity seed-tracking pixel never fires.
- **Third-party beacons:** Four `beacon.krxd.net` (Krux/Salesforce DMP) pixels sit in a hidden div. Two are `1x1_usermatch.gif` calls that pass a SHA-256 value (`partner_uid=9153f33f…ed00`) and a subscriber ID (`partner_uid=121173391`). This is not a defect, but it is third-party identifier sharing on open.
- **Insecure tracking pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=…` uses plain HTTP. It may be blocked, and where it loads it exposes `mi_u` unencrypted.
- **Unverified links:** The QA run skipped HTTP probes on all 36 tracking and click-redirect links (domains like `click.emails.skechers.com`). Link health and destinations are unconfirmed.

## 3. Rendering & Accessibility
- **Missing alt text (QA-confirmed):**
  - `dde00662-169f-447d-b0e2-fc65f6c2290c.png` has no alt. It is hosted at `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/…`, so it is a content-bearing image rather than a pixel.
  - `o.gif` has no alt. This is minor, because it is a tracking pixel.
  - The `pixel.app.returnpath.net` image also has no `alt`.
- **HTTP image sources:** The `dde00662…png` image on `image.emails.skechers.com` and `o.gif` load over `http://`. They can be blocked or flagged as mixed content in some clients, which may leave a broken image.
- **Malformed meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` lack `http-equiv`, so they do nothing.
- **Zoom restrictions:** The viewport has `maximum-scale=1`, and the CSS sets `-webkit-text-size-adjust: none`. Both limit user zoom and text resizing.
- **Missing language attribute:** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang`.
- **Layout tables:** The visible layout tables (`<table width="640" … cellpadding="0">`) have no `role="presentation"`, so screen readers may announce them as data tables. This applies to the visible portion only.

## 4. Personalization & Merge Tokens
- **Empty greeting (QA FAIL, confirmed):** The greeting renders with an empty name field ("Hi ,"). There is no fallback or default value. The token resolved to an empty string, so the send lacks a conditional or default for missing first names.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication headers:** `Authentication-Results` was not found. The QA note says it is expected through the AgentMail relay, so SPF, DKIM, and DMARC status is unknown rather than failing.
- **Unsubscribe and address:** The truncated HTML did not reach the footer, and no `List-Unsubscribe` or `List-Unsubscribe-Post` headers were supplied. The unsubscribe link, physical postal address, and one-click header could not be checked.
- **Sender:** From is `no-reply@emails.skechers.com`. A no-reply sender is not a CAN-SPAM violation, but it gives recipients no reply path.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- UTM parameters and landing destinations could not be verified. All 36 links are redirect-wrapped and were not probed, and the HTML is truncated.
- The tracking IDs show the campaign `MKG_US_NA_U_MULTI_ENGAGEDL30D_EN_10192026` in the `krxd` and `ink1000` pixels. No landing-page alignment issues were found because none could be tested.

## 7. Recommendations
1. Add a default to the name merge field (for example "Hi there,") or suppress the greeting when the name is empty. This is the only QA FAIL.
2. Fix the Return Path pixel to `https://pixel.app.returnpath.net/pixel.gif?r=…`, or remove it if it is no longer used.
3. Move `image.emails.skechers.com` and `ink1000.com` assets to HTTPS. Add descriptive `alt` text to `dde00662-169f-447d-b0e2-fc65f6c2290c.png`, and `alt=""` to the tracking pixels.
4. Use `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`. Add `lang="en"` to `<html>` and `role="presentation"` to the layout tables. Consider dropping `maximum-scale=1`.
5. Rerun the audit with the full HTML and raw headers to check the footer unsubscribe link, postal address, `List-Unsubscribe`, SPF/DKIM/DMARC, and the UTM values after redirect resolution.
