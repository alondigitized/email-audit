# Final Call: Extra 15% Off Sale for Members
**Score:** 9/10 · **Type:** Email audit · **2026-07-05**
## Executive summary

- They're calling this a "Final Call" and today's July 5th — so at least the timing makes sense. The July 4th weekend is done, the sale is wrapping up, and Skechers wants one last shot at my wallet. I get it. And as a Skechers Plus member, the extra 15% on top of sale prices is genuinely useful — that's stacking savings, which is the way I like to shop.
- But here's the thing: before I even tapped through, I saw that same wall of raw JSON code in my preview slot. Again. I've been counting — this is at least the fourteenth straight Skechers email with broken preview text. At this point I'm not even surprised, just tired. The BOGO or 20%-off-single-pair hero is visible right away, the Men's section has a guy near an RV with a flag — that's more my speed than the women's lifestyle shot leading. I'd probably scroll down, grab the code, and shop the men's sale — but I wouldn't forward this to anyone. Mark as read after clicking.

## What's working

- The "Final Call" framing is earned — July 5th is the right day to close out a Stars and Stripes sale, and I actually believe the urgency for once.
- Member exclusive 15% off stacking on top of the existing sale is real value; that's the kind of math that makes me open the app.
- The Men's section imagery (guy, casual clothes, RV in the background) is the closest I've seen this brand get to putting someone like me in the email — that outdoor-comfortable Boomer vibe works.
- "DISCOUNT APPLIED AT CART" removes a friction point I hate — no promo code hunting for the main offer.
- The offer hierarchy is clean: hero BOGO → gender sections → member deal. Even if the member deal is buried, the layout is readable without zooming.

## What's weak

- The extra 15% member discount — the entire reason I opened this email — is buried below three gender sections at the bottom. Lead with what the subject promised.
- That preview text is still broken JSON schema code. Fourteenth time. Someone needs to fix this; it actively undermines trust every single open.
- "LET'S GET TESTING" appears near the footer — either that's a render artifact or a QA note that shipped to production. Either way it's unprofessional and I noticed it.
- Not one word about comfort, cushioning, arch support, or walking performance anywhere in the email. I'm a Skechers Plus member because I wear their comfort line — this email treats me like a discount hunter, not a foot-comfort loyalist.
- Three gender categories (Women, Men, Kids) share equal billing. I don't have kids and I'm not shopping women's — that space could be used to surface a specific men's comfort style I'd recognize.

## Recommendations

- 1. **Move the member exclusive offer to the hero.** The subject says "Extra 15% Off for Members" — make that the first thing I see. Put the code front and center above the fold. The BOGO can live below it.
- 2. **Fix the preview text. Now. Permanently.** This has appeared in every single Skechers Plus email I've audited. It's a systemic issue and it costs credibility every time.
- 3. **Add one comfort-specific callout in the Men's section.** Even a line like "memory foam insoles" or "arch fit technology" under the men's CTA would make me feel like this email knows why I shop here.
- 4. **Remove or explain "LET'S GET TESTING"** in the footer — if it's placeholder copy, kill it; if it's intentional, make it readable.
- 5. **Trim the gender-section parity.** Men + one featured men's comfort style would outperform three equal gender tiles for a subscriber like me.

### 1. Technical Summary

The email has no merge-token or compliance blockers, but carries two concrete rendering risks: a protocol-less tracking pixel that will silently fail, and 12 assets served over HTTP that modern email clients will block or proxy. The automated QA summary line ("100% pass rate, 0 warnings") contradicts the 14 warnings emitted in the same run — the summary is unreliable and should not be trusted as a gate.

### 2. Link & Tracking Issues

**Return Path pixel — missing protocol (will silently 404)**
```html
<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1dbf0dcef79cbad82c12fe25342701e4499" />
```
No `http://` or `https://` prefix. Email clients treat this as a relative path, so the request never leaves the client. Inbox placement monitoring via Return Path is broken for every recipient of this send.

**ink1000.com open-tracking pixel over HTTP**
```
src="http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=PRO_US_NA_U_SITEBUNDLE_LOYL_EN_07052026"
```
HTTP-only. Gmail and Outlook.com proxy or block non-HTTPS pixel loads, which will under-count opens for this third-party open tracker.

**27 click-redirect links skipped by QA**
All route through `click.emails.skechers.com` (SFMC). Expected for ESP click tracking — no action needed, but destination URL UTM coverage should be verified separately (see §6).

**Krux DMP pixels (3 beacons via `beacon.krxd.net`)**

**2 images missing `alt` text**
- `o.gif` (ink1000 pixel) — minor; decorative pixel, `alt=""` is acceptable
- `49468f73-4651-4af3-bea2-61d1ae5db486.png` — content image with no alt, fails WCAG 1.1.1

**Malformed `<meta>` tags**
Both meta tags omit `http-equiv`, which is required for the attributes to be interpreted:
```html
<!-- current (broken) -->
<meta content="text/html; charset=utf-8" />
<meta content="IE=Edge" />

<!-- correct -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```
Charset declaration failure can cause encoding issues in older Outlook versions.

**`-webkit-text-size-adjust: none`**
Set globally via `* { -webkit-text-size-adjust: none }`. This suppresses user-initiated text scaling on iOS, which fails WCAG 1.4.4 (Resize Text). Should be `100%`, not `none`.

**Duplicate media query blocks**
`@media (max-width: 375px)` and `@media (max-width: 640px)` contain identical rule sets. The 375px block is entirely redundant since 640px subsumes it. Not a rendering bug but adds ~1 KB to payload.
