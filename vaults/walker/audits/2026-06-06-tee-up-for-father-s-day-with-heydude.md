## Technical Audit

## Technical Audit — Famous Footwear: "Tee up for Father's Day with HEYDUDE"

---

### 1. Technical Summary

The email is structurally sound for a legacy HTML4 table-based layout, but carries three confirmed technical defects: a plain-text body that is URL-dominated (deliverability risk), a mixed-content HTTP image source that will be blocked by modern email clients, and pervasive missing alt text across 26 images. No critical rendering failures, but the HTTP asset and plain-text ratio are actionable before re-send.

---

### 2. Link & Tracking Issues

**No broken links detected.** All 28 click-through URLs are wrapped by `click.email.famousfootwear.com` (Salesforce Marketing Cloud / ExactTarget click tracking). QA skipped HTTP probing on these — correct behavior for redirect chains.

**Open pixel confirmed present:**
```
https://click.email.famousfootwear.com/open.aspx?7HRFMDOYX6DEPJEDZTKWWK3O4E.70253&d=70253&bmt=0
```
Standard 1×1 pixel, `alt=""`, `width="1" height="1"` — no issues.

**Plain-text URL density — deliverability risk:**
QA reports 8,155 of 10,643 plain-text characters (76.6%) are URLs. Spam filters (SpamAssassin, Postmaster) penalize plain-text bodies where URL content exceeds ~60–70%. This is likely caused by the ESP injecting raw redirect URLs into the plain-text mirror without stripping tracking parameters. The plain-text version should use descriptive anchor text (`Shop HEYDUDE Men's Shoes: famousfootwear.com/...`) rather than raw click-wrapped URLs.

---

### 3. Rendering & Accessibility

**Critical — HTTP image asset (mixed content):**
```
src: http://cl.S7.exct.net/LiveContent.aspx?qs=ABB7InYiOjEsImQiOjQ4OTl9...
```
This is an SFMC LiveContent dynamic block loaded over plain HTTP. Gmail, Apple Mail, and Outlook all proxy or block non-HTTPS image sources. This content block will either render as a broken image or be silently suppressed. Must be migrated to HTTPS, or the LiveContent block must be served through a HTTPS-enabled endpoint. **This is the only QA-flagged warning in the pass/fail summary.**

**26 images missing alt text:**
Every product/content image in the email has `alt=""`. While decorative spacers legitimately use empty alt, product shots and CTA images (e.g., `7eec9981`, `c7cabc50`, all the shoe imagery) should carry descriptive alt text for:
- Screen reader users (ADA/WCAG 2.1 AA)
- Image-blocked rendering environments (default in many corporate Outlook configs)

The logo image (`3b6a7dc1`) also has `alt=""` — acceptable if decorative, but a logo should typically have `alt="Famous Footwear"`.

**Malformed `<meta>` charset tag:**
```html
<meta content="text/html; charset=UTF-8" />
```
Missing the required `http-equiv="Content-Type"` attribute. Correct form:
```html
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
```
Without `http-equiv`, this tag is inert — charset is undeclared in the HTML layer. In practice, ESP injection typically adds a correct header at the MIME level, so rendering impact is low, but it is a malformed tag.

**`user-scalable=0` in viewport:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=0" />
```
Disabling pinch-to-zoom fails WCAG 2.1 Success Criterion 1.4.4 (Resize Text). iOS Safari enforces this restriction in some accessibility contexts. Remove `maximum-scale=1, user-scalable=0`.

**DOCTYPE:** HTML 4.01 Transitional — legacy but expected and appropriate for broad email client compatibility. No action needed.

### 4. Personalization & Merge Tokens

No unfired merge tokens (e.g., `%%FIRSTNAME%%`, `{{var}}`) are visible in the provided HTML source.

One suspicious fragment in the source:
```html
Join Famously <strong>YOU</stron…
```
The closing `</strong>` tag appears to be malformed (`</stron…` is truncated in the provided source). If this is present in the live send and not a truncation artifact from the audit input, it would leave an unclosed `<strong>` tag that can cause bold to bleed into subsequent content in strict parsers.

**Recommendation:** Verify the closing tag in the canonical sent HTML.

### 6. Email-to-Site Continuity (UTM / Landing Page Alignment)

All destination URLs are wrapped in `click.email.famousfootwear.com` redirect chains. QA did not follow redirects, so final-destination UTM parameters cannot be confirmed from this audit.

**Standard SFMC behavior** appends UTM params at the redirect target, but this must be verified by manually following one sample link. Confirm that destination URLs carry at minimum:
- `utm_source=email`
- `utm_medium=email`
- `utm_campaign=<campaign_id>` (e.g., `fathers_day_heydude`)

The promo code `SIZZLING` appears in the preheader but is not confirmed present as a pre-applied parameter on destination landing pages — verify that the linked category/PDP pages either auto-apply the code or display it prominently above the fold.
