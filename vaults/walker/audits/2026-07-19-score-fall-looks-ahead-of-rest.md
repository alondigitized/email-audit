## Technical Audit — adidas "Score fall looks ahead of rest"

### 1. Technical Summary

Two hard failures: a broken redirect destination that resolves to an unroutable URL type, and a completely absent plain-text fallback. Four HTTP (non-HTTPS) image sources will be blocked silently in most modern clients.

---

### 2. Link & Tracking Issues

**[FAIL] Broken redirect destination**
The QA probe on this click-tracked URL:
```
https://dv.adidas.com/o/4bfd09dd-a06b-4fc5-9789-2b81320f5354?cp_tp=v3.eJzj...&cp_cid=d63aafc3fa4b9098&mi_cid=...
```
resolved to an internal path of type `/g/4bfd09dd-a06b-4fc5-9789-2b81320f5354?txn=46346c80-8327-11f1-b272-9e016bacd681`, which the prober flags as `unknown url type`. This is consistent with the redirect chain terminating in a mobile app deep link or a malformed SFMC landing page route. Subscribers clicking this link on desktop will hit a dead end or error page.

**[INFO] 23 tracking links skipped**
All pass through `dv.adidas.com` (SFMC click-redirect). Not an error, but none were probed for final destination health — only the one above surfaced because its resolved URL type was invalid.

---

### 3. Rendering & Accessibility

**[WARN] Four HTTP image sources — same asset, referenced four times**
```
http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg
```
Alt text: `"arrow"`. Gmail, Outlook.com, and Apple Mail all upgrade to HTTPS or block mixed-content images silently. The arrow will render as a broken image or be suppressed in these clients. The asset is duplicated four times in the markup; all four need the scheme changed to `https://`.

**[WARN] HTTP tracking pixel**
```
http://click.comms.adidas.com/CI0/0102019f788dde4b-6fc3f4b0-5f29-4cc4-8668-97dd860ea3bc-000000/EJzgANMtqW...
```
Open-tracking pixel served over HTTP. Same blocking risk. Also missing `alt=""` (should be empty string, not absent, to prevent broken-image icons).

**[WARN] Two images missing alt attributes entirely**
- `4bfd09dd-a06b-4fc5-9789-2b81320f5354` (hero or product image via `dv.adidas.com`)
- The tracking pixel above

Missing `alt` on content images fails WCAG 1.1.1 and causes screen readers to read out raw filenames or URLs.

**[INFO] Duplicate `@font-face` declarations**
`AdihausDIN` (400, 700) and `AdineuePRO` (400, 600) are each declared twice across two separate `<style>` blocks, with slightly different `src` fallback lists (`Calibri` and `Sans Serif` present in block 1, absent in block 3). Neither block loads a remote web font — both fall back to local system fonts. The duplication is harmless but inflates CSS payload; the `Calibri`/`Sans Serif` entries in block 1 are inconsistent with block 3 and could be a copy-paste artifact from different template versions.

**[INFO] Malformed charset meta tag**
```html
<meta content="text/html; charset=UTF-8" />
```
Missing `http-equiv="Content-Type"`. Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />
```
Without `http-equiv`, some older clients (Outlook 2007–2013) may not pick up the charset declaration.

### 5. Compliance (CAN-SPAM, Unsubscribe, Authentication)

CAN-SPAM does not mandate a text part, but its complete absence increases spam filter scores across SpamAssassin-derived filters and violates best-practice guidance from major ISPs (Gmail Postmaster, Yahoo Mail). Unsubscribe link and physical address were not visible in the truncated HTML provided. These are standard for adidas campaigns and assumed present — verify in the full source that both appear above the fold of the footer.
