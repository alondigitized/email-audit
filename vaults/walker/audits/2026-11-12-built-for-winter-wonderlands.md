## Technical Audit

# Technical Audit: HOKA "Built for winter wonderlands ❄️"

## 1. Technical Summary
The email has no plain-text part (0 chars) and 10 images with no alt text. This leaves its image-wrapped links with no accessible name. Every probed Cordial tracking redirect returned 4xx, but that looks like the probe being rejected rather than a real outage (see section 2). The HTML source was truncated, so only what the source and QA data confirm is flagged.

## 2. Link & Tracking Issues
- **8 of 8 probed tracked links failed.** Seven returned **406** and the unsubscribe link returned **403**. All are `https://e.emails.hoka.com/c2/1664:…:1/<hash>?jwtH=…&jwtP=…&jwtS=…` redirects.
  - The failing links are the hero (`/a4a0f282`), logo (`/d06f1a38`), three HowToWear images (`/1e2eed8d`, `/1d3799bf`, `/f97a6dc3`), two product tiles (`/66b8b739`, `/93775cb2`), `return-start` (`/a9ec5f62`) and Unsubscribe (`/420d0ddd`).
  - A uniform 406/403 across every link on one tracking domain points to the probe's user agent or headers being rejected by Cordial or its CDN. It does not suggest broken destinations.
  - I could not confirm real-client behavior from this data. Re-test with a browser-like UA and Accept headers.
- **The "31% pass rate" is misleading.** 12 links were probed and 11 were skipped, so it reflects a small sample dominated by these failures.
- **Destinations decoded from `jwtP`:**
  - The hero (`/a4a0f282`) goes to `https://www.hoka.com/en/us/new-arrivals/`.
  - The logo goes to `https://www.hoka.com/`.
  - The three HowToWear images go to `https://www.hoka.com/en/us/hiking/`.
  - The product tiles go to `/en/us/womens-lifestyle/kaha-2-frost-moc-gtx/1155196.html?dwvar_1155196_color=WNKP` and `/en/us/mens-lifestyle/kaha-2-frost-moc-gtx/1155210.html?dwvar_1155210_color=WLY`.
  - `return-start` goes to `https://www.hoka.com/en/us/return-start/`.
  - The unsubscribe link goes to `https://options.hoka.com/unsubscribe?cid=…`.
- **Possible tracking pixels:**
  - `e.emails.hoka.com/o/p/…` and `mg.emails.hoka.com/o/…` appear twice, on two different sending hosts (`e.` and `mg.`). The second is likely a secondary ESP pixel.
  - Both lack alt text. An empty `alt=""` would be correct for pixels.

## 3. Rendering & Accessibility
- **Plain-text fallback is missing.** The QA check reports "Text version is 0 chars". This hurts deliverability and affects text-only and screen-reader clients.
- **10 images have no alt text:**
  - Content images: `US_20261112_HowToWear_a/b/c/g.jpg`, `US_Kaha2FrostMocGTX_TopLeft_1179205-WNKP.jpg`, `US_Kaha2FrostmocGTX_TopRight_1179204-WLY.jpg` and `US_20261109_TripleBlackStyles_d.jpg`.
  - `LogoFooterPrimary.png` and the two tracking pixels.
- **Several of those images are the only content of a link**, so the link has no accessible name. The QA tool records their link text as `[image: …]`. This applies to the hero, HowToWear a/b/c and both product tiles.
- **`<title></title>` is empty.**
- **Viewport meta is malformed and duplicated.**
  - The first `<meta content="text/html; charset=utf-8" />` has no `http-equiv` or `charset` attribute, so it does nothing.
  - There are two `viewport` tags. Both set `maximum-scale=1`, which blocks pinch-zoom on some mobile clients. The second adds `user-scalable=yes`, but the conflict is ambiguous.
- **Invalid CSS from empty template variables:** `.nav_padding {padding-top:px !important;padding-bottom:px !important;}` and `.nav_border {border-top:px solid ;}`. These are ignored but indicate unpopulated variables.
- **Web fonts (`TheFutureHOKA*.woff2`) load from `www.hoka.com/on/demandware.static/...`.** Most email clients ignore `@font-face`, so these fall back to system fonts. No issue was flagged unless the fallback stack is missing, and the source was truncated before I could check.

## 4. Personalization & Merge Tokens
No unresolved merge tokens (`{{…}}`, `%%…%%`) were found in the visible source. The tracked URLs carry a per-recipient `hmail=<64-hex>` (apparently a SHA-256 hash of the email address) and `cordial_id`. These resolved correctly. The `<title>` is empty, so it carries no personalization.

## 5. Compliance
- **Unsubscribe link is present** (`options.hoka.com/unsubscribe?cid=…`) but returned **403** to the probe. This is likely the same bot-rejection pattern as section 2, but it is unverified, so re-test with a real client.
- **`Authentication-Results` header not found.** SPF/DKIM/DMARC status is unknown because the AgentMail relay does not expose it. Sender `info@emails.hoka.com` and tracking hosts `e.`/`mg.emails.hoka.com` all sit on the same parent domain, so alignment is plausible, but it is not confirmed.
- **`List-Unsubscribe` / `List-Unsubscribe-Post` headers were not provided to me**, so I cannot confirm one-click support. Verify them in the raw headers.
- The physical postal address was not visible in the truncated source, so it is unverified.

## 6. Email-to-Site Continuity
- **UTM parameters are consistent on every decoded link.** They are `utm_source=US_Broadcast`, `utm_medium=email` and `utm_campaign=H_US_BR_20261112_Kaha2FrostMocGTX_Spotlight_FES_A3Day_HighestEngaged_90MemberEngagers_90GTXTag_720HikePurchasers_WishlistAdd`.
  - The campaign name exposes internal segmentation (engagement tier, purchase and wishlist criteria) in the visible URL. This is a minor data-exposure and hygiene note.
- **Possible stale asset:** the hero image is `US_20261109_TripleBlackStyles_d.jpg` (dated 11/09 and named for a different campaign). It links to the generic `/new-arrivals/` page, while the rest of the email is dated 11/12 and about Kaha 2 Frost Moc GTX. I cannot verify the page contents from this data.
- **Three separate images link to the same `/hiking/` URL** (HowToWear a, b, c) with distinct tracking hashes. This is fine for click attribution, but it is redundant.
- No landing-page verification was possible because all probes failed at the redirect.

## 7. Recommendations
1. Re-probe with a realistic browser UA and Accept headers. If the redirects and unsubscribe link still fail, escalate. If they pass, tune the QA probe to avoid false "broken" results.
2. Add a plain-text MIME part, since 0 chars is a deliverability and accessibility gap.
3. Add meaningful `alt` text to every content image, especially linked ones. Use `alt=""` for the tracking pixels and ensure the footer logo has `alt="HOKA"`.
4. Fix the head: set a real `<title>`, add `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">`, keep a single viewport tag, and drop `maximum-scale=1`.
5. Remove or populate the empty CSS variables (`padding-top:px`, `border-top:px solid`).
6. Confirm `List-Unsubscribe` and `List-Unsubscribe-Post` headers, SPF/DKIM/DMARC pass, and the postal address in the footer from the raw message.
7. Review whether `TripleBlackStyles_d.jpg` and its `/new-arrivals/` link belong in this campaign.
