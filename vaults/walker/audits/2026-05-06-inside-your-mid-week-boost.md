# Inside: Your mid-week boost
**Score:** 7/10 · **Type:** Email audit · **2026-05-06**

- This is a DSW email, not Skechers — and that distinction matters right away. I'm a DSW shopper, so the name I recognize. ### 3. Rendering & Accessibility

**`Src:` (capital S) in all 10 `@font-face` declarations — confirmed bug.**

```css
Src: url("https://braze-images.com/appboy/.../original.woff") format('woff');
```

`src:` is a CSS property and must be lowercase. Capital `Src:` is ignored by spec-compliant parsers. All 10 font faces (Futura PT Regular/Medium/Demi/Bold, HelveticaNow Regular/Medium/MediumItalic/Bold/BoldItalic/Italic) fall through to system font fallbacks in any client that correctly rejects the malformed declaration.

**`<meta>` tags missing `http-equiv` attribute — two instances:**

```html
<meta content="text/html; charset=utf-8" />        <!-- missing http-equiv="Content-Type" -->
<meta content="IE=Edge" />                           <!-- missing http-equiv="X-UA-Compatible" -->
```

Both tags are inert as written. The charset declaration in particular should be `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` for correct XHTML parsing.

**`text-size-adjust: none` in reset:**

```css
* { -ms-text-size-adjust: none; text-size-adjust: none; }
```

The reset applies `100%` for `-webkit-text-size-adjust` but `none` for the standard and `-ms-` prefixed versions. `none` disables all UA text scaling, which conflicts with WCAG 1.4.4 (resize text). Should be `100%` across all three.

**Font format coverage:**
- Futura PT: `.woff` only — no `woff2`. All modern clients support woff2 with ~30% smaller payloads.
- HelveticaNow: `.ttf` only — no `woff` or `woff2`. TTF is the largest format and unnecessary for web/email contexts.

**Off-black color values (`#000001`):**

Used in `.border-top-black` and `.dm-font-black`. Likely intentional to prevent Gmail dark-mode color inversion (a known workaround), but worth documenting so future editors don't treat it as a typo.
