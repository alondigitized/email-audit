# 20% off for the holidays? Holi-YAY!
**Score:** 6/10 · **Type:** Email audit · **2026-10-22**
## Executive summary

- DSW again. This is the third send today with the same 20% off and code JINGLE. I saw "Open for 20% off!" and "Want 20% off? Youuuu got it." earlier. The giant "20% OFF*" on green is still easy to read on my phone. But I've now seen it three times in one day, so it's wearing thin.
- This one is lighter on the UGG slippers that filled my inbox on the 19th through the 21st. The grid of shoes below the offer is all women's: a Mary Jane, a loafer, ankle boots, a sneaker and a Chelsea boot. Only the gray chunky sneaker looks like it could be mine, and the Chelsea boot might be. The "Gifts for him" banner with slippers and sneakers is the one thing aimed at me, and it sits halfway down.
- I probably would not click. The code is fine, but nothing here shows me a cushioned, slip-on walking shoe. I'd mark it read. I wouldn't forward it.

## What's working

- The giant "20% OFF*" on green is clear, and the large type is easy on my eyes.
- The code JINGLE is in the hero, so I don't have to hunt for it.
- The "Shop Women / Men / Kids / Everything" links let me skip straight to the men's section.
- The gray sneaker and the pink "Gifts for him" banner with slippers and sneakers are closer to what I wear.
- The "Shop by size" row with wide width is good. Wide shoes matter to me.

## What's weak

- Three near-identical 20% sends in one day feels like pestering. It cheapens the offer.
- Five of the six products in the grid look women's. I'm a 62-year-old man and this feels like it was sent to someone else.
- Nothing mentions cushioning, arch support or slip-on ease. Those are the things I buy on.
- The "Extra 20% off reg. price!" labels in small red type are hard to read, and they confuse me. Is that on top of JINGLE, or the same deal?
- The asterisk and the fine print at the bottom are very long. Brands like Skechers are excluded from the 20%, and that is buried at the bottom. Skechers is one of the brands I cross-shop.
- The "Gifts for him" banner is below the fold and easy to miss.

## Recommendations

- 1. Send one 20% email and don't repeat it three times a day. If you must resend, change the creative and not just the subject.
- 2. Show men's styles in the hero grid. Include slip-ons, walking shoes and cushioned sneakers. Add one line like "Easy on, all-day comfort."
- 3. Say once, near the offer, which brands are excluded, and drop the confusing "Extra 20%" labels.
- 4. Move "Gifts for him" higher and add a button that is easy to tap.

- **Subject Alt B:** `Slip-ons and walkers: 20% off through Sunday`
- **Preheader Alt A:** `Use code JINGLE through Oct 25. Regular-price styles only.`
- **Preheader Alt B:** `Cushioned, easy-on shoes for him. Wide widths too.`

## Technical Audit

## 1. Technical Summary
The email's SMS opt-in CTA ("Opt-In to Texts Get 15% Off") returned HTTP 400 when probed. The HTML also has malformed `<meta>` declarations, a zoom-blocking viewport, and two images without `alt`. Authentication status could not be verified.

## 2. Link & Tracking Issues
- **Broken CTA (confirmed):** The link "Opt-In to Texts Get 15% Off" returned **400**. Its URL is `https://ablink.dsw.com/f/a/UB7oi5nSzr4Z66o_IDVagw~~/AAQRxRA~/d4SHIJXX…` (a very long tracked redirect). This is the only failed link among the 12 probed. 55 links were skipped, so the rest are unverified.
- **Possible probe artifact:** SMS opt-in redirects sometimes reject non-mobile or bot user agents. Retest from a mobile UA before treating this as a live outage.
- **Plain-text part:** 24,712 of 28,966 characters (about 85%) are URLs, because every link is wrapped in a long `ablink.dsw.com` tracking redirect. This is a spam-filter risk (QA WARN).
- **All destinations are hidden behind `ablink.dsw.com`.** The final landing URLs can't be seen from the source.

## 3. Rendering & Accessibility
- **Missing `alt` text (2 images, QA-confirmed):**
  - `https://ablink.dsw.com/q/BU3RQLtQxFLbEjXa7-Z_GQ~~/AAQRxRA~/1AzriBV4…`
  - `https://mi.dsw.com/p/up/e6f23fb0…/o.gif?mi_u=…`
  
  Both look like open-tracking pixels. If so, the fix is `alt=""` (decorative) and ideally `width="1" height="1"`.
- **Viewport blocks zoom:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />`. `maximum-scale=1` prevents pinch-zoom, which fails WCAG 1.4.4.
- **Malformed meta tags:**
  - `<meta content="text/html; charset=utf-8" />` has no `http-equiv="Content-Type"`, so the charset declaration does nothing.
  - `<meta content="IE=Edge" />` has no `http-equiv="X-UA-Compatible"`, so it also does nothing.
- **Dark mode:** `.dm-bg-white { background: #ffffff !important; }` keeps a white background in dark mode. That is probably intentional, so I'm not flagging it as a defect.

## 4. Personalization & Merge Tokens
No issues found. The subject line and the visible source contain no unrendered tokens (`{{ }}`, `%%`, `[FNAME]`). The source is truncated, so the body is only partly covered.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication-Results header not found.** The QA check says this is expected via the AgentMail relay, so SPF/DKIM/DMARC status is **unknown**, not failed. The sender is `dsw@e.dsw.com`, a dedicated subdomain.
- **Unsubscribe:** The QA run always probes an unsubscribe link and reported no failure for it.
- **Not verifiable from the data provided:** `List-Unsubscribe` / `List-Unsubscribe-Post` headers, and the physical postal address in the footer (the source is truncated).

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- UTM parameters can't be evaluated because the links are Braze-style redirects (`ablink.dsw.com`) and the final URLs weren't captured.
- The only visible campaign identifier is `mi_ecmp=20261022_P261522_V1_WM-_Offer_Stan…` on the `mi.dsw.com` pixel. It is truncated, so I can't judge it.
- The one continuity failure is the SMS opt-in CTA, which returns an error instead of a landing page.

## 7. Recommendations
1. **Fix or retest the SMS opt-in link** (400). Check it with a mobile user agent. If it still fails, repair the redirect target or the Braze link configuration, since this is a 15%-off acquisition CTA.
2. **Correct the meta tags:** `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` and `<meta http-equiv="X-UA-Compatible" content="IE=Edge" />`.
3. **Remove `maximum-scale=1`** from the viewport meta.
4. **Add `alt=""`** to the two tracking pixels (`mi.dsw.com/.../o.gif` and the `ablink.dsw.com/q/...` image).
5. **Shorten tracking URLs or add a real text alternative** to cut the plain-text URL ratio (about 85%).
6. **Capture the raw headers** (Authentication-Results, List-Unsubscribe) and the resolved landing URLs with UTMs. Then the compliance and continuity sections can be confirmed instead of marked unknown.
