## Technical Audit — adidas Skateboarding / Thrasher / AFA Email

---

### 1. Technical Summary

One CTA link is confirmed broken due to a redirect path mismatch, and the email has zero plain-text fallback content — a CAN-SPAM compliance gap. Eight arrow images and one tracking pixel are served over HTTP, risking suppression in privacy-enforcing clients.

---

### 2. Link & Tracking Issues

**FAIL — Broken redirect (broken experience)**
The QA checker reports `unknown url type: '/g/fb6625a2-5c12-474a-8530-7e9dac31468a'`. The click-tracking wrapper resolves to a `/g/` path, but the dynamic content server at `dv.adidas.com` uses `/o/` paths (confirmed in the resolved destination URL: `https://dv.adidas.com/o/fb6625a2-5c12-474a-8530-7e9dac31468a?cp_tp=v3.eJ...`). The `/g/` → `/o/` mismatch means this CTA is dead for affected recipients.

**INFO — 36 tracking links skipped**
All click-redirect URLs through `click.comms.adidas.com` were skipped by the HTTP probe. This is expected ESP behavior; no action required unless click-through attribution is failing.

---

### 3. Rendering & Accessibility

**WARN — 8× HTTP image source (same asset, repeated)**
The arrow image `b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg` is loaded 8 times via `http://image.link.adidas.com/...`. Gmail, Outlook.com, and Apple Mail proxy or block non-HTTPS images; this asset will be suppressed in those clients.

**WARN — 1× HTTP tracking pixel**
`http://click.comms.adidas.com/CI0/0102019f04741f16-...` is served over HTTP. Same blocking risk; also degrades open-rate accuracy.

**WARN — 2 images missing `alt` text**
- Dynamic content image: `fb6625a2-5c12-474a-8530-7e9dac31468a` (no `alt` attribute)
- Tracking pixel: `MsVX4GfdRoYYP47p_N88PAs3m...` (no `alt` attribute)
Missing `alt` on the content image causes a blank gap when images are blocked; the tracking pixel should have `alt=""`.

**Minor — Malformed charset meta tag**
```html
<meta content="text/html; charset=UTF-8" />
```
Missing `http-equiv="content-type"`. Correct form:
```html
<meta http-equiv="content-type" content="text/html; charset=UTF-8" />
```
Some older Outlook builds may mis-detect encoding without this.

**Minor — Duplicate `@font-face` blocks**
`AdihausDIN` and `AdineuePRO` `@font-face` declarations appear in two separate `<style>` blocks in `<head>`. No functional breakage, but it adds ~1 KB of redundant CSS and can cause specificity confusion in some parsers.

---

### 4. Personalization & Merge Tokens

No unresolved merge tokens visible in the provided HTML. The `txn` value in the broken link (`txn=2b406380-7192-11f1-96d8-aea38baf8e0c`) and `mi_mid` are populated with real UUIDs, indicating render-time substitution completed. No issues found in the visible portion.

---

### 5. Compliance

**FAIL — Plain-text fallback is 0 characters**
QA reports the `text/plain` MIME part is empty. CAN-SPAM requires a readable version of the email content; a zero-byte text part also increases spam scoring in SpamAssassin-based filters. The multipart/alternative envelope exists but the text body is unpopulated.

**INFO — Unsubscribe and physical address**
Not visible in the truncated HTML. Presumed present in the footer (standard adidas template); if absent that is a hard CAN-SPAM violation. Verify footer includes: (a) postal address, (b) one-click or low-friction unsubscribe link.

**INFO — Crawl suppression and referrer policy present**
```html
<meta name="ROBOTS" content="NOINDEX, NOFOLLOW" />
<meta name="referrer" content="no-referrer" />
```
Both are correctly set to prevent indexing and referrer leakage.

---

### 6. Email-to-Site Continuity

**No standard UTM parameters detected.** All outbound links use adidas-internal tracking parameters (`cp_tp`, `cp_cid`, `mi_cid`, `mi_mid`). These are MessageMedia/Movable Ink parameters and do not feed Google Analytics or any standard web analytics tool unless a server-side mapping layer exists. If web analytics continuity is required, UTM params need to be appended at the ESP layer.

The broken `/g/` link (section 2) means at least one product CTA produces a dead landing page for recipients who click it — the downstream URL (`dv.adidas.com/o/fb6625a2...`) appears valid, so fixing the redirect path should restore continuity.
