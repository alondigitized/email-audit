### 3. Rendering & Accessibility

**Confirmed issues:**

**`maximum-scale=1` blocks pinch-to-zoom (WCAG 1.4.4 violation)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents visually impaired users from zooming. Drop `maximum-scale=1` entirely — it no longer suppresses double-tap zoom in modern iOS/Android, so it provides no layout benefit.

**`text-size-adjust: none` overrides OS accessibility settings**
```css
* { -ms-text-size-adjust: 100%; -webkit-text-size-adjust: 100%; text-size-adjust: none }
```
The unprefixed `text-size-adjust: none` overrides the `100%` prefixed declarations in the same ruleset — contradictory and suppresses user-configured font scaling. Change to `text-size-adjust: 100%`.

**`Src:` (capital S) in all 10 `@font-face` declarations — invalid CSS**
```css
@font-face { font-family: 'Futura_PT_Regular'; Src: url("https://braze-images.com/...") format('woff'); }
```
All 10 `@font-face` blocks use `Src:` instead of `src:`. Most parsers are lenient and will ignore the capitalization, but it is spec-invalid and will silently fail in strict parsers. Rename to lowercase `src:`.

**No `lang` attribute on `<html>` element**
```html
<html xmlns="http://www.w3.org/1999/xhtml">
```
Screen readers use `lang` to select the correct pronunciation engine. Add `lang="en"` (or locale-appropriate value).

**Font format coverage gap:** Futura variants load only `.woff`; HelveticaNow variants load only `.ttf`. Neither set provides `.woff2` (30–40% smaller). Low severity, but adds load time on supporting clients (Apple Mail, Samsung Mail).

**Cache-busting inconsistency:** HelveticaNow URLs carry a query string (`?1755182939`); Futura URLs do not. If Futura font files are ever updated at the same URL, clients will serve stale cached versions.
