- The 20% off hero is large, high-contrast, and impossible to miss — exactly how a number should land on a phone screen.
- "Inside: you have 20% off" as a subject is clean and implies the discount is mine specifically, which made me tap.
- "Grab something nice with it" as a preheader doesn't repeat the subject — it extends it, and that's the right move.
- The Shop by Size grid with Wide Width and Wide Calf buttons is the one moment the email remembered that fit matters, and for a guy with wide feet, those two buttons are actually useful.
- DSW VIP section mentions free shipping and 2% back — loyalty benefits visible without hunting for them.

## What's weak

- "So New, So You" is six images of women's heels, wedges, and strappy sandals. Not a sneaker, a slip-on, or a walking shoe in sight. I am not the target of that section.
- The Shoeprise Savings Hunt banner promotes an in-store event dated June 13 & 14 — eleven days ago. Sending this on June 25 is a production error, full stop.
- No comfort, cushioning, or arch support language anywhere in the body — the one thing that would actually make me reach for my wallet.
- The 20% off has no visible expiration date in the body, which makes me wonder if it's real or just the same banner they've been rotating all month.
- This is somewhere around the tenth DSW email I've gotten in two weeks. The fatigue is real; every send they push out dilutes the urgency of every future one.

## Recommendations

- 1. **Replace the "So New, So You" product grid with a men's comfort/walking shoe module** — Brooks, Skechers slip-ons, New Balance walking, or wide-width sandals. One relevant grid is worth more than six gorgeous irrelevant images.
- 2. **Pull the expired in-store event immediately.** Either replace with an active offer or remove that section entirely. Stale dates destroy trust faster than any other single error.
- 3. **Add an expiration date to the 20% off** — even "through this weekend" gives me a reason to act now instead of later.
- 4. **Add one comfort-specific callout** — a single line like "Cushioned soles. Wide widths. All 20% off." would do more for a guy like me than any lifestyle photo.
- 5. **Thin the send cadence.** After ten-plus DSW emails in two weeks, the brand is training me to ignore them.

### 3. Rendering & Accessibility

**[HIGH] `<meta charset>` tag is malformed.**
```html
<meta content="text/html; charset=utf-8" />
```
Missing `http-equiv="Content-Type"`. Correct form for XHTML Transitional:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without this, some older Outlook and Lotus Notes clients may not honor the charset declaration.

**[MEDIUM] `Src:` capitalized in all 10 `@font-face` declarations.**
Every `@font-face` block uses `Src:` (capital S) instead of the spec-required `src:`. Most renderers are lenient, but this is a CSS spec violation that can cause silent font load failures in stricter parsers (e.g., some webmail clients).

**[MEDIUM] `maximum-scale=1` in viewport meta blocks user zoom.**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Disabling pinch-to-zoom on mobile violates WCAG 1.4.4 (Resize Text, Level AA). Remove `maximum-scale=1` or replace with `maximum-scale=5`.

**[MEDIUM] Duplicate `-ms-text-size-adjust` declarations in the same rule, second wins as `none`.**
```css
*{-ms-text-size-adjust: 100%; ... -ms-text-size-adjust: none; text-size-adjust: none}
```
The `100%` value is immediately overridden by `none` in the same rule block. The effective value is `none` for all elements, disabling auto text-size adjustment in IE/Windows Mobile. If `none` is intentional, remove the dead `100%` declaration; if not, remove `none`.

**[LOW] No `woff2` format declared for any web font.**
Futura PT fonts only specify `woff`; HelveticaNow fonts only specify `ttf`. Neither family offers `woff2`, which provides ~30% better compression and is supported by all modern clients. Absence is not a breakage but degrades load performance.

**[LOW] `#000001` used as "black" in dark mode and border styles.**
```css
.dm-font-black { color: #000001 !important; }
.border-top-black { border-top: 1px #000001 solid !important; }
```
This is a known Outlook dark-mode workaround (Outlook skips color-inversion on near-black). Flagged for awareness — it is intentional but undocumented, and the one-off value `#000001` will look identical to `#000000` in all other clients.
