### 3. Rendering & Accessibility

**Confirmed issues:**

- **`Src:` (capital S) in all `@font-face` blocks** — invalid CSS property name. The correct property is lowercase `src:`. All 10 font declarations are affected. Strict CSS parsers (some webmail clients) will silently drop these rules, falling back to system fonts.

  ```css
  /* Wrong — 10 occurrences */
  Src: url("https://braze-images.com/...") format('woff');
  /* Correct */
  src: url("https://braze-images.com/...") format('woff');
  ```

- **`<meta content="text/html; charset=utf-8" />` missing `http-equiv`** — attribute `http-equiv="Content-Type"` is absent. Outlook and some legacy clients rely on this pragma. Should be:

  ```html
  <meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
  ```

- **`<meta content="IE=Edge" />` missing `http-equiv`** — `http-equiv="X-UA-Compatible"` is absent. The tag is effectively a no-op as written.

  ```html
  <meta http-equiv="X-UA-Compatible" content="IE=Edge" />
  ```

- **`text-size-adjust: none` applied globally via `* {}`** — Setting this to `none` (instead of `100%`) prevents users from adjusting text size through OS/browser accessibility settings. This is a WCAG 1.4.4 concern. Both `-ms-text-size-adjust` and `-webkit-text-size-adjust` are also set to `none` via the same rule.

- **`supported-color-schemes` in `:root` CSS block** — `supported-color-schemes` is not a valid CSS property; it only works as a `<meta>` tag (which is already present). The CSS rule is a no-op:

  ```css
  /* No-op — delete this line */
  :root { supported-color-schemes: light dark; }
  ```

- **Single font format per `@font-face`** — Futura_PT variants declare only `.woff`; HelveticaNow variants declare only `.ttf`. No format fallback stack. If either CDN file is unavailable, there is no secondary format to attempt.

- **Alt text on images** — Cannot verify; HTML truncated before `<img>` tags in the body. This must be confirmed in the full source.
