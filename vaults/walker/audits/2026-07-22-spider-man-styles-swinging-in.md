### 1. Technical Summary

The primary technical risks are seven footer images served over HTTP that will fail to render in strict HTTPS email clients, and an unprobed tracking link pool that prevents full destination verification.

### 3. Rendering & Accessibility

**Seven images served over HTTP** — will be blocked or fail silently in clients that enforce HTTPS-only remote content (Apple Mail, Outlook for Mac, some webmail):

| Alt Text | HTTP Source |
|---|---|
| Download on the App Store | `http://image.crocs-email.com/lib/.../9c36c0ef-….png` |
| Get It On Google Play | `http://image.crocs-email.com/lib/.../13246762-….png` |
| Find Your Store | `http://image.crocs-email.com/lib/.../c4df71ec-….png` |
| Instagram | `http://image.crocs-email.com/lib/.../e18949ff-….png` |
| Facebook | `http://image.crocs-email.com/lib/.../80f68cd8-….png` |
| TikTok | `http://image.crocs-email.com/lib/.../51d8144e-….png` |
| YouTube | `http://image.crocs-email.com/lib/.../1187ef58-….png` |

All use the same `image.crocs-email.com` host — this is an ESP asset domain that almost certainly supports HTTPS. A simple protocol swap should resolve all seven.

**Tracking pixel missing `alt` attribute:**
```html
<img style="visibility:hidden;display:none" height="1" width="1"
     src="https://demandwarecrocs.demdex.net/event?...">
```
No `alt=""` present. Screen readers may announce this as an unlabeled image depending on client. Add `alt=""`.

**`charset` meta tag missing `http-equiv`:**
```html
<meta content="text/html; charset=utf-8" />
```
Should be `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />`. Without `http-equiv`, older Outlook versions may misparse encoding.

HTML is truncated — the following **must be verified in the full source**:

**Authentication headers** (SPF, DKIM, DMARC) are not inspectable from HTML source alone — verify via raw message headers or the sending domain's DNS records for `crocs-email.com`.

No issues with preheader implementation.

### 6. Email-to-Site Continuity

Campaign slug `us_20260722_collection_spiderman_launch` is correctly set in the open-tracking pixel, indicating UTM parameters are intended. However, because all 31 click links were behind redirect wrappers and skipped by the probe, **UTM propagation to crocs.com cannot be confirmed**. If any CTA links are missing `utm_campaign=us_20260722_collection_spiderman_launch` (or equivalent), attribution will be lost for this send.
