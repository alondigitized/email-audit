### 1. Technical Summary

Standard ESP-delivered promotional email with broadly sound responsive CSS structure. Two actionable issues require pre-send correction: an unresolved merge token in a tracking pixel and missing `alt` attributes on 7 images including product shots.

---

### 2. Link & Tracking Issues

**Unresolved merge token in open-tracking pixel** — HIGH

```
src: https://0di86k1v.emltrk.com/v2/0di86k1v?d=[UNIQUE]
```

The `[UNIQUE]` placeholder is a literal string in the HTML source. If it was not substituted at send time, every recipient shares the same pixel URL, collapsing open-tracking to a single aggregated hit rather than per-recipient events. Confirm the ESP substituted this value before treating open-rate data as reliable.

**29 click-redirect links not probed** — INFO

QA skipped HTTP probing on all 29 tracked links (ESP redirect domains). Destination URL integrity — including broken links and mis-matched landing pages — was not verified by the automated pass and should be spot-checked manually.

---

### 3. Rendering & Accessibility

**Missing `alt` text on 7 images** — confirmed by QA

| Image | Source domain |
|---|---|
| 4× product shots | `i8.amplience.net` |
| 1× hero/banner | `image.email.shoecarnival.com` |
| 2× tracking pixels | `ieezzy5m.emltrk.com`, `0di86k1v.emltrk.com` |

Product and hero images need descriptive `alt` text for screen-reader users and for rendering in image-off clients (e.g., corporate Outlook). Tracking pixels should carry `alt=""` (empty, not absent) to suppress broken-image icons.

**Malformed `<meta>` charset declaration**

```html
<meta content="text/html;" charset="utf-8" />
```

This splits what should be a single `http-equiv` declaration across two attributes. The correct form for HTML 4.01 Transitional is:

```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

Most clients will tolerate this, but it is technically invalid and may cause charset mis-detection in older Outlook versions.

**`<meta content="IE=edge" />` missing `http-equiv`**

```html
<meta content="IE=edge" />   <!-- missing http-equiv="X-UA-Compatible" -->
```

Without `http-equiv`, this hint is ignored. Low risk given IE usage share, but trivial to fix.

**Dark mode: light-only declaration**

```html
<meta name="color-scheme" content="light" />
<meta name="supported-color-schemes" content="light" />
```

Explicitly opts out of dark mode. Apple Mail and Outlook for iOS will force their own dark-mode overrides on images and text. If dark-mode variants are not tested, this is a rendering risk on iOS/macOS clients.
