# Up to 25% off shoes
**Score:** 4/10 · **Type:** Email audit · **2026-05-11**
## Executive summary

- New Balance, not Skechers. That's the first thing I noticed — wrong brand entirely. I'm a loyal Skechers Plus member; I'm not out here browsing New Balance emails. That said, I'll give credit where it's due: the offer is front and center, the email loaded clean, and "up to 25% off shoes" is plain English I can read without my glasses. The hero is a nice simple layout — a shopping bag on a tan background, clear headline, one button.
- But here's the thing — I'm a 62-year-old guy who shops for slip-ins and comfort shoes, and this email gave me a flat grid of Men / Women / Kids with zero signal that anything in here would fit my feet or my back. The "More to explore" section showed me some dark athletic shoes and a pack of crew socks. Socks. I'm clicking for socks? Pass.

## What's weak

- **Wrong brand for my wallet** — I'm a Skechers Plus member. New Balance is a competitor. This email has zero relevance to my loyalty status or brand preference.
- **Men's section is generic, not comfort-focused** — The category grid says "Men / Women / Kids" with no copy about comfort technology, wide widths, or slip-ons. That's what I'd need to feel spoken to.
- **"More to explore" is filler** — WW550v1 Slip Resistant, 2002 Lace, Action No Show Socks 4-Pack... nothing there made me lean in. The slip-resistant shoe thumbnail is tiny and dark.

- **Models/demographic signals absent** — No people shown at all — just product shots. I can't tell if these shoes are made for someone my age.

- 2. **Surface the slip-resistant or walking category prominently** — The WW550v1 Slip Resistant is buried in a small card at the bottom. That's actually the shoe most relevant to me — put it in the hero.
- 3. **Show a real deadline with more urgency** — "Through May 16th" is fine but low-energy. A countdown or "this weekend only" framing would make me act faster.

- 5. **Remove the socks from the featured grid** — Action Crew Socks 2-Pack as a featured item undersells the email.

## Technical Audit — New Balance "Up to 25% off shoes"

---

### 1. Technical Summary

The email contains an unresolved template placeholder in a background-image URL, two conflicting definitions of the `.bg1` CSS class, and malformed `@font-face` blocks that will silently fail to load web fonts. These are functional defects, not cosmetic ones.

---

### 2. Link & Tracking Issues

**HTTP (non-HTTPS) background image URL — likely unresolved placeholder**
```css
.bgwhite { background-image: url('http://image.XXXXX.png'); }
```
`XXXXX` is an unsubstituted template variable. The image will 404, and the `http://` scheme will trigger mixed-content warnings in clients that enforce HTTPS (Gmail, Outlook.com). This class appears to be applied to a section background, so the failure will be visually blank.

**Truncated source** — unable to confirm UTM parameters on CTA links. See Section 6.

---

### 3. Rendering & Accessibility

**`.bg1` class defined twice with conflicting values:**
```css
/* line ~15 */  .bg1 { background-color: #ffffff; }
/* line ~90 */  .bg1 { background: #58546d; }
```
The second declaration wins in all clients that respect cascade order. Any element using `.bg1` expecting white will render purple-grey instead.

**`@font-face` blocks have no `src:` property:**
```css
@font-face { font-family: linotype-didot, serif; font-weight: 400; font-style: normal; }
/* no src: url(...) */
```
All nine `@font-face` declarations are empty stubs. Web fonts (`proxima-nova`, `linotype-didot`) will not load — clients will fall through to the `Arial`/`Times New Roman` fallbacks. If these fonts are hosted externally (e.g., Adobe Fonts / Typekit), a `<link>` import in `<head>` is required instead; none is visible in the truncated source.

**Malformed IE compatibility meta tag:**
```html
<meta content="IE=edge" />
```
Missing `http-equiv="X-UA-Compatible"`. Correct form:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Outlook desktop rendering may be affected.

**Conflicting DOCTYPE + XHTML namespace:**
```html
<!DOCTYPE html PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" ...>
<html xmlns="http://www.w3.org/1999/xhtml" ...>
```
HTML 4.01 Transitional and XHTML namespacing are mutually exclusive. Most modern clients ignore DOCTYPE entirely, but this is a structural inconsistency. Standard practice for marketing email is `<!DOCTYPE html>` (HTML5 minimal).

**Dark mode implementation:** Present and structurally correct (`@media (prefers-color-scheme: dark)` + `color-scheme` meta). No issues from what is visible.
