## Technical Audit

## 1. Technical Summary
The email's markup has the basics (`lang="en"`, viewport meta, UTF-8 declaration). The automated checks found one hard failure, a missing plain-text part, plus several insecure (`http://`) image sources and missing alt text. The HTML supplied was truncated, so the footer, unsubscribe link and CTA hrefs could not be inspected.

## 2. Link & Tracking Issues
- **Insecure image sources.**
  - `http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg` ("arrow") is flagged twice.

  - Clients that block mixed or non-HTTPS content may drop these images, and the HTTP request can be observed or altered in transit.
- **Tracking links not probed.** 13 click-tracking links were skipped by the QA check because they are on tracking domains. Redirect resolution and final destination status are unverified.
- **Tracked image.** The `click.comms.adidas.com/CI0/…` URL is used as an `<img src>`, so it is probably an open-tracking or tracked-asset request. It is served over HTTP.

## 3. Rendering & Accessibility
- **Missing alt text**, from the QA check:
  - `https://dv.adidas.com/o/680c0b40-56b6-487e-b45b-eacd6d7c7ed8?cp_tp=…`
  - `http://click.comms.adidas.com/CI0/…/apbXDfBIvedp0cQbVd-kdyIdz…`
  - With images blocked or read by a screen reader, these have no text equivalent. If the `dv.adidas.com` image is a hero or banner, it may carry the message on its own.
- **Ineffective charset declaration.** The source has `<meta content="text/html; charset=UTF-8" />` with no `http-equiv="Content-Type"` or `charset=` attribute. Parsers ignore it. This is only a risk if the MIME part lacks a charset.
- **Duplicate style blocks.** `@font-face` rules for AdihausDIN and AdineuePRO, and the footer media queries, are declared in two separate `<style>` blocks. This is redundant. Some clients that strip or truncate `<style>` content could be affected.
- **Legacy doctype.** HTML 4.01 Transitional is acceptable for email clients. It is not a defect.
- **Fonts.** The custom `@font-face` rules use only `local()` sources, so they fall back to system Arial or Helvetica. This is a fallback, not a failure.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens (`{{…}}`, `%%…%%`, `[FIRSTNAME]`) are visible in the supplied source or the QA output. The truncated portion was not checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **No plain-text alternative (FAIL).** The text version is 0 characters. This hurts spam scoring and accessibility, and it is a multipart/alternative best-practice failure.
- **Authentication headers not verifiable.** `Authentication-Results` was not found because the message came through the AgentMail relay, so SPF, DKIM and DMARC status is unknown. This is a limit of the test setup, not a confirmed sender fault. The sender domain is `us-news.comms.adidas.com`.
- **Unsubscribe and physical address.** The `List-Unsubscribe` and `List-Unsubscribe-Post` headers, the footer unsubscribe link and the postal address were not in the supplied data. They are unconfirmed, not failing.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not assessable. The CTA hrefs are not in the truncated source, and the 13 tracking links were not followed, so UTM parameters and landing destinations are unverified. Links route through the `click.comms.adidas.com` redirect domain. Any UTMs would be applied at redirect time and need a follow-the-redirect check.

## 7. Recommendations
1. **Add a `text/plain` part.** This is the only hard failure. Include the main CTA URLs and the unsubscribe link.
2. **Serve all images over HTTPS.** Fix `image.link.adidas.com/…/b0c011a2-…jpg` and `click.comms.adidas.com/CI0/…`.
3. **Add `alt` attributes** to the `dv.adidas.com/o/680c0b40-…` image and the `click.comms.adidas.com/CI0/…` image. Use `alt=""` for decorative images.
4. **Fix the charset meta.** Use `<meta http-equiv="Content-Type" content="text/html; charset=UTF-8">`, and confirm the MIME part declares the charset.
5. **Merge the duplicate `<style>` blocks** into one.
6. **Re-run the audit with the full HTML and raw headers.** This lets you verify the unsubscribe headers, SPF/DKIM/DMARC, the tracking-link redirect chain and UTM presence.
