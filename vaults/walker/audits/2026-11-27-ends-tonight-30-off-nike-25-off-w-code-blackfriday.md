## Technical Audit

## 1. Technical Summary
The HTML is a conventional table-based ESP template (Cordial-style `emltrk.com` tracking) with responsive CSS. Two tracking pixels have malformed URLs, and the QA run could not verify authentication, tracking links, or footer compliance. Those gaps come from the relay and from the truncated source.

## 2. Link & Tracking Issues
- **Unverified links:** 33 tracking links were skipped by the QA probe (click-redirect domains), so destinations and redirect health are unconfirmed.
- **Malformed pixel URL (1):** `https://ieezzy5m.emltrk.com/v2/ieezzy5m?i=72180589&t=utm_campaign=SCA_20261127_nike_jordan_clogs_boots_black_friday_PM​`
  - The value ends in an invisible zero-width character (U+200B) after `PM`. Some clients and proxies will percent-encode or strip it, which can fragment campaign attribution.
  - `utm_campaign=` is nested inside a `t=` value instead of being its own query parameter.
- **Unresolved placeholder (2):** `https://0di86k1v.emltrk.com/v2/0di86k1v?d=[UNIQUE]`
  - The literal `[UNIQUE]` was delivered, so the token was not substituted.
  - Unencoded `[` and `]` are also not valid in a URL query.

## 3. Rendering & Accessibility
- **Missing alt text, content images:**
  - `https://image.email.shoecarnival.com/lib/fe3311737164047d701077/m/1/8596c416-45c9-4d51-afc5-a39814038aba.jpg`
  - `https://image.email.shoecarnival.com/lib/fe3311737164047d701077/m/1/56f4d386-deaa-4ef4-83a9-77da7e03c3a0.jpg`
  - Screen readers will read the filename, or nothing if the image is the only content of a link.
- **Missing alt text, tracking pixels:** the two `emltrk.com` pixels need `alt=""` and ideally `width="1" height="1"`.
- **Link styling:** the global rule `a, a:link, a:visited … { text-decoration:none !important; color:inherit !important; }` removes underline and color from every link. Any inline text link is then indistinguishable from body text unless it is styled as a button. This fails WCAG 1.4.1 (use of color).
- **Ineffective meta tags:** `<meta content="IE=edge" />` and `<meta content="text/html;" charset="utf-8" />` have no `http-equiv`. The IE-edge tag does nothing, and the charset declaration is non-standard under the HTML 4.01 doctype.
- **Doctype mismatch:** the HTML 4.01 doctype is combined with `xmlns="http://www.w3.org/1999/xhtml"` and `<meta … />` self-closing syntax. This is harmless in most clients but inconsistent.

## 4. Personalization & Merge Tokens
- `d=[UNIQUE]` in the `0di86k1v.emltrk.com` pixel is an unresolved token, so per-recipient open tracking is likely broken for that pixel.
- No other tokens are visible in the truncated source.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication-Results:** the header was not found. The QA tool attributes this to the AgentMail relay, so SPF, DKIM and DMARC are unverified. This is not evidence of a sender misconfiguration.
- **Footer and headers:** the truncated source does not include the footer, so the unsubscribe link, physical address and `List-Unsubscribe` / `List-Unsubscribe-Post` headers could not be checked. No violation is claimed.
- **Sending domain:** the From domain `email.shoecarnival.com` matches the image host `image.email.shoecarnival.com`, which is consistent.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Campaign tag:** it is `SCA_20261127_nike_jordan_clogs_boots_black_friday_PM`, and the date matches the send date. It appears only in the malformed pixel `t=` value, not as a standard `utm_*` parameter.
- **Landing pages:** all 33 click-through links were skipped, so UTM propagation, the BLACKFRIDAY code and Nike landing-page alignment could not be verified.

## 7. Recommendations
1. Remove the U+200B from the `ieezzy5m` pixel URL and pass `utm_campaign` as a proper parameter.
2. Fix the `[UNIQUE]` substitution in the `0di86k1v` pixel, or confirm it is intentionally replaced at send time. URL-encode the brackets either way.
3. Add descriptive `alt` text to the two `image.email.shoecarnival.com` JPGs, and add `alt=""` to both tracking pixels.
4. Restore underline or a distinct color on inline text links, or scope the `color:inherit !important; text-decoration:none !important` rule to button links only.
5. Change the meta tags to `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
6. Re-run QA on the full, untruncated HTML with raw headers (SPF, DKIM, DMARC, `List-Unsubscribe`). Resolve the tracking redirects with a followed-redirect check to confirm landing URLs and UTM carry-through.
