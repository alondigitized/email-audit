## What's weak

- Nearly every picture is women's. It's a model in a skirt, a heeled suede boot and a tall black boot.
- The men's content is one small rubber boot in a row of three. I'd have to tap through to find anything for a man.
- There's nothing about cushioning, arch support, or slip-on comfort. It's all style and price.

## Technical Audit

## 1. Technical Summary
The HTML is a standard Braze/SendGrid-style template with dark-mode CSS and tracked links. The one hard failure is a 400 on the "Opt-In to Texts Get 15% Off" link. There are also accessibility gaps in the document head and image attributes. The source was truncated, so footer and body findings are limited to what the QA data covers.

## 2. Link & Tracking Issues
- **[FAIL] 400 on the SMS opt-in CTA.** The link text is "Opt-In to Texts Get 15% Off". The URL is `https://ablink.dsw.com/f/a/34ZpSpos2HmuFk-MVlBxTg~~/AAQRxRA~/ZYh-BoGj…`. It is a wrapped click-tracking redirect.
  - A 400 from the redirector means the tracking token was rejected or malformed. It could also be a bot or HEAD-probe rejection.
  - The QA data can't tell these apart. Verify with a real GET and a browser click.
  - If it is a real failure, the email's SMS-acquisition CTA is dead.
- **Probe coverage is partial.** 12 links were probed and 55 skipped. The unsubscribe link is always probed and has no reported failure. Links outside the probed set are unverified.
- **Tracking pixel.** `https://mi.dsw.com/p/up/e6f23fb0…/o.gif?mi_u=225090073&mi_ecmp=20261112_P261679_V1_W-_Offer_Value` is an open-tracking pixel that carries a subscriber ID (`mi_u`) in the query string. That is expected behavior, not a defect.

## 3. Rendering & Accessibility
- **Missing alt text on two images (QA WARN):**
  - `https://ablink.dsw.com/q/umBevXTMZap8ZSb_y8Bafg~~/…`. It is a tracked image, and its role (content or decorative) can't be determined from the truncated source. If it is content, this is a real accessibility gap.
  - `o.gif` is the 1x1 tracking pixel. It should have `alt=""`, which is a minor fix.
- **No `lang` attribute.** The root element is `<html xmlns="http://www.w3.org/1999/xhtml">`. Screen readers can't pick the correct language profile.
- **Viewport blocks zoom.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` prevents pinch-zoom, which is a WCAG 1.4.4 concern.
- **Malformed meta tags.**
  - `<meta content="text/html; charset=utf-8" />` has no `http-equiv`, so it declares nothing.
  - `<meta content="IE=Edge" />` has no `http-equiv` either.
  - The charset is normally set by the MIME `Content-Type` header, so impact is likely low, but the tags are dead markup.
- **Generic `<title>`.** The title is just `DSW`. It is minor and only matters in web-view or archive contexts.
- **Plain-text part is mostly URLs.** The QA check found 22,728 of 27,076 characters are URLs (84%). That is a spam-filter risk and a poor plain-text experience. The cause is long `ablink.dsw.com` tracking URLs.

## 4. Personalization & Merge Tokens
No issues found. The visible source has no unrendered `{{ }}`, `${}`, or `%%` tokens. The one unusual value is `W-` in `mi_ecmp=…_W-_Offer_Value`. It might be an empty segment variable, but that can't be confirmed from the data, so it is not flagged.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication-Results header not found.** SPF, DKIM and DMARC status is unknown. The QA note attributes this to the AgentMail relay stripping it, so it is a test-harness limitation and not a confirmed sender fault. Verify via raw headers at the original delivery point.
- **Unsubscribe and physical address.** The unsubscribe link is probed and not reported as failing. The footer was truncated, so the physical address and `List-Unsubscribe` headers could not be checked.
- **Sender.** `From: DSW <dsw@e.dsw.com>` uses a dedicated subdomain, which is good practice.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **UTM parameters can't be evaluated.** All links are wrapped in `ablink.dsw.com` redirects, so final destinations and UTM parameters aren't visible in the data.
- **Campaign ID.** The `mi_ecmp` value is `20261112_P261679_V1_W-_Offer_Value`. It tracks by that ID rather than standard UTMs.
- **Boot-offer landing page.** The landing page for the "30% off boot styles" offer wasn't probed in the material provided.

## 7. Recommendations
1. **Priority:** Manually test the "Opt-In to Texts Get 15% Off" link with a GET and in a browser. If it still returns 400, regenerate the tracked link or fix the destination.
2. Add `lang="en"` to `<html>` and remove `maximum-scale=1` from the viewport tag.
3. Fix or remove the two dead meta tags. Use `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
4. Add meaningful `alt` text to the tracked content image, and `alt=""` to `o.gif`.
5. Reduce plain-text URL bloat with a shorter tracking domain or fewer wrapped links in the text part.
6. Re-run with a fuller HTML sample and raw headers to check the footer, `List-Unsubscribe`, SPF/DKIM/DMARC, and the destination UTMs.
