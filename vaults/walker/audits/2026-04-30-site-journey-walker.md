I'm a 62-year-old guy who just wants to find my Slip-ins, confirm they have a deal, and buy them. ## Technical Audit

## Technical Summary

8-step mobile journey audit across skechers.com. TTFB is consistently fast (23–27ms) but View Cart is an outlier at 132ms. The site carries an unusually heavy third-party script payload. The View Cart page has a broken document shell (missing `<title>` and `lang`), indicating a likely SPA routing or partial-render failure. Kasada bot-protection SDK is generating self-inflicted 429s throughout the session. A third-party outfitting widget (Stylitics) has a CORS misconfiguration. LCP and CLS data was not captured and should be re-run.

## Accessibility

**16 violations across 3 pages. Two are critical/serious structural failures.**

**View Cart — 4 violations, all serious/moderate:**
- `document-title`: `<title>` element is empty or absent. This is a hard failure — screen readers announce the tab as untitled, and it indicates the page shell did not fully render.
- `html-has-lang`: `lang` attribute missing from `<html>`. AT cannot determine language for pronunciation.
- `landmark-one-main`: No `<main>` element present. Full page content is landmark-orphaned.
- `page-has-heading-one`: No `<h1>`. Document outline is broken.

**Homepage — 9 violations:**
- `aria-required-parent` (critical): ARIA role present without required parent container. Likely a listbox/option or tablist/tab structure missing its wrapper.
- `link-name` (serious): One or more `<a>` tags have no discernible text (no text content, `aria-label`, or `title`). Common cause: icon-only links or image links with no `alt`.
- `landmark-main-is-top-level` / `landmark-no-duplicate-main` / `landmark-complementary-is-top-level` / `landmark-unique`: Multiple nested and duplicate landmarks — indicates a component injection pattern (likely Monetate or a CMS slot) is inserting page sections without respecting the existing landmark tree.
- `heading-order`: Non-sequential heading levels (e.g., `<h1>` → `<h3>`).
- `aria-allowed-role` (minor): A role is applied to an element that doesn't permit it.
- `region`: Content outside any landmark region.

**Search "slip in" — 3 moderate violations:** Duplicate/nested `<aside>` and `<main>` landmarks, content outside landmarks. Pattern matches the homepage sidebar/widget injection issue.

## Mobile Optimization

**Viewport height JS hack:**
```html
style="--vh: 6.640000000000001px;"
```
The site uses a JavaScript-computed `--vh` custom property to work around iOS Safari's dynamic viewport behavior (the classic 100vh bug). The floating-point artifact (`6.640000000000001` instead of `6.64`) is a JS arithmetic precision issue — harmless visually but indicates this is a raw `window.innerHeight / 100` calculation. Modern CSS (`dvh`, `svh`, `lvh`) eliminates the need for this entirely and is supported in iOS Safari 15.4+. The JS approach fires on resize/orientation change and can cause layout recalculation jank.

No other mobile-specific structural issues are visible from the HTML sample. Viewport meta tag is assumed present (not visible in truncated source but no violations were flagged against it).

## Console & Network Errors

**429 — Kasada fingerprinting endpoint (5 hits):**
```
/149e9513-01fa-4fb0-aad4-566afd725d1b/2d206a39-8ed7-437e-a3be-862e0f06eea3/fp?x-kpsdk-v=j-1.2.386
```
This is the Kasada bot-detection SDK (`kpsdk`) sending fingerprint probes. All 5 are rate-limited with 429. In a real user session this would not occur — the 429s are triggered by the automated browser context being flagged by Kasada as non-human. The SDK retries on rejection, generating additional requests. This is expected behavior in a headless/automated test but confirms Kasada is active and correctly detecting non-browser clients. **Not a production bug for real users, but will corrupt any automated perf or monitoring data collected from a headless browser.**

**429 — `/cart/` (1 hit):**
The cart page document itself returned 429. This is more concerning — it may indicate Kasada is blocking the cart page render for flagged sessions, or the cart endpoint has its own rate limit that fires under test conditions. Either way, this is the direct cause of the View Cart TTFB outlier and the missing document shell (no `<title>`, no `<html lang>`).

**CORS block — Stylitics:**
```
Access to CSS stylesheet at 'https://web-assets.stylitics.com/style.css?...' from origin 'https://www.skechers.com' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header
```
Stylitics (outfit/shoppable-look widget) is serving a stylesheet without the required CORS header. The widget will render without its styles. This is a Stylitics infrastructure misconfiguration — skechers.com needs to raise it with the vendor. The specific version hash (`a1c0a40fa3`) suggests a versioned deploy that may have dropped the header.

## Recommendations

**P0 — Fix immediately:**
1. **Investigate View Cart 429.** Determine whether Kasada is gating the cart page document for flagged sessions and whether real mobile users on slow connections can trigger this. A cart page that returns 429 means an unrecoverable empty document.
2. **Fix View Cart document shell.** The missing `<title>` and `html[lang]` on View Cart are either caused by the 429 returning an error shell, or by a SPA route that never sets document metadata. Add a fallback title + lang in the error state and ensure the cart route sets both on navigation.

**P1 — Fix this sprint:**
3. **Fix Homepage `link-name` violations.** Audit all icon-only and image links for `aria-label` or visible text. This is a WCAG 2.1 AA failure.
4. **Fix `aria-required-parent` violation.** Locate the ARIA composite widget (likely a carousel, listbox, or tab panel) missing its wrapper role and add it.
5. **Fix Stylitics CORS.** File a ticket with Stylitics to re-add `Access-Control-Allow-Origin: https://www.skechers.com` (or `*`) to their stylesheet CDN response.
6. **Re-run audit capturing LCP and CLS.** Use a real browser (non-headless) with Kasada bypass or a whitelisted IP to get uncontaminated Web Vitals.

**P2 — Backlog:**
7. **Audit landmark injection from Monetate/CMS slots.** The duplicate `<main>` and nested `<aside>` violations across homepage and search are caused by injected content — likely a Monetate action or component slot inserting landmark-wrapped HTML into an already-landmarked page. Enforce that injected content uses `<div>` wrappers only, not `<main>`, `<section>`, or `<aside>`.
8. **Replace `--vh` JS hack with `dvh`.** Migrate to `height: 100dvh` for full-bleed mobile layouts. Saves a JS resize listener and eliminates the precision artifact.
9. **Audit third-party script necessity.** 20+ third-party scripts on every page is high. Confirm each vendor is still active, deduplicate the duplicate Yahoo script (`ytc.js` loads twice), and evaluate moving non-critical pixels to a server-side tag via the existing Stape CDN integration.
