# Take an extra 20% off select markdowns
**Score:** 8/10 · **Type:** Email audit · **2026-07-10**
## Executive summary

- Another one from New Balance — tenth or so in two weeks by my count, though this time the offer in the subject line actually made me pause. "Extra 20% off select markdowns" is plain English, and the deadline in the preview ("Offer ends July 16th") told me everything I needed before I even opened it. That part works.
- Then I got inside and the first thing staring at me is a pile of composition notebooks and crumpled paper. I had to blink and check that I didn't open the wrong email. This is a shoe sale, right? The notebooks are back-to-school creative — I get it, the calendar says July — but it doesn't make me think about my feet. Once I scrolled past the hero, the offer headline showed up clearly, the price-range tiles were easy enough to tap, and there was a "Shop now" button. So the bones are fine. Then I looked at the actual shoes in "More to explore": a skate shoe (NB Numeric Tiago Lemos), a couple of retro sneakers, a six-pack of socks. Nothing that says comfort walking, nothing that says cushion, nothing that says this was picked for a guy in his sixties who wants his feet to stop aching by mile two.
- I would not click. I might glance at the price tiles if I had a minute, but I'd probably just swipe to archive. I would not forward this to anyone.

## What's working

- **Offer is front and center** — "Take an extra 20% off select markdowns" is a real sentence with a real number. No mystery, no "exclusive event," no vague percentage range.
- **Preview text earns its keep** — "Offer ends July 16th" tells me the deadline without repeating the subject line word-for-word. That's exactly what preview text is for.
- **Price-range tiles are useful** — Under $50 / $50–$100 / $100–$150 / $150+ is the kind of navigation that works on a phone with one thumb. Simple, obvious, no tiny dropdowns.
- **No render bugs** — Email loads clean, no broken images, no garbled text, nothing overlapping. That's the minimum but plenty of brands can't manage it.
- **Deadline is credible** — "Now through Thursday" with an actual calendar date (July 16) in the preview doesn't feel made-up.

## What's weak

- **Notebooks as the hero image** — I'm here because I want shoes. Opening an email with a pile of school supplies is disorienting and costs a couple of seconds of goodwill I'm not going to get back.
- **Promo code is friction on a phone** — EXTRA20 means I have to type something at checkout, or screenshot this, or trust that I'll remember it. At 62 with my thumbs, that's a real barrier. Just apply the discount automatically.
- **Product grid has nothing for me** — A skate shoe, two retro fashion sneakers, and a sock multipack. Zero cushioning callouts, zero walking-shoe options, nothing that maps to what I'm actually shopping for.
- **Small fine-print text** — The exclusions block below the CTA is tiny. I can tell it says something about "previous purchases" and "other offers" but I'd need to zoom in on my phone, and I'm not going to do that.
- **Tenth email in two weeks** — After the kids' back-to-school push ("We're back," July 9), another kids email (July 2), and the end-of-season event (July 1), this one is landing in crowded territory. The cadence is wearing me out.

## Recommendations

- 1. **Drop the notebooks image; use a comfort/walking shoe** — If this is a markdown sale, show me what's actually on markdown. A 990, a Fresh Foam, anything with a wide toe box — something that signals this sale has shoes for people like me, not just teenagers heading back to school.
- 2. **Kill the promo code; apply the discount automatically** — Auto-discount at cart is table stakes now. EXTRA20 is friction that drops mobile conversions. NB can track it on the backend without making me type.
- 3. **Swap "More to explore" for walking/comfort models** — If I'm Walker Miles and I've clicked into a markdown sale, show me the Fresh Foam 1080, the 990v6, the 860 — wide widths available, cushioning callout, something I actually need to know.
- 4. **Increase fine-print font size** — Not asking for a legal essay, just make it legible at arm's length on a phone. Two more pixels won't break the layout.
- 5. **Subject Alt A:** `Extra 20% off comfort & walking markdowns — ends Thursday`
- 6. **Subject Alt B:** `Your markdowns. 20% more off. Through July 16.`
- 7. **Preheader Alt A:** `Fresh Foam, 990s, and more — now at clearance price plus extra 20%`
- 8. **Preheader Alt B:** `Walking and comfort styles included — code applies at checkout`

## Technical Audit — New Balance "Extra 20% off select markdowns"

### 1. Technical Summary

The email uses an HTML 4.01 Transitional doctype with several CSS authoring errors — a duplicate conflicting class definition and non-functional `@font-face` blocks — that could cause rendering inconsistencies. Full link, compliance, and personalization analysis is limited by source truncation.

---

### 2. Link & Tracking Issues

**HTTP asset in CSS rule**
`.bgwhite` sets a background image over HTTP:
```css
.bgwhite { background-image: url('http://image.XXXXX.png'); }
```
Some clients (particularly Gmail on iOS/Android) block or silently drop HTTP asset loads when the page is viewed over HTTPS. This URL also appears to be a placeholder (`XXXXX`) — if this shipped as-is, the asset would 404.

*Full redirect-chain and UTM coverage cannot be assessed; source is truncated before body links appear.*

---

### 3. Rendering & Accessibility

**Duplicate `.bg1` class with conflicting values**
Defined twice in `<style>`:
```css
.bg1 { background-color: #ffffff; }   /* line ~7 */
...
.bg1 { background: #58546d; }         /* line ~65 */
```
The second declaration wins in cascade order, turning any `.bg1` element from white to a dark purple-grey. Any table cell relying on `.bg1` for a white background is broken.

**`<meta content="IE=edge" />` missing `http-equiv`**
```html
<meta content="IE=edge" />
```
Should be:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without `http-equiv`, this tag is ignored. Outlook 2010/2013 (which keys on this directive) may fall back to Quirks Mode rendering.

**`@font-face` blocks have no `src:` descriptor**
All nine `@font-face` declarations declare `font-family`, `font-weight`, and `font-style` but omit `src:`. A `@font-face` rule without `src` is inert — no font file is fetched. The email falls back entirely to Arial/Times New Roman. If `proxima-nova` is loaded via Adobe Fonts JS elsewhere, that script won't execute in most email clients, confirming the fallback path.

**Invalid `font-family` value inside `@font-face` descriptors**
```css
@font-face { font-family: proxima-nova,sans-serif; ... }
```
The `font-family` descriptor in `@font-face` defines a name, not a stack. Comma-separated generic keywords (`sans-serif`) are not valid here per CSS Fonts Level 3/4. Parsers will likely accept only `proxima-nova` and discard the rest, but this is malformed CSS.

**Duplicate `font-family` descriptor in italic variant**
```css
@font-face { font-family: proxima-nova,sans-serif; font-weight: 700; font-style: italic;font-family: proxima-nova,sans-serif; }
```
`font-family` appears twice in the same block — a copy-paste artifact. Harmless in this case (identical value) but indicates template assembly errors.
