### 3. Rendering & Accessibility

**Critical — Unclosed `@media` blocks (CSS parse failure):**

```css
/* 414px block opens but never closes before next @media */
@media screen and (max-width: 414px) { .padl10m { padding-left: 0px; }
@media screen and (max-width: 412px) { .padl10m { padding-left: 0px; }
```

Both the `414px` and `412px` blocks are missing their closing `}`. CSS parsers in strict clients (Apple Mail, Outlook.com) will discard all rules from the first malformed block onward through the end of the `<style>` tag. This silently breaks all responsive rules at ≤414px — affects iPhone SE, older Android, and small-viewport devices.

**Minor — Duplicate `<meta name="viewport">`:**

```html
<meta content="width=device-width; initial-scale=1.0; maximum-scale=1.0;" name="viewport" />
<meta name="viewport" content="width=device-width" />
```

The second declaration overrides the first, stripping `initial-scale=1.0` and `maximum-scale=1.0`. The intended scale-lock is effectively absent. Keep one declaration with all intended values.

**Minor — Missing `http-equiv` on Content-Type meta:**

```html
<meta content="text/html; charset=utf-8" />
```

Should be:

```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

Without `http-equiv`, some legacy clients ignore the charset declaration entirely.
