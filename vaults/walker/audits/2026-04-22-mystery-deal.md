### 3. Rendering & Accessibility

**Bug — `Src:` capitalized in all 10 `@font-face` declarations:**
```css
Src: url("https://braze-images.com/appboy/.../original.woff") format('woff');
```
The CSS property `src` is case-sensitive in standards-compliant parsers. `Src:` will be silently ignored, causing all custom web fonts (Futura PT, Helvetica Now) to fail to load. Affects every `@font-face` block in the template. Fallback system fonts will render instead.

**Bug — `<meta>` tags missing `http-equiv` attribute:**
```html
<meta content="text/html; charset=utf-8" />
<meta content="IE=Edge" />
```
Both are non-functional as written. Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```
The charset declaration being ignored could cause mojibake in non-UTF-8-defaulting clients.

**Bug — conflicting `text-size-adjust` in reset CSS:**
```css
* { -ms-text-size-adjust: 100%; -webkit-text-size-adjust: 100%; ... -ms-text-size-adjust: none; text-size-adjust: none }
```
The reset first sets `-ms-text-size-adjust: 100%`, then overrides it with `none` in the same `*` rule. `none` disables resize adjustment entirely; `100%` is the correct cross-client value. This can cause text scaling issues in Windows Mail / Outlook.com.

**Observation — near-black dark mode values:**
```css
.dm-bg-black { background: #00000F !important; }
.dm-font-black { color: #000001 !important; }
```
Off-by-one-from-black values are a known pattern to prevent Apple Mail from inverting pure `#000000` in dark mode. Intentional if confirmed by template owners; worth documenting as expected behavior so future editors don't "fix" them.
