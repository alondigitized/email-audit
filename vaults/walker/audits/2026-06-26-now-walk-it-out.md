## What's weak

- **No price hook anywhere** — six-plus emails in ten days and HOKA still hasn't offered me a dime off; at some point I start wondering why I'm still opening these
- **"Now walk it out" subject falls flat** — "walk it out" is a younger person's phrase and the "Now" implies urgency that the email body doesn't back up
- **Women's and Men's split 50/50 in the grid** — if HOKA knows I'm male from my purchase history, lead with the men's colorways; showing me women's shoes first dilutes the sense that this was aimed at me
- **Free Shipping is behind a text-message wall** — I want the shoes, not a text subscription; this feels like a list-building move dressed up as a perk
- **No star ratings under the Bondi 9 or Transport 2** — the Bondi 9 is one of the most reviewed walking shoes on the market; not showing even a summary rating is a missed trust signal

### 3. Rendering & Accessibility

**Issue — Duplicate and conflicting `<meta name="viewport">` tags:**
```html
<!-- tag 1 -->
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<!-- tag 2 — conflicts -->
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
`maximum-scale=1` (tag 1) suppresses user zoom; `user-scalable=yes` (tag 2) re-enables it. Browsers take the first encountered value; the second tag is dead weight and signals a copy-paste error. Remove tag 2 and decide on a single authoritative viewport policy.

**Issue — Malformed CSS values in `@media (max-width: 480px)`:**
```css
.nav_padding  { padding-top:px !important; padding-bottom:px !important; }
.nav_border   { border-top:px solid ; }
```
Both rules are missing the numeric dimension before `px`. The property values are invalid and will be ignored by all parsers. If these classes are applied to nav spacer elements, they will silently fall back to inherited or default values rather than the intended zero/custom spacing. Fix: supply a value (e.g., `0px`, `10px`) or remove the rules if unused.

**Issue — `font-display: swap` in `@font-face`:**
```css
@font-face { font-family: "TheFutureHOKA"; ... font-display: swap; }
```
`font-display` is a CSS property for browsers, not email clients. All major email renderers (Gmail, Outlook, Apple Mail) ignore it. It is harmless but should be omitted to keep the `<style>` block lean and avoid triggering overly strict spam filters that penalize large style blocks.

**Issue — `<meta charset>` missing `http-equiv`:**
```html
<meta content="text/html; charset=utf-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, some legacy email clients (Outlook 2007–2016) may not honour the charset declaration.
