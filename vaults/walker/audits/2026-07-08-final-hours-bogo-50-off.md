# Final! Hours! BOGO 50% OFF!
**Score:** 8/10 · **Type:** Email audit · **2026-07-08**
## Executive summary

- Well, here we go again. Third "final hours" alarm from DSW in the span of a week — first they FINAL HOUR'd the 25% off deal into the grave back on July 5th, and now BOGO gets the same treatment. I'm starting to hear wolf. When everything is a last call, nothing is.
- That said, the BOGO 50% off offer is right there at the top, big and red, and the secondary 40% off clearance hook in the preview is a genuine add — those two stacked together is real money if I can find men's comfort shoes in my size. Problem is, I scroll down through this email and it's heels. Strappy sandals. Wedges. Women's fashion shoes top to bottom. Not a walking shoe or a wide-toe box in sight.
- I'd mark this as read and move on. The deal exists and DSW is on my radar, but nothing in this email is speaking to me. I wouldn't click, wouldn't forward.

## What's working

- **BOGO 50% OFF hero is unmissable.** Big red text, top of the fold — I can see the offer without hunting.
- **Clearance callout in the preview text is a smart add.** "Last call for 40% off clearance, too" says something different than the subject line, which is the right move.
- **Size selector visible in the clearance block.** That's a practical convenience — even if I didn't click through, the fact that they show sizes in-email is useful.
- **No visual chaos.** The email renders cleanly. Images load, layout holds, text is legible at a glance on my phone.

## What's weak

- **Every single product I can see is women's shoes.** Strappy heels, wedge sandals, fashion mules. I'm a 62-year-old man looking for cushioned walking shoes and I've got zero reason to scroll.
- **"Final! Hours!" subject punctuation feels like a scam.** Each word getting its own exclamation point reads like it came from a spam folder. Doesn't instill confidence.
- **This is the same urgency beat DSW used on the 25% off campaign.** "FINAL HOURS" on July 5th, BOGO launch July 6th, "last day" July 8th — now "Final! Hours!" again. The pattern is exhausting. I'm numb to it.
- **"YOUR MID WEEK MOOD BOOST" section adds nothing for me.** I don't shop for a mood. I shop because my feet hurt and I need something that fits right.
- **Zero comfort / support language visible anywhere.** No "cushioned," no "arch support," no "wide width" — nothing for my decision criteria.

## Recommendations

- 1. **Split the email by gender.** Send me the men's comfort clearance version. Everything visible here is women's product. This should be a different creative entirely for male subscribers.
- 2. **Drop the exclamation-point stutter in the subject.** "Final! Hours!" looks like phishing bait. Pick one strong noun and let it breathe.
- 3. **Lead the clearance block with sizing.** The size buttons are the most useful element in this email — put that earlier, not buried at the bottom. Clearance is where I find deals on shoes that actually fit.
- 4. **Rotate the urgency language.** DSW has run "final hours / last day / ends tomorrow" on back-to-back sends for two weeks now. One alternate frame: "We picked the best clearance men's walkers before they're gone."

- **Subject Alt B:** `Last chance: BOGO 50% off + clearance deals`

### 3. Rendering & Accessibility

**Issue — `Src:` (uppercase) in all `@font-face` declarations**
All 10 `@font-face` blocks use `Src:` instead of the spec-required lowercase `src:`. CSS property names are case-insensitive per spec, but several strict email client parsers (notably older Outlook WebView) reject non-lowercase property names, silently skipping the rule and falling back to system fonts.

```css
/* INVALID — all 10 blocks have this */
Src: url("https://braze-images.com/...woff") format('woff');
/* Should be */
src: url("https://braze-images.com/...woff") format('woff');
```

**Issue — `<meta charset>` missing `http-equiv`**
```html
<!-- Present -->
<meta content="text/html; charset=utf-8" />
<!-- Should be -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv="Content-Type"`, some Outlook/Lotus Notes versions don't apply the charset declaration, risking mojibake on non-ASCII characters.

**Issue — `<meta IE=Edge>` missing `http-equiv`**
```html
<!-- Present -->
<meta content="IE=Edge" />
<!-- Should be -->
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```

**Issue — `supported-color-schemes` is not a valid CSS property**
In the `:root` dark mode block:
```css
:root {
  color-scheme: light dark;
  supported-color-schemes: light dark; /* ← not a CSS property */
}
```
`supported-color-schemes` is only valid as a `<meta name="supported-color-schemes">` tag (already correctly present). The CSS declaration is a no-op but signals a copy-paste error from an outdated template.

**Issue — No `woff2` format for any custom fonts**
Futura PT variants load only `.woff`; HelveticaNow variants load only `.ttf`. Apple Mail and modern WebKit clients support `woff2` which is ~30% smaller. Absence means slower font resolution in clients that render web fonts.

**Cannot assess** — `alt` text on images not visible in truncated source. Verify all `<img>` tags carry descriptive `alt` values; decorative images should have `alt=""`.
