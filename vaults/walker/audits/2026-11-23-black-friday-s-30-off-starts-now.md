## Technical Audit

## 1. Technical Summary
The email has two confirmed defects: a raw `%%gender%%` merge token and a click-tracked CTA ("Opt-In to Texts Get 15% Off") that returned HTTP 400. The automated QA pass rate was 50%. The HTML source was truncated, so the body, footer and unsubscribe markup could not be inspected.

## 2. Link & Tracking Issues
- **Broken CTA (FAIL).** The link with text "Opt-In to Texts Get 15% Off" returned **400**. The URL is `https://ablink.dsw.com/f/a/lekJscGCYJI6N087f5MaXw~~/AAQRxRA~/CHE-kp6E…`, a very long redirect-wrapped tracking URL.
  - The QA output shows no label in front of the link text, so the link may have no anchor `title` or `aria-label`.
  - A 400 on a signed tracking URL can mean the redirect token was truncated or malformed. It can also mean the ESP rejected the automated probe. It needs a manual click-through to tell which, but it should be treated as a live defect for the SMS opt-in, which is the highest-value conversion in the email.
- **Link coverage.** Only 12 of 77 links were probed, so the other 65 are unverified. The probe ranks by click likelihood and always includes an unsubscribe link, and none of the 12 probed links other than the CTA above are reported as failing.
- **Tracking pixel.** `https://mi.dsw.com/p/up/e6f23fb0…/o.gif?mi_u=225090073&mi_ecmp=20261123_P261708_V1_WM-_Offer_Stan…` is an open-tracking pixel. Its query string carries a user ID (`mi_u`). Nothing is wrong with that, but this is where the per-recipient identifier appears.

## 3. Rendering & Accessibility
- **Missing alt text (2 images).**
  - The image linked via `https://ablink.dsw.com/q/_qaDU1Yz5WXvxfiQLkovew~~/…` has no alt attribute. Because it is an image inside a link, screen readers will announce the raw URL or nothing.
  - `o.gif` has no alt attribute. This is lower severity, but the tracking pixel should carry `alt=""` and `role="presentation"` or `aria-hidden="true"`.
- **Zoom disabled.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` blocks pinch-zoom on mobile, which fails WCAG 1.4.4.
- **Ineffective meta tags.** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv` attribute, so neither declares anything. The charset is then left to the HTTP `Content-Type` header.
- **Plain-text part.** The plain-text alternative is 27,538 of 33,157 characters URLs (83%), which is over the 70% warning threshold. Long tracking URLs are inflating the text part, and spam filters can read that as a negative signal.
- **Dark mode.** Dark-mode support (`color-scheme` meta and `prefers-color-scheme` styles) is present.

## 4. Personalization & Merge Tokens
- **FAIL: unrendered merge token `%%gender%%`.** The `%%…%%` syntax is not Braze Liquid, which the `braze-images.com` assets suggest this email uses (Braze uses `{{ }}`). It is more likely a leftover token from another platform's template, or an unsubstituted segment value. It shows up as literal text or inside a URL.
- Check whether the token sits in an `href` or query string. If it does, the destination may be breaking or mis-segmenting the visitor.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication-Results header not found.** SPF, DKIM and DMARC status is unknown. The QA tool notes that this is expected when mail passes through the AgentMail relay, so this is a gap in the test setup and not a finding against the sender. The From domain is `e.dsw.com`.
- **Unsubscribe and physical address.** The truncated source doesn't show the footer, so neither could be verified. The QA probe didn't report an unsubscribe failure. No `List-Unsubscribe` header data was provided.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **UTM parameters.** All links are wrapped in `ablink.dsw.com` redirects, so the final destinations and any UTM parameters can't be seen in the source.
- **Campaign ID.** The only visible campaign identifier is `mi_ecmp=20261123_P261708_V1_WM-_Offer_Stan…` on the pixel.
- **Landing pages.** The only landing page tested was the CTA, which returned 400, so landing-page alignment can't be assessed.

## 7. Recommendations
1. Manually click the "Opt-In to Texts Get 15% Off" link. If it fails, regenerate it in the ESP. Check that the tracking URL isn't truncated or double-encoded in the template.
2. Find `%%gender%%` in the template and replace it with the correct Liquid tag. Add a fallback value, and add a pre-send check that fails on any `%%…%%` or `{{…}}` left in the rendered output.
3. Add `alt` text to the image linked via `ablink.dsw.com/q/_qaDU1Y…`, and `alt=""` to `o.gif`.
4. Remove `maximum-scale=1` from the viewport meta.
5. Add `http-equiv="Content-Type"` to the charset meta, and `http-equiv="X-UA-Compatible"` to the IE meta if it's kept.
6. Shorten or trim the plain-text part so it has more descriptive copy relative to URLs.
7. For future audits, pass the untruncated HTML and the raw headers (`Authentication-Results`, `List-Unsubscribe`, `List-Unsubscribe-Post`) so the compliance and UTM checks can run.
