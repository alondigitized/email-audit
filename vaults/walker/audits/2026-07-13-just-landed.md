### 3. Rendering & Accessibility

**Duplicate `<meta name="viewport">` tags** — Two conflicting declarations in `<head>`:

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```

iOS Safari uses the first; the second is ignored. The `maximum-scale=1` on the first tag suppresses pinch-to-zoom — an accessibility defect (WCAG 1.4.4).

**Malformed charset meta** — Missing `http-equiv` attribute:

```html
<meta content="text/html; charset=utf-8" />
```

Should be `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />`. As written, no email client will parse this as a charset declaration. If the email body contains non-ASCII characters, rendering may break in older clients.

**Broken mobile CSS rules** — Two rules in the `@media (max-width:480px)` block have missing numeric values:

```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
.nav_border  { border-top:px solid ; }
```

Both are invalid CSS and will be silently dropped. Any element using `.nav_padding` or `.nav_border` on mobile will fall back to desktop styles — likely a layout regression on narrow viewports.

**Empty `<title>` tag** — `<title></title>`. Some webmail clients (Yahoo, AOL) surface this in tab/window labels. Low severity but trivially fixable.

**`font-display: swap` in `@font-face`** — Not supported in any email client; declaration is harmlessly ignored but adds parse overhead across five `@font-face` blocks.

**Link color near-black (`#000001`)** — `a { color:#000001; }`. Intentional trick to suppress default blue link color in some clients, but verify this is deliberate; it renders identically to `#000000` visually but may cause unexpected behavior in clients that check for exact `#000000`.
