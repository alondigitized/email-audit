### 3. Rendering & Accessibility

**`@font-face` property name casing — confirmed bug:**
All 10 `@font-face` declarations use `Src:` (capital S) instead of the valid CSS property `src:`. CSS property names are case-insensitive per spec, but several email clients parse stylesheets with stricter rules (notably older Samsung Mail and some Outlook WebView variants). This can cause silent font-load failures with no visible error.

```css
/* Observed (all 10 @font-face blocks) */
Src: url("https://braze-images.com/appboy/...") format('woff');

/* Correct */
src: url("https://braze-images.com/appboy/...") format('woff');
```

**Futura PT fonts: woff-only, no woff2 fallback.**
HelveticaNow fonts serve `.ttf` (larger payload). Neither set includes a `woff2` source, which is the most widely supported and compressed format in modern email clients (Apple Mail, Gmail web). Minor performance impact.

**Invalid `Margin:` property on heading resets:**
```css
h1, h2, h3, h4, h5, h6, p, ul, li {
    margin: 0 !important;
    Margin: 0   /* ← invalid; dropped by all parsers */
}
```
`Margin:` with a capital M is not a valid CSS property. It is silently ignored — harmless today but signals a template authoring error.

**Missing `http-equiv` on two meta tags:**
```html
<!-- Missing http-equiv="Content-Type" -->
<meta content="text/html; charset=utf-8" />

<!-- Missing http-equiv="X-UA-Compatible" -->
<meta content="IE=Edge" />
```
Both are inert without their `http-equiv` attribute. The charset declaration should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

**`-ms-text-size-adjust: none` in global reset:**
```css
* { -ms-text-size-adjust: none; }
```
The value should be `100%`, not `none`. Setting to `none` in Windows Phone/older IE mobile disables automatic text-size adjustment entirely rather than locking it to 100%, which can produce illegibly small text on small viewports.
