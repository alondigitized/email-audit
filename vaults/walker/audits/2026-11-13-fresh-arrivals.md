## Technical Audit

## 1. Technical Summary
The email renders from a table-based HTML 4.01 template with responsive media queries, but it has no plain-text part (0 chars). It also loads several images over `http://` and has some missing alt attributes. The source was truncated and the links are click-wrapped, so compliance and UTM checks are only partly possible.

## 2. Link & Tracking Issues
- **22 tracking links were not probed.** They sit on click-redirect domains, so final destinations, redirect chains and dead links are unverified. This is a coverage gap, not a confirmed defect.
- **Insecure image hosts.**
  - `http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg` (the "arrow" image) appears 4 times over HTTP.
  - `http://click.comms.adidas.com/CI0/010201a1d23d42c1-e0c82cdc-1ef5-4229-8198-92769f5c7991-000000/GOugmH--…` is also loaded over HTTP. The `/CI0/` path looks like the open-tracking pixel. If so, clients that block mixed or insecure content will drop the open signal.
- **`<meta name="referrer" content="no-referrer">`** is present. It is harmless for the email, but it means no referrer is passed on image loads.

## 3. Rendering & Accessibility
- **Missing alt text** on two images:
  - `dv.adidas.com/o/0e4c6ae5-ad8b-43c4-859c-b9e6a8a5e0b2?cp_tp=…`. If this is a content image, it is invisible to screen readers and to image-blocked views.
  - The `click.comms.adidas.com/CI0/…` image. This is likely the tracking pixel, so it is low impact, but it should still carry `alt=""`.
- **Weak charset declaration.** `<meta content="text/html; charset=UTF-8" />` has no `http-equiv="Content-Type"`, so it is not a valid charset declaration. Some clients may fall back to a default encoding if the header doesn't cover it.
- **Font stacks.** The `@font-face` rules for `AdihausDIN` and `AdineuePRO` only use `src: local('Arial'), local('Helvetica')…`. They never load a web font, so every client gets a system font. The same blocks are also duplicated in several `<style>` sections, which adds weight.
- **Positive signals:** `<html lang="en">`, `x-apple-disable-message-reformatting`, a viewport meta tag, `format-detection`, and `font-display: swap`.

## 4. Personalization & Merge Tokens
No issues found. No unrendered tokens (`{{…}}`, `%%…%%`, `[FIRSTNAME]`) appear in the visible source or the QA output. The truncated portion is unchecked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **[FAIL] No plain-text alternative.** The text version is 0 chars. This hurts deliverability and accessibility, and spam filters weigh it.
- **Authentication unverified.** No `Authentication-Results` header was found. The QA notes this is expected via the AgentMail relay, so SPF/DKIM/DMARC status for `us-news.comms.adidas.com` is unknown. This is a tooling limitation, not a confirmed adidas failure.
- **Unverified:** the unsubscribe link, the physical postal address and the `List-Unsubscribe` / `List-Unsubscribe-Post` headers. None of these appear in the truncated source or the QA data.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not assessable. The links are wrapped by `click.comms.adidas.com`, and the destination URLs and any UTM parameters are not visible in the excerpt. The QA skipped the HTTP probes, so landing-page status and alignment with the "Fresh arrivals" subject are unverified.

## 7. Recommendations
1. Add a multipart `text/plain` part with the key links and the unsubscribe URL. This is the only hard QA failure.
2. Serve `image.link.adidas.com` and the `click.comms.adidas.com/CI0/…` pixel over HTTPS. Otherwise the images and open tracking can be blocked.
3. Add descriptive `alt` text to the `dv.adidas.com/o/0e4c6ae5-…` image, and `alt=""` to the tracking pixel.
4. Use `<meta http-equiv="Content-Type" content="text/html; charset=UTF-8">` so the charset is declared properly.
5. Re-run the audit with the full, untruncated HTML and the raw headers (`Authentication-Results`, `List-Unsubscribe`). Resolve the click-redirect links in a follow-up to confirm the destination URLs and UTM parameters, and to check the footer for the unsubscribe link and postal address.
