# Last day left to get 25% off!
**Score:** 7/10 · **Type:** Email audit · **2026-07-05**
## Executive summary

- I opened this one the same way I've been opening every DSW email this week — out of pure muscle memory. At this point I could set a watch by them. But when I got inside, the first thing I saw was "SO NEW, SO YOU" over a grid of women's heels and pumps. I'm a 62-year-old man shopping for something cushioned and easy on my feet. Those little block-heeled mules aren't it, hon.
- The 25% off offer is technically there — it says "CLAIM 25% OFF" in small text above the hero — but you have to hunt for it. The hero sells new arrivals, not the discount. The Semi-Annual Sale banner lower down is actually bolder and more honest about what's happening. The wide-width shop button was the one moment I felt like they remembered I exist. Everything else felt aimed at someone else's closet.
- I won't click. I'm not forwarding this. This is the tenth-ish DSW email in a week and the products on display are not mine. I'll mark it read and move on.

## What's working

- **"SHOP WIDE WIDTH" button** — that one spoke directly to me. Comfort shoppers know fit matters, and wide width is a real need. First sign all week they remembered men with wider feet exist.
- **Semi-Annual Sale banner** — the red bar with "SALE(!)" is visually punchy and honest. Twice a year, tons of deals — clear, credible, no nonsense.
- **Size range goes to 11** — I noticed the size selector includes 9, 9.5, 10, 11 at the bottom row. That says men's, even if the hero doesn't.
- **25% off is concrete** — whatever else went wrong, the offer amount is specific. No mystery discount, no "up to" hedging.

## What's weak

- **Hero products are women's shoes** — pumps, block heels, flats. I'm not the target and the visual lead makes that crystal clear before I've read a word.
- **"CLAIM 25% OFF" is tiny** — it's small grey text floating above a big lifestyle headline. The offer should be the headline.
- **"Last day" credibility problem** — DSW already said "Final hours" on July 2nd. Three days later it's still the last day? I'm a Boomer, not an amnesiac.
- **Preview text bleeds garbage** — after "+ Our Semi-Annual Sale is STILL on" there's a wall of invisible spacer characters. On my phone that looks like the email broke mid-sentence.
- **Cadence is exhausting** — ten emails in a week selling the same 25% off. Even a sale I'd want starts feeling cheap after the fifth reminder.

## Recommendations

- 1. **Lead with men's comfort shoes in the hero** — if I'm in DSW's database as someone who bought men's walking shoes, show me those. One hero image of a men's cushioned sneaker or slip-on at 25% off changes this email entirely.
- 2. **Make the offer the headline** — "25% OFF TODAY ONLY" above the fold in big type, not buried in small print. The discount is the hook; use it.
- 3. **Retire "last day" after the third send** — rotate to "Today only" or "Ends tonight" so it doesn't read as a running joke.
- 4. **Trim the preview** — cut the spacer characters and write a real second line: "Men's wide-width picks included."
- 5. **Acknowledge the cadence fatigue** — something like "We know we've been loud this week. Here's why it's worth it:" — a little self-awareness goes a long way with someone who's counted ten emails.

### 3. Rendering & Accessibility

**`http-equiv` missing on two meta tags**
Both the charset and IE compatibility metas are no-ops as written:
```html
<!-- missing http-equiv="Content-Type" -->
<meta content="text/html; charset=utf-8" />

<!-- missing http-equiv="X-UA-Compatible" -->
<meta content="IE=Edge" />
```
These should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```

**`Src:` capitalization in all 10 `@font-face` declarations**
CSS property names are case-insensitive per spec, but some legacy email renderers parse them literally. All 10 declarations use `Src:` — should be `src:`.

**`maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocks user pinch-zoom on mobile. WCAG 1.4.4 (Resize Text, Level AA) violation.

**`text-size-adjust: none` in global reset**
```css
-ms-text-size-adjust: none; text-size-adjust: none
```
Suppresses OS-level font scaling. Degrades accessibility for low-vision users; `100%` is the safe value.

**No `woff2` format declared for any font**
Futura PT family: `.woff` only. HelveticaNow family: `.ttf` only. `woff2` is universally supported in modern clients and ~30% smaller. Missing `woff2` means slower font load or fallback to system fonts in some clients.

**`supported-color-schemes` used as a CSS property**
```css
:root { supported-color-schemes: light dark; }
```
`supported-color-schemes` is not a valid CSS property — only `color-scheme` is. The correct signal is the `<meta name="supported-color-schemes">` tag already present in `<head>`. The CSS declaration is dead weight.
