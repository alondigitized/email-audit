### 3. Rendering & Accessibility

**Confirmed issues:**

**A. Missing `http-equiv` on charset meta tag**
```html
<!-- Found -->
<meta content="text/html; charset=utf-8" />

<!-- Correct -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv="Content-Type"`, some legacy email clients (Outlook 2003, Lotus Notes) may fail to declare encoding, risking character corruption.

**B. Duplicate `<meta name="viewport">` declarations**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
Two conflicting viewport tags — the first disallows user scaling (`maximum-scale=1`), the second allows it (`user-scalable=yes`). Last-write wins in most parsers, creating inconsistent behavior. Consolidate into one.

**C. Malformed CSS values in `@media (max-width: 480px)` block**
```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
.nav_border  { border-top:px solid ; }
```
`px` without a leading number is invalid CSS. These rules will be silently discarded. If nav spacing or border is expected on mobile, these need numeric values (e.g., `0px`, `10px`).

**D. `font-display: swap` in `@font-face` blocks**
This property is a browser CSS hint — it has no effect in any email client. Not harmful, but dead code across all five `@font-face` declarations.

**E. Custom web fonts (`TheFutureHOKA`, `TheFutureHOKAMono`)**
Loaded from `https://www.hoka.com/on/demandware.static/…`. Gmail (web + Android), Outlook 2007–2019/365 on Windows, and Samsung Mail all ignore `@font-face` declarations. If fallback `font-family` stacks in the body are not defined (cannot confirm from truncated source), affected clients will fall back to the browser/OS default serif or sans-serif rather than an intentional fallback.

**F. `-webkit-text-size-adjust: none` on universal selector**
```css
* { -webkit-text-size-adjust: none; }
body { -webkit-text-size-adjust: 100% !important; }
```
The `*` rule applies `none` to all elements. The `body` override corrects the root, but child elements inherit `none` unless individually overridden. On iOS Mail, this can block pinch-to-zoom text scaling on table cells and `<td>` content below body level.
