### 3. Rendering & Accessibility

**[HIGH] Nested `@media` blocks — invalid CSS**

Starting at the third `<style>` block, `@media` queries are nested inside each other without closing the outer block first:

```css
@media screen and (max-width: 414px) {
  .padl10m { padding-left: 0px; }
  @media screen and (max-width: 412px) {   /* ← nested, invalid */
    .padl10m { padding-left: 0px; }
    @media screen and (max-width: 405px) { /* ← double-nested */
```

CSS2.1 (the spec email clients implement) does not permit nested at-rules. The entire block from `414px` onward will be silently discarded by Outlook, Yahoo Mail, and most Android clients. Affected breakpoints: 414px, 412px, 405px, 389px, 375px, 360px, 348px, 345px. Each must be a top-level `@media` rule.

---

**[MEDIUM] Duplicate `<meta name="viewport">` tags**

```html
<meta content="width=device-width; initial-scale=1.0; maximum-scale=1.0;" name="viewport" />
<meta name="viewport" content="width=device-width" />
```

The second tag (line 4 of `<head>`) overrides the first in WebKit-based clients, dropping `initial-scale=1.0` and `maximum-scale=1.0`. Remove the second, less-specific tag.

---

**[LOW] `<meta>` tags missing `http-equiv` attribute**

```html
<meta content="text/html; charset=utf-8" />          <!-- missing http-equiv="Content-Type" -->
<meta content="IE=edge" />                            <!-- missing http-equiv="X-UA-Compatible" -->
```

Both tags require `http-equiv` to have any effect. Without it, charset declaration and IE compatibility mode are not applied. Correct forms:

```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```

---

**[LOW] XHTML namespace uses `https://`**

```html
<html xmlns="https://www.w3.org/1999/xhtml" lang="en">
```

The canonical XHTML namespace URI is `http://www.w3.org/1999/xhtml` (no TLS). Most parsers are lenient, but strict XML validators and some older Outlook builds will reject the document or fall back to quirks mode. Change to `http://`.

---

**[INFO] Dark mode meta redundancy**

Both a `<meta name="color-scheme">` tag and a `:root { color-scheme: ... }` CSS declaration are present, which is correct belt-and-suspenders practice. No action needed.
