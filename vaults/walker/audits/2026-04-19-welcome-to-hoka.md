### 3. Rendering & Accessibility

**Duplicate, conflicting `<meta name="viewport">` tags:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
Two viewport declarations with different `user-scalable` values. Browsers take the last one; the conflict is unnecessary and may cause inconsistency across clients.

**Empty `<title>` element:**
```html
<title></title>
```
Some email clients (iOS Mail, Outlook mobile) surface the `<title>` in notification previews. Leaving it blank is a missed opportunity and can look broken in client previews.

**Missing `http-equiv` attribute on charset meta:**
```html
<meta content="text/html; charset=utf-8" />
```
Should be `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />`. Without `http-equiv`, this tag has no normative effect in HTML4/XHTML clients; charset declaration is only honored via the `http-equiv` form in legacy clients.

**`-webkit-text-size-adjust: none` on `*` selector:**
```css
* { -webkit-text-size-adjust: none; }
body { -webkit-text-size-adjust: 100% !important; }
```
The `*` reset sets `none`, which disables user font-size scaling on mobile. The `body` override corrects it for `<body>`, but any element not inheriting from body (e.g., elements in `<head>` or edge-case renders) could be affected. WCAG 1.4.4 (Resize Text) risk.

**Non-standard near-black / near-white color values:**
```css
a { color:#000001; }
.footer_text a { color:#fffffe; }
```
`#000001` and `#fffffe` are one bit off from pure black/white. This is sometimes used as a spam-filter workaround but is technically incorrect and may fail automated accessibility contrast checks against dark backgrounds.

**Typekit `@import` blocked by major clients:**
```css
@import url("https://p.typekit.net/p.css?...");
```
Gmail (web and Android), Outlook (all versions), and Yahoo strip `@import` statements. The fonts will silently fall back to system fonts in the majority of the recipient base. This is expected behavior for email but should be documented; the visual design must account for it.
