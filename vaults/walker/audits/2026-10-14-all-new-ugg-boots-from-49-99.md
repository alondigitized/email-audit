## Technical Audit

## 1. Technical Summary
The email's main technical defect is a failing SMS opt-in CTA ("Opt-In to Texts Get 15% Off" returns HTTP 400 on the tracked link). QA pass rate is 75%. The other findings are minor accessibility and deliverability warnings.

## 2. Link & Tracking Issues
- **[FAIL] Broken CTA, HTTP 400.** The link text is "Opt-In to Texts Get 15% Off". The URL is `https://ablink.dsw.com/f/a/s2LNBD5XdCUYdB1DSmyw_g~~/AAQRxRA~/wznQqMVI…`. It is a tracked redirect through `ablink.dsw.com`.
  - The 400 comes from the click-tracking wrapper, not from a destination page. The cause is probably a malformed or truncated encoded payload, or the tracker rejecting the probe request.
  - A 400 from the probe doesn't prove real users hit the same error. It is the only hard failure in the run, so retest it from a normal client before treating it as confirmed.
  - If real users do get the 400, the email's SMS-acquisition incentive is dead on arrival.
- **Coverage gap.** Only 12 of 60 links were probed and 48 were skipped (footer, social and utility links were deprioritized). Those 48 are unverified.
- **Tracking pixels.** There are two. `https://mi.dsw.com/p/up/e6f23fb0…/o.gif?mi_u=225090073&mi_ecmp=20261014_P261452_V1_W-_New_NewUggE` is a second-party open pixel. The `ablink.dsw.com/q/zHgWfkAisdQKOSDX3_d9cw~~/…` image looks like the ESP's own open pixel. Both are present, so opens are counted twice by two systems.

## 3. Rendering & Accessibility
- **Missing alt text on 2 images.** These are the `ablink.dsw.com/q/…` image and `o.gif`. Both appear to be 1x1 tracking pixels, so the fix is an explicit `alt=""`. Without it, some screen readers announce the filename or URL.
- **Viewport blocks zoom.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` disables pinch-zoom on mobile, which fails WCAG 1.4.4 (Resize Text).
- **Inert meta tags.** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv` attribute, so they do nothing. Charset is then left to the HTTP `Content-Type` header, which is usually fine.
- **Web fonts.** The Futura and HelveticaNow `@font-face` declarations come from `braze-images.com`, with `woff` and `ttf` formats. Support is weak in many email clients, and the truncated source doesn't show the fallback stacks, so I can't confirm those.

## 4. Personalization & Merge Tokens
No issues found. No unrendered merge tokens (`{{ }}`, `%%`, `[FNAME]`) appear in the visible source or QA output. The source was truncated, so the body wasn't fully checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
No issues found in the provided data.
- QA does not flag the unsubscribe link, and its probe set always includes one.
- SPF, DKIM, DMARC and `List-Unsubscribe` headers were not part of the supplied data. They are unverified, not passing.
- **[WARN] Plain-text part is >70% URLs** (21,256 of 24,588 chars). This ratio looks like spam to filters. It comes from long encoded `ablink.dsw.com` redirect URLs repeated throughout the text part.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
The destination UTMs can't be verified. All probed links are encoded `ablink.dsw.com` redirects, and the final landing URLs weren't captured. The only campaign identifier visible is `mi_ecmp=20261014_P261452_V1_W-_New_NewUggE` on the pixel. The CTA that would need continuity checking (the SMS opt-in) is the one that failed, so its landing page is unknown.

## 7. Recommendations
1. Retest the SMS opt-in link from a normal client. If it still returns 400, re-generate the tracked link or fix the destination in the ESP, and check that the payload isn't truncated.
2. Add `alt=""` to both tracking pixels.
3. Remove `maximum-scale=1` from the viewport meta.
4. Replace or drop the meaningless meta tags: use `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
5. Shorten the plain-text part, either by using a shorter tracking domain or by hand-writing it with fewer links.
6. Consolidate to one open-tracking pixel unless both are needed.
7. Re-run QA with the full HTML and headers to cover the 48 unprobed links, the UTM parameters and authentication.
