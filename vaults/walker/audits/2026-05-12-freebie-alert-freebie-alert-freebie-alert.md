# FREEBIE ALERT. FREEBIE ALERT. FREEBIE ALERT…

## Executive summary

- My first reaction opening this was — is this a spam folder escapee? Three "FREEBIE ALERT" in a row all-caps feels like something my grandkid's phone would flag. Once I actually got inside, DSW showed up, and I recognized the store, so I gave it a chance. The free cooler tote sounds fun, and I noticed the 25% off banner, which got my attention. But then I scrolled down and all I saw was a young woman draped across a floor in trendy sneakers — and the headline reads "THEY SEE YOU TRENDIN'." That ain't me. I'm not trendin'. I'm looking for something that keeps my feet from hurting after a two-hour walk around the mall.

The "Shop Men's Width" button was the one thing that made me feel like they remembered I'm a guy with feet that aren't a size 9 medium. That was a real signal. ## What's working

- **Free gift hook** — "GET IT BEFORE IT'S GONE / FREE COOLER TOTE" is prominent near the top and gives me a reason to care without thinking too hard.
- **25% off is concrete** — I can do that math. Real money off, not "up to an extra 10% on select styles with exclusions."
- **"Shop Men's Width"** — That button actually speaks to me. Lots of guys my age need wide or extra-wide, and most emails skip that entirely.
- **Shop by Size grid** — Practical. I can tap my size and go. No hunting around.
- **DSW branding is clean** — No render problems that I could see. Images loaded, layout held together on the phone screen.

## What's weak

- **Hero model and headline are dead wrong for me** — Young woman, "THEY SEE YOU TRENDIN'" — I'm not the audience and the photo makes that obvious. Nobody in this email looks like a 60-something guy.
- **Subject line is a disaster** — Three "FREEBIE ALERT" in all-caps feels like the email equivalent of someone yelling in a parking lot. I almost didn't open it.
- **Preview text is mostly invisible garbage** — After "Summer's hottest sneaker trends >>>" there are what looks like a hundred blank characters stuffed in. That's sloppy.
- **Too many competing sections** — Tote freebie, trendy pick, 25% off, size shop, width shop — I can't tell what the main point is. I end up doing nothing.
- **No comfort-specific language anywhere** — Not a word about cushioning, arch support, or walking. If DSW is trying to win my repeat business, this doesn't give me a reason to pick them over Hoka's website.

## Recommendations

- 1. **Lead the hero with a comfort-walk story, not trend.** Show a guy my age in a New Balance or Skechers walking shoe with copy like "All-day comfort, half the price." That's what gets me to scroll.
- 2. **Cut the section count in half.** Pick one offer — either the tote freebie *or* 25% off — and make that the whole email. Two strong offers fighting each other is one weak email.
- 3. **Fix the subject line.** Repetition and all-caps reads as spam on my phone. One clear hook is better than three shouts.
- 4. **Preheader needs real copy, not whitespace padding.** Use that space to reinforce the offer.
- 5. **Tie the "Shop Men's Width" button higher up.** It's buried. If that's who you're targeting, put it in the hero.

---

### 3. Rendering & Accessibility

**Issue 1 — Malformed charset meta tag**
```html
<meta content="text/html; charset=utf-8" />
```
Missing required `http-equiv="Content-Type"` attribute. Correct form:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without it, XHTML DOCTYPE parsers may not register the encoding declaration.

**Issue 2 — `Src:` (capital S) in all 10 `@font-face` blocks**
```css
Src: url("https://braze-images.com/...") format('woff');
```
CSS property names are case-insensitive per spec, so this is benign in practice, but it is a Braze template artifact that lint tools will flag and that strict XML parsers could reject.

**Issue 3 — `maximum-scale=1` blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on iOS, violating WCAG 1.4.4 (Resize Text, Level AA). Common in email but worth flagging for accessibility-conscious programs.

**Issue 4 — No `lang` attribute on `<html>`**
```html
<html xmlns="http://www.w3.org/1999/xhtml">
```
Screen readers cannot infer document language for correct pronunciation. Should be `<html xmlns="..." lang="en">`.

**Issue 5 — `-ms-text-size-adjust: none` in global reset**
```css
* { -ms-text-size-adjust: none; }
```
The value `none` disables text scaling on Windows Phone / IE Mobile entirely. The standard reset value is `100%`, not `none`. Low real-world impact (platform is end-of-life) but incorrect.

**Issue 6 — TTF-only for HelveticaNow; no WOFF2**
All HelveticaNow variants load `.ttf` only. WOFF2 is universally supported and ~30% smaller. The Futura PT variants correctly use `.woff`. Inconsistency means HelveticaNow loads slower on supporting clients.

**Note (intentional hack):** `color: #000001` and `background: #00000F` are deliberate near-black values used to prevent Gmail dark mode from overriding true `#000000`. This is a known workaround, not a bug.
