# BOGO 50% off shoes ends SOON
**Score:** 6/10 · **Type:** Email audit · **2026-10-17**
## Executive summary

- It's DSW again, and it's the fourth BOGO email in three days. After "Buy one, get one 50% off shoes" yesterday and the two "Stock up" and "BOGO 50% off shoes is on!" sends the day before, this one feels like a rerun with a new subject line. The big green banner says "BOGO 50% OFF*" and I got it in two seconds. At least there's no countdown bar and no code this time. The offer is also clear: buy a pair, get half off a second pair.
- Then I scroll down and the picture changes. Every shoe in the grid is a women's style: a fuzzy lace-up bootie, a mary jane, a leopard ankle boot, a wedge mule, a heeled sandal, a flat. There's nothing for me there. The Brooks banner is the only part that speaks to a guy who wants cushioning and arch support. I'd click that one, and only that one.
- Would I click? Maybe, for the Brooks, if I'm shopping that week. Would I forward it? No. I'd read it and move on, and I'm getting tired of the same sale arriving every morning.

## What's working

- The "BOGO 50% OFF*" headline is huge and readable on my phone without zooming.
- The Brooks banner at "starting at $75" is the one thing that fits how I shop. It names a brand I actually cross-shop.
- The black "SHOP NOW" buttons are large and easy to tap with my thumb.
- The "Shop by size" row, plus "Shop wide width," is useful for a guy with wide feet.
- "Valid October 15-18" is a real end date, so the urgency in the subject feels credible.

## What's weak

- Every product in the "So new, so you" grid is a women's style. Nothing there is for a 62-year-old man, and "So you" doesn't land.
- The Brooks banner shows a pink, peach women's-looking runner. It says "Adrenaline" only in the preview text, not in the email, so I can't tell which shoe I'd be getting.
- It's the same BOGO sale I've been getting for days. It doesn't feel like the sender knows me.
- The fine print is a wall of tiny gray text on black. The exclusions (no Skechers as a second pair, no "Final Sale" items) are buried down there, and I can't read it comfortably.
- "'Tis the season to gift early!" is a holiday nudge that doesn't match anything I'm shopping for.
- I see no slip-on, hands-free or cushioned-comfort content at all, and no men's product.

## Recommendations

- 1. Segment the product grid by gender. For a male subscriber, show men's comfort and walking shoes such as slip-ons and cushioned sneakers, not heels and flats. This is the biggest lift.
- 2. Make the Brooks block a men's shoe, name the model and show the price. For example, "Brooks Adrenaline GTS, men's, from $75."
- 3. Space the sends out. One BOGO email a day is plenty, so use the other days for different content.
- 4. Put the key exclusions in a plain sentence near the banner, such as "Valid Oct 15–18, no code needed." Cut the legal block down or make it larger.
- 5. Move the "Shop by size" and wide-width buttons higher up the email.
- **Subject Alt A:** `BOGO 50% off ends Sunday: Brooks from $75`
- **Subject Alt B:** `Last 2 days: 2nd pair half off, men's comfort shoes`
- **Preheader Alt A:** `Brooks Adrenaline from $75, plus wide widths in stock.`
- **Preheader Alt B:** `No code needed. Valid through Oct 18 in stores and online.`

## Technical Audit

## 1. Technical Summary
The email has one confirmed functional defect: the "Opt-In to Texts Get 15% Off" tracked link returned HTTP 400 when probed. Beyond that, it has minor accessibility and markup issues. The QA pass rate was 62%, and the remaining warnings are mostly limits of the QA tooling or the truncated source.

## 2. Link & Tracking Issues
- **[FAIL] Broken link (400):** the "Opt-In to Texts Get 15% Off" link points to `https://ablink.dsw.com/f/a/gH_F2pLp-mA-XRdpYMp9SA~~/AAQRxRA~/ygOxdO0V…` (a long click-tracking redirect). It returned 400 on probe, and the QA output shows no resolved destination.
  - This is the only link that failed among the 12 probed. I can't tell from the data whether the 400 is a bot-probe artifact (for example, an SMS opt-in endpoint rejecting non-mobile user agents) or a real failure. Re-test it from a mobile user agent before treating it as live breakage.
  - If it is real, the SMS-signup incentive is unreachable for recipients.
- **Probe coverage:** 54 of 66 links were skipped (footer, utility and social links). Their status is unverified, though the unsubscribe link is always probed and no failure was reported for it.
- **Tracking pixel:** `https://mi.dsw.com/p/up/e6f23fb0…/o.gif?mi_u=225090073&mi_ecmp=20261017_P261418_V1_WM-_Offer_Stan…` is an open pixel. It carries a numeric user ID (`mi_u`) and a campaign ID (`mi_ecmp`) in the query string. This is normal for tracking, but it is a persistent per-user identifier in a GET URL.

## 3. Rendering & Accessibility
- **[WARN] Missing alt text on 2 images:**
  - `o.gif` (the `mi.dsw.com` tracking pixel).
  - The image behind `https://ablink.dsw.com/q/gMR7f3eC46QtuTLRiy8F0w~~/…`. The `/q/` path suggests a second tracking pixel, but I can't confirm that from the truncated source.
  - If both are 1×1 pixels, they should carry an explicit `alt=""` so screen readers skip them. If the second is content, it needs descriptive alt text.
- **Malformed `<meta>` tags in `<head>`:**
  - `<meta content="text/html; charset=utf-8" />` has no `http-equiv`, so it declares nothing.
  - `<meta content="IE=Edge" />` has the same problem.
  - Low impact in practice, because the charset is normally set in the Content-Type header.
- **Plain-text part:** 24,122 of 28,793 characters (84%) are URLs, which is above the 70% threshold. This comes from long tracking-wrapped links and can hurt spam scoring on the text/plain part.
- The viewport, dark-mode and Outlook (`mso-*`) handling in the visible `<head>` look sound. The HTML was truncated, so I did not check the body.

## 4. Personalization & Merge Tokens
No issues found. No unrendered merge tokens (`{{ }}`, `%%…%%`, `[FIRST_NAME]`) appear in the visible source or the subject.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **[WARN] Authentication-Results header not found:** this is an artifact of the AgentMail relay, as the QA note says ("SPF/DKIM status unknown"). It is not evidence of a sender failure, but SPF, DKIM and DMARC are unverified. Check them against the original headers or a seed-list test.
- The unsubscribe link is probed with no failure reported. I could not check the physical postal address or `List-Unsubscribe` / `List-Unsubscribe-Post` headers because the source is truncated and the headers were not provided.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- Every link goes through the `ablink.dsw.com` redirect wrapper, so UTM parameters and destination URLs can't be read from the HTML. They are unverified.
- Only the failed opt-in link had a visible destination problem, and it has no resolved landing page. The other 11 probed links returned no errors.

## 7. Recommendations
1. Re-test the "Opt-In to Texts" link (`ablink.dsw.com/f/a/gH_F2pLp-…`) from a mobile user agent and in a real client. If it still returns 400, fix the destination or redirect mapping before the next send.
2. Add `alt=""` to both tracking images, and confirm what the `ablink.dsw.com/q/…` image is.
3. Fix the head metas: `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=Edge">`.
4. Reduce URL weight in the text/plain part, for example by shortening tracking links or trimming duplicated links.
5. Capture raw headers on future runs (SPF, DKIM, DMARC, `List-Unsubscribe`) so the compliance section can be assessed instead of marked unknown.
6. Resolve the tracked links to their final URLs so UTM parameters and landing-page alignment can be audited.
