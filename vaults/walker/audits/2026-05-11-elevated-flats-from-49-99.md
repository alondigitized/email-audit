### 3. Rendering & Accessibility

**[HIGH] Invalid `@font-face` property capitalization — all 10 font declarations**
```css
/* All declarations use capital S */
Src: url("https://braze-images.com/appboy/...") format('woff');
```
`Src:` is not a valid CSS property. The correct property is lowercase `src:`. This will silently fail in every email client that supports web fonts (Apple Mail, iOS Mail, Outlook macOS). Fallback stack will render instead, but the custom Futura PT and HelveticaNow fonts will never load.

**[MEDIUM] `maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom. Blocks accessibility for low-vision users on mobile. WCAG 1.4.4 failure.

**[LOW] `text-size-adjust: none` applied globally**
```css
* { -ms-text-size-adjust: none; text-size-adjust: none }
```
The `100%` value (present earlier in the same block) is correct; `none` on `*` is more aggressive and can suppress legitimate OS-level text scaling for accessibility users. These two declarations conflict — `none` wins due to specificity.

**[LOW] Missing WOFF2 format for Futura PT fonts**
Only `.woff` is declared for the Futura family. WOFF2 compresses 20–30% smaller and is supported by all modern email clients that support web fonts. HelveticaNow uses `.ttf` — also no WOFF2.

**[INFO] `#000001` near-black values**
`border-top: 1px #000001 solid` and `color: #000001` appear in both the mobile and dark-mode blocks. This is a known intentional hack to prevent Gmail dark mode from inverting pure black (`#000000`). Not a bug, but document it if this template is maintained by multiple engineers.
