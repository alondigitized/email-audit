### 3. Rendering & Accessibility

**Duplicate, conflicting `viewport` meta tags** (lines 5–6 of `<head>`):
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
These conflict on `user-scalable`: the first implicitly disables zoom; the second explicitly enables it. Last-wins behavior varies by client. One tag should be removed.

**Broken CSS values — `.nav_padding` and `.nav_border`:**
```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
.nav_border  { border-top:px solid ; }
```
Both rules have bare `px` with no numeric value and `.nav_border` has a trailing empty color. These are invalid and will be silently ignored by all parsers, collapsing any intended mobile nav spacing.

**Empty `<title>` element:**
```html
<title></title>
```
Some clients (Samsung Mail, older Outlook mobile) surface the `<title>` as a tab or window label. An empty value produces a blank label; set it to the subject line or brand name.

**`-webkit-text-size-adjust: none` on the universal selector:**
```css
* { -webkit-text-size-adjust: none; }
```
`none` (vs. `100%`) fully disables font scaling on WebKit/Blink mobile clients, including user-initiated zoom. This is more aggressive than necessary and conflicts with `user-scalable=yes` in the second viewport tag. Change to `100%`.

**Web fonts — fallback stack not visible:** Four `@font-face` weights of `TheFutureHOKA` are declared loading from `hoka.com` CDN. Gmail (all surfaces) and Outlook (Windows) strip `@font-face` blocks entirely. A generic `sans-serif` fallback must be present in every `font-family` declaration; cannot confirm from truncated source.
