# Technical Audit: Shoe Carnival, "Boots under $20 to make their day!"

The HTML source was truncated after the `<style>` blocks, so body markup, footer and link `href`s were not available. I only flag what the visible source and QA data support, and I mark what I couldn't verify.

## 1. Technical Summary
The email's head and CSS are standard ESP boilerplate with a few malformed meta tags. The clearest defects are an unresolved `[UNIQUE]` placeholder in a tracking pixel URL and a malformed `t=utm_campaign=` query string in the other pixel. Authentication and footer compliance could not be verified from the data provided.

## 2. Link & Tracking Issues
- **Unresolved merge placeholder in a pixel:** `https://0di86k1v.emltrk.com/v2/0di86k1v?d=[UNIQUE]`. The literal `[UNIQUE]` was never substituted. That pixel likely can't identify the recipient or the open. Square brackets are also not valid unencoded in a URL query.
- **Malformed pixel query string:** `https://ieezzy5m.emltrk.com/v2/ieezzy5m?i=72180589&t=utm_campaign=SCA_20261118_skechers_coop_AM​`
  - `t=utm_campaign=...` nests a key=value pair inside a parameter value, which looks like a template concatenation error.
  - The URL ends with an invisible character (U+200B zero-width space, visible as `AM​`). It can break parsing and campaign-name matching in analytics.
- **Unprobed tracking links:** 29 tracking links were skipped by the HTTP probe (click-redirect domains). Their destinations and status codes are unverified, not confirmed broken.
- **Link text density:** plain text is 5721 of 8149 characters URLs (about 70%). This is a spam-filter risk signal, driven by long tracked URLs.

## 3. Rendering & Accessibility
- **Missing `alt` on content images:**
  - `…/23a03225-7c93-49fa-988c-8821675cac1b.jpg`
  - `…/fe4e293c-bccf-488a-bbf7-db06bf5745de.jpg`

  Both are on `image.email.shoecarnival.com`. With images blocked, or for screen readers, they give no content (and may announce the filename).
- **Tracking pixels missing `alt`:** the two `emltrk.com` pixels should use `alt=""` and a `width="1" height="1"` attribute so they are ignored by assistive tech.
- **Malformed meta tags:**
  - `<meta content="text/html;" charset="utf-8" />` lacks `http-equiv="Content-Type"`. The `charset` attribute still works in most clients.
  - `<meta content="IE=edge" />` lacks `http-equiv="X-UA-Compatible"`, so it does nothing.
- **Doctype mismatch:** the HTML 4.01 Transitional doctype is combined with `xmlns="http://www.w3.org/1999/xhtml"` and self-closing tags. This is harmless in email clients but invalid.
- **Link styling override:** the global rule `a, a:link, … { text-decoration:none !important; color:inherit !important; }` removes default link color and underline everywhere. Any link without an explicit styled wrapper is visually indistinguishable from text. I couldn't verify this against the body markup.
- **Small text:** `.responsive-text { font-size: 12px !important; }` at max-width 600px is below the 14px that most mobile accessibility guidance suggests.
- **Possible mobile overflow:** `.body { min-width: 100vw; }` (max-width 450px) can cause horizontal scroll when a vertical scrollbar is present.

4. Add `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"` to the two meta tags.
5. Reduce plain-text URL weight by shortening tracked links, or by generating a cleaner plain-text part.
