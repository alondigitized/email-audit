### 3. Rendering & Accessibility

**[HIGH] Duplicate conflicting `<meta name="viewport">` tags:**
```html
<!-- tag 1 -->
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<!-- tag 2 -->
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
- `maximum-scale=1` in tag 1 blocks user zoom. `user-scalable=yes` in tag 2 contradicts it. The first declaration wins in most parsers, effectively locking zoom — an accessibility violation (WCAG 1.4.4).
- **Fix:** Keep exactly one viewport tag: `content="width=device-width, initial-scale=1"` — drop `maximum-scale=1`.

**[MEDIUM] Malformed charset meta tag:**
```html
<meta content="text/html; charset=utf-8" />
```
Missing `http-equiv="Content-Type"`. Outlook and several legacy clients require the explicit `http-equiv` attribute to parse charset correctly.
- **Fix:** `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />`

**[LOW] Empty `<title>` tag:**
```html
<title></title>
```
Some clients (Samsung Mail, some webmail) surface the title in tab or preview contexts. Leaving it empty can display as a blank or as the raw `<From>` header.

**[LOW] Adobe Typekit fonts via `@import`:**
```css
@import url("https://p.typekit.net/p.css?s=1&k=hva0tmw&...");
```
Gmail, Outlook (all Windows versions), and Yahoo strip `@import` and external `@font-face` references. Futura PT / New Spirit will not render in the majority of email clients — all text falls back to system fonts. This is an expected tradeoff, but the font investment is effectively zero-ROI for most of the audience.

**Cannot assess** — `alt` attributes on `<img>` tags not visible in truncated source.
