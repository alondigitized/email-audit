---

### 3. Rendering & Accessibility

**Duplicate `<meta name="viewport">` tags** — two conflicting declarations in `<head>`:
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
They conflict on `user-scalable` (omitted vs. `yes`) and attribute order differs. Browser/client behavior on duplicate viewport tags is undefined; the second should be removed.

**Missing `http-equiv` on charset meta:**
```html
<meta content="text/html; charset=utf-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, Outlook 2007–2019 may not honor the declared charset.

**Empty `<title>` tag** — `<title></title>` renders as blank in Gmail's browser tab and can surface as "no subject" in some preview panes. Should match the subject line or a short descriptor.

**`maximum-scale=1` in both viewport declarations** — prevents pinch-zoom on mobile. Violates WCAG 1.4.4 (Resize Text, Level AA). Recommend removing `maximum-scale` or setting it to `5`.

**Malformed CSS values in mobile media query** (confirmed in source):
```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
.nav_border  { border-top:px solid ; }
```
Both declarations have missing numeric values before `px` and `.nav_border` is missing its color value. These rules are silently dropped by all CSS parsers — any intended mobile nav padding/border is not applied.

**Global `border:none` reset** — `* { border:none; }` strips borders from all elements including `<table>` spacer rows. If any layout depends on a 1px table border for spacing, it will collapse invisibly.
