# Last day to BOGO + get 40% off clearance
**Score:** 8/10 · **Type:** Email audit · **2026-07-08**
## Executive summary

- This is the second "last day" drum I've heard from DSW in two days. Yesterday it was "Ends tomorrow: BOGO 50% OFF" — today it's "Last day to BOGO + get 40% off clearance." I'll give them this: stacking the 40% clearance angle on top of the BOGO is a fresher hook than yesterday's send, and on my phone the subject line actually made me look twice. Two deals in one line is better math than one deal repeated.
- But I open it and I'm scrolling past women's shoes. Strappy heeled sandals, pointed-toe flats, slingbacks — "SO NEW, SO YOU" they say, and none of that is me. The size grid starts at a 5. If DSW's system knows I bought men's walking shoes from them last year, this is not what you put in front of a 62-year-old man. I kept scrolling hoping to find a pair of Skechers GOwalk or a New Balance on clearance. I found an Afterpay banner instead.
- I'd probably click anyway — I know the men's section is buried somewhere on DSW's site — but barely. I would not forward this to a friend.

## What's working

- **Dual-offer subject line** — "BOGO + 40% off clearance" in the same line is genuinely more interesting than yesterday's single-note "Ends tomorrow" version; felt like actual news.
- **Hero is unmissable** — "BOGO 50% OFF*" in massive white-on-dark text is the first thing you see. No zooming in, no guessing what the deal is.
- **Wide width CTAs** — "SHOP WIDE WIDTH" and "SHOP WIDE CALF" are the most relevant lines in the email for someone like me. That kind of practical callout builds real trust.
- **VIP perks are surfaced** — Free shipping for VIP is right there in the convenience row. I see it, it registers, it matters.
- **"Last day" urgency is now credible** — After "Ends tomorrow" yesterday, saying "Last day" today actually lands. Doesn't feel manufactured.

## What's weak

- **The product grid is women's shoes** — Heels, strappy sandals, pointed-toe flats in "SO NEW, SO YOU." I'm a 62-year-old man. This is someone else's email.
- **Size range starts at a 5** — Men's sizes should open at 7 or higher. A comfort shopper like me runs 10.5–11W. Seeing a grid starting at 5 confirms this wasn't built for me.
- **"SO NEW, SO YOU" is dead air** — That whole section could disappear and I'd be better off. New fashion arrivals in heeled styles have zero pull for me.
- **Fifth BOGO-era email in three days** — I've gotten "Say whaaaat," the "going on, btw" follow-up, "5 hot trends," "Ends tomorrow," and now this. The deal is good. The cadence is wearing on me.
- **Preheader spacer characters** — "All good things must come to an end" is fine copy, but the wall of invisible padding characters after it looks sloppy in some clients.

## Recommendations

- 1. **Swap the product grid for men's comfort shoes** — One row of Skechers GOwalk, Hoka Bondi, or New Balance 990 on BOGO clearance and I'm clicking immediately. If DSW is segmenting this list at all by gender, this is the fix that matters most.
- 2. **Lead with the 40% clearance as the fresh angle** — BOGO has been running for three days; 40% off clearance is the actual news. Give it its own hero callout or at least make it co-equal in the header.
- 3. **Shift the size grid to men's range** — 9 through 13, wide width prominently labeled. The women's grid reads like a targeting miss that a single segment variable would fix.
- 4. **Compress the cadence on the next campaign** — Consider consolidating the final-day send into one strong "doors close tonight" email with a countdown rather than a string of near-identical BOGO messages.

### 3. Rendering & Accessibility

**`http-equiv` missing on two meta tags:**
```html
<!-- Actual -->
<meta content="text/html; charset=utf-8" />
<meta content="IE=Edge" />

<!-- Required -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```
Without `http-equiv`, these tags are inert. Charset fallback behavior varies by client; Outlook ignores the IE compatibility hint entirely.

**Invalid CSS property casing — `Src:` in all `@font-face` blocks:**
```css
Src: url("https://braze-images.com/...original.woff") format('woff');
```
CSS property names are case-insensitive per spec, but several email client CSS parsers (notably older versions of Outlook's WebView and some Samsung Mail builds) treat `Src:` as an unknown property and skip the declaration. All 10 `@font-face` blocks are affected. Should be lowercase `src:`.

**Conflicting `text-size-adjust` values in reset:**
```css
-webkit-text-size-adjust: 100%;
-ms-text-size-adjust: 100%;   /* set to 100% ... */
-ms-text-size-adjust: none;   /* ... then immediately overridden to none */
text-size-adjust: none;
```
The unprefixed `text-size-adjust: none` overrides the earlier `100%` declarations. `none` prevents user text scaling entirely, which is an accessibility concern and may trigger Apple Mail rendering differences.

**`supported-color-schemes` CSS property is non-standard:**
```css
:root { supported-color-schemes: light dark; }
```
The valid CSS property is `color-scheme`. The `supported-color-schemes` name is an older Apple-only alias in meta form only; in CSS `:root` it is unrecognized and silently ignored. The `<meta name="supported-color-schemes">` tag in `<head>` is the correct Apple Mail target — the CSS duplicate is dead code.

**Font format coverage:** All Futura PT variants are served as `.woff` only; all HelveticaNow variants as `.ttf` only. No `woff2` source is declared. `woff2` is supported in Apple Mail, Gmail (Android), and Samsung Mail and would reduce font payload ~30%. Not a rendering blocker, but a performance gap.
