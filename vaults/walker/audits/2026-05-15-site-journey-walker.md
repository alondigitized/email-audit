## Technical Audit

## Technical Summary

Skechers.com runs on Salesforce Commerce Cloud (SFCC/Demandware). The mobile journey has three actionable problem areas: (1) Kasada bot-protection SDK self-rate-limiting at 429, blocking the cart page and fingerprinting endpoint; (2) the View Cart route renders without a `<title>` or `html[lang]`, indicating a broken SPA/overlay document-update path; and (3) third-party script duplication inflates initial parse cost. TTFB is healthy across most steps (26–135 ms); LCP and CLS were not collected, so render-blocking and layout shift cannot be assessed.

---

## Accessibility

**Critical**
- `aria-required-parent` (Homepage): An ARIA role is used without its required DOM parent context — likely a child role (e.g. `option`, `listitem`, `menuitem`) rendered outside its owning container. Breaks assistive-technology tree traversal.

**Serious**
- `document-title` (View Cart): The cart renders with an empty or absent `<title>`. Indicates the SPA shell is not calling `document.title` on route change.
- `html-has-lang` (View Cart): `<html>` lacks a `lang` attribute on the cart route. Same root cause as the missing title — the cart appears to be loaded as a document fragment or overlay that bypasses the base HTML shell.

**Moderate (8 violations across Homepage and Search)**
- Duplicate `<main>` landmark and `<main>` not at top level (Homepage) — nested inside another landmark, likely caused by a CMS component injecting its own `<main>`.
- `<aside>` not top-level (Homepage, Search) — complementary content nested inside `<article>` or `<section>`.
- Multiple `landmark-unique` failures (Homepage, Search) — repeated `role="navigation"` or similar without distinguishing `aria-label`.
- `heading-order` (Homepage) — non-sequential heading levels (e.g., `h1` → `h3`), typically from independently-styled CMS components.
- `region` violations (Homepage, Search) — page content outside any landmark region.

---

## SEO

- **View Cart missing `<title>`**: Googlebot indexes the cart URL; an empty title results in either no SERP entry or a URL-derived title. Fix: ensure the SPA route update sets `document.title` before rendering.
- **`html-has-lang` on View Cart**: Google uses the lang attribute for language targeting and indexing. Missing it on a transactional page will degrade international correctness signals.
- All other sampled pages carry `lang="en"` and appear to have appropriate head structure (SFCC default template is intact).

Each is an additional DNS lookup, TCP handshake, and parse budget cost on mobile.

## Mobile Optimization

- **`--vh` floating-point precision**: The custom property is set to `6.640000000000001px` — a JavaScript floating-point artifact from `window.innerHeight / 100`. This is a standard iOS Safari 100vh workaround, but the imprecise value can cause sub-pixel rendering inconsistencies at scale. Round to 2 decimal places: `Math.round(vh * 100) / 100`.
- **No `preconnect` hints observed** for the heaviest third-party origins (Monetate, QuantumMetric, GTM). `dns-prefetch` is present for Monetate only. Adding `<link rel="preconnect">` for the top 3–5 origins would reduce connection latency on mobile networks.
- LCP and CLS data missing — cannot assess image lazy-load strategy or font/layout shift on mobile viewports.

## Console & Network Errors

**Kasada SDK 429 (6 occurrences — highest severity)**

```
429 /149e9513-01fa-4fb0-aad4-566afd725d1b/2d206a39-8ed7-437e-a3be-862e0f06eea3/fp?x-kpsdk-v=j-1.2.412
```

This is Kasada's client-side fingerprinting endpoint (`/fp`). The SDK is rate-limiting its own requests, which means either:
1. The Kasada token refresh interval is misconfigured and exceeding per-client request limits, or
2. The automation/test environment is triggering Kasada's bot heuristics, causing the challenge to loop.

**Direct business impact**: One of the 429s is on `/cart/` itself — the cart page route is returning 429, meaning real users hitting Kasada's rate limit will see a failed cart load. This is the critical path to checkout.

**Stylitics CORS failure**

```
Access to CSS at 'https://web-assets.stylitics.com/style.css?...' blocked by CORS policy: No 'Access-Control-Allow-Origin' header
```

Stylitics (outfit recommendation widget) is serving a stylesheet from a CDN that does not set CORS headers. This is a third-party misconfiguration, but it breaks the outfit widget rendering entirely. Skechers should file a support ticket with Stylitics and/or proxy the stylesheet through their own CDN.

**`net::ERR_FAILED`**: One unspecified network failure — origin URL not captured, cannot diagnose further.

## Recommendations

**P0 — Fix immediately**
1. **Kasada `/cart/` 429**: Coordinate with Kasada support to diagnose why `/cart/` is returning 429 for real traffic. If this is a token-bucket misconfiguration, it's silently blocking checkout for a subset of users. Reproduce outside automated tooling to confirm scope.
2. **View Cart document head**: The cart route is missing `<title>` and `<html lang>`. If this is an SFCC overlay/modal (e.g., a mini-cart rendered in a `<dialog>` or off-canvas drawer over the base page), the base page title and lang must remain in the DOM. If it's a full page route, the SFCC template needs to populate both.

**P1 — Fix in next sprint**
3. **Deduplicate Monetate**: Two concurrent Monetate SDK versions will double personalization event firing. Audit whether both are intentional (A/B SDK migration) or legacy remnant. Remove the older `v2` entry if the `v3` custom.js covers the same functionality.
4. **Deduplicate `creativecdn.com` and `ytc.js`**: Both load twice on category pages. GTM container audit needed — these are likely duplicate tag configurations.
5. **Fix `aria-required-parent`**: Locate the component emitting orphaned ARIA roles (likely a carousel or dropdown component) and wrap child elements in the correct parent role container.

**P2 — Planned improvement**
6. **Add `preconnect` for top origins**: Add `<link rel="preconnect" href="https://cdn.quantummetric.com">`, `<link rel="preconnect" href="https://se.monetate.net">`, and `<link rel="preconnect" href="https://www.googletagmanager.com">` to the SFCC head template.
7. **Round `--vh` value**: Change the viewport-height JS from `window.innerHeight / 100` to `Math.round(window.innerHeight) / 100` to eliminate the floating-point artifact.
8. **Collect LCP and CLS**: Re-run the audit capturing full Web Vitals. TTFB alone cannot confirm Core Web Vitals pass/fail for Google Search ranking purposes.
9. **Stylitics escalation**: File a ticket with Stylitics to add `Access-Control-Allow-Origin: https://www.skechers.com` to their CDN configuration for `web-assets.stylitics.com`.
