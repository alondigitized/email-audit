### 3. Rendering & Accessibility

**A. Duplicate conflicting property in the `*` reset rule** *(confirmed in source)*

```css
*{
  -ms-text-size-adjust: 100%;   /* declared first */
  ...
  -ms-text-size-adjust: none;   /* overrides above — wrong */
  text-size-adjust: none;
}
```

`-ms-text-size-adjust: none` wins by cascade order. The intended value is `100%` (prevents Outlook/IE from auto-scaling text). `none` can break text sizing for users who require larger text. This is likely a copy-paste accumulation error.

**B. `Src:` capitalization in all 10 `@font-face` blocks** *(confirmed in source)*

```css
@font-face {
  font-family: 'Futura_PT_Regular';
  Src: url("https://braze-images.com/...") format('woff');
}
```

`Src:` (capital S) is non-standard. CSS property names are case-insensitive in browsers, but strict XML parsers and some older Outlook rendering paths may silently skip the rule, falling back to system fonts. Correct form is `src:` (lowercase).

**C. `maximum-scale=1` in viewport meta** *(confirmed)*

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

Blocks pinch-to-zoom on mobile. Violates WCAG 2.1 SC 1.4.4 (Resize Text). No email client enforces this viewport directive strictly, but it's still a compliance flag on accessibility audits.

**D. Missing `http-equiv` on charset meta** *(confirmed)*

```html
<meta content="text/html; charset=utf-8" />
```

Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

Without `http-equiv`, some legacy email clients (older Lotus Notes, some Outlook versions) will not pick up the declared charset and may misinterpret non-ASCII characters.

**E. HelveticaNow fonts delivered as `.ttf`, Futura PT as `.woff`**

TTF files are significantly larger than WOFF. On a slow mobile connection, font load failure may cause a FOUT or fallback rendering. Inconsistency also suggests two separate asset pipelines — the Futura PT set lacks the cache-busting query strings (`?1755182939`) that HelveticaNow has, creating uneven cache behavior.

**F. `supported-color-schemes` as CSS property inside `:root`** *(confirmed)*

```css
:root {
  color-scheme: light dark;
  supported-color-schemes: light dark;  /* non-standard */
}
```

`supported-color-schemes` is not a valid CSS property (it was a proposed draft name that was never standardized). The correct CSS property is `color-scheme`, which is already present. The redundant non-standard declaration is harmless but should be removed.
