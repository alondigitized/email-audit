## Technical Audit

## 1. Technical Summary
The email is a Salesforce Marketing Cloud-style build (`link.email.newbalance.com` click wrapping). The visible source has leftover template placeholders and non-functional `@font-face` rules, and 3 images lack alt text. The HTML is truncated, so the footer, body links and headers could not be inspected.

## 2. Link & Tracking Issues
- **Placeholder URL in CSS:** `.bgwhite {background-image: url('http://image.XXXXX.png');}` is a template placeholder over insecure `http://`. If the class is applied, it requests a nonexistent asset. Some clients also flag it as mixed content.
- **Probe coverage:** QA probed 12 material links and skipped 21 (footer, utility and social). It reported no broken links among the probed set. The skipped links are unverified.
- **Tracking pixel:** `https://link.email.newbalance.com/mo/egR1f966kc_818512772_12645344_718305_23888078.gif` is the open-tracking beacon. It is flagged only for missing alt text (see section 3). It will not register opens where images are blocked or proxied.

## 3. Rendering & Accessibility
- **Missing alt text (3 images, from QA):**
  - `ShippingIcons_06.png`
  - `ShippingBanner_DarkMode_03.png`
  - the tracking GIF above
  
  The two shipping images are content-bearing and need descriptive alt text. The tracking pixel should have `alt=""`.
- **`@font-face` without `src`:** every rule, such as `@font-face { font-family: linotype-didot,serif; ... }` and `@font-face { font-family: proxima-nova,sans-serif; ... }`, has no `src`. The custom fonts can never load, so everything renders in the Arial and Times New Roman fallbacks. The `font-family` values inside `@font-face` also contain comma-separated fallbacks, which is invalid there.
- **Malformed meta tag:** `<meta content="IE=edge" />` has no `http-equiv`, so it does nothing.
- **Conflicting CSS:** `.bg1` is defined twice with different values (`background-color:#ffffff` and `background:#58546d`). The later rule wins and overrides the first.
- **Doctype mismatch:** the HTML 4.01 Transitional doctype is paired with an `xmlns` XHTML namespace on `<html>`. This is harmless but inconsistent.
- **Dark mode:** `color-scheme` and `supported-color-schemes` meta tags and `prefers-color-scheme` rules are present. Contrast could not be checked because the source is truncated.
- **Generic title:** `<title>New Balance Template</title>` is the template name, not the campaign. It can show up in web-view and some preview contexts.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens appear in the visible source or QA output. The truncated body could not be fully checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication:** `Authentication-Results` was not found. The QA note attributes this to the AgentMail relay, so SPF, DKIM and DMARC status is unknown. This is a monitoring gap, not a confirmed failure. The sender domain is `email.newbalance.com`.
- **Plain-text part:** 10,638 of 12,013 characters (about 89%) are URLs, which is above the 70% warning threshold. This usually means wrapped tracking URLs are inflating the text part. It is a minor spam-scoring risk.
- **Unsubscribe and address:** the QA run states an unsubscribe link is always probed and reported no failure. The unsubscribe URL, the physical postal address and the `List-Unsubscribe` and `List-Unsubscribe-Post` headers were not in the data, so they could not be verified.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not verifiable. Destination URLs are hidden behind `link.email.newbalance.com` redirects, and the visible source has no UTM parameters or landing URLs. The QA data does not report probe redirect targets. The shipping assets live under `/myNB_Welcome/`, so welcome-series modules may have been reused in this polka-dot promo. That is an asset-hygiene observation, not a functional defect.

## 7. Recommendations
1. Add alt text to `ShippingIcons_06.png` and `ShippingBanner_DarkMode_03.png`, and set `alt=""` on the tracking GIF.
2. Remove `.bgwhite`'s `http://image.XXXXX.png` placeholder, or replace it with an HTTPS asset if it is used.
3. Add `src` (with a webfont host) to the `@font-face` rules, or delete them and rely on the Arial and Times fallbacks.
4. Delete the duplicate `.bg1` rule, fix `<meta http-equiv="X-UA-Compatible" content="IE=edge">`, and set a campaign-specific `<title>`.
5. Capture full headers (`Authentication-Results`, `List-Unsubscribe`) at the source mailbox so authentication can be verified past the relay.
6. Reduce the URL density of the plain-text part, or generate it with shorter links.
7. Extend link probing to the full HTML, including the footer, and log resolved landing URLs and their UTM parameters so continuity can be checked.
