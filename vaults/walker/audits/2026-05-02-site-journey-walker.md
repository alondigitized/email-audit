## Technical Audit

## Technical Summary

Eight-step mobile journey across skechers.com (Salesforce Commerce Cloud / SFCC platform). TTFB is excellent site-wide except for a 5× spike on `/cart/`. The primary technical debt is concentrated in: (1) an unmanaged third-party script sprawl that loads 20+ vendors per page with several duplicates, (2) a View Cart page that renders without a `<title>` or `lang` attribute — indicating a client-side-only SPA route that bypasses server-rendered document metadata, and (3) repeated 429s from Kasada (KPSDK) bot-detection that silently fail on every page load.

---

## Accessibility

**15 violations across 3 pages. 2 serious on View Cart are highest priority.**

| Severity | Rule | Page | Notes |
|---|---|---|---|
| Critical | `aria-required-parent` | Homepage | ARIA child role rendered outside required parent container — likely a carousel or list widget |
| Serious | `link-name` | Homepage | One or more `<a>` tags have no accessible text (likely icon-only links with no `aria-label`) |
| Serious | `document-title` | View Cart | `<title>` element is empty or absent — screen readers announce nothing |
| Serious | `html-has-lang` | View Cart | `<html>` element missing `lang` attribute — language detection fails for AT |
| Moderate | `heading-order` | Homepage | Heading levels skip (e.g. `<h1>` → `<h3>`) — breaks document outline |
| Moderate | `landmark-no-duplicate-main` / `landmark-main-is-top-level` | Homepage | Multiple `<main>` elements, and at least one is nested — invalid landmark structure |
| Moderate | `landmark-one-main` / `page-has-heading-one` | View Cart | Cart renders in a context with no `<main>` and no `<h1>` |
| Moderate | `landmark-complementary-is-top-level` / `landmark-unique` | Search | `<aside>` nested inside another landmark; duplicate landmark roles |

**Root cause on View Cart**: the cart page appears to be a fully client-rendered view (no SSR). The server sends a shell without `<title>` or `lang`, and the client JS fails to set them before axe runs. Fix: set `document.title` and verify `<html lang>` is present in the server-rendered shell, or move to SSR for this route.

---

## SEO

- **View Cart — missing `<title>`**: Google will either synthesize a title or omit the page from index. Cart pages are typically `noindex`, but confirm the `robots` meta tag is present on this route.
- **Heading order violations on Homepage** hurt crawl-time content hierarchy. Googlebot uses heading structure to understand page sections.
- **Duplicate script tags on Men category** (`tags.creativecdn.com/dhGobFICKSkk6J9nvQPw.js` loaded twice; `s.yimg.com/wi/ytc.js` loaded twice on Homepage and Login) — no direct SEO harm, but adds parse cost.
- No canonical tag issues observable from available source excerpts.

---

## Performance

**TTFB is good. LCP and CLS not captured — these are the metrics that matter most for Core Web Vitals scoring.**

| Step | TTFB | Flag |
|---|---|---|
| Homepage → Search | 25–30ms | Normal |
| View Cart | 124ms | 5× spike — likely synchronous session/cart API call blocking the response |

**Third-party script payload is the primary performance risk.** Each page loads 20+ external scripts in `<head>`, many unconditionally:

- Monetate loaded from **two different script URLs** (`/js/3/` and `/js/2/`) on the same page — likely a mis-configured tag manager rule causing double-load.
- WebFontLoader (`cdnjs.cloudflare.com/webfont/1.6.28`) loaded `async` but triggers multiple `wf-mulish-*` class writes to `<html>` — causes style recalculation. Self-hosting the font and using `font-display: swap` would eliminate this.
- `--vh: 6.64px` on `<html>` is set by JS (mobile viewport height fix). This is fine but means any element using `--vh` will not render correctly until JS executes.
- No evidence of resource hints (`<link rel="preload">`) for LCP images in visible source.

**Recommendation**: run a HAR trace to quantify total third-party weight. The current tag count suggests 500KB–1MB of JS from ad/analytics vendors alone.

---

## Mobile Optimization

- `--vh` custom property is a known SFCC mobile viewport workaround (addresses the iOS address-bar height bug). The pattern is functional but means viewport-height-dependent layouts are JS-dependent.
- No `<meta name="viewport">` visible in the truncated source, but it is almost certainly present further in `<head>` — cannot confirm without a full source dump.
- `vice-managed-src` on several `<script>` tags is TrustArc's mechanism for consent-gated script loading — this is correct practice for GDPR/CCPA compliance on mobile browsers.
- No `<link rel="preconnect">` to known critical third parties (Monetate, Bloomreach, GA4) — only `dns-prefetch` is used. Upgrading these to `preconnect` would reduce TLS handshake latency for above-the-fold resources.

## Console & Network Errors

**6× HTTP 429 on Kasada KPSDK fingerprinting endpoint:**
```
/149e9513-01fa-4fb0-aad4-566afd725d1b/2d206a39-8ed7-437e-a3be-862e0f06eea3/fp?x-kpsdk-v=j-1.2.386
```
These are Kasada's client-side bot detection probes. The 429s mean the KPSDK token bucket for this session/IP is exhausted — the anti-bot system is rate-limiting its own challenge endpoint. This is a misconfiguration in Kasada's rate limit thresholds. It does not block the user, but it generates noise in error reporting and may degrade Kasada's bot-signal quality.

**1× 429 on `/cart/`:**
The cart page itself returns 429 on at least one request. Combined with the TTFB spike to 124ms, this suggests the cart endpoint is under load or has an aggressive rate limit that fires during normal browsing. This is a functional risk — users could see a broken cart.

**1× CORS block on Stylitics stylesheet:**
```
https://web-assets.stylitics.com/style.css?base=hotspots&theme=skechers&version=a633fea7cb
```
The Stylitics CDN is not returning `Access-Control-Allow-Origin: https://www.skechers.com` for this asset. The stylesheet fails to load, which will break the Stylitics "Complete the Look" widget styling. This is a Stylitics-side misconfiguration — either their CDN headers need updating or the integration is using a stale embed version (`a633fea7cb`).

## Recommendations

**P0 (Functional breakage):**
1. **Cart 429**: Investigate rate limit config on the `/cart/` endpoint. Verify it does not fire for authenticated users with a valid session. Add alerting on 429 rate for `/cart/`.
2. **View Cart missing `<title>` and `lang`**: Add server-rendered document metadata to the cart shell. This is both an a11y legal risk (WCAG 2.1 §2.4.2) and an SEO concern.
3. **Stylitics CORS**: File a bug with Stylitics to update CORS headers on `web-assets.stylitics.com` for the skechers theme, or pin to a version where the headers are correct.

**P1 (Reliability / Compliance):**
4. **Kasada 429 flood**: Work with Kasada support to tune the per-session rate limit on the `/fp` endpoint so it doesn't self-throttle during normal page navigation.
5. **`aria-required-parent` (Critical)**: Audit carousel/list components on Homepage for orphaned ARIA child roles. This is the only critical-severity axe violation.
6. **`link-name` (Serious)**: Add `aria-label` to all icon-only anchor tags site-wide, especially in navigation and product cards.

**P2 (Performance):**
7. **Deduplicate Monetate tags**: Remove the `/js/2/` or `/js/3/` entry — one is redundant. Audit GTM for duplicate tag firing rules.
8. **Deduplicate `creativecdn` and `ytc.js`**: Both fire twice on multiple pages. Check GTM trigger logic.
9. **Upgrade `dns-prefetch` to `preconnect`** for Monetate, GA4, and Bloomreach origins to reduce TLS round-trip cost.
10. **Self-host Mulish font** with `font-display: swap` to eliminate the WebFontLoader JS dependency and associated FOUC/style recalculation.

**Measurement gap**: LCP and CLS are unset for all 8 steps. These are the two Google CWV metrics that affect search ranking. Instrument RUM (e.g. via the existing Quantum Metric integration) to capture field LCP/CLS before any performance optimization work.
