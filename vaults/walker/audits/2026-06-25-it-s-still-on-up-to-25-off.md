### 3. Rendering & Accessibility

**`http-equiv` missing on two meta tags (malformed)**
```html
<meta content="text/html; charset=utf-8" />           <!-- missing http-equiv="Content-Type" -->
<meta content="IE=Edge" />                             <!-- missing http-equiv="X-UA-Compatible" -->
```
Both tags are effectively inert as written. The charset declaration is especially important — without it, some clients fall back to a default encoding.

**`Src:` capitalization in `@font-face` rules (invalid CSS property)**
```css
Src: url("https://braze-images.com/...") format('woff');
```
All 10 `@font-face` blocks use `Src:` (capital S). CSS property names are case-insensitive in browsers but some email client CSS parsers (notably older Outlooks, Yahoo Mail) treat this as an unknown declaration and skip font loading entirely, forcing fallback stack rendering.

**Conflicting `text-size-adjust` values in the same rule**
```css
*{-ms-text-size-adjust: 100%; ... -ms-text-size-adjust: none; text-size-adjust: none}
```
`-ms-text-size-adjust` is declared twice — `100%` then `none` — in a single rule. The `none` value wins (last declaration). `text-size-adjust: none` also suppresses OS-level text scaling, which fails WCAG 1.4.4 (Resize Text) in clients that honor it.

**`maximum-scale=1` in viewport**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Accessibility issue; WCAG 1.4.4 violation.

**Single format per `@font-face`, no format fallback**
Futura PT fonts load only `.woff`; HelveticaNow fonts load only `.ttf`. No `woff2` (better compression, wider support) and no multi-format stack. If a client blocks the CDN request, the entire font falls back with no graceful degradation within the `@font-face` rule itself (reliant on `font-family` stack in element styles, which is not visible in the truncated source).

**Non-standard `supported-color-schemes` in CSS `:root`**
```css
:root { color-scheme: light dark; supported-color-schemes: light dark; }
```
`supported-color-schemes` is not a valid CSS property — it belongs only in `<meta name="supported-color-schemes">` (correctly present in `<head>`). The CSS declaration is a no-op and adds dead code noise.
