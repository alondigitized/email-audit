### 3. Rendering & Accessibility

**`.bg1` class collision — confirmed bug:**
The class is declared twice with conflicting values:
```css
/* Declaration 1 — line ~8 */
.bg1 { background-color: #ffffff; }

/* Declaration 2 — line ~89 */
.bg1 { background: #58546d; }  /* overwrites to dark purple */
```
Any element using `.bg1` will render with a dark purple/grey background (`#58546d`) instead of white. This will break any white-background section that relies on this class.

**Non-functional `@font-face` blocks — confirmed bug:**
All nine `@font-face` declarations are missing `src:` properties:
```css
@font-face {
  font-family: proxima-nova, sans-serif;
  font-weight: 700;
  font-style: normal;
  /* no src: — font will never load */
}
```
Web fonts (`proxima-nova`, `linotype-didot`) will never load from these rules. Fallbacks (`Arial`, `Times New Roman`) will render instead. This is typically benign since most email clients block remote fonts anyway, but the declarations are dead code and indicate these were likely intended to point to a hosted font CDN (Adobe Fonts / Typekit).

Harmless in outcome here, but indicates a copy-paste error in the template.
