- 2. **Put the offer in the subject.** The May 14th send proved it works — "Extra 20% off Skechers starts NOW" outperforms "Major summer savings inside" in every measurable way for someone like me.
- 3. **Segment the send or build a men-first layout.** Put men's walking shoes above the fold; push the women's and kids' blocks lower or to a separate send entirely.

### 1. Technical Summary

Functionally deliverable email with standard ESP infrastructure (Salesforce Marketing Cloud), but carries a systemic alt-text failure across all 29 content images and one mixed-content HTTP image asset that will be blocked in secure mail clients.

---

### 2. Link & Tracking Issues

**32 click-redirect links unverified** — All CTAs route through `click.email.famousfootwear.com` with opaque `?qs=` query strings. No HTTP probing was possible; destination health is unconfirmed.

**Open pixel uses HTTP redirect chain** — The open-tracking pixel at `click.email.famousfootwear.com/open.aspx?HSCLSELWGUYE5NO6YUYNMBMN6Y.70246` is a redirect-based tracker. Standard pattern, no defect, but noted for completeness.

**No UTM parameters visible on outbound links** — All click-through URLs are opaque tracking redirects with no visible `utm_source`, `utm_medium`, or `utm_campaign` parameters in the HTML source. Attribution at destination depends entirely on SFMC redirect resolution — if that layer fails or is blocked, web analytics receives no campaign signal.

---

### 3. Rendering & Accessibility

**Critical — 29 images missing alt text.** Every content image has `alt=""`. Affects screen reader users and image-blocked rendering (common in corporate mail clients). Affected assets include all product images, logo (`3b6a7dc1`), dividers, and CTA button graphics.

**Logo image has empty alt** — `3b6a7dc1-6955-49f8-868a-bf62a15122ee.png` (200×65, the Famous Footwear logo) has `alt=""`. Should be `alt="Famous Footwear"`.

**Mixed-content HTTP image** — One LiveContent dynamic image loads over HTTP:
```
src="http://cl.S7.exct.net/LiveContent.aspx?qs=..."
```
Modern clients (Gmail, Outlook 365, Apple Mail) will block non-HTTPS image sources. This asset will render as a broken image for a significant portion of recipients.

**`<meta content="text/html; charset=UTF-8" />` is malformed** — The charset meta tag is missing the `http-equiv` attribute: should be `<meta http-equiv="Content-Type" content="text/html; charset=UTF-8" />`. Browsers and mail clients may fall back to default encoding.

**`user-scalable=0` in viewport meta** — `maximum-scale=1, user-scalable=0` prevents pinch-to-zoom on mobile. Accessibility violation (WCAG 1.4.4); removes user control over text size.

**Malformed HTML tag in source** — `<strong>` close tag appears corrupted in truncated source (`</stron…`). If this extends into the live email, it will break DOM structure downstream of that point in some parsers.
