# The 530
**Score:** 7/10 · **Type:** Email audit · **2026-07-03**
## Executive summary

- I see "New Balance" in the sender column and "The 530" in the subject and I think — okay, specific model, at least tell me something. I open it and the very first thing I see is a young woman with great legs in a tiny skirt. That's the hero image. The whole email is a lookbook for a retro running shoe in six colorways, and then at the bottom they're selling me matching hoodies because the 530 "completes the look."
- This isn't for me. I'm 62, I wear sensible pants, and I don't need a "matching set." I want to know if the shoe is cushioned, if it has decent arch support, and whether they carry it in a wide. None of that is here. The 530 is being sold as a fashion sneaker — the styling, the color grid, the young female lifestyle shots all say so. There's nothing in this email that speaks to a guy my age looking for a comfortable everyday walking shoe.
- I'd close it without clicking. Not forwarding. If I need a New Balance shoe I'll go to the site directly, but this email didn't earn that visit.

## What's working

- New Balance is a brand I recognize and trust — the sender name alone was enough to get me to open it
- Email is clean and renders properly; everything loaded, nothing broken
- Free shipping banner at the top is upfront and readable — spotted it immediately
- "Shop Adults" CTA is at least in the right product category for me
- Six colorways in a clean grid give a solid overview of the options, even if none of them are calling my name

## What's weak

- Hero model is a young woman in a mini skirt — I'm a 62-year-old guy, this demographic signal is completely off, and it's the first thing I see
- Zero comfort messaging anywhere — no cushioning callout, no arch support, no wide width option, nothing that tells me if this shoe works for my feet
- "Shop Adults" and "Shop Kids" as parallel CTAs again — July 2nd was all kids' shoes, and now kids is still in the frame; New Balance keeps contaminating my sends with kids content
- "Complete the look" section pushing hoodies and graphic tees is irrelevant to me — I came here for a shoe, not an outfit
- No pricing incentive — just $90 regular price with no discount, no deadline, no loyalty hook; nothing that makes today different from any other day

## Recommendations

- 1. **Swap the hero model for a male model 50+.** I need to see myself in the shoe. A stylish older guy wearing the 530 on a morning walk would speak directly to me instead of making me feel like this email landed in the wrong inbox.
- 2. **Add one comfort callout in the hero area.** Even a single line — "cushioned midsole, built for all-day wear" — bridges the gap between "fashion sneaker" and "shoe worth my attention."
- 3. **Remove "Complete the look" entirely, or send it separately.** Shoe shoppers at my stage of life aren't cross-shopping hoodies in the same email.
- 4. **Give me a reason to buy today.** Free shipping on $75 is a floor, not an incentive. A time-limited code or a weekend-only discount would actually move me.
- 5. **Fix the segmentation.** I've now received kids-adjacent content across multiple consecutive sends (July 2 was 100% kids, and "Shop Kids" is still a parallel CTA here). I'm clearly in the wrong list.

### 1. Technical Summary

The template is structurally sound (HTML4 Transitional, dark mode implemented) but contains an unresolved template placeholder in a CSS `url()`, empty `@font-face` declarations that will cause silent font fallback, and a CSS class collision. The truncated source prevents a complete audit of links, compliance footer, and UTM parameters.

### 2. Link & Tracking Issues

- **Unresolved placeholder in CSS background-image:** `.bgwhite` declares `background-image: url('http://image.XXXXX.png')` — the domain token `XXXXX` was never substituted. This image will 404 on render.
- **HTTP instead of HTTPS:** The same `url()` uses `http://`, which may trigger mixed-content blocking in security-strict clients even if the token were resolved.
- **Truncated source:** CTA `href` values are not visible. Cannot confirm tracking parameters are present across all links.

---

### 3. Rendering & Accessibility

- **Empty `@font-face` declarations:** All nine `@font-face` rules (Proxima Nova, Linotype Didot, etc.) declare `font-family`, `font-weight`, and `font-style` but include no `src:` property. Web fonts will silently fall back to `Arial` / `Times New Roman` in every client. This is either an intentional omission (relying on pre-loaded Adobe Fonts) that needs documentation, or a build error.
- **CSS class collision — `.bg1` defined twice:**
  - Definition 1 (line ~18): `.bg1 {background-color: #ffffff;}`
  - Definition 2 (line ~143): `.bg1 {background:#58546d;}` (purple-gray)
  - The second wins by cascade order. One is wrong.
- **Duplicate `font-family` property in single `@font-face` rule:**
  ```css
  @font-face { font-family: proxima-nova,sans-serif; font-weight: 700;
    font-style: italic; font-family: proxima-nova,sans-serif; }
  ```
  Duplicate property in the same rule — copy-paste artifact, parsers discard the first.
- **Malformed meta tag:** `<meta content="IE=edge" />` is missing `http-equiv="X-UA-Compatible"`. Correct form: `<meta http-equiv="X-UA-Compatible" content="IE=edge" />`.
- **Single narrow breakpoint:** Responsive styles fire only at `max-width: 414px`. Devices 415px–600px (larger phones, portrait tablets) receive no responsive treatment.
- **Dark mode link override:** `a {color:#cf0a2c !important;}` forces all links to brand red in dark mode. Any white-on-black CTA button links will render as red-on-black — low contrast.
