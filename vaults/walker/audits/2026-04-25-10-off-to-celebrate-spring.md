### 3. Rendering & Accessibility

**Malformed meta tags (two instances):**

```html
<!-- Missing http-equiv="Content-Type" -->
<meta content="text/html; charset=utf-8" />

<!-- Missing http-equiv="X-UA-Compatible" -->
<meta content="IE=Edge" />
```

Both tags are inert without their `http-equiv` attributes. The charset tag should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
The IE compatibility tag should be:
```html
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```
Outlook on Windows uses the charset declaration for rendering; missing `http-equiv` risks encoding fallback behavior on older Outlook builds.

**CSS reset conflict — `-ms-text-size-adjust`:**

Within the `*` selector, two contradictory declarations appear in sequence:
```css
* {
  -ms-text-size-adjust: 100%;   /* line 1 */
  ...
  -ms-text-size-adjust: none;   /* line 2, wins via cascade */
}
```
`none` disables text size adjustment entirely on IE Mobile / Windows Phone. The intended value is `100%`. The trailing `none` should be removed.

**`@font-face` property casing:**

All 10 `@font-face` blocks use `Src:` (capital S) instead of `src:`. CSS property names are case-insensitive per spec, so this is technically valid, but it is non-standard and will fail any strict CSS linter. Low severity.

**Intentional near-black color hack:**

`#000001` is used throughout (e.g., `.dm-font-black`, `.border-top-black`) instead of `#000000`. This is a known technique to prevent Gmail's dark mode from inverting true black — intentional, not an error. No action needed, but should be documented in the template's internal notes so future editors don't "fix" it.

**Non-standard CSS property in `:root`:**

```css
:root {
  supported-color-schemes: light dark;
}
```
`supported-color-schemes` is not a valid CSS property — it is only valid as a `<meta>` tag content value. The correct CSS property is `color-scheme`. The `:root` block should contain only `color-scheme: light dark;`. The erroneous property is silently ignored by all clients, so there is no active breakage, but it should be corrected.

**Alt text on images:** Cannot verify from truncated source. Must confirm all `<img>` tags carry non-empty `alt` attributes for accessibility and plain-text fallback rendering.
