## Technical Audit

# Technical Audit: HOKA "Style + utility" (2026-10-16)

## 1. Technical Summary
The email is a Cordial-sent HTML broadcast with consistent UTM tagging. The QA run found no plain-text part, 10 images with no `alt` attribute (8 content images plus the footer logo and a tracking pixel), and invalid or duplicated head markup. All 12 probed click-tracking links returned 4xx, but the pattern points to the probe being blocked rather than the links being dead.

## 2. Link & Tracking Issues
- **All 12 probed `e.emails.hoka.com/c2/...` redirects failed.** Eleven returned 406 and the unsubscribe link returned 403.
  - The JWT payload on each link decodes to a valid `linkUrl`, for example `https://www.hoka.com/en/us/lifestyle/?utm_source=US_Broadcast&utm_medium=email&...`. Identical failures across every link suggest the Cordial edge is rejecting the probe's user agent, so these are likely false positives.
  - The QA summary also says "12 material link(s) probed, 12 skipped", which contradicts the 12 FAILs. Treat the results as inconclusive until the links are re-tested with a browser UA.
- **Link text gives no accessible name.** Eight image links read `[image: US_20261016_TerrainPack_*.jpg]` because the images have no `alt`. The first link reads only "HOKA".
- **No per-link differentiation in the UTMs.** Every link carries the same `utm_campaign=H_US_BR_20261016_EliteTerrainSystemCollection_A60Day_...` and no `utm_content` or `utm_term`.
  - Image links `_a`, `_b`, `_c`, `_g` and the header link can't be told apart in site analytics.
- **Inconsistent PDP parameters.**
  - Image `_d` links to `.../1182950.html?dwvar_1182950_color=BBLC` with no size.
  - Image `_e` links to the same product with `color=OYW&dwvar_1182950_size=M8%2FW9`.
  - Image `_f` links to `1176684.html` with `color=BBLC&size=M8%2FW9`.
  - Pre-selected sizes appear on only two of the three product links.

## 3. Rendering & Accessibility
- **No plain-text alternative.** QA reports "Text version is 0 chars" (FAIL).
- **Missing `alt` on 10 images.**
  - Content images: `US_20261016_TerrainPack_a` through `_h`, hosted at `images.usw2.cordial.com/1664/...`.
  - Footer logo: `LogoFooterPrimary.png`.
  - Tracking pixels: `e.emails.hoka.com/o/p/...` and `mg.emails.hoka.com/o/...`. The pixels should carry `alt=""`.
  - Because the CSS sets `img {display:block}`, nothing shows if images are blocked, and the email is image-heavy (8 full-width slices).
- **Invalid charset meta.** `<meta content="text/html; charset=utf-8" />` has no `http-equiv`, so it doesn't declare the charset.
- **Empty `<title></title>`.**
- **Two conflicting viewport metas.** The first is `width=device-width, initial-scale=1, maximum-scale=1`. The second adds `user-scalable=yes`. The `maximum-scale=1` in the first can block pinch-zoom in some clients.
- **Invalid CSS from unrendered template values.** In `.nav_padding {padding-top:px !important;padding-bottom:px !important;}` and `.nav_border {border-top:px solid ;}` the length and color values are empty.
- **Possible over-reset.** `* {... -webkit-text-size-adjust: none;}` is overridden on `body`, so this is likely harmless. Custom `@font-face` files load from `hoka.com/on/demandware.static/...`, and the truncated source didn't let me verify the font fallback stack.

## 4. Personalization & Merge Tokens
No issues found. The truncated source shows no unrendered tokens. The per-recipient `hmail=` and `cordial_id=` values in the tracked URLs are populated.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Unsubscribe link is present but unverified.** The link text is "Unsubscribe", pointing to `options.hoka.com/unsubscribe?cid=...`.
  - The probe got a 403, most likely bot-blocking. Confirm manually that it resolves.
  - The unsubscribe URL also carries the campaign UTMs, which is unnecessary.
- **SPF/DKIM/DMARC unknown.** The `Authentication-Results` header was not found because the email came through the AgentMail relay. Alignment of `info@emails.hoka.com` can't be confirmed from this data.
- **Not confirmable from the truncated source:** the physical postal address and the `List-Unsubscribe` / `List-Unsubscribe-Post` headers.

## 6. Email-to-Site Continuity
- **UTMs are consistent:** `utm_source=US_Broadcast`, `utm_medium=email`, and one long `utm_campaign` string on every link. The string encodes audience and segment tags (`365LifestylePurchasers`, `270BlackShoesTag`, `0918LaunchOpeners`).
- **Generic destinations for most images.** Images `_a`, `_b`, `_c` and `_g` all land on the generic `/en/us/lifestyle/` page, which makes the click paths for these four slots indistinguishable. Only `_d`, `_e` and `_f` deep-link to PDPs.
- **Utility links go to `/en/us/return-start/` and `/en/us/discount-programs/`.** I couldn't confirm whether their landing pages match the campaign, because every probe failed.

## 7. Recommendations
1. Re-probe the 12 links with a browser-like UA (or a Cordial-allowlisted UA). Treat the 4xx results as unconfirmed until then, and check the unsubscribe link by hand.
2. Add a plain-text MIME part. This is the only confirmed deliverability FAIL.
3. Add descriptive `alt` text to images `_a` through `_h` and the logo, and `alt=""` to the tracking pixels.
4. Fix the head markup:
   - Use `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">`.
   - Fill in `<title>`.
   - Keep a single viewport meta and drop `maximum-scale=1`.
   - Remove or complete the empty `.nav_padding` and `.nav_border` rules.
5. Add `utm_content` per slot (for example `hero`, `tile_c`, `pdp_torsummit`) so clicks can be attributed.
6. Apply `dwvar_*_size` on all three PDP links or on none.
7. Re-run the capture with the full headers to check SPF/DKIM/DMARC and `List-Unsubscribe`, and with the full HTML to check the postal address.
