## Technical Audit

## Technical Audit — DSW "Get $10 or more off these best sellers" Email

---

### 1. Technical Summary

Email is rendered via Braze, using an XHTML 1.0 Transitional doctype with custom web fonts (Futura PT + HelveticaNow) hosted on `braze-images.com`. Several invalid CSS property names in `@font-face` blocks will silently break web font loading across all clients.

---

### 2. Link & Tracking Issues

**Cannot fully assess** — HTML source is truncated before body links appear. The following is confirmed from the visible portion:

- Font asset URLs for HelveticaNow include timestamp query strings (e.g., `?1755182939`):
  ```
  https://braze-images.com/.../original.ttf?1755182939
  ```
  If DSW updates font assets mid-send and these URLs rotate, mid-delivery recipients will load different font binaries than early recipients. This is a minor consistency risk, not a blocking issue — but the cache-busting string has no value in an email context where fonts are loaded once.

---

### 3. Rendering & Accessibility

**Critical: `Src:` (capital S) in all 10 `@font-face` declarations**

CSS property names are case-sensitive per spec. `Src:` is not a valid descriptor — it should be `src:`. All ten `@font-face` blocks are affected:

```css
/* WRONG — all 10 blocks */
@font-face {
  font-family: 'Futura_PT_Regular';
  Src: url("https://braze-images.com/...") format('woff');
}
```

Strict CSS parsers (WebKit in Apple Mail, some Android clients) will silently discard the invalid descriptor and fall through to system fonts. Futura PT and HelveticaNow will not render for a significant portion of the audience.

**`maximum-scale=1` in viewport meta**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

This prevents users from zooming text. Fails WCAG 1.4.4 (Resize Text, Level AA). iOS Safari respects this value and will block pinch-zoom.

**`text-size-adjust: none` applied globally**

The `*` reset block sets both `-webkit-text-size-adjust: 100%` (correct) and then `text-size-adjust: none` (incorrect for non-prefixed browsers). The unprefixed `none` overrides the corrective `100%` in browsers that have dropped the prefix:

```css
* {
  -webkit-text-size-adjust: 100%;  /* correct */
  -ms-text-size-adjust: none;      /* problematic on non-Outlook */
  text-size-adjust: none;          /* overrides the webkit rule in modern browsers */
}
```

Fix: change `text-size-adjust: none` to `text-size-adjust: 100%`.

**`supported-color-schemes` declared as a CSS property**

```css
:root {
  color-scheme: light dark;
  supported-color-schemes: light dark;  /* not a valid CSS property */
}
```

`supported-color-schemes` is only valid as an HTML `<meta>` tag (which is correctly present in the `<head>`). As a CSS property it is ignored — no functional breakage, but it is dead code.

**Font format: TTF only for HelveticaNow, WOFF only for Futura PT**

Neither font family offers a WOFF2 fallback. WOFF2 is ~30% smaller and supported by all modern email clients that support web fonts at all. No functional breakage, but increases load time unnecessarily.

**Missing `http-equiv` attributes on two meta tags**

```html
<!-- Should be: <meta http-equiv="Content-Type" content="text/html; charset=utf-8" /> -->
<meta content="text/html; charset=utf-8" />

<!-- Should be: <meta http-equiv="X-UA-Compatible" content="IE=Edge" /> -->
<meta content="IE=Edge" />
```

Both tags are missing `http-equiv`. Without it, the charset directive may not be processed by older Outlook versions and the IE compatibility hint is silently ignored.
