# Don’t forget: 25% off select shoes
**Score:** 8/10 · **Type:** Email audit · **2026-05-16**
## Executive summary

- I know exactly what this is before I even scroll — same sale they pushed five days ago on May 11, just with "Don't forget" slapped on the front. New Balance sent me "Up to 25% off shoes" then, got a mild look from me, and now here it is again dressed as a reminder. Seven emails in eleven days from this brand. I'm keeping count.
- That said, the stacked red shoeboxes are a genuinely strong opener. It grabbed me on a small phone screen — clean, no clutter, no person I have to decide whether I relate to. The offer copy is readable without zooming, the Men/Women/Kids buttons make sense, and the NBSTYLE code is right there in plain sight. What actually moved me was the "25% off all insoles" section near the bottom — that ends **tomorrow**, and insoles I actually think about. Arch support, cushioning, keeping my feet from aching after a few hours on them. That felt real and useful.
- Would I click? Probably on the insoles — that deadline is credible. The main shoe banner I'd browse, scan the men's section, and close it if nothing jumped out. I wouldn't forward this; it's a standard sale reminder, not a tip worth sharing.

## What's working

- **NBSTYLE is front and center** — the code, the percentage, the categories it applies to are all right there. I don't have to hunt through fine print to find out how to redeem.
- **Men / Women / Kids segmentation** — three clean buttons, no ambiguity about where I belong. Simple and fast on a phone.
- **Insoles section with a hard deadline** — "May 11 through May 16" means this closes tomorrow. That's the only genuinely urgent offer in the whole email, and it's the one most relevant to a comfort-focused buyer like me.
- **No render issues** — everything loaded, text is crisp, layout holds together. At my age I notice when emails are a mess, and this one isn't.

## What's weak

- **"Don't forget" confirms I already forgot — and why** — this is the same sale from five days ago with a reminder subject. The urgency is fake if the offer just keeps rolling forward.
- **No end date on the main shoe sale** — the insoles block managed a specific date range; the hero offer couldn't? I have no idea if 25% off shoes expires tonight or next month.
- **Nothing in the product tiles speaks to comfort** — Fresh Foam Arishi, WARRW1 Slip Resistant, Fresh Foam X 860V1. Fine shoe names, but I need to see "arch support," "cushioned footbed," "wide widths available" to know if any of these are built for my feet. I'm not going to research it blind.
- **No demographic signal** — the hero is a stack of boxes, no model, no lifestyle image. I have no idea if New Balance is talking to a 62-year-old on a walk or a 28-year-old in a gym. At minimum, a man walking in these shoes would tell me who this email is for.
- **Seven emails in eleven days** — I'm not unsubscribing, but I'm caring less each time I open one.

## Recommendations

- 1. **Put a hard deadline on the shoe sale** — "Ends Sunday" in the hero does more work than "Don't miss out." If the insoles section can commit to a date range, the main offer can too.
- 2. **Move insoles higher** — it's the strongest comfort signal in this whole email. A 62-year-old with tired feet responds to arch support faster than a generic shoe sale. Lead with the most targeted offer, not bury it.
- 3. **Add one comfort callout to the hero** — "25% off shoes built for all-day comfort" versus "25% off select shoes." That single word change separates this from every other discount email in my inbox.
- 4. **Consolidate the cadence** — one good email every three or four days is more convincing than daily noise. I start tuning out around day four.
- 5. **Swap in a men's lifestyle shot** — doesn't need to be fancy, just a man actually wearing these shoes in a recognizable situation. The shoe-box tower is striking but anonymous.

- **Subject Alt B:** `Walker, your 25% off expires this weekend`
- **Preheader Alt A:** `Men's cushioned styles included — insoles 25% off through tomorrow`

### 1. Technical Summary

The email uses an HTML 4.01 Transitional shell with modern dark-mode CSS layered on top — a common ESP pattern, but this instance contains an unfilled template placeholder in a background image URL and a duplicate CSS class definition that produces a color conflict. No catastrophic rendering failures, but two issues require fixes before send.

---

### 2. Link & Tracking Issues

**Unfilled template token in background image URL**
```css
.bgwhite { background-image: url('http://image.XXXXX.png'); }
```
- `XXXXX` is clearly an unresolved merge token — the image will 404 on send.
- The URL also uses plain `http://`, which will trigger mixed-content warnings in clients that enforce HTTPS (Gmail web, Apple Mail on macOS). Replace with the resolved HTTPS asset URL.

**Full link audit not possible** — HTML is truncated before the body links appear. Recommend running a full link-check pass (all `href` values) to verify UTM params and no remaining `XXXXX`-style tokens in CTA hrefs.

---

### 3. Rendering & Accessibility

**Duplicate `.bg1` class — color conflict**
The stylesheet defines `.bg1` twice with incompatible values:
```css
.bg1 { background-color: #ffffff; }   /* line ~10 — white */
...
.bg1 { background: #58546d; }          /* line ~90 — purple-gray */
```
CSS cascade means the second declaration always wins. Any element using `.bg1` will render purple-gray, not white. One of these definitions must be removed or renamed.

**`@font-face` declarations have no `src:` URLs**
All nine `@font-face` blocks (proxima-nova, linotype-didot, etc.) are declared without a `src:` property:
```css
@font-face { font-family: proxima-nova,sans-serif; font-weight: 700; font-style: normal; }
```
Invalid `@font-face` blocks are silently ignored — fonts fall through to the `Arial, sans-serif` stack. If web fonts were intended, src URLs are required. If fallback-only was the intent, remove the dead blocks to reduce payload.

**`<meta>` tag missing `http-equiv` attribute**
```html
<meta content="IE=edge" />
```
Should be:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without `http-equiv`, this tag is a no-op in Outlook/IE rendering engines.

**Positive:** Dark mode implementation (`@media (prefers-color-scheme: dark)`, `color-scheme: light dark`) is present and structured correctly.
