### 3. Rendering & Accessibility

**`<meta http-equiv>` malformed:**
```html

```
Missing `http-equiv="X-UA-Compatible"`. The `content` attribute alone is ignored. Correct form:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```

**`<style>` precedes `<meta charset>`:**
The first `<style>` block appears before `<meta content="text/html;" charset="utf-8" />`. Charset declaration should be the first element in `<head>` to guarantee correct encoding before any content is parsed.

**Dark mode not declared:**
```html
<meta name="color-scheme" content="light" />
<meta name="supported-color-schemes" content="light" />
```
Forces light rendering in Apple Mail and Samsung clients. No `prefers-color-scheme: dark` media query present. Subscribers using system dark mode will see uncontrolled inversion on images and potentially white text on white backgrounds in Outlook.

**Duplicate CSS property (dead code):**
```css

  color:inherit !important;
  color:inherit;   /* ← redundant; the !important line above takes precedence */
}
```

**Conflicting class names for the same behavior:**
`.mobilehide` and `.mobile-hidden` both map to `display: none !important` across two separate media query blocks. One is likely a legacy artifact. If templates mix them, elements may fail to hide correctly.

**`pointer-events: none` on tel/sms links:**
