### 3. Rendering & Accessibility

**Bug — Malformed CSS values (mobile breakpoint, `@media max-width: 480px`):**
```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
.nav_border  { border-top:px solid ; }
```
Both declarations are missing the numeric value before `px` and `border-top` is missing its color. These will be silently dropped by all CSS parsers, leaving the nav element with incorrect padding/border on mobile.

**Bug — Duplicate `<meta name="viewport">` tag:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
Two conflicting viewport declarations — the first disallows user scaling (`maximum-scale=1` with no `user-scalable`), the second allows it. Browser behavior on duplicate meta tags is undefined; the second declaration may be ignored. Remove the duplicate; keep whichever policy is intentional.

**Defect — Missing `http-equiv` on charset meta:**
```html
<meta content="text/html; charset=utf-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, the charset declaration is non-standard and may not be honored by Outlook and older WebKit-based clients.

**Minor — Empty `<title>` tag:**
```html
<title></title>
```
Some ESPs and spam filters use the title element. An empty title is not a deliverability risk but is a missed fallback for clients that surface it (e.g., tab title in web-based clients).

**Note — Near-black/near-white link colors:**
```css
a { color: #000001; }
.footer_text a { color: #fffffe; }
```
Values `#000001` and `#fffffe` are a known workaround to prevent Gmail and Apple Mail from auto-recoloring links (they only trigger on exact `#000000` / `#ffffff`). This is intentional and technically valid — not a defect.
