## Technical Audit

1. Technical Summary
Email is functional but has a critical broken unsubscribe link and no plain-text fallback, plus widespread use of insecure HTTP image sources.

2. Link & Tracking Issues
- **Broken unsubscribe link (400 error)** — QA flagged the "Unsubscribe" link as returning HTTP 400: `https://skechers.attentivemail.com/ls/click?upn=u001.LNc6VorXOZu5avyAvDTfGQbua6CZqR1ErPMp2bSFS3jZfyDWjlmxsiKiFGWozVAXb47jSjdUP...` This is a functional failure, not just a compliance risk (see Section 5).
- All observed links route through Attentive's click-tracking redirector (`skechers.attentivemail.com/ls/click?upn=...`), consistent with standard ESP link-wrapping.
- 12 of 37 total links were probed (QA prioritizes by click likelihood); 25 footer/utility/social links were deprioritized per standard methodology — no broken links reported among those probed besides the unsubscribe link.

3. Rendering & Accessibility
- **Two images missing alt text**: `303949_WHPK_HERO_LG` (hero product image) and `a6ec5198-5437-4eaa-8613-eacc775726f9.jpg`. Screen readers will announce nothing meaningful for these.
- **Nine images served over `http://` instead of `https://`**, including the Skechers logo (`dde00662-...png`), hero CTA image (`58e7efe1-...jpg`), app store badges, payment/social icons, and the open-tracking pixel. Many mail clients (Outlook, Gmail proxy) block or flag mixed-content HTTP images, degrading render quality.
- Responsive/media-query CSS is present (`@media (max-width:620px)`) with mobile-specific padding and font-size overrides for rows 16/17/19 — no structural issues found in the truncated markup.
- MSO/Outlook conditional handling (`mso-table-lspace`, `x-apple-data-detectors` reset) is present as expected.

4. Personalization & Merge Tokens
No issues found — no unresolved merge tags (e.g. `{{first_name}}`, `%%FIELD%%`) or broken personalization syntax detected in the provided HTML.

5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Unsubscribe link is broken (400 response)** — this is a CAN-SPAM compliance failure, not just a UX bug, since the mechanism must be functional and operable without extraordinary effort.
- Sender address `hello@msgs.skechers.com` uses a dedicated subdomain, consistent with typical SPF/DKIM alignment practice, but authentication headers (SPF/DKIM/DMARC) are not present in the provided source/QA data to verify — cannot confirm pass/fail.
- Physical mailing address was not present in the truncated HTML excerpt — cannot confirm CAN-SPAM footer compliance from available data.

6. Email-to-Site Continuity (UTM params, landing page alignment)
- No UTM parameters are present on any link; all tracked URLs use Attentive's `upn=` token scheme instead of standard `utm_source/utm_medium/utm_campaign` query params. This is expected for Attentive-routed clicks (resolved server-side), but means GA4/site-side campaign attribution depends entirely on Attentive's redirect resolving correctly — the broken unsubscribe link raises the question of whether other redirect resolutions are reliable.
- Cannot verify final landing page alignment (e.g., whether product links land on matching PDPs) since destination URLs resolve through the Attentive redirector and were not independently followed in this audit.

7. Recommendations
1. Fix the unsubscribe link immediately — 400 error is both a compliance and deliverability risk (ISPs monitor unsubscribe success rates).
2. Add a plain-text MIME alternative — currently 0 chars, which hurts spam filtering/deliverability and violates ESP best practice for multipart emails.
3. Switch all `http://image.emails.skechers.com/...` asset references to `https://` to prevent mixed-content blocking in mail clients.
4. Add descriptive `alt` text to the hero image (`303949_WHPK_HERO_LG`) and the secondary product image (`a6ec5198-...jpg`).
5. Confirm SPF/DKIM/DMARC alignment for `msgs.skechers.com` and verify a physical mailing address is present in the full (non-truncated) footer.
