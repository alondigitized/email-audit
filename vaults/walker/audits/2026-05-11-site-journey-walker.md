## Technical Audit

## Technical Summary

8-step mobile journey audited: Homepage → Log In → Men category → Men > Shoes → Product detail → Add to Cart → View Cart → Search "slip in". TTFB is consistently fast (25–36ms) except View Cart (138ms). LCP and CLS were not captured across any step — a measurement gap. 15 axe violations span 3 pages; View Cart has two serious structural defects (`document-title`, `html-has-lang`). The dominant error pattern is Kasada bot-detection SDK (6× HTTP 429) plus one Stylitics CORS misconfiguration. Third-party script load is extremely heavy and contains duplicate tags.

---

## Accessibility

**Critical (1)**
- `aria-required-parent` — Homepage: ARIA role used without the required parent container. Screen readers will misinterpret element ownership.

**Serious (2)**
- `document-title` — View Cart: `<title>` element is empty or absent. Fails WCAG 2.4.2. Also degrades SEO if the page is crawled.
- `html-has-lang` — View Cart: `<html>` element missing `lang` attribute. The homepage renders `lang="en"` correctly; this is page-specific, suggesting the cart is a separate render context (likely a Salesforce Commerce Cloud modal or microfront-end) that does not inherit the base template.

**Moderate (10)**
- Homepage: `heading-order` (skipped heading levels); `landmark-complementary-is-top-level` (`<aside>` nested inside another landmark); `landmark-main-is-top-level` (`<main>` nested); `landmark-no-duplicate-main` (multiple `<main>`); `landmark-unique` (repeated landmark roles); `region` (content outside landmark regions).
- View Cart: `landmark-one-main` (no `<main>`); `page-has-heading-one` (no `<h1>`).
- Search: `landmark-complementary-is-top-level`; `landmark-unique`; `region`.

**Minor (1)**
- `aria-allowed-role` — Homepage: `role` attribute value is invalid for the host element type.

The View Cart defects (`document-title`, `html-has-lang`, `landmark-one-main`, `page-has-heading-one`) collectively suggest it is rendered as an isolated client-side shell that does not share the site's standard HTML scaffold.

## Mobile Optimization

- **`--vh` CSS variable**: set inline on `<html>` as `6.640000000000001px`. This is a standard pattern to work around the iOS Safari 100vh bug (real viewport height = `var(--vh) * 100`). The floating-point precision artifact (`6.640000000000001` instead of `6.64`) is caused by JS division and is cosmetically harmless but signals the fix is unpolished.
- No explicit `<meta name="viewport">` visible in the truncated HTML samples — assumed present but should be verified.
- No other mobile-specific structural issues identifiable from the provided data.

## Console & Network Errors

**Kasada SDK 429 (5× network + 5× console)**
- URL: `/149e9513-01fa-4fb0-aad4-566afd725d1b/2d206a39-8ed7-437e-a3be-862e0f06eea3/fp?x-kpsdk-v=j-1.2.405`
- This is Kasada's client-side bot-detection fingerprinting endpoint. The path structure (`UUID/UUID/fp`) is Kasada's standard token acquisition flow. Repeated 429s indicate the automated test session was flagged and rate-limited by Kasada, which is expected behavior for headless browsers. However, this means the fingerprinting loop retried at least 5 times before giving up, generating console noise and extra network round trips on real user sessions that trip Kasada's heuristics.

**Cart page 429 (1× network)**
- URL: `https://www.skechers.com/cart/`
- The cart page HTML endpoint itself returned 429. This is the direct cause of the elevated TTFB on View Cart. If Kasada challenged the session before serving the cart render, legitimate users with unusual browser configurations could receive a failed cart load, which is a conversion-impacting defect.

**Stylitics CORS failure (1× console)**
- `https://web-assets.stylitics.com/style.css?base=hotspots&theme=skechers&version=146f27f3c5` blocked — no `Access-Control-Allow-Origin` header for the `https://www.skechers.com` origin.
- Stylitics serves a "shop the look" overlay widget. Without its stylesheet, the widget renders unstyled or fails silently. This requires Stylitics to add `skechers.com` to their CDN's CORS allowlist — a vendor-side fix.

## Recommendations

**P0 — Fix immediately**
1. **View Cart `<title>` and `html[lang]`**: the cart render context must include a proper HTML scaffold. If it's a Salesforce Commerce Cloud partial, ensure the base template is applied. These are WCAG failures and Search Console will surface them.
2. **Cart 429 under Kasada**: audit the Kasada policy to ensure legitimate human sessions are not rate-limited at the `/cart/` render step. A 429 on cart load directly blocks checkout.

**P1 — Fix soon**
3. **`aria-required-parent` (critical) on Homepage**: identify the element using the role and wrap it in the correct parent container.
4. **Stylitics CORS**: file a ticket with Stylitics support to add `https://www.skechers.com` to the `Access-Control-Allow-Origin` allowlist for `web-assets.stylitics.com`.
5. **Remove duplicate script tags**: `ytc.js` (×2 Homepage) and `creativecdn` (×2 Men category) are firing double analytics hits and wasting parse time. Audit GTM container for misconfigured tags.

**P2 — Measure and track**
6. **Capture LCP and CLS**: all 8 steps have no LCP/CLS data. Instrument with `PerformanceObserver` or a Real User Monitoring tool. Without LCP, Core Web Vitals pass/fail is unknown.
7. **Third-party script audit**: 20+ vendors per page is high. Conduct a script-value audit against analytics contracts; consolidate where possible via GTM rather than direct `<script>` injection. Category pages load 4–5 additional vendor scripts not present on Homepage, suggesting inconsistent tag management.
8. **Homepage landmark structure**: resolve `landmark-no-duplicate-main`, `landmark-main-is-top-level`, and `landmark-complementary-is-top-level` — these indicate the HTML landmark hierarchy is malformed, likely from nested layout components that each emit their own landmark elements.
