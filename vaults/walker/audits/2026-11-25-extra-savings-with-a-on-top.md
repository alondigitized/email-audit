# Technical Audit: Crocs, "EXTRA savings with a 🎀 on top!"

Only the head and the first part of the body were available, because the HTML was truncated. Anything in the body past the preheader and tracking pixel, including the footer, links and alt text, is marked "not verifiable" rather than flagged.

## 1. Technical Summary
The head markup and preheader are mostly well built, with `lang="en"`, a viewport meta, a responsive media query and a 1x1 open pixel. Two real defects show up in the source: malformed `<meta>` tags and a third-party pixel with no alt text. Authentication status couldn't be determined from the data given.

## 2. Link & Tracking Issues
- **Link health is unverified.** The QA run skipped 20 tracking links because they are click-redirect domains. Their final destinations and HTTP status are unconfirmed.
- **Open pixel is correctly formed.** It sits in a hidden 1px wrapper: `https://click.crocs-email.com/open.aspx?qs=…&d=10212&bmt=0`, with `width="1" height="1" alt=""`.
- **Second tracking pixel with no alt text (QA WARN).** The pixel is `https://demandwarecrocs.demdex.net/event?d_dpid=196107&c_emailopened=Yes&d_dpuid=9153f33f…`. It is a separate Adobe Audience Manager (demdex) open-event beacon in addition to the ESP pixel. It needs `alt=""` so screen readers don't announce the URL. It also carries a per-recipient `d_dpuid` identifier.

## 3. Rendering & Accessibility
- **Charset and compatibility metas are malformed.**
  - `<meta content="text/html; charset=utf-8" />` has no `http-equiv="Content-Type"`.
  - `<meta content="IE=edge" />` has no `http-equiv="X-UA-Compatible"`.
  - Without the attribute, the browser ignores both tags, so the charset declaration does nothing. This email contains emoji and zero-width and soft-hyphen characters in the preheader padding. Those depend on the charset being set at the MIME level, so check the `Content-Type` header.
- **Present and correct:**
  - `<html lang="en">`
  - the viewport meta
  - `x-apple-disable-message-reformatting`
  - `format-detection`
  - the Gmail hack (`u + .email-body #new-gmail-hack`)
  - the Apple data-detector override
  - the `@media (max-width: 639px)` responsive utilities
  - the hidden preheader with padding characters
- **Web font fallback is not verifiable.** `TT Crocs` loads from `media.crocs.com` via `@font-face`. The `font-family` fallback stacks are in the truncated body.
- **Dark mode:** the head has no `color-scheme` meta and no `prefers-color-scheme` rules. This is minor and not a defect.
- **Body image alt text, link contrast and table `role="presentation"` are not verifiable** from the truncated source.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens (`%%…%%`, `{{…}}`, `[FNAME]`) appear in the visible source. The preheader says "Your code is inside!", but the code itself is in the truncated section, so it's unconfirmed.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication-Results header not found (QA WARN).** SPF, DKIM and DMARC alignment are unknown. The QA note attributes this to the AgentMail relay, so it may be an artifact of the capture path rather than a sender fault. The From domain `crocs-email.com` is a dedicated sending domain.
- **Unsubscribe link, physical postal address and `List-Unsubscribe` / `List-Unsubscribe-Post` headers are not verifiable.** The footer is in the truncated section, and headers weren't supplied. This is not a finding of non-compliance.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not verifiable. Links route through `click.crocs-email.com` redirects, and the 20 probes were skipped. That means UTM propagation and landing-page alignment with the "up to 60% off + extra 20% off" offer can't be confirmed.

## 7. Recommendations
1. Fix the metas: use `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` and `<meta http-equiv="X-UA-Compatible" content="IE=edge" />`.
2. Add `alt=""` to the demdex pixel `<img>`. Also confirm that sending a per-recipient `d_dpuid` to a third party matches Crocs' privacy disclosures.
3. Re-run the audit with the full, untruncated HTML. Then check the unsubscribe link, the postal address, body alt text, the `font-family` fallbacks and the UTM parameters.
4. Re-capture the raw message headers directly from the receiving mailbox to confirm SPF, DKIM and DMARC. Also check for `List-Unsubscribe` and `List-Unsubscribe-Post`.
5. Resolve the 20 redirect links with a follow-redirects probe, such as a `curl -IL` with a browser User-Agent. Confirm each lands on a 200 on `crocs.com` and that the promo code applies.
