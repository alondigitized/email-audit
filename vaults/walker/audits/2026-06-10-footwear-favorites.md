### 3. Rendering & Accessibility

**[HIGH] Duplicate `.bg1` class — color collision**
The stylesheet defines `.bg1` twice with conflicting values:
```css
/* definition 1 */
.bg1 { background-color: #ffffff; }

/* definition 2 — later in sheet, wins */
.bg1 { background: #58546d; }  /* dark purple */
```
Any element carrying `.bg1` will render with a dark purple background (`#58546d`), not white. If this class is used on content containers it will produce a visually broken dark band in light-mode clients.

**[MEDIUM] `<meta name="viewport">` missing `width=device-width`**
```html
<meta name="viewport" content="initial-scale=1, user-scalable=yes" />
```
Without `width=device-width`, iOS Mail and some Android clients will default to a desktop-width viewport and then scale down, degrading mobile layout. Correct value:
```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

**[MEDIUM] Malformed IE compatibility meta tag**
```html
<meta content="IE=edge" />
```
The `http-equiv="X-UA-Compatible"` attribute is missing, making this tag a no-op. Outlook desktop (which uses IE/Trident rendering) will not receive the edge-mode instruction. Fix:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```

**[LOW] `@font-face` declarations without `src`**
All nine `@font-face` blocks declare `font-family`, `font-weight`, and `font-style` but omit the `src:` property entirely. These are non-functional stubs. Web fonts (`proxima-nova`, `linotype-didot`) will not load from these rules — clients will immediately fall back to `Arial`/`Times New Roman`. If the fonts are loaded via a separate `<link>` tag (not visible in truncated source), these stubs are dead code and should be removed to reduce parse overhead. If they are the sole font mechanism, this is a functional defect.

**[LOW] Dark-mode anchor override too broad**
```css
@media (prefers-color-scheme: dark) {
  a { color: #cf0a2c !important; }
}
```
This red override applies to every `<a>` in dark mode, including CTA buttons where link text is set to `#ffffff` (classes `.cta1a`, `.cta1b`, `.la2`, etc.). In dark-mode Gmail and Apple Mail the CTA label text will render red-on-dark-button rather than white-on-dark-button. Scope this rule to body-copy anchors only.

**DOCTYPE/namespace mismatch (informational)**
The document uses `HTML 4.01 Transitional` DOCTYPE alongside `xmlns="http://www.w3.org/1999/xhtml"`. This hybrid pattern is widely used in email and does not cause hard failures, but it is technically contradictory.
