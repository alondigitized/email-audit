## What's weak

- Two discounts (30% and 20%) with no clue which applies to me. I had to read the fine print.
- The fine print at the bottom is tiny, and I can't read it without zooming. The "Discount auto-applied at cart" note under each banner is small too.

- 2. Put prices and a star rating under each shoe, with "from $XX."
- 3. Use a men's walking or slip-in shoe as the hero, with a model closer to my age.
- 4. Cut the footer clutter and make the fine print bigger. A line like "Ends tomorrow" would add credible urgency, since the offer ends 11/10.
- 5. Merge "Shop Comfort" and "Shop All Comfort" into one button.

## Technical Audit

## 1. Technical Summary
The email has one confirmed broken-experience defect: an empty greeting slot (`Hi ,`). The visible source also has an unresolvable pixel URL with no scheme, two insecure (`http://`) images without alt text, and several accessibility gaps. The HTML is truncated, so footer, unsubscribe and link-level checks could not be done.

## 2. Link & Tracking Issues
- **Scheme-less tracking pixel:** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…">` has no `http(s)://` prefix. Clients will treat it as a relative path, so the request won't reach Return Path and deliverability or seed-list measurement is lost. It also has no `alt`. The automated QA did not flag this.
- **Unprobed links:** 35 tracking links on click-redirect domains (e.g. `click.emails.skechers.com`) were skipped, so link validity is unverified.
- **Third-party beacons:** Four hidden `beacon.krxd.net` 1x1 images carry a 64-hex `partner_uid` (`9153f33f…ed00`) and a numeric subscriber ID (`121173391`) in the query string. They are wrapped in `display:none` and `width/height=0` and also load over a separate `ink1000.com` pixel. This is a privacy and performance observation, not a defect.
- **Insecure pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8107766165&mi_ecmp=…` is non-HTTPS, so it may be blocked or flagged as mixed content.

## 3. Rendering & Accessibility
- **Missing alt text (QA-confirmed):**
  - `o.gif` (ink1000.com)
  - `dde00662-169f-447d-b0e2-fc65f6c2290c.png`
- **Non-HTTPS images (QA-confirmed):**
  - `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-….png` is non-HTTPS content on the brand's own image host, so it may be blocked.
  - `http://www.ink1000.com/…/o.gif` (the tracking pixel above) has the same problem.
- **Invalid charset meta:** `<meta content="text/html; charset=utf-8" />` has no `http-equiv`, so it declares nothing. `<meta content="IE=Edge" />` has the same defect.
- **Zoom disabled:** `<meta name="viewport" content="… maximum-scale=1">` blocks pinch-zoom (WCAG 1.4.4).
- **Focus outline removed:** `a { outline: none; }` removes the keyboard focus indicator.
- **Text resize disabled:** `* { -webkit-text-size-adjust: none; }` disables iOS text scaling.
- **No document language:** `<html xmlns="…">` has no `lang` attribute.
- **Layout tables lack roles:** Tables such as `<table cellpadding="0" cellspacing="0" border="0">` have no `role="presentation"`.

## 4. Personalization & Merge Tokens
- **Empty greeting slot (QA FAIL):** The greeting renders as `Hi ,`, so the first-name field resolved to an empty string. The template has no fallback value, such as `%%=IIF(Empty(@firstname),"there",@firstname)=%%` in SFMC syntax. This affects every recipient with a null first name.
- No other unresolved tokens were found in the visible source.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication-Results not found (QA WARN):** This is attributed to the AgentMail relay, so SPF/DKIM/DMARC status for `no-reply@emails.skechers.com` is unverified. It does not indicate a sender-side defect.
- The unsubscribe link, physical postal address, and `List-Unsubscribe` / `List-Unsubscribe-Post` headers are not in the truncated source or QA data, so they could not be assessed.
- The From address is `no-reply@`, which is a reply-ability concern but not a CAN-SPAM violation.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- Click destinations are wrapped by the ESP and were not resolved, so UTM parameters and landing-page alignment could not be verified.
- The campaign ID `MKG_US_NA_U_COMF_ENGAGEDL30D_EN_11092026` appears in the beacon URLs and the `ink1000.com` pixel (`mi_ecmp=`), so campaign naming is consistent across trackers.
- The preheader promises "30% off select styles", and the landing pages were not checked against it.

## 7. Recommendations
1. **Fix the greeting fallback.** Add a default (e.g. "there") for an empty first name, or suppress the greeting.
2. **Fix the Return Path pixel.** Change it to `https://pixel.app.returnpath.net/pixel.gif?r=…` and add `alt=""`.
3. **Serve all images over HTTPS.** Change `image.emails.skechers.com/lib/…/dde00662-….png` and `ink1000.com/…/o.gif` to `https://`.
4. **Add alt text** to the content image `dde00662-….png`. Use `alt=""` on the tracking pixels.
5. **Correct the head meta tags.** Use `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
6. **Remove `maximum-scale=1` and `outline:none`,** and add `lang="en"` to `<html>`. Add `role="presentation"` to the layout tables.
7. **Re-run the audit on the full HTML and raw headers.** Check the unsubscribe link, postal address, `List-Unsubscribe`, SPF/DKIM/DMARC, and resolved click-through UTMs and landing pages.
