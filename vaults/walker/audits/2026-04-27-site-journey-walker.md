## 3. What's Working

**Men's category menu is genuinely good.** Large text, full-width tap targets, clean list. "Hands Free Slip-ins" is right there at the bottom of the Men's menu without needing to drill into a sub-category. "Comfort Technologies" is also visible. If I know to tap MENU, I can get where I'm going in two taps. That's the best part of this whole journey.

**Product detail page is solid.** The GO RUN Glide-Step Arch Fit page had clear, large text — "MEN'S" label, $120.00 price, star rating (17 reviews, roughly 4 stars), and the "Buy 1, Get 1 50% OFF" callout in red right under the price. The Slip-ins badge on the shoe image is a nice trust signal. I could read all of this without squinting.

**BOGO 50% OFF is prominent throughout.** The blue banner at the very top never goes away. As a price-conscious guy, I noticed it every screen. That's the right call.

**Size/width validation works.** When I tried to add to cart without picking a size and width, it flagged both errors in red immediately. I knew exactly what I missed. The ADD TO CART button at the bottom is large and blue — hard to miss.

**274 results on the Slip-ins page is confidence-building.** There's a lot to choose from. The fit filter buttons (Wide Fit, Extra Wide Fit, Medium Fit) are right at the top of the listing — good for someone like me who cares about fit.

## 4. What's Weak

**The cart is completely blank.** Step 8 was a white screen. Nothing loaded. No items, no total, no checkout button. I have no idea if my shoe even made it into the cart. This is not a UX problem — this is a broken page. A 62-year-old who hits a white screen after spending five minutes picking a shoe is not coming back to try again. He's calling the 1-800 number or giving up entirely.

**Homepage doesn't know I exist.** It's the Mother's Day Shop. Full screen. Pink flowers, women, children. I am a Skechers Plus member who buys men's Slip-ins. Nothing on that homepage is for me. There's no "Welcome back, Walker" — no "Shop Men's," no Slip-ins call-out, no loyalty points banner. I have to find MENU myself and navigate from scratch like a first-time visitor.

**Login step is invisible.** Step 3 was supposed to show me logging in, but the screenshot looks identical to the homepage. I can't tell if I was logged in at any point during this journey. The account icon in the header gives no visual cue — no name, no "Hi Walker," no member badge. If I'm supposed to feel like a valued Plus member, there's no evidence the site recognized me at all.

**Search leads with women's shoes.** I searched "slip in" — 1,030 results, which is fine — but the first two products I see are "BOBS Skip Cute - Keep It Sweet (Women's)" and "Arch Fit 2.0 - Easy Chic (Women's)." Both. Women's. I'm a man searching for slip-ins. The site knows nothing about me. A simple gender signal from my logged-in account should filter or at minimum surface men's styles first.

**Popup dismissal wasn't visible.** Step 2 was supposed to show a dismissed popup, but the screen looks nearly identical to Step 1 — just a slightly different secondary banner text ("Get Mom a Gift She'll Love" vs. "Spring Apparel Sale"). ## Technical Audit

## Technical Summary

Salesforce Commerce Cloud (Demandware) stack. Eight steps audited across homepage, auth, category, PDP, cart, and search. Primary technical concerns: bot-protection SDK rate-limiting legitimate cart requests (direct revenue impact), a broken third-party widget due to misconfigured CORS, duplicate script injection, and a cart page that ships with no `<title>` or `<html lang>`.

---

## Accessibility

**16 axe violations across 3 pages.**

**Critical**
- `aria-required-parent` (Homepage): ARIA role used outside its required parent container — screen reader tree is malformed.

**Serious**
- `link-name` (Homepage): One or more `<a>` elements have no discernible text. Likely icon-only links with no `aria-label`.
- `document-title` (View Cart): `<title>` element is empty or missing. The cart is either CSR-rendered and the title is never injected, or the template has a bug.
- `html-has-lang` (View Cart): `<html>` element has no `lang` attribute on the cart page. Every other page has `lang="en"`.

**Moderate (8)**
- Duplicate `<main>` landmark (Homepage), `<main>` inside a non-top-level container (Homepage), missing `<main>` landmark (View Cart), heading order violations (Homepage), content outside landmarks (Homepage, Search), duplicate/nested `<aside>` (Homepage, Search), duplicate landmark roles (Homepage, Search).

The View Cart `lang` + `title` gap is consistent with a client-side-rendered shell that never receives server-provided metadata — if this page is SPAed while others are SSR'd, that's the likely root cause.

---

## SEO

- **Missing `<title>` on View Cart** — cart is typically noindexed but this indicates a metadata pipeline gap that may affect other dynamic pages.
- **Missing `lang` on View Cart** — search engines use this for language targeting.
- **Heading order violations on Homepage** — headings are not semantically sequential, which weakens content hierarchy signals.
- No canonical, structured data, or hreflang issues are visible from the truncated HTML, but the script-heavy `<head>` delays parser reaching metadata tags.

## Mobile Optimization

- `--vh` custom property is set correctly (iOS Safari 100vh fix is present), but the JS approach adds a layout recalculation on resize.
- No `<meta viewport>` visible in the truncated HTML samples — not confirmed absent, but worth verifying it includes `width=device-width, initial-scale=1` without `user-scalable=no` (the latter is an accessibility violation on its own).
- Duplicate script injections will trigger duplicate network requests on mobile where bandwidth matters most.

## Console & Network Errors

**429 rate limiting — Kasada KP SDK (5 occurrences)**

```
https://www.skechers.com/149e9513-01fa-4fb0-aad4-566afd725d1b/
  2d206a39-8ed7-437e-a3be-862e0f06eea3/fp?x-kpsdk-v=j-1.2.381
```

This is the [Kasada](https://www.kasada.io/) bot-protection fingerprinting endpoint. The SDK is rate-limiting its own challenge calls. This means the Kasada integration is either misconfigured (challenge rate set too aggressively) or the client is generating challenge volume that the server-side policy rejects. This is not benign noise — Kasada failures degrade session integrity checks.

**429 on `/cart/` (1 occurrence)**

The cart page itself returned 429. Combined with the 171 ms TTFB spike on View Cart, this suggests Kasada is blocking or throttling the actual cart load for sessions that failed the fingerprint challenges above. **This is a direct checkout funnel break** — users caught in the Kasada retry loop cannot load their cart.

**CORS block — Stylitics**

```
Access to CSS at 'https://web-assets.stylitics.com/style.css?...'
from 'https://www.skechers.com' blocked by CORS policy:
No 'Access-Control-Allow-Origin' header present
```

The Stylitics outfit/hotspot widget CSS is blocked. The Stylitics server is not returning the correct CORS header for this origin. The widget is non-functional on these pages. Fix is on Stylitics's side (add `skechers.com` to their allowed origins) or on Skechers's side (proxy the stylesheet through their own CDN).

**net::ERR_FAILED (1 occurrence)**

One resource load failed entirely. Without the URL this can't be attributed, but it likely corresponds to the CORS-blocked Stylitics request above.

## Recommendations

**P0 — Checkout breaking**
1. Investigate Kasada configuration: the fingerprint endpoint is rate-limiting legitimate browser sessions, causing `/cart/` to 429. Either the challenge policy is too strict, or the SDK version (`j-1.2.381`) has a retry bug. Coordinate with Kasada support.

**P1 — Broken widget**
2. Fix Stylitics CORS: confirm `www.skechers.com` is in Stylitics's `Access-Control-Allow-Origin` allowlist for `web-assets.stylitics.com`. If Stylitics can't fix promptly, proxy `style.css` through Skechers's own CDN.

**P1 — Accessibility / SEO**
3. View Cart page is missing `<title>` and `html[lang]` — if this is a CSR shell, ensure the framework injects these on hydration. If SSR, the template is broken.
4. Fix `aria-required-parent` and `link-name` violations on Homepage — both are screen-reader-breaking.

**P2 — Script hygiene**
5. Remove duplicate script injections (`tags.creativecdn.com` × 2 on Men category, `ytc.js` × 2 on Homepage/Login) — likely a tag manager misconfiguration.
6. Upgrade `//se.monetate.net` protocol-relative URL to `https://`.
7. Audit total third-party script count (15+) — consider tag manager consolidation or a facade/lazy-load pattern for below-fold pixels.

**P3 — Measurement gaps**
8. LCP and CLS were not captured for any step — instrument these via `PerformanceObserver` or a RUM provider to get full Core Web Vitals coverage before any performance optimization work.
