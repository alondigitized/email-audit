# Your 15% OFF is waiting.
**Score:** 5/10 · **Type:** Email audit · **2026-04-16**
## Executive summary

- Functional but low-efficiency. The offer is there; the urgency and specificity are not.

## What's working

- **Offer clarity:** "15% OFF" in large type is immediately legible. The pink-on-white treatment gives it prominence.
- **Lifestyle image triptych:** Three distinct panels (women's, men's, kids') with "Famous for…" headlines efficiently cover the family breadth and inject personality.
- **Clean layout:** Single-column structure is mobile-friendly and easy to scan.
- **Rewards section present:** Including Famously YOU at all is better than ignoring loyalty members.

## What's weak

- **Hero is offer-only, not offer + product:** The 15% hero has no imagery — no shoe, no foot, no lifestyle shot. It's a coupon, not a brand moment. Wasted real estate.
- **"Easy Way to Say Thanks" headline is weak:** Vague gratitude copy without context. Thanks for what? The recipient has no frame of reference.
- **No urgency signal:** No expiration date is visible in the hero or CTA area. "Is waiting" in the subject implies something pending, but the email never closes the loop with a deadline.
- **Multiple CTAs dilute focus:** "SHOP NOW," "SHOP WOMEN," "SHOP MEN," "SHOP KIDS" — at least four CTAs appear before the fold. No primary action is prioritized.
- **Rewards section is tiny and low-contrast:** The Famously YOU module appears near the bottom with small type and low visual weight. For a loyalty-driving email, this is a missed opportunity.
- **No personalization visible:** No name, no reward balance, no recently browsed styles. Feels batch-and-blast.

## Recommendations

- 1. **Add a hero image.** One strong lifestyle or product image directly under the 15% headline would increase engagement. Even a shoe silhouette would help.
- 2. **Add an expiration date in the hero.** "Offer expires Sunday" or a countdown creates urgency that the subject line promises but the body doesn't deliver.
- 3. **Reduce CTAs to one primary action above the fold.** Let the category split (women/men/kids) live further down.
- 4. **Promote the rewards module.** If the recipient has a balance, show it ("You have 320 points — use them now"). This is the highest-value personalization lever available.
- 5. **Anchor the offer to a reason.** "Easy Way to Say Thanks" is too vague. Tie it to a milestone, season, or category ("Spring styles just landed — here's 15% off").

### 3. Rendering & Accessibility

**[HIGH] Unclosed nested `@media` blocks**
In the third `<style>` block, media queries are opened without closing braces before the next query begins:
```css
@media screen and (max-width: 414px) { .padl10m { padding-left: 0px; }
@media screen and (max-width: 412px) { .padl10m { padding-left: 0px; }
@media screen and (max-width: 405px) { ...
```
CSS parsers will treat each subsequent query as nested inside the prior one — invalid CSS. Rules targeting 412px and 405px will fail to apply in compliant parsers (all major clients except Outlook's Word renderer, which ignores `@media` entirely).

**[MEDIUM] Missing `http-equiv` on charset meta**
```html
<meta content="text/html; charset=utf-8" />
```
Correct form: `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />`. Without `http-equiv`, Outlook desktop may not honor the charset declaration, risking character encoding fallback.

**[MEDIUM] Duplicate `<meta name="viewport">` tags**
Two viewport declarations present:
```html
<meta content="width=device-width; initial-scale=1.0; maximum-scale=1.0;" name="viewport" />
<meta name="viewport" content="width=device-width" />
```
- The first uses semicolons as separators (non-standard; should be commas). `initial-scale` and `maximum-scale` may be silently dropped.
- The second tag overrides the first in compliant parsers, discarding scale constraints.
- Keep one: `<meta name="viewport" content="width=device-width, initial-scale=1.0" />`.

**[MEDIUM] `-webkit-text-size-adjust: none`**
```css
-webkit-text-size-adjust: none;
-ms-text-size-adjust: none;
```
`none` blocks all user-initiated text scaling — violates WCAG 1.4.4 (Resize Text, AA). Should be `100%`.

**[LOW] Incorrect XHTML namespace URI**
```html
<html xmlns="https://www.w3.org/1999/xhtml">
```
Canonical namespace is `http://` (no TLS). Most parsers silently accept `https://`, but it is technically non-conformant and may cause strict XML validators to reject the document.

**[LOW] Non-standard `supported-color-schemes` CSS property**
```css
:root { color-scheme: light dark; supported-color-schemes: light dark; }
```
`supported-color-schemes` is not a valid CSS property. The correct mechanism is the already-present `<meta name="supported-color-schemes">` in `<head>`. The `:root` declaration is a no-op and should be removed to avoid confusion.
