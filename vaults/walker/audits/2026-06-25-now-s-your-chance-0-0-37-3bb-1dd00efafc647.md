# Now's your chance
**Score:** 7/10 · **Type:** Email audit · **2026-06-20**
## Executive summary

- "Now's your chance" hit my inbox and I stopped cold. Because this is the exact same subject line New Balance used back on June 11th — and that email was about kids' shoes. So my first thought, before I even opened it, was *here we go again*. But the preview this time says "Top styles on sale now" instead of "Top kids' styles," so I cracked it open.
- Once I'm inside, the email is cleaner than some of the recent ones. There's a real sale — 25% off with a code, good through Wednesday. That's something I can use. The product grid shows six shoe models, a couple of CTAs for men and women, and eventually a section at the bottom that spells out the promo. My problem is that everything on that product grid is retro lifestyle runners — the 530, the 9060, the 574, the 740. These are sneakerhead shoes, not shoes built for a guy like me who needs cushioning and real arch support. I want to know what's on sale in the comfort walking line, and that's nowhere in this email.
- I'd mark it read. I wouldn't click, and I definitely wouldn't forward it. The sale is real but the shoes they're putting front and center aren't mine.

## What's working

- **Promo code is right there** — SUMMER26 is printed in the email with a visible deadline ("through Wednesday"), no hunting required.
- **"Shop men" button is the first CTA** — they finally split the men/women CTAs instead of burying me in a unisex landing page.
- **No broken images or layout chaos** — the whole thing renders clean, good spacing, readable even on my phone screen.
- **Summer urgency is credible** — SUMMER26 + Wednesday cutoff actually creates a real deadline, not vague FOMO.

## What's weak

- **Recycled subject line is a trust problem** — "Now's your chance" ran June 11th for kids' shoes. Using it again this month feels lazy and makes me wonder what I'm walking into before I open.
- **Six products, zero comfort messaging** — the entire grid is heritage runners (530, 9060, 574). Not a word about cushioning, arch support, or Fresh Foam. They're selling style, not fit.
- **Hero shot skews young** — the legs in that hero image are wearing a slim pant and a fashion sneaker. That's not me. That's somebody's grandson.
- **25% off what, exactly?** — "top styles" and "select shoes" don't tell me if the walking shoes I'd actually buy are included or if it's just the fashion runners in that grid.

## Recommendations

- 1. **Feature at least one genuine comfort/walking model in the product grid** — even one Fresh Foam or 990V with a callout like "built for all-day wear" would've earned a click from me.
- 2. **The hero copy should lead with the offer, not a vague headline** — "Up to 25% off through Wednesday" in big type above the fold beats "Now's your chance" every day of the week.
- 3. **Retire this subject line** — you used it in June already and it flopped on a different audience. New send, new subject.
- 4. **Call out specifically which categories are in the sale** — "shoes and apparel" isn't enough. Tell me if walking shoes are included.

### 2. Link & Tracking Issues

This is plaintext HTTP — modern clients (Gmail, iOS Mail) will block or warn on mixed-content. Also, `XXXXX` is an unresolved template placeholder; this background image will 404 in production.

### 3. Rendering & Accessibility

**Duplicate `.bg1` class with conflicting values**
```css
/* defined at line ~6 */
.bg1 { background-color: #ffffff; }

/* redefined ~100 lines later */
.bg1 { background-color: #58546d; }
```
The second definition wins everywhere `.bg1` is applied. Whichever is intentional, the other is dead code that indicates a template merge error.

**Empty `@font-face` declarations — no `src:` property**

All nine `@font-face` blocks (proxima-nova, linotype-didot, proxima-nova-condensed, ITC Garamond) declare `font-family` and `font-weight` but contain no `src:` URL. Custom fonts will not load in any client; the fallback stack (Arial, Times New Roman) will render instead. This is silent — no error is thrown.

**Malformed `@font-face` for proxima-nova 700 italic**
```css
@font-face {
  font-family: proxima-nova,sans-serif;
  font-weight: 700;
  font-style: italic;font-family: proxima-nova,sans-serif;  /* duplicate property */
}
```
The duplicate `font-family` property after `font-style` is a copy-paste error. Parsers ignore the second occurrence but it signals the block was hand-edited incorrectly.

**`<meta>` tag missing `http-equiv` attribute**
```html
<meta content="IE=edge" />
```
Should be:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without `http-equiv`, this tag is parsed as a generic metadata element and the IE rendering hint is not applied.

**Single responsive breakpoint at 414px only**
```css
@media only screen and (max-width:414px) { ... }
```
No coverage for 375px (iPhone SE/14 mini), 390px (iPhone 14/15), or 430px (iPhone 14/15 Pro Max). Images in `.image1` will be the only fluid element; table-based layout outside that selector won't reflow on most current-generation iPhones.

**Dark mode rule truncated in source**
```css
@media (prefers-color-scheme: dark) {
  body { background:#151415 !important; }
  a { color:#cf0a2c !important; }
  .bg1…   ← truncated
```
Cannot confirm the dark mode block is properly closed. An unclosed `@media` block will cause all subsequent CSS to be interpreted as dark-mode-only and break light-mode rendering in clients that parse the full stylesheet (Apple Mail, Outlook iOS).

**Legacy DOCTYPE**
```html
<!DOCTYPE html PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" ...>
```
Gmail strips the DOCTYPE entirely; most other clients treat it as HTML5. Not a rendering blocker, but signals the template predates modern email standards and should be migrated to `<!DOCTYPE html>`.
