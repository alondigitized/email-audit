- "hurryyyy" in the preheader looks sloppy, not urgent

### 3. Rendering & Accessibility

**`Src:` capitalization in all `@font-face` blocks — High**
CSS property names are case-sensitive per spec. All 10 `@font-face` declarations use `Src:` (capital S) instead of `src:`. Strict CSS parsers in some email clients will silently drop these rules, falling back to system fonts.

```css
/* All 10 @font-face blocks: */
Src: url("https://braze-images.com/...") format('woff');
/* Should be: */
src: url("https://braze-images.com/...") format('woff');
```

**Missing `http-equiv` on meta tags — Medium**
Two meta tags are missing required `http-equiv` attributes:
```html
<!-- Broken: -->
<meta content="text/html; charset=utf-8" />
<meta content="IE=Edge" />
<!-- Should be: -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```
Without `http-equiv`, these tags are inert. The charset declaration in particular may cause rendering issues in older Outlook versions.

**`maximum-scale=1` blocks user zoom — Medium**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Locking zoom violates WCAG 1.4.4 (Resize Text, Level AA). Users who need to enlarge text cannot do so.

**Font format gaps — Low**
- Futura PT: only `.woff` provided, no `.woff2`. Modern clients prefer `.woff2` (smaller, faster).
- HelveticaNow: only `.ttf` provided — no `.woff` or `.woff2`. TTF is the least compressed format and will load slower on mobile.
