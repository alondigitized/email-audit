# So many deals 💰 So little time ⏱️
**Score:** 5/10 · **Type:** Email audit · **2026-08-05**
## Executive summary

- Same BOGO banner, same purple trim, same "2X points" — I've seen this exact top block from Famous Footwear at least five times this summer now. What's different this time is the big grid underneath: Nike, Jordan, adidas, Crocs, DUDE, Birkenstock, Brooks all lined up with their own percent-off stickers. Brooks catches my eye — that's a real comfort-walking brand I actually cross-shop — but it's buried as one tile among nine, competing with Jordan kicks and kids' Crocs.
- Problem is, the whole email pivots hard into "back-to-school" territory after the BOGO band — teacher discounts, "get fitted" with a kid model, family lookbook with children front and center. None of that is for me. I'm not buying school shoes for anybody.
- I'd scroll past this one. The Brooks tile might get a tap if I were already in a browsing mood, but the subject line gave me nothing new and the body is 80% back-to-school noise. Not forwarding it, not marking it as a must-open next time either.

## What's working

- The BOGO ½ off banner is still easy to read at a glance, same as every other Famous Footwear send this month.
- Brooks shows up by name with "up to 25% off" — that's a brand I actually track against Hoka and New Balance.
- Birkenstock gets its own tile again, and that brand has pulled me in before (their sandal email got an 8/10 from me back on 7/20).
- No layout bugs — everything rendered clean, images loaded, nothing overlapping.

## What's weak

- The whole email is dressed up for back-to-school — teacher discounts, a kid getting "fitted" in store, a family lookbook. None of that applies to me.
- My category (men's comfort walking shoes) gets one small tile out of nine — same real estate as kids' socks and Jordan sneakers.
- Subject "So many deals, so little time" is the same vague grab-bag framing I've flagged before — no product, no number, no reason to open over the last four nearly-identical sends.
- The preview text is just a raw tracking link, not real copy — that's a miss I haven't seen from them before.

## Recommendations

- 1. Segment this — if they know I've never clicked anything school- or kid-related, drop me into a men's-comfort version of this same layout with Brooks, Hoka-style rivals, and New Balance up top instead of the back-to-school grid.
- 2. Fix the preview text — it's leaking a raw click-tracking URL instead of actual preheader copy. That's a quick template fix.
- 3. Give Brooks its own moment instead of a shared tile — a shoe like the Defiance Max with arch support is exactly my kind of purchase, but it's easy to scroll right past here.
- 4. Vary the subject line format — five sends this month have all been "look, deals!" with an emoji. Try leading with an actual brand or product name like the Birkenstock send that worked.

# Technical Email Audit — Famous Footwear "So many deals" Campaign

## 1. Technical Summary
Standard SFMC-style promotional email (table-based HTML 4.01 layout, Outlook/ExternalClass resets, responsive breakpoints at 480px/640px). Automated QA reports 100% pass / 0 errors / 0 warnings at the check level, but flags 30 images with missing/empty alt text and skips validation of 46 click-tracking links by design.

## 2. Link & Tracking Issues
- Open tracking pixel present: `https://click.email.famousfootwear.com/open.aspx?...&d=70253&bmt=0` (1×1, standard SFMC open-tracking format).
- All CTAs route through the SFMC click-tracking redirector `click.email.famousfootwear.com/?qs=...` (e.g., the header logo and "Want Free Shipping?" links). Destination URLs are opaque base64/encoded tokens, not plaintext.
- QA explicitly skipped HTTP probing of all 46 tracking links ("Tracking/click-redirect domains — skipped HTTP probe"), so live-destination/404 validation was **not** performed by either the QA pass or this review.
- The provided HTML source is truncated mid-attribute on the second CTA link (`qs=ABB7...LM7…`), so a full link inventory/dedup check isn't possible from this excerpt.

## 3. Rendering & Accessibility
- Viewport meta sets `maximum-scale=1, user-scalable=0`, which disables pinch-to-zoom — fails WCAG 1.4.4 (Resize Text). Evidence: `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=0" />`.
- QA flags 30 images missing alt text across the message. Confirmed in source for two of them:
  - Logo image (`3b6a7dc1...png`) has `alt=""` while wrapped in an `<a href>` — the link has no accessible name for screen readers/assistive tech.
  - Divider image (`4ccff4ad...jpg`, 2px tall spacer) has `alt=""` — acceptable use of empty alt for a purely decorative element, not a real defect.
  - The remaining 28 flagged images fall outside the truncated excerpt, so their alt values can't be independently verified here; treat QA's finding as authoritative for those.
- Layout uses standard table-based structure with `ReadMsgBody`/`.ExternalClass` resets for Outlook/webmail compatibility and media queries at 480px/640px with mobile-specific class overrides (`.container`, `.responsive-td`, `.fluid`) — no rendering defects observed in the visible markup.

## 4. Personalization & Merge Tokens
No issues found. No AMPscript (`%%...%%`), merge fields, or dynamic content blocks are present in the visible source excerpt.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
Cannot be assessed — the provided HTML is truncated before the footer, so the unsubscribe link and physical mailing address (required by CAN-SPAM) are not present in this excerpt. Raw email headers (SPF/DKIM/DMARC results) were not included in the provided data. Do not treat this as "pass"; it's an evidence gap.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Cannot be assessed — all outbound links are wrapped in the SFMC click-tracking redirector, which obscures the final destination URL and any UTM parameters. QA intentionally skipped probing these links, so landing-page alignment was not verified.

## 7. Recommendations
1. Add descriptive alt text to the 30 flagged content images (product/promo imagery) — currently inaccessible to screen readers and unhelpful when images are blocked by default in most mail clients.
2. Add an accessible alt value to the header logo image since it's the sole content of a link (`<a href>...<img alt="">`).
3. Drop `maximum-scale=1, user-scalable=0` from the viewport meta tag to restore pinch-zoom for accessibility.
4. Supply the full HTML (through the footer) to verify unsubscribe link and CAN-SPAM-required physical address.
5. Supply raw email headers to verify SPF/DKIM/DMARC authentication.
6. Resolve/unwrap a sample of the 46 click-tracking redirect links to confirm final destination URLs carry correct UTM parameters and resolve to live, matching landing pages.
