## Technical Audit

## 1. Technical Summary
The email is structurally sound for a table-based, responsive layout, but it has no plain-text alternative, an `http://` tracking image with no alt text, and two head-level defects (an ineffective charset declaration and an incomplete viewport meta). The HTML is truncated and the 16 tracking links were not probed, so links, headers and UTMs could not be checked.

## 2. Link & Tracking Issues
- **Unverified links:** QA skipped the HTTP probe on all 16 tracking links because they use click-redirect domains (`click.comms.adidas.com`). Destination status, redirect chains and expiry are unconfirmed.
- **Insecure tracking asset:** `http://click.comms.adidas.com/CI0/010201a1295981b3-308b682f-0d83-4af2-a5e0-b489c94df6a8-000000/jt6D3wpIqtDUI75zRvt7uyEZ9h1dTwMqqajDG2C8DDA=452` is loaded as an image over plain HTTP.
  - Clients that block mixed or insecure content may drop it.
  - If it is the open-tracking pixel, open counts will be under-reported.
  - I can't confirm from the truncated source that it is a pixel.

## 3. Rendering & Accessibility
- **Missing alt text (QA, 2 images):**
  - `https://dv.adidas.com/o/8c3ca7a7-fe71-43f3-bb4d-51e02dec7f3d?cp_tp=...`
  - The `click.comms.adidas.com/CI0/...=452` image above.
  - If the first is a content image, its message disappears with images off. If the second is a pixel, `alt=""` is the correct fix.
- **Charset declaration:** `<meta content="text/html; charset=UTF-8" />` has no `http-equiv="Content-Type"` or `charset` attribute, so it doesn't declare the encoding. This only matters if the MIME `Content-Type` header lacks a charset.
- **Viewport:** `<meta name="viewport" content="initial-scale=1.0" />` omits `width=device-width`. The responsive rules are `@media ... max-width:639px/640px`, so some mobile clients may not apply them as intended.
- **Legacy doctype:** The doctype is HTML 4.01 Transitional while the markup uses self-closing `<meta ... />`. This is harmless in email clients, but it is inconsistent.
- **Web fonts:** Every `@font-face` for `AdihausDIN` and `AdineuePRO` uses only `src: local('Arial'), local('Helvetica'), ...`. No remote font file is loaded, so the intended brand fonts never render and all clients fall back to system fonts.
- **Redundant CSS:** The `@font-face` and `@media` rules are declared twice in separate `<style>` blocks, which adds weight. I can't check Gmail's ~102KB clipping limit from the truncated source.
- **Positives:** `<html lang="en">` is present, and `x-apple-disable-message-reformatting` and `format-detection` are set.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens such as `{{ }}`, `%%`, or `[FIRST_NAME]` appear in the visible source. The rest of the body was truncated.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **No plain-text part (QA FAIL):** "Text version is 0 chars". This is the only scored failure. It hurts deliverability, since many spam filters penalize HTML-only mail. It also affects accessibility and clients that render text only.
- **Not verifiable:** The unsubscribe link, the physical postal address, `List-Unsubscribe` / `List-Unsubscribe-Post` and SPF/DKIM/DMARC results are not in the supplied data. The From domain `us-news.comms.adidas.com` and the tracking domain `click.comms.adidas.com` share the `comms.adidas.com` parent, which is good for alignment.
- **Referrer meta:** `<meta name="referrer" content="no-referrer" />` and `ROBOTS NOINDEX, NOFOLLOW` are present. They are not compliance problems, but the referrer meta is ignored by most email clients.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not assessable. All CTAs are wrapped in `click.comms.adidas.com` redirects, and QA skipped them. The final landing URLs and any UTM parameters weren't resolved, so I can't confirm campaign tagging or landing-page alignment.

## 7. Recommendations
1. **Add a multipart/alternative `text/plain` part.** It should include the CTAs and the unsubscribe link. This is the only QA FAIL.
2. **Add `alt` text.**
   - Use descriptive text for the `dv.adidas.com/o/8c3ca7a7-...` image.
   - Use `alt=""` for the tracking pixel, with `width="1" height="1"` if it is one.
3. **Serve the tracking image over HTTPS.** Change `http://click.comms.adidas.com/CI0/...` to `https://`.
4. **Fix the head meta tags.**
   - Use `<meta http-equiv="Content-Type" content="text/html; charset=UTF-8">`.
   - Use `<meta name="viewport" content="width=device-width, initial-scale=1.0">`.
5. **Fix the font stack.** Either point `@font-face` at hosted font files or drop the no-op `local()`-only declarations. Remove the duplicate `<style>` block.
6. **Re-run the audit with full data.** Include the complete HTML, the raw headers and a resolved-redirect pass on the 16 links. That would let us confirm unsubscribe, authentication, `List-Unsubscribe`, UTMs and the clipping size.
