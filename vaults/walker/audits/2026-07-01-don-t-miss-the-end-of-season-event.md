# Don’t miss the end of season event
**Score:** 6/10 · **Type:** Email audit · **2026-07-01**
## Executive summary

- New Balance showed up in my inbox again — seventh time in about two weeks by my count — and this time they're waving "end of season event" at me. I'll be honest: I almost didn't open it. Not because the subject was bad (the "don't miss it" framing does its job), but because my inbox is starting to feel like a clearance rack notification service. I'm a New Balance customer. I own their 990s. But even loyal customers have a fatigue point.
- When I actually open it, there's that same tower of red shoeboxes. I saw this exact image in the June 24 email advertising 25% off. Now it's July 1, the discount ticked up to 30%, and the boxes haven't moved. It's like they photographed the display room once and just swap out the number underneath. The hero copy says "Don't miss out." which is fine, the Shop Now button is there, but nothing in this email is pointing me toward a specific shoe that would actually work for my feet.
- I'd mark this as read. I wouldn't click the main CTA, and I wouldn't forward it to a friend. The only thing that might pull me into a tap is the 990v6s Slip Resistant sitting in the product grid at the bottom — but that's despite the email, not because of it.

## What's working

- **The 30% offer is visible immediately** — the top banner and hero copy both put the discount front and center without any hunting.
- **Preview text does its job** — "Up to 30% off select styles" adds the specific discount the vague subject line left out; that pairing is solid inbox strategy.
- **"More to explore" product grid is real** — I can see the 990v6s Slip Resistant, Fresh Foam Arishi, 2002 Lace — names I recognize. Having actual product names visible beats a pure brand-image email.
- **Subject stays under 50 characters** — 35 chars, reads cleanly on my phone without truncation.

## What's weak

- **Same red shoebox tower from June 24.** I saw this image a week ago when the sale was "almost over." Now it's back with a different number underneath. Recycling creative tells me the brand is on autopilot, not running a real curated event.
- **"Shop the sale" tiles are broken or empty.** The Men / Women / Kids tiles in the middle section are solid gray boxes with no imagery — just text labels on a grey background. Whether that's a render failure or a design choice, it reads as broken and erodes trust mid-scroll.
- **No comfort, cushion, or walking angle anywhere.** Nothing in this email tells me these shoes are built for someone with feet like mine. The 990v6s Slip Resistant is right there in the product grid, and they still didn't build the story around it.
- **No hard deadline.** The fine print cites an effective date of June 28 but never says when the sale ends. "End of season" is too vague — I want to know if I have 24 hours or two weeks.
- **Seven emails in two weeks.** The June 24 email told me the sale was "almost over." June 26 followed up. Now it's July 1 and the same event is still running. That cadence reads as noise, not urgency.

## Recommendations

- 1. **New hero image — specifically a shoe, not a shoebox.** Lead with the 990v6s Slip Resistant on a guy roughly my age walking somewhere real. That photo would stop my thumb. The red box stack tells me nothing about comfort.
- 2. **Put a hard deadline in the email body.** "Ends Sunday July 6 at midnight" is more compelling than "end of season." Vague urgency is no urgency.
- 3. **One line of comfort copy in the hero.** Something like "Built for all-day comfort. 30% off through Sunday." would do more work than "There's still time to shop the end of season event."
- 4. **Fix the "Shop the sale" image tiles.** Gray boxes with text labels are worse than no images at all. If images won't render, replace the section with a text-based divider row rather than leaving blank rectangles.
- 5. **Throttle the send cadence.** At seven emails in two weeks, even good offers start looking like spam. Space these out or vary the creative so each send feels like a distinct reason to re-engage.

- **Preheader Alt A:** `Slip-resistant 990s, Fresh Foam cushioning — on sale now through Sunday`
- **Preheader Alt B:** `Men's comfort styles from $X — final days of the season event`

### 1. Technical Summary

The email is built on a standard HTML 4.01 Transitional table layout with dark mode support wired correctly. Two confirmed infrastructure defects exist — one insecure/placeholder image URL and one malformed meta tag — and the truncated source prevents full compliance and link-tracking verification.

### 2. Link & Tracking Issues

**Confirmed issue — placeholder/broken background image URL:**
```css
.bgwhite {
  background-image: url('http://image.XXXXX.png');
}
```
- Uses `http://` (not `https://`), which will trigger mixed-content warnings in clients that render in a secure context.
- `XXXXX` is a redaction artifact or unfilled template variable. If this resolves to a live asset, it must use HTTPS. If it's a placeholder, the CSS rule should be removed before send.

**Cannot fully assess:** Link-level UTM parameters and click-tracking wrappers are not visible in the truncated source (covered in §6).

---

### 3. Rendering & Accessibility

**Confirmed issue — malformed IE compatibility meta:**
```html
<meta content="IE=edge" />
```
Missing the required `http-equiv` attribute. Correct form:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without it, the directive is silently ignored in Outlook/IE rendering engines.

**Confirmed issue — `@font-face` declarations have no `src`:**
```css
@font-face { font-family: linotype-didot,serif; font-weight: 400; font-style: normal; }
@font-face { font-family: proxima-nova,sans-serif; font-weight: 700; font-style: normal; }
/* ... (all 9 declarations) */
```
None of the `@font-face` blocks include a `src:` property. These declarations are non-functional as written — the rules register nothing. Web fonts in email are typically loaded via Adobe Fonts / Typekit `<link>` in the `<head>`; if that external `<link>` exists further in the source (truncated), these blocks are redundant noise. If there is no external font loader, fallback fonts (`Arial`, `Times New Roman`) will render throughout.

**One malformed `@font-face` block has a duplicated `font-family` property:**
```css
@font-face {
  font-family: proxima-nova,sans-serif;
  font-weight: 700;
  font-style: italic;
  font-family: proxima-nova,sans-serif;  /* duplicate — second declaration wins, first ignored */
}
```

**Dark mode:** Correctly implemented. `color-scheme` meta, `supported-color-schemes` meta, and `@media (prefers-color-scheme: dark)` override block are all present. No issues.

**Alt text:** Cannot verify from truncated source — all `<img>` tags are beyond the provided excerpt.
