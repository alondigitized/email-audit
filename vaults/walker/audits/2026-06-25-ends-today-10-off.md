# Ends today: $10 off!
**Score:** 8/10 · **Type:** Email audit · **2026-06-21**
## Executive summary

- My thumb opened this on pure DSW muscle memory — same as it has for most of the last two weeks. "Ends today: $10 off!" in the subject, and yeah, I've seen some variation of that line in what feels like every DSW email since Father's Day approached. The preview text did something a little different though — "The perfect Father's Day gift if you ask us…" — which at least made me think this one might actually be *about* me for once.
- Then the email loaded. First thing I see after the discount tiers is "SO NEW, SO YOU" with six photos of women's heels, strappy sandals, and high-heeled dress shoes. I'm a 62-year-old man. None of that is for my feet. I had to scroll past all of that before I hit the "Dad's Day Savings" section — Nike, New Balance, Crocs, Converse — which is exactly what I came for. Why is the men's Father's Day content buried *below* the women's new arrivals in an email that's explicitly marketed as a Father's Day send?
- The tiered offer (buy more, save more) is actually the most interesting structure DSW has put in front of me in a while — better than the flat "$10 off" they've been running on repeat. The "Shop Wide Width" button down near the sizes was a small but appreciated nod in my direction. But I'm not clicking "Shop More New Arrivals" on women's heels. I'd click the Dad's Day savings "Shop Now" button, though I wish they'd told me *which* New Balance shoes were on sale, not just the logo.
- **Verdict: I'd scroll to the Dad's Day section and probably click — but only because I already know the site. A stranger to DSW would've bailed at the women's shoes.**

## What's working

- The tiered BUY MORE, SAVE MORE offer at the top is the clearest and most compelling discount structure DSW has put in front of me in a while — $10/$20/$60 tiers with the HELLOSUMMER code visible right there.
- "Dad's Day Savings" naming the brands explicitly — Nike, New Balance, Crocs, Converse — is the most relevant thing in this email for me. I recognize every one of those names.
- "SHOP MEN" appears in the text links below the main offer block, which at least tells me there's a men's landing page.
- "Shop Wide Width" in the size section is a real comfort signal that DSW understands what guys like me actually need.
- No broken images, no overlapping text — the email renders clean even on a phone screen.

## What's weak

- "SO NEW, SO YOU" is six photos of women's heels and strappy sandals dropped right in the middle of an email pitched as a Father's Day deal. That section has zero relevance to me and actively makes me feel like this email wasn't meant for me.
- The size selector runs from 5 to 11 — those smaller sizes signal women's footwear even before I squint. A men's size selector should start at 7 and go up to at least 14.
- The $10 off subject line is the fourth or fifth variation of this exact same offer I've seen from DSW this month ("Oh no, $10 off ends tomorrow," "$10 off ends tomorrow!," "Helloooo, $10 off!"). The urgency word changes but the offer doesn't — and I've started to feel the diminishing returns.
- The preheader — "The perfect Father's Day gift if you ask us…" — is immediately choked by a long string of invisible-but-clearly-there spacer characters. Whatever inbox I'm using is going to show junk after that ellipsis.

## Recommendations

- 1. **Move Dad's Day Savings to the top hero slot** — above or immediately below the tiered offer, before any women's content. If you're pitching a Father's Day email to men, lead with the men's section. Burying it behind women's heels loses me before I get there.
- 2. **Name a specific shoe in the Dad's Day block** — "New Balance 608 — 25% off" or "Crocs Classic Clogs from $29" gives me something to click toward, not just a logo.
- 3. **Differentiate the offer** — the $10 off has run so many times I'm starting to tune it out. The tiered structure this email uses is actually better; lean into it with "Save up to $60 today only" instead of leading with the minimum.
- 4. **Swap the size grid for a men's-specific one** — or at minimum add a "Shop Men's Sizes" shortcut that skips straight to 8–13.
- 5. **Fix the preheader junk characters** — the spacer padding after "The perfect Father's Day gift if you ask us…" is going to show as garbage in a lot of inboxes.
- **Subject Alt A:** `Dad's Day: 25% off New Balance, Crocs & more`
- **Subject Alt B:** `Ends tonight — save up to $60 on men's brands`
- **Preheader Alt A:** `Shop men's Big-Deal Brands up to 25% off. Today only.`
- **Preheader Alt B:** `Nike, New Balance, Crocs — up to 25% off ends at midnight.`

### 3. Rendering & Accessibility

**Confirmed bugs:**

**a. `Src:` capitalization in all `@font-face` blocks (critical)**
All 10 `@font-face` declarations use `Src:` (capital S) instead of the CSS-spec `src:`. CSS property names are case-sensitive in strict parsers. This will silently fail in WebKit-based clients (Apple Mail, iOS Mail) and some Android clients — falling back to system fonts rather than Futura PT or HelveticaNow.

```css
/* BUG — all 10 @font-face blocks */
Src: url("https://braze-images.com/.../original.woff") format('woff');
/* Should be */
src: url("https://braze-images.com/.../original.woff") format('woff');
```

**b. Conflicting `-ms-text-size-adjust` in the `*` rule**
The universal reset sets both values in the same declaration block; `none` wins via cascade order:

```css
*{
  -ms-text-size-adjust: 100%;   /* set first */
  ...
  -ms-text-size-adjust: none;   /* overrides — wins */
}
```

`none` disables text scaling on IE Mobile/Windows Phone. The intent appears to be `100%` (suppress auto-inflate without disabling scaling). Low real-world impact today, but is a latent bug.

**c. Missing `http-equiv` attributes on two meta tags**

```html
<!-- BUG: no http-equiv attribute -->
<meta content="text/html; charset=utf-8" />
<!-- Should be -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />

<!-- BUG: no http-equiv attribute -->
<meta content="IE=Edge" />
<!-- Should be -->
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```

Without `http-equiv`, both tags are inert. The charset declaration is especially important for Outlook on Windows.

**d. `supported-color-schemes` as a CSS property is non-standard**

```css
:root {
  color-scheme: light dark;          /* valid */
  supported-color-schemes: light dark; /* not a real CSS property */
}
```

`supported-color-schemes` is only valid as a `<meta>` tag (which is correctly present). The CSS declaration does nothing and is noise.

**e. Near-black color values — intentional but worth documenting**
`.dm-bg-black` uses `#00000F`, `.dm-font-black` and `.border-top-black` use `#000001`. This is a known workaround to prevent Gmail dark mode from inverting true `#000000`. Intentional, but should be documented in the template's changelog so future editors don't "correct" them.

**f. Font format coverage**
Futura PT loads only `.woff`; HelveticaNow loads only `.ttf`. No `.woff2` (20–30% smaller, universally supported in modern clients). Not broken, but a bandwidth optimization opportunity.
