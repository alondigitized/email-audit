## Technical Audit — DSW Pride Month Email

---

### 1. Technical Summary

Email is built and delivered via Braze, using a table-based XHTML 1.0 Transitional layout with dark mode support. Several CSS property errors and a conflicting text-size-adjust declaration are present; font loading strategy adds unnecessary payload weight.

---

### 2. Link & Tracking Issues

- **Incomplete audit scope**: HTML source is truncated before the body — click-tracking parameters and redirect chains in body links cannot be verified.
- **Font CDN dependency**: All 10 font assets are hosted on `braze-images.com` (e.g., `https://braze-images.com/appboy/communication/assets/font_assets/files/67dd7a3bf1de1d0066403c87/original.woff`). This is Braze's shared CDN, not a custom sender domain. A CDN availability issue would cause silent fallback to system fonts with no deliverability signal.

---

### 3. Rendering & Accessibility

**Missing `http-equiv` on charset meta:**
```html
<meta content="text/html; charset=utf-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Some older Outlook and Lotus Notes clients require `http-equiv` to correctly apply the charset declaration.

**User zoom disabled (WCAG 1.4.4 violation):**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
`maximum-scale=1` prevents users from zooming — fails WCAG Success Criterion 1.4.4 (Resize Text). Remove `maximum-scale=1`.

**Capitalized `Src:` in all 10 `@font-face` blocks:**
```css
Src: url("https://braze-images.com/...") format('woff');
```
`src` must be lowercase in CSS. Webkit-based clients (older Apple Mail, some mobile) skip invalid `@font-face` rules silently, causing fallback to system fonts across all variants.

**Duplicate conflicting `-ms-text-size-adjust` in universal selector:**
```css
*{-ms-text-size-adjust: 100%; ... -ms-text-size-adjust: none;}
```
The second declaration overrides the first within the same rule block. Effective value is `none` in IE/older Edge, disabling text size adjustment entirely in those clients. Consolidate to a single declaration.

**`supported-color-schemes` in CSS `:root` is invalid:**
```css
:root {
  color-scheme: light dark;
  supported-color-schemes: light dark;  /* not a CSS property */
}
```
`supported-color-schemes` is only valid as an HTML `<meta>` tag (correctly present in `<head>`). Inside CSS it has no effect — dead code, safe to remove.

**HelveticaNow fonts loaded as TTF with cache-busting query strings:**
```
original.ttf?1755182939
```
TTF files are substantially larger than WOFF2 equivalents (typically 2–3×). Six HelveticaNow TTF files are declared, all with identical cache-busting timestamps. Convert to WOFF2 and consolidate to only weights actually used.

**Font declaration count:** 10 `@font-face` rules fire on every open (4 Futura PT + 6 HelveticaNow). If Futura PT is body copy and HelveticaNow is a newer addition (or vice versa), unused families should be removed.
