### 3. Rendering & Accessibility

**Confirmed issues:**

**a. `<meta>` tags missing `http-equiv`**
```html
<!-- As written — non-functional in strict parsers -->
<meta content="text/html; charset=utf-8" />
<meta content="IE=Edge" />

<!-- Should be -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=Edge" />
```
Without `http-equiv`, neither tag does anything. The charset declaration is redundant via MIME type but the IE compatibility directive is silently dropped, which matters for Outlook Desktop rendering.

**b. Duplicate `text-size-adjust` with conflicting values**
```css
* {
  -ms-text-size-adjust: 100%;   /* set */
  ...
  -ms-text-size-adjust: none;   /* overrides — last declaration wins in IE */
  text-size-adjust: none;
}
```
The `none` value disables text size adjustment entirely rather than normalizing it to 100%. This is a copy-paste reset error; the intent is `100%` on all three variants.

**c. `@font-face` uses non-standard capitalized `Src:` property**
```css
@font-face {
  font-family: 'Futura_PT_Regular';
  Src: url("...") format('woff');  /* capital S — non-standard */
}
```
All 10 `@font-face` blocks repeat this. CSS property names are technically case-insensitive per spec, but some email preprocessors and linters treat this as invalid and strip the block, causing web fonts to silently fail everywhere (clients that support web fonts would fall back to system fonts instead).

**d. `maximum-scale=1` in viewport**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocks user pinch-to-zoom on mobile. WCAG 1.4.4 (Resize Text, Level AA) violation. Low deliverability risk but flagged for accessibility compliance.

**e. Inconsistent font formats across font families**
- Futura PT: `.woff` only (no `.woff2`, no `.ttf` fallback)
- HelveticaNow: `.ttf` only (no `.woff` / `.woff2`)

Each `@font-face` block has a single `format()` hint with no fallback chain. Clients that support `.woff2` but not `.woff` will miss Futura entirely. In practice web font support in email is ~60% (Apple Mail, Samsung Mail); this affects quality of rendering in those clients.
