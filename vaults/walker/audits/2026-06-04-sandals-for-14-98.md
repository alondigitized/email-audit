### 3. Rendering & Accessibility

**[HIGH] Non-functional IE/Outlook compatibility meta tag**
```html
<meta content="IE=edge" />
```
Missing required `http-equiv="X-UA-Compatible"` attribute. The tag is inert as written — Outlook desktop will not receive the edge-rendering directive. Correct form:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```

**[MEDIUM] Malformed charset declaration**
```html
<meta content="text/html;" charset="utf-8" />
```
This mixes two encoding declaration patterns incorrectly. `content="text/html;"` is truncated (missing `charset=utf-8`) and the standalone `charset` attribute is HTML5 syntax. Pick one:
- HTML5: `<meta charset="utf-8" />`
- Legacy: `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />`

Most clients will tolerate this, but it is technically malformed and may behave unexpectedly in strict parsers.

**[MEDIUM] DOCTYPE / namespace mismatch**
```html
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" ...>
<html lang="en" xmlns="http://www.w3.org/1999/xhtml">
```
HTML 4.01 Transitional DOCTYPE paired with an XHTML namespace is an inconsistent document model. Email clients that parse strictly (some versions of Outlook, older Samsung Mail) may enter quirks mode or drop the namespace silently. Align to one: either drop `xmlns` for plain HTML4, or switch to XHTML 1.0 Transitional DOCTYPE.

**[LOW] Dark mode forced off — no fallback**
```html
<meta name="color-scheme" content="light" />
<meta name="supported-color-schemes" content="light" />
```
Light-only declaration means Apple Mail and Outlook dark mode clients will attempt their own color inversion on elements not explicitly handled. If images contain white backgrounds and the body background is `#FFFFFF`, forced inversion can produce dark halos around product images. No dark mode `@media (prefers-color-scheme: dark)` block is present.

**[LOW] Empty media query block**
```css
@media only screen and (max-width: 320px) {
  /* global 320 wide styles for targeting smallest iPhones */
}
```
Dead code. No declarations inside the block. Safe to remove; adds payload bytes with no benefit.

**[LOW] Redundant CSS declarations**
In the link reset rule block:
```css
color:inherit !important; color:inherit;
```
`color:inherit` appears twice (with and without `!important`). The second declaration is unreachable. Minor weight issue.

**[LOW] Four overlapping `<style>` blocks in `<head>`**
Breakpoints split across blocks at 600px, 660px, 450px, and 320px. The 600px and 660px blocks share overlapping selectors (`.responsive-text`, `.photo`, `.image`, etc.) with slightly different max-width triggers. Consolidating reduces parse overhead and eliminates potential specificity conflicts in clients that process blocks sequentially.
