### 3. Rendering & Accessibility

**Confirmed issues:**

**Empty `<title>` tag**
```html
<title></title>
```
Some email clients (Apple Mail, Outlook desktop) render the title in the tab or preview pane. An empty title is a missed fallback and can appear as a blank window title.

**Missing `http-equiv` on charset `<meta>`**
```html
<meta content="text/html; charset=utf-8" />
```
Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, some legacy Outlook and Lotus Notes clients may not parse the charset declaration.

**Duplicate `<meta name="viewport">` tags with conflicting `content`**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
<meta content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=yes" name="viewport" />
```
Two viewport declarations — the first sets `maximum-scale=1` (which implicitly disables user scaling on iOS), the second contradicts it with `user-scalable=yes`. The browser will use one and ignore the other unpredictably. Consolidate to a single tag.

**Broken CSS property values in mobile media queries**
```css
.nav_padding { padding-top:px !important; padding-bottom:px !important; }
.nav_border  { border-top:px solid ; }
```
Both rules have numeric values stripped — `px` with no number, and `border-top` with no width or color. These will be ignored by all parsers. If these classes are applied to live elements, the intended mobile spacing and divider will silently fail.

**`font-display: swap` in `@font-face`**
Not harmful, but `font-display` is not supported in any major email client and adds dead weight to the CSS block.

**Web font fallback dependency**
Custom fonts (`TheFutureHOKA`, `TheFutureHOKAMono`) load from `hoka.com/on/demandware.static/`. Gmail (web and Android), Outlook (Windows), and Samsung Mail do not render web fonts. Verify the `font-family` stacks throughout the template include a safe system font fallback (e.g., `Arial, Helvetica, sans-serif`), otherwise those clients render the browser default serif.
