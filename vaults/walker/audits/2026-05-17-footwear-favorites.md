### 2. Link & Tracking Issues

One confirmed HTTP asset reference in CSS:
```css

```
Any `http://` asset in an `https://` mail client triggers a mixed-content warning or silent block in modern clients (Gmail, Apple Mail). This background image will fail to render for a significant portion of recipients.

---

### 3. Rendering & Accessibility

**Conflicting `.bg1` class (critical render bug):**
The class is defined twice with different values:
```css
/* Declaration 1 */
.bg1 { background-color: #ffffff; }

/* Declaration 2 — overrides above */
.bg1 { background: #58546d; }
```
Any element using `.bg1` will render as `#58546d` (dark purple-grey), not white. This will visually break sections expected to have a white background.

**Malformed `@font-face` blocks — no `src:` declarations:**
All nine `@font-face` rules (proxima-nova, linotype-didot, proxima-nova-extra-condensed, etc.) are declared without `src:` URLs:
```css
@font-face { font-family: linotype-didot,serif; font-weight: 400; font-style: normal; }
```
Without a `src:`, these rules do nothing. If these are Adobe Fonts (Typekit), the embed `<script>` or `<link>` tag is absent from the visible `<head>`. All custom font rendering will silently fall back to `Arial` / `Times New Roman` / `sans-serif`.

**Duplicate property in one `@font-face` block (syntax error):**
```css
@font-face {
  font-family: proxima-nova,sans-serif;
  font-weight: 700;
  font-style: italic;
  font-family: proxima-nova,sans-serif;  /* duplicate */
}
```
The second `font-family` declaration is redundant and technically a CSS parse error.

**Malformed IE compatibility meta tag:**
```html
<meta content="IE=edge" />
```
Missing `http-equiv` attribute. Correct form:
```html
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without it, the directive is ignored by Outlook on Windows.

**Mixed doctype/namespace:**
```html
<!DOCTYPE html PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" ...>
<html xmlns="http://www.w3.org/1999/xhtml" ...>
```
HTML 4.01 Transitional doctype with an XHTML namespace is inconsistent. Modern email clients handle this tolerably, but it may cause parsing quirks in Outlook 2016/2019.
