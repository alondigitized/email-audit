# New Red, White & New DEALS!
**Score:** 7/10 · **Type:** Email audit · **2026-06-25**
## Executive summary

- Seven emails in seven days. I'm a loyal customer, not a pen pal. I'll say this — I recognized the Shoe Carnival name the moment it landed, and "30% off" is the kind of number that gets my thumb to stop scrolling. But then I opened it and the first face I saw was a kid — maybe twelve years old — in basketball shorts on a tennis court. That's who Shoe Carnival thinks I am? The whole top half of this email screams Nike and Jordan, which are sneaker brands I associate with my grandkids, not a 62-year-old guy trying to find something with a decent insole.
- The $10 off with code SUMMER10 buried at the bottom is actually the offer I'd use — it works online, which is how I shop — but by the time I scrolled down to it I'd already mentally checked out. The brands up top (Nike, Adidas, Jordan) aren't the ones I cross-shop. I want Skechers, New Balance, maybe Brooks. None of those are on this page.
- I'd mark this one read and move on. Wouldn't click, wouldn't forward. The coupon code might pull me back if I'm already planning a purchase, but this email didn't create that intention.

## What's working

- **The 30% off Nike hero is visually dominant.** I landed on it immediately — big blue numbers, clean layout. The hierarchy is doing its job even if the offer isn't for me.
- **Adidas section is cleanly laid out.** Three shoes, clear price cut, easy to skim on a phone — good execution on that section.
- **SUMMER10 online code is explicit.** I appreciate that they spelled it out — "ONLINE CODE: SUMMER10" — instead of making me hunt for it or wonder if it's in-store only. That's one less headache.
- **Seasonal relevance is clear.** Red, white, blue, patriotic energy — this reads July 4th immediately. At least they moved on from Father's Day.

## What's weak

- **That kid is not me.** The hero model is a child. I'm 62. "For the Family" is what you write when you've given up targeting anyone in particular.
- **None of these brands are my brands.** Nike, Jordan, Adidas — that's the athletic court crowd. I shop Skechers, New Balance, Hoka. Not a single comfort brand in the email.
- **The preview text is broken again.** Yesterday's email had the same problem — a wall of garbled URL in the inbox preview ("Shoe Carnival https://click.email.shoecarnival.com/?qs=ABB7..."). Two days in a row. At this point it's not a glitch, it's a pattern, and it's the first thing I see before I even open the email.
- **Seven emails in seven days is too many.** I start tuning out after three. The June 19–24 run wore me down, and now here's another one.

## Recommendations

- 1. **Fix the preheader — it has now broken two sends in a row.** Whatever is generating that URL dump as preview text needs to be corrected before the next deploy. A real preheader line here would have been "Up to 30% off Nike, Adidas + grab $10 off your order with SUMMER10" — that's the whole email in one line.
- 2. **Swap in at least one comfort brand.** If Shoe Carnival carries New Balance or Skechers walkers — and they do — put one in this email. Even a single row under the Adidas block. Give me a reason to click.
- 3. **Replace the kid model with an adult male.** I don't need to see myself literally, but a grown man wearing one of these shoes would read as relevant. A kid on a court sends me to the kids' section.
- 4. **Surface the $10 off coupon higher.** It's the most universally useful offer in the email and it's at the very bottom. Move it to the middle or add a teaser for it in the hero.
- 5. **Dial back the send cadence.** Skip a day. Two even. I'll still be here.

### 3. Rendering & Accessibility

**Dark mode forced off — confirmed:**
```html
<meta name="color-scheme" content="light" />
<meta name="supported-color-schemes" content="light" />
```
Apple Mail and Outlook Mobile will trigger OS-level color inversion rather than a native dark render. If the email has white text on dark backgrounds anywhere, this will produce illegible output on dark-mode clients (roughly 35–40% of mobile opens).

**Malformed meta tags — confirmed:**
```html
<meta content="text/html;" charset="utf-8" />   <!-- missing http-equiv="Content-Type" -->
<meta content="IE=edge" />                        <!-- missing http-equiv="X-UA-Compatible" -->
```
Both tags are missing their `http-equiv` attribute. The `charset` attribute alone is HTML5-valid, but this document declares HTML 4.01 Transitional, where the charset must live inside `content="text/html; charset=utf-8"`.

**Duplicate CSS property — confirmed:**
```css
a, a:link, ... {
  color:inherit !important;
  color:inherit;   /* redundant — no-op after the !important above */
}
```
The second declaration is dead weight; some legacy parsers handle declaration-order differently and could apply the non-`!important` value over an inherited chain.

**Overlapping breakpoints — confirmed:**
Two separate `@media` blocks fire at `max-width: 600px` and `max-width: 660px` with overlapping class definitions (`.pad20`, `.photo`, `.show`, `.hide`, etc.). On viewports between 601–660px, both blocks are active and later-declared rules silently win. This is order-dependent and fragile — consolidate to one breakpoint.

**`.mobilehide` Gmail workaround — confirmed:**
```css
.mobilehide { display: none; color: #ffffff; }
```
The `color: #ffffff` is a text-color fallback for Gmail, which strips `display:none` in some rendering modes. Hidden content would render as invisible white text — not parsed as hidden by screen readers/assistive tech. If `.mobilehide` elements contain meaningful alt text or links, they remain reachable to AT despite being visually hidden.

**Missing `role="presentation"` on layout tables** — cannot confirm from truncated source, but standard practice for this template pattern. Verify all layout `<table>` elements carry `role="presentation"` to suppress table semantics for screen readers.
