### 3. Rendering & Accessibility

**Issue — Empty `<title>` tag:**
```html
<title></title>
```
Some clients (notably Outlook Web App) display the `<title>` value as the browser tab label. An empty title is a missed opportunity but not a breakage.

**Issue — `lang` attribute on `<div>`, not `<html>`:**
```html
<html lang="en"> ✓ (correct)
<div lang="en"> (redundant; not the issue)
```
Actually `<html lang="en">` is *not present* in the provided source — the `lang` appears only on the inner `<div>`. Screen readers key off the `<html>` element. The `<html>` tag has no `lang` attribute in this source.

**Issue — `-webkit-text-size-adjust: none` on `<body>`:**
```html
style="... -webkit-text-size-adjust: none; -ms-text-size-adjust: 100%; ..."
```
`none` disables text resizing entirely on iOS Safari/WebKit. The `-ms-` counterpart correctly uses `100%`. The webkit value should also be `100%`, not `none`. This can cause text to render too small on some iOS contexts.

**Issue — Duplicate `margin` declarations in `<body>` style:**
```html
style="margin-right: auto; margin-left: auto; margin: 0px; ... margin: 0; padding:0;"
```
`margin: 0px` overrides the preceding `auto` side values. Three separate margin declarations in one attribute — sloppy and the auto-centering intent is immediately nullified.

**Issue — Repeated `border-collapse` in table style:**
```html
style="... border-collapse:collapse;border-collapse:collapse;border-collapse:collapse;"
```
Harmless but indicates a copy-paste artifact in the template.
