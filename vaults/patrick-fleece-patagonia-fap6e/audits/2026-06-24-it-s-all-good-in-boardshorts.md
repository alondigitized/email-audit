### 3. Rendering & Accessibility

**Issue 1 — `-webkit-text-size-adjust: none` on `<body>`**

```html
body style="... -webkit-text-size-adjust: none; ..."
```

`none` disables iOS Safari's automatic font scaling entirely. The correct value is `100%`, which suppresses *unwanted* zooming while preserving user-initiated scaling. This can fail WCAG 1.4.4 (Resize Text) and causes small text to be unreadable on iPhones without pinch-zoom.

**Issue 2 — Empty `<title>` tag**

```html
<title></title>
```

Gmail web client and some Outlook versions surface the `<title>` in tab labels or preview panes. An empty title degrades accessibility for screen readers opening the email in a browser tab. Should contain the email subject or a descriptive string.

**Issue 3 — `CopernicusEmail` missing `.woff` fallback**

`RidgewayEmail` declares both `.woff` and `.woff2` sources. `CopernicusEmail` declares only `.woff2`:

```css
src: url(...GalaxieCopernicus-Book.woff2) format("woff2");
```

Older Android email clients (pre-Chromium WebView) that support web fonts but not woff2 will fall back silently to Georgia/Palatino rather than the branded typeface. Low risk in practice but inconsistent with the Ridgeway treatment.

**Issue 4 — Redundant/conflicting margin declarations on `<body>`**

```html
style="margin-right: auto; margin-left: auto; margin: 0px; ... margin: 0;"
```

The shorthand `margin: 0px` overrides the earlier `auto` lateral margins, and `margin: 0` is then repeated. Functionally harmless (the final value wins) but a copy-paste artifact that should be cleaned up to avoid confusion.
