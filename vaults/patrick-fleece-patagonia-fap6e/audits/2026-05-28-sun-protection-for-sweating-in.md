### 3. Rendering & Accessibility

**Confirmed issues:**

**[HIGH] Conflicting `-webkit-text-size-adjust` in `<body>` inline style**
The same `style` attribute contains both values:
```
-webkit-text-size-adjust: none; ... -webkit-text-size-adjust: 100%;
```
Last declaration wins so `100%` takes effect, but `none` is dead code that creates maintenance risk — a future edit trimming the attribute could accidentally activate `none`, disabling iOS font scaling and breaking layout on iPhone.

**[MEDIUM] CopernicusEmail font missing woff fallback**
RidgewayEmail correctly declares both `woff` and `woff2` sources. CopernicusEmail only declares `woff2`:
```css
src: url(https://images.patagonia.com/eMedia/fonts/GalaxieCopernicus/GalaxieCopernicus-Book.woff2) format("woff2");
```
Older Outlook for Mac (2011) and some Android WebView builds do not support woff2 and will fall through to system serif with no branded font.

**[LOW] Empty `<title>` tag**
```html
<title></title>
```
Screen readers and some clients surface the title. Should be set to the subject line or a descriptive value.

**[LOW] Duplicate inline style properties on `<body>`**
`width: 100%` appears twice; `margin: 0px` and `margin: 0` both appear. No rendering impact, but signals copy-paste drift in the template.

**[INFO] Preheader `<td>` carries redundant `.hide` class**
The inner `<div>` is already `display:none`. Applying `.hide` to the wrapper `<td>` is harmless but inconsistent with the pattern used in the rest of the template.
