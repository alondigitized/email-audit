# Technical Audit: Patagonia, "Vintage styles for the mountain minded"

The HTML source was truncated after the preheader, so body links, footer, unsubscribe markup and UTM parameters could not be inspected. Findings below are limited to the visible `<head>`, the preheader and the QA output.

## 1. Technical Summary
The visible markup is structurally sound: it has `lang`, `role="presentation"` layout tables and a hidden preheader with a spacer hack. The only confirmed defects are an empty `<title>` and a tracking pixel without alt text. The QA warnings are mostly capture limitations of the AgentMail relay, not confirmed email defects.

## 2. Link & Tracking Issues
- **No link verification:** 12 material links were selected for probing and all 12 were skipped, so no destination status codes, redirect chains or unsubscribe reachability were checked.
- **Open pixel, no alt:** `https://trk.na.patagonia.com/wf/open?upn=u001.…` has no alt text. It is a tracking pixel, so the fix is `alt=""`. This is minor, but it is the only image the QA check flagged.
- **Tracking domain:** `trk.na.patagonia.com` shares the `na.patagonia.com` subdomain of the From address, so it is a branded, aligned tracking host.

## 3. Rendering & Accessibility
- **Empty title:** `<title></title>` is empty in `<head>`. This is confirmed in the source and affects the "view in browser" tab title and some assistive tech.
- **No viewport meta:** `<head>` contains `charset` and `x-apple-disable-message-reformatting` but no `<meta name="viewport">`. Responsive behavior relies on the `@media (max-width:600px/540px)` rules, so this is low severity.
- **Conflicting body styles:** the `<body>` inline style sets `-webkit-text-size-adjust: none` and later `100%`. It also repeats `margin`, `width` and `border-collapse` several times. The last declaration wins, so this is harmless but redundant.
- **Preheader:** `display:none; max-height:0; overflow:hidden` plus the `&zwnj;&nbsp;` spacer is standard. It has no `mso-hide:all`, which is a minor Outlook edge case.
- **Webfonts:** `@font-face` fonts load from `images.patagonia.com` with `font-display: swap`. Fallback stacks are not visible in the truncated source.
- **Positives:** `lang="en"` is on `<html>` and the wrapper `<div>`, and the layout tables use `role="presentation"`.

## 4. Personalization & Merge Tokens
No issues found in the visible source. No unresolved tokens such as `{{…}}`, `%%…%%` or `[FNAME]` appear in the head or preheader.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe and List-Unsubscribe-Post:** the QA check did not find either header. Its own note says the relay may not capture them, so this is unconfirmed rather than a verified defect. If the header is truly absent, Gmail and Yahoo bulk-sender requirements (RFC 8058 one-click) would not be met.
- **Authentication-Results:** not found. SPF, DKIM and DMARC status is unknown because of the relay. Check the raw message headers from the original inbox.
- **Footer:** the physical address and the in-body unsubscribe link are outside the truncated source, so they could not be assessed.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not assessable. No body links were captured and no link probes ran, so UTM parameters and landing page alignment are unverified.

## 7. Recommendations
1. Populate `<title>` (for example, with the subject line).
2. Add `alt=""` to the open-tracking pixel, `trk.na.patagonia.com/wf/open`.
3. Add `<meta name="viewport" content="width=device-width, initial-scale=1">`, and remove the duplicate inline declarations on `<body>`.
4. Re-run the audit with the full HTML so the footer, unsubscribe link and UTMs can be checked.
5. Fix the audit pipeline: capture raw headers (`List-Unsubscribe`, `List-Unsubscribe-Post`, `Authentication-Results`) before the relay strips them, and ensure the probe step runs. Otherwise the 57% pass rate reflects tooling gaps, not email quality.
