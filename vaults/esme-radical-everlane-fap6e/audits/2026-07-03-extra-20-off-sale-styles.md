# Extra 20% Off Sale Styles
**Score:** 8/10 · **Type:** Email audit · **2026-07-03**
## Executive summary

- This is Everlane's eleventh consecutive promotional email in eight days, and the creative is effectively a copy-paste of the July 2 send ("What's Better Than Fireworks? An Extra 20% Off") — same "SUMMER CLEAROUT SALE" red-on-blue hero, same black SHOP NOW button, same four-category product flatlay beneath it. The only edit is the subject line, which stripped the Fourth of July hook and replaced it with the bare-bones "Extra 20% Off Sale Styles."
- The central problem is a subject-to-body disconnect: the subject promises "Extra 20% Off," but the hero leads with "UP TO 70% OFF SALE STYLES INCLUDING NEW MARKDOWNS" and never explains the extra 20% mechanism. A subscriber who opens expecting a stacked discount or a code has nowhere to find it. That erodes trust — and on the eleventh send in eight days, trust is already thin.
- The environmental impact block mid-email — a recycling blurb followed by a "READ OUR LATEST IMPACT REPORT" CTA — is an inexplicable placement in a clearance-sale email. Everlane's brand equity earns it a shrug rather than immediate unsubscribes, but it interrupts purchase intent at exactly the worst moment.

## What's working

- "UP TO 70% OFF SALE STYLES INCLUDING NEW MARKDOWNS" in the hero is clear, specific, and genuinely compelling offer copy.
- Four category-level CTAs (SHOP SALE DRESSES / TEES / SHORTS / PANTS) give buyers a faster path than a single homepage link.
- Email renders cleanly — no broken images, no overlapping text, no empty fields.
- Subject line at 26 characters is crisp for mobile and contains zero spam signals.
- Flatlay product grid stays on-brand; the items read as summer-appropriate and on-season.

## What's weak

- "Extra 20% Off" in the subject is never surfaced in the email body — the hero ignores it entirely, leaving the offer mechanism unexplained.
- Hero creative has now run at least four times in eight days; creative fatigue is real and this send adds nothing new visually.
- No deadline or expiration date anywhere, removing the primary reason to act now rather than later.
- The sustainability/impact block mid-email is an editorial non-sequitur that stalls scroll momentum in a conversion-focused send.
- No model photography, no fit or lifestyle context — just flatlay, which makes it harder to imagine wearing anything.

## Recommendations

- 1. **Pay off the subject above the fold.** If "Extra 20% Off" is the mechanism, say it in the hero: "EXTRA 20% OFF EVERYTHING ALREADY UP TO 70% OFF." A stacked discount is a strong offer — burying it in the subject line while the body runs different copy wastes it entirely.
- 2. **Retire this hero creative.** It has now run at least four times in eight days. Pull a lifestyle shot from the June 29 shorts editorial send — that was the freshest creative in the run and earned the strongest review precisely because it broke from this template.
- 3. **Add a credible deadline.** "Ends Sunday at midnight" or "Offer expires tonight" is the single highest-ROI copy addition available. Without it, there is no trigger to act.
- 4. **Cut the impact block from sale emails.** Move it to a standalone brand-values send once a month. Don't ask a clearance buyer to read about supply-chain ethics.
- 5. **Test one hero product with a named price.** "The Perform Dress — $48 (was $98)" in the hero would outperform the generic category grid by a wide margin.

- **Subject Alt B:** `Your extra 20% is here (on already-reduced styles)`
- **Preheader Alt A:** `Sale dresses, tees, shorts, pants — clearance prices just dropped again.`
- **Preheader Alt B:** `Up to 70% off + extra 20% on top. No code needed. Ends tonight.`

### 1. Technical Summary

Email is built on Klaviyo's MJML-based framework with MSO/VML Outlook conditionals. The truncated source reveals several infrastructure-level issues; a complete audit of links, merge tokens, and compliance blocks requires the full HTML.

---

### 2. Link & Tracking Issues

**Cannot fully audit** — HTML is truncated before body links appear. From what is visible:
- No link hrefs are present in the `<head>` portion to inspect for UTM params
- External font import at `https://static-forms.klaviyo.com/fonts/api/v1/USb9mf/custom_fonts.css` is a third-party CDN dependency; if it times out, rendering falls back to Arial/Helvetica silently

**Requires full HTML**: confirm UTM params (`utm_source`, `utm_medium`, `utm_campaign`) on all `<a>` hrefs, and that click-tracking wraps are present on every CTA.

---

### 3. Rendering & Accessibility

**Confirmed issues:**

- **Duplicate `img` CSS rule** — `img { border: 0; line-height: 100%; ... }` is declared twice in the same `<style>` block. The second declaration adds `max-width: 100%` and `height: auto` that the first lacks. This is harmless but indicates a template copy/paste error and adds unnecessary bytes.

- **Inconsistent responsive breakpoints** — Most mobile media queries fire at `max-width: 480px`, but the `.hide` utility class fires at `max-width: 600px`:
  ```css
  @media screen and (min-device-width: 10px) and (max-width: 600px) { .hide { ... } }
  ```
  Devices 481–600px wide (many Android phones) will trigger `.hide` but not the column-stacking or padding resets, producing a hybrid layout that was likely unintended.

- **Empty `<title>` tag** — `<title> </title>` is whitespace-only. Some clients (Apple Mail, Outlook) display the title in preview panes or tab labels. Should reflect the email subject or brand name.

- **Global link color suppression** — Two separate `<style>` blocks both set `color:#000` on `a`, `a:link`, `a:visited`, `a:active`, `a:hover`. This globally suppresses all link color including CTA buttons. Button color must be enforced via inline `style` attributes to survive this override; confirm that all CTAs use inline color declarations.

- **`@import` inside `<style>`** — Gmail (which strips `<head>` styles in non-Google-sent mail) will drop the Klaviyo custom font import. Fallback stack (`Arial, "Helvetica Neue", Helvetica, sans-serif`) applies — acceptable, but confirm font fallback renders correctly at QA.

- **Alt text** — Cannot confirm from truncated HTML. All `<img>` tags must carry `alt` attributes (even `alt=""` for decorative images).
