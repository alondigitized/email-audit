# Stripes Are Having a Moment. Again.
**Score:** 7/10 · **Type:** Email audit · **2026-06-03**
## Executive summary

- Everlane pivots from linen (twice in the last week, most recently June 2's "Linen Love") to stripes — a sensible category shift, but the self-aware "Again." in the subject telegraphs that this is a perennial pull rather than a genuine editorial event. The creative is clean: a strong hero with a confident model in a striped knit, a tightly edited three-product grid (top, culotte, sandal), and Everlane's reliably witty body copy. Visually this is one of the better-composed emails in this recent run.
- The problem is that nothing here creates urgency or specificity beyond the aesthetic. No price, no deadline, no single linked hero product. Combined with six consecutive editorial emails since May 28, this send will land in an inbox where the subscriber has already been trained that Everlane doesn't have an offer this week. The "SHOP THE COLLECTION" CTA is correct but generic — it's the same energy as every other editorial Everlane send.
- The sustainability block dropped into the lower third is boilerplate Everlane infrastructure. It has appeared in prior sends, breaks the editorial momentum, and adds friction between the product grid and the footer. For an email this short, it's dead weight.

## What's working

- **Hero composition is strong**: The model in the striped knit against a clean background immediately communicates the theme with zero ambiguity.
- **Body copy earns its place**: "Nautical by nature. All aboard, obviously." is brief, witty, and on-brand — doesn't overstay its welcome.
- **Three-item grid tells a story**: Top + culotte + sandal read as a styled outfit, not a random assortment.
- **Zero render bugs**: Layout is clean, no broken images, text sits correctly throughout.
- **Subject length is mobile-optimal**: 36 characters, reads in full on any device.

## What's weak

- **No offer, again**: This is the seventh consecutive editorial email since May 27. "Shop the Collection" with no price hook is wearing thin on a subscriber who's received six identical ask-without-giving emails.
- **Sustainability boilerplate kills momentum**: The materials/impact block drops in directly after the product grid, breaking the path from browse to click. It belongs in the footer or a dedicated impact email.
- **"Again." undersells itself**: The self-aware admission that stripes are recurring softens urgency instead of leaning into why *this* summer's stripe is the one worth buying.
- **No product-level depth**: No fabric call-out, no size range mention, no price anchoring — nothing that makes the stripes shown feel distinct from any other stripe collection, anywhere.

## Recommendations

- 1. **Add one concrete hook to the hero**: Even "From $68" or "Free shipping this week" transforms a browse email into a transactional one. This is the single highest-leverage change available.
- 2. **Remove the sustainability block from this send**: It dilutes the editorial and belongs in an Everlane impact email of its own, or reduced to a one-line footer line. The creative doesn't need it.
- 3. **Make the product links specific**: "SHOP THE COLLECTION" links to a category page. One of the three grid products should link directly to its PDP — the striped knit especially, since that's what the hero model wears.
- 4. **Lean into the seasonal angle more specifically**: "Made for Summer" is vague. Name the fabric or the wash. "Cotton-linen stripe" or "Breathable knit, ready for the heat" adds real buying signal.

### 3. Rendering & Accessibility

**Issue 1 — Empty `<title>` tag**
```html
<title> </title>
```
The title contains only whitespace. Screen readers announce this as blank; some clients display it in the tab/preview. Should be set to the subject line or a meaningful value.

**Issue 2 — h4 mobile font size is 10px**
```css
@media only screen and (max-width: 480px) {
  h4 { font-size: 10px !important; ... }
}
```
10px is below the WCAG-recommended 12px minimum for readable body text. This will render as illegibly small product labels or captions on mobile.

**Issue 3 — All link states override to `#000` / `text-decoration:none`**
```css
a:not([name]), a:link, a:visited, a:active, a:hover { color:#000; text-decoration:none }
```
Removes all visual affordance distinguishing links from plain text. Fails WCAG 1.4.1 (Use of Color) unless links are differentiated by means other than color — not verifiable in truncated source.

**Issue 4 — Duplicate `img` rule block**
The `img { border:0; line-height:100%; ... }` rule appears twice in the `<style>` block (once in the base reset, once in a later block). While browsers handle this gracefully, it indicates the template stylesheet was not deduplicated, inflating payload size.

**Issue 5 — External font dependency (render-blocking)**
```html
@import url(https://static-forms.klaviyo.com/fonts/api/v1/USb9mf/custom_fonts.css);
```
`@import` inside `<style>` is render-blocking in clients that support it. If the Klaviyo CDN is slow or the request is blocked (corporate firewalls, iOS Mail privacy relay), the fallback stack (`Arial, "Helvetica Neue", Helvetica, sans-serif`) activates silently. Not a breakage risk, but confirm the fallback renders acceptably.
