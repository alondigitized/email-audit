# 30% Off Warm-Weather Staples
**Score:** 7/10 · **Type:** Email audit · **2026-06-13**
## Executive summary

- This is the third email in three days with functionally the same creative: a 30% off hero, a woman in warm Everlane tones, and a "SHOP NOW" button. The subject has been rotated from "Summer Styles" to "Linen Must-Haves" to now "Warm-Weather Staples," but the hero copy still reads **"30% OFF SUMMER STYLES"** — the exact same text as the June 11 send. That's not a campaign; that's a slot machine pulling the same lever with a new label each time.
- To its credit, the email renders cleanly. The "VACATION ESSENTIALS EVENT" frame is new language and a slightly smarter hook than the raw discount shout — but it's immediately undercut by the same generic hero copy it's supposed to elevate. The six-product grid below has range (skirt, tee, dress, shorts, pants, structured tee) but lands with no names, no prices, and no fit language, so it reads as filler rather than curation.
- Three days in, any engaged subscriber has seen this creative twice already. Fatigue is real, and no amount of subject-line rotation fixes a creative that hasn't changed.

## What's working

- **Clean visual hierarchy** — hero offer is immediately above the fold, the eye moves naturally from discount → subheadline → product grid → CTA.
- **"The pieces you'll wear together, at better prices"** — the pairing hook is the strongest original line in the email; it implies outfit building, not just product dumping.
- **No render bugs** — layout is intact, images load, nothing overlaps.
- **Six-item product grid** — breadth signals that the sale has real selection, not just a feature item.
- **Subject line length** — 28 characters clears mobile comfortably.

## What's weak

- **Hero copy doesn't match the subject** — subject promises "Warm-Weather Staples," hero delivers "30% OFF SUMMER STYLES." Same disconnect flagged on the June 12 audit.
- **Third consecutive day with the same creative** — cadence is broken; this send cannot out-rotate its way to a fresh impression.
- **No deadline on the offer** — "30% Off" with no end date removes all urgency from the click.
- **Product grid has zero context** — no names, no prices, no fit descriptors. Six unnamed product images don't curate; they accumulate.
- **"SHOP NOW" is doing all the CTA work twice** — no verb-plus-noun specificity ("Shop the Sale," "Explore Vacation Styles") to differentiate the two buttons or tie back to "Vacation Essentials."

## Recommendations

- 1. **Retire this creative for at least four days.** The 30% off message has aired three times in three rows. Even a strong subject cannot open an email the subscriber has already mentally filed under "more of the same."
- 2. **Align hero copy with the subject.** If the subject commits to "Warm-Weather Staples," the hero headline should say exactly that — not carry over "SUMMER STYLES" from June 11.
- 3. **Add a deadline.** "Ends Sunday" or "3 days left" converts the discount from ambient to actionable. It's the single highest-lift change on any 30%-off send.
- 4. **Name and price the products in the grid.** "The Perform Tee — $42 (was $60)" beats a naked product shot every time.
- 5. **Differentiate the two CTAs.** First button: "Shop the Vacation Edit." Second button (after the grid): "See All Sale Styles." Same "SHOP NOW" twice kills hierarchy.

### 3. Rendering & Accessibility

**Empty `<title>` tag**
```html
<title> </title>
```
A whitespace-only title is rendered by some clients (notably Apple Mail tab labels). Should be truly empty or set to the subject line.

**`@import` for custom fonts is unsupported in major clients**
```css
@import url(https://static-forms.klaviyo.com/fonts/api/v1/USb9mf/custom_fonts.css);
```
Gmail, Outlook, and Yahoo strip or block `@import` inside `<style>`. The font will silently fail. Fallback stack (`Arial, "Helvetica Neue", Helvetica, sans-serif`) is present, so degradation is graceful — but the import will never load for the majority of recipients.

**Inconsistent font-family name for custom font**
- `h1` references `"MaisonNeue-Light"` (hyphenated)
- `h2`, `h3`, `h4` reference `"Maison Neue"` (space-separated)

These are likely two different `@font-face` names. If only one is declared in the imported CSS, the other will silently fall back. Needs verification against the font CSS at `static-forms.klaviyo.com/fonts/api/v1/USb9mf/custom_fonts.css`.

**Duplicate CSS blocks add unnecessary weight**
```css
/* Appears twice verbatim: */
img { border: 0; line-height: 100%; outline: none; text-decoration: none; -ms-interpolation-mode: bicubic }

/* Also duplicated: */
@media only screen and (max-width: 480px) { .hide { ... } }

/* p margin reset appears in two separate rule blocks */
```
Not breaking, but adds ~300–500 bytes of dead CSS weight.

**Breakpoint inconsistency — gap zone at 481–600px**
- Most responsive rules collapse at `max-width: 480px`
- `.hide` utility uses `max-width: 600px`

Elements using `.hide` will be hidden on viewports 481–600px wide while the layout has not yet collapsed to mobile. This creates a potential layout gap on small tablets and large-screen phones.

**Link color accessibility**
```css
a:not([name]), a:link, a:visited, a:active, a:hover { color: #000; text-decoration: none }
```
All links render as plain black text with no underline. Without additional visual differentiation (bold, border-bottom, background), this fails WCAG 2.1 SC 1.4.1 (Use of Color). Cannot confirm whether CTA buttons use a different inline style, as link markup is in the truncated portion.
