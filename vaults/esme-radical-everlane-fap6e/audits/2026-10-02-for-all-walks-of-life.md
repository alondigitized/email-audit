## Technical Audit

## 1. Technical Summary
The email is a Klaviyo-built, MJML-style template sent through a `trk.send.everlane.com` click-tracking domain. The QA run failed on two tracked links (38% pass rate). Several compliance and authentication checks are inconclusive because the relay doesn't capture headers. The HTML source was truncated, so the body, footer and most links could not be inspected.

## 2. Link & Tracking Issues
- **Relative redirect targets (2 FAIL).** The probe followed these tracked links and got `unknown url type` because the redirect target had no scheme or host:
  - "Icon | Sign Up for Texts" → `https://trk.send.everlane.com/l/01M3YMPQ1ASHZD20NGJ78J6KCP_18` resolves to `/pages/sms-signup?_kx=…&bxid=…&cm_fl…`
  - "Everlane Logo" → `https://trk.send.everlane.com/l/01M3YMPQ1ASHZD20NGJ78J6KCP_0` resolves to `/pages/womens?_kx=…&bxid=…&cm_flow_i…`
  - If the tracker really returns a relative `Location`, a browser will resolve it against `trk.send.everlane.com`, not `everlane.com`, and the click will 404. I couldn't confirm which case this is. It could also be a probe artifact where the redirect chain lost its host. Test both links in a real client.
  - The logo link is a top-position, high-traffic link. If it is broken, it is the most serious finding.
- **Probe coverage was partial.** 12 links were probed and 16 skipped, so the 38% pass rate reflects only the probed set.
- **Tracking pixel without alt text.** `<img src="https://trk.send.everlane.com/o/01M3YMPQ1ASHZD20NGJ78J6KCP">` is the open-tracking pixel. This is low impact, but an `alt=""` would be cleaner.

## 3. Rendering & Accessibility
- **Empty title.** `<title> </title>` contains only whitespace.
- **No language attribute.** `<html xmlns=… xmlns:o=… xmlns:v=…>` has no `lang`, which screen readers use to pick a pronunciation.
- **Small mobile text.** At `max-width: 480px`, `h4 { font-size: 10px !important }` is below common legibility minimums (about 13–14px). This only matters if the body uses `h4` for readable copy.
- **Web fonts.** The `@import url(https://static-forms.klaviyo.com/…/custom_fonts.css)` is stripped by many clients. The font stacks fall back to Arial/Helvetica, so no issue.
- **Outlook handling.** MSO conditionals, `o:OfficeDocumentSettings` and `mj-outlook-group-fix` are present, so no issue.

## 4. Personalization & Merge Tokens
No issues found in the visible source. No unrendered tokens such as `{{ }}`, `{% %}` or `*|…|*` appear in the truncated HTML. The footer and body weren't available to check.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe and List-Unsubscribe-Post (RFC 8058): not found.** The QA tool notes the AgentMail relay may strip them. This is unconfirmed, not a verified defect. Check the raw message at the sender, because Gmail and Yahoo bulk-sender rules require one-click unsubscribe.
- **Authentication-Results: not found.** SPF, DKIM and DMARC status is unknown. The relay is the likely cause, so check the original delivery.
- **Footer not verified.** The truncated source has no visible unsubscribe link or physical address. The QA tool says an unsubscribe link is always probed, but no result for it was reported. Confirm it is present and working.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- The tracked URLs carry Klaviyo identifiers (`_kx`, `bxid`, `cm_flow_i…`), but the truncated output shows no `utm_source`, `utm_medium` or `utm_campaign`. The parameters may be appended after the redirect. Verify that the final landing URLs carry UTMs so GA attribution works.
- Landing alignment can't be assessed for the two failed links, because the destinations only appear as relative paths (`/pages/womens`, `/pages/sms-signup`).

## 7. Recommendations
1. **Verify the two relative redirects first.** Click `…_0` and `…_18` in a real client. If they land on `trk.send.everlane.com/pages/…`, the tracking-domain config or link template is emitting host-less URLs and needs to return absolute `https://www.everlane.com/…` targets.
2. Check the original message headers for `List-Unsubscribe`, `List-Unsubscribe-Post: List-Unsubscribe=One-Click`, and SPF/DKIM/DMARC pass results.
3. Confirm the footer has a working unsubscribe link and a postal address.
4. Add `lang="en"` to `<html>` and a meaningful `<title>`.
5. Add `alt=""` to the tracking pixel.
6. Confirm UTM parameters survive to the final landing URLs.
7. Re-run the audit with untruncated HTML so the body, footer and remaining 16 links can be checked.
