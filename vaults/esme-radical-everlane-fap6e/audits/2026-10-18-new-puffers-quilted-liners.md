## Technical Audit

**1. Technical Summary**
The Everlane email is a Klaviyo-built template with every link routed through the `trk.send.everlane.com` click-tracker. The QA run found one broken tracked link, an image with no alt text, and no captured compliance or authentication headers. The header gaps are probably artifacts of the AgentMail relay and may not be real defects.

**2. Link & Tracking Issues**
- **[FAIL] Broken link, "Everlane" (header or logo link).** The tracker URL `https://trk.send.everlane.com/l/01M58C8FGAP20NGE6F90DEJ1MM_0` failed with `unknown url type: '/pages/womens?_kx=…&bxid=…&cm_flow_i…'`.
  - The redirect target is a relative path (`/pages/womens?...`) with no scheme or host.
  - A relative destination is invalid in a click-tracker redirect. The Klaviyo link was most likely built with a path-only URL, so the redirect has no domain to resolve against.
  - Browsers or mail clients may resolve this differently from the QA probe. It could land on `trk.send.everlane.com/pages/womens` (a 404), or fail outright.
  - This is the brand-logo link, so it is a high-traffic click target.
- **Probe coverage:** 12 material links were probed and 13 were skipped as footer, utility or social links. The 13 skipped links are unverified.
- **Pass rate:** 43% overall. The report does not say which links failed beyond the one above, so I can't tell whether other tracked links fail the same way.

**3. Rendering & Accessibility**
- **Missing alt text:** the image with src `https://trk.send.everlane.com/o/01M58C8FGAP20NGE6F90DEJ1MM` has no alt attribute.
  - The path `/o/` is the open-tracking pixel pattern, so this is most likely the 1×1 tracking pixel.
  - If so, it should carry `alt=""` (and ideally `width="1" height="1"`) so screen readers skip it. This is low severity.
- **Empty title:** `<title> </title>` holds only whitespace. Some clients and screen readers use the title as the document name. This is minor.
- **Dark-mode classes:** `.ev-clay-dark` and `.ev-clay-light` use `[data-ogsc]` for Outlook.com dark mode, which is correct. I can't verify the other dark-mode behavior because the HTML was truncated.
- **Font import:** `@import url(https://static-forms.klaviyo.com/...custom_fonts.css)` is unsupported in Gmail and several other clients. The stacks fall back to Arial and Helvetica, so the impact is limited.

**4. Personalization & Merge Tokens**
No issues found. The truncated HTML and the QA data show no unrendered tokens such as `{{ }}`, `{% %}` or `*|…|*`.

**5. Compliance (CAN-SPAM, unsubscribe, authentication headers)**

  - If Everlane does not send them, that is a gap against the Gmail and Yahoo bulk-sender requirements, which expect one-click unsubscribe.
  - This can't be confirmed from the relay copy. Check the raw headers from a direct delivery to a test inbox.
- **[WARN] No Authentication-Results header.** SPF, DKIM and DMARC status is unknown. The QA tool again attributes this to the relay.
- **From address:** `support@everlane.com` is used for a marketing send. The tracking domain `trk.send.everlane.com` is a subdomain of the sender domain, which helps alignment.
- **Footer and unsubscribe link:** an unsubscribe link is always included in the probe set, but the truncated HTML doesn't show the footer. I can't verify the physical postal address or the visible unsubscribe link.
