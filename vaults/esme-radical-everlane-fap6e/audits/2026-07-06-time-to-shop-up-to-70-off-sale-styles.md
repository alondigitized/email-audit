# Time to Shop: Up to 70% Off Sale Styles
**Score:** 8/10 · **Type:** Email audit · **2026-07-06**
## Executive summary

- This is Everlane's fourteenth consecutive promotional email in roughly nine days — and it arrived on the **same day** as the "Last Chance: Up to 70% Off" send audited earlier today. The subject, hero headline, offer mechanics, and CTA are functionally identical to the prior twelve sends. The coral-gradient creative swap that felt like a fresh pivot in the July 5th and July 6th "LAST CALL" email has now been reused again, draining the novelty it briefly earned.
- Taken as a standalone piece, it's clean: the gradient holds attention, "DON'T MISS OUT" reads instantly, and the offer — Extra 20% off styles already up to 70% off — is specific and the fine print shows it expires tonight at 11:59 PM PST. Execution is competent.
- The problem is cumulative credibility. Sending "Last Chance" and then "Don't Miss Out" hours apart on the same day signals that the sale never actually ends, which undercuts urgency for anyone who has been on the list this week. This email will feel like noise to the majority of recipients.

## What's working

- **Coral gradient hero is visually clean** — headline, offer copy, and CTA all land in one uncluttered block with no image-loading risk.
- **Offer is legible and specific** — "Extra 20% off, already up to 70% off" communicates real value without ambiguity.
- **CTA is unambiguous** — black "SHOP NOW" bar reads immediately as a button; no confusion about where to click.
- **Fine print confirms expiry** — "Offer valid until 07/06/2026 at 11:59 PM PST" is visible and specific, lending credibility to the deadline.
- **No render bugs** — layout is tight, no broken assets, no overlapping text.

## What's weak

- **Same-day "Last Call" → "Don't Miss Out" sequence is bait-and-switch adjacent** — subscribers who saw the July 6th "Last Chance" send will correctly conclude that urgency signals from this brand mean nothing.
- **"SHOP NOW" is the weakest possible CTA verb+noun** — there is no category specificity, no product hook, no reason to click over browsing directly.
- **Hero copy says nothing about why now** — "DON'T MISS OUT" is a pure anxiety prompt with no new reason to act that wasn't present in the prior thirteen sends.
- **No product imagery** — a gradient-only hero hides merchandise; a subscriber with no residual desire to buy has nothing to latch onto.
- **"Time to shop top styles for less."** below the CTA is placeholder-level copy that adds zero information.

## Recommendations

- 1. **Stop sending same-day doubles.** The single highest-leverage change is not creative — it's suppressing a second blast on a day when a "last chance" already went out. One send with a real expiry builds more urgency than two sends that contradict each other.
- 2. **Swap the CTA to a category or product** — "Shop Women's Sale" / "Shop Men's Sale" / "Shop Dresses" forces a click decision around something real.
- 3. **Add one product image to the hero** — even a single folded item gives the eye something to covet.
- 4. **If keeping the gradient creative, make the deadline the hero** — "Ends Tonight" in large type would do more work than "DON'T MISS OUT."
- **Subject Alt A:** `Ends at midnight: extra 20% off sale styles`
- **Subject Alt B:** `Tonight only — an extra 20% off up to 70% off`
- **Preheader Alt A:** `Final hours on the summer clearout. Shop women's and men's picks before they're gone.`
- **Preheader Alt B:** `Your extra 20% expires at 11:59 PM — here's what's left worth grabbing.`

### 2. Link & Tracking Issues

**External font request on open (privacy/tracking vector)**
The `<style>` block loads a remote stylesheet unconditionally on render:
```
@import url(https://static-forms.klaviyo.com/fonts/api/v1/USb9mf/custom_fonts.css)
```
This fires a GET request on every open, exposing IP, device, and render time to Klaviyo's CDN — even in clients with pixel-blocking enabled. Consider self-hosting the font file or accepting the system fallback stack (`Arial, "Helvetica Neue", Helvetica`), which is already declared and renders acceptably.

**Link destinations unauditable** — source is truncated before `<body>` content. Full source needed to confirm click-tracking wrapping and destination URLs.

### 3. Rendering & Accessibility

**Empty `<title>` tag**
```html
<title> </title>
```
Contains only whitespace. Some clients display the title in notification previews or tab labels. Should be `<title>Time to Shop: Up to 70% Off Sale Styles</title>` to match subject.

**All link states suppress visual differentiation**
```css
a:not([name]) {color:#000;text-decoration:none}
a:link    {color:#000;text-decoration:none}
a:visited {color:#000;text-decoration:none}
a:active  {color:#000;text-decoration:none}
a:hover   {color:#000;text-decoration:none}
```
`:hover` and `:visited` are set identically to default. Links are visually indistinguishable from surrounding text. This is a WCAG 1.4.1 (Use of Color) issue — underlines or color contrast must distinguish links from non-link text.

**h4 mobile font-size is 10px**
```css
@media only screen and (max-width: 480px) { h4 { font-size: 10px !important; ... } }
```
10px is below the WCAG 2.5.5 / general accessibility floor of 12px for body-level text. Raise to at least 12px.

**Image `alt` attributes unverifiable** — source truncated before `<img>` tags appear. Must be confirmed in full source.

**MSO conditional comments present** — Outlook VML and PixelsPerInch settings are correctly included. No issue.
