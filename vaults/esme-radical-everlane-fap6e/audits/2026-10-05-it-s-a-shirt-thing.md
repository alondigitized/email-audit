## Technical Audit

## 1. Technical Summary
The email is a Klaviyo-built message, sent through the `trk.send.everlane.com` click tracker. The only confirmed code-level defect is an empty `<title>`. The QA "FAIL" link results and the header warnings look like limits of the probe and the AgentMail relay rather than confirmed defects. The HTML is truncated, so the footer, unsubscribe link and body links could not be checked.

## 2. Link & Tracking Issues
- **Two probe failures, likely tool artifacts:**
  - `https://trk.send.everlane.com/l/01M46C1NQMJ517CCDFZXKVREWC_18` ("Icon | Sign Up for Texts") fails with `unknown url type: '/pages/sms-signup?_kx=…'`.
  - `.../01M46C1NQMJ517CCDFZXKVREWC_0` ("Everlane Logo") fails with `unknown url type: '/pages/womens?_kx=…'`.
  - Both errors show a path with no scheme or host, so the tracker appears to answer with a relative `Location` header. Relative redirects are valid under RFC 7231 and browsers resolve them, but the QA prober did not. This is probably a checker limitation, not a dead link.
  - It is unconfirmed whether the destination host resolves correctly. Re-test with a client that resolves relative redirects.
- **Probe coverage is partial:** only 12 of 28 links were probed and 16 were skipped, so the 38% pass rate is not representative of the whole email.
- **Tracking pixel:** the "missing alt text" finding is `https://trk.send.everlane.com/o/01M46C1NQMJ517CCDFZXKVREWC`, which is the open-tracking pixel (`/o/`), not content imagery. Adding `alt=""` would be tidier, but it is not an accessibility defect.

## 3. Rendering & Accessibility
- **Empty title:** `<title> </title>` is whitespace only. It affects "view in browser" pages and some screen readers.
- **No language attribute:** `<html xmlns="http://www.w3.org/1999/xhtml" …>` has no `lang` attribute, which screen readers use to pick pronunciation.
- **Web font import:** `@import url(https://static-forms.klaviyo.com/fonts/api/v1/USb9mf/custom_fonts.css)` is ignored by Gmail and some other clients. The font stacks fall back to `Arial, "Helvetica Neue", Helvetica, sans-serif`, so this is acceptable.
- **Other rendering support:** the MSO conditionals, `mj-outlook-group-fix`, and the 480px and 600px media queries are present and standard. No rendering defects were found in the visible source.

## 4. Personalization & Merge Tokens
No issues found in the visible source. No unrendered tokens (`{{ }}`, `{% %}`, `*|…|*`) appear in the truncated HTML. The footer and body were not available to check.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Unverifiable from this data:**
  - `List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) were not found.
  - `Authentication-Results` (SPF/DKIM/DMARC) was not found.
  - The QA notes say the AgentMail relay may strip these headers, so absence does not prove they are missing from the sent mail.
- **Not confirmed:** the unsubscribe link and the physical postal address are in the truncated footer. The QA tool states it always probes an unsubscribe link, and it reported no failure for one.
- **Sender:** `support@everlane.com` is a support-style From address for a marketing send. This is a minor observation, not a violation.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Click params:** links carry Klaviyo/Customer.io-style identifiers (`_kx=…`, `bxid=…`, `cm_fl…`). The destination URLs are cut off in the QA output, so it is unconfirmed whether `utm_source`, `utm_medium` or `utm_campaign` are present.
- **Landing page:** the logo link points to `/pages/womens`, so landing page alignment with the "It's a Shirt Thing" subject could not be assessed.

## 7. Recommendations
1. Fill in `<title>` (for example, the subject line) and add `lang="en"` to `<html>`.
2. Re-probe the two flagged tracker links with a client that follows relative `Location` redirects. If the redirects resolve, dismiss the failures. If not, ask the ESP to return absolute redirect URLs.
3. Verify `List-Unsubscribe`, `List-Unsubscribe-Post` and `Authentication-Results` against the raw message as received, not the relay copy.
4. Retrieve the full HTML to check the footer (unsubscribe, address), UTM parameters, and any personalization tokens.
5. Add `alt=""` to the tracking pixel to clear the QA warning.
