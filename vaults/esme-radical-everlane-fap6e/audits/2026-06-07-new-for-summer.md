# New for Summer
**Score:** 7/10 · **Type:** Email audit · **2026-06-07**
## Executive summary

- After six consecutive editorial sends with real concepts behind them — linen (twice), stripes, matching sets, soft tops — Everlane has defaulted to the plainest possible fallback: a 3×3 product grid under "New Arrivals," no editorial hook, no price, no story. The subject line "New for Summer" is the most generic thing Everlane has put in an inbox in this entire run, and the body doesn't rescue it. There's nothing wrong with the email technically; it just has nothing to say.
- The sustainability boilerplate ("We don't just say we're better — we mean it") reappears in the secondary section as it does in nearly every Everlane send. It's table stakes, not signal. The audience has seen it before and will scroll past it.
- This is a classic content-calendar gap filler — someone had to send something today, and "new arrivals grid" was the path of least resistance. After the genuine editorial momentum of "Two Pieces, Zero Decisions" (June 5, a genuinely clever concept) and "New Linen Arrivals Just Landed" (June 6), this feels like a step backward.

## What's working

- **Product grid renders cleanly.** Nine items, good variety (tanks, dresses, shorts, skirts), coherent summer palette — no broken images, no overlapping text.
- **"SHOP NEW ARRIVALS" CTA is unambiguous.** Clear button, reads as the primary action immediately.
- **Correct seasonal coherence.** The items on display are genuinely summer-weight clothing — the content matches the subject.
- **No render bugs or visual clutter.** Clean Everlane template, hierarchy is legible even at thumbnail scale.

## What's weak

- **"New for Summer" is the weakest subject in the recent run.** It says less than "New Arrivals, Right Now" (May 31) and far less than "Two Pieces, Zero Decisions" or "New Linen Arrivals Just Landed." No product named, no offer, no category hook.
- **No editorial concept.** The previous six sends each had a point of view. This one is a product dump. There is no sentence in this email that tells me *why* I should care about these specific pieces today.
- **No price or offer signal anywhere.** Seven consecutive sends from Everlane without a single discount or price point. The audience is being trained that Everlane emails never contain reasons to buy urgently.
- **Sustainability section is repeat boilerplate.** Appears in roughly the same position in nearly every send — it no longer functions as differentiation, it's noise.
- **Cadence fatigue risk.** Seven emails in seven days, and this is the most generic of the batch. Unsubscribe pressure is real.

## Recommendations

- 1. **Kill "New for Summer" and lead with a specific product or category.** The grid contains floral sundresses, a linen-look ruffled skirt, and a denim button-front — any one of those is a more compelling subject than the generic umbrella. Pick the strongest item and name it.
- 2. **Give the grid an editorial frame.** Even one line of copy above the grid ("The pieces getting the most add-to-carts this week" or "Five things worth grabbing before the weekend") turns a product dump into a curated moment.
- 3. **Add a price or social proof signal.** Even "starting at $48" or "top-rated this week" gives the subscriber a reason to click now vs. later.
- 4. **Rotate the sustainability section cadence.** Put it in every third email, not every email — it will land harder when it appears.

### 3. Rendering & Accessibility

**Duplicate `img` CSS block**
The `img` reset rule is declared twice in the same `<style>` block — once near the top and again after the Klaviyo font import. While browsers/clients cascade correctly, the redundancy is noise and can mask overrides.

```css
/* occurrence 1 */
img { border: 0; line-height: 100%; outline: none; text-decoration: none; -ms-interpolation-mode: bicubic }
/* occurrence 2 */
img { border: 0; height: auto; line-height: 100%; outline: none; text-decoration: none; max-width: 100% }
```
Note: `height: auto` and `max-width: 100%` only appear in the second block — the first occurrence's `-ms-interpolation-mode` is the sole non-overlapping property.

**Inconsistent responsive breakpoints**
Column stacking and font scaling use `max-width: 480px`; hide/show utility classes use `max-width: 600px`. Devices between 481–600px wide will get stacked columns but won't trigger `.hide` / `.font*` overrides.

```css
/* 480px breakpoint — column layout */
@media only screen and (max-width: 480px) { div.kl-row.colstack ... }
/* 600px breakpoint — utility classes */
@media screen and (min-device-width: 10px) and (max-width: 600px) { .hide ... .font20 ... }
```

**`h4` mobile font-size: 10px**
```css
@media only screen and (max-width: 480px) { h4 { font-size: 10px !important; line-height: 1.3 !important } }
```
10px falls below WCAG 2.1 minimum legibility guidance (14px body minimum). If `h4` is used for product price or label text on mobile, this will render as unreadable.

**Empty `<title>` tag**
```html
<title> </title>
```
Whitespace-only title. Some preview pane renderers (Outlook Web, Gmail preview) surface the `<title>` as fallback preview text. Should either be removed or set to a meaningful value to avoid rendering artifacts.

**External font dependency**
```css
@import url(https://static-forms.klaviyo.com/fonts/api/v1/USb9mf/custom_fonts.css);
```
Font families `"MaisonNeue-Light"` and `"Maison Neue"` are served entirely from Klaviyo's CDN with no self-hosted fallback. If the CDN request is blocked (corporate firewalls, aggressive email clients) the entire custom font stack silently falls back to Arial. This is expected behavior for web fonts in email, but worth confirming fallback rendering is acceptable.
