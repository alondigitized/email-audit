# Save Up to 40% On Select Faves
**Score:** 6/10 · **Type:** Email audit · **2026-06-05**
## Executive summary

- This is Bombas's second archive-sale email in two days — yesterday (June 4) was "Up to 40% Off Select Styles: Archive Sale," and today is "Save Up to 40% On Select Faves" hitting the same discount ceiling. The creative is nearly identical: same hero model in black lingerie-adjacent activewear, same "UP TO 40% OFF" headline, same three-CTA row (Women / Men / Kids). The only meaningful additions are a "Limited Time" badge on the hero and a concrete deadline — "SALE ENDS 6/8 · 12PM ET" — which is genuinely new and the strongest single element in this email.
- The problem is creative fatigue. A subscriber who opened yesterday's archive email is looking at a near-clone. The deadline anchors urgency well, but the hero copy and model photography are lifted from the same shoot. "ALL TIME FAVORITES" as a secondary headline is softer than yesterday's "Archive Sale" — it retreats from specificity just as the brand needs to be pushing harder to close out remaining inventory.
- The four icon badges below the CTAs (recycled packaging, 100% something, two others) are too small and illegible at mobile scale — they add visual clutter without landing the social proof message.

## What's working

- **Deadline is concrete and visible** — "SALE ENDS 6/8 · 12PM ET" is exactly the kind of credible, specific urgency that drives last-push clicks.
- **"Limited Time" badge on the hero** — adds a second urgency layer without feeling spammy.
- **Three-column CTA row (Women / Men / Kids)** — still the right segmentation move; subscribers can self-select immediately.
- **Clean visual hierarchy** — discount headline → model → CTAs → deadline → secondary CTAs reads in the right order.

## What's weak

- **Near-identical creative to yesterday's email** — same model, same pose, same headline ceiling; a subscribed reader will feel like they're opening a duplicate.
- **"ALL TIME FAVORITES" undercuts the archive framing** — softer than "Archive Sale" and dilutes the clearance urgency that should be driving conversions on day 2.
- **Icon badges are illegible** — the four trust/feature badges below the CTAs are too small to read; they add noise, not proof.
- **No product specificity below the fold** — nothing showing what styles are actually discounted; yesterday at least had the "Archive Sale" label to frame expectations.
- **Repeat send without a reason to re-open** — no new hook (no price drop, no added categories, no "last chance" framing that's meaningfully different).

## Recommendations

- 1. **Reframe the headline as a deadline push, not a re-announcement.** Replace "UP TO 40% OFF / ALL TIME FAVORITES" with "Last 3 Days — Archive Sale Ends 6/8" to make this feel like a continuation, not a duplicate.
- 2. **Swap or differentiate the hero model/shot** — even a different angle or colorway signals this is a new send worth opening.
- 3. **Add 2–3 featured product tiles below the CTA row** — show a specific sock or tee that's 40% off; it gives the eye something to linger on and the click a destination.
- 4. **Enlarge or drop the icon badges** — either make them legible (larger, with readable label text) or cut them to keep the layout tight.
- 5. **Add a "since you didn't grab it yesterday" soft nudge in the sub-copy** — "Still here: our archive faves, up to 40% off through Monday" acknowledges the cadence without being aggressive.
- **Subject Alt A:** `Last Chance: Archive Faves Up to 40% Off — Ends Monday`
- **Subject Alt B:** `3 Days Left: Up to 40% Off Our All-Time Best`
- **Preheader Alt A:** `Sale ends 6/8 at noon — these styles won't come back.`
- **Preheader Alt B:** `Still 40% off: the archive picks your cart is waiting on.`

### 3. Rendering & Accessibility

**Issue — Missing CSS class selector dot (mobile-third):**
Inside the `@media only screen and (max-width:600px)` block:
```css
mobile-third { width: 33% !important; max-width: 33% !important; }
```
The leading `.` is absent, so this rule is a dead declaration. The element using class `mobile-third` will not receive the intended mobile width. (The corrected `.mobile-third` selector does appear in the `@media screen and (max-width:480px)` block, so only the 600px breakpoint is broken.)

**Issue — Duplicate `xmlns` attribute on `<html>`:**
```html
<html xmlns="http://www.w3.org/1999/xhtml" ... xmlns="http://www.w3.org/1999/xhtml" ...>
```
`xmlns` is declared twice. This is invalid per the XHTML spec and may trigger parser warnings in strict XML-mode renderers.

**Issue — `<o:AllowPNG>` not self-closed:**
```xml
<o:allowpng>
<o:pixelsperinch>96</o:pixelsperinch>
```
Microsoft's VML schema requires `<o:AllowPNG/>` (self-closing, PascalCase). The open-tag form may suppress PNG alpha-channel support in older Outlook builds (2007–2013).

**No issues found:** `role="article"`, `aria-roledescription="email"`, `aria-label`, and `lang="en"` are all correctly present. Dark mode via `prefers-color-scheme` is implemented with matching `.dark-mode-hide`/`.dark-mode-show` toggles.

### 5. Compliance (CAN-SPAM, Unsubscribe, Authentication)

**Issue — Schema.org type is non-standard:**
```html

```
`DiscountOffer` is not a recognized Schema.org type. The correct type is `https://schema.org/Offer` (also note: HTTP vs HTTPS — validators will flag the insecure scheme). This breaks Gmail's native offer-card rendering.
