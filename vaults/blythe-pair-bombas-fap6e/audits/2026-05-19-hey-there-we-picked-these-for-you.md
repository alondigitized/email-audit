# Hey there—we picked these for you
**Score:** 9/10 · **Type:** Email audit · **2026-05-19**
## Executive summary

- This is Bombas's fourth consecutive email in four days — and it shows. The creative rotates to a use-case browse format (Every Day, Ache Relief, Working Out, Cozy Days, Stylin') with dual gender paths on every tile, which is genuinely useful navigation for someone unfamiliar with the line. The hero lands cleanly: "TOP-RATED SOCKS 20% OFF" does the job. But the subject line — "Hey there—we picked these for you" — promises personalization that the email doesn't deliver. There's no name, no past-purchase signal, no behavioral hook. The five tiles are the same five category pages any anonymous visitor sees on the website.
- Compounding the problem: the discount code COMFORT20 is the same one that appeared in the May 16 "New Here? Here's 20% Off" welcome email. Three days later, the same code is repackaged as "personalized picks." A subscriber who noticed the first send will recognize the recycled offer immediately.
- The email renders cleanly and the offer is real. The execution is competent. But the subject/body mismatch — implying curation, delivering generic browse — is this send's central flaw.

## What's working

- **Hero is unambiguous.** "TOP-RATED SOCKS 20% OFF" with code COMFORT20 visible above and below the fold requires zero mental effort.
- **Use-case tile structure is genuinely browsable.** Five occasions (Every Day, Ache Relief, Cozy Days, Working Out, Stylin') cover the main purchase triggers without overwhelming.
- **Dual gender pathing on every tile.** "Shop Women / Shop Men" on each tile reduces the path to conversion — smart for a gender-split product line.
- **Free shipping callout.** "BTW, ORDERS $75+ SHIP FREE" is a clean secondary incentive that addresses a common checkout-abandonment trigger.
- **Clean render.** No broken images, no overlapping text, consistent brand palette throughout.

## What's weak

- **Personalization claim is hollow.** "Hey there—we picked these for you" with no name and five generic category tiles is a broken promise. Subscribers notice.
- **Same code as three days ago.** COMFORT20 debuted in the May 16 welcome email — recycling it signals the "picks" are automated boilerplate, not actual curation.
- **No urgency anywhere.** No expiry on the 20% offer, no "ending soon," no stock signal. There's no reason to click now vs. next week.
- **Fourth email in four days.** After the May 16 welcome, May 17 social proof, and May 18 guarantee email, cadence fatigue is real — even a solid send gets discounted when the inbox is already crowded with the same brand.
- **No specific products surfaced.** Every CTA drops to a category page. One or two hero SKUs with a name, rating, and price would drive materially more clicks than five browse tiles.

## Recommendations

- 1. **Show actual picks, not categories.** Pull 2–3 specific bestselling SKUs with star ratings and prices. "We picked these for you" only lands if the email proves it with real products.
- 2. **Add urgency to the code.** "20% off — ends Sunday" changes the calculus. Unbounded offers are easy to defer indefinitely.
- 3. **Break the cadence.** Four consecutive days is the real underlying problem. Even a one-day gap after the May 18 guarantee email would have helped this land.
- 4. **Personalize or drop the subject claim.** Either use the subscriber's name and a real behavioral signal, or rewrite the subject to match what the email actually delivers.
- **Subject Alt A:** `Your top picks — 20% off, code COMFORT20`
- **Subject Alt B:** `Fan-faves picked for you: everyday, athletic, cozy`
- **Preheader Alt A:** `Code COMFORT20 — fan-faves in every day, athletic, and cozy styles, 20% off`
- **Preheader Alt B:** `Five styles, one code: COMFORT20 for 20% off your first order`

### 2. Link & Tracking Issues

**Cannot fully assess** — HTML is truncated before any `<a href>` tags appear. The following cannot be confirmed from the provided source:
- Presence and consistency of UTM parameters
- Click-tracking redirect wrapper (e.g. `trk.klsend.com`, `links.bombas.com`)
- Whether any links point to HTTP (non-HTTPS) destinations

**Flagged — Google Fonts external load:**
```html
@import url(https://fonts.googleapis.com/css2?family=Poppins:ital,wght@...&display=swap);
```
This fires an outbound request to Google servers on open, functioning as an implicit open-tracking pixel for Google. `@import` inside `<style>` is also blocked by Apple Mail, Outlook, and Yahoo — the custom font silently fails in the majority of email clients. Recommend switching to a `<link>` tag with `media="screen"` and confirming a web-safe fallback stack is applied everywhere `font-family: Poppins` appears.

---

### 3. Rendering & Accessibility

**Bug — CSS selector missing leading dot:**
```css
/* Inside @media only screen and (max-width:600px) */
mobile-third{width:33%!important;max-width:33%!important}
```
The selector is `mobile-third` instead of `.mobile-third`. Any element using `class="mobile-third"` on mobile will not receive the intended 33% width. The corrected `.mobile-third` selector appears in the `@media (max-width:480px)` block but not the 600px block.

**Bug — duplicate `.mobile-half` definition in same media query:**
`.mobile-half{width:50%!important}` appears twice inside `@media only screen and (max-width:600px)`. The second declaration is a no-op and creates maintenance confusion.

**Dual preheader implementation:**
Two hidden preheader divs exist:
```html
<!-- Div 1: empty, uses color+opacity hide technique -->
<div style="color:#f3f3f3;display:none!important;..."></div>

<!-- Div 2: actual preheader text, uses max-height:0 + overflow:hidden technique -->
<div style="display:none;max-height:0;overflow:hidden">Stop struggling. Start saving 20%.</div>
```
The first div contains no text content. Only the second div's text will render as the inbox preview snippet. The empty first div is dead code; remove it.

**Accessibility — positive findings:**
```html
<div role="article" aria-roledescription="email" aria-label="Email from Bombas" lang="en" dir="ltr">
```
Proper ARIA landmarks, language, and directionality are declared. Dark mode support via `@media (prefers-color-scheme:dark)` with `.dark-mode-hide`/`.dark-mode-show` utility classes is present.
