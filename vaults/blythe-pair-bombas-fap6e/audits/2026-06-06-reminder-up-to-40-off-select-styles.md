# 🚨 Reminder: Up to 40% Off Select Styles
**Score:** 8/10 · **Type:** Email audit · **2026-06-06**
## Executive summary

- This is Bombas's third consecutive archive sale email in three days — June 4 launched it (9/10), June 5 followed up (6/10), and today's send is the deadline reminder. The one new element that earns this email its keep is the specific "SALE ENDS 6/8 - 12PM ET" closing-window signal: that's a concrete, credible deadline that transforms what would otherwise be pure copy-paste into a real urgency prompt. The "Reminder:" banner in the hero is an honest framing — not manufactured panic.
- That said, everything else is frozen in amber from the prior two sends: the same bowl-of-socks hero, the same 40% ceiling, and the same three-category CTA wall with no featured product. A subscriber who ignored Monday and Tuesday has not been given a single new reason to click today. The middle section — small circular badges, "Our Crowd-Sourced Collection Offers" — reads as ambient boilerplate that adds no purchase urgency.
- The deadline justifies this email's existence. But Bombas has now sent the same discount three days running without surfacing a specific product or deepening the offer, which is a wasted final send.

## What's working

- **SALE ENDS 6/8 - 12PM ET** is the only genuinely new element and it does real work — specific date and time create a credible close.
- Clean render throughout — no broken images, no layout artifacts, Bombas brand identity is intact.
- "The Archive Sale is still live" is honest, low-pressure copy that doesn't oversell the urgency.
- Deadline appears twice (below the hero and in the countdown bar), which reinforces it without being obnoxious.

## What's weak

- Third consecutive archive sale email in three days — list fatigue is compounding with no new offer hook.
- No featured product anywhere: category-only CTAs ("Shop Women / Men / Kids") give a subscriber nothing specific to want.
- The circular badges section ("Our Crowd-Sourced Collection Offers," "100%") is small, reads as boilerplate, and adds nothing to the sale story.
- The 🚨 emoji in the subject is the first alarm signal in this run — works once, but reads slightly desperate as a reminder tactic.

## Recommendations

- 1. **Surface one archive hero product** — pull the bestselling or most-interesting discontinued style into the hero, link directly to the PDP. "Last chance on the [product]" outperforms a category wall every time.
- 2. **Make the deadline the CTA** — replace "Shop Women / Men / Kids" with a single primary button: "Shop Before It Closes Sunday" or "Grab Yours Before 12PM ET." The deadline is the lever; use it as the CTA copy.
- 3. **Retire the boilerplate badges section** — the "Crowd-Sourced Collection Offers" block is selling Bombas's process, not this sale. Swap it for product thumbnails of the best archive items with their discounted prices.
- 4. **Deepen or vary the offer** — even "free shipping on archive orders over $35" would give a repeat recipient a new reason versus the prior two sends.

### 3. Rendering & Accessibility

**Confirmed issue — broken CSS selector (missing `.`):**
In the `@media only screen and (max-width:600px)` block:
```css
/* BROKEN — missing leading dot */
mobile-third { width: 33% !important; max-width: 33% !important; }
```
This targets a nonexistent element type `mobile-third` instead of the class `.mobile-third`. Elements using `class="mobile-third"` will not receive the 33% column width at the 600px breakpoint. The 480px breakpoint correctly uses `.mobile-third` (with dot), making this inconsistent across breakpoints.

**Confirmed issue — duplicate `xmlns` attribute:**
```html
<html xmlns="http://www.w3.org/1999/xhtml" ... xmlns="http://www.w3.org/1999/xhtml">
```
`xmlns` is declared twice on the `<html>` element. Spec-invalid; parsers will silently drop the duplicate, but it indicates a templating layer issue.

**Dark mode `.dark-mode-show` default state:**
The media query sets `.dark-mode-show { display: block !important; }` but no default `display: none` is declared in the non-dark stylesheet. If inline styles on those elements don't hide them, they may render in both light and dark mode on clients that partially support dark mode.
