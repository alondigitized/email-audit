# Welcome! Your 10% off code is inside
**Score:** 8/10 · **Type:** Email audit · **2026-05-11**
## Executive summary

- This is a textbook welcome email — clean, on-brand, and does exactly what it needs to: hand over a discount code and introduce the Zappos ecosystem in one scroll. The hero sneaker is vivid, the 10% code is front-and-center, and the Zappos VIP teaser is a smart secondary placement that plants the loyalty seed on day one.
- That said, it is entirely generic. No name, no category signal, no hint that Zappos knows anything about why you signed up. The "Welcome to Zappos!" headline could have been written in 2015. For a brand sitting on this much browsing data, the lack of any first-party personalization is a real miss.
- Solid B+: executes the template reliably without being memorable.

## Recommendations

- 1. **Personalize the hero copy to the browsing category** — if Zappos captured browse intent before sign-up, use it: "Welcome to Zappos — your Running gear awaits" beats a generic greeting every time.
- 2. **Add first-name to subject and hero** — "Your 10% off, [First Name]" is table stakes for welcome sends; the current copy leaves it generic.
- 3. **Replace "SHOP NOW" with a category-specific CTA** — "Shop Women's Sneakers" or "Browse Running Shoes" would close the gap between the Adidas hero and the destination click.
- 4. **Amplify the expiry in the offer block** — "Expires in 13 days" set in bolder type would out-perform the small-print date. Make the clock feel real.
- 5. **Shorten the promo code** — `YFNH57A2RP499RZAR` is 18 characters, brutal to type manually. A "click to apply" shortcut or a cleaner code (WELCOME10) would reduce friction.

## Full review
## 1. Take

This is a textbook welcome email — clean, on-brand, and does exactly what it needs to: hand over a discount code and introduce the Zappos ecosystem in one scroll. The hero sneaker is vivid, the 10% code is front-and-center, and the Zappos VIP teaser is a smart secondary placement that plants the loyalty seed on day one.

That said, it is entirely generic. No name, no category signal, no hint that Zappos knows anything about why you signed up. The "Welcome to Zappos!" headline could have been written in 2015. For a brand sitting on this much browsing data, the lack of any first-party personalization is a real miss.

Solid B+: executes the template reliably without being memorable.

## 2. What stood out

The hero image is genuinely strong — a crisp Adidas Originals silhouette on a yellow-accented background, with bold "Welcome to Zappos!" overlay. That yellow carries through to the offer block and the SHOP NOW button, giving the email real visual coherence. The offer module is clean and honest: the code `YFNH57A2RP499RZAR` is spelled out, the 05/24/2026 expiry is disclosed, and the asterisk exclusions sit immediately below — not buried in footer fine print.

What's absent: zero demographic or behavioral signal in the creative. No model, no lifestyle edit, no category hook. The Adidas sneaker is deliberately neutral — broad appeal over targeted relevance. The dual Zappos App / Zappos VIP module is a nice touch, offering first-timers two engagement paths beyond the immediate purchase. But the navigation bar (Shoes / Performance / Kids / Sale) is purely functional — no "because you looked at…" messaging anywhere. For a first-touch welcome, that's a wasted opportunity to show the subscriber they're already known.

## 3. What I'd change

1. **Personalize the hero copy to the browsing category** — if Zappos captured browse intent before sign-up, use it: "Welcome to Zappos — your Running gear awaits" beats a generic greeting every time.
2. **Add first-name to subject and hero** — "Your 10% off, [First Name]" is table stakes for welcome sends; the current copy leaves it generic.
3. **Replace "SHOP NOW" with a category-specific CTA** — "Shop Women's Sneakers" or "Browse Running Shoes" would close the gap between the Adidas hero and the destination click.
4. **Amplify the expiry in the offer block** — "Expires in 13 days" set in bolder type would out-perform the small-print date. Make the clock feel real.
5. **Shorten the promo code** — `YFNH57A2RP499RZAR` is 18 characters, brutal to type manually. A "click to apply" shortcut or a cleaner code (WELCOME10) would reduce friction.

## Technical Audit — Zappos Welcome Email

### 1. Technical Summary

Six hard failures across font resource loading (two 404s, four DNS failures) leave Univers entirely unrenderable and Open Sans partially degraded; compliance headers required by Gmail/Yahoo bulk sender policy are missing from the relay capture.

---

### 2. Link & Tracking Issues

**Font URLs — 404 (deprecated Google Fonts version)**
The `@font-face` rules reference Open Sans at path version `/v13/`, which Google Fonts has deprecated:
```
https://fonts.gstatic.com/s/opensans/v13/cJZKeOuBrn4kERxqtaUH3ZBw1xU1rKptJj_0jans920.woff2
https://fonts.gstatic.com/s/opensans/v13/MTP_ySUJH_bn48VBG8sNShampu5_7CjHW5spxoeN3Vs.woff2
```
Both return HTTP 404. Open Sans falls through to the `mso-font-alt: Arial` Outlook fallback and the `[style*="Open Sans"]` override rule catches it in modern clients — degraded but functional.

**Univers font host — DNS unresolvable**
All four Univers weight variants fail at DNS:
```
https://live.upstream.findzen.com/fonts/UniversLTStd-Light.woff2
https://live.upstream.findzen.com/fonts/UniversLTStd.woff2
https://live.upstream.findzen.com/fonts/UniversLTStd-Bold.woff2
https://live.upstream.findzen.com/fonts/UniversLTStd-XBlack.woff2
```
`live.upstream.findzen.com` does not resolve. Univers is entirely unrenderable in any client that attempts to load it; fallback chain (`Helvetica, Arial, sans-serif`) activates. This is a complete font failure, not just degradation.

**Tracking links**
29 click-redirect URLs were skipped by the probe (expected for redirect-based tracking). Destination integrity cannot be confirmed from this audit.

No structural issue, though the `.footer.darkmode` rule sets `color: #210ef4` (bright blue) on dark backgrounds — contrast ratio likely fails WCAG AA for 11px text, but visual review is out of scope here.

### 5. Compliance

**`List-Unsubscribe` header — not captured**
The AgentMail relay did not surface this header. Gmail and Yahoo require `List-Unsubscribe` on all bulk sends; its absence (or relay-stripping) risks inbox placement degradation and potential policy violation.

**`List-Unsubscribe-Post` (RFC 8058) — not captured**
One-click machine unsubscribe required by Gmail bulk sender requirements (enforced since February 2024) for senders above 5,000/day threshold. Not confirmed present.

**Authentication-Results — not captured**
SPF and DKIM pass/fail status cannot be determined from the relay capture. If authentication is failing upstream, deliverability impact is immediate.

> Note: all three compliance findings are relay-capture gaps — the headers may exist upstream and be stripped by AgentMail before reaching the audit pipeline. Confirm against raw SMTP headers or the sending platform's delivery logs before treating these as sender-side failures.
