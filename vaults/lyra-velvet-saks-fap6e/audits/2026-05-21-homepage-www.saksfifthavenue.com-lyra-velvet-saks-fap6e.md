# Homepage snapshot · www.saksfifthavenue.com · 2026-05-21
**Score:** 1/10 · **Type:** Site journey · **2026-05-21**
## Executive summary

- I opened Saks on my phone and hit a wall — literally a "WE'RE SORRY" block page, not a homepage. Instead of Pre-Fall imagery and a Valentino hero, I'm staring at a bot-detection error screen citing "unusual activity" from my IP. This is a security gate, not a brand experience, and it's the only thing visible above the fold.

## What's working

- The error typography is clean and legible — Saks' serif wordmark sensibility carries through even in the sorry state, so at least the brand font feels intentional.
- The blurred background suggests a lifestyle/city image underneath, hinting the real homepage probably has editorial production value.

## What's weak

- **The entire homepage is inaccessible.** I see zero products, zero navigation, zero offers — a dead end on arrival.
- **The error message lists "IP 75.140.9.0"** exposed in plain text — clinical, cold, and jarring for a luxury brand. Saks should know better than to surface raw IP strings to a real shopper.
- **"Rapid taps or clicks" as a trigger reason** is insulting — I'm a mobile-first shopper; fast tapping is literally how I browse. This catches real customers.
- **No fallback or redirect** — the page offers no path forward. No "try again," no link to the app, no customer service contact. Dead end.

## Recommendations

- **Build a luxury-branded fallback page** — if the bot wall fires, the UX should still feel like Saks. A soft "try again" CTA, a link to the iOS app, and a client services number would salvage the experience.
- **Raise the bot-detection threshold for mobile users** — fast taps are a mobile pattern, not a bot signal. Tune the heuristic so real shoppers on 5G don't get blocked.
- **Remove the raw IP address from the visible error copy** — replace with a masked reference ID. Showing the IP is both ugly and unnecessary for a customer-facing message.
- **Add a bypass path for authenticated SaksFirst members** — a recognized Diamond-tier session should never trigger a generic bot block.
