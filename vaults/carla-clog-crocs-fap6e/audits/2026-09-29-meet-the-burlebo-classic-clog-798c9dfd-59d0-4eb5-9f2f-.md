# Technical Audit: Crocs, "Meet the BURLEBO Classic Clog"

## 1. Technical Summary
The HTML source is mostly sound (viewport meta, MSO conditionals, Apple/Gmail hacks, mobile breakpoint at 639px). It has a malformed tracking-pixel tag, 7 images served over plain `http://`, and a hidden third-party pixel with no alt attribute. The compliance and authentication checks are inconclusive because the relay didn't capture the headers.

## 2. Link & Tracking Issues
- **Malformed tag on the open pixel.** The Exact Target pixel is closed with a stray `</custom>`: `<img src="https://click.crocs-email.com/open.aspx?WN3ZTKUR3YPUFIBHLRBKB6MH5A.10202&d=10202&bmt=0" width="1" height="1" alt=""></custom>`. There is no opening `<custom>` tag, so this is invalid markup. Most clients ignore it, but strict parsers and some Outlook/MSO renderers can mishandle it.
- **Raw `&` in the pixel URL.** The `&d=` and `&bmt=` parameters are not escaped as `&amp;`. This is a minor validity issue and is usually tolerated.
- **Unverified click links.** 24 tracking links on `click.crocs-email.com` were skipped by the HTTP probe, so redirect chains, status codes and final destinations are unverified. This is a coverage gap, not a confirmed defect.
- **Second tracking pixel.** `https://demandwarecrocs.demdex.net/event?d_dpid=196107&c_emailopened=Yes&d_dpuid=1c110d5f7d8fbc329b0a8ea915c05b3c631d53c…` is an Adobe Audience Manager open-event pixel. It sits alongside the ET open pixel, so opens are double-counted across systems. The `d_dpuid` value is an identifier embedded in the URL.

## 3. Rendering & Accessibility
- **Missing alt on the demdex pixel.** The `event` image has no `alt` attribute (QA WARN). It is a hidden tracking pixel, so screen-reader impact is low. Adding `alt=""` would still be cleaner.
- **Insecure image sources.** 7 images load over `http://`, all from `image.crocs-email.com/lib/fe66157070650c797512/m/1/`:
  - `9c36c0ef-…png` (App Store badge)
  - `13246762-…png` (Google Play badge)
  - `c4df71ec-…png` (Find Your Store)
  - `e18949ff-…png` (Instagram)
  - `80f68cd8-…png` (Facebook)
  - `51d8144e-…png` (TikTok)
  - `1187ef58-…png` (YouTube)

  Clients that don't proxy images, or that enforce HTTPS, may block them and show a mixed-content warning. Because these images have alt text, blocked images degrade to the alt text. The pixels above are served over HTTPS, so the same host is already HTTPS-capable.
- **Generic `<title>`.** The title is `Crocs`, not the subject line. This is a minor issue that only affects the web-view and browser tab.
- **Other markup.** The `lang`/`xml:lang` attributes, preheader block with `display:none !important`, `format-detection` meta and `x-apple-data-detectors` reset are all present. No issues found beyond the above.

## 4. Personalization & Merge Tokens
No issues found. The visible source contains no unresolved merge tokens (`%%…%%`, `{{…}}`, `[FIRSTNAME]`). The source is truncated, so the body content past the preheader could not be checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` not found (WARN)** and **`List-Unsubscribe-Post` (RFC 8058) not found (WARN).** The QA note says the AgentMail relay may strip these headers. This is unconfirmed, so it isn't a proven sender defect. The sender should be checked against a raw copy of the message.
- **`Authentication-Results` not found (WARN).** SPF, DKIM and DMARC status is unknown for the same relay reason. The From domain `crocs-email.com` matches the tracking domain `click.crocs-email.com`, which is consistent with aligned sending. Alignment is not verified.
- **Footer not visible.** The physical address and the body unsubscribe link fall in the truncated portion of the HTML, so they could not be verified.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Unable to verify. Every click goes through the `click.crocs-email.com` redirector, and the probe skipped all 24 links, so final URLs and any UTM parameters were not observed. No issues are confirmed.

4. Check `List-Unsubscribe` and `List-Unsubscribe-Post` on a direct (non-relay) copy of the message. Gmail and Yahoo bulk-sender rules require one-click unsubscribe.
5. Re-run the audit with the full, untruncated HTML. Resolve the redirect chains on `click.crocs-email.com` to check UTM parameters and destination pages, and confirm the footer address and unsubscribe link.
