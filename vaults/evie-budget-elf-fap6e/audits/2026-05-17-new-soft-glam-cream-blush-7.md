- **Subject line is this email's best asset** — product name + price + "NEW!" + emoji in 33 characters is nearly perfect inbox copy.
- **Hero image earns the scroll** — model application shot with shade swatches and product jar is on-brand and visually cohesive.
- **"INGREDIENTS FOR BUTTER SKIN" copy** connects the blush to e.l.f.'s skin-benefit narrative, reinforcing the broader franchise instead of treating blush as a standalone SKU.

## What's weak

- **Mascara module is recycled creative** — the "sculpt & flush with 1 brush / more lash, less cash" block is the same asset from the 2026-05-15 mascara email, two days ago. A subscriber who reads both notices.
- **"THE CREAM TEAM" cross-sell dilutes the launch** — grouping multiple cream products mid-email splits attention right when the blush has momentum.
- **Target retail section adds length without urgency** — a logo + where-to-buy callout near the bottom doesn't pull toward a click; it just adds scroll depth.
- **No price callout visible in the hero body** — the $7 is in the subject but may not be repeated prominently enough above the fold in the body to reinforce the value prop for anyone who missed it in the inbox.

- 2. **Put the $7 in the hero headline**, not just the subject. "NEW! $7 Cream Blush" as a subhead under the product name makes the value pop without relying on the subject line doing all the work.
- 3. **Replace the mascara cross-sell with a Beauty Squad loyalty CTA** — this is a new product, the ideal moment to prompt a reward point earn. The 2026-05-16 birthday loyalty email showed they have the module ready to use.
- 4. **Tighten the Target section** into a single-line text link or remove it — retail availability is a footnote, not a feature section.

### 3. Rendering & Accessibility

**Empty `<title>` tag**
```html
<title></title>
```
Some email clients (notably newer Outlook builds and Gmail tabs) surface the `<title>` value. An empty title degrades accessibility for screen reader users who navigate by document title.

**9px font size injected via mobile media query**
```css
@media (max-width:660px) {
  .row-6 .column-1 .block-1.heading_block h1 { font-size:9px!important }
}
```
9px is below any accessible minimum (WCAG recommends ≥14px for body text; headings should be larger). This appears to be a layout hack (collapsing a duplicate header block on mobile) but the `!important` override could suppress any other corrective rule. Confirm the target element is truly meant to be invisible, and if so use `display:none` or `max-height:0` instead of a near-invisible font size.

**Link affordance suppression**
```css
#MessageViewBody a { color:inherit; text-decoration: none }
```
This strips underline and color differentiation from all links in Gmail's Android app (which injects `#MessageViewBody`). Inline `color` and `text-decoration` on individual `<a>` tags would be needed to override this intentionally, but the rule as written applies globally.

**Google Fonts blocked by most email clients**
```html
<link href="https://fonts.googleapis.com/css?family=Open+Sans" ...>
<link href="https://fonts.googleapis.com/css?family=Jost" ...>
```
Outlook (all versions), Gmail app, and some corporate clients block external stylesheets. Fallback `Arial, Sans-serif` is specified inline, so rendering degrades gracefully — but Jost (a brand font) will never render in Outlook. Acceptable if intentional; flag if brand consistency in Outlook is a requirement.
