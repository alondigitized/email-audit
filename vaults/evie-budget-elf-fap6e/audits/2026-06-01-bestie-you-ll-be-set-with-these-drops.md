# Bestie, you’ll be set with these drops ✨ 
**Score:** 8/10 · **Type:** Email audit · **2026-06-01**
## Executive summary

- This is e.l.f.'s weekly digest template — the "Highlight Reel" format that bundles recent drops into a scrollable catalog. Set against this week's laser-focused single-product sends (the $5 Main Stain Lip Marker on May 26, the Allure award send on May 30, the $12 lip combo on May 31), this email has no anchor: there's no price in the hero, no specific product call-out, and the subject line gives the subscriber zero reason to open *this* week's edition over any other.
- The welcome offer banner is the most compelling thing in the email — a personal redemption code sitting at the very top — but the rest of the send never builds on it. The "HOT AS E.L.F. THIS WEEK" 2x2 grid comes closest to creating urgency, but the products are unlabeled, so the subscriber is clicking on anonymous squares. That's a direct conversion leak.
- As a periodic housekeeping send, this is competent — clean layout, trusted brand, multiple entry points. But sent in a week with five prior daily promotional emails, this digest risks being the one that trains subscribers to skim.

## What's working

- Welcome offer banner with a personalized redemption code creates above-the-fold perceived value
- "YOUR WEEKLY HIGHLIGHT REEL" branding is consistent with e.l.f.'s irreverent voice — this is clearly a recurring format that builds habit
- Hero image is clean and premium-feeling: the black branded box + pink powder background reads as editorial, not promotional
- "HOT AS E.L.F. THIS WEEK" 2x2 grid with individual SHOP NOW buttons gives four direct click paths for browser-mode subscribers
- Perks bar (free shipping $35+, free gifts $25+, Afterpay, receipt scanning) reinforces value at the bottom without cluttering the hero

## What's weak

- "YOUR NEW OBSESSIONS" thumbnail row is too small — products are unidentifiable at email width, making the section decorative rather than actionable
- Subject "Bestie, you'll be set with these drops ✨" is generic and interchangeable with half the brand's weekly sends — no product name, no price, no specific hook
- Zero prices anywhere in the email body — a stark departure from the playbook that made the $5 Main Stain Lip Marker (May 26) and $12 lip combo (May 31) strong performers
- "HOT AS E.L.F. THIS WEEK" products have no names, no prices, no brief descriptors — you're clicking blind
- Weekly digest framing signals low urgency; nothing in the email creates a reason to act now vs. browsing elfcosmetics.com later tonight

## Recommendations

- 1. **Make the welcome offer code the spine of the email.** The personalized code is the most valuable signal in this send — it should drive the subject, the hero headline, and the first CTA. Restructure: welcome offer redemption first, curated drops second.
- 2. **Add product names and prices to the "HOT AS E.L.F. THIS WEEK" grid.** Even one line — product name + "$9" — per tile would eliminate the anonymous-click problem and create price anchoring.
- 3. **Give this week's digest a news hook.** "We added 5 new drops this week" or a callback to the Allure award (the May 30 send landed at 8/10 precisely because it had a third-party reason to exist) turns a recurring template into a weekly event.
- 4. **Enlarge or cut "YOUR NEW OBSESSIONS."** At current thumbnail size, this section is invisible. Either make the products recognizable or remove the section and use the space for the welcome offer CTA.
- 5. **Put at least one price in the hero block.** Every high-performing e.l.f. send this week anchored on a price. This one doesn't.

### 3. Rendering & Accessibility

**`<title>` tag is empty.**
```html
<title></title>
```
Some clients (iOS Mail, Gmail web) surface the title in browser tabs or notification previews. Empty title is a missed signal and causes validation warnings.

**Invalid `font-family` declaration — empty string as first value.**
```css
font-family:'',Verdana,Sans-serif
```
The leading empty string `''` is invalid CSS. Browsers silently skip it and fall back to Verdana. This pattern is consistent with an unfilled template variable (e.g., a custom font name that was never substituted). Confirm the template variable is bound before send.

**Google Fonts loaded twice with inconsistent specs.**
- In `<head>` (non-MSO only): `https://fonts.googleapis.com/css?family=Jost` — loads default weight only
- In inline `<style>` in `<body>` (all clients): `@import url('https://fonts.googleapis.com/css2?family=Jost:ital,wght@0,100..900;1,100..900&display=swap')` — loads full weight range

Non-MSO clients issue two separate HTTP requests for the same font. The `<link>` variant loads a narrower weight set than the `@import`, creating a race condition where the lighter weight spec could win depending on parse order.

**`tabindex="-1"` on logo link removes it from keyboard tab order.**
```html
<a href="https://links.elfcosmetics.com/…" target="_blank" style="outline:none" tabindex="-1">
```
Combined with `outline:none`, this makes the logo link completely unreachable via keyboard navigation. WCAG 2.1 SC 2.1.1 requires all interactive elements to be keyboard-accessible.

**`#MessageViewBody a` suppresses link underlines globally.**
```css
#MessageViewBody a{color:inherit;text-decoration:none}
```
This Gmail-targeted rule removes underlines from all links inside message body, which may violate WCAG 2.1 SC 1.4.1 (use of color) if link color alone doesn't distinguish them from surrounding text.

**Nested `nl-container` table structure (template-in-template artifact).**
The outer wrapper already establishes `<table class="nl-container">`, and a second identical `nl-container` is rendered inside a `<div>` within a body cell. This is a template composition artifact (a block was embedded inside another block) and can cause double-margin or alignment drift in Outlook.
