## Technical Audit

## 1. Technical Summary
The email is built on a standard table-based, MSO-aware layout with a preheader and a mobile media query. The automated QA run did flag 4 link-probe failures, but all four share one pattern: the tracked redirect resolves to a relative `Location`, which the prober could not follow. These are likely probe artifacts and unconfirmed as real breakage. The HTML supplied is truncated, so only the portions shown could be checked.

## 2. Link & Tracking Issues
- **4 [FAIL] probes, all `unknown url type: '/…'`.** Each `links.elfcosmetics.com/f/a/…` click-tracker returned a relative path instead of an absolute URL:
  - `/products/holy-hydration-thirst-burst-drops?Size=Regular+1+oz+%2F+30+ml` ("Shop Now")
  - `/products/bright-icon-vitamin-c-e-ferulic-serum?Size=Regular+1+oz+%2F+30+ml` ("Shop Now")
  - `/account/login?return_to=%2Faccount` (receipt scanning link)
  - `/pages/mobile-app?lid=r09pgd3sh928&af_reengagement_window=30d&onelink_id=wTtZ&is_retargeting=true&shortlink=email&pid=Email&utm_sou…` (app download link)
- **Likely cause:** a relative `Location` header from the redirect is valid for browsers but not resolved by the QA client. Treat these as unverified, not as confirmed dead links. The relative redirect itself is unusual for an ESP tracker and worth a manual click-through.
- **Receipt-scanning link:** it targets `/account/login?return_to=/account`. Recipients who are not logged in will land on a login wall rather than on the feature. This is inferred from the URL, not observed.
- **Probe coverage:** only 12 of 43 links were probed and 31 were skipped, so the remaining links are unverified.
- **Tracker parameters:** the tracker URLs are opaque, so the click destinations cannot be audited from the source alone.

## 3. Rendering & Accessibility
- **Missing alt text (1 image):** `src="https://links.elfcosmetics.com/q/H6k-A4Gha…"` has no `alt`. The `/q/` path suggests a tracking pixel, so a decorative `alt=""` would be the correct fix.
- **Hero image:** `alt="e.l.f."` is present but uninformative as the only text for a linked image. If images are blocked, the link has no meaningful label.
- **Empty `<title>`:** `<title></title>` is empty. Some clients and screen readers use it.
- **Empty font-family:** `font-family:'',Verdana,Sans-serif` appears in an empty `mobile_hide` block. It is harmless but sloppy.
- **Web font:** the Google Fonts `<link>` is wrapped in `<!--[if !mso]><!-->` and falls back to `Arial,Sans-serif`. This is acceptable.
- **Layout robustness:** tables use `role="presentation"`, `lang="en"` is set, and the VML/MSO namespaces and settings are present.
- **Hidden preheader:** it uses `display:none`, `mso-hide:all` and `max-height:0`, which is correct.
- **Nested `nl-container` tables:** these are repeated inside `html_block` wrappers. This adds weight and nesting depth but isn't a defect on its own.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens such as `{{…}}`, `%%…%%` or `[FIRSTNAME]` appear in the visible source or QA output.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` not found [WARN]:** the QA note says the header may not be captured by the AgentMail relay. This cannot be confirmed as missing at the sender.
- **`List-Unsubscribe-Post` (RFC 8058) not found [WARN]:** the same relay caveat applies. Gmail and Yahoo require one-click unsubscribe for bulk senders.
- **`Authentication-Results` not found [WARN]:** SPF, DKIM and DMARC status is unknown from this capture. The From domain `m.elfcosmetics.com` is a subdomain, which is good practice.
- **Body unsubscribe link and postal address:** neither was visible in the truncated HTML, though the QA probe notes an unsubscribe link is always probed. They are unverified here.
- **Plain-text part:** 13,117 of 15,478 characters (about 85%) are URLs. This is a deliverability warning, caused by long tracker URLs in the text part.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **UTM parameters:** only the app-download link shows visible tracking parameters (`pid=Email`, `shortlink=email`, `utm_sou…`, truncated). The product links show no UTMs in the redirect targets, only `?Size=Regular+1+oz+%2F+30+ml`. UTMs may be added by the ESP tracker, but the probe could not confirm it.
- **Landing page alignment:** both "Shop Now" CTAs point at specific product pages with a pre-selected `Size` variant, which matches the promoted travel trio. The destination content could not be checked because the probes failed.
- **App link:** it carries AppsFlyer OneLink parameters (`onelink_id=wTtZ`, `is_retargeting=true`) and routes through `/pages/mobile-app`. Check that this path handles deep-link and mobile fallback correctly.

## 7. Recommendations
1. Click through the 4 failed tracker links manually, in a browser, to confirm they land on the intended pages. If the relative `Location` redirect is real, ask the ESP to emit absolute URLs.
2. Fix the probe client to resolve relative `Location` headers against the redirect's base URL. Otherwise this check will keep generating false failures.
3. Add `alt=""` to the `/q/` image, or a descriptive `alt` if it is visible content. Consider fuller alt text for the hero image.
4. Populate `<title>` (for example, with the subject line).
5. Capture raw headers from the original delivery (not the relay copy) to verify `List-Unsubscribe`, `List-Unsubscribe-Post`, SPF, DKIM and DMARC.
6. Confirm UTM tagging on product links, and confirm the receipt-scanning link handles logged-out users.
7. Reduce the plain-text URL density by shortening tracker URLs or adding more descriptive text.
