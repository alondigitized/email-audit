# These gift sets are *giving* 🎁
**Score:** 7/10 · **Type:** Email audit · **2026-11-26**
## Executive summary

- This is a gift-set email that opens with a real offer and then drifts into a product catalog. The top banner is the strongest part: "limited time only! YOU ARE SO GIFTED. Get that e.l.f.ing bag + a 7 pc set with every purchase of $50+. Shipping's on us!" It has an offer, a threshold and a CTA. It is also nearly the same offer as the 11/24 "YOU ARE SO GIFTED." send, which promised "up to 7 gifts" and delivered one.
- Below the banner, the gift-wrapped pink boxes and the "KIT THEM SOMETHING GOOD." headline set up a gifting theme. Then the email pivots to three "new!" products: the Glow Reviver flavor balms at $18, the Sheer You Glow duo at $14, and the 10-pc brush kit at $35. The Sheer You Glow duo is the same lip-and-cheek territory as the 11/25 Halo Glow Blushlighter launch, so the product-led streak continues. - Verdict: it's a competent holiday send with clear prices and consistent CTAs, but too long and too repetitive. The Black Friday freebie gets one small banner while four "SHOP NOW" buttons compete underneath.

## What's working

- The top banner states a concrete offer: a free bag and 7-pc set at $50+, plus free shipping.
- The pink gift-box hero fits the "gift sets" subject and the Thanksgiving/Black Friday timing.
- Each product block has a price in the headline ($18, $14, $35) and a white-on-black "SHOP NOW" button.
- The pink and black palette is cohesive, and the black copy panels keep the text readable.
- The "Top Picks for You" row suggests some personalization.

## What's weak

- The banner is small and sits above the hero. It feels like a header, not the main message, so the offer isn't what the eye lands on first.
- The subject promises gift sets. The body shows a duo, a flavor balm pair and a brush kit, and none is clearly labeled a gift set.
- Every product is tagged "new!" while the offer is about gifting. The messaging is mixed.
- Four near-identical black blocks with the same button create a long scroll and no clear primary CTA.
- The grey category bars are blank, wasted space with no imagery. The legal fine print in the footer is tiny.
- The offer is repeated from 11/24, and it's the fifth or sixth send in a week, so cadence fatigue is a risk.

## Recommendations

- 1. Make the free-bag + 7-pc offer the full-width hero, with the dollar threshold and a deadline in large type. Move the gift-box photo underneath.
- 2. Cut the three product blocks to one gifting block, or label each as a gift set with a "gift for X" angle.
- 3. Drop the "new!" tags on gift items. Use "gift-ready" or "under $20" instead.
- 4. Replace the empty category bars with image tiles, or remove them.
- 5. Space this send away from the 11/24 "YOU ARE SO GIFTED." send, or change the creative so it doesn't repeat.

## Technical Audit

## 1. Technical Summary
The HTML is a table-based Braze/Beefree-style build with a preheader, `lang="en"`, `role="presentation"` tables and a mobile media query. Automated QA reports a 30% pass rate. Two of the three FAILs are probably probe limitations rather than broken links. One link does send users to a login wall.

## 2. Link & Tracking Issues
- **Relative redirect targets (probably a probe artifact).** Two tracked links failed with `unknown url type`:
  - "Shop Now" → `/products/squeeze-me-more-lip-balm-duo?Color=Mango+%26+Watermelon`
  - "Receipt scanning…" → `/account/login?return_to=%2Faccount`

  This is the error a Python `urllib`-style client raises when it follows a redirect whose `Location` header is a relative path. Browsers resolve those against the origin, so real recipients likely land fine. It is still worth checking that `links.elfcosmetics.com` returns absolute `Location` values, since some clients and security scanners are stricter.
- **Non-ASCII characters in a redirect target.** The "beauty squad - Download the e.l.f. app" link failed with `'ascii' codec can't encode characters in position 174-176`. A raw non-ASCII sequence, likely a symbol, is in the destination or `Location` header instead of being percent-encoded. Browsers usually tolerate this. Strict parsers and scanners may not, and the cause could not be confirmed from the data.
- **Long tracked URLs.** Every link is wrapped in `links.elfcosmetics.com/f/a/<~300-char token>~~`. This is why the plain-text part is 11,882 of 13,740 characters URLs (86%). Spam filters may weigh a plain-text part that is mostly URLs.
- **Probe coverage.** Only 12 of 41 links were probed, so the other 29 are unverified.

## 3. Rendering & Accessibility
- **Empty `<title>`.** The source has `<title></title>`.
- **Missing `alt`.** One image has no alt text: `src=https://links.elfcosmetics.com/q/NAmpfe3P0rD7Ma0_NQAcNA~~/…`. This is probably the tracking pixel, but the truncated source can't confirm it. Add `alt=""` if it is decorative.
- **Tiny mobile heading.** `.row-6 .column-1 .block-1.heading_block h1{font-size:9px!important}` sets an h1 to 9px under 660px wide. That is below legible and accessible size, unless the heading is intentionally hidden.
- **Duplicate class names.** The first block nests a full `nl-container`/`row-1` table inside the outer `row-1`, which gives duplicate class names. It is harmless for rendering but adds bloat.
- **Web font.** The Google Fonts `<link>` is wrapped in `<!--[if !mso]><!-->` and the font stack falls back to `Arial,Sans-serif`. No issue.

## 4. Personalization & Merge Tokens
No issues found. No unresolved tokens (`{{ }}`, `%%`, `[FNAME]`) appear in the visible source. The HTML was truncated, so later sections were not reviewed.

## 5. Compliance
- **`List-Unsubscribe` and `List-Unsubscribe-Post` not found.** The QA tool notes AgentMail may strip these headers, so this is unconfirmed. It matters because Gmail and Yahoo require RFC 8058 one-click unsubscribe from bulk senders.
- **Authentication-Results not found.** SPF, DKIM and DMARC status is unknown from this capture.
- **Footer not seen.** The truncated source doesn't show the physical address or the unsubscribe link, so CAN-SPAM body requirements couldn't be confirmed. The QA tool says an unsubscribe link was included in probing and reports no failure for it.

## 6. Email-to-Site Continuity
- **Login wall for a promo link.** The "Receipt scanning – Earn rewards anywhere you shop e.l.f." link resolves to `/account/login?return_to=%2Faccount`. Logged-out recipients land on a login form, not a rewards explainer.
- **Product link.** "Shop Now" resolves to a product page with `?Color=Mango+%26+Watermelon`. The variant parameter is correctly encoded, and the page matches the creative.
- **UTM parameters.** These couldn't be verified. The redirect chains weren't followed to the final URL because of the relative-`Location` probe failures, so the destination query strings are unknown.

## 7. Recommendations
1. Check that `links.elfcosmetics.com` returns absolute `Location` headers and percent-encodes non-ASCII characters in the "Download the app" destination. Fix the probe to resolve relative redirects so it doesn't report false FAILs.
2. Point the rewards/receipt-scanning link at a public landing page, or at a login page that returns the user to the rewards destination.
3. Set a real `<title>`, add `alt=""` or descriptive alt to the flagged image, and raise the mobile `h1` above 9px.
4. Verify `List-Unsubscribe` and `List-Unsubscribe-Post` in the raw message from the ESP, not the AgentMail relay. Confirm SPF, DKIM and DMARC alignment for `m.elfcosmetics.com`.
5. Re-run QA on the full, untruncated HTML and probe the 29 skipped links, so the footer, UTMs and remaining tokens can be checked.
