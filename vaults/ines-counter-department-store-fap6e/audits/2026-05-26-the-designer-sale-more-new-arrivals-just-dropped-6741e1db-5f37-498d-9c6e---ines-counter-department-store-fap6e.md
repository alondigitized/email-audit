# The Designer Sale: More new arrivals just dropped
**Score:** 9/10 · **Type:** Email audit · **2026-05-26**
## Executive summary

- Fifteen. That's the count, and this one arrives with at least a slightly defensible hook — "more new arrivals just dropped" is the first thing NM has said in a week that gives me a reason to open besides sheer habit. The red hero lands clean, the offer is in the first line of copy, and the product grid shows me Zimmermann, Valentino Garavani, Rhode, and Charo Ruiz La Perla. Those are my actual brands, and I notice when a brand bothers to get that right.
- That said, I've been NM's most loyal inbox opener for fifteen emails in six days, and the goodwill account is overdrawn. "LIMITED TIME" with zero end date is an empty threat at this point — I've been reading that phrase since email nine. Worse, the loyalty block at the bottom invites me to "join the fast list today" for 15% off. I'm a Circle member. I buy at the counter event. I return at the counter event. Pitching me a signup discount like I wandered in off the street is the kind of mistake that reminds me I'm a name in a batch send, not a known customer.
- I'd click women's shoes or handbags because Valentino Garavani is genuinely in there and I have a documented weakness. I would not forward this to anyone.

## What's working

- **The hero is immediate and legible.** "UP TO 50% OFF" is readable before I've even decided to look — no clever teaser, no buried offer. After Macy's last week with its multi-step confirm flow, I appreciate bluntness.
- **Product selection earns the send.** Zimmermann, Valentino Garavani (both bag and heels), Rhode, Charo Ruiz La Perla — this is a credible edit for a 47-year-old with a real budget. Sephora doesn't try this hard to feel luxe; NM still does, and it shows.
- **Six category CTAs do the navigation work for me.** I'm not forced to hope the hero dumps me into women's shoes. I can go exactly where I intend.
- **Visual hierarchy is clean.** Hero → products → categories, in that order. Nothing fights for attention.
- **"New arrivals" is the one angle that justifies email fifteen.** It's a reason to look again even after the previous four Designer Sale sends. Slim justification, but real.

## What's weak

- **"LIMITED TIME" is meaningless without a date.** Compare to Macy's confirmed-deadline format — that email had a specific action with implied expiry. NM just waves at scarcity and expects me to feel pressure I've stopped feeling.
- **No markdown prices on any product.** I can see the Valentino heels; I can't see that they dropped from $980 to $490. Showing the actual reduction next to the product is the single biggest gap between this and a cart add.
- **The loyalty block is tone-deaf for an existing member.** "Claim your 15% off / join our fast list today" is cold-traffic messaging. I opened fourteen previous emails — I'm not a prospect. Replace this for identified members with an event invite or member-early access tease.
- **Ariat sneakers in a Valentino grid.** Ariat is a fine brand, but it reads as a filler tile in a layout that otherwise signals aspirational luxury. My eye snags on it for the wrong reason.

## Recommendations

- 1. **Put a closing date in the hero.** "Ends June 1" or "Last weekend" printed right under "UP TO 50% OFF" rescues all the urgency this email currently leaves on the table. This is the single highest-lift change.
- 2. **Show the markdown on at least three grid items.** Original price, sale price, product name — that's the information that separates a browse from a click. Zimmermann at $695, now $347 moves me. A photo thumbnail alone doesn't.
- 3. **Segment the loyalty block.** If I'm a Circle member, show me an in-store event preview or a member-only access message. Reserve the 15% signup offer for non-members. The current layout insults me every send.
- 4. **Slow the cadence.** Fifteen emails is not a campaign — it's attrition. Three to four targeted sends for a Designer Sale event is aggressive but manageable; fifteen is the reason I check the unsubscribe link while I'm reading.

### 3. Rendering & Accessibility

**Commented-out viewport meta tags left in `<head>` (lines 3–4 of `<head>` block):**
```html
<!--<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" />-->
<!--<meta name="viewport" content="width=320, initial-scale=0.29">-->
<!--<meta name="viewport" content="width=1024">-->
```
Dead code bloats source. No rendering impact, but indicates template hygiene debt.

**`*[class=X]` attribute selectors throughout the mobile CSS block.** This pattern (`*[class=contenttable]`) requires an exact string match on the `class` attribute. Elements with multiple classes (e.g., `class="contenttable foo"`) will not match. If any element carries compound classes, those responsive overrides silently fail.

**CSS hamburger nav (checkbox hack) will not function in Outlook/Windows** (no `:checked` pseudo-class support). Fallback rendering is unknown from truncated source — confirm a static desktop nav is present for MSO conditional comments.

**`<title>` has a trailing space:** `<title>Neiman Marcus </title>` — minor, no functional impact.

---

### 4. Personalization & Merge Tokens

**`@refid` is a no-op concatenation:**
```html
@refid = CONCAT(@base_refid,"")
```
Concatenating with an empty string produces an identical value to `@base_refid`. This is either a template stub where a suffix (campaign variant, segment code) was never filled in, or dead logic. If `@refid` and `@base_refid` are meant to differ, this is a tracking data gap.

**`@user` has an unresolved dual-scenario comment:**
```html
<!--/* SET @user = HASHED_EMAIL_SHA256 */ -->
```
The comment block instructs the developer to "CHOOSE ONE SCENARIO" — one populates `@user` via a Lookup to `EMAIL_ID`, the other sets it to `HASHED_EMAIL_SHA256`. The SHA256 scenario is commented out. If downstream link parameters or pixels expect a hashed email in `@user`, they are receiving a raw `EMAIL_ID` integer instead. Verify what the click-tracking URLs and any onsite identity resolution expect in the `@user` slot.

**`@uEm` and `@cmdid`** are declared via Lookup from `NM_CRM_Feed` but their usage is not visible in the truncated source. If either is passed as a query parameter in tracking URLs and the CRM lookup returns null for a subscriber, URLs will contain empty parameter values.

### 5. Compliance

**`List-Unsubscribe` header not detected (QA WARN).** This header is required by Gmail and Yahoo for bulk senders (>5k/day) under their 2024 enforcement. Its absence — even if attributable to AgentMail relay stripping — means one-click unsubscribe is not surfaced natively in those clients, increasing spam complaint risk.

**`List-Unsubscribe-Post` header not detected (QA WARN / RFC 8058).** Required companion to `List-Unsubscribe` for one-click compliance. Gmail uses this to trigger the unsubscribe endpoint without opening a browser. Missing = users must click through to a landing page, which degrades compliance posture.

**`Authentication-Results` header not found (QA WARN).** SPF and DKIM status are unverifiable through the AgentMail relay. Confirm SPF/DKIM/DMARC pass on the sending domain `e.neimanmarcus.com` directly with the ESP — do not rely on relay-captured headers.

**Plain-text part is 87% URLs by character count (5,315 / 6,089 chars).** Spam filters (SpamAssassin, Gmail heuristics) penalize plain-text bodies that are nearly all URLs. A properly generated plain-text alternative should contain the email's readable content, not just link dumps.
