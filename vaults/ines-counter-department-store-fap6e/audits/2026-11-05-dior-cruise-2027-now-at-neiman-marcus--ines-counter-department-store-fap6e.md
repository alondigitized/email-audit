The HTML is truncated and the relay stripped the headers, so compliance, link and continuity checks can't be confirmed either way. ## 2. Link & Tracking Issues
- **14 tracking links not probed.** QA skipped them as click-redirect domains, so their destinations and status codes are unverified.
- **Plain-text part is mostly URLs.** QA reports 2652 of 3133 characters (about 85%) are URLs, which points to long redirect URLs in the text alternative. This is a mild spam-filter and readability risk, not a confirmed bug.
- **Unresolved tokens in hrefs can't be ruled out.** The truncated source doesn't show the link bodies, so I can't check for unresolved `@refid`, `@uEm` or `@cmdid` values.

## 3. Rendering & Accessibility
- **No `lang` attribute.** The tag is `<html xmlns="http://www.w3.org/1999/xhtml">`, so screen readers have no declared language.
- **Zoom blocked.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` prevents pinch-zoom, which fails WCAG 1.4.4 on clients that honor it.
- **CSS hamburger menu.** It uses `.navbar-checkbox:checked ~ .menu` inside the `@media (max-width: 600px)` block. The `:checked` technique is unsupported in Gmail and most Outlook clients, and the fallback isn't visible in the truncated source.
- **Attribute selectors that break on multiple classes.** `*[class=contenttable]`, `*[class=hide]` and `*[class=mobile]` are exact-match selectors, so any element with a second class won't get the mobile override.
- **Invalid font stack.** `.disclaimerText` uses `font-family: Arial, Helvetica, 'sans-serif'`. Quoting `sans-serif` turns it into a font name rather than the generic fallback.
- **Alt text and table roles.** I can't assess these because the body is truncated.

## 4. Personalization & Merge Tokens
- **No rendered merge tokens visible.** Nothing in the visible portion is an unresolved `%%…%%` or `{{…}}` token.
- **Authoring comment left in the delivered HTML.** It reads `<!--REQUIRED variables: @email … Lookup("NM_Subscriber_New_Consolidated", …) … Lookup("NM_CRM_Feed", "uEm"…) CHOOSE ONE SCENARIO BELOW --> <!--/* SET @user = HASHED_EMAIL_SHA256 */ -->`.
  - It exposes internal data extension names and lookup fields (`NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`, `uEm`, `cmdid`).
  - "CHOOSE ONE SCENARIO" suggests the template wasn't fully cleaned before send.
  - The comment also sits before the DOCTYPE.

- **No Authentication-Results header.** SPF, DKIM and DMARC status is unknown. The sender is `NeimanMarcus@e.neimanmarcus.com`, which is a subdomain of `neimanmarcus.com`, so alignment can't be verified here.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)

- **Possible tracking scheme.** The template references `@refid` and `@base_refid`, so the campaign may use a `refid`/`cmdid` scheme rather than UTMs. That is only inferred from the comment.
