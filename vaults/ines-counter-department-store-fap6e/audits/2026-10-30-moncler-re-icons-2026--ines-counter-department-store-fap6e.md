## Technical Audit

## 1. Technical Summary
The visible source is a standard table-based SFMC email with responsive and hamburger-nav CSS. It has one confirmed code-level problem: internal ESP template notes left in the delivered HTML. The source is truncated, so the QA warnings about headers and links can't be checked against the body.

## 2. Link & Tracking Issues
- 15 tracking links were skipped because they are click-redirect domains, so none were probed. Destination validity, redirect chains and 404s are unverified. This is a coverage gap, not a confirmed defect.
- The plain-text part is about 85% URLs (2,840 of 3,325 chars). That is above the 70% warning threshold. It suggests the text alternative is mostly raw tracking links with little readable copy, which can add a small spam-filter signal.

## 3. Rendering & Accessibility
- **Template notes in delivered HTML:** The source opens with a developer comment (`<!--REQUIRED variables: @email ... @base_refid ... Lookup("NM_Subscriber_New_Consolidated", ...) ... Lookup("NM_CRM_Feed", "uEm", ...) CHOOSE ONE SCENARIO BELOW -->`) and a second comment, `<!--/* SET @user = HASHED_EMAIL_SHA256 */ -->`.
  - This exposes internal data extension and field names (`NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`, `uEm`, `cmdid`) to every recipient.
  - It also adds payload weight.
  - It sits before the `<!DOCTYPE>`. Content ahead of the doctype can trigger quirks mode in some legacy clients.
- **Missing language attribute:** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang` attribute. Screen readers can't pick the correct pronunciation rules.
- **Zoom disabled:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` blocks pinch-zoom on iOS and Android, which is a WCAG 1.4.4 concern.
- **Generic title:** `<title>Neiman Marcus </title>` is generic and has trailing whitespace. It is not tied to the subject, "Moncler Re/Icons 2026".
- **Hamburger nav:** It relies on a checkbox hack (`.navbar-checkbox:checked~.hamburger/.menu`) inside `@media (max-width:600px)`.
  - Gmail (including GANGA) and some Android clients don't support `:checked`, so the nav may not open there.
  - The `*[class=...]` attribute selectors are also fragile. Gmail strips some of them, and they only match elements whose class is exactly that value.
  - I can't confirm any fallback, because the body is truncated.
- **Legacy CSS:** `.ReadMsgBody` is an Outlook.com-era hook and is now dead code. This is minor.
