# Your $50-$1,250 gift card is waiting…
**Score:** 8/10 · **Type:** Email audit · **2026-06-06**
## Executive summary

- I already opened the June 4th version of this exact email — the one with the $50–$1,250 tiers laid out, the code visible, the whole event explained — and gave it an 8. So when "Your gift card is waiting" landed this morning, my first reaction was: *you mean the one you already told me about twice?* The "Your" in the subject borrows intimacy it hasn't earned. There's no name, no tier confirmation, no signal that Neiman Marcus knows whether I've already spent or am one purchase away from qualifying. It reads like a retargeting blast that got dressed up with an ellipsis.
- That said — the creative itself is clean. The hero renders immediately, the tiers are right there in the table, the promo code JUNEGC is front and center, and the product grid below features names I'd actually browser: Oscar de la Renta, Jimmy Choo, Jacquemus, Chloé, Veronica Beard. These are brands for my tier, styled for my age. The email knows who it's dressing.
- What kills the momentum is the bottom half: six separate SHOP buttons — SHOP WOMEN'S, SHOP SHOES, SHOP WOMEN'S CLOTHING, SHOP HANDBAGS, SHOP NEW, SHOP JEWELRY — strung out in a grid with equal visual weight. Compare this to Sephora's June 5th "LAST DAY" send, which despite mislabeling me with a wrong name at least committed to one destination. Here I'm handed six equally-urgent nowhere-buttons and expected to pick. I'll mark it read, and if the event actually expires soon, I'll find out from the next email in the series.

## What's working

- Tier table and promo code JUNEGC are above the fold with no hunting — the offer is the hero
- Designer product grid (Oscar de la Renta, Jacquemus, Jimmy Choo, Chloé, Veronica Beard) speaks to a woman who shops at this spend tier
- "ONLINE ONLY" label is prominent — no store-vs-online confusion
- Renders cleanly — no broken images, no overlapping text, no lorem ipsum
- "Get rewarded two ways when you shop new collections" is a smart double frame: new arrivals AND earn-back

## What's weak

- "Your gift card is waiting" with no name and no tier status is fake personalization — Macy's at least uses my surname on triggered confirmation emails
- No deadline visible in the hero; "waiting" implies urgency but there's nothing for it to land on
- Six competing SHOP CTAs flatten the hierarchy entirely; there's no single action to take
- This is the same event from June 4th with no new information — a re-send without an honest reason to re-open
- Fine print spans the entire bottom of the email; it doesn't feel hidden but it makes the offer feel complicated before I've even decided to spend

## Recommendations

- 1. **Put my name and tier status in the hero** — "Ines, your $50 gift card is waiting" with a note on where I stand vs. the qualifying threshold would make this feel like a real nudge rather than a broadcast
- 2. **Add a hard deadline** — even "Offer ends June 8" gives the "waiting" framing actual teeth
- 3. **Collapse six SHOP buttons to one** — "Shop Qualifying Collections" as a single CTA under the tier table would keep the eye moving downward
- 4. **Shrink or drop the product grid** — the event creative stands on its own; eight products plus six shop buttons is inbox clutter on a follow-up email I've already seen
- 5. **Own the re-send** — "You haven't earned yet — still time to qualify" tells me this targets non-converters; without that signal it just looks like they forgot they sent me this
- **Subject Alt A:** `Ines, your gift card expires soon — code JUNEGC`
- **Subject Alt B:** `Still time to earn up to $1,250 back before it's gone`
- **Preheader Alt A:** `Spend $250+ by [date] — JUNEGC applies at checkout on new arrivals`
- **Preheader Alt B:** `Tiers start at $250. Here's what you'd earn on your next purchase.`

### 3. Rendering & Accessibility

**`maximum-scale=1` in active viewport meta tag.**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">
```
Disabling pinch-to-zoom fails WCAG 1.4.4 (Resize Text, Level AA). Remove `maximum-scale=1`.

**Three dead viewport meta tags left in source (commented out).**
```html
<!--<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" />-->
<!--<meta name="viewport" content="width=320, initial-scale=0.29">-->
<!--<meta name="viewport" content="width=1024">-->
```
Template hygiene issue; no functional impact but indicates accumulated copy-paste debt. The `user-scalable=no` variant would have the same WCAG 1.4.4 violation as above.

**iOS 9 webkit animation bugfix is present.**
```css
body { -webkit-animation: bugfix infinite 1s; }
@-webkit-keyframes bugfix { from { padding: 0; } to { padding: 0; } }
```
iOS 9 is end-of-life (2016). This adds parse overhead with no benefit on any current client. Safe to remove.

**`*[class=...]` attribute selectors used throughout mobile CSS.** This pattern (e.g., `*[class=contenttable]`) is a legacy hack for Gmail's pre-2016 class-stripping behavior. Modern Gmail supports standard class selectors. Not a breakage, but produces unnecessary specificity complexity.

**`<title>Neiman Marcus </title>` has a trailing space.** Minor; no functional impact.

---

### 4. Personalization & Merge Tokens

**SHA-256 hashing of `@user` is commented out.**
```amscript
<!--/* SET @user = HASHED_EMAIL_SHA256 */-->
```
As deployed, `@user` is set via:
```amscript
@user Lookup("NM_Subscriber_New_Consolidated", "EMAIL_ID", "EMAIL_ADDRESS", @email)
```
This returns the raw `EMAIL_ID` integer, not a hashed email address. If `@user` is appended to any tracking URL or passed to an analytics endpoint, it exposes an internal subscriber identifier rather than the intended hashed value. **Confirm whether `@user` appears in any link parameters before the next send.**

**"CHOOSE ONE SCENARIO BELOW" requires manual pre-send selection.** The template comment indicates two deployment paths exist and one must be manually activated. This is a human-error risk point; no automated guard is visible in the source.

**`@refid = CONCAT(@base_refid,"")` is a no-op.** Concatenating with an empty string serves no purpose; likely a copy-paste artifact from a template that previously appended a suffix.

**Four separate `Lookup()` calls to two data extensions** (`NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`) each querying by `EMAIL_ADDRESS`. At high send volume, batching `NM_CRM_Feed` lookups into a single `LookupRows()` call reduces query overhead, but this is a performance note, not a correctness issue.
