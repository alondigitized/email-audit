## Technical Audit

## 1. Technical Summary
The HTML is a table-based, XHTML 1.0 Transitional layout with redirect-wrapped tracking links. The automated QA found two failures: an empty greeting slot (`Hi ,`) and a missing plain-text part (0 chars). Several compliance and authentication checks can't be verified from the captured data.

## 2. Link & Tracking Issues
- All visible links go through the opaque redirector `https://app.sephora.com/T/v61000001a19c9c2783b48f6b369fb45280/…?__dU__=…`. The destination can't be read from the source.
- QA probed 12 material links and skipped 45. No probe failures were reported, so there are no confirmed broken links. The skipped links, mostly footer and social, are unverified.
- The open-tracking pixel is `https://app.sephora.com/O/AQEAAZcF2g…`. It is hidden with `display:none; max-height:0; font-size:0; mso-hide:all` and has no `alt`, `width` or `height`. This is the source of QA's "Image missing alt text" finding.

## 3. Rendering & Accessibility
- **Fixed width:** the wrapper table sets `style="min-width:700px; width:700px"`. The only media query is `@media only screen and (max-width:480px)`, and it contains no rule that relaxes this width. On narrow viewports the email will likely scroll horizontally. It also conflicts with `viewport … maximum-scale=1`.
- **Malformed CSS in the media query:** `<!--[if mso]> img.mso-size {…}<![endif]-->` sits inside the `@media` block of a `<style>` element. Non-Outlook parsers read those tokens as part of the selectors. The `img.mso-size` rule is invalid, and the next selector (`<![endif]--> .mobileHeaderTierRouge`) is likely dropped too. The Outlook-only sizing does not apply as intended, and `.mobileHeaderTierRouge` mobile sizing may be lost.
- **Invalid meta value:** `<meta name="robots" content="no index">` should be `noindex`. It has no practical effect in email.
- **JSON-LD:** the `<script type='application/ld+json'>` block has `"discountCode": ""` and a bare `"@type": "PromotionCard"`, which is not a valid schema.org type. Most clients strip scripts anyway, and it may be rejected by those that read it.
- **Plain-text part:** QA failed this check because the text version is 0 chars. Text-only clients and some spam filters will get no content.
- **Alt text:** only the hidden tracking pixel was flagged, so there is little real accessibility impact. The truncated source doesn't allow checking other images.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** the greeting renders as `Hi ,` with the first-name field empty. No raw `{{token}}` syntax was observed. The fallback appears to render an empty string instead of a default such as "Hi there,". I couldn't confirm this from the truncated source and am relying on the QA result.

## 5. Compliance
- **List-Unsubscribe / List-Unsubscribe-Post:** QA did not find either header. QA notes that the AgentMail relay may not capture them, so this is unverified, not a confirmed defect. Without RFC 8058 one-click support, Gmail and Yahoo bulk-sender requirements are at risk if the headers are truly absent.
- **Authentication-Results:** not captured, so SPF, DKIM and DMARC status are unknown. The From domain `beauty.sephora.com` can't be assessed.
- **Footer unsubscribe link and physical address:** the truncated source doesn't show them. QA states an unsubscribe link is always included in link probing, but the result isn't shown. Neither could be confirmed.

## 6. Email-to-Site Continuity
- UTM parameters can't be evaluated. The visible links are redirect-wrapped and the source is truncated, so the final landing URLs are unknown.
- Nothing in the data shows landing-page misalignment. The preheader ("The Sephora Savings Event is about to begin.") is consistent with the subject.

## 7. Recommendations
1. Add a fallback to the greeting merge field (e.g., "Hi there,"), or suppress the greeting when the name is empty.
2. Add a multipart/alternative text part with a real plain-text body, including the unsubscribe URL.
3. Move the `<!--[if mso]>` block out of the `@media` rule, or put Outlook styles in a conditional `<style>` block. Then check that `.mobileHeaderTierRouge`, `.mobileHeaderTierVIB` and the other rules after it still apply.
4. Replace `min-width:700px; width:700px` with `width:100%; max-width:700px`, or add a mobile override.
5. Add `alt=""`, `width="1"` and `height="1"` to the tracking pixel.
6. Re-run the audit against the raw MIME, not the relay copy, to verify `List-Unsubscribe`, `List-Unsubscribe-Post` (RFC 8058) and SPF/DKIM/DMARC alignment.
7. Fix `content="no index"` to `noindex` and drop or correct the JSON-LD block. Both are low priority.
8. Follow the redirect chains for the primary CTAs to check landing URLs and UTM parameters.
