- The black hero block is clean and editorial — "Brand New Styles Just Landed" reads with authority and matches the Neiman Marcus tone I actually trust.

- "Shop Women's" and "Shop All Women's New Arrivals" are clear verb-plus-noun CTAs — no lazy "Discover" copy anywhere.

## What's weak

- Half the email is men's — Ferragamo, Burberry plaid, men's trousers — I did not open this for him, and I resent the vertical real estate.
- Zero offer. No percentage off, no loyalty event, no free shipping minimum — nothing to make me pull the card today versus tomorrow versus never.
- My InCircle membership is completely invisible. Macy's at least puts a points reminder in the hero; NM treats me like a stranger here.
- The "1,000+" number in the subject creates a real expectation of curation or surprise; what I got was a 12-item product grid with no context for why these twelve, why now.
- After back-to-back editorial sends (Mombasa, La Vacanza), pivoting to a generic new-arrivals grid with no offer or narrative feels like NM lost the thread entirely.

- 2. **Lead with one hero product at price** — the Cult Gaia bag or the Prada heel, shot large, named, priced. One item I can picture on myself is worth more than twelve thumbnails.
- 3. **Add an InCircle call-out in the hero** — even a single line: "InCircle members: double points on all new arrivals this week." That is the difference between browse and buy for me.
- 4. **Give the 1,000 a filter** — break it down: "230 new shoes, 180 ready-to-wear, 90 bags." Make the number feel like a map, not a boast.

### 1. Technical Summary

The AMPscript template retains a partially-disabled variable scenario and a near-empty plain-text body dominated by URLs, both of which are active spam-signal contributors.

### 2. Link & Tracking Issues

**Notes:**
- The plain-text alternative appears to be auto-generated from links only, with no prose content. Spam filters (SpamAssassin, Postfix content filters) treat a plain-text ratio this high as a strong spam signal. A minimal prose summary of the email content should be prepended.

### 3. Rendering & Accessibility

**Viewport experimentation debt:** Three viewport meta variants are present but commented out directly above the live one:

```html
<!--<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" />-->
<!--<meta name="viewport" content="width=320, initial-scale=0.29">-->
<!--<meta name="viewport" content="width=1024">-->
```

These are dead code and indicate prior rendering instability. Not a current bug, but a maintenance risk if a future editor uncomments the wrong line.

**Interactive hamburger menu (checkbox hack):** The template implements a CSS-only mobile nav using `:checked ~` selectors:

```css
.mobileCont:checked~table *[class=contentInteractive] { display: block !important; }
```

This pattern works in Apple Mail but is silently ignored in Gmail (web and app) and all Outlook versions. If this nav is functional content rather than decorative, users on Gmail/Outlook see neither the menu nor its fallback — the interaction simply disappears.

**iOS9 animation workaround still present:**

```css
body { -webkit-animation: bugfix infinite 1s; }
@-webkit-keyframes bugfix { from { padding: 0; } to { padding: 0; } }
```

iOS 9 is end-of-life (2019). This fires a real (no-op) animation on every modern Apple Mail render. Safe to remove.

**`alt` attributes:** Not verifiable from the truncated source, but image-heavy NM templates historically omit or leave `alt=""` on decorative images. Should be confirmed in full source.

**`<title>` tag has trailing whitespace:** `<title>Neiman Marcus </title>` — minor, but shows in browser tab previews and some screen reader announcements.

---

### 4. Personalization & Merge Tokens

**Ambiguous `@user` variable scenario:**

The template header contains this instruction followed by a conflicting definition:

```html
<!-- CHOOSE ONE SCENARIO BELOW -->
<!--/* SET @user = HASHED_EMAIL_SHA256 */ -->
```

The SHA256 scenario is commented out using `/* */` inside an HTML comment (`<!-- -->`). The live path sets `@user` via a Lookup to `NM_Subscriber_New_Consolidated`. This is correct behavior, but the dead SHA256 block is fragile: AMPscript parsers may handle `<!-- /* */ -->` differently across SFMC versions, and the instruction "CHOOSE ONE SCENARIO BELOW" implies this is a template decision point that should be resolved and removed from production sends.

**No-op CONCAT on `@refid`:**

```
@refid = CONCAT(@base_refid,"")
```

Concatenating with an empty string is a no-op. This is either a placeholder for a suffix that was removed or a vestigial pattern. If the suffix was intentional (e.g., a split-test suffix), its absence is a tracking gap.

**Silent Lookup failure exposure:** Four separate data lookups (`NM_Subscriber_New_Consolidated` × 2, `NM_CRM_Feed` × 2) run at render time. SFMC Lookup returns an empty string on miss, not an error. If `@uEm` or `@cmdid` are used in tracking URLs and resolve empty for a subset of subscribers, those links will silently drop CRM identifiers without any send-time warning.

**Gmail/Yahoo one-click unsubscribe requirement:** Since February 2024, Gmail and Yahoo require bulk senders (>5k/day) to support RFC 8058 one-click unsubscribe via `List-Unsubscribe-Post`. Its absence is a deliverability violation for those ISPs, not just a compliance recommendation.

**SPF/DKIM:** The sending domain `e.neimanmarcus.com` is a dedicated ESP subdomain. Authentication-Results not appearing in the QA relay suggests headers were stripped or not captured — this needs to be verified against raw message headers from a real inbox delivery, not the relay snapshot.

### 6. Email-to-Site Continuity

UTM parameters on the 26 tracked links cannot be confirmed without resolving the redirect chain (all were skipped by QA). The following should be verified manually:

- `utm_source` — should be `email` or equivalent, not a generic campaign ID
- `utm_medium` — should be `email`
- `utm_campaign` — should match `@base_refid` or the campaign calendar entry
- `utm_content` — CTA-level differentiation (header nav vs. hero vs. product tile)

The `@refid` no-op CONCAT (see §4) may mean campaign attribution is correct but lacks the intended content-level granularity if the suffix was meant to differentiate module positions.

3. **Replace the URL-only plain-text body** with a short prose summary (2–4 sentences) followed by the link list. A 90% URL ratio is a reliable spam trigger.
