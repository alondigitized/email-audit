- The grid skews toward younger evening pieces like the red slip dress and the Alice + Olivia. Nothing speaks to a 47-year-old beauty customer.

## Technical Audit

## 1. Technical Summary
The visible HTML head is structurally sound for a table-based email. It ships internal ESP template comments, and its viewport meta blocks user zoom. The QA run flagged only header and plain-text warnings, with no hard failures. The HTML source is truncated, so the body (links, images, footer) could not be inspected.

## 2. Link & Tracking Issues
- **Not verified:** 31 tracking links were skipped by the QA probe (click-redirect domains), so none were checked for resolution, redirect chain or dead destinations.
- **Plain-text part:** 5,862 of 7,809 characters (~75%) are URLs. The text alternative is mostly raw tracking links, which is a spam-filter signal and poor for text-only readers.
- No broken links were confirmed in the visible source.

## 3. Rendering & Accessibility
- **Zoom blocked:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` disables pinch-zoom on mobile. This fails WCAG 1.4.4 (Resize Text). Remove `maximum-scale=1`.
- **Generic title:** `<title>Neiman Marcus </title>` is generic and has a trailing space. It is low impact, but it is the only document-level label.
- **Content before DOCTYPE:** a large comment block precedes `<!DOCTYPE ...>`. This can push legacy engines (Outlook/Word-based) into quirks mode.
- **CSS-only hamburger nav:** the mobile nav depends on `.navbar-checkbox:checked~.menu`, with `.menu{display:none}`. Gmail and some Android clients don't support `:checked`, so the menu may be unreachable there. I could not see whether a fallback link row exists in the truncated source.
- **Fragile selectors:** the `*[class=contenttable]` and `*[class=mobile]` selectors only match an exact class attribute. Any element with multiple classes will silently skip the mobile overrides.
- Image alt text and `role="presentation"` usage could not be assessed because the source is truncated.

## 4. Personalization & Merge Tokens
No issues found in the visible source. The `@email`, `@refid` and `@user` variables appear only inside the leading comment, which is not rendered. Body tokens could not be checked.

**Template leakage** (a code-hygiene issue, not a merge failure): the shipped HTML begins with a developer comment. It exposes internal Data Extension names (`NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`), lookup fields (`EMAIL_ID`, `uEm`, `cmdid`) and a "CHOOSE ONE SCENARIO BELOW" instruction. The comment also contains an unbalanced-parenthesis `Lookup(...))` expression. Strip comments in the production render.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication)
- **[WARN] List-Unsubscribe not found.** The QA note says AgentMail may not capture the header, so this is unconfirmed rather than a proven sender defect.
- **[WARN] List-Unsubscribe-Post (RFC 8058) not found.** The same caveat applies. Gmail and Yahoo require one-click unsubscribe for bulk senders, so check the raw headers at the origin.
- **[WARN] Authentication-Results not found.** SPF, DKIM and DMARC status is unknown through the relay. The From domain is `e.neimanmarcus.com`, so check it against the original message headers.
- **Footer:** the physical address and unsubscribe link are not in the truncated source, so they could not be verified.

## 6. Email-to-Site Continuity
No issues found that can be confirmed. UTM parameters and landing-page alignment could not be assessed, because the 31 tracking links were not resolved and the source is truncated.

## 7. Recommendations
1. Remove `maximum-scale=1` from the viewport meta (accessibility).
2. Strip the template comment block, including the DE and field names, from the production render. Place whatever remains after the DOCTYPE.
3. Confirm `List-Unsubscribe` and `List-Unsubscribe-Post: List-Unsubscribe=One-Click` in the raw headers at the origin, not through the relay.
4. Verify SPF, DKIM and DMARC alignment from the original message.
5. Rebalance the plain-text part so it has descriptive copy rather than ~75% raw URLs.
6. Confirm the hamburger nav has a non-`:checked` fallback for Gmail and Android.
7. Re-run the audit with full HTML and resolved tracking links, so footer compliance, alt text and UTM continuity can be checked.
