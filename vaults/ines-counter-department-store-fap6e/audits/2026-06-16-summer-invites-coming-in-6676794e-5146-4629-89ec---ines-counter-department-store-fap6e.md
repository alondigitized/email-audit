## Technical Audit — Neiman Marcus "Summer invites coming in?" (2026-06-19)

---

### 1. Technical Summary

The email sends cleanly against legacy email-client compatibility targets but carries meaningful deliverability risk from an unverifiable authentication chain and a plain-text body that is almost entirely tracking URLs. Two compliance headers are absent from what the relay captured, and AMPscript setup comments indicate manual, error-prone variable selection logic that has not been cleaned up before send.

---

### 2. Link & Tracking Issues

**35 tracking links skipped by QA probe.**
All outbound links route through a click-redirect domain; none could be probed for 4xx/5xx errors or redirect destination. Broken destination URLs would be invisible in pre-send QA under this setup.

**Plain-text body is 70% URLs (3,138 / 3,658 chars).**
Spam filters (SpamAssassin `RATIO_URL_TO_TEXT`, Gmail scoring) penalize high URL density in plain-text parts. A plain-text alternative should be human-readable prose with only the most critical links; all tracking URLs should be stripped or replaced with short descriptive links.

---

### 3. Rendering & Accessibility

**Commented-out viewport variants left in `<head>`.**
Three alternative `<meta name="viewport">` tags are present but commented out:
```html
<!--<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" />-->
<!--<meta name="viewport" content="width=320, initial-scale=0.29">-->
<!--<meta name="viewport" content="width=1024">-->
```
These are dead code and suggest unresolved testing ambiguity. They should be removed before production.

**CSS checkbox-hack interactive nav has near-zero email client support.**
The hamburger menu relies on `:checked` pseudo-class selectors (`.mobileCont:checked~table`, `.navbar-checkbox:checked~`) and CSS transitions. These are unsupported in Outlook (all versions), Gmail (web + app), and Yahoo Mail. The fallback behavior — hidden menu with no fallback disclosure — degrades navigation silently on the majority of clients.

**No `alt` text confirmed in truncated source for image-heavy layout.**
The HTML is image-table-based; no `alt` attributes are visible in the provided excerpt. If images are suppressed (Outlook default, low-bandwidth), recipients see a blank email. This also fails WCAG 2.1 SC 1.1.1 and many ISP rendering checks.

**`-webkit-animation: bugfix` iOS 9 hack is present in production CSS.**
```css
body { -webkit-animation: bugfix infinite 1s; }
@-webkit-keyframes bugfix { from { padding: 0; } to { padding: 0; } }
```
iOS 9 is end-of-life. This is a no-op performance cost and should be removed.

---

### 4. Personalization & Merge Tokens

**Unresolved dual-path `@user` variable.**
The AMPscript block header reads:
```
@user Lookup("NM_Subscriber_New_Consolidated", "EMAIL_ID", "EMAIL_ADDRESS", @email)
```
Then immediately below:
```
<!--/* SET @user = HASHED_EMAIL_SHA256 */ -->
```
The comment `CHOOSE ONE SCENARIO BELOW` is still in the production send. If the hashed-email branch should be active, it is currently commented out and `@user` resolves to `EMAIL_ID` instead. If `EMAIL_ID` is the intended value, the dead comment block should be removed.

**`@refid = CONCAT(@base_refid,"")` is a no-op.**
Concatenating with an empty string performs no transformation. If this was intended to append a suffix (e.g., a campaign variant code), the suffix was omitted. If `@refid` is just an alias for `@base_refid`, replace with a direct assignment.

**Two separate lookups against `NM_Subscriber_New_Consolidated` for `@user` and `@emailid` using the same key.**
```
@user  Lookup("NM_Subscriber_New_Consolidated", "EMAIL_ID", "EMAIL_ADDRESS", @email)
@emailid Lookup("NM_Subscriber_New_Consolidated", "EMAIL_ID", "EMAIL_ADDRESS", @email)
```
Both return the same field (`EMAIL_ID`) from the same DE on the same key. One of these is redundant; intended behavior should be confirmed — likely one was meant to return a different column.

---

### 5. Compliance

**`List-Unsubscribe` header not captured by AgentMail relay.**
This header is required under Google/Yahoo bulk-sender requirements (≥5k/day to Gmail) and strongly recommended under CAN-SPAM. Its absence in the relay capture means one-click unsubscribe is either missing or was stripped. Must be verified against raw SMTP headers, not the relay representation.

**`List-Unsubscribe-Post` (RFC 8058) header not found.**
Gmail and Apple Mail use this for native one-click unsubscribe UI. Without it, Gmail downgrades the unsubscribe flow to a redirect, increasing friction and complaint risk.

**`Authentication-Results` header not found.**
SPF, DKIM, and DMARC pass/fail status cannot be confirmed. The sending domain is `e.neimanmarcus.com` (ESP subdomain); its DKIM alignment against `neimanmarcus.com` in the `From:` header should be verified to confirm DMARC `relaxed` alignment passes. Absence in the relay capture does not confirm failure, but it cannot be ruled out.

### 6. Email-to-Site Continuity

**Cannot validate UTM parameters or landing page destinations.**
All 35 links are wrapped in click-redirect tracking URLs that the QA probe could not resolve. It is not possible to confirm:
- Whether UTM params (`utm_source`, `utm_medium`, `utm_campaign`) are appended correctly
- Whether destination pages are live and returning 200
- Whether campaign-specific landing pages exist and are consistent with email content

A secondary probe through the redirect chain (or pre-send link audit via a click-tracking report) is required.
