# $10 off your $50 purchase⁺ or $20 off your $100 purchase⁺ in store or online (Terms & excl. apply) ends today!
**Score:** 9/10 · **Type:** Email audit · **2026-05-25**
## Executive summary

- This is Ulta's urgency reminder for the exact same tiered discount that landed four days ago on 5/21 — "$10 off $50 / $20 off $100" — with "ends today!" appended to the subject as the only meaningful differentiation. The creative is clean and the offer is legible; Ulta executes this template flawlessly. The strategic problem is that it's the fourth Ulta send in roughly five days (5/21 tiered discount, 5/20 Benefit spotlight, and two mystery-offer sends in early May), and this version actually *removes* the name personalization ("Marisol") that made the 5/21 version feel targeted. Stripping the name from the subject for a reminder send is a step backward.
- The "free mystery gift" teaser below the hero discount is a nice sweetener, but it competes for attention without resolving — subscribers don't know what they're getting, so it's a curiosity hook more than a conversion driver. The product grid is rich but somewhat generic; nothing below the hero is pinned to any specific category preference.
- Net judgement: technically competent, strategically lazy. The single lever pulled here was "add deadline urgency"; everything else is copy-paste from 5/21. A subscriber who ignored the first send probably ignores this too.

## What's working

- **Offer hierarchy is immediate.** The two discount circles ($10/$20 off) dominate the fold — no guessing what the email is about.
- **"Ends today" urgency is credible** because it pairs with a specific spend threshold, not vague FOMO language.
- **"Free mystery gift" is a secondary hook** that adds incentive beyond the discount without cluttering the hero.
- **Ultamate Rewards panel** is present, reinforcing the loyalty value prop for members who are close to a tier threshold.
- **No render bugs visible** — layout is clean, images load, no orphaned alt text or overlapping elements.

## What's weak

- **Personalization stripped.** The 5/21 send opened with "Marisol" in the subject and hero. This send omits the name entirely — a regression for what is ostensibly a more urgent, harder-working send.
- **Subject line is 95 characters long.** Mobile clients truncate at ~40–50 chars; recipients see "$10 off your $50 purchase⁺ or $20 off yo…" — the urgency signal ("ends today!") is completely cut off on phones.
- **Creative is identical to 5/21.** Four days later, same badges, same layout, same "friendly reminder" hook. There's zero visual signal that this is a last-chance send vs. the original.
- **CTA copy is "SHOP NOW"** — generic, no destination specificity. No "Shop Skincare" or "Shop Your Faves" that would create a tighter loop to the user's category.

## Recommendations

- 1. **Frontload the deadline in the subject.** Move "ends today" to the start, cut the legalese to the preheader.
- **Subject Alt A:** `Ends today: $10 off $50 or $20 off $100 at Ulta`
- **Subject Alt B:** `Last chance, Marisol — $10 or $20 off ends tonight`
- 2. **Restore name personalization.** The 5/21 send used "Marisol" throughout; this reminder should too. A personalized last-chance email outperforms a generic one.
- **Preheader Alt A:** `Your offer expires tonight — shop in store or online before it's gone.`
- **Preheader Alt B:** `Mystery gift included. Your $10/$20 off ends at midnight.`
- 3. **Add a visible countdown or deadline time.** "Ends today" is vague. "Ends tonight at 11:59 PM" creates a real close. A countdown GIF in the hero is high-impact for this use case.
- 4. **Differentiate the creative from 5/21.** Even a "FINAL HOURS" badge overlay on the discount circles signals urgency visually without a redesign.
- 5. **Make the mystery gift concrete or cut it.** Either reveal what it is (name it, show it) or replace with a third product category recommendation. A mystery hook works once; on a reminder send it feels like you're still withholding.

### 3. Rendering & Accessibility

**Issue 1 — Google Fonts loaded via `<link>` (blocked in production):**
```html
<link href="https://fonts.googleapis.com/css2?family=DM+Sans:..." rel="stylesheet">
```
Gmail, Outlook, Apple Mail on iOS, and Yahoo all strip or block external stylesheet `<link>` tags. DM Sans will silently fall back to the declared stack (`Helvetica, Arial, sans-serif`). This is survivable but means the font is never actually used — the `<link>` is dead weight.

**Issue 2 — Global link style removes all visual affordance (WCAG 2.1 failure):**
```css
#MessageViewBody a {
  color: inherit !important;
  text-decoration: none !important;
}
```
This makes every link invisible as a link — no underline, no distinguishing color — unless the individual element explicitly re-declares it. Violates WCAG 2.1 SC 1.4.1 (Use of Color) and SC 1.3.3. Affects screen reader users and low-vision users who rely on non-color cues.

**Issue 3 — Dead commented-out code shipping in production:**
The full hamburger menu implementation (~60+ CSS rules) is commented out with a ticket reference (`91925`) but still included in the sent payload:
```css
/* 91925 Commenting out hamburger menu
   |BEGIN Hamburger Menu
   ... [~60 rules] ...
   END Hamburger Menu */
```
Adds unnecessary bytes to every send. Strip before production.

**Issue 4 — Store dropdown `z-index: 0` may render behind other positioned elements:**
```css
#menu-wrapper-store { z-index: 0; position: absolute; ... }
```
The commented-out hamburger used `z-index: 10`. The active store dropdown uses `z-index: 0`, which will place it behind any sibling with `position` set. This is a likely bug if the dropdown ever renders.

**Issue 5 — Truncated CSS property on `#menu-wrapper-store`:**
The source ends mid-property: `position: absolute; t…` — this suggests the HTML was cut before `top:` was declared. Cannot verify whether the positioning is complete.

**No issues found:** `lang="en-US"` on `<html>` is correct. MSO conditionals and `o:AllowPNG` are present. Viewport meta is declared. Dark mode meta (`color-scheme: light dark`) is implemented in both `<meta>` and `:root` CSS — correct dual declaration.
