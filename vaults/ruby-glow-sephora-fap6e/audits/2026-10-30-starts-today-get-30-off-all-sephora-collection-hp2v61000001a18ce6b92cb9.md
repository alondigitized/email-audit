# STARTS TODAY: Get 30% off ALL Sephora Collection 😊
**Score:** 8/10 · **Type:** Email audit · **2026-10-30**
## Executive summary

- This is the strongest Sephora send in the recent run because it leads with one clear offer. The hero is a big "30% OFF" medallion for all Sephora Collection, dated 10/30–11/9, under a "STARTS TODAY" header. It follows the 10/29 "Top-shelf beauty" email, which teased this event as "Coming soon", so the payoff lands. The subject and hero match. Offer codes (ALLONSALE online, SCSAVE at Kohl's) and the free-shipping strip sit right under the hero.
- The rest of the email is a long, busy scroll. A Rouge points challenge, a credit-card perk, and a "Beauty on Demand" fulfillment row follow the hero. Next come a Sephora Collection product grid, skincare and hair gift sets, a Kohl's store locator, a "Holiday Gift Guide" and a wall of fine print. A barcode for in-store redemption closes it. Most of this is useful, but it dilutes the single message. The offer is also unclear: it says "Insider, Save on ALL" yet is gated behind codes, and the terms are small.
- Judgement: a well-timed, credible event email with an unambiguous hero. It is weighed down by length and by a store-locator and gift-guide tail that doesn't belong in a sale-day send.

## What's working

- The 30% off medallion is large and instantly readable, and the date range (10/30–11/9) sets a clear window.
- The subject and hero match, and "STARTS TODAY" delivers on the 10/29 teaser.
- The free-shipping and no-minimum returns strip removes a purchase barrier.
- The product grid shows Sephora Collection items with prices ($16, $13, $99 advent calendar), which makes the discount concrete.
- The barcode at the bottom gives in-store shoppers a way to redeem.

## What's weak

- The email is extremely long, and the Kohl's store locator, gift guide and legal text bury the offer.
- Two code sets (ALLONSALE/SCSAVE) plus "terms apply" asterisks make the "ALL" claim feel conditional.
- The extra-perks blocks (500 points challenge, credit card) compete with the main CTA.
- Skincare, hair gift sets and the Kayali "Just Arrived" block dilute the Sephora Collection focus.
- The product grid shows full prices rather than sale prices, so the 30% saving isn't visible on the items.

## Recommendations

- 1. Cut everything after the product grid except a single footer, and move the store locator and barcode to a short "In store" block.
- 2. Show sale prices ("$16 → $11.20") in the grid so the saving is visible.
- 3. Merge the two code lines into one clear line: "Use ALLONSALE online. Show barcode in store."
- 4. Collapse the points and credit-card blocks into one slim perk bar.
- **Subject Alt A:** `Today only starts it: 30% off Sephora Collection`
- **Subject Alt B:** `30% off all Sephora Collection, 10/30–11/9`
- **Preheader Alt A:** `Code ALLONSALE online, plus free shipping on every order.`
- **Preheader Alt B:** `Lip, brow and gift sets, all 30% off through 11/9.`

## Technical Audit

## 1. Technical Summary
The visible HTML source is a standard table-based XHTML Transitional layout with two open-tracking pixels. The one hard failure is the missing plain-text part (0 chars). The header warnings (List-Unsubscribe, Authentication-Results) are probably relay capture gaps, not confirmed defects. The HTML is truncated, so the footer, CTA links and unsubscribe markup could not be inspected.

## 2. Link & Tracking Issues
- No broken links were reported: 12 material links were probed and 36 were skipped by ranking. The skipped links are unverified, not passing.
- The truncated source shows two tracking images:
  - `https://mi.sephora.com/p/up/f6716d0a0f52104e/o.gif?mi_u=4970293024993920&mi_ecmp=20261030_SC_30_off_Starts_Today_BI`. This is a 1x1 pixel with a per-recipient ID (`mi_u`) and a campaign code (`mi_ecmp`).
  - `https://app.sephora.com/O/AQEAAZcF2g…`. This is a second open pixel from a different tracking domain, hidden with `display:none; max-height:0; font-size:0; mso-hide:all`.
- Two open pixels on different subdomains is redundant, but it is not a defect.
- The QA "Image missing alt text" warnings are false positives for deliverability or accessibility purposes:
  - `o.gif` already has `alt="" aria-hidden="true"`, which is correct for a decorative pixel.
  - The `app.sephora.com/O/…` pixel has no `alt` attribute at all. It is `display:none`, so there is no practical impact. Adding `alt=""` would clear the warning.

## 3. Rendering & Accessibility
- **Zoom restriction.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` disables pinch-zoom, which fails WCAG 1.4.4 (resize text).
- **Invalid robots value.** `<meta name="robots" content="no index">` should be `noindex`. The value is invalid as written and has no effect in mail clients.
- **Malformed CSS.** The `<!--[if mso]> img.mso-size {…} <![endif]-->` conditional is nested inside the `@media only screen and (max-width:480px) { … }` block in `<style>`. It is not valid CSS and may cause the following rules to be dropped by some parsers.
- **Fixed width.** The wrapper is `width="700" style="min-width:700px; width:700px"`. This forces horizontal overflow on narrow viewports unless the inner `max-width:700px` tables and the 480px media query fully override it. I couldn't confirm that from the truncated source.
- **Generic title.** `<title>Sephora</title>` is not descriptive. This is minor, since it matters mainly for web-view rendering.
- **Structured data.** The JSON-LD block has `"discountCode": ""` and an empty `PromotionCard`. Most clients strip `<script>`, and Gmail only honors specific schemas, so this is dead markup with no effect.
- **Preheader.** The `Save big now through 11/9.` text is followed by a `&zwnj;&nbsp;` padding run, which is correct.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens such as `{{…}}`, `%%…%%` or `[FIRSTNAME]` appear in the visible source. The per-recipient `mi_u` value is populated in the pixel URL. The truncated body could not be checked for tokens.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **[FAIL] No plain-text part.** The text version is 0 chars, so this is a multipart/alternative gap. It hurts deliverability and accessibility, since text-only and screen-reader-preferred clients get nothing. This is the only confirmed failure.
- **[WARN] List-Unsubscribe and List-Unsubscribe-Post not found.** The QA tool itself notes AgentMail may not relay these headers, so this is unconfirmed. Sephora is a large sender, and Gmail and Yahoo bulk-sender rules require RFC 8058 one-click unsubscribe, so it is likely present at the origin. Verify against the raw message headers.
- **[WARN] Authentication-Results absent.** This is also an expected relay artifact, so SPF, DKIM and DMARC status is unknown, not failed. The envelope domain `beauty.sephora.com` is a dedicated sending subdomain, which is a good sign, but alignment is unverified.
- **Footer not visible.** The physical postal address and in-body unsubscribe link are in the truncated portion and could not be checked. The QA tool says an unsubscribe link was included in probing.

2. Confirm `List-Unsubscribe` and `List-Unsubscribe-Post: List-Unsubscribe=One-Click` in the raw origin headers, and check SPF, DKIM and DMARC alignment from the original message, not the relay copy.
