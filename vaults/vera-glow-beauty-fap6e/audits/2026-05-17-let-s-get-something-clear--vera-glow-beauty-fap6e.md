### 3. Rendering & Accessibility

**[HIGH] Invalid HTML comments inside CSS `@media` block**

```css
@media only screen and (max-width: 600px) {
  *[class=hide] { display: none !important; }
  <!-- *[class=contenttable] { width:414px !important;} -->
  <!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
```

HTML comment syntax (`<!-- -->`) is invalid inside a CSS block. This will cause CSS parsers to emit a parse error; the two rules inside the comments are silently dropped (as intended), but depending on client, the parse error may also drop the surrounding valid rules in the same block. Use `/* */` for CSS comments.

**[MEDIUM] Duplicate font loading — double HTTP requests**

Each of the three Brown font variants is loaded twice: once via `<link rel="stylesheet" href="https://db.onlinewebfonts.com/...">` in `<head>`, and again via `@import url(...)` inside the `<style>` block. This fires 6 font stylesheet requests where 3 would suffice. Remove the redundant `@import` declarations.

**[MEDIUM] `maximum-scale=1` in viewport meta**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

Disables user zoom on mobile. This fails WCAG 1.4.4 (Resize Text, Level AA) and is flagged by accessibility validators. Remove `maximum-scale=1`.

**[LOW] Global `line-height: 100%` reset**

```css
*{ line-height: 100%; }
```

Applied via universal selector, this overrides line-height on all elements. On text-heavy cells this compresses descenders into adjacent lines. Scope this reset to the specific elements that need it rather than the universal selector.
