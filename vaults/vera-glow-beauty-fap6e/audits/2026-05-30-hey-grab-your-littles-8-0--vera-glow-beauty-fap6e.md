# Hey! Grab your Littles 8.0!
**Score:** 8/10 · **Type:** Email audit · **2026-05-30**
## Executive summary

- Email fourteen, give or take — I stopped counting as carefully because DE burned through whatever goodwill "Adios, 25% off..." earned them, and my brain has this whole folder categorized as "they'll extend it again." So when this one lands with "Hey! Grab your Littles 8.0!" I actually felt my scrolling thumb pause. That is a different energy. No countdown clock, no fake deadline — just the Littles, at $65, with a clean AM/PM breakdown of how to actually use the thing. The pivot from sale exhaustion to product education is the right call.
- But then the very top of the email has a yellow box with a code that reads `CRWL_CW-P225-2h3-52`. That is not a promo code a human designed. That is a Klaviyo automation token that leaked into the render, and my first reaction is "something broke." It undercuts what is otherwise the most honest send DE has made in two weeks.
- Would I click? Probably yes — the Littles 8.0 is a real purchase consideration and the routine breakdown is legitimately useful content. Would I forward it to a friend? No. Fourteen emails in a week means I quietly add this to my cart and say nothing.

## What's working

- **The creative pivot is real.** After thirteen back-to-back F&F urgency emails, a calm product story with a price and a how-to guide reads like an actual exhale.
- **AM/PM routine breakdown** with functional labels ("to brighten," "to hydrate," "to exfoliate") is exactly the content that makes me feel like DE knows what their products do — and trusts that I do too.
- **$65 hero price** is front and center in the product image; I do not have to dig for the cost.
- **"SHOP LITTLES"** is clean and specific — ILIA would have written "Explore the Collection" and charged me more for the privilege; DE kept the CTA tight.
- **"Summer Skin, Sorted"** in the lower section is seasonally correct. I genuinely need a travel kit right now.

## What's weak

- **That header code.** `CRWL_CW-P225-2h3-52` looks like a leaked automation token, not a promo code. It breaks trust in the first two seconds.
- **The 15% Off Club offer is completely disconnected from the Littles.** I do not know if the $65 price is before or after the 15%, and there is no copy bridging the two. Am I saving $9.75 right now, or is this a "welcome to the club" placeholder that does nothing today?
- **No urgency on "8.0."** The versioning implies this is a new iteration, but there is no "just dropped" or "limited run" framing. Compare ILIA's 9/10 teaser — "Coming 06.02 — our *softest* launch yet" — which built anticipation without a single discount. DE's version just lands without a reason to act today vs. next week.
- **Zero social proof on a $65 multi-product kit.** Charlotte Tilbury never lets a product run without a credibility anchor — one aggregate star rating or a pull quote would do real work here.

## Recommendations

- 1. **Fix or remove that header code — this is the highest-priority fix.** Either make the promo code human-readable ("LITTLES15") or pull the welcome box entirely until the token is resolved. It reads as broken.
- 2. **Tie the 15% explicitly to the Littles at checkout.** Cross out $65, show $55.25, put "your club discount applied" in one line. That header box becomes a conversion driver instead of a question mark.
- 3. **Give the 8.0 a launch hook.** "New this season" or "upgraded formula" in the hero copy costs nothing and gives me a reason to buy today rather than save for later.
- 4. **Pull one review anchor into the AM section.** Aggregate star rating, one line, under the routine breakdown. Done.
- 5. **Audit cadence before the next send.** Fourteen emails in roughly seven days — even a genuinely good pivot like this one is landing in an inbox that learned to skim everything from this sender.

## Technical Audit — Drunk Elephant "Grab your Littles 8.0!"

---

### 1. Technical Summary

XHTML 1.0 Transitional with VML/Outlook compatibility markup. Three confirmed structural defects: HTML comment syntax embedded inside `<style>` CSS blocks (dead rules), triple-redundant font loading, and a zoom-blocking viewport meta tag.

---

### 2. Link & Tracking Issues

**No UTM parameters observed** on any href in the available source. All CTA links appear to point to bare `drunkelephant.com` URLs with no `utm_source`, `utm_medium`, or `utm_campaign` parameters — unconfirmable in full without the complete source, but none are present in the truncated portion.

**Sending domain mismatch**: `From` header uses `cheers.drunkelephant.com`, while body links resolve to `www.drunkelephant.com`. No issues if SPF/DKIM cover the subdomain, but continuity should be verified (see §5).

---

### 3. Rendering & Accessibility

**Critical — Dead CSS rules (invalid HTML comments inside `<style>`):**
```css
@media only screen and (max-width: 600px) {
  <!-- *[class=contenttable] { width:414px !important;} -->
  <!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
}
```
HTML comment syntax (`<!-- -->`) inside a `<style>` block is not valid CSS. These two responsive-width rules will never apply. Affected classes `contenttable` and `mobile` will not resize on 600px-or-narrower viewports.

**Accessibility — Zoom disabled:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
`maximum-scale=1` prevents user-initiated zoom. This violates WCAG 1.4.4 (Resize Text, Level AA) and is blocked by default in iOS 16+.

**Accessibility — Text size adjust suppressed:**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none;}
```
Value should be `100%`, not `none`. `none` disables the OS-level font scaling that low-vision users rely on, and `*{}` applies it globally.

**Performance — Triple font loading:**
The Brown font family is loaded three ways simultaneously:
1. `<link href="https://db.onlinewebfonts.com/...">` (3 separate link tags)
2. `@import url(https://db.onlinewebfonts.com/...)` inside `<style>`
3. `@font-face` blocks also inside `<style>`

This produces 6+ redundant HTTP requests per render. Consolidate to `@font-face` only (most compatible in email) and drop the `<link>` and `@import` declarations.

**Third-party font CDN risk:** `BrownBold`, `BrownLight`, and `BrownThin` are sourced from `db.onlinewebfonts.com`, a third-party service with no SLA. `BrownRegular` is correctly self-hosted on `drunkelephant.com`. All variants should be self-hosted.
