# Adios, 25% off...
**Score:** 7/10 · **Type:** Email audit · **2026-05-26**
## Executive summary

- Email ten. *Ten.* I have a folder in my Gmail called "DE F&F 2026" and it now has ten items in it. I opened this one because "Adios, 25% off..." is genuinely the cleverest subject line of the entire run — the farewell framing is on-brand and it briefly made me feel like something was actually ending. Then I opened it and the very first thing I see is a countdown timer sitting at 00:00:00:00. All zeros. Dead. Charlotte Tilbury pulled the exact same expired-timer move about a week ago and I said the same thing then: if your clock hits zero and the email still fires, you've made yourself look either incompetent or dishonest. On what is supposed to be the emotional close of a ten-email campaign, that's a brutal own goal.
- The rest of the email is actually solid — the GWP tiers ($100+ / $75+) are clearly signed, the kit section with 35% off gives me a reason to browse, and the visual hierarchy is clean. Drunk Elephant's product photography is always good. But I've seen this hero five times in two weeks, and "HI, FRIEND!" is doing the least possible work in the personalization field. It's giving mass-blast energy when this should be the intimacy send.
- I'd mark this read without clicking purely because the dead timer shook my trust in the offer being live. Wouldn't forward it.

## What's working

- **"Adios" framing lands.** The subject line is the best creative DE has shipped in this campaign — it's bittersweet, it's on-brand voice, and it works as a genuine farewell.
- **GWP tiers are clearly communicated.** Spend $100+ gets the Hydra bundle, spend $75+ gets F-Balm full size — both signed in the body, no hunting required.
- **Kit section earns its scroll.** "KIT 'EM WHILE THEY'RE HOT! 35% off kits" with four individually named kits and prices visible is actually useful deal content, not just hero padding.
- **Visual hierarchy is clean.** Eye goes banner → hero 25% off → GWP offers → kits. Nothing competing for attention mid-scroll.
- **Brand voice is consistent throughout.** The product copy sounds like Drunk Elephant — playful, warm, not pushy. That matters for trust on send #10.

## What's weak

- **The countdown timer reads 00:00:00:00.** Zero hours, zero minutes, zero seconds. Charlotte Tilbury did this on her "LAST CHANCE" send and I called it out then — a dead timer tells me the sale might literally be over before I'm reading this email. That is not a close, that is a fumble.
- **"HI, FRIEND!" is not personalization.** Ten emails deep into a campaign with a subscriber who clearly opened nine of them, and DE still hasn't dropped my first name in. ILIA has been personalizing by name throughout their F&F run. This is table stakes in 2026.
- **The banner copy ("SHOP SHOP SHOP!") is doing nothing.** It's not conveying urgency, it's not adding offer info — it's noise that competes with the actual hero.
- **Cadence fatigue is real.** Send #10 in roughly 10–11 days. Sephora's "ENDS TODAY" was blasted three times in one day last week — DE hasn't hit that level of chaos, but this campaign has crossed the point where each new send costs relationship equity instead of building it.

## Recommendations

- 1. **Fix the countdown timer or cut it entirely.** A live, accurate timer is urgency. A zero timer is a broken promise. If the tech can't guarantee accuracy at send time, use static "Sale ends at midnight" copy instead — Sally Beauty does this and it reads honest.
- 2. **Personalize the opening.** Drop the first name. "HI, VERA" > "HI, FRIEND" every single time. This is the close of a major campaign — treat me like a known customer.
- 3. **Make the kits section the hero on send #10.** I've seen the 25% off sitewide hero nine times. Leading with the 35% off kits would have felt like a new reason to click, not a replay.
- 4. **Retire "SHOP SHOP SHOP" from the banner.** Replace with a live or static deadline line: "Sale ends tonight at 11:59 PM PT" — gives me information, not just noise.
- 5. **Trim the fine print wall.** The bottom third of this email is dense asterisk text. If the offer requires five disclaimers to be legal, summarize them in two lines and link to full terms.
- **Subject Alt A:** `Last hours: your 25% is expiring`
- **Subject Alt B:** `Final call — 25% off ends tonight`
- **Preheader Alt A:** `Kits at 35% off + free F-Balm when you spend $75`
- **Preheader Alt B:** `Last chance to stack your F&F haul — sale ends tonight`

### 3. Rendering & Accessibility

**Critical: HTML comment syntax inside CSS `@media` block**
In the `@media only screen and (max-width: 600px)` block, two rules are wrapped in HTML comment delimiters:
```css
<!-- *[class=contenttable] { width:414px !important;} -->
<!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
```
CSS parsers do not strip HTML comments — they are treated as parse errors. These two rules will silently fail in all standards-compliant clients (Gmail, Apple Mail, Outlook iOS/Android). If `.contenttable` or `.mobile` layout behavior is depended on at narrow viewports, the mobile layout will break.

**Triple font loading for the same families**
Brown Bold, Brown-Light, and Brown-Thin are each loaded three times:
1. `<link href="https://db.onlinewebfonts.com/c/...">` in `<head>`
2. `@import url(https://db.onlinewebfonts.com/c/...)` in `<style>`
3. `@font-face { src: url("https://db.onlinewebfonts.com/t/...") }` in `<style>`

This generates 6–9 redundant HTTP requests per render. Only `@font-face` survives in most email clients anyway; the `<link>` and `@import` declarations are stripped by webmail clients (Gmail, Outlook.com) at parse time and add latency without benefit in native clients.

**Third-party font CDN single point of failure**
All custom font variants (BrownBold, BrownLight, BrownThin) are served from `db.onlinewebfonts.com`. BrownRegular uses `drunkelephant.com/on/demandware.static/...`. If `db.onlinewebfonts.com` is unavailable at open time, three of the four declared font weights silently fall back to the system stack. No explicit `font-family` fallback stack is declared in the `@font-face` rules — fallback behavior depends on `body` or element-level CSS not visible in this excerpt.

**`maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
`maximum-scale=1` disables user pinch-to-zoom on iOS. This is an accessibility issue (WCAG 1.4.4 — Resize Text) and is flagged by automated accessibility scanners.

**Global `line-height: 100%` override**
```css
*{line-height: 100%}
```
The `*` selector overrides all element-level line-height, including any that are set inline on `<td>` or `<p>` elements. This is a known cause of text clipping in taller glyphs and can produce visual defects in Outlook (which applies `mso-line-height-rule:exactly` separately).

**`max-height:1000000px` on `*`**
```css
*{max-height:1000000px}
```
This is a known workaround to prevent iOS Mail from collapsing large emails, but applying it globally via `*` can interfere with `display:none` hiding of elements on desktop — some clients override hidden element dimensions when `max-height` is explicitly set.
