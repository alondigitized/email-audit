### 3. Rendering & Accessibility

**Empty `<title>` tag.** `<title></title>` is blank. Outlook and some webmail clients surface this as the window/tab label. Low severity, but should contain the subject line or brand name.

**`tabindex="-1"` on the logo link.** The anchor wrapping the logo image sets `tabindex="-1"`, removing it from keyboard tab order:
```html
<a href="https://links.elfcosmetics.com/..." tabindex="-1">
```
This is incorrect for a navigable link. Keyboard-only users cannot reach it. Should be removed or set to `tabindex="0"`.

**9px heading on mobile.** The media query includes:
```css
.row-6 .column-1 .block-1.heading_block h1 { font-size: 9px !important }
```
9px is well below the WCAG 2.1 minimum recommended text size (~14px) and Apple's 11px floor for legibility. This will be effectively unreadable on mobile and may trigger accessibility flags.

**Nested duplicate `nl-container` structure.** Inside the outer `html_block` elements, the source contains a full inner `nl-container` table with its own `row row-1` / `row-content stack` hierarchy — this is a double-wrapping pattern that can cause fixed-width overflow or collapsed columns in Outlook and older Android Gmail clients.

**Google Fonts loaded unconditionally for non-MSO clients.** Two separate `<link>` calls load `Open Sans` and `Jost` via `fonts.googleapis.com`. This is behind the `<!--[if !mso]><!--> ... <!--<![endif]-->` conditional, so Outlook is excluded correctly. Fallback stack (`Arial, Sans-serif`) is present. No issue, but two separate font requests could be consolidated into one (`family=Open+Sans|Jost`) to reduce render-blocking round trips.
