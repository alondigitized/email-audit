- Okay, I have to clock this immediately: this is the third lip-centric email e.l.f. has sent me in a week. - **$15 price point is visible in the hero** — no digging, no click required, the offer is the headline. That's the right call.

## What's weak

- **Third lip email in seven days** — July 1 was $20 lip combos, July 5 was Soft Glam family (which touched lips), now this. I need a palette cleanser in my inbox. Glossier recently sent a zero-product teaser ("Something new is coming") that reset the story entirely — e.l.f. could learn from that pacing reset.
- **No urgency signal anywhere I can see** — no "ends Sunday," no countdown, no "limited stock." The Sephora "ENDS TODAY" emails I've been tracking this week create genuine FOMO. This one just... floats.
- **$15 vs. $20 from last Tuesday is buried** — if the price actually dropped, that's the hook. Nothing in the subject or hero frames it as a new lower price. I had to do the math myself from memory, which is not the job.
- **"SHOP + GET" CTA copy is vague** — what am I getting? SHOP NOW works. "SHOP + GET" without completing the thought reads like truncated copy.

- 1. **Frame the price drop explicitly** — if these are $5 cheaper than Tuesday's combos, say "Now $15" or "Prices just dropped." That's the story, and right now it's invisible.

- 3. **Rewrite "SHOP + GET" to complete the sentence** — "SHOP + GET YOUR COMBO" or just "BUILD YOUR $15 COMBO." Give me the reward in the button.
- 4. **Vary the inbox cadence** — rotate to a skincare or eye story mid-week and come back to lips on Friday. The July 4 SPF email actually broke the pattern well; this swings back too fast.
- 5. **Surface the @ALURBEAUTY collab higher** — the influencer tag is buried below the fold in what looks like the second content block. If it's a real collab, that's above-the-fold social proof.

### 3. Rendering & Accessibility

**Empty `<title>` element:**
```html

```
Screen readers (VoiceOver, NVDA) announce the document title. A blank title provides no context. Should be set to the email subject or a short description.

**Redundant nested layout shell:**
Inside `block-1`'s `html_block`, a complete second `nl-container` > `row row-1` > `row-content stack` layout is embedded — a full email shell nested within another. This is the Braze "custom HTML block inside drag-and-drop template" anti-pattern. It produces duplicate `width:640px` frame constraints and can cause double-border or misalignment artifacts in Outlook (which processes nested tables independently).

**Three empty content blocks:**
`block-2`, `block-3`, and `block-4` contain only whitespace:
```html
<div style="font-family:Open Sans,Arial,Sans-serif;text-align:center" align="center"> </div>
```
These appear to be unfilled template placeholders. They add ~450 bytes of dead markup and may create unexpected vertical spacing in some clients (particularly older Android Gmail).

**`#MessageViewBody a` override is too broad:**
```css
#MessageViewBody a { color: inherit; text-decoration: none }
```
This Gmail-targeting override strips underlines and inherited color from all links in the message body — including any unsubscribe or footer links that rely on visual distinction for compliance readability.

**Google Fonts via `<link>` tag:**
```html

<link href="https://fonts.googleapis.com/css?family=Open+Sans" ...>

```
Correct MSO conditional guard. However, the `?family=Open+Sans` query string is missing the `display=swap` parameter, which can cause invisible text during font load in webmail clients that do render web fonts (Apple Mail, some iOS mail apps).
