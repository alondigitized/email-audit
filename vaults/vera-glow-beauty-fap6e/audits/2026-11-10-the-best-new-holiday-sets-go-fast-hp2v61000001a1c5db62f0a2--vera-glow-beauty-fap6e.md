## Technical Audit

## 1. Technical Summary
The HTML source is a 700px fixed-width table layout with Epsilon/Harmony click-wrapped links. It has no plain-text alternative (QA FAIL, 0 chars) and a few accessibility and markup defects. The header-based compliance and authentication warnings look like relay artifacts, not confirmed sender faults.

## 2. Link & Tracking Issues
- **No broken links confirmed.** The QA probe covered 12 material links and skipped 33. It reported no failures, but the skipped links are unverified.
- **Redirect-wrapped links.** CTAs use `https://app.sephora.com/T/v61000001a1c5db62f0a255a76e96c660f0/.../?__dU__=...`. Final destinations aren't visible in the source, so landing URLs can't be audited.
- **Open-tracking pixel.** `<img src='https://app.sephora.com/O/AQEAAZcF2g...' style="display:none; max-height:0; font-size:0; mso-hide:all"/>`. It is hidden and works as intended. The QA alt warning on it is a false positive, though an empty `alt=""` would still be cleaner.
- **Single-quoted attributes.** The pixel uses `src='...'` while the rest of the markup uses double quotes. It is valid but inconsistent.

## 3. Rendering & Accessibility
- **Missing alt text (QA-confirmed).** `20261110_Holiday_Skincare_Sets_Dedicated_bottom_el...` is a content image with no `alt`. Screen readers and image-blocking clients get nothing for it.
- **No `lang` attribute.** `<html xmlns=... xmlns:v=... xmlns:o=...>` has no `lang`.
- **Zoom disabled.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` blocks pinch-zoom (WCAG 1.4.4).
- **Fixed-width tables.** The wrapper has `min-width:700px; width:700px`. The visible `@media (max-width:480px)` block only resizes `.mobile*` classes and has no `.tbl` override. This may be in the truncated portion, so it needs confirming.
- **Malformed CSS.** `<!--[if mso]> img.mso-size {...}<![endif]-->` sits inside the `@media` block. Some parsers may drop the rules that follow it, such as `.mobileHeaderTierRouge` and `.mobileIcon`.
- **Invalid robots value.** `<meta name="robots" content="no index">` should be `noindex`. It has no practical effect in email.
- **Generic title.** `<title>Sephora</title>` is not descriptive.
- **JSON-LD block.** It has `"discountCode": ""` and a bare `PromotionCard` type. Most clients strip `<script>` tags and the markup is invalid, so it is low impact.
- **Preheader.** It is implemented correctly with `display:none` and `&zwnj;&nbsp;` padding.

## 4. Personalization & Merge Tokens
No issues found. No unresolved tokens (`{{`, `%%`, `[[`) appear in the visible source. The empty `discountCode` is in structured data only, not rendered.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Plain-text part missing (QA FAIL).** The text version is 0 chars. This is a real deliverability and accessibility defect, because multipart/alternative is expected.
- **List-Unsubscribe and List-Unsubscribe-Post (RFC 8058) not found.** QA attributes this to the AgentMail relay possibly not capturing headers. It is unconfirmed, so this audit can't call it a sender violation. Check the raw message to verify.
- **Authentication-Results missing.** SPF, DKIM and DMARC status is unknown for the same relay reason. No issue can be asserted.
- **Footer not auditable.** The in-body unsubscribe link and physical address fall in the truncated HTML. QA says an unsubscribe link was always included in probing, but this audit can't confirm its target.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Can't be verified. The wrapped `app.sephora.com/T/...` URLs hide the destination URLs and any UTM parameters, and the QA probe reported no landing-page data. The `__dU__` token is an opaque per-recipient identifier. No UTM issue is asserted.

1. Add a plain-text MIME part. This is the only confirmed FAIL.
2. Add descriptive `alt` text to the `20261110_Holiday_Skincare_Sets_Dedicated_bottom_el...` image, and `alt=""` to the tracking pixel.
