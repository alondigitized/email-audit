## What's working

- Free AETURA trial sizes at the banner top is a concrete GWP hook — I clocked it immediately and it gave me a reason to stay scrolling.
- "Going Viral" editorial framing plays to exactly how I actually discover new products — TikTok, Reddit, whatever's blowing up — and Rhode is the right anchor for that story.
- "HOT ON SOCIAL +" is doing real work as a social-proof signal; doesn't feel forced.
- The multi-category layout (skincare → hair → lip → fragrance via Harlem Perfume Co.) gives this email more depth than the first "Obsessed? Same." send — it's actually a richer email than its twin.
- Beauty Insider is present at the bottom; I can at least see my tier is acknowledged somewhere.

## What's weak

- Same subject line as an email I already reviewed from Sephora *today*. This is the "Summer's hottest beauty ☀️" July 8th situation all over again and it makes the whole operation look like a send-list mistake, not a campaign.
- Rhode is featured as the hero again — which, fine, it's a strong product, but if you're going to send a second email in one day, the hero should shift or this reads as a resend.
- No urgency anywhere — the GWP feels open-ended, which means I'll tell myself I'll come back and then I won't.
- Cadence is genuinely broken at eleven sends in thirteen days. Even as a Rouge-tier loyalist who *wants* to know about launches, this is inbox fatigue territory. Drunk Elephant's "Time to come clean" earned its spot because it felt like a single, confident editorial statement — this feels like Sephora forgot what they sent this morning.

- 1. **Retire the subject line immediately** — using "Obsessed? Same." twice in one day is an ops error, not a strategy. If this is a second wave targeting non-openers from the morning send, the subject must change, period. You can't A/B the same subject against itself.
- 2. **Rotate the hero away from Rhode for the second send** — even swapping to Harlem Perfume Co. or the AETURA GWP as the primary visual would differentiate this from the first wave.
- 3. **Put a deadline on the GWP** — "Free AETURA trial sizes, today only" or "while supplies last, ends midnight" would flip that from "nice to know" to "open my cart."
- 4. **Move the multi-category depth (hair + lip + fragrance) to the TOP** — that's actually the thing that makes this email different from the morning send. Lead with the differentiation.

### 3. Rendering & Accessibility

**`maximum-scale=1` blocks user zoom (WCAG 1.4.4 violation)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Disabling pinch-zoom on mobile fails WCAG SC 1.4.4 (Resize Text, Level AA). Should be removed or set to `maximum-scale=5`.

**`text-size-adjust: none` applied universally**
```css
div, a, tr, table, body, span, img, strong, td {
  -webkit-text-size-adjust: none;
  -ms-text-size-adjust: none;
  -moz-text-size-adjust: none;
  text-size-adjust: none;
}
```
Blanket suppression of OS-level text scaling overrides user accessibility preferences across all elements. Standard practice is `100%` (allow scaling) rather than `none`.

**No `lang` attribute on `<html>` element**
```html
<html xmlns="http://www.w3.org/1999/xhtml" xmlns:v="..." xmlns:o="...">
```
Missing `lang="en"` (or locale-appropriate value). Screen readers cannot infer document language for correct pronunciation.

**Duplicate CSS rules for `.show` and `.appear`**
```css
*[class=show], .show { display: block!important; display: table!important; }
*[class=appear], .appear { display: block!important; display: table!important; }
```
`display: block!important` immediately overridden by `display: table!important` in the same rule. The `block` declarations are dead code. No rendering breakage, but indicates a copy-paste artifact.

**`robots` meta value uses a space**
```html
<meta name="robots" content="no index" />
```
Correct value is `noindex` (no space). Most crawlers handle both, but the space-separated form is non-standard and may not be honored by all parsers.

**Layout tables lack `role="presentation"`** *(inferred — body truncated)*
Table-based email layouts should carry `role="presentation"` so screen readers skip structural markup. Cannot confirm body table tags without full source.
