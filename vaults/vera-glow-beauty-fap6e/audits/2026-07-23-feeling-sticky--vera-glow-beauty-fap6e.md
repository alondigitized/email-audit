### 3. Rendering & Accessibility

**Bug — HTML comments inside CSS media queries (rules silently dropped):**
```css
@media only screen and (max-width: 600px) {
  <!-- *[class=contenttable] { width:414px !important;} -->
  <!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
```
`<!--` / `-->` are HTML comment delimiters, not CSS. Any CSS parser that doesn't apply legacy quirks mode will ignore these lines entirely. `.contenttable` and `.mobile` width overrides will not apply on mobile in standards-compliant clients (Gmail, Apple Mail, Outlook mobile).

**Bug — Duplicate font loading for the same three typefaces:**
The following fonts are loaded via both a `<link rel="stylesheet">` in `<head>` AND an `@import` inside `<style>`, causing double HTTP requests:
- `4150d76a852e1c349e0b6fe15f29d9ca` (Brown Bold)
- `6145ed704c26a497680e82c477f40b46` (Brown Light)
- `68d0f9847ef9a5695d6efa71521067ec` (Brown Thin)

**Risk — Third-party font CDN (`db.onlinewebfonts.com`):**
Three of the four custom fonts are served from `db.onlinewebfonts.com`, a third-party aggregator, rather than a brand-controlled CDN. `BrownRegular` is self-hosted at `drunkelephant.com/on/demandware.static/...` — the approach is inconsistent. If `onlinewebfonts.com` is slow or blocked, three of four weights fail with no fallback.

**Risk — Aggressive `text-size-adjust` override:**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
Setting `none` (rather than `100%`) on the `*` selector disables text scaling globally. This fails WCAG 1.4.4 (Resize Text) — users who have text size overrides set at the OS level will have them suppressed.
