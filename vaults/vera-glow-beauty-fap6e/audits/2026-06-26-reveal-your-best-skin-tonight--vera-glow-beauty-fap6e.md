### 3. Rendering & Accessibility

**A. Invalid HTML comments inside CSS block (silently kills two mobile rules)**

Inside the `@media only screen and (max-width: 600px)` block:
```css
<!-- *[class=contenttable] { width:414px !important;} -->
<!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
```
`<!-- -->` is HTML comment syntax; it is not valid CSS. CSS parsers do not recognize it as a comment — the tokens are dropped or cause a parse error. Both `contenttable` and `mobile` width rules are effectively disabled. Any elements using those classes will not reflow correctly on mobile.

**Fix:** Replace with CSS comment syntax: `/* ... */` or remove the comments entirely and restore the rules.

---

**B. `text-size-adjust: none` on all elements**

```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none;}
```
`none` prevents users (including those with low vision) from increasing text size via OS/browser settings. The correct value is `100%`, which prevents automatic upscaling while preserving user control. This is an accessibility regression and will fail WCAG 1.4.4 (Resize Text).

**Fix:** Change to `-webkit-text-size-adjust:100%; -ms-text-size-adjust:100%;` (consistent with the `<body>` rule already in place one line above).

---

**C. Redundant triple font-loading — two of three paths will fail in most clients**

The Brown font family is declared three ways:

| Method | Will survive Gmail? | Notes |
|---|---|---|
| `<link>` tags in `<head>` | No | Gmail strips `<head>` link tags |
| `@import` inside `<style>` | No | Gmail strips `@import` |
| `@font-face` in `<style>` | Partial | Gmail strips `<style>` in some contexts; Outlook ignores entirely |

All three methods load from `db.onlinewebfonts.com`, a third-party aggregator not under brand control. The `BrownRegular` `@font-face` is the only path sourcing from `www.drunkelephant.com/on/demandware.static/...` (brand CDN), which is the correct approach.

**Issues:**
- `BrownBold`, `BrownLight`, `BrownThin` `@font-face` declarations all point to `db.onlinewebfonts.com` — not the brand CDN. If that service throttles, rotates, or drops assets, those weights fail silently.
- Redundant `<link>` + `@import` adds unnecessary HTTP requests that will be blocked by most clients anyway.

**Fix:** Self-host all four weights on `drunkelephant.com/on/demandware.static/...` matching the `BrownRegular` pattern. Remove the `<link>` tags and `@import` declarations; keep only `@font-face` with brand CDN `src`.

---

**D. Unusual breakpoint at 418px**

A `@media only screen and (max-width: 418px)` block duplicates font-size overrides already present in the 600px block. 418px does not correspond to any standard device viewport. This appears to be a legacy rule targeting an old iPhone screen width. Verify whether it is still needed; if not, remove to reduce CSS bloat.
