# 4 PC NARS gift with select $50 online purchase** Terms & excl. apply 🪄

## Executive summary

- I just reviewed this exact offer earlier today. Like, *today*. Same subject, same "4 PC NARS gift with select $50 online purchase" headline, same wand emoji. Ulta sent this twice in the span of a few hours — which is giving me Charlotte Tilbury déjà vu from the June 3rd double-tap situation. The email itself is actually solid: the NARS hero imagery is clean, the product grid gives me the full category picture, and a GWP at $50 is math I can work with. But the cadence is the story. When I see a second send land before I've even made up my mind about the first one, it doesn't feel like urgency — it feels like an ops error.
- If this were my *first* time seeing it today, I'd be clicking. The offer is real, it's a brand I rotate through, and the 10% member benefit strip at the top stacks nicely with the GWP. But it's not my first time. So I'm already in the mental discount bin on this one. I'll probably shop the NARS GWP, but not because of this second send — despite it.

## What's working

- **NARS hero imaging is doing the heavy lifting** — the large compact shot reads as luxe even at mobile thumbnail size, and the product grid below earns the brand.
- **The 10% off member strip at the top** is a nice stacking signal — it reinforces that being a Diamond member has active value right now, not just point accumulation.
- **GWP threshold is genuinely achievable** — $50 at NARS isn't a reach when a single lipstick or complexion product qualifies; this doesn't feel like a bait spend.
- **Visual hierarchy is clear** — NARS brand comes first, offer second, product browse third; my eye moves in the right order down the page.
- **No render bugs** — layout holds clean, images loaded, no placeholder text visible.

## What's weak

- **Second send of the day is a credibility drain** — I've now received this exact offer framing twice before noon, and it makes Ulta's CRM look like it has a duplicate-send problem rather than a segmentation strategy.
- **Subject line legal clutter** — putting `** Terms & excl. apply` in the actual subject line is doing no one any favors; it signals there are outs before I've even opened.
- **No urgency signal or deadline visible anywhere** — unlike the Charlotte Tilbury GWP from June 3rd which at least gestured at a time window, I have no reason to act today vs. tomorrow vs. next week.
- **Zero personalization** — after how many NARS purchases have gone through my Ulta account, a "based on your love of NARS" hook would cost nothing and land so much harder.

## Recommendations

- 1. **Kill the duplicate send.** This is the single highest-lift fix. One well-timed NARS GWP email beats two identical ones every time; the second send actively undermines the first.
- 2. **Pull the `** Terms & excl. apply` out of the subject line** and push it to a small-print line in the hero — clean up that subject for inbox display.
- 3. **Add a deadline.** Even "through Sunday" or "while supplies last" creates a decision frame. e.l.f. does this in every single send and it works.
- 4. **Personalization hook in hero copy** — something like "You've been in your NARS era — make it count" instead of generic brand copy.

### 3. Rendering & Accessibility
- **Google Fonts will not load in most email clients.** `<link href="https://fonts.googleapis.com/css2?family=DM+Sans...">` is stripped by Gmail and blocked by Outlook. There is no explicit CSS fallback stack for DM Sans outside the `.helvetica` class (`Helvetica, Arial, sans-serif`). Any element using DM Sans directly will silently fall back to client default, causing layout shifts in pixel-precise designs.
- **Dead CSS payload.** The hamburger menu block (`/* 91925 Commenting out hamburger menu ... END Hamburger Menu */`) is commented out but the full rule set — `#mobile-label`, `#mobile-checkbox`, `#menu-wrapper`, etc. — remains in the stylesheet as commented text, adding ~3–4 KB to the `<style>` block for no render benefit.
- **`@-ms-viewport { width: device-width; }`** is a dead IE 10 Mobile hack with no effect in any current client; minor byte waste.
- **`translate="no"` on `<html>`** disables browser/client translation for all recipients. This is aggressive; non-English speakers cannot use auto-translate. Intentional only if the brand explicitly requires it.
- **`#MessageViewBody a { color: inherit !important; text-decoration: none !important; }`** resets all link styling globally. In Gmail Web, this makes CTA links visually identical to surrounding body text unless each link has an explicit inline `color` and `text-decoration`. Confirm all CTAs have inline style overrides.
- **`<title>Ulta Beauty </title>`** contains a trailing space — likely a template rendering artifact; harmless but indicates incomplete token cleanup.
