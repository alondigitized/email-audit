# Technical Audit: Sephora Insider, "‼️ APP EARLY ACCESS: Glossier, LANEIGE, and more ‼️"

## 1. Technical Summary
The email is a table-based XHTML 1.0 Transitional build sent through Epsilon (`images.harmony.epsilon.com`). The QA run found no plain-text part, two images without alt text, and a viewport/text-size setup that blocks user zoom. The header-based compliance checks could not be confirmed because the relay didn't capture the headers. The HTML source is truncated, so everything below is limited to the visible portion and the QA data.

## 2. Link & Tracking Issues
- No broken links reported. Only 12 of 64 links were probed and 52 were skipped (footer, utility and social links are deprioritized). The probe results weren't included in the QA data, so link health is **unverified**, not clean.
- The tracked image `https://app.sephora.com/O/AQEAAZcF2gAndjYxMDAw...` has a long opaque token path. It is a per-recipient tracking or open pixel, which is expected for this ESP setup. No defect is shown.
- Unsubscribe link: the QA tool says one is always probed, but its result isn't in the findings. I can't confirm it resolves.

## 3. Rendering & Accessibility
- **Plain-text fallback missing (QA FAIL):** the text version is 0 chars. The email is HTML-only, which hurts deliverability scoring and leaves text-only clients and screen-reader fallbacks with nothing.
- **Missing alt text (QA WARN, 2 images):**
  - `https://app.sephora.com/O/AQEAAZcF2gAndjYxMDAw...`
  - `https://images.harmony.epsilon.com/ContentHandler/images/de0a3226-.../2021_Navs_Header_06...`
  - The second image is a nav header. With no alt text, images-off and screen-reader users get no navigation context.
- **Zoom restriction:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` blocks pinch-zoom on mobile, which is a WCAG 1.4.4 concern.
- **Text resizing disabled:** the CSS sets `-webkit-text-size-adjust: none; -ms-text-size-adjust: none; -moz-text-size-adjust: none; text-size-adjust: none` on `div, a, tr, table, body, span, img, strong, td`. This stops user-initiated text scaling.
- **Invalid meta value:** `<meta name="robots" content="no index" />` should be `noindex`. It has no practical effect in email clients.
- **Generic title:** `<title>Sephora</title>` is not descriptive. This is minor.
- The mobile CSS uses `*[class=…]` attribute selectors with `!important`. This is a legacy pattern but works in the major clients. No defect is shown.

## 4. Personalization & Merge Tokens
No issues found. No unrendered merge tokens (`{{…}}`, `%%…%%`, `[FIRST_NAME]`) appear in the visible HTML. The truncated portion couldn't be checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe header not found (WARN)** and **List-Unsubscribe-Post (RFC 8058) not found (WARN):** the QA note says the AgentMail relay may strip these. This is **unconfirmed**, not a verified sender defect. Verify against the raw message at the original receiving mailbox. Gmail and Yahoo bulk-sender rules require one-click unsubscribe.
- **Authentication-Results not found (WARN):** SPF, DKIM and DMARC status is unknown, and the relay is the likely cause. The From domain is `beauty.sephora.com`. Check alignment from raw headers outside the relay.
- The physical address and in-body unsubscribe link are in the footer, which was truncated. They couldn't be verified.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not assessable. The truncated source didn't expose CTA hrefs, UTM parameters or landing page URLs. The one visible `app.sephora.com` link is an image-tracking path rather than a landing destination. No issues are confirmed.

## 7. Recommendations
1. **Add a multipart text/plain part.** This is the only confirmed QA FAIL.
2. **Add descriptive alt text** to the two flagged images. Use `alt=""` only for purely decorative ones.
3. **Remove `maximum-scale=1`** from the viewport meta and reconsider `text-size-adjust: none`. Scope it to iOS-specific fixes if it is needed at all.
4. **Re-test compliance headers against raw messages** that bypass the relay: List-Unsubscribe, List-Unsubscribe-Post and Authentication-Results. Update the QA tool so it doesn't report relay-stripped headers as sender failures.
5. **Capture the full HTML, footer included,** and raise the probe budget. That would let the audit verify the unsubscribe link, CTA UTMs and landing-page alignment.
6. **Fix the robots meta** to `noindex`. This is low priority.
