## Technical Audit

# Technical Audit: Drunk Elephant Cyber Week, "Biggest sale of the year: 30% off."

Only the truncated HTML and the automated QA output were available. Findings outside what they show are marked unverified.

## 1. Technical Summary
The email is a table-based XHTML 1.0 Transitional template with no hard errors (0 issues, 3 warnings). The confirmed problems are plain-HTTP image sources, missing alt attributes on tracking images, a recipient email address in a tracking URL, and a few markup and accessibility defects. Unsubscribe and authentication status could not be verified.

## 2. Link & Tracking Issues
- **Click links not probed.** 19 tracking links were skipped because they use click-redirect domains, so destination status and redirect chains are unverified.
- **Tracking image has no alt text.** `https://mi.drunkelephant.com/p/up/80acaf1c74f9e002/o.gif?mi_u=98161986&mi_ecmp=us_de_broadcast_promotion_bfcmallaccessst` (open pixel). A pixel should have `alt=""`, and ideally `width="1" height="1"` as well.
- **Second tracking image has no alt text.** `https://drunkelephantus.everestengagement.com/ea/dKhpn7WOgU/?e=…&c=us_de_broad…`.
- **Two tracking vendors.** The email loads `mi.drunkelephant.com` and `everestengagement.com`. Neither is a problem by itself, but there are two separate third-party calls per open.

## 3. Rendering & Accessibility
- **Plain-HTTP images.** The social icons (Facebook, Instagram, TikTok) load from `http://image.cheers.drunkelephant.com/lib/fe3211717064057c751c78/m/1/…png`. Clients that block mixed content or proxy images may drop them. The same host should serve HTTPS, so switching the scheme is likely enough.
- **Misplaced `@import`.** The three `@import url(https://db.onlinewebfonts.com/…)` rules come after `body{…}` in the `<style>` block. `@import` is only valid before other rules, so compliant parsers ignore them. The `<link>` tags in `<head>` still load the same fonts in clients that support them.
- **Third-party font dependency.** `BrownBold`, `BrownLight` and `BrownThin` load from `db.onlinewebfonts.com`. Gmail and Outlook strip or ignore them, so those clients fall back to system fonts. `BrownRegular` is hosted on `drunkelephant.com/on/demandware.static/…/v1719565389232/…`, a versioned Demandware path that can break when the site is redeployed.
- **Zoom disabled.** The viewport meta tag has `maximum-scale=1`, which blocks pinch-zoom and is an accessibility failure (WCAG 1.4.4).
- **No `lang` attribute.** The tag is `<html xmlns=…>` with no `lang`, which hurts screen-reader pronunciation.
- **HTML comments in CSS.** `<!-- *[class=contenttable] … -->` sits inside the `@media` block. Parsers handle this inconsistently, and the rules inside are dead code anyway.
- **Duplicate selectors.** `*[class=vouchertext4]` and `.vouchertext4` repeat each other in both media queries. This is harmless bloat.
- **Document title.** `<title>Drunk Elephant</title>` is generic and doesn't match the subject.

## 4. Personalization & Merge Tokens
- **Recipient email in a URL.** The Everest pixel URL contains `e=darcy-ferment-drunkelephant-fap6e@etell.app`. It is rendered correctly rather than as a raw token. But the plaintext address appears in a query string, where it can show up in proxy logs, referrers and image-proxy caches.
- **No unresolved tokens.** None were found in the visible HTML. The truncated remainder is unchecked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` and `List-Unsubscribe-Post` not found.** The QA tool notes the AgentMail relay may strip these headers, so this is unconfirmed rather than a confirmed defect. It is still a risk for Gmail and Yahoo bulk-sender rules (RFC 8058).
- **SPF/DKIM/DMARC unknown.** `Authentication-Results` was not captured. The From domain is `cheers.drunkelephant.com`, so alignment can't be assessed.
- **Footer unverified.** The in-body unsubscribe link and the physical postal address are not visible in the truncated source.

## 6. Email-to-Site Continuity
- **Campaign IDs are consistent.** The two tracking pixels use `mi_ecmp=us_de_broadcast_promotion_bfcmallaccessst` and `c=us_de_broad…`.
- **No visible UTM parameters.** No `utm_*` parameters appear in the visible portion. Attribution appears to run through the ESP and redirect IDs instead.
- **Landing pages unverified.** All 19 click-tracked links were skipped, so landing-page alignment with the "30% off" offer cannot be confirmed.

## 7. Recommendations
1. Serve the social icons over HTTPS (`image.cheers.drunkelephant.com`).
2. Add `alt=""` to both tracking pixels, and add `width="1" height="1"` where missing.
3. Remove `maximum-scale=1` from the viewport meta tag, and add `lang="en"` to `<html>`.
4. Move the `@import` rules to the top of the `<style>` block, or drop them since the `<link>` tags already load the fonts. Make sure the fallback font stack is robust for Gmail and Outlook.
5. Hash or tokenize the recipient address in the Everest `e=` parameter instead of exposing it in plaintext.
6. Confirm that the raw message has `List-Unsubscribe` and `List-Unsubscribe-Post: List-Unsubscribe=One-Click`, and that SPF, DKIM and DMARC align. Check this against the original message rather than the relay copy.
7. Rerun the audit with the full HTML and a redirect-following probe, so the 19 click links, the footer and the landing pages can be verified.
