## 3. Rendering & Accessibility
- **Invalid `@import` placement:** the `<style>` block opens with `body {…}` and only then has three `@import url(https://db.onlinewebfonts.com/…)` rules. Per the CSS spec, `@import` must come before all other rules, so these imports are ignored. The same fonts are also loaded by `<link>` tags in `<head>`, so the `@import` lines are redundant.
- **Third-party font dependencies:**
  - `db.onlinewebfonts.com` serves BrownBold, BrownLight and BrownThin.
  - `BrownRegular` loads from a versioned Demandware path (`…/v1719565389232/fonts/BrownRegular.eot`) that will break when the storefront redeploys.
  - Most email clients ignore web fonts, so fallbacks matter.
- **Missing alt text (flagged by QA):**
  - `o.gif` (mi.drunkelephant.com pixel).
  - The `everestengagement.com/ea/dKhpn7WOgU/` image.
  - Both are likely tracking pixels and should carry `alt=""` explicitly.
- **Insecure images:** three social icons use `http://`: Facebook (`cc02d07d-…png`), Instagram (`9b452915-…png`) and TikTok (`29f975e1-…png`), all from `http://image.cheers.drunkelephant.com/lib/fe3211717064057c751c78/m/1/`. These can be blocked or flagged as mixed content.
- **Fragile media-query selectors:** the rules use exact-match attribute selectors such as `*[class=vouchertext4]`, `*[class=mobile1]` and `*[class=blocktable]`. These stop matching if an element gets a second class. The `*{line-height:100%}` and `*{-webkit-text-size-adjust:none}` universal rules are also heavy-handed.
