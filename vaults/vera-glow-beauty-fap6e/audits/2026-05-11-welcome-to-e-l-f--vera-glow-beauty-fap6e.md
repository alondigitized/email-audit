## Technical Audit — e.l.f. Cosmetics Welcome Email

### 1. Technical Summary

The email is structurally sound for a table-based layout but contains a confirmed nested `nl-container` duplication indicating a template-composition error. There are also mixed ESP artifact signals (Braze image CDN + Sailthru-style link tracking) that warrant investigation.

---

### 2. Link & Tracking Issues

**ESP mismatch — high confidence signal.**

- Logo CTA uses Sailthru link-wrapping format: `https://links.elfcosmetics.com/f/a/<token>~~/` — the `/f/a/` path prefix and `~~/` token delimiters are Sailthru's canonical redirect pattern.
- Logo image is hosted on Braze CDN: `https://braze-images.com/appboy/communication/assets/image_assets/images/6532bc91543698004cb67f6e/original.png?1697823889`

This combination — Sailthru link tracking wrapping a Braze-hosted asset — suggests either (a) an in-flight ESP migration where image assets were not re-uploaded to the new platform, or (b) a hardcoded Braze URL that survived a migration to Sailthru. If the brand is fully on one ESP, the image should be re-hosted there to eliminate the external Braze dependency.

**Stale image asset.** The `?1697823889` cache-buster is a Unix timestamp resolving to **October 20, 2023** — this asset has not been updated in ~2.5 years. Not blocking, but verify the logo hasn't been refreshed since then.

**Destination URLs not assessable** from truncated source — full link audit requires decoded redirect targets.

---

### 3. Rendering & Accessibility

**Empty `<title>` tag.**
```html
<title></title>
```
Some email clients (notably Apple Mail and Outlook desktop) surface the `<title>` value. Empty title is a missed opportunity and may display as blank in client previews.

**Nested `nl-container` table — confirmed template composition error.**

The outer shell already establishes `class="nl-container"`, but the logo block embeds a second complete `nl-container` tree inside `block-1`'s `<div>`:
```html
<table class="nl-container" …>          <!-- outer -->
  …
  <td class="pad"><div …>
    <table class="nl-container" …>      <!-- inner duplicate -->
```
This creates redundant table nesting that can cause rendering drift in Outlook (extra cell spacing) and inflates HTML weight unnecessarily.

**Google Fonts `<link>` stripped by Gmail.**
```html
<!--[if !mso]><!-->
<link href="https://fonts.googleapis.com/css?family=Open+Sans" …>
<!--<![endif]-->
```
Gmail (web + app) strips `<link>` tags from `<head>`, so Open Sans will not render there. Fallback chain `Arial, Sans-serif` is functional — this is a rendering degradation, not a breakage.

**Futura (brand headline font) is not web-loaded anywhere.** The 72px headline uses:
```css
font-family: 'Futura Std ExtraBold', 'Futura Extra Bold', 'Futura', Verdana, Geneva, sans-serif;
```
Futura is not a system font on Windows or Android. Clients without it fall to Verdana — visually inconsistent with brand intent. No `@font-face` or web font `<link>` loads Futura.

**`tabindex="-1"` on logo anchor** — correct; removes the decorative link from keyboard tab order.

**`alt="e.l.f."` on logo image** — adequate and present.
