### 3. Rendering & Accessibility

**Google Fonts `<link>` tag will silently fail in most clients:**
```html
<link href="https://fonts.googleapis.com/css2?family=DM+Sans:...&display=swap" rel="stylesheet">
```
Gmail (webmail and app), Outlook (all desktop versions), Yahoo Mail, and Samsung Email strip or block external `<link>` stylesheets. DM Sans will not render for the majority of recipients. The declared fallback `.helvetica { font-family: Helvetica, Arial, sans-serif; }` exists but it is a class — not a `body` or `td` default — so coverage depends on how broadly it is applied to elements in the truncated body.

**Dead CSS inflating payload:**
A large hamburger-menu block is commented out with ticket reference `91925`. The commented code runs several hundred bytes inside `<style>`. While inert, it increases raw email size, which affects Gmail's clipping threshold (102 KB) and can trigger the "Message clipped" truncation.

```css
/* 91925 Commenting out hamburger menu |BEGIN Hamburger Menu
   #mobile-label { ... }
   ...
   END Hamburger Menu */
```
Recommendation: strip entirely before send.

**`<title>` tag has a trailing space:**
```html
<title>Ulta Beauty </title>
```

Minor — no functional impact but indicates a template rendering artifact.

**`translate="no"` on `<html>` element:**
Suppresses browser/client auto-translation globally. Intentional for brand copy, but will also block translation for legal disclaimer text and terms — a potential accessibility concern for non-English-dominant recipients in Ulta's database.
