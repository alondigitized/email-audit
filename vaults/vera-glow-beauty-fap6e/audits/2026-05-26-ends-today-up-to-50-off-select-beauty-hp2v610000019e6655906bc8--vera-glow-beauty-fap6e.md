### 3. Rendering & Accessibility

**[CONFIRMED] `maximum-scale=1` blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Fails WCAG 1.4.4 (Resize Text) and is flagged by modern email accessibility linters. Remove `maximum-scale=1`.

**[CONFIRMED] `text-size-adjust: none` applied to body-level elements**
```css
div, a, tr, table, body, span, img, strong, td {
  -webkit-text-size-adjust: none;
  -ms-text-size-adjust: none;
  -moz-text-size-adjust: none;
  text-size-adjust: none;
}
```
Applying this to `body` and block-level elements suppresses OS-level font scaling for low-vision users. Acceptable scoped to `.sup` (its declared purpose); applying it globally is an accessibility defect.

**[CONFIRMED] Duplicate responsive CSS rule blocks**
The `@media (max-width: 480px)` block declares `.show` and `.appear` twice each with identical selectors:
```css
/* First declaration */
*[class=show], .show { display: block !important; width: 100% !important; … }
/* Second declaration — immediately follows */
*[class=show], .show { display: block!important; display: table!important; }
```
Same pattern for `.appear`. The duplicate `display: block` / `display: table` on the second pass is redundant dead weight and increases parse time, though rendering impact is minimal in practice.

**[CONFIRMED] Missing `lang` attribute on `<html>` element**
```html
<html xmlns="..." xmlns:v="..." xmlns:o="...">
```
No `lang="en"` (or locale variant). Screen readers cannot determine language; WCAG 3.1.1 failure.

**[CONFIRMED] `robots` meta value is malformed**
```html
<meta name="robots" content="no index" />
```
`"no index"` (with space) is not a recognized directive — the correct token is `"noindex"`. Email clients ignore this tag, but it indicates a template hygiene issue.

**[Inconclusive] Image alt text** — body truncated; cannot audit.
