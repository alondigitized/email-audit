### 2. Link & Tracking Issues

**Encoded redirect chain, no visible UTM params in source**
All links route through `links.elfcosmetics.com/f/a/<token>~~/...` — a Sailthru-format opaque redirect. UTM parameters are not present in the raw `href`; they would only appear post-redirect. This makes pre-send link auditing impossible without decoding the payload, and breaks any tooling that inspects raw source for UTM coverage.

**Image asset timestamp suggests stale cache-buster**
Hero image URL: `https://braze-images.com/appboy/communication/assets/image_assets/images/6537d6e7f775160058956f5a/original.png?1698158310`
The query param `1698158310` is a Unix timestamp resolving to **October 24, 2023** — over 2.5 years ago. If this is a cache-busting parameter, it is not being regenerated per send, and will not force re-fetch if the asset is updated.

**Logo image is a full-width CTA with a single tracked link**
The e.l.f. logo `<img>` at the top is wrapped in an `<a>` pointing to the encoded redirect. If this redirect target is not the homepage or a contextually relevant landing page, it's a missed alignment opportunity (see §6).

### 3. Rendering & Accessibility

**Empty `<title>` tag**
```html
<title></title>
```
Several email clients (Apple Mail, Outlook for Mac, Samsung Mail) display the `<title>` value in the window or tab chrome. Empty title degrades the experience for recipients with multiple emails open and reduces screen-reader context.

**`#MessageViewBody a` rule suppresses link color and underline in Gmail**
```css
#MessageViewBody a { color: inherit; text-decoration: none; }
```
This Gmail-targeted override strips all visual link differentiation. Any inline `<a>` text that doesn't have an explicit `color` and `text-decoration` style on the element itself will be invisible as a link to Gmail users. Confirmed risk for any text-based CTAs in the body (not visible in truncated source, but a structural hazard).

**Redundant nested `nl-container` table**
Row 1 wraps an `html_block` that itself contains a full second `nl-container > row > row-content > column` table tree. This produces at least 6 additional unnecessary table nesting levels, which increases parse complexity in Outlook's Word renderer and can cause unexpected width/margin calculations.

**Three consecutive empty `html_block` divs (block-2, block-3, block-4)**
```html
<div style="font-family:Open Sans,Arial,Sans-serif;text-align:center" align="center"> </div>
```
These render as zero-content nodes that still emit whitespace. In Outlook they can materialize as phantom spacing rows. Should be removed or replaced with a proper `spacer_block`.

**Google Fonts loaded via `<link>` without `media` guard**
```html
<!--[if !mso]><!--><link href="https://fonts.googleapis.com/css?family=Open+Sans" ...><!--<![endif]-->
```
The conditional comment correctly skips Outlook, but the URL uses the legacy `?family=` API (not `css2`). This works but is the older endpoint. More importantly: if the recipient's network blocks Google Fonts (corporate proxies, privacy-hardened clients), there is no `@font-face` fallback embedded — the stack falls back to `Arial,Sans-serif`, which is the intended fallback but is never explicitly tested to ensure layout doesn't break.

**No `lang` attribute on inner tables**
`lang="en"` is set on `<html>` — correct. But screen readers and translation engines in some clients re-scope to the inner table structure; no inner `lang` declarations means any multilingual content blocks (if present in the full source) would inherit incorrectly.

### 6. Email-to-Site Continuity

**UTM parameters not auditable from raw source**
Because all hrefs are Sailthru opaque redirects, UTM attribution cannot be verified without decoding. Best practice is to confirm in the ESP's link manager that UTMs are appended post-redirect with at minimum:
- `utm_source=email`
- `utm_medium=email`
- `utm_campaign=<campaign-slug>`
- `utm_content=<cta-identifier>`

Without `utm_content` per CTA, GA4/analytics cannot distinguish which link drove a conversion.

**Hero image link destination unknown**
The single visible CTA (logo image) routes to an encoded redirect. If it resolves to the homepage rather than a Bronzing Drops PDP or dedicated landing page, it breaks subject-line-to-landing-page continuity ("Summer skin / UV rays" → should land on SPF/bronzing product page, not homepage).
