# Grab 20% Off Before It’s Gone!
**Score:** 7/10 · **Type:** Email audit · **2026-06-08**
## Executive summary

- Drunk Elephant, which sent me two emails on June 5th alone and has been dropping into my inbox basically every other day since the Friends & Family marathon finally ended, shows up with a subject line that reads like a sitewide flash sale. "Grab 20% Off Before It's Gone!" — I open expecting to throw a Lala Retro in my cart. What's actually inside? A SheerID verification gate for teachers, nurses, military members, and first responders. I am none of those. That gap between subject promise and body reality is the entire problem with this send.
- To be fair to DE: the execution inside the email is clean. "IT SERVES YOU RIGHT." is a genuinely good pun — it earns its hero placement. Bumping the existing SheerID discount from 15% to 20% for a limited window is a smart retention move for the people who qualify. The layout is very DE — restrained, minimal, mobile-friendly. The three-step verification flow is clear. But none of that matters to me specifically, because I'm the wrong person to receive this.
- I'm marking this as read. Not forwarding. The only version of this email I click is if I somehow become a registered nurse between now and whenever "limited time only" expires.

## What's working

- "IT SERVES YOU RIGHT." — sharp headline pun, doesn't oversell itself, lands clean in the hero without feeling try-hard
- The 15% → 20% framing is a smart upgrade signal — it implies DE already had a program and is actively improving it, which reads as appreciation rather than just acquisition
- Clean three-step layout for the verification flow — numbered, scannable, no jargon
- The segmentation chips at the bottom (A Teacher, A Student, A Medical Professional, etc.) are clear tappable entry points for anyone who qualifies — good UX decision
- No render bugs, text is legible, layout holds on mobile — DE's execution is consistently clean

## What's weak

- The subject line is a bait-and-switch — "Grab 20% Off Before It's Gone!" reads as a general flash sale, not a profession-gated program; non-qualifying subscribers feel misled the moment the email loads
- This should have been segmented before it sent — if SheerID already has verified users in the database, that's the list; everyone else gets a softer awareness message, not a sale-coded subject line
- "For a limited time only!" is doing zero urgency work — compare this to how Sally Beauty ran their summer email with specific dates; vague deadline language kills the FOMO before it starts
- Not one DE product visible in the body — no Lala Retro, no B-Hydra, no hero SKU to covet while clicking through verification; qualified recipients have nothing to want yet
- DE has sent me five emails in eight days — this professional-discount announcement gets buried in the cadence noise from "Hydrated skin," "Bestsellers await you!," and the double-send on June 5th

## Recommendations

- 1. **Segment this send to profession-qualified or SheerID-verified subscribers only** — if the data exists, use it; if it doesn't, build a soft opt-in version for the broader list that doesn't promise a discount they can't access
- 2. **Rewrite the subject to match the actual offer** — stop the bait-and-switch; tell me who this is for before I spend the open
- 3. **Add a specific end date** — "offer ends June 22" does what "limited time only" cannot; credible urgency needs an anchor
- 4. **Drop one hero product into the body** — even a single SKU gives qualified recipients something to covet during the verification flow, and reduces the "nothing to buy here" friction
- 5. **Dial back the overall send cadence** — an email this targeted deserves space to land; it gets lost after five sends in eight days
- **Subject Alt A:** `Teachers, nurses & first responders: your discount just got better`
- **Subject Alt B:** `Your 20% professional discount — now through [Date]`
- **Preheader Alt A:** `We bumped your SheerID rate from 15% to 20% for a limited time — verify or re-verify to claim`
- **Preheader Alt B:** `Get verified once, save every month. Now at 20% off.`

### 3. Rendering & Accessibility

**[HIGH] HTML comment tokens inside `<style>` block**
```css
@media only screen and (max-width: 600px) {
  <!-- *[class=contenttable] { width:414px !important;} -->
  <!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
```
`<!-- -->` delimiters inside a CSS block are invalid. Modern parsers treat this as raw CSS text, not a comment. These two rules will never apply on mobile, silently breaking `contenttable` and `mobile` class width overrides for subscribers under 600px.

**[HIGH] Duplicate font load — `<link>` + `@import` for same URLs**
Three `<link>` tags and three `@import` statements in `<style>` reference identical `db.onlinewebfonts.com` URLs for Brown Bold, Brown-Light, and Brown-Thin. This doubles HTTP requests for the same assets on every render. Example:
- `<link href="https://db.onlinewebfonts.com/c/4150d76a852e1c349e0b6fe15f29d9ca?family=Brown+Bold">`
- `@import url(https://db.onlinewebfonts.com/c/4150d76a852e1c349e0b6fe15f29d9ca?family=Brown+Bold);`

**[MEDIUM] Third-party font CDN dependency (`db.onlinewebfonts.com`)**
All Brown typeface variants load from `db.onlinewebfonts.com`, a public font redistribution service. Corporate email gateways and proxy-heavy environments routinely block requests to unlisted CDNs. The "Brown" typeface is a commercially licensed font (Lineto Fonts); hosting it via this CDN is likely a licensing violation. First-party `drunkelephant.com/demandware.static` sources exist in the `@font-face` block for BrownRegular only — other weights should follow the same pattern.

**[MEDIUM] `maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from pinch-zooming on mobile. Violates WCAG 1.4.4 (Resize Text, AA). This is particularly relevant for an audience reading product ingredient details.

**[MEDIUM] `.appleLinks` suppresses all link visibility in Apple Mail**
```css
.appleLinks a {color: #000000 !important; text-decoration: none !important;}
```
Any element wrapped in `.appleLinks` will render its links as black, undecorated text in Apple Mail — visually indistinguishable from body copy. If CTAs or promo code links fall inside this wrapper, they will be invisible to Apple Mail subscribers (a significant share of mobile opens).

**[LOW] Global `line-height: 100%` reset**
```css
* { line-height: 100% }
```
Applying `line-height: 100%` to `*` overrides proper leading on all text elements. In Outlook, `100%` line-height on `<td>` elements can cause text overlap at larger font sizes.

**[LOW] Missing `lang` attribute on `<html>` tag**
No `lang="en"` visible on the `<html>` element. Affects screen reader language detection and client-side spell-checking.
