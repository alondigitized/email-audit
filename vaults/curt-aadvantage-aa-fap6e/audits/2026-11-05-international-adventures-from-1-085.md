## Technical Audit

## 1. Technical Summary
The email renders from a standard XHTML table layout with a hidden preheader and dark-mode CSS. It has three confirmed defects: an unencoded space in a tracked `href`, an empty `Hi ,` greeting, and a 403 on one CTA. The remaining flags are CSS hygiene issues. The compliance and authentication checks couldn't be verified.

## 2. Link & Tracking Issues
- **Malformed href (confirmed).** The "American Airlines" link contains a literal space in the `x=` parameter: `…%7cMKT%7cUSPFMOC%7cAA Brand-Airline%7cERINC%7c…`. The other delimiters are percent-encoded (`%7c`), so this one was missed. Strict parsers reject it ("URL can't contain control characters"). Mail clients that don't normalize the space may truncate the URL at `AA`, which drops the `hp2=` hash and could break click attribution or the redirect.
- **403 on CTA.** "Get more from your getaway" returned 403 at `https://l.loyalty.ms.aa.com/rts/go2.aspx?h=6678556&tp=i-1NGB-GT-…`. Tracked redirectors often 403 automated probes, so this may be bot-blocking rather than a user-facing failure. It is unverified from real clients. The link text was also empty in the QA row, so the anchor may wrap an image.
- **Coverage gap.** Only 12 of 29 links were probed and 17 were skipped, so the other links are unverified.
- **Insecure image source.** `http://i.loyalty.ms.aa.com/wpm/1021/ContentUploads/american_airlines/CTAs/oneworld_logo_special_online_80x80.gif` ("oneworld logo") uses plain HTTP. Gmail's image proxy upgrades it, but other clients may block it or show a mixed-content warning.

## 3. Rendering & Accessibility
- **Dark-mode override is too broad.** `@media (prefers-color-scheme:dark){ span, a, td { color:#ffffff !important; } }` forces white text on every `td`, `a` and `span`. Any cell without the `.lightblue-bg` class and with a light or white background (for example white content cards) will end up white-on-white, because only `.lightblue-bg` and `.cta-bg` get background overrides.
- **Zoom disabled.** `<meta name="viewport" content="…maximum-scale=1">` blocks pinch-zoom, which is a WCAG 1.4.4 concern.
- **Broken relative asset path.** `#swapbg { background-image: url("../20230508_HTML-32134_M_bg.png") !important; }` is a relative URL that will not resolve in an email client. The mobile background swap will fail, and the filename suggests a stale template.
- **Redundant font loading.** The Roboto font is loaded three times: `<link rel="stylesheet">`, `@import` and `<link rel="preconnect">`. Gmail and Outlook strip most of these, so the fallback stack matters. The `[if gte mso 9]` style block is also duplicated verbatim.
- **Blunt global rules.** `p { margin:0 auto; text-align:center }` and `* { line-height:100%; -webkit-text-size-adjust:none }` can cause unintended inheritance and prevent text resizing on iOS.
- **Not assessable.** The HTML was truncated, so I can't check alt text beyond the QA finding on the oneworld logo.

## 4. Personalization & Merge Tokens
- **Empty name slot (confirmed).** The greeting renders as `Hi ,` with the name field empty. There is no fallback value. This is either a failed merge or a test or seed-account artifact. The fix is to add a default (`Hi there,`) or suppress the greeting when the name is empty.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Headers not captured.** `List-Unsubscribe`, `List-Unsubscribe-Post` (RFC 8058) and `Authentication-Results` were all not found. The QA tool notes the AgentMail relay may strip them. These are **unverified, not confirmed absent**. From `loyalty@loyalty.ms.aa.com`, a bulk sender to Gmail and Yahoo, the headers are required, so they should be checked against raw source from a direct-delivery inbox.
- **Unsubscribe link.** The QA run says an unsubscribe link is always probed, but no result for it is listed. I can't confirm its status or the physical address from the truncated source.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- Links use a proprietary redirector (`l.loyalty.ms.aa.com/rts/go2.aspx`) with a pipe-delimited campaign code in `x=` (`EML|SOLO|20261105|MKT|USPFMOC|…|US_ROUTE_TRAN_QASA_SALE`). There are no `utm_*` parameters in the visible URLs. Attribution depends on the redirector passing that code through to the destination, and that can't be verified here.
- Final landing pages were not resolved. The probe stopped at the redirect (the 403 on one CTA), so I can't check that the pages match the "from $1,085*" offer.

## 7. Recommendations
1. Percent-encode the space (`%20`) in the `x=` parameter of the "American Airlines" link and add an encoding check in the ESP template build.
2. Manually click the 403 CTA from a real client or a browser user-agent to see whether it is probe-blocking or a real error.
3. Add a fallback for the first-name merge field and gate the greeting when it is empty.
4. Serve the oneworld logo over HTTPS.
5. Scope the dark-mode color override to specific classes instead of `span, a, td`, and add background overrides for light cells.
6. Remove `maximum-scale=1` from the viewport meta tag.
7. Remove the broken relative `#swapbg` background URL, or replace it with an absolute HTTPS URL.
8. Remove the duplicate MSO style block and the redundant font loading.
9. Check the raw headers (`List-Unsubscribe`, `List-Unsubscribe-Post`, SPF, DKIM, DMARC) from a direct-delivery inbox. The relay results don't prove anything either way.
10. Re-run the link probe at full coverage (all 29 links) and include landing-page resolution to confirm the continuity checks.
