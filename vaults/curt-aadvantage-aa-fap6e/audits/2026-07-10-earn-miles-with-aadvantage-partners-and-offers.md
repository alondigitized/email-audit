# Earn miles with AAdvantage® partners and offers
**Score:** 9/10 · **Type:** Email audit · **2026-07-10**
## Executive summary

- This is a partner-offer compilation email with IHG Hotels as the hero. After a string of AA-native sends — 9,000-mile flights, FIFA sweeps, an experiential benefits pivot, and last week's Vacations sub-brand cross-sell — this email returns to the loyalty ecosystem: earn miles at hotels, cruises, and dining; spend them at the Exchange marketplace. That's the right message for a member this far into onboarding, and the IHG partnership is a credible, globally recognizable anchor.
- Where it breaks down is before the open. "Earn miles with AAdvantage® partners and offers" is the most generic possible container for content that includes a specific hotel brand, a cruise partner with a hard deadline 11 days out, and an AAdvantage Dining enrollment ask. IHG belongs in the subject line. The body earns the click; the subject line doesn't earn the open.
- The four-block secondary grid is functionally fine — the layout is clean, the CTAs are distinct — but the email is asking for five separate actions simultaneously. That's acceptable as a monthly partner digest but makes it difficult to optimize for a single conversion. The June 22 / July 6 flight replay pair already showed AA is willing to repeat itself; this send avoids that trap by introducing genuinely new partners, which is the right call.

## What's working

- IHG hero communicates the earn mechanism ("up to 3 AAdvantage® miles for every $1 spent") immediately — a frequent traveler knows exactly what they're evaluating
- The "Book by 7/21" deadline on the cruise block is the only hard date in the email and creates real urgency for that specific offer
- Four-block partner grid is visually balanced with distinct CTAs — no offer cannibalizes another
- "You are why we fly" footer maintains AA's emotional brand close; consistent across every send in this sequence
- No render bugs anywhere in the screenshot

## What's weak

- "Earn miles with AAdvantage® partners and offers" is a folder label, not a subject line — IHG is named inside the email but hidden from the inbox
- No July/summer hook; with the cruise's 7/21 deadline and a summer travel season in full swing, the seasonal angle is completely unused
- "Explore hotels" as the hero CTA is as generic as "Discover" — the actual hook ("earn 3 miles per $1") is stronger than the button copy
- Five simultaneous asks (hotels, cruise, dining enroll, dining earn, Exchange spend) with no visual priority signal beyond layout order
- Zero personalization — no name token, no member tier acknowledgment, no callback to past activity

## Recommendations

- 1. **Name IHG in the subject.** It's a globally recognized brand with 7,000+ properties. "Earn miles at IHG, cruises & dining" would outperform the generic container on open rate alone.
- 2. **Rewrite the hero CTA to lead with the earn rate.** "Earn 3X miles at IHG hotels" is specific; "Explore hotels" could apply to any travel email from any brand.
- 3. **Add a summer urgency layer.** July 2026, cruise deadline 7/21 — these are natural hooks that go unused. Connect the send to a reason to act now.
- 4. **Trim to three offers.** The cruise has a deadline and should get more visual weight. AAdvantage Dining and the Exchange can go in a dedicated digest; they dilute the IHG and cruise story here.
- 5. **Insert a name or tier token in the subhead.** "Curt, here's how your miles work harder this summer" requires one merge tag and turns a batch send into a targeted one.

- **Preheader Alt A:** `Plus: cruise miles offer ends 7/21 — don't miss the deadline`

### 3. Rendering & Accessibility

**Duplicate MSO conditional block (confirmed bug):**
The `<!--[if gte mso 9]>` style block is emitted twice verbatim. No functional breakage, but it bloats the payload and signals a template assembly error.

**Unclosed `@media` dark-mode block (confirmed bug):**
```css
@media (prefers-color-scheme:dark) {
  ...
  [data-ogsc] span, [data-ogsc] a, [data-ogsc] td { color: #ffffff !important; }
/* ← no closing } before </style> */
```
The `@media` wrapper is never closed. CSS parsers that are strict (Apple Mail, Samsung Mail) will discard the entire dark-mode block. All dark mode styling is silently non-functional.

**Overly broad dark-mode text override:**
Inside the broken `@media` block: `span, a, td { color: #ffffff !important; }` forces white on every span/anchor/td. If the block were fixed and a client only overrides text color (not backgrounds), light-on-light combinations would appear in hybrid-render clients (e.g., Gmail Android dark mode).

**`-webkit-text-size-adjust: none` on universal selector:**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
`none` (not `100%`) suppresses user-initiated text scaling — a WCAG 1.4.4 violation. Safe fix: use `100%`.

**`maximum-scale=1` in viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocks pinch-to-zoom on iOS. WCAG 1.4.4 failure. Remove `maximum-scale=1`.

**Redundant Google Fonts load:**
Fonts are requested via both `<link rel="stylesheet" href="https://fonts.googleapis.com/...">` and `@import url('https://fonts.googleapis.com/...')` inside a `<style>` block. This triggers two network requests for the same resource. Most clients strip `<head>` `<link>` tags anyway, making the `@import` the only operative path — the `<link>` and `<link rel="preconnect">` tags are effectively dead weight in email context.

**Duplicate `.gmailfix` property:**
```css
.gmailfix { display: none; display: none!important; }
```
Redundant declaration. Harmless but indicates copy-paste template hygiene issues.
