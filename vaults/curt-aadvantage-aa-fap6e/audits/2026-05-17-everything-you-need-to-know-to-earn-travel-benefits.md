# Everything you need to know to earn travel benefits
**Score:** 8/10 · **Type:** Email audit · **2026-05-17**
## Executive summary

- This is AA's third email to a new AAdvantage member in two days (following the welcome and temp-password sends), and it does exactly what a good onboarding sequence should: it teaches before it sells. The miles-vs-loyalty-points explainer is genuinely useful for someone who just created an account and doesn't know the program. The layout is clean, the 100th anniversary branding is consistent, and the buried 3,000-bonus-miles offer gives a tangible first action.
- The big miss is structural: the single highest-intent moment — the personalized "Earn 3,000 bonus miles" offer — is buried behind two dense educational sections and a tip callout. By the time the eye gets there, momentum is lost. That offer deserves to be the hero, not the footnote.
- For a brand that nailed the triggered welcome email (May 15), this one feels like a batch content-marketing send dressed up as a personalized follow-up. It's useful, not urgent.

## What's working

- The miles-vs-loyalty-points comparison diagram is clean and genuinely clarifies a confusing program mechanic — right answer for a Day 3 onboarding email.
- The "Just for you" 3,000-mile offer is concrete, low-friction (only $0.50+ purchase required), and well-labeled as personalized.
- "Register now" is a sharp, unambiguous CTA — no vague "Discover more" language.
- No render bugs: images load, layout is intact, text doesn't overlap.
- 100th anniversary branding in the header maintains continuity with the welcome email.

## What's weak

- The bonus-miles offer is buried well below the fold — a new member who skims will miss the one thing worth acting on.
- "Add your card here" CTA appears above the hero content, creating competing priorities before context has been established.
- "How will you earn? → Flights / Partners / Credit card" section is redundant with the prior welcome email and pads the length without new value.
- The subject ("Everything you need to know…") is an evergreen content-marketing headline with zero urgency and zero offer signal — it doesn't hint at the 3,000-mile opportunity inside.
- No deadline visible on the 3,000-mile offer — "register now" without a date creates no real urgency.

## Recommendations

- 1. **Lead with the offer.** Flip the structure: open with the "Just for you: 3,000 bonus miles" panel as the hero, then use the educational content as supporting context below it. The personalized offer is the most valuable thing in this email.
- 2. **Set a deadline.** Add an explicit expiry ("Offer expires June 1") to the bonus-miles panel to convert soft interest into immediate action.
- 3. **Rewrite the subject to tease the offer.** The current subject buries the lede.
- **Subject Alt A:** `Your 3,000 bonus miles are waiting — here's how to earn`
- **Subject Alt B:** `New member tip: earn 3,000 miles with your first purchase`
- 4. **Tighten or kill the "How will you earn?" section.** The welcome email already covered this. Replace it with a single "Your next milestone" status nudge toward Gold status.
- 5. **Preheader should preview the offer, not the content.**
- **Preheader Alt A:** `Register now and earn 3,000 bonus miles on your first eligible purchase.`
- **Preheader Alt B:** `Miles expire if unused — here's how to keep yours active.`

### 3. Rendering & Accessibility

**Issue 3.1 — Duplicate MSO conditional block**
The `<!--[if gte mso 9]>` style block is emitted identically twice in `<head>`. Redundant weight; no functional harm, but indicates a template merge defect.

**Issue 3.2 — Misspelled fallback font name**
```css
/* desktop .scrollmenu rule */
font-family: Roboto, ariel, helvetica, sans-serif;
```
`ariel` is not a font name — should be `Arial`. The mobile media query override correctly uses `Arial`. On clients where Roboto doesn't load (Gmail web strips Google Fonts), Outlook on Windows will skip `ariel` and fall through to `helvetica`, which is fine, but this is a latent bug in any client that applies it literally.

**Issue 3.3 — Google Fonts double-loaded**
Roboto is requested twice: once via `<link rel="stylesheet" href="https://fonts.googleapis.com/css2?...">` and again via `@import url('https://fonts.googleapis.com/...')` inside a `<style>` block. This generates two identical HTTP requests before render. Remove the `@import`; the `<link>` tag is sufficient (and preferred by ESP pre-fetchers).

**Issue 3.4 — Truncated CSS declaration in dark-mode block**
```css
[data-ogsc] .dark-text { color: #f9fafb !important; }
[data-ogsc] .light-text { color: #181E25 !importan…
```
The `!important` keyword is cut off mid-declaration. If this truncation exists in the actual sent HTML (not only in this audit excerpt), the `.light-text` dark-mode override will be silently dropped by all CSS parsers — rule ignored, no error surfaced.

**Issue 3.5 — Missing descendant combinator in `[data-ogsc]` selector**
```css
[data-ogsc].ctablue-bg { background-color: #0860C4 !important; }
```
All other `[data-ogsc]` rules include a space (descendant selector). This one is a compound selector targeting an element that simultaneously has `data-ogsc` AND class `ctablue-bg` — almost certainly unintentional. Should be:
```css
[data-ogsc] .ctablue-bg { background-color: #0860C4 !important; }
```

**Issue 3.6 — `maximum-scale=1` blocks pinch-zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from zooming on mobile. Violates WCAG 1.4.4 (Resize Text, Level AA). Remove `maximum-scale=1`.

**Issue 3.7 — Global `text-size-adjust: none`**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; ... }
```
Suppresses OS-level font scaling across all elements. Conflicts with user accessibility settings. The accepted pattern is `100%` on `body`, not `none` on `*`.
