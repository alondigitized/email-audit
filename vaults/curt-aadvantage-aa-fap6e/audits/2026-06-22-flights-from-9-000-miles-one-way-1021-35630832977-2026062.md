# Flights from 9,000 miles one way
**Score:** 8/10 · **Type:** Email audit · **2026-06-22**
## Executive summary

- This is AA's seventh email to this AAdvantage member, arriving 23 days after the last send — the longest gap in the sequence since the welcome email. That breathing room works in its favor: after six tightly-spaced onboarding messages through May, a late-June flight redemption offer feels earned rather than pestering. The creative makes a smart gear-shift from "here's how AAdvantage works" to "here's what you can do with your miles right now." Three destination tiers (U.S. / Mexico–Caribbean / Europe) map the full redemption spectrum cleanly, and the account module at the bottom closes the loop by connecting the offer to the member's actual points balance.
- The main drag is a mid-email pivot into a shopping/partner promotion ("The next top awaits — save up to 40%") that has nothing to do with flights. It reads like a second email pasted in, and it fragments a narrative that was building momentum. The "0 Loyalty Points" shown for a new member is another minor self-inflicted wound — likely confusing to someone who doesn't yet know what Loyalty Points are or how they differ from AAdvantage miles.
- Clean design, solid creative direction, one unnecessary detour. Fix the focus problem and this is a very strong redemption-prompt send.

## What's working

- **Concrete subject line ("9,000 miles one way")** sets the price before the open and earns the click on specificity alone.
- **City-level copy in the U.S. block** ("Chicago to historic streets in Philadelphia or southern charm in Charlotte") makes domestic feel real, not generic.
- **Three-tier destination structure** lets the reader self-select — domestic, regional, international — without forcing a single choice.
- **Account module at the bottom** showing AAdvantage points balance is smart personalization: it connects the offer directly to what the member already holds.
- **23-day cadence gap** after the heavy May onboarding burst was the right call; this send doesn't feel like the 4th identical promo this week.

## What's weak

- **Shopping/partner section ("The next top awaits — save up to 40%")** is jarring — completely off-theme, disrupts the flight-redemption arc, and forces an unrelated decision mid-scroll.
- **"0 Loyalty Points"** is displayed without context for a new member; it reads as "you have nothing" and could undermine the feel-good of the offer.
- **"Search flights" CTA on Europe vs. "Book now" on U.S. and Mexico** is an inconsistency that signals lack of polish and implies Europe is harder to book (even if true).
- **"For a limited time"** is vague. No deadline date anywhere — urgency is claimed but not credible.

## Recommendations

- 1. **Cut the shopping section.** The flight-redemption message should be single-minded. If the partner promotion has value, give it its own dedicated send.
- 2. **Add a real deadline.** Replace "for a limited time" with a specific date ("Now through July 15"). Put that date in the subject or at minimum the first body sentence.
- 3. **Standardize the CTAs.** All three destination blocks should have the same button label. "Book now" across the board, or "Search flights" across the board — not a mix.
- 4. **Contextualize "0 Loyalty Points"** with a tooltip or small-print explanation so new members don't interpret it as a failure state.
- 5. **Add urgency to the subject line** — this is the highest-leverage single change.

- **Preheader Alt A:** `U.S., Caribbean, and Europe — all within reach of your AAdvantage balance`

### 3. Rendering & Accessibility

**[HIGH] Broken relative path in mobile CSS**
```css
#swapbg {
  background-image: url("../20230508_HTML-32134_M_bg.png") !important;
}
```
Relative URLs do not resolve in email clients — there is no base filesystem context. The mobile hero background image will fail silently in all email clients when the viewport is ≤ 480px. Must be an absolute `https://` URL.

**[HIGH] Unclosed `@media (prefers-color-scheme:dark)` block**
The dark-mode `@media` block ends without a closing `}` before `</style>`. In strict CSS parsers (Apple Mail, some Outlook versions), this causes the entire `<style>` block to be discarded, disabling all dark-mode overrides and potentially corrupting other styles.

**[MEDIUM] Google Fonts loaded twice**
The font is fetched via both a `<link>` tag and a `@import` in the same `<style>` block:
```html
<link href="https://fonts.googleapis.com/css2?family=Roboto:...&display=swap" rel="stylesheet">
```
```css
@import url('https://fonts.googleapis.com/css2?family=Roboto:...&display=swap');
```
This issues two identical render-blocking HTTP requests per open. Remove the `@import`; the `<link>` tag is sufficient (and `@import` in email is less reliable anyway).

**[MEDIUM] Duplicate MSO conditional comment blocks**
The `<!--[if gte mso 9]>` block containing font-family overrides appears twice verbatim. No functional harm in Outlook, but it inflates message size and indicates a template assembly error.

**[MEDIUM] `maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Disables pinch-to-zoom. Violates WCAG 1.4.4 (Resize Text, Level AA). Change to `maximum-scale=5` or remove the constraint.

**[LOW] Overly broad dark-mode color override**
```css
span, a, td { color: #ffffff !important; }
[data-ogsc] span, [data-ogsc] a, [data-ogsc] td { color: #ffffff !important; }
```
Applying `#ffffff` to all `span`, `a`, and `td` without a container scope will force white text on any element that doesn't have an explicit dark background, including potentially preheader text or fallback cells. Scope to a wrapper class (e.g., `.email-body span`).

**[LOW] `* { -webkit-text-size-adjust: none }`**
The wildcard rule sets `none` (not `100%`). `none` completely disables automatic text size adjustment in WebKit-based clients, which can make small text unreadable on mobile without zooming (which is also blocked by `maximum-scale=1`).

**[LOW] `p { text-align: center; margin: 0 auto; }`**
Global center-alignment on all `<p>` tags is aggressive and will override any paragraph-level alignment set elsewhere in the template.
