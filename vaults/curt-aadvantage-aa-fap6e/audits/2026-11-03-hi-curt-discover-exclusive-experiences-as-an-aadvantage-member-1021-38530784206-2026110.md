## Technical Audit

## 1. Technical Summary
The email's markup is standard table-based XHTML, but the automated QA run found serious problems. Six CTA tracking links exceeded 10 redirects, two primary links returned 403, and the body greeting has an empty name slot. The header-dependent compliance and authentication checks couldn't be completed. The HTML source is truncated, so findings from the footer and later sections rely on the QA data.

## 2. Link & Tracking Issues
- **Excessive redirects (6 links, all `[FAIL]`).** These are the main CTAs: "See Disney On Ice", four "Get tickets" links (`h=6672827`, `6672829`, `6672831`, `6672833`) and "Explore more AAdvantage Events SM" (`h=6672834`). All are `https://l.loyalty.ms.aa.com/rts/go2.aspx?...`, and each chain went past 10 hops.
  - Long chains add latency and risk timeouts or loops on mobile networks.
  - Some clients and security gateways abort long chains.
  - Click-through reliability on every event CTA is therefore in doubt.
- **403 on 2 links.** Both are on the same tracker: the header "American Airlines" link (`h=6672803`) and "Events and experiences just for you" (`h=6672808`).
  - A 403 from a crawler may be bot-blocking rather than a failure for real users.
  - The probe can't tell the two apart, so verify with a real-browser test.
- **Coverage gap.** 12 links were probed and 26 were skipped. The skipped links, mostly footer and social, are untested.
- **Insecure image.** The "oneworld logo" image uses `http://i.loyalty.ms.aa.com/wpm/1021/ContentUploads/american_airlines/CTAs/oneworld_logo_special_online_80x80.gif`. Non-HTTPS images can be blocked or proxy-rewritten, and some clients show a mixed-content warning.

## 3. Rendering & Accessibility
- **Pinch-zoom disabled.** The viewport meta has `maximum-scale=1`: `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />`. This blocks pinch-zoom on mobile, which is a WCAG 1.4.4 concern.
- **Text-size adjustment overridden.** The `body` rule sets `-webkit-text-size-adjust: 100%`, but the later `* { -webkit-text-size-adjust: none; ... }` rule overrides it. That removes iOS text-size adjustment.
- **Dark-mode color override.** `@media (prefers-color-scheme:dark) { span, a, td { color:#ffffff !important; } }` forces white text on every `span`, `a` and `td`. Any cell that keeps a light inline background and has no `.lightblue-bg` or `.cta-bg` class would render white on light. I can't confirm this, because the body markup is truncated.
- **Duplicate MSO block.** The `<!--[if gte mso 9]>` style block appears twice with identical content. This is harmless but adds weight.
- **Non-self-closed meta tags.** `<meta name="x-apple-disable-message-reformatting">` and the `<link rel="preconnect">` tags aren't self-closed in an XHTML 1.0 doctype. This is a validity nit and has no known rendering impact.
- **Webfont loading.** Roboto loads via both `<link>` and `@import` from `fonts.googleapis.com`. Gmail and several clients ignore this, so the fallback stack matters. The MSO block defines one, but I couldn't confirm a fallback outside Outlook.
- **Alt text.** I couldn't verify alt attributes, because the image markup is outside the truncated source.

## 4. Personalization & Merge Tokens
- **Empty greeting slot (`[FAIL]`).** The QA check found the body greeting renders as "Hi ," with no name.
- **Inconsistency with the subject.** The subject line renders correctly as "Hi Curt, discover…". The subject token resolves, but the body token apparently doesn't, or the check ran against a render where the field was empty. The same data field is probably mapped differently in the two places.
- This was detected from rendered output, so it isn't a raw `%%token%%` leak.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe and List-Unsubscribe-Post (RFC 8058).** Neither header was found. The QA note says the AgentMail relay may strip them, so this is **unverified, not confirmed missing**. Check the original message at the source.
- **Physical address (`[WARN]`).** None was detected. The HTML is truncated, so the footer wasn't fully inspected. Confirm the address in the full source.
- **Authentication-Results.** The header is absent, which is expected through the relay. SPF, DKIM and DMARC status is unknown from this data.
- **Unsubscribe link.** The QA summary says an unsubscribe link is always probed, but no unsubscribe result is listed, so I can't confirm its status.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Non-standard tracking.** There are no `utm_*` parameters in the visible hrefs. Tracking uses a proprietary click wrapper (`go2.aspx?h=…&tp=…&pi=…`), and the 403-returning links carry `x=…EML|SOLO|20261103|AADV|MKT|AAdvantage||EventsExperiences` plus `hp2=…`. This looks like a campaign-code convention (channel, send date, program, theme) that web analytics must map manually.
- **Landing alignment unverifiable.** The six event CTAs never resolved within 10 hops, so I can't check that "Get tickets" or "See Disney On Ice" land on the matching event pages.
- **Parameter inconsistency.** The two 403 links include an `x=` campaign code. The event-CTA URLs shown don't, though their destinations may append it downstream. I can't tell from this data.

## 7. Recommendations
1. Investigate the redirect chains on the `h=6672827`–`6672834` links, and reduce them to the minimum hops. Retest with a real browser user agent to separate real loops from crawler artifacts.
2. Retest the two 403 links with a browser-like client. If real users also get 403, fix the tracker configuration.
3. Fix the greeting merge token for empty or fallback names (for example, use a default like "Hi there,"). Align it with the subject-line token mapping.
4. Remove `maximum-scale=1` from the viewport meta. Remove or scope the `* { -webkit-text-size-adjust: none }` rule.
5. Serve the oneworld logo over `https://`.
6. Review the dark-mode `span, a, td { color:#fff !important }` rule against all light-background cells.
7. Verify `List-Unsubscribe` and `List-Unsubscribe-Post` and the full authentication headers on the original message, not the relayed copy. Confirm the physical address in the full footer source.
8. Remove the duplicate MSO conditional style block.
