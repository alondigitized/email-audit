# Hi Curt, discover exclusive experiences as an AAdvantage® member
**Score:** 8/10 · **Type:** Email audit · **2026-07-07**
## Executive summary

- American Airlines pivots to experiential benefits here — events, concerts, sports access, and the "Wicked" partnership — rather than the miles-earning mechanics that dominated the onboarding sequence. That's a logical evolution after the July 2 FIFA World Cup sweepstakes send, and the "Events and experiences just for you" hero headline frames the AAdvantage Events™ product clearly. The layout is clean and the event thumbnail grid communicates variety quickly.
- The problem is the opening salutation: the subject line reads **"Hi Curt"** — a hard-coded or failed-merge first name that does not belong to this subscriber. In an email whose entire premise is personalized discovery ("just for you"), greeting the reader with the wrong name is a trust-killing misfire. That alone would bury any goodwill the creative earns. Stacked on top: this lands the day after a 9,000-miles-flight push, making this the second AA send in 48 hours with no urgency anchor on either one.
- The experiences content is legitimate and the branding is solid. But wrong-name personalization + limp CTAs ("Discover," "Explore") + zero time pressure make this a scroll-and-archive send rather than a click-through one.

## What's working

- **AAdvantage Events™ positioning is clear** — the product name, logo treatment, and thumbnail grid establish this as a distinct member benefit, not a generic promo.
- **Visual variety** — event tiles span sports, entertainment ("Wicked"), outdoor adventure, and live events; the breadth signals a real catalogue.
- **"You are why we fly" close** lands with emotional weight and reinforces brand loyalty before the footer.
- **Clean render** — no broken images, no overlapping text, no obvious layout breakage across the modules visible.
- **Continuity from the July 2 experiential pivot** — the FIFA/World Cup email introduced experiences as a theme; this deepens it logically.

## What's weak

- **Wrong name in the subject line** — "Hi Curt" on a send to a different subscriber is a basic personalization failure visible before the email even opens; it undercuts every "just for you" claim in the body.
- **No concrete offer** — no specific savings, access windows, presale codes, or member-exclusive pricing is visible; "exclusive" rings hollow without proof.
- **CTA copy is weak** — "Explore more AAdvantage Events™" and "Discover more AAdvantage® experiences" are both vague discover/explore non-verbs; neither creates urgency or specificity.
- **Cadence pressure** — arriving the day after a 9,000-miles flight push, this is the second AA email in 48 hours with no urgency reason for either.
- **No event-level specificity visible** — thumbnail images don't surface event names, dates, or locations at a glance, so there's nothing to act on without clicking through to a browse page.

## Recommendations

- 1. **Fix the personalization token first** — "Hi Curt" in the subject is the most damaging thing in this send. Audit the merge tag, re-suppress any records where first name is null/defaulted, and re-send to the affected segment with a corrected subject.
- 2. **Anchor one featured experience** — pick the single best event (e.g., a Wicked presale date, a specific World Cup package) and make it the hero with a date, a seat count, or a "only X left" signal. Everything else becomes supporting grid.
- 3. **Rewrite the CTAs** — swap "Discover/Explore" for action-first copy tied to scarcity or exclusivity: "Claim Your Member Access," "See Available Dates," "Book Before It Sells Out."
- 4. **Wait 48 hours minimum** — don't send a second email the day after a flight-offer push. The cadence makes both sends feel lower-value.
- 5. **Add a preheader that sells** — if the preheader is leaking junk or repeating the subject, a single line like "Member-only presales, VIP sports access, and more — see what's waiting" would double the inbox case for opening.
- **Subject Alt A:** `Curt, your member events are ready — see what's on`
- **Subject Alt B:** `AAdvantage members get in first — event access inside`
- **Preheader Alt A:** `Presales, VIP sports, Wicked tickets — your exclusive list is live`
- **Preheader Alt B:** `Member-only experiences dropping now — here's what you can book`

### 3. Rendering & Accessibility

**Critical — Unclosed `@media` block (CSS parse failure):**
```css
@media (prefers-color-scheme:dark) {
  /* rules... */
  [data-ogsc] span, [data-ogsc] a, [data-ogsc] td { color: #ffffff !important; }
/* ← missing closing } before </style> */
</style>
```
The dark-mode `@media` rule is never closed. CSS parsers that are strict (Gmail, some Outlook versions) will drop all rules inside the block or cascade errors into the next `<style>` block.

**Duplicated MSO conditional block:**
The `<!--[if gte mso 9]>` font-fallback style block appears verbatim twice in `<head>`. No functional harm in Outlook, but inflates message size and signals a template assembly error.

**Triple Google Fonts load:**
```html
<link rel="preconnect" href="https://fonts.googleapis.com">       <!-- preconnect -->
<link href="https://fonts.googleapis.com/css2?family=Roboto...">   <!-- stylesheet fetch -->
<style>@import url('https://fonts.googleapis.com/css2?...');</style> <!-- redundant @import -->
```
All three reference the same Roboto family. The `@import` is redundant and blocks rendering in clients that support it; remove it.

**Overly broad dark-mode color override:**
```css
span, a, td { color: #ffffff !important; }
[data-ogsc] span, [data-ogsc] a, [data-ogsc] td { color: #ffffff !important; }
```
Forces white on every `span`, `a`, and `td` in dark mode — including any colored CTA buttons, status badges, or disclaimers. High risk of washing out intentionally colored elements.

**`maximum-scale=1` on viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Accessibility failure (WCAG 1.4.4 — Resize Text). Should be removed or changed to `maximum-scale=5`.

**Universal `line-height: 100%` selector:**
```css
* { line-height: 100%; }
```
Collapses line height on multi-line text elements globally. Confirmed by `p { margin: 0 auto; text-align: center; }` also being set globally — these two together will squash multi-line paragraphs. Should be scoped, not universal.
