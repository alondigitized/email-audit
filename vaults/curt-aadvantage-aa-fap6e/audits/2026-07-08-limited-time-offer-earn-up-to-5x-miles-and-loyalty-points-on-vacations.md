# Limited-time offer: Earn up to 5X miles and Loyalty Points on vacations
**Score:** 8/10 · **Type:** Email audit · **2026-07-08**
## Executive summary

- This is a cross-sell from American Airlines Vacations — a sub-brand, not the main AAdvantage loyalty team that has been running this inbox sequence. That's the first thing to notice: after ten emails from AA's loyalty/marketing arm, a new sender domain (`loyalty.ms.aa.com` labeling itself "American Airlines Vacations") introduces a new product vertical. The pivot from "earn miles on flights" to "earn miles on vacation packages" is a logical upsell, and the dual-value hook — miles multiplier *plus* up to $1,530 in savings — is genuinely compelling for an AAdvantage member.
- The creative holds up structurally: a clean tropical hero, a well-laid-out tier table showing exactly how many miles per dollar each status level earns vs. the bonus rate, a hard deadline (July 28), and a single clear CTA. The offer is honest and the deadline credible. What drags it down is the complete absence of any specific destination or product — you're clicking to a generic vacation packages landing page — and a subject line that clocks in at 71 characters and drops no personalization, which is a regression from prior sends that called Curt by name.
- The enormous fine-print block at the bottom (visually half the email's length) is the most glaring executional miss. This isn't a legal necessity problem — it's a placement problem. Reserve 8+ scores for emails that feel premium end to end; this one is solid but not exceptional.

## What's working

- **Tier table is genuinely useful.** Showing the baseline vs. bonus miles per dollar by status level (3→5, 5→7, 7→9, 9→11) is concrete and gives each reader a personalized reason to care based on their actual tier.
- **Dual value proposition.** Miles multiplier *and* "Save up to $1,530" cover both the points-accumulator and the deal-seeker in the same send.
- **Hard deadline visible in body.** July 28, 2026 is stated clearly, which gives the "limited-time" claim in the subject actual teeth.
- **Hero visual hierarchy works.** "Make it a MaximizeMiles™ getaway" lands immediately above the tropical imagery; the eye goes hero → table → CTA without confusion.
- **Clean render.** No broken images, no overlapping text, no layout breakage visible at any viewport in this screenshot.

## What's weak

- **Subject is 71 characters — 40% over the mobile-safe threshold.** "Limited-time offer: Earn up to 5X miles and Loyalty Points on vacations" will truncate on nearly every mobile client before "Loyalty Points" even appears.
- **No personalization in subject or hero.** Two prior sends in this sequence greeted "Hi Curt" in the preview/body; dropping that here is a missed easy win.
- **No specific destination or product.** The CTA goes somewhere generic. The "Surf and more" mention in the teal module is a tease with no follow-through — no hero destination, no featured hotel, no specific route.
- **Fine print block is visually overwhelming.** The legal disclaimer takes up roughly 40% of the rendered email's height. Even if legally required, it could be collapsed into a single-line link or moved to a gray footer strip rather than dominating the scroll.
- **Sub-brand handoff is abrupt.** Ten emails from AA's loyalty team, then suddenly "American Airlines Vacations" with no bridge copy explaining the relationship. A cold subscriber might question the sender legitimacy before opening.

## Recommendations

- 1. **Cut the subject to under 50 chars and punch the multiplier.** The "5X miles" number is the hook — lead with it.
- **Subject Alt A:** `Earn 5X miles on your next vacation – ends July 28`
- **Subject Alt B:** `MaximizeMiles™: up to 5X on packages through July 28`
- **Preheader Alt A:** `Your AAdvantage status unlocks more miles per dollar — here's your exact rate`
- **Preheader Alt B:** `Plus save up to $1,530 on select packages. Offer ends July 28.`
- 2. **Pick one hero destination and link to it directly.** Feature a specific city pair or resort ("Miami → Cancun from $X + bonus miles") so the CTA lands on a pre-filtered result, not a homepage. Specific destinations lift click rate measurably.
- 3. **Collapse the fine print.** Replace the multi-paragraph legal wall with a single "Terms and conditions apply" hyperlink. The offer's legitimacy isn't in doubt; the wall just erodes perceived quality.
- 4. **Add Curt's name to the hero or sub-headline.** Even "Curt, your Platinum status earns you 9 miles per dollar" in the first body line would sharpen the tier table's relevance and re-establish the personalized tone from earlier sends.
- 5. **Bridge the sub-brand.** A single line — "From the team behind your AAdvantage miles" — after the AA Vacations logo would preserve trust continuity with a subscriber who has been engaging the main loyalty team.

### 1. Technical Summary

The email uses a standard XHTML 1.0 Transitional table layout with MSO conditional blocks and dark mode support. Two structural bugs — an unclosed conditional comment and a duplicate font loader — introduce Outlook rendering risk and unnecessary network overhead.

### 2. Link & Tracking Issues

- **Sender subdomain**: `loyalty.ms.aa.com` is an ESP-managed relay subdomain, which is standard. SPF/DKIM/DMARC alignment cannot be verified from HTML; see Compliance section.
- **No issues confirmed** within the visible source fragment — audit should be re-run against the full HTML including all `<a href>` elements.

### 3. Rendering & Accessibility

**A — Unclosed MSO conditional comment (Outlook breakage risk)**

```html
<!--[if mso]>
  <style>
    font, span, td, table, div { font-family: Arial, serif !important; }
  </style>
<!--[if gte mso 9]>   ← new conditional opens without closing the previous one
```

The `<!--[if mso]>` block is never terminated with `<![endif]-->` before the next conditional opens. In Outlook's rendering engine this causes the `[if gte mso 9]` block to be treated as nested inside the outer conditional, making both blocks apply simultaneously to MSO ≥ 9 clients and potentially doubling style declarations.

**B — Duplicate `[if gte mso 9]` style block**

The `<!--[if gte mso 9]>` block containing the full `body,table,td` font-family override appears **twice** with identical content. This is dead markup that inflates message size and can produce specificity collisions in Outlook.

**C — Duplicate Google Fonts load**

Both a `<link>` tag and an `@import` rule load the identical Roboto URL:

```html
<link href="https://fonts.googleapis.com/css2?family=Roboto:...&display=swap" rel="stylesheet">
…
<style>
  @import url('https://fonts.googleapis.com/css2?family=Roboto:...&display=swap');
</style>
```

This fires two separate HTTP requests for the same resource. Gmail strips `<link>` tags, so the `@import` is the effective fallback — but both should not coexist. Remove the `<link>` block and retain only the `@import`.

**D — Wrong generic fallback in MSO font stack**

```html
font-family: Arial, serif !important;
```

Arial is a sans-serif face; `serif` as the generic fallback is semantically incorrect and will produce a serif typeface if Arial is unavailable. Should be `Arial, sans-serif !important`.

**E — Overly broad dark mode color override**

```css
@media (prefers-color-scheme:dark) {
  span, a, td { color: #ffffff !important; }
}
```

This blanket rule overrides every link and table-cell color to white in dark mode, including CTA button text. If any button uses a white or near-white background in dark mode (see `.cta-bg { background-color: #3b93f7 }`), white text on that button will remain readable — but any non-CTA link rendered on a white or light-colored cell will become invisible. Scope this rule to a specific class (e.g., `.dark-text`) rather than applying it to all `span, a, td`. The `[data-ogsc]` block carries the same issue.

**F — Viewport accessibility: user zoom blocked**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

`maximum-scale=1` prevents pinch-to-zoom. Combined with the global `*` rule:

```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```

…this blocks both OS-level and user-initiated text scaling. This fails **WCAG 2.1 SC 1.4.4 (Resize Text)**. Remove `maximum-scale=1` and use `-webkit-text-size-adjust: 100%` (not `none`) on `body` only.
