# Enter to win: FIFA World Cup 26™ Final Party in NYC

## What's working

- **Prize specificity is high** — tickets to the FIFA WC26 Final, round-trip airfare, and NYC hotel are called out clearly; no "you could win prizes" vagueness.
- **48-hour window creates real urgency** — "Enter by July 3, 2026" is credible and time-boxed in a way that generic "limited time" copy never is.
- **"Enter today" CTA is unambiguous** — prominent yellow-orange button above the fold, clear verb-action copy.
- **FOX Sports co-branding adds legitimacy** — the partnership signals this is a real prize, not a phishing-style contest.
- **Nine-day inbox gap before this send** — the cadence respects the subscriber; the June 22 email wasn't just yesterday, so this doesn't feel like pile-on.

## What's weak

- **Split CTA kills focus** — the FOX One app download block is a competing conversion ask on a deadline email; one email, one action.
- **"Enter to win" in the subject is a mild spam-pattern signal** — common enough across promotional senders that many readers scan past it; also triggers some filtering heuristics.
- **Subject doesn't signal member exclusivity** — nothing in the subject tells an AAdvantage member this prize is theirs because of their status; it reads like a mass sweepstakes blast.
- **Dense fine print wall at the bottom** — standard for sweepstakes legally, but the volume of small text creates a visible trust dip on scroll.

- 1. **Cut the FOX One app CTA entirely from this email** — spin it into its own send. A 48-hour window needs a single funnel; the app block introduces a second decision that will cost clicks on the primary ask.
- 2. **Rewrite the subject to signal member-exclusive access** — "AAdvantage member" or "for members" as the first hook raises the perceived exclusivity and filters in exactly the right audience.
- 3. **Surface the 48-hour deadline in the subject or preheader** — the July 3 cutoff is the strongest conversion lever in this email and it's buried in body copy.
- 4. **Tie the prize back to AAdvantage** — one line in the hero like "fly there on miles" or "your miles could get you closer" makes this feel like a loyalty reward, not a generic Fox Sports promo.

### 3. Rendering & Accessibility

**Critical — Unclosed dark-mode `@media` block:**
```css
@media (prefers-color-scheme:dark) {
  /* ... rules ... */
  [data-ogsc] span, [data-ogsc] a, [data-ogsc] td { color: #ffffff !important; }
  /* ← no closing } before </style> */
</style>
```
The `@media (prefers-color-scheme:dark)` rule is never closed. Browsers will silently recover, but some email clients (notably Gmail's CSS sanitizer) may discard the entire block or bleed dark-mode rules into light-mode rendering.

**Duplicate MSO conditional block:** The `<!--[if gte mso 9]>` font-fallback `<style>` block appears verbatim twice in `<head>`. No rendering breakage, but it adds ~600 bytes and forces a second CSS parse pass in Outlook.

**Double Google Fonts load:**
```html
<link href="https://fonts.googleapis.com/css2?family=Roboto:..." rel="stylesheet">
...
<style>
  @import url('https://fonts.googleapis.com/css2?family=Roboto:...');
</style>
```
Both the `<link>` tag and the `@import` inside `<style>` request the same Roboto variant. This is redundant — most clients that support one also support the other, but some clients execute both, causing two font-file fetches. Keep only the `<link>` tag; `@import` inside `<style>` blocks is broadly unsupported in email clients anyway.

**`maximum-scale=1` on viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents user zoom. Fails WCAG 1.4.4 (Resize Text, Level AA). Should be removed.

**Aggressive global CSS reset:**
```css
* { -webkit-text-size-adjust: none; line-height: 100%; max-height: 1000000px; }
```
`line-height: 100%` applied to `*` overrides any element-specific line-height and can collapse multi-line text. This is a known compatibility hack but will cause visual issues on any element that doesn't explicitly override it. Scope it narrowly rather than with `*`.

**Preheader padding:** The hidden preheader uses ~54 repetitions of `&#847;&zwnj;&nbsp;&#8199;&shy;` to pad preview text. This is standard practice but some aggressive spam filters treat excessive special-character density as a signal. No action required unless deliverability issues arise.
