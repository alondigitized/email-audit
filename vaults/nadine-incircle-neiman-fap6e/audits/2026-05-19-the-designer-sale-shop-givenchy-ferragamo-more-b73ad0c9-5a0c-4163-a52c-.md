# The Designer Sale: Shop Givenchy, Ferragamo & more
**Score:** 9/10 · **Type:** Email audit · **2026-05-19**
## Executive summary

- This is a day-after follow-up to the Designer Sale launch — NM is keeping the sale alive in the inbox by naming specific brands in the subject (Givenchy, Ferragamo) instead of leading with the offer alone. The red hero is crisp and the offer is unambiguous: "UP TO 50% OFF / SHOP SALE." The nine-brand product grid gives the email a reason to exist beyond just the launch.
- The critical problem: Ferragamo is called out in the subject line as a named draw but does not appear anywhere in the nine-brand product grid. Givenchy makes it in, Ferragamo does not. That's a bait-and-switch signal — a subscriber who opens specifically for Ferragamo will scan the grid, not find it, and either bounce or feel misled. The 5/18 launch email earned a 10 partly because everything it promised was visible; this one breaks that contract.
- Cadence is also becoming a concern. This is the third designer sale email in three days (5/17 exclusive access, 5/18 launch, 5/19 this send), and the creative is nearly identical to the launch — same red hero, same discount, same button. Without a deadline or a new angle, the email reads as recycled creative rather than a fresh reason to shop.

## What's working

- Red hero lands the offer immediately — "LIMITED TIME / THE DESIGNER SALE / UP TO 50% OFF" requires zero effort to parse.
- Nine-brand product grid provides real browsing value; more specific than the launch email's single "UP TO 50% OFF" hero.
- Six category CTA buttons (Women's Clothing, Men's, Shoes, Handbags, Dresses) make it easy to self-select — this is better navigation than a single generic "Shop Sale."
- Givenchy appears in the subject AND in the grid — that promise is kept.
- No render bugs, clean layout, no overlapping text.

## What's weak

- Ferragamo is named in the subject line but absent from the product grid — the most glaring trust break in the email.
- "LIMITED TIME" is the only urgency signal; no specific deadline (day, date, or hours remaining), which makes it feel hollow after three consecutive sale emails.
- The creative is near-identical to the 5/18 launch — same hero color, same headline, same discount. No new angle, no escalation.
- No preheader — the inbox preview likely leaks navigation or "LIMITED TIME," which adds nothing to the subject.
- Loyalty/InCircle benefits are invisible here despite NM sending a dedicated InCircle pitch the same day (5/19).

## Recommendations

- 1. **Feature Ferragamo in the grid or remove it from the subject.** The subject creates an expectation; the email has to fulfill it. Either swap one brand tile for Ferragamo or rewrite the subject to only name brands that appear.
- 2. **Add a hard deadline.** "Ends Sunday" or "72 hours left" transforms "LIMITED TIME" from wallpaper into genuine urgency. The 5/17 exclusive-access email did this well and scored 9 — this one doesn't.
- 3. **Change the hero angle to signal escalation.** The 5/18 launch said "It's here." This one should say something like "Still going — but not for long" or lead with a category to create differentiation.
- 4. **Write a real preheader** that complements the subject rather than leaking body text.
- 5. **Tie in InCircle.** NM sent a loyalty pitch the same day — a single "InCircle members: extra 10% off sale" line here would cross-sell both emails and reward members without a separate send.
- **Subject Alt A:** `Givenchy, Ferragamo & 7 more — up to 50% off`
- **Subject Alt B:** `The Designer Sale ends Sunday — Givenchy, Ferragamo & more`
- **Preheader Alt A:** `Nine designer brands, one deadline. Shop before it's gone.`
- **Preheader Alt B:** `Up to 50% off Givenchy, Ferragamo, Burberry, and more — limited time.`

## Technical Audit — Neiman Marcus "The Designer Sale" (2026-05-19)

---

### 1. Technical Summary

The email is a standard SFMC (Salesforce Marketing Cloud) AMPScript template with a table-based layout. Two confirmed issues require attention: a silently broken variable assignment in the AMPScript preamble, and unconfirmed compliance headers that may be suppressed by the AgentMail relay.

---

### 2. Link & Tracking Issues

**Plain-text URL density — deliverability risk**
QA confirms 5,140 of 5,910 plain-text characters are URLs (87%). Many spam filters treat >70% URL density in the plain-text part as a spam signal. This often results from auto-generated plain-text that serializes every href verbatim with no surrounding prose.

**26 tracking links not probed**
All outbound links pass through a click-redirect domain. HTTP probes were skipped for these, so broken destinations and missing UTM parameters cannot be confirmed or ruled out programmatically. Manual spot-check of 3–5 links is recommended before send.

---

### 3. Rendering & Accessibility

**`maximum-scale=1` blocks user zoom** (accessibility)
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">
```
Prevents pinch-to-zoom on mobile. WCAG 1.4.4 (Level AA) requires text to be resizable to 200% without assistive technology.

**Three commented-out viewport tags are dead code**
```html
<!--<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" />-->
<!--<meta name="viewport" content="width=320, initial-scale=0.29">-->
<!--<meta name="viewport" content="width=1024">-->
```
No functional impact, but signals version drift and should be removed.

**iOS 9 `@-webkit-keyframes bugfix` animation still present**
```css
body { -webkit-animation: bugfix infinite 1s; }
@-webkit-keyframes bugfix { from { padding: 0; } to { padding: 0; } }
```
iOS 9 is ~10 years old; this workaround adds a render-cycle no-op animation to every render. Safe to remove.

**`ReadMsgBody` / `ExternalClass` resets** — Outlook 2003 / legacy Hotmail hacks. Harmless but unused in any current client.

**Alt text** — Cannot confirm from the truncated source. Images must have descriptive `alt` attributes for screen readers and image-blocked clients.

---

### 4. Personalization & Merge Tokens

**Critical: `@user` assignment is double-commented out and will not execute**

```html
<!--/* SET @user = HASHED_EMAIL_SHA256 */ -->
```

This wraps an AMPScript statement in both an HTML comment (`<!-- -->`) and a JavaScript-style block comment (`/* */`). AMPScript inside `<!-- -->` is still parsed by SFMC, but the inner `/* ... */` is treated as literal text — the assignment never fires. If `@user` is consumed downstream (e.g., in a personalization URL or audience segment), it will resolve to an empty string or throw a lookup error silently.

**Fix:** The intent is likely to select one of two scenarios. The active scenario should use unambiguous AMPScript syntax outside any comment wrapper:
```
%%[ SET @user = HASHED_EMAIL_SHA256 ]%%
```

**`@refid = CONCAT(@base_refid,"")` is a no-op**
Concatenating an empty string literal adds no value. If a suffix was intended (e.g., a campaign variant code), it is currently missing.

**Silent Lookup failures on `NM_CRM_Feed`**
`@uEm` and `@cmdid` are populated via `Lookup()` against `NM_CRM_Feed`. If a subscriber record does not exist in that DE, both variables return empty strings with no fallback. Confirm whether downstream usage of these variables handles the empty case.
