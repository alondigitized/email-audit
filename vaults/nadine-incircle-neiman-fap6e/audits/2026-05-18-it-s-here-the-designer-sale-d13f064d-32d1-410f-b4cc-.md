# It’s here! The Designer Sale
**Score:** 8/10 · **Type:** Email audit · **2026-05-18**
## Executive summary

- This is the official designer sale launch email — the natural sequel to yesterday's "Your exclusive access ends tonight!" pre-sale (scored 9/10). The creative formula is nearly identical: red hero, percentage headline, nine-brand product grid. It executes cleanly.
- The core gap versus yesterday: the urgency collapsed. "Limited time" without a date is a retreat from "exclusive access ends tonight." If yesterday's email was a hard deadline close, today is a vague follow-up. Subscribers who opened yesterday and hesitated need a new reason to act *now* — this email doesn't give them one.
- The designer grid is the real selling work here. Seeing ALAIA, Christian Louboutin, Jacquemus, and Burberry in two rows triggers genuine browse intent faster than any headline. The six category CTAs below are functional but mechanically delivered, with the weakest ones likely below the fold on mobile.
- **Verdict:** Solid sale-launch execution that will perform on volume but leaves meaningful lift on the table by recycling yesterday's creative without escalating the offer or urgency.

## What's working

- Red hero delivers the offer immediately — "THE DESIGNER SALE / UP TO 50% OFF / SHOP SALE" is visible before any scroll on desktop
- Nine named designer brands in the product grid (ALAIA, Burberry, Courreges, Christian Louboutin, Cult Gaia, Givenchy, Jacquemus, Polo Ralph Lauren, Victoria Beckham) do aspirational selling faster than any copy
- "Exclusions Apply" is visibly disclosed under the SHOP SALE button — not buried in fine print
- Category CTA grid (Women's Clothing, Men's, Shoes, Handbags, Dresses) covers the major shopping entry points
- Footer app download and personal stylist callout neatly cross-sells the services email sent earlier today

## What's weak

- "LIMITED TIME" with no end date: yesterday's email said "access ends tonight" — today offers zero deadline, which is a meaningful urgency downgrade
- Visual repetition with yesterday: same red hero, same grid structure, same offer framing — looks like a copy-paste follow-up, not a campaign escalation
- "Up to 50% off" without a floor number is the weakest possible sale headline — it could mean 10% on most items; no anchor price or "from $X" callout is visible
- Five emails in three days from Neiman Marcus (5/16, 5/17 × 2, 5/18 × 2) — cadence fatigue is real and this email offers nothing new enough to justify the send
- Six CTA buttons below the grid is too many — the bottom three (Men's Shoes, Shop Men's, Shop Dresses) are likely below the fold on mobile

## Recommendations

- 1. **Add a hard deadline.** "Sale ends Sunday night" or even "Ends in 72 hours" — any credible time anchor. "Limited time" is filler that every subscriber has trained themselves to ignore.
- 2. **Show one hero product with a before/after price.** Pick the ALAIA dress or the Christian Louboutin heel and show "$895 → $447." Concrete savings outperform abstract percentages every time.
- 3. **Differentiate from yesterday's email.** The exclusive window is closed — now it's open to all. Lead with that shift: "The exclusive window is over — the sale is now open to everyone."
- 4. **Reduce CTAs to three.** Women's / Men's / Shoes. Consolidate handbags and dresses into the women's click. Fewer, larger buttons perform better on mobile.
- 5. **Set an explicit preheader.** The first visible text in this render is the nav bar — if no hidden preheader text is set, inbox clients will surface "WOMEN MEN SHOES SALE" as the preview, which undermines the subject.
- **Subject Alt A:** `The Designer Sale is live — ends Sunday`
- **Subject Alt B:** `ALAIA. Burberry. Jacquemus. Up to 50% off.`
- **Preheader Alt A:** `Up to 50% off your favorite designers — while styles last.`
- **Preheader Alt B:** `Christian Louboutin, ALAIA, Burberry and more — sale prices live now.`

### 3. Rendering & Accessibility

**`maximum-scale=1` in viewport meta restricts zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">
```
Prevents users from pinching to zoom on mobile — a WCAG 2.1 SC 1.4.4 failure. This is the live meta; the zoom-blocking variants are correctly commented out elsewhere, but this one is active.

**Responsive styles rely on `*[class=X]` attribute selectors**
```css
*[class=contenttable] { width: 100% !important; }
*[class=mobile] { width: 100% !important; ... }
```
Gmail apps (Android and iOS) strip `class` attributes from email elements, so all of these breakpoint overrides are inert in Gmail mobile — the most common mobile email client. Layout will render at desktop width on Gmail app regardless of screen size.

**Multiple commented-out viewport meta tags indicate historical instability**
Three alternate viewport strategies are present as comments:
```html
<!--<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" />-->
<!--<meta name="viewport" content="width=320, initial-scale=0.29">-->
<!--<meta name="viewport" content="width=1024">-->
```
These are dead code but signal the responsive strategy was iterated without cleanup. No rendering defect confirmed from comments alone, but they clutter the source and create confusion during QA.

**iOS 9 keyframe hack still present**
```css
body { -webkit-animation: bugfix infinite 1s; }
@-webkit-keyframes bugfix { from { padding:0; } to { padding:0; } }
```
Labeled "Hamburguer fix IOS9" in a comment. iOS 9 reached end-of-life in 2016. This adds a continuous CPU animation with no functional effect on modern clients.

### 5. Compliance

**`List-Unsubscribe` header absent** (QA confirmed)
Major mailbox providers (Gmail, Yahoo, Outlook) use this header to surface a native unsubscribe button. Its absence means recipients must find the in-body unsubscribe link — increasing friction and spam complaints. Google and Yahoo's 2024 bulk sender requirements make this header mandatory for >5,000 msg/day senders.

**`List-Unsubscribe-Post` header absent** (QA confirmed, RFC 8058)
One-click unsubscribe (POST-based, not redirect-based) is required by Gmail/Yahoo bulk sender policy. Without it, the mailbox provider's unsubscribe button either doesn't appear or requires a click-through rather than a single action.

**`Authentication-Results` header not captured**
SPF, DKIM, and DMARC pass/fail status is unknown due to AgentMail relay interception. The sending domain `e.neimanmarcus.com` is an ESP subdomain — DKIM alignment with the `From:` domain (`neimanmarcus.com`) should be verified out-of-band. A DMARC failure on a high-volume send would trigger bulk foldering.

**CAN-SPAM physical address and unsubscribe mechanism** — not verifiable from the truncated source provided. Confirm both are present in the footer of the full HTML.
