# Save up to 70% on A.L.C. & more during Last Call
**Score:** 8/10 · **Type:** Email audit · **2026-07-14**
## Executive summary

- This is NM's return to the red Last Call hero after a brief two-day pivot to gift cards and new arrivals (July 12–13). The A.L.C. brand call-out in the subject is a smart move to make this feel more differentiated than the five-plus identical "Extra 25% off" sends since July 8 — but A.L.C. is not visibly featured as a hero anywhere in the body. That's a subject-body bait-and-switch, and sharp subscribers will notice.
- The email is cleanly rendered, the stacking discount math is legible, and the nine-brand product grid gives the sale genuine breadth. But two things stick out immediately: the Bugaboo brand (a Dutch baby stroller company) appears alongside Balmain, Stuart Weitzman, and Manolo Blahnik in the product grid — that's a jarring algorithmic misfire for a luxury fashion audience. And there are duplicate category CTAs ("SHOP HANDBAGS" and "SHOP BAGS" both present), which signals sloppiness.
- The bigger strategic problem is cadence fatigue. The July 11 "extra 25% off / up to 70% off" send scored 9/10 in this audit record because it was still fresh. This send uses an identical hero block. The "Last Call" urgency conditioning is burning out fast, and without a hard deadline date, "Last Call" is losing its punch.

## What's working

- Clean red hero with legible stacking discount math — "Extra 25% off → up to 70% total" is immediately scannable
- Nine-brand product grid creates genuine breadth-of-sale signal for a sale seeker
- A.L.C. in the subject is a legitimate segmentation attempt — right move, wrong execution
- Six category CTAs give multiple entry points without requiring a decision at the hero
- "Match with a personal style advisor" CTA at the bottom is a differentiated trust signal not common in pure promotional email

## What's weak

- A.L.C. is named in the subject but is not visibly called out anywhere in the email body — a clear subject-body promise gap
- Bugaboo (baby strollers) appears in the designer product grid next to Balmain and Manolo Blahnik — algorithmic product selection misfire that will confuse a luxury fashion reader
- "SHOP HANDBAGS" and "SHOP BAGS" both appear as CTAs — redundant, looks like a QA miss
- No hard deadline or countdown — after six days of "Last Call" framing with no specific end date, the urgency has been thoroughly diluted
- "SHOP MEN'S" CTA appears in an email whose entire product grid is women's fashion, diluting the targeting signal

## Recommendations

- 1. **Feature A.L.C. as a visual hero in the body** — if a brand anchors the subject line, give it a dedicated hero slot or at minimum a labeled product callout. The gap between "A.L.C." in the subject and "none of these nine items is labeled A.L.C." in the body is a trust eroder. Ship this next send.
- 2. **Audit the product grid** — Bugaboo does not belong here. A single manual QA pass to remove non-fashion brands from the "designer sale" grid would eliminate this jarring misfire.
- 3. **Add a hard deadline with a specific date** — "Sale Ends Sunday at Midnight" or "Ends Tonight" outperforms "Last Call" alone by forcing a real decision window. Especially critical now that the Last Call run is in its seventh day.
- 4. **Consolidate and fix the CTAs** — drop the duplicate SHOP BAGS/SHOP HANDBAGS, drop SHOP MEN'S from a female-targeted send, keep only 3–4 most relevant to the brands shown.
- 5. **Break the red hero monotony** — even rotating to a lifestyle editorial image over the same stacking discount text would re-engage fatigued subscribers. NM's July 11 wedding editorial and the Saint Laurent Roundup both scored higher than the straight promo sends for this reason.

- **Preheader Alt A:** `Shop A.L.C., Manolo Blahnik, Cinq à Sept and more — extra 25% off select sale styles, ending soon.`
- **Preheader Alt B:** `Your favorite designers. Extra 25% off. But not for long.`

## Technical Audit

## Technical Audit — Neiman Marcus "Save up to 70% on A.L.C." Email

---

### 1. Technical Summary

SFMC-templated email with AMPscript conditional variable scenarios; the SHA-256 hashed-email path (`@user`) is commented out, leaving its assignment ambiguous for this send. QA confirms missing `List-Unsubscribe` headers and unverifiable SPF/DKIM — both create active deliverability and compliance exposure.

---

### 2. Link & Tracking Issues

**26 click-tracking redirects — destinations unverifiable**
All outbound links route through NM's click-redirect infrastructure. QA skipped HTTP probing on all 26. No UTM parameter presence, destination URL health, or redirect chain integrity could be confirmed.

**`@refid` no-op concatenation**
```
@refid = CONCAT(@base_refid,"")
```
Concatenating with an empty string is a no-op. If a campaign suffix was intended (e.g., `CONCAT(@base_refid,"_LC")`), it was never applied. This will silently produce the same value as `@base_refid` in all tracking URLs, potentially collapsing variant attribution.

**`@cmdid` / `@uEm` null-lookup risk**
Both are sourced via `Lookup("NM_CRM_Feed", ...)`. If a subscriber is absent from `NM_CRM_Feed`, both resolve to an empty string. If these values are interpolated into click URLs (common for NM's personalized landing experience), the result is malformed tracking parameters with no error surfaced.

---

### 3. Rendering & Accessibility

**CSS hamburger nav will silently break in most clients**
The mobile nav uses a CSS-only `:checked` pseudo-class toggle:
```css
*[class].navbar-checkbox:checked~*[class].menu { visibility: visible !important; ... }
```
This technique only functions in Gmail web and Apple Mail. All Outlook versions, Yahoo Mail, and most Android clients will render a non-functional hamburger icon with a permanently hidden menu. No fallback is present.

**Overlapping breakpoint blocks**
Two separate `<style>` blocks define conflicting breakpoints — 600px in block 1, 480px and 520px in block 2. Specificity resolution is client-dependent and may cause unintended layout behavior on mid-range viewport widths (481–599px).

**`lang` attribute absent on `<html>`**
```html
<html xmlns="http://www.w3.org/1999/xhtml">
```
No `lang="en"` declared. Screen readers cannot infer language for pronunciation; also fails WCAG 2.1 §3.1.1.

**Layout tables lack `role="presentation"`**
Not visible in the truncated source, but standard accessibility expectation for table-based layouts. Should be confirmed in full source.

**Minor: trailing whitespace in `<title>`**
```html
<title>Neiman Marcus </title>
```
No functional impact, but indicates template hygiene debt.

**Multiple commented-out viewport meta tags**
Three alternate viewport definitions are left as HTML comments, suggesting in-progress debugging. Dead weight; should be cleaned before canonical template archival.

---

### 4. Personalization & Merge Tokens

**`@user` (SHA-256) path is commented out — assignment is ambiguous**

```html
<!--/* SET @user = HASHED_EMAIL_SHA256 */-->
```

The template header says "CHOOSE ONE SCENARIO BELOW." The SHA-256 scenario is disabled via comment. If `@user` is not assigned in the un-truncated body via the alternate Lookup scenario, the variable is null for this send. Any pixel, URL parameter, or conditional block that references `@user` will silently produce an empty value or throw an AMPscript runtime error depending on error-handling configuration.

**Lookup fallback chain has no default guards visible**
```
@user = Lookup("NM_Subscriber_New_Consolidated", "EMAIL_ID", "EMAIL_ADDRESS", @email)
@uEm  = Lookup("NM_CRM_Feed", "uEm", "EMAIL_ADDRESS", @email)
@cmdid = Lookup("NM_CRM_Feed", "cmdid", "EMAIL_ADDRESS", @email)
```
No `IIF()` or `Empty()` guards visible. Null returns from any of these propagate silently into downstream URL construction.

---

### 5. Compliance

**`List-Unsubscribe` header absent** — HIGH PRIORITY
As of February 2024, Google and Yahoo require `List-Unsubscribe` headers for all bulk senders (>5,000 messages/day). Neiman Marcus almost certainly qualifies. This header is set at the MTA/ESP layer (SFMC's SAP), not in HTML — but QA confirms it was not present in the received message. Gmail may suppress the native unsubscribe button and apply spam-folder routing for non-compliant senders.

**`List-Unsubscribe-Post` (RFC 8058) absent**
One-click unsubscribe via POST is required alongside the above. Its absence means Gmail's one-click flow will not engage, increasing spam complaint risk.

**Authentication-Results not captured**
SPF/DKIM/DMARC status on `e.neimanmarcus.com` could not be verified via the AgentMail relay. The subdomain is a dedicated SFMC SAP send domain and should be fully authenticated, but this cannot be confirmed from available data. A seed-send header inspection is needed.

**Plain-text version is >70% URLs**
QA finding: 5,268 of 6,101 plain-text characters are URLs. This is a known spam-filter signal. The plain-text version likely contains auto-generated HTML-stripped content rather than human-readable copy.

**CAN-SPAM footer** — not visible in truncated source; assumed present based on NM standard templates, but should be confirmed.
