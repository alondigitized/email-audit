# Win-win: 15% off & you’re in the know! ​
**Score:** 5/10 · **Type:** Email audit · **2026-05-16**
## Executive summary

- This is a list-confirmation welcome email — "You're on the List" — dressed up as a 15% discount send. Neiman Marcus is using the new-subscriber moment to introduce the brand's designer roster (Veronica Beard, VEJA, Chloé, FRAME, Chez a Sept, Rag & Bone, Golden Goose, Marc Jacobs) while dangling a one-time promo code as the hook. The structure is clean and the NM brand voice is intact.
- The problem: the subject line promises "win-win: 15% off" but the email hero buries the code below a generic headline, and the discount is asterisked with fine print that chips away at the "honest offer" signal. The product grid is visually pleasant but no single item is featured — it's a brand mosaic, not a shopping prompt.
- Net judgment: a competent but generic list-welcome that squanders a high-intent moment. The 15% code is the strongest hook, but everything around it is designed to browse, not convert.

## What's working

- **Welcome moment is well-chosen.** Catching a subscriber at list-signup is the highest-intent window; deploying a code here is smart timing.
- **Brand aesthetic is clean.** Minimal serif layout, tight white space, no visual clutter — consistent with the NM luxury positioning.
- **Promo code is prominently displayed.** `NMW6ELC-RYIZ-RSG50NN` is in its own code block, easy to screenshot or copy.
- **Multi-brand product grid.** Showing eight distinct designer brands quickly conveys breadth of assortment.
- **Utility footer.** App download, personal stylist match, Find-a-Store, Contact, and My Account links are all present and visible.

## What's weak

- **Hero headline is wasted.** "You're on the List" is brand copy, not an action driver — the subject promised 15% off and the hero should lead with that.
- **No prices shown.** Luxury or not, showing price on at least one item gives the discount a concrete value (15% of what?).
- **Asterisk on the offer.** The "15% OFF*" asterisk signals exclusions; fine print at the bottom likely carves out sale, beauty, or designer labels — undercuts the "honest offer" signal.
- **CTA is weak.** "Start Shopping" is generic — no category, no urgency, no product link. A subscriber who came for shoes gets the homepage.
- **No social proof or personalization.** No "welcome, here's what shoppers like you love" framing; the grid reads as randomly assorted.

## Recommendations

- 1. **Lead with the code in the hero.** Swap "You're on the List" for "15% Off Starts Now" and move the code + CTA above the fold as the first visual element after the logo.
- 2. **Make the CTA category-specific.** Replace "Start Shopping" with "Shop Women's" or "Shop New Arrivals" to give the click a destination.
- 3. **Anchor the discount with one aspirational price.** Show a single styled product — e.g., a VEJA sneaker at $165, now $140 — so "15% off" has a real-world reference.
- 4. **Remove or explain the asterisk up front.** Either lead with the exclusions plainly ("Excludes sale and beauty") or run a truly site-wide code. The asterisk on a welcome email creates instant trust erosion.
- 5. **Add a deadline.** "Code expires in 7 days" creates credible urgency without feeling spammy.

## Technical Audit

## Technical Audit — Neiman Marcus "Win-win: 15% off" Email

---

### 1. Technical Summary

The email is a standard Salesforce Marketing Cloud (SFMC) deployment using AMPscript for personalization. Two infrastructure-level concerns stand out: unresolved merge token logic in the HTML comments and missing authentication headers at the relay layer.

---

### 2. Link & Tracking Issues

**27 tracking links skipped (click-redirect domains)** — QA could not probe destination URLs; broken destination links cannot be ruled out. These are presumably routed through NM's click-tracking domain (e.g., `click.e.neimanmarcus.com`).

**Plain-text part is 70% URLs** (4,745 of 6,137 chars) — The plain-text alternative is almost entirely raw redirect URLs with no human-readable copy. This triggers spam filters that use text-to-link ratio heuristics and degrades the experience for plain-text clients.

---

### 3. Rendering & Accessibility

**9 product images missing `alt` text:**
```
product1.png – product9.png
src: https://neimanmarcus.com/promo-email/PROMOTIONAL/cat86620752/product*.png
```
All 9 are flagged with no `alt` attribute. When images are blocked (common in Outlook, corporate mail), these cells render as blank space with no fallback label. This also fails WCAG 2.1 SC 1.1.1.

**Commented-out viewport meta variants** — Three `<meta name="viewport">` tags are commented out directly above the active one. Dead code; negligible risk but signals template hygiene issues.

**Hamburger nav uses CSS `:checked` trick** — Works in Apple Mail / Gmail app but is non-functional in Outlook (all versions) and many webmail clients that strip `<input type="checkbox">` interactions. No Outlook fallback is visible in the truncated source.

---

### 4. Personalization & Merge Tokens

**AMPscript variable block is in an HTML comment, not an AMPscript block:**
```html
<!--REQUIRED variables: @email ... @user Lookup(...) @emailid ... -->
<!--/* SET @user = HASHED_EMAIL_SHA256 */-->
```
The `SET @user = HASHED_EMAIL_SHA256` line is inside an HTML comment (`<!-- -->`), not wrapped in `%%[ ]%%` or `<script runat="server">`. If this is meant to execute at send time, it will **not** run — it will be treated as a static comment and stripped. The `@user` variable will be uninitialized, silently producing empty output or a runtime error wherever `@user` is referenced downstream (e.g., identity resolution, suppression logic).

The `@refid = CONCAT(@base_refid,"")` pattern (concatenating with an empty string) is a known SFMC workaround to force string type-casting, but it implies `@base_refid` may arrive as a non-string type from the sendable DE — worth validating at the data extension level.

---

### 5. Compliance

| Check | Status | Evidence |
|---|---|---|
| `List-Unsubscribe` header | **MISSING** | Not captured by AgentMail relay |
| `List-Unsubscribe-Post` (RFC 8058) | **MISSING** | One-click unsubscribe not confirmed |
| `Authentication-Results` (SPF/DKIM) | **UNKNOWN** | Header absent at relay; raw delivery status unverifiable |

`List-Unsubscribe` and `List-Unsubscribe-Post` are required by Gmail and Yahoo's 2024 bulk-sender mandates for lists >5K/day. Their absence (even if only at the capture layer) warrants verification against the original SMTP headers before treating as compliant. The missing `Authentication-Results` header means SPF/DKIM pass/fail cannot be confirmed from this audit — must be checked at the MTA.

---

### 6. Email-to-Site Continuity

**Cannot verify UTM parameters** — All 27 destination links are behind a click-redirect domain and were not probed. UTM tagging, promo code pre-population, and landing page alignment are unverifiable from this audit. A separate link-destination spot-check is needed.

**Promo code delivery mechanism** — The subject references "15% off" but the HTML source is truncated before any coupon/promo-code block. If the discount code is rendered via an AMPscript variable (e.g., `%%=PromoCode=%%`), and the personalization block above is broken (see §4), the code may render empty for some recipients.

---

### 7. Recommendations

| Priority | Issue | Action |
|---|---|---|
| **High** | `SET @user` in HTML comment | Move the AMPscript `SET` statement into a valid `%%[ ]%%` block before the `<html>` tag |
| **High** | Missing `List-Unsubscribe` / `List-Unsubscribe-Post` | Confirm headers are present in raw SMTP delivery; add `%%[ ... ]%%`-based unsubscribe header injection if absent |
