- **Spend-tier table** is front and center — threshold and reward are scannable in seconds without reading a word of copy.
- **Six-brand product grid** is credible and specific; Jimmy Choo, Zimmermann, and FRAME do more selling than any lifestyle headline could.
- **"SHOP & EARN" CTA** is more specific than a generic "Shop Now" — it names the mechanic in two words.
- **Subject line at 48 chars** — short, no spam signals, "$500 gift card" is the leading hook.
- **"Get summer-ready" subhead** keeps the email feeling seasonal rather than evergreen.

## What's weak

- **"Extended for one more day" after "last chance" yesterday** is a brand-trust burn. Subscribers who saw both sends now know every NM deadline is negotiable.
- **Subject says "$500 gift card," email says "$50–$500"** — a small bait-and-switch that creates a let-down moment at open.
- **No InCircle or member-tier signal** — nothing signals this is exclusive or personalized for a high-spend loyalist. It reads mass.
- **No visible preheader** — the render shows no dedicated preheader text, meaning inbox preview likely defaults to nav links ("WOMEN MEN SHOES SALE") or "LIMITED TIME" — both wasted real estate.
- **Fourth iteration fatigue** — the July 12 version scored 8/10 for good reason; this one is the same skeleton with exhausted urgency.

## Recommendations

- 1. **Honor the deadline or don't set one.** "Extended for one more day" after "last chance" is the moment subscribers learn to ignore all future urgency signals from this brand. One hard close executed once outperforms four soft ones.
- 2. **Fix the subject-to-body mismatch.** Lead with the minimum earn ("$50 gift card") or the tier mechanic, not the max. "Earn a $500 gift card" sets a ceiling expectation that the email immediately scales back.
- 3. **Write a real preheader.** If the tier mechanic is the offer, spell it out: "Spend $500, earn $50 — tiers up to $500 back."
- 4. **Add InCircle or personalization signal** — even a "for valued customers" header would help this feel segmented rather than broadcast.
- 5. **Make the promo code visible and prominent** — it's there but small. For $500+ spenders, a visible code feels earned.

## Technical Audit — Neiman Marcus "Earn a $500 gift card" (Extended)

---

### 1. Technical Summary

The template is a Salesforce Marketing Cloud (AMPscript) send with a table-based XHTML layout. Three QA warnings require attention — most critically, unverified authentication headers and missing one-click unsubscribe support — and the HTML source contains an incomplete/commented-out personalization assignment that may silently produce empty merge field values.

---

### 2. Link & Tracking Issues

**26 click-redirect links skipped** — all route through `e.neimanmarcus.com` (the ESP click-tracking domain). Because the QA probe does not chase redirects through that domain, final destination URLs, UTM parameter presence, and landing page health are entirely unverified for this send.

No broken links were detected in the subset that could be probed.

### 3. Rendering & Accessibility

| Finding | Evidence |
|---|---|
| Three conflicting viewport `<meta>` tags are commented out | Lines in `<head>`: `width=device-width`, `width=320, initial-scale=0.29`, `width=1024` — copy-paste accumulation; the live tag is correct but the dead tags are clutter risk if accidentally uncommented |
| Two separate `<style>` blocks with overlapping breakpoints | Block 1: `max-width: 600px`; Block 2: `max-device-width: 480px / 520px` — fragmented responsive logic increases specificity conflict risk |

### 4. Personalization & Merge Tokens

**Critical: `@user` assignment is commented out.**

```html
<!--/* SET @user = HASHED_EMAIL_SHA256 */-->
```

The variable declaration block lists `@user` as a required variable derived from a SHA-256 hash of the email address. The actual `SET` statement is wrapped in an HTML comment, meaning it never executes. Any downstream reference to `@user` (e.g., in tracking parameters or preference center links) will resolve to an empty string or throw an AMPscript runtime error depending on how it's referenced.

Additional concerns:

- `@refid = CONCAT(@base_refid,"")` — concatenating with an empty string literal suggests a suffix was intended but removed; `@refid` will equal `@base_refid` exactly, which may be correct, but should be confirmed against the campaign calendar spec.
- The comment says **"CHOOSE ONE SCENARIO BELOW"** but the selected scenario is not visible in the truncated source. If the template ships with the scenario comment block intact, rendered recipients will see raw HTML comment text in certain parser-broken clients (rare but possible with aggressive sanitizers).
- `@cmdid` and `@uEm` are looked up from `NM_CRM_Feed` — if a subscriber record is missing from that DE, both will be empty with no null-guard visible in the source.

### 6. Email-to-Site Continuity

All 26 links were skipped by the HTTP probe, so UTM parameter coverage cannot be confirmed. Specific risks:

- If `@user` is empty (see §4), any link that appends `?user=@user` will send a blank parameter to the analytics layer, breaking identity stitching between the email send and on-site session.
- `@refid` used in tracking URLs will carry the raw `@base_refid` value with no campaign suffix — attribution reports should be checked to confirm segments are distinguishable.
- Landing page alignment with the "Earn a $500 gift card" subject line / "Extended for one more day" urgency framing is unverifiable without chasing the redirects manually.

---

### 7. Recommendations

1. **Immediately audit `@user` assignment** — determine whether the commented-out `SET @user = HASHED_EMAIL_SHA256` was intentional (field removed from downstream use) or an accidental omission. If any link or data extension write references `@user`, the current template sends blank values.
2. **Add `List-Unsubscribe-Post` header** — configure the ESP send definition to include RFC 8058 one-click unsubscribe. Required for Gmail bulk sender compliance.
3. **Verify authentication headers end-to-end** — confirm SPF/DKIM pass on the `e.neimanmarcus.com` envelope domain via a test send to a tool like Mail-Tester or MX Toolbox; do not rely solely on the AgentMail relay capture.
4. **Probe redirect chain on at least a sample of the 26 tracking links** — confirm UTM parameters (`utm_source`, `utm_medium`, `utm_campaign`) are present on final destination URLs and that `@user` / `@refid` are populated correctly.
5. **Remove or consolidate dead `<meta>` viewport tags and the hamburger CSS checkbox hack** — the interactive menu will not function in Gmail (>40% of B2C opens); add a static fallback navigation or remove the dead CSS weight.
6. **Add null guards for `@cmdid` and `@uEm`** — wrap lookups in `IIF(EMPTY(@cmdid), "default", @cmdid)` or equivalent to prevent silent empty-parameter issues for subscribers not present in `NM_CRM_Feed`.
