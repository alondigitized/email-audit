# Private Event: 40% off select designer styles
**Score:** 7/10 · **Type:** Email audit · **2026-11-18**
## Executive summary

- This is a clean, single-offer sale email, and it's also the third near-identical discount send in four days. The hero is a cream block with "PRIVATE EVENT" in large serif type and "40% OFF" in red. The details are "SELECT DESIGNER STYLES", "LIMITED TIME | CODE NMACCESS", and a black "SHOP NOW" button. The offer is impossible to miss.
- The creative has no product, no model and no brand name beyond "select designer styles". It's a typographic poster. It's also a repeat. On 11/15 the "early access ends today: up to 40% off" send used a similar hero and a code (NMSALE). On 11/16 the Designer Sale launched at up to 50% off. On 11/17 the gift-card send followed. Now there's another 40% code, NMACCESS, with "Private Event" framing that tries to make a standing sale feel exclusive. A subscriber would see through it.
- Judgment: clear and readable, but generic and fatigued. It will get skimmed. It needs product proof and a real reason for the "private" label.

## What's working

- The "40% OFF" in red is the clear focal point, with strong contrast on the cream background.
- The hierarchy is clean: eyebrow, headline, offer, qualifier, button.
- The code NMACCESS is bolded in the hero, so it's easy to find.
- The send is light and fast to scan, with no broken images or layout issues.
- The footer is tidy and puts the app, stylist, store finder and account links in one place.

## What's weak

- There is no product imagery at all. Nothing shows what's actually 40% off.
- "SHOP NOW" is generic and goes to a broad "select designer styles" destination. It also sits above a lot of dead space.
- "Exclusions Apply" under the button, plus a dense fine-print block at the bottom, undercuts the "Private Event" promise.
- The deadline (11/26/26 at 10:00 PM CT) is buried in the fine print. The hero only says "LIMITED TIME".
- It's the third discount email in four days, so the "private event" and "exclusive" framing feels hollow.
- The code has to be entered manually in the bag, which adds friction.

## Recommendations

- 1. Add 3–6 real products or named designers in a grid under the hero. A product-free 40% banner is the biggest miss.
- 2. Put the real deadline in the hero, for example "Ends 11/26 | Code NMACCESS".
- 3. Change the button copy to something specific, such as "Shop 40% off designer" or "Shop women's designer". Then link each product to its own page.
- 4. Reduce the gap between sends, or differentiate this one. If "private" is real, say who it's for, such as loyalty members or InCircle tiers.
- 5. Add an "Apply code at checkout" or auto-apply link to cut friction.

- **Preheader Alt A:** `Select styles from top designers. Use code NMACCESS at checkout before 11/26.`

## Technical Audit

## 1. Technical Summary
The email is a table-based XHTML Transitional template with a mobile media-query system. The truncated source shows a leaked SFMC/AMPscript developer comment and a zoom-blocking viewport tag. The QA run found 0 hard failures and 4 warnings, and all four are unresolved or unverifiable because the relay doesn't capture headers.

## 2. Link & Tracking Issues
- **Not verified:** 14 tracking/click-redirect links were skipped by the HTTP probe (`[WARN] 14 tracking link(s) skipped`). Their destinations and redirect health are untested.
- **Plain-text part:** 2638 of 3595 characters (about 73%) are URLs (`[WARN] Plain-text is >70% URLs`). The text alternative is mostly raw tracking links, which can add spam-filter risk and gives plain-text readers a poor experience.
- No other link problems are visible in the truncated source.

## 3. Rendering & Accessibility
- **Zoom disabled:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` blocks pinch-zoom. This fails WCAG 1.4.4 (Resize Text).
- **Invalid font stack:** `.disclaimerText` uses `font-family: Arial, Helvetica, 'sans-serif'`. The quoted `'sans-serif'` is read as a font name, not the generic keyword, so the generic fallback is lost.
- **Fragile selectors:** the mobile rules use exact-match attribute selectors such as `*[class=hide]`, `*[class=mobile]` and `*[class=contenttable]`. They stop matching when an element carries more than one class.
- **Duplicate declaration:** `*[class].show` sets `width` twice (`width: auto !important` and `width: 278px`), so the second is dead or conflicting.
- **Hamburger nav:** it depends on the `:checked` checkbox hack (`.navbar-checkbox:checked~.menu`). This is unsupported in Gmail and several Outlook clients. The truncated source doesn't show whether a fallback exists, so I can't confirm it.
- **Title:** `<title>Neiman Marcus </title>` has a trailing space and doesn't reflect the subject. This is minor.

## 4. Personalization & Merge Tokens
- **Leaked template comment:** the delivered HTML opens with the developer comment `<!--REQUIRED variables: @email ... @base_refid ... Lookup("NM_Subscriber_New_Consolidated", ...) ... Lookup("NM_CRM_Feed", "uEm", ...) ... CHOOSE ONE SCENARIO BELOW --> <!--/* SET @user = HASHED_EMAIL_SHA256 */ -->`.
  - It exposes internal Data Extension names (`NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`) and field names (`EMAIL_ID`, `uEm`, `cmdid`).
  - The instruction to "choose one scenario" was never resolved.
  - The comment contains unbalanced parentheses (`@user Lookup(...))`).
  - It sits before the `<!DOCTYPE>`, which can trigger quirks mode in some older clients.
- No unresolved `%%…%%` or `@var` tokens are visible in the rendered portion of the source.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` and `List-Unsubscribe-Post`:** both are missing. The QA tool notes that the AgentMail relay may strip them, so I can't confirm a real defect. If they are absent at the sender, Gmail and Yahoo bulk-sender rules (RFC 8058 one-click) are not met.
- **`Authentication-Results`:** the header is missing, so SPF, DKIM and DMARC status is unknown. The sender is `e.neimanmarcus.com`, and alignment couldn't be checked.
- **Body footer:** the visible unsubscribe link and physical address are outside the truncated source, so they can't be assessed.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Insufficient data. The truncated source shows no destination URLs, and the 14 tracking links weren't resolved. The template uses `@refid` / `@base_refid` and a hashed email (`@user`), which suggests refid-based tracking rather than UTM parameters. I can't confirm this or check landing-page alignment.

## 7. Recommendations
1. Strip the SFMC variable and AMPscript comment from the production send. This removes the exposed DE names and the unresolved scenario selector.
2. Remove `maximum-scale=1` from the viewport tag.
3. Change `'sans-serif'` to the unquoted `sans-serif` in `.disclaimerText`.
4. Check `List-Unsubscribe` and `List-Unsubscribe-Post` on the raw message at the sender, bypassing the relay. Also confirm SPF, DKIM and DMARC alignment for `e.neimanmarcus.com`.
5. Rewrite the plain-text part so it has more prose and fewer bare URLs, bringing it under the 70% URL threshold.
6. Resolve a sample of the 14 skipped tracking links to check for 200 status, redirect chains, and `utm_*` or `refid` on landing.
7. Replace the exact-match `*[class=x]` selectors with `.x`, and confirm the hamburger nav has a fallback for Gmail and Outlook.
