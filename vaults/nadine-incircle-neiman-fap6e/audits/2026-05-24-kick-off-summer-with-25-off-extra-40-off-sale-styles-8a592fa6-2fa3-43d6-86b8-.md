# Technical Audit — Neiman Marcus "Kick off summer with 25% off + extra 40% off sale styles"

## 1. Technical Summary
The HTML is a legacy XHTML 1.0 Transitional template rendered through Salesforce Marketing Cloud (AMPscript merge tokens visible at top), with standard table-based layout. QA flags missing compliance headers (likely stripped by the AgentMail relay) and a plain-text part dominated by tracking URLs.

## 2. Link & Tracking Issues
- 26 tracking/click-redirect links present; HTTP reachability was not probed, so destination health is unverified.
- Plain-text alternative is **5315/6204 chars URLs (>85%)** — this severely hurts spam scoring and is a deliverability liability. Plain-text part should be regenerated with link labels rather than raw `http://click...` redirects.
- No UTM parameters visible in the truncated source — cannot confirm campaign attribution wiring (see §6).

## 3. Rendering & Accessibility
- Doctype is **XHTML 1.0 Transitional** referencing `https://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd` — acceptable for email but dated.
- `<title>` is just `"Neiman Marcus "` (trailing space) — non-descriptive for screen readers / preview panes.
- No `lang` attribute on `<html>` — accessibility regression for assistive tech.
- Heavy reliance on `*[class=...]` attribute selectors in media queries; Gmail historically strips these — verify mobile rendering in Gmail iOS/Android.
- Accessibility of images cannot be evaluated from the truncated source (alt-text audit incomplete).

## 4. Personalization & Merge Tokens
- AMPscript block at top of source is **leaking into the rendered HTML** as an HTML comment:
  ```
  <!--REQUIRED variables: @email ... @user Lookup("NM_Subscriber_New_Consolidated", ...) @uEm = Lookup("NM_CRM_Feed", "uEm", "EMAIL_ADDRESS", @email)) ...-->
  ```
  This exposes internal Data Extension names (`NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`), column names (`uEm`, `cmdid`, `EMAIL_ID`), and the SHA256-hashed-email convention. Recon value for a phisher; should be stripped at send time or wrapped in `%%[ ... ]%%` so SFMC removes it.
- Unmatched parentheses in the comment (`Lookup(..., @email))`) suggest the AMPscript was never fully cleaned up from a template draft.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` header missing** (QA WARN) — may be relay-stripped by AgentMail, but cannot be confirmed.
- **`List-Unsubscribe-Post: List-Unsubscribe=One-Click` missing** (RFC 8058) — Gmail/Yahoo bulk-sender requirements (Feb 2024+) effectively mandate this for senders >5k/day. Confirm present at the SFMC sending boundary.
- **`Authentication-Results` header not captured** — SPF/DKIM/DMARC status unknown via this capture path. Verify directly at a mailbox provider.
- Physical postal address and visible unsubscribe link could not be confirmed from the truncated body.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- All outbound links are wrapped by SFMC click tracker (`e.neimanmarcus.com` redirector); final destination URLs and UTM params are not inspectable in source — cannot verify `utm_source=email`, `utm_campaign`, `utm_medium` consistency or landing-page alignment without resolving redirects.

## 7. Recommendations
1. Wrap the AMPscript variable preamble in `%%[ ... ]%%` so it is not emitted as an HTML comment exposing DE schema.
2. Regenerate the plain-text part — replace raw tracker URLs with labeled link text to drop URL ratio well below 70%.
3. Add `lang="en"` to `<html>` and give `<title>` a descriptive, trimmed value.
4. Confirm `List-Unsubscribe` and `List-Unsubscribe-Post: List-Unsubscribe=One-Click` are present at the actual SMTP boundary (test against a Gmail account and inspect raw headers); the relay capture path may be hiding them.
5. Verify SPF/DKIM/DMARC alignment for `e.neimanmarcus.com` independently of the AgentMail capture.
6. Resolve a sample tracking link end-to-end to confirm UTM parameters and that landing pages reflect the 25%/extra-40% offer.
7. Validate mobile rendering in Gmail iOS/Android given heavy `*[class=...]` selector usage in media queries.
