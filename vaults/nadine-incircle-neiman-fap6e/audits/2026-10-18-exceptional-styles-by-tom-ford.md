## Technical Audit

## 1. Technical Summary
The visible HTML is a standard table-based SFMC template with a leaked internal comment block and a viewport setting that blocks pinch-zoom. The source was truncated and the QA run skipped probing all 19 tracking links, so link, footer, and compliance checks are mostly unverified. The 4 QA warnings are likely relay artifacts, not confirmed defects.

## 2. Link & Tracking Issues
- **Unverified:** QA skipped the HTTP probe on 19 tracking/click-redirect links, so destination validity, redirect chains, and 404s are unknown.
- **Plain-text part:** 3592 of 4092 characters (about 88%) are URLs. This is consistent with long tracking URLs in the text alternative. It is a deliverability risk, not a functional break.
- No specific malformed `href`s are visible in the truncated source.

## 3. Rendering & Accessibility
- **Pinch-zoom disabled:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` fails WCAG 1.4.4 (Resize Text) on mobile clients that honor it.
- **Content before the DOCTYPE:** A large HTML comment precedes `<!DOCTYPE ...>`. Legacy clients and IE-based renderers can drop into quirks mode when anything precedes the doctype.
- **Checkbox-hack hamburger nav:** `.navbar-checkbox:checked~.menu`, `.hamburger` and `.close` appear in the CSS. These menus generally fail in Gmail and Outlook, and the CSS-only toggle is not reliably keyboard- or screen-reader-accessible. The fallback behavior can't be confirmed from the truncated source.
- **Exact-match attribute selectors:** `*[class=contenttable]` and similar only match when `class` is exactly that value. Any element with an added class silently loses its mobile styles.
- **Title:** `<title>Neiman Marcus </title>` is generic and has a trailing space. This is minor.
- Alt text, image dimensions, and the Outlook/VML fallback can't be assessed because the source is truncated.

## 4. Personalization & Merge Tokens
- **Internal template comment leaked into the delivered HTML:** It reads `REQUIRED variables: @email … @base_refid … Lookup("NM_Subscriber_New_Consolidated", "EMAIL_ID", "EMAIL_ADDRESS", @email) … Lookup("NM_CRM_Feed", "uEm"/"cmdid" …) … CHOOSE ONE SCENARIO BELOW --> <!--/* SET @user = HASHED_EMAIL_SHA256 */ -->`. This exposes data extension names, field names, and the AMPscript/personalization design to every recipient, so it is an information-disclosure and QA-hygiene issue. It also suggests the unresolved "CHOOSE ONE SCENARIO" template instructions were never stripped.
- **No unresolved tokens in the visible portion:** I saw no `%%…%%` or `{{…}}` strings in the visible source. The rest of the body is not available.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication)
- **List-Unsubscribe header not found [WARN]:** The QA note says AgentMail may not capture it, so this is unconfirmed. If it is truly absent, it falls short of Gmail/Yahoo bulk-sender requirements.
- **List-Unsubscribe-Post (RFC 8058) not found [WARN]:** Same caveat, so one-click unsubscribe support is unconfirmed.
- **Authentication-Results not found [WARN]:** SPF, DKIM, and DMARC status are unknown. The relay strips this header, so it cannot be judged from this sample.
- **Footer:** The in-body unsubscribe link and the physical postal address are not in the truncated source, so they can't be verified.

## 6. Email-to-Site Continuity
- **Not assessable:** The 19 links were not resolved, and no UTM or `refid` parameters are visible in the truncated source.
- **Hashed identifier:** The leaked comment references `@refid`, `@uEm`, `@cmdid`, and a hashed email (SHA256). These likely get appended to links. Confirm that a hashed email, not a raw one, is what appears in click URLs.

## 7. Recommendations
1. Strip the SFMC variable/scenario comment block from the production send, including the pre-DOCTYPE comment. Move the documentation into the template's non-rendered metadata.
2. Remove `maximum-scale=1` from the viewport meta tag.
3. Confirm `List-Unsubscribe` and `List-Unsubscribe-Post: List-Unsubscribe=One-Click` against the original headers, not the AgentMail copy. Also verify SPF, DKIM, and DMARC alignment for `e.neimanmarcus.com`.
4. Rerun QA against the full, untruncated HTML. Resolve the 19 tracking links through their redirects, then check the final URLs, UTM parameters, and footer unsubscribe and address.
5. Make the hamburger-nav fallback degrade to a visible link list in clients without checkbox support.
6. Shorten the plain-text version, for example with fewer or shorter tracked URLs, so URLs are a smaller share of the text.
