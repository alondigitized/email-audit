# The more you buy, the more you save
**Score:** 7/10 · **Type:** Email audit · **2026-10-01**
## Executive summary

- This is a tiered spend-and-save promo with a strong hero. The mustard block leads with "UP TO $650 OFF", a single code (JUST4U), a black SHOP NOW button, and a spend/save table ($150→$30, $400→$100, $1,000→$300, $2,000+→$650). The eye lands on the offer first, and the mechanic is clear in seconds.
- It is also generic. The subject, "The more you buy, the more you save," gives no dollar figure and no deadline. The only end date, 10/4 at 10 PM CT, sits in the fine print at the bottom. The nine-product grid is mostly occasion wear and outerwear (a gown, a blazer, loafers), with no prices. It reads as a shelf, not a recommendation.
- It also lands the day after "Ends today: 25% off select styles & 20% off select jewelry" (09-30), so a subscriber sees a second discount in 24 hours. That is promo fatigue after a week of editorial sends (McQueen, Rag & Bone, Bottega Veneta). Judgement: well-built and clear, but the subject undersells it and the deadline is hidden. Solid middle-of-the-pack, with room to be sharper.

## What's working

- The hero offer dominates: large "UP TO $650 OFF" on a warm yellow block with a high-contrast black button.
- The spend/save table makes the tiers scannable and nudges a bigger basket.
- The promo code is shown in the hero, so there is no hunting for it.
- The 3x3 designer grid on neutral backgrounds is clean, with no broken images or layout bugs.
- A secondary row of category buttons (Women's, Handbags, Men's, Home) gives shoppers a way in beyond the grid.

## What's weak

- The deadline ("Ends 10/4/26 at 10:00 PM CT") appears only in the fine print. The hero says "Limited time," which is vague.
- No product shows a price or a post-discount price, so the offer isn't tied to anything concrete.
- The "Exclusions apply" disclaimer is small, and the long fine print (no beauty, jewelry, exclusives, and so on) makes the offer feel less honest than the hero implies.
- The 15% text-signup banner competes with the main offer and adds a second discount message.
- The hero CTA is a generic "SHOP NOW," and the category buttons are generic too.

## Recommendations

- 1. Move the deadline into the hero ("Ends Sunday 10/4") and into the subject. This is the biggest lift, since real urgency is currently buried.
- 2. Put the dollar figure in the subject so the inbox sees a concrete offer.
- 3. Add prices or "now $X with code" to the product grid so shoppers can see what the discount buys.
- 4. Make the CTA specific, for example "Shop & save up to $650," and link the grid tiles to the individual products.
- 5. Move the text-signup banner below the footer links, or drop it from promo sends, so there is one offer.
- **Subject Alt A:** `Save up to $650 — ends Sunday`
- **Subject Alt B:** `$30 off $150, $650 off $2,000+`
- **Preheader Alt A:** `Use code JUST4U on new-season designer styles through 10/4.`
- **Preheader Alt B:** `Spend more, save more: tiers from $30 to $650 off, online only.`

## Technical Audit

## 1. Technical Summary
The visible HTML is a standard XHTML 1.0 Transitional, table-based SFMC-style template. It has a leaked ESP logic comment and a viewport setting that blocks zoom. The source is truncated and the QA run has 0 failures, so body, footer and link-level checks are only partly confirmed.

## 2. Link & Tracking Issues
- **31 tracking links were not probed.** The click-redirect domains were skipped, so destination status, redirect chains and expiry are unverified.
- **Plain-text part is 79% URLs** (5441 of 6884 chars). This is consistent with long redirect-wrapped URLs inlined in the text alternative. It is a spam-filter and readability risk (QA WARN).
- No broken or malformed hrefs are visible in the truncated source.

## 3. Rendering & Accessibility
- **Zoom is disabled:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">`. `maximum-scale=1` blocks pinch-zoom, which conflicts with WCAG 1.4.4 (Resize Text).
- **No `lang` attribute:** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang` (or `xml:lang`), so screen readers can't pick the right language.
- **Exact-match class selectors:** the mobile rules use `*[class=contenttable]`, `*[class=mobile]`, `*[class=hide]` and similar. These only match when the class attribute is exactly that value. Any element with multiple classes will silently skip the mobile override. I can't confirm this from the truncated markup.
- **Checkbox hamburger nav:** the `.navbar-checkbox:checked~` pattern is not supported in Gmail and several other clients. A fallback is not visible in the excerpt.
- **Minor:** `<title>Neiman Marcus </title>` has trailing whitespace and doesn't match the subject line.
- Image alt text and image-to-text ratio can't be assessed because the source is truncated.

## 4. Personalization & Merge Tokens
- No unresolved merge tokens are visible in the rendered portion of the source.
- **Template logic leaked into delivered HTML.** The pre-`<!DOCTYPE>` comment (`REQUIRED variables: @email … @base_refid … @refid … @uEm … @cmdid`) ships to recipients. It exposes internal Data Extension names (`NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`) and field names (`EMAIL_ID`, `uEm`, `cmdid`). It also contains a note, `SET @user = HASHED_EMAIL_SHA256`, that the template author left unresolved. The comment text also has unbalanced parentheses in the `Lookup(...))` expressions. Nothing in the comment executes, but a draft-level configuration note reached production.
- Because the comment says to "CHOOSE ONE SCENARIO", the sender may not have finalized which `@user` scenario the template uses. Check that the body doesn't contain a raw `@user` or `%%` token (not visible in the excerpt).

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) were not found.** QA attributes this to the AgentMail relay possibly stripping them. It is unconfirmed, so don't treat it as a sender defect. For Gmail/Yahoo bulk-sender requirements, check the raw message.
- **`Authentication-Results` was not found.** SPF, DKIM and DMARC status is unknown. The From domain `e.neimanmarcus.com` is a subdomain, but alignment can't be verified from this data.
- The visible-body unsubscribe link and physical postal address are in the truncated footer and can't be confirmed.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- Not assessable. All 31 tracking links were skipped, so landing URLs, UTM parameters and refid propagation are not observable. The template does build a `@refid` from `@base_refid`, so campaign attribution probably runs through the redirect rather than visible UTMs.

## 7. Recommendations
1. Strip the SFMC variable and scenario comment from the production send (build-time or AMPscript-only, not HTML comments).
2. Remove `maximum-scale=1` from the viewport meta, and add `lang="en"` and `xml:lang="en"` to `<html>`.
3. Switch the mobile overrides to `[class~=...]` or single-class selectors where elements carry multiple classes, and confirm there is a non-checkbox fallback for the nav.
4. Verify `List-Unsubscribe` and `List-Unsubscribe-Post` and SPF/DKIM/DMARC on the raw message, not the AgentMail copy.
5. Shorten the plain-text alternative, for example with shorter tracking URLs or fewer links, to lower its URL ratio.
6. Re-run the audit with the full HTML and a link-resolution pass that follows the click-tracking redirects, so UTMs and landing-page alignment can be checked.
