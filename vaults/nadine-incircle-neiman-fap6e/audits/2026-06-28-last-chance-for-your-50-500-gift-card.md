# Last chance for your $50–$500 gift card
**Score:** 9/10 · **Type:** Email audit · **2026-06-28**
## Executive summary

- This is the **fourth touch** on NM's gift card earn promotion in five days — June 24 launched it (9/10), June 25 was second touch (9/10), June 27 was third (9/10), and now June 28 is "Last chance." The subject line is the strongest NM has used across all four sends: urgent, specific, and under 50 chars. But the email body doesn't deliver on it. There's no explicit deadline date, no countdown, no "ends tonight at 11:59 PM CT" anywhere — the urgency the subject creates evaporates the moment you open.
- The underlying mechanic is still solid. The spend/earn tier table is clear, the code is prominent, SHOP & EARN is unambiguous, and the layout renders clean. But a subscriber who opened any of the three prior sends will find zero creative differentiation inside — same headline, same table, same structure, same code. The only new signal is the subject line.
- The verdict: this send will convert the fence-sitters who saw the earlier three and didn't bite — that's exactly what a last-chance send should do — but the body squanders the urgency the subject promises.

## What's working

- **"Last chance" + specific dollar range in 40 chars** is the strongest subject NM has used across this entire campaign run.
- **Spend/earn tier table** ($200→$50, $300→$75, $500→$125, $1,000→$500) is scannable and communicates value instantly.
- **Clean visual hierarchy** — offer hero is above the fold, code NM.JUNE is visible, SHOP & EARN is unambiguous.
- **No render bugs** — tight layout, no broken images, no orphaned text.
- **Six category CTAs** (Women's, Clothing, Shoes, Men's, Handbags, Home) give different shopper types a clear entry point.

## What's weak

- **Body copy ignores "Last chance"** — no deadline date, no countdown, no "tonight only" copy reinforces the subject's urgency once you're inside.
- **Fourth consecutive send on identical creative** — same headline, same table, same code, same structure. Repeat openers feel zero uplift.
- **Product thumbnails are too small** — the 3×3 grid doesn't create desire and fails to connect specific products to the earn mechanic.
- **Dense fine print block** at the bottom is long and unformatted — particularly counterproductive on a send designed to drive same-day action.
- **Six CTAs produce decision paralysis** — no hero product, no single recommended action.

## Recommendations

- 1. **Put the deadline in the body, immediately.** "Offer ends tonight, June 28 at 11:59 PM CT" as the first line under the hero — or a simple red urgency banner. This is the single highest-lift change for any last-chance send.
- 2. **Feature one hero product tied to the earn tier** — "These Jimmy Choos ($395) earn you a $75 gift card." Makes the promo tactile instead of abstract; also gives a repeat opener something new to see.
- 3. **Cut to 2–3 CTAs.** SHOP WOMEN'S + SHOP MEN'S + SHOP SALE. Six buttons diffuse intent.
- 4. **Accordion or collapse the fine print.** A "See full terms ↓" link keeps disclosure without the wall of text that signals friction at decision time.
- 5. **Add a small urgency signal to the hero image** — a "Today only" pill or red badge reinforces the subject line's urgency where it counts.
- **Subject Alt A:** `Ends tonight: earn a $50–$500 gift card`
- **Subject Alt B:** `Your $500 gift card window closes today`
- **Preheader Alt A:** `Code NM.JUNE · Last day to shop & earn — check your tier`
- **Preheader Alt B:** `Spend $200, earn $50 · Offer expires tonight at 11:59 PM CT`

### 3. Rendering & Accessibility

**Commented-out duplicate viewport tags** — Three conflicting `<meta name="viewport">` tags are present, all commented out except the active one:
```html
<!--<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" />-->
<!--<meta name="viewport" content="width=320, initial-scale=0.29">-->
<!--<meta name="viewport" content="width=1024">-->
```
These are inert but indicate the template has accumulated legacy edits without cleanup. No rendering impact, but signals version control debt.

**CSS hamburger nav via checkbox hack** — The mobile nav is implemented with a `<input type="checkbox">` toggle pattern and `visibility`/`opacity` transitions. Gmail (web and Android) strips `<style>` blocks partially; the `*[class].navbar-checkbox:checked~*[class].menu` selectors are unlikely to function in Gmail, leaving mobile users without a nav. This is a known limitation of this pattern in email clients.

**`alt` text** — The HTML is truncated before images appear; alt text completeness cannot be confirmed. This should be verified in the full source.

### 4. Personalization & Merge Tokens

**Dead-code variable assignment for `@user`** — This is the most significant technical defect:

```html
<!--/* SET @user = HASHED_EMAIL_SHA256 */ -->
```

This AMPscript `SET` statement is wrapped in an HTML comment (`<!-- -->`), so it **never executes at render time**. The required-variables comment block at the top of the template defines `@user` as:
```
Lookup("NM_Subscriber_New_Consolidated", "EMAIL_ID", "EMAIL_ADDRESS", @email)
```
If `@user` is used downstream as the hashed email identifier (e.g., for audience matching, site personalization handoff, or tracking), it will silently carry the `EMAIL_ID` value instead of `HASHED_EMAIL_SHA256`, or it may be empty/null depending on which definition SFMC resolves at render. If `@user` populates any link parameter, this corrupts identity stitching across all 26 tracked links.

**`@refid = CONCAT(@base_refid,"")` is a no-op** — This is a passthrough that adds no value; likely a placeholder that should have appended a suffix. Harmless unless a suffix was intended.

**Internal data extension names exposed in HTML comments** — Visible to any recipient who views source:
```
NM_Subscriber_New_Consolidated
NM_CRM_Feed
```
These are not secrets per se, but they disclose internal SFMC architecture. Standard practice is to strip AMPscript comment blocks before send.

### 5. Compliance

**`List-Unsubscribe` header — not captured** (QA WARN)
The header is absent from what the relay captured. This header is required by Gmail and Yahoo bulk sender policies (enforced since Feb 2024 for senders >5k/day). If the header is present at the MTA level but not relayed, this is a relay gap; if genuinely absent, it is a compliance failure.

**`List-Unsubscribe-Post` header — not captured** (QA WARN, RFC 8058)
One-click unsubscribe (the POST mechanism) is required by the same Gmail/Yahoo bulk sender policy. Its absence from captured headers is the same ambiguity as above but higher severity — Gmail suppresses the unsubscribe UI when this header is missing, which can trigger spam classification.

**SPF/DKIM authentication status — unknown** (QA WARN)
`Authentication-Results` was not captured by the AgentMail relay. Sending domain is `e.neimanmarcus.com`. SPF/DKIM/DMARC alignment cannot be confirmed from available data.

**CAN-SPAM physical address** — Not verifiable from truncated source; the footer (`.disclaimerText`, `.footerText`) exists in the CSS but content is cut off. Must be confirmed in full source.
