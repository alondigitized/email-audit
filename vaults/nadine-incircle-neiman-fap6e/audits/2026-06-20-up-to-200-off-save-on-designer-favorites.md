# Up to $200 off! Save on designer favorites
**Score:** 8/10 · **Type:** Email audit · **2026-06-20**
## Executive summary

- This is NM's spend-to-save pivot — a deliberate gear-shift from the percentage-off Designer Sale that dominated June 18-19. The hero lands cleanly: a gold/cream box announces "UP TO $200 OFF," lays out four spend tiers in a legible table ($250→$50 / $500→$100 / $750→$150 / $1,000+→$200), drops promo code JUNE in large type, and puts a dark "SHOP THE SALE" button directly below. The InCircle Triple Points callout sits right underneath, adding a loyalty layer without burying it. So far, so good.
- Then the email loses the thread. Below the hero it pivots to a nine-product editorial grid labeled "More Reasons to Love: Earn Triple Points on Top Styles" — Stuart Weitzman, Jason Wu, Cinq à Sept, FRAME, STAUD, Joe's Jeans, Jimmy Choo. These products have no visible price or tie-in to the spend-to-save offer. A subscriber who opens for the $200 code hits the tiers, then gets shuffled into a style-story section that doesn't obviously help them reach a tier threshold. The two messages dilute each other. NM's June 18-19 Designer Sale sends (scored 9/10 both days) were stronger precisely because they stayed on one message end-to-end.
- Competent hero, split personality body. Worth opening for the code; conversion potential is left on the table.

## What's working

- Spend-to-save tier table ($250–$1,000+) is immediately scannable — four columns, clean layout, no ambiguity about how much you need to spend.
- Promo code JUNE is large and legible inside the hero itself — subscribers don't have to hunt for it.
- InCircle Triple Points callout appears immediately below the hero, rewarding loyal members without burying the incentive in fine print.
- "SHOP THE SALE" is dark, high-contrast, and verb-forward — the primary CTA is unambiguous.
- Overall render is clean: no broken images, no overlapping text, no visible layout drift.

## What's weak

- Split messaging: the hero is a spend-to-save deal; the body is a Triple Points style editorial. They don't reinforce each other or help the reader reach a spend tier.
- "LIMITED TIME" with no end date, and "code: JUNE" only implies month-end — no credible urgency anchor is stated anywhere.
- Product grid is 80% women's brands; no obvious men's product support despite a "SHOP MEN'S" CTA at the bottom.
- Subject headline "up to $200 off" overstates most subscribers' likely outcome — that number requires $1,000+ spend; the entry point ($50 off $250) would convert more readers.
- No social proof, no editorial copy, no reviews in the product grid section — just nine product shots with brand names.

## Recommendations

- 1. **Commit to one message end-to-end.** Keep the spend-to-save hero, then fill the product grid with items that help subscribers reach the *next* tier — "Need $250 to unlock $50 off? Here are six pieces under $300." That turns the editorial into conversion fuel.
- 2. **Add a hard deadline.** Replace "LIMITED TIME" with a specific date ("Ends Sunday, June 22"). The code JUNE implies month-end but vagueness is a click killer.
- 3. **Lead with the entry point, not the ceiling.** "$50 off a $250 purchase — no minimum fuss" converts more subscribers than "up to $200 off" which implies a $1,000 buy-in.
- 4. **Ease the cadence.** This is the 7th NM email in four days (June 17–20). Consolidating spend-to-save with the Designer Sale messaging into fewer, denser sends reduces unsubscribe pressure.
- **Subject Alt A:** `Save $50–$200 today — code JUNE`
- **Subject Alt B:** `Your $200-off code is inside`
- **Preheader Alt A:** `Spend $250, save $50. Spend more, save more. Ends Sunday.`
- **Preheader Alt B:** `Use code JUNE at checkout — 4 tiers, real savings, regular-price styles.`

## Technical Audit

## Technical Audit — Neiman Marcus "Up to $200 off" Email

### 1. Technical Summary

HTML is structured for Salesforce Marketing Cloud (AMPscript-driven) with a CSS-only hamburger nav and interactive product panels. The most significant finding is a non-executing AMPscript block in an HTML comment, which could silently drop a required personalization variable in one deployment scenario.

---

### 2. Link & Tracking Issues

**26 tracking links skipped (QA: unprobed)**
All click-redirect links passed through a tracking domain (consistent with `e.neimanmarcus.com` infrastructure) and were not HTTP-probed. Destination URLs, UTM integrity, and redirect chain depth are unverified. No broken links were detected in the probed set, but the 26 unprobed links represent full coverage risk.

---

### 3. Rendering & Accessibility

**Commented-out viewport tags (3 variants, 2 dead)**
Three `<meta name="viewport">` declarations are present in `<head>`; two are HTML-commented-out. The live tag is correct (`width=device-width, initial-scale=1, maximum-scale=1`). The dead tags (`user-scalable=no`, `width=320, initial-scale=0.29`, `width=1024`) are harmless but signal template drift — a future editor could accidentally uncomment a conflicting value.

**CSS-only interactive elements have narrow client support**
`.contentInteractive` / `.mobileCont:checked` pattern (CSS checkbox toggle for interactive product panels) renders correctly in Apple Mail but is unsupported in Gmail (web/Android), Outlook, and Yahoo Mail. Content hidden under `.contentInteractive` is inaccessible on those clients unless a fallback is present — the truncated source prevents confirming fallback state.

**Attribute selector responsive pattern**
Mobile breakpoints use `*[class=contenttable]` (exact-match attribute selectors), a known workaround for older Android 4.x Gmail. No functional issue on current clients, but this is fragile against class concatenation.

**`<title>` trailing whitespace**
`<title>Neiman Marcus </title>` — cosmetic, no client impact.

---

### 4. Personalization & Merge Tokens

**Critical: AMPscript block inside HTML comment will not execute**

```html
<!--/* SET @user = HASHED_EMAIL_SHA256 */-->
```

In Salesforce Marketing Cloud, AMPscript is only processed when wrapped in `%%[ ]%%` delimiters. This line is a plain HTML comment — the AMPscript interpreter ignores it entirely. The surrounding note says "CHOOSE ONE SCENARIO BELOW," implying this is an intentional deployment switch. If this scenario is supposed to be active, `@user` will not be set to `HASHED_EMAIL_SHA256` and any downstream reference to `@user` in this path will resolve to the value from the `Lookup()` call above (email ID from `NM_Subscriber_New_Consolidated`), silently producing wrong data rather than erroring.

**`@refid` no-op concatenation**

```html
@refid = CONCAT(@base_refid,"")
```

Concatenating with an empty string is a no-op. This looks like a template placeholder where a campaign suffix (e.g., `"-A"`, `"_R1"`) was cleared out but the `CONCAT()` wrapper was left. If `@refid` is expected to differ from `@base_refid`, this is broken.

**Variable dependency chain**
`@user`, `@emailid`, `@uEm`, and `@cmdid` all depend on `@email` Lookup calls against two data extensions (`NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`). If either DE is unavailable or the subscriber row is missing, all four variables will be empty with no visible error. No null-guard or default values are declared in the visible header.

---

### 5. Compliance

**List-Unsubscribe header not captured (QA WARN)**
The `List-Unsubscribe` header was absent in the relay-captured headers. This header is required for Gmail's one-click unsubscribe (enforced for bulk senders since 2024) and is strongly expected for CAN-SPAM compliance. This may be a relay capture gap rather than a true absence — but it is unverified.

**List-Unsubscribe-Post header not captured (QA WARN / RFC 8058)**
Required for Gmail and Apple Mail one-click unsubscribe UI. Same caveat as above — relay may not forward it — but must be confirmed present at the MTA level.

**SPF/DKIM/DMARC authentication not captured (QA WARN)**
`Authentication-Results` header absent from relay capture. Cannot confirm SPF pass, DKIM signature validity, or DMARC alignment for `e.neimanmarcus.com`. Given the sender domain is a dedicated ESP subdomain, DKIM is almost certainly present at send time, but this audit cannot confirm it.

---

### 6. Email-to-Site Continuity

**Unverifiable — all 26 links unprobed**
Because all tracked links were skipped by the HTTP prober, UTM parameter presence, correct campaign/source/medium values, and landing page alignment cannot be assessed. No UTM parameters are visible in the raw HTML (they would be embedded in the redirect destination, not the tracking URL itself).
