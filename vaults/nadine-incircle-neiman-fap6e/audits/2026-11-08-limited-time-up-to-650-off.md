## What's working

- The hero offer is unmissable: large "UP TO $650 OFF" type on teal, with the code NOVSAVE directly beneath it.
- The spend/save tier table makes the value concrete and shows what each spend level earns.
- The white SHOP NOW button contrasts strongly against the teal.
- The product grid is clean and consistent, with uniform grey tiles and bold designer names that signal luxury.
- Fine print is complete, and the exclusions are disclosed in full.

## What's weak

- The deadline of 11/14/26 is buried in the fine print, so "Limited time" has no visible urgency.
- The product tiles show no prices, no "after code" pricing and no product-level links that are obvious from the render.
- Six teal category buttons compete with the hero CTA. "SHOP WOMEN'S" and "SHOP WOMEN'S CLOTHING" overlap in meaning.
- The code NOVSAVE is plain text, not a tappable or copyable element, and the first-time reader must remember it through checkout.
- "Up to $650" is a headline for spend of $2,000+, so most shoppers would get $50–$300. The exclusions line also sits in small grey text.

## Recommendations

- 1. Put the end date in the hero: "Ends 11/14" beside or under "LIMITED TIME." This is the single biggest lift for urgency.
- 2. Show "$X after code" pricing on at least a few of the product tiles so the offer connects to specific items.
- 3. Cut the six category buttons to two or three, and remove the duplicate women's button.
- 4. Lead with the mid-tier outcome ("$300 off $1,000") instead of the $650 ceiling to feel more attainable and honest.
- 5. Vary the creative from the earlier sale and gift-card sends so the cadence doesn't feel repetitive.

## Technical Audit

## 1. Technical Summary
The visible HTML head has a few real defects: an ESP template comment leaked into the delivered source, a zoom-blocking viewport, and no `lang` attribute. The automated compliance and authentication warnings come from the relay and can't be confirmed as sender defects. The source is truncated, so the body, links and footer weren't inspected.

## 2. Link & Tracking Issues
- **Not verifiable:** the QA check skipped HTTP probing on 29 tracking links because they are click-redirect domains. Redirect resolution, destination status codes and expiry are untested.
- **Plain-text part:** 5,488 of 6,911 characters (about 79%) are URLs. This is a QA warning and is consistent with long tracking URLs repeated in the text part. It is a possible spam-filter signal, not a confirmed failure.
- The truncated HTML shows no individual `href` values, so I can't comment on link structure or broken links.

## 3. Rendering & Accessibility
- **Viewport blocks zoom:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">`. `maximum-scale=1` limits pinch-zoom and conflicts with WCAG 1.4.4 (Resize Text).
- **No document language:** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang` or `xml:lang`, which screen readers use to pick pronunciation.
- **Comment before the DOCTYPE:** the HTML starts with a `<!-- ... -->` block, then `<!DOCTYPE ...>`. Content ahead of the doctype can trigger quirks mode in some clients.
- **Malformed DTD URL:** the XHTML 1.0 Transitional DOCTYPE points at `https://www.w3.org/TR/xhtml1/DTD/...`, not the standard `http://` identifier. Clients ignore it, so the impact is low.
- **Unclosed meta tags:** the `<meta>` tags aren't self-closed (`<meta http-equiv=... charset=UTF-8">`) under an XHTML doctype. This is a strictness problem only.
- **Fragile mobile selectors:** the mobile CSS uses exact-match attribute selectors such as `*[class=contenttable]`, `*[class=hide]` and `*[class=mobile]`. These stop matching if an element carries more than one class.
- **Checkbox-hack navigation:** the hamburger nav (`.navbar-checkbox:checked~.menu`, `.mobileCont:checked`) relies on `:checked` and sibling selectors. Gmail and several Outlook builds don't support these. The truncated source doesn't show whether a fallback exists.
- **Generic title:** `<title>Neiman Marcus </title>` is generic and has a trailing space. This is minor.

## 4. Personalization & Merge Tokens
- No unresolved tokens appear in the visible, rendered portion of the source.
- The leaked comment names the template variables `@email`, `@base_refid`, `@refid`, `@user`, `@emailid`, `@uEm` and `@cmdid`. It also names the data extensions `NM_Subscriber_New_Consolidated` and `NM_CRM_Feed`. The comment is inert, but it shows the personalization lookups and `uEm`/`cmdid` identifiers. Whether they populate correctly can't be checked from the truncated source.
- The comment's `Lookup(...)` calls have unbalanced parentheses (`@user Lookup(...))`). That is harmless in a comment, but it shows the template was not cleaned up.

## 5. Compliance
- **List-Unsubscribe:** QA found no header. QA itself notes the AgentMail relay may strip it, so this is not a confirmed defect. Check the raw message from the sending ESP.
- **List-Unsubscribe-Post (RFC 8058):** not found, with the same caveat. One-click unsubscribe is required by Gmail and Yahoo for bulk senders.
- **Authentication-Results:** absent, which is expected via the relay. SPF, DKIM and DMARC alignment are unknown. The From domain `e.neimanmarcus.com` is a branded subdomain, which is a good sign but isn't proof.
- **Footer:** the in-body unsubscribe link and the physical postal address aren't visible in the truncated HTML, so they can't be verified.

## 6. Email-to-Site Continuity
- No UTM parameters or landing URLs are visible in the truncated source, so I can't assess them.
- The template comment shows a `@refid` built from `@base_refid`. This suggests campaign tracking uses a refid parameter instead of UTMs. Confirm that against the real hrefs.

## 7. Recommendations
1. Strip the ESP template comment (variable and data-extension names) from the delivered HTML. It leaks internal structure and sits before the DOCTYPE.
2. Change the viewport to `width=device-width, initial-scale=1` so users can zoom.
3. Add `lang="en"` (and `xml:lang`) to `<html>`.
4. Fix the DOCTYPE system identifier and self-close the `<meta>` tags, or move to HTML5.
5. Replace `[class=x]` exact-match selectors with `[class~=x]` or plain class selectors, and confirm the checkbox-hack nav has a fallback for Gmail and Outlook.
6. Re-run QA against the raw ESP message, not the relay copy. That will confirm `List-Unsubscribe`, `List-Unsubscribe-Post` and the SPF/DKIM/DMARC results.
7. Shorten the plain-text part's URL load, or make sure it carries enough readable copy relative to the tracking URLs.
8. Re-run the audit on the full HTML and use a redirect-aware link probe on the 29 tracking links, to cover links, UTMs and footer compliance.
