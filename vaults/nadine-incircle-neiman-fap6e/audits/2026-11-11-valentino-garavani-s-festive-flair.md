## Technical Audit

## 1. Technical Summary
The visible HTML source has an exposed Salesforce Marketing Cloud template comment before the DOCTYPE and a few accessibility gaps (no `lang`, zoom disabled). The QA warnings on headers and link probing are mostly capture limits of the AgentMail relay. The HTML is truncated, so the body (links, images, footer) could not be audited.

## 2. Link & Tracking Issues
- **Not verifiable:** 17 tracking links were skipped because they are click-redirect domains. Final destinations and redirect health are unconfirmed.
- **Plain-text part:** QA reports 3169 of 3661 characters (about 87%) are URLs. This is typical of tracked links printed in full. It is a deliverability warning, not a broken link.
- No broken links were confirmed.

## 3. Rendering & Accessibility
- **Zoom disabled:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">`. `maximum-scale=1` blocks pinch-zoom in clients that honor it, which is a WCAG 1.4.4 concern.
- **No document language:** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang` attribute. Screen readers will fall back to the default language.
- **Weak title:** `<title>Neiman Marcus </title>` has a trailing space and doesn't describe the email.
- **Checkbox hamburger nav:** The mobile menu uses `.navbar-checkbox:checked~.menu` (the CSS checkbox hack) and a `-webkit-animation: bugfix` hack. This is unsupported in Gmail and many Android clients, and not keyboard-accessible. Whether a fallback nav exists can't be confirmed from the truncated source.
- **Class selectors:** `*[class=contenttable]` and similar match only an exact class string. An element with multiple classes won't match, so the mobile overrides may fail silently.
- **Minor CSS:** `.show` declares `width` twice (`auto !important` and `278px`).
- **Not verifiable:** image `alt` text, image dimensions and the layout tables are outside the truncated source.

## 4. Personalization & Merge Tokens
- **Template comment in production HTML:** The source begins with `<!--REQUIRED variables: @email ... @base_refid ... @uEm = Lookup("NM_CRM_Feed", "uEm", "EMAIL_ADDRESS", @email)) @cmdid ... CHOOSE ONE SCENARIO BELOW --> <!--/* SET @user = HASHED_EMAIL_SHA256 */ -->`.
  - It sits before `<!DOCTYPE>`, which can trigger quirks mode in some clients.
  - It exposes internal Data Extension names (`NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`) and field names (`EMAIL_ID`, `uEm`, `cmdid`).
  - It includes an unfinished instruction ("CHOOSE ONE SCENARIO BELOW"), which suggests the template wasn't cleaned before send.
- No unresolved `%%…%%` or `@var` tokens were confirmed in the visible body. The footer and links are not visible.

## 5. Compliance
- **`List-Unsubscribe` not found:** The QA tool notes the relay may not capture it, so this is unconfirmed.
- **`List-Unsubscribe-Post` not found (RFC 8058):** This is also possibly a relay artifact. Gmail and Yahoo bulk-sender rules require one-click unsubscribe, so it should be checked against the raw message.
- **`Authentication-Results` not found:** SPF, DKIM and DMARC status is unknown. The sending domain `e.neimanmarcus.com` is a dedicated subdomain.
- **Not verifiable:** the unsubscribe link and the physical postal address in the footer are outside the truncated source.

## 6. Email-to-Site Continuity
Not assessable. The 17 tracking links were not resolved, so UTM parameters, landing-page alignment and the `refid` from the template comment can't be checked.

## 7. Recommendations
1. Remove the SFMC variable-declaration comment from the rendered output, or at minimum move it after the DOCTYPE. Don't expose DE names.
2. Remove `maximum-scale=1`, add `lang="en"` to `<html>` and give `<title>` a meaningful value.
3. Check the raw `.eml` from the sending side for `List-Unsubscribe`, `List-Unsubscribe-Post: List-Unsubscribe=One-Click` and SPF/DKIM/DMARC alignment. If they are present, mark the QA warnings as relay artifacts.
4. Provide a fallback for the checkbox-hack nav, such as a static link row, for clients that strip it.
5. Use `[class~=…]` or plain class selectors so the mobile overrides still apply when elements carry multiple classes.
6. Re-run the audit with the full HTML and a redirect-following probe of the tracked links to check final URLs and UTMs.
