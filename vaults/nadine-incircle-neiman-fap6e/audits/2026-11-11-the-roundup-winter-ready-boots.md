## Technical Audit

## 1. Technical Summary
The visible HTML is a table-based XHTML 1.0 Transitional email, apparently built in Salesforce Marketing Cloud (SFMC). The source was truncated, so most body-level checks (alt text, unsubscribe link, UTMs) could not be confirmed. The QA run's four warnings are all header or relay artifacts rather than confirmed defects.

## 2. Link & Tracking Issues
- 16 tracking/click-redirect links were skipped by the QA probe, so none were validated. Destination resolution, expiry and redirect chains are **unverified**.
- The plain-text part is 2984/3486 characters (about 86%) URLs. That is a real structural problem: the text alternative is mostly raw tracking URLs, and a ratio like this can add spam-filter weight. It is probably a template or auto-generated text part.
- No broken links were confirmed.

## 3. Rendering & Accessibility
- `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` caps zoom at 1x. That blocks pinch-zoom and is a WCAG 1.4.4 resize-text concern.
- The mobile rules use exact-match attribute selectors such as `*[class=contenttable]`, `*[class=mobile]` and `*[class=hide]`. They only match when `class` is that exact value, so any element with multiple classes will silently miss the responsive rules.
- The hamburger nav depends on `:checked` sibling selectors (`.navbar-checkbox:checked~.menu`). Gmail and several Outlook clients strip or ignore this, so the nav likely has no mobile fallback there. This is inferred from the CSS and not tested.
- `<title>Neiman Marcus </title>` is generic and has a trailing space. It is minor.
- The XHTML DOCTYPE is declared with an `https://` DTD URL. That is harmless, but it is a non-canonical identifier.
- Alt text, `role="presentation"` on layout tables, `lang` and color contrast **could not be assessed** because the source was truncated. The `<html>` tag shown has no `lang` attribute.

## 4. Personalization & Merge Tokens
- The source opens with a leaked, unrendered developer comment. It contains SFMC variable definitions and internal Data Extension names (`NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`) and field names (`EMAIL_ID`, `EMAIL_ADDRESS`, `uEm`, `cmdid`). It also contains the line `CHOOSE ONE SCENARIO BELOW`.
- This is template scaffolding that shipped to recipients. It exposes internal schema naming and bloats the payload.
- I saw no unresolved `%%…%%` or `{{…}}` tokens in the visible portion.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- `List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) were not found. The QA note says the AgentMail relay may strip them, so this is **unconfirmed**. Verify against the original raw message at the sender. Gmail and Yahoo bulk-sender rules require one-click unsubscribe.
- `Authentication-Results` was not found. This is expected through the relay, so SPF, DKIM and DMARC are **unknown**. Nothing indicates a failure.
- The visible HTML did not include the footer, so I could not confirm the physical postal address or the in-body unsubscribe link.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not assessable. The visible HTML contains no resolved destination URLs, and the 16 tracking links were not probed. The `@refid` / `@base_refid` variables in the header comment suggest campaign attribution is carried through a refid parameter and not UTMs. That is inferred and not confirmed.

## 7. Recommendations
1. Strip the SFMC variable and scenario comment block from the production template, using SFMC `<!--- --->` / AMPscript comments or a build-step minifier, so it is not delivered.
2. Fix the text part. Generate a proper plain-text alternative with readable copy and fewer raw tracking URLs.
3. Remove `maximum-scale=1` from the viewport meta tag.
4. Use `[class~=...]` or `[class*=...]` selectors, or inline responsive hooks, so multi-class elements still match. Provide a non-checkbox fallback for the nav.
5. Re-run the QA on the raw `.eml` from a seed inbox to confirm `List-Unsubscribe`, `List-Unsubscribe-Post` and SPF/DKIM/DMARC. Also resolve the 16 tracking links manually or with an allowlisted probe, and re-audit with the full, untruncated HTML.
