# Technical Audit: Neiman Marcus, "Rag & Bone's fall inspiration"

## 1. Technical Summary
The HTML is a table-based SFMC template with a hamburger-nav checkbox hack. The QA run found 0 hard failures and 4 warnings, all of them header or link-verification gaps. Two source-level issues are confirmed: pinch-zoom is disabled, and the top of the markup exposes internal template documentation.

## 2. Link & Tracking Issues
- **Unverified:** 16 tracking links were skipped by the probe ("Tracking/click-redirect domains — skipped HTTP probe"). Redirect health, final destinations and 404s are unknown.
- **Plain-text part:** 2820 of 3307 characters (about 85%) are URLs, against the 70% warning threshold. This is likely long tracking URLs in the text alternative. It is a mild spam-filter and readability risk.
- The truncated source doesn't show any broken or malformed `href` values.

## 3. Rendering & Accessibility
- **Zoom disabled:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` blocks pinch-zoom on mobile. This is a WCAG 1.4.4 concern.
- **Missing language attribute:** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang`, which hurts screen-reader pronunciation.
- **Checkbox-hack nav:** the mobile menu uses `.navbar-checkbox:checked~.menu` with `display:none` defaults. Gmail app, Outlook and some webmail clients don't support `:checked`, so the nav is inert or hidden there. Whether a fallback exists can't be confirmed from the truncated source.
- **Fragile selectors:** the media queries use exact-match `*[class=contenttable]`, `*[class=mobile]` and `*[class=hide]`. These stop matching if an element carries more than one class, and Gmail's class handling is unreliable. Any element with a combined class would not get its responsive rule.
- **Legacy CSS:** `.ReadMsgBody` and `.ExternalClass` are legacy, and `-webkit-animation: bugfix` is an iOS9 workaround. All of it is dead weight.
- **Generic title:** `<title>Neiman Marcus </title>` is generic and has a trailing space. This is minor.
- **Unverified:** image alt text and image-to-text ratio can't be assessed because the source is truncated.

## 4. Personalization & Merge Tokens
- **Exposed template docs:** the block before `<!DOCTYPE>` lists internal SFMC data-extension names (`NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`) and lookup fields (`EMAIL_ID`, `uEm`, `cmdid`). It also says "CHOOSE ONE SCENARIO BELOW", plus a commented-out `SET @user = HASHED_EMAIL_SHA256`. It is inside an HTML comment, so it doesn't render, but it ships to every recipient and leaks internal schema.
- **Doctype placement:** a comment before the doctype is harmless in most clients. It can push some legacy renderers into quirks mode.
- No unresolved visible tokens (`%%…%%`, `{{…}}`) appear in the visible portion of the source.

## 5. Compliance
- **[WARN] List-Unsubscribe header not found.** The QA note says the AgentMail relay may not capture it. That is unconfirmed, and the header may exist at origin.
- **[WARN] List-Unsubscribe-Post (RFC 8058) not found.** One-click unsubscribe support is unverified. Gmail and Yahoo require it for bulk senders.
- **[WARN] Authentication-Results not found.** SPF, DKIM and DMARC status is unknown. The sender uses the `e.neimanmarcus.com` subdomain, which is a good sign but not proof of alignment.
- The footer's physical address and unsubscribe link were not visible in the truncated source, so they can't be confirmed.

## 6. Email-to-Site Continuity
- **Unverified:** no UTM parameters or landing URLs are visible in the truncated source. The 16 tracking links were not resolved, so campaign parameters and landing-page alignment can't be assessed.
- The template's `@refid` and `@base_refid` variables suggest ref-ID tagging, but the final URLs were not seen.

## 7. Recommendations

2. Add `lang="en"` to `<html>`.
3. Strip the internal SFMC documentation comment and dead commented-out viewport tags at send time. Move them to template docs outside the delivered markup.
