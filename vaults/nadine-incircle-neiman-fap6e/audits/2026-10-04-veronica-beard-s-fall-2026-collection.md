## 2. Link & Tracking Issues

- **Plain-text part is mostly URLs.** 2995 of 3487 characters are URLs (`[WARN] Plain-text is >70% URLs`). This is a spam-filter risk and makes the text part hard to read. It points to long tracked URLs in the text alternative, though the source doesn't show how the text part is built.
- No other link defects can be confirmed from the truncated source.

## 3. Rendering & Accessibility
- **Content before the DOCTYPE.** A large HTML comment sits ahead of `<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Transitional//EN" ...>`. Content before the doctype can trigger quirks mode in some clients, notably older Outlook and some webmail.
- **Zoom is blocked.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` sets `maximum-scale=1`, which prevents pinch-zoom on mobile. This is a WCAG 1.4.4 resize-text concern.
- **CSS-only hamburger menu.** The nav uses the `.navbar-checkbox:checked~.menu` hack inside `@media (max-width:600px)`. Gmail and some other clients strip or ignore `:checked`, so the menu may not open. The `.menu` rule also sets `display:none` and `visibility:hidden`, and nothing in the visible source provides a fallback.
- **Exact-match class selectors.** The mobile rules use `*[class=contenttable]`, `*[class=mobile]` and similar. These only match when `class` is exactly that value, so an element with a second class won't pick up the responsive styles. I can't confirm any such elements in the truncated markup.
- **Missing alt text, `lang`, and `role="presentation"`.** Not verifiable from the visible portion. `<html xmlns=...>` has no `lang` attribute, and `<title>Neiman Marcus </title>` has a trailing space.

## 4. Personalization & Merge Tokens
- **Template internals exposed in the delivered source.** The opening comment documents ESP variables (`@email`, `@base_refid`, `@refid`, `@emailid`, `@uEm`, `@cmdid`). It also names the internal data extensions and fields `NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`, `EMAIL_ID` and `EMAIL_ADDRESS`. It includes `/* SET @user = HASHED_EMAIL_SHA256 */` and the line "CHOOSE ONE SCENARIO BELOW", meaning an unused scenario selector was left in. The comment text itself suggests a `Lookup()` that returns `EMAIL_ID` populates `@user` (a hashed-email scenario is also mentioned). Anyone viewing source can read these names, so this is information disclosure. It also suggests a build step that failed to strip authoring comments.
- No unresolved merge tokens (`%%...%%`, `{{...}}`) appear in the visible portion.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` header not found.** QA notes it may not be captured by the AgentMail relay, so this is unconfirmed rather than proven missing.
- **`List-Unsubscribe-Post` header not found.** Without it, RFC 8058 one-click unsubscribe isn't confirmed. Gmail and Yahoo require it for bulk senders. The same relay caveat applies.
- **`Authentication-Results` not found.** SPF, DKIM, and DMARC alignment are unknown. The sender is `NeimanMarcus@e.neimanmarcus.com`, a subdomain, so alignment should be checked at the source rather than through the relay.
- **Footer unreviewed.** The physical postal address and in-body unsubscribe link are in the truncated portion, so they can't be confirmed.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not verifiable. The 17 tracked links weren't resolved, and no final URLs or UTM parameters are visible in the truncated source. The `@refid` and `@base_refid` variables in the header comment suggest campaign attribution is carried in the redirect rather than in visible UTMs, but this is an inference.

## 7. Recommendations
1. **Strip authoring comments at build or send time.** Remove the `<!--REQUIRED variables ...-->` block, the `SET @user` comment, and the scenario selector. Move the `<!DOCTYPE>` to the first line of the document.
2. **Remove `maximum-scale=1`** from the viewport meta tag.
3. **Make the hamburger menu degrade gracefully.** Give clients without `:checked` support an always-visible linked nav fallback.
4. **Verify the headers at the source.** Check `List-Unsubscribe` and `List-Unsubscribe-Post` (with `List-Unsubscribe=One-Click`) on the raw message, plus SPF, DKIM, and DMARC for `e.neimanmarcus.com`. Use a seed-list test or raw headers rather than the relay copy.
5. **Rebuild the plain-text part** with fewer and shorter URLs, using one link per CTA.
6. **Re-run QA on the full HTML** and with the click-redirect probe enabled, to cover the 17 skipped links, UTM and refid mapping, alt text, and the footer address and unsubscribe link.
