# Last chance: Your 15% offer expires soon!​
**Score:** 7/10 · **Type:** Email audit · **2026-05-23**
## Executive summary

- This is a triggered activation email — the promo code prefix "NMWELC" and the "LOOK FORWARD TO:" section about personalization benefits give it away as a welcome or re-engagement send, not a broadcast promo. That context matters: a 15% welcome offer is a reasonable hook, and the "Going, Going, Gone…" headline borrows urgency from the subject line cleanly. The design is minimal and on-brand — black nav bar, warm hero image of what appears to be a luxury shoe or bag, clean serif headline, one button.
- The email's structural weakness is the promo code itself: `NMWELC-4YDZ-RGS0SNW` is 20 characters long. If it doesn't auto-apply on click, a meaningful fraction of recipients will abandon at checkout. The CTA sends you to general shopping rather than a pre-filtered category, which dilutes the urgency of "last chance" — you land somewhere generic when the subject implied you were racing the clock.
- Against the recent NM cadence (a near-daily stream of Designer Sale emails plus a spend-to-save send on 5/22), this email is the cleanest break in pattern this week. It should stand out in the inbox — but "expires soon" without a visible specific deadline is a missed conversion lever.

## What's working

- **Concrete percentage** — 15% off is specific; it anchors expectations better than vague "savings" language.
- **Single CTA discipline** — one button, one job; no competing links in the hero.
- **"LOOK FORWARD TO:" section** — frames the subscription itself as valuable (personalization, arrivals alerts, style advisor), turning an expiring offer email into a brand-value pitch.
- **On-brand visual hierarchy** — serif headline → offer → code → button reads cleanly; no clutter in the hero zone.
- **Subject breaks the recent pattern** — after five Designer Sale emails and a spend-to-save send, a personal 15% expiring offer is genuinely different and should earn an above-average open rate.

## What's weak

- **Promo code is unwieldy** — `NMWELC-4YDZ-RGS0SNW` is 20 characters; if it requires manual entry, checkout abandonment will spike.
- **"START SHOPPING" is too generic** — for a "last chance" send, the button should surface a specific category or entry point (shoes, new arrivals, etc.).
- **No deadline specificity** — "expires soon" in subject and hero copy, but no date or time visible in the body. That vagueness undercuts the urgency signal.
- **Hero image is ambiguous** — the warm amber product shot is attractive but indistinct at email render size; it doesn't anchor the shopper in a specific category they want to click into.
- **"LOOK FORWARD TO:" competes with conversion** — surfacing app downloads and style advisor below the fold is smart long-term brand-building, but on a last-chance expiring offer it introduces decision friction before the click.

## Recommendations

- 1. **Make the deadline concrete** — replace "expires soon" everywhere with the actual end date/time. "Offer ends Sunday at midnight" is a click driver; "expires soon" is background noise.
- 2. **Auto-apply the code on click** — if this isn't already wired, it should be. Long manual codes kill conversion. CTA should read "APPLY MY 15% + SHOP" and pre-load the discount.
- 3. **Replace "START SHOPPING" with a category CTA** — "SHOP SHOES" or "SHOP NEW ARRIVALS" routes the opener into a funnel rather than a homepage.
- 4. **Sharpen the hero image** — show one clearly identifiable product with a price point (e.g., "$895 → $761 with your offer") to make the savings feel real and tangible.
- 5. **Move "LOOK FORWARD TO:" to a separate welcome email** — it belongs in an onboarding sequence, not a last-chance conversion email.
- **Subject Alt A:** `Your 15% off ends Sunday — don't leave it behind`
- **Subject Alt B:** `Going, going… your 15% expires at midnight`
- **Preheader Alt A:** `Code auto-applies at checkout. Shop shoes, bags, and more before it's gone.`
- **Preheader Alt B:** `Shop the brands you love — your welcome offer expires in 24 hours.`

## Technical Audit

## Technical Audit — Neiman Marcus "Last chance: 15% offer" Email

### 1. Technical Summary

The email is a Salesforce Marketing Cloud (SFMC) AMPscript template with a CSS-only hamburger nav and interactive product tabs. Three infrastructure-level warnings surfaced in QA (missing unsubscribe headers, unknown authentication state), and the HTML contains a nested media query bug and AMPscript variables that may not execute.

---

### 2. Link & Tracking Issues

**36 click-redirect links skipped by QA probe** — all route through `e.neimanmarcus.com` click-tracking redirects. Because the probe cannot follow them, the following cannot be confirmed automatically:
- Whether UTM parameters survive the redirect chain
- Whether final landing URLs are live and correctly targeted

**Zero-width space in subject line** — the subject `Last chance: Your 15% offer expires soon!​` contains a `&#8203;` (U+200B zero-width space) appended after the `!`. This is a known ESP deduplication-bypass trick but can surface as a rendering artifact in plain-text fallback or preview snippets in some clients.

---

### 3. Rendering & Accessibility

**Nested media query — invalid CSS** (`<style>` block 2, lines ~2–15 of second block):
```css
@media only screen and (max-device-width: 480px), screen and (max-width: 480px) {
  /* … */
  @media only screen and (max-device-width: 520px), screen and (max-width: 520px) {
    .ImgSize2x2 { max-width: 160px !important; … }
```
Media queries cannot be nested in standard CSS. The 520px ruleset will be silently ignored in most email clients. The 2×2 grid layout (`.ImgSize2x2`) will not collapse correctly on narrow screens.

**`max-device-width` is deprecated** — both media queries use `max-device-width` alongside `max-width`. While the `max-width` fallback covers modern clients, `max-device-width` is obsolete (removed from the CSS spec). No practical breakage today, but indicates aging template code.

**Three commented-out viewport meta tags** in `<head>`:
```html
<!--<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" />-->
<!--<meta name="viewport" content="width=320, initial-scale=0.29">-->
<!--<meta name="viewport" content="width=1024">-->
```
These are dead code from prior viewport experiments. No functional impact, but they inflate template size and create maintenance confusion.

**CSS-only interactive content** (`.contentInteractive` / checkbox hack hamburger nav) — these patterns work only in clients that support `:checked` pseudo-class on `<input>` (primarily Apple Mail, iOS Mail). Gmail, Outlook, and most web clients will silently fall back to the non-interactive state. This is by design for email, but the fallback path should be confirmed to render correctly in those clients.

**`<title>` tag trailing space** — `<title>Neiman Marcus </title>` — minor, cosmetic, but surfaces in browser tab previews if the email is opened in a web version.

---

### 4. Personalization & Merge Tokens

**AMPscript variable block is inside an HTML comment** — the template opens with:
```html
<!--REQUIRED variables: @email … @user … @emailid … -->
<!--/* SET @user = HASHED_EMAIL_SHA256 */ -->
```
AMPscript inside HTML comments (`<!-- %%[ ]%% -->` or `<!--/* */-->`) **does not execute** in SFMC. If the actual AMPscript initialization blocks are not present elsewhere in the template (outside comments, before the DOCTYPE or in `%%[ ]%%` blocks), all variables (`@user`, `@refid`, `@emailid`) will be null at send time.

**"CHOOSE ONE SCENARIO BELOW" instruction** — the comment indicates the template requires a manual scenario selection before deployment. This is a human-error risk: no programmatic guard prevents sending without selecting the correct scenario.

**`@refid = CONCAT(@base_refid, "")` is a no-op** — concatenating with an empty string adds no value and suggests this line was simplified from a prior concatenation (e.g., appending a suffix). If a suffix was intentionally removed, this line should be `SET @refid = @base_refid` for clarity.
