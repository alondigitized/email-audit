# Join InCircle & unlock benefits as you shop​
**Score:** 8/10 · **Type:** Email audit · **2026-05-19**
## Executive summary

- This is a loyalty program / credit card recruitment email — NM is pitching the InCircle value stack to non-members (and under-engaged members) with no deadline and no joining incentive. The design is clean, the four-panel benefit grid is well organized, and the brand voice is consistent. It does the basics right.
- The problem is context and timing. This lands the morning after "It's here! The Designer Sale" (10/10 by yesterday's audit) and a new arrivals editorial — both high-urgency, high-energy sends. Going from "UP TO 50% OFF / shop the sale" to "apply for a credit card to maybe earn benefits later" is a jarring gear-shift. The subscriber's attention budget is already taxed; this email demands a bigger commitment (credit application) while offering zero reason to act today instead of next week.
- The email functions as a well-produced brochure. It would score higher if it tied the InCircle pitch to the active sale ("earn points while you shop the Designer Sale") or added a short-window joining incentive. Without that, it's a competent pitch that will be scrolled past.

## What's working

- **Concrete benefit language.** "$100 Point Card for every 10,000 points" is a calculable number — more credible than vague "exclusive savings" copy.
- **Clean four-panel benefit grid.** Points → Shipping → Perk Cards → Concierge is a logical stack that builds perceived value progressively.
- **Strong hero visual.** Red-dress model against white space lands the luxury positioning immediately and matches NM brand codes.
- **Both audiences served.** The "Already an InCircle Member?" section with a Sign In CTA prevents alienating current members who receive this.

## What's weak

- **No urgency, no joining hook.** Zero deadline, zero limited-time incentive. Applying for a credit card is a high-friction ask without a reason to act today.
- **Credit card requirement is buried.** The subject and hero don't surface the NM/BG credit card requirement — subscribers expecting a free loyalty sign-up will hit friction on the application page.
- **"Circle 3 & Above" gates three of four benefits.** That qualifier appears on Points, Shipping, AND Perk Cards — the email is pitching perks that new applicants likely won't access for a long time. It undercuts the sell.
- **"Discover More" is a dead CTA.** No destination signal, no verb-noun action. A cold reader has no reason to click it over the "Apply Now" button above it.
- **Sixth email in four days.** The cadence from this brand (see history: 05-16, 05-17×2, 05-18×2, now 05-19) is aggressive. Engagement on this send will be depressed.

## Recommendations

- 1. **Add a joining incentive to the hero.** This is the single highest-leverage change. "Join InCircle now and earn double points on your first purchase through May 25" creates urgency and anchors the credit application to an immediate payoff — rather than a vague future reward stack.
- 2. **Surface the credit card requirement in the subject or hero subhead.** "Apply for the Neiman Marcus Credit Card and unlock..." sets accurate expectations before the click. Burying it creates post-click drop-off.
- 3. **Move "Circle 3 & Above" to a footnote.** Let the benefits land first. The tier gate mid-panel deflates the pitch at the worst possible moment — mid-consideration.
- 4. **Replace "Discover More" with a specific destination.** "Explore All Circle Tiers" or "See How Points Add Up" tells the reader exactly what's behind the button.
- 5. **Tie this email to the active Designer Sale.** Yesterday's sale email is live right now. "Shop the Designer Sale — and every purchase builds toward your first $100 Point Card" makes InCircle immediately relevant instead of abstract.
- **Subject Alt A:** `Your next NM purchase could earn you $100 back`
- **Subject Alt B:** `InCircle members earn on every purchase — are you in?`
- **Preheader Alt A:** `Free 2-day shipping, $100 Point Cards, and Concierge access — here's what you're missing`
- **Preheader Alt B:** `For every 10,000 points you earn, get $100 toward your next purchase`

## Technical Audit — Neiman Marcus "Join InCircle" Email

Three automated QA warnings require action: missing compliance headers (likely a relay capture gap), unverified authentication, and 36 unprobed tracking links. Several in-source code issues also need cleanup.

---

### 3. Rendering & Accessibility

**Nested `@media` block (invalid CSS):**
```css
@media only screen and (max-device-width: 480px), screen and (max-width: 480px) {
  ...
  @media only screen and (max-device-width: 520px), screen and (max-width: 520px) { /* ← nested, invalid */
```
CSS does not allow `@media` nested inside another `@media` in non-preprocessor contexts. The 520px breakpoint rules (`.ImgSize2x2`, `.TxtSize2x2`) will be silently ignored in most email clients.

**Dead commented-out viewport tags (3 variants):**
```html
<!--<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" />-->
<!--<meta name="viewport" content="width=320, initial-scale=0.29">-->
<!--<meta name="viewport" content="width=1024">-->
```
Template hygiene issue; harmless but indicates the active viewport was never confirmed and old candidates were left in place.

**`'sans-serif'` quoted in `.disclaimerText`:**
```css
font-family: Arial, Helvetica, 'sans-serif';
```
Quoting `sans-serif` makes it a literal named-font lookup, not the CSS generic fallback. If Arial and Helvetica both fail, no system fallback is applied. Should be unquoted.

**Trailing whitespace in `<title>`:**
```html
<title>Neiman Marcus </title>
```
Minor; no rendering impact but indicates template wasn't finalized/linted.

---

### 4. Personalization & Merge Tokens

**Unresolved scenario selector:**
```html
<!--/* SET @user = HASHED_EMAIL_SHA256 */-->
```
The comment block instructs senders to "CHOOSE ONE SCENARIO BELOW" but the SHA256 scenario is commented out. The active `@user` value is the `EMAIL_ID` lookup from `NM_Subscriber_New_Consolidated`. If the intended data flow requires a hashed email (e.g., for ad matching or analytics), the wrong identifier is being passed.

**AMPscript setup comments exposed in production HTML:**
```html
<!--REQUIRED variables: @email ... @base_refid (from Campaign Calendar) @refid = CONCAT(@base_refid,"") ...-->
```
These comments expose internal data extension names (`NM_Subscriber_New_Consolidated`) and variable scaffolding in the delivered HTML. Not a critical security issue for a marketing email, but it leaks infrastructure detail to anyone viewing source.

**`@refid` concatenation is a no-op:**
```ampscript
@refid = CONCAT(@base_refid,"")
```
Concatenating with an empty string is a no-op. If `@base_refid` is unpopulated, `@refid` silently becomes an empty string with no error, causing tracking/attribution to break without alerting the sender.
