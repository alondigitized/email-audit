## Technical Audit

## 1. Technical Summary
The visible HTML source is a table-based XHTML Transitional template with several robustness and hygiene issues. These are an exposed ESP variable comment, a zoom-restricting viewport, and a mobile nav that relies on the checkbox hack. The source is truncated and 15 tracking links were not probed, so the link, UTM, and personalization checks are mostly unverifiable.

## 2. Link & Tracking Issues
- **No confirmed broken links.** QA reports 0 issues.
- **Tracking links not validated.** `[WARN] 15 tracking link(s) skipped` because they are click-redirect domains. Their destinations, status codes, and redirect chains are unverified.
- **Plain-text part is mostly URLs.** `[WARN] 2619/3120 chars are URLs` (about 84%). A plain-text alternative exists, but it is dominated by long tracking URLs. That raises spam-filter risk and makes the text part hard to read.

## 3. Rendering & Accessibility
- **Zoom is restricted.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` blocks pinch-zoom on clients that honor it, such as Android webviews. That is a WCAG 1.4.4 concern.
- **Mobile nav is brittle.** The hamburger menu uses the checkbox hack (`*[class].navbar-checkbox:checked~*[class].menu`), with `.menu` set to `display:none` and `visibility:hidden` by default.
  - Gmail and Outlook do not support `:checked`, so mobile users there likely get no navigation.
  - I couldn't see the markup to confirm a fallback.
- **Class selectors are exact-match.** `*[class=contenttable]`, `*[class=mobile]`, and `*[class=hide]` only match when the class attribute is exactly that value. Any element with a second class silently loses its responsive rules.
- **Global `p` rule can bleed.** `p { margin: 0 auto; text-align: center; }` applies to every paragraph. Any paragraph that doesn't override alignment inherits center.
- **Doctype is out of order.** The ESP comment precedes `<!DOCTYPE>`, and the DTD URL uses `https://www.w3.org/TR/xhtml1/...`. Neither is harmful in modern clients, but both are non-standard.
- **Title is not descriptive.** `<title>Neiman Marcus </title>` has a trailing space and doesn't reflect the campaign.
- **Alt text is unverified.** The source was truncated before the images, so I can't confirm alt text.

## 4. Personalization & Merge Tokens
- **No unresolved tokens in the visible markup.** The only token-like text is inside the leading HTML comment.
- **Internal ESP logic is exposed.** That comment ships in the delivered HTML. It reveals Salesforce Marketing Cloud-style variable names (`@email`, `@refid`, `@uEm`, `@cmdid`, `@user`) and Data Extension names (`NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`). It also contains template instructions ("CHOOSE ONE SCENARIO BELOW") and a commented-out scenario (`SET @user = HASHED_EMAIL_SHA256`). This is an information leak and a sign the template wasn't cleaned before send.
- **Body personalization is unverifiable** because the source is truncated.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- `[WARN] List-Unsubscribe header not found` and `[WARN] List-Unsubscribe-Post header not found (RFC 8058)`. QA notes the AgentMail relay may strip these, so absence is not confirmed on the sender side.
- `[WARN] Authentication-Results header not found`. SPF, DKIM, and DMARC status is unknown for the same relay reason. The sender domain is `e.neimanmarcus.com`, a dedicated subdomain.
- The footer unsubscribe link and physical address were not in the truncated source, so I can't confirm them.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not assessable. No hrefs appear in the truncated source, and the 15 tracking links were not resolved. The `@refid` / `@base_refid` variables suggest campaign attribution via a ref ID rather than UTM parameters. That is unconfirmed.

## 7. Recommendations
1. Strip the pre-DOCTYPE ESP comment from the production render. It exposes DE names and lookup logic.
2. Remove `maximum-scale=1` from the viewport meta.
3. Provide a non-`:checked` mobile nav fallback, such as a plain link row or a "Shop" link to the site menu. Verify it in Gmail and Outlook.
4. Use `[class~=...]` selectors, or single-purpose classes, so responsive rules survive additional classes.
5. Scope the global `p` rule, and set a meaningful `<title>`.
6. Shorten the tracking URLs in the plain-text part, or reduce the link count, to improve the text-to-URL ratio.
7. Verify the `List-Unsubscribe` and `List-Unsubscribe-Post` headers and SPF/DKIM/DMARC against the raw message at the sender, not through the relay. Then resolve the 15 tracking links and check their UTM/ref parameters and landing pages.
