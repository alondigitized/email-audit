## Technical Audit

## 1. Technical Summary
The visible HTML source shows a table-based XHTML 1.0 Transitional template with a CSS-checkbox hamburger menu. It has two real code-level issues: internal Salesforce Marketing Cloud (SFMC) variable documentation left in the delivered HTML, and a viewport meta tag that blocks pinch-zoom. The source is truncated and the automated checks are limited by the AgentMail relay, so the link, header and compliance findings below are mostly unverified, not confirmed defects.

## 2. Link & Tracking Issues
- **No confirmed broken links.** The QA run skipped 16 tracking links because they are click-redirect domains, so none were probed. Destination validity, redirect chains and final landing URLs are unverified.
- **Plain text is URL-heavy.** The check reports 3012 of 3500 characters (about 86%) as URLs, which fails the >70% threshold. Long tracked URLs in the text part inflate this ratio and can raise spam-filter scoring. This is a WARN, not a confirmed defect.

## 3. Rendering & Accessibility
- **Zoom is restricted.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">` blocks pinch-zoom, which conflicts with WCAG 1.4.4 (Resize Text).
- **No language attribute.** The `<html xmlns="http://www.w3.org/1999/xhtml">` tag has no `lang`, so screen readers can't pick the right pronunciation rules.
- **Weak title.** `<title>Neiman Marcus </title>` is generic and has trailing whitespace. It doesn't identify the email, though it's low impact.
- **Fragile mobile selectors.** The mobile CSS uses exact-match attribute selectors such as `*[class=contenttable]`, `*[class=mobile]` and `*[class=hide]`. These stop matching if an element carries more than one class.
- **Hamburger nav depends on `:checked`.** The `.navbar-checkbox:checked~.menu` pattern is unsupported in Gmail and in many Outlook builds. The visible source doesn't show a fallback, so mobile navigation may be inaccessible in those clients.
- **Not verifiable.** Alt text, image dimensions and role attributes fall in the truncated portion of the source.

## 4. Personalization & Merge Tokens
- **Template documentation is leaking.** The opening HTML comment is delivered to every recipient. It contains the SFMC variable list and internal Data Extension names: `NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`, and the fields `EMAIL_ID`, `uEm` and `cmdid`. It also contains `@user Lookup(...))`, which has unbalanced parentheses and is a sign of copy-paste drift in the template. This isn't a rendering error, but it exposes internal data-model names and should be stripped before send.
- **Unresolved tokens: none found.** There are no visible unrendered `%%...%%` or `@var` tokens in the rendered portion, though the source is truncated.
- **Identifier exposure is unconfirmed.** The comment references `HASHED_EMAIL_SHA256`, `@uEm` and `@cmdid`. These may be appended to link URLs, but that can't be verified from the truncated source.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **WARN: `List-Unsubscribe` header not found.** QA notes it may not be captured by the AgentMail relay, so this is unconfirmed.
- **WARN: `List-Unsubscribe-Post` not found (RFC 8058).** One-click unsubscribe support is unverified. Gmail and Yahoo bulk-sender rules require it.
- **WARN: `Authentication-Results` not found.** SPF, DKIM and DMARC status is unknown because of the relay. The From domain is `e.neimanmarcus.com`.
- **Not verifiable:** the footer unsubscribe link and physical postal address fall in the truncated source.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
No issues can be confirmed. The 16 tracking links were not resolved, so UTM parameters, `refid` propagation and landing-page alignment are unchecked.

## 7. Recommendations
1. **Remove the SFMC variable-documentation comment** (and any other developer comments) from the production template, or strip comments in the send pipeline.
2. **Change the viewport meta** to `width=device-width, initial-scale=1` and drop `maximum-scale=1`.
3. **Add `lang="en"`** (and `xml:lang`) to `<html>`, and give `<title>` a specific, trimmed value.
4. **Confirm the `List-Unsubscribe` and `List-Unsubscribe-Post: List-Unsubscribe=One-Click` headers** on the raw message from the origin ESP, since the relay may be stripping them.
5. **Check SPF, DKIM and DMARC** from the original message headers or a seed-list test, not through the relay.
6. **Re-run the link probe** on a resolver that follows the click-redirects, and check the final URLs for UTM parameters and 200 status.
7. **Confirm the hamburger menu has a fallback** (static links) for Gmail and Outlook clients without `:checked` support.
8. **Trim the plain-text part** with shorter or untracked URLs, or add more descriptive text.
