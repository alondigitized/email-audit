# Up to $200 off + triple InCircle points
**Score:** 9/10 · **Type:** Email audit · **2026-06-15**
## Executive summary

- This is NM's strategic pivot after a brutal six-send "Extra 20% Off Designer Sale" drumbeat that ran June 9–14. Where that sequence targeted the discount-motivated designer shopper, this June 15 email targets the full-price buyer with a dollar-off tier mechanic (spend $150 to unlock savings, up to $200 off) layered on top of an InCircle triple-points accelerator. The campaign logic is sound — exhaust the sale segment, then re-engage the loyalty-driven regular-price buyer — and the execution is clean.
- The tiered spend/save table is the email's single best creative decision: it transforms an abstract "up to $200 off" promise into an explicit, scannable contract. Code JUNE is visible, the product grid is on-brand, and the InCircle hook is genuinely differentiated from anything NM has sent this month. Compare that to the June 14 "Don't miss out on an extra 20% off" send — functionally a copy-paste of June 12 and June 13 — and this email represents a real step up.
- The miss is prioritization. The InCircle triple-points angle is buried in a secondary banner despite being the more compelling hook for the member audience receiving this. For someone fatigued by a week of sale emails, "earn 3X points on everything you love" is more emotionally resonant than a discount grid — and it's not the lead story.

## What's working

- Tiered spend/save table is immediately scannable: subscribers know exactly what to spend before they click.
- InCircle triple points is a fresh hook NM has not used in this sequence — it stacks loyalty acceleration on top of savings.
- "Code: JUNE" sets a soft month-end deadline without false urgency.
- Product grid (Stuart Weitzman, Jimmy Choo, FRAME, STAUD, Jason Wu) is curated and current — not the same designer-sale inventory from the past six emails.
- Category CTAs at the bottom (SHOP WOMEN'S SHOES, SHOP JEWELRY, SHOP HANDBAGS) give clean wayfinding beyond the generic primary button.

## What's weak

- InCircle triple points is demoted to a secondary banner — the brand's most differentiated hook isn't the lead.
- "SHOP THE SALE" is the primary CTA button despite six more specific CTAs directly below it; the generic label undercuts the targeted product grid.
- No hard deadline — "Limited time" is vague; "Code JUNE expires June 30" would be one line that converts vagueness into a calendar date.
- Product thumbnails are brand-name-only — no product title, price, or detail visible at this size; nothing to create impulse interest before the click.
- Seventh email in five days from NM — subscriber fatigue is a real risk even with a fresh creative direction.

## Recommendations

- 1. **Co-headline the InCircle angle in the hero.** "Earn 3X InCircle Points + Up to $200 Off — Code JUNE" does more work for the loyalty segment than leading with the discount alone. The dual benefit (save now + earn faster) is the reason to buy full-price instead of waiting for a better sale.
- 2. **Add an explicit deadline.** One sentence under the promo code: "Offer valid through June 30." The code name implies it, but a date closes the loop for subscribers who plan purchases.
- 3. **Promote one category CTA to primary.** Pick the top-clicked category from subscriber data (likely SHOP WOMEN'S SHOES or SHOP HANDBAGS) and make that button the hero CTA instead of the catch-all "SHOP THE SALE."
- 4. **Trim the product grid from 9 to 4–6 items.** Elevate one hero product (a Jimmy Choo or Stuart Weitzman standout) with a larger image above the grid — more editorial, less catalog, and a clear break from the June 9–14 grid aesthetic.
- **Subject Alt A:** `Triple InCircle points + up to $200 off — code JUNE`
- **Subject Alt B:** `Your June reward: 3X points + save up to $200`
- **Preheader Alt A:** `Earn faster this month — triple points stack on top of your savings through June.`
- **Preheader Alt B:** `Spend $150, save $50. Spend $750, save $200. Plus 3X InCircle points — all through June.`

## Technical Audit — Neiman Marcus "Up to $200 off + triple InCircle points"

---

### 1. Technical Summary

SFMC AMPscript deployment with table-based layout and a CSS hamburger nav. QA surfaced three warnings: List-Unsubscribe headers missing at the relay layer, SPF/DKIM status unverifiable, and 26 click-redirect links unprobed. The AMPscript variable block contains an ambiguous scenario comment that indicates one of two lookup strategies is supposed to be selected before send.

---

### 2. Link & Tracking Issues

**26 tracking links unprobed.** All click-redirect domains were skipped during HTTP probing. Destination URLs, HTTP status codes, and redirect chain integrity are unverified — broken CTAs cannot be ruled out.

**Tracking parameter risk from silent lookup failures.** `@refid`, `@uEm`, and `@cmdid` are injected into link URLs via SFMC AMPscript lookups against `NM_Subscriber_New_Consolidated` and `NM_CRM_Feed`. SFMC lookup functions return empty string on no-match by default — no error handling is visible in the source. A subscriber absent from either DE will produce links with empty or malformed tracking parameters (e.g., `?cmdid=&uEm=`).

---

### 3. Rendering & Accessibility

**Fragile mobile class selectors.** Media queries use the `*[class=X]` attribute-equality pattern throughout (e.g., `*[class=contenttable]`, `*[class=mobile]`). This selector matches only when the attribute value is exactly that string — adding a second class on any element silently breaks the responsive rule.

**CSS hamburger nav has limited client support.** The `:checked~` sibling selector pattern (`.navbar-checkbox:checked~.menu`) requires CSS3 support not present in Outlook desktop or older Samsung Mail. No `mso-hide` fallback is visible in the truncated source.

**iOS9 animation hack is live dead code.**
```css
body { -webkit-animation: bugfix infinite 1s; }
```
This workaround targeted a 2015 iOS bug. It runs an infinite animation on `<body>` in every modern client for no benefit.

**Multiple commented-out viewport tags left in `<head>`.** Three alternate viewport directives are commented out (`width=320`, `width=1024`, `user-scalable=no`). No functional impact, but indicates iterative patching without cleanup and inflates payload.

**`<title>` has a trailing space:** `<title>Neiman Marcus </title>`. Minor, but visible in some browser-based readers and preview panes.

---

### 4. Personalization & Merge Tokens

**Ambiguous `@user` variable — "CHOOSE ONE SCENARIO" comment not resolved.**

The AMPscript block opens with:
```
CHOOSE ONE SCENARIO BELOW
```
followed by an active `Lookup()` assignment and a commented-out SHA-256 hashed email alternative:
```
<!--/* SET @user = HASHED_EMAIL_SHA256 */ -->
```
If this comment was not intentionally resolved before send, the wrong identity token may be in use for downstream personalization or pixel attribution. The scenario selection comment should not be present in a production send.

**`@emailid` has dual-path logic with undocumented fallback.** The comment states: *"from sendable DE if available, otherwise Lookup to Subscriber_New."* The fallback implementation is not visible in the truncated source — cannot confirm whether a null guard is in place.

**`@uEm` and `@cmdid` sourced from a separate DE (`NM_CRM_Feed`).** Subscribers not present in this feed receive empty strings for both variables. No conditional logic or default value is shown.

---

### 5. Compliance

**`List-Unsubscribe` header not detected (QA WARN).** Gmail and Yahoo require this header for bulk senders (policy enforced since February 2024). The QA note attributes the absence to the AgentMail relay, not necessarily the originating MTA — but inbox placement at both providers is at risk if the header is not reaching the recipient's server.

**`List-Unsubscribe-Post` (RFC 8058) not detected (QA WARN).** One-click unsubscribe is a hard requirement under Google/Yahoo bulk sender guidelines. If this header is absent at delivery (not just at the relay), the email is non-compliant with current inbox provider policy.

**SPF/DKIM authentication status unverifiable (QA WARN).** `Authentication-Results` header was not captured by the relay. The sending domain `e.neimanmarcus.com` is a dedicated ESP subdomain (consistent with SFMC SAP), so authentication is likely configured — but it cannot be confirmed from this sample. A DMARC failure on even one MTA path would affect inbox placement.
