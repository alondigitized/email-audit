# Summer style: 1,000+ new arrivals

- Neiman Marcus opens June with a clean new-arrivals blast after a relentlessly sale-heavy May. ## What's working

- **Hero contrast is immediately legible.** Black background, bold white capitals — the eye lands instantly with zero ambiguity about the email's purpose.
- **Luxury brand roster is credible.** Brunello Cucinelli, Chloé, Jacquemus, Ferragamo, Burberry, Bottega Veneta all above the fold; the assortment earns NM's premium positioning.
- **Split gender routing is clean.** Separate "Shop All Women's New Arrivals" and "Shop All Men's New Arrivals" CTAs avoid forcing a choice at the hero and let each segment self-select.
- **Subject line "1,000+" is a concrete signal.** Specific volume makes the email feel substantial rather than a one-off brand moment.
- **No render bugs.** Product images load, text doesn't overlap, layout holds.

## What's weak

- **No offer means no urgency.** After the Designer Sale's "last chance" drumbeat through all of May, pure editorial requires an exceptionally strong visual story to drive clicks. This grid is fine, not extraordinary.
- **Product images are tiny.** Six products squeezed into a two-row grid means each item is thumbnail-sized — you can't see garment detail, texture, or styling at this scale.
- **No preheader copy visible.** Without a dedicated preheader, the inbox preview likely bleeds nav-link junk ("WOMEN MEN SHOES SALE") — a wasted chance to reinforce the subject.
- **Personal style advisor CTA is buried.** It's a potentially differentiating feature for NM, but it sits in the footer below all the product content where attention is already gone.

- 1. **Add a light urgency layer without discounting.** "First to see 1,000+ styles — available now, while they last" costs nothing and primes scarcity for the inevitable "selling fast" follow-up.
- 2. **Increase hero product size.** One editorial hero image — a model in a standout piece from the grid — would anchor the browse intent and give the grid context. The current all-text hero is fine for the inbox but doesn't inspire.
- 3. **Write a real preheader.** "Chloé, Jacquemus, Brunello Cucinelli — all just landed" pairs perfectly with the subject and fills the preview pane with something useful.
- 4. **Surface the personal style advisor above the first product row.** It's a genuine differentiator vs. every other luxury DTC email; it should live where attention is highest.
- 5. **Add one price anchor.** Even "From $X" or "pieces from $150–$2,800" signals the range and qualifies buyers before the click.

### 1. Technical Summary

The send infrastructure exposes two authentication gaps (SPF/DKIM unverified, one-click unsubscribe absent) that create deliverability and compliance risk. The AMPscript template retains a partially-disabled variable scenario and a near-empty plain-text body dominated by URLs, both of which are active spam-signal contributors.

### 2. Link & Tracking Issues

| Finding | Evidence | Severity |
|---|---|---|
| 26 click-redirect URLs not probed | QA: `26 tracking link(s) skipped` — all routed through a click-tracking domain | Medium |
| Plain-text body is 90% URLs | QA: `5,214 / 5,764 chars are URLs` | High |

**Notes:**
- The plain-text alternative appears to be auto-generated from links only, with no prose content. Spam filters (SpamAssassin, Postfix content filters) treat a plain-text ratio this high as a strong spam signal. A minimal prose summary of the email content should be prepended.
- The 26 tracking links cannot be validated for correct UTM parameters or broken destinations without resolving the redirect chain. Manual spot-check is required.

### 3. Rendering & Accessibility

**Viewport experimentation debt:** Three viewport meta variants are present but commented out directly above the live one:

```html
<!--<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" />-->
<!--<meta name="viewport" content="width=320, initial-scale=0.29">-->
<!--<meta name="viewport" content="width=1024">-->
```

These are dead code and indicate prior rendering instability. Not a current bug, but a maintenance risk if a future editor uncomments the wrong line.

**Interactive hamburger menu (checkbox hack):** The template implements a CSS-only mobile nav using `:checked ~` selectors:

```css
.mobileCont:checked~table *[class=contentInteractive] { display: block !important; }
```

This pattern works in Apple Mail but is silently ignored in Gmail (web and app) and all Outlook versions. If this nav is functional content rather than decorative, users on Gmail/Outlook see neither the menu nor its fallback — the interaction simply disappears.

**iOS9 animation workaround still present:**

```css
body { -webkit-animation: bugfix infinite 1s; }
@-webkit-keyframes bugfix { from { padding: 0; } to { padding: 0; } }
```

iOS 9 is end-of-life (2019). This fires a real (no-op) animation on every modern Apple Mail render. Safe to remove.

**`alt` attributes:** Not verifiable from the truncated source, but image-heavy NM templates historically omit or leave `alt=""` on decorative images. Should be confirmed in full source.

**`<title>` tag has trailing whitespace:** `<title>Neiman Marcus </title>` — minor, but shows in browser tab previews and some screen reader announcements.

---

### 4. Personalization & Merge Tokens

**Ambiguous `@user` variable scenario:**

The template header contains this instruction followed by a conflicting definition:

```html
<!-- CHOOSE ONE SCENARIO BELOW -->
<!--/* SET @user = HASHED_EMAIL_SHA256 */ -->
```

The SHA256 scenario is commented out using `/* */` inside an HTML comment (`<!-- -->`). The live path sets `@user` via a Lookup to `NM_Subscriber_New_Consolidated`. This is correct behavior, but the dead SHA256 block is fragile: AMPscript parsers may handle `<!-- /* */ -->` differently across SFMC versions, and the instruction "CHOOSE ONE SCENARIO BELOW" implies this is a template decision point that should be resolved and removed from production sends.

**No-op CONCAT on `@refid`:**

```
@refid = CONCAT(@base_refid,"")
```

Concatenating with an empty string is a no-op. This is either a placeholder for a suffix that was removed or a vestigial pattern. If the suffix was intentional (e.g., a split-test suffix), its absence is a tracking gap.

**Silent Lookup failure exposure:** Four separate data lookups (`NM_Subscriber_New_Consolidated` × 2, `NM_CRM_Feed` × 2) run at render time. SFMC Lookup returns an empty string on miss, not an error. If `@uEm` or `@cmdid` are used in tracking URLs and resolve empty for a subset of subscribers, those links will silently drop CRM identifiers without any send-time warning.

### 5. Compliance

| Check | Result | Evidence |
|---|---|---|
| `List-Unsubscribe` header | **Missing** | QA: `List-Unsubscribe header not found` |
| `List-Unsubscribe-Post` (RFC 8058) | **Missing** | QA: `one-click unsubscribe may not be supported` |
| SPF/DKIM authentication | **Unknown** | QA: `Authentication-Results header not found` |
| CAN-SPAM physical address | Not verifiable | Truncated source — footer not included |

**Gmail/Yahoo one-click unsubscribe requirement:** Since February 2024, Gmail and Yahoo require bulk senders (>5k/day) to support RFC 8058 one-click unsubscribe via `List-Unsubscribe-Post`. Its absence is a deliverability violation for those ISPs, not just a compliance recommendation.

**SPF/DKIM:** The sending domain `e.neimanmarcus.com` is a dedicated ESP subdomain. Authentication-Results not appearing in the QA relay suggests headers were stripped or not captured — this needs to be verified against raw message headers from a real inbox delivery, not the relay snapshot.

---

### 6. Email-to-Site Continuity

UTM parameters on the 26 tracked links cannot be confirmed without resolving the redirect chain (all were skipped by QA). The following should be verified manually:

- `utm_source` — should be `email` or equivalent, not a generic campaign ID
- `utm_medium` — should be `email`
- `utm_campaign` — should match `@base_refid` or the campaign calendar entry
- `utm_content` — CTA-level differentiation (header nav vs. hero vs. product tile)

The `@refid` no-op CONCAT (see §4) may mean campaign attribution is correct but lacks the intended content-level granularity if the suffix was meant to differentiate module positions.

---

### 7. Recommendations

**P0 — Fix before next send:**
1. **Add `List-Unsubscribe` and `List-Unsubscribe-Post` headers** at the ESP/SFMC send config level. Gmail and Yahoo enforce this; missing it risks inbox placement for the entire file.
2. **Verify SPF/DKIM alignment** for `e.neimanmarcus.com` by pulling raw headers from a delivered test send. Do not rely on the relay snapshot.
3. **Replace the URL-only plain-text body** with a short prose summary (2–4 sentences) followed by the link list. A 90% URL ratio is a reliable spam trigger.

**P1 — Fix in next template revision:**

6. **Resolve or remove the no-op `@refid` CONCAT** — either add the intended suffix or simplify to `SET @refid = @base_refid`.
