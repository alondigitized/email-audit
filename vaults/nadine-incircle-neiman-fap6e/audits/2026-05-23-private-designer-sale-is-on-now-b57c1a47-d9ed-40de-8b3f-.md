# Private Designer Sale is on now!
**Score:** 8/10 · **Type:** Email audit · **2026-05-23**
## Executive summary

- This is NM's sixth consecutive Designer Sale send in roughly seven days. The creative is clean and on-brand — cream background, oversized serif type, red discount line, single CTA — but it is also nearly stripped bare. There is no product photography, no designer name-dropping, no featured item to covet. You're selling the sale as an abstraction, not as a reason to buy something specific right now.
- The "Private Event" framing is the most interesting swing in this email, and it mostly misses. After five prior broadcasts on the same sale, "private" reads as boilerplate NM vocabulary — not a genuine access unlock. The 40% off headline is the strongest offer in this series, but the "UP TO" qualifier and visible "Exclusions Apply" line land immediately after, blunting the impact before the eye even reaches the CTA.
- The technical execution is flawless: no render bugs, clear visual hierarchy, promo code in the body. But relative to NM's own 9/10 "new arrivals" send from 5/21 — which simply added brand names (Zimmermann, etc.) to an identical grid layout — this email underperforms by refusing to show any product at all. Clean is not the same as effective.

## What's working

- Visual hierarchy is textbook: logo → headline → 40% OFF in red → CTA. Nothing competes with the offer.
- Promo code (NMSALE) is surfaced in the body copy — low friction, no hunting required.
- 40% off is the strongest discount number in this entire Designer Sale series; it's genuinely a new hook vs. prior sends.
- "SHOP SALE" is direct and unambiguous — no "Discover" or "Explore" hedging.
- Render is clean: no broken images, no overlap, no lorem ipsum.

## What's weak

- Zero product photography — no models, no hero items, no designer logos; nothing to anchor desire in a luxury send.
- "Private Event" is hollow branding after six near-identical broadcasts; the exclusivity claim is not earned.
- Sale end date (6/1/26) is buried in fine print only — no urgency signal in the hero or near the CTA.
- No designer names called out anywhere; NM's own 5/21 "new arrivals" email proved that brand name-dropping is where luxury email earns its click.
- Cadence fatigue is real: a subscriber who has received five+ Designer Sale emails this week has declining motivation to open, let alone click.

## Recommendations

- 1. **Surface the deadline in the hero.** Add "Sale ends June 1" as a single line above or below the CTA button. The end date is already in the fine print — promoting it costs nothing and creates legitimate urgency the subject line currently lacks.
- 2. **Add 2–3 designer names or product shots.** Even the weakest executions in this series (5/19 Givenchy/Ferragamo spotlight, 7/10) outperformed pure text-hero sends because there was something specific to covet. A three-product strip with brand labels would transform this from an announcement into a temptation.
- 3. **Make "Private" mean something or drop it.** If this code is member-only or account-unlocked, say "Your private access code." If it's a broadcast code, "Private Event" is misleading and erodes trust at open. Either commit or cut.
- 4. **Rest the cadence or change the angle sharply.** The 5/22 "Summer-ready styles going fast!" tried a lifestyle angle on the same sale and landed at 5/10. This one tries exclusivity framing. Neither works as a fresh hook. The 5/21 "new arrivals" at 9/10 succeeded because it presented different inventory. The next send in this series needs a true creative pivot (specific designer collaboration, editorial POV, new category) or it should be skipped.

## Technical Audit

## Technical Audit — Neiman Marcus "Private Designer Sale is on now!"

---

### 1. Technical Summary

This is a Salesforce Marketing Cloud (SFMC) AMPscript template with table-based layout and a hamburger nav. The QA sweep surfaces two compliance-level gaps (unsubscribe headers, authentication visibility) and a plain-text URL density problem that raises deliverability risk at inbox filters.

---

### 2. Link & Tracking Issues

**28 click-redirect links skipped by HTTP probe** — destination URLs could not be verified. No confirmation that:
- All links resolve (no 4xx/5xx dead ends)
- Redirect chains terminate at the correct landing page
- UTM parameters survive the redirect hop

**Plain-text payload is 70.6% URLs** (2,470 of 3,450 chars). Spam filters including Gmail's and SpamAssassin penalize plain-text parts that are predominantly raw URLs with little surrounding prose. This is likely caused by SFMC auto-generating the plain-text version from the HTML without pruning tracking wrappers.

**`@refid` is a no-op CONCAT:**
```
@refid = CONCAT(@base_refid,"")
```
Concatenating with an empty string produces `@base_refid` unchanged. This pattern typically means a suffix (e.g., a variant code or creative ID) was removed but the CONCAT wrapper was not cleaned up. If `@refid` is injected into link query strings, it carries no differentiation beyond the base campaign ID.

---

### 3. Rendering & Accessibility

**Missing `lang` attribute on `<html>`:**
```html
<html xmlns="http://www.w3.org/1999/xhtml">
```
No `lang="en"` — screen readers cannot infer document language. Violates WCAG 2.1 SC 3.1.1.

**Trailing whitespace in `<title>`:**
```html
<title>Neiman Marcus </title>
```
Minor; some preview pane renderers surface the title string.

**Three commented-out `<meta viewport>` tags** remain in the `<head>`. Dead markup adds payload weight and signals template hygiene issues, but causes no rendering failures.

**Hamburger nav via CSS `:checked` trick** — functional in WebKit/Blink clients but silently breaks in Outlook (all versions) and older Samsung Mail, which ignore `visibility`, `opacity`, and `transition` on pseudo-class state. No fallback nav is visible in the truncated source.

**Image alt text** — cannot confirm from truncated source, but the inline CSS pattern (no explicit `alt` on `<img>` tags visible) is a common gap in NM templates. Images-off rendering would be blank.

---

### 4. Personalization & Merge Tokens

**Manual scenario selection required — error-prone:**
```
<!-- CHOOSE ONE SCENARIO BELOW -->
<!--/* SET @user = HASHED_EMAIL_SHA256 */ -->
```
The template requires the sender to uncomment the correct `@user` assignment before send. The SHA256 scenario is currently commented out, meaning `@user` is populated via CRM Lookup. There is no programmatic guard — an operator mistake silently sends wrong or empty `@user` values into every personalized URL.

**Three separate Lookup calls at send-time:**
```
Lookup("NM_Subscriber_New_Consolidated", "EMAIL_ID", ...)
Lookup("NM_CRM_Feed", "uEm", ...)
Lookup("NM_CRM_Feed", "cmdid", ...)
```
If any row is missing from the DE, the variable returns an empty string. Empty `@uEm` or `@cmdid` silently corrupts downstream URL parameters with no visible error to the sender.

### 5. Compliance

| Check | Status | Evidence |
|---|---|---|
| `List-Unsubscribe` header | **MISSING** | QA WARN — not captured by AgentMail relay |
| `List-Unsubscribe-Post` (RFC 8058) | **MISSING** | QA WARN — one-click unsubscribe absent |
| SPF/DKIM `Authentication-Results` | **UNKNOWN** | QA WARN — header not found via relay |
| CAN-SPAM physical address | Cannot confirm (source truncated) | — |

**The missing `List-Unsubscribe-Post` is the highest-priority issue.** As of February 2024, Gmail requires RFC 8058 one-click unsubscribe for senders exceeding 5,000 messages/day. A list of Neiman Marcus' scale without this header is subject to Gmail deferral and spam folder placement. Yahoo Mail enforces the same requirement.

The missing `Authentication-Results` header is likely an artifact of the AgentMail relay stripping or not forwarding the header — SPF/DKIM may be correctly configured at the ESP level, but this cannot be confirmed from captured data.

---

### 6. Email-to-Site Continuity

With 28 click-redirect links unprobed, UTM parameter integrity cannot be confirmed end-to-end. The presence of `@refid`, `@uEm`, and `@cmdid` in the template comment block suggests these are injected into link query strings — but:

1. If `@refid` is the no-op CONCAT described above, campaign differentiation in analytics is lost
2. If any CRM Lookup returns empty, `uEm` or `cmdid` parameters arrive at the site as blank values, polluting session attribution
3. Redirect chain depth is unknown — deep chains increase latency and drop UTM params if any intermediate hop does not forward query strings

---

### 7. Recommendations

**P0 — Compliance (act before next send):**
- Confirm `List-Unsubscribe` and `List-Unsubscribe-Post` headers are set at the SFMC send classification level, not in the HTML body. If using SFMC's native unsubscribe, verify the send classification has "SafeUnsubscribe" or equivalent configured to emit both headers.
- Obtain a raw `.eml` capture (not via relay) to verify `Authentication-Results`, `DKIM-Signature`, and `Return-Path` are present and passing.

**P1 — Deliverability:**
- Replace the auto-generated plain-text part with a hand-authored version containing prose + a small set of key links. Target <30% URL density.
- Probe all 28 redirect URLs in CI to catch broken links before send.

**P2 — Personalization safety:**
- Replace the manual "CHOOSE ONE SCENARIO" comment pattern with a conditional AMPscript block that selects the `@user` assignment based on a DE field or send-time parameter. Removes human error from the critical path.
- Add null-guards around `@uEm` and `@cmdid` lookups; default to a known fallback value rather than an empty string.
- Fix or remove the `CONCAT(@base_refid,"")` wrapper — either append the intended suffix or assign `@refid = @base_refid` directly.

**P3 — Accessibility / hygiene:**
- Add `lang="en"` to the `<html>` element.
- Remove the three commented-out `<meta viewport>` tags.
- Audit all `<img>` elements for non-empty, descriptive `alt` attributes.
