# Private Designer Sale is on now!
**Score:** 9/10 · **Type:** Email audit · **2026-05-23**
## Executive summary

- This is NM's sixth Designer Sale send in roughly seven days — launched 5/17, urgency on 5/18, Givenchy/Ferragamo spotlight 5/19, new designers added 5/21, "going fast" on 5/22, and now this. The creative makes a bold choice: zero product imagery, pure typographic hierarchy — large serif "PRIVATE EVENT," red "40% OFF," visible promo code, single dark CTA. It's clean and on-brand.
- The "Private Event" framing is doing heavy lifting it hasn't earned. Without a name, a loyalty tier, or a category preference surfaced, "private" is just copy. A subscriber who has received five near-identical sale emails this week reads this as another blast with a new headline.
- If you've been getting NM mail all week, your attention budget is spent. The execution is good; the problem is the cadence. The email would land harder at send one or two.

## What's working

- Typographic hierarchy is sharp: eye travels naturally PRIVATE EVENT → 40% OFF → SHOP SALE
- Promo code NMSALE is front-and-center — no hunting required
- "SHOP SALE" button is unambiguous — specific verb + noun, high contrast, no guessing
- Off-white cream layout renders cleanly with zero broken elements
- Footer "Match with a personal style advisor" is a nice luxury-tier touch

## What's weak

- Zero product imagery — there's nothing to desire; a luxury sale email should show the goods
- "UP TO 40% OFF select designer styles" ceiling claim will disappoint most shoppers who find 20–25% on most SKUs
- "Private Event" rings hollow as broadcast copy on a week-long public sale
- End date (June 1) is buried in the fine print legalese rather than anchored in the hero where it creates urgency
- Sixth send in seven days — this creative offers no new hook, and the 5/22 "Summer-ready styles are going fast!" send already burned "urgency" as a device

## Recommendations

- 1. **Add 3–4 product shots** — a Valentino bag, Givenchy sneakers, something aspirational at 40% off. Luxury shoppers click things they want to own, not abstract discount percentages.
- 2. **Move the deadline into the hero** — a simple "Ends June 1" line next to the offer transforms the urgency from fine-print legal to real motivation.
- 3. **Name the designers** — "Up to 40% off Valentino, Givenchy, Totême & more" outperforms "select designer styles" by every measure.
- 4. **Earn or drop "Private"** — if this is a broadcast, lose "Private Event." If it's member-gated, surface the tier (InCircle) so recipients know why they're in the room.
- 5. **Rest the cadence** — the next Designer Sale send needs a hard-close countdown or a genuinely new angle; a seventh repeat will cannibalize list health.

## Technical Audit — Neiman Marcus "Private Designer Sale is on now!"

**From:** NeimanMarcus@e.neimanmarcus.com | **Date:** 2026-05-23

---

### 1. Technical Summary

The email is a standard table-based SFMC AMPscript deployment with a CSS-only hamburger nav. Four QA warnings were flagged, the most consequential being missing one-click unsubscribe headers and unverifiable authentication status — both of which are deliverability risks under Gmail/Yahoo 2024+ bulk sender rules.

---

### 2. Link & Tracking Issues

**28 tracking links present — not probed.**
All click-redirect URLs were skipped by the HTTP probe. Destination URL integrity (broken links, redirect chains, HTTPS enforcement) cannot be confirmed from this audit pass.

**Plain-text body is 70.6% URLs (2,470 / 3,450 chars).**
This ratio is a known spam-filter trigger. Plain-text alternates should include readable prose with URLs interspersed, not a URL dump. Evidence: QA deliverability warning.

**`@refid = CONCAT(@base_refid, "")` is a no-op.**
The refid is assigned by concatenating the base value with an empty string — this produces an identical output. If `@refid` was intended to have a suffix appended (e.g., a version tag or channel code), that logic is missing.

---

### 3. Rendering & Accessibility

**Multiple commented-out `<meta viewport>` tags indicate unresolved historical conflicts.**
Three viewport definitions exist in the `<head>`, two commented out:
```html
<!--<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" />-->
<!--<meta name="viewport" content="width=320, initial-scale=0.29">-->
<!--<meta name="viewport" content="width=1024">-->
```
Only one is active. The dead markup adds noise and suggests the template was stitched from older versions without cleanup.

**CSS-only interactive hamburger nav has narrow client support.**
The `:checked` pseudo-class toggle (`.mobileCont:checked ~ table *[class=contentInteractive]`) will silently fail in Outlook (all versions), Samsung Mail, and several Android native clients. Affected users see no navigation at all, since `contentInteractive` defaults to `display: none !important`.

**`<title>` has a trailing space:** `<title>Neiman Marcus </title>`. Minor, but affects tab/preview rendering in some clients.

**`alt` attribute coverage cannot be confirmed** from the truncated source. Given the image-heavy nature of NM campaigns, this warrants a full-source check.

---

### 4. Personalization & Merge Tokens

**`@user` assignment scenario is commented out — value is indeterminate.**
The template header says "CHOOSE ONE SCENARIO BELOW" and lists two options. The only visible assignment is wrapped in both an HTML comment and an AMPscript comment, making it inert:
```html
<!--/* SET @user = HASHED_EMAIL_SHA256 */-->
```
If `@user` is referenced downstream in tracking URLs or personalization blocks without a live assignment, it will render as an empty string or throw an AMPscript runtime error. The active assignment (presumably the `Lookup()` path) is not visible in the truncated source — this requires verification against the full template.

**`@uEm` and `@cmdid` are populated via `NM_CRM_Feed` lookups.** If a subscriber's email is absent from that DE, both values return null. Any link or block that depends on `@cmdid` without a null-guard will break silently for unmatched records.

### 5. Compliance

| List-Unsubscribe-Post (RFC 8058) | **MISSING** | QA: one-click unsubscribe unsupported |

**The missing `List-Unsubscribe` and `List-Unsubscribe-Post` headers are the highest-severity finding.** Gmail and Yahoo have required both for bulk senders (>5,000/day) since February 2024. Absence risks inbox demotion or bulk-folder routing. These are typically injected by the ESP (SFMC) or at the MTA layer — the fact that they are absent at the relay suggests either a misconfigured sending domain, a relay passthrough stripping headers, or an SFMC sending profile that has not enabled the List-Unsubscribe injection option.

**Authentication status is unverifiable** because `Authentication-Results` was not captured by the AgentMail relay. SPF and DKIM pass/fail for `e.neimanmarcus.com` cannot be confirmed. This should be cross-checked against MX Toolbox or a raw header capture before the next send.

### 6. Email-to-Site Continuity

**Cannot fully verify** without probing the 28 skipped tracking links. Specific concerns to validate manually:

- Confirm all 28 tracking redirects resolve over HTTPS with no mixed-content hops.
- Verify UTM parameters are present and consistent across all CTAs (`utm_source`, `utm_medium`, `utm_campaign` at minimum).

### 7. Recommendations

**Priority 1 — Before next send**
1. **Fix List-Unsubscribe headers.** Enable `List-Unsubscribe` injection in the SFMC sending classification or confirm the MTA relay is not stripping them. Add `List-Unsubscribe-Post: List-Unsubscribe=One-Click` per RFC 8058.
2. **Verify `@user` assignment.** Confirm which scenario is active in the live template and that `@user` has a live AMPscript assignment, not a commented-out one.
3. **Capture a raw `Authentication-Results` header** from a seed send to confirm SPF/DKIM pass for `e.neimanmarcus.com`.

**Priority 2 — Template hygiene**
4. **Rebuild plain-text alternate** with readable prose; keep URLs below 30% of total character count to reduce spam-filter exposure.
5. **Null-guard `@cmdid` and `@uEm`** lookups: `IIF(EMPTY(@cmdid), "default_value", @cmdid)` to prevent silent personalization failures for unmatched CRM records.
6. **Remove dead viewport and commented-out scenario markup** from the template before the next production deploy.

**Priority 3 — Accessibility**
7. Audit `alt` attributes on all `<img>` tags in the full source. Screen-reader pass rate for image-heavy emails drops significantly without them.
8. Add a non-interactive fallback nav for clients that don't support `:checked` CSS toggles — a simple linked list of text nav items is sufficient.
