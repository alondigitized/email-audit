# Take $50-$200 off your next purchase
**Score:** 8/10 · **Type:** Email audit · **2026-06-16**
## Executive summary

- This is a clean, structurally sound spend-to-save email — spend $250–$1,000+, save $50–$200, code JUNE, earn Triple InCircle Points. The hierarchy works: gold hero box → spend/save table → InCircle bar → brand product grid → category CTAs. Nothing is broken, nothing is buried. If this were the first time NM had sent it, it would score very well.
- The problem is it isn't the first time. Yesterday — June 15 — NM sent "Up to $200 off + triple InCircle points" (9/10 in the brand history) with functionally identical offer mechanics and the same InCircle Triple Points overlay. The code JUNE presumably ran on both. Today's subject line is a minor reframe ("Take $50-$200 off your next purchase" instead of "Up to $200 off + triple InCircle points"), but the email body is nearly indistinguishable. For any subscriber who opened yesterday, this is a re-send with a different subject and the same creative.
- The brand is burning goodwill on a second bite at an apple that was already eaten. The six-day Extra 20% Off drumbeat that ran June 9–14 finally broke cadence with the June 15 pivot to a spend-to-save mechanic. Going right back to the same send June 16 collapses that reset immediately.

## What's working

- **Spend/save table is clean and transparent** — four tiers ($250→$50, $350→$75, $500→$100, $1,000+→$200) with "Exclusions Apply" disclosed. No bait-and-switch.
- **InCircle Triple Points callout earns its own dark bar** — it's visible as a second reason to transact, not buried in fine print.
- **Product grid hits recognizable luxury names** — Stuart Weitzman (twice), Jimmy Choo, FRAME, STAUD, Ungaro. The brands do the trust-building that copy can't.
- **Category CTAs at the bottom are exhaustive** — Women's Clothing, Men's, Women's Shoes, Jewelry, Handbags, Home. Low-friction escape hatch for anyone who isn't triggered by the sale offer.
- **No render bugs** — all images load, layout is clean, text is legible, no broken grid.

## What's weak

- **Creative is a functional re-send of yesterday's June 15 email** — same offer, same InCircle hook, same product brands, just a different subject line. Subscribers who opened June 15 see nothing new.
- **"Limited Time" with no deadline** — the urgency banner says limited time but there's no end date. The code JUNE implies the month, but that's a 30-day window, not urgency.
- **Hero doesn't lead with the InCircle angle** — the spend/save table is the dominant frame, but for the InCircle member (clearly the target), "Triple Points on Every Purchase" is the more differentiating hook. It's buried below the fold.
- **No personalization** — no name, no "as an InCircle member" acknowledgment, no category nudge based on past behavior. For a brand like NM at this price point, anonymous feels lazy.
- **Product grid labels are small and hard to scan** — brand names appear below each image in a light font. On mobile, this would compress into illegibility.

## Recommendations

- 1. **Don't re-send the same offer the next day without a material change** — if you need a second touch, change the creative frame: surface a specific product, add a countdown, show new brands. A subject-line swap alone doesn't justify a re-send.
- 2. **Put a hard deadline on the hero** — "Code JUNE: Use by Sunday" or "Offer ends June 22" converts "limited time" into real urgency. Without a date, the pressure signal is noise.
- 3. **Lead with InCircle for segmented sends** — if this list is InCircle members, the hero should say "Earn Triple Points + Save Up to $200" with the loyalty angle first. Swap the InCircle bar from below the hero to above the spend/save table.
- 4. **Add one editorial product hero** — the spend/save table reads like a bank flyer. One aspirational hero image (a specific Jimmy Choo or Stuart Weitzman product) before the table would ground the savings in something the reader wants.
- **Subject Alt A:** `Code JUNE: Save up to $200, ends Sunday`
- **Subject Alt B:** `InCircle members: Triple Points + up to $200 off`
- **Preheader Alt A:** `Spend $250, save $50 — or go big for $200 off. Shop sale styles now.`
- **Preheader Alt B:** `Stack your points this weekend — triple InCircle points on every qualifying purchase.`

## Technical Audit

## Technical Audit — Neiman Marcus "Take $50-$200 Off" Email

---

### 1. Technical Summary

Standard SFMC AMPscript-driven, table-based HTML email. QA returned a 57% pass rate driven by three warnings: missing compliance headers (`List-Unsubscribe`, `List-Unsubscribe-Post`) and unresolved authentication status — all attributable to AgentMail relay capture limitations rather than confirmed send-side failures, but worth verifying at the ESP level.

---

### 2. Link & Tracking Issues

**26 tracking/redirect links skipped** — QA could not probe destinations because all CTA hrefs route through a click-redirect domain (typical SFMC `click.e.neimanmarcus.com` or equivalent). This is expected behavior, but it means:
- Broken destination URLs would not surface in automated checks.
- UTM parameters on final landing pages are unverifiable from this capture (see §6).

**AMPscript `@refid` dependency** — campaign tracking is built on `CONCAT(@base_refid,"")`. If `@base_refid` is not populated in the sendable DE for any subscriber, `@refid` silently resolves to an empty string, dropping campaign attribution on all 26 links for that recipient.

---

### 3. Rendering & Accessibility

**Three commented-out viewport tags** in `<head>`:
```html
<!--<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" />-->
<!--<meta name="viewport" content="width=320, initial-scale=0.29">-->
<!--<meta name="viewport" content="width=1024">-->
```
These are inert but indicate unresolved historical viewport experiments. The active tag (`width=device-width, maximum-scale=1`) is correct; the dead tags should be removed to reduce template debt.

**Conflicting responsive breakpoints** — two separate `<style>` blocks define breakpoints at `600px` and `480px`/`520px` respectively, with different class selectors (`.contenttable`, `.ImgSize`, `.ImgSize2x2`). No confirmed rendering break, but overlap between the `600px` block and the `480px` block means elements in the 481–599px range may receive only partial responsive treatment.

**iOS 9 hamburger animation hack** (archaic, non-breaking):
```css
body { -webkit-animation: bugfix infinite 1s; }
```
iOS 9 reached end-of-life in 2019. This adds unnecessary paint cost on all modern WebKit clients and can be removed.

**Alt text** — not verifiable from the truncated source, but with 26+ tracked image links, any missing `alt` attributes on product images will fail accessibility in screen readers and appear blank in image-off clients (Gmail desktop default).

---

### 4. Personalization & Merge Tokens

**Variable declarations exist only in HTML comments** — the entire AMPscript variable block at the top of the email is inside `<!-- ... -->`:
```html
<!--REQUIRED variables: @email ... @user ... @uEm ... @cmdid ...-->
```
HTML comments are not executed by SFMC. This block appears to be inline documentation, not live code. The actual AMPscript `%%[...]%%` execution blocks must exist elsewhere in the template (below the truncation point). If they do not, all personalization variables (`@uEm`, `@cmdid`, `@emailid`, `@refid`) will resolve to empty strings.

**`@user` assignment is commented out**:
```html
<!--/* SET @user = HASHED_EMAIL_SHA256 */-->
```
The comment indicates `@user` should be set to a SHA-256 hashed email (likely for audience matching/suppression). This line is currently inert. If any downstream logic, tracking pixel, or audience sync depends on `@user`, it will receive a null value.

**`@uEm` and `@cmdid` sourced from `NM_CRM_Feed`** — these require a successful `Lookup()` against that DE. If a subscriber's email is absent from `NM_CRM_Feed`, both fields silently empty out. No fallback or error-handling is visible.

### 6. Email-to-Site Continuity

All 26 links route through a redirect domain, so UTM parameter integrity on final landing pages is unverifiable from this capture. Key risks:

- If `@refid` resolves to empty (see §2), any UTM value injected as `&cm_sp=%%=v(@refid)=%%` in link parameters will produce malformed or blank attribution in GA4/Adobe Analytics.
- No direct (non-redirected) links were present to spot-check UTM structure.

Recommended: pull a test send to a seed address and inspect final redirect destinations for `utm_campaign`, `utm_medium`, `utm_source`, and `cm_sp` parameters before deployment.

### 7. Recommendations

**Priority / blocking:**
1. **Confirm `List-Unsubscribe` and `List-Unsubscribe-Post` headers are set at the SFMC send classification level** — required for Gmail bulk sender compliance. If missing, add via SFMC Send Classification or `%%=HTTPGet()=%%` header injection.
2. **Verify AMPscript execution blocks exist below the truncation point** — if the `%%[ ... ]%%` block is absent and only the HTML comment documentation exists, all personalization and tracking will silently fail at send time.
3. **Confirm `@user` SHA-256 assignment is live code somewhere in the template** — the commented-out line is inert.
4. **Validate `@refid` population** for the sendable DE before send — run a row count on `NM_Subscriber_New_Consolidated` and `NM_CRM_Feed` against the target list to confirm Lookup() hit rate.

**Non-blocking / cleanup:**
5. Remove the three commented-out `<meta viewport>` tags.
6. Remove the iOS 9 `@-webkit-keyframes bugfix` hack.
7. Consolidate the two responsive `<style>` blocks into one to eliminate the 481–599px gap.
