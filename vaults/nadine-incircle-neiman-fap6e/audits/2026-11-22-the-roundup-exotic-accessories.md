## Technical Audit

## 1. Technical Summary
The email's visible HTML source has a few hygiene and accessibility defects: internal template comments left in the output, no `lang` attribute, and a viewport that blocks zoom. Compliance and authentication can't be confirmed. The source is truncated, and the relay stripped the headers that would show them.

## 2. Link & Tracking Issues
- **16 tracking/click-redirect links were not probed** (QA INFO). Their destinations, redirect chains and status codes are unverified.
- **The plain-text part is mostly URLs:** 3012 of 3515 characters (about 86%) per QA. This points to long tracking URLs in the text alternative. Spam filters can penalize this, and it is hard to read for text-only clients.
- No broken links were confirmed. The QA run found 0 issues.

## 3. Rendering & Accessibility
- **No `lang` attribute:** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang` or `dir`. Screen readers can't pick the correct language profile (WCAG 3.1.1).
- **Zoom is blocked:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">`. `maximum-scale=1` stops pinch-zoom on some mobile clients (WCAG 1.4.4).
- **Comment before the DOCTYPE:** the large "REQUIRED variables" comment sits above `<!DOCTYPE ...>`. In some legacy clients and IE-based renderers, anything before the doctype can trigger quirks mode. The DTD URL is also `https://www.w3.org/TR/xhtml1/...`, but the canonical identifier is `http://`.
- **Checkbox-hack hamburger menu:** the CSS uses `.navbar-checkbox:checked~*[class].menu`, `.hamburger` and `.close`. This depends on `:checked` support, which Gmail and Outlook generally lack. It is also not keyboard-accessible. I couldn't see a non-interactive fallback in the truncated source, so confirm one exists.
- **Narrow selectors:** the mobile rules use exact-match attribute selectors such as `*[class=contenttable]` and `*[class=hide]`. They stop matching if an element gets a second class.

## 4. Personalization & Merge Tokens
- **No unresolved tokens** were found in the visible, rendered portion of the truncated source.
- **Template internals are left in the delivered HTML:** the top comment exposes data extension and field names (`NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`, `EMAIL_ID`, `uEm`, `cmdid`) and the stray instruction `CHOOSE ONE SCENARIO BELOW`. It looks like a Salesforce Marketing Cloud (SFMC) template whose comment wasn't stripped. This is a minor information leak and a sign the build step skipped a cleanup.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` was not found** (QA WARN), and neither was **`List-Unsubscribe-Post`** (RFC 8058 one-click). QA notes the AgentMail relay may strip these headers. This is unconfirmed, not proven missing. Gmail and Yahoo bulk-sender rules require both, so check the raw message at the origin.
- **`Authentication-Results` was not found** (QA WARN), so SPF, DKIM and DMARC alignment are unknown. The sender is `e.neimanmarcus.com`. Verify at the origin or with a seed-list test.
- The truncated source doesn't show the footer, so the unsubscribe link and physical address can't be confirmed.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not assessable. The 16 tracking links were skipped, and the visible source doesn't show final destination URLs or UTM parameters. The comment does reference `@refid`/`@base_refid`, which suggests campaign IDs are applied through redirects rather than UTMs. That is unverified.

## 7. Recommendations
1. Add `lang="en"` to `<html>`, and consider `xml:lang`.
2. Remove `maximum-scale=1` from the viewport meta tag.
3. Strip the SFMC variable comment, and any other build-time comments, in the send pipeline. If one must stay, put it after the DOCTYPE.
4. Check the raw message at the origin for `List-Unsubscribe`, `List-Unsubscribe-Post` and `Authentication-Results`. Rerun QA on a direct-delivery copy to rule out relay stripping.
5. Shorten the text-alternative links, or reduce the number of URLs in the plain-text part.
6. Resolve the 16 tracking links with a redirect-following check to verify destinations and UTMs.
7. Confirm the hamburger nav has a working fallback in Gmail and Outlook, with a visible link set or accessible alternatives.
