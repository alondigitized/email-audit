# Don’t miss out on a $50–$500 gift card
**Score:** 9/10 · **Type:** Email audit · **2026-07-13**
## Executive summary

- This is Neiman Marcus's second consecutive send of the same spend-to-earn gift card mechanic in as many days. Yesterday's "Earn a $50–$500 gift card with your purchase today" (July 12, 8/10) already delivered this exact offer — same tiered table ($500→$50, $1,000→$75, $3,000→$250, $11,000+→$500), same promo code, same product-grid layout with luxury designers. Today's version rotates the subject to FOMO framing but does nothing else differently. If you opened yesterday's email, this one registers as a nudge at best, list fatigue at worst.
- The creative itself is solid: the spend/earn table is scannable, the hero is the first thing the eye lands on, and the designer product grid — Jimmy Choo, Zimmermann, FRAME, Veronica Beard, Theory — gives subscribers real browsing destinations. Five category CTAs cover the full NM occasion set cleanly. "Get summer-ready" keeps the seasonal moment alive.
- The problem is cadence, not craft. NM is deploying a "don't miss out" urgency play with no visible expiration date on an offer that already ran yesterday. That combination erodes trust faster than the subject line can recover it.

## What's working

- Spend/earn table is immediately readable — tiers and dollar amounts are clear without hunting through fine print
- Designer product grid (Jimmy Choo, Zimmermann, FRAME, Theory) provides actual browsing hooks, not just a hero banner
- Five category-labeled CTAs (Women's Clothing, Women's Shoes, Men's Clothing, Handbags, Home) cover the full shopping occasion set
- "Get summer-ready" subheadline anchors the send in a genuine seasonal moment
- Clean render — no broken images, overlapping text, or layout issues

## What's weak

- Identical offer to yesterday's July 12 send; subscribers who opened that email have no new reason to act
- "LIMITED TIME" label in the hero with no visible end date — the urgency claim has no anchor
- No InCircle or member-tier callout; the gift card earn is a stronger hook when it's framed as a member benefit rather than a generic code
- Five CTAs carry equal visual weight with no hierarchy — there is no single primary action pulling the click

## Recommendations

- 1. **Put a real deadline in the hero.** "LIMITED TIME" with no date is decorative urgency. "Ends Tuesday" or a visible countdown would immediately sharpen the case to act now rather than tomorrow.
- 2. **Collapse five CTAs to one primary.** Pick the highest-converting category (Women's Clothing or Shoes) as the main button. Let the others live as text links below. Equal-weight buttons diffuse the click.
- 3. **Add an InCircle / loyalty tier hook.** A single line — "InCircle members: your earn counts toward your next status tier" — makes the offer feel exclusive and drives incremental basket size.
- 4. **Segment this resend to non-openers only.** Everyone who opened July 12's send is getting a near-identical email 24 hours later. Suppress the openers and reframe for the non-openers with a real deadline.
- **Subject Alt A:** `Ends midnight: earn up to $500 in gift cards`
- **Subject Alt B:** `Your gift card expires soon — $50 to $500 up for grabs`
- **Preheader Alt A:** `Spend $500, earn $50. Spend $1,000, earn $75. Tiers go up to $500 back.`
- **Preheader Alt B:** `Shop Jimmy Choo, Zimmermann & more — every dollar earns you a gift card.`

### 3. Rendering & Accessibility

**`maximum-scale=1` on viewport meta blocks user zoom.**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">
```
This prevents pinch-to-zoom on mobile, which fails WCAG 1.4.4 (Resize Text). Two alternative viewport tags are present but commented out — one of them (`user-scalable=no`) would be worse; the `width=device-width` variant without `maximum-scale` would be correct.

**Three conflicting viewport meta tags in source.** Two are commented out, but the commented-out variants (`width=320, initial-scale=0.29` and `width=1024`) signal unresolved responsive strategy debt. Not breaking, but increases maintenance risk.

**Hamburger nav uses CSS checkbox hack with `position: absolute`.** This pattern has known non-rendering in Outlook desktop and Outlook.com. If any subscriber opens on Outlook, the mobile nav degrades silently with no fallback visible in the truncated source.

**`p { margin: 0 auto; text-align: center; }` is a global reset.** This forces center-alignment on all paragraph elements, which will override any inline `text-align` on `<p>` tags throughout the email body in clients that load `<style>` blocks.

**No `role="presentation"` or `aria-hidden="true"` visible on layout tables.** Screen readers will attempt to interpret structural layout tables as data tables.

---

### 4. Personalization & Merge Tokens

**`@user` SHA-256 assignment is double-commented and likely unset.**

```html
<!--/* SET @user = HASHED_EMAIL_SHA256 */ -->
```

This line uses both an HTML comment (`<!-- -->`) and an AMPscript block comment (`/* */`), making it inert. The block header says "CHOOSE ONE SCENARIO BELOW" but no active scenario block is visible. If `@user` is referenced anywhere in the email body or tracking URLs for identity stitching or personalization, it will resolve as empty/null.

**Internal data model is exposed in HTML comment block.** The required-variables comment at the top leaks:
- Table names: `NM_Subscriber_New_Consolidated`, `NM_CRM_Feed`
- Field names: `EMAIL_ID`, `EMAIL_ADDRESS`, `uEm`, `cmdid`

This is visible to anyone who views source on the email. Not exploitable on its own, but provides reconnaissance into the Salesforce Marketing Cloud data model.

**`@uEm` and `@cmdid` sourced from `NM_CRM_Feed` via lookup.** If a subscriber's email is not present in `NM_CRM_Feed`, these lookups return empty string — verify that downstream uses of these variables have null-guards (e.g., `IIF(EMPTY(@uEm), ...)`) or the sends will silently produce malformed tracking parameters.

### 5. Compliance

**`List-Unsubscribe` header not captured.**
QA finding: `[WARN] List-Unsubscribe header not found`. This header is required by Gmail and Yahoo bulk sender policy (enforced February 2024 for >5k/day senders). Its absence — even if only undetected at the relay layer — should be confirmed against raw message headers before the next send.

**`List-Unsubscribe-Post` header not captured (RFC 8058).**
One-click unsubscribe (the `POST` method variant) is required by Gmail/Yahoo policy for bulk senders. If not present, Gmail will show a slower multi-step unsubscribe flow and may down-rank deliverability.

**SPF/DKIM authentication status unknown.**
`Authentication-Results` header not captured by AgentMail relay. Sending domain is `e.neimanmarcus.com` (subdomain). Cannot confirm SPF pass or DKIM signature validity from available data.
