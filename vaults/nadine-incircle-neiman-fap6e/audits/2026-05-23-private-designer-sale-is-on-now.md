# Private Designer Sale is on now!
**Score:** 8/10 · **Type:** Email audit · **2026-05-23**
## Executive summary

- This is the "Private Event" pivot in NM's Designer Sale campaign — which has been running since 5/17 and is now on its sixth consecutive send. The reframing is smart: calling it a "Private Event" adds a layer of exclusivity that the prior sends (5/22: "Summer-ready styles are going fast!") lacked. The promo code NMSALE and the legible deadline in the fine print (ends 6/1/26) make this more actionable than the previous urgency push.
- The problem is execution: there is zero product photography. The entire email is typographic — headline, offer, button, legal. For a brand that lives on aspiration and visual merchandising, this is a missed swing. The 5/21 "new arrivals" send scored 9/10 precisely because it showed a full product grid with recognizable brand logos. This one gives you nothing to want.
- The cadence is also taxing. Six Designer Sale emails in seven days trains subscribers to ignore or tune out. The "Private Event" repositioning is a smart tool for a mid-campaign refresh, but the creative needs product to justify opening the vault.

## What's working

- **"PRIVATE EVENT" framing is the right move** — elevates the same sale to feel exclusive and members-only, a genuine creative upgrade over the prior "styles are going fast" urgency beat.
- **Offer mechanics are airtight** — discount percentage (40%), promo code (NMSALE), and deadline (6/1/26, 10 PM CT) are all visible and specific.
- **Visual hierarchy lands** — the eye moves cleanly from PRIVATE EVENT → red 40% OFF → SHOP SALE; no clutter competes with the offer.
- **Clean render** — no broken images, no overlapping text, no lorem ipsum; looks exactly as intended.

## What's weak

- **No product photography** — six emails into the campaign and this one asks you to click on nothing but a headline. The 5/21 "1,000+ new arrivals" email showed grids of actual product; this one does not.
- **InCircle is invisible** — a "Private Event" is the perfect hook to surface loyalty exclusivity (early access, bonus points, member-only pricing tier), and NM left it completely out.
- **Deadline buried in legal gray text** — "Ends 6/1/26 at 10:00 PM CT" lives only in the fine print. Putting that date in the hero copy would add real urgency.
- **"Up to" undermines the promise** — "UP TO 40% OFF" means most items won't be 40% off; without a product anchor, the gap between the headline and reality feels wide.
- **Campaign fatigue is real** — this is the sixth Designer Sale email in seven days; the "Private Event" label helps but doesn't fully reset the signal.

## Recommendations

- 1. **Add product photography** — even a 2×2 grid of hero items (a bag, a shoe, a jacket, a beauty product) gives the reader something to covet. The 5/21 send proved this format converts.
- 2. **Surface the deadline in the hero** — move "Ends June 1" into the body copy, next to the promo code, not only in the fine print.
- 3. **Unlock the InCircle angle** — if this is a "Private Event," say "InCircle members: exclusive early access" or "Earn triple points this weekend." That earns the "Private" language.
- 4. **Sharpen the promo code placement** — "CODE | NMSALE" is easy to miss in the current sans-serif lockup; make it a boxed callout or pill so it reads as scannable shorthand.
- **Subject Alt A:** `Your private 40% off code is inside`
- **Subject Alt B:** `Members-only: Designer Sale ends June 1`
- **Preheader Alt A:** `Use code NMSALE — ends June 1 at 10 PM`
- **Preheader Alt B:** `Shop Valentino, Ferragamo, and more before it's over`

## Technical Audit

## Technical Audit — Neiman Marcus "Private Designer Sale is on now!"

**Sender:** NeimanMarcus@e.neimanmarcus.com | **ESP:** Salesforce Marketing Cloud (AMPscript)

---

### 1. Technical Summary

The email is a standard SFMC AMPscript send with no critical rendering failures, but it carries two high-priority compliance gaps (missing `List-Unsubscribe` headers) that violate Gmail/Yahoo bulk sender requirements, and an unresolved AMPscript scenario fork left in the template that creates ambiguity around the hashed-email variable.

---

### 2. Link & Tracking Issues

**28 tracking links** routed through a click-redirect domain — standard SFMC behavior, not actionable, but not auditable through the AgentMail relay.

**Plain-text body is 71.6% URLs** (2,470 of 3,450 chars). Spam filters (SpamAssassin, Proofpoint) penalize plain-text alternates that are almost entirely link strings. This is a common side effect of auto-generated plain-text from an HTML-heavy template. The plain-text version should be hand-crafted or stripped of bare tracking URLs.

No issues found with link structure in the visible HTML fragment.

---

### 3. Rendering & Accessibility

**Multiple commented-out `<meta name="viewport">` tags** remain in `<head>`:
```html
<!--<meta name="viewport" content="width=device-width, initial-scale=1, user-scalable=no" />-->
<!--<meta name="viewport" content="width=320, initial-scale=0.29">-->
<!--<meta name="viewport" content="width=1024">-->
```
These are dead code from prior template iterations. Not rendering-breaking but signal poor template hygiene.

**Two separate `<style>` blocks** — one for the main responsive layout (`max-width: 600px`) and one for product grid overrides (`max-device-width: 480px` / `520px`). The `max-device-width` descriptor is deprecated in the CSS spec; `max-width` is the correct replacement. Gmail on Android may not honor `max-device-width` media queries.

**`.ReadMsgBody` and `.ExternalClass` resets** are present — these target Outlook.com circa 2012 and are no longer needed. Not harmful, just legacy noise.

**`-webkit-animation: bugfix` iOS9 hamburger hack** is present. iOS9 is ~0.01% of traffic; this is dead weight.

**`<title>` tag has a trailing space**: `<title>Neiman Marcus </title>` — minor, but shows template sloppiness.

No `alt` text quality is assessable from the truncated source, but the presence of hamburger-nav interactive CSS suggests image-heavy layout; alt text coverage should be verified against the full source.

---

### 4. Personalization & Merge Tokens

**Unresolved scenario fork in AMPscript header comment:**

```html
<!--/* SET @user = HASHED_EMAIL_SHA256 */ -->
```

The template header documents two scenarios for `@user` — one using `EMAIL_ID` from a lookup, and one using `HASHED_EMAIL_SHA256`. The SHA256 scenario is wrapped in `/* */` inside an HTML comment (`<!-- -->`). SFMC's AMPscript processor ignores HTML comments, so this is inert at send time — but it indicates the template has an unresolved design decision. If the intent is to use a hashed email for downstream personalization or tracking, this block is never executed and the feature is silently absent.

**Active lookups confirmed:**
- `Lookup("NM_Subscriber_New_Consolidated", "EMAIL_ID", "EMAIL_ADDRESS", @email)` — subscriber ID
- `Lookup("NM_CRM_Feed", "uEm", "EMAIL_ADDRESS", @email)` — CRM segment field
- `Lookup("NM_CRM_Feed", "cmdid", "EMAIL_ADDRESS", @email)` — command/segment ID

Two separate DE lookups on the same email key (`NM_Subscriber_New_Consolidated` and `NM_CRM_Feed`) could be consolidated into a single lookup per send row if both DEs are joined in the sendable DE, reducing processing overhead.

`@refid = CONCAT(@base_refid, "")` — concatenating with an empty string is a no-op. If this is a placeholder for a suffix, it should be documented; otherwise remove it.

### 5. Compliance

| Check | Status | Evidence |
|---|---|---|
| `List-Unsubscribe` header | **MISSING** | QA: header not captured by relay |
| `List-Unsubscribe-Post` (RFC 8058) | **MISSING** | QA: one-click unsubscribe not supported |
| SPF/DKIM authentication | **UNKNOWN** | `Authentication-Results` not present in relay capture |
| Unsubscribe link in body | Not verifiable from truncated source | — |
| Physical mailing address | Not verifiable from truncated source | — |

**High priority:** Gmail and Yahoo have required `List-Unsubscribe` and `List-Unsubscribe-Post` headers for bulk senders (≥5,000/day) since February 2024. Missing these headers risks:
- Inbox placement demotion in Gmail
- Inability for recipients to use the native Gmail "Unsubscribe" button, increasing spam complaints
- Potential bulk sender policy violation flag

SFMC supports `List-Unsubscribe` injection via the send classification or a manual header addition in the Email Studio send properties. This should be confirmed in the account send configuration, not just the HTML template.

**Authentication-Results not captured** — the AgentMail relay did not surface SPF/DKIM pass/fail. Given the sending domain is `e.neimanmarcus.com` (a dedicated ESP subdomain), DKIM alignment is likely correct, but this cannot be confirmed from available data. Verify via a seed send to a Gmail account and inspect the "Original Message" headers.

### 6. Email-to-Site Continuity

28 tracking links were skipped by the probe. Without being able to resolve the redirect chain, UTM parameter coverage cannot be confirmed. Key questions that require a full link audit:

- Do all CTAs append `utm_source`, `utm_medium`, `utm_campaign`, and `utm_content`?
- Does `@refid` (the campaign reference ID) appear in link parameters for attribution?
- Do `cmdid` and `uEm` (CRM feed fields) surface in any personalized link parameters for 1:1 attribution?

The `@cmdid` / `@uEm` fields pulled from `NM_CRM_Feed` suggest segment-level personalization is intended; if these are not threaded into landing page URLs or onsite session capture, the CRM feed lookup cost has no downstream payoff.
