# 📣Time for an exclusive offer: how’s 20,000 points sound?
**Score:** 5/10 · **Type:** Email audit · **2026-09-28**
## Executive summary

- This is a straight-up points-for-registration send — register, stay 2 nights, get 20,000 bonus points, with a 60-day window ending October 13, 2026. It's clean and legible: one hero pool image, a clear 3-step earn structure, and a single repeated CTA ("Register in 1-Click"). No render bugs, no clutter.
- But subscribers have seen this exact play from IHG all year — a "register + stay = bonus points" mechanic recurs constantly (20K on 2026-08-06 and 09-05, 140K six times since July). At 20,000 points this is a smaller ask than the flagship 140K card pitches, which actually makes it feel like a lesser-tier offer being dressed up as "exclusive." The word "exclusive" in the subject line isn't backed up by anything in the body — there's no name, tier, or segment reference that makes it feel personal.
- Solid execution, tired mechanic, overclaimed subject. This lands mid-pack.

## What's working

- Hero visual (infinity pool at sunset) is well-chosen and on-brand for a travel rewards email.
- The 3-step "Earn in 3 easy steps" block makes the mechanic instantly scannable — no ambiguity about what to do.
- CTA button ("Register in 1-Click") is repeated twice and uses clear, specific verb+action copy.
- Deadline (October 13, 2026) is stated plainly near the top, giving credible urgency.
- Brand marks and hotel portfolio logos at the bottom reinforce trust/recognition without cluttering the primary message.

## What's weak

- "Exclusive offer" in the subject is not substantiated anywhere in the visible body — no member name, tier badge, or personalized reason this recipient specifically qualifies.
- 20,000 points reads as a downgrade after months of 140,000-point card pitches in the same inbox — no framing explains why this offer matters if you're not chasing the card.
- No fine print/terms are surfaced above the fold (only a small "terms and conditions" link) — feels like it's hiding qualifying details (which properties, elite tier requirements) until after the click.
- Layout is very text-and-button heavy after the hero; nothing visually distinguishes the actual point value (20,000) as a hero number the way better designed offer emails do.

## Recommendations

- 1. Make "exclusive" earn its keep — add a line like "Because you're a [Tier] member" or reference past stays; otherwise drop the word entirely, since IHG can't substantiate it and repeat subscribers will notice.
- 2. Give 20,000 points visual weight equal to the "140K" hero numbers IHG uses elsewhere — right now the number is buried in body copy rather than being the dominant visual element.
- 3. Add one line of context on point value (e.g., "enough for a free night at select hotels") so the offer feels concrete rather than abstract.
- 4. Vary the creative — three 20K/140K "register and stay" sends in under two months with near-identical layouts is cadence fatigue; a different visual template would help this one stand out.

- **Preheader Alt A:** `Register by October 13 — stay twice, earn big.`
- **Preheader Alt B:** `A quick 2-night stay unlocks 20,000 IHG points.`

## Technical Audit

1. Technical Summary
The email is a standard IHG ESP (Cheetah Digital/mc.ihg.com) template with functional tracking pixels and link redirects, but automated QA could not confirm unsubscribe compliance headers or authentication status, and two tracking assets have markup defects.

- No broken static links identified in the visible HTML source.

3. Rendering & Accessibility
- Image missing `alt` text: `src="https://pxl.mon-trk.com/954cb38e-4a43-4730-b327-6b102c213a01/532026/0037y00002BeqgfAAB"` — tracking pixel, low severity but should still carry `alt=""` for valid markup.
- Image missing `alt` text: `src="http://mi.ihg.com/p/up/2b47e4754a78cfd7/o.gif?mi_u=695150425&mi_ecmp=532026&9/28/2026 12:00:00 AM"` — same issue.
- The same `mi.ihg.com` pixel URL contains unencoded characters (raw `&` before non-entity params, and an unencoded space/colon in `9/28/2026 12:00:00 AM`), indicating a malformed query string from an unescaped date token in the tracking pixel — this is a template/build defect, not just a missing alt.

4. Personalization & Merge Tokens
- No unresolved merge tags (e.g. `%%FIRSTNAME%%`, `{{token}}`) visible in the truncated source.
- The malformed timestamp embedded in the `mi.ihg.com` pixel URL (`9/28/2026 12:00:00 AM`) suggests a merge/date-token that was concatenated into the URL without encoding — likely the same root cause as the broken pixel above.

5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- `List-Unsubscribe` header not found — one-click unsubscribe support cannot be confirmed from the captured headers. Note QA flags this may be a relay artifact (AgentMail may strip/not capture the header) rather than a sender-side omission.
- `List-Unsubscribe-Post` (RFC 8058) not found — same caveat applies.
- `Authentication-Results` header not found — SPF/DKIM/DMARC pass/fail status is unknown from this capture; cannot confirm authentication compliance either way.
- Recommend confirming these three headers at the raw MTA/SMTP layer (outside the AgentMail relay) before treating as a sender-side compliance gap.

6. Email-to-Site Continuity (UTM params, landing page alignment)
- Cannot assess: all outbound CTAs route through skipped tracking-redirect domains, so destination URLs and any UTM parameters are not visible in this capture.

7. Recommendations
- Fix the malformed `mi.ihg.com` tracking pixel URL — encode the date/timestamp value being concatenated into the query string (raw `&`, space, and `:` characters are invalid in a URL query).
- Add `alt=""` to both tracking pixels for valid markup (cosmetic, non-blocking).
- Serve the `mi.ihg.com` pixel over HTTPS; `http://` sources risk being blocked by mail clients enforcing mixed-content/TLS policies.
- Re-run header capture directly against the source SMTP transaction (bypassing the AgentMail relay) to get a definitive read on `List-Unsubscribe`, `List-Unsubscribe-Post`, and `Authentication-Results` before flagging as non-compliant.
- Manually resolve a sample of the 36 skipped tracking links to confirm final landing-page URLs and UTM parameter presence.
