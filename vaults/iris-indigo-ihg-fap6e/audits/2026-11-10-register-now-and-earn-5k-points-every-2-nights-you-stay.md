# Register now and earn 5K points every 2️ nights you stay
**Score:** 6/10 · **Type:** Email audit · **2026-11-10**
## Executive summary

- This is a clean, single-idea promo: "STAY 2 NIGHTS, EARN 5K POINTS" in a teal hero with a red "REGISTER IN 1-CLICK" button. The Hotel Indigo image below it gives the hero some warmth. The hierarchy works and the offer is easy to read. The render is small, so my read of the body copy is limited.
- It still feels like another points-bonus send. The brand history shows four sends of the 20,000-point offer (09-28, 10-05, 10-28, 11-04), and this one swaps in a 5K-per-2-nights mechanic. The mechanic is more interesting because it repeats, but it is harder to size up. The hero never says what 5K points is worth, and it doesn't show the cap or the total available.
- Nothing in the render is broken. The weak spots are a very long legal block, a long brand-logo wall and a generic "Make your points pile up on US and UK stays" headline. The email is competent but not personalized. I'd call it a 6.

## What's working

- The hero states one offer, "STAY 2 NIGHTS / EARN 5K POINTS", with a high-contrast red button.
- The three-step "Sign up today / Earn / Repeat" block explains the repeating mechanic simply.
- The CTA is repeated after the steps, so the reader doesn't have to scroll back up.
- The Hotel Indigo hero image breaks up the flat teal banner and adds some visual interest.
- The email gives a clear end date, December 31, 2026.

## What's weak

- No personalization appears in the hero, despite the "Iris" first-name subject lines in earlier sends.
- The offer is hard to value. 5K points every 2 nights has no cash equivalent and no stated maximum.
- The body copy is a dense paragraph with eligibility details (US/UK stays, brand list) tucked into small text.
- The logo wall and legal block take up well over half the scroll and push the real content to the top.
- The subject's "2️" keycap emoji looks glitchy, and the offer is a repeat of the same bonus-points theme.

## Recommendations

- 1. Put the value in the hero: "Earn up to X points, about $Y in free nights", with the cap stated.
- 2. Put the member's name and tier in the hero, for example "Iris, earn 5K points every 2 nights."
- 3. Trim the body to three bullets: eligible brands, regions, and the deadline.
- 4. Collapse the logo wall and move the legal text behind a "Terms" link.
- 5. Replace the keycap emoji with plain "2 nights".

- **Preheader Alt A:** `Register once and keep earning on every 2-night stay through Dec 31.`

## Technical Audit

## 1. Technical Summary
The email has a malformed T&C link (a double `??` in the query string, probed as 403) and a tracking pixel whose URL contains an unencoded date and uses plain `http://`. The QA run also flagged a raw `{C}` token. The compliance and authentication warnings come from the AgentMail relay not capturing headers, so they are inconclusive.

## 2. Link & Tracking Issues
- **Malformed query string (confirmed in URL):** both "terms & conditions" links use `.../member-offers/5k2n??cm_mmc=EMAIL-_-IHGOR-_-AMER-_-en-_-REV-_-FirstAidKit5K2N_20263053-_-SENDURLID-_-563316&mi_u=695150425&mi_ecmp=563316&trso=EMAIL_563316#terms`. The double `??` makes the first parameter parse as `?cm_mmc`, so campaign attribution may be lost or mis-keyed.
- **403 on T&C link (2 instances):** the QA probe got HTTP 403. ihg.com may be blocking the automated probe, so this is unconfirmed as a real user-facing failure. The `??` is a plausible cause and should be tested in a real browser.
- **Duplicate failing link:** the same URL appears twice, so a fix is needed in both places.
- **Unverified links:** 23 tracking/redirect links were skipped by the HTTP probe, so their destinations are not validated.
- **Insecure, malformed open pixel:** `http://mi.ihg.com/p/up/2b47e4754a78cfd7/o.gif?mi_u=695150425&mi_ecmp=563316&11/10/2026 12:00:00 AM`.
  - It uses `http://`, which may be blocked or rewritten by clients.
  - It has an unencoded date string with spaces and slashes appended as a bare query key. This looks like a date merge field left unencoded, and the URL is invalid.
  - Open tracking from this pixel is likely unreliable.
- **Second pixel:** `https://pxl.mon-trk.com/954cb38e-4a43-4730-b327-6b102c213a01/563316/0037y00002BeqgfAAB` carries a CRM contact ID (`003…` prefix) in the path. The QA tool flagged it for missing alt, which is expected for a pixel.

## 3. Rendering & Accessibility
- **Content before DOCTYPE:** `<div style="display:none;"> </div>` and comments precede `<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN"...>`. Content before the doctype can trigger quirks mode in some clients.
- **Broken CSS selector:** `ReadMsgBody { width: 100%; }` is missing its `.` prefix, so it is treated as an element selector and does nothing.
- **Pixel alt text:** both tracking images lack `alt`. Add `alt=""` and `width="1" height="1"` so screen readers skip them.
- **Subject line encoding:** the subject renders as "every 2️ nights". The `2` is followed by a stray variation selector (U+FE0F) without the keycap combiner (U+20E3), which can show as a blank or tofu glyph.
- **Present and fine:** `lang="en"`, a viewport meta tag, and web font fallbacks (`Montserrat, Arial, Helvetica, sans-serif`).
- The HTML was truncated, so body-level checks (alt on content images, button markup) could not be done.

## 4. Personalization & Merge Tokens
- **Raw `{C}` token (QA FAIL):** one raw token was found. The truncated source doesn't show where it sits, so I can't say whether it is visible copy or a CSS/MSO artifact. Search the full HTML for `{C}` and confirm it doesn't render.
- **Unresolved date field:** the open-pixel URL has the date value `11/10/2026 12:00:00 AM` appended unencoded (see §2). That is a merge value injected without URL-encoding.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe / List-Unsubscribe-Post (RFC 8058):** not found. The QA note says AgentMail may not relay these headers, so absence is **unconfirmed**. Verify against the raw message at the source.
- **Authentication-Results:** not captured. SPF, DKIM and DMARC are unknown from this data. From `IHGOneRewards@mc.ihg.com`, check the sending-domain records directly.
- **Visible unsubscribe link and postal address:** the truncated HTML doesn't show the footer, so I couldn't verify them.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Tracking scheme:** the links use IHG's own parameters (`cm_mmc`, `mi_u`, `mi_ecmp=563316`, `trso=EMAIL_563316`), not `utm_*`. This is consistent across links and the campaign ID `563316` matches the pixels. It is only a problem if downstream analytics expects `utm_*`.
- **`??` and the 403:** the malformed query string is the one concrete risk to attribution on landing, and the landing page itself could not be verified (403).
- **Per-recipient ID:** `mi_u=695150425` is a per-recipient identifier exposed in plain URLs, including any forwarded ones. This is a design note, not a defect.

## 7. Recommendations
1. Fix `5k2n??cm_mmc=` to `5k2n?cm_mmc=` in both T&C links, then retest in a real browser to separate a bad URL from bot blocking.
2. Move the open pixel to `https://` and URL-encode the date value, or remove the date parameter.
3. Add `alt=""` and explicit 1×1 dimensions to both tracking pixels.
4. Search the full HTML for `{C}` and remove or resolve it.
5. Move the hidden `<div>` and comments after the DOCTYPE, and change `ReadMsgBody` to `.ReadMsgBody`.
6. Replace the subject's `2️` with a plain `2`, or add U+20E3 to complete the keycap emoji.
7. Check `List-Unsubscribe`, `List-Unsubscribe-Post` and `Authentication-Results` on the original message rather than the relayed copy.
8. Probe the 23 skipped tracking links with a method that follows redirects, to validate their final destinations.
