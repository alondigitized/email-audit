# Now’s the time to get 100% more points 🙌
**Score:** 8/10 · **Type:** Email audit · **2026-07-01**
## Executive summary

- This is IHG One Rewards' third buy-points email in nine days — following the June 22 "💯 Special offer: Get 100% more points, Iris" and the June 29 "Extra points are calling, Iris ☎️" sends. The creative is nearly pixel-identical to the June 22 send: same three-step structure, same orange BUY NOW CTA, same 100% bonus hook. The mechanical execution is clean — no broken images, clear hierarchy, two prominent CTAs. But the send drops the one thing that made the earlier emails feel targeted: the recipient's name. "Iris" appeared in both prior subjects; it's gone here. For a subscriber who's already seen this offer twice, the fatigue is real and the missing personalization makes it feel like a blast.
- The email earns its keep on fundamentals — the offer is real and the layout is scannable — but IHG is burning list health by re-pitching the same promotion to the same audience with the same creative and no escalation or novelty. The June 22 email could have been the only send needed.
- Clear judgment: competent but over-deployed. The offer converts on brand trust alone, not on anything this particular execution did right.

## What's working

- **Clean three-step flow.** Buy → Get 100% more → Start planning is instantly readable on mobile; no cognitive load.
- **Dual above-fold CTAs.** One BUY NOW button appears before the three-step section; a second one closes it. Either scroll depth gets a tap target.
- **100% is a hard number.** "100% more points" in both the subject and hero copy is concrete — no vague "earn more" language.
- **No render bugs.** Hero image loads, brand grid loads, buttons display correctly, no overlapping elements.
- **Brand grid earns trust.** The hotel-brand mosaic (InterContinental, Kimpton, Crowne Plaza, etc.) at the bottom reinforces the network breadth and justifies why buying points is worthwhile.

## What's weak

- **Personalization dropped.** Both prior sends used "Iris" in the subject; this one doesn't. For an already-fatigued subscriber, losing the name makes the email feel like a list blast.
- **Third-strike cadence.** Nine days, three nearly-identical buy-points emails. No escalation in offer, no differentiated creative angle — the fatigue cost likely exceeds any incremental conversion lift.
- **Subject is a near-clone of June 22.** "Now's the time to get 100% more points 🙌" vs. "💯 Special offer: Get 100% more points, Iris." The offer framing is so similar that a subscriber who saved the June 22 email will feel misled.
- **No deadline in the email body hero.** The July 19 expiration appears only in body fine print, not in the hero. A countdown or expiry date in the headline would justify "Now's the time."
- **BUY NOW CTA is generic.** Every points-offer email from every loyalty brand uses this exact button. "Buy Points — Earn Double" would be more specific to the mechanic.

## Recommendations

- 1. **Put the deadline in the hero.** Change the headline from "This is your chance for 100% more points" to "Buy by July 19 — get 100% more points." One line, no ambiguity, the urgency lives where the eye lands.
- 2. **Add personalization back.** The name "Iris" should be in the subject. It was in both prior sends; its absence here signals a production slip, not a strategic choice.
- 3. **Escalate the offer or the frame.** If this is the third email on the same promotion, give subscribers a reason to care. Add a minimum purchase threshold callout ("Buy 50,000 → get 100,000"), or frame it as "final days."
- 4. **Make BUY NOW more specific.** "Double My Points" or "Buy Points — Get 100% Bonus" is still punchy but tells you what clicking does.
- 5. **Suppress recent openers / non-buyers.** If IHG has engagement data, the third send should go only to subscribers who didn't open or click the prior two — not the full list.
- **Subject Alt A:** `Iris, last chance: 100% points bonus ends July 19`
- **Subject Alt B:** `Buy 50K points, keep 100K — offer ends July 19`
- **Preheader Alt A:** `Double every point you buy before the deadline hits.`
- **Preheader Alt B:** `Your bonus points won't earn themselves — July 19 cutoff.`

## Technical Audit — IHG One Rewards "100% More Points" Email

### 1. Technical Summary
Email is sent via Points.com infrastructure (`points-mail.com`) using a standard XHTML 1.0 Transitional table layout. Three critical failures are present: the primary buy-points CTA returns HTTP 403, no unsubscribe mechanism exists in the body (CAN-SPAM violation), and authentication headers are unverifiable through the relay.

---

### 2. Link & Tracking Issues

**[FAIL] Primary CTA returns HTTP 403**
`https://ssogateway.points.com/SSOGateway/gateway.do?ssoProduct=buy_fasttrack&ssoSource=ihg&channel=SILK&ssoData=801a1cdf...`
The buy-points SSO gateway is returning 403. This may be IP-based blocking of the QA probe, but it could also indicate an expired or invalid `ssoData` token if the email was sent with static session credentials. Verify the SSO token lifecycle — if tokens expire before the offer end date, all CTAs in this send are broken for late openers.

**[FAIL] Privacy statement URL returns HTTP 403 — trailing period in URL**
`https://www.ihg.com/content/gb/en/customer-care/privacy_statement.`
The URL has a literal trailing period (`.`), which is a template authoring error. This will produce a 404/403 for any recipient who clicks the privacy link.

**[WARN] 29 tracking/click-redirect links skipped**
All click-through URLs appear to route through a redirect domain. Destination URLs and UTM parameters could not be verified by the QA probe.

**[NOTE] Font preconnect 404s are false positives**
`https://fonts.googleapis.com` and `https://fonts.gstatic.com` are `<link rel="preconnect">` hints, not navigable links. The QA probe HTTP-probing them as links is a tool artifact; no action needed.

---

### 3. Rendering & Accessibility

**[FAIL] 30+ images missing `alt` text**
Content images are missing `alt` attributes, including:
- `0612cf26-ec2e-4e9c-acd2-ad88a584c4d0.png` (hosted on `image.points-mail.com` — likely a hero or offer image)
- `603f2770-6bfd-45f6-8c2f-652bb772a282.png` (same CDN — likely secondary content image)
- `Shopping-cart-icon_1-IHG-email-template-new-2024-u...` (functional icon, needs descriptive alt)
- `star-icon_2-IHG-email-template-new-2024-update.png` (functional icon, needs descriptive alt)

Spacer GIFs (`spacer-IHG-email-template-new-2024-update.gif`) appear 28+ times and should use `alt=""` explicitly — omitting the attribute entirely causes some screen readers to announce the filename.

**[WARN] Empty `<title>` tag**
`<title></title>` — Some clients (notably Outlook web) display the title tag in the browser tab or message preview pane. Should be populated with a meaningful fallback.

**[PASS] Responsive CSS present**
`@media only screen and (max-width:599px)` breakpoint is implemented. MSO VML conditionals are present for Outlook image rendering.

---

### 4. Personalization & Merge Tokens

The SSO gateway URL includes a long `ssoData` hash that appears to be recipient-specific. If this is a static value baked into the template (rather than per-recipient merge), all recipients share the same session token — a potential security issue.

HTML source is truncated; cannot confirm whether any unresolved merge tokens (e.g., `{{FIRST_NAME}}`, `*|FNAME|*`) remain in the body. Manual inspection of the full source required.

---

### 5. Compliance

**[FAIL] No unsubscribe link found in body**
CAN-SPAM Section 5(a)(5) requires a functional opt-out mechanism visible in the email body. The QA check found none. If the unsubscribe mechanism is image-based (not text), it would be invisible when images are blocked — still non-compliant.

**[WARN] `List-Unsubscribe` header not detected**
RFC 2369 `List-Unsubscribe` header is absent (or not captured through the AgentMail relay). Gmail and Apple Mail use this header to surface native unsubscribe UI; its absence increases spam classification risk.

**[WARN] `List-Unsubscribe-Post` header not detected**
RFC 8058 one-click unsubscribe is not implemented. Google and Yahoo both require this for bulk senders (>5K/day) per their 2024 sender requirements.

**[WARN] SPF/DKIM authentication status unverifiable**
`Authentication-Results` header not captured through relay. Cannot confirm whether `points-mail.com` is an authorized sender for `ihg.com` via SPF/DKIM alignment.

---

### 6. Email-to-Site Continuity

Cannot verify UTM parameters on 29 tracked links because the QA probe skipped all redirect-domain URLs. Key questions to validate manually:

- The privacy URL (`privacy_statement.`) trailing-period bug means analytics for that link will be zero even if clicked.
