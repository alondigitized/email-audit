- There's nothing for a runner here. No performance angle, no mileage, no running-club hook. It's pure fashion.

- The preheader line is repeated almost word-for-word in the first line of the body copy. That wastes real estate.
- There's no sizing, availability, price or reviews. I can't tell whether this is a limited drop or a shelf item.

# Technical Audit: adidas, "Spots 🤝 Samba"

## 1. Technical Summary
The HTML source is mostly sound. It has `lang="en"`, a responsive media-query set and a `format-detection` meta tag. Confirmed defects are a missing plain-text part, four `http://` image sources plus an `http://` tracking image, and images without alt text. Compliance and authentication could not be verified, and the source was truncated, so footer, unsubscribe and CTA links were not inspected.

## 2. Link & Tracking Issues
- **17 tracking links not probed.** They are on click-redirect domains (QA: "17 tracking link(s) skipped"). Destination validity, redirect chains and landing status are unverified.
- **Insecure tracking image.** The image with alt-less `SxZUj4PYtglzTJ8dfCYwpzsNzTHONtJCWR4y-HHK9T8=452` is served over plain HTTP: `http://click.comms.adidas.com/CI0/010201a0f9ea1ff5-1e98eb8e-af14-4d8c-8bc1-7eda18d01024-000000/...`. Its path pattern suggests it is an open-tracking pixel. That is an inference, not confirmed by the QA output. If so, clients that block non-HTTPS content will drop it and under-report opens.
- **Mixed-content links.** The `click.comms.adidas.com` host is used with `http://`. Check whether the click-redirect links share this scheme. The QA run skipped them, so this is unconfirmed.

## 3. Rendering & Accessibility
- **Non-HTTPS images.** The `arrow` image (`http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg`) appears four times over `http://`. It may be blocked or flagged as mixed content in some clients. The same host likely serves `https://`.
- **Missing alt text.** The `dv.adidas.com/o/b32fbb66-8bc9-4346-829c-08828d7598aa?...` image has no alt attribute. Screen readers will announce the filename or URL, and with images off there is no fallback. The tracking image above also lacks alt text. Where an image is decorative, it needs `alt=""`.
- **Viewport meta.** `<meta name="viewport" content="initial-scale=1.0">` has no `width=device-width`. Some clients may not scale the layout as the `max-width:640px` and `639px` media queries intend.
- **Fonts.** The `@font-face` rules for `AdihausDIN` and `AdineuePRO` use only `local('Arial')`, `local('Helvetica')` and similar sources. No web font file is loaded, so rendering falls back to those system fonts. This is harmless but redundant, and it adds CSS weight.
- **Doctype.** The HTML 4.01 Transitional doctype is common in email and not a defect.

## 4. Personalization & Merge Tokens
No issues found in the visible source. No unresolved tokens such as `{{...}}`, `%%...%%` or `[FIRST_NAME]` appear. The truncated body was not scanned.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **No List-Unsubscribe header.** QA found none. The report says it may not be captured by the AgentMail relay, so this is unconfirmed rather than proven missing.
- **No List-Unsubscribe-Post header.** RFC 8058 one-click support is not evidenced. The same relay caveat applies. Gmail and Yahoo bulk-sender rules require one-click for large senders.
- **Authentication unverified.** `Authentication-Results` was not found, so SPF, DKIM and DMARC alignment could not be assessed. The sending domain is `us-news.comms.adidas.com`. Verify against raw headers from a direct inbox.
- **Footer not checked.** The visible in-body unsubscribe link and physical postal address could not be checked because the source was truncated.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Unverifiable. All 17 links are on tracking-redirect domains and the HTTP probe was skipped, so final URLs, UTM parameters and landing pages were not resolved. This is a gap in the tooling, not a confirmed defect.

## 7. Recommendations
1. **Add a plain-text part.** The QA FAIL shows 0 chars. This is the only hard FAIL. Confirm whether the relay is stripping it before treating it as an adidas defect.
2. **Serve all images over HTTPS.** Change `image.link.adidas.com` (the arrow) and `click.comms.adidas.com` (tracking image) to `https://`.
3. **Add alt text.** Give `dv.adidas.com/o/b32fbb66-...` a descriptive alt, or `alt=""` if decorative. Do the same for the tracking image.
4. **Update the viewport meta** to `width=device-width, initial-scale=1.0`.
5. **Improve audit coverage.** Capture raw headers (`List-Unsubscribe`, `List-Unsubscribe-Post`, `Authentication-Results`) from a direct inbox. Resolve the 17 redirect links with a redirect-following probe to check UTMs and destinations. Run the audit on the untruncated HTML.
