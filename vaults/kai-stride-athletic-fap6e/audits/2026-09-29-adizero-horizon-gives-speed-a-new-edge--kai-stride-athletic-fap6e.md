## Technical Audit

## 1. Technical Summary
The email has table-based markup with a `lang` attribute and responsive media queries, but the QA run failed on a missing plain-text part. It also found mixed-content (`http://`) images, including the open-tracking pixel, and missing alt text. Header-level checks (auth, unsubscribe) could not be verified.

## 2. Link & Tracking Issues
- **14 tracking links were not probed.** They are click-redirect domains (`click.comms.adidas.com`), so destinations and redirect chains are unverified.
- **The tracking pixel is served over plain HTTP.** The image `HvuvwHdH_j-5u0d4pgdJdQ15xdRjUHwHLnUtCWPILbc=452` loads from `http://click.comms.adidas.com/CI0/010201a0eab7e3bb-…`. Clients that block mixed content will drop it and under-report opens. The URL also leaks over an unencrypted channel.
- **The same `http://` problem affects a content image.** The "arrow" image `http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg` appears twice.
- `<meta name="referrer" content="no-referrer">` is set. It suppresses the referrer on outbound clicks and image loads, which can hurt attribution where clients honor it.

## 3. Rendering & Accessibility
- **Missing alt text on two images:**
  - `dv.adidas.com/o/0af15d91-e774-4c80-996a-bc80cc2e5689?cp_tp=…`
  - The tracking pixel above. An empty `alt=""` is acceptable for a pixel, but it is absent here.
- **The viewport meta is incomplete.** It is `<meta name="viewport" content="initial-scale=1.0">` with no `width=device-width`. The email relies on media queries (`max-width:639px`, etc.), and some mobile clients may not scale as intended.
- **The doctype is HTML 4.01 Transitional.** That is a common, low-risk choice for email, so it is not flagged as a defect.
- **Custom fonts have no real web-font source.** `@font-face` for `AdihausDIN` and `AdineuePRO` uses only `src: local('Arial')…`, so it falls back to system fonts. This is intentional-looking and low severity.
- The HTML source is truncated, so I can't verify the rest of the images, buttons or heading structure.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens (`%%…%%`, `{{…}}`) are visible in the truncated HTML.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **[FAIL] The plain-text alternative is 0 characters.** This hurts deliverability scoring and accessibility. It could be an ingestion artifact, but the QA data reports it as missing.
- **`List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) were not found.** The QA note says the relay may strip them, so treat these as unconfirmed rather than a sender defect. If they are genuinely absent, they matter for Gmail/Yahoo bulk-sender requirements.
- **`Authentication-Results` was not captured**, so SPF/DKIM/DMARC status is unknown. The sender domain is `us-news.comms.adidas.com`.
- The visible unsubscribe link and the physical postal address are not in the truncated HTML, so I can't confirm them.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not verifiable. The 14 links are wrapped in click-tracker redirects and were skipped, so I can't check final destinations, UTM parameters, or alignment with the Adizero Horizon subject line.

## 7. Recommendations
1. Serve the tracking pixel and the "arrow" image over HTTPS (`click.comms.adidas.com`, `image.link.adidas.com`).
2. Add `alt` text to the `dv.adidas.com` image. Add `alt=""` to the pixel.
3. Include a `text/plain` MIME part. First check whether the 0-char result comes from the AgentMail relay.
4. Capture the raw headers (`List-Unsubscribe`, `List-Unsubscribe-Post`, `Authentication-Results`) from the original message rather than the relay copy, so the compliance checks can be resolved.
5. Change the viewport meta to `width=device-width, initial-scale=1.0`.
6. Improve the QA pipeline so it resolves redirect chains for click-tracking domains. That would make UTM and landing-page checks possible.
