## Technical Audit — Michaels × Jonathan Adler Party Email (2026-05-19)

---

### 1. Technical Summary

The email is functionally deployable but has two HTTP image sources that will fail in modern clients, multiple tracking pixels without alt text, and authentication headers that are invisible to the relay — leaving SPF/DKIM verification status unknown.

---

### 2. Link & Tracking Issues

**21 tracking links unverified** — all click-through URLs route through `click.emdeals.michaels.com` (Salesforce Marketing Cloud redirect). Destination health could not be confirmed by probe; any broken landing pages would be silent.

**Pixel soup: 4 distinct tracking systems firing simultaneously:**
- `click.emdeals.michaels.com/open.aspx` (Salesforce open pixel)
- `na5.thunderhead.com/one/rt/track/ONE-PFSLHYI824-2685/pixel` (Thunderhead/One)
- `nova.collect.igodigital.com/c2/100010552/track_event` (iGoDigital/Salesforce CDP)
- `svopn.e.michaels.com/?sv_cid=0415_03847&sv_emopen=true` (SilverPop/Acoustic legacy pixel)

No functional bug, but the SilverPop pixel suggests a legacy system is still firing alongside SFMC — worth confirming this is intentional and not a vestigial tracking tag.

**`customerEmail` param is base64-encoded, not hashed** — visible in the `HEADER_HOME` link's `customerEmail=bWlyYS1nbGl0dGVyLW1pY2hhZWxzLWZhcDZlQGV0ZWxsLmFwcA==`. Base64 is trivially reversible; this is a PII exposure risk in forwarded emails and server logs.

---

### 3. Rendering & Accessibility

| Issue | Evidence |
|---|---|
| HTTP image source (content image) | `http://image.emdeals.michaels.com/lib/fe4015707564057d701173/m/1/e323ae89-6f89-4b47-8f9a-f33897013cd1.jpg` — will be blocked or flagged in Gmail, Outlook 365, and Apple Mail with "load images" prompts |
| HTTP tracking pixel | `http://svopn.e.michaels.com/?sv_cid=0415_03847` — same mixed-content block risk |
| 4 images missing `alt` text | Open pixel, Thunderhead pixel, iGoDigital pixel, SilverPop pixel — all have `alt=""` or no `alt` attribute; screen readers will announce the raw URL or "image" |
| `<!DOCTYPE>` placed mid-document | The `<!DOCTYPE HTML PUBLIC ...>` declaration appears *after* a `<table>` block, inside the body. This is invalid and triggers quirks mode in some clients |
| Duplicate `p { margin: 1em 0; }` rule | Defined twice in `<head>` styles — cosmetic redundancy, no rendering impact |
| `max-height: auto` | `max-height: auto` is not a valid CSS value (should be `none` or a length); used in `.fluid` mobile rule. Benign in practice but technically invalid |

### 5. Compliance

**`List-Unsubscribe` header absent** — not detected by the AgentMail relay. CAN-SPAM requires a functional unsubscribe mechanism; RFC 2369 `List-Unsubscribe` is the standard machine-readable form. Major ISPs (Gmail, Yahoo) use this header for their native unsubscribe UI — its absence increases spam folder placement risk.

**`List-Unsubscribe-Post` (RFC 8058) absent** — one-click unsubscribe not supported. Gmail and Yahoo have required this for bulk senders (>5k/day) since February 2024. This is a deliverability compliance gap if Michaels sends at that volume.

**`Authentication-Results` header not captured** — SPF, DKIM, and DMARC pass/fail status is unknown through the current relay. Cannot confirm the sending domain `emdeals.michaels.com` is properly authenticated. This should be verified directly via MX Toolbox or a raw header capture.

**Unsubscribe link** — an HTML unsubscribe link is present in the footer (standard SFMC footer pattern visible in the structure), satisfying the minimum CAN-SPAM requirement, but machine-readable headers are still missing.

---

**No issues found** with UTM structure. Landing page alignment cannot be verified without probing the 21 click URLs, which were skipped due to redirect domain policy.

### 7. Recommendations

| Priority | Action |
|---|---|
| **High** | Upgrade both HTTP image sources to HTTPS — `image.emdeals.michaels.com` and `svopn.e.michaels.com`. Mixed-content blocks will silently break images for a significant share of recipients |
| **High** | Add `List-Unsubscribe` and `List-Unsubscribe-Post` headers to the sending configuration (SFMC Sender Profile or Delivery Profile settings). Required for Gmail/Yahoo bulk sender compliance |
| **Medium** | Replace base64 `customerEmail` param with a one-way hash (SHA-256 + salt) in click URLs to eliminate PII leakage in forwarded email and CDN logs |
| **Medium** | Confirm whether the SilverPop/Acoustic pixel (`svopn.e.michaels.com`) is still intentional — if Michaels has fully migrated to SFMC, this is a stale tag adding a broken HTTP request |
| **Medium** | Capture raw `Authentication-Results` headers on next send to verify SPF/DKIM/DMARC status for `emdeals.michaels.com` |
| **Low** | Move `<!DOCTYPE>` to the top of the document, before any HTML output — current placement inside a table body is technically invalid |
| **Low** | Add empty `alt=""` explicitly to all tracking pixels (some already have it; ensure consistency for screen reader hygiene) |
