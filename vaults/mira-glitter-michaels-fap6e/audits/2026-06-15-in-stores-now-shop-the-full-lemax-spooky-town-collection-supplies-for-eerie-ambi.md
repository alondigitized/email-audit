- **Rich Lemax product imagery** — the haunted village pieces are atmospheric and instantly recognizable to collectors; no generic Halloween stock here.
- **Two-layer discount structure** — 25% off visible at the scroll top, 30% coupon mid-email, creates compounding purchase motivation without feeling contradictory.

- **Michaels Rewards "Earn $5" visible** — loyalty reinforcement for members at a natural mid-email pause point.

## What's weak

- **Subject is 90+ characters and uses "IN STORES NOW!" in all caps** — two spam-adjacent signals in the first four words; mobile clients truncate before you reach "Lemax."
- **June Halloween requires no acknowledgment** — the email never addresses why the fall collection is arriving in summer, which reads as tone-deaf to a non-collector subscriber who doesn't know this is Michaels' annual tradition.
- **Product grid is dense without a clear editorial hierarchy** — multiple Lemax SKUs compete equally; no "bestseller" or "staff pick" signal to guide the undecided buyer.
- **30% off coupon fine print is buried** — likely exclusion-heavy based on past Michaels sends; the offer visually appears generous but the qualifier context is not immediately readable at this resolution.

## Technical Audit

## Technical Audit — Michaels "Lemax Spooky Town" Email

### 1. Technical Summary

The email has a malformed document structure (content precedes `<!DOCTYPE>`), two HTTP-sourced images that will be blocked by modern clients, and compliance headers that are either absent or not captured by the relay. Four tracking systems are firing simultaneously, elevating plain-text URL density to 80%.

---

### 2. Link & Tracking Issues

**DOCTYPE out of order.** A `<table>` block containing `<!--MASTER_Coremetrics_SLPH_Content-->` appears *before* the `<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN">` declaration. This forces all clients into quirks mode before the document even begins, invalidating the DOCTYPE entirely.

**Invalid HTML elements.** Two `</custom>` closing tags appear immediately after the open-tracking pixel `<img>`:
```html
<img src="https://click.emdeals.michaels.com/open.aspx?A3T7WWZ5BY2EVBTLY4KCNFIGNU..." ...>
</custom>
</custom>
```
`<custom>` is not a valid HTML element; these are likely template artifacts that were not stripped at render time.

**21 click-tracking links unverifiable.** All links route through `click.emdeals.michaels.com` redirects. Destination URLs and redirect chain health cannot be confirmed programmatically. Manual spot-check of final destinations is required.

**Four concurrent tracking/analytics systems detected:**
- Coremetrics (IBM) — `click.emdeals.michaels.com/open.aspx`
- Thunderhead One — `na5.thunderhead.com/one/rt/track/ONE-PFSLHYI824-2685/pixel`
- iGoDigital/SFMC — `nova.collect.igodigital.com/c2/100010552/track_event`
- SilverPop beacon — `svopn.e.michaels.com/?sv_cid=0415_03847`

Multiple redundant systems each add latency and increase the URL character count in the plain-text version.

**Plain-text version is 80% URLs.** QA reports 24,620 of 30,924 plain-text characters are URLs. Spam filters (SpamAssassin, Gmail, Outlook) penalize plain-text parts where URL content dominates this heavily. The plain-text alternative likely needs to be authored separately rather than auto-generated from the HTML.

---

### 3. Rendering & Accessibility

**Two HTTP image sources** — will be blocked by Gmail, Outlook.com, Apple Mail, and most corporate clients that enforce HTTPS mixed-content policies:
- `http://image.emdeals.michaels.com/lib/fe4015707564057d701173/m/1/e323ae89-6f89-4b47-8f9a-f33897013cd1.jpg` (content image)
- `http://svopn.e.michaels.com/?sv_cid=0415_03847&sv_emopen=true&sv_svemi=...` (SilverPop open pixel)

**Four images missing `alt` text:**
| Image | src excerpt |
|---|---|
| Content image | `e323ae89-6f89-4b47-8f9a-f33897013cd1.jpg` (HTTP) |
| Thunderhead pixel | `na5.thunderhead.com/.../pixel?uri=outbound...` |
| iGoDigital pixel | `nova.collect.igodigital.com/.../track_event` |
| SilverPop open pixel | `svopn.e.michaels.com/?sv_cid=0415_03847` |

Tracking pixels should carry `alt=""` (empty, not absent) to suppress screen reader announcements. The content image missing alt text is a WCAG 1.1.1 failure.

**Invalid CSS property.** Mobile media query contains:
```css
img { max-height: auto !important; }
```
`max-height: auto` is not a valid CSS value (valid values are `<length>`, `<percentage>`, `none`, `max-content`, etc.). Browsers silently ignore this declaration. No functional breakage expected, but it indicates the stylesheet was not validated.

---

### 4. Personalization & Merge Tokens

Subscriber identity is encoded in link parameters rather than merge tokens, which is standard for SFMC/Coremetrics but creates two observable issues:

- `customerEmail=bWlyYS1nbGl0dGVyLW1pY2hhZWxzLWZhcDZlQGV0ZWxsLmFwcA==` — base64-encoded recipient email address is present in at least one link URL visible in the HTML source. Base64 is not encryption; the address is trivially recoverable.
- The Thunderhead pixel URL is truncated at `emailaddress%3DMIR` — the full email address appears to be appended to the pixel URL as a query parameter. If the full value renders in production, this transmits PII to a third-party domain (`thunderhead.com`) in a GET request, which may conflict with privacy policy commitments depending on jurisdiction.

No unresolved merge token placeholders (e.g., `{{FirstName}}`, `%%first_name%%`) are visible in the truncated source.

---

### 5. Compliance

**List-Unsubscribe header not captured** by the AgentMail relay. Gmail and Yahoo require this header for bulk senders (≥5K/day) as of February 2024. If the header is present at the MTA level but stripped by the relay, it is invisible to inbox providers reading the received message — functionally equivalent to absent.

**List-Unsubscribe-Post header absent (RFC 8058).** One-click unsubscribe (the machine-readable `POST` method required by Gmail/Yahoo bulk sender policy) is not confirmed present. Without it, Gmail shows a manual "Unsubscribe" flow rather than the one-click button, increasing friction and complaint risk.

**Authentication-Results header not found.** SPF, DKIM, and DMARC pass/fail status is unknown due to AgentMail relay not surfacing this header. Sending domain is `emdeals.michaels.com`; alignment between envelope-from, header-from, and DKIM `d=` tag cannot be verified from the captured source.

CAN-SPAM physical address and unsubscribe link are presumably present in the footer (not visible in the truncated source) — no finding here without the full HTML.

---

### 6. Email-to-Site Continuity

UTM-style parameter present in at least one link:
```
cm_mmc=EMAIL-_-Brand_Story-_-20260615_S2_SeasonalHalloweenLemax_FullLaunch_Story_FF_US-_-HEADER_HOME
```
This is Coremetrics `cm_mmc` attribution, not standard GA4 `utm_*` parameters. If the site also runs GA4, sessions from this email will not be attributed in GA4 unless a parallel `utm_source` parameter is present. Cannot confirm from the truncated source whether both are appended.

`sfmc_Sub` and `emId` subscriber tokens are appended to landing page URLs — these are SFMC click-tracking parameters and will appear in server logs and any analytics tools that capture the full query string, including the hashed subscriber ID.
