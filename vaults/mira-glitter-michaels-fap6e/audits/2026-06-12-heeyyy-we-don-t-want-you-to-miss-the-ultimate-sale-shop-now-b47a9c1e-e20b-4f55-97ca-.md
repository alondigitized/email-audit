# Heeyyy! 👋 We don’t want you to miss The Ultimate Sale. Shop now →
**Score:** 7/10 · **Type:** Email audit · **2026-06-12**
## Executive summary

- This is Michaels' attempt to inject some personality into what has become an almost daily "Ultimate Sale" drum-beat — the subject's chatty "Heeyyy! 👋" is clearly engineered to stand out from the inbox pile after days of near-identical blasts. But the email body immediately undermines that promise: it's the same wall-of-offers grid that's appeared in every send this week, stacking 40% off, 50% off, multiple BOGO tiles, 70% off, 60% off, and 30% off panels in a single vertical scroll. The tonal dissonance between the breezy subject and the overwhelmingly dense body is jarring.
- There's nothing wrong with individual components here — the 40% off coupon is prominent, the Michaels Rewards callout at the bottom is a solid retention touch, and the tiles render cleanly. The core problem is fatigue. Anyone who opened the June 10 "restock your craft stash" send (scored 7/10 in the audit history) is looking at essentially the same email for the fourth time in 48 hours. The "Heeyyy!" hook reads less like warmth and more like desperation.
- Judgment: a tired send dressed up in casual clothes. The offer stack is real but the execution is on autopilot.

## What's working

- **40% off coupon lands at the top** — it's the first value signal after the logo and immediately anchors the email.
- **Clean render** — all image tiles appear intact, no broken images or overlapping text visible in the screenshot.
- **Michaels Rewards / Earn $5 callout at the bottom** — a retention hook that rewards existing members and nudges non-members to join.
- **Multiple BOGO tiles** — Buy 1 Get 1 framing is high-perceived-value and eye-catching even in a dense grid.
- **70% off summer decor** — the deepest discount is visible and credible for a seasonal clearance push.

## What's weak

- **Subject-to-body tonal whiplash** — "Heeyyy!" promises a personal or surprising message; the body is the same tile grid as the last four sends.
- **No single hero product** — the email presents six or more distinct discount tiers simultaneously, giving the eye nowhere to land and diluting all of them.
- **Offer fatigue is real** — this is at minimum the 17th promotional email in roughly four days from this brand; the casual subject hook won't rescue a subscriber who is already tuning out.
- **No credible deadline** — "don't miss The Ultimate Sale" implies urgency but no end date or clock is visible, making the urgency hollow.
- **30% off section gets visually lost** — buried mid-scroll below several stronger offers, it adds noise without adding value.

## Recommendations

- 1. **Pick ONE hero offer and lead with it, full-width** — if 70% off summer decor is the real news, that should be the entire above-the-fold moment, not tile #4 in a grid.
- 2. **Add a visible end date** — "Sale ends Sunday" or a countdown widget would make the urgency in the subject line credible rather than performative.
- 3. **Match the subject's casual register in the body** — if you're going to open with "Heeyyy!", the first body copy should feel like a quick personal note, not a flyer.
- 4. **Suppress this segment if they opened the June 10 send** — subscribers who already engaged with the same offer don't need a fifth remind; suppress or send a different angle (e.g., "here's what's selling fast from The Ultimate Sale").
- 5. **Consolidate the offer tiers** — pick two max (e.g., 40% off everything + 70% clearance), cut the rest, give each breathing room.
- **Subject Alt A:** `40% off everything — this weekend only`
- **Subject Alt B:** `Your 40% off coupon expires soon, [first name]`
- **Preheader Alt A:** `Plus 70% off summer decor while it lasts.`
- **Preheader Alt B:** `This is the deepest discount we've run all season.`

## Technical Audit — Michaels "Ultimate Sale" Email (2026-06-12)

### 1. Technical Summary

The email is a Salesforce Marketing Cloud / Coremetrics-tracked send from `emdeals.michaels.com` with multiple third-party pixel integrations. Core rendering stack is functional, but there are confirmed HTTP mixed-content issues, invalid HTML elements, and compliance header gaps that warrant fixes before future sends.

---

### 2. Link & Tracking Issues

**22 click-redirect URLs unprobed** — all route through `click.emdeals.michaels.com/?qs=...` (SFMC encoded links). Destination integrity cannot be verified without decoding.

**Open pixel** — `https://click.emdeals.michaels.com/open.aspx?DXTF4NMWXZWEPDN2EDJRLGFN3A.100214` — HTTPS, standard.

**Three additional tracking pixels active:**
- Thunderhead ONE: `https://na5.thunderhead.com/one/rt/track/ONE-PFSLHYI824-2685/pixel`
- iGoDigital/SFMC Collect: `https://nova.collect.igodigital.com/c2/100010552/track_event`
- Sievert: `http://svopn.e.michaels.com/?sv_cid=0415_03847` — **HTTP only** (see §3)

**PII in click URL parameters** — the header logo link encodes the recipient address as base64 in `customerEmail`:
```
customerEmail=bWlyYS1nbGl0dGVyLW1pY2hhZWxzLWZhcDZlQGV0ZWxsLmFwcA==
```
This decodes to the persona inbox address. Base64 is not encryption; the address is recoverable from server logs and any intermediary proxy. This is a common SFMC pattern but is worth flagging for compliance review if PII-in-URL is restricted.

### 3. Rendering & Accessibility

**HTTP image sources (will be blocked by Gmail, Outlook.com, Apple Mail):**
- `http://image.emdeals.michaels.com/lib/fe4015707564057d701173/m/1/e323ae89-6f89-4b47-8f9a-f33897013cd1.jpg` — a content image, not a tracking pixel. Will render as broken image in modern clients over HTTPS.
- `http://svopn.e.michaels.com/?sv_cid=0415_03847&sv_emopen=true&...` — Sievert open-tracking pixel over HTTP.

**Missing `alt` text on content image:**
```
src: http://image.emdeals.michaels.com/...e323ae89-6f89-4b47-8f9a-f33897013cd1.jpg
```
Tracking pixels missing `alt=""` (empty string) is expected but flagged by the QA checker; those are lower priority than the content image.

**Invalid HTML elements — `</custom>` tags:**
```html
<img src="https://click.emdeals.michaels.com/open.aspx?..." width="1" height="1" alt="">
</custom>
</custom>
```
Two orphaned `</custom>` closing tags immediately after the open pixel. Not a valid HTML element; likely a legacy SFMC template artifact. Most clients ignore them, but strict XML-mode parsers (some corporate email gateways) may reject the document.

**Malformed comment at document top:**
```html
<!-- <!-- -->
```
Nested comment open — invalid in HTML. Browsers and email clients handle this inconsistently; it should be cleaned up.

**Invalid CSS value:**
```css
max-height: auto !important;
```
`auto` is not a valid value for `max-height` (valid: `none`, a length, or a percentage). Most clients silently ignore it, but it is a spec violation and could behave unexpectedly in WebKit renderers.

**Duplicate CSS declaration:**
`p { margin: 1em 0; }` appears twice in the same `<style>` block. No functional impact, but indicates template hygiene issues.

### 5. Compliance

**`List-Unsubscribe` header — not confirmed.** QA relay did not capture it. If absent at the MTA level, Gmail and Yahoo will not render the native unsubscribe UI, and the send will violate Google/Yahoo bulk sender requirements (mandatory for >5k/day senders since Feb 2024).

**`List-Unsubscribe-Post` (RFC 8058) — not confirmed.** Required for Gmail one-click unsubscribe compliance alongside the standard header.

**`Authentication-Results` header — not captured.** SPF/DKIM pass/fail status unknown. Sending domain is `emdeals.michaels.com`; DMARC alignment cannot be confirmed from available data.

**Plain-text body is 82% URLs** (31,019 of 37,708 chars). This is a strong spam-filter signal. The plain-text part is almost certainly auto-generated from the HTML with no editorial pass, resulting in a near-URL-only body. Spam filters (SpamAssassin, Proofpoint) penalize this pattern.

**CAN-SPAM physical address** — not visible in the truncated source. Must be present in the email footer; cannot confirm from available HTML.
