# The Thanksgiving Shop is open 🍁
**Score:** 5/10 · **Type:** Email audit · **2026-09-27**
## Executive summary

- This is Pottery Barn's cleanest seasonal-hub execution yet in this run — "GIVE THANKS" leads with a set Thanksgiving dining table on dark charcoal paneling, a legible "SHOP THANKSGIVING" button, and immediately underneath, a one-line mission statement ("Find all the essentials to decorate, serve, and host a memorable Thanksgiving meal"). Unlike the 9/25 "Holiday Headquarters" email that spread three occasions across one send, this one commits fully to Thanksgiving, then organizes the crawl into three clear categories (Tabletop, Decor, Dining Furniture) with dark overlay labels — the most disciplined visual hierarchy I've seen from this brand.
- Where it loses points is length and repetition after the fold: the email runs through a Thanksgiving hosting guide, the Caterer's Box, a "Recommended Just For You" grid, then pivots hard into Halloween and Design Services — undercutting its own single-occasion focus by the bottom third. It's a strong top and a bloated middle-to-end.
- Overall this is a top-tier hero for Pottery Barn but a mediocre full-email experience — score reflects the split.

## What's working

- Hero image is a fully set, styled Thanksgiving table — instantly on-theme, no stock-photo feel.
- "SHOP THANKSGIVING" is a high-contrast white button on dark wood, unmissable and unambiguous.
- Three-category crawl (Tabletop, Decor, Dining Furniture) uses consistent dark-label-on-photo treatment — visually cohesive, easy to scan.
- No render bugs — all images load cleanly, text is crisp, no overlap.
- "Serve up to 12 guests" Caterer's Box banner adds a concrete, relevant sub-offer for hosting-season shoppers.

## What's weak

- No discount or price anchor visible anywhere in the email — every prior PB send in this history at least had a starting price or % off; this one is pure catalog browsing.
- The email sprawls into unrelated modules (Halloween Shop, Free Design Services, curtain rods, bed frames) that dilute the Thanksgiving focus established in the hero.
- "Recommended Just For You" grid feels generic/algorithmic (curtain hardware, ghost decor, a bed) rather than curated for a Thanksgiving-shopper mindset.
- Preview text is missing/not visible — appears to just be the "Discover 1400+ New Arrivals" nav bar, not real preheader copy.

## Recommendations

- 1. Add one concrete offer near the hero (e.g., "Free Shipping on Tabletop" or a specific % off dinnerware) — every high-performing promo email in this history has this, and this one is the outlier without it.
- 2. Cut the Halloween Shop and Free Design Services blocks from this send, or move them into a separate email — they contradict the Thanksgiving-only positioning the hero sets up.
- 3. Replace "Recommended Just For You" with Thanksgiving-adjacent picks only (serveware, linens, centerpieces) to keep relevance through the full scroll.
- 4. Write real preheader copy instead of leaving the nav bar as the de facto preview.

## Technical Audit

1. Technical Summary
Standard ExactTarget/Salesforce Marketing Cloud transactional template with heavy tracking instrumentation; primary compliance concerns are missing unsubscribe headers and widespread mixed-content/accessibility gaps.

2. Link & Tracking Issues
- All navigational links route through `click.e.potterybarn.com` redirect wrapper (e.g., `https://click.e.potterybarn.com/u/?qs=ABB7...`) — standard ESP click-tracking, not flagged as an issue itself.
- 53 tracking/click-redirect links were skipped by automated HTTP probing (expected behavior for redirect-domain links, not a defect).
- Multiple open-tracking pixels present: `d.turn.com/r/dd/...`, `svopn.potterybarn.com/?sv_cid=0053_00597&sv_emopen=true&sv_sveme=lila-hearth-potterybarn-fap6e@etell.app`, `clickcp.potterybarn.com/o/...`. The `svopn.potterybarn.com` pixel is served over plain `http://` (see Rendering section).
- Recipient email address (`lila-hearth-potterybarn-fap6e@etell.app`) is embedded in cleartext in at least two tracking pixel URLs (`svopn.potterybarn.com` open pixel and `coreemail.html?email=...`), and again in the customer-service link query string.

3. Rendering & Accessibility
- Two images loaded over insecure `http://`, which will be blocked or flagged by modern mail clients (Gmail, Outlook) enforcing mixed-content/TLS policies:
  - `http://edm.potterybarn.com/pb/thekey/CC_Banner/PB/Foot_NonMem_PB.jpg`
  - `http://edm.potterybarn.com/pb/2022/0311_Key_CC_Email_BrandBanner/slices_02.jpg`
- 40+ `<img>` elements missing `alt` attributes (full list in QA data), including all primary content slices (`slices_01.jpg`–`slices_18.jpg`) and product images (e.g., `cayman-platform-bed-1-l.jpg`, `banks-extendable-dining-table-76-128-1-l.jpg`). Screen readers and blocked-image fallback views will render these as unlabeled.
- Stray `<style>` block contains raw PHP-style `header()` calls (`header('Content-Type: image/jpeg'); ...`) inside a CSS `<style>` tag — inert as CSS but indicates a templating/build artifact leaked into markup; some mail clients may render this as visible text if CSS parsing fails.
- `<title></title>` is empty — no fallback text for browser tab / webmail list rendering.
- `@media` breakpoints target both 650px and 700px with overlapping/redundant `img {max-width}` rules — not a functional bug but a maintenance smell (duplicate rule wins by cascade order, no visible defect confirmed).

4. Personalization & Merge Tokens
- No unresolved merge tags (e.g., `%%FIRSTNAME%%`, `{{token}}`) found in the visible source truncation.
- Recipient identifier is passed as a literal, resolved email address in tracking/pixel URLs rather than an opaque token — a data-hygiene observation, not a rendering defect.

5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- `List-Unsubscribe` header: not found by QA scan. Note caveat: may be a relay-capture limitation (AgentMail) rather than confirmed absence at the source — cannot confirm sender omitted it.
- `List-Unsubscribe-Post` header (RFC 8058, one-click unsubscribe): not found — same relay caveat applies.
- `Authentication-Results` header (SPF/DKIM/DMARC): not found — cannot verify authentication status from this data; flagged as unknown, not failing.
- In-body unsubscribe/customer-service link present: `https://www.potterybarn.com/customer-service/coreemail.html?email=lila-hearth-potterybarn-fap6e@etell.app` — uses HTTPS, satisfies CAN-SPAM's requirement for a functioning opt-out mechanism in the body regardless of header status.

6. Email-to-Site Continuity (UTM params, landing page alignment)
- Primary navigation and CTA links use the `click.e.potterybarn.com` ExactTarget redirect wrapper with an opaque `qs=` payload rather than visible UTM parameters — cannot confirm final landing-page UTM tagging from the truncated source; destination parameters are resolved server-side after redirect.
- No UTM query parameters (`utm_source`, `utm_campaign`, etc.) are visible on any link in the provided HTML — either stripped for this truncated excerpt or embedded in the opaque redirect token; indeterminate from available evidence.

7. Recommendations
- Migrate the two remaining `http://` image sources to `https://` to prevent mixed-content blocking in Gmail/Outlook.
- Add descriptive `alt` text to all content and product images, particularly the numbered `slices_NN.jpg` banner segments and named product shots — currently zero accessibility fallback for blocked-image or screen-reader views.
- Remove the orphaned PHP `header()` call block from the `<style>` tag — build/templating leak with no functional purpose in the shipped HTML.
- Populate `<title>` with descriptive text for tab/webmail-list rendering.
- Confirm independently (outside this relay) that `List-Unsubscribe`/`List-Unsubscribe-Post` headers and SPF/DKIM/DMARC pass at the raw SMTP layer, since AgentMail capture is a known blind spot here.
