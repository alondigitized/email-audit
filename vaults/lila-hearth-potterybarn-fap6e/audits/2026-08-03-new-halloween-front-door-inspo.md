# NEW 🎃 Halloween front door inspo
**Score:** 8/10 · **Type:** Email audit · **2026-08-03**
## Executive summary

- This is Pottery Barn's most tightly art-directed Halloween send of the recent stretch — a single "front door" concept carried end-to-end through five sequential decor vignettes (ghosts, jack-o'-lanterns, wreaths, a harvest table) before pivoting into the standard "Recommended For You" grid. Visually it's the strongest execution since 2026-08-01's indigo story: warm, muted palette (cream, black, terracotta), no clashing seasonal clip-art, real styled porches instead of stock Halloween kitsch.
- The catch is there's no offer anywhere in the hero or shop sections — this is a pure inspiration/catalog play, not a sale. Compare to 2026-07-31's "Welcome to Holiday HQ 🎃🦃🎄," which already used the pumpkin emoji to open the seasonal-prep hub; this send arrives three days later re-covering the same Halloween beat with a narrower "front door" lens. It reads as a content refresh, not a new campaign.
- Verdict: beautifully produced, on-brand, and easy to browse — but it's a lookbook email with zero urgency or price hook, so it'll perform on brand affinity and aesthetics alone, not on conversion pressure.

## What's working

- The hero image (styled porch with white ghost lanterns and pumpkins) is genuinely arresting and immediately legible as "Halloween decor inspiration," not a generic new-arrivals shot.
- Every section pairs a lifestyle photo with 1-2 shoppable products directly below it ("Lit Ghost Collection," "Terracotta Cutout Pumpkin," "Faux Leaf and Berry Wreath") — browsing-to-shopping friction is low.
- The black "Halloween Headquarters" banner breaks up the product-grid monotony and gives a clear secondary CTA into a guide.
- Consistent typography and color story from top to footer — no jarring seasonal-clipart moment that clashes with the brand's usual restraint.
- Clean render: no overlapping text, broken images, or layout breaks anywhere in the scroll.

## What's weak

- No offer of any kind in the shoppable sections — no %/$ off, no bundle price, nothing beyond the standard 10%-back credit card mention in the footer.
- No urgency signal — nothing suggesting "shop before Halloween sells out" or a delivery-by-date cue, despite this being seasonal inventory.
- Repeats the same Halloween beat 2026-07-31's "Holiday HQ" send already opened three days prior — cadence is starting to feel like the brand is circling the same seasonal moment rather than escalating it.
- "RECOMMENDED JUST FOR YOU" grid (curtain rods, a platform bed, a dining table) is a jarring tonal break after five straight Halloween vignettes — it reads bolted-on rather than personalized.
- No reviews, ratings, or social proof anywhere near the featured Halloween products.

## Recommendations

- 1. Add a concrete offer line under the hero (e.g., "20% off Halloween Decor" or "New arrivals, up to 25% off") — right now there's no reason to act today versus bookmarking for later.
- 2. Insert a light urgency cue near "SHOP ALL HALLOWEEN" — a ship-by date or "while supplies last" would convert browsing into checkout.
- 3. Either cut the "Recommended Just For You" block for this send or reframe it as "Complete the Look" with fall/harvest-adjacent items instead of a bed and dining table — the tonal whiplash undercuts the cohesive styling above it.
- 4. Differentiate this from the 7/31 Holiday HQ send explicitly — lean harder into "front door" as a distinct sub-theme (curb appeal, first impression) rather than general Halloween decor, so subscribers don't feel like they're rereading the same email.

## Technical Audit

## Technical Summary
The email is a standard MIME/XHTML transitional template using an ESP click-tracking wrapper (click.e.potterybarn.com / clickcp.potterybarn.com), but ships with pervasive missing `alt` attributes, several `http://` image sources, and a block of invalid/leaked server-side code embedded in the `<style>` tag.

## 2. Link & Tracking Issues
- All primary links route through opaque ESP redirect wrappers (`click.e.potterybarn.com/u/?qs=ABB7...`, `clickcp.potterybarn.com/o/ed542cdf-...?mi_mid=...`), so final destination URLs cannot be verified from source — QA skipped HTTP probing on all 55 tracking/redirect links (`INFO: 55 tracking link(s) skipped`).
- Multiple open-tracking pixels present: `http://svopn.potterybarn.com/?sv_cid=0053_00597&sv_emopen=true&sv_sveme=lila-hearth-potterybarn-fap6e@etell.app` and `https://clickcp.potterybarn.com/o/ed542cdf-4148-47ee-9a95-092b0471bd9a?mi_mid=...`.
- Third-party ad-tech pixel loaded from `d.turn.com/r/dd/id/L21rdC84NjEvY2lkLzE3NDc3ODk3MzMvdC8y/cat/1` (Amobee/Turn) — cross-domain conversion tracking, outside the ESP's own domains.
- The `sv_sveme` open-tracking pixel is served over **plain HTTP**, not HTTPS (see Compliance/Rendering below).

## 3. Rendering & Accessibility
- **43 images missing `alt` text** per QA output (hero banner, all `slices_XX.jpg` product tiles, footer banners, tracking pixels). Screen readers will announce nothing or fall back to raw filenames/URLs for these.
- **4 image sources use `http://` instead of `https://`**: `edm.westelm.com/we/evergreen/spacer_0.gif`, `edm.potterybarn.com/pb/thekey/CC_Banner/PB/Foot_NonMem_PB.jpg`, `edm.potterybarn.com/pb/2022/0311_Key_CC_Email_BrandBanner/slices_02.jpg`, and the `svopn.potterybarn.com` open-tracking pixel. Mixed content may be blocked or flagged by mail clients that enforce TLS.
- Invalid markup: the second `<style>` block in `<head>` contains literal PHP code fragments — `header('Content-Type: image/jpeg'); header("Cache-Control: ...`. This is not valid CSS and appears to be leaked server-side template code that was never stripped before send. It's inert in rendered HTML but is a build/pipeline defect worth flagging to the ESP.
- External stylesheet dependency: `<link href="https://fonts.googleapis.com/css2?family=Montserrat&display=swap" rel="stylesheet">` — most major mail clients (Outlook desktop, Gmail app, Yahoo) strip or block external `<link>` stylesheets, so this font will silently fail to load in a large share of clients; no fallback font-family is declared alongside it in the excerpt shown.
- `<meta name="viewport" content="width=320, initial-scale=0.29">` and `content="width=1024"` variants are present but commented out — dead code, not a functional bug.

## 4. Personalization & Merge Tokens
- Recipient email is passed in cleartext as a URL query parameter in at least two places: `https://www.potterybarn.com/customer-service/coreemail.html?email=lila-hearth-potterybarn-fap6e@etell.app` and `sv_sveme=lila-hearth-potterybarn-fap6e@etell.app` (the latter over unencrypted HTTP). This exposes the subscriber's email address in browser history, server logs, and any referrer chain, and combined with the plain-HTTP pixel, in transit.
- No unresolved/broken merge tags (e.g. `{{first_name}}`, `%%EMAIL%%`) were found in the visible source.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- `List-Unsubscribe` header not detected and `List-Unsubscribe-Post` (RFC 8058 one-click unsubscribe) not detected in the captured headers. QA flags these as **relay-limited warnings** ("may not be captured by AgentMail relay"), so this is not confirmed as a sender-side omission — recommend verifying against raw headers from a direct SMTP capture rather than the relay.
- `Authentication-Results` header (SPF/DKIM/DMARC status) not present in the captured headers, same relay caveat applies — sender authentication status is unverified, not confirmed failing.
- No visible unsubscribe link/footer text in the truncated HTML source provided; cannot confirm CAN-SPAM footer compliance (physical address, unsubscribe mechanism) from the excerpt.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- Cannot verify UTM parameter presence or landing-page alignment: every outbound link is wrapped in an opaque ESP redirect (`click.e.potterybarn.com/u/?qs=<base64/opaque token>`), and QA explicitly skipped these 55 links rather than resolving final destinations. No raw `potterybarn.com` product/category URLs with UTM parameters are exposed in source.
- One direct (non-wrapped) link to the site does appear — `https://www.potterybarn.com/customer-service/coreemail.html?email=...` — but it carries no UTM/campaign parameters, only the PII email parameter noted above.

## 7. Recommendations
1. Strip the leaked PHP `header()` code fragment from the `<style>` block in `<head>` — it's a template/build pipeline defect, not intentional markup.
2. Add descriptive `alt` text to all content images (currently 43 flagged) and empty `alt=""` to purely decorative spacers/pixels for screen-reader compliance.
3. Migrate remaining `http://` image and pixel sources (`edm.westelm.com`, `edm.potterybarn.com/pb/thekey`, `edm.potterybarn.com/pb/2022`, `svopn.potterybarn.com`) to HTTPS to avoid mixed-content blocking and unencrypted PII transmission.
4. Stop passing raw recipient email addresses as URL query parameters (`email=`, `sv_sveme=`), especially over plain HTTP — use a hashed/opaque subscriber ID instead.
5. Re-verify `List-Unsubscribe`/`List-Unsubscribe-Post`/`Authentication-Results` against a direct header capture (not the AgentMail relay) before treating their absence as a compliance gap.
6. If UTM/landing-page auditing is required going forward, resolve the ESP redirect wrappers (or request unwrapped URLs from the sender) so link destinations can be probed.
