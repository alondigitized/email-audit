# Pull up a chair—new dining tables are here
**Score:** 5/10 · **Type:** Email audit · **2026-08-14**
## Executive summary

- This is Pottery Barn's dedicated dining-table launch — "Most-Loved Dining Tables" hero, then four named tables (Summerville, Rigato, Radcliffe, Toscana) each with a moody, well-styled lifestyle shot, a one-line material/use-case description, and a Shop Now link. It's a clean, category-focused execution, closer in spirit to the vase send (2026-08-12, 6.00/10) than the sprawling catalog dumps — one product family, told with some editorial restraint.
- The problem is depth without direction: four nearly-identical wood dining tables get four nearly-identical treatments, and nothing tells me which one to actually want. There's no price on any of them, no "seats 4/6/12" comparison at a glance (it's buried in prose), and no urgency or offer anywhere in the hero. After the tables, it tips right back into brand-wide filler — accessory categories, "Recommended Just For You," Halloween Shop, Design Crew sweepstakes — diluting what could've been a tight, high-intent seasonal send.
- Solid photography, weak conversion mechanics. This lands mid-pack — respectable but not a click magnet.

## What's working

- Clear single-category focus: four dining tables, each with its own hero image, name, and short descriptor — easy to scan.
- "NEW" and "BESTSELLER" badges give quick signal on which tables are fresh vs. proven.
- Each table description names a concrete differentiator (trestle base for legroom, seats-up-to-12, three sizes/six finishes) rather than generic copy.
- Styling is consistent and seasonally appropriate — warm, autumnal tablescapes that fit an August-to-fall hosting narrative.
- No render bugs — images, buttons, and text all display cleanly.

## What's weak

- Zero pricing anywhere in the table section — for furniture, that's the single biggest purchase-decision blocker, and it's absent for all four products.
- No offer or urgency of any kind — this is a pure browse email with no reason to act today.
- Four tables in a row with almost identical shot composition (wood table, dining chairs, neutral room) makes it easy to skim past all of them without registering a favorite.
- "Shop the Look" vs "Shop Now" vs "Shop All Dining Tables" — inconsistent CTA copy across the same product grid.
- Post-table content (accessories grid, recommended products, Halloween Shop, Design Crew sweepstakes) is generic brand filler that dilutes an otherwise focused send — same complaint as the entryway styling guide (2026-08-13, 6.00/10).

## Recommendations

- 1. Add starting prices under each table name — "from $X" is the single highest-leverage fix; furniture buyers won't click through four products blind.
- 2. Cut the send to the four tables + one clear "Shop All Dining Tables" CTA, and move Buffets/Chairs/Dinnerware/Linens and "Recommended Just For You" into a separate, focused hosting-accessories send.
- 3. Add a light urgency or incentive hook specific to this category — e.g., free swatches, white-glove delivery timing before hosting season, or a limited-time credit-card financing callout (Affirm is already mentioned lower in the email — pull it up near the tables).
- 4. Standardize CTA copy to one verb across all four products ("Shop Now" everywhere, not a mix with "Shop the Look").
- 5. Differentiate the four table images more — vary camera angle or room style so each table reads as a distinct choice rather than a repeated template.

- **Subject Alt B:** `New dining tables, from $[X]`
- **Preheader Alt A:** `4 new tables, six finishes, and a season of hosting ahead`
- **Preheader Alt B:** `Trestle, farmhouse, or bestseller — pick your table`

## Technical Audit — Pottery Barn "Pull up a chair—new dining tables are here"

**1. Technical Summary**
Email uses a standard MSO/Outlook-hardened HTML table layout with heavy inline styling; automated QA found no broken links but flagged missing alt attributes across nearly all images, several HTTP (non-TLS) asset/tracking sources, and absent unsubscribe/authentication headers at the transport layer.

**2. Link & Tracking Issues**
- 61 tracking/click-redirect links (`click.e.potterybarn.com`, `svopn.potterybarn.com`, `clickcp.potterybarn.com`, `d.turn.com`) were skipped by HTTP probing as expected redirect infrastructure — no failures confirmed, but also not verified live.
- Open-tracking pixel served over plaintext HTTP: `http://svopn.potterybarn.com/?sv_cid=0053_00597&sv_emopen=true&sv_sveme=...` — mixed-content risk, may be blocked by clients enforcing HTTPS-only image loading, silently breaking open tracking.
- `Foot_NonMem_PB.jpg` and `slices_02.jpg` (brand banner) also load over `http://edm.potterybarn.com/...` — same mixed-content exposure for footer rendering.

**3. Rendering & Accessibility**
- 45+ `<img>` elements are missing `alt` text (product slices, banners, footer nav slices, tracking pixel `img` tags). This degrades screen-reader accessibility and image-blocked-client fallback (recipients see nothing where alt text would normally appear).
- `spacer_0.gif` is loaded from `http://edm.westelm.com/we/evergreen/spacer_0.gif` — both non-HTTPS and cross-brand (West Elm domain) sourcing for a Pottery Barn layout spacer.
- MSO conditional comments (`<!--[if gte mso 9]>`, `<!--[if mso 16]>`) and Outlook-specific fixes are present, indicating standard Litmus/Email-on-Acid hardening.
- `<style>` block contains stray PHP-style `header(...)` calls (`header('Content-Type: image/jpeg'); ...`) embedded as literal text inside a CSS `<style>` tag — dead code with no effect in an email client, but signals a template artifact that leaked from a server-side image script into the HTML source.

**4. Personalization & Merge Tokens**
- Recipient email is merge-injected into functional URLs (`coreemail.html?email=lila-hearth-potterybarn-fap6e@etell.app`, `sv_sveme=lila-hearth-potterybarn-fap6e@etell.app`) — tokens resolved correctly, no unresolved `{{...}}` or `%%...%%` placeholders found in the visible source.

**5. Compliance (CAN-SPAM, unsubscribe, authentication headers)**
- `List-Unsubscribe` header: not found in the delivered message — mail clients (Gmail/Outlook) that surface a native one-click unsubscribe UI cannot do so without this header.
- `List-Unsubscribe-Post` (RFC 8058): not found — even if `List-Unsubscribe` were present, one-click unsubscribe would not qualify without this companion header.
- `Authentication-Results` header: not found, so SPF/DKIM/DMARC pass/fail status cannot be confirmed from this data. Note both header warnings are qualified as possibly relay-related ("may not be captured by AgentMail relay") — this may be a capture artifact rather than a sender-side omission; treat as unconfirmed rather than a definitive gap.
- No inline unsubscribe link visible in the truncated HTML sample provided — cannot confirm presence/absence of a body-level unsubscribe link since the source was truncated before the footer.

**6. Email-to-Site Continuity (UTM params, landing page alignment)**
- Header/nav link routes through `click.e.potterybarn.com` redirect wrapper (`https://click.e.potterybarn.com/u/?qs=...`) rather than a direct UTM-tagged URL — destination and UTM parameters are opaque in this encoded `qs` payload and can't be verified from source alone.
- Customer-service link resolves to a direct site URL with email param: `https://www.potterybarn.com/customer-service/coreemail.html?email=...` — no UTM/campaign parameters present on this link, so site-side attribution for this click path is not trackable.

**7. Recommendations**
- Add `alt` attributes to all content-bearing images (slices, banners); at minimum add empty `alt=""` to purely decorative spacer/pixel images to satisfy accessibility tooling without introducing noise.
- Migrate the two remaining HTTP asset URLs (`edm.westelm.com` spacer, `edm.potterybarn.com` footer banner/slice, `svopn.potterybarn.com` open pixel) to HTTPS to avoid mixed-content blocking in strict clients.
