# Online SALE exclusive: Bestselling furniture
**Score:** 6/10 · **Type:** Email audit · **2026-09-27**
## Executive summary

- This is a clean, on-brand furniture sale email — hero banner, four collection blocks each tagged "NOW ON SALE," then a "Recommended Just For You" grid, then Halloween Shop and Design Crew banners. It's well-organized and easy to scan, but it's also generic: no percentage or dollar figure appears anywhere, and "Select Furniture" tells you nothing about what's actually discounted. Compared to 2026-09-25's "Our Holiday Headquarters is OPEN" (6/10) — which had a sharper structural hook — this one plays it safer and less distinctively.
- The furniture category itself is a stronger high-consideration signal than towels or bedding, so it should pull decent opens from anyone browsing big-ticket items. But without a visible discount amount, this reads more like a category nudge than a "shop now" trigger, and it'll underperform against Pottery Barn's better sends in this run.

## What's working

- Clear vertical hierarchy: hero → four labeled collections (Aubrey, Toscana, Livingston, Farmhouse) → recommended grid → seasonal cross-sells.
- Every collection block has its own visible "NOW ON SALE" red flag tag, reinforcing the promo without repeating body copy.
- No render bugs — images load cleanly, text is legible, buttons are crisp black-and-white on-brand styling.
- "Recommended Just For You" personalization framing adds a segmentation signal even if the products look generic.
- Multiple clear CTAs ("SHOP FURNITURE SALE," "SHOP ALL SALE," "SHOP ALL IN-STOCK FURNITURE") give several entry points.

## What's weak

- Zero concrete discount is shown anywhere in the render — no %, no $ off, just "Now on Sale." That's a meaningful miss for a hero-level sale email.
- "Select Furniture" in the hero is vague; a shopper can't tell from the top fold which collections or categories qualify without scrolling.
- Four back-to-back near-identical collection blocks (image + red tag + name) make the middle of the email visually repetitive and monotonous.
- The email drifts off-topic at the bottom (Halloween Shop, Design Crew) diluting the furniture-sale focus established at the top.

## Recommendations

- 1. Put a real number in the hero — "20% Off Select Furniture" beats "Select Furniture Now on Sale" for both scannability and click intent. This is the single biggest lever here.
- 2. Add discount callouts per collection block (e.g., "20% off" pill next to "NOW ON SALE") so browsers can gauge value without clicking into each collection.
- 3. Trim to 2-3 hero collections instead of 4 near-identical blocks, or vary the layout (alternate image side, mix in a price) to break the repetition.
- 4. Move Halloween Shop / Design Crew content to a separate send — this email should stay furniture-sale-only to avoid diluting the CTA.

- **Subject Alt B:** `Your online-exclusive furniture sale starts now`
- **Preheader Alt A:** `Aubrey, Toscana, Livingston & Farmhouse — all discounted through Sunday.`
- **Preheader Alt B:** `Shop bestselling collections before they're gone.`

## Technical Audit

1. Technical Summary
Marketing-cloud template (Sailthru/similar) with valid link and mixed-content tracking assets; no unsubscribe/authentication headers were captured by the relay, and alt text is absent across nearly all images.

2. Link & Tracking Issues
- Primary CTA link uses Sailthru-style redirect: `https://click.e.potterybarn.com/u/?qs=ABB7...` — well-formed, no issues found.
- Open-tracking pixel served over plain HTTP: `http://svopn.potterybarn.com/?sv_cid=0053_00597&sv_emopen=true&sv_sveme=lila-hearth-potterybarn-fap6e@etell.app` — mixed content; some mail clients/proxies block non-HTTPS pixels, undercounting opens.
- That same open-tracking URL embeds the recipient email address in plaintext in the query string (`sv_sveme=...@etell.app`) — PII exposed in a GET request logged by intermediate proxies/CDNs.
- 50 additional tracking/redirect links present but not resolvable via static HTTP probe (expected for click-tracking domains); not flagged as broken, just unverified.
- Secondary open pixel via `https://clickcp.potterybarn.com/o/ec7c325b-...` — HTTPS, no issue.

3. Rendering & Accessibility
- 40+ `<img>` tags missing `alt` attributes (hero banners, product slices, footer nav slices, legal/footer images) — screen readers and image-blocked clients will render nothing meaningful.
- Two images served over HTTP instead of HTTPS: `http://edm.potterybarn.com/pb/thekey/CC_Banner/PB/Foot_NonMem_PB.jpg` and `http://edm.potterybarn.com/pb/2022/0311_Key_CC_Email_BrandBanner/slices_02.jpg` — mixed-content risk, may be blocked or flagged by mail clients enforcing HTTPS.
- Embedded `<style>` block contains raw PHP-style `header()` calls (`header('Content-Type: image/jpeg'); ...`) inside a CSS `<style>` tag — inert/dead code left in from template reuse; harmless since it's not executed as PHP, but indicates unclean template output.
- Responsive breakpoints defined via `@media` queries for 480px/650px/700px — standard, no issues found.

4. Personalization & Merge Tokens
- No unresolved merge tags (e.g. `{{first_name}}`, `%%field%%`) found in the visible source.
- Recipient identifier is passed as a literal, already-resolved email address in tracking URLs (`lila-hearth-potterybarn-fap6e@etell.app`) rather than a hashed/opaque token — this is a data-hygiene issue, not a broken-merge issue (see Compliance/Tracking above).

5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- List-Unsubscribe header not detected — QA notes this may be a relay-capture limitation (AgentMail) rather than a sender-side omission; cannot confirm compliance either way from this data.
- List-Unsubscribe-Post (RFC 8058 one-click unsubscribe) not detected — same caveat as above.
- Authentication-Results header (SPF/DKIM/DMARC) not detected — same relay-capture caveat; authentication status is unknown, not confirmed failing.
- Footer unsubscribe/preference-center link present via `coreemail.html?email=...` (customer-service page) — link structure appears intact; not independently verified for functionality.

6. Email-to-Site Continuity (UTM params, landing page alignment)
- Header CTA link routes through `click.e.potterybarn.com` redirect infrastructure rather than exposing a direct `potterybarn.com` URL with UTM parameters in the truncated source — cannot confirm UTM tagging or final landing-page alignment without following the redirect chain.
- No issues found in the visible/static portion of the source regarding domain mismatch (all links resolve under `potterybarn.com` / `e.potterybarn.com` / `westelm.com` family domains, consistent with brand).

7. Recommendations
- Serve the two HTTP-only image assets (`Foot_NonMem_PB.jpg`, `slices_02.jpg`) and the open-tracking pixel over HTTPS to avoid mixed-content blocking.
- Add descriptive `alt` text to all content images (hero, product slices) and empty `alt=""` to purely decorative spacers/dividers.
- Move recipient email out of the open-tracking pixel's query string (`sv_emopen` param) to a hashed/opaque ID to avoid exposing PII in URL logs.
- Remove the dead PHP `header()` snippet embedded in the `<style>` block — leftover template artifact with no functional purpose.
- Confirm List-Unsubscribe / List-Unsubscribe-Post / Authentication-Results headers directly against raw SMTP headers (outside the AgentMail relay) to close the compliance-verification gap flagged by QA.
