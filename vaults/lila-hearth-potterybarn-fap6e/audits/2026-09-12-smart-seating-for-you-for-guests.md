# Smart seating (for you & for guests)
**Score:** 5/10 · **Type:** Email audit · **2026-09-12**
## Executive summary

- This is Pottery Barn's seating category email, "Thoughtful Seating," organized into use-case zones — Entryway, Bedroom, Reading Nook, Dining Room — each anchored with a moody, well-styled lifestyle photo (leather club chair by a fireplace, plaid armchair in a book nook, upholstered dining bench). It's clean, on-brand, and well-shot, continuing the same editorial-not-discount posture the brand has run all week (following "Classic plaid, now in season" on 2026-09-11 and the rug color-story email the same day).
- The problem is depth, not execution: there's no discount, no urgency, and the copy is entirely generic ("A soft spot to slip off shoes," "A place to get ready for the day") — none of it differentiates one bench from another. It reads more like a catalog spread than a targeted send, which is consistent with the brand's recent run of 5-6/10 editorial plays. It's pleasant but skippable.

## What's working

- Clear room-by-room structure (Entryway/Bedroom/Reading Nook/Dining Room) makes it easy to jump to the relevant use case.
- Hero shot (fireplace + leather chair) is warm and aspirational, sets tone immediately.
- "Recommended Just For You" section signals personalization/browsing history.
- No layout bugs — images render cleanly, no overlap or broken assets.
- Secondary nav strip (Decor/Lighting/Bedding/Tabletop) gives an easy exit ramp if seating isn't the need.

## What's weak

- No offer anywhere in the body — no %, no free shipping, nothing time-bound.
- Subject "Smart seating (for you & for guests)" doesn't match any body copy — "for guests" never appears in the layout shown.
- Copy per section is filler ("A soft spot to slip off shoes and extra seating in a pinch") rather than product-specific detail (materials, dimensions, price).
- A financing/credit-card pitch ("10% Back in Rewards," Affirm) is jammed into the footer of what's otherwise a furniture email — same cross-sell pattern as the 2026-09-12 Visa card send, diluting the seating message.

## Recommendations

- 1. Add one concrete offer or urgency hook — even "Free shipping on seating this week" would lift open/click likelihood more than any copy polish.
- 2. Rewrite subject to match "for guests" — either add a guest-seating callout in the body or drop the phrase from the subject; right now it's a mismatch.
- 3. Swap generic section copy for one spec each (e.g., "Solid oak frame, seats 2, $349") so the click has a reason beyond "browse."
- 4. Move the credit-card/Affirm block out of this email into its own dedicated send — it repeats the same tactic seen in the "Get 10% back with a Pottery Barn Visa" send and clutters the seating narrative.

## Technical Email Audit — Pottery Barn "Smart seating" campaign

### 1. Technical Summary
The email is a standard MSO/Outlook-conditional table-based HTML template with tracking pixels and click-redirects; automated QA passed at 50% with 0 hard errors but 4 warning categories, driven mainly by missing image alt text and unauthenticated header data.

### 2. Link & Tracking Issues
- All primary CTAs route through `click.e.potterybarn.com/u/?qs=...` (Sailthru/PB ESP redirect wrapper) — 72 tracking/redirect links were skipped by the automated HTTP probe by design (redirect domains), so link-destination validity is unconfirmed and should be manually click-tested before send.
- Open-tracking beacons present: `svopn.potterybarn.com/?sv_cid=0053_00597&sv_emopen=true&sv_sveme=lila-hearth-potterybarn-fap6e@etell.app` — served over **http://**, not https. Plaintext transmission of a raw email address in a query parameter over an unencrypted connection is a data-exposure issue (email address leaks to any network intermediary).
- Second tracking pixel `clickcp.potterybarn.com/o/8b38358e-6eaf-4072-b241-6bfdc1e00c58?mi_cid=...&mi_mid=...` (Sailthru) uses https — fine.
- Turn.com pixel (`d.turn.com/r/dd/id/...`) present — third-party ad-retargeting beacon, not a functional/rendering defect but worth noting for a data-sharing/compliance review.
- Plain-text part is >70% URL characters (12,917/17,205 chars) — indicates the plain-text alternative was likely auto-generated from HTML without a clean text template. This increases spam-filter scoring risk on some providers.

### 3. Rendering & Accessibility
- 60 `<img>` tags missing `alt` attributes, spanning hero/product slices, footer nav slices, and product shots (e.g. `toscana-extendable-dining-table-60-1245-1-l.jpg`, `reeva-handwoven-rug-3-l.jpg`, `chunky-wool-jute-rug-l.jpg`). With images disabled (default in Outlook/Gmail-cached-image-off scenarios), the email will render as a mostly blank/whitespace layout — no fallback text for screen readers or blocked-image clients.
- Two images served over **http://** instead of https:
  - `http://edm.potterybarn.com/pb/thekey/CC_Banner/PB/Foot_NonMem_PB.jpg`
  - `http://edm.potterybarn.com/pb/2022/0311_Key_CC_Email_BrandBanner/slices_02.jpg`
  Mixed-content images on http can be blocked or flagged by mail clients that enforce TLS, causing broken visuals in the footer banner region.
- Layout uses nested MSO-conditional tables with legacy DOCTYPE (XHTML 1.0 Transitional) and multiple redundant `<style>` blocks — standard/expected for a legacy ESP template, not itself a defect.
- Note: a stray `<style>` block in `<head>` contains raw PHP-style `header(...)` calls as literal text (`header('Content-Type: image/jpeg'); ...`) — these are inert as CSS (browsers/mail clients will ignore invalid property syntax) but indicate a copy-paste leftover from server-side code that doesn't belong in a `<style>` tag. No functional rendering impact, but should be cleaned up as dead markup.

### 4. Personalization & Merge Tokens
- No unresolved merge tags (e.g. `{{first_name}}`, `%%FIRSTNAME%%`) found in the visible source.
- Recipient email address is embedded in cleartext in multiple tracking/service URLs: `coreemail.html?email=lila-hearth-potterybarn-fap6e@etell.app` and the two `svopn`/`sv_sveme` open-tracking URLs. This is standard for Sailthru-style ESPs but confirms PII is passed via URL query string, relevant if a compliance/privacy review is in scope.

### 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)

- **Authentication-Results header** (SPF/DKIM/DMARC): not found in the captured headers — authentication status is unknown from this data. This is a relay-capture limitation, not proof of misconfiguration, but should be verified independently given Gmail/Yahoo's 2024+ bulk sender authentication requirements.
