# Memorial Day Sale ⏳ Time is running out!
**Score:** 7/10 · **Type:** Email audit · **2026-05-25**
## Executive summary

- This is Pottery Barn's twentieth-or-so Memorial Day email in roughly a week, and it arrives the same day as yesterday's "ENDS TOMORROW" send — meaning the urgency promise is still true, but barely, and subscribers who saw yesterday's email will notice the same hook word-for-word. The red banner is identical to every prior send. What saves this one from a pure wallpaper score is the "RECOMMENDED JUST FOR YOU" section below the fold: actual product thumbnails with names (Captain Platform Bed, Farmhouse Platform Bed, Hartford Upholstered Bed, Tuscany Extendable Dining Table), which breaks the category-grid-only pattern that has plagued the last several sends.
- The subject, however, throws it away. "Time is running out!" is the weakest possible urgency hook — zero specificity, no offer amount, no product — especially after the 5/25 send already said "ENDS TOMORROW" with a clock emoji. The subject line problem is the ceiling here: however good the personalization in the body is, the inbox view offers no reason to open over yesterday's message.
- Mechanically clean, no render bugs, and the personalization section is a legitimate step forward. But a weak subject line + cadence fatigue from being the ~20th consecutive Memorial Day promo makes this mid-pack for the campaign.

## What's working

- **"Recommended Just For You" section is real.** Six specific product thumbnails with actual names — beds, a dining table, a bookend — break the pure-category-grid pattern and give a scroll-stopper that prior sends lacked.
- **"ENDS TOMORROW" callout remains credible.** After a week of premature urgency, the banner at top finally lines up with the actual campaign end date (Memorial Day 5/26).
- **Clean render, no layout bugs.** Typography is legible, images load, nothing overlaps.
- **Credit card loyalty rewards visible.** "Earn 50% Back in Rewards" is a meaningful CTA for cardholders buried in the lower body.
- **Dual-tier offer is explicit.** "Extra 20% off Select Styles. Plus new deals up to 40% off" is a real offer with caveat disclosed in the hero itself.

## What's weak

- **Subject is the weakest of the campaign.** "Time is running out!" says nothing about the offer, the product, or the deal depth — compare to 5/23's "Memorial Day deals on your dream bedding" which actually delivered on its promise.
- **Category grid is the same eleven-item block** as every prior send — Furniture, Outdoor, Sofas & Chairs, Bedding, Decor, etc. It's wallpaper at this point.
- **The personalized recs are below the fold** and buried under the category grid and cross-brand link section; most subscribers on mobile will never reach them.
- **Cross-brand "Family of Brands" section dilutes focus.** Pottery Barn Kids, Teen, Mark & Graham, Williams-Sonoma — fine as a bottom-of-email unit, but placing it *above* the personalized recs is backwards prioritization.
- **No pricing shown on recommended products.** The product cards have names and images but no prices or sale callouts, reducing the "buy now" impulse.

## Recommendations

- 1. **Move "Recommended Just For You" above the category grid.** The personalization is the only differentiator in this send; it needs to be the second thing after the hero, not the fourth.
- 2. **Put sale pricing on the product cards.** Show "Was $X, now $Y" or "20% off" inline on each recommended item — that converts browsers.
- 3. **Rewrite the subject to name the product or the discount**, not a generic urgency phrase.
- **Subject Alt A:** `Extra 20% off — last day for Memorial Day deals`
- **Subject Alt B:** `Beds, tables, outdoor — final 20% off today only`
- 4. **Preheader should quote a personalized product, not repeat the sale name.**
- **Preheader Alt A:** `Your saved beds and furniture are included — sale ends tonight`
- **Preheader Alt B:** `The Captain Bed is 20% off today. Last chance.`
- 5. **Kill the category grid or reduce it to 4 top categories.** Eleven equal-weight links is a decision-paralysis block at this point in the campaign.

## Technical Audit — Pottery Barn Memorial Day Sale Email

---

### 1. Technical Summary

Standard table-based ESP-sent email (Salesforce Marketing Cloud via `e.potterybarn.com`). Two confirmed defects require immediate attention: orphaned PHP server code injected into a CSS block, and an empty `<title>` element. Truncated source prevents full compliance verification.

---

### 2. Link & Tracking Issues

**UTM visibility — cannot confirm.** All clicks route through `click.e.potterybarn.com/u/?qs=<opaque-base64>`. UTM parameters, if present, are appended server-side by the ESP redirect. No UTM params are visible in the raw `href` values, so attribution depends entirely on the redirect chain functioning correctly. If the ESP redirect ever breaks, all click attribution is lost with no fallback.

**Image host path includes "2016":**
```
https://edm.potterybarn.com/pb/2016/nav/nav0.jpg
```
Likely a static asset path that has never been updated. Not a functional issue, but worth flagging as a long-term CDN dependency risk.

**Source truncated** — cannot audit all CTAs for broken or duplicate tracking parameters.

---

### 3. Rendering & Accessibility

**Critical: PHP header() calls injected into a `<style>` block.** Lines inside the third `<style>` tag are orphaned server-side PHP, not CSS:

```css
header('Content-Type: image/jpeg');
header("Cache-Control: no-store, no-cache, must-revalidate, max-age=0");
header("Cache-Control: post-check=0, pre-check=0", false);
header("Pragma: no-cache");
```

This is a template assembly error — PHP output from an image-serving script was written into the wrong output buffer. Email clients silently discard invalid CSS, so it does not break rendering, but it indicates a broken build pipeline and the same defect may have hit other recipients or campaigns.

**Empty `<title>` tag:**
```html
<title></title>
```
Some clients (Gmail web, Apple Mail) surface the title in tab or notification UI. Empty is a missed opportunity at minimum; in some clients it displays as a blank string next to the subject line.

**`maximum-scale=1` in viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. WCAG 1.4.4 violation for users with low vision.

**Global `-webkit-text-size-adjust: none`:**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```
Applied via the `*` selector, this disables system font scaling across the entire email. Conflicts with WCAG 1.4.4.

**Hardcoded 414 px mobile breakpoint:**
```css
.showmobile { width:414px !important; }
```
iPhone 12/13/14 width. Clips or misaligns on smaller Android devices (~360 px viewport) and newer large-display phones.

**`role="presentation"` on layout tables** — correctly applied. No issues.

This does not affect CAN-SPAM compliance directly, but it will strip referrer data from any server-side analytics on the landing site that relies on `document.referrer` rather than UTM params.
