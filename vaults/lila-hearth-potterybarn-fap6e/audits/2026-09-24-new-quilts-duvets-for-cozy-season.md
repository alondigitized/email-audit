## Technical Audit

1. Technical Summary
Standard Cheetah Digital/PB ESP template with heavy legacy markup carryover; core delivery mechanics (unsub headers, tracking, alt text) show multiple gaps, though rendering scaffolding itself is sound.

2. Link & Tracking Issues
- Header logo link routes through `click.e.potterybarn.com/u/?qs=...` (Cheetah Digital click-tracking) — functioning redirect wrapper, no issue with structure itself.
- 60 tracking/redirect links were skipped by automated HTTP probing (expected behavior for click-redirect domains, not a defect).
- Two legacy open-tracking pixels present and duplicative: `d.turn.com/r/dd/id/...` (Turn/Amobee) and `svopn.potterybarn.com/?sv_cid=0053_00597&sv_emopen=true&sv_sveme=...@etell.app` — the latter transmits the recipient email address in cleartext as a URL query parameter (`sv_sveme=lila-hearth-potterybarn-fap6e@etell.app`) over **HTTP, not HTTPS**. This exposes PII in transit and in server logs.
- Same HTTP (non-TLS) issue on a second pixel: `http://edm.potterybarn.com/pb/thekey/CC_Banner/PB/Foot_NonMem_PB.jpg` and `http://edm.potterybarn.com/pb/2022/0311_Key_CC_Email_BrandBanner/slices_02.jpg`.

3. Rendering & Accessibility
- 45+ `<img>` elements missing `alt` attributes across hero slices, product shots, and footer banners (e.g., `slices_01.jpg` through `slices_18.jpg`, product images like `remmy-swivel-chair-1-l.jpg`, `cayman-platform-bed-1-l.jpg`). With images blocked by default in most mail clients, this leaves the layout as blank space with no fallback text.
- Table-based layout with MSO conditional comments (`<!--[if gte mso 9]>`, `<!--[if mso 16]>`) and Outlook `o:OfficeDocumentSettings` present — standard Outlook rendering support, no issue found.
- Responsive breakpoints defined at 480px/650px/700px via media queries — no issues found in the truncated source.
- `<meta name="robots" content="noindex, nofollow">` and `<meta name="referrer" content="no-referrer">` present — correct for transactional/marketing email, no issue.
- Stray `<style>` block contains PHP-style `header()` calls (`header('Content-Type: image/jpeg'); header("Cache-Control: ...")`) sitting inside a CSS `<style>` tag — these are inert as CSS (browsers/email clients will ignore them as invalid rules) but indicate a template-authoring error where server-side PHP header code leaked into the client-side stylesheet. No functional rendering impact, but signals a broken build/templating step upstream.

4. Personalization & Merge Tokens
- Recipient identifier appears correctly interpolated in multiple locations as `lila-hearth-potterybarn-fap6e@etell.app` (coreemail.html customer-service link, sv_sveme open-tracking pixel) — merge token resolved, no unresolved `{{token}}` or `%%FIELD%%` placeholders found in the visible source.
- No other personalization tokens (first name, loyalty tier, etc.) observed in the truncated HTML.

5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- `List-Unsubscribe` header not found — fails RFC 2369 best practice; combined with no visible unsubscribe link in the truncated body, this is a risk area pending confirmation from the full HTML footer.
- `List-Unsubscribe-Post` header not found (RFC 8058) — one-click unsubscribe unsupported, which major mailbox providers (Gmail, Yahoo) increasingly require for bulk senders to avoid deliverability penalties.
- `Authentication-Results` header not found — SPF/DKIM/DMARC pass/fail status cannot be verified from this capture; this may be an artifact of the AgentMail relay stripping headers rather than a true authentication failure, but it should be confirmed against raw SMTP headers.
- Physical mailing address / CAN-SPAM footer not visible in the truncated source — cannot confirm compliance; flagging as unverified rather than a confirmed defect.

6. Email-to-Site Continuity (UTM params, landing page alignment)
- Primary CTA/logo link uses opaque encoded tracking payload (`qs=ABB7InYiOjEsImQiOjUwMDl9...`) rather than transparent UTM parameters — this is normal for Cheetah Digital-wrapped redirects (UTMs are typically appended server-side after the redirect resolves), so not flagged as a defect, but it means UTM alignment cannot be verified directly from this source.
- Customer-service link resolves to a real on-site page: `https://www.potterybarn.com/customer-service/coreemail.html?email=...` — correctly targeted, no issue found.
- Product-page image sources point to live `potterybarn.com` PDP asset paths (e.g., `/pbimgs/ab/images/dp/wcm/202629/0576/remmy-swivel-chair-1-l.jpg`) — consistent with production site structure, no issue found.

7. Recommendations
- Add `List-Unsubscribe` and `List-Unsubscribe-Post` headers to meet RFC 8058 one-click unsubscribe requirements.
- Force HTTPS on the two remaining HTTP image/pixel sources (`Foot_NonMem_PB.jpg`, `slices_02.jpg`) and the `svopn.potterybarn.com` open-tracking pixel — the latter is the higher priority since it leaks a recipient email address over plaintext HTTP.
- Add `alt` text to all content-bearing `<img>` tags (product shots, hero slices, banners) to preserve messaging when images are blocked.
- Remove the orphaned PHP `header()` calls from the `<style>` block — harmless today but indicates a templating pipeline defect worth fixing at the source.
- Verify `Authentication-Results` (SPF/DKIM/DMARC) directly against raw SMTP headers outside the AgentMail relay, since absence here may be a capture artifact rather than an authentication failure.
