## Technical Audit

## 1. Technical Summary
The email is an image-sliced layout built on nested fixed-width tables. It has a malformed `<style>` block, 30+ images with missing or empty `alt`, and two `http://` image sources. The plaintext recipient address appears in two pixel URLs. Authentication and List-Unsubscribe headers could not be verified, because the relay did not capture them.

## 2. Link & Tracking Issues
- **Unverifiable destinations:** all 36 links go through `click.e.potterybarn.com/?qs=ABp7Im...`, an opaque encoded token. The QA tool skipped probing them, so destinations, redirect chains and 404s are unconfirmed.
- **Link text for image links:** the nav and hero links wrap images with `alt=""` (for example `slices_02.jpg`). They have no accessible name, so screen readers will announce a bare link.
- **Third-party ad pixels:** `secure.leadback.advertising.com/adcedge/lb?site=695501...` and `d.turn.com/r/dd/id/.../cat/1` are third-party retargeting beacons. They are flagged as images without alt, but they are tracking pixels, so the alt warning is low-impact. Some clients and privacy features will block them.
- **Dead code shipped to recipients:** a commented-out credit-card banner block (`cm_ite=PB_header_nonmember`) is still in the HTML. It adds weight and exposes internal campaign parameters.

## 3. Rendering & Accessibility
- **Malformed CSS (confirmed in source):** the second `<style>` block opens with stray PHP text: `header('Content-Type: image/jpeg'); header("Cache-Control: no-store..."); header("Pragma: no-cache");`. CSS parsers fold this into the prelude of the next rule, so the `a[x-apple-data-detectors]` rule is likely invalidated. Apple Data Detectors would then restyle auto-linked dates, addresses and phone numbers.
- **Missing alt text (QA, confirmed):**
  - `slices_02.jpg` to `slices_11.jpg` in `edm.westelm.com/we/2026/US/101326_HO26_D1_WEK_EM_Xbrand_OnBehalfOf_KR_700px/`, which is the main body content.
  - `slices_01.jpg` and `slices_03.jpg` to `slices_18.jpg` in `edm.potterybarn.com/pb/2026/US/Email-Footer/`.
  - `Foot_NonMem_PB.jpg` and `0311_Key_CC_Email_BrandBanner/slices_02.jpg`.

  The body slices carry `alt=""` in the visible source. With images blocked, the body is blank and the email has no text equivalent.
- **Insecure image sources:** `http://edm.potterybarn.com/pb/thekey/CC_Banner/PB/Foot_NonMem_PB.jpg` and `http://edm.potterybarn.com/pb/2022/0311_Key_CC_Email_BrandBanner/slices_02.jpg`. Both may be blocked or trigger mixed-content warnings.
- **Width mismatch:** the wrapper tables are `width="650"`, but the body content tables are `width="700"`. That overflows the container by 50px, and the 650px wrapper has no mobile handling.
- **Responsive selectors don't match the visible markup:** the media query targets `table[class="wrapper"]` and `img[class="photo"]`. The visible tables and images have no such classes, so the mobile rules appear inert. The source is truncated, so later sections may differ.
- **Document structure:**
  - Comments precede the `<!DOCTYPE>`, which can trigger quirks mode in older Outlook/IE rendering engines.
  - `<html>` has no `lang` attribute.
  - There is no `<title>`.
  - Layout tables have no `role="presentation"`.
  - Legacy `<center>` and `bgcolor` are used under an XHTML Strict doctype.
- **Unused web font:** the Montserrat `<link>` to `fonts.googleapis.com` is not referenced by any visible `font-family`. It is an extra external request that Gmail strips.

## 4. Personalization & Merge Tokens
- No unresolved merge tokens (`%%...%%`, `{{...}}`) are visible. The ampScript slot at the top is empty.
- **PII in URLs:** the recipient address `lila-hearth-potterybarn-fap6e@etell.app` is in plaintext in the pixel URLs `www.potterybarn.com/customer-service/coreemail.html?email=...` and `svopn.potterybarn.com/?sv_cid=0053_00597&sv_emopen=true&sv_sveme=...`. This leaks the address to proxies, logs and Referer headers. A hashed or encoded identifier would avoid that.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe and List-Unsubscribe-Post (RFC 8058):** neither header was found. The QA tool notes the AgentMail relay may strip them, so this is unconfirmed rather than a proven defect. Gmail and Yahoo bulk-sender rules require both.
- **SPF/DKIM/DMARC:** `Authentication-Results` was not captured, so status is unknown. The sender is `PotteryBarn@e.potterybarn.com`, an aligned subdomain, but this can't be verified here.
- **Footer unsubscribe link and physical address:** neither is visible in the truncated source, so they can't be assessed. The footer is all image slices (`Email-Footer/slices_01–18.jpg`) with no alt text. If the unsubscribe text is embedded in an image, it is inaccessible and fails if images are blocked. Confirm there is a live-text link.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- No `utm_*` parameters are visible. Attribution is likely encoded inside the opaque `qs=` token, so campaign tagging can't be verified from the HTML.
- Landing pages could not be checked because the tracking links were not probed. The visible hero assets are hosted on `edm.westelm.com` while all links resolve through the `potterybarn.com` click domain. Confirm the redirects land on the West Elm Kids destination the creative implies.

## 7. Recommendations
1. Remove the stray `header(...)` lines from the `<style>` block so the Apple Data Detectors rule applies.
2. Add descriptive `alt` text to every content slice (`slices_02–11`, footer `slices_01–18`) and to the nav/CTA images. Use `alt=""` only for decorative images and tracking pixels.
3. Change the two `http://` image URLs to `https://`.
4. Fix the 700px vs 650px mismatch. Add real classes (`wrapper`, `photo`) to the table and image markup, or update the media query selectors.
5. Add `lang`, `<title>` and `role="presentation"`. Move the comments after the DOCTYPE. Remove the commented-out banner HTML and the unused Montserrat `<link>`.
6. Replace the plaintext email address in the `coreemail.html` and `svopn` pixel URLs with a hashed or opaque ID.
7. Re-run the audit against the raw MIME to confirm `List-Unsubscribe`, `List-Unsubscribe-Post`, `Authentication-Results` and a live-text footer unsubscribe link.
8. Resolve the `click.e.potterybarn.com` redirects out-of-band to confirm landing pages and UTM carry-through.
