- **The JSON preview text — again.** Third time this week. This is embarrassing and it's going to hurt open rates across the list
- **Zero kids content in the hero or featured sections** — the only nod to kids is a buried nav link; for a subscriber who primarily shops for her children, that's a miss
- **Subject is punny but vague** — "The Secret's in the Sole" doesn't tell me there's a BOGO offer hiding inside; I almost skipped it
- **No loyalty/rewards callout** — I'm a Skechers repeat buyer; where's the Elite points nudge?
- **Cadence fatigue** — this is email number seven from Skechers in eight days; the well is getting shallow

- 1. **Fix the JSON preview text.** Full stop. Nothing else matters until this is gone. Test on a live inbox preview tool before every send.
- 2. **Add a kids module above the fold** — even a single row with "Shop Girls" / "Shop Boys" right under the BOGO banner would have stopped my scroll dead.
- 3. **Make the BOGO banner explicitly say "including kids styles"** if it does — that one phrase would convert me instantly.
- 4. **Pull in a loyalty line** — "You're X points from your next reward" or just "Members save extra" somewhere in the header.

## Technical Audit — Skechers "The Secret's in the Sole" (2026-05-17)

---

### 1. Technical Summary

One confirmed broken experience (empty personalization token) and a systemic HTTP image-hosting issue affecting 13+ assets across email clients that enforce mixed-content blocking. No structural rendering failures, but the mixed-content problem is widespread enough to degrade delivery in security-conscious clients (Gmail via proxy, Outlook 365).

---

### 2. Link & Tracking Issues

**No issues found** with link structure itself — all 27 click-redirect links route through `click.emails.skechers.com` as expected for SFMC. Links were not probed (correct behavior for redirect domains).

**One tracking pixel concern:** The Returnpath pixel at `pixel.app.returnpath.net/pixel.gif` is loaded over HTTP (no protocol prefix in the src), which will be upgraded or blocked depending on the receiving client's mixed-content policy. Evidence:
```
src="pixel.app.returnpath.net/pixel.gif?r=964ce1dbf..."
```
This pixel is in the hidden preheader table and affects inbox placement data accuracy if blocked.

---

### 3. Rendering & Accessibility

**HTTP images — systemic (13 assets):** The ESP image CDN `image.emails.skechers.com` is serving all images over `http://`, not `https://`. Gmail proxies all HTTP images through its own CDN, which can alter URLs and break cache-busting. Outlook 365 may block them entirely with a security prompt. Affected assets include the Skechers logo, App Store badge, Google Play badge, social icons (Instagram, Facebook, YouTube), and feature icons (AfterPay, Find A Store, Curbside Pickup).

Representative evidence:
```
src="http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662...png"  ← logo
src="http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/49468f73...png"  ← missing alt
```

**Missing alt text (2 images):**
- `o.gif` (ink1000.com tracking pixel) — alt="" present but image is also HTTP
- `49468f73-4651-4af3-bea2-61d1ae5db486.png` — no alt attribute at all; if blocked, renders as broken image with no fallback text

**CSS specificity conflict — `.show` class:** Two `@media` blocks define `.show` with overlapping breakpoints (max-width: 680px and max-width: 480px). The second `<style>` block in `<head>` redefines `.show` for 480px. This is harmless in practice but adds parse overhead and creates ambiguity if breakpoints shift.

---

### 4. Personalization & Merge Tokens

**[FAIL] Empty greeting — confirmed broken experience:**

The QA check detected a rendered empty name field in the greeting slot (e.g., `"Hi ,"` with no subscriber name). This indicates the personalization merge token failed to resolve — either the contact record has a null/empty first-name field, or the fallback value was not configured in the SFMC AMPscript/HML block.

This is the single highest-priority issue in this send.

---

### 5. Compliance (CAN-SPAM, Unsubscribe, Authentication)

**No structural CAN-SPAM issues detected** from the available HTML — physical address and unsubscribe link presence could not be confirmed from the truncated source, but the send infrastructure (`no-reply@emails.skechers.com` via SFMC) is consistent with authenticated sending.

**Krakendata (krxd.net) sync pixels present:** Two user-match beacons fire on open:
```
https://beacon.krxd.net/1x1_usermatch.gif?partner=LprH63a7_sfmc_100007688_sha25&partner_uid=[SHA256_HASH]
https://beacon.krxd.net/1x1_usermatch.gif?partner=LprH63a7_sfmc_100007688_subid&partner_uid=122277199
```
The `sha25` (SHA-256 hashed email) sync is standard for DMP onboarding. Verify this is covered in the current privacy policy disclosure, particularly under CCPA/US state law opt-out requirements, as hashed-email audience syncing to a third-party DMP (Salesforce Data Cloud / Kraken) requires disclosure.
