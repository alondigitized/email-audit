## Technical Audit

# Technical Audit — "The Season's Freshest Shades ☀️"

## 1. Technical Summary
Email renders structurally but ships with a broken merge token (empty greeting) and pervasive HTTP-only image sources that risk being blocked by Gmail/Outlook image proxies. Tracking pixel stack is heavy (SFMC + Krux + ReturnPath + ink1000) but functional.

## 2. Link & Tracking Issues
- 27 tracking/click-redirect links skipped by automated HTTP probe — not verified end-to-end. Recommend manual sampling of `click.emails.skechers.com` redirects.
- Multiple overlapping tracking beacons fire on open: SFMC open pixel (`click.emails.skechers.com/open.aspx`), Krux (`beacon.krxd.net`) with three separate calls (sha25 usermatch, subid usermatch, ad_impression), ReturnPath (`pixel.app.returnpath.net`), and ink1000 (`www.ink1000.com/p/up/...`). Each adds load time and a failure surface.
- ReturnPath pixel `src="pixel.app.returnpath.net/pixel.gif?..."` is **missing a protocol scheme** — will resolve as a relative URL inside the rendered MIME context and almost certainly 404.

## 3. Rendering & Accessibility
- **Non-HTTPS image hosts** on `image.emails.skechers.com` and `www.ink1000.com` — Gmail's image proxy will upgrade where possible, but strict clients (corporate Outlook, some webmail) may block. Affects logo, hero, app-store badges, social icons, and service icons (Curbside, AfterPay, Find A Store).
- **Missing `alt` attributes** on `o.gif` (tracking pixel — acceptable) and `49468f73-...png` (content image — **not acceptable**, fails WCAG 1.1.1 and degrades image-off rendering).
- Duplicate `@media` blocks at `max-width:375px` and `max-width:640px` contain identical rule sets — bloats payload with no functional difference; consolidate.
- `<meta content="IE=Edge" />` is missing its `http-equiv="X-UA-Compatible"` attribute — the tag is inert as written.
- First `<meta charset>` tag also lacks `http-equiv` / `name` — malformed but tolerated by most clients.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot** — rendered output shows `"Hi ,"` indicating the first-name merge variable resolved to an empty string. Either the recipient's `FirstName` field is null in the SFMC data extension or the AMPscript/SSJS `%%FirstName%%` lookup lacks a default fallback. Add a `%%=IIF(EMPTY(@FirstName), "there", @FirstName)=%%` style guard.

## 5. Compliance
- Cannot verify SPF/DKIM/DMARC from HTML body — would require raw headers. From-domain `emails.skechers.com` is a known SFMC-delegated sending subdomain, typically aligned.
- Unsubscribe link and physical postal address not visible in the truncated source — must be confirmed in the full footer for CAN-SPAM compliance.
- No List-Unsubscribe header visible from this payload (header-level check needed separately).

## 6. Email-to-Site Continuity
- All click destinations are wrapped in `click.emails.skechers.com` redirects; landing-page UTM params and final-URL alignment cannot be confirmed without expanding the redirect chain. The campaign ID `MKG_US_NA_U_MULTI_ENGAGEDOPEN_EN_05262026` appears in the impression beacon but its propagation to landing-page UTMs is unverified.

## 7. Recommendations
1. **Fix the empty-greeting bug** — add a default-value guard on the first-name merge token; this is the only hard failure in the QA run.
2. **Force HTTPS on all image hosts** — rewrite `http://image.emails.skechers.com` and `http://www.ink1000.com` to `https://` (or protocol-relative `//`) in the SFMC template.
3. **Fix the ReturnPath pixel URL** — prepend `https://` to `pixel.app.returnpath.net/pixel.gif?...`.
4. **Add `alt=""` (decorative) or descriptive alt** to `49468f73-...png` and any other content images currently missing it.
5. **Fix the `X-UA-Compatible` meta tag** — add `http-equiv="X-UA-Compatible"`.
6. **De-duplicate the 375px and 640px media query blocks** to reduce payload size.
7. **Sample-test a handful of `click.emails.skechers.com` redirects** to confirm destinations and UTM hygiene, since the automated probe skipped them.
