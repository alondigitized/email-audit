- The girls' tile is a brown fuzzy boot, and the boys' tile is a pixel-art sneaker. Neither looks like velcro, light-up, or a durable black/blue lace-up.

## Technical Audit

## 1. Technical Summary
The email renders, but the personalization merge fails ("Hi ,"), and several tracking images use insecure or malformed `src` values. The HTML supplied is truncated, so the footer, unsubscribe link and headers could not be inspected.

## 2. Link & Tracking Issues
- **28 tracking links were not probed.** The QA tool skipped them as click-redirect domains, so their destinations and redirect health are unverified.
- **Malformed pixel URL (from source):** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…" width="1" height="1" />` has no scheme. Clients will resolve it as a relative path, so the request fails and the Return Path/Validity seed-tracking pixel never fires. It also has no `alt`.
- **Insecure pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=PRO_US_NA_U_SITEBUNDLE_FULL_EN_10022026` loads over plain HTTP and may be blocked or trigger mixed-content warnings. It also lacks `alt`.
- **Third-party beacons:** Four `beacon.krxd.net` pixels (user-match and ad-impression) sit in the hidden preheader block. Two carry identifiers in the URL: `partner_uid=adf27fee…189a` (a SHA-256 value, likely a hashed email) and `partner_uid=122277199` (a subscriber ID). They are hidden with `display:none` and 0×0 sizing.

## 3. Rendering & Accessibility
- **Insecure image:** `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png` loads over HTTP and has no `alt` attribute (QA WARN ×2). The same host likely serves HTTPS, so switching the scheme is probably enough.
- **Charset and compat meta tags are ineffective.** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv` attribute, so neither declares anything. Encoding falls back to the client's default, which is a risk for the `®` in `<title>Skechers®</title>`.
- **No `lang` attribute** on `<html xmlns="http://www.w3.org/1999/xhtml">`, which affects screen-reader pronunciation.
- **Layout tables have no `role="presentation"`**, for example the `<table cellpadding="0" cellspacing="0" border="0">` wrappers. Screen readers may announce them as data tables.
- **Mobile CSS:** The two `.mobile-content`/`.desktop-content` rules (`display:none !important` at ≥768px) depend on `@media screen`. Gmail and other clients that strip `<style>` blocks would show both versions, but the truncated source doesn't let me confirm whether both blocks are present.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** The greeting renders as "Hi ," because the first-name field is empty and there is no fallback. This is a broken-experience defect. The cause is either a missing profile attribute or an AMPscript/SFMC `%%FirstName%%` call with no default value. A conditional fallback ("Hi there,") or suppressing the greeting when the field is blank would fix it.
- No other unresolved tokens such as `%%…%%` or `{{…}}` appear in the visible source.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Not verifiable.** The source is truncated before the footer, so the unsubscribe link, physical postal address and `List-Unsubscribe`/`List-Unsubscribe-Post` headers could not be checked. No SPF, DKIM or DMARC results were supplied either.
- **Observation:** The sender is `no-reply@emails.skechers.com`. This is not itself a violation, but it offers no reply path.
- **Privacy:** The hashed-email and subscriber-ID beacons to `krxd.net` and `ink1000.com` (section 2) are third-party data sharing. Confirm they are covered in the privacy policy and consent flow.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Not verifiable.** The 28 click-tracked links were skipped and the visible source shows no destination URLs, so UTM parameters and landing-page alignment could not be checked.
- The campaign identifier `PRO_US_NA_U_SITEBUNDLE_FULL_EN_10022026` appears in the pixel URLs. Confirm the same value reaches the landing pages via `utm_campaign`.

## 7. Recommendations

2. Add the missing scheme: change `pixel.app.returnpath.net/pixel.gif?...` to `https://…`.

4. Fix the meta tags: `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` and `<meta http-equiv="X-UA-Compatible" content="IE=Edge" />`.
