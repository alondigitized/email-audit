## Technical Audit

## 1. Technical Summary
The email has one confirmed personalization failure (an empty greeting slot, `Hi ,`) and one malformed tracking pixel (a scheme-less `src`). It also loads several images over `http://` and has no alt text on some of them. The HTML source was truncated, so footer, unsubscribe and CTA link checks could not be completed.

## 2. Link & Tracking Issues
- **Malformed pixel URL:** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…" width="1" height="1" />` has no scheme. Clients resolve it as a relative path, so the request never reaches Return Path and the deliverability and seed-list tracking is lost. It also has no `alt`.
- **Plain-HTTP tracker:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=MKG_US_NA_U_CATEGORY_GENDER_EN_11142026` is non-HTTPS and may be blocked or trigger mixed-content warnings.
- **Link probing:** 45 tracking links were skipped by QA (click-redirect domains such as `click.emails.skechers.com`). Destination validity and redirect health are unverified.
- **Pixel count:** There are 5 pixels inside the `display:none` wrapper (the SFMC open pixel plus 3 `beacon.krxd.net` pixels and the Return Path pixel). A sixth (`ink1000.com`) sits in a separate 1x1 table. Several third-party calls per open add latency and failure points.

## 3. Rendering & Accessibility
- **Missing alt text (QA-confirmed):**
  - `o.gif`, which is the ink1000 tracking pixel.
  - `dde00662-169f-447d-b0e2-fc65f6c2290c.png`, served from `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/`. As a content image, this one matters for screen readers and for image-blocked clients.
- **Non-HTTPS content image:** The same `dde00662…png` loads over `http://`, so it may be blocked in clients that enforce HTTPS.
- **Viewport:** `<meta name="viewport" content="… maximum-scale=1" />` disables pinch-zoom, which is a WCAG 1.4.4 failure.
- **Meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` lack `http-equiv`, so neither declaration takes effect.
- **Layout tables:** The visible layout tables (`<table cellpadding="0" cellspacing="0" border="0">`) have no `role="presentation"`. The `<html>` element has no `lang` attribute. Both are visible in the truncated source.
- **Hidden tracking pixels:** The pixels use `display:none` and sit in a hidden wrapper. Some clients ignore that, and a few pixels have no `alt`.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** The rendered greeting reads `Hi ,`. The first-name field resolved to empty, and no fallback or default value is defined in the SFMC/AMPscript personalization string. This is a broken experience for any recipient without a first name on file, and it is likely a test-seed artifact as well.
- No unresolved `%%…%%` or `{{…}}` tokens are visible in the truncated source.

## 5. Compliance
- **Authentication:** `Authentication-Results` was not found. QA attributes this to the AgentMail relay stripping it, so SPF, DKIM and DMARC status is unknown. This is not a confirmed sender defect.
- **Unsubscribe and footer:** The footer, physical address and `List-Unsubscribe` / `List-Unsubscribe-Post` headers are not in the supplied data, so they could not be verified.
- **Sender:** `no-reply@emails.skechers.com` is a non-replyable sender, so replies are not possible.
- **Hashed identifier sharing:** `beacon.krxd.net/1x1_usermatch.gif` passes `partner_uid=adf27fee…189a`. This is a 64-character hex value that, given the `sha25…` partner name, appears to be a SHA-256 hash, plausibly of the email address. A second usermatch pixel passes `partner_uid=122277199`, which looks like a subscriber ID. Passing these to a third-party DMP should be covered by the privacy disclosures and consent. This is a risk to flag, not a confirmed violation.

## 6. Email-to-Site Continuity
- **Link-level checks:** UTM parameters and landing-page alignment could not be verified. CTA hrefs are wrapped in click-tracker redirects, and the QA run skipped probing them.
- **Campaign ID:** The campaign identifier is consistent across trackers: `MKG_US_NA_U_CATEGORY_GENDER_EN_11142026` in both the `krxd` and `ink1000` URLs. That matches the send date, 2026-11-14.
- **Offer vs. landing page:** The preheader says "Buy one, get one 50% off", but the landing-page offer match was not checked.

## 7. Recommendations
1. **Fix the greeting:** Add a fallback to the personalization string (e.g. `%%=IIF(Empty(@firstName),"there",@firstName)=%%`), or suppress the greeting when the name is empty.
2. **Fix the Return Path pixel:** Change the `src` to `https://pixel.app.returnpath.net/pixel.gif?r=…`, and add `alt=""`.
3. **Move assets to HTTPS:** Serve `image.emails.skechers.com/lib/.../dde00662-….png` and `www.ink1000.com/.../o.gif` over HTTPS.
4. **Add alt text:** Give `dde00662….png` descriptive alt text, and add `alt=""` to the tracking pixels.
5. **Viewport:** Remove `maximum-scale=1`.
6. **Meta tags and layout:** Add `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"` to the two meta tags. Add `lang="en"` to `<html>` and `role="presentation"` to the layout tables.
7. **Re-run QA on the full HTML:** Check the footer, unsubscribe link, `List-Unsubscribe` headers and the UTM parameters on destination URLs.
8. **Authentication:** Verify SPF, DKIM and DMARC from a direct (non-relay) copy of the message, since the relay hides this.
