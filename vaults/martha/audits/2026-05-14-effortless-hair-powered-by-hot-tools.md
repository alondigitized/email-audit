### 3. Rendering & Accessibility

**Confirmed issues:**

- **`<meta content="text/html; charset=utf-8" />`** (line ~6): Missing required `http-equiv="Content-Type"` attribute. Correct form: `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />`. Some older Outlook and Lotus Notes clients fall back to system encoding without this.

- **`<meta content="IE=edge" />`** (line ~8): Missing `http-equiv="X-UA-Compatible"`. Should be `<meta http-equiv="X-UA-Compatible" content="IE=edge" />`.

- **`img { white-space: pre; }`** in `<style>`: `white-space` has no valid effect on replaced elements (`<img>`). This is a no-op but signals template cruft; harmless in practice but should be cleaned.

- **`'Founders Grotesk'`** referenced in `a { font-family: 'Founders Grotesk', Helvetica, sans-serif; }` with no corresponding `@font-face` declaration in the provided source. If not declared elsewhere in the full HTML, every anchor will silently fall back to Helvetica. Confirm declaration exists below the truncation point.

- **Open Sans loaded from `fonts.gstatic.com/s/opensans/v17/`**: This is Google Fonts API v17 — the current release is v36+. The URLs still resolve but may become stale. More importantly, Gmail (non-Google Workspace), Outlook.com, and Yahoo block external `@font-face` requests entirely, so these declarations only benefit Apple Mail and iOS Mail. No rendering breakage, but the bandwidth is wasted for the majority of the list.

- **Mobile breakpoint at `max-width: 499px`**: Industry standard is 600px. Devices with viewport widths between 500–600px (tablets in portrait, some Android flagships) will receive desktop layout at a size where it may not render well.

- **Image alt text**: Cannot verify from truncated source. Confirm all `<img>` tags carry meaningful `alt` attributes for image-off rendering.
