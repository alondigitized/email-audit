## Technical Audit

## 1. Technical Summary
The email is a Salesforce Marketing Cloud (SFMC) send with 36 click-tracked links. It has one confirmed personalization failure (empty greeting) and a malformed, scheme-less tracking pixel URL. It also loads two images over `http://` and has several baseline accessibility gaps in the head and markup. The HTML source was truncated, so the footer, unsubscribe link and link UTMs could not be checked.

## 2. Link & Tracking Issues
- **Scheme-less pixel URL (confirmed in source):** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1…" width="1" height="1" />` has no `https://`. Mail clients resolve it as a relative path, so the request fails and the Validity/Return Path seed-tracking pixel never loads. It also has no `alt` attribute.
- **Insecure image sources (QA, confirmed):**
  - `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?...` (tracking pixel)
  - `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png` (content image)

  Gmail proxies these, but other clients and security gateways may block them or show mixed-content warnings. The Skechers-owned image host should serve HTTPS.
- **Many third-party pixels:** the hidden block contains 3 `beacon.krxd.net` calls (`usermatch` ×2, `ad_impression`) plus `ink1000.com`, in addition to the SFMC open pixel (`click.emails.skechers.com/open.aspx?qs=…`). This adds latency and blocking risk.
- **Click links not probed:** 36 links on click-redirect domains were skipped, so destination status is unverified.

## 3. Rendering & Accessibility
- **Wrong `<meta>` syntax:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv`, so neither takes effect. Charset then depends on the HTTP `Content-Type` header.
- **Zoom disabled:** the viewport tag has `maximum-scale=1`, which blocks pinch-zoom (WCAG 1.4.4).
- **No document language:** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang` or `xml:lang`.
- **Layout tables:** the visible layout tables (e.g. the `<table width="1" height="1">` and the 640px wrapper) have no `role="presentation"`, so screen readers may announce them as data tables.
- **Alt text:**
  - `dde00662-…png` is missing alt (QA). If it is a content image, this is a real gap.
  - The three `krxd` pixels and the `returnpath` pixel have no `alt` attribute.
  - The QA warning on `o.gif` is a false positive for accessibility, because the source has `alt=""`, which is correct for a decorative pixel.
- **Text scaling disabled:** `* { -webkit-text-size-adjust: none; }` stops iOS text scaling.
- **Dark-mode support:** no `color-scheme` meta or `prefers-color-scheme` rules appear in the visible CSS.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** the greeting renders as `Hi ,` because the name field is empty. This is a broken merge with no fallback.
- No unresolved raw tokens (`%%…%%`, `{{…}}`) are visible in the truncated source.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication:** the `Authentication-Results` header was not found because the message passed through the AgentMail relay. SPF, DKIM and DMARC are unknown, so this is a test-harness limitation and not a confirmed sender defect. The From address is `no-reply@emails.skechers.com`.
- **Unsubscribe and postal address:** these are in the truncated footer, and `List-Unsubscribe` headers were not provided, so they could not be verified.
- **Third-party data sharing:** the `krxd` URLs pass a SHA-256 hash (`partner_uid=adf27fee…189a`) and a subscriber ID (`partner_uid=122277199`) to a data-management platform. This is a privacy-disclosure and consent consideration under CCPA/GDPR, not a CAN-SPAM violation.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- The campaign identifier `MKG_US_NA_W_CATEGORY_GENDER_EN_11082026` is consistent across the `krxd` and `ink1000` pixels (`campaignid=` and `mi_ecmp=`).
- UTM parameters and landing pages could not be checked. The links are `click.emails.skechers.com` redirects that were skipped, and the body is truncated. The "Members take 20% off sitewide" preheader offer therefore can't be matched to a destination.

## 7. Recommendations
1. Add a fallback to the greeting merge (e.g. `Hi there,`, or drop the greeting when the name is empty) and fix whatever leaves the first-name field blank.
2. Change `pixel.app.returnpath.net/...` to `https://pixel.app.returnpath.net/...`, or remove it if it is no longer used.
3. Serve `image.emails.skechers.com` over HTTPS and switch `ink1000.com` to `https://`.
4. Add a meaningful `alt` to `dde00662-…png`, and `alt=""` to all pixels.
5. Fix the head metas to `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`. Remove `maximum-scale=1`, add `lang="en"` to `<html>`, and add `role="presentation"` to layout tables.
6. Re-run the audit against the full HTML and raw headers to check the footer unsubscribe link, `List-Unsubscribe`/`List-Unsubscribe-Post`, SPF/DKIM/DMARC alignment, and UTMs on the resolved click-through URLs.
