**Score:** 8/10 · **Type:** Email audit · **2026-07-02**
## Executive summary

- Okay, so I open my inbox during school drop-off and see the preview text — and it's the same JSON code dump I saw **twice yesterday** from this exact brand. At this point it's a Skechers thing at this point, and honestly the goodwill is wearing thin. I'm talking about a preview that starts with `[{ "@context": "http://schema.org/"...` — like, does anyone actually look at these before they hit send?
- Now, past the dumpster-fire preview text? The email body is actually solid. The BOGO 50% off is a real deal, the Plus member stacking code is right there in the email, and the patriotic theme is appropriately timed for July 4th. The layout is clean and the offer is front and center without me having to scroll. There's even a Kids section, which at least tells me someone on the list team knows I might have kids.
- But here's my honest reaction: I probably click through because the BOGO is genuinely compelling, especially if I can stack the 15% with my Plus account. ## What's working

- The BOGO 50% off hero is strong and immediately visible — that's the kind of specific deal that stops my thumb mid-scroll.
- The Plus member stacking code (SALE15, extra 15%) is a smart loyalty touch — rewards me for being in the program.
- The July 4th patriotic theme is well-timed and the red/white visual treatment is cohesive throughout the email.
- The Kids section exists and has its own CTA — at least I know I can click through and find stuff for my kids without hunting.
- The email body renders cleanly with no broken images or layout chaos — what's in the email actually looks professional.

## What's weak

- The JSON preheader is back — this is the third time in two days I've seen this exact bug from Skechers, and it's embarrassing at this point.
- "Stars, Stripes, and Savings" tells me absolutely nothing about what's inside — no percentage, no product, no reason to open if I'm scanning 40 emails fast.
- The Kids section feels like an afterthought — one small shoe image, no product name, no size mention, no girl/boy distinction for my 5-year-old and 9-year-old.
- No lifestyle model imagery at all — just floating shoes, which makes it feel like a catalog page rather than something curated for me as a mom.
- The sale deadline is buried in tiny fine print — I shouldn't need a magnifying glass to find when this ends.

## Recommendations

- 1. **Fix the JSON preheader — this is a P0 fire.** Every email sent after the first time this happened is a credibility hit. This should not be a third offense.
- 2. **Put the offer in the subject line.** "Stars, Stripes, and Savings" is filler. Tell me BOGO 50% is happening and I will open every time.
- 3. **Give the Kids section real weight.** Show me a girl's sneaker with some sparkle and a boy's lace-up and I'm immediately clicking. One generic red kids shoe doesn't make me feel seen as a mom.
- 4. **Surface the sale deadline prominently in the hero** — "Ends July 5" next to the BOGO callout would create actual urgency.
- 5. **Add the member code to the hero.** SALE15 is buried mid-email; if it were next to the BOGO offer, it reinforces why being a Plus member matters.

## Technical Audit

## Technical Audit — "Stars, Stripes, and Savings" (Skechers PLUS, 2026-07-02)

---

### 1. Technical Summary

The email has a systemic HTTP/mixed-content problem across 11+ image assets hosted on `image.emails.skechers.com`, plus a malformed Return Path monitoring pixel URL. These will cause silent failures in Gmail, Apple Mail, and Outlook, affecting image rendering and inbox placement telemetry.

---

### 2. Link & Tracking Issues

**Return Path pixel — missing protocol (broken URL)**
```html
<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1dbf0dcef79cbad82c12fe25342701e4499" .../>
```
No `https://` prefix. This is a relative URL pointing to a local path, not an external domain. The pixel will 404 silently, breaking deliverability/inbox-placement monitoring for this send.

**ink1000 open pixel — HTTP**
```
http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=PRO_US_NA_U_SITEBUNDLE_FULL_EN_07022026
```
Plain HTTP; will be blocked or upgraded by modern clients. Also missing `alt=""`.

**Krux subscriber ID in plain text**
```html
<img src="https://beacon.krxd.net/1x1_usermatch.gif?partner=LprH63a7_sfmc_100007688_subid&partner_uid=122277199" .../>
```
`partner_uid=122277199` appears to be a raw subscriber/list ID sent to a third-party DMP (Salesforce Audience Studio / Krux). The adjacent SHA256-hashed pixel is correctly anonymized; this one is not. Worth a privacy/data-sharing review depending on consent scope.

**27 click-redirect links skipped** — destination URLs and UTM parameters unverifiable from QA probe. See Section 6.

---

### 3. Rendering & Accessibility

**HTTP image sources — 11 confirmed assets**

All assets on `http://image.emails.skechers.com` will trigger mixed-content warnings or be blocked outright:

| Asset | Issue |
|---|---|
| Skechers logo (`dde00662…png`) | HTTP + renderable — likely blocked |
| Unknown content image (`49468f73…png`) | HTTP + missing `alt` |
| App Store badge | HTTP |
| Google Play badge | HTTP |
| Curbside Pickup icon | HTTP |
| AfterPay logo | HTTP |
| Find A Store icon | HTTP |
| Instagram, Facebook, YouTube icons | HTTP (3 assets) |

Gmail (since 2013) proxies and re-serves images over HTTPS; if the source is HTTP, it rewrites the URL, but broken or unreachable HTTP origins still fail. Apple Mail blocks mixed content entirely on iOS 16+.

**`-webkit-text-size-adjust: none` applied globally**
```css
* { -webkit-text-size-adjust: none; }
```
Prevents system font scaling in iOS Mail, breaking accessibility for users with Display Accessibility settings enabled. Should be scoped to `body` or specific containers at most.

**`maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Disables pinch-to-zoom in iOS Mail. WCAG 1.4.4 failure (Resize Text, Level AA).

**Redundant CSS breakpoints across two `<style>` blocks**

`.hideme`, `.widthFull`, `.width50percent`, `.show`, `.mobile-hidden` rules are duplicated across three breakpoints (`375px`, `480px`, `640px`) split across two separate `<style>` blocks. No functional breakage, but increases parse overhead and maintenance risk.

### 5. Compliance

**CAN-SPAM / unsubscribe** — Footer not included in the truncated source; unable to verify physical mailing address and one-click unsubscribe. No issues confirmed from visible HTML.

**Authentication headers** — Not available from HTML source alone; DKIM/SPF/DMARC pass/fail requires raw message headers. Sending domain `emails.skechers.com` should be verified against Skechers' published SPF and DKIM selectors separately.

**Data sharing (Krux pixels)** — Two third-party user-match pixels fire on open, one passing a raw subscriber ID. If any recipients are in California (CCPA) or EU (GDPR), this constitutes a data disclosure to a third party. Confirm this is covered by consent collected at sign-up.
