## Technical Audit

# Technical Audit: "Slip into October in style"

## 1. Technical Summary
The email has one confirmed broken-experience defect, an empty greeting slot (`Hi ,`). It also has several tracking-pixel and image-hygiene problems: a scheme-less pixel URL, `http://` image sources, and missing `alt` attributes. The HTML source was truncated, so the footer, the body links and the auth headers could not be checked.

## 2. Link & Tracking Issues
- **Broken pixel URL:** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…">` has no scheme. Clients resolve it as a relative path, so the request never reaches Return Path. The seed/inbox-placement tracking won't register, and the email may be requesting a bad URL on its own host.
- **Insecure tracking pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=MKG_US_NA_U_SLIPIN_PROD_EN_10172026` loads over plain HTTP. Clients that block mixed content will drop it, and the request is exposed in transit.
- **Hashed email in a third-party URL:** The Krux beacon `https://beacon.krxd.net/1x1_usermatch.gif?partner=LprH63a7_sfmc_100007688_sha25&partner_uid=adf27fee…189a` carries what appears to be a SHA-256 of the recipient's address. A second beacon carries a numeric subscriber ID (`partner_uid=122277199`). The pixels are hidden, but the request still sends this identifier to a third party.
- **Unverified links:** 34 tracking links were skipped because they are click-redirect domains, so none of their destinations were validated.

## 3. Rendering & Accessibility
- **Malformed meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv` attribute, so neither declares anything. The charset declaration is ineffective, which risks mojibake for `®` and other special characters in some clients.
- **Missing `alt` text:**
  - `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png` (QA-flagged).
  - `o.gif` from ink1000 (QA-flagged).
  - The three Krux beacons and the Return Path pixel, in the visible source (the QA check did not report these).
  - Only the first image above is likely to be user-visible. The rest are tracking pixels.
- **Insecure image source:** `dde00662-….png` loads over `http://image.emails.skechers.com/…`. It may be blocked or show a mixed-content warning. The same host should serve HTTPS.
- **Missing `lang` attribute:** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang`.
- **Missing `role="presentation"`:** The layout tables seen in the source (`<table cellpadding="0" cellspacing="0" border="0">` and the 640px wrapper) have no `role="presentation"`. Screen readers may announce them as data tables.
- **Hidden-pixel markup:** Hiding the pixels with `display:none` plus `width="0" height="0"` is inconsistent. Some clients strip hidden content or hide the container, which can suppress pixel loads.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** The QA check found a greeting with an empty name field (`Hi ,`). The merge field resolved to an empty string with no fallback. This is visible to the recipient and should be fixed with a default value (e.g., `Hi there,`) or by suppressing the greeting when the name is blank.
- The greeting markup was outside the truncated source, so the exact token could not be inspected.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication-Results header not found:** SPF, DKIM and DMARC status is unknown. The QA tool notes this is expected through the AgentMail relay, so it is not evidence of a sender-side failure. The sending domain (`emails.skechers.com`) would need a check against the original message.
- **Sender address:** `no-reply@emails.skechers.com` is a non-replyable sender. This is a best-practice concern, not a CAN-SPAM violation.
- **Not verifiable:** The unsubscribe link, `List-Unsubscribe` / `List-Unsubscribe-Post` headers and the physical postal address are not in the truncated source or the QA data.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Campaign ID in pixels only:** `MKG_US_NA_U_SLIPIN_PROD_EN_10172026` appears in the Krux ad-impression pixel and the ink1000 pixel.
- **Not verifiable:** The UTM parameters and landing pages on the 34 click-tracked links were not visible, so the campaign naming could not be compared with the pixel IDs.

## 7. Recommendations
1. Add a fallback to the first-name merge field, or suppress the greeting when it's empty (fixes `Hi ,`).
2. Fix the Return Path pixel to `https://pixel.app.returnpath.net/pixel.gif?r=…`.
3. Change `http://www.ink1000.com/…/o.gif` and `http://image.emails.skechers.com/…/dde00662-….png` to HTTPS, and confirm both hosts serve valid certificates.
4. Add `alt=""` to the decorative and tracking images. Add descriptive `alt` text to `dde00662-….png` if it's visible content.
5. Replace the two meta tags with `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` and `<meta http-equiv="X-UA-Compatible" content="IE=edge" />`.
6. Add `lang="en"` to `<html>` and `role="presentation"` to the layout tables.
7. Review whether sending a hashed email and subscriber ID to `beacon.krxd.net` fits the stated privacy policy and consent practices.
8. Re-run the audit against the full HTML and raw headers to cover the unsubscribe/footer, the `List-Unsubscribe` headers, SPF/DKIM/DMARC, and UTM consistency across the 34 links.
