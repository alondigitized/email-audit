### 3. Rendering & Accessibility

**Issue 1 — Malformed `<meta>` tags (confirmed):**

```html
<meta content="text/html; charset=utf-8" />
<meta content="IE=edge" />
```

Both are missing their `http-equiv` attribute. Correct forms:

```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```

Without `http-equiv`, these directives are inert. The charset declaration in particular may not be honoured by strict parsers, risking character encoding fallback on special characters (e.g., the `✨` in subject line).

**Issue 2 — Undefined font family `'Founders Grotesk'` (confirmed):**

```css
a {
  font-family: 'Founders Grotesk', Helvetica, sans-serif;
}
```

Six `@font-face` blocks define only `'Open Sans'`. No declaration for `'Founders Grotesk'` exists in the `<head>`. Every link in the email will silently fall back to Helvetica. If the brand typeface is intended for anchors, the web-font must be declared or the rule corrected to `'Open Sans'`.

**Issue 3 — `white-space: pre` on `img` (confirmed):**

```css
img { -ms-interpolation-mode:bicubic; white-space:pre; }
```

`white-space: pre` is not a valid or meaningful property for replaced elements (`<img>`). It has no rendering effect in most clients but is noise that could interact unexpectedly with whitespace-sensitive parsers. Should be removed.

**Issue 4 — Stale Google Fonts version:**

All `@font-face` `src` URLs reference `opensans/v17` (circa 2019). Current version is v40+. Google Fonts versioned URLs remain stable, so this is not a breakage risk, but kerning and glyph corrections in v18–v40 are absent.

**Cannot assess from truncated source:** image `alt` attribute completeness, link contrast ratios, `role`/`aria-label` on decorative images.
