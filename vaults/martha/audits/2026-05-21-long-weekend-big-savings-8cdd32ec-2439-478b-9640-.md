# Long Weekend, Big Savings
**Score:** 8/10 · **Type:** Email audit · **2026-05-21**
## Executive summary

- Oh for the love of — the JSON preview is *back*. Two emails in a row (May 19, May 20) that actually looked normal in my inbox, and now we're right back to schema garbage where the preheader should be. I flagged this five consecutive times between May 14 and May 18, and someone apparently fixed it for a minute and then broke it again. At this point I'm not even surprised, just tired.
- The email body itself is actually solid for me right now. Memorial Day BOGO 50% off is real money when I'm buying sneakers for two growing kids. The layout is clean, the offer is front and center, and — crucially — there is a SHOP KIDS' button that's visible without scrolling too far. The Skechers Plus reward callout is a nice touch because yes, I track my points.
- I'd probably click through to the kids' section, but I would not forward this to anyone. The broken inbox preview has become a brand perception problem at this point, and I'd be embarrassed to share something this sloppily packaged.

## What's working

- **BOGO 50% off is unmissable** — big red text, hero placement, immediately clear math. For a two-kid household this offer is genuinely compelling.
- **SHOP KIDS' CTA is present** — small wins, but it's there and I don't have to hunt for it.
- **Skechers Plus $5 reward callout** — I'm a member and I noticed it. That "earn more" hook works on me.
- **Memorial Day timing is right** — I'm actively thinking about summer shoes for the kids right now; this landed at the right moment in the season.
- **Afterpay / Klarna logos in footer** — I use buy-now-pay-later for bigger basket orders and the options being visible reduces friction.

## What's weak

- **The JSON preview text is back** — We literally fixed this for May 19 and 20, and now it's broken again on May 21. This is a QA systems failure, not a one-off accident.
- **Kids' section is third in the scroll** — Women's, then Men's, *then* Kids'. I shop for my kids first; the hierarchy doesn't match my actual behavior.
- **No deadline on the offer** — "Long Weekend" implies Memorial Day but I don't see a "Sale ends Monday" anywhere. Without a hard date, the urgency softens.
- **Kids' imagery is too generic** — I can't tell if those shoes are for a 5-year-old girl or a 9-year-old boy. I need to see sparkle/light-up or durable lace-up to know if this applies to my specific kids.
- **This feels like a repeat send** — The May 18 email was also Memorial Day BOGO with almost the same layout. If this is a resend-to-non-openers, it reads as lazy to me.

## Recommendations

- 1. **Fix the preview text pipeline permanently** — this is send #7 or #8 with broken preview. Every broken preview undercuts open rates and erodes brand trust. A/B test a real preheader this week.
- 2. **Move SHOP KIDS' up or add it to the hero row** — make the hero CTA split: "Shop Women's | Shop Men's | Shop Kids'." A mom clicks kids' first.
- 3. **Add a hard deadline** — "Sale ends Monday, May 26" somewhere in the hero would meaningfully lift urgency.
- 4. **Segment or personalize the kids section** — even a "Girls' Sneakers | Boys' Sneakers" split beneath the Kids' header would help me route faster.
- 5. **Vary the creative from May 18** — if this is a resend, change the hero visual or headline so it doesn't feel like I'm being recycled content.

## Technical Audit — "Long Weekend, Big Savings" (Skechers, 2026-05-21)

### 1. Technical Summary

One broken-experience bug (empty name merge token) and a systemic HTTP image-serving issue affecting the entire asset CDN. No structural rendering failures, but the HTTP images create a security-warning risk in clients that enforce HTTPS for remote content.

---

### 2. Link & Tracking Issues

**Tracking pixel served over HTTP**
- `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif` — plain HTTP. Gmail and most modern clients proxy images over HTTPS; a non-HTTPS pixel may be silently blocked or flagged.
- Return Path pixel has no protocol specified: `pixel.app.returnpath.net/pixel.gif` — defaults to HTTP in XHTML. Inbox placement monitoring data may be unreliable.

**27 click-redirect links unverifiable**
- All CTA links route through `click.emails.skechers.com`. The QA probe skipped these (correct behavior), so UTM parameter correctness cannot be confirmed from this audit alone. See §6.

**Krxd DMP beacons** — HTTPS, no issue.

**Open pixel** (`click.emails.skechers.com/open.aspx`) — HTTPS, no issue.

---

### 3. Rendering & Accessibility

**HTTP image CDN — systemic**
All content and footer images are served from `http://image.emails.skechers.com` (plain HTTP). Affected assets:

Risk: clients with strict mixed-content policies (Apple Mail on iOS 15+, some Outlook versions) may block or flag these images. The CDN `image.emails.skechers.com` should be reachable over HTTPS — this appears to be a configuration omission, not a missing certificate.

**Missing alt text**
- `o.gif` (ink1000 pixel) — no `alt` attribute
- `49468f73-4651-4af3-bea2-61d1ae5db486.png` — no `alt` attribute; this appears to be a content image, meaning subscribers with images disabled see nothing in that slot

**Duplicate media query blocks**
Two separate `<style>` blocks define `.show` and `.mobile-hidden` breakpoint rules at different max-widths (375px, 480px, 640px, 680px). This is not a rendering failure in practice but adds maintenance risk and parse overhead.

**`-webkit-text-size-adjust: none`** — set globally on `*`. This is intentional for email but suppresses user accessibility preferences system-wide in WebKit clients.

---

### 4. Personalization & Merge Tokens

**[FAIL — Broken Experience]** Greeting renders as `"Hi ,"` — the subscriber first-name token resolved to an empty string. This is the sole broken-experience finding in QA.

Likely cause: the merge field (e.g., `%%First Name%%` or `{{firstName}}`) had no fallback value defined for subscribers with a null or empty name field. Standard fix is a conditional default: `Hi %%[IF EMPTY(FirstName, 1)]%%there%%[ELSE]%%%%=FirstName=%%%%[ENDIF]%%,`.

No other unresolved tokens observed in the visible HTML.

### 5. Compliance (CAN-SPAM, Unsubscribe, Authentication)

The HTML is truncated before the footer, so the physical mailing address and unsubscribe link cannot be directly confirmed from the source provided. QA did not flag a missing unsubscribe link, which suggests it is present downstream.

**Headers not available for review** — DKIM, SPF, and DMARC authentication cannot be assessed from HTML source alone. Sender domain is `emails.skechers.com`; authentication should be verified at the MTA level.

**Preheader** is implemented correctly via `display:none` with a fallback `<div class="preheader">` pattern. No issues.
