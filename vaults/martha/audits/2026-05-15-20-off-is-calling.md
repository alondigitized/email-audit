# $20 Off Is Calling ✨
**Score:** 9/10 · **Type:** Email audit · **2026-05-15**
## Executive summary

- OK so I'm seeing this on my phone probably while my kids are doing something I'm pretending requires no supervision. Sally Beauty again — this is like the fourth or fifth one this week, I swear. The flash sale structure is immediately obvious: $10 off $50, $20 off $75, code is right there. No hunting for it. Honestly? That part is done right.
- What stops me is I open this and it's... hair color. All of it. The model, the featured products, the "top searched online" section — it's permanent dye, Wella, ion, the works. That's fine, I'm not opposed to buying hair color, but I don't think of Sally first when I need it, and I'm not currently in that headspace. I'm thinking about whether my son needs new cleats before summer league starts.
- I'd probably glance at the offer, note the May 17 deadline, and decide whether I need to top off my hair color stock. If yes, I click. If no, I mark it read and move on. I would not forward this — it's a straight promo, nothing surprising or delightful enough to share with a friend.

## What's working

- **The offer is immediately legible** — "$10 off $50 / $20 off $75" stacked in giant type with the code right below. I don't have to go hunting.
- **Deadline is visible in the hero** — "Ends May 17" is right there, not buried in fine print. That two-day window actually feels real.
- **"Top searched online" gives me a shortcut** — I don't want to browse; showing me what other people are buying is a useful prompt and feels credible.
- **No broken images, clean layout** — renders fine on mobile, nothing janky or overlapping.
- **Klarna callout is there** — I'm price-sensitive and that $75 threshold is a stretch; knowing I can split it is genuinely helpful.

## What's weak

- **Cadence is getting loud** — I've had Sally emails on the 5th, 7th, 10th, 11th (twice), and 14th. Today's the 15th. At some point I start feeling like I'm being hassled, not marketed to. The "Free 2 Hour Delivery" email on the 10th felt special; this one just feels like another drop in the bucket.
- **No loyalty hook** — I have a Sally Beauty Rewards account and there's zero mention of points, member pricing, or my balance. That's a missed touch for someone like me who specifically responds to rewards.
- **"Shop now" is fine but generic** — Given the products are all hair color, "Shop Hair Color" or "Shop the Flash Sale" would've been more precise.
- **The model reads young and unattached** — she's gorgeous but she's giving "free Saturday afternoon" energy. The email treats me like a solo beauty consumer, not a mom who's fitting in a purchase between school pickups.

## Recommendations

- 1. **Add a loyalty hook in the hero** — even one line: "Sally Rewards members earn double points through May 17." That costs nothing and makes me feel like a known customer instead of a randomer on their list.
- 2. **Segment the "top searched" picks tighter** — if I've bought brunette color before, show me brunette products. If they're sending the same four products to everyone, that's a missed personalization moment.
- 3. **Chill on the cadence** — I know this is a batch-send decision, but a promo almost every day erodes the sense of urgency. The flash sale can't feel special if everything is a flash sale.
- 4. **CTA copy** — change "Shop now" to "Shop the Flash Sale" or "Grab $20 Off" to make it feel action-tied to the offer.
- **Subject Alt A:** `Flash Sale: $20 Off Ends Sunday`
- **Subject Alt B:** `Your $20 Off Code Expires May 17`
- **Preheader Alt A:** `$10 off $50 or $20 off $75 — code SAVE20, online only through Sunday.`
- **Preheader Alt B:** `Stock up before Sunday: SAVE20 takes $20 off your $75+ order.`

### 3. Rendering & Accessibility

**Issue — malformed `<meta>` tags (two instances):**

```html
<!-- Missing http-equiv="Content-Type" -->
<meta content="text/html; charset=utf-8" />

<!-- Missing http-equiv="X-UA-Compatible" -->
<meta content="IE=edge" />
```

Both tags are missing their `http-equiv` attribute. Without it, the charset declaration is inert — clients that don't default to UTF-8 may mis-render special characters (the `✨` in the subject line and any curly quotes or em-dashes in body copy). The IE=edge hint is similarly ignored, though it has no practical impact on modern clients.

**Correct form:**
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```

**Issue — `img { white-space: pre; }` declaration:**

```css
img { -ms-interpolation-mode:bicubic; white-space:pre; }
```

`white-space:pre` is a non-standard and potentially harmful declaration on `img` elements. It has no defined effect on replaced elements but can cause whitespace artifacts or layout gaps in edge cases (particularly older WebKit and some webmail renderers that partially parse inline CSS). Standard practice is to omit it entirely.

**Issue — 'Founders Grotesk' referenced but not loaded:**

```css
a { font-family:'Founders Grotesk', Helvetica, sans-serif; }
```

No `@font-face` declaration for Founders Grotesk exists in the `<head>`. Six `@font-face` blocks load Open Sans variants, but Founders Grotesk is absent. All `<a>` elements will silently fall back to Helvetica. If this is intentional (system-font fallback), the primary font name should be removed to avoid misleading the cascade. If it should render, the woff2 source must be added.

**Issue — Stale Google Fonts version pin:**

All Open Sans `@font-face` declarations reference `opensans/v17/` from `fonts.gstatic.com`. The current Open Sans release is v40+. While Google typically keeps old version URLs alive indefinitely, v17 predates variable font support and Unicode coverage updates. This is low-urgency but worth updating on next template revision.

**No issues found:** Viewport meta is correctly formed; `x-apple-disable-message-reformatting` is present; `a[x-apple-data-detectors]` override is correctly scoped; mobile breakpoint structure (stack/hide/show classes) appears syntactically sound in the visible portion.
