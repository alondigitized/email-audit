### 3. Rendering & Accessibility

**`<meta>` tags missing required `http-equiv` attributes (two instances):**
```html
<!-- as written — ineffective -->
<meta content="text/html; charset=utf-8" />
<meta content="IE=edge" />

<!-- correct form -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without `http-equiv`, these are inert custom attributes. The charset declaration in particular may cause mojibake in older Outlook/Lotus clients.

**`img { white-space: pre; }` — non-standard rule:**
```css
img { -ms-interpolation-mode:bicubic; white-space:pre; }
```
`white-space: pre` on `<img>` elements has no defined effect and can introduce unexpected spacing in WebKit-based renderers. The conventional fix for the bottom-gap issue is `display: block`, not `white-space: pre`.

**Google Fonts loading stale version (v17, current is v40+):**
```
https://fonts.gstatic.com/s/opensans/v17/...
```
Web fonts via `@font-face` are blocked in Gmail (web and app), Outlook 2007–2021 (Word renderer), and most Android mail clients. Fallback to `Helvetica, sans-serif` will apply silently in the majority of the subscriber base — this is expected behavior but the stale version tag is unnecessary technical debt.

**`Founders Grotesk` referenced but no `@font-face` declaration present:**
```css
a { font-family:'Founders Grotesk', Helvetica, sans-serif; }
```
No corresponding `@font-face` block for Founders Grotesk exists in the visible source. Every email client will immediately fall back to Helvetica — link typography will not match design intent.

**Alt text on images:** Not verifiable from truncated source. Must confirm all `<img>` tags carry descriptive `alt` attributes (not empty `alt=""`) for accessibility and image-off rendering.
