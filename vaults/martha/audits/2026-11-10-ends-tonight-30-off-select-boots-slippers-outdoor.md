## Technical Audit

# Technical Audit: "Ends Tonight! 30% off select boots, slippers, & outdoor"

The HTML source was truncated after the header and tracking-pixel block, so the body, footer and links were not inspected. Findings below come from the visible source and the automated QA output only.

## 1. Technical Summary
The email has one confirmed broken-experience defect: an empty personalization slot that renders "Hi ,". It also has a malformed tracking pixel, two non-HTTPS images, missing alt text, and ineffective `<meta>` declarations. The 71% QA pass rate comes from that one FAIL plus warnings.

## 2. Link & Tracking Issues
- **Scheme-less pixel URL.** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…" width="1" height="1">` has no `http(s)://`. Clients resolve it as a relative path, so the Return Path/Validity seed-tracking pixel will 404 or never fire. It also has no `alt`.
- **HTTP tracking pixel.** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=PRO_US_NA_U_SITESELECT_ENGAGEDL7D_EN_11102026` is non-HTTPS and may be blocked or flagged as mixed content. The `mi_u` value is sent in cleartext.
- **Pixel volume.** The pre-body block contains six 0/1px beacons: one SFMC open pixel (`click.emails.skechers.com/open.aspx`), three `beacon.krxd.net` usermatch/impression GIFs, the Return Path pixel and the ink1000 pixel. Several are third-party.
- **Unprobed links.** 46 tracking links were skipped by the QA tool as click-redirect domains, so click-through destinations and status codes are unverified.

## 3. Rendering & Accessibility
- **Missing alt text (QA WARN).** `o.gif` (ink1000) and `dde00662-169f-447d-b0e2-fc65f6c2290c.png` have no alt attribute. In the visible source, the three `krxd.net` beacons and the Return Path pixel also have none (the SFMC open pixel has `alt=""`).
- **HTTP content image.** `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-….png` loads over HTTP and may be blocked. As a content image rather than a pixel, it can cause a visible broken-image gap.
- **Ineffective meta tags.** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv` attribute, so neither declaration is valid. Charset then depends solely on the HTTP header.
- **Zoom blocked.** The viewport meta sets `maximum-scale=1`, which disables pinch-zoom. `* { -webkit-text-size-adjust: none }` also stops iOS text scaling.
- **No document language.** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang` attribute.
- **Layout tables.** The visible `<table>` elements have no `role="presentation"`, so screen readers may announce them as data tables.
- **Hidden-content method.** The preheader and pixel wrappers rely on `display:none !important`, which is acceptable.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot.** The greeting renders as `Hi ,` because the first-name field is blank for this recipient. There is no visible fallback.
- **Evidence limit.** The greeting is in the truncated portion, so the exact merge syntax cannot be shown. The fix is a fallback default or conditional (for example, AMPscript `IIF(Empty(@firstname), "there", @firstname)`) or suppressing the greeting.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **[WARN] Authentication-Results header not found.** SPF/DKIM/DMARC status is unknown. The QA notes this is expected via the AgentMail relay, so it is a test-harness limitation rather than a confirmed sender fault. The From domain `emails.skechers.com` is consistent with the click and image domains.
- **Not verifiable.** The footer, physical postal address and unsubscribe link are in the truncated HTML. The `List-Unsubscribe` and `List-Unsubscribe-Post` headers were not supplied. I'm not flagging them as missing.
- **Privacy observation.** `beacon.krxd.net/1x1_usermatch.gif?partner=…_sha25&partner_uid=adf27fee…189a` sends a 64-hex SHA-256 value (likely a hashed identifier) to a third party. A second usermatch call passes `partner_uid=122277199`, probably a subscriber ID. The first partner name is truncated to `_sha25`, which may indicate a misconfigured key. This warrants a privacy-policy and consent check.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Unverifiable.** All 46 links were skipped as tracking redirects, and no resolved destination URLs or UTM parameters are in the data.
- **Campaign identifier.** `PRO_US_NA_U_SITESELECT_ENGAGEDL7D_EN_11102026` appears in the pixel URLs. It is not confirmed to propagate to link `utm_campaign`.

## 7. Recommendations
1. Fix the empty greeting. Add a fallback or suppress the greeting when the first name is blank. This is the only hard failure.
2. Correct the Return Path pixel to `https://pixel.app.returnpath.net/pixel.gif?...`.
3. Move `o.gif` and `dde00662-….png` to HTTPS. Confirm `image.emails.skechers.com` serves a valid certificate over HTTPS.
4. Add `alt=""` to all decorative pixels, and descriptive alt text to `dde00662-….png` if it is a content image.
5. Change the meta tags to `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
6. Remove `maximum-scale=1`, and drop or reconsider `-webkit-text-size-adjust: none`.
7. Add `lang="en"` to `<html>` and `role="presentation"` to layout tables.
8. Re-run QA on the full HTML and raw headers. This should cover the footer, unsubscribe link, `List-Unsubscribe` headers and Authentication-Results. Also resolve the redirect chains to check UTM parameters and landing-page status.
9. Review the krxd/ink1000 third-party pixels for consent and hashed-identifier handling.
