## Technical Audit

## 1. Technical Summary
Email is structurally sound XHTML 1.0 Transitional with responsive media queries, but ships with a broken personalization token (empty greeting), a non-HTTPS image CDN across all assets, and missing alt text on multiple images. One pixel tracker uses a relative URL that will likely 404 in most clients.

## 2. Link & Tracking Issues
- **Malformed tracker URL**: `pixel.app.returnpath.net/pixel.gif?r=964ce1...` is missing the `https://` scheme. As a relative path it will resolve against the rendering client's base URL and fail. Should be `https://pixel.app.returnpath.net/pixel.gif?...`.
- **27 tracking/click-redirect links skipped** by HTTP probe — not validated end-to-end. Cannot confirm redirect chain integrity or final-destination 200 status without manual sampling.
- **Open-pixel + Krux + ReturnPath + ink1000** stack loads 5 separate tracking beacons in the hidden header block; one (`ink1000`) is duplicated outside the `display:none` wrapper.

## 3. Rendering & Accessibility
- **Mixed content (HTTP images)**: All `image.emails.skechers.com` assets and the `ink1000.com` open pixel are served over `http://`. Gmail/Apple Mail proxy images, but strict clients (some corporate webmail, mobile previews with HSTS) may block or downgrade-warn. Affected: logo, hero, app-store badges, payment/social icons (~10+ assets).
- **Missing `alt` attributes** on at least:
  - `o.gif` (ink1000 tracker — should be `alt=""` since decorative)
  - `49468f73-4651-4af3-bea2-61d1ae5db486.png` (content image — needs descriptive alt)
- **Duplicate `@media only screen and (max-width: 640px)` block** repeats the entire `max-width: 375px` ruleset verbatim — bloats the head and is a maintenance hazard.
- **Conflicting `mobile-content` / `desktop-content` defaults**: `.mobile-content { display: block }` with no mobile-scoped override means it stays visible on desktop until the `min-width: 768px` rule fires; clients without media query support (Outlook desktop) will show both blocks.
- Missing `<meta http-equiv>` attribute name on the `IE=Edge` meta tag (`<meta content="IE=Edge" />` lacks `http-equiv="X-UA-Compatible"`).

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot** confirmed by QA: greeting renders as `Hi ,` — merge token for first name resolved to empty string. Indicates either a missing fallback in the SFMC AMPscript (`%%=v(@FirstName)=%%` without `IIF`/`ISNULL`) or a subscriber record with NULL FirstName not caught by the send filter.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- HTML source is truncated before the footer — **unsubscribe link, physical postal address, and List-Unsubscribe header presence cannot be verified** from this excerpt.
- Sending domain `emails.skechers.com` is a standard SFMC subdomain; SPF/DKIM/DMARC headers not provided in this payload, so authentication status is unverified.

## 6. Email-to-Site Continuity
- HTML excerpt does not include any CTA `<a href>` targets — UTM parameter presence and landing-page alignment cannot be assessed from the provided source.
- Campaign ID `MKG_US_NONPURCLICK_U_COZY_NONPURCH_EN_05232026` is consistently passed to Krux (`campaignid=`) and ink1000 (`mi_ecmp=`), suggesting cross-vendor attribution is wired correctly.

## 7. Recommendations
1. **Fix the merge token**: wrap FirstName with a fallback, e.g. `%%=IIF(EMPTY(@FirstName), "there", @FirstName)=%%`, or exclude NULL-FirstName subscribers from sends that use a personalized greeting.
2. **Migrate all image hosts to HTTPS** — both `image.emails.skechers.com` and `ink1000.com` open-pixel. SFMC supports HTTPS image hosting; this is a config flip in Content Builder.
3. **Repair the ReturnPath pixel URL** by adding the `https://` scheme.
4. **Add `alt=""` to all tracking pixels** and descriptive alt text to the content image `49468f73-...png`.
5. **Deduplicate the 375px/640px media query block** — collapse into a single rule.
6. **Fix the X-UA-Compatible meta tag**: `<meta http-equiv="X-UA-Compatible" content="IE=Edge" />`.
7. **Manually sample the 27 skipped tracking redirects** to confirm final URLs return 200 and carry expected UTM params (not visible in this excerpt).
8. **Verify footer compliance elements** (unsubscribe, postal address, List-Unsubscribe header) against the full HTML — not assessable here.
