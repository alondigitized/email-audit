## Technical Audit

## 1. Technical Summary
The email has one confirmed broken-experience defect (empty greeting merge field) and one malformed tracking pixel URL with no scheme. It also has insecure `http://` image sources and several accessibility and markup gaps. The HTML was truncated and 32 click-tracking links were not probed, so footer, unsubscribe, and link-level checks could not be completed.

## 2. Link & Tracking Issues
- **Scheme-less pixel URL (confirmed in source):** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…" width="1" height="1" />` has no `https://`. Clients resolve it as a relative path, so the request fails and the Return Path/Validity seed-tracking pixel never loads.
- **Mixed content / `http://` sources (QA WARN ×2):**
  - `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=…&mi_ecmp=MKG_US_NA_U_RUN_PROD_EN_11242026`
  - `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png`
  - Gmail's image proxy and Apple Mail Privacy features may block or rewrite these. The second is a content image on the brand's own domain, so it is likely to show as broken in strict clients.
- **Unverified links:** 32 click-redirect links were skipped (tracking domains). Destination status, redirect chains, and final landing URLs are unknown.
- **Open pixel placement:** the primary open pixel (`click.emails.skechers.com/open.aspx?qs=…`) sits inside `<div style="display:none !important">` within a `display:none` `<td>`. Some clients don't fetch images inside `display:none` containers, so open tracking can be undercounted.

## 3. Rendering & Accessibility
- **Alt text:**
  - The QA warning for `o.gif` looks like a false positive. The source has `alt=""`, which is valid for a tracking pixel.
  - The three `beacon.krxd.net` pixels and the `returnpath` pixel have no `alt` attribute at all.
  - `dde00662-…png` is flagged by QA for missing alt, and that image is a content image. Confirm whether it carries meaning.
- **Viewport:** `maximum-scale=1` in `<meta name="viewport">` blocks pinch-zoom (WCAG 1.4.4).
- **Text scaling:** `* { -webkit-text-size-adjust: none; }` disables iOS text resizing.
- **Meta tags malformed:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` both lack `http-equiv`, so neither declaration takes effect. The charset then relies on the HTTP/MIME header.
- **Table semantics:** visible layout tables, such as `<table cellpadding="0" cellspacing="0" border="0">` and `<table class="widthFull" width="640">`, have no `role="presentation"`. Screen readers may announce them as data tables.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** the greeting renders as `Hi ,`, so the first-name merge field resolved to empty with no fallback. The greeting itself was cut off in the truncated source. This is likely a missing profile value for the test recipient, but the template has no default value or conditional (e.g. `%%=IIF(Empty(@firstname),…)=%%`), so any member with a blank first name gets the same broken greeting.
- No unresolved `%%…%%` or `{{…}}` tokens are visible in the supplied source.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication:** the `Authentication-Results` header was not found. QA attributes this to the AgentMail relay, so SPF, DKIM, and DMARC status is **unverified**. It is a test-harness limitation, not a confirmed sender defect.
- **Unsubscribe and physical address:** not in the truncated source, so they cannot be confirmed. `List-Unsubscribe` and `List-Unsubscribe-Post` headers are also not in the supplied data.
- **Third-party data sharing:**
  - Hidden pixels send a 64-hex value to `beacon.krxd.net/1x1_usermatch.gif?partner=LprH63a7_sfmc_100007688_sha25&partner_uid=adf27fee…`. The `sha25` partner name suggests a SHA-256 hash of the subscriber's email.
  - A second pixel sends the subscriber ID: `partner_uid=122277199`.
  - These are user-match calls to a Salesforce/Krux data platform. They should be covered by the privacy policy and consent basis, and some privacy-focused clients will block them.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Campaign ID:** it is consistent across tracking systems (`MKG_US_NA_U_RUN_PROD_EN_11242026` in both the krxd `campaignid` and the ink1000 `mi_ecmp`). The send date (11/24/2026) matches.
- **UTMs and landing pages:** not assessable. All 32 CTAs go through `click.emails.skechers.com` redirects that were not resolved, so there is no evidence of UTM parameters, landing-page alignment, or whether the "Aero Series" 15% offer appears on the destination.

## 7. Recommendations
1. Fix the Return Path pixel to `https://pixel.app.returnpath.net/pixel.gif?r=…`.
2. Change both `http://` image sources (`ink1000.com` and `image.emails.skechers.com`) to `https://`. Confirm the image host serves a valid certificate.
3. Add a fallback to the first-name merge field (e.g. `Hi there,` or drop the name) so blank profiles don't render `Hi ,`.
4. Add `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"` to the two meta tags.
5. Remove `maximum-scale=1` from the viewport tag. Add `role="presentation"` to layout tables. Add `alt=""` to the krxd and returnpath pixels, and meaningful alt text to `dde00662-…png` if it is a content image.
6. Move the primary open pixel out of the `display:none` container, for example into a 1×1 visible-but-transparent location.
7. Re-run QA with the full HTML (not truncated) and a real-header capture. Then follow the 32 redirects to verify destination status, UTM presence, `List-Unsubscribe` headers, the footer unsubscribe link, and SPF/DKIM/DMARC alignment.
