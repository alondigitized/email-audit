### 3. Rendering & Accessibility

**Issue 1 — Undeclared font family (confirmed):**
The global anchor rule references a font that is never loaded:
```css
a { font-family: 'Founders Grotesk', Helvetica, sans-serif; }
```
No `@font-face` declaration for `Founders Grotesk` exists anywhere in the `<style>` block. All six `@font-face` blocks load Open Sans variants only. Every `<a>` element will silently fall back to Helvetica. If brand typography on CTAs is intentional, the font must be added or the rule corrected.

**Issue 2 — `img { white-space: pre; }` (confirmed):**
```css
img { -ms-interpolation-mode: bicubic; white-space: pre; }
```
`white-space: pre` on `<img>` is not a standard email hack and has no documented benefit. It can trigger unexpected whitespace gaps around images in WebKit-based clients (Apple Mail, iOS Mail). Should be removed.

**Issue 3 — Malformed `<meta>` attributes (confirmed):**
```html
<meta content="text/html; charset=utf-8" />
<meta content="IE=edge" />
```
Both are missing their `http-equiv` attributes. Correct forms:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without `http-equiv="Content-Type"`, Outlook 2007–2019 (Word rendering engine) may not respect the charset declaration and can misrender special characters (em-dashes, curly quotes, accented characters).

**Issue 4 — Stale Google Fonts version (minor):**
All `@font-face` sources reference Open Sans `v17` (e.g., `opensans/v17/...`). Current CDN version is v40+. The v17 URL still resolves, but it is an unnecessarily old pin. No functional breakage today, but worth updating on next template refresh.
