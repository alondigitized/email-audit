## Technical Audit

## 1. Technical Summary
The email has a confirmed broken personalization slot (empty greeting, "Hi ,") and several tracking-pixel defects: an insecure `http://` pixel and a scheme-less pixel URL. Authentication status and the footer/unsubscribe markup could not be verified from the truncated source and QA data.

## 2. Link & Tracking Issues
- **Scheme-less pixel URL (confirmed in source):** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…">` has no `https://`. Clients resolve it as a relative path, so the Return Path/Validity pixel won't fire. It also has no `alt`.
- **Insecure pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=PRO_US_NA_U_SITEEXTRA_LOYL_EN_10312026`. It is plain HTTP, so clients that block mixed or insecure content will drop it, and the request is exposed in transit. The URL carries a user ID (`mi_u`).
- **Third-party beacons (`beacon.krxd.net`):** three hidden pixels (`1x1_usermatch.gif` ×2, `1x1_ad_impression.gif`) are sent to a third-party DMP. The URLs carry a SHA-256 hash of the recipient's email (`partner_uid=adf27fee…`) and a subscriber ID (`partner_uid=122277199`). They have no `alt`, and hiding them with `display:none` / `width=0` is unreliable in some clients.
- **Skipped probes:** 30 tracking links were not HTTP-probed because they use click-redirect domains (e.g. `click.emails.skechers.com`). Link validity and destinations are unverified.
- **Open pixel:** `click.emails.skechers.com/open.aspx?qs=…` is HTTPS and formed correctly.

## 3. Rendering & Accessibility
- **Alt text:** QA flags `o.gif` as missing `alt`, but the source shows `alt=""`, which is valid for a decorative pixel. Treat that warning as a false positive. It is a real gap for the `krxd.net` and `returnpath.net` pixels, which have no `alt` attribute, and QA also flags `dde00662-169f-447d-b0e2-fc65f6c2290c.png` as missing alt text.
- **Insecure image:** `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png` is served over HTTP. It may be blocked or show mixed-content warnings.
- **Charset and compatibility metas:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` lack `http-equiv`, so neither declaration takes effect.
- **Language:** `<html xmlns=…>` has no `lang` attribute, which screen readers rely on.
- **Zoom:** `maximum-scale=1` in the viewport meta disables pinch-zoom, which is a WCAG 1.4.4 issue.
- **Layout tables:** the visible tables (e.g. `<table cellpadding="0" cellspacing="0" border="0">`) have no `role="presentation"`.
- **Doctype:** XHTML 1.0 Transitional is acceptable but dated.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** the greeting renders as "Hi ," because the name field resolved to empty. There is no visible fallback value, so a missing first name leaves a malformed greeting.
- Other tokens could not be checked because the source is truncated.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **[WARN] Authentication-Results header not found:** SPF, DKIM and DMARC alignment are unknown. QA attributes this to the AgentMail relay, so it is a test-environment limitation rather than a confirmed sender fault.
- The sender is `no-reply@emails.skechers.com`. A no-reply sender is not a CAN-SPAM violation, but it gives recipients no reply channel.
- The unsubscribe link, physical postal address, and `List-Unsubscribe` / `List-Unsubscribe-Post` headers are not in the truncated source or QA output. They are unverified, not confirmed missing.
- The hashed-email beacons to `krxd.net` may need privacy-policy disclosure. This is a possible issue, not a confirmed violation.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- Click-tracking redirects hide the final URLs, so UTM presence and landing-page alignment can't be verified.
- The only campaign identifier visible is `PRO_US_NA_U_SITEEXTRA_LOYL_EN_10312026`, which appears in the pixel parameters (`campaignid=`, `mi_ecmp=`). It is dated 10/31 and consistent across pixels.

## 7. Recommendations
1. Add a fallback to the first-name merge field (e.g. "Hi there,"), or suppress the comma when the name is empty.
2. Fix `pixel.app.returnpath.net/pixel.gif` to `https://…` and add `alt=""`.
3. Move `ink1000.com/…/o.gif` and `image.emails.skechers.com/…/dde00662-….png` to HTTPS, and add real `alt` text to the PNG.
4. Add `alt=""` to all tracking pixels.
5. Change the metas to `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
6. Add `lang="en"` to `<html>` and `role="presentation"` to layout tables. Remove `maximum-scale=1`.
7. Re-run QA against full headers and the untruncated HTML to confirm `Authentication-Results`, the unsubscribe link and headers, the postal address, and UTM parameters on resolved destinations.
8. Review the third-party hashed-email beacons against the privacy policy.
