# Technical Audit — "Red, White & BOGO 50% Off This Memorial Day"

## 1. Technical Summary
Email renders on legacy SFMC/XHTML 1.0 Transitional scaffold with broken personalization (empty greeting slot) and pervasive non-HTTPS image hosts. Tracking pixels and CTAs are wired, but multiple sources risk being blocked by modern mail clients.

## 2. Link & Tracking Issues
- 27 tracking/click-redirect links present (`click.emails.skechers.com`) — not probed, so destination integrity unverified.
- Multiple third-party tracking pixels fire on open: `click.emails.skechers.com/open.aspx`, `beacon.krxd.net` (Salesforce Krux, 3 variants), `pixel.app.returnpath.net`, and `ink1000.com/p/up/.../o.gif`. Stack is heavy but functional.
- Return Path pixel `<img src="pixel.app.returnpath.net/pixel.gif?r=...">` is missing a protocol scheme — will resolve as a relative URL against the rendering origin and 404 in most clients.

## 3. Rendering & Accessibility
- **All `image.emails.skechers.com` and `ink1000.com` images served over `http://`** — Gmail, Apple Mail, and Outlook web increasingly block/strip mixed content. Affects logo, app-store badges, social icons, "Find A Store", "Curbside Pickup", "AfterPay" — i.e. brand + footer chrome.
- Missing `alt` attributes on `o.gif` (tracker, acceptable) and `49468f73-...png` (content image — accessibility regression).
- Duplicate `@media (max-width: 375px)` and `@media (max-width: 640px)` blocks contain identical rule sets — dead CSS bloat.
- `.mobile-content` / `.desktop-content` toggle relies on `min-width: 768px` desktop breakpoint, but the mobile rule sets fire up to 640px — devices in the 641–767px range will show *both* variants.
- `<meta content="IE=Edge" />` is missing its `http-equiv="X-UA-Compatible"` attribute — the directive is inert.
- First `<meta charset>` tag is also missing `http-equiv="Content-Type"`.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot** — QA detected `"Hi ,"` rendering. Indicates an unresolved SFMC AMPscript/personalization string (likely `%%FirstName%%` with no fallback). Real bug, visible to recipient.

## 5. Compliance
HTML truncated before footer — unsubscribe link, postal address, and `List-Unsubscribe` headers not visible in the provided source, so CAN-SPAM compliance cannot be confirmed from this excerpt. No issues found in the visible portion, but footer verification is required.

## 6. Email-to-Site Continuity
- Campaign ID `PRO_US_NONPURCLICK_U_SITEBUNDLE_NONPURCH_EN_05252026` is consistently propagated through Krux and ink1000 trackers.
- CTA destination URLs are obscured behind `click.emails.skechers.com` redirectors in the truncated source — UTM parameter presence on final landing pages cannot be verified without unwrapping the redirects.

## 7. Recommendations
1. **Fix the empty greeting** — add a default value (`%%=v(@FirstName)=%%` with `IIF`/`Lookup` fallback, or remove the comma-name pattern entirely).
2. **Migrate all `image.emails.skechers.com` and `ink1000.com` assets to HTTPS** — single biggest deliverability/rendering risk in this send.
3. **Fix the Return Path pixel** — add explicit `https://` scheme to `pixel.app.returnpath.net/pixel.gif`.
4. **Add `alt` to `49468f73-...png`** (and audit other content images in the truncated section).
5. **Repair the IE=Edge meta tag** — add `http-equiv="X-UA-Compatible"`, or drop it (Outlook ignores it anyway).
6. **Collapse the duplicate 375px/640px media query blocks** into one `max-width: 640px` rule.
7. **Resolve the 641–767px breakpoint gap** so mobile/desktop content blocks don't both render.
8. **Verify list-unsubscribe one-click header** (`List-Unsubscribe: <mailto:...>, <https://...>` + `List-Unsubscribe-Post: List-Unsubscribe=One-Click`) is set at the ESP level — Gmail/Yahoo bulk-sender requirement.
