## Technical Audit

## 1. Technical Summary
The email has one confirmed personalization failure (an empty greeting slot, "Hi ,"), a malformed tracking pixel with no protocol, and two `http://` images that are missing alt text. The HTML is truncated, so the footer, unsubscribe block, and most link hrefs could not be inspected.

## 2. Link & Tracking Issues
- **Broken pixel URL:** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…" width="1" height="1" />` has no scheme. Clients resolve it as a relative path, so the request goes nowhere. The Return Path/Validity seed-tracking beacon never fires. It also has no `alt`.
- **Insecure tracking pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=MKG_US_NA_U_PERFORM_PERF_EN_10042026` uses plain HTTP. Gmail and Apple Mail proxies may block or rewrite it, and it can trigger mixed-content warnings.
- **Unprobed links:** 27 tracking links were skipped as click-redirect domains, so none of their destinations were validated.
- **Third-party beacons:** Four `beacon.krxd.net` pixels (two `usermatch`, one `ad_impression`) sit in the hidden preheader block. They add third-party requests and are often blocked by privacy-protection features.
- **Open pixel:** `https://click.emails.skechers.com/open.aspx?...` is fine (HTTPS).

## 3. Rendering & Accessibility
- **Images without alt:**
  - `o.gif` (ink1000.com tracking pixel).
  - `dde00662-169f-447d-b0e2-fc65f6c2290c.png` at `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/…`. This looks like a content image, so missing alt is a real accessibility gap.
- **Insecure content image:** The `.png` above is served over `http://` from the brand's own image host. It may be blocked or show a mixed-content warning. The same host should serve it over HTTPS.
- **Viewport:** `maximum-scale=1` in `<meta name="viewport">` blocks pinch-zoom, a WCAG 1.4.4 concern.
- **Malformed meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` are missing `http-equiv`, so they do nothing.
- **Missing semantics:** The visible layout tables (e.g. `<table class="widthFull" width="640" …>`) have no `role="presentation"`. The `<html>` tag has no `lang` attribute.
- **Hiding method:** The preheader and pixel wrapper use `display:none !important`. This is acceptable, but `-webkit-text-size-adjust: none` can interfere with iOS text scaling.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting:** The greeting renders with an empty name field ("Hi ,"). The merge value is blank and has no fallback. The template needs a default (e.g. "Hi there,") or conditional logic to drop the greeting.
- The tracking URLs (`d=100226`, `ZAWSZ26VZA6…`) carry subscriber identifiers. They resolved, so the name field is the only broken token observed.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Not verifiable:** The HTML is truncated before the footer and no raw headers were supplied. The unsubscribe link, physical postal address, `List-Unsubscribe`/`List-Unsubscribe-Post`, and SPF/DKIM/DMARC results could not be checked. The sender is `no-reply@emails.skechers.com`, a subdomain aligned with the click and image hosts.
- **Possible privacy disclosure:** Two krxd.net pixels pass identifiers: `partner=LprH63a7_sfmc_100007688_sha25&partner_uid=adf27fee…189a` (a 64-hex value, consistent with a SHA-256 hash) and `partner_uid=122277199`. If the hash is of the recipient's email, that is third-party data sharing which the privacy policy should cover. This is an inference from the parameter name and value length, not confirmed.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Not assessable:** The 27 click-tracked links were skipped, so final destinations and UTM parameters were not verified.
- **Campaign ID:** `MKG_US_NA_U_PERFORM_PERF_EN_10042026` appears consistently in the krxd `campaignid` and ink1000 `mi_ecmp` parameters.
- **Unconfirmed:** Whether that ID is carried into landing-page UTMs is unknown.

## 7. Recommendations
1. **Fix the greeting merge.** Add a fallback or conditional so "Hi ," cannot render. This is the only confirmed customer-facing defect.
2. **Fix the Return Path pixel.** Use `https://pixel.app.returnpath.net/pixel.gif?r=…`, or remove it if seed monitoring is retired.
3. **Move `o.gif` and the `.png` to HTTPS.** Serve `image.emails.skechers.com` assets over HTTPS.
4. **Add alt text.** Use `alt=""` on the tracking pixels and a descriptive `alt` on the `.png`.
5. **Remove `maximum-scale=1`** from the viewport meta.
6. **Correct the meta tags** to `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"`.
7. **Add `role="presentation"` and `lang`** to the layout tables and `<html>`.
8. **Re-run the audit on the full HTML and raw headers.** This would let the unsubscribe, address, authentication, link, and UTM checks complete.
