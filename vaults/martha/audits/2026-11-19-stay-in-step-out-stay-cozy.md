## Technical Audit

## 1. Technical Summary
The email has one confirmed merge-token failure (empty greeting, `Hi ,`) and several markup defects. These include a scheme-less Return Path pixel, two `http://` images with no alt text, and ineffective `<meta>` declarations. The HTML source was truncated, so the footer, unsubscribe block and content links could not be inspected.

## 2. Link & Tracking Issues
- **Malformed tracking pixel:** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1dbf0dc…">` has no scheme. Mail clients resolve it as a relative path, so the request fails and Return Path inbox-placement tracking is lost for this send. The tag also has no `alt`.
- **Insecure third-party pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=MKG_US_NA_U_MULTI_PROD_EN_11192026` is plain HTTP, so clients may block it or show mixed-content warnings.
- **Unverified links:** 43 tracking links on `click.emails.skechers.com` (SFMC redirects) were skipped by the QA probe. Their destination health is unverified.
- **Redundant beacons:** Three Krux beacons (`beacon.krxd.net/1x1_usermatch.gif` ×2, `1x1_ad_impression.gif`) sit alongside the SFMC open pixel, adding third-party requests per open.

## 3. Rendering & Accessibility
- **Missing alt text:**
  - `o.gif` (ink1000.com) has no `alt`.
  - `dde00662-169f-447d-b0e2-fc65f6c2290c.png` has no `alt`.
  - The Krux beacons and the Return Path pixel also have no `alt`. These are decorative, so they should have `alt=""`.
- **HTTP image source:** `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-…png` is non-HTTPS and may be blocked or rewritten. It is a first-party host, so it can move to HTTPS.
- **Ineffective meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv` attribute, so neither declaration takes effect. The charset is not declared in the document.
- **Zoom disabled:** `<meta name="viewport" content="…maximum-scale=1">` blocks pinch-zoom. This is a WCAG 1.4.4 failure.
- **Text-size override:** `* { -webkit-text-size-adjust: none; }` disables text-size adjustment on iOS.
- **Missing structure:** `<html>` has no `lang` attribute. The layout tables (`<table cellpadding="0" cellspacing="0" border="0">`) have no `role="presentation"`.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** QA detected a greeting with an empty name field (`Hi ,`). The merge field resolved to null with no fallback. In SFMC AMPscript, use a default such as `%%=IIF(Empty(@firstName),"there",@firstName)=%%`, or drop the name from the greeting when it is empty.
- I could not locate the greeting in the truncated source, so this relies on the QA finding.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication-Results:** The header was not found. This is attributed to the AgentMail relay, so SPF/DKIM/DMARC status is unknown, not failed. It cannot be confirmed from this capture.
- **Unsubscribe and address:** The footer was not in the truncated HTML, and `List-Unsubscribe` headers were not provided. The unsubscribe link, `List-Unsubscribe-Post` and the physical address could not be verified.
- **Hashed identifiers to third parties:** The Krux beacons send `partner_uid=adf27fee…189a` (a SHA-256 value, per `partner=…_sha25…`) and `partner_uid=122277199` (subscriber ID) to `beacon.krxd.net`. This is a privacy and disclosure concern in the HTML source.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Campaign ID only on beacons:** `MKG_US_NA_U_MULTI_PROD_EN_11192026` appears in the Krux and ink1000 pixels.
- **UTMs not verifiable:** All content links are wrapped in `click.emails.skechers.com` redirects, and the 43 links were not probed. UTM parameters and landing-page alignment with the "Members take 30% off sitewide" preheader cannot be confirmed.

## 7. Recommendations
1. Add a fallback to the first-name merge so the greeting never renders as `Hi ,`.
2. Fix the Return Path pixel to `https://pixel.app.returnpath.net/pixel.gif?r=…` and add `alt=""`.
3. Switch `ink1000.com/o.gif` and `image.emails.skechers.com/…dde00662….png` to HTTPS. Add `alt` text to the content image and `alt=""` to the tracking pixels.
4. Use `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
5. Remove `maximum-scale=1` from the viewport tag and drop `-webkit-text-size-adjust: none`. Add `lang="en"` and `role="presentation"` on layout tables.
6. Re-run QA against the full HTML and raw headers. Check Authentication-Results, `List-Unsubscribe`, the footer address, and the resolved destinations and UTMs of the 43 redirected links.
7. Review the Krux hashed-email and subscriber-ID beacons against the privacy policy and consent basis.
