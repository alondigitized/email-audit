# 25% off $100 for Members – Starts Now
**Score:** 8/10 · **Type:** Email audit · **2026-07-22**
## Executive summary

- Okay, so the offer stopped me immediately — 25% off when you hit $100, and the fine print says *including sale styles*. That is not nothing. Skechers almost never lets you stack a code on top of already-marked-down stuff, so that line alone made me lean forward. I'm a Plus member, I'm in the thick of back-to-school shopping, and this code expires July 31, which is right when I need to pull the trigger on new sneakers for both kids.
- But then I scrolled and found exactly what I always find: a beautiful women's shoe with its own hero image, a men's shoe with its own hero image, and then... a text button for kids. No photo. No "hey, here's what your kindergartner can wear on day one." No velcro, no light-up sole, nothing. The offer technically covers kids' shoes too, but the email doesn't sell it that way. I have to do extra mental work to get there myself, and on a Sunday afternoon with two kids needing my attention, I don't have that bandwidth.
- I'd click the "SHOP KIDS'" button because the discount is real and I know what I'm looking for — but this email didn't earn that click, the offer did. I wouldn't forward it; my friends would have the same "where's the kids stuff?" feeling I do.

## What's working

- **25% off + code SAVINGS + "including sale styles"** — that last phrase is the whole email. Extremely clear, high-credibility offer, and the copy actually says it out loud.
- **"SKECHERS PLUS MEMBER EXCLUSIVE" banner** — I see I'm being treated as a member, not a stranger. That matters to me; I've been stacking points for a while.
- **Valid through 7/31 deadline** — concrete, believable, and actually lines up with when I need to be buying school shoes. The urgency isn't manufactured.
- **No broken images or layout chaos** — the email body itself renders cleanly. After some clunky sends this week, I appreciate a mail that just... works visually.
- **"SHOP NOW, PAY LATER" callout (afterpay/Klarna)** — I've used these before for bigger family hauls. Good to see it confirmed before I start adding things to cart.

## What's weak

- **Kids section is a ghost** — Women's gets a shoe photo, Men's gets a shoe photo, Kids gets a plain gray button with zero product imagery. I shop for my kids *first*. Show me something.
- **The preview text in my inbox was pure JSON garbage** — I saw structured data schema markup instead of actual copy. That's a technical embarrassment and it cost the email half its inbox appeal before I even opened it.
- **Email fatigue is real this week** — this is the seventh Skechers email in seven days. After the great "Final Hours" send on the 20th and the slip-ins push on the 19th, my thumb is getting hover-y over the unsubscribe link.
- **"SHOP NOW" CTA is too broad** — I'm clicking anyway, but a CTA that said "Shop Kids' Shoes" right next to that offer would have saved me three taps.

## Recommendations

- 1. **Give kids a hero image, not just a button.** Show me a light-up sneaker for a five-year-old and a durable lace-up for a nine-year-old. That's what I'm spending $100 on and it's July — lead with it.
- 2. **Fix the preview text immediately** — the JSON-LD schema is bleeding into every inbox that opened this. Swap in real copy before the next send. This is recoverable for the next campaign.
- 3. **Reframe the hero for families** — "Head-to-Toe Savings" is fine but generic. "Back to School savings for the whole crew — including sale styles" is a sentence that makes me sit up.
- 4. **Add a family bundle callout** — one short line like "Spend $100 on the kids + yourself? Done." would frame the math for me as a mom who ends up buying for multiple people in one cart.
- 5. **Throttle the cadence** — seven emails in seven days is eroding the goodwill a genuinely good offer like this one deserves.

## Technical Audit

## Technical Audit — Skechers "25% off $100 for Members" (2026-07-22)

---

### 1. Technical Summary

The email sends cleanly but carries two infrastructure-level defects that will cause silent failures in production: all image assets are served over HTTP (not HTTPS), which modern email clients will block, and one tracking pixel has a malformed URL missing its protocol scheme. These are not cosmetic issues — they affect deliverability signals and asset rendering.

---

### 2. Link & Tracking Issues

**Return Path pixel — missing protocol**
```html
src="pixel.app.returnpath.net/pixel.gif?r=964ce1dbf0dcef79cbad82c12fe25342701e4499"
```
No `https://` prefix. Most email clients will interpret this as a relative path and fail to load it. Return Path/Validity inbox monitoring depends on this pixel firing; a broken URL silently kills that signal.

**Raw subscriber ID exposed in Krux pixel**
```
partner_uid=122277199
```
The SHA-256 hashed UID on the adjacent pixel is expected. The raw numeric subscriber ID alongside it is unnecessary PII surface in HTML source.

**26 click-redirect links not validated**
All outbound links route through `click.emails.skechers.com`. The QA probe skipped all 26. UTM parameters on final landing pages are unverifiable without following the redirect chain — see Section 6.

**Campaign ID confirmed consistent across pixels**
`PRO_US_NONPUR_U_SPENDMIN_NONPURCH_EN_07222026` appears in both the Krux impression pixel and the Ink1000 pixel. Naming is consistent.

---

### 3. Rendering & Accessibility

**HTTP image sources — will be blocked**
All 10+ production images are served from `http://image.emails.skechers.com` (no TLS). Gmail, Apple Mail, and Outlook all enforce HTTPS for remotely loaded images. These will render as broken image placeholders for recipients with image loading enabled unless the CDN auto-upgrades HTTP→HTTPS (unverifiable from source).

Affected assets include the Skechers logo, App Store badge, Google Play badge, Curbside Pickup, AfterPay, Find A Store, and all social icons:
```
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-...png  (logo)
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/49468f73-...png
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/0ec56c9f-...png  (App Store)
... (8 more)
```

**Missing alt text**
Two images have no `alt` attribute:
- `o.gif` (Ink1000 tracking pixel) — acceptable for a hidden pixel but the `alt=""` attribute should be explicit
- `49468f73-4651-4af3-bea2-61d1ae5db486.png` — a visible content image with no alt; screen readers skip it

**Viewport blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
`maximum-scale=1` prevents pinch-zoom on mobile. This is an accessibility regression for low-vision users and violates WCAG 1.4.4.

**`-webkit-text-size-adjust: none` applied globally**
```css
* { -webkit-text-size-adjust: none; }
```
Disables iOS automatic font size adjustment across all elements. Intentional for layout stability, but also suppresses accessibility-driven zoom on iOS. Scope should be narrowed if possible.

**`<meta charset>` missing `http-equiv`**
```html
<meta content="text/html; charset=utf-8" />
```
Missing `http-equiv="Content-Type"`. While most clients tolerate this, the correct form is `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />`.

**Duplicate responsive breakpoint rules**
The `@media only screen and (max-width: 375px)` and `@media only screen and (max-width: 640px)` blocks are byte-for-byte identical. One is redundant dead code — adds payload without function.
