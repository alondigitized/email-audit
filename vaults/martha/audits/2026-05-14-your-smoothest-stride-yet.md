# Your Smoothest Stride Yet
**Score:** 7/10 · **Type:** Email audit · **2026-05-14**
## Executive summary

- I almost deleted this without opening it. The preview text in my inbox was a wall of raw code — like, actual JSON bracket stuff — which made me do a double-take and wonder if something was wrong with the email or if it was even legit. That's a bad first impression coming from a brand I actually like and have an account with.

But the whole email is adults, adults, adults — sleek performance sneakers, lifestyle models, a dedicated "THANK YOU TEACHERS" section. ## What's working

- BOGO 50% off (or 50% off a single pair) is a strong, legible offer — it's the first thing my eye went to and it's relevant for buying multiple pairs at once
- The Glide-Step slip-ins caught my eye as something I might actually want for myself — hands-free is a real mom feature
- Email body is visually clean and easy to scan — no broken images, no layout chaos, loads fast
- Buy now, pay later options (Afterpay, Klarna) are visible at the bottom — that matters when I'm buying shoes for multiple kids in one go
- The SHOP MEN'S / SHOP WOMEN'S split is useful UX for a multi-buyer household

## What's weak

- The preview text is raw JSON schema code leaking into the inbox — that's a trust-killer before I even open the email
- Not a single kids' shoe appears in the hero, a product module, or anywhere above the footer — just a text link saying "KIDS" buried at the bottom
- The entire "THANK YOU, TEACHERS!" section is premium real estate that does zero work for me; feels like a different email got bolted on
- Subject line "Your Smoothest Stride Yet" has no offer signal, no urgency, no category — I have no reason to open it over the 12 other emails in my inbox
- No loyalty or rewards mention anywhere — I have a Skechers account and I shop partly to accumulate points; this email treated me like a stranger

## Recommendations

- 1. **Fix the preview text immediately** — JSON schema leaking into the inbox is a production bug that tanks open rates and signals something is technically broken; this is the single highest-priority fix before the next send
- 2. **Add a kids module above the fold** — even one row of three kids styles under the BOGO banner would completely change how relevant this email feels to a parent
- 3. **Lead the subject with the deal** — if there's a BOGO happening, tell me in the subject; I open based on what's in it for me, not aspirational copy
- 4. **Tie the BOGO to the loyalty program** — "Stack your points + BOGO" is exactly the kind of combination that gets a loyalty member to click same-day
- 5. **Segment out or shrink the teacher section** — if I'm not teacher-segmented, this section should be a small banner at most, not a full-width feature block

### 1. Technical Summary

One critical personalization failure (empty greeting slot) will surface in recipients' inboxes, and a systemic HTTP-only image CDN will cause images to be blocked by all major modern clients that enforce HTTPS content policies. A tracking pixel also has a missing protocol prefix rendering it entirely non-functional.

---

### 2. Link & Tracking Issues

**[CRITICAL] Return Path pixel — missing protocol**
```
src="pixel.app.returnpath.net/pixel.gif?r=964ce1dbf0dcef79cbad82c12fe25342701e4499"
```
No `http://` or `https://` prefix. Browsers/clients interpret this as a relative path; the inbox reputation pixel fires against nothing. Complete data loss for that send on Return Path monitoring.

**[WARN] Movable Ink pixel served over HTTP**
```
src="http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&..."
```
HTTP origin; Gmail and Outlook proxy all external images over HTTPS — a protocol mismatch here means the Movable Ink personalization signal may not record correctly.

**[INFO] Krux/Salesforce Audience Studio user-match beacons contain a SHA-256 hashed email**
```
partner_uid=adf27fee67323d52536b18110294bf793c265b830082caba4b1a32664832189a
```
64-character hex string passed to `beacon.krxd.net` on every open. This constitutes a third-party data share of a derived identifier. Verify this is disclosed in the privacy policy and permissible under applicable state laws (CCPA) for this segment.

**[INFO] 27 click-redirect links** all route through `click.emails.skechers.com`; final destination URLs and UTM integrity could not be probed (see §6).

### 3. Rendering & Accessibility

**[CRITICAL] All body images served over HTTP**

Every image hosted on `image.emails.skechers.com` uses `http://`:
- Logo: `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png`
- Footer icons (App Store, Google Play, Curbside, AfterPay, Find A Store, Instagram, Facebook, YouTube): all `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/...`

Gmail, Outlook 365, and Apple Mail proxy external images — HTTP origins produce mixed-content warnings or silent failures. Recipients see a broken-image email.

**[WARN] Two images missing `alt` text**
- `o.gif` (Movable Ink pixel) — low severity since it's a 1×1 tracker, but should have `alt=""`
- `49468f73-4651-4af3-bea2-61d1ae5db486.png` — appears to be a content image (not decorative) at `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/49468f73...`; absence of alt leaves screen readers silent

**[WARN] `-webkit-text-size-adjust: none`**
```css
* { -webkit-text-size-adjust: none; }
```
Should be `100%`, not `none`. `none` disables the user's ability to enlarge text on mobile — accessibility regression and violates WCAG 1.4.4.

**[INFO] Malformed meta tags**
```html
<meta content="text/html; charset=utf-8" />       <!-- missing http-equiv -->
<meta content="IE=Edge" />                          <!-- missing http-equiv -->
```
Both are missing the `http-equiv` attribute. Clients that rely on these hints may misparse encoding or compatibility mode.

### 4. Personalization & Merge Tokens

**[FAIL] Empty greeting slot**

QA confirmed: greeting renders as `"Hi ,"` — the first-name merge token resolved to an empty string. Likely cause: subscriber record has a null/blank `FirstName` field with no fallback value configured in the template. The ESP template should include a conditional fallback, e.g.:
```
Hi %%[ IF @fname != "" ]%% %%=v(@fname)=%%,%%[ ELSE ]%% there,%%[ ENDIF ]%%
```

No other merge tokens were identifiable in the truncated source beyond the subscriber ID visible in the Krux beacon (`partner_uid=122277199`).
