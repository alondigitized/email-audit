## Technical Audit

## 1. Technical Summary
The HTML shows several template and tracking-pixel defects: an unresolved `[CACHEBUSTER]` macro, an HTTP-only pixel, empty `src` images, and malformed `<meta>` tags. SPF/DKIM/DMARC, the unsubscribe mechanism and UTM parameters could not be verified. The HTML was truncated and the 54 tracked links were not probed.

## 2. Link & Tracking Issues
- **Unresolved macro in a third-party pixel:** `https://t.myvisualiq.net/impression_pixel?r=[CACHEBUSTER]&et=i&ago=212&ao=883&aca=-11&si=-11&ci=-11&pi=-11&ad=-11&advt=-…`
  - The literal `[CACHEBUSTER]` was never substituted, so the cache-busting value is missing and clients or proxies may cache the pixel and undercount impressions.
  - The `-11` values in `aca`, `si`, `ci`, `pi` and `ad` look like default or unset placeholders. Campaign, placement and ad IDs may not be reaching the vendor.
- **Non-HTTPS pixel:** `http://login.dotomi.com/ucm/UCMController?dtm_com=2&dtm_cid=2990&dtm_cmagic=f6b5f8&dtm_fid=103&dtm_format=6&cli_promo_id…`
  - Clients and image proxies that enforce HTTPS, or flag mixed content, may block it, so the Dotomi/Conversant tracking would not fire.
- **Empty-`src` images:** Two `<img>` elements have an empty `src` (QA: `Image missing alt text: : src: `).
  - This is probably an unrendered template slot. Empty `src` can trigger a request to the document URL in some clients, or show a broken-image icon.
- **Subscriber ID in a pixel URL:** `https://pxl.mon-trk.com/987bfe61-f108-4c0f-99ff-4b5d2e0c19ef/2337283/003aZ00000s0I5yQAE`
  - The final path segment looks like a Salesforce Contact ID (`003…` prefix). It is a per-recipient identifier exposed to a third-party domain.
- **Unprobed links:** 54 tracking/click-redirect links were skipped, so link health and final destinations are unverified.

## 3. Rendering & Accessibility
- **Malformed meta tags:**
  - `<meta content="text/html; charset=utf-8" />` has no `http-equiv="Content-Type"`.
  - `<meta content="IE=edge" />` has no `http-equiv="X-UA-Compatible"`.
  - Both are inert as written. The charset declaration will not be honored, so any non-ASCII characters rely on the transport header.
- **Alt text:**
  - The `UCMController`, `impression_pixel`, `003aZ00000s0I5yQAE` and two empty-`src` images have no `alt` attribute. For tracking pixels, the fix is `alt=""` plus `width="1" height="1"` and a hidden style. Without them, some screen readers announce the filename or URL.
  - The QA check shows no alt problems on content images, but the HTML was truncated, so I can't confirm that.
- **Font fallback:** `a{font-family:'Founders Grotesk', Helvetica, sans-serif}` references a font with no `@font-face` in the visible CSS. The fallback stack covers this, so the impact is low. The Open Sans `@font-face` rules use `font-display: swap`, which is fine.

## 4. Personalization & Merge Tokens
- The only confirmed unresolved token is `[CACHEBUSTER]` in the myvisualiq pixel (see section 2).
- Placeholder `-11` values in the same URL suggest incomplete macro substitution.
- The visible portion of the source shows no other unresolved `%%…%%`, `{{…}}` or `${…}` tokens. The truncated body is unchecked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication headers:** The QA warning `Authentication-Results header not found` is attributed to the AgentMail relay, so SPF/DKIM/DMARC status is unknown. This is a limitation of the capture, not a confirmed sender defect. The `From` domain is `em.sallybeauty.com`.
- **Unsubscribe and physical address:** The visible HTML is truncated before any footer, so I can't confirm any of these:
  - the unsubscribe link
  - a postal address
  - a `List-Unsubscribe` / `List-Unsubscribe-Post` header
- **Third-party tracking:** Several vendor pixels fire (mon-trk, myvisualiq, Dotomi). That is a disclosure matter for the sender's privacy policy, not a CAN-SPAM violation.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Unverifiable. All 54 click-tracking links were skipped, so the final landing URLs, UTM parameters and redirect chains were not resolved. No continuity issues are confirmed.

## 7. Recommendations
1. Fix the `myvisualiq` pixel so `[CACHEBUSTER]` is replaced at send time, and confirm the `-11` placeholders are populated with real campaign/placement IDs.
2. Change the Dotomi pixel to `https://login.dotomi.com/…`, or confirm the vendor supports it. Add `alt=""`, `width="1"`, `height="1"` and `style="display:none"` to all tracking pixels.
3. Remove or populate the two empty-`src` `<img>` elements in the template.
4. Correct the meta tags to `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` and `<meta http-equiv="X-UA-Compatible" content="IE=edge" />`.
5. Review whether the Salesforce Contact ID in the `pxl.mon-trk.com` URL should be exposed to a third party, or replaced with a hashed or opaque token.
6. For a complete audit, capture the full (untruncated) HTML and raw headers (`Authentication-Results`, `List-Unsubscribe`, `Received-SPF`). Also run the redirect-chain resolver on the 54 tracking links to verify UTMs and landing pages.
