# Find your fall favorites and save 25% on apparel
**Score:** 5/10 · **Type:** Email audit · **2026-09-27**
## Executive summary

- Okay, 25% off bags and apparel — but let's be real, I clicked in hoping for something for the kids and got matching lilac pink and moss green sweat sets for grown women, again. It's a pretty email, I'll give them that — the "Cozy Sets for the Season" hero with the hoodie and joggers actually looks nice, and I don't hate the two color-story blocks. But there is not a single kid product in this entire email until you hit the gray "SHOP ADDITIONAL STYLES" text links at the very bottom, where "Kids" is one word buried between "Men" and "Wide." My whole Saturday routine is hunting for sneakers for Emma and Mason, and this is once again an adult loungewear catalog with my name slapped on top.
- I'm not clicking through to shop — maybe I tap "Kids" out of habit to see if anything's on sale, but that's it. Not forwarding this to anyone, it's not funny-bad, it's just not for me.

## What's working

- The hero shot is clean and the cozy-sweats concept is genuinely appealing for fall, if I were shopping for myself.
- "Hi, Martha" + 1000 points + $5 reward redeemable up top is a nice personal touch I do notice.
- 25% off apparel and 20% off boots are both clear, specific numbers with a visible deadline (thru 9/28) for the boots offer.
- The UGG-style boot shot in "Complete the Look" is legitimately cute and on-trend.

## What's weak

- Zero kids' product anywhere above the fold or really anywhere except a tiny text link — this is the third time this month I've gotten an all-adult apparel email from this brand.
- Both color stories (Lilac Pink, Live Moss) are Women's only, same adult models, same styling — no boys' or girls' sneakers, no velcro, no light-up soles, nothing.
- No family bundle, no promo code visible for either offer — I have to click through and hope it auto-applies.
- "AI-GENERATED MODEL" tag on the hero photo is a little offputting, not going to lie.

## Recommendations

- 1. Put at least one kids' product block above the fold — even a single "Back-to-Play Sneakers for Kids, 25% off" tile would've gotten my thumb to stop scrolling.
- 2. Show the actual promo code in the body instead of making me click through blind.
- 3. Swap "Kids" from a buried text link to a real image tile in the "Shop Additional Styles" section, same size as Women/Men.
- 4. Segment this — send the loungewear email to moms shopping for themselves, and a separate kids-back-to-school-style email to the same list on a different day.
- **Subject Alt A:** `New fall styles for the whole family — 25% off`
- **Subject Alt B:** `Cozy sets for you, sneakers still on sale for the kids`
- **Preheader Alt A:** `25% off apparel, 20% off boots — plus kids' styles inside`
- **Preheader Alt B:** `Your $5 reward is ready. Shop fall favorites for everyone.`

## Technical Audit

1. Technical Summary
Email renders via standard SFMC responsive table markup with proper tracking pixels, but ships with a broken personalization token and two non-HTTPS image sources that will trigger mixed-content/mail-client blocking.

2. Link & Tracking Issues
- 30 click-redirect links (click.emails.skechers.com and similar) were skipped for HTTP probing per QA — standard for tracked SFMC links, not itself a defect, but unverified for 404/redirect validity.
- Open-tracking pixel present: `https://click.emails.skechers.com/open.aspx?H57OADU5PK6UFHOK6KO22AFK3Q.100226&d=100226&bmt=0` — HTTPS, correctly hidden (`display:none !important`).
- Kantar/Oracle beacon `beacon.krxd.net/1x1_ad_impression.gif?...&campaignid=MKG_US_NA_W_APPAREL_GENDER_EN_09272026` — HTTPS, fine.
- Return Path pixel `pixel.app.returnpath.net/pixel.gif?...` is protocol-relative (missing `https://` scheme, e.g. `src="pixel.app.returnpath.net/..."`) — this will resolve as a relative path against the current document base rather than the intended external host, breaking the beacon.

3. Rendering & Accessibility
- Two images missing `alt` text (QA FAIL/WARN):
  - `o.gif` (ink1000.com tracking pixel) — acceptable since it's a 1x1 tracking pixel, no accessibility impact.
  - `dde00662-169f-447d-b0e2-fc65f6c2290c.png` (image.emails.skechers.com) — this is a content image; missing `alt` fails accessibility (screen readers get no fallback) and provides no context if image loading is blocked.
- Two images served over `http://` instead of `https://`:
  - `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?...`
  - `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png`
  Both will be flagged as mixed content and are likely to be blocked or rewritten by mail clients (Gmail/Outlook proxy over HTTPS, but direct http:// references are non-standard and increase spam-filter risk).
- Media queries and MSO/Outlook conditional CSS are present and well-formed (`.ReadMsgBody`, `.ExternalClass`, `x-apple-data-detectors` handling) — no issues found there.

4. Personalization & Merge Tokens
- QA FAIL: Empty greeting slot — greeting renders as "Hi ," with the name merge field empty. This indicates either a missing fallback value in the merge token (e.g., `%%FirstName%%` with no default) or a subscriber record with a null first-name field reaching production. This is a functional personalization bug, not a data-quality edge case to ignore — recommend adding a fallback (e.g., "there"/"friend") and confirming with a real subscriber sample.

5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- HTML source provided is truncated before the footer/unsubscribe block, so unsubscribe link, physical mailing address, and List-Unsubscribe header cannot be verified from this excerpt — flag as unverified rather than fail.
- No SPF/DKIM/DMARC header data was included in the payload — authentication headers cannot be assessed from HTML source alone; recommend pulling raw headers separately.

6. Email-to-Site Continuity (UTM params, landing page alignment)
- Campaign ID `MKG_US_NA_W_APPAREL_GENDER_EN_09272026` is consistently applied across the Kantar/Oracle beacon, ink1000 pixel, and (implied) click-tracking domain — good cross-tracking consistency.
- Actual CTA destination URLs are not visible in the truncated HTML source, so UTM parameter alignment with the landing page cannot be confirmed — recommend reviewing full link list against landing page UTM expectations.

7. Recommendations
- Fix empty greeting merge token: add a fallback value for missing first name.
- Change both `http://` image sources to `https://` (ink1000.com pixel and the SFMC-hosted PNG).
- Add descriptive `alt` text to the content image `dde00662-169f-447d-b0e2-fc65f6c2290c.png`.
- Fix the Return Path pixel's missing URL scheme (`pixel.app.returnpath.net/pixel.gif` → should be `https://pixel.app.returnpath.net/pixel.gif`) to prevent it resolving as a broken relative path.
