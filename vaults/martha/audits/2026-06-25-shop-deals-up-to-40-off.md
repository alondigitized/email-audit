**Score:** 8/10 · **Type:** Email audit · **2026-06-23**
## Executive summary

- Sally Beauty — again. By my count this is somewhere around their seventh or eighth email to me since June 1, and I'm reading these out of routine more than excitement at this point. That said, "Big Deals Days" with 20% off sitewide is actually their most actionable pitch since the June 22 "Summer's Brightest Finds" send, which felt editorial without a strong deal behind it. What they fumbled was the preview text — "Sally Beauty Shop top beauty brands during Big Deals" repeats the sender name and burns 52 characters telling me essentially nothing I couldn't read from the subject line.

## What's working

- **Hero is the whole story at a glance.** "20% off sitewide" in large type was the first thing my eye landed on — no digging required.
- **Real deadline in the hero copy.** "Ends June 26" with today being the 25th is genuine urgency, not manufactured pressure.
- **Stacked deal tiles work.** The 40% off styling tools and 40% off Ion hair care tiles below the fold gave me actual reasons to keep scrolling.
- **Rewards mention in the subhead.** "Earn more rewards" is small but as a loyalty member I clocked it immediately.
- **Free 2-hour delivery callout.** Smart to surface this on the last day of a sale — removes the "I'll just get it in-store" hesitation.

## What's weak

- **Cadence fatigue is the lead problem.** Seven-plus emails in June means "Big Deals Days" landing feels like another alarm I've been hitting snooze on, not an event.
- **Subject line is completely generic.** "Shop deals up to 40% off" could be any brand, any product. There's zero signal that this is a named event ending in 24 hours.
- **Preview text wastes its slot.** Opening with "Sally Beauty" mirrors the sender name and leaves nothing useful in the inbox preview.
- **Asterisk on "sitewide\*" in the hero.** The fine-print note is tiny — I'd click expecting 20% off everything and potentially hit a wall of exclusions.
- **No personalization anywhere.** Sally knows my purchase history. This email has no indication they do.

## Recommendations

- 1. **Put the deadline in the subject.** That is the single highest-leverage change — "ends tomorrow" or "last day" would have meaningfully changed my open behavior from browse-maybe to open-now.
- 2. **Rewrite the preview text entirely.** Don't open with the brand name. Use those 50 characters for the deadline or a specific category hook.
- 3. **Add one hero product link.** "The Dyson dupe curling set is 40% off — today only" pulls a click from browsers like me; "Shop Big Deals" sends me to a landing page to figure it out myself.
- 4. **Rest the cadence.** Two strategic emails in June pointing to a Big Deals Days launch would have hit harder than eight. The urgency machine is broken because it's always urgent.

## 3. Rendering & Accessibility

**`http-equiv` missing from charset meta (confirmed bug):**
```html
<meta content="text/html; charset=utf-8" />
```
The `http-equiv="Content-Type"` attribute is absent. The correct form is:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without it, some older Outlook and Lotus Notes clients may fail to declare encoding, risking character corruption on special characters (em-dashes, accented letters, currency symbols).

**`Founders Grotesk` referenced but never declared:**
```css
a { font-family: 'Founders Grotesk', Helvetica, sans-serif; }
```
No `@font-face` block for Founders Grotesk exists in the visible CSS — only Open Sans variants are declared. Every anchor element will silently fall back to Helvetica. If brand consistency requires the custom font on CTAs, the @font-face block (or a hosted web font reference) is missing.

**External @font-face will be suppressed by major clients:**
All six Open Sans `@font-face` declarations pull from `fonts.gstatic.com`. Gmail (webmail and mobile), Outlook (all desktop versions), and Samsung Mail strip external CSS or block third-party font requests. Body text will render in the system fallback. This is expected behavior for email; flag only if test matrix assumes font fidelity in those clients.

**`img { white-space: pre; }` — unusual rule:**
```css
img { -ms-interpolation-mode: bicubic; white-space: pre; }
```
`white-space: pre` is a text property with no defined effect on replaced elements (`<img>`), but some rendering engines carry it unexpectedly when images are nested inside `<td>` or `<a>` that inherit the rule. Low risk, but it's non-standard and should be removed.

**Open Sans pinned to v17 (stale):**
All `fonts.gstatic.com` URLs reference `/opensans/v17/`. Google Fonts currently serves v40+. Google maintains backward-compatible URLs for old versions, so this is not an immediate break — but it is a maintenance debt that could surface if Google ever drops old version hosting.

**Positive signals:** `x-apple-data-detectors` reset present, `x-apple-disable-message-reformatting` meta present, `u ~ div` Gmail Dark Mode width fix present.
