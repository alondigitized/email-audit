## Technical Audit

## Technical Audit — Skechers "Next-Level Comfort, All Summer Long"

---

### 1. Technical Summary

The email is structurally sound but has one confirmed rendering-breaking merge token failure and a pervasive HTTP (non-HTTPS) image delivery problem across the entire asset library that will cause mixed-content blocks in modern clients.

---

### 2. Link & Tracking Issues

**26 click-tracking links** route through `click.emails.skechers.com` (Salesforce Marketing Cloud redirect domain) — standard practice, no issues with the pattern itself. Links were not probed due to redirect domain policy.

**One tracking pixel uses plain HTTP:**
```
http://www.ink1000.com/p/up/7076d8b15a776085/o.gif
```
This is a third-party open/impression pixel (ink1000.com). HTTP pixels are blocked by Gmail, Outlook.com, and Apple Mail proxy caching layers. It also lacks `alt=""`, making it a minor accessibility gap.

**Krux/Salesforce DMP pixel** (`beacon.krxd.net`) fires via HTTPS — no issue.

**Return Path seed pixel** (`pixel.app.returnpath.net`) is missing the protocol scheme entirely:
```html
<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1...">
```
No `http://` or `https://` prefix. This will fail to load in all clients (treated as a relative path).

---

### 3. Rendering & Accessibility

**HTTP image sources — systemic.** All images served from `image.emails.skechers.com` use `http://`:
```
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/...
```
Affected assets include the Skechers logo, app store badges, social icons, footer icons (Curbside Pickup, AfterPay, Find A Store), and at least one unlabeled product image. Gmail and Outlook.com will block or proxy-cache these; iOS Mail will show broken image placeholders on strict privacy settings.

**Missing alt text** on two images:
- `o.gif` (ink1000 pixel) — acceptable for a tracking pixel, but `alt=""` should be explicit
- `49468f73...png` — unidentified content image with no alt attribute; screen readers will read the raw filename

**`-webkit-text-size-adjust: none`** is set globally via `* { -webkit-text-size-adjust: none; }`. This prevents iOS Mail from scaling up small text and is an accessibility regression for users who rely on system font scaling.

**Duplicate responsive breakpoints:** `@media (max-width: 375px)` and `@media (max-width: 640px)` declare identical rule sets. The 375px block is redundant (640px is a superset) and adds unnecessary parse weight.

---

### 4. Personalization & Merge Tokens

**FAIL — Empty greeting:** The automated QA check confirms a broken merge token producing `"Hi ,"` — a subscriber name field that resolved to empty. This is a confirmed rendering bug visible to recipients. The fallback value for the first-name merge tag is either missing or empty string rather than a safe default (e.g., `%%=v(@firstName)=%%` with no `defaulting` clause in AMPscript, or an unguarded Liquid `{{ first_name }}`).

No other merge token failures detected in the truncated source.

---

### 5. Compliance

**Preheader present:** `<div class="preheader">Stock Up on Sandals With BOGO 50% Off or Take 20% off 1 Pair</div>` — correctly hidden from render, visible to preview pane. No issue.

**Unsubscribe:** Not visible in the truncated HTML, but the presence of a Salesforce Marketing Cloud send infrastructure (`click.emails.skechers.com`, SFMC open pixel) implies standard footer inclusion. Cannot confirm from the provided source — should be verified in the full HTML.

**CAN-SPAM physical address:** Same caveat — not present in truncated source; must appear in footer.

**Authentication headers** (SPF/DKIM/DMARC): Not assessable from HTML alone. Sending domain `emails.skechers.com` should be verified via MX Toolbox or header inspection on a delivered copy.

---

### 6. Email-to-Site Continuity

**Campaign ID present in pixels:**
```
campaignid=MKG_US_L90D_U_CATEGORY_ENGAGEDCLICK_EN_06112026
```
This confirms a campaign segment identifier exists in the impression pixel. Whether the same UTM parameters (`utm_campaign`, `utm_source`, `utm_medium`) are appended to click-through destination URLs cannot be confirmed without inspecting the decoded click-redirect targets.

The 26 skipped tracking links should be spot-checked to confirm UTM params are present on final destination URLs (e.g., `skechers.com/...?utm_source=email&utm_medium=email&utm_campaign=MKG_US_L90D...`).
