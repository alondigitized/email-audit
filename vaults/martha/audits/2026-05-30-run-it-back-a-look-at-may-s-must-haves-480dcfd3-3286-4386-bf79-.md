# Run it Back: A Look at May's Must-Haves
**Score:** 8/10 · **Type:** Email audit · **2026-05-30**
## Executive summary

- Okay, I'll be real — the only reason I opened this was out of habit and the BOGO banner I half-remembered from yesterday. "Run it Back" as a concept sounds like the marketing team ran out of ideas on a Friday afternoon and decided to recycle May's hits into one email. And sure enough, that's exactly what this is — a greatest-hits mashup of adult sneakers and boat shoes, with my 5-year-old and 9-year-old completely invisible in the body copy.
- The BOGO 50% off is front and center, which I always appreciate, but it's the same offer I've seen from Skechers basically every send this month. And then there's the preview text — JSON schema garbage, AGAIN. I flagged this mentally on the 27th, again on the 28th, and here we are on the 30th and it's still broken. At this point I half-expect it.
- The sections I scroll through — Low Profile Sneakers, Boat Shoes, Colorful Looks — are all adult-leaning and skew male. The only acknowledgment that kids exist is a tiny "KIDS" text link buried in the footer navigation. I wouldn't click. I wouldn't forward it. I'd mark it as read and move on.

## What's working

- **BOGO 50% off is right at the top** — no hunting required; I know immediately there's a real offer inside.
- **"SHOP CASUAL SNEAKERS" and "SHOP BOAT SHOES" CTA labels** are specific enough that I know exactly where each button goes, which I prefer over a vague "Discover."
- **Layout is clean** — no overlapping text, no broken image placeholders, no white boxes of doom. It rendered correctly, which sounds like a low bar but has not always been a given lately.
- **25% off apparel** is a secondary offer that adds value if I was already thinking about grabbing something for myself.

## What's weak

- **JSON schema preview text — still.** This is the fourth or fifth consecutive email with this issue. It's embarrassing at this point, and it actively killed my desire to open.
- **No kids content in the email body at all** — a 5-year-old girl and 9-year-old boy are why I'm on Skechers' list in the first place, and there's zero hero, module, or product callout for them.
- **Adult male model dominates the hero** — I don't see myself or my family in this email; I see a guy on a dock in boat shoes.
- **"Boat Shoes" is a whole dedicated section** — I have never once bought boat shoes and never will. This feels like it was built for a completely different subscriber segment.
- **Retrospective framing ("Run it Back")** is low-energy — it signals the brand has nothing new to show me, which, combined with the near-daily cadence, is starting to feel like noise.

## Recommendations

- 1. **Fix the preview text immediately** — this one change alone would lift open rate across the board; it's been broken for days. Whatever template is generating the JSON schema blob needs to be patched before the next send.
- 2. **Add a kids module to the body** — even one tile for "New in Girls' Shoes" and one for "Boys' Sneakers Under $50" would make this email relevant to me. The KIDS nav link at the bottom doesn't count.
- 3. **Reframe the hero or cut the "Run it Back" concept entirely** — if the offer is the same BOGO from May 25th, the hook needs to work harder. Lead with a reason to act *now*, not a nostalgia trip through May.
- 4. **Swap "Boat Shoes" module for something seasonal and family-friendly** — end-of-school / summer is right here; summer camp sneakers, pool-ready slip-ons for kids, something that speaks to where my family is at right now.
- 5. **Add a loyalty/rewards callout** — I'm a rewards member; a "double points this weekend" nudge would move me faster than a generic BOGO alone.
- **Subject Alt A:** `BOGO 50% Off: May's Top Picks, Still Available`
- **Subject Alt B:** `Stock Up Before Summer — May's Best Sellers`
- **Preheader Alt A:** `BOGO 50% off ends soon — kids, women, and men's top sellers inside`
- **Preheader Alt B:** `The styles everyone bought in May — grab them before they're gone`

### 1. Technical Summary

The email has one broken-experience defect (empty personalization token) and a systemic HTTP image-serving issue affecting 13+ assets. All other structural and compliance signals appear intact based on available source.

---

### 2. Link & Tracking Issues

**No broken destination links confirmed.** All 26 click links route through `click.emails.skechers.com` (Salesforce Marketing Cloud redirect domain) — these were skipped by the HTTP probe, which is expected behavior for redirect chains.

**Third-party pixel exposure (low severity):**
- `beacon.krxd.net` (Salesforce DMP / Krux) fires two user-match pixels and one impression pixel, all with PII-adjacent fields:
  - `partner_uid=adf27fee67323d52536b18110294bf793c265b830082caba4b1a32664832189a` — SHA-256 hashed identifier
  - `partner_uid=122277199` — plaintext internal subscriber ID
  - `campaignid=MKG_US_NONPURCLICK_U_MULTI_NONPURCH_EN_05302026`
- `ink1000.com` fires a secondary open-tracking pixel over **HTTP** (see §3).

These are functional, but the krxd `subid` pixel transmits an unhashed internal ID — confirm this is intentional and within your data-sharing agreement with the DMP.

---

### 3. Rendering & Accessibility

**HIGH — HTTP image sources blocked in modern clients:**

13 images are served over `http://` rather than `https://`. Gmail, Apple Mail (iOS 15+), and Outlook 365 all enforce HTTPS for remote content and will block or show broken images for:

| Asset | URL pattern |
|---|---|
| Skechers logo | `http://image.emails.skechers.com/…/dde00662-…png` |
| App Store badge | `http://image.emails.skechers.com/…/0ec56c9f-…png` |
| Google Play badge | `http://image.emails.skechers.com/…/9bb508d0-…png` |
| Curbside Pickup icon | `http://image.emails.skechers.com/…/00100b23-…png` |
| AfterPay icon | `http://image.emails.skechers.com/…/07cb60b5-…png` |
| Find A Store icon | `http://image.emails.skechers.com/…/fc08601a-…png` |
| Instagram, Facebook, YouTube icons | `http://image.emails.skechers.com/…` |
| Secondary open pixel | `http://www.ink1000.com/…/o.gif` |
| Unnamed decorative image | `http://image.emails.skechers.com/…/49468f73-…png` |

Root cause: `image.emails.skechers.com` is being referenced without the `s`. All assets should resolve at `https://image.emails.skechers.com` — this is likely a template or CDN config error, not a missing cert.

**Missing alt text:**
- `o.gif` (ink1000 pixel) — minor; tracking pixels should have `alt=""`
- `49468f73-4651-4af3-bea2-61d1ae5db486.png` — unnamed image has no alt text; if decorative use `alt=""`, if functional provide a description

**`-webkit-text-size-adjust: none` on `*` selector** — this disables user-initiated font scaling globally, which reduces accessibility for low-vision readers and fails WCAG 1.4.4 (Resize Text). Should be `100%` not `none`.

### 4. Personalization & Merge Tokens

**FAIL — Empty greeting name field:**

QA confirmed: the greeting renders as `"Hi ,"` with no subscriber first name populated. The merge token (likely `%%First Name%%` or equivalent AMPscript/HBS variable) resolved to an empty string for at least one recipient segment, indicating:

- Missing fallback default in the personalization expression (e.g., AMPscript should use `@firstName` with a `IIF(EMPTY(@firstName), "there", @firstName)` guard)
- Or the field was not populated in the send data extension for this audience

This is a broken-experience defect — every recipient with a missing first name sees a malformed greeting.
