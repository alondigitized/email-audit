## Technical Audit

## 1. Technical Summary
Email renders structurally but ships with a broken personalization token (empty greeting) and pervasive non-HTTPS image sources that risk being blocked by mail clients. Tracking infrastructure is heavy but functional; no compliance headers visible in the provided source.

## 2. Link & Tracking Issues
- 31 tracking/click-redirect links were skipped by automated probing — actual destination reachability is unverified.
- Multiple third-party tracking pixels stacked in the preheader: `click.emails.skechers.com/open.aspx`, two `beacon.krxd.net/1x1_usermatch.gif` calls (Salesforce Krux), `beacon.krxd.net/1x1_ad_impression.gif`, `pixel.app.returnpath.net/pixel.gif`, and `ink1000.com/p/up/...o.gif`. The Return Path pixel is missing a protocol (`src="pixel.app.returnpath.net/..."`) — browsers/clients will resolve it as a relative URL against the message, breaking the beacon.
- The `ink1000.com` open-tracking pixel is served over `http://` — opens from HTTPS-preview clients (Gmail, Apple Mail image proxy) may be blocked, undercounting opens.

## 3. Rendering & Accessibility
- **All hosted images load over `http://image.emails.skechers.com/...`** — Gmail's image proxy upgrades these, but stricter clients (Outlook with image blocking, corporate gateways) may drop them. Affected assets include the masthead `Skechers` logo, app store badges, social icons, and store-locator/curbside/AfterPay icons.
- Missing `alt` attributes on `o.gif` (tracking — acceptable) and on content image `49468f73-4651-4af3-bea2-61d1ae5db486.png` (not acceptable — fails screen-reader and image-blocked fallback).
- `<meta http-equiv="X-UA-Compatible" content="IE=Edge">` is malformed — the `content` attribute is present but no `http-equiv` is set on that meta tag in source (`<meta content="IE=Edge" />`). Same issue on the charset meta (`<meta content="text/html; charset=utf-8" />` lacks `http-equiv="Content-Type"`).
- Duplicate `@media` blocks for `max-width: 375px` and `max-width: 640px` repeat identical rules — bloats CSS but not a functional defect.

## 4. Personalization & Merge Tokens
- **[FAIL]** Greeting renders as `"Hi ,"` — merge token for first name resolved to empty string. Either the recipient profile lacks a first-name value or the template lacks a default fallback (e.g. `%%=IIF(EMPTY(@FirstName),"there",@FirstName)=%%` in SFMC AMPscript).
- No other unresolved tokens detected in the truncated source.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- From-address `no-reply@emails.skechers.com` is consistent with the sending subdomain — good for DMARC alignment, but raw `Received`/`DKIM`/`SPF`/`DMARC` headers were not provided, so authentication cannot be verified from this source alone.
- Unsubscribe link and physical postal address are not visible in the truncated HTML provided — cannot confirm CAN-SPAM §5(a)(3)/(5) compliance. Verify both are present in the truncated footer region.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- Click destinations are wrapped by `click.emails.skechers.com` redirects (SFMC) and were not unwrapped by the probe — UTM parameter presence on the final landing URLs cannot be confirmed from the source.
- Campaign ID `MKG_US_NA_K_CATEGORY_GENDER_EN_05242026` appears in the Krux ad-impression beacon and ink1000 pixel, suggesting consistent campaign tagging upstream. Recommend manually unwrapping one click-tracker to confirm `utm_source/medium/campaign` reach the landing page.

## 7. Recommendations
1. **Fix greeting fallback** — add a default value in the merge token so empty profiles render `Hi there,` instead of `Hi ,`.
2. **Force HTTPS on all image hosts** — rewrite `http://image.emails.skechers.com/...` and `http://www.ink1000.com/...` to `https://` across the template; the Skechers CDN already supports TLS.
3. **Fix the Return Path pixel URL** — prefix `https://` to `pixel.app.returnpath.net/pixel.gif?...` so the beacon resolves.
4. **Add `alt=""` (decorative) or descriptive alt** to `49468f73-...png` and all tracking pixels.
5. **Repair meta tags** — `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=Edge">`.
6. **Verify footer** contains a working one-click unsubscribe + physical address (truncated from source provided).
7. **Sample-unwrap one tracked link** to confirm UTM parameters survive the SFMC redirect to skechers.com.
