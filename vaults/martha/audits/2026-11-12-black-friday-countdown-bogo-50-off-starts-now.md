## Technical Audit

## 1. Technical Summary
The email has one confirmed rendering failure (an empty greeting slot, `Hi ,`) and several markup and tracking-pixel defects: a protocol-less pixel URL, `http://` image sources, and missing `alt` attributes. The HTML was truncated, so the unsubscribe footer, most link `href`s and UTM parameters could not be checked.

## 2. Link & Tracking Issues
- **Malformed pixel URL:** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…">` has no scheme. Clients resolve it as a relative path, so the request fails and the Return Path/Validity seed-tracking pixel never fires.
- **Insecure tracking pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=PRO_US_NA_U_BUNDLE_FULL_EN_11122026` is plain HTTP. Clients that proxy or block mixed content will drop it. It also embeds an identifier (`mi_u=8108404282`) in a cleartext URL.
- **Stacked third-party beacons:** four `beacon.krxd.net` requests (usermatch ×2, ad_impression) sit alongside the SFMC open pixel (`click.emails.skechers.com/open.aspx`). Two of them pass `partner_uid` values: a SHA-256 hash (`adf27fee…`) and a subscriber ID (`122277199`). Image-blocking clients lose all of these, and privacy-focused clients (such as Apple Mail Privacy Protection) will pre-fetch them.
- **Skipped probes:** 29 click-redirect links were not HTTP-probed. Their destinations are unverified.

## 3. Rendering & Accessibility
- **Missing `alt`, confirmed by QA:** `o.gif` (ink1000) and `dde00662-169f-447d-b0e2-fc65f6c2290c.png`. The second file is served from `http://image.emails.skechers.com/lib/fe3115…/` and looks like a content image, so this is the more significant one. With images off or on a screen reader, it has no text equivalent.
- **Missing `alt` in the source:** the `krxd.net` and `returnpath` pixels have no `alt` either. These are hidden, so the impact is minor.
- **Mixed content:** the `dde00662…png` image is on `http://` (`image.emails.skechers.com`). It may be blocked or flagged as insecure in some clients.
- **Malformed `<meta>` tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv` attribute, so they do nothing. Charset declaration relies on the HTTP/MIME headers.
- **Zoom restriction:** the viewport meta sets `maximum-scale=1`, which blocks pinch-zoom (WCAG 1.4.4).
- **Layout tables:** the visible layout tables (`<table class="widthFull" width="640">`) have no `role="presentation"`.
- **Text-size CSS:** `* { -webkit-text-size-adjust: none; }` disables iOS text scaling.
- **Mobile breakpoints:** `max-width: 375px` and `640px` rule sets are near-duplicates, and `.mobile-content`/`.desktop-content` use a separate `768px` breakpoint. Between 641px and 767px the display toggles may conflict. This is a risk, not a confirmed bug.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** the greeting renders as `Hi ,`, so the first-name field is empty and has no fallback. The subscriber record likely lacks a first name. The AgentMail test inbox may therefore not reflect production, but any real subscriber with a blank name field would see the same output. The SFMC personalization string needs a default value, such as `%%=IIF(Empty(@firstName),"there",@firstName)=%%`, or the greeting block should be suppressed when empty.
- No other unresolved `%%…%%` or `{{…}}` tokens were visible in the truncated source.

## 5. Compliance
- **Authentication headers:** `Authentication-Results` was not found. QA attributes this to the AgentMail relay, so SPF, DKIM and DMARC alignment are **unverified**, not failing. The `From` domain `emails.skechers.com` is consistent with the tracking subdomains.
- **Unsubscribe and postal address:** these fall in the truncated portion of the HTML. `List-Unsubscribe` / `List-Unsubscribe-Post` headers were not provided either. No issue can be asserted.
- **Tracking disclosure:** the `krxd.net` pixels carry hashed and subscriber identifiers. This is a privacy-policy matter and cannot be confirmed from the email alone.

## 6. Email-to-Site Continuity
- **UTM and landing-page checks:** not possible. All 29 click links go through the redirect domain and were skipped, and the visible `href`s are not in the truncated source.
- **Campaign ID:** the `PRO_US_NA_U_BUNDLE_FULL_EN_11122026` identifier is consistent across the ink1000 and krxd pixels, so campaign attribution looks consistent for those two.

## 7. Recommendations
1. Add a fallback to the first-name merge field, or hide the greeting when it is empty (**high**, the only QA FAIL).
2. Fix the Return Path pixel by adding `https://`: `https://pixel.app.returnpath.net/pixel.gif?r=…`.
3. Move `ink1000.com/…/o.gif` and `image.emails.skechers.com/…/dde00662….png` to HTTPS, and add `alt` text to the content image (`alt=""` is fine for decorative or tracking images).
4. Add `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"` to the two meta tags. Remove `maximum-scale=1` from the viewport.
5. Add `role="presentation"` to the layout tables.
6. Re-run the audit against a raw `.eml` or the full HTML, with headers preserved, to check SPF/DKIM/DMARC, `List-Unsubscribe`, the footer, and the final destination URLs and UTM parameters of the 29 skipped links.
