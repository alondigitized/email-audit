## Technical Audit

## 1. Technical Summary
The email has one confirmed broken-personalization defect (empty greeting) and a missing plain-text part. The visible source also has a scheme-less tracking pixel URL, two insecure (`http://`) images without alt text, and head-level markup errors. The HTML was truncated, so footer, unsubscribe and CTA markup could not be inspected.

## 2. Link & Tracking Issues
- **Scheme-less pixel URL:** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…">` has no `https://`. Clients resolve it as a relative path, so the Return Path (Validity) seed/monitoring pixel won't fire. It also has no `alt`.
- **HTTP tracking pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=MKG_US_NA_U_CATEGORY_WIDE_EN_10182026_B` is non-HTTPS and can be blocked or trigger mixed-content handling.
- **Link probing skipped:** 32 tracking links on click-redirect domains (e.g. `click.emails.skechers.com`) were not probed over HTTP. Destination validity and redirect health are unverified.
- **Pixel stack:** There are five hidden pixels (`click.emails.skechers.com/open.aspx`, three `beacon.krxd.net` pixels, and the `returnpath` pixel) plus the `ink1000` pixel. They sit inside `display:none` containers, which some clients skip when loading images, so open counts may be understated.

## 3. Rendering & Accessibility
- **Missing alt text (QA-confirmed):**
  - `o.gif` (ink1000)
  - `dde00662-169f-447d-b0e2-fc65f6c2290c.png` (`http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/…`). This one is a content image, so it is a real accessibility gap.
- **HTTP content image:** The `dde00662…png` image on `image.emails.skechers.com` is served over `http://`, so it may be blocked or flagged as mixed content.
- **Ineffective head meta tags:**
  - `<meta content="text/html; charset=utf-8" />` has no `http-equiv`, so it declares nothing.
  - `<meta content="IE=Edge" />` has no `http-equiv` either.
  - Without a working charset declaration, `®` and other non-ASCII characters rely entirely on the MIME header.
- **Viewport blocks zoom:** `maximum-scale=1` in `<meta name="viewport">` prevents pinch-zoom on mobile, which is an accessibility problem.
- **Missing `lang`:** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang` attribute.
- **Layout tables:** The visible layout tables (`<table class="widthFull" width="640" …>`) have no `role="presentation"`, so screen readers may announce table structure.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** The greeting renders as "Hi ," because the name field is empty. There is no fallback value in the merge logic.
- **No unresolved tokens in the visible source:** The truncated portion could not be checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **[FAIL] No plain-text part:** The text version is 0 chars. A multipart/alternative with a text part is expected for deliverability and spam scoring. If AgentMail dropped the part during relay capture, this is a capture artifact and not a sender defect.
- **[WARN] Authentication unknown:** No `Authentication-Results` header was found, so SPF, DKIM and DMARC status is unverified. The sender is `no-reply@emails.skechers.com` and the click domain is `click.emails.skechers.com`, so alignment looks plausible, but it isn't confirmed.
- **Hashed identifier sharing:** The `beacon.krxd.net` pixels pass a SHA-256 hash (`partner_uid=adf27fee…189a`) and a subscriber ID (`partner_uid=122277199`) to a third party. This is an observation for privacy and consent review, not a confirmed violation.
- **Not verifiable:** Unsubscribe link, `List-Unsubscribe` / `List-Unsubscribe-Post` headers and physical postal address all fall in the truncated or unprovided portion.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Campaign ID:** It is consistent across pixels (`MKG_US_NA_U_CATEGORY_WIDE_EN_10182026_B` in both the `krxd` `campaignid` and the `ink1000` `mi_ecmp`).
- **Not verifiable:** UTM parameters and landing-page alignment could not be assessed. The click URLs are truncated and the 32 tracking links were not followed.

## 7. Recommendations
1. Add a fallback to the greeting token (e.g. "Hi there,") or suppress the greeting when the name is empty.
2. Prefix the Return Path pixel with `https://`.
3. Move the `ink1000` pixel and the `dde00662…png` image to HTTPS, and add `alt` to both: `alt=""` for the pixel, and descriptive text for the content image.
4. Fix the head meta tags: `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
5. Remove `maximum-scale=1` from the viewport tag, and add `lang="en"` and `role="presentation"` on layout tables.
6. Send a multipart message with a real plain-text alternative. First confirm whether the empty text part is a capture artifact.
7. Re-run the audit with the full HTML and raw headers to verify:
   - unsubscribe and `List-Unsubscribe` headers
   - SPF/DKIM/DMARC
   - physical address
   - UTM parameters
   - landing-page alignment
