### 3. Rendering & Accessibility

**`http-equiv` missing on two `<meta>` tags**
```html
<!-- actual -->
<meta content="text/html; charset=utf-8" />
<meta content="IE=edge" />

<!-- correct -->
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta http-equiv="X-UA-Compatible" content="IE=edge" />
```
Without `http-equiv`, both tags are inert. The charset declaration is not interpreted by Outlook/IE rendering paths, which can corrupt multibyte characters.

**`Founders Grotesk` referenced but never declared**
The global `a {}` rule sets `font-family:'Founders Grotesk', Helvetica, sans-serif`, but no `@font-face` block for Founders Grotesk appears in the `<style>` block. Six `@font-face` rules load Open Sans only. Every link in the email silently falls back to Helvetica.

**Stale Google Fonts version**
All six `@font-face` `src:` URLs reference `opensans/v17/`. Current version on `fonts.gstatic.com` is v40+. While the files still resolve today, v17 paths are deprecated and may be removed without notice.

**`white-space:pre` on `img` elements**
```css
img { -ms-interpolation-mode:bicubic; white-space:pre; }
```
`white-space:pre` is not a valid property for replaced elements (`<img>`). It has no effect on images but will apply to any inline fallback text, potentially breaking alt-text wrapping in image-off environments.

**Mobile breakpoint at 499px**
The sole responsive breakpoint is `@media only screen and (max-width: 499px)`. The de facto standard for email is 600px container + 480px breakpoint. At viewport widths 500–599px (common on modern Android), no mobile styles apply.
