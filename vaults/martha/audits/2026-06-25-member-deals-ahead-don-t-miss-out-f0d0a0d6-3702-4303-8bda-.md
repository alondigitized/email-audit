# Member Deals Ahead! Don't Miss Out
**Score:** 8/10 · **Type:** Email audit · **2026-06-21**
## Executive summary

- This is "Deal #2" in Skechers' Member Appreciation Month, and honestly — as someone who's gotten at least three BOGO emails from them in the last eleven days — the whole thing is starting to feel like groundhog day. When "Member Deals Ahead! Don't Miss Out" showed up in my inbox I already knew what was inside before I opened it. I was right: another buy-one-get-one.
- Once I'm inside though, the BOGO is presented cleanly — the offer reads instantly, the SHOP TODAY button is obvious, and the "SKECHERS Plus Members" framing does make me feel a little bit seen. The sweepstakes (win a $250 gift card) is a nice wrinkle I didn't expect. But then I hit the kids section and it's just a lone button with zero product images. I'm literally shopping for a 5-year-old and a 9-year-old and Skechers handed me an empty shelf.
- And that preview text is still broken JSON schema garbage — same bug from the June 17th send, same bug from June 12th. At this point it's not a mistake, it's a pattern. I'd mark this read, pocket the deal link mentally, and wait to see if they ever show me actual kids' shoes.

## What's working

- BOGO is instantly legible — "BUY ONE, GET ONE 50% OFF OR 20% OFF 1 PAIR" is bold and no-nonsense, I didn't have to hunt for the offer
- "SKECHERS Plus Members" framing makes this feel like my deal, not a sitewide blast to strangers
- The sweepstakes ($250 gift card enter-to-win) is a genuine surprise element — not something I expected from a standard member promo
- "Deal #2" sequencing creates a light narrative thread across the sends, which is more interesting than just repeating the same flat ad
- Renders cleanly on mobile — no broken images, readable text, tap targets feel reasonable

## What's weak

- SHOP KIDS' is a lonely button with zero product imagery — women's and men's both get a photo grid, kids get nothing; for a mom of two this is a real miss
- The hero splits attention between the sweepstakes and the BOGO — two separate value propositions fighting for the same first scroll, and neither fully wins
- This is the third BOGO-style email in eleven days; "Don't Miss Out" rings hollow when the offer hasn't meaningfully changed since June 14th
- Preview text is still broken JSON schema — I flagged the same bug in the June 17th "Step in and Stand Out" send and again in June 12th "Staff Picks"; this is a systemic problem now, not a one-off

- 1. **Fix the preview text — this is now a three-peat bug.** File an engineering ticket. Every send this goes out it's leaking potential opens to subscribers who see garbage before they tap.
- 2. **Give SHOP KIDS' a product row.** Two or three images — one pair for a girl around 5, one for a boy around 9 — same treatment women's and men's get. If you have purchase data on me, this is table stakes.
- 3. **Put "Deal #2" in the subject line.** The sequencing idea is smart but invisible from the inbox. Make the narrative legible where it counts.
- 4. **Move the sweepstakes to a slim banner below the BOGO**, not a co-equal hero element — the gift card angle is good, it just shouldn't compete with the primary offer.
- 5. **Add a hard deadline.** "Member Appreciation Month" ends when? "Offer ends June 30" makes me click today. "Month" makes me think I'll get to it later — and then I don't.

### 1. Technical Summary

The email is structurally sound with standard table-based layout and dual-breakpoint responsive CSS. The primary systemic issue is that all image assets are served over HTTP, not HTTPS — this is a pervasive infrastructure problem that will cause silent image blocking in many modern email clients.

---

### 2. Link & Tracking Issues

**Open pixel — HTTP:**
```
http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=...
```
Served over plain HTTP. This open-tracking pixel will be blocked or upgraded by Gmail, Outlook (modern), and Apple Mail's MPP proxy. Open rate data for this send is unreliable.

**Returnpath pixel — missing scheme:**
```html
<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1dbf0dcef79cbad82c12fe25342701e4499" />
```
No `http://` or `https://` prefix. This URL will fail to load entirely — it is not a relative path in email context. Returnpath deliverability/reputation signal for this send is broken.

**Krux/Salesforce DMP pixels — 0×0, no `alt`:**
Three `beacon.krxd.net` pixels are present for third-party user-matching. These are 0×0 with `display:none`, which is correct, but they emit subscriber identity (`partner_uid=122277199`) to a third-party ad platform. Confirm this is disclosed in privacy policy and consented via list sign-up flow.

**26 click-redirect links skipped by QA:** All CTAs route through `click.emails.skechers.com` — expected, no issue, but means destination URL verification was not performed. Landing page alignment (Section 6) cannot be fully confirmed from available data.

---

### 3. Rendering & Accessibility

**HTTP image sources — 12 affected assets:**

All `image.emails.skechers.com` assets use `http://`, not `https://`. Affected images include the Skechers logo, app store badges, social icons, and footer icons:

```
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-...png  (logo)
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/49468f73-...png
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/0ec56c9f-...png  (App Store)
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/11/9bb508d0-...png  (Google Play)
... (8 additional footer assets)
```

Gmail, Outlook.com, and Apple Mail proxy/block mixed-content images. The logo failing to render is a high-visibility breakage. Fix: serve all assets from `https://`.

**Missing `alt` text — 2 confirmed:**
- `o.gif` (open pixel) — alt="" acceptable for tracking pixels, but flagged
- `49468f73-...png` — this is a content image (not a pixel), missing alt entirely. If it's a hero or promo image, screen readers and image-off renderers will have no fallback text.

**`<meta content="text/html; charset=utf-8" />` — malformed:**
The `http-equiv` attribute is missing: `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />`. Some older Outlook versions may misinterpret charset without it.

**Duplicate media query breakpoints:**
`max-width: 375px` and `max-width: 640px` blocks are defined twice (once in the main `<style>` block, once repeated). The `max-width: 480px` block appears in a second `<style>` tag in `<body>`. Redundant rules increase parse weight but do not cause breakage.

**`-webkit-text-size-adjust: none`:**
Applied globally via `* { -webkit-text-size-adjust: none; }`. The value `none` (vs. `100%`) disables user font scaling entirely, which is an accessibility concern on iOS for users with visual impairments.

### 6. Email-to-Site Continuity (UTM / Landing Page)

All CTAs pass through `click.emails.skechers.com` click-tracking redirects. UTM parameter presence on destination URLs cannot be confirmed without resolving those redirects (the QA tool skipped them). This is the most common source of attribution gaps in Skechers sends — destination URLs should be spot-checked manually or via redirect-following in QA tooling.

Campaign ID in pixels (`PRO_US_NA_U_BUNDLE_LOYL_EN_06212026`) should match UTM `utm_campaign` values on destination URLs if analytics attribution is required.
