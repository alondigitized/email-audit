# Today Only! Extra 10% off for Members
**Score:** 7/10 · **Type:** Email audit · **2026-07-24**
## Executive summary

- Okay, here we go again — and I literally mean *again*. Same JSON gibberish in my inbox preview as yesterday. I almost swipe-deleted this before I even opened it, and honestly the only reason I didn't is because "Today Only!" + "Extra 10% off for Members" is a subject line that knows exactly what to say to a Skechers Plus member who is trying to knock out her back-to-school list on a budget. Once I'm inside the email, it's actually a solid deal: stacked offer, clear codes, a dedicated SHOP KIDS section. That part works. But Skechers needs to fix the preview bug — this is two days running now and it's eroding the trust they built with me all week.
- Would I click? Yes, specifically the SHOP KIDS button, because the savings make sense for stocking up. Would I forward to a friend? Probably not — this feels like a member exclusive, and honestly I'd rather keep the deal to myself and clean up my cart. Would I open it again next time with that same broken preview? I'm getting closer to auto-filtering these to a folder I check twice a week instead of every day.

## What's working

- **Stacked offer at the top, impossible to miss** — 10% off with SAVE10 AND 25% off $100+ with SAVINGS, both codes visible before I have to scroll. As a mom building a back-to-school haul that is going to hit $100+ anyway, this is genuinely useful math.
- **"Today Only" + "Plus Members" framing** — I feel like I'm getting something other people aren't. That still works on me.
- **SHOP KIDS button with that little orange accent tag** — it's small but it caught my eye on the way down. There IS a path to what I actually came for.
- **Clean seasonal design** — the tropical leaf background reads "summer sale" without being obnoxious. Layout is tidy, nothing is fighting for space.
- **Afterpay and Klarna logos at the bottom** — I never use these, but seeing them confirms the brand is keeping up with how people actually shop. Reassuring.

## What's weak

- **Same JSON preview garbage as July 23** — two days in a row now. At this point it's not a one-off bug, it's a pattern, and it makes me wonder what else is broken behind the scenes.
- **SHOP KIDS is buried, not hero** — the email opens on women's shoes, then men's shoes, then kids'. For someone like me whose first and second items on the list are a 5-year-old's sneakers and a 9-year-old's school shoes, that ordering feels backwards.
- **No kids products shown in the kids section** — the shoe under SHOP KIDS looks like it could be an adult neon-colorway sneaker. I can't tell. Show me a velcro sneaker or a light-up sole and I'm clicking instantly.
- **Two codes, unclear if they stack** — 10% off AND 25% off $100+? Do I enter both at checkout? Do they stack? The email doesn't say. That's friction I'll hit at checkout and it's going to annoy me.

## Recommendations

- 1. **Fix the preview text — today.** This is the highest-leverage change. The email body is good; the preview is sabotaging opens. Two days in a row is a broken deployment, not a fluke.
- 2. **Flip the category order to Kids → Women → Men.** Or at minimum, give kids its own hero moment in the back-to-school season. The majority of my cart is for my kids.
- 3. **Show real kids products in the SHOP KIDS tile** — a velcro sneaker in pink or a light-up sole for girls, a durable lace-up in blue/grey for boys. The browsing starts before I even click.
- 4. **Add one line clarifying code stacking** — "Enter both codes at checkout — they stack!" would remove the hesitation entirely.
- 5. **Add a family bundle or total savings example** — "Buy 3 pairs, save $40+" makes the math real for a mom stocking up.

- **Subject Alt B:** `Your Member Deal Expires Tonight — 10% Extra Off`
- **Preheader Alt A:** `Use code SAVE10 + SAVINGS at checkout — stack both on kids, women's & more.`
- **Preheader Alt B:** `Today-only stacked savings for Skechers Plus members — grab the kids' styles before they sell out.`

### 2. Link & Tracking Issues

```
Missing `https://` prefix entirely. This is not a valid URL — the pixel fires nowhere. Inbox placement measurement from ReturnPath/Validity is silently broken for this send.

**HTTP-only ink1000 tracking pixel**
```

**26 click-redirect links unverified** — all route through `click.emails.skechers.com`. QA probe skipped all of them. Destination URL hygiene (UTM params, 404s) is unconfirmed.

**Missing alt text on content image**
`49468f73-4651-4af3-bea2-61d1ae5db486.png` has no `alt` attribute. This appears to be a product/content image (not a tracking pixel), so it will render as a broken image icon for image-off readers and fail basic accessibility.

**Duplicate responsive CSS blocks**
`max-width: 375px` and `max-width: 640px` media query rules are declared twice — once in the first `<style>` block and once repeated. Harmless functionally but adds ~1.2 KB of avoidable weight.

**`desktop-content` visibility pattern**
```css
.desktop-content { display: none; }  /* base */
@media (min-width: 768px) { .desktop-content { display: block !important; } }
```
The base rule lacks `!important`, which means it can be overridden by inline styles in Outlook's rendering engine. If any desktop-content element has an inline `display` value, it may render on mobile.
