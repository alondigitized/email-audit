## Technical Audit

## 1. Technical Summary
The email renders with a broken personalization slot (`Hi ,`) and carries several insecure or malformed tracking pixels, including one with no URL scheme. The HTML was truncated, so footer, unsubscribe and CTA links could not be checked.

## 2. Link & Tracking Issues
- **Scheme-less pixel:** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db...">` has no `https://`. Clients resolve it as a relative path, so the request fails. This Return Path/Validity deliverability pixel never fires. It also has no `alt`.
- **HTTP pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=MKG_US_NA_U_SLIPIN_PROD_EN_11202026` is non-HTTPS, so clients may block it or flag mixed content.
- **Link probing:** 56 tracking links were skipped, all on click-redirect domains such as `click.emails.skechers.com`. Final destinations and redirect health are unverified.
- **Unlabeled pixels:** Three `beacon.krxd.net` pixels (`1x1_usermatch.gif` ×2, `1x1_ad_impression.gif`) use `width="0" height="0"` and have no `alt`. Hidden containers mean no visual impact.

## 3. Rendering & Accessibility
- **Missing alt text:**
  - `o.gif` (ink1000 pixel).
  - `dde00662-169f-447d-b0e2-fc65f6c2290c.png` at `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/...`. This is a content image, not a pixel, so screen readers and image-blocked clients get no text.
- **Non-HTTPS content image:** The same `dde00662...png` loads over `http://`, so it may be blocked.
- **Ineffective meta tags:**
  - `<meta content="text/html; charset=utf-8" />` has no `http-equiv="Content-Type"`, so it declares nothing.
  - `<meta content="IE=Edge" />` has no `http-equiv="X-UA-Compatible"`.
- **Zoom restriction:** The viewport meta sets `maximum-scale=1`, which blocks pinch-zoom (WCAG 1.4.4). `-webkit-text-size-adjust: none` also prevents text resizing on iOS.
- **Layout tables:** The visible layout tables (`<table cellpadding="0" cellspacing="0" border="0">`) have no `role="presentation"`, so screen readers may announce them as data tables.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** The greeting renders as `Hi ,` because the name field is empty. No fallback value is configured, which is visible to every recipient with a missing first name.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication:** `Authentication-Results` was not found. The QA tool attributes this to the AgentMail relay, so SPF, DKIM and DMARC status is unverified, not confirmed failing. The From domain is `emails.skechers.com`.
- **Unsubscribe / physical address:** Not visible in the truncated source, so no finding either way. `List-Unsubscribe` headers were not provided.
- **Third-party data sharing:** The Krux (Salesforce DMP) `usermatch` pixels pass `partner_uid=adf27fee...189a`, a SHA-256 value tagged `sha25`, and a subscriber ID, `122277199`. These pixels link the recipient's identity to a third-party ad network. That is a privacy-disclosure consideration. I could not verify whether the policy covers it.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **UTMs:** Not verifiable. The links are SFMC redirect wrappers, and no destination URLs are visible in the truncated source.
- **Campaign ID:** `MKG_US_NA_U_SLIPIN_PROD_EN_11202026` appears in the ink1000 and Krux pixels. A matching campaign ID on the landing-page URLs could not be checked.
- **Offer alignment:** Not checkable. The preheader offers "Members take 30% off Slip-ins", and the landing pages were not resolved.

## 7. Recommendations
1. Add a fallback to the greeting merge field, for example `Hi there,`. Suppress the greeting entirely when the name is empty.
2. Fix the Return Path pixel to `https://pixel.app.returnpath.net/pixel.gif?r=...`.
3. Switch `ink1000.com` and `image.emails.skechers.com` assets to HTTPS. Add `alt` text to `dde00662...png`, and `alt=""` to decorative pixels.
4. Correct the meta tags with `http-equiv="Content-Type"` and `http-equiv="X-UA-Compatible"`. Remove `maximum-scale=1` and `-webkit-text-size-adjust: none`. Add `role="presentation"` to layout tables.
5. Re-run the audit with the full HTML and raw headers. That would verify the unsubscribe link and `List-Unsubscribe`, SPF/DKIM/DMARC, the footer address, and the UTM parameters on the resolved CTA destinations.
