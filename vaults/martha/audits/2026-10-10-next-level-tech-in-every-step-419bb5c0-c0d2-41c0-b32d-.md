## Technical Audit

## 1. Technical Summary
The email's main defect is an unresolved greeting merge field (`Hi ,`). There is also a protocol-less tracking pixel (`pixel.app.returnpath.net/...`), two `http://` images, missing alt text, and malformed `<meta>` tags. The HTML was truncated, so footer, unsubscribe and link-level checks could not be done.

## 2. Link & Tracking Issues
- **Broken pixel URL:** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db...">` has no scheme. Clients will treat it as a relative path, so the request fails and Return Path / Validity seed tracking is lost. It also has no `alt`.
- **Insecure tracking pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=MKG_US_NA_U_COMF_ENGAGEDL60D_EN_10102026` is plain HTTP and may be blocked or rewritten by image proxies. The result is unreliable measurement.
- **Open pixel placement:** the primary open pixel, `https://click.emails.skechers.com/open.aspx?...`, is inside `<div style="display:none !important">`. Some clients skip images in hidden containers, which can undercount opens.
- **Third-party beacons:** four `beacon.krxd.net` pixels are in the same hidden block. Two are user-match pixels with `partner_uid=adf27fee67323d52...` (a SHA-256 hash) and `partner_uid=122277199` (a subscriber ID). They are low-risk functionally, but they pass identifiers to a third party.
- **Unprobed links:** 32 tracking links on click-redirect domains were skipped in the QA run, so their destinations are unverified.

## 3. Rendering & Accessibility
- **Missing alt text (QA WARN):**
  - `o.gif` (ink1000)
  - `dde00662-169f-447d-b0e2-fc65f6c2290c.png` (`http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/...`)
  - the Return Path pixel
- **HTTP image:** `dde00662-...png` is served over `http://` from `image.emails.skechers.com`. This is a content image, not a pixel, so blocking would visibly break the layout.
- **Malformed meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv`, so neither declaration takes effect. The charset is not declared.
- **Zoom blocked:** `<meta name="viewport" content="..., maximum-scale=1">` disables pinch-zoom on mobile, which is an accessibility problem.
- **No document language:** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang` attribute. The `<title>` is only "Skechers®".
- **Layout tables:** the visible layout tables, for example `<table cellpadding="0" cellspacing="0" border="0">`, have no `role="presentation"`. The remainder of the source was truncated, so I couldn't check the rest.
- **Style block in body:** `<style>div.preheader{...}</style>` is inside `<body>`. Some clients strip it, and the inline `display:none !important` on the preheader limits the impact.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** the greeting renders as `Hi ,` because the name field is empty. This is a merge-field failure with no fallback value. It is the only item flagged as a broken experience, and it probably accounts for the 86% pass rate.
- The Krux and ink1000 identifiers (`mi_u=8108404282`, `partner_uid=122277199`) were populated, so subscriber data was available at send time. The failure looks specific to the first-name attribute, not to the whole send.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **No issues found in the visible source.** The sender is `SKECHERS <no-reply@emails.skechers.com>`, a consistent subdomain.
- **Not verifiable:** the footer, physical address, unsubscribe link, and `List-Unsubscribe` / `List-Unsubscribe-Post` headers were truncated or not supplied. The same goes for SPF, DKIM and DMARC results. I'm not reporting these as passing.
- Note: `no-reply@` as the From address is a deliverability and reply-handling weakness, not a CAN-SPAM violation.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Not verifiable:** CTA hrefs are wrapped in `click.emails.skechers.com` redirects, and QA skipped all 32 of them. The final landing URLs, UTM parameters and landing-page match with the "extra 10% off sitewide" preheader could not be confirmed.
- **Campaign ID:** it appears consistently in the beacons as `MKG_US_NA_U_COMF_ENGAGEDL60D_EN_10102026`. That is useful for attribution if it also reaches the site analytics.

## 7. Recommendations
1. Add a fallback to the first-name merge field (e.g. `%%=IIF(Empty(@firstname),"there",@firstname)=%%`), or drop the name from the greeting when it's empty. Put the send behind a pre-flight check that flags empty-name renders.
2. Change the Return Path pixel to `https://pixel.app.returnpath.net/pixel.gif?r=...` and add `alt=""`.
3. Switch `http://image.emails.skechers.com/...dde00662-...png` and `http://www.ink1000.com/...o.gif` to HTTPS. Add `alt=""` to the pixel, and meaningful `alt` text to the content image.
4. Fix the meta tags: `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
5. Remove `maximum-scale=1` from the viewport tag, and add `lang="en"` to `<html>`.
6. Add `role="presentation"` to layout tables.
7. Re-run QA on the full HTML, and resolve the redirects (with a tracking-aware probe) to check the unsubscribe link, the `List-Unsubscribe` headers, UTM parameters and landing pages.
