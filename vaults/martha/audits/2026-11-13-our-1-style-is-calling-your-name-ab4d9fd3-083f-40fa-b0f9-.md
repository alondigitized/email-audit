## Technical Audit

## 1. Technical Summary
The email has a confirmed personalization failure (empty greeting, `Hi ,`) and several tracking-pixel defects: a scheme-less Return Path pixel URL, plaintext HTTP image sources, and missing alt text. Link destinations, UTM parameters and unsubscribe/footer markup couldn't be verified, because the HTML was truncated and 42 tracking links were skipped.

## 2. Link & Tracking Issues
- **Broken pixel URL:** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1dbf0dcef79cbad82c12fe25342701e4499" width="1" height="1" />` has no scheme. Email clients resolve it as a relative path, so the request fails and the Return Path (Validity) seed/inbox-placement tracking never fires. It also has no `alt` attribute.
- **Non-HTTPS tracking pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=MKG_US_NA_U_CATEGORY_ENGAGEDL60D_EN_11132026` loads over HTTP and may be blocked or rewritten. Its `mi_u=8108404282` identifier is sent in cleartext.
- **Non-HTTPS content image:** `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png` is on the sender's own domain, so an HTTPS version very likely exists.
- **Hidden third-party beacons:** The four `beacon.krxd.net` pixels (`usermatch` ×2, `ad_impression` ×1) sit in a `display:none` container. One passes what looks like a SHA-256 of the recipient identifier (`partner_uid=adf27fee…189a`). Many clients strip `display:none` content, so these are unreliable. The tracking is non-functional in those clients.
- **Skipped probes:** 42 links on tracking/redirect domains (e.g. `click.emails.skechers.com`) were not HTTP-probed, so the final destinations and their status codes are unverified.

## 3. Rendering & Accessibility
- **Missing alt text:** `o.gif` and `dde00662-169f-447d-b0e2-fc65f6c2290c.png` have no `alt` attribute (QA WARN). The 1×1 pixel is harmless, but the PNG is a content image.
- **Malformed meta tags:**
  - `<meta content="text/html; charset=utf-8" />` has no `http-equiv`, so it declares nothing.
  - `<meta content="IE=Edge" />` has no `http-equiv` either.
- **Zoom restricted:** `viewport` contains `maximum-scale=1`, which blocks pinch-zoom (WCAG 1.4.4).
- **Text resizing disabled:** `* { -webkit-text-size-adjust: none; }` disables iOS text-size adjustment.
- **No document language:** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang` attribute.
- **Table semantics:** The visible layout tables (`<table cellpadding="0" cellspacing="0" border="0">`, `<table width="1" height="1" …>`) lack `role="presentation"`. Screen readers may announce them as data tables.
- **Hidden tracking markup:** `.hidden` and `.mobile-hidden` use `display:none`, which removes the content from the accessibility tree. This is fine for pixels but should not be applied to real content.

## 4. Personalization & Merge Tokens
- **[FAIL] Empty greeting slot:** The greeting renders as `Hi ,`. The first-name field was empty, with no fallback value. The `%%…%%`-style token or AMPscript needs a default, or the greeting line should be conditional.
- No other unresolved tokens (`%%`, `{{`, `[FIRSTNAME]`) were reported by QA in the visible HTML.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Authentication-Results:** Not found (QA WARN). This is expected via the AgentMail relay, so SPF/DKIM/DMARC alignment for `emails.skechers.com` is **unverified**, not failed.
- **Unsubscribe and address:** The unsubscribe link and physical postal address are not visible in the truncated source. `List-Unsubscribe` and `List-Unsubscribe-Post` headers were not provided. Compliance can't be confirmed or denied from this data.
- **Third-party identifier sharing:** The `krxd.net` beacons pass a hashed identifier (`partner_uid=adf27fee67323d52…`) and a sub-ID (`122277199`) to a third party. This should be covered by the privacy disclosures, but the HTML can't confirm that.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **UTMs not verifiable:** All 42 click links go through redirect domains and were skipped, so UTM parameters and landing-page alignment can't be assessed.
- **Campaign ID consistent:** `MKG_US_NA_U_CATEGORY_ENGAGEDL60D_EN_11132026` appears identically in the `krxd` `campaignid` and the `ink1000` `mi_ecmp` params.
- **Preheader and offer:** The preheader says "buy one, get one 50% off". The offer and landing-page copy weren't available to compare.

## 7. Recommendations
1. **Fix the greeting fallback:** Add a default (e.g. `Hi there,`) or suppress the greeting when the name is empty. This is the only confirmed user-facing break.
2. **Fix the Return Path pixel:** Change it to `https://pixel.app.returnpath.net/pixel.gif?r=…` and add `alt=""`.
3. **Move HTTP images to HTTPS:** Switch `ink1000.com/…/o.gif` and `image.emails.skechers.com/…/dde00662-…png` to HTTPS, and ask the vendor to confirm HTTPS support for the ink1000 pixel.
4. **Add alt text:** Give the PNG a descriptive `alt` and the tracking pixels `alt=""`.
5. **Correct the meta tags:** Use `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` and `<meta http-equiv="X-UA-Compatible" content="IE=edge" />`.
6. **Remove the accessibility blockers:** Drop `maximum-scale=1` and `-webkit-text-size-adjust: none`, add `lang="en"` to `<html>`, and add `role="presentation"` to the layout tables.
7. **Re-run QA on the full source:** The audit pipeline should use the untruncated HTML and the raw headers. That would verify the footer unsubscribe link, the postal address, `List-Unsubscribe`, and the final URLs and UTMs behind the 42 skipped tracking links. Check SPF/DKIM/DMARC from the original delivery path rather than the AgentMail relay.
