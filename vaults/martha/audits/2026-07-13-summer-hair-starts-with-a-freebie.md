### 3. Rendering & Accessibility

**Issue 1 — Malformed `charset` meta tag:**
```html
<meta content="text/html; charset=utf-8" />
```
Missing `http-equiv="Content-Type"`. Without it, Outlook 2016+ and some webmail clients may ignore the charset declaration entirely. Correct form:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```

**Issue 2 — Malformed `X-UA-Compatible` meta tag:**
```html
<meta content="IE=edge" />
```
Missing `http-equiv="X-UA-Compatible"`. No functional effect in modern clients, but indicates the template was not linted before send.

**Issue 3 — `Founders Grotesk` referenced with no `@font-face` declaration:**
The global anchor style declares:
```css
a { font-family: 'Founders Grotesk', Helvetica, sans-serif; }
```
No `@font-face` block loads this font — only Open Sans variants are declared. All links silently fall back to Helvetica on every client. If this is an intentional system-font reference, document it; if it should render the brand typeface, a web font source is missing.

**Issue 4 — Stale Google Fonts version pinned:**
All `@font-face` sources point to `fonts.gstatic.com/s/opensans/v17/` (Open Sans v17). Current production version is v40+. Google maintains URL backwards compatibility, so this is low-severity, but the template is using a 5+ year old font snapshot.

**Issue 5 — `white-space: pre` on `img` elements:**
```css
img { -ms-interpolation-mode: bicubic; white-space: pre; }
```
`white-space` is not applicable to replaced elements (`<img>`). This is vestigial cruft that has no effect but signals the template has not been audited since its original authoring.

**Cannot assess:** `alt` text coverage and `role`/`aria` attributes require the full body HTML.
