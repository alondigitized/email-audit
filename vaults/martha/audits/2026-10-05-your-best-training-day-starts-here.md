## Technical Audit

## 1. Technical Summary
The email has one confirmed merge-token failure (an empty greeting slot, `Hi ,`) and several tracking-pixel defects: two `http://` image sources, a scheme-less pixel URL, and missing alt text. Only the first part of the HTML was available, so the footer, unsubscribe link and authentication headers could not be checked.

## 2. Link & Tracking Issues
- **Scheme-less pixel URL:** `<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1db…">` has no `https://`. Clients resolve it as a relative path, so it will 404 and the Return Path/Validity seed tracking won't fire.
- **Non-HTTPS pixel:** `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?mi_u=8108404282&mi_ecmp=MKG_US_NA_U_PERFORM_PERF_EN_10052026` is plain HTTP and may be blocked or rewritten by proxies such as Gmail's.
- **Stacked third-party beacons:** three `beacon.krxd.net` calls (`1x1_usermatch.gif` twice, `1x1_ad_impression.gif` once), plus the ink1000 and returnpath pixels, load alongside the ESP open pixel `click.emails.skechers.com/open.aspx?…`. Each adds a failure point and extra requests.
- **Unverified links:** 29 tracking links were skipped by the QA probe because they are click-redirect domains. Their destinations, status and redirect chains are unverified.

## 3. Rendering & Accessibility
- **Missing alt text (QA-confirmed):**
  - `o.gif` (ink1000)
  - `http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png`
- **Missing alt on beacons (source):** the three `krxd.net` images and the returnpath image have no `alt` attribute. The krxd images are inside `display:none`, and the returnpath image is in the same hidden `div` with no `style`, so this is low impact.
- **Non-HTTPS content image:** the `dde00662-…png` image uses `http://image.emails.skechers.com/…`. If it is a visible content image, it can be blocked or flagged as mixed content.
- **Ineffective meta tags:** `<meta content="text/html; charset=utf-8" />` and `<meta content="IE=Edge" />` have no `http-equiv`, so they declare nothing. Charset then depends on the HTTP header or the client's guess.
- **Zoom disabled:** the viewport meta sets `maximum-scale=1`, which blocks pinch-zoom (WCAG 1.4.4).
- **Focus outline removed:** the global rule `a { outline: none; }` removes keyboard focus indicators, and no replacement `:focus` style is present in the visible CSS.
- **No document language:** `<html xmlns="http://www.w3.org/1999/xhtml">` has no `lang` or `xml:lang`.
- **Layout tables:** visible tables (for example `<table width="640" …>`) have no `role="presentation"`.

## 4. Personalization & Merge Tokens
- **QA FAIL, empty greeting slot:** the greeting renders as `Hi ,`, so the first-name merge field resolved to an empty string. No fallback value is applied. The greeting is outside the truncated HTML, so only the QA data confirms it.
- **Third-party identifier:** the `krxd.net` usermatch URLs carry `partner_uid=adf27fee…189a` (a 64-hex value, apparently SHA-256 per the `…_sha25` partner label) and `partner_uid=122277199` (apparently the SFMC subscriber ID). These are rendered per recipient, so the merge worked there.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Not verifiable:** the HTML was truncated before the footer, so the unsubscribe link, physical postal address and `List-Unsubscribe`/`List-Unsubscribe-Post` headers were not available. SPF, DKIM and DMARC results were also not provided, so none of these are flagged.
- **Sender address:** `no-reply@emails.skechers.com` is the only header evidence. A Reply-To value was not provided.
- **Third-party data sharing:** the krxd usermatch pixels pass identifiers to an ad-tech partner. That is a disclosure and consent consideration, not a CAN-SPAM violation.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **UTMs unverified:** the 29 CTA/tracking links were skipped, so UTM parameters, landing URLs and destination alignment could not be checked.
- **Campaign ID:** `MKG_US_NA_U_PERFORM_PERF_EN_10052026` appears in the krxd and ink1000 pixels, but nothing confirms it matches any `utm_campaign` value on the links.
- **Preheader vs. subject:** the preheader text `Members BOGO 50% off` is in a `display:none` div. Landing-page alignment with the "Members BOGO" claim could not be tested.

## 7. Recommendations
1. Add a default to the first-name merge field, or use a name-less greeting, so `Hi ,` can't render.
2. Fix `pixel.app.returnpath.net/pixel.gif?…` to `https://pixel.app.returnpath.net/pixel.gif?…`.
3. Move `ink1000.com/…/o.gif` and `image.emails.skechers.com/…/dde00662-….png` to HTTPS, and confirm the second host has a valid certificate.
4. Add `alt=""` to decorative and tracking images and meaningful `alt` to the content image `dde00662-….png`.
5. Replace the meta tags with `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` and `<meta http-equiv="X-UA-Compatible" content="IE=edge">`.
6. Drop `maximum-scale=1` from the viewport meta, restore a visible `:focus` style, and add `lang="en"` to `<html>`.
7. Add `role="presentation"` to layout tables.
8. Re-run the audit on the full HTML and headers to check unsubscribe, the postal address, `List-Unsubscribe`, SPF/DKIM/DMARC, and the UTM parameters on the 29 skipped links.
