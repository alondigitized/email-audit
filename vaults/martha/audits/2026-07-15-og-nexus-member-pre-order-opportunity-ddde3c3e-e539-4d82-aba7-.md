## What's weak

- **The preview text is a trust-destroying bug** — What showed in my inbox before I opened was raw JSON-LD schema markup. That looks like spam or a broken send, full stop.
- **Not one number anywhere** — No price, no discount, no savings. If I'm going to commit to a pre-order, I need to know what it costs before I waste my time reading.

- 1. **Fix the preheader immediately** — JSON-LD schema markup is leaking directly into the preview text field. This is the single most damaging issue in the whole send; it tanks open rate before anyone reads a word of actual copy.
- 2. **Show a price, any price** — "Member price: $XX" or "Limited edition, starting at $XX" gives me something to anchor on. A pre-order ask with no number is a dead end for a price-sensitive shopper.
- 3. **Get specific about what "member" means** — "You're getting first access before it opens to the public" beats the generic "member pre-order opportunity" every time.
- 4. **Add a secondary BTS rescue row** — One module below the hero with "Back to School deals for the kids →" would salvage the visit for Plus members like me who are in buy-for-the-kids mode right now.

## Technical Audit

## Technical Audit — Skechers OG Nexus Pre-Order Email

**From:** no-reply@emails.skechers.com | **Subject:** OG Nexus member pre-order opportunity!

---

### 1. Technical Summary

The email is structurally sound and renders correctly across breakpoints, but has two systemic infrastructure issues: all image assets are served over HTTP instead of HTTPS, and a third-party tracking pixel (`ink1000.com`) is also HTTP-only. Both will cause asset blocking in modern email clients (Gmail, Apple Mail) that enforce mixed-content policies.

---

### 2. Link & Tracking Issues

**Tracking pixels — mixed protocols:**
- Open pixel via `click.emails.skechers.com` (HTTPS) — OK
- Open pixel via `http://www.ink1000.com/p/up/...` — **HTTP, will be blocked**
- Two Krux/Salesforce DMP usermatch beacons (`beacon.krxd.net`) — HTTPS, OK
- Return Path seed pixel (`pixel.app.returnpath.net`) — **missing protocol prefix entirely** (`pixel.app.returnpath.net/pixel.gif...` with no `http://` or `https://`), which will cause a broken relative URL in most clients

**25 click-redirect links** all route through `click.emails.skechers.com` — standard ESP tracking, no issues beyond the expected redirect chain.

---

### 3. Rendering & Accessibility

**HTTP image sources (all from `image.emails.skechers.com`):**

Every image in the email body is served over HTTP. Gmail and Apple Mail 16+ block non-HTTPS image sources:

|---|---|

| Hero/product image | `http://image.emails.skechers.com/.../49468f73-....png` |

`image.emails.skechers.com` almost certainly supports HTTPS — this is a CDN configuration issue, not a missing certificate. All `src` values should use `https://`.

**Missing alt text:**
- `o.gif` (ink1000 tracking pixel) — no `alt=""` attribute; minor but technically non-conformant
- `49468f73-....png` (appears to be a content image, not a spacer) — missing alt text; screen readers will skip it

**Viewport meta tag malformed:**
```html
<meta content="text/html; charset=utf-8" />
<meta content="IE=Edge" />
```
Both tags are missing the `http-equiv` attribute. The charset declaration should be `<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />` and the IE compat tag `<meta http-equiv="X-UA-Compatible" content="IE=Edge" />`. These won't break modern clients but are malformed per spec and may affect Outlook rendering.

**`-webkit-text-size-adjust: none`** — set globally on `*`. This suppresses iOS auto-sizing entirely rather than the safer `100%` value, which can make small text unreadable on mobile without pinch-zoom.

### 4. Personalization & Merge Tokens

No unresolved merge tokens visible in the truncated source. The campaign ID `MKG_US_NA_U_PREORDER_LOYL_EN_07152026` embedded in the Krux pixel and ink1000 pixel correctly reflects today's date (2026-07-15) and the loyalty segment (`LOYL`).

The subscriber ID in the Krux pixel (`partner_uid=122277199`) is a raw numeric ID rather than a hashed value — the adjacent `sfmc_100007688_sha25` beacon suggests SHA-256 hashing is used elsewhere. Confirm this ID is not a plaintext PII identifier before sending at scale.

### 5. Compliance

**CAN-SPAM:** Physical address and unsubscribe link not visible in the truncated source — assumed present in the footer (standard for Skechers templates). **Verify these are present before send.**

**Unsubscribe:** Not visible in truncated source. Must confirm a one-click or clearly labeled unsubscribe mechanism exists in the full footer per CAN-SPAM §5(a)(3).

**Authentication headers:** Not auditable from HTML source alone. The sending domain `emails.skechers.com` should have SPF, DKIM (selector aligned to ESP), and DMARC `p=quarantine` or higher. Recommend verifying via `dig TXT _dmarc.emails.skechers.com` before deploy.

**Preheader:** Present and correctly hidden — `"We're opening up pre-orders again just for you"`. No issues.

---

### 6. Email-to-Site Continuity

UTM parameters are not visible on click-redirect URLs in the source — they are likely appended by the ESP at send time or resolved at redirect. Confirm that all destination URLs receive at minimum:
- `utm_source=email`
- `utm_medium=email`
- `utm_campaign=MKG_US_NA_U_PREORDER_LOYL_EN_07152026`

Without these, GA4 will attribute pre-order clicks to `(direct)` or `(none)`, breaking campaign attribution for this loyalty cohort.
