# See What Everyone's Adding To Their Cart
**Score:** 7/10 · **Type:** Email audit · **2026-06-03**
## Executive summary

- Okay, so I'm scrolling my inbox during nap time and I see "See What Everyone's Adding To Their Cart" from Skechers — and honestly my first instinct is *meh*. It's a classic social-proof hook but it's also the vaguest possible way to tease a shopping email. What is everyone adding? Kids stuff? Women's sneakers? Dress shoes for my husband I did not ask about? I genuinely don't know until I open it.
- Then I actually open it and the BOGO banner snaps everything into focus — okay, there's a real offer here. But the hero is a young guy sitting on the floor in sneakers, and the whole upper half of the email is basically "Best Sellers for dudes." The Women's section shows one lonely beige sneaker and then we're into Men's. My kids — who are the main reason I'm even in the Skechers app right now — don't show up above the fold at all. "KIDS" appears as a tiny text link buried in the "Shop Additional Styles" row near the bottom. That's it.
- What really killed me though was the preview text. It wasn't even readable copy — it looked like a string of technical garbage in my inbox. Something about `@context schema.org` — like someone accidentally shipped the email's JSON schema data as the preheader. Not a great first impression. I'll mark it as read without clicking, but I'm not going to forward this one to anyone.

## What's working

- **BOGO 50% banner is the first thing my eye lands on** — clear offer, clear action, exactly where it should be.
- **"SHOP WOMEN'S BEST SELLERS" CTA** — specific enough to tell me where I'd land, not just a generic homepage dump.
- **Visual layout is clean** — no broken images, no overlapping text, the sections stack logically on mobile.
- **Consistent with the current campaign** — the BOGO deal has been running all week; it feels like a real promo, not a one-day surprise.

## What's weak

- **The hero is a young man** — as a mom shopping for my kids and occasionally for myself, a male-dominated hero sends me the wrong signal about whether this email was sent for me.
- **Zero kids visibility above the fold** — "KIDS" is a text link in the footer area. For someone whose primary reason to open Skechers emails is a 5-year-old and a 9-year-old, this is a miss.
- **The preview text is broken** — what rendered in my inbox was raw JSON schema data (`@context`, `@type`, `Organization`). That's a technical snafu that makes the whole send look sloppy before I even get inside.
- **No personalization, no points, no Plus badge** — after the June 1st "Hi Martha" + points balance email, this one feels like I'm a stranger again. That regression is noticeable.
- **Cadence fatigue is real** — this is the seventh email in about six days. The BOGO well is running dry; I've seen this offer so many times this week it's stopped feeling urgent.

## Recommendations

- 1. **Fix the preheader immediately** — the leaked JSON schema data in the preview is an operational bug that should be patched before the next send. A real preheader like "BOGO 50% — your best sellers, now on sale" would replace broken text and give the subject line a proper partner in the inbox.
- 2. **Add a kids row above the 25% apparel section** — even one row showing a light-up sneaker for girls and a durable lace-up for boys would speak directly to the segment most likely clicking from family-oriented accounts.
- 3. **Make the social-proof subject line do more work** — "See What Everyone's Adding" promises crowd wisdom but doesn't deliver a hint of category or offer. Tie it to the deal.
- 4. **Restore the Plus personalization from the June 1st email** — "Hi Martha" + visible point balance made me feel like a known customer. This one treated me like a cold prospect.
- **Subject Alt A:** `Best Sellers + BOGO 50% — see what's trending`
- **Subject Alt B:** `What families are buying this week (BOGO inside)`
- **Preheader Alt A:** `Buy one, get one 50% off — women's, kids', and men's top picks`
- **Preheader Alt B:** `Your favorite comfort styles are on sale — shop the list`

## Technical Audit

## Technical Audit — Skechers "See What Everyone's Adding To Their Cart" (2026-06-03)

---

### 1. Technical Summary

One confirmed broken-experience bug (empty personalization token in greeting) and a systemic HTTP image-hosting issue affecting 10+ assets across `image.emails.skechers.com`. All other categories are clean.

---

### 2. Link & Tracking Issues

**No broken destination links found.** 26 click-redirect links were skipped from HTTP probing (expected — all route through `click.emails.skechers.com`).

Three distinct tracking pixels fire on open:
- `click.emails.skechers.com/open.aspx` — Salesforce Marketing Cloud open beacon
- `beacon.krxd.net/1x1_usermatch.gif` — Krux/Salesforce DMP user-match (fires twice: SHA-256 hash + raw subscriber ID `122277199`)
- `pixel.app.returnpath.net/pixel.gif` — Validity/Return Path inbox monitoring

No issues with the tracking infrastructure itself, but see §3 for the HTTP pixel below.

---

### 3. Rendering & Accessibility

**[FAIL] HTTP image sources — blocked by major clients**

10 images are served over plain `http://` from `image.emails.skechers.com`. Gmail, Apple Mail, and Outlook all block or proxy-strip non-HTTPS image sources. Affected assets:

| Asset | Impact |
|---|---|
| `dde00662…` (Skechers logo) | Logo may not render |
| `49468f73…` (unlabeled) | Missing alt → silent blank |
| `0ec56c9f…` (App Store badge) | CTA broken |
| `9bb508d0…` (Google Play badge) | CTA broken |
| `00100b23…` (Curbside Pickup) | Feature callout broken |
| `07cb60b5…` (AfterPay) | Payment option invisible |
| `fc08601a…` (Find A Store) | Store CTA broken |
| `b782e0aa…`, `a5c4cae0…`, `8c5738fc…` | Social icons broken |

Additionally, the ink1000 open pixel fires over HTTP:
```
http://www.ink1000.com/p/up/7076d8b15a776085/o.gif
```
This pixel has no `alt` attribute — both issues combined mean it contributes nothing in image-blocked clients.

**Missing alt text** confirmed on two images: `o.gif` (ink1000 pixel) and `49468f73-4651-4af3-8db486.png`. The logo and social/badge images do have alt text set correctly.

**Responsive CSS** uses two near-duplicate `@media` blocks (max-width 375px and 640px) with identical rules — minor dead weight but no rendering defect.

---

### 4. Personalization & Merge Tokens

**[FAIL] Empty greeting name — broken experience**

QA detected an unresolved merge token producing a rendered output of `"Hi ,"` (name field blank). This is a data-binding failure at send time — the subscriber record either had a null first-name field or the fallback default value was not configured in the template.

Evidence: QA flag `Empty greeting slot: Greeting has empty name field (e.g. "Hi ,")` — confirmed as the sole broken-experience issue.

No other unrendered token syntax (`%%`, `{{`, `*|`) visible in the truncated HTML.

---

### 5. Compliance (CAN-SPAM, Unsubscribe, Authentication)

**No issues found** in the areas visible from the HTML. The preheader/hidden div is structurally present. Full compliance elements (physical mailing address, unsubscribe link) are expected in the footer which was truncated — these were not flagged by QA, so assumed present.

Authentication headers (SPF, DKIM, DMARC) are not verifiable from HTML source alone; no anomalies surfaced in QA data.

---

### 6. Email-to-Site Continuity (UTM Params, Landing Page Alignment)

**No issues found.** All destination links route through `click.emails.skechers.com`, which should carry UTM parameters and campaign attribution. The campaign ID `MKG_US_NONPURCLICK_U_BEST_NONPURCH_EN_06032026` is consistent across the Krux impression pixel and the ink1000 pixel — attribution chain is coherent.

---

### 7. Recommendations

| Priority | Action |
|---|---|
| **P0** | Fix null first-name fallback. Set a default value (e.g., `"Valued Member"`) in the SFMC template so `Hi ,` never renders. |
| **P0** | Migrate all `image.emails.skechers.com` assets to HTTPS. Every HTTP `src` is a rendering failure in Gmail/Apple Mail. This is a systemic CDN config issue, not a per-email fix. |
| **P1** | Add `alt=""` to `49468f73…` image and the ink1000 pixel. The pixel correctly takes `alt=""` (empty); the content image needs a descriptive value. |
| **P2** | Evaluate whether the ink1000 secondary open pixel adds signal not already covered by the SFMC beacon. If redundant, remove to reduce HTTP risk surface. |
