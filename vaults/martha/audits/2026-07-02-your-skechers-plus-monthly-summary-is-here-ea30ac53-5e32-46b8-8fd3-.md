## What's weak

- The "We picked these just for you" product recs are four pairs of adult women's sneakers. I shop for a 5-year-old and a 9-year-old first — where are the kids' picks tied to my actual purchase history?

- That preview text JSON disaster: this is the fifth consecutive send where I've seen this exact bug. I'm a loyal member and at this point it signals nobody's QA-ing these emails. It's eroding trust.

- 1. **Fix the preheader — for real, this time.** Five broken preview texts in a row. Whatever the schema.org JSON injection is, kill it. This is the single highest-leverage fix and it costs nothing to ship.

- 3. **Add a soft deadline to the reward.** "Your $5 is waiting — use it before July 31" turns passive notification into action.
- 4. **Replace "Points Earned: 0 / Points Spent: 0" with forward momentum.** Something like "Earn 200 more points this month to unlock your next reward" reframes zeros as opportunity, not inactivity.

## Technical Audit

## Technical Audit — Skechers Plus Monthly Summary (TRG_US_EN_MONTHLYSUMMARY_1_06302026)

---

### 1. Technical Summary

The email is structurally sound for a legacy table-based layout but ships with one production-critical asset served from a dev subdomain, a broken tracking pixel (missing protocol), and a wide pattern of HTTP image URLs that will leak subscriber identifiers unencrypted.

---

### 2. Link & Tracking Issues

**[CRITICAL] Return Path pixel missing protocol**
```html
<img src="pixel.app.returnpath.net/pixel.gif?r=964ce1dbf0dcef79cbad82c12fe25342701e4499" .../>
```
No `http://` or `https://` prefix. This is a relative URL pointing nowhere — the pixel will not fire, meaning Validity/Return Path inbox monitoring gets no signal for this send.

**[WARN] 24 click-redirect links unverifiable**
All CTAs route through `click.emails.skechers.com`. UTM parameter passthrough to `skechers.com` landing pages could not be confirmed from the source alone (HTML truncated). Should be spot-checked post-send against GA4 acquisition data.

**[INFO] Three separate tracking pixel vendors in one send**
- `click.emails.skechers.com` (SFMC open pixel)
- `beacon.krxd.net` (Salesforce Audience Studio / Krux — two variants: SHA-256 hashed UID + raw subscriber ID `122277199`)
- `http://www.ink1000.com` (Epsilon/Conversant DMP)
- `pixel.app.returnpath.net` (broken, see above)

The Krux `partner_uid=122277199` beacon passes a plaintext subscriber ID over HTTP — see section 3.

---

### 3. Rendering & Accessibility

**[CRITICAL] Dev-environment image domain in production send**
```
https://image.devemails.skechers.com/lib/fe33157075640674761d74/m/1/summary-tier-blue-angle.png
```
The subdomain `devemails` (vs. `emails`) is a staging asset host. This image may 404 or render a test placeholder for all recipients. Every other image uses `image.emails.skechers.com`.

**[HIGH] 12 images served over HTTP**
Affected assets include the Skechers logo, tier badge, app store badges, social icons, and the Epsilon DMP beacon. Example:
```
http://image.emails.skechers.com/lib/fe3115707564047a731c78/m/1/dde00662-169f-447d-b0e2-fc65f6c2290c.png
```
Gmail web and Outlook.com proxy images through their own HTTPS CDNs, so rendering is usually preserved — but the original HTTP request still fires, transmitting the subscriber token unencrypted before proxying. Apple Mail on iOS/macOS will silently block non-proxied HTTP requests since Mail Privacy Protection.

**[MEDIUM] `@import` inside a `<style>` block in the email body**
```css
@import url('https://fonts.googleapis.com/css2?family=Mulish:wght@400;700;900&display=swap');
```
This appears inside a `<style>` tag within a `<td>` — not in `<head>`. `@import` is stripped by Gmail, Outlook.com, and most webmail clients. Recipients in those clients will fall back to system fonts, which may break the tier-status layout if it relies on Mulish metrics.

**[MEDIUM] `-webkit-text-size-adjust: none` applied globally**
```css
* { -webkit-text-size-adjust: none; ... }
```
Universal `*` selector blocks user-initiated text scaling in all WebKit email clients (Apple Mail, Samsung Mail). WCAG 1.4.4 failure for users who need larger text.

**[LOW] Missing alt text on 4 images**
- `o.gif` (Epsilon beacon — alt="" acceptable for tracking pixels)
- `summary-tier-blue-angle.png` (tier badge — should have descriptive alt)
- `49468f73...png` (unknown content — no alt)
- Skechers logo has alt="Skechers" (correct)

**[LOW] Duplicate media query blocks**
The 375px and 640px breakpoints define identical rule sets twice (once in the first `<style>` block, once duplicated). Adds ~1.5 KB to payload with no rendering benefit. The 480px block in a second `<style>` tag partially overlaps the 640px rules.

**[LOW] Malformed charset meta tag**
```html
<meta content="text/html; charset=utf-8" />
```
Missing `http-equiv="Content-Type"`. Should be:
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
```
Without `http-equiv`, some legacy clients (Lotus Notes, older Outlook) may not honor the charset declaration.

### 6. Email-to-Site Continuity
