## Technical Audit

## 1. Technical Summary
The email uses a standard SFMC/ExactTarget-style responsive table layout with correct mobile breakpoints, but ships several tracking/open pixels over plain HTTP and two images with missing `alt` attributes.

## 2. Link & Tracking Issues
- 32 tracking/click-redirect links were skipped by the automated HTTP probe (expected behavior for redirect domains like `click.emails.skechers.com`) — not independently verified as live.
- Open-tracking pixel: `https://click.emails.skechers.com/open.aspx?...&d=100226&bmt=0` — HTTPS, fine.
- Third-party beacons present: `beacon.krxd.net` (Salesforce DMP/Krux) fires 3x — 2 user-match pixels + 1 ad-impression pixel (`campaignid=MKG_US_NONPUR_U_MULTI_ENGAGEDL30D_EN_08242026`), plus a `pixel.app.returnpath.net` deliverability pixel (missing scheme — `src="pixel.app.returnpath.net/..."` is a protocol-relative-looking but actually schema-less URL; will likely fail to load in most clients since it's not prefixed with `//` or `https://`).
- Secondary open/measurement pixel: `http://www.ink1000.com/p/up/7076d8b15a776085/o.gif?...` — plain HTTP (flagged by QA), no `alt`, likely blocked by default image-blocking in Outlook/Gmail, which will undercount opens from that vendor.

## 3. Rendering & Accessibility
- Media queries are duplicated (max-width:375px and 640px blocks are identical) — harmless but redundant; no functional bug.
- Mobile/desktop content toggle (`.mobile-content` / `.desktop-content` via `min-width:768px`) is implemented correctly with `!important` overrides.
- QA-confirmed accessibility issues:
  - Missing `alt` text: `o.gif` (ink1000 pixel) and `49468f73-4651-4af3-bea2-61d1ae5db486.png` (a content image, not a 1x1 pixel — this one matters for screen readers).
  - 9 images served over `http://` instead of `https://` (main Skechers logo, hero/content image, app store badges, curbside/AfterPay/store-locator icons, social icons). QA correctly flags these as likely to be blocked by mail clients that enforce HTTPS-only image loading (Outlook, some Gmail configs), causing broken/missing images for recipients.

No CTA/product links or their UTM parameters are visible in the truncated HTML, so email-to-landing-page UTM alignment cannot be verified from the provided source.

## 7. Recommendations

4. Provide full (non-truncated) HTML for the footer/unsubscribe block and CTA links in a follow-up pass to complete the Compliance and Email-to-Site Continuity sections.
