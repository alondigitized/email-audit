### 1. Technical Summary

Standard XHTML 1.0 Transitional welcome email with three responsive breakpoints. Two infrastructure-level issues require remediation: insecure font asset URLs and a CSS cascade ordering bug affecting narrow-viewport layouts.

---

### 3. Rendering & Accessibility

**[HIGH] Insecure HTTP font URLs**
Both `@font-face` declarations load assets over `http://`, not `https://`:
```
http://vafloc01.s3.amazonaws.com/WBStatic/site1101240/public/fonts/Loew/Loew_Black/Loew-Black-no_hints.otf
http://vafloc01.s3.amazonaws.com/WBStatic/site1101240/public/fonts/Loew/Loew/Loew-Regular-no_hints.otf
```
Gmail, Outlook.com, and Apple Mail all enforce HTTPS for remote resources. These assets will silently fail to load in most modern clients; fallback to `Arial, sans-serif` will trigger. Fix: serve from HTTPS (S3 bucket policy or CloudFront).

**[MEDIUM] CSS cascade ordering bug — `.mobile3` width conflict**
The `416px` breakpoint sets `.mobile3 { width: 207px }`, but the `500px` breakpoint (which appears *later* in the stylesheet) sets `.mobile3 { width: 374px }`. Since both breakpoints apply to screens ≤416px, and CSS cascade order wins, the `500px` rule overrides the `416px` rule on the narrowest phones. The 207px intent is never realized. The `500px` block should be ordered before the `416px` block in source.

**[LOW] Dead `@-moz-document` blocks**
Two empty Mozilla-specific blocks with no rules:
```css
@-moz-document url-prefix() { }
@-moz-document { }
```
These are deprecated in Firefox 61+ (CVE-based removal) and have no effect. Safe to remove.

**[LOW] `@font-face` in email has ~15% client support**
Custom fonts render only in Apple Mail and iOS Mail. The Arial fallback will fire in Gmail, Outlook, Yahoo, and most webmail. Not a bug, but worth flagging if Loew is brand-critical.

**[INFO] `img { display: block }` is correctly set** — prevents phantom spacing gaps in Gmail. No issue.
