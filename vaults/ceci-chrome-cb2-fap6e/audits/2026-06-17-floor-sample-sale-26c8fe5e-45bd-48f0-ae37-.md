# FLOOR SAMPLE SALE
**Score:** 7/10 · **Type:** Email audit · **2026-06-17**
## Executive summary

- CB2 is leading with the Floor Sample Sale — a concept that sounds appealing but lands as hollow in execution. There is no discount percentage in the hero. "Floor sample sale" without a specific number is marketing shorthand the brand understands but a casual subscriber does not. You're being asked to drive to a store to discover the price. That is a 2003 print-ad strategy in a 2026 email.
- Compounding that, CB2 has already sent an email today (the "NEW ITEMS ADDED: Warehouse Sale" at 8/10). This second send on the same day stacks three active sale modules — Floor Sample, Design Legends, Warehouse — into one scroll. The brand is not curating; it's carpet-bombing. The render is clean and the visual template is solid, but the strategic discipline is gone.
- The most damning detail: the hero CTA is "FIND A STORE," which sends a digitally-engaged email subscriber to a store locator. That is real friction, not theoretical. The Warehouse Sale at 60% off buried two modules down is the strongest actual offer in this email.

## What's working

- Hero photography is strong — the warm, textured living room image earns the full-width treatment and creates immediate lifestyle pull.
- Visual hierarchy is correct: Floor Sample Sale dominates, the sub-modules stack cleanly below without competing for the same visual weight.
- "ENDS TONIGHT!" on the Design Legends module adds genuine urgency and gives a reason to act now.
- "EARN 10% BACK" loyalty callout near the bottom is a smart retention nudge for members scrolling past the sale sections.
- The "MORE FOR YOU" personalized product grid at the bottom gives online shoppers something clickable beyond store locators.

## What's weak

- No discount percentage on the hero Floor Sample Sale — the offer is vague and requires a store visit to evaluate.
- "FIND A STORE" as the primary CTA is a dead end for anyone intending to shop online, which is the majority of email openers.
- Three competing sale modules in one email (Floor Sample + Design Legends + Warehouse) dilutes all three; the Warehouse Sale at 60% off deserved its own moment.
- "LEAVE US A REVIEW, WIN $5000" inserted between the sale modules and the product grid is jarring — it breaks the shopping flow with an unrelated sweepstakes ask.
- Same-day second email (Warehouse Sale was already sent today) pushes cadence into fatigue territory; this send will cannibalize opens and unsubscribes from the earlier one.

## Recommendations

- 1. **Put the discount in the hero.** "Floor Samples: 30–70% Off In-Store" is a concrete offer. The current "FLOOR SAMPLE SALE" headline says nothing a subscriber couldn't infer — add the number or don't send the email.
- 2. **Kill two of the three sale modules.** If this is a Floor Sample email, own it. Link Design Legends and Warehouse to a single "More Savings" link at the footer — not two full hero modules that compete with your lead story.
- 3. **Replace "FIND A STORE" with a "Preview Floor Samples Online" or "Shop Available In-Store Items" CTA** that at minimum bridges the journey. If the inventory isn't browsable online, that is a website problem worth solving before the next in-store send.
- 4. **Move "LEAVE US A REVIEW" to a dedicated post-purchase flow**, not mid-sale email.
- 5. Flip the module order: Warehouse Sale (60% off) should be the secondary module hero, not buried third after a vague in-store offer.
- **Subject Alt A:** `Floor samples: up to X% off in-store this week`
- **Subject Alt B:** `In-store only: Floor Sample Sale starts today`
- **Preheader Alt A:** `Deep cuts on one-of-a-kind display pieces — find your store.`
- **Preheader Alt B:** `Sofas, chairs, lighting — one price, in store only.`

### 3. Rendering & Accessibility

**`maximum-scale=1` disables pinch-to-zoom (WCAG 1.4.4 violation):**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Remove `maximum-scale=1`. It prevents low-vision users from zooming on mobile.

**Overly aggressive `line-height` reset:**
```css
* { line-height: 100% }
```
Applied to every element globally. Multi-line text (especially in buttons and footers) can collapse or clip across Gmail, Apple Mail, and Outlook. Use targeted selectors instead.

**Mobile breakpoint is too narrow:**
```css
@media only screen and (max-width: 418px) { .mobile { width: 414px !important; } }
```
iPhone 15 Pro is 393 logical px wide; most Android flagships are 360–412px. A breakpoint at 418px is borderline and will miss a significant share of devices. Standard email practice is `max-width: 600px` for the responsive pivot.

**Conflicting desktop media queries:**
```css
@media only screen and (min-width: 690px) { img { max-width: 690px } }
@media only screen and (min-width: 768px) { img { max-width: 100% !important } }
```
Screens 690–767px get `max-width: 690px`; screens 768px+ get `100%`. This is probably intentional for a 690px container, but the 768px rule silently overrides it for large-viewport clients and could cause images to stretch beyond the container.

**Unfilled developer placeholder comment left in production HTML:**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
This is template residue (note also the typo: "IMPUT" instead of "INPUT"). It has no rendering impact but confirms the template was not fully sanitized before send.

**No `role="presentation"` on layout tables** — minor, but screen readers will announce them as data tables. Standard practice for email is to add `role="presentation"` to all structural `<table>` elements.

### 6. Email-to-Site Continuity

**Cannot confirm UTM coverage** — links are not present in the truncated source. Verify:
- All CTA links include `utm_source=email&utm_medium=email&utm_campaign=floor-sample-sale` (or equivalent)
- No raw tracking redirect URLs resolve to 404s or redirect to a homepage instead of the sale landing page

**Font cross-origin dependency:** Body fonts are loaded from both `https://www.cb2.com/` and `https://www.crateandbarrel.com/`. A Crate & Barrel CDN outage or CORS policy change would silently break CB2 email typography. This is a structural fragility, not an active breakage.

**Double-slash in font URLs:**
```css
src: url("https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2")
```
Multiple occurrences. Double slashes are normalized by servers but indicate copy-paste errors in the template and should be cleaned up.

**Duplicate `@font-face` declarations for the same family:**
Three separate `@font-face` blocks declare `font-family: "Lineto Brown Sub"` — one for the base, one for `font-weight: 400`, one for `font-weight: 600`. This is functionally redundant (the base declaration already loads both weights) and adds unnecessary HTTP requests on clients that render webfonts (Apple Mail, some iOS clients).
