### 3. Rendering & Accessibility

**Unfired template placeholder left in deployed HTML:**
```html

```
This comment is visible in raw source with a typo (`IMPUT` → `INPUT`). It signals the template was not fully cleaned before send. No rendering impact, but indicates a broken pre-send QA step.

**Duplicate `@font-face` declarations for `"Lineto Brown Sub"`** — three separate blocks declare the same `font-family` name with overlapping weight/format combinations. Only the last matched rule wins per spec; the earlier two `woff`/`eot` declarations for weights 400 and 600 are effectively overridden. This wastes bytes and creates ambiguity if weights are ever reordered.

**Non-standard mobile breakpoint:**
```css
@media only screen and (max-width: 418px) { .mobile { width: 414px !important; } }
```
Breakpoint fires at 418px but sets a hard-coded 414px width (iPhone SE/6/7/8 physical width). Devices between 418–480px wide get neither the mobile nor desktop layout cleanly. Industry standard breakpoint is 480px or 600px.

**`max-width` conflict in responsive rules:**
```css
@media only screen and (min-width: 768px) { img { max-width: 100% !important } }
@media only screen and (min-width: 690px) { img { max-width: 690px } }
```
Both rules fire on screens ≥ 768px. The `100% !important` in the 768px block overrides the 690px cap, making the 690px rule partially dead. Depending on container width, images could exceed 690px on wide desktop clients.
