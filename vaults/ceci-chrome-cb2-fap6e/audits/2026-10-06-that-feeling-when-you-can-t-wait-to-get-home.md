## Technical Audit

## 1. Technical Summary
The email's markup is mostly sound, with `lang="en"`, a doctype and MSO conditional fallbacks. The QA run (57% pass, 0 errors, 3 warnings) can't verify authentication or one-click unsubscribe, because AgentMail stripped the headers. It also flagged 29 images without alt attributes and skipped all 66 tracked links.

## 2. Link & Tracking Issues
- **Unverified links:** 66 links were skipped because they use click-redirect domains. The QA data doesn't confirm that any destination resolves, so link health is unknown.
- **Third-party pixels:** `https://sr.rlcdn.com/448796.gif?s=56aaa278…cfd8&n=1` through `n=5` is five sequential LiveRamp pixel calls. The same 64-character identifier (`56aaa2787a67…`) appears as `mi_u=` on `mi.crateandbarrel.com` assets and in the `s=` parameter on the third-party `rlcdn.com` pixels. This means the per-recipient identifier is shared with a third party. I can't confirm what it hashes from the truncated source. If it is derived from the email address, that is a privacy exposure.
- **First-party pixels:** `mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif` is an open pixel. `dv.crateandbarrel.com/o/c871d02b-…?mi_cid=…&mi_mid=…` is another tracker. Both are normal for the platform, but they add to the roughly seven tracking images and make open rates unreliable.
- **Possibly stale asset:** the hero GIF path `scene7.com/is/content/Crate/00_Email/2026/07_July/2026_0716_CB_BrandAnthem/…` is dated July, in an October send. The asset loads, but it suggests a reused or non-templated path.

## 3. Rendering & Accessibility
- **Missing alt text, content images:** 29 images lack alt attributes. Examples:
  - `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/*.jpg`, 12 images.
  - `m/47/bbf6f9d4-…png`.
  - The Scene7 `…BrandAnthem_02.gif`.
  - `mi.crateandbarrel.com/p/rp/*.png`, 7 images that appear to be dynamic recommendation tiles.

  If these carry content or links, screen-reader and images-off users get nothing.
- **Missing alt text, tracking pixels:** the `rlcdn.com` GIFs, `o.gif` and the `dv.` tracker should carry `alt=""`. The attribute is absent, and the data doesn't show whether it is empty or missing.
- **Zoom blocked:** `<meta name="viewport" … maximum-scale=1>` prevents pinch-zoom. This is a WCAG 1.4.4 concern.
- **Text sizing:** `body { -webkit-text-size-adjust:none }` and `*{-webkit-text-size-adjust:none}` override the earlier `100%` declarations, which disables text-size scaling in WebKit.
- **Invalid markup:**
  - `<title>Crate & Barrel</title>` has an unescaped `&` under the XHTML 1.0 doctype.
  - `<meta charset>` is duplicated alongside the `http-equiv` charset.
  - `format-detection` is declared three separate times.
  - The template placeholder comment `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->` was left in production.
- **CSS conflict:** `@media (min-width:768px) { img {max-width:600px} }` and `@media (min-width:640px) { img {max-width:640px} }` overlap. The later rule wins, so the 600px cap never applies.
- **Narrow breakpoint:** the mobile breakpoint is 460px, so wide phones and small tablets get the desktop layout. This is observed from the CSS, not tested.

## 4. Personalization & Merge Tokens
No issues found. The captured HTML shows no unrendered merge tokens such as `%%…%%`, `{{…}}` or `[FIRST_NAME]`. The source is truncated, so the rest is unchecked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` not found [WARN]:** the QA note says the relay may not capture it. The data can't confirm whether the sender included it.
- **`List-Unsubscribe-Post` not found [WARN]:** this is the RFC 8058 header. Gmail and Yahoo bulk-sender rules require one-click unsubscribe for senders of this volume, so it needs checking against the raw message.
- **`Authentication-Results` not found [WARN]:** SPF, DKIM and DMARC status is unknown. The From domain is `mail.crateandbarrel.com`, so alignment can't be assessed.
- **Footer unsubscribe link and postal address:** both are beyond the truncated HTML, so I can't verify them. I'm not flagging either as a failure.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not verifiable. All 66 links were skipped as redirect or tracking links, and the QA data has no resolved destinations or UTM parameters. The only parameters visible are the platform's own (`mi_u`, `mi_cid`, `mi_mid`). I found no evidence of a problem and none of correct tagging.

## 7. Recommendations
1. Run a header check on the raw message, not the relay copy. Confirm `List-Unsubscribe`, `List-Unsubscribe-Post: List-Unsubscribe=One-Click`, and SPF/DKIM/DMARC alignment for `mail.crateandbarrel.com`.
2. Add descriptive `alt` text to the 22 content and recommendation images. Add `alt=""` to the 7 tracking pixels.
3. Remove `maximum-scale=1`, and drop the `-webkit-text-size-adjust:none` overrides.
4. Audit what identifier `mi_u` and the `rlcdn.com` `s=` parameter carry, and whether sharing it with LiveRamp is covered by the privacy policy.
5. Clean up the template: escape `&` in `<title>`, remove the duplicate meta tags and the `IMPUT HERE` comment, and fix the overlapping `img` max-width media queries.
6. In the next QA pass, resolve redirect chains for a sample of the 66 links to confirm landing URLs and UTM tagging. Capture the full HTML so the footer can be checked.
