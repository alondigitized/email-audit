### 3. Rendering & Accessibility

**[CONFIRMED — HIGH]** `maximum-scale=1` in the viewport meta tag:
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Disables pinch-to-zoom for mobile users. Violates WCAG 1.4.4 (Resize Text, AA). Remove `maximum-scale=1`.

**[CONFIRMED — MEDIUM]** `<title>` tag contains wrong brand name:
```html
<title>Crate & Barrel</title>
```
Sender is "Crate & Kids." Template was not rebranded. This surfaces in some email clients as the document title and in screen reader announcements.

**[CONFIRMED — MEDIUM]** Global `*` selector applies `line-height: 100%` to every element:
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; max-height:1000000px; mso-line-height-rule:exactly; line-height: 100%}
```
This overrides any per-element line-height, collapsing text spacing on multiline headings and body copy across clients that honor it.

**[CONFIRMED — MEDIUM]** Conflicting `img` `max-width` media queries with overlapping breakpoints:
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
The 768px rule is declared first; the 640px rule is declared second and cascades over it for all viewports ≥640px, including ≥768px. Effective result: `max-width: 640px` everywhere ≥640px — the 600px desktop cap is silently overridden. Rule order should be reversed, or collapse into a single rule.

**[CONFIRMED — LOW]** No dark mode handling. Both color-scheme meta tags are light-only:
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Clients that force dark mode (Apple Mail, Outlook 2021+) may invert or recolor elements unpredictably with no fallback styles.

**[CONFIRMED — LOW]** Developer placeholder comment left in production:
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
"IMPUT" is also a typo. No font import follows. If no custom font is used, remove the comment. If one is intended, it is missing.

**[CONFIRMED — LOW]** Duplicate meta declarations:
- `format-detection` appears 4 times (once combined, then three separate single-attribute versions)
- `charset` is declared twice (`http-equiv="Content-Type"` + standalone `<meta charset="utf-8">`)

No rendering impact, but inflates HEAD size unnecessarily.
