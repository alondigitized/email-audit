### 3. Rendering & Accessibility

**Issue 1 — Conflicting `img` max-width media queries (CSS cascade bug)**
Two desktop media queries target `img` max-width in reverse specificity order:

```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }  /* declared first */
@media only screen and (min-width: 640px) { img { max-width: 640px } }  /* declared second — wins */
```

At viewports ≥768px, both rules match. The 640px rule appears later in the stylesheet and overrides the 768px rule, so `max-width: 640px` always wins on desktop. The 600px constraint for the larger breakpoint is effectively dead. Likely unintended; the rules should be in ascending breakpoint order, or consolidated.

**Issue 2 — `maximum-scale=1` blocks user zoom (WCAG 1.4.4)**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

Prevents pinch-to-zoom on mobile. Violates WCAG 1.4.4 (Resize Text, Level AA) and is flagged by Apple/Google accessibility audits.

**Issue 3 — Dark mode explicitly disabled**

```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```

Forces light-only rendering. On clients that honor this (Apple Mail, iOS Mail), the email will not adapt to dark mode. With ~35–50% of opens on iOS/macOS Mail where dark mode prevalence is high, this risks a harsh white background blasting in a dark-mode context rather than a graceful degradation.

**Issue 4 — Duplicate `format-detection` meta tags**

The following meta appears four times total:
- Combined declaration: `content="telephone=no,address=no,email=no,date=no,url=no"`
- Then three individual overrides for `date=no`, `address=no`, `telephone=no`

Redundant and bloats `<head>` size. The combined declaration is sufficient; the individual duplicates can be removed.

**Issue 5 — Duplicate charset declaration**

```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta charset="utf-8">
```

Both are present. Harmless but redundant. Only the `http-equiv` form is needed for XHTML Transitional.
