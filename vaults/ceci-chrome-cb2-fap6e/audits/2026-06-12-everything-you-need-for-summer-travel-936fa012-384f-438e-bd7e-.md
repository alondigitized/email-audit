### 3. Rendering & Accessibility

**[CONFIRMED] Title tag brand mismatch**
```html
<title>Crate & Barrel</title>
```
Sending entity is `Crate & Kids`. Some email clients surface `<title>` as the tab label or in screen reader announcements. Should read `Crate & Kids`.

**[CONFIRMED] Conflicting desktop `img` max-width media queries**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
The 640px query appears **after** the 768px query in source order. At viewports ≥768px both rules apply; the later declaration wins (`max-width: 640px`), rendering the 768px rule dead code. Net effect: images cap at 640px across all desktop widths. Either reorder or consolidate into a single rule.

**[CONFIRMED] `maximum-scale=1` blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from zooming on mobile — a WCAG 1.4.4 failure. Remove `maximum-scale=1`.

**[CONFIRMED] `*{ -webkit-text-size-adjust: none }` — universal selector**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```
Applying to all elements (not just `body`) is overly aggressive and can break text scaling in WebKit when a user has system accessibility font-size preferences. Scope to `body` only.

**[CONFIRMED] Duplicate `format-detection` meta tags**
`format-detection` appears four times: once as a combined declaration, then individually for `date`, `address`, and `telephone`. Redundant; the combined declaration suffices.

**Cannot evaluate**: `role="presentation"` on layout tables, `alt` text completeness on images — source is truncated before body content.
