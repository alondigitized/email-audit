- **No discount anchor in the hero** — the 20%-off Back-to-School Sale from 7/23 is nowhere visibly connected to this email; it reads as full-price browsing.
- **No size guide or fit callout in body** — the subject promises size guidance but the email delivers a product grid, not a size-matching tool or chart.

### 3. Rendering & Accessibility

**`maximum-scale=1` on viewport (confirmed)**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom. Violates WCAG 1.4.4 (Resize Text). Remove `maximum-scale=1`.

**Wildcard `text-size-adjust: none` (confirmed)**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
Applied to all elements via `*` selector, this overrides OS-level font scaling for users with visual impairments. Should be scoped to `body` only, and value should be `100%` not `none`.

**Conflicting desktop image breakpoints (confirmed)**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
On screens ≥768px both rules apply; the 600px cap wins (last-declared loses to specificity/cascade order here — actually the 768 rule is declared first, 640 second, so on screens ≥768px the 640px rule overrides, capping images at 640px when 600px was intended for desktop). Consolidate into a single rule or clarify intent.

**Dark mode not supported (confirmed)**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Forces light rendering in Apple Mail and iOS — no dark mode fallback defined. Low-severity but increasingly common in inboxes.
