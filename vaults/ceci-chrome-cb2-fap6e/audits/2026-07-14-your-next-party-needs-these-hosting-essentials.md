### 3. Rendering & Accessibility

**Confirmed issues:**

- **`maximum-scale=1` in viewport** prevents user-initiated zoom on mobile, a WCAG 1.4.4 (Resize Text) violation:
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
  ```

- **Conflicting `img` max-width media queries** — two `min-width` rules targeting different breakpoints will resolve unexpectedly. At ≥768px viewports, `max-width: 600px` wins (declared later, overrides the 640px rule). At 640–767px, `max-width: 640px` applies. This means desktop images are capped at 600px even when the container is 640px wide:
  ```css
  @media only screen and (min-width: 768px) { img { max-width: 600px } }  /* wins at ≥768px */
  @media only screen and (min-width: 640px) { img { max-width: 640px } }  /* only active at 640–767px */
  ```
  Intended behavior is unclear; if the container is 640px, the 600px cap produces a 40px gap.

- **Dark mode not handled** — `color-scheme: light` and `supported-color-schemes: light` force light rendering in Apple Mail and Outlook. No `@media (prefers-color-scheme: dark)` block is present. Background `#e6e7e8` set on `body` may render as near-white in forced-dark clients if overridden by the client.

- **Alt text cannot be confirmed** — source is truncated before `<img>` tags. Must verify all product images carry descriptive `alt` attributes.
