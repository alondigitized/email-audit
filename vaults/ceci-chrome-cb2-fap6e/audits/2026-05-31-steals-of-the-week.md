# STEALS OF THE WEEK
**Score:** 7/10 · **Type:** Email audit · **2026-05-31**
## Executive summary

- "STEALS OF THE WEEK" is CB2's weekly-digest format arriving on the same day as their AD100 designer house tour — making this the second CB2 email on 5/31 and the fifth in four days. The email is a grab-bag compilation: Midseason Sale, outdoor 40% off, up to 60% off on something, interior design services, a $1,000 threshold offer, and a product grid at the bottom. There's no single hero. Every section competes equally for attention, which means nothing wins.
- The execution is technically clean — CB2's minimal aesthetic holds, no render bugs, clear "SHOP NOW" buttons throughout. But creatively this is CB2running a clearance rack email in a luxury brand's clothes. The outdoor section is a straight reprise of the 5/30 "OUTDOOR IS ON SALE" send (scored 9/10 for tight execution); here it's buried as module two of six.
- The core problem: this email exists to hit a send-day cadence, not to give a subscriber a reason to click. A subscriber who opened yesterday's outdoor send, or the 5/30 design services pitch, has already seen everything here — repackaged under a vague "steals" label.

## What's working

- **CB2 aesthetic is intact.** Clean layout, consistent typography, no render bugs — the brand's minimal identity holds even in a cluttered send.
- **Multiple concrete discounts are visible.** 40% off outdoor and "up to 60% off" are explicit numbers, not soft "up to X%" teases.
- **Short subject line.** At ~18 characters, it's well within mobile truncation limits.
- **Product grid at the bottom.** The "More For You" tiles add depth for browsers who scroll — at least some section feels fresh rather than purely repetitive.

## What's weak

- **No single hero.** Six stacked modules of equal visual weight mean the eye never lands anywhere. The outdoor 40% off section that was a tight 9/10 send yesterday is now competing with five other things.
- **"SHOP NOW" everywhere.** Every CTA is identical — no differentiation by category or intent. A subscriber doesn't know what they'd be clicking into.
- **Cadence fatigue is severe.** This is the 5th send since 5/28 and the 2nd on 5/31 alone. "STEALS OF THE WEEK" lands feeling like a clearance bin email, not a curated steal.
- **Subject is all bark, no bite.** "STEALS OF THE WEEK" in ALL CAPS promises something specific and delivers nothing — no category, no percentage, no product name.
- **Design services module is out of place.** The $1,000 interior design threshold feels like a non-sequitur in a markdown email — it was already given its own dedicated send on 5/30 and doesn't belong buried in a deals digest.

## Recommendations

- 1. **Pick one steal and lead with it.** Collapse this to a tight two-module email: the single biggest percentage-off offer as the hero, one supporting product grid. The multi-module stack signals "we don't know what you want" — a single clear steal signals confidence.
- 2. **Rewrite every CTA to match the module.** "Shop Outdoor Deals" / "Shop 60% Off Lighting" / "Book a Designer" — any verb + category beats "SHOP NOW" times six.
- 3. **Cut the design services module entirely from this send.** It got its own email yesterday. Including it here in a deals digest dilutes both the deal positioning and the services positioning.
- 4. **Subject Alt A:** `Save up to 60% — this week only`
- 5. **Subject Alt B:** `Your best CB2 deal this week`
- 6. **Preheader Alt A:** `Outdoor, lighting, and more — biggest markdowns of the Midseason Sale.`
- 7. **Preheader Alt B:** `40% off the outdoor collection + up to 60% off select styles.`

### 3. Rendering & Accessibility

**[HIGH] Unstripped template placeholder in `<head>`:**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
This production artifact was not removed before send. Also contains a typo (`IMPUT` → `INPUT`). No functional breakage, but exposes internal build tooling in public source.

**[MEDIUM] Conflicting `img` max-width media queries:**
```css
@media only screen and (min-width: 768px) { img { max-width: 100% !important } }
@media only screen and (min-width: 690px) { img { max-width: 690px } }
```
At viewport widths ≥ 768px, both rules match. The second rule (690px cap) is declared after the first and carries equal specificity, so it wins — overriding the `100%` rule at all desktop widths. The `768px` block is effectively dead for `img`. Intended behavior is unclear; if images should be uncapped on wide desktop, the order or specificity needs correction.

**[MEDIUM] Mobile breakpoint at `max-width: 418px`:**
The responsive block triggers only below 418px. This misses common viewport widths (419–767px) including landscape phone and many Android devices, which receive neither desktop nor mobile styles.

**[LOW] `maximum-scale=1` in viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Suppresses user-initiated zoom on mobile. Fails WCAG 2.1 SC 1.4.4 (Resize Text). Common in email but worth flagging for accessibility posture.

**[LOW] Global text-size-adjust disabled:**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
Applied universally via the `*` selector. Disabling on `body` only is safer and less likely to cause rendering artifacts in non-email contexts.

**[LOW] Duplicate `@font-face` for "Lineto Brown Sub":**
The family is declared three separate times — once with `.eot`/`.woff2`/`.woff` sources, and twice more with individual `.woff2` files at `font-weight: 400` and `600`. The first declaration lacks weight/style descriptors, creating ambiguity in font matching. Consolidate into a single, well-described face-per-weight pattern.
