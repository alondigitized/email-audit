# Refresh their room & earn Double Rewards →
**Score:** 6/10 · **Type:** Email audit · **2026-05-22**
## Executive summary

- This is Crate & Kids' second send of the day under the misfire "Crate & Kids SALE" display name — a branding problem flagged in this morning's "Summer gear (and toys!) are here…" audit that still hasn't been fixed. The creative hook this time is a genuine departure from the week's discount drumbeat: "get upgrades in days, not weeks" leads with delivery speed rather than markdown depth, which is a smart angle for Memorial Day (last chance to receive before the holiday weekend). Double Rewards serves as the loyalty sweetener layered on top.
- The problem is execution diffusion. Below the hero, the email fans out into a dense multi-section product grid — bedding, furniture, outdoor toys, decor — that competes with itself and buries the delivery-speed story. By the time you're two scrolls in, the urgent "get it in days" framing has completely dissolved into a generic browse experience.
- Net judgement: the central idea is better than this brand's recent sends, but the "Crate & Kids SALE" sender label, undifferentiated grid below the fold, and the absence of a specific discount percentage keep it from converting that idea into results.

## What's working

- **Delivery-speed hook is fresh.** "Get upgrades in days, not weeks" is the first non-discount creative angle across all six recent sends — gives a fatigued list a real reason to re-engage.
- **Hero image earns the headline.** The styled bedroom scene is aspirational and on-brand; the room-refresh framing lands visually.
- **Double Rewards is surfaced prominently.** Loyalty members have a concrete reason to act (points acceleration), and it's visible early.
- **Memorial Day event context is retained.** The campaign continuity is intact — subscribers who saw the 5/21 escalation will read this as a progression, not a cold start.
- **Subject line is mobile-safe.** ~42 characters, no spam signals, readable on a lock screen.

## What's weak

- **"Crate & Kids SALE" sender name is still broken.** This is day two of the same mistake; inbox trust erodes each time a promotional-looking sender name fires instead of the brand.
- **No explicit percentage discount in the hero.** The week's prior sends all led with 40%, 50%, or 60% off — this one buries the number (if it exists at all), making the offer feel softer by comparison.
- **Below-the-fold product grid is visually undifferentiated.** Six-plus sections of small product thumbnails give the eye nowhere to land and dilute the delivery-speed narrative established in the hero.
- **Arrow emoji in subject ("→") signals nothing.** It reads like a UI artifact more than a meaningful call to urgency; it doesn't add curiosity or specificity.
- **Cadence tax is real.** This is send #2 from Crate & Kids today; subscribers who already opened this morning's send are likely to skim or skip.

## Recommendations

- 1. **Fix the sender display name immediately.** "Crate & Kids" — no "SALE" suffix. Every send carrying that label is a credibility leak. This is the single highest-leverage change across the entire recent run.
- 2. **Put a number in the hero.** "Get upgrades in days — and up to 50% off" closes the loop the delivery hook opens. Right now the offer feels implied rather than stated.
- 3. **Collapse the product grid to one featured category.** Pick the single room type (e.g., beds + bedding) that indexes highest for click-to-purchase at Memorial Day, and remove the rest. A tighter send outperforms a catalog.
- 4. **Give the delivery promise a deadline.** "Order by [date] for delivery before Memorial Day weekend" makes the "days not weeks" line actionable; without it the urgency is abstract.
- 5. **Replace the arrow with a deadline signal in the subject.**
- **Subject Alt A:** `Order by Sunday — arrives before the holiday`
- **Subject Alt B:** `Double Rewards + delivery in days (not weeks)`
- **Preheader Alt A:** `Up to 50% off The Memorial Day Event — room upgrades that arrive on time.`
- **Preheader Alt B:** `Fast shipping + 2x points. Here's what to grab before the weekend.`

### 3. Rendering & Accessibility

**[HIGH] `maximum-scale=1` blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. WCAG 2.1 SC 1.4.4 (Resize Text) failure. Many accessibility scanners flag this automatically. Remove `maximum-scale=1` or replace with `maximum-scale=5`.

**[MEDIUM] Conflicting `text-size-adjust` declarations**
The first `<style>` block sets:
```css
body { -webkit-text-size-adjust: 100%; -ms-text-size-adjust: 100%; }
```
A later rule in the same block overrides it globally:
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
The `*` selector wins. The `body` rule is dead code. In some clients this can cause text to render at unexpected sizes. Consolidate to one intentional value on `body` and remove from `*`.

**[MEDIUM] Desktop image `max-width` media queries conflict**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
Source order means the 768px rule overrides the 640px rule for viewports ≥768px. Result: images cap at 640px on tablets (640–767px) but shrink to 600px on full desktop (≥768px). This is almost certainly inverted intent. Swap the source order or set the 768px rule to `max-width: 640px` if 640px is the intended maximum.

**[LOW] Duplicate `format-detection` meta tags**
`telephone`, `address`, and `date` suppression appear twice each (once in the combined tag, once individually). Harmless but indicates template drift between the boilerplate block and the client-added block.

**[LOW] `line-height: 100%` on `*` selector**
```css
* { line-height: 100%; }
```
Applied globally, this collapses line-height to font-size for every element. Clients that don't support `mso-line-height-rule: exactly` may render text tighter than designed. Consider scoping to `table td` instead of `*`.

### 5. Compliance

**[HIGH] Stray developer placeholder in production `<head>`**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
"IMPUT" is a typo of "INPUT." This is an unfilled build-time comment shipped to recipients. No security risk, but it reveals internal tooling/template conventions and indicates the QA process did not diff against a clean template. Remove before sending.

**[MEDIUM] `<title>` contains unencoded ampersand**
```html

```
The doctype declares XHTML 1.0 Transitional, which requires `&amp;` for ampersands in text content. Should be `<title>Crate &amp; Barrel</title>`. Some XML-strict parsers will reject the document; most email clients are forgiving but this is a conformance defect.
