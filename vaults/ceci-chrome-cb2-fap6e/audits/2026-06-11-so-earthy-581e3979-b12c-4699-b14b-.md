### 2. Link & Tracking Issues

**Double-slash font asset URLs** — At least four `@font-face` declarations use a double-slash after the domain, which forces a server-side redirect on every font load:

```
https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2
https://www.cb2.com//Styles/CB2/fonts/BrownRegular/lineto-brown-regular.woff2
https://www.cb2.com//Styles/CB2/fonts/GTSectra/GT-Sectra-Display-Regular.woff2
```

The single-path declarations (`https://www.cb2.com/Styles/...`) are correct; the duplicates are not.

**Cross-domain font dependency** — The `HNW05` font family (four weights) is loaded from `crateandbarrel.com`, not `cb2.com`:

```
https://www.crateandbarrel.com/webfonts/1e07d600-3787-4517-bd3d-b140f9e54ec2.woff2
```

This creates a hard runtime dependency on a sibling brand's CDN. If those paths change or CORS policy is tightened, fallback fonts render silently.

**Remainder of links not assessable** — Source is truncated; CTA hrefs, redirect chains, and tracking pixels cannot be verified.

### 3. Rendering & Accessibility

**Production template placeholder shipped** — The following development comment appears verbatim in the `<head>`:

```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```

This is an unfilled authoring instruction, not a functional comment. "IMPUT" is also a typo. It is benign to rendering but signals the template was not fully sanitized before send.

**`maximum-scale=1` viewport** — The meta viewport tag:

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

Prevents pinch-to-zoom on mobile. This violates WCAG 2.1 SC 1.4.4 (Resize Text) and is flagged by Apple's accessibility guidelines for iOS mail clients.

**`-webkit-text-size-adjust:none` on universal selector** — The rule `*{-webkit-text-size-adjust:none}` in the global styles disables user-controlled font scaling across all elements. Combined with the viewport restriction above, users who rely on system font size settings (accessibility users, older users) receive no override path.

**`mso-line-height-rule: exactly` applied globally** — Applied via `*{}` and repeated on `.spacer,.divider,...`. With `line-height: 100%` also set globally, this combination can clip descenders on taller glyphs in Outlook 2016–2019 when custom fonts fall back to system fonts.
