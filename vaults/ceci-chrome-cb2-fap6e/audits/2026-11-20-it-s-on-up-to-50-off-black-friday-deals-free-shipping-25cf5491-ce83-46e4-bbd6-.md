## Technical Audit

## 1. Technical Summary
The HTML is a table-based XHTML 1.0 Transitional template with MSO conditionals and a mobile breakpoint at 460px. The main confirmed defects are about 40 images flagged as missing alt text and a viewport tag that blocks pinch-zoom. The compliance and authentication warnings come from the AgentMail relay and can't be confirmed as sender faults. The HTML source was truncated, so tracked-link and footer checks are incomplete.

## 2. Link & Tracking Issues
- **Destinations not verified.** 83 tracking links were skipped as click-redirect domains, so none were HTTP-probed. Redirect chains and 404s are unconfirmed.
- **Third-party pixels.** Five `https://sr.rlcdn.com/448796.gif?s=56aaa278…&n=1` through `n=5` calls are the same hashed ID with an incrementing `n`. This is LiveRamp, a third-party identity sync. The hashed `s=` value in the URL is a persistent identifier sent to a third-party domain on open.
- **First-party tracking.** `mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif?mi_u=…` is the open pixel. `dv.crateandbarrel.com/o/f2a3a63d-…?mi_cid=…&mi_mid=…` is a second tracker. Six `mi.crateandbarrel.com/p/rp/f3c0d22992a01946.png?mi_u=…` requests are identical. The same asset is fetched repeatedly, which is redundant weight.
- No broken links were reported (QA: 0 issues).

## 3. Rendering & Accessibility
- **Missing alt text.** About 40 images were flagged. This count includes the repeated pixels.
  - **Content images (about 25).** Examples are `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/*.jpg`, the Scene7 hero `2026%5F1122%5FCBK%5FBF%5FDealsGrid%5FREMIX%5FHero…`, the animated `…UppababyLaunch%5Fanim` and the `…WoolRugs%5FImg.gif`. If these are linked, images-off clients and screen readers get no accessible name for the link.
  - **Spacers and pixels.** The `25%5FMI%5FBottom%5FSpacer%5F40px%5FWhite` spacers, the `rlcdn` pixels and the `o.gif`/`dv` trackers should carry `alt=""` and `role="presentation"`.
  - **Caveat.** The QA tool can't distinguish an absent `alt` from an empty one. Check whether the spacers and pixels already have `alt=""`.
- **Pinch-zoom disabled.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` blocks user zoom in clients that honor it. This is a WCAG 1.4.4 concern.
- **Text scaling disabled.** The universal selector `*{-webkit-text-size-adjust:none; …}` and `body{-webkit-text-size-adjust:none}` override the earlier `100%` values. This prevents user font scaling on iOS.
- **Markup hygiene.**
  - The XHTML doctype is used with a bare `&` in `<title>Crate & Barrel</title>`, which is invalid XML.
  - `<meta charset="utf-8">` is not self-closed.
  - `format-detection` is declared in four redundant meta tags.
  - A leftover template comment reads `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->`.
  - Empty rule `td,th,div,p,a { }` in the MSO block.
- **Global `p{margin:0 auto; text-align:center}`** will force center alignment on any `<p>` that doesn't override it. Not a confirmed defect.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens (`%%…%%`, `{{…}}`, `[FIRST_NAME]`) appear in the visible source or in the QA output. The `mi_u` and `mi_cid` parameters are resolved per-recipient identifiers. I can't assess the truncated remainder.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe missing (WARN).** The tool noted the header "may not be captured by AgentMail relay". This is unconfirmed as a sender defect.
- **List-Unsubscribe-Post missing (WARN).** This is the RFC 8058 one-click header, with the same relay caveat. Gmail and Yahoo bulk-sender rules require it for senders over 5,000 messages a day.
- **Authentication-Results missing (WARN).** SPF/DKIM/DMARC status is unknown. The `From` domain `mail.crateandbarrel.com` is a dedicated subdomain, but alignment can't be verified here.
- **Footer not inspected.** The in-body unsubscribe link and the physical postal address are in the truncated section and could not be checked.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not verifiable. All 83 links went through tracking redirects and none were probed. The truncated HTML shows no `utm_*` parameters on the visible links, and tracking appears to rely on `mi_*` parameters. Landing-page alignment with the "up to 50% off + free shipping" subject can't be confirmed.

## 7. Recommendations
1. Add descriptive `alt` to all linked content images. Use `alt=""` and `role="presentation"` on the spacers and tracking pixels.
2. Remove `maximum-scale=1` from the viewport meta. Remove the `text-size-adjust:none` overrides.
3. Confirm `List-Unsubscribe` and `List-Unsubscribe-Post` against raw headers captured outside the relay, or via a seed-inbox test.
4. Run a probe on the resolved redirect destinations, for example by following the tracking links with a headless fetch. Check for `utm_*` on the final landing URLs.
5. Dedupe the six identical `f3c0d22992a01946.png` requests and review whether five `rlcdn` pixels are needed.
6. Escape `&` as `&amp;` in `<title>`. Remove the duplicate `format-detection` metas and the leftover template comment.
7. Capture the full HTML and the raw headers so the footer, unsubscribe link and postal address can be audited.
