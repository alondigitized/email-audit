# Summer’s heating up! Shop up to 60% off →
**Score:** 8/10 · **Type:** Email audit · **2026-07-17**
## Executive summary

- This is Crate & Barrel's biggest discount claim of the week — "up to 60% off" is a meaningful escalation from yesterday's "up to 35% off" Breville/Le Creuset send. The hero is clean and the sale message lands immediately. But the email tries to do five things at once: push the sale, run a $500 sweepstakes, highlight Le Creuset specifically, surface personalized picks, and promote the app. That's too many narratives for a single send, and the sweepstakes in particular breaks the sale momentum right when you want the subscriber to click to shop.
- The Le Creuset callout — "over 20% off select Le Creuset" — is a notable stumble relative to brand history. Yesterday's July 16 C&B send led with "Save on Breville, Le Creuset & more! Shop up to 35% off." Today's Summer Sale is allegedly bigger (60% off!), but the Le Creuset line *dropped* from "up to 35%" to "over 20%." Any subscriber who saw both emails will notice the contradiction and may feel misled, even if the category math technically works out.
- Bottom line: the email is solid but unfocused. The sale signal is strong; the execution dilutes it with too many detours before reaching the shop-now moment.

## What's working

- **Hero is immediately legible** — "up to 60% off / The Summer Sale" lands above the fold with a clear CTA button; no ambiguity about what this email is selling.
- **Le Creuset callout is specific** — naming a premium brand with a standalone section adds credibility and gives kitchen-focused readers an on-ramp.
- **Personalized picks section** ("set [these] for you") signals segmentation and is a genuine lift over generic catalog grids.
- **App promotion is non-intrusive** — tucked toward the bottom rather than competing with the sale hero.
- **Clean render** — no broken images, overlapping text, or layout failures visible in the screenshot.

## What's weak

- **Sweepstakes ($500 giveaway) interrupts the sale flow** — it appears immediately below the hero and pulls attention away from shopping right when purchase intent is highest.
- **Le Creuset discount appears worse than yesterday's send** — "over 20% off" undercuts the credibility of a "bigger Summer Sale" vs. the July 16 "up to 35% off" email.
- **No deadline visible** — "Summer Sale" is vague; without a date or countdown, urgency is purely implied by season.
- **Too many CTA buttons** — sale, sweepstakes, sofa, Le Creuset, personalized picks, app, TheDesignDesk. Attention is scattered.
- **TheDesignDesk editorial block at the bottom** feels like a different email stapled on — the editorial voice clashes with the promotional energy of a 60%-off push.

## Recommendations

- 1. **Cut or move the sweepstakes section.** Either make it a dedicated send or push it below the product grid. Don't interrupt sale momentum with a contest entry.
- 2. **Fix the Le Creuset story.** Either match or beat yesterday's 35% off claim, or drop Le Creuset from this email entirely. The downgrade from 35% to 20% is a trust eroder for anyone in your file who opened both.
- 3. **Add a hard deadline.** "Ends Sunday" or "3 days left" would convert more fence-sitters than any copy change.
- 4. **Consolidate to 2-3 CTAs max.** Pick a lane: summer sale hero → one product category callout → personalized picks. Cut the sofa section or the app promotion.
- 5. **Drop TheDesignDesk block.** Save it for an editorial day. It belongs in a sends like the July 16 "stripes" or "fairy tale" emails, not here.

### 3. Rendering & Accessibility

**CSS media query cascade conflict (functional bug)**

Two `@media (min-width)` blocks in `<head>` set `img { max-width }`, with the broader rule declared *last*, overriding the narrower one:

```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }  /* declared first */
@media only screen and (min-width: 640px) { img { max-width: 640px } }  /* declared second — wins at 768px+ */
```

At all widths ≥ 640px the 640px cap wins via cascade order. The intended 600px desktop max-width never applies.

**`maximum-scale=1` blocks accessibility zoom**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

Prevents pinch-to-zoom on mobile — violates WCAG 1.4.4 (Resize Text, Level AA).

**Dark mode opt-out**

```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```

Explicitly disables dark mode adaptation. Email will render a white background in dark-mode mail clients (Apple Mail, Outlook 2021+) with no OS-level fallback.

**Duplicate `format-detection` meta tags**

Four declarations where one combined tag suffices — the omnibus declaration is immediately followed by three single-attribute duplicates:

```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
...
<meta name="format-detection" content="date=no">       <!-- redundant -->
<meta name="format-detection" content="address=no">    <!-- redundant -->
<meta name="format-detection" content="telephone=no">  <!-- redundant -->
```

No rendering impact, but inflates `<head>` byte count and indicates template cleanup was skipped.

**Aggressive global `line-height`**

```css
* { line-height: 100%; }
```

A `line-height` of `100%` equals `1em` — correct for single-line cells but clips descenders in multi-line text blocks. Recommend `1.4`–`1.6` for body copy.

**`-webkit-text-size-adjust: none` on `*` selector**

Disables system font scaling for low-vision users on iOS/Safari. The `html`-scoped version (`-webkit-text-size-adjust: 100%`) on the `body` rule partially counteracts this, but the `*` rule re-applies to every descendant.
