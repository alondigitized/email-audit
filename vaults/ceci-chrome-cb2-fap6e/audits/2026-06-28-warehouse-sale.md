# WAREHOUSE SALE
**Score:** 7/10 · **Type:** Email audit · **2026-06-28**
## Executive summary

- This is CB2's standalone "WAREHOUSE SALE" send — a clean two-word subject, a hero block with "UP TO 60% OFF," and a category grid (FURNITURE / LIGHTING / DECOR / RUGS / SHOP ALL). The top half is competent: the typography is legible, the discount is stated upfront, and the lifestyle imagery is on-brand. Down to this point, it's a workmanlike warehouse clearance email.
- Then CB2 runs a full-width "THE JULY 4TH SALE — UP TO 50% OFF" banner directly below, and the email breaks. The subscriber is now holding two simultaneous sales with different discount ceilings and zero explanation of how they relate. Is the Warehouse Sale a subset of July 4th? A different pool of product? The email doesn't say. The "MORE FOR YOU" product grid at the bottom is the most useful thing here — individual SKUs with prices — but it can't rescue an email that already asked too much of the reader.
- This is the same structural error that killed the June 25 Floor Sample Sale send, where three stacked promotions created congestion no CTA could resolve. After nine-plus consecutive CB2 sale sends, the word "sale" is pulling less weight each time, and this email does nothing to re-earn it.

## What's working

- **Hero is legible and on-brand:** "WAREHOUSE SALE / UP TO 60% OFF" renders cleanly with strong type hierarchy and a warm lifestyle image.
- **Category grid is immediately practical:** FURNITURE / LIGHTING / DECOR / RUGS / SHOP ALL gives a decision path without making the subscriber hunt.
- **"MORE FOR YOU" personalizes the bottom half:** Named products with individual pricing is the most specific — and clickable — element in the send.
- **Loyalty hook present:** "EARN 10% BACK" surfaces in the footer for members.
- **July 4th banner anchors the send in time:** It at least signals this is a live promotional window, even if the execution is messy.

## What's weak

- **Two competing offers, no disambiguation:** 60% off (warehouse) vs. 50% off (July 4th) runs simultaneously with no explanation of scope, product pools, or which to choose.
- **No deadline on the primary offer:** The warehouse sale has no urgency anchor — "while supplies last" or a hard end date is completely absent from the hero.
- **Subject line is bare-minimum:** "WAREHOUSE SALE" in all-caps signals promotional blast, not targeted event. No depth, no hook, no discount stated.
- **No product hero:** The email links to categories, not to one item worth stopping for. The June 26 "It's back. And now it's on sale." send at least implied a specific product — this one doesn't.
- **Deep in a fatigued send cycle:** The June 25 Floor Sample Sale already had three-offer congestion. This email repeats the same structural failure a send later.

## Recommendations

- 1. **Pick one sale per email.** Either the Warehouse Sale or the July 4th Sale — not both. Two discount depths in one send means neither lands.
- 2. **Add a deadline to the warehouse hero.** One line — "ends July 3" or "while supplies last" — gives the offer urgency it completely lacks right now.
- 3. **Feature one product in the hero.** Pull the strongest value from the warehouse (a $1,800 sofa at $700, whatever it is) and hero it above the category grid. Specific beats categorical in clearance sends.
- 4. **Drop the ALL CAPS subject.** Title case reads the same but doesn't pattern-match to spam filters or fatigued subscriber eyes.
- 5. **Connect the subject to the personalized grid.** If "MORE FOR YOU" is dynamic, hint at it in the preheader: "your recommended pieces are marked down."
- **Subject Alt A:** `Warehouse Sale — up to 60% off furniture & lighting`
- **Subject Alt B:** `The CB2 pieces worth grabbing before July 4th`
- **Preheader Alt A:** `Past-season furniture and decor, cleared to make room — shop before it's gone.`
- **Preheader Alt B:** `60% off select furniture, lighting, decor and rugs. Ends soon.`

### 3. Rendering & Accessibility

**`maximum-scale=1` on viewport meta (line 5):**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocks user-initiated zoom on mobile. Fails WCAG 1.4.4 (Resize Text). Remove `maximum-scale=1`.

**Universal selector text-size-adjust override:**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none;}
```
Applying this to `*` rather than `body` is overly aggressive and suppresses OS-level accessibility text scaling across all elements.

**Non-standard mobile breakpoint at 418px:**
```css
@media only screen and (max-width: 418px) { .mobile { width:414px !important; } }
```
Gap exists between 419px–767px — no media query targets this range. Devices in that band (many Android phones, tablets in portrait) receive desktop layout with no override. Standard thresholds are 480px or 600px.

**Stale developer comment in production HTML:**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
Typo ("IMPUT") and placeholder text shipped to end recipients. No functional impact but indicates incomplete production hygiene.

**Redundant and conflicting `@font-face` for "Lineto Brown Sub":**
The same `font-family: "Lineto Brown Sub"` is declared three times:
- First: `eot` + `woff2` + `woff` (no `font-weight` specified → defaults to 400)
- Second: `woff2` only, `font-weight: 400`
- Third: `woff2` only, `font-weight: 600`

The first unweighted declaration conflicts with the second (both are weight 400, different source sets). Email clients resolve this unpredictably. The Light variant (`Lineto Brown Light Sub`) only declares `.woff` with no `.woff2` fallback.

**Cross-origin font loading from sibling brand:**
```css
@font-face { font-family:"HNW05"; src: url("https://www.crateandbarrel.com/webfonts/...") }
```
CB2 email loads Helvetica Neue (HNW05) from `crateandbarrel.com`. If that domain's CDN is unavailable or applies CORS restrictions, the fallback font chain fires silently. Font should be hosted on `cb2.com` or a shared CDN.

**Double-slash in font URLs (minor):**
```
https://www.cb2.com//Styles/CB2/fonts/...
```
Technically resolves correctly but indicates copy-paste error in template.
