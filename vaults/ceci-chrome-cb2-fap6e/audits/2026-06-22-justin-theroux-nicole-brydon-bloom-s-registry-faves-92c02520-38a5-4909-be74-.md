## 3. Rendering & Accessibility

**`<title>` brand mismatch**
```html
<title>Crate & Barrel</title>
```
Sender identity is "Crate & Kids"; the title reads "Crate & Barrel." Shown in browser-preview tabs, some webmail clients, and screen-reader preambles.

**User zoom blocked — WCAG 1.4.4 violation**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
`maximum-scale=1` prevents pinch-to-zoom on mobile. Remove `maximum-scale=1`.

**Global text-size-adjust disabled**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
Applied to every element via the universal selector. Disabling text scaling system-wide is an accessibility anti-pattern and can suppress OS-level font enlargement for low-vision users. Scope to `body` only (value `100%`, not `none`).

**Conflicting desktop image max-width rules**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
Both rules are in the `<head>` in this order. On viewports ≥ 768px the 600px rule wins (declared later and more specific viewport), overriding the 640px intent. On 640–767px only the 640px rule applies. The 768px block should be removed or merged; keep a single authoritative desktop breakpoint.

**`format-detection` meta duplicated**
The tag `telephone=no,address=no,email=no,date=no,url=no` appears once as a combined value and then again split across three separate tags (`date=no`, `address=no`, `telephone=no`). Not breaking, but dead markup.

**Dark mode not declared**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Forces light mode only. Apple Mail, Gmail app, and Outlook on iOS will not attempt dark-mode adaptation. If intentional, no action needed; if unintentional, add `light dark` to both values.
