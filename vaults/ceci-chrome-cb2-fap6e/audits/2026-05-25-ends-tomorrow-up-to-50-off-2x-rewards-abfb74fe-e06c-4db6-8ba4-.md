# ENDS TOMORROW: Up to 50% off & 2x Rewards!
**Score:** 7/10 · **Type:** Email audit · **2026-05-25**
## Executive summary

- This is Crate & Kids' Memorial Day close — a clean dresser hero, a 50% off headline, and the Double Rewards beat the brand has hammered all week. The layout is well-structured: hero → product grid → loyalty hook → curated picks → app upsell → footer. On its own, it's a competent send.
- The problem is twofold. First, the body hero copy reads **"ends today!"** while the subject line says **"ENDS TOMORROW"** — a direct contradiction a reader catches in two seconds and which immediately erodes trust. Second, this is now the sixth (or more) Memorial Day email from this sender family in six days. The cadence alone is a suppression mechanism regardless of execution quality.
- Bottom line: a solid template undermined by a copy conflict and subscriber exhaustion. The "ends today/ends tomorrow" mismatch is the single most urgent fix.

## What's working

- **Sage-green dresser hero is strong creative** — distinct color, lifestyle-forward, stops the scroll better than a flat product shot.
- **50% off is prominently placed** in the hero, no hunting required.
- **Double Rewards hook is visible** mid-email as a second reason to act — layering the loyalty benefit on top of the discount is smart.
- **Product grid is clean** — multiple SKUs shown with individual price points visible, giving the reader options without chaos.
- **App upsell is present** with a specific incentive (chance at $100), not just a generic "download our app."

## What's weak

- **"Ends today!" in the body directly contradicts "ENDS TOMORROW" in the subject** — this is the worst kind of visible error; it signals sloppiness and makes the urgency feel manufactured.
- **Sixth Memorial Day email in the same week** — no matter how good the creative, cadence fatigue suppresses opens and clicks; a subscriber who opened the first three is likely deleting on sight.
- **"Shop Now" CTA is generic** — with a dozen product tiles visible, the CTA does no work differentiating *what* to shop for.
- **No countdown timer in this send** — the 2026-05-25 Crate & Barrel main-brand email used a live timer (00:06:55 hero) to amplify the "last day" urgency; skipping that here when urgency is the entire premise is a miss.
- **Demographic targeting feels broad** — kids furniture is a niche category but the email shows no signal it knows *this* subscriber's child's age or past purchase category.

## Recommendations

- 1. **Fix the ends today/ends tomorrow conflict immediately** — this should block the send until resolved. If the sale ends on 5/26, the body must say "ends tomorrow" not "ends today."
- 2. **Add a countdown timer to the hero** — the sibling Crate & Barrel brand did this on the same day; it is more persuasive than static text for a deadline claim.
- 3. **Cut the cadence or segment harder** — anyone who opened/clicked in the first three days of the Memorial Day series should get a simpler, shorter re-engagement email, not an identical full send.
- 4. **Replace "Shop Now" with a category-specific CTA** — "Shop Kids' Furniture" or "Shop Nursery" earns more clicks from subscribers who actually have a kid's room project in mind.
- 5. **Surface one anchor product with a name + specific savings amount** — e.g. "The Vale Dresser: now $X (save $Y)" gives the reader a concrete reason to click versus a category discount.
- **Subject Alt A:** `Ends tomorrow — 50% off kids' furniture + 2x Rewards`
- **Subject Alt B:** `Last day: Up to 50% off The Memorial Day Event`
- **Preheader Alt A:** `Crib, dresser, bookcase — take an extra look before it's gone.`
- **Preheader Alt B:** `Double Rewards expire at midnight. Here's what's left.`

### 3. Rendering & Accessibility

**Wrong `<title>` tag (confirmed):**
```html
<title>Crate & Barrel</title>
```
This email is from the "Crate & Kids" sub-brand. Several email clients (notably Apple Mail, Outlook Web) surface the `<title>` to screen readers. This will announce the wrong brand name to assistive technology users.

**Unreplaced template placeholder comment (confirmed):**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
<!----> 
```
The comment `[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]` (note: typo — "IMPUT" should be "INPUT") was not removed before send. No font `@import` was inserted, which means either (a) the intended custom font was silently dropped, or (b) the template was not cleaned up. The empty `<!---->` immediately after suggests the insertion point was cleared but the marker comment was not.

**`maximum-scale=1` in viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Disables pinch-to-zoom on mobile. This is an accessibility failure (WCAG 1.4.4) for users who need to enlarge text. This pattern is common in email templates but should be flagged.

**Contradictory image `max-width` media queries:**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
The 768px rule (capping images at 600px) will always override the 640px rule (capping at 640px) on desktop, since both apply at ≥768px and cascade order favors the first rule. This means desktop images are constrained to 600px despite the 640px container. Likely unintentional — the 640px rule is dead code.

**Duplicate `format-detection` meta tags:**
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
The combined declaration at the top covers all cases; the three individual declarations below are redundant. No functional breakage, but indicates template hygiene issues.

**No dark mode support:**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Dark mode rendering is explicitly disabled. Apple Mail (a major client for this demographic) will force-invert colors on `light`-only emails in some configurations, potentially breaking brand colors. Consider adding `light dark` and testing in Apple Mail dark mode.

**Global `line-height: 100%` override:**
```css
* { line-height: 100%; }
```
Applied via the universal selector. This collapses line height on all elements globally, which can cause text to overlap on multi-line strings in certain clients. It is overridden inline in many places, but any element that misses an explicit `line-height` inline style is at risk.
