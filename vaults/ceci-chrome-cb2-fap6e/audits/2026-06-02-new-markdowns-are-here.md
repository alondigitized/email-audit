### 3. Rendering & Accessibility

**[HIGH] Stale template placeholder in `<head>`**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
This comment shipped verbatim to recipients. "IMPUT" is also misspelled ("INPUT"). Indicates a pre-send checklist failure; no rendering impact, but confirms the template was not fully sanitized.

**[MEDIUM] Double-slash in three `@font-face` src URLs**
```css
url("https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2")
url("https://www.cb2.com//Styles/CB2/fonts/BrownRegular/lineto-brown-regular.woff2")
url("https://www.cb2.com//Styles/CB2/fonts/GTSectra/GT-Sectra-Display-Regular.woff2")
```
A double slash after the domain (`cb2.com//Styles/…`) produces a different path than intended. Most web servers normalize this silently, but strict or CDN-fronted configs may return 404. Single-slash equivalents are correct elsewhere in the same file — inconsistency suggests a copy-paste error.

**[MEDIUM] Cross-domain font dependency on `crateandbarrel.com`**
The `HNW05` family (4 weights) is loaded from:
```css
src: url("https://www.crateandbarrel.com/webfonts/1e07d600-…woff2")
```
CB2 emails depending on a sibling brand's domain means any cache purge, CDN config change, or CORS policy update on that domain silently breaks font rendering. These files should be mirrored to `cb2.com` or a shared CDN origin.

**[MEDIUM] Conflicting `@font-face` for "Lineto Brown Sub" weight 400**
The font is declared twice at `font-weight: 400` — once pointing to the Light variant (no `font-display: swap`) and once to the Regular variant (with `font-display: swap`). Browser behavior when two identical `@font-face` weight/style descriptors collide is implementation-defined; the second declaration typically wins, but the missing `font-display: swap` on the first means a FOIT risk if that declaration is resolved first in certain clients.

**[LOW] `maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents user-initiated zoom on mobile. WCAG 2.1 SC 1.4.4 (Resize Text) flags this as an accessibility failure.

**[LOW] `*{-webkit-text-size-adjust:none}` on wildcard selector**
Suppresses iOS automatic text size adjustment across every element. Combined with the above, this creates a double-block on user/system text scaling. The intent is to prevent unwanted auto-scaling, but the wildcard scope is too broad — should be scoped to `body` only.
