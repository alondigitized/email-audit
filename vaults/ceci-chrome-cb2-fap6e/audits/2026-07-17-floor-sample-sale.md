### 3. Rendering & Accessibility

**`maximum-scale=1` in viewport meta — confirmed issue**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom. Fails WCAG 2.1 SC 1.4.4 (Resize text). Impacts users with low vision on mobile clients that respect this attribute (Gmail Android, Apple Mail).

**Global `text-size-adjust: none` — confirmed issue**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; ... }
```
Applied to the wildcard selector. The correct value is `100%`, not `none`. `none` disables browser auto-sizing on all elements, not just the body — can cause unreadably small text on mobile when font sizes are specified in px.

**Non-standard mobile breakpoint — confirmed issue**
```css
@media only screen and (max-width: 418px) { .mobile { width: 414px !important; ... } }
```
418px excludes iPhone 14 Plus (430px logical width) and iPhone 15 Plus (430px). The `.mobile` override won't trigger on those devices. Standard practice is `max-width: 480px` or `600px` for email.

**Duplicate `@font-face` declarations for "Lineto Brown Sub" — confirmed issue**
The same family name is declared three times:
1. No `font-weight`/`font-style` (loads `.eot` + `.woff2` + `.woff`)
2. `font-weight: 400` (loads `.woff2` only)
3. `font-weight: 600` (loads `.woff2` only)

Declaration 1 has no weight descriptor, so it matches all weights and will shadow declarations 2 and 3 in clients that process `@font-face` in source order. The light variant (`lineto-brown-light`) may render in place of the regular/bold weight.

**Double-slash in font URLs — confirmed issue**
Three `@font-face` declarations contain a double slash in the path:
```
https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2
https://www.cb2.com//Styles/CB2/fonts/BrownRegular/lineto-brown-regular.woff2
https://www.cb2.com//Styles/CB2/fonts/GTSectra/GT-Sectra-Display-Regular.woff2
```
Most servers normalize `//` with a 301 redirect, but email clients processing CSS `src:` URLs may not follow redirects, causing those variants to silently fail.

**Cross-domain font load — low-risk observation**
`HNW05` is loaded from `https://www.crateandbarrel.com/webfonts/` within a CB2-branded email. This is likely intentional (shared brand infrastructure), but any future domain or CORS change at crateandbarrel.com breaks CB2 email font rendering with no CB2-side indicator.
