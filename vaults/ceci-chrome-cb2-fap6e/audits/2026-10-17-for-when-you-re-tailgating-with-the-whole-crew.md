## Technical Audit

## 1. Technical Summary
The email renders from a table-based XHTML 1.0 Transitional template with MSO conditionals and a mobile breakpoint at 460px. The QA run found no hard failures, only 3 warnings. The main confirmed issue is about 45 images flagged for missing alt text. Header-based compliance and authentication checks could not be evaluated.

## 2. Link & Tracking Issues
- **78 tracking links were not probed.** They are on click-redirect domains and were skipped, so destination validity, redirect chains and 404s are unverified.
- **Five identical third-party pixels** are `https://sr.rlcdn.com/448796.gif?s=56aaa278…&n=1` through `n=5`. `rlcdn.com` is LiveRamp. They are all the same pixel with only the `n` counter changing, and each adds a third-party request and a data-sharing surface. Repeating one pixel five times is redundant.
- **Per-recipient identifiers in image URLs.** The `mi_u=56aaa2787a67…` token appears on `mi.crateandbarrel.com/p/rp/*.png` and `mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif`. `dv.crateandbarrel.com/o/2c69184e-…` carries `mi_cid` and `mi_mid`. This is normal ESP tracking, but each URL is unique per recipient, so these images are not cacheable.
- **A Scene7 asset has a truncated filename.** The `s7d5.scene7.com/.../2026%5F0914%5FCB%5FNFLCollection%5FSocial%5FVideo.` src is cut off in the QA output, so I can't tell whether the file exists. It's an NFL video asset, likely a GIF or poster frame, and is worth a manual check.

## 3. Rendering & Accessibility
- **Missing alt text on 45 images, confirmed by QA.**
  - About 30 are content images on `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/*.jpg|gif` (for example `56be7a63-…jpg` and `e5a45dc0-…gif`). With images blocked or a screen reader, these show no text.
  - The remaining images are tracking pixels: `mi.crateandbarrel.com/p/rp/*.png` (7), `rlcdn` (5), `o.gif` (1) and `dv.crateandbarrel.com` (1). These should carry `alt=""`. The QA tool can't tell a missing `alt` from an empty one, so I can't confirm which of these are actually wrong.
- **Animated GIFs without alt.** `e5a45dc0-…gif` and `e92eca67-…gif` are flagged, and the animated content has no text equivalent.
- **Duplicate and conflicting `<meta name="format-detection">` tags.** The head declares `telephone=no,address=no,email=no,date=no,url=no`, then repeats `date=no`, `address=no` and `telephone=no` separately. Clients may handle the repeats inconsistently.
- **Placeholder comment left in the head.** `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->` is a template remnant. It's harmless but sloppy, and the typo suggests the template wasn't cleaned up.
- **Global `*{... line-height:100%}`** with `max-height:1000000px`, plus `img {max-width:600px}` and `img {max-width:640px}` in overlapping desktop media queries, which makes the max-width logic ambiguous. This is a risk, not a confirmed defect.
- **`<title>Crate & Barrel</title>`** has an unescaped `&`, which is invalid in XHTML 1.0.

## 4. Personalization & Merge Tokens
No issues found in the visible source. No unresolved merge tokens such as `%%…%%`, `{{…}}` or `[FNAME]` appear in the truncated HTML or the QA output. The rest of the HTML was not provided, so this is limited to the visible portion.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Not verifiable:** `List-Unsubscribe`, `List-Unsubscribe-Post` (RFC 8058) and `Authentication-Results` were not found. The QA tool attributes this to the AgentMail relay, so it's a capture limitation and not evidence the sender lacks them. SPF, DKIM and DMARC status is unknown.
- **Not verifiable:** The footer unsubscribe link and the physical postal address aren't visible in the truncated HTML, so CAN-SPAM footer elements are unconfirmed.
- **Sender domain:** `mail.crateandbarrel.com` is a dedicated sending subdomain, which is good practice. It uses the same parent domain as the image and tracking hosts (`image.`, `mi.`, `dv.`), so alignment looks consistent.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Unconfirmed. The 78 links went through click-redirect domains and weren't probed, and the truncated HTML doesn't show final destination URLs or UTM parameters. I can't assess landing page alignment with the NFL/tailgate subject line from the data provided.

## 7. Recommendations
1. **Add descriptive alt text** to the ~30 content images, especially the animated GIFs, and set `alt=""` explicitly on the tracking pixels.
2. **Collapse the five `sr.rlcdn.com/448796.gif` pixels** (`n=1..5`) to one, unless each is deliberately attributed to a separate section.
3. **Escape the `&`** in `<title>` and consolidate the `format-detection` meta tags.
4. **Re-run with full headers,** from a direct SMTP capture or the raw MIME source, to verify `List-Unsubscribe`, `List-Unsubscribe-Post` and SPF/DKIM/DMARC.
5. **Resolve the redirect chains** on a sample of the 78 tracked links to check destinations, UTM presence and landing page match. Fix the truncated Scene7 filename check at the same time.
6. **Remove the template remnant comment** (`IMPUT HERE CLIENT FONT IMPORT…`).
