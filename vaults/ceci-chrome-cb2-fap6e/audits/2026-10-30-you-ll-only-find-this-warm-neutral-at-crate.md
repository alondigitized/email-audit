## Technical Audit

## 1. Technical Summary
The visible markup is a standard ESP-built XHTML table layout (Marigold/"MI" templating). The main confirmed problems are widespread missing image alt text and a viewport setting that blocks zoom. The compliance and authentication checks came back inconclusive because the relay didn't capture the headers. The HTML source is truncated, so footer and body checks are limited.

## 2. Link & Tracking Issues
- **Click links not verified.** 69 tracking links were skipped by the HTTP probe because they are tracking or redirect domains. Destination health and redirect chains are unverified.
- **Third-party pixels.** Five `https://sr.rlcdn.com/448796.gif?s=…&n=1` to `n=5` pixels (LiveRamp) are in the body. The `s=` value (`56aaa2787a6773d0f164733102dce5192f75df7c634bb941bb6406869640cfd8`) shares its prefix with the `mi_u=` parameter on `mi.crateandbarrel.com` assets. That suggests the same hashed recipient identifier is shared with a third party. Five identical pixels differing only by `n` is redundant.
- **Open-tracking pixels.** `mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif` and `dv.crateandbarrel.com/o/7f103ac3-…?mi_cid=…&mi_mid=…` are both present, and both are missing alt text.

## 3. Rendering & Accessibility
- **Missing alt text on 35 images** (per QA). These split into three groups:
  - About 21 content images on `image.mail.crateandbarrel.com/lib/…` and `s7d5.scene7.com`. This includes the hero (`2026_0326_CB_VF_SmegMocha_1_hero_v1…`), `…SmegMocha_SocialVideo-…` and `2026_1011_CB_HolidayDecorating_Secondary…`. With images blocked or read by a screen reader, these are empty or filename-only.
  - 7 `mi.crateandbarrel.com/p/rp/*.png` images. These look like dynamic recommendation images and likely need product-name alt text.
  - 7 tracking pixels (`rlcdn` ×5, `o.gif`, `dv…`). These should carry `alt=""`. The QA check can't tell absent alt from empty alt, so a missing alt on these is low severity.
- **Zoom blocked.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` prevents pinch-zoom on some clients. This is a WCAG 1.4.4 concern.
- **Text resizing disabled.** The universal rule `*{-webkit-text-size-adjust:none; … line-height:100%}` and `html{-webkit-text-size-adjust:none}` prevent text scaling in iOS and WebKit clients.
- **Unescaped ampersand.** `<title>Crate & Barrel</title>` under an XHTML 1.0 Transitional doctype should be `&amp;`. This is minor, and the source may have been decoded before display.
- **Template leftovers.** The source contains the placeholder comment `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->`. It has no rendering impact but is sloppy. There are also duplicate `format-detection` meta tags, a duplicate charset declaration (`http-equiv` plus `<meta charset>`), and an empty `td,th,div,p,a { }` rule in the MSO block.
- **Dead CSS.** `@media (min-width:768px){img{max-width:600px}}` is overridden by `@media (min-width:640px){img{max-width:640px}}`, which comes later with equal specificity. The 600px rule never takes effect.

## 4. Personalization & Merge Tokens
No issues found in the visible source. No unrendered tokens (`%%…%%`, `{{…}}`) appear in the truncated HTML. Personalization is only visible through hashed `mi_u`, `mi_cid` and `mi_mid` parameters. The footer and body were not available to check.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) not found.** The QA tool itself says the AgentMail relay may strip these headers. Treat this as **unconfirmed**, not a confirmed sender failure. Verify against the raw message at the source mailbox.
- **`Authentication-Results` not found.** SPF, DKIM and DMARC status is unknown for the same reason. The From domain `mail.crateandbarrel.com` is a dedicated sending subdomain, but alignment can't be confirmed from this data.
- **In-body unsubscribe link and physical postal address.** Not verifiable because the HTML is truncated before the footer.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not assessable. All 69 links are redirect-tracked and weren't resolved, and the truncated source shows no destination URLs. No UTM parameters or landing page mismatches can be confirmed.

## 7. Recommendations
1. **Add descriptive alt text** to all ~21 content images and the 7 dynamic `mi…/p/rp/` product images. Set `alt=""` explicitly on the 7 tracking pixels.
2. **Remove `maximum-scale=1`** from the viewport meta, and drop the blanket `-webkit-text-size-adjust:none` on `*`.
3. **Verify unsubscribe and authentication headers** on the original message (not the relay copy): `List-Unsubscribe`, `List-Unsubscribe-Post: List-Unsubscribe=One-Click`, and SPF, DKIM and DMARC alignment.
4. **Resolve a sample of the 69 tracked links** with a redirect-following probe to confirm final URLs, status codes and UTM parameters.
5. **Review the five LiveRamp pixels.** Consolidate them, and confirm the hashed-identifier sharing is disclosed in the privacy policy.
6. **Clean the template:** escape `&` in the title, remove the `IMPUT HERE` comment, dedupe the meta tags, and delete the dead `img` max-width rule.
7. **Re-run the audit with the full, untruncated HTML** so the footer, unsubscribe link, postal address and landing URLs can be checked.
