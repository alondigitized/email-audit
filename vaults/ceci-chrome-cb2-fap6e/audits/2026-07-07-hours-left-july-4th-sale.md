# HOURS LEFT: JULY 4TH SALE
**Score:** 8/10 · **Type:** Email audit · **2026-07-07**
## Executive summary

- This is CB2's final-hours close on the July 4th sale — the countdown shows 17 hours and change remaining, which is the most honest urgency signal in this entire week-long sequence. The execution is clean: the timer, the 50% off call, and the category grid all load above the fold, and the Warehouse Sale cross-sell below gives in-store shoppers a separate reason to engage. For a subscriber who's been orbiting a purchase decision, this is the email that tips the scale.
- The problem is the creative layer. "BETTER THAN FIREWORKS" is a tagline that expired 72 hours ago — it's July 7th, and nobody is still thinking about fireworks. The "July 4th Sale" label itself has been getting more awkward with each passing day, and CB2's brand history shows they've been sending variations of this email every single day since at least July 3rd. Sale fatigue is real; by this point, the audience has been conditioned to ignore the brand name in the sender field because they know it's another one.
- Bottom line: the countdown timer saves this email. Everything else is mechanical repetition of copy that peaked three days ago.

## What's working

- **Countdown timer with actual hours** — 17:19 remaining is specific, credible, and visible immediately on open; this is the one urgency signal that doesn't feel manufactured.
- **50% off headline is unmissable** — the red oversized typography on a light background creates instant hierarchy; no hunting for the offer.
- **Three category CTAs below the fold** — SHOP OUTDOOR / SHOP FURNITURE / SHOP TABLETOP give buyers a direct lane without forcing them to the homepage; this is better than a generic CTA.
- **Warehouse Sale cross-sell** — smart inclusion for subscribers who missed yesterday's dedicated Warehouse email; up to 60% off is a stronger number and may convert people who found 50% insufficient.

## What's weak

- **"BETTER THAN FIREWORKS" tagline is past its sell-by date** — on July 7, this reads as a copy asset that was never updated; it undermines the sense that anyone is paying attention to the clock.
- **"July 4th Sale" framing is stale** — the brand has called this the "July 4th Sale" for four-plus days post-holiday; the brand history shows they never refreshed the campaign name as the calendar moved.
- **"SHOP NOW" hero CTA is too generic** — given that the timer is running out on a specific sale, "SHOP BEFORE IT ENDS" or "GET 50% OFF" would carry the urgency into the button.
- **No product specificity in the hero** — the hero image is a lifestyle/shadow composition rather than a specific product at a specific discounted price; buyers who haven't clicked all week need a concrete anchor, not ambiance.
- **Seventh-plus send in the sequence with minimal creative evolution** — the category grid and layout are nearly identical to the July 5th and 6th sends; even the final-hours email needed one fresh visual to earn the open.

## Recommendations

- 1. **Kill "BETTER THAN FIREWORKS" immediately** — replace with something that acknowledges the real moment: "Final Hours. Up to 50% Off." The tagline slot can do actual selling work here.
- 2. **Add one specific discounted product in the hero** — a sofa or outdoor chair at a named before/after price gives wavering buyers the concrete anchor they need to click.
- 3. **Change "SHOP NOW" to "SHOP BEFORE IT ENDS"** — the CTA should echo the countdown timer's urgency, not ignore it.
- 4. **Rename the campaign in the body copy** — something like "THE SUMMER SALE" or just "50% OFF ENDS TONIGHT" ages better than a holiday tie-in three days past the holiday.
- **Subject Alt A:** `HOURS LEFT: Up to 50% off ends tonight`
- **Subject Alt B:** `Final hours — 50% off furniture + outdoor`
- **Preheader Alt A:** `The countdown is real. Shop furniture, outdoor, tabletop before the sale closes.`
- **Preheader Alt B:** `Under 18 hours left — plus Warehouse Sale up to 60% off in store.`

### 3. Rendering & Accessibility

**Double-slash font paths (confirmed):**
Three `@font-face` declarations use double slashes in the CB2 origin path:
```
https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2
https://www.cb2.com//Styles/CB2/fonts/BrownRegular/lineto-brown-regular.woff2
https://www.cb2.com//Styles/CB2/fonts/GTSectra/GT-Sectra-Display-Regular.woff2
```
Most servers normalize this via 301, but strict clients (some corporate proxies, older Outlook WebApp) may fail to load these resources. The single-slash declarations elsewhere in the same file confirm this is a copy-paste defect.

**Conflicting desktop media queries:**
Two separate `@media` blocks both target `img` max-width for desktop:
```css
@media only screen and (min-width: 690px) { img { max-width: 690px } }
@media only screen and (min-width: 768px) { img { max-width: 100% !important } }
```
On viewports ≥ 768px, the `!important` rule overrides the 690px cap and lets images render at full table width — likely unintended given the 690px cap exists. On 690–767px viewports, images are hard-capped at 690px with no override. The two rules are contradictory and should be collapsed into one.

**Mobile breakpoint targets a single device size:**
```css
@media only screen and (max-width: 418px) { .mobile { width:414px !important } }
```
This triggers only on ≤ 418px viewports, corresponding to iPhone SE/mini. Standard email mobile breakpoints use 600px. Android devices, iPad mini in portrait, and older iPhones in landscape will get neither the mobile nor the desktop layout — they'll render the table at whatever parent width the client assigns.

**`maximum-scale=1` blocks zoom:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
This prevents text zoom in iOS Safari. WCAG 1.4.4 requires text to be resizable up to 200% without assistive technology. Low-vision users are blocked from scaling the content.

**Link color near-invisible from body text:**
```css
a { color: #333333; }
```
`#333333` on a `#ffffff` background passes contrast (12.6:1) but is visually indistinguishable from body text if no underline or weight change is applied. Cannot confirm whether body `<a>` tags have additional visual differentiation without seeing the full HTML.

**Leftover template placeholder comment:**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
"IMPUT" is a typo for "INPUT." This comment shipped in production, indicating the send checklist did not include a template-artifact review. No functional impact, but signals process gap.
