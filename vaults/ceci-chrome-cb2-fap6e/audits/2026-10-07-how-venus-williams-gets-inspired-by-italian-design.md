## Technical Audit

## 1. Technical Summary
The email is built on a Movable Ink-style template with `lang="en"` set and a viewport meta tag, but it has 39 images with no `alt` attribute. The header-level compliance and authentication checks are inconclusive because AgentMail didn't capture the headers, and the truncated HTML and skipped tracking links limit link and UTM verification.

## 2. Link & Tracking Issues
- **77 tracking links were not probed.** The QA tool skipped them as click-redirect domains, so destination validity, redirect chains and 404s are unverified.
- **Per-recipient identifiers sit in image URLs.** `mi_u=56aaa278…` appears on `mi.crateandbarrel.com/p/rp/*.png` and `o.gif`. `dv.crateandbarrel.com/o/65b94b79-…?mi_cid=…&mi_mid=…` is also a dynamic-content endpoint. These are expected for dynamic content, but those images won't render if the MI endpoints fail or are blocked.
- **Five identical `sr.rlcdn.com/448796.gif` pixels** differ only by `&n=1` to `&n=5`. They are third-party LiveRamp pixels, which means five extra third-party requests per open and some privacy exposure.
- No broken links were confirmed. The only HTTP-probed data is the skipped set above.

## 3. Rendering & Accessibility
- **39 images lack alt text** (flagged `[WARN]`):
  - 24 are content images on `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/` and `/m/47/`, such as `bbf6f9d4-…png` and `32ba04b3-…jpg`. If any are linked or carry text, they are inaccessible and blank when images are blocked.
  - 7 are `mi.crateandbarrel.com/p/rp/*.png` images, probably dynamic content, which also lack alt.
  - 1 is `971aa10f-…jpg`.
  - 7 are tracking pixels (`rlcdn` ×5, `o.gif`, `dv.…/o/65b94b79…`). These should carry `alt=""` explicitly.
- **`<meta name="viewport" … maximum-scale=1>`** blocks pinch-zoom, a WCAG 1.4.4 concern.
- **`<title>Crate & Barrel</title>`** has an unescaped `&`, which is invalid under the declared XHTML 1.0 Transitional doctype.
- **Doctype and meta tags are mixed or duplicated.** An XHTML doctype is paired with HTML5 `<meta charset="utf-8">`, and the file has a duplicate charset declaration and three redundant `format-detection` metas.
- **A template placeholder was left in the source:** `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->`.
- **Global rule `p{margin:0 auto; text-align:center}`** is broad and may override paragraph alignment.
- **Overlapping `img` max-width rules:** `@media (min-width:768px){img{max-width:600px}}` is followed by `@media (min-width:640px){img{max-width:640px}}`. Source order means the 640px rule wins at ≥768px, so the 600px rule is dead code.
