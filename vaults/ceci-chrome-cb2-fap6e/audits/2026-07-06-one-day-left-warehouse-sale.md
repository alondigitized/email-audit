# ONE DAY LEFT: Warehouse Sale
**Score:** 7/10 · **Type:** Email audit · **2026-07-06**
## Executive summary

- This is CB2's Warehouse Sale closer — a distinct in-store event with up to 60% off, running in parallel with the online July 4th 50% off sale. The email earns its keep by being structurally honest: two clearly separated sale events, each with its own CTA, so the subscriber knows exactly what they're clicking into. The countdown timer (01:07:25:35) is the emotional engine — with one day left, this is a now-or-never push.
- That said, the email is working harder than it needs to. After a Warehouse Sale standalone send on July 3 and a consolidation email on July 5 that already rolled up all three events, this is the third time subscribers have seen the Warehouse + July 4th stack in 72 hours. The creative is largely recycled — same deep burgundy sofa hero shot, same countdown timer position, same layout. For a genuinely final-day send, the urgency is real but the creative refresh is minimal.
- Judgment: the structure is sound and the offer is legitimate, but the brand is coasting on the same assets at the exact moment it should be escalating creative to drive the last conversions.

## What's working

- **Countdown timer leads** — placed immediately below the nav bar, it establishes time pressure before the subscriber reads a single word of copy.
- **Two-sale architecture is clearly delineated** — Warehouse Sale (60% off, in-store) and July 4th Sale (50% off, online) each get their own block and CTA, avoiding ambiguity.
- **"MORE FOR YOU" personalized product grid** — six product tiles with visible prices anchor the bottom half and give the subscriber somewhere to go beyond a generic homepage link.
- **No render bugs** — clean layout, images load, no overlapping or broken elements visible.
- **Strong discount numbers** — 60% and 50% are both concrete, headline-legible figures.

## What's weak

- **Hero image is repeated creative** — the same dark burgundy sofa has led multiple emails in this sequence; by day eight-plus, it no longer signals "new."
- **Warehouse Sale is in-store only, but that isn't prominent** — the distinction matters hugely to online-only shoppers who may click, bounce, and lose trust.
- **Subject line misses the 60% figure** — "ONE DAY LEFT: Warehouse Sale" buries the best number; a subscriber scanning their inbox has no idea which sale or what the discount is.
- **"More For You" grid product names are illegible at render size** — the six tiles are small enough that price and name require zooming, reducing click pull on mobile.
- **No social proof or urgency on specific items** — given it's the final day, a "low stock" or "selling fast" label on even one product would sharpen urgency meaningfully.

## Recommendations

- 1. **Lead the subject with the deepest discount number** — "ONE DAY LEFT: Warehouse Sale" should be "ONE DAY: Up to 60% Off Warehouse Sale." That one change carries the most lift; it's the only number that's bigger than the online sale.
- 2. **Add explicit in-store callout to the Warehouse block** — a single line ("In-store only · Nearest store →") eliminates confusion and pre-qualifies clickers, reducing bounce.
- 3. **Swap the hero image** — any asset that hasn't been used in this sequence (a rug, a dining set, a lighting piece) reads as fresher than the burgundy sofa that's been in rotation since at least July 3.
- 4. **Add a "selling fast" or "limited quantities" badge to one hero product** — a final-day warehouse email is the single best place for scarcity copy; it's credible here in a way it isn't on a rolling sale.
- 5. **Enlarge the "More For You" tiles or cut to three** — four to six undersized product images compete with each other; three larger tiles with readable prices and names would convert better.
- **Subject Alt A:** `ONE DAY: Up to 60% Off at the Warehouse`
- **Subject Alt B:** `Final hours — Warehouse Sale ends today`
- **Preheader Alt A:** `Up to 60% off in-store + 50% off online. Both end today.`
- **Preheader Alt B:** `Warehouse Sale closes tonight — shop your nearest CB2 store.`

### 3. Rendering & Accessibility

**[CONFIRM]** `maximum-scale=1` in viewport meta:
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
This prevents user zoom on mobile — a WCAG 2.1 SC 1.4.4 violation. Remove `maximum-scale=1`.

**[CONFIRM]** Production template artifact comment left in `<head>`:
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
Typo ("IMPUT" vs "INPUT") and the comment itself confirms this is a dev template placeholder that was never removed before send.

**[CONFIRM]** Double-slash in four font `src` URLs:
```
https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2
https://www.cb2.com//Styles/CB2/fonts/BrownRegular/lineto-brown-regular.woff2
https://www.cb2.com//Styles/CB2/fonts/GTSectra/GT-Sectra-Display-Regular.woff2
```
The double-slash (`//`) after the domain is technically a valid path (servers normalize it), but it is malformed and will generate 301/302 redirects on some CDN configurations. The single-slash variants used elsewhere in the same file are correct.

**[CONFIRM]** Mobile breakpoint is `max-width: 418px`, not the standard `600px`:
```css
@media only screen and (max-width: 418px) { ... }
```
This only triggers responsive styles on very narrow screens (iPhone SE and narrower). Most modern phones (375px–430px CSS width at 2–3× DPR) may or may not hit this depending on device. Should be audited against target device matrix — if intentional, document it.

**[CONFIRM]** `*` selector resets `line-height: 100%` globally:
```css
*{-webkit-text-size-adjust:none; ... line-height: 100%}
```
This will collapse multi-line text in elements that don't explicitly override `line-height`, potentially causing text to overlap in some clients. This is a legacy pattern but carries real rendering risk.
