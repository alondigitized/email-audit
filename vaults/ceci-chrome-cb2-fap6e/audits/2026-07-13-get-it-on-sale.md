# GET IT ON SALE
**Score:** 9/10 · **Type:** Email audit · **2026-07-13**
## Executive summary

- This is CB2's third Summer Edit / 40%-off email in five days — the July 9 launch, the July 11 reprint, and now this. The subject line "GET IT ON SALE" is the weakest of the three: no percentage, no category, no deadline, and it arrives in all-caps, which reads as the brand shouting into an unresponsive inbox. If the July 11 send was a reprint, this is a photocopy of the reprint.
- Inside, the email is competent but diffuse. Five distinct modules stack up — the Summer Edit hero, a design-services pitch, a "New & Best Selling" block, a review contest, and a personalized product grid — and they compete with each other rather than reinforce a single action. A subscriber who didn't convert on July 9 or July 11 isn't going to be moved by the same hero at a lower subject-line quality.
- The brand built serious momentum through the July 4th sale and the July 10 Todd Snyder collab. This send trades on that goodwill without adding anything new. The offer hasn't changed, the creative hasn't changed, and the ask is even blander than before.

## What's working

- The 40% off hero is immediately visible at top — no hunting for the value prop.
- "SHOP THE SALE" is a clean, unambiguous CTA with a visible button.
- The "$5,000 Refresh" design-services block adds a non-sale reason to engage, which the July 11 reprint lacked.
- The "LEAVE US A REVIEW, WIN $1,000" incentive is a smart loyalty angle that differentiates this send from the prior two (even if it gets buried below the fold).
- Photography and brand voice are consistent — no visual breakage or off-brand moments.

## What's weak

- "GET IT ON SALE" is a career-worst subject line from a brand that managed "JUST DROPPED: CB2 x Todd Snyder" three days ago — no %, no category, no urgency, full caps.
- Five competing modules (sale, design services, new arrivals, review contest, personalized recs) means there's no primary CTA — the email asks for everything and emphasizes nothing.
- No visible sale deadline anywhere in the email — the 40% off has no urgency mechanism, so "get it" feels hollow.
- This is the third near-identical Summer Edit email this week; cadence fatigue is actively working against the open rate.
- The "More For You" product grid at the bottom is too small to read at any reasonable render size, making the personalization invisible.

## Recommendations

- 1. **Retire this subject line immediately.** "GET IT ON SALE" adds zero information over the July 11 subject ("UP TO 40% OFF"). If a deadline exists, show it. If it doesn't, invent a category hook: "40% off every rug and light we sell" beats "GET IT ON SALE" on every dimension.
- 2. **Pick one primary module.** Either this is the Summer Edit email or it's the design-services email. Running both in the same send at the same visual weight halves the conversion power of each.
- 3. **Move the review contest up.** "WIN $1,000" is the only fresh hook in this email — it should be in the subject or preview, not buried below the fold as module five.
- 4. **Add an expiry date to the hero.** Even "this week only" beats the current no-deadline 40% off framing, which signals the sale never ends and therefore never requires action.
- **Subject Alt A:** `40% off ends Sunday — furniture, decor, more`
- **Subject Alt B:** `Win $1,000. Shop 40% off. Two reasons to open.`
- **Preheader Alt A:** `The Summer Edit sale is live — and we're giving away $1,000 in reviews`
- **Preheader Alt B:** `Up to 40% off sitewide. Plus: leave a review and win $1,000.`

### 3. Rendering & Accessibility

**`maximum-scale=1` blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents visually impaired users from zooming. WCAG 1.4.4 violation.

**Universal text-size-adjust suppression**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
Applied to all elements, not just `body`. This suppresses OS-level accessibility font scaling globally.

**`line-height: 100%` on universal selector**
```css
* { line-height: 100%; }
```
A percentage line-height on `*` is computed relative to each element's own font size, which collapses line height unpredictably on nested elements. Should be a unitless value (e.g., `1`) or scoped to specific selectors.

**Malformed CSS comment embedding HTML comment syntax**
```css
/* <!-- MI styling starts--> */
```
HTML comment syntax inside a CSS block comment. Technically benign in most parsers but non-conformant and a sign of template injection issues.

**Duplicate `@font-face` declarations for the same family/weight**
Three separate `@font-face` blocks declare `font-family: "Lineto Brown Sub"` — two with `font-weight: 400` — which creates a resolution ambiguity. The first declaration (for `.eot`) lacks a `font-display` property entirely.

**Double-slash in asset URLs**
```css
url("https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2")
```
Double slash after domain appears in 3+ font URL declarations. Most servers normalize this, but it's technically malformed and can fail on strict origin servers or CDN rules.

**`<title>` does not match subject line**
```html
<title>CB2, FURNITURE AND DECOR FOR THE MODERN HOME</title>
```
Subject is "GET IT ON SALE." The `<title>` is a generic brand tagline, not contextually aligned. Used by some email clients in preview/tab display.
