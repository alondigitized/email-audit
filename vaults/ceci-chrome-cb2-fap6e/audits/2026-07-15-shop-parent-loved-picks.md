### 3. Rendering & Accessibility

**[CONFIRMED] `<title>` brand mismatch:**
```html
<title>Crate & Barrel</title>
```
The sending brand is "Crate & Kids" but the `<title>` tag reads "Crate & Barrel". This surfaces in browser-rendered previews and some accessibility readers. Should read `<title>Crate & Kids</title>`.

**[CONFIRMED] Conflicting image `max-width` media queries — 768px rule is dead:**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }  /* declared first */
@media only screen and (min-width: 640px) { img {max-width: 640px} }  /* declared after — overrides at 768px+ */
```
At viewport widths ≥768px, both rules match. Because the 640px rule appears later in the stylesheet at equal specificity, it wins. The 768px/600px constraint is effectively dead. At all widths ≥640px, images are capped at 640px. The 600px desktop rule should be placed after the 640px rule, or both should be consolidated.

**[CONFIRMED] `maximum-scale=1` blocks user zoom:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile — WCAG 2.1 failure (Success Criterion 1.4.4). Remove `maximum-scale=1`.

**[CONFIRMED] Wildcard `text-size-adjust: none` disables OS-level text scaling:**
```css
*{-webkit-text-size-adjust:none;-ms-text-size-adjust:none; ...}
```
Applying `text-size-adjust: none` via `*` overrides user/OS accessibility font scaling for all elements. Replace with `body { -webkit-text-size-adjust: 100%; }`.

**[CONFIRMED] Duplicate `format-detection` meta tags:**
`telephone=no` appears in two separate meta tags; `address=no` appears in two separate meta tags. One consolidated tag is sufficient:
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
```
The duplicates are redundant noise but harmless; remove for cleanliness.

**[CONFIRMED] `.showmobile` fixed width may overflow narrow Android viewports:**
```css
.showmobile { width: 414px !important; }   /* inside @media (max-width: 460px) */
```
On 360px-wide Android devices (common), 414px overflows the viewport by 54px. Should use `width: 100% !important` or `max-width: 414px`.

**[CONFIRMED] No dark mode color-scheme declared:**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
Email declares light-only. If the email contains white text on dark backgrounds or inverse sections, these will render incorrectly in Apple Mail dark mode. Acceptable if the design is confirmed light-only; otherwise add `light dark` and include `@media (prefers-color-scheme: dark)` overrides.
