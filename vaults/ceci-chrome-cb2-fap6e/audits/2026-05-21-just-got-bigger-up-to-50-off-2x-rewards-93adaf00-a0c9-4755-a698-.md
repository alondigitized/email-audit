# JUST got bigger! Up to 50% off + 2x Rewards!
**Score:** 7/10 · **Type:** Email audit · **2026-05-21**
## Executive summary

- This is Crate & Kids' Memorial Day escalation — and it appears to be a subject-line variant (or re-segmented send) of the "Just got BIGGER: Earn 2x Rewards + up to 50% off The Memorial Day Event" email already reviewed today at 8/10. The body creative looks structurally identical: nursery dresser hero, product grid tiles, a Double Rewards callout, a "we love these for you" personalized module, The Design Desk cross-promo, and app download CTA at the bottom.
- The offer is real and the escalation is warranted — 50% off is a genuine ceiling increase from yesterday's 40% — so the email earns its place in the sequence. The layout is clean, hierarchy works (hero → offer → product grid → loyalty → cross-sell), and the brand voice is consistent across every module.
- The drag is cadence. This is at minimum the fourth Crate & Kids / Crate & Barrel email in two days, and the subject is so close to the morning send that a subscriber checking their inbox twice could mistake this for a duplicate. The ALL-CAPS "JUST" is also doing the email no favors — it reads as a shout rather than confidence.

## What's working

- **50% ceiling is front and center** in both subject and hero — the upgrade from 40% is the news and it's stated immediately.
- **Double Rewards module** appears mid-email as a loyalty anchor, rewarding members who scroll.
- **"We love these for you"** personalization block adds relevance without requiring the subscriber to hunt for their category.
- **Design Desk cross-sell** is a soft, value-add close — doesn't feel like another promo push.
- **Clean multi-column product grid** with thumbnails gives visual variety and multiple entry points to click.

## What's weak

- **Subject-line ALL-CAPS "JUST"** reads as a spam signal and cheapens the urgency — the earlier send's title-case "Just got BIGGER" was the stronger execution.
- **Subject is essentially a rewording of the morning send** — a subscriber who opened both will feel the sequence has stalled rather than escalated.
- **No explicit deadline visible in hero** — "Memorial Day" implies Saturday/Monday urgency but no countdown or end-date is visible in the render.
- **CTA buttons ("Shop Now" generic copy)** repeat across every section; a category-specific button ("Shop Nursery," "Shop Rugs") would lift click specificity.
- **The Design Desk cross-promo at the bottom** is borrowed from the standalone send two days ago — it's starting to feel templated rather than intentional.

## Recommendations

- 1. **Merge or suppress this send if the morning version went to the same segment.** The marginal lift from a subject-line variant doesn't justify a fifth email in 48 hours. If this is a separate segment, mark it clearly with a personalization signal in the subject.
- 2. **Add a hard deadline to the hero** — even "Ends Monday" in the badge would convert browsers who need a push.
- 3. **Give each CTA section-specific copy** — "Shop Nursery Furniture," "Shop Rugs," not generic "Shop Now" repeated four times.
- 4. **Drop the ALL-CAPS "JUST"** — the escalation story is strong enough without shouting.
- 5. **Rotate The Design Desk out** — it appeared as a standalone send on 5/20 and is appearing again here; subscribers will tune it out.

### 3. Rendering & Accessibility

**`<title>` brand mismatch — confirmed bug**
```html
<title>Crate & Barrel</title>
```
Sender is "Crate & Kids SALE." Screen readers (NVDA, JAWS, VoiceOver) announce the document title on load — this surfaces the parent brand, not the sub-brand.

**Conflicting `img` max-width media queries — confirmed cascade bug**
```css
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```
The `640px` query is declared *after* `768px`. Both match at ≥768px viewport, so cascade gives `640px` the win on all desktop. The `600px` rule is never applied.

**`maximum-scale=1` blocks user zoom — WCAG 1.4.4 violation**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents mobile users from zooming text. Fails WCAG 2.1 SC 1.4.4 (Resize Text, Level AA).

**`-webkit-text-size-adjust: none` in global `*` selector**
```css
* { -webkit-text-size-adjust: none; ... }
```
Applied globally — overrides the `<body>`-level `100%` value set two rules earlier, and suppresses iOS dynamic type adjustments across all text nodes.

**Duplicate `format-detection` meta tags**
`telephone=no`, `date=no`, and `address=no` each appear in both a combined tag and standalone tags. Harmless, but signals stale template hygiene.

**Unflushed developer placeholder comments in production HTML**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
<!---->
```
The typo (`IMPUT`) confirms this was a fill-in directive, not intentional markup. Both survived to send.
