### 3. Rendering & Accessibility

**Issue — Unfilled template placeholder in production HTML:**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
<!---->
```
This is a build-time authoring comment (note typo: "IMPUT" not "INPUT") shipped to recipients. It is inert but indicates a manual assembly step was not completed or cleaned. Low severity, but confirms the template was not programmatically finalized.

**Issue — `maximum-scale=1` in viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents user-initiated zoom on mobile. WCAG 1.4.4 (Resize Text, Level AA) requires text to be resizable up to 200% without loss of content or functionality. This blocks that entirely on iOS Safari.

**Issue — Aggressive `text-size-adjust` suppression:**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none;}
```
Applied to `*` selector. Overrides OS-level text scaling for visually impaired users. Recommend scoping only to `body` with `100%` instead of `none`.

**Issue — Duplicate `format-detection` meta tags:**
`format-detection` is declared three times — once as a combined value, then individually:
```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```
Redundant; last declarations win in some clients. Consolidate to one tag.

**Issue — Conflicting desktop image max-width media queries:**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
The `640px` query is declared after `768px` in source order. At viewport widths ≥768px, both rules apply; the `640px` query wins by cascade order, capping images at 640px — overriding the intended 600px desktop cap. Reverse declaration order or use a more specific selector for the 600px rule.

**Issue — Dark mode forced off:**
```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```
~30–40% of email opens are in dark mode (Apple Mail, iOS Mail). No dark mode overrides are present in the CSS. Images with white/light backgrounds will appear uncropped and potentially harsh on dark backgrounds.
