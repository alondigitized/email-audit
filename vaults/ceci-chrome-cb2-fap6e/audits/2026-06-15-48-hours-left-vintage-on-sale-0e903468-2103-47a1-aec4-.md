# 48 HOURS LEFT: VINTAGE ON SALE
**Score:** 8/10 · **Type:** Email audit · **2026-06-15**
## Executive summary

- CB2 is running a double-sale email here — "Design Legends Sale, UP TO 20% OFF" as the hero, followed immediately by "Warehouse Sale, UP TO 60% OFF" below. That ordering is backwards. The bigger, more compelling number (60%) is buried under the weaker one (20%), which undermines both offers. The subject leans into the Design Legends "vintage" angle but the body connection to "vintage" is a single subtitle line ("AUTHENTIC VINTAGE REDESIGNS FOR A NEW ERA") — thin thread for a subject hook.
- The June 13 send already announced "ALMOST OVER: Design Legends Sale." Two days later, the sale is still running. That erodes deadline credibility for anyone who opened both. The $1,000 review giveaway module is a smart mid-funnel trust builder, but it lands mid-scroll below two competing CTAs and gets lost.
- Bottom line: the mechanics are all present — urgency, discount, CTA — but the creative choices work against each other. Flip the hero order, lead with 60% off, and this becomes a much stronger send.

## What's working

- **Urgency is front-loaded.** "TWO DAYS LEFT" is the first thing the eye hits — no ambiguity about the clock ticking.
- **Two concrete discount depths visible:** UP TO 20% OFF and UP TO 60% OFF — both specific, neither vague.
- **$1,000 review giveaway** is a differentiated module that most competitors don't run; builds social proof pipeline.
- **"MORE FOR YOU" product grid** gives personalized product browse without requiring a separate send.
- **Clean render** — no broken images, no overlapping text, no obvious layout bugs.

## What's weak

- **60% off is buried below 20% off.** The weaker offer leads the email; the Warehouse Sale — the actual headline value — is the second hero.
- **"VINTAGE ON SALE" in subject is a loose hook.** It refers to the Design Legends vintage-reissue concept, but without context that mapping isn't obvious to a casual inbox scanner.
- **"Design Legends Sale" has been "almost over" since June 13** — two consecutive urgency-close emails on the same sale stretches the deadline's credibility.
- **Both CTAs say "SHOP NOW"** — identical copy for two different destinations; zero differentiation to help intent-matching.
- **No above-the-fold product specificity** — the hero is a lifestyle/editorial shot, not a single product with a name and price anchoring the offer.

## Recommendations

- 1. **Flip the hero order — Warehouse Sale (60% off) first, Design Legends (20% off) second.** The 60% number is the strongest thing in this email. Don't make subscribers scroll past the weaker offer to find it.
- 2. **Make the CTA copy distinct.** "SHOP WAREHOUSE SALE" and "SHOP DESIGN LEGENDS" so each button lands somewhere specific and the two offers feel intentionally curated, not just stacked.
- 3. **Subject: drop "VINTAGE," lead with the real number.** The 60%-off angle is more compelling than the editorial "vintage" frame for a commercial urgency email.
- **Subject Alt A:** `48 HRS: Up to 60% Off in the Warehouse Sale`
- **Subject Alt B:** `Two days left — Design Legends + Warehouse Sale`
- 4. **Anchor one product with name + price in the hero.** Even a single "from $X" price point converts the editorial image into a shopping signal.
- 5. **Preheader should name a specific category or product**, not restate the urgency the subject already covers.
- **Preheader Alt A:** `Sofas, dining, and lighting — all marked down.`
- **Preheader Alt B:** `Shop vintage reissues and warehouse finds before they're gone.`

### 3. Rendering & Accessibility

**Unfilled template placeholder (hard defect)**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
This is a raw production template stub — `IMPUT` is a misspelling of `INPUT`. It indicates the template was sent without completing or removing this placeholder. If a font import was supposed to go here, it was omitted.

**Mobile breakpoint too narrow**
```css
@media only screen and (max-width: 418px) { .mobile { width:414px !important; } }
```
418px only catches devices at exactly iPhone SE width. iPhone 14/15 (390–430px logical width), most Android flagships (360–412px), and many mid-range devices will miss this breakpoint entirely. The standard email mobile threshold is 480px or 600px. Recipients on affected devices get the desktop layout forced into a narrower viewport.

**Double-slash paths in font URLs (broken asset risk)**
Multiple `@font-face` declarations have double forward slashes in the path:
```css
url("https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2")
url("https://www.cb2.com//Styles/CB2/fonts/BrownRegular/lineto-brown-regular.woff2")
url("https://www.cb2.com//Styles/CB2/fonts/GTSectra/GT-Sectra-Display-Regular.woff2")
```
Most web servers normalize `//` to `/`, but this is not guaranteed on all CDN/origin configs. Should be corrected to single slash.

**Cross-brand font CDN dependency**
```css
@font-face { font-family:"HNW05";
  src: url("https://www.crateandbarrel.com/webfonts/1e07d600-3787-4517-bd3d-b140f9e54ec2.woff2")
```
`HNW05` (Helvetica Neue) is loaded from `crateandbarrel.com`, a sibling brand's domain. If that domain's CDN has downtime, blocks cross-origin requests, or the path moves, CB2 email font rendering degrades silently. Should be hosted on CB2's own CDN or a shared brand asset CDN.

**`Lineto Brown Light Sub` missing woff2**
```css
@font-face { font-family: "Lineto Brown Light Sub";
  src: url("https://www.cb2.com/Styles/CB2/fonts/BrownLight/lineto-brown-light.woff"); }
```
Only `.woff` is declared here — no `woff2` format hint. All modern email clients that support web fonts prefer `woff2`. A later duplicate `@font-face` block *does* add `woff2` for weight 400, but the first declaration without a `format()` hint will win in some parsers.

**`maximum-scale=1` blocks zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
`maximum-scale=1` prevents users from pinching to zoom, which fails WCAG 1.4.4 (Resize Text). iOS 10+ ignores this for accessibility, but it is still considered a defect for audit purposes.

**Global `text-size-adjust: none`**
```css
* { -webkit-text-size-adjust:none; -ms-text-size-adjust:none; }
```
Applied to `*` (every element) rather than `body` only. Combined with `maximum-scale=1`, this doubly impairs low-vision users who rely on browser/OS font scaling.
