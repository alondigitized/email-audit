# NEW ITEMS ADDED: Warehouse Sale
**Score:** 8/10 · **Type:** Email audit · **2026-06-17**
## Executive summary

- CB2 played this card four days ago. The June 13 "100+ new items added to Warehouse Sale" was sharp because the angle was fresh; this send is a near-clone of that construction. The execution is competent — 60% off is the dominant headline, the category tiles give fast entry points, and the member-additional-discount line adds real value for subscribers — but the underlying premise is stale the moment a regular subscriber reads the subject line.
- What saves it slightly is the structural diversity inside the email: the "NOT SOLD OUT, YET" re-engagement module and the "MORE FOR YOU" personalization grid give this more depth than a flat sale blast. But those modules can't compensate for an inbox arrival that looks nearly identical to what arrived Tuesday.
- Clear verdict: this is a well-built email suffering from campaign-level decision-making that ran the "new items added" hook one send too soon. A subscriber who converted on June 13 has no new reason to act; a subscriber who didn't has already filtered this pattern out.

## What's working

- **60% OFF is the undisputed hero** — dominant size, high in the email, impossible to miss on mobile before scrolling.
- **Category tiles** (FURNITURE / LIGHTING / DECOR / RUGS / SHOP ALL) are a fast, frictionless entry point that respects the browsing intent of different shoppers.
- **Member-exclusive additional discount line** (visible in green below the hero headline) is genuinely value-additive and gives existing loyalty members a reason to click that non-members don't have.
- **"NOT SOLD OUT, YET"** is a smart inventory-scarcity module — it reframes hesitation from a prior browse session as urgency without being manipulative.
- **"MORE FOR YOU" personalization** at the bottom creates a relevant second click path beyond the category tiles.

## What's weak

- **Exact repeat angle**: "NEW ITEMS ADDED: Warehouse Sale" is structurally identical to June 13's subject — subscribers who noticed that email will feel the repetition immediately.
- **No deadline anywhere in the email** — Warehouse Sale with no close date has nothing tethering urgency to right now. The June 15 "48 HOURS LEFT" earned its 8/10 because it had a clock; this doesn't.
- **ALL CAPS subject prefix** ("NEW ITEMS ADDED") reads like a push notification, not a send you lean into — and it stacks on top of weeks of similar energy.
- **"LEAVE A REVIEW, WIN $1000"** is a loyalty/retention module dropped into a browse-and-buy email mid-scroll — it interrupts purchase intent with an unrelated ask.
- **Design Legends Sale banner at the top** (20% off) sits above the Warehouse Sale hero (60% off), putting the weaker offer first — same backwards hierarchy flagged in the June 15 audit.

## Recommendations

- 1. **Retire "NEW ITEMS ADDED" for at least one send** — you burned the "100+ new items" angle on June 13 and this is its diminished echo. Instead, lead with the category freshest to the drop or a closing deadline: "Last chance: 60% off lighting, chairs + more" lands harder.
- 2. **Add a deadline.** Even "ends Sunday" gives the reader a reason to act today instead of bookmarking. No date = no urgency.
- 3. **Flip the Design Legends / Warehouse Sale order** — if both are present, 60% off leads; 20% off follows as an addendum.
- 4. **Move "LEAVE A REVIEW, WIN $1000"** to a post-purchase trigger, not a mid-browse interrupt.
- 5. **Subject Alt A:** `60% off + fresh finds — Warehouse Sale update`
- 6. **Subject Alt B:** `New lounge chairs, rugs + more: still 60% off`
- 7. **Preheader Alt A:** `New arrivals just hit the sale — member extra savings inside`
- 8. **Preheader Alt B:** `The pieces you saved are still here — and now 60% off`

### 2. Link & Tracking Issues

### 3. Rendering & Accessibility

**[HIGH] Unresolved template placeholder in production HTML:**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
This is a vendor template comment left in the live send. It is misspelled ("IMPUT" → "INPUT") and indicates the font-import slot was never actioned or removed. No functional breakage, but it reveals internal tooling to anyone inspecting source.

**[HIGH] Double-slash path in multiple `@font-face` `src` URLs:**
```css
src: url("https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2")
src: url("https://www.cb2.com//Styles/CB2/fonts/GTSectra/GT-Sectra-Display-Regular.woff2")
```
RFC 3986 treats `//` after the authority as valid but CB2's web server may return 301/404 on the double-slash path depending on IIS/nginx config. If fonts fail to load, the fallback chain (`Helvetica, sans-serif`) kicks in silently — no client-visible error, but brand font rendering is lost.

**[MEDIUM] Conflicting `@font-face` declarations for "Lineto Brown Sub":**
The same `font-family` name is declared three separate times:
1. No `font-weight`/`font-style` descriptors (matches everything)
2. `font-weight: 400` with woff2 only
3. `font-weight: 600` with woff2 only

Declaration 1 has no discriminating descriptors, so it will match all weight requests before declarations 2 and 3 in some rendering engines, making the weight-600 bold variant unreachable. The 400/600 declarations should replace, not supplement, the unqualified declaration.

**[MEDIUM] `maximum-scale=1` in viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents user-initiated zoom. WCAG 1.4.4 (AA) requires content to be resizable up to 200% without loss of content. This fails for low-vision users on iOS Safari.

**[MEDIUM] Global text-size-adjust disabled:**
```css
*{-webkit-text-size-adjust:none;-ms-text-size-adjust:none;}
```
Applied to `*` (every element). This overrides the OS-level text size accessibility setting. Should be scoped to `body` and set to `100%`, not `none`.

**[LOW] Mobile breakpoint width is 418px:**
```css
@media only screen and (max-width: 418px) { .mobile { width:414px !important; } }
```
The breakpoint targets ≤418px but the inner width is hardcoded to 414px. This is clearly written for iPhone 14 (logical width 390px) or older iPhones (375px). Devices between 415–418px wide will enter this media query but get a 414px-wide container that overflows by 0–4px. Typical safe values are `375px` (smallest target) or `390px`.
