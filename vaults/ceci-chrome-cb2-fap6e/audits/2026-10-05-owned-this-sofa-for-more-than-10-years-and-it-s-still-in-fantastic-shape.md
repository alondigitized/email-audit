## Technical Audit

## 1. Technical Summary
The email is a Movable Ink-powered (`mi.crateandbarrel.com`, `dv.crateandbarrel.com`) XHTML-Transitional template. QA passed 57% with 0 errors and 3 warnings, and the main confirmed issue is widespread missing `alt` text. The HTML source was truncated, so the footer, unsubscribe link and UTM parameters could not be inspected.

## 2. Link & Tracking Issues
- **Unverified links:** 68 links were skipped because they use tracking and click-redirect domains. Destination health, redirect chains and 404s are unconfirmed.
- **Repeated third-party pixel:** `https://sr.rlcdn.com/448796.gif?s=56aaa278…&n=1` through `n=5` (a LiveRamp pixel) fires five times with the same `s=` identifier. One call would do the job, and each extra call adds a request and a privacy surface.
- **Identifier in image URLs:** the `mi.crateandbarrel.com/p/rp/*.png?mi_u=56aaa278…` and `…/o.gif?mi_u=…` URLs carry a long per-recipient identifier. This is normal for Movable Ink, but those images will break if the MI render service is slow or blocked.
- No broken links were confirmed.

## 3. Rendering & Accessibility
- **Missing alt text:** about 35 images are flagged with no `alt` attribute.
  - **Content images:** about 19 look like content, for example `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/*.jpg`/`.png`/`.gif`, including `14417eb4-…gif`, and the scene7 image `2026_0716_CB_UphBestsellers_CTV_REMIX`. Where images are blocked, readers get no fallback.
  - **Dynamic images:** seven `mi.crateandbarrel.com/p/rp/*.png` images (`560d850e7e517ede.png`, `789e7381ff44be74.png` and others) are dynamically rendered and likely carry content. They too are missing `alt`.
  - **Tracking pixels:** these should carry `alt=""` explicitly so screen readers skip them. They are the 5× `rlcdn.com` GIFs, `o.gif` and `dv.crateandbarrel.com/o/0b799024-…`.
- **Pinch-zoom blocked:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` stops users from zooming, which is an accessibility problem (WCAG 1.4.4).
- **Unescaped ampersand:** `<title>Crate & Barrel</title>` under an XHTML 1.0 Transitional doctype should be `&amp;`. It is harmless in most clients but invalid.
- **Duplicate meta tags:** `format-detection` is declared three times (`telephone=no,address=no,…`, `date=no`, `address=no`, `telephone=no`). Both `http-equiv` Content-Type and `<meta charset>` are present.
- **Conflicting breakpoints:** `@media (min-width:768px){img{max-width:600px}}` appears before `@media (min-width:640px){img{max-width:640px}}`. At 768px and wider both match and the later rule wins, so the 600px cap never applies.
- **Template leftover:** the comment `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->` was never removed, and there is an empty `<!--[if !mso]><!--> <!--<![endif]-->` block.
- **Global resets:** `p{margin:0 auto; text-align:center}` and `*{line-height:100%}` are global resets that can cause inconsistent text spacing in some clients.

## 4. Personalization & Merge Tokens
- **Merge tokens:** none were found in the visible HTML, and no unrendered tokens (`{{…}}`, `%%…%%`) were seen. The truncated section is unchecked.
- **Dynamic content:** personalization appears to be delivered through `mi_u` on the Movable Ink image URLs, which is working as designed.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` not found [WARN]:** the QA note says the AgentMail relay may be stripping it. This is unconfirmed, so treat it as unknown rather than a sender fault.
- **`List-Unsubscribe-Post` not found [WARN]:** the RFC 8058 one-click header is also missing, with the same relay caveat. Gmail and Yahoo bulk-sender rules expect it.
- **`Authentication-Results` not found [WARN]:** SPF, DKIM and DMARC status is unknown for the same reason. The sender domain is `mail.crateandbarrel.com`.
- **Footer:** the visible footer, with its physical address and unsubscribe link, falls past the truncation point and could not be checked.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- UTM parameters and landing URLs could not be verified. The 68 tracked links were not probed and the source was truncated.
- Image assets are hosted across three origins: `image.mail.crateandbarrel.com`, `s7d5.scene7.com` and `mi.crateandbarrel.com`.
- One hero asset path contains `2026_0716` (July 16), while the email arrived 2026-10-05. This is probably a reused CTV asset, but it is unconfirmed.

## 7. Recommendations
1. Add descriptive `alt` text to all content images, including the seven dynamic `mi.crateandbarrel.com/p/rp/*.png` ones. Set `alt=""` on tracking pixels.
2. Remove `maximum-scale=1` from the viewport meta tag.
3. Dedupe the `rlcdn.com` pixel from five calls to one.
4. Escape the ampersand in the `<title>`, consolidate the duplicate `format-detection` and charset meta tags, and fix the min-width media query order.
5. Strip the leftover template comments from the HTML.
6. For the QA pipeline, capture raw headers (`List-Unsubscribe`, `List-Unsubscribe-Post`, `Authentication-Results`) from the original message instead of the relayed copy. Also use the full HTML so the footer, unsubscribe link and UTMs can be checked.
