# Now showing: FX’s “The Bear” x Crate & Barrel
**Score:** 8/10 · **Type:** Email audit · **2026-06-18**
## Executive summary

- This is the most strategically interesting Crate & Barrel email in the recent run — and that bar has been low. After six warehouse-sale and clearance emails in eight days (including two near-identical "up to 60% off" sends on June 17 alone), a co-branded FX collaboration that arrives with zero discount language is a deliberate palate cleanser. The Bear x Crate & Barrel is a high-credibility match: the show's professional kitchen aesthetic and Crate & Barrel's chef-grade cookware assortment are genuinely complementary, not forced.
- The execution is mostly solid. The hero is dark, moody, and on-brand for The Bear's visual language — colanders, pans, and that lived-in professional kitchen feel. The scroll unfolds a logical sequence: hero → collection highlights → secondary product grid → lifestyle close. That cadence respects editorial storytelling instead of throwing twelve CTAs at the viewer immediately.

For a subscriber who has been trained by Crate & Barrel's recent warehouse-sale cadence to expect a deal, the absence of one creates a small but real conversion gap. The email earns attention; it just doesn't harvest it efficiently.

- **No commercial hook.** No discount, no limited-quantity signal, no deadline — makes it a brochure, not a conversion email.

### 3. Rendering & Accessibility

**Template placeholder comment left in production:**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
Typo ("IMPUT" vs "INPUT") and the empty comment `<!---->` immediately after confirm this is a development artifact that was not cleaned before send. Harmless to rendering but exposes internal tooling conventions.

**Versioning artifact exposed:**
```html
<!--V2-->
```
Visible at line 1 of the body — internal template version tag not stripped before production send.

**`maximum-scale=1` in viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents user zoom on mobile — WCAG 2.1 SC 1.4.4 (Resize Text) failure. Zoom suppression is a documented accessibility defect; remove `maximum-scale=1`.

**Duplicate `format-detection` meta tags:**
Three separate `<meta name="format-detection">` declarations appear (combined, then telephone-only, then address-only, then date-only). Redundant; last declaration wins in most parsers. Not a rendering defect, but indicates copy-paste template slippage.

**Duplicate charset declaration:**
```html
<meta http-equiv="Content-Type" content="text/html; charset=utf-8" />
<meta charset="utf-8">
```
Both present — redundant but not harmful. Standard practice is one or the other for HTML email.

**Conflicting `img` `max-width` media queries:**
```css
@media only screen and (min-width: 768px) { img {max-width: 600px} }
@media only screen and (min-width: 640px) { img {max-width: 640px} }
```
Both target `img` with the same specificity. At ≥768px, both rules match and cascade order gives `max-width: 640px` (the later declaration) precedence over the `600px` rule, making the 768px breakpoint effectively a no-op. If 600px was intentional for desktop, the rule order must be reversed.

**`-webkit-text-size-adjust: none` applied universally:**
```css
*{-webkit-text-size-adjust:none; ...}
```
The `*` selector targets all elements including anchor and button text. On iOS, this can prevent system-level text resizing for users with accessibility settings enabled. Should be scoped to `body` only.
