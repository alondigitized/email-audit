# Dining chairs, elevated
**Score:** 7/10 · **Type:** Email audit · **2026-06-09**
## Executive summary

- CB2 is systematically marching through furniture categories this week — sofas on June 8th ("We found you the perfect sofa"), dining chairs on June 9th. The category logic is sound: if you just bought or browsed a sofa, you're likely thinking about the whole room. The creative, however, doesn't lean into that narrative. "Dining chairs, elevated" reads like a merchandising tag, not an editorial statement. Compare it to June 8th's "THE HUNT IS OVER" hero framing or June 6th's "*This* is midcentury" — this email is noticeably flatter in voice.
- The email is visually competent: clean CB2 aesthetic, good product photography, clear hierarchy. The hero chair (an olive/forest green velvet round-back) photographs beautifully and the grid of SKUs below gives the subscriber real browsing options. Nothing is broken; nothing is embarrassing.
- But "elevated" is one of the most overworked words in retail marketing right now, and CB2 is better than that. The email functions — it does not inspire. After six sends in four days, a subscriber who opened every one of them needs more than category merchandising to click.

- Product grid below the hero gives immediate browsing options without requiring a click to the PDP first.
- Visual hierarchy is clean — eye moves top to bottom without confusion; no competing focal points.
- CB2's minimal design language is consistent and lends authority; the brand doesn't look like it's discounting under pressure.

## What's weak

- "Elevated" in the subject is generic and tired — it could belong to any furniture brand, any category, any season.
- No urgency visible in the render — the Midseason Sale has been running for days; there's no deadline copy to close the loop.
- The sofa-to-dining-room narrative arc (June 8th → June 9th) goes unexploited — the body copy doesn't acknowledge the room-building story.
- Cadence is punishing; this is the seventh-plus CB2 email in four days, and the email makes no acknowledgement that the offer is worth the subscriber's attention right now.

- 4. **Add a best-seller or "X sold this week" flag to at least one product tile.** Social proof is absent across the entire email; even a single badge would add click pull.

### 3. Rendering & Accessibility

**[HIGH] Unfilled production template comment with typo**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
"IMPUT" is a typo for "INPUT." This is a template artifact that was never removed before send. No functional breakage, but signals the build was not cleaned before production.

**[HIGH] `maximum-scale=1` blocks zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom. This fails WCAG 1.4.4 (Resize Text) and is flagged by accessibility validators.

**[MEDIUM] Global text-size-adjust disabled**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```
Applied to the `*` selector, this overrides OS-level font scaling for users with vision needs. Should be scoped to `body` only and set to `100%`, not `none`.

**[MEDIUM] Mobile breakpoint too narrow**
```css
@media only screen and (max-width: 418px) { .mobile { width:414px !important; } }
```
iPhone 15 Pro Max renders at 430px CSS width in portrait; this breakpoint will not fire on current flagship devices. The `width:414px` inner value also assumes an older 414px layout width. Should be raised to `max-width: 480px` or use `600px` as the standard email threshold.

**[LOW] Conflicting global line-height**
```css
*{ line-height: 100%; }
```
Setting `line-height: 100%` globally on `*` collapses line spacing to 1.0× the font size everywhere. This can make multi-line text illegible unless overridden on every individual element. Renders fine in most email clients that strip `*` selectors, but risky in Gmail/web views.

**[MEDIUM] Cross-brand font asset loading**
```css
@font-face { font-family:"HNW05"; src: url("https://www.crateandbarrel.com/webfonts/...") }
```
Four `HNW05` `@font-face` rules load assets from `crateandbarrel.com`, not `cb2.com`. If Crate & Barrel's CDN applies CORS restrictions or the asset path changes, these fonts silently fail in CSS-supporting clients. Fallback fonts (`Arial`, `Helvetica`) will render instead — low visual risk but a latent dependency.

**[LOW] Double-slash in CB2 font URLs**
```css
src: url("https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2")
```
Three `@font-face` declarations use `cb2.com//Styles/` (double slash). Most web servers normalize this, but it is technically a malformed URL and can return 301 redirects or 404s depending on server config. The single-slash declarations elsewhere in the same block are correct.

**[LOW] Duplicate/inconsistent `@font-face` for "Lineto Brown Sub"**
Three separate `@font-face` blocks declare the same family name. Two of them assign `font-weight: 400`, creating a duplicate entry. Browser/client font resolution for this weight is non-deterministic.
