# THE FURNITURE EVENT IS ON
**Score:** 5/10 · **Type:** Email audit · **2026-07-23**
## Executive summary

- CB2 is back with another sale-anchor email, but this one has a named event — "THE FURNITURE EVENT" — which gives it slightly more editorial lift than the generic "ENDS TODAY" sends from July 22. The hero is a dark, moody room vignette with "40% OFF" stamped large in the center, followed by rugs, a rewards loyalty module, and a personalized "MORE FOR YOU" product grid. The structure is competent but the creative is nearly identical to the drumbeat CB2 has been sending all week. After the editorial reprieve of "THINGS OF QUALITY" and "EXPERT DESIGN, ON US," going back to the heavy discount banner format feels like a step backward in brand equity.
- The loyalty module (Reward Dollars that add up faster, 10% back, 7% back tiers) is a genuine differentiator and lands in a natural mid-scroll position. But the overall impression is: CB2 found a working template and is running it into the ground. A subscriber who got the July 22 double-send has now seen this exact visual register three times in two days.
- Judgement: solid execution of a tired format. The event naming is the one incremental upgrade worth noting.

## What's working

- **Named event framing** — "THE FURNITURE EVENT IS ON" gives the sale a reason-to-exist that pure "ENDS TODAY" urgency lacks.
- **40% OFF hero is impossible to miss** — large, high-contrast type on a dark background; offer reads instantly.
- **Loyalty rewards module** — tiered 10%/7% back breakdown with "No annual fee" is specific and trust-building; visible without heavy scrolling.
- **Rugs secondary section** — "NEW & BEST SELLING RUGS" adds a second category entry point beyond the hero sale.
- **Personalized product grid** — "MORE FOR YOU" at the bottom shows some segmentation effort.

## What's weak

- **Creative déjà vu** — visually indistinguishable from the July 22 "UP TO 40% OFF ENDS TODAY" and "Hours left for up to 40% off" sends; a subscriber on a fresh context window might not open at all.
- **No deadline visible** — "THE EVENT IS ON" tells me it started, not when it ends; the July 22 emails had "ENDS TODAY" urgency that is now absent.
- **Subject line is vague** — "THE FURNITURE EVENT IS ON" is generic; no discount quantum, no deadline, no specific hook.
- **Dark hero crop is tight** — the room vignette reads as mostly shadow; the actual product being sold (specific furniture) is not identifiable.
- **Rugs CTA is the only text button visible** — "SHOP NOW" under the rugs section is a generic verb with no noun anchor.

## Recommendations

- 1. **Add the discount + deadline to the subject** — "40% off furniture ends Sunday" does three jobs the current subject doesn't.
- 2. **Show one hero SKU by name** — anchor the dark vignette to a specific sofa or dining table with a name and price; the hero currently sells the sale, not a product.
- 3. **Give the rugs CTA a noun** — "SHOP RUGS" beats "SHOP NOW" every time for click clarity.
- 4. **Move the loyalty module higher** — Reward Dollars are a retention tool; they should appear above the fold or immediately below the hero, not mid-scroll.
- 5. **Rest the sale-banner creative for at least one cycle** — the editorial register of "THINGS OF QUALITY" outperformed on brand equity; alternating would protect both.

- **Subject Alt B:** `Sofas, dining, rugs: up to 40% off now`
- **Preheader Alt A:** `Shop the furniture event before it ends — plus earn up to 10% back in Reward Dollars`

## Technical Audit — CB2 "THE FURNITURE EVENT IS ON"

### 1. Technical Summary

Table-based XHTML 1.0 Transitional email with MSO/VML conditional comment blocks and a custom web font stack. Several template hygiene issues and one confirmed accessibility violation are present in the visible HTML; full link/compliance analysis is limited by the truncated source.

---

### 2. Link & Tracking Issues

**Cross-domain font dependency** — Four `@font-face` declarations load assets from `https://www.crateandbarrel.com/webfonts/` (a separate domain from `cb2.com`). If that domain has a CDN hiccup or DNS issue, the `HNW05` font family degrades silently. No fallback font is specified in the `a {}` rule that would match `HNW05`.

**Double-slash URLs** — Three font `src` values contain a double slash:
```
https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2
https://www.cb2.com//Styles/CB2/fonts/BrownRegular/lineto-brown-regular.woff2
https://www.cb2.com//Styles/CB2/fonts/GTSectra/GT-Sectra-Display-Regular.woff2
```
Most servers normalize this, but it is a defect in the template. Click-tracking URLs and UTM parameters cannot be audited from the truncated source.

---

### 3. Rendering & Accessibility

**`maximum-scale=1` in viewport meta (WCAG 1.4.4 violation):**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
This prevents pinch-to-zoom for users with low vision. Apple Mail and some Android clients honor this attribute.

**Global text-size-adjust suppression:**
```css
* { -webkit-text-size-adjust: none; -ms-text-size-adjust: none; }
```
Applied to every element — not just specific problematic nodes. This compounds the zoom issue above and can trigger WCAG 1.4.4 failures in audit tools.

**`@font-face` conflict — three declarations for the same family name:**  
`"Lineto Brown Sub"` is declared three times: once with no weight/style descriptor (loads only `.woff`), once as `font-weight: 400` (`.woff2`), and once as `font-weight: 600` (`.woff2`). The unscoped first declaration may override the weight-specific ones in older clients.

**`font-display: swap` in email `<style>` block:**  
This CSS property is ignored by virtually all email clients. It has no effect here and adds dead code.

**Narrow breakpoint — `max-width: 418px`:**  
The responsive block targets 418px and hardcodes `.mobile { width: 414px }`, which is iPhone 6/7/8-specific. Devices wider than 418px but narrower than the desktop layout (~690px) receive no responsive treatment.

**Unremoved template placeholder:**
```html
<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->
```
"IMPUT" is a misspelling of "INPUT." This comment is a template artifact that was not cleaned before send. It is inert but indicates the template was not fully audited pre-deployment.
