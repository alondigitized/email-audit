## Technical Audit

## 1. Technical Summary
The HTML is a table-based XHTML Transitional template with Outlook/MSO fallbacks, but about 60 images have no alt text and the viewport meta tag blocks pinch-zoom. Header-based compliance and authentication checks couldn't be verified, and all 106 links are behind click-redirect domains, so none were probed.

## 2. Link & Tracking Issues
- **Unverifiable links:** QA skipped HTTP probes on all 106 links because they use tracking or click-redirect domains. Destination status, redirect chains and final URLs are unverified.
- **Third-party pixel repeated 5 times:** `https://sr.rlcdn.com/448796.gif?s=…&n=1` through `&n=5` appear as five separate 1x1 images. These are LiveRamp (rlcdn) pixels, each missing alt text. Repeated identical beacons add image requests and third-party data sharing.
- **Other beacons:** `https://mi.crateandbarrel.com/p/up/50c75a732e99b42a/o.gif?mi_u=…` and `https://dv.crateandbarrel.com/o/8bca5247-…?mi_cid=…&mi_mid=…` are open-tracking and view pixels with no alt attribute.
- **Per-recipient ID in image URLs:** the `mi_u=` parameter is on the `mi.crateandbarrel.com/p/rp/*.png` images (7 images). These are dynamic per-recipient images, so they won't render if the recipient's client blocks images.

## 3. Rendering & Accessibility
- **Missing alt text, about 60 images (confirmed by QA):**
  - Content images on `image.mail.crateandbarrel.com/lib/fe9013727564027a7c/m/1/*.jpg` and `.gif`, such as `5e9468a1-…jpg` and `c65ab55e-…gif`, and the hero `image.mail.crateandbarrel.com/…/m/47/bbf6f9d4-…png`.
  - The animated hero on `s7d5.scene7.com/is/content/Crate/00_Email/2026/11_Core/2026_1104_CB_GiftGuide/…hero_V2-ezgif.c…`.
  - The 7 dynamic `mi.crateandbarrel.com/p/rp/*.png` images.
  - Without alt text, the email is unreadable with images blocked and for screen readers. If these images carry the product or offer content, that information is lost.
- **Zoom disabled:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` prevents pinch-zoom, which fails WCAG 1.4.4 (resize text).
- **Text-size override:** the universal `*{-webkit-text-size-adjust:none; … line-height:100%}` rule disables user text scaling in WebKit clients. It also forces `line-height:100%` globally.
- **Conflicting `img` max-width rules:** `@media (min-width:768px){img{max-width:600px}}` is followed by `@media (min-width:640px){img{max-width:640px}}`. Both match at 768px and wider, and the later rule wins, so the 600px rule never applies.
- **Template leftovers:**
  - Unfilled placeholder comment `<!--[IMPUT HERE CLIENT FONT IMPORT SCRIPT if needed]-->` (typo included).
  - Duplicate `format-detection` meta tags.
  - Redundant `Content-Type` and `charset` metas.
  - Empty MSO `td,th,div,p,a { }` rule.
  - These are harmless but show an unpruned template.
- **Title tag:** `<title>Crate & Barrel</title>` uses an unescaped `&` under an XHTML doctype (should be `&amp;`). It is also a generic title rather than the subject line.
- **Animated GIF:** the hero filename (`…-ezgif.c…`) suggests an animated GIF. The truncated source doesn't show an MSO first-frame fallback, so Outlook desktop behavior is unverified.

## 4. Personalization & Merge Tokens
No issues found. The truncated source shows no unrendered merge tokens (`{{…}}`, `%%…%%`, `[FNAME]`). The only per-recipient values are the `mi_u`/`mi_cid`/`mi_mid` tracking IDs, which are populated.

## 5. Compliance
- **`List-Unsubscribe` header not found (WARN)** and **`List-Unsubscribe-Post` (RFC 8058) not found (WARN)**. QA notes the AgentMail relay may strip these headers, so this is unconfirmed. If they are really absent, the email doesn't meet Gmail and Yahoo bulk-sender one-click unsubscribe requirements.
- **`Authentication-Results` not found (WARN):** SPF, DKIM and DMARC alignment are unknown, because the relay doesn't expose the header. The From domain is `mail.crateandbarrel.com`.
- **Body unsubscribe link and physical address:** the footer is beyond the truncation point, so these couldn't be verified.

## 6. Email-to-Site Continuity
Unverifiable. All 106 links go through redirect domains and were not resolved, so UTM parameters, landing-page alignment and the final destinations for the hero and product links can't be confirmed. The truncated source shows no raw `crateandbarrel.com` destination URLs or UTM parameters.

## 7. Recommendations
1. Add descriptive `alt` to all content images, starting with the hero and product tiles. Add `alt=""` to the tracking pixels (`rlcdn`, `o.gif`, `dv.` beacon).
2. Remove `maximum-scale=1` from the viewport meta, and drop `-webkit-text-size-adjust:none` from the `*` selector.
3. Deduplicate the five `rlcdn` pixels, or confirm each is needed.
4. Fix the `img` max-width conflict and escape the `&` in `<title>`.
5. Re-run the QA against raw headers, not the AgentMail relay copy. This would confirm `List-Unsubscribe`, `List-Unsubscribe-Post` and `Authentication-Results` (SPF/DKIM/DMARC).
6. Follow the redirect chains in a separate check with the 106 links, to verify destination status and UTM parameters.
7. Re-run the audit on the full HTML. The truncation hides the footer (unsubscribe, address) and the link destinations.
