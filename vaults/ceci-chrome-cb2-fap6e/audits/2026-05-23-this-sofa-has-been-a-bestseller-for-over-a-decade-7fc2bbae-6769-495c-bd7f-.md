### 3. Rendering & Accessibility

**CSS cascade conflict — desktop image breakpoint is dead code**

```css
/* line ~120 */
@media only screen and (min-width: 768px) { img { max-width: 600px } }
@media only screen and (min-width: 640px) { img { max-width: 640px } }
```

The `640px` rule appears *after* the `768px` rule in the stylesheet. For any viewport ≥ 768px, both rules match and the later `640px` declaration wins due to CSS cascade order. The `768px` rule (`max-width: 600px`) is effectively unreachable. Images will render at `640px` max on all desktop clients, never `600px` as intended.

**Viewport zoom lock — WCAG 1.4.4 failure**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

`maximum-scale=1` prevents user-initiated zoom. This violates WCAG 2.1 Success Criterion 1.4.4 (Resize Text, Level AA). Modern iOS Safari ignores this in some contexts, but Android browsers enforce it.

**No dark mode support**

```html
<meta name="color-scheme" content="light">
<meta name="supported-color-schemes" content="light">
```

Dark mode clients (Apple Mail, Outlook on iOS) will force-invert or auto-adjust colors with no vendor-provided overrides. This is a rendering risk, not a bug per se, but intentionally declaring `light`-only without corresponding dark mode CSS rules means no controlled fallback.

**Duplicate `format-detection` declarations**

```html
<meta name="format-detection" content="telephone=no,address=no,email=no,date=no,url=no">
<!-- later: -->
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="telephone=no">
```

Three attributes from the first tag are re-declared as standalone tags. Harmless but indicates template hygiene issues (see item 4).

**Global `line-height: 100%` via `*` selector**

```css
*{ ... line-height: 100%; }
```

Applying `line-height: 100%` universally can clip descenders on tight line heights and interferes with client-side font scaling. Should be scoped to `p, td, span` rather than the universal selector.
