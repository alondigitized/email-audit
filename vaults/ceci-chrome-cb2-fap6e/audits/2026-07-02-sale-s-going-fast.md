# SALE’S GOING FAST
**Score:** 8/10 · **Type:** Email audit · **2026-07-02**
## Executive summary

- "SALE'S GOING FAST" is CB2's urgency pivot — after four-plus announcement sends ("Up to 50% off furniture," "MORE ADDED TO SALE," "New items added. One week left to shop."), this email is meant to trigger FOMO before the July 4th window closes. The strategic logic is sound: announcement → expansion → urgency is a textbook sale sequence. The execution is solid but not surprising. The body headline "IT'S SELLING FAST / Up to 50% OFF!" mirrors the subject almost word-for-word, which feels like a wasted creative handoff — the subject creates the hook, the hero is supposed to cash it. Instead it just echoes.
- The visual package is clean: a moody dark-green hero with a velvet accent chair, category shortcuts (OUTDOOR, FURNITURE, LIGHTING, DECOR, TABLETOP), a warehouse callout (up to 60% off), and a personalized "MORE FOR YOU" product grid below the fold. The template is CB2's standard sale shell — recognizable, well-rendered, no visible bugs. The "MORE FOR YOU" row is the most differentiated element; it's doing real segmentation work and is the only thing that doesn't feel like copy-paste from the last four sends.
- The problem is cadence. This is at minimum the fifth CB2 email since June 29, and likely the third in two days. By the time "SALE'S GOING FAST" lands, a real subscriber has already seen "GOING FAST" logic from the prior "One week left" send. The urgency is losing its teeth.

## What's working

- **Subject-to-body alignment is tight.** "SALE'S GOING FAST" → "IT'S SELLING FAST" is a deliberate echo; the creative team clearly wrote these together.
- **Dual-offer structure is effective.** 50% off up front, 60% warehouse callout lower — the secondary offer rewards anyone who keeps scrolling.
- **Category grid shortcut navigation** (OUTDOOR, FURNITURE, LIGHTING, DECOR, TABLETOP) is a consistent CB2 pattern that genuinely accelerates click-to-category routing.
- **"MORE FOR YOU" personalized product row** is the standout differentiator — specific items, individual product cards, presumably linked directly. This is the email's highest-signal click driver.
- **Visual hierarchy is clean.** Hero → CTA → categories → warehouse → personalized — the eye follows a clear path without fighting the layout.

## What's weak

- **The subject sacrifices specificity for drama.** "SALE'S GOING FAST" contains no offer percentage, no product category, no deadline date — compared to the July 1 "MORE ADDED TO SALE" send (scored 9/10 in this session), it's a step backward in informational density.
- **Hero headline repeats the subject instead of advancing it.** "IT'S SELLING FAST / Up to 50% OFF!" could have revealed what specifically is selling fast — a category, a hero product, the number of items remaining. It doesn't.
- **Urgency is crying wolf at this point.** After five sends in four days, this is at least the second time CB2 has implied inventory is running low. Real subscribers know the sale extended; "going fast" doesn't sting.
- **The apostrophe in "SALE'S" reads slightly off** — it scans as "Sale is going fast" which is grammatically fine, but in a brand context where every word is set in ALL CAPS, the contraction feels like a rough draft rather than polished retail voice.

## Recommendations

- 1. **Put a specific signal of depletion in the subject.** "Sizes selling out" or "X styles left" beats vague urgency every time. The hero could then validate it with a countdown or low-stock badge on a specific hero item.
- 2. **Break the hero-repeats-subject pattern.** If the subject is urgency ("SALE'S GOING FAST"), the hero should give the reader the next piece of information — the concrete number (50% off), the category, or a time deadline ("Sale ends July 4 at midnight").
- 3. **Surface a specific hero product in the lead image**, not just a lifestyle vignette. The green velvet chair is gorgeous but unnamed; linking it to a PDP would capture high-intent readers who opened because of that visual.
- 4. **Restructure "MORE FOR YOU" above the warehouse block.** Personalized picks have higher click intent than a generic warehouse callout; right now the warehouse cuts the page flow before the personalized content lands.
- **Subject Alt A:** `Selling out: up to 50% off ends July 4`
- **Subject Alt B:** `Final days — your picks are going fast`
- **Preheader Alt A:** `Warehouse styles up to 60% off — grab yours before they're gone`
- **Preheader Alt B:** `The chair you've been eyeing? Still available. For now.`

**Issue 1 — Template development comment left in production output**

This is an unremoved ESP template placeholder (also misspelled: "IMPUT" vs "INPUT"). It is inert but signals the build process didn't strip dev comments before send.

**Issue 2 — Narrow mobile breakpoint likely misses many devices**
```css
@media only screen and (max-width: 418px) { .mobile { width:414px !important; } }
```
The 418 px ceiling targets iPhone SE (375 px) but will miss common Android viewports (360–412 px wide) that exceed 418 px. The fluid/responsive styles inside this block won't activate on those devices.

**Issue 3 — `maximum-scale=1` blocks pinch-to-zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Disabling zoom is a WCAG 1.4.4 (Resize Text) violation and affects users with low vision.

**Issue 4 — Double forward slashes in font URLs**
```css
src: url("https://www.cb2.com//Styles/CB2/fonts/BrownLight/lineto-brown-light.woff2")
```
Three `@font-face` blocks use `//` in the path segment (e.g., `cb2.com//Styles/`). Most servers normalize this, but it is technically malformed and can fail on strict CDN/proxy configs.

**Issue 5 — Cross-domain font loading (cb2.com + crateandbarrel.com)**
The `HNW05` font family loads from `crateandbarrel.com` while branded CB2 fonts load from `cb2.com`. If either domain's CORS policy or CDN config changes, font fallback silently activates.

**Issue 6 — Aggressive global `*` reset**
```css
* { -webkit-text-size-adjust:none; -ms-text-size-adjust:none; max-height:1000000px; mso-line-height-rule:exactly; line-height:100% }
```
Applying `line-height:100%` globally via the `*` selector overrides any element-specific line-height and can collapse multi-line text blocks in clients that don't have more-specific rules set.
