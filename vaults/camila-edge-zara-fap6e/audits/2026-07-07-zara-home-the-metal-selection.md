### 3. Rendering & Accessibility

**`line-height: auto` is invalid CSS.**
```css
.heightmobile { height: auto!important; line-height: auto!important; }
```
`auto` is not a valid value for `line-height`. Valid values are `normal`, a unitless number, or a length. Clients that reject invalid declarations will silently drop this rule; text spacing on mobile will be uncontrolled.

**`<div>` wrapping a `<tr>` is invalid HTML.**
```html
<div style="mso-hide:all;">
  <tr>
    <td ...>
```
A `<tr>` cannot be a child of a `<div>` — it must be a direct child of `<table>`, `<thead>`, `<tbody>`, or `<tfoot>`. Strict parsers (and some Outlook versions) will eject the `<tr>` from the table context, breaking the layout block this is intended to hide.

**Viewport meta uses semicolons as separators.**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
The spec requires comma-separated properties. Most clients tolerate semicolons, but this is non-compliant and may fail in stricter parsing environments.

**`user-scalable=no` blocks zoom.** This is an accessibility violation (WCAG 1.4.4 — Resize Text). Users with low vision cannot zoom the email on mobile.

**Google Fonts `<link>` tag will be stripped by all major clients.** Gmail, Outlook (all versions), Apple Mail on older iOS, and Yahoo all strip or ignore `<link rel="stylesheet">` in email. Roboto Condensed will never load. No web-safe fallback stack is visible in the truncated CSS — if the body copy relies on this font with no fallback, rendering will fall to the client default (typically Arial or Times).

**`.banner95` class has mismatched width.**
```css
.banner95 {width: 97%!important; ...}
```
The class name declares 95% but applies 97%. Minor, but causes layout confusion when debugging.

**Duplicate `.bot40` rule.** The media query defines `.bot40 {padding-bottom: 40px!important;}` twice. No conflict, but dead code.
