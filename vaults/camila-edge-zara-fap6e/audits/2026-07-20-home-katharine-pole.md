### 3. Rendering & Accessibility

**Confirmed issues:**

**[HIGH] `user-scalable=no` in viewport meta**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
Prevents pinch-to-zoom. Fails WCAG 1.4.4 (Resize Text, Level AA). iOS Mail and some Android clients may also partially ignore this, causing inconsistent rendering.

**[MEDIUM] Invalid CSS: `line-height: auto`**
```css
.heightmobile { height: auto!important; line-height: auto!important; }
```
`auto` is not a valid value for `line-height`. Valid values are `normal`, a unitless number, a length, or a percentage. Behavior is undefined across clients — some will ignore it, others may collapse the element.

**[MEDIUM] Block element (`<div>`) wrapping table row (`<tr>`) in preheader**
```html
<!--[if !mso 9]><!-->
<div style="mso-hide:all;">
  <tr>
    <td ...>
```
A `<div>` directly wrapping a `<tr>` is invalid HTML. Browsers and email clients in standards mode will error-correct unpredictably — most will hoist the `<tr>` out of the `<div>` or drop it. This is the preheader row; a rendering failure here can cause the preheader text to appear in the body or disappear entirely.

**[LOW] Viewport meta uses semicolons as separators**
```html
content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;"
```
The spec requires commas. Most clients accept semicolons, but it is non-conformant and a latent risk on strict parsers.

**[INFO] `line-height: 100%` on `.ExternalClass *`**
```css
.ExternalClass * {line-height: 100%;}
```
Standard Outlook/Hotmail reset — correct and expected.
