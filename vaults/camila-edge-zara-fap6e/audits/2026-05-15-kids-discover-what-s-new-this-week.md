# Kids | Discover what's new this week
**Score:** 6/10 · **Type:** Email audit · **2026-05-15**
## Executive summary

- This is Zara's second Kids email in five days — May 10 sent "Kids | SUMMER CAMP" and here we are again with a pure editorial grid of summer children's looks, zero pricing, and no promotional hook. The photography is clean and seasonally coherent (beach/summer palette, bright colors, natural light), but the formula is now visibly on repeat. ## What's weak

- **Zero shopping CTA in the body** — the only button visible is "DOWNLOAD OUR APP," which is an acquisition ask, not a conversion tool for someone already reading your email.
- **No prices anywhere** — not even a "starting from" anchor. For a parent deciding whether to browse, this is a hard wall.
- **Second kids email in five days** — May 10's "SUMMER CAMP" send was almost structurally identical. Cadence fatigue is real and this does nothing to differentiate.
- **Fragmented grid, no hero product** — eight-plus images compete equally; the eye has no obvious first stop and no single item is given editorial priority.

### 2. Link & Tracking Issues

### 3. Rendering & Accessibility

**Viewport meta: semicolons used as delimiters (spec violation)**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
The `content` attribute of `<meta name="viewport">` requires comma-separated key-value pairs, not semicolons. Some WebKit-based clients may parse this incorrectly, breaking responsive layout. Fix: replace `;` with `,`.

**`user-scalable=no` + `maximum-scale=1.0` — WCAG 1.4.4 failure**
Both properties disable pinch-to-zoom, which is a Level AA accessibility failure affecting users with low vision. Remove both properties; the responsive CSS already handles layout at `max-width: 640px`.

**External Google Fonts stylesheet will be blocked by most clients**
```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700&display=swap&subset=cyrillic,cyrillic-ext" rel="stylesheet">
```
Gmail (web and app), Outlook (all versions), and Yahoo strip or block `<link>` tags. Roboto Condensed will silently fall back to the system sans-serif stack in the majority of the audience. This is low-severity if the fallback stack is acceptable, but the stylesheet load is wasted and adds a DNS lookup. Either inline the `@font-face` declarations (where supported) or remove the `<link>` entirely.

**Invalid `line-height: auto` in CSS**
```css
.heightmobile { height: auto!important; line-height: auto!important; }
```
`auto` is not a valid value for `line-height`. This declaration will be ignored by all compliant CSS parsers. Remove it to avoid confusion; no functional replacement is needed since `line-height` inherits correctly without it.

**Structurally invalid preheader markup — `<tr>` outside `<table>`**
```html
<!--[if !mso 9]><!-->
<div style="mso-hide:all;">
  <tr>
    <td ...>
```
A `<tr>` is a direct child of a `<div>`, which is invalid in both HTML and XHTML. Browsers recover silently, but this can cause unpredictable rendering in older email clients. The preheader content should be wrapped in its own `<table role="presentation">`.
