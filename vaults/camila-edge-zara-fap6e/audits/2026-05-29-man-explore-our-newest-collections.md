### 3. Rendering & Accessibility

**Google Fonts via `<link>` tag** — blocked by Gmail (strips `<link>` from `<head>`), Outlook (all versions), and Apple Mail on iOS in some configurations. The fallback stack is not declared alongside the `font-family: Roboto+Condensed` reference, so affected clients will fall back to the system sans-serif silently.
```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700&display=swap&subset=cyrillic,cyrillic-ext" rel="stylesheet">
```

**Invalid CSS — `line-height: auto`** in `.heightmobile`:
```css
.heightmobile { height: auto!important; line-height: auto!important; }
```
`auto` is not a valid value for `line-height`. Will be ignored by all parsers; if this class is applied to text rows, mobile line-height will fall back to browser/client default, potentially collapsing or expanding spacing.

**Malformed MSO conditional + div nesting** — the preheader block opens with:
```html
<!--[if !mso 9]><!-->
<div style="mso-hide:all;">
<tr>
  <td ...>
```
A `<div>` wraps a `<tr>` outside a `<table>` context. Technically invalid; most clients coerce this, but the MSO conditional is targeting the wrong precedence (should be `<!--[if !mso]>`) and the div is never shown to be closed in the visible source.

**`viewport` meta uses semicolons as delimiters** — spec requires commas:
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
Most modern clients tolerate this but it is non-conformant and can break on stricter parsers.
