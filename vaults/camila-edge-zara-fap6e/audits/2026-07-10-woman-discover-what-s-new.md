### 3. Rendering & Accessibility

**Critical — invalid table structure in preheader:**

```html
<table role="presentation" width="640" ...>
  <!--[if !mso 9]><!-->
  <div style="mso-hide:all;">
    <tr>
      <td ...>
```

A `<div>` is not a valid child of `<table>`. Per the HTML spec, browsers will eject the `<div>` (and its `<tr>` subtree) out of the table into the surrounding flow, breaking the intended layout. This affects all standards-mode renderers (Apple Mail, Gmail webview, Samsung Mail). Correct fix: wrap the conditional block in `<tbody>` or restructure the preheader outside the `<table>`.

**Google Fonts load will silently fail in most clients:**

```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700&display=swap&subset=cyrillic,cyrillic-ext" rel="stylesheet">
```

Gmail, Outlook (all versions), and Yahoo block external CSS. The font will fall back silently — not a breakage, but the declared typeface never renders for the majority of recipients.

**`viewport` meta uses semicolons, not commas:**

```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;">
```

The spec requires comma-separated values. Semicolons are tolerated by most clients but technically non-conformant.

**`user-scalable=no` blocks pinch-to-zoom** — fails WCAG 1.4.4 (Resize Text, Level AA). Users with low vision cannot zoom the email on mobile.

**Preheader padding technique uses invisible Unicode characters (`&#8199;&#847;`)** — this is a common pattern but some spam filters penalize it (Postmaster Tools, SpamAssassin rules). No confirmed deliverability issue here, just a flag.

**`IE=edge` meta is dead weight** — IE is EOL; harmless but can be removed.
