# Back in stock: Selected pieces
**Score:** 7/10 · **Type:** Email audit · **2026-05-14**
## Executive summary

- This is quintessential Zara: cold, editorial, confidence bordering on indifference. The hero shot (a woman in a red military jacket at a marina) is striking, and the 8-product grid below is clean and correctly styled. The "back in stock" hook carries real native urgency — these items sold out once, implying they'll sell out again — but Zara does almost nothing to activate it. No prices, no product names, no countdown, no threshold ("only 3 left"). The email hands you the reason to act and then refuses to close.
- The grid itself is coherent: military cropped jackets in red, white, black, and olive paired with wide-leg striped and polka-dot trousers. It reads like a capsule drop, not eight random restocked SKUs. That's good curation. What kills momentum is the complete absence of a product CTA anywhere in the body — clicking requires you to assume every image is a link, which many recipients won't.
- Overall: Zara's brand holds the email together, but this is a missed conversion opportunity. The message earns an open; it doesn't earn a click.

## What's working

- **Hero image commands attention immediately** — editorial quality, strong red color blocking, clearly Zara's aesthetic.
- **"Back in stock" framing is the right hook** — implies scarcity without fabricating it.
- **Product curation is coherent** — four jacket colorways + coordinating bottoms reads as a curated capsule, not a clearance dump.
- **Layout is clean with zero render bugs** — images load, grid aligns, no broken elements visible.
- **Subject line under 30 chars** — mobile-friendly, no truncation risk.

## What's weak

- **No prices anywhere in the email** — for a back-in-stock message where someone may be on the fence, price is the deciding detail.
- **No product names** — items are labeled "01" through "08" with no text descriptor; this is style over function to a fault.
- **No product-level CTA button** — the only explicit CTA is "DOWNLOAD OUR APP" in the footer; there's nothing pulling the reader toward a product page.
- **Zero urgency mechanism beyond the premise** — no stock count, no deadline, no "selling fast" copy to reinforce the scarcity signal.
- **"Selected pieces" in the subject is frustratingly vague** — subscribers who don't open will have no idea what category or style they're missing.

## Recommendations

- 1. **Add prices under each product image** — single highest-impact change; turns browsing into buying intent.
- 2. **Add a "Shop Now" button per row or per product** — at minimum, a single above-fold CTA button so the click path is unambiguous.
- 3. **Name the products** — replace "01–08" labels with a one-line product name; aids SEO and sets expectation on click.
- 4. **Inject a stock signal** — even "Limited quantities" in small caps beneath each item would activate the back-in-stock urgency that the subject implies.
- 5. **Move "Download our app" to last** — currently it's the only CTA above the legal footer; it competes with (and wins against) the product intent.

### 3. Rendering & Accessibility

**A. Invalid HTML structure in preheader block (confirmed)**

```html
<div style="mso-hide:all;">
  <tr>
    <td ...>
```

A `<div>` directly wrapping `<tr>` is invalid HTML. `<tr>` must be a child of `<tbody>`, `<thead>`, or `<tfoot>`, which must be inside a `<table>`. Some clients (particularly older Outlook via Word renderer) will either collapse or misplace this row, potentially breaking the preheader padding or causing a phantom gap at the top of the email.

**B. `user-scalable=no` in viewport meta (confirmed)**

```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```

Prevents pinch-to-zoom on mobile. Violates WCAG 1.4.4 (Resize Text, Level AA). Should be removed or replaced with `user-scalable=yes`.

**C. Viewport meta uses semicolons as separators (confirmed)**

The `content` attribute above uses semicolons (`;`) instead of the spec-required commas (`,`). Most mobile clients are tolerant of this, but it is non-conformant and can silently fail in stricter parsers.

**D. Missing `lang` attribute on `<html>` element (confirmed)**

```html
<html xmlns="http://www.w3.org/1999/xhtml">
```

No `lang="en"` declared. Screen readers default to the OS language setting rather than the document's intended language. Required for WCAG 3.1.1 (Language of Page).

**E. Invalid CSS value — `line-height: auto` (confirmed)**

```css
.heightmobile { height: auto!important; line-height: auto!important; }
```

`line-height: auto` is not a valid CSS value (valid values: `normal`, unitless number, length, or percentage). All CSS parsers will ignore this declaration silently, meaning the rule has no effect. If a specific line-height was intended for mobile, this needs to be corrected.

**F. Google Fonts will not render in Gmail or Outlook (confirmed)**

```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700&display=swap&subset=cyrillic,cyrillic-ext" rel="stylesheet">
```

- Gmail (webmail and Android app) strips all `<link>` tags from `<head>`.
- Outlook (all desktop versions) ignores web font declarations entirely.
- Combined, these two clients represent the majority of Zara's likely US send volume. The Roboto Condensed fallback to system fonts will silently activate for most recipients with no visual parity guarantee.
- Additionally, the `cyrillic,cyrillic-ext` subset is loaded for a `US_en` audience — this is unnecessary payload (adds ~20–30 KB to the CSS request) and suggests the template was reused from a multi-region variant without stripping locale-specific resources.
