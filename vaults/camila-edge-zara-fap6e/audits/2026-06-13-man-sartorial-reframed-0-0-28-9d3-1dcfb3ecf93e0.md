### 3. Rendering & Accessibility

**Invalid HTML: `<div>` as direct parent of `<tr>`**
```html
<div style="mso-hide:all;">
  <tr>
    <td ...>
```
A block `<div>` cannot legally wrap a `<tr>` outside a `<table>`. Most clients silently repair this, but Outlook's Word renderer may drop the row entirely or misapply the `mso-hide` rule.

**Malformed MSO conditional comment**
```html
<!--[if !mso 9]><!-->
```
Standard syntax is either `<!--[if !mso]><!-->` (exclude all MSO) or `<!--[if mso 9]>` (target MSO 9). The space between `!mso` and `9` is not a valid conditional expression; Outlook will treat this as an unrecognized condition and may ignore or expose the wrapped block.

**Viewport `user-scalable=no`**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
Disabling pinch-zoom fails WCAG 1.4.4 (Resize Text) and is blocked outright on iOS 10+. This directive has no protective benefit in email and should be removed.

**Viewport meta uses semicolons, not commas**
The `content` attribute separates properties with `;` instead of `,`. Technically malformed per the HTML spec; most mobile clients parse it anyway, but it should be corrected.

**`<html>` element missing `lang` attribute** — No `lang="en"` (or locale equivalent) is present on the root element. Screen readers will default to the OS language rather than the content language.

**Alt text on images** — Not verifiable from truncated source; flagged for manual check.
