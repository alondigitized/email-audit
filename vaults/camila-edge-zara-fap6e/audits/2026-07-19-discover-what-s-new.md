### 3. Rendering & Accessibility

**`user-scalable=no` in viewport meta** — accessibility violation.
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
Prevents pinch-to-zoom. Violates WCAG 1.4.4 (Resize Text, Level AA). Remove `user-scalable=no` and `maximum-scale=1.0`.

**Viewport `content` attribute uses semicolons, not commas** — technically malformed per the HTML spec. Most browsers are tolerant, but `maximum-scale` may be ignored in strict parsers:
```
content="width=device-width; initial-scale=1.0; ..."
                            ^                  ^
                       should be commas
```

**Invalid DOM structure — `<div>` wrapping `<tr>` outside `<td>`:**
```html
<div style="mso-hide:all;">
  <tr>
    <td ...>
```
A `<div>` is not a valid parent for `<tr>`. Browsers will silently correct this but behavior varies across email clients, particularly older Outlook versions that use the Word rendering engine.

**Malformed MSO conditional comment:**
```html
<!--[if !mso 9]><!-->
```
Standard syntax is either `<!--[if !mso]><!--` (hide from all Outlook/Word) or `<!--[if gte mso 9]>` (target Outlook 2000+). `!mso 9` is not a recognized conditional expression and will be ignored by Outlook, potentially breaking the preheader hiding logic.

**Google Fonts external dependency** — render-blocking in clients that allow external CSS (Apple Mail, some webmail). Clients that block external resources (Gmail Android, many corporate environments) will silently fall back — acceptable, but the Cyrillic subset is loaded regardless of recipient locale:
```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700&...&subset=cyrillic,cyrillic-ext" ...>
```
