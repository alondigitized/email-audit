# Adizero Dropset Pro is ready to race
**Score:** 5/10 · **Type:** Email audit · **2026-07-05**
## Executive summary

- This is a product-launch email for the Adizero Dropset Pro — a training shoe engineered for speed and stability — but it lands with almost none of the energy a shoe launch deserves. The hero is a text block on white: "SPEED AND STRENGTH." No product shot. No athlete. No visual of the Dropset Pro itself. For a shoe positioned on performance credentials (LIGHTSTRIKE PRO, energy rods, dynamic stability), the absence of the product is a fundamental miss.
- What makes it worse is the second act: a full-blown "SUMMER SAVINGS — 30% OFF FOR THE SEASON" block with code SAVE. That's the same summer clearance promotion adidas ran on June 30 ("First chance to dive into 30% off"). Bolting a sitewide discount onto a product launch email collapses the hierarchy entirely — you can't tell if this email is about the Dropset Pro or about summer deals. A reader who just opened for the shoe has to mentally separate two unrelated messages.
- Verdict: a weak launch send. The copy is fine, the offer is familiar, but there's no product imagery to sell the shoe and no reason this particular email had to exist today.

## What's working

- **Subject line is product-specific and concrete** — "Adizero Dropset Pro is ready to race" is unusually direct for adidas and immediately tells the subscriber what's inside.
- **Tech copy is present** — LIGHTSTRIKE PRO and energy rods are named in the body, which gives performance buyers something to latch onto.
- **30% off is a clean, credible offer** — code SAVE, clearly stated, same mechanic as June 30 so existing subscribers already know it works.
- **No render bugs** — layout is clean, text doesn't overlap, no broken images.

## What's weak

- **No product image of the Dropset Pro** — the hero is white text on white background; the shoe is never shown.
- **30% sitewide deal dilutes the launch** — this is the exact same promotion from July 30; stacking it here makes the launch feel like a promotional hook rather than a genuine product moment.
- **CTAs are generic** — "SHOP NOW" and "FIND THE STORE" don't reference the Dropset Pro; clicking either lands you on a general page, not the shoe's PDP.
- **No athlete, no social proof, no performance context** — a training shoe lives and dies on aspiration and credibility; neither is present visually.
- **"Exclusively apply." fine print** — visible but vague; a subscriber can't tell what's excluded from the sale.

## Recommendations

- 1. **Lead with a hero shot of the Dropset Pro on-foot** — any lifestyle or in-gym image of the shoe. The text "SPEED AND STRENGTH" earns nothing without the product behind it.
- 2. **Make the primary CTA product-specific** — "SHOP ADIZERO DROPSET PRO" instead of "SHOP NOW." Link directly to the PDP.
- 3. **If you're going to include the 30% offer, subordinate it** — move the SUMMER SAVINGS block below the fold as a secondary message, not a co-equal hero. Right now it competes with the launch.
- 4. **Add one performance credential visually** — a stat, a weight, a comparison chart. "Lighter than X. Stronger than Y." — something a training buyer can anchor on.
- 5. **Replace "FIND THE STORE" with a sizing/availability call-to-action** — performance buyers check stock before going in-store; give them the inventory link.

## Technical Audit

## Technical Audit — adidas "Adizero Dropset Pro" Email

### 1. Technical Summary

The email is built on a standard HTML 4.01 Transitional table layout with adidas's `comms.adidas.com` ESP infrastructure and a Movable Ink-style personalization layer (`dv.adidas.com`). QA surfaced one broken link, a missing plain-text fallback, six HTTP image sources, and two images without alt text — all actionable before the next send.

---

### 2. Link & Tracking Issues

**[FAIL] Broken relative URL**

One link resolves to an unknown/relative path instead of an absolute URL:

```
unknown url type: '/g/05a27910-cfba-4abf-a4b6-5de3da645671?txn=90412c80-7816-11f1-be57-d2520cded5b8'
```

The outer tracking shell (`https://dv.adidas.com/o/05a27910...`) resolved, but the inner destination path `/g/...` is relative — no host. If the click-redirect passes this as a final URL, the recipient lands on a broken page. This needs an absolute URL (`https://www.adidas.com/...`) as the destination.

**[INFO] 29 tracking links skipped**

All CTA links route through `click.comms.adidas.com` redirects. These were not probed by QA. Confirm they resolve correctly in a pre-flight click test, particularly any links sharing the broken `txn` parameter above.

**[INFO] `no-referrer` meta tag present**

```html
<meta name="referrer" content="no-referrer">
```

This suppresses the HTTP `Referer` header on any link click that opens in a browser context. Landing-page analytics and some A/B testing tools rely on referrer for attribution. Not always an issue (ESP click-tracking captures the click), but confirm with analytics team.

---

### 3. Rendering & Accessibility

**[FAIL] 6 images loaded over HTTP (not HTTPS)**

The same arrow icon is served via HTTP six times:

```
http://image.link.adidas.com/lib/fe6515707c62007e7715/m/3/b0c011a2-d468-414b-a8a2-8595b3ec7b34.jpg
```

Gmail (with image proxying via `googleusercontent.com`) and Apple Mail with "Load Remote Images" policies may block or flag mixed-content HTTP images. The ESP CDN at `image.link.adidas.com` almost certainly supports HTTPS — switch the `src` scheme.

**[FAIL] Tracking pixel served over HTTP**

```
http://click.comms.adidas.com/CI0/0102019f30085985-4f8bc414-3b69-4442-b08c-f26c5ef5820c-000000/...
```

Open-tracking pixel is also HTTP. Same mixed-content risk, and some clients will suppress it entirely.

**[WARN] 2 images missing `alt` text**

- Personalization/dynamic image: `dv.adidas.com/o/05a27910-cfba-4abf-a4b6-5de3da645671`
- Open-tracking pixel: `click.comms.adidas.com/CI0/...`

The tracking pixel intentionally has no alt (correct), but the dynamic content image should carry a descriptive `alt` attribute for screen readers and image-blocked environments.

**[INFO] Custom fonts fall back to local system fonts only**

Both `AdihausDIN` and `AdineuePRO` are declared with `local()` sources only — no remote web font URLs. This is intentional for email (avoids CORS and load latency), but the brand-specific typefaces will never render; all clients fall back to Arial/Helvetica. Expected behavior for this setup.

The personalization layer appears to use opaque `dv.adidas.com` tokens resolved server-side at send time, which is correct. The `mi_cid` and `mi_mid` parameters in tracking URLs confirm Movable Ink personalization is active.

No issues found based on available source.

### 5. Compliance (CAN-SPAM / RFC 8058)

**[WARN] `List-Unsubscribe` and `List-Unsubscribe-Post` headers not confirmed**

QA did not capture these headers via the AgentMail relay — likely a relay inspection gap rather than a missing header in actual delivery. However:

- `List-Unsubscribe` is required for Gmail bulk sender compliance (>5k/day threshold) and Yahoo/Google sender policy enforcement effective Feb 2024.
- `List-Unsubscribe-Post` (RFC 8058) enables one-click unsubscribe in Gmail and Apple Mail — required for bulk senders under the same policy.

Verify that both headers are present in actual delivered mail headers (`Authentication-Results`, `List-Unsubscribe`, `List-Unsubscribe-Post`) using a seed inbox test (e.g., Litmus, Mail Tester, or a raw IMAP header dump).

**[WARN] SPF/DKIM authentication status unknown**

`Authentication-Results` header was not captured. The sending domain `us-news.comms.adidas.com` should have SPF and DKIM configured. Confirm with a seed send to a Gmail address and inspect headers for:

```
Authentication-Results: ... spf=pass ... dkim=pass
```

**[INFO] Physical address and unsubscribe link**

CAN-SPAM requires a physical postal address and a functional unsubscribe mechanism in the email body. These are standard adidas footer elements — present based on the footer CSS classes (`.mobile-footer-padding-block`, `.net-footer-logo-v2`), but confirm the unsubscribe link in the footer is functional.

### 6. Email-to-Site Continuity

The `/g/05a27910-cfba-4abf-a4b6-5de3da645671` destination does not resolve. Any recipient clicking that specific CTA reaches a dead end — the product landing page does not load.

**[INFO] UTM parameter coverage unverified**

All 29 click links pass through `click.comms.adidas.com` which strips the raw URL. QA did not follow the redirect chain. Confirm that final landing URLs carry consistent UTM parameters (`utm_source=email`, `utm_medium=...`, `utm_campaign=...`) to ensure GA4/Adobe Analytics attributes revenue to this send.
