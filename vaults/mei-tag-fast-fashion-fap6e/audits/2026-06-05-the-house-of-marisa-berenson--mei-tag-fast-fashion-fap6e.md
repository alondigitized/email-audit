- **Marisa Berenson is not a TikTok moment.** She's a reference point for fashion historians, not for someone who just aged into their mid-20s. ASOS would have anchored the same editorial inspiration to something I've actually seen in the wild — they did it with "Summer pieces everyone's wearing" and at least named the trend.

### 3. Rendering & Accessibility

**[HIGH] Structurally invalid HTML — `<tr>` outside `<table>`**
The preheader block wraps a `<tr>` element inside a `<div>`, not inside a `<table>/<tbody>`:
```html
<div style="mso-hide:all;">
  <tr>
    <td align="center" height="0" width="0" class="hiddenmobile">
```
A `<tr>` is only valid as a child of `<tbody>`, `<thead>`, `<tfoot>`, or `<table>`. Certain email clients (Yahoo Mail, older Samsung Mail) will attempt to repair this by ejecting the `<tr>` from the `<div>`, which can break layout or duplicate content.

**[MEDIUM] External Google Fonts `<link>` tag — will not load in major clients**
```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700&display=swap&subset=cyrillic,cyrillic-ext" rel="stylesheet">
```
Gmail (web and Android), Outlook (all Windows versions), and Samsung Mail block or ignore external `<link>` stylesheets. The font will silently fall back to the client's default sans-serif. Additionally, the `subset=cyrillic,cyrillic-ext` parameter loads unnecessary character sets for a US/en send, adding latency to clients that do render it (Apple Mail, iOS).

**[MEDIUM] Invalid CSS value: `line-height: auto`**
```css
.heightmobile { height: auto!important; line-height: auto!important; }
```
`auto` is not a valid value for `line-height`. Valid values are `normal`, a unitless number, a length, or a percentage. This declaration will be silently dropped by all CSS parsers, meaning intended mobile line-height resets for `.heightmobile` elements will not apply.

**[LOW] Duplicate CSS rule: `.bot40` defined twice**
```css
.bot40 {padding-bottom: 40px!important;}  /* line ~85 */
...
.bot40 {padding-bottom: 40px!important;}  /* line ~93 */
```
Functionally a no-op since both declarations are identical, but indicates a copy-paste error in the responsive stylesheet block.

**[LOW] Viewport meta uses semicolons instead of commas**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
The viewport meta specification requires comma-separated values. Semicolons are widely tolerated but technically non-conformant. More critically, `user-scalable=no` blocks zoom on mobile — an accessibility concern (WCAG 1.4.4 Resize Text).
