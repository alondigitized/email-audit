### 3. Rendering & Accessibility

**Issue 3a — Invalid div nested inside table (HIGH)**
```html
<!--[if !mso 9]><!-->
<div style="mso-hide:all;">
  <tr>
    <td ...>
```
A `<div>` cannot be a direct child of `<table>` (outside `<td>`/`<th>`). This is malformed markup. Gecko and WebKit browsers auto-correct it by moving the div outside the table, which breaks the intended MSO hide logic and may cause layout drift in Gmail web, Apple Mail, and Samsung Mail. The correct pattern is to wrap the `<tr>` in `<!--[if !mso]><![endif]-->` conditional comments instead.

**Issue 3b — Viewport meta uses semicolons as separators (MEDIUM)**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;">
```
The HTML spec requires commas as separators for viewport content values. Some parsers (notably older Android WebView) may misparse semicolon-delimited values, breaking responsive scaling on those clients.

**Issue 3c — `user-scalable=no` violates WCAG 1.4.4 (MEDIUM)**
The `maximum-scale=1.0; user-scalable=no` combination prevents users from pinching to zoom. This fails WCAG 2.1 Success Criterion 1.4.4 (Resize Text) and is blocked by iOS 10+ Safari regardless, making the directive both an accessibility violation and a no-op on the most common mobile client.

**Issue 3d — Invalid CSS value on `.heightmobile` (LOW)**
```css
.heightmobile { height: auto!important; line-height: auto!important; }
```
`auto` is not a valid value for `line-height`. Valid values are `normal`, a unitless number, a length, or a percentage. Browsers interpret this as `normal`, but it may produce unexpected behavior in Outlook for iOS and should be corrected to `line-height: normal`.

**Issue 3e — External Google Fonts blocked by major clients (LOW)**
```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700&display=swap&subset=cyrillic,cyrillic-ext" rel="stylesheet">
```
Gmail (web and Android), Outlook (all desktop versions), and Yahoo Mail block external `<link>` stylesheets. Roboto Condensed will silently not load for the majority of recipients. This is an accepted limitation of email rendering, but if brand-accurate typography is required, embed the critical `@font-face` declarations inline in `<style>` instead.
