### 3. Rendering & Accessibility

**CONFIRMED ISSUE — Missing `@font-face` for `FuturaPT-DemiBold`:**
```css
/* declared */
@font-face { font-family: "FuturaPT-Book"; ... }
@font-face { font-family: "FuturaPT-Heavy"; ... }

/* referenced in rule — NO declaration exists */
h1, h2, h3 { font-family: 'FuturaPT-DemiBold', Futura, Arial, sans-serif; }
```
All `<h1>`–`<h3>` elements will render in `Arial` (or `Futura` if locally installed), not the intended DemiBold weight. Add the missing `@font-face` block or alias the rule to `FuturaPT-Heavy`.

**MINOR — Legacy SVG font format included:**
Each `@font-face` block includes `format("svg")`. SVG fonts have been unsupported since iOS 9 (2015) and add unnecessary payload size to the `<head>`.

**MINOR — Mobile breakpoint at `460px`:**
```css
@media screen and (max-width: 460px) { ... }
```
Gmail on Android and some older email clients render at a 480px viewport. Responsive styles will not trigger for that window of devices (460px–480px). Standard safe breakpoint is `480px` or `600px`.

**MINOR — Dual preheader divs:**
```html
<div style="display: none; mso-hide: all;">We've got styles for every setting…</div>
<div style="display: none; mso-hide: all;">&nbsp;&zwnj;&…</div>
```
The second `<div>` (zero-width non-joiners for inbox padding) is a known technique, but some aggressive spam filters flag multiple `display: none` blocks. Confirm this is intentional preheader stuffing, not an authoring error.
