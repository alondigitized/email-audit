- Men's Collection AND Kids Collection blocks are still here — same complaint I had after the FIFA send, the Caramel London send, literally every send. This is a segmentation problem and it keeps breaking the vibe.

### 3. Rendering & Accessibility

**Issue — Google Fonts loaded via `<link>` tag (blocked in most clients):**
```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700&display=swap&subset=cyrillic,cyrillic-ext" rel="stylesheet">
```
Gmail, Outlook (all versions), and Yahoo strip external `<link>` tags. The font will silently fall through to the browser/system default. Either accept this (if system fallbacks are defined) or load via `@import` inside `<style>` — though `@import` support is also limited. Confirm fallback stack is acceptable.

**Issue — `user-scalable=no` in viewport meta (WCAG 1.4.4 violation):**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
Prevents pinch-to-zoom on mobile. Fails WCAG 1.4.4 (Resize Text, Level AA). Remove `user-scalable=no` and `maximum-scale=1.0`.

**Issue — Invalid CSS value `line-height: auto`:**
```css
.heightmobile { height: auto!important; line-height: auto!important; }
```
`auto` is not a valid value for `line-height` (valid values: `normal`, unitless numbers, lengths, percentages). Replace with `line-height: normal !important`. Some clients may ignore the entire rule or behave unpredictably.

**Issue — Preheader suppressed for Outlook:**
```html

<div style="mso-hide:all;">

</div>
```

Both the MSO conditional comment and `mso-hide:all` prevent Outlook from rendering this node. Outlook's preview pane will fall through to the first visible body text instead. If the first visible body content is an image (likely, given this layout), Outlook users will see no preview text or an image filename.
