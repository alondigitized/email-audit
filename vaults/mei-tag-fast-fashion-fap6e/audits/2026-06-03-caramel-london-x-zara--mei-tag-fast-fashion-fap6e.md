### 3. Rendering & Accessibility

**`user-scalable=no` in viewport meta (confirmed issue)**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0;
  maximum-scale=1.0; user-scalable=no;" />
```
Prevents pinch-zoom on mobile. This violates WCAG 1.4.4 (Resize Text, Level AA) and is an accessibility defect. Remove `maximum-scale=1.0; user-scalable=no;`.

**Semicolon-delimited viewport attributes (minor)**
The `viewport` meta uses semicolons as attribute separators instead of commas. The HTML spec requires commas. Most parsers tolerate this, but it is non-standard and should be corrected.

**Malformed table structure in preheader (confirmed issue)**
A `<div>` is used as a direct child of `<table>`, wrapping a `<tr>`:
```html
<table ...>
  <div style="mso-hide:all;">   ← invalid: div inside table
    <tr>
      <td ...>preheader text</td>
```
A `<div>` cannot be a direct child of `<table>`. Browsers will often self-correct, but Outlook and strict-mode clients may misrender or drop the preheader. The `mso-hide` conditional should be applied with `<!--[if !mso]><!--> ... <!--<![endif]-->` wrapping the `<tr>` directly, not a `<div>` wrapping the `<tr>`.

**Google Fonts external load**
```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700
  &display=swap&subset=cyrillic,cyrillic-ext" rel="stylesheet">
```
- Gmail, all Outlook versions, and Apple Mail with "Block Remote Content" will not load this font. System fallback stack takes over — this is expected behavior for email, but verify the fallback is acceptable.
- The `cyrillic,cyrillic-ext` subset is included for a `US_en` targeted send. This is unnecessary and adds ~25–40 KB of payload to the font request.

**CSS class name mismatch (minor)**
```css
.banner95 { width: 97%!important; ... }
```
Class is named `banner95` but applies `width: 97%`. This is a naming inconsistency that will not cause a rendering error but creates maintenance confusion.
