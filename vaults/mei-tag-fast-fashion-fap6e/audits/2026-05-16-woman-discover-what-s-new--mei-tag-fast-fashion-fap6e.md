### 2. Link & Tracking Issues

### 3. Rendering & Accessibility

**Invalid DOM structure in preheader block:**
A `<tr>` is placed as a direct child of a `<div>`:
```html
<div style="mso-hide:all;">
  <tr>
    <td ...>preheader text</td>
  </tr>
```
`<tr>` must be a descendant of `<table>/<tbody>/<thead>/<tfoot>`. Browsers and email renderers in strict mode will auto-repair this by promoting or dropping the row, potentially surfacing the preheader text into the visible body or suppressing it entirely.

**Google Fonts `<link>` tag will be stripped:**
```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700..." rel="stylesheet">
```
Gmail strips all `<link>` tags. Outlook ignores external CSS entirely. Yahoo blocks third-party stylesheets. Roboto Condensed will silently fall back to the client's default serif/sans — verify the fallback stack in body copy `font-family` declarations (not visible in the truncated source).

**`user-scalable=no` in viewport meta:**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
Disabling pinch-zoom violates WCAG 2.1 SC 1.4.4 (Resize Text). Remove `user-scalable=no` and `maximum-scale=1.0`.

**Viewport meta uses semicolons as delimiters** instead of commas. Technically malformed per spec; most mobile clients parse it correctly, but it is a latent risk with stricter parsers.

**Preheader zero-width padding technique:**
```html
&#8199;&#847; &#8199;&#847; ...
```
Uses HAIR SPACE (U+200F) + COMBINING GRAPHEME JOINER (U+034F) as padding to prevent body text from bleeding into the preheader preview. Fragile: some clients (Samsung Mail, newer Outlook mobile) strip or mishandle these code points, causing visible junk characters or preheader overflow. A `max-height:0; overflow:hidden; display:none` wrapper `<div>` is the more robust pattern.
