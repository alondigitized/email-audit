# Extra 30% off selected Sale styles
**Score:** 8/10 · **Type:** Email audit · **2026-07-18**
## Executive summary

- Okay so seven days ago ASOS literally sent me the same offer — "get up to 30% extra off Sale styles" with the busted comma merge tag — and now they're back with the exact same play, just repackaged with a code (XTRA30) and a Monday-morning deadline. The Rina Lipa drop on July 15 felt like a brand-level glow-up, like ASOS finally remembered they have an identity. This email is the hangover after that. It's a clean, functional sale email but it is absolutely not talking to me like they know me.
- That said, the product grid has taste. Chunky brown slides, wide-leg linen vibes, a lavender crop set, a mini skirt moment — whoever pulled the merch edit was paying attention. The "Ends Monday 8am BST" specificity on the code is genuinely useful. It's not a disaster, it's just aggressively anonymous.
- Would I click? Probably yes but only because I'm already hunting sale styles this week — not because this email earned the click. Would I forward it? Absolutely not. This reads like ASOS is running their promo playbook on a loop and hoping I don't notice.

## What's working

- **The code + deadline combo is actionable** — "Use code XTRA30 / Ends Monday 8am BST" gives me exactly what I need to decide if I should shop now or wait. That's real urgency, not fake countdown energy.
- **Hero hierarchy is clean** — "EXTRA 30% OFF SELECTED SALE STYLES" hits first and nothing competes with it. No visual clutter pulling my eye elsewhere.
- **Product grid has genuine trend alignment** — chunky slides, wide-leg jeans, lavender crop top, white mini set. These are styles I'd actually compare against Zara and H&M right now.
- **"SHOP WOMEN'S" CTA is unambiguous** — a verb and a noun, no "Discover" or "Explore" nonsense.
- **No render bugs** — after the comma catastrophe on July 11, just rendering correctly feels like a win at this point.

## What's weak

- **It's the same offer they ran July 11** — I know because I audited it. Rotating the same 30% sale seven days later with slightly different packaging is not a campaign, it's a coping mechanism.
- **"SHOP MEN'S" button on what should be a women's send** — Zara would never put a men's CTA in their Woman weekly edit. H&M at least segments their TGIF send. This makes me feel like ASOS is blasting the same creative to their entire list.
- **Zero personalization or segmentation signal** — treated like a stranger, not a subscriber they've had for years. The Rina Lipa email at least felt like it was written for someone who follows drops.
- **"Selected" is doing a lot of quiet work** — that qualifier is buried. After I click and find out it's limited to 200 items, that's a frustrating experience.

## Recommendations

- 1. **Lead with the product, not the mechanic** — Put the hero image above the offer copy. Show me the chunky slide or the wide-leg moment FIRST, then tell me it's 30% off. That's how H&M won me on their TGIF send — the visual pulled me in before I even read the discount.
- 2. **Kill the "SHOP MEN'S" button** — If you know I shop Women's, why is there a Men's CTA burning primary real estate? Split the send or at least de-emphasize it.
- 3. **Replace "selected Sale styles" with a count or category** — "Extra 30% off 500+ Sale styles" or "Extra 30% off dresses, sets & shoes" makes "selected" feel abundant, not limiting.
- 4. **Give the preheader some work to do** — "Your summer wishlist is waiting" is generic filler. Tell me the specific categories on sale or reference the code.
- **Subject Alt A:** `XTRA30: your summer sale haul, 30% extra off`
- **Subject Alt B:** `Slides, sets, dresses — 30% extra off Sale`
- **Preheader Alt A:** `Code XTRA30 · Ends Monday 8am · Dresses, sets, shoes & more`
- **Preheader Alt B:** `500+ Sale styles just got cheaper. Ends Monday.`

### 3. Rendering & Accessibility

**Issue — Global `font-size: 0em` on table elements:**
```css
table, tr, td, th { font-size: 0em; ... }
```
This ghost-spacing technique requires every content cell to explicitly reset `font-size`. Any `<td>` missing an inline or class-level font-size reset will render invisible text. High Outlook/Lotus Notes risk.

**Issue — CSS table centering won't work in Outlook:**
```css
table { margin: 0 auto; }
```
Outlook (Word rendering engine) ignores `margin: 0 auto` for table centering. Requires `align="center"` attribute on the `<table>` element itself. If outer wrapper tables rely solely on this CSS, layout will be left-aligned in Outlook 2016–2021.

**Issue — No `role="presentation"` visible on layout tables:**
Screen readers will announce layout tables as data tables. Cannot confirm whether `role="presentation"` is applied inline on body tables (source truncated), but it is absent from the CSS defaults.

**Issue — SVG font format included (unnecessary):**
```css
url("...FuturaPT-Book.svg") format("svg")
```
SVG fonts are deprecated, unsupported by all modern browsers and email clients, and add dead weight to the `@font-face` stack. Remove all five SVG `src` entries across both `@font-face` declarations.

**Note — Media query breakpoint is 460px:**
```css
@media screen and (max-width:460px)
```
Industry standard is 600px (some use 480px). Devices between 461px–599px receive desktop layout in a mobile viewport. Common Android mid-range devices fall in this range.

**Positive findings:**

- `<meta name="x-apple-disable-message-reformatting">` present
- `<meta name="format-detection" content="telephone=no, date=no, ...">` present
- `mso-font-alt: Arial` fallback declared on both `@font-face` blocks
