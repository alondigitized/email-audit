# Sale: now up to 70% off
**Score:** 8/10 · **Type:** Email audit · **2026-06-29**
## Executive summary

- Okay so ASOS finally says the quiet part loud — 70% off, no extra math required. That red ticker running "FURTHER REDUCTIONS" before you even hit the hero is doing real psychological work, and the headline itself lands clean. After the June 28 email made me calculate 60% + 25% extra in my head to get to the real number, this one just tells me the number. That's an upgrade.
- But here's the thing: the actual email is almost identical to every other ASOS send this week. Same model layout, same four-button category grid, same red/white/dark palette. I've been in this sale cycle since June 22 — that's five emails in eight days — and this one doesn't give me a single new reason to believe I'll find something left in my size. The June 25 Bershka/Pull&Bear email felt like ASOS actually had curation taste. This one feels like the "okay we're clearing inventory, just go" version.
- I'd click — but purely on instinct, not because this email earned it. 70% off is 70% off. I would absolutely not forward this. If anything I'd just text a friend the discount percentage verbally.

## What's working

- **"FURTHER REDUCTIONS" ticker at the very top** signals escalation before I even read the hero — Zara never does this and it's genuinely effective urgency
- **70% in the hero is unambiguous** — no mental math, no stacking, just a number that hits instantly
- **Four quick-access CTAs** (Sale Under £10, Sale Under £15, Summer Under £50, Bestsellers) give me a route straight to my price tier without sorting — that's better UX than H&M who just dumps me on a category page
- **Model diversity is good** — the black slip dress, the pink co-ord, the cream oversized jacket all read as actual Gen Z pieces, not what a 45-year-old thinks Gen Z wears
- **"SELLING FAST" section** adds scarcity without being annoying about it

## What's weak

- **Hero subtext reads broken** — the line beneath "70% OFF" appears to say something like "We can't dropped the prices to low" which is a visible copy error; that's embarrassing at this scale
- **"SAVING SUITS YOU" is a confusing header** — if it's a swimsuit pun, the images around it (floral mini dress, black sandals) don't confirm it, so it just reads like a weird slogan
- **Prices display in £** — if I'm US-based, this is the wrong regional template and creates immediate friction; Zara gets my currency right every time
- **"SHOP ALL" is the laziest CTA they could have written** — after five emails in one sale cycle I need a more specific hook than that
- **No deadline makes "Limited time only" meaningless** — after seeing that phrase in every single ASOS send this week it's just visual noise now

## Recommendations

- 1. **Fix the hero subtext immediately** — "We can't dropped the prices to low" is a copyediting miss that undercuts an otherwise clean hero; one round of proofing catches this
- 2. **Add a real deadline** — "Ends midnight tonight" or "24 hours left" changes the math on whether I scroll now or come back later (I never come back later)
- 3. **Replace "SHOP ALL" with something with a verb-noun** — "SHOP 70% OFF" or "SHOP THE SALE" still simple, but it reflects the offer
- 4. **Clarify "SAVING SUITS YOU"** — if it's swimwear, label it swimwear; if it's sets, call them sets; a pun that requires decoding isn't a pun, it's friction
- 5. **Add a size or inventory signal** — "Sizes selling fast" or even a low-stock badge on one item in the SELLING FAST section would make me click that section specifically instead of bouncing to a generic shop-all page
- **Subject Alt A:** `Prices just dropped to 70% off — final hours`
- **Subject Alt B:** `Last chance: summer sale hits 70% off today`
- **Preheader Alt A:** `Hundreds of styles from £10 — further reductions just dropped`
- **Preheader Alt B:** `70% off means now. These styles sell out fast.`

### 3. Rendering & Accessibility

**`font-display: swap` on `@font-face`**
```css
font-display: swap;   /* appears in both FuturaPT-Book and FuturaPT-Heavy declarations */
```
Web-only CSS property — ignored by every email rendering engine. Harmless but indicates web CSS was copied without email adaptation.

**Web font support gap**
`FuturaPT-Book` / `FuturaPT-Heavy` loaded from `images.asos-media.com`. Web fonts fail silently in Outlook (all versions), Gmail (Web/Android/iOS), and Yahoo Mail — which together represent the majority of opens. The `mso-font-alt: Arial` and `font-family: ..., Arial, sans-serif` fallback stacks are correctly declared, so the fallback chain appears sound.

**`font-size: 0em` on table elements — silent text suppression risk**
```css
table, tr, td, th { font-size: 0em; }
```
Standard whitespace-gap fix, but any `<td>` that doesn't explicitly override `font-size` will render its text invisible. Must confirm every content cell in the body has an explicit `font-size` property.

**Mobile breakpoint at 460px — too narrow**
```css
@media screen and (max-width:460px) { ... }
```
De facto standard is 480px. Devices reporting viewport widths of 461–479px (e.g., some Android devices) won't trigger the mobile layout and will receive the desktop table layout instead.

**CSS ticker animation — broad client incompatibility**
```css
@keyframes ticker { ... }
@supports (animation: ticker 5s linear infinite) {
  .fallback { display: none !important; }
  .ticker   { display: block !important; }
}
```
`@keyframes` / `animation` unsupported in Outlook (all), Gmail Web, Gmail Android, Samsung Mail. The `@supports` fallback toggle is correctly implemented — non-supporting clients see `.fallback`, supporting clients see `.ticker`. No fix needed, but confirm `.fallback` content is fully self-contained and not dependent on `.ticker` being visible.

**Duplicate charset declaration**
```html
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8">
<meta charset="utf-8">
```
Both present. Not harmful, but redundant — one should be removed to avoid ambiguity in strict parsers.

**`-webkit-font-smoothing` on `*`**
```css
* { -webkit-font-smoothing: antialiased !important; }
```
Overly broad selector; applies smoothing to non-text elements. No functional breakage, but the `!important` makes it difficult to override in any component that intentionally opts out.
