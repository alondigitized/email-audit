### 3. Rendering & Accessibility

**Invalid HTML structure — `<tr>` as direct child of `<div>`:**
```html
<!--[if !mso 9]><!-->
<div style="mso-hide:all;">
  <tr>  ← invalid; <tr> requires a <table> parent
    <td ...>
```
A `<div>` cannot legally parent a `<tr>`. Parsers will attempt error recovery, but behavior is undefined across clients — Gmail, Outlook 365, and Apple Mail may all handle this differently. This is in the preheader block.

**Invalid CSS value — `line-height: auto`:**
```css
.heightmobile { height: auto!important; line-height: auto!important; }
```
`auto` is not a valid `line-height` value. Valid values are `normal`, a unitless number, a length, or a percentage. This will be silently ignored, potentially collapsing line spacing on mobile for any element carrying this class.

**Viewport meta uses semicolons as delimiters (should be commas):**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
The `content` attribute for `viewport` uses commas as separators per spec. Semicolons are handled permissively by most modern browsers but are technically invalid and may fail in older WebKit-based email clients.

**`user-scalable=no` — WCAG 1.4.4 violation:**
Blocking pinch-to-zoom prevents users with low vision from reading content. Combined with `maximum-scale=1.0` this is doubly locked. This fails WCAG 2.1 Success Criterion 1.4.4 (Resize Text, Level AA).

**Google Fonts via `<link>` — blocked in most email clients:**
```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700&display=swap&subset=cyrillic,cyrillic-ext" rel="stylesheet">
```
Gmail (all variants), Outlook (all versions), and Yahoo strip external `<link>` tags. Roboto Condensed will not load for the majority of recipients. The CSS fallback stack in `.imagemobile` (`Helvetica, Arial, sans-serif`) will apply — confirm this fallback is acceptable at all rendered sizes.

Additionally, the `cyrillic,cyrillic-ext` subset is loaded for a `US_en` campaign. This adds unnecessary payload with no functional benefit for the target locale.

**Link color contrast — likely WCAG AA failure:**
```css
a { color: #999898; }
```
`#999898` on `#ffffff` (white background declared on the outer `<table bgcolor="#ffffff">`) yields a contrast ratio of approximately **2.85:1**, below the WCAG AA minimum of 4.5:1 for normal text. Cannot confirm all link contexts from truncated source, but the global `a` rule applies broadly.
