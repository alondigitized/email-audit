# Woman | The weekly edit
**Score:** 6/10 · **Type:** Email audit · **2026-07-17**
## Executive summary

- Okay so I've been watching Zara's inbox behavior like a hawk and they've sent me five emails in seven days — Man, Home, Pre-Owned, and now this, which is at least a "Woman" send so points for staying in my lane. But "The weekly edit" as a subject is doing the absolute bare minimum. There's no hook, no trend moment, no urgency — it's just... Zara showing me Zara things, again. The email itself is peak editorial Zara: beautiful images, lots of sections, zero offers, and me scrolling wondering why I should care today versus last Thursday.
- The FW COLLECTION header appearing in mid-July genuinely confused me. I know fashion runs ahead but I'm literally buying linen right now — the Elegant Linen section below it makes sense, but opening on Fall/Winter in the middle of summer is a choice. ## What's weak

- **FW COLLECTION leading in July** — this is a sequencing miss; even if you're seeding Fall now, opening on autumn when I'm buying for summer weekend plans makes me feel like the email isn't actually for me right now
- **No offer, no hook** — ASOS just dropped a Rina Lipa collab email (8/10, the best thing in my inbox this week) with a real human anchor and a reason to click; this is just "look at things" with no pull
- **Five emails in seven days** — the July 10 "Woman | Discover what's new" email was already a repeat subject line from July 3, then Men's on July 11, Home on July 14, Pre-Owned July 15, now this. The cadence is eroding trust in each individual open
- **Zero urgency or deadline** — no "ends Sunday," no "limited sizes," nothing that makes me feel like I need to act right now versus checking the app in three days
- **Subject line is doing nothing** — H&M's MOVE hiking email this week at least told me what the category was; "the weekly edit" tells me it's Thursday and Zara has a newsletter

### 2. Link & Tracking Issues

### 3. Rendering & Accessibility

**Invalid `line-height: auto` value:**
```css
.heightmobile { height: auto!important; line-height: auto!important; }
```
`auto` is not a valid value for `line-height` (valid keyword is `normal`). Browsers and email clients will ignore this declaration, potentially collapsing line height unexpectedly on mobile.

**Zoom prevention — WCAG 1.4.4 violation:**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
`maximum-scale=1.0` + `user-scalable=no` prevents pinch-to-zoom. This fails WCAG 2.1 SC 1.4.4 (Resize Text) and will trigger accessibility flags in ESPs that run compliance scans.

**Malformed viewport meta syntax:**
The viewport meta uses semicolons as separators instead of commas. The spec requires comma-separated key-value pairs. Several mobile WebKit implementations will fail to parse this correctly.

**External Google Fonts `<link>` will be stripped:**
```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700&display=swap&subset=cyrillic,cyrillic-ext" rel="stylesheet">
```
Gmail (both web and Android), Outlook (all desktop versions), and Apple Mail in proxy mode strip or block `<head>` external stylesheets. Roboto Condensed will not render in the majority of clients; fallback system fonts will be used silently.

**Malformed preheader HTML structure:**
A `<div>` wrapping a `<tr>` appears outside of `<table>`/`<tbody>` context:
```html
<div style="mso-hide:all;">
  <tr>
    <td ...>preheader content</td>
  </tr>
</div>
```
A `<tr>` is not valid outside a table container. Outlook's rendering engine and strict HTML parsers will misinterpret this, potentially surfacing the preheader text visibly or breaking the table layout that follows.
