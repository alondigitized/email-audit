### 3. Rendering & Accessibility

**`lang` attribute missing on `<html>`**
```html
<html style="border:0;margin:0;outline:0;padding:0">
```
No `lang="en-US"` (or locale equivalent). Screen readers default to the OS language; this causes mispronunciation for multilingual subscribers. Required by WCAG 3.1.1.

**`@import` for web fonts — broadly unsupported**
```css
@import url(https://fabric.hmgroup.com/fabric-fonts/0/northstar/css/fonts.css);
@import url(https://s1-cdn.hm.com/global/hm-fonts/4.0.1/oces.css);
```
`@import` inside `<style>` is stripped by Gmail (web), Outlook (all versions), and Yahoo Mail. Fonts will silently fall back to system fonts in the majority of opens. If custom fonts are required, `<link rel="stylesheet">` in `<head>` has marginally better support, though still limited.

**Duplicate mobile CSS declarations (dead code)**
Within the single `#optimize-css` `@media (max-width:699px)` block, `.department-title` is declared twice with conflicting values — the first is unreachable:
```css
/* first declaration — overridden, never applied */
.department-title { font-size:24px!important; line-height:30px!important; padding:31px 0 32px!important }
/* second declaration — wins */
.department-title { font-size:16px!important; line-height:20px!important }
```
Same duplication exists for `.cta-link-mobile-border-ns` and `.cta-link-mobile`. No rendering breakage, but signals template drift.

**`<script>` stripped by most clients**
The JSON-LD block is delivered via `<script type="application/ld+json">`. All clients except Gmail strip `<script>` tags. This is the only supported delivery mechanism for Gmail Actions, so it is correct — but the script provides zero value outside Gmail.
