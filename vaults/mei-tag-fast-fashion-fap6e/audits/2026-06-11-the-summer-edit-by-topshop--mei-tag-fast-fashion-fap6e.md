### 3. Rendering & Accessibility

**Issue — Malformed `<meta>` placement:**
Meta tags (`Content-Type`, `charset`, `viewport`, `format-detection`, `x-apple-disable-message-reformatting`) are placed inside `<body>` wrapped in a `<p>` element, not inside `<head>`. The sequence is:

```html
<body>
  <div>...</div>
  <p>
    <meta http-equiv="Content-Type" content="text/html; charset=UTF-8">
    <meta charset="utf-8">
    ...
```

This is invalid HTML. Most email clients are tolerant, but Outlook and some parsing pipelines may drop or mishandle meta directives declared in-body. The `charset` and `viewport` metas in particular have no effect when not in `<head>`.

**Issue — Empty first preheader div:**
The first hidden div (the one with `visibility:hidden; max-height:0px`) is empty — no text content. The actual preheader text ("Discover lightweight layers...") appears in a *second* hidden div further down. This suggests the first slot may have been a template placeholder that was never populated, or the injection point is mismatched. Inbox preview will show the second div's text correctly, but the empty first div is dead markup.

**Minor — Mobile breakpoint at 460px:**
The sole responsive breakpoint is `@media screen and (max-width:460px)`. Modern flagship devices (iPhone 15 Pro: 393px logical width, Galaxy S24: 412px) fall within this range, but it's tight. Devices at 461–520px logical width receive the desktop layout with no adaptation.

**Acceptable — `font-size: 0em` on table/td/tr:**
This is a standard whitespace-gap suppression technique. `0em` is functionally identical to `0px` here. No issue.
