## Technical Audit

## 1. Technical Summary
The email's 16% QA pass rate comes almost entirely from 403 responses on the `t19.email.hm.com/r/` tracking redirector, and those are likely bot-blocking rather than real breakage. Confirmed source-level issues are unpopulated JSON-LD placeholders, extensive missing image alt text, and a URL-heavy plain-text part.

## 2. Link & Tracking Issues
- **12 of 12 probed links returned 403.** These covered "Shop now" (8 links, ids ending `f8e22c72`/`73`/`74`/`75`/`8a`/`8b`/`8e`/`8f`/`52`/`54`), the "H&M" logo link (`…f8e22c51`), two image links, and Unsubscribe (`…f8e22cb2`).
- **Cause is unconfirmed.** Every link uses the same `t19.email.hm.com/r/?id=hdb823584-…` redirector, and all of them failed identically. That pattern points to the redirector rejecting the automated probe (WAF or user-agent filtering) rather than 12 separately broken links. Treat it as "unverified", not "dead".
- **The unsubscribe link is among the 403s** (`…f8e22cb2&…&p4=3326930539&p5=9be06746…`). It could not be verified, so manual confirmation matters most here.
- **Coverage is thin.** Only 12 links were probed and 62 were skipped, so nothing is known about the rest.
- **Tracking parameters carry per-recipient identifiers.** `rid=3326930539` and `erid=MzMyNjkzMDUzOQ==` (base64 of the same `rid`) are in every URL. This is not a defect.

## 3. Rendering & Accessibility
- **Missing alt text on about 22 images.**
  - The QA scan flagged both the `cq5dam.web.1400.1400.jpeg` and `cq5dam.web.750.750.jpeg` variants for each hero.
  - Examples: `image.hm.com/content/dam/hm/regional-local-activities/ame/2026-ame/wk48/1370962002_202604_LB_0013.jpg/…` and `…/wk48/us187_s4/1357640001_202604_LB_1178.jpg/…`.
  - Two tracking-link images (`t19.email.hm.com/r/?id=hdb823584-1375-4f14-9208-8d41…`) are also missing alt.
  - Because the alt is missing, link text for these image links falls back to the filename (e.g. `[image: cq5dam.web.1400.1400.jpeg]`). Screen readers and images-off clients get no useful label.
- **Duplicate 1400/750 image pairs.** Each hero is rendered twice, as desktop and mobile variants (`is-hidden-mobile`/`is-hidden-desktop`). Both copies lack alt, doubling the exposure. This is a standard pattern, but only one of each pair should be exposed to assistive tech.
- **Invalid CSS value:** `.is-hidden-desktop{… line-height:auto!important …}` in `<style id="optimize-css">`. `auto` is not valid for `line-height`, so the declaration is dropped.
- **Web fonts via `@import`** (`fabric.hmgroup.com/…/fonts.css`, `s1-cdn.hm.com/global/hm-fonts/4.0.1/oces.css`). Gmail and several other clients ignore or strip these. This is only an issue if the font stack lacks fallbacks, and the truncated source does not show that.
- **Stale asset paths.** The HTML references `.../home/week-43/HHMI265P02-FN-3x2.j…` and `…/wk-47/…` in what is a `wk48` send. This is minor and only worth a check.
- **Truncated source.** The HTML shown is truncated, so `lang`, `<title>`, role attributes and the body's table markup could not be audited.

## 4. Personalization & Merge Tokens
No issues found. The subject and visible source contain no unresolved merge tokens such as `%%…%%`, `{{…}}` or `[FIRST_NAME]`. The HTML is truncated, so this covers only the portion shown.

The JSON-LD block (`<script type="application/ld+json">`) contains template placeholders that were never populated:
- `"subjectLine":""`
- `"discountCode":""`, `"availabilityEnds":""`
- `"availabilityStarts":"2018-12-31T18:59:59-05:00"`, a 2018 default left in the template
- PromotionCard `"image":""`, `"url":""`

Gmail can't render this as a promo card, and a 2018 `availabilityStarts` could mark the offer as expired.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) were not found.** The QA tool notes the AgentMail relay may strip them, so this is unconfirmed. Verify against the raw message headers, since Gmail and Yahoo bulk-sender rules require one-click unsubscribe.
- **`Authentication-Results` is absent**, so SPF, DKIM and DMARC alignment is unknown. This is a relay limitation, not evidence of failure. The From domain `email.hm.com` matches the tracking subdomain `t19.email.hm.com`, which is a good sign for alignment.
- **An Unsubscribe link exists in the body**, but its 403 on probing is unresolved (see section 2).
- **A physical postal address could not be checked** because the footer is cut off in the truncated source.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not verifiable. Every destination is wrapped in the `t19.email.hm.com/r/` redirector and returned 403, so the final landing URLs, their UTM parameters and landing-page alignment could not be resolved. The `p1=DM6243796`, `p3=20261126` and `p2` hash parameters are the only campaign identifiers visible. Plain-text and HTML links appear to share the same redirector. No destination-level mismatch can be asserted.

## 7. Recommendations
1. Re-probe the `t19.email.hm.com/r/` links with a browser-like user agent or a real-browser (Playwright) fetch. Check in particular the Unsubscribe link (`…f8e22cb2`) and the "Shop now" links, to separate bot-blocking from true breakage. Follow the redirects to capture the final URLs and UTM parameters.
2. Pull the raw `.eml` headers (not the relay-processed copy) to confirm `List-Unsubscribe`, `List-Unsubscribe-Post: List-Unsubscribe=One-Click`, and SPF/DKIM/DMARC results.
3. Add meaningful `alt` text to all hero and product images, or `alt=""` on decorative duplicates. Give the hero links accessible labels. Expose only one of each 1400/750 pair to assistive tech.
4. Populate or remove the JSON-LD placeholders (`subjectLine`, `discountCode`, 2018 `availabilityStarts`, empty PromotionCard `image`/`url`).
5. Fix `line-height:auto` to `normal`, or remove it, in `.is-hidden-desktop`.
6. Reduce the plain-text part's URL density (526 of 604 characters, over 70%). Add more descriptive text around the long tracking URLs.
7. Increase probe coverage beyond 12 of 74 links in the next run.
