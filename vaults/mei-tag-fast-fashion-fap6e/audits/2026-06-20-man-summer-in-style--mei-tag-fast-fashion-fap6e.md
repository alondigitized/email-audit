### 3. Rendering & Accessibility

**Google Fonts `<link>` tag will silently fail in Gmail and Apple Mail**
Gmail strips the entire `<head>` including `<link>` elements. Roboto Condensed will not load; the email falls back to whatever system font the client substitutes. This is a silent failure — no error, just a different typeface than designed.
```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700..." rel="stylesheet">
```
Fix: embed the font-face as a `<style>` block, or accept the system fallback and test for it.

---

**`user-scalable=no` in viewport — WCAG 1.4.4 violation**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
This prevents users from pinching to zoom, which directly affects users with low vision. WCAG 2.1 SC 1.4.4 (Resize Text) requires text to be resizable to 200% without loss of content. Remove `maximum-scale=1.0` and `user-scalable=no`.

---

**Invalid CSS: `line-height: auto`**
```css
.heightmobile { height: auto!important; line-height: auto!important; }
```
`auto` is not a valid value for `line-height` (valid values: normal, a number, a length, a percentage). Browsers ignore invalid declarations silently; the intended effect (reset line-height) requires `line-height: normal !important`.

---

**Invalid HTML: `<tr>` as child of `<div>` inside `<table>`**

In the preheader block, a `<div>` is injected as a direct child of a `<table>` (outside any `<tbody>`/`<tr>`) and then a `<tr>` is placed inside that `<div>`:
```html
<table ...>
  <!--[if !mso 9]><!-->
  <div style="mso-hide:all;">
    <tr>
      <td ...>
```
Both `<div>` as a direct table child and `<tr>` inside `<div>` are invalid per HTML spec. Browsers auto-correct this differently — Outlook may render the `<div>` block outside the table, breaking layout. The MSO conditional syntax `<!--[if !mso 9]><!-->` is also non-standard; the correct form is `<!--[if !mso]><!-->`.
