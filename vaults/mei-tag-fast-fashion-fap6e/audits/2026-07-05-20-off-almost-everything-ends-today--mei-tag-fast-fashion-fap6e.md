#  20% off almost everything ends today
**Score:** 9/10 · **Type:** Email audit · **2026-07-05**
## Executive summary

- Okay so I genuinely cannot with H&M right now. This is the fifth — FIFTH — email this week where they've shown up in my inbox with a 20% off story. Stars and stripes, red white and all new, the main event, and now "ends today." I feel like a character in a Groundhog Day movie except every morning I wake up and it's still the 20% off sale at H&M.
- That said, this specific execution is carrying itself better than I expected at this point. The hero model is wearing a blue baroque-print dress that is genuinely doing something — it's got coastal Amalfi meets Y2K maximalism energy and I almost forgot I was annoyed. "LAST DAY" stacked above the offer is the most urgent framing all week, and for once I actually believe it because it's July 5th and the holiday weekend is literally over. If I was ever going to click this promo, today is the day my resistance finally breaks.
- I would not forward this to a friend as an email — I would screenshot the hero dress and airdrop it with zero context. Click? Yeah, probably. But only because H&M has spent four days training me like a Pavlovian shopper and I've run out of willpower.

## What's working

- The baroque blue-print hero dress is trend-aware and summer-specific — it doesn't read clearance, it reads editorial, which is rare for a promotional email
- "LAST DAY" above "20% OFF SITEWIDE" is the first time this campaign's deadline has actually felt like a deadline — urgency lands
- Stacked offers (20% sitewide + up to 70% in the dedicated sale block) give two different price motivations without cluttering the layout
- The email renders completely clean — no broken images, no overlapping text, layout is tight all the way down
- "The holiday may be over, but the glow-up isn't" is actually a decent hook for July 5th — it's timely and doesn't feel copy-pasted from a template

## What's weak

- This is the fifth 20% off send in a week — "ends today" only works as a deadline if I believe there won't be a sixth email tomorrow with a new angle on the same number
- The top banner ("Become a member, 10% off your first purchase") is a new-member acquisition pitch that I, an existing subscriber, have zero use for — and it's almost certainly leaking as the inbox preview, which means my first signal before opening is "join our loyalty program," not "sale ends today"
- "20% off almost everything" in the subject versus "20% OFF SITEWIDE" in the hero is a quiet bait-and-switch — pick one, H&M
- SHOP NOW goes to a generic destination — ASOS routes me directly to a size-filtered sale landing page with 30% extra off clearly called out; H&M still drops me at the front door
- The fine print at the bottom is a wall of dense legal text that immediately undercuts the clean layout above it

## Recommendations

- 1. **Reset after this.** If this is genuinely the last day of 20% off, the next email needs to be a completely different chapter — new arrivals, a fall preview teaser, anything that tells me the sale is over and life goes on. Five back-to-back percentage-off emails trains subscribers to wait for discounts instead of buying at full price.
- 2. **Fix the preview text immediately.** The member acquisition banner is almost certainly leaking as inbox preview. Set a dedicated preheader that matches the urgency of the subject instead of pitching loyalty signup to people who are already on the list.
- 3. **Reconcile the offer language.** "Almost everything" versus "sitewide" — these mean different things. If there are exclusions, name them once in small print near the CTA and commit to "sitewide" in the headline. The hedging reads as fine print before I even open the fine print.
- 4. **Make the CTA destination earn the click.** Link the hero directly to the women's sale page pre-filtered, not the homepage. ASOS does this every single send and it's the reason their click-through feels effortless.
- 5. **Give the sale section one human sentence.** "Up to 70% off + new styles added" is functional but cold. Something like "the stuff that sold out last week just dropped in price" would get me scrolling past the SHOP BY grid.
- **Subject Alt A:** `Last call: 20% off ends at midnight`
- **Subject Alt B:** `Final hours — 20% off before it's gone for real`
- **Preheader Alt A:** `No code needed. Free shipping over $40. The baroque dress is still in stock.`
- **Preheader Alt B:** `The sale closes tonight — grab it before next week's full price.`

## Technical Audit — H&M "20% off almost everything ends today"

---

### 1. Technical Summary

Standard ESP-delivered HTML email with table-based layout and responsive CSS. The most significant technical issue is a partially-rendered JSON-LD schema block containing stale hardcoded dates and multiple empty merge fields that were never populated.

---

### 2. Link & Tracking Issues

HTML source is truncated before link `href` values are visible, so UTM coverage cannot be fully confirmed. One structural issue is observable:

- **JSON-LD `PromotionCard.url` is an empty string** (`"url":""`) — if Google uses this for promotional tab rendering, the card will have no destination.

Cannot audit individual link UTM parameters or click-tracking wrapper domains from the provided truncation. Full source required.

---

### 3. Rendering & Accessibility

**`@import` CSS stripped by Gmail:**
```css
@import url(https://fabric.hmgroup.com/fabric-fonts/0/northstar/css/fonts.css);
@import url(https://s1-cdn.hm.com/global/hm-fonts/4.0.1/oces.css);
```
Gmail (web and Android) strips `@import` rules entirely. Both font imports will silently fail, falling back to system fonts for all Gmail recipients. This is a known ESP limitation and standard fallback behavior, but worth confirming fallback stack is acceptable.

**`img.image + div { display: none !important; }`**
This rule hides any `<div>` immediately following an `.image` element. If any image has an adjacent accessibility or alt-text fallback `<div>`, it will be suppressed in all clients.

**Non-standard media query:**
```css
@media screen yahoo { .show-webkit-table { display: none; } }
```
`screen yahoo` is not a valid CSS media query. No client will evaluate it. If this was intended to target the Yahoo Mail rendering engine, it has no effect.

**Missing `lang` attribute:** The `<html>` tag has no `lang="en"` (or any language). Screen readers default to the OS language, which can misread content for international subscribers.

---

### 4. Personalization & Merge Tokens

The JSON-LD `DiscountOffer` block contains unfilled template fields sent in production:

```json
{
  "@type": "DiscountOffer",
  "discountCode": "",
  "description": "",
  "availabilityStarts": "2018-12-31T18:59:59-05:00",
  "availabilityEnds": ""
}
```

- **`discountCode` and `description` are empty strings** — these appear to be merge tokens that were not resolved before send.
- **`availabilityEnds` is empty** — required field for offer validity signaling.
- **`availabilityStarts` is hardcoded to `2018-12-31T18:59:59-05:00`** — this is 7+ years stale, indicating the schema template has never been updated. Google's Gmail Promotions tab uses this data; a 2018 start date may cause the offer to render as expired or be deprioritized.

Similarly in `EmailMessage`:
```json
{"@type":"EmailMessage","subjectLine":"","@context":"http://schema.org/"}
```
`subjectLine` is an empty string rather than the actual subject line, which should be `" 20% off almost everything ends today"`.
