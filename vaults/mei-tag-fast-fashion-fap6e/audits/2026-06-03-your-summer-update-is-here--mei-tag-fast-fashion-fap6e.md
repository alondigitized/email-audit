### 3. Rendering & Accessibility

**Font loading via `@import` — broken in Gmail, Outlook, and others**
```html
<style>
  @import url(https://fabric.hmgroup.com/fabric-fonts/0/northstar/css/fonts.css);
  @import url(https://s1-cdn.hm.com/global/hm-fonts/4.0.1/oces.css);
</style>
```
`@import` inside `<style>` blocks is unsupported in Gmail (all variants), Outlook desktop (2013–2021), and Windows Mail. Both H&M custom font families will silently fall back to system fonts in these clients. The correct approach is `<link rel="stylesheet">` in `<head>`, which has broader support, or inlining `@font-face` declarations directly.

**Missing `lang` attribute on `<html>`**
```html
<html style="border:0;margin:0;outline:0;padding:0">
```
No `lang` attribute present. Screen readers cannot infer language, and spell-check/text-to-speech behavior is undefined. WCAG 2.1 §3.1.1 (Level A) requires this.

**`display:inline` on block-level mobile show class**
```css
.is-hidden-desktop { display:inline!important; }
```
Using `display:inline` to reveal elements that contain `<table>` or `<td>` ancestors will collapse block formatting context in several clients. Should be `display:block` or `display:table` depending on the element type.

**`<meta name="viewport">` missing `initial-scale`**
```html
<meta name="viewport" content="width=device-width"/>
```
Standard practice is `content="width=device-width, initial-scale=1"`. Without `initial-scale=1`, some Android WebView and older Samsung clients may render at a zoomed-out default scale.
