- **Same subject line as seven days ago** — "Woman | The weekly edit" ran on July 17th (scored 6/10) and now it's back July 24th. It's literally called "the weekly edit" so this will just... keep happening every week forever. Which means I'll never open it with any sense of what I'm getting.

- **ZW Collection at the top is wrong for me** — ZW (Zara Woman) skews older, more work-capsule. Opening with it signals this email wasn't segmented for me at all.
- **Travel editorial is noise** — "Travel Now | New York City" at the bottom feels like they ran out of product content and padded it. I'm not cross-referencing Zara for travel inspo.

### 3. Rendering & Accessibility

**[HIGH] Invalid table structure — `<div>` wrapping `<tr>`**
```html
<div style="mso-hide:all;">
  <tr>
    <td align="center" height="0" width="0" class="hiddenmobile">
```
A `<div>` is inserted as a direct child of `<table>` wrapping a `<tr>`. This is malformed HTML. Per the XHTML spec the `<div>` DOCTYPE claims, a `<div>` cannot appear between `<table>` and `<tr>`. Outlook and some Gecko-based clients will inject or drop nodes to repair this, causing the preheader row to render visibly or shift layout.

**[MEDIUM] `user-scalable=no` + `maximum-scale=1.0` in viewport meta**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
Disables pinch-to-zoom on mobile. Violates WCAG 1.4.4 (Resize Text, Level AA). Many mobile ESPs and Apple Mail on iOS will ignore this, but it should be removed.

**[LOW] External Google Fonts load via `<link>` in `<head>`**
```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700&display=swap&subset=cyrillic,cyrillic-ext" rel="stylesheet">
```
Blocked in Gmail (strips `<head>` content), Outlook (all versions), and most corporate environments with external resource filtering. The CSS does not declare a corresponding web-safe fallback in the `<link>` element itself. Inline `font-family` fallback stacks in the body need to be verified (source is truncated).

**[LOW] Preheader padding via Unicode zero-width characters**
```html

```
Hair space + combining grapheme joiner technique is standard but can render as visible characters in a small number of older Android mail clients and some accessibility screen readers (NVDA/JAWS may vocalize spacing artifacts).
