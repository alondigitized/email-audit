### 3. Rendering & Accessibility

**Confirmed issues:**

| Issue | Evidence | Severity |
|---|---|---|
| `<meta>` tags in `<body>` wrapped in `<p>` | `<body> <div>…</div> <p> <meta http-equiv=…> <meta charset=…>` — both metas appear as body children, not in `<head>` | High |

| `-webkit-text-size-adjust: none` on `body` | `body { -webkit-text-size-adjust: none; }` — blocks user font scaling, WCAG 1.4.4 violation | Medium |
| Conflicting text-size-adjust | `body` sets `none`; `*` selector sets `100%` — body-level wins, negating the `*` fix | Low |
| SVG font format included | `url("…FuturaPT-Book.svg") format("svg")` — SVG fonts are deprecated in all modern browsers; adds HTTP request overhead | Low |
| Single breakpoint at 460px | `@media screen and (max-width:460px)` only — no 600px breakpoint for tablet clients | Low |

### 7. Recommendations

1. **Fix `<meta>` tag placement (High)** — Move all `<meta>` tags into a `<head>` block. The current `<p><meta …></p>` in `<body>` is invalid and will be silently dropped or misparsed by strict renderers (notably some versions of Outlook and Gmail's sanitizer).

2. **Populate the preheader div (Medium)** — Add static fallback copy or a merge token with a non-empty default. An empty preheader causes inbox clients to pull the first rendered text (often an image alt or navigation label) as preview text.

3. **Change `-webkit-text-size-adjust` to `100%` on `body` (Medium)** — Replace `none` with `100%` to restore user font scaling without losing the intended rendering fix. This aligns with WCAG 1.4.4 (Resize Text).

4. **Remove SVG font format (Low)** — Drop the `.svg` `@font-face` source; it saves one HTTP request and eliminates a format no current email client renders.

5. **Add 600px breakpoint (Low)** — Tablet-width clients (iPad Mail, some Android) fall through to desktop layout at widths where the single-column mobile layout would improve readability.
