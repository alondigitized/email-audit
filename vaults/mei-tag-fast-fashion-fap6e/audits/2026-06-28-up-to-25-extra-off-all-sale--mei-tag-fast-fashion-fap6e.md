## What's working

- **Math is stacked and visible immediately** — "25% extra off" on a "60% off" sale = the headline does the calculation work for me, I don't have to figure it out
- **Deadline is specific** — "Ends Monday, 9am BST" is a real cut-off, not vague urgency theater
- **Promo code lives in the hero** — no hunting through footer fine print, it's right there
- **"YOU'D LOOK GREAT IN THESE" pulls actual recs** — the floral wrap and yellow suit look curated, not a generic bestsellers dump; that personalization signal earns attention
- **Models are young and diverse** — the styling grid reads Gen Z summer, not department-store catalog

## What's weak

- **Cadence fatigue is real** — five emails in six days and two of them have been "extra X% off sale" — the urgency is diluted by repetition
- **"SHOP WOMEN'S / SHOP MEN'S" split is lazy** — ASOS has my gender data; surfacing menswear CTA every time is noise that makes the email feel less targeted
- **Zero trend language anywhere** — for a brand I follow because of trend velocity, this email could be from any discount retailer; compare to the June 25 Bershka/Pull&Bear email which actually told me *what* was dropping
- **Brand logos buried at the bottom** — Levi's and New Balance in the "SHOP OUR TOP BRANDS" block is genuinely relevant to me (I track which fast-fashion brands are riding the NB wave) but that section is so far down I almost missed it

- 1. **Stack the combined math in the headline** — "UP TO 75% OFF WHEN YOU STACK" is the number that makes me screenshot and send to my group chat; "25% extra off all Sale" requires mental math I shouldn't have to do
- 2. **Kill the gender split CTA** — replace "SHOP WOMEN'S / SHOP MEN'S" with one personalized or trend-category CTA like "SHOP WHAT'S TRENDING IN SALE" — she came for trends, not a binary
- 3. **Lift the brand logos section** — Levi's and New Balance above the fold would tell a trend story that Zara and H&M can't match right now; it's being wasted below the scroll
- 4. **Add a cadence anchor** — signal in preheader or body that this is the *final* push of the sale cycle so it doesn't read as the fifth chapter of the same promo

### 3. Rendering & Accessibility

**Issue — `-webkit-text-size-adjust: none` on `body`:**
```css
body, #body_style {
  -webkit-text-size-adjust: none;
  -ms-text-size-adjust: none;
}
```
Setting to `none` prevents iOS from scaling text when the user has a larger preferred font size. Recommended value is `100%`, which prevents browser auto-scaling while still respecting user accessibility settings. This also appears a second time as `* { -webkit-text-size-adjust: 100%; }` — the `body` rule takes precedence, making the wildcard redundant and the `none` value the effective one.

**Issue — Global link underline removal:**
```css
a, span { text-decoration: none; color: inherit; }
```
Removes all visual link differentiation. Violates WCAG 1.4.1 (use of color alone to convey meaning). CTAs styled as buttons are exempt if they have sufficient contrast, but inline text links are not distinguishable from surrounding copy.

**Issue — Responsive breakpoint gap at 460px:**
```css
@media screen and (max-width:460px) { ... }
```
Standard email breakpoint is 600px. Devices with viewports between 461–599px (many Android phones in landscape, small tablets) render the desktop layout. If the desktop layout is fixed at 600px, it will overflow or require horizontal scroll on these viewports.

**Issue — `font-size: 0em` on all table elements:**
```css
table, tr, td, th { font-size: 0em; }
```
Standard ghost-whitespace fix, but any text placed directly inside a `<td>` without a wrapping `<p>` or `<span>` will be invisible. Confirm all body copy is wrapped in block elements.

**No issue — VML conditional comments:** Correctly scoped to `[if gt mso 15]` and wrapped in `<noscript>` per current best practice.

**No issue — Font loading:** `font-display: swap` is set; multiple formats (woff2, woff, otf, ttf, svg) cover all clients. SVG format is legacy-only and adds negligible weight but causes no harm.

**No issue — `lang="en"` on `<html>`:** Present and correct.
