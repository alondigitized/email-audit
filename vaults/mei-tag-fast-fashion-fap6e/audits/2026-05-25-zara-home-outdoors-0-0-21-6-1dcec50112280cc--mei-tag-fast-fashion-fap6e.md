### 3. Rendering & Accessibility

**Viewport meta uses semicolons as separators (spec violation)**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
The correct separator is a comma. While most modern clients tolerate this, it is non-conformant and can fail in stricter parsers.

**`user-scalable=no` blocks pinch-to-zoom** — accessibility failure; violates WCAG 1.4.4 (Resize Text).

**Google Fonts `<link>` will be stripped or blocked** by Gmail, Yahoo, and Outlook. The `Roboto Condensed` declaration in `<head>` will silently fall back to system fonts in the majority of inboxes. If this font is critical to layout, it is effectively absent for most recipients.

**Invalid CSS value: `line-height: auto`**
```css
.heightmobile { height: auto!important; line-height: auto!important; }
```
`auto` is not a valid `line-height` value. This declaration is ignored; intended behavior is undefined.

**Malformed XHTML structure in preheader block** — a `<tr>` element appears as a direct child of a `<div>`, which is invalid in both HTML and XHTML:
```html
<div style="mso-hide:all;">
  <tr>   <!-- invalid: tr inside div -->
    <td ...>
```
This can cause Outlook and strict-mode clients to misrender or collapse the preheader region.

**Preheader padding uses `&#847;` (U+034F Combining Grapheme Joiner)** — this is the standard zero-width padding technique and is functionally correct, but a small number of clients (notably older Android mail) can render these as visible dots or squares.
