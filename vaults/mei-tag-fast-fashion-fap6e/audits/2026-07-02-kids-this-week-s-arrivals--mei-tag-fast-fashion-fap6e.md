### 3. Rendering & Accessibility

**Malformed preheader DOM structure**
A `<tr>` element is a direct child of a `<div>`, which is invalid HTML. The pattern in source:
```html
<!--[if !mso 9]><!--> <div style="mso-hide:all;">
  <tr>
    <td ...> <!-- preheader content --> </td>
  </tr>
```
`<tr>` must be a descendant of `<table>`/`<tbody>`, never of `<div>`. Parsers that enforce strict nesting (some WebKit renderers, AMP validators) will drop or misplace this element.

**`user-scalable=no` in viewport meta**
```html
<meta name="viewport" content="width=device-width; initial-scale=1.0; maximum-scale=1.0; user-scalable=no;" />
```
Disabling user zoom fails WCAG 2.1 SC 1.4.4 (Resize Text). iOS 10+ ignores this in Safari, but it remains a compliance risk and should be removed.

**Viewport meta uses semicolons instead of commas as separators**
The `content` attribute above uses `;` as delimiters. The spec requires `,`. Most browsers are lenient, but it is technically malformed.

**Invalid CSS value — `line-height: auto`**
```css
.heightmobile { height: auto!important; line-height: auto!important; }
```
`auto` is not a valid value for `line-height` (valid values: `normal`, `<number>`, `<length>`, `<percentage>`). Compliant parsers will ignore this declaration, potentially causing unintended line-height inheritance on mobile.

**External Google Fonts stylesheet**
```html
<link href="https://fonts.googleapis.com/css?family=Roboto+Condensed:400,700&display=swap&subset=cyrillic,cyrillic-ext" rel="stylesheet">
```
External `<link>` stylesheets are stripped by Gmail (all clients), Outlook 2007–2021, and Yahoo Mail. Roboto Condensed will silently fall back to the system sans-serif in the majority of clients. If this font is load-bearing for layout metrics, column widths or text overflow must be validated against the fallback stack.
