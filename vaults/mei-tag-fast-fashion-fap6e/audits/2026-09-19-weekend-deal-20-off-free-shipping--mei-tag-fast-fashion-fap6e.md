## Technical Audit

1. Technical Summary
Templated H&M promo email with unpopulated JSON-LD metadata and a QA scan showing all 12 probed material links returning HTTP 403.

2. Link & Tracking Issues
- All probed redirect links through `t19.email.hm.com/r/?id=...` return **403 Broken link** — includes the primary "Shop now" CTAs (3x), header "H&M" logo link, both hero images, Women/Men/Kids nav links, and the Unsubscribe link. 12/12 probed links fail.
- Links carry ESP click-tracking params (`did`, `rid`, `erid`, `p1`–`p5`) consistent with a redirector; the 403 responses indicate the tracking domain/token is rejecting the request (expired preview token, bot/UA block, or an invalid `id` for this rendering), not necessarily a dead destination — cannot confirm final landing URLs since the redirector itself blocks resolution.
- Two CTA links have identical anchor text ("Shop now") but different `id` hash suffixes (`f83744ff`, `f8374500`, `f8374505`) — link text alone doesn't disambiguate which region of the email each maps to.

3. Rendering & Accessibility
- 5 `<img>` elements missing `alt` text: the two tracking pixel/redirect images and three content images (`cq5dam.web.1400.1400.jpeg` / `cq5dam.web.750.750.jpeg` pairs for at least 3 distinct product images, plus one pixel).
- Link text on two CTAs is polluted with invisible characters: `"‌  ﻿Shop now"` contains a zero-width non-joiner (U+200C) and BOM/zero-width no-break space (U+FEFF) before the visible text — will read oddly to screen readers announcing hidden characters, and can break exact-text QA/link matching.
- One image-only link has no accessible name at all: link text renders as `"[image: cq5dam.web.1400.1400.jpeg]"` / `"[image: cq5dam.web.750.750.jpeg]"`, i.e., filename fallback rather than descriptive alt — a screen reader user gets no context on the product being linked.
- Extensive `!important`-laden responsive CSS (`optimize-css` block) targets `#MessageViewBody` (Outlook.com) and `@media screen yahoo` hacks — standard client-targeting patterns, no structural issues observed in the truncated source.

4. Personalization & Merge Tokens
- The `application/ld+json` `EmailMessage`/`DiscountOffer`/`PromotionCard` schema has multiple empty string fields: `"subjectLine":""`, `"discountCode":""`, `"availabilityEnds":""`, `"description":""`, `"url":""` (image also empty). These are unresolved merge/template tokens — the structured data will validate as syntactically valid JSON-LD but semantically empty, so Gmail/Google promotional markup features (e.g., discount code display) will not render.
- `availabilityStarts` is hardcoded to `"2018-12-31T18:59:59-05:00"` — a stale/placeholder date unrelated to the 2026-09-19 send, confirming this JSON-LD block is not being populated per-send.

5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- Unsubscribe link is present in-body but returns **403** per QA scan — functionally broken one-click unsubscribe from the rendered email.
- `List-Unsubscribe` header: not found (WARN) — may be a relay artifact (AgentMail) rather than absence at origin; cannot confirm from this data alone.
- `List-Unsubscribe-Post` header (RFC 8058 one-click): not found — one-click unsubscribe via mail client cannot be confirmed.
- `Authentication-Results` header (SPF/DKIM/DMARC): not found — sender authentication status unknown via this relay; not evidence of an actual auth failure.

6. Email-to-Site Continuity (UTM params, landing page alignment)
- Links use H&M's proprietary redirector/click-tracking scheme (`did`, `rid`, `erid`, `p1`–`p5` params) rather than standard UTM parameters — no `utm_source`/`utm_medium`/`utm_campaign` present on any probed URL, so campaign attribution depends entirely on the `p1=DM6061096` style internal IDs.
