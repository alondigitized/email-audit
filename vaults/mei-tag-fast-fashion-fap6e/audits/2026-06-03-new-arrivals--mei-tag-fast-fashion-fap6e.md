### 3. Rendering & Accessibility

**`<meta>` tags misplaced inside `<body>`:**
```html
<body>
  <div style="display:none..."></div>
  <p>
    <meta http-equiv="Content-Type" content="text/html; charset=UTF-8">
    <meta charset="utf-8">
    ...
```
Meta tags must live in `<head>`. Placing them inside `<p>` inside `<body>` is invalid HTML. Most clients are lenient here, but it can confuse Outlook's Word rendering engine and cause unpredictable layout behavior.

**Duplicate charset declarations:**
Both `http-equiv="Content-Type"` and `charset="utf-8"` are declared simultaneously — redundant, though harmless.

**`FuturaPT-DemiBold` referenced but never declared:**
```css
h1, h2, h3 {
  font-family: 'FuturaPT-DemiBold', Futura, Arial, sans-serif;
}
```
Only `FuturaPT-Book` and `FuturaPT-Heavy` have `@font-face` declarations. `FuturaPT-DemiBold` will silently fall through to `Futura` → `Arial` on all headings.

**`FuturaPT-Heavy` declared at `font-weight: 600`:**
```css
@font-face {
  font-family: "FuturaPT-Heavy";
  font-weight: 600;
}
```
"Heavy" conventionally maps to 800–900. Declaring it at 600 means any `font-weight: 700+` rule will not select this face as expected.

**Preheader structure:**
Two hidden divs exist — the first is empty, the second contains the actual preheader text (`Shop what's just landed at ASOS`). The empty first div is vestigial; no functional break, but indicates a template assembly issue.

**Alt text:** Cannot assess — image tags not present in the truncated source.

### 5. Compliance (CAN-SPAM, Unsubscribe, Authentication)

**Cannot fully assess** — physical mailing address and unsubscribe link are not present in the truncated source. These are required by CAN-SPAM and must appear in the full email; flag for verification against the complete HTML.

**From domain:** `hello@official.asos.com` sends from a subdomain (`official.asos.com`). SPF and DKIM records must explicitly cover this subdomain — it will not inherit `asos.com`'s top-level authentication. Verify with:
