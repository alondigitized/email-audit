# 20% off full-price ends tomorrow 👀
**Score:** 9/10 · **Type:** Email audit · **2026-05-31**
## Executive summary

- This is the final-day urgency send in a four-email campaign sequence (VIP tease 5/29 → public launch 5/30 → day-2 reminder 5/31 → this). Mechanically, it executes the "ends tomorrow" frame exactly right: the announcement bar surfaces the deadline and promo code (TOM) in the first pixels, the 20% OFF hero is dominant and unambiguous, and the category tile grid with embedded discount badges makes scanning fast. That's all solid work.
- The problem is volume. This is Backcountry's second email today and the fourth consecutive day on the same offer. A subscriber who's opened every message in this sequence isn't learning anything new here — the creative architecture is functionally identical to the 5/31 morning send ("20% off full-price items is ON 🏁"). The urgency mechanic ("ends tomorrow") does differentiate the subject line, but anyone who wanted to shop at 20% off has had four days to do it.
- The email stands on its own. The campaign has been run one send too long, and this one bears the weight of that decision.

## What's working

- Announcement bar leading with "ENDS TOMORROW | CODE: TOM" puts the deadline and activation code in the first-pixel scan zone — no digging required.
- 20% OFF badge repeated consistently on every category tile removes any ambiguity about offer scope.
- Category segmentation (Men's Apparel, Women's Apparel, Men's Footwear, Women's Footwear, Climb, Bike) gives multiple entry points for different buyer intents.
- TOP BRANDS section late in the scroll provides a brand-discovery hook that recovers engagement at depth.
- No visible render bugs — layout, images, and typography all appear clean.

## What's weak

- Second Backcountry email today on the same offer; cadence fatigue is the single biggest headwind at this point.
- Hero CTA "SHOP NOW" is generic for a last-chance send — does nothing to reinforce the urgency already in the subject.
- Promo code (TOM) is surfaced only in the announcement bar; on mobile clients that clip or hide the top bar, it disappears entirely.
- No personalization or behavioral hook ("you haven't shopped yet," "items in your category") to distinguish this from the prior three sends.

## Recommendations

- 1. **Suppress the second daily send for prior-openers / prior-clickers.** If someone already bought off the 5/31 morning email, hitting them again with the same offer in the evening is a relationship cost with no upside. Target this send to non-openers of the morning message only.
- 2. **Sharpen the hero CTA.** "Shop Before Midnight" or "Shop the Final Hours" costs nothing to change and directly echoes the subject-line urgency — "SHOP NOW" wastes that momentum.
- 3. **Repeat the code in the hero body.** "Use code TOM at checkout" as a one-liner under the 20% OFF headline ensures it survives any mobile top-bar clipping.
- 4. **Add one behavioral or personalization hook.** Even a rule-based one ("Top picks in Men's Footwear since you browsed last week") separates this send from a broadcast blast.

### 2. Link & Tracking Issues

**External font stylesheet — single point of failure**
```
https://partner-fonts.bluecore.com/backcountry/backcountry_fonts_1769208036.css
```
Loaded via `<link rel="stylesheet">` in `<head>`. Most email clients strip `<link>` tags entirely (Gmail, Outlook), so this load silently fails in the majority of clients. The risk is already mitigated if the CSS also declares stack fallbacks inline, but if Backcountry brand fonts are defined only in this file, all non-Apple-Mail clients will fall back to system defaults.

### 3. Rendering & Accessibility

**Confirmed CSS bug — `.md-fluid-row .col-9` width missing; `.md-fluid-row .col-8` duplicated**

In the mobile media query:
```css
/* correct */
.fluid-row .col-8,.md-fluid-row .col-8 { width: 66% !important; }

/* BUG: second selector should be .md-fluid-row .col-9, not .col-8 */
.fluid-row .col-9,.md-fluid-row .col-8 { width: 74.25% !important; }
```
Result: `.md-fluid-row .col-8` gets `74.25%` (last-rule-wins cascade) instead of `66%`. `.md-fluid-row .col-9` has no mobile width rule and inherits desktop width, breaking the 9-column responsive grid in media-query-capable clients (Apple Mail, Samsung Mail, Outlook iOS).

**`-webkit-text-size-adjust: none !important` applied too broadly**
```css
div,p,a,li,span,td { -webkit-text-size-adjust: none !important; }
```
Using `none` (rather than `100%`) prevents iOS Safari from scaling up small text if a user has set accessibility font size preferences. Should be `100%`.

**No `lang` attribute on `<html>`**
Not present in the truncated source. Missing `lang` breaks screen-reader language detection and is an accessibility/compliance gap.
