# 20% off full-price items is ON 🏁
**Score:** 9/10 · **Type:** Email audit · **2026-05-31**
## Executive summary

- This is a day-2 reminder on an active 20% off full-price-items sale — the third send in three consecutive days (VIP tease 5/29, public launch 5/30, now this). The core offer and creative architecture are functionally identical to yesterday's "has landed" send: same orange-strip "LIMITED TIME ONLY" banner, same dark-hero outdoor imagery, same product grid, same SHOP NOW buttons. A subscriber who opened yesterday is looking at nearly the same email today.
- The execution is clean — no broken images, clear hierarchy, Summit Club top-bar context — but the creative has nothing new to say. The product grid (footwear, gaiters) does exactly what a browse-prompt grid should do, but there's no pricing, no countdown, and no urgency mechanism to differentiate this from yesterday.
- The honest read: this is a competent day-2 cadence send that will catch the people who missed yesterday, but offers near-zero reason to click for anyone who already saw the launch email.

## What's working

- **20% off is instantly readable** — the oversized headline type dominates within the first scroll, no ambiguity about the offer.
- **Top bar adds a secondary hook** — the "10% instant cash back with Summit Club · Join Now" line gives passive subscribers a membership prompt that doesn't dilute the main CTA.
- **Brand logo strip (Nemo, Outdoor Research, +More)** bridges the hero and the product grid cleanly, reinforcing that the 20% applies to recognizable brands.
- **Product grid has specific names** (Topo Athletic ST-6, Scarpa Falkon Plus GTX, Merrell Wrap Sneaker) rather than generic thumbnails — each card is a real product link, not a homepage dump.
- **No render bugs visible** — images load, text doesn't overlap, mobile layout holds.

## What's weak

- **Creative is indistinguishable from yesterday's launch email** — anyone who opened "has landed" (5/30) is looking at a pixel-near-identical send with a minor subject-line tweak.
- **No urgency mechanism** — the 5/29 VIP tease had a 24-hour window that made urgency feel credible. This send just says "LIMITED TIME ONLY" in a banner with no clock, no end date, no stakes.
- **Product grid shows no prices** — the cards give product names but no price points or discount callouts, which removes the most concrete reason to click through.
- **Hero image is dark and small-scale** — the two silhouetted figures on a rock read as generic stock; compared to previous Backcountry sends with more defined product-as-hero imagery, this is the weakest visual in the recent cadence.
- **SHOP NOW fatigue** — the body has three separate "SHOP NOW" buttons with no differentiated destination signals (category vs. brand vs. product).

## Recommendations

- 1. **Add a deadline or a clock.** Even "Ends Monday night" in the hero strip changes the calculus entirely. The 5/29 VIP send worked because "24-hour window" made urgency real. Day-2 sends need a hard close time or they read as indefinite.
- 2. **Show prices in the product grid.** At minimum, show the sale price next to the MSRP for the four featured products. "$140 → $112" is more compelling than "Shop Now" with no context.
- 3. **Differentiate the subject line hard from yesterday.** "Has landed" → "is ON 🏁" is too close. If you're sending day-2, signal that something is new (a featured brand, a top seller, or a countdown).
- 4. **Swap the hero to a specific product or a brand focus.** The dark silhouette imagery is a visual step down from the urgency creative used earlier in the week. A clean product hero with a visible price tag at 20% off would outperform.
- 5. **Consolidate the three SHOP NOW buttons** — one hero CTA to the sale landing page, and the brand-logo strip as the secondary click path.
- **Subject Alt A:** `"Day 2: 20% off — top picks before they go"`
- **Subject Alt B:** `"Still running: 20% off Scarpa, Nemo, The North Face"`
- **Preheader Alt A:** `"Full-price gear from The North Face, Osprey, Rab — all 20% off today."`
- **Preheader Alt B:** `"Sale ends soon — grab the Scarpa GTX boot and more at 20% off."`

### 3. Rendering & Accessibility

**Confirmed bug — CSS selector typo in mobile stylesheet:**

```css
/* As written: */
.fluid-row .col-9, .md-fluid-row .col-8 { width: 74.25% !important; }

/* Should be: */
.fluid-row .col-9, .md-fluid-row .col-9 { width: 74.25% !important; }
```

`.md-fluid-row .col-8` is re-declared here (overriding the correct 66% rule above it), and `.md-fluid-row .col-9` receives no mobile width override at all. Any 9-column fluid row in the md breakpoint will render at wrong width on mobile.

**`-webkit-text-size-adjust: none` applied globally:**

```css
div, p, a, li, span, td { -webkit-text-size-adjust: none !important; }
```

Using `none` (not `100%`) fully disables iOS/Android font scaling for users with accessibility text-size settings. This is a WCAG 1.4.4 violation. Change to `100%`.

**External CSS dependency:**
`partner-fonts.bluecore.com` stylesheet must load before custom fonts render. Clients that block remote CSS (Outlook desktop, some enterprise webmail) will fall back to system fonts — acceptable if fallback stack is defined, but worth confirming in Bluecore template settings.

**`<title>` tag:** Contains raw emoji via numeric entity (`&#127937;`) — renders correctly in most clients but may display as `?` or empty in some legacy preview panes. Low priority.

**Viewport meta present:** `<meta name="viewport" content="width=device-width">` — correct.
**Charset declared:** `utf-8` — correct.
**Format detection disabled:** `telephone=no` — correct for retail email.
