# Welcome to Backcountry 🐐 Enjoy 15% off your next purchase
**Score:** 8/10 · **Type:** Email audit · **2026-05-16**
## Executive summary

- This is a classic welcome email from Backcountry — the kind that tries to do five jobs at once and ends up doing none of them perfectly. The 15% off welcome discount is front and center, the branding is clean, and the "Jump Right In" category grid is a solid onboarding mechanic. However, the preheader leads with a niche First Responder 20% off promo that creates immediate cognitive dissonance for the 90%+ of recipients who aren't first responders. You click to claim 15% off and the first thing your inbox showed you was a different, better deal you probably don't qualify for.
- The email's biggest structural problem is scope creep: welcome + promo code + first responders offer + category navigation + newsletter signup + Summit+ loyalty program. That's six competing asks. The promo code is the only one that matters on day one, and it gets diluted by everything around it.
- Overall this is a competent but unfocused welcome send. The 15% offer is real value, the brand is trustworthy, but the execution buries its own lede.

## What's working

- **15% off hero is unmissable** — large type, promo code shown, and a "SHOP NOW" button right below; the offer is immediately actionable.
- **"Jump Right In" category grid** is an excellent welcome mechanic — gives new subscribers a map of the catalog without overwhelming.
- **Summit+ cash-back section** smartly introduces the loyalty program in the welcome flow, planting the seed for retention.
- **Layout is clean, no render bugs** — images load, text doesn't overlap, hierarchy reads naturally top-to-bottom.
- **Backcountry branding is consistent** throughout — mountain imagery, goat mascot, earthy palette all reinforce the outdoor identity.

## What's weak

- **Preheader is a first-responder offer** — if you're not a healthcare worker, teacher, or military member, the 20%-off preheader feels like bait that doesn't apply to you before you even open the email.
- **No expiry on the 15% promo code** — removing time pressure on the primary offer is a missed urgency lever; welcome discounts should have a clear deadline (e.g., "Valid 7 days").
- **"SHOP NOW" is repeated six-plus times** with no specificity — by the third instance it means nothing; each CTA should pull toward a category.
- **Ski/snowboard imagery is off-season** — action shots of snowboarders in May (spring/summer transition period) signal catalog misalignment.
- **Four distinct asks compete for attention** — shop with code, first responders offer, sign up for drops, join Summit+. For a welcome email, one CTA should dominate.

## Recommendations

- 1. **Fix the preheader immediately** — the First Responder offer should not be the preview text for a generic welcome email. Segment it or replace the preheader with a line that amplifies the 15% off and welcomes the subscriber.
- 2. **Add a 7-day expiry to the promo code** — "Code expires May 22" in the hero creates urgency without false scarcity.
- 3. **Cut the email in half** — remove the "Fresh Drops" newsletter signup and the Heroes section from the welcome email; save them for drip emails 2 and 3. One primary job per email.
- 4. **Make CTAs category-specific** — replace generic "SHOP NOW" with "Shop Men's Gear," "Shop Women's Apparel," etc. to match the grid labels already visible.
- 5. **Swap ski imagery for May-appropriate content** — hiking, camping, trail running. A snowboarder in mid-May reads as stale.

- **Subject Alt B:** `Welcome 🐐 Here's 15% off. Use it this week.`

## Technical Audit

## Technical Audit — Backcountry Welcome Email

### 1. Technical Summary
Email is built on Bluecore ESP using a table-based layout with inline responsive CSS. One confirmed CSS selector regression and a missing `lang` attribute are the primary technical issues; the rest depends on the truncated link/footer content.

---

### 2. Link & Tracking Issues
- **External font dependency with no fallback**: The `<link>` tag loads `https://partner-fonts.bluecore.com/backcountry/backcountry_fonts_1769208036.css` at render time. If that CDN is slow or unavailable, the font silently degrades — but no system-font fallback is declared in the `<link>` element itself. If the font-face declarations inside that stylesheet don't include a `font-display: swap` or equivalent fallback, text may render blank until timeout in some clients.
- **Click-tracking URLs**: Not visible in the truncated source. Bluecore wraps all hrefs through its redirect layer — confirm that the 15% off CTA and any product links carry UTM parameters *before* the Bluecore redirect, not just after, so GA4 / attribution tools see them on the first hop.

---

### 3. Rendering & Accessibility
- **Missing `lang` attribute**: `<html>` has no `lang="en"` attribute. Screen readers (NVDA, VoiceOver) default to system language, which breaks pronunciation for non-default locales and fails WCAG 3.1.1.
- **CSS selector regression — col-9 / col-8 conflict**:
  ```css
  .fluid-row .col-9, .md-fluid-row .col-8 { width: 74.25% !important; }
  ```
  The second selector should be `.md-fluid-row .col-9`, not `.md-fluid-row .col-8`. As written, `.col-8` gets two conflicting widths (66% and 74.25%) in fluid rows, and `.md-fluid-row .col-9` is never defined — any 9-column fluid block on mobile will collapse to 100% via the catch-all rather than the intended 74.25%.
- **`-webkit-text-size-adjust: none !important` on all text elements**: Applied globally to `div,p,a,li,span,td`. Using `none` (not `100%`) fully disables user font-size scaling in WebKit, overriding accessibility settings. `100%` is the correct value to prevent iOS auto-inflate while preserving user overrides.
- **Alt text**: Not verifiable from the truncated source — confirm all `<img>` tags have non-empty `alt` attributes, particularly the hero and product images.

---

### 4. Personalization & Merge Tokens
- No unresolved merge tokens visible in the provided source.
- Subject line emoji (`&#128016;` / 🐐) is HTML-entity-encoded in the `<title>` tag, which is correct; subject line delivery uses the raw Unicode character — no issue.
- Confirm the recipient email address is substituted dynamically in the unsubscribe link and any "email preferences" URL, not hardcoded or left as a template placeholder.

---

### 5. Compliance (CAN-SPAM / GDPR / Authentication)
- **Unsubscribe / physical address**: Not visible in the truncated source. Confirm the footer contains: (a) a one-click unsubscribe link, (b) Backcountry's physical mailing address, and (c) that the unsubscribe mechanism processes within 10 business days per CAN-SPAM §5(a)(3).
- **Sending domain**: `orders.backcountry.com` is a dedicated sending subdomain, which is correct practice. Verify SPF, DKIM, and DMARC are aligned for this subdomain specifically (not just `backcountry.com`) — a subdomain policy of `p=none` on DMARC would pass technically but provide no enforcement protection.
- **List-Unsubscribe header**: Should be present in the SMTP headers as both `mailto:` and `https:` variants for one-click unsubscribe support in Gmail and Apple Mail. Not verifiable from HTML alone — check raw message headers.

---

### 6. Email-to-Site Continuity
- **UTM parameters**: Cannot confirm from truncated source. All links to `backcountry.com` should carry at minimum `utm_source`, `utm_medium`, and `utm_campaign`. For a welcome/discount email, also confirm `utm_content` differentiates the hero CTA from any nav or footer links so click attribution is granular.
- **Discount code delivery**: If the 15% off code is delivered via merge token or dynamic block (Bluecore personalization), confirm the code renders correctly for new accounts with no prior purchase history — the most common failure mode for welcome flows is a condition branch that returns an empty string when the new-user flag is set.
- **Landing page alignment**: Confirm the CTA URL lands on a page that prominently displays the 15% off offer or auto-applies the code. A disconnect between email promise and landing page content is the top conversion killer for welcome flows.
