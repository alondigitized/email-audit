# Hero Dirt Sweepstakes! Win a Santa Cruz Vala & More
**Score:** 6/10 · **Type:** Email audit · **2026-05-19**
## Executive summary

- This is a sweepstakes acquisition email, a hard format pivot from the relentless promotional cadence Backcountry has been running all week (five sale blasts since May 17). The hero concept is simple: answer a quiz ("Hero Dirt") and get entered to win a Santa Cruz Vala GX AXS eMTB, a Backcountry Slickrock kit, and a 2-night glamping stay. The prize stack is genuinely compelling for an MTB-oriented subscriber — a $10,000+ bike headlining it is not a soft prize.
- The execution is messy, though. The layout leans on a hand-annotated "doodle" style overlaid on the hero that reads as cluttered rather than playful. The copy block beneath the hero does most of the lifting, but it's dense and small-type. The single "ENTER NOW" CTA is clean and unambiguous, which saves the email from falling apart entirely.
- Judged honestly, this is a format refresh that needed more polish. It breaks the sale-blast fatigue but trades legibility for aesthetic. A strong concept at 60% execution.

## What's working

- **Prize is real and specific** — "Santa Cruz Vala GX AXS" with a dollar value implied by the brand name; not vague merchandise.
- **Single, clean CTA** — "ENTER NOW" button is prominent, centered, and unambiguous.
- **Format break from the sale sequence** — after five consecutive promotional sends this week, a sweepstakes creates genuine inbox contrast.
- **Prize bundle is well-curated** — bike + kit + camping stay tells a coherent "MTB adventure" story rather than random prizes.

## What's weak

- **Hero readability is poor** — hand-drawn annotations and overlaid copy ("THIS COSTS $", "ADD $$$", "RACE HERE") compete with each other and are difficult to parse at a glance.
- **Body copy is too dense and small** — the narrative paragraph under the hero is small-size text that requires active reading; a bulleted prize list would scan faster.
- **No urgency signal in the body** — the June 20 deadline is buried in the prose, not called out visually.
- **No social proof or prize visual isolation** — the Santa Cruz bike is in the hero collage but never gets a clean hero shot that would make someone stop scrolling.
- **Doodle aesthetic feels inconsistent** with Backcountry's typically clean outdoor photography style seen in earlier sends.

## Recommendations

- 1. **Replace the cluttered doodle hero with a clean Santa Cruz bike shot** — the bike is the prize; give it a full-bleed hero that makes someone stop. The annotations add noise, not value.
- 2. **Pull the prize stack into a scannable visual list** — three icons/images: bike, kit, glamping stay. One line each. Legible at a glance.
- 3. **Surface the deadline visually** — "Enter by June 20" should be a callout chip or bold line above the CTA, not buried in a prose paragraph.
- 4. **Tighten the body copy** — current version is two dense sentences; replace with "Take our Hero Dirt quiz → get entered to win" in 15 words or fewer.

### 3. Rendering & Accessibility

**Issue — External font stylesheet stripped by major clients:**
```html
<link rel="stylesheet" href="https://partner-fonts.bluecore.com/backcountry/backcountry_fonts_1769208036.css">
```
Gmail (web and Android), Outlook (Win/Mac), and Samsung Mail strip `<link>` tags from `<head>`. Custom fonts silently fall back to system fonts in these clients. This is expected behavior for email, but worth confirming the fallback stack in the CSS is acceptable.

**Issue — CSS selector typo in responsive grid:**
```css
.fluid-row .col-9, .md-fluid-row .col-8 { width: 74.25% !important; }
```
The rule targets `.md-fluid-row .col-8` instead of `.md-fluid-row .col-9`. As a result, `.md-fluid-row .col-9` has no mobile-width rule and will render at its inherited/desktop width on narrow viewports. `.md-fluid-row .col-8` is double-defined (both the intended `66%` rule above and this `74.25%` rule), with the last declaration winning.

**Issue — Aggressive text-size suppression:**
```css
div,p,a,li,span,td { -webkit-text-size-adjust:none !important; }
```
`-webkit-text-size-adjust: none` (not `100%`) disables iOS automatic text scaling entirely, which can impair readability for users with accessibility needs. The correct defensive value is `100%`.

**Preheader technique:** Zero-width non-joiner (`&#8204;`) padding after the preheader text is a valid anti-preview-bleed technique. No issue.
