## Technical Audit

## 1. Technical Summary
The visible HTML source has several CSS and markup defects (a malformed `body` style, a property-less `table, td` rule, and a bare nested `<table>`). The automated QA found no hard failures, but its 4 warnings are mostly unverifiable because the relay didn't capture headers and the source is truncated before the footer. Link destinations, UTM parameters and footer compliance content couldn't be checked.

## 2. Link & Tracking Issues
- **Opaque tracking links:** QA skipped 43 links on the click-redirect domain (`click.e.thenorthface.com/?qs=…`) without probing them, so none of their destinations are verified. The `qs` payload is an opaque token, so landing URLs can't be read from the source.
- **Empty hidden link:** the first element in the body is `<a href="https://click.e.thenorthface.com/?qs=ABp7Im…" target="_blank"><img src=".../honeypot_pixel.png" width="1" height="1" style="display: none;"></a>`. This looks like a deliberate bot or spam-trap link, but the anchor has no visible content or text. Scanners that follow every link (security gateways, link-checkers) may register a click on it. That is a tracking-data quality risk, not a defect to fix.
- **Plain-text part:** QA reports 8089 of 9693 characters (~83%) are URLs, over the 70% threshold. The long tracking URLs likely drive this, and it can add a small spam-filter score.

## 3. Rendering & Accessibility
- **Invalid `body` inline style:** `style="font-family:'HelveticaNeue-Medium', …, sans-serif margin: 0; padding: 0;"` is missing a semicolon after `sans-serif`. Parsers will drop the `font-family` declaration, and may drop `margin` and `padding` too, depending on error recovery.
- **Property-less CSS rule:** `table, td { 'HelveticaNeue-Medium', 'Helvetica Neue Medium', … }` has no `font-family:` property name, so the rule is invalid and ignored. The same applies to `h1…h6 { 'HelveticaNeue-Medium', … !important; margin: 0px; }`, where the font list is dropped and only `margin: 0px` may survive.
- **Unclosed `@media` block:** in the second `<style>`, `@media only screen and (max-width: 480px) { …` is never closed with `}` before `</style>`. Most clients recover, but strict parsers (Gmail's sanitizer, for example) may discard the block. That would break the `.showMobile` and `*[class*="show"]` mobile rules.
- **Invalid table nesting:** `<table bgcolor="#f4f4f4" style="width:100%…">` is followed directly by `<!-- Begin Preheader Block --> <table id="backgroundWrapper" …>` with no `<tr><td>` wrapper. Browsers and Outlook (Word engine) repair this unpredictably. The outer table also lacks `role="presentation"`, `cellpadding` and `cellspacing`, as do several inner `<table>` elements (`<table> <tr> <td>` around the preheader).
- **Missing alt text:** QA flagged `honeypot_pixel.png` (`https://image.e.thenorthface.com/lib/fe3811717164047a741772/m/1/honeypot_pixel.png`) as having no `alt`. It is `display:none`, so the impact is minor, but the anchor around it is an empty, potentially focusable link.
- **Generic title:** `<title>The North Face</title>` doesn't match the subject line. This is minor.
- **Okay:** `lang="en"`, charset and viewport meta, and the MSO `OfficeDocumentSettings` block are present.
- **Not assessable:** the source is truncated, so alt text on the rest of the images and the table closing structure couldn't be checked.

## 4. Personalization & Merge Tokens
No issues found. The visible source has no unresolved merge tokens (`%%…%%`, `{{…}}`, `[FIRSTNAME]`).

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **No `List-Unsubscribe`:** QA found no `List-Unsubscribe` header. QA notes it may not be captured by the AgentMail relay, so this is unconfirmed.
- **No `List-Unsubscribe-Post`:** QA found no `List-Unsubscribe-Post` (RFC 8058). The same relay caveat applies. If it is genuinely absent, one-click unsubscribe isn't supported, which Gmail and Yahoo require for bulk senders.
- **No `Authentication-Results`:** the header wasn't captured, so SPF, DKIM and DMARC status is unknown. The `From` domain is `e.thenorthface.com`.
- **Footer not seen:** the truncated source doesn't show the footer, so the physical postal address and in-body unsubscribe link couldn't be checked.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not verifiable. Every CTA goes through `click.e.thenorthface.com` with an opaque `qs` token. QA skipped the HTTP probes, and no `utm_*` parameters appear in the visible source. I can't confirm the destinations or whether they match the "jackets down for the cold" subject and preheader ("Outerwear in colors and styles for whatever winter brings.").

## 7. Recommendations
1. **Fix the CSS (sender):** add the missing `;` in the `body` style, add `font-family:` to the `table, td` and `h1–h6` rules, and close the `@media (max-width: 480px)` block.
2. **Fix the markup (sender):** wrap the outer `<table bgcolor="#f4f4f4">` content in `<tr><td>`, and add `role="presentation"` and `cellpadding="0" cellspacing="0" border="0"` to all layout tables.
3. **Fix the honeypot link (sender):** add `alt=""` to the honeypot image and `tabindex="-1" aria-hidden="true"` to its anchor, or hide the whole anchor, so it isn't an empty focusable link.
4. **Capture the headers (our pipeline):** capture raw headers outside the AgentMail relay (a direct MX or Cloudflare worker copy) to confirm `List-Unsubscribe`, `List-Unsubscribe-Post` and `Authentication-Results`. Until then, treat the three header warnings as inconclusive.
5. **Resolve the tracking links (our pipeline):** resolve the `click.e.thenorthface.com` redirects with a single non-following GET to read the `Location` header and check UTM and landing-page alignment. Also store the full, untruncated HTML so the footer and image `alt` attributes can be audited.
6. **Treat the plain-text warning as low priority:** the URL ratio comes from tracking-link length, so it is only worth acting on if the sender controls the text-part generation.
