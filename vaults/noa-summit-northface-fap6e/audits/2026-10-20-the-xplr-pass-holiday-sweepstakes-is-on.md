# The XPLR Pass Holiday Sweepstakes is on.
**Score:** 7/10 · **Type:** Email audit · **2026-10-20**
## Executive summary

- This is a sweepstakes email, and a good break from the six fall-layer lookbooks The North Face sent between 09-28 and 10-16. The mechanic is simple: favorite holiday picks and you could win one of four $1,000 e-gift cards. The hero is a gondola carrying duffels, and the blue "how to enter" block is easy to follow.
- The $1,000 headline works, but the real goal is XPLR Pass sign-ups and product favoriting, and the email says so plainly. The back half is a standard three-section gift grid (Her, Him, Kids) with small heart icons. That's the same catalog format as the 10-02 "Complete your fall look" send, which means a lot of scrolling after the offer. The email is clean and on-season, but it's long, and the "Enter Today" button sits below the first screen on mobile.
- Judgement: a solid, honest, well-structured promo that isn't in a rut. It would do better if the entry mechanic were cut down and the deadline were prominent.

## What's working

- "Favorite your holiday picks for a chance to win a $1,000 e-gift card." states the prize in one line.
- The four numbered steps in the blue block make entry easy to understand.
- "Enter Today" appears twice, as a black button on white and a white button on blue, so it's easy to find.
- The XPLR Pass loyalty strip at the bottom ("Free Shipping always. Points on every purchase.") ties the sweepstakes to membership.
- Splitting the grid into Her, Him and Kids, each with its own "Shop Gifts for…" button, gives clear paths.

## What's weak

- The "Terms apply" asterisk and the Official Rules link are tiny. Four winners from a large list is a thin prize pool, and the odds aren't stated.
- The 11.13 end date is buried in step 4, so urgency is weak.
- The hero is a lifestyle image with no button, so the first screen has a headline but no action.
- The product grids are long, and some products are repeated, such as the Thermoball mules in both the Her and Him sections. That dilutes the sweepstakes message.
- The entry flow has four steps and requires sign-in or sign-up first, which is a lot of friction. Product tiles show no prices or ratings.

## Recommendations

- 1. Put the deadline and a button in the hero, for example "Enter by 11/13" with an "Enter Today" button, so the action is visible on the first screen.
- 2. Cut the product grid to about four featured favorites with a single "Shop Gifts" button, or move the grids below a clear "heart to enter" prompt.
- 3. Show the odds, or the number of winners, near the headline ("4 winners") and make the rules link larger.
- 4. Add urgency near the bottom, and add a "save to your list" reminder tied to entry.

- **Preheader Alt A:** `Four winners. Sign in, save your favorites, and you're entered through 11/13.`

## Technical Audit

## 1. Technical Summary
The visible source has several CSS syntax errors (a dropped `font-family`, a malformed `body` style, an unclosed `@media` block) and invalid table nesting, and its plain-text part is heavily URL-weighted. The compliance and authentication checks couldn't be confirmed: the headers weren't captured, and the footer and link destinations are outside the truncated source.

## 2. Link & Tracking Issues
- **Opaque ESP wrapping (cannot verify):** All 48 tracked links use `https://click.e.thenorthface.com/?qs=…` (an encoded redirect). The QA probe skipped them, so destination status, redirect chain and landing pages are unverified.
- **Honeypot link:** The first element is `<a href="https://click.e.thenorthface.com/?qs=ABp7Im…"><img src=".../honeypot_pixel.png" width="1" height="1" style="display: none;"></a>`. It looks like an intentional spam-trap link. If a security scanner or link prefetcher follows it, it could generate false click or bot signals. Confirm your ESP excludes it from engagement metrics.
- **Plain-text part:** 9,029 of 10,639 characters (about 85%) are URLs, so the plain-text alternative is mostly long tracking URLs. This can hurt spam scoring and readability for text-only clients.

## 3. Rendering & Accessibility
- **Missing `font-family` property (head CSS):** `table, td { 'HelveticaNeue-Medium', … sans-serif; }` has no property name. The same happens in the `h1…h6` rule. Browsers drop those declarations, so `h1`–`h6` and tables fall back to the client default font. The `margin: 0px` in the heading rule is still applied.
- **Missing semicolon on `<body>`:** `style="font-family:'HelveticaNeue-Medium', … sans-serif margin: 0; padding: 0;"`. The `font-family` value becomes invalid and is dropped, and `margin: 0` is probably lost too. The head rule `body { margin: 0 auto !important; padding: 0 !important }` partly compensates.
- **Unclosed `@media`:** The `@media only screen and (max-width: 480px) { … }` block in the `<!--[if false]><!-->` style has no closing `}` before `</style>`. Browsers auto-close it at the end of the stylesheet, but stricter parsers may not. It could also swallow any rules added after it.
- **Invalid table nesting:** `<table bgcolor="#f4f4f4" …>` is followed directly by `<!-- Begin Preheader Block --> <table id="backgroundWrapper" …>`, with no `<tr><td>` between them. The HTML parser will foster-parent the inner table. The outer table also lacks `role="presentation"`, `cellpadding`, `cellspacing` and `border`. The inner `<table> <tr> <td>` around the preheader also lacks `role="presentation"`, so screen readers may announce layout tables.
- **`max-width` on layout:** `#backgroundWrapper` and `<td … style="max-width: 600px;">` rely on `max-width`, which Outlook desktop (Word engine) ignores. No MSO ghost table is visible in the truncated source, so it may render full-width there.
- **Missing alt on the honeypot image (QA warning):** `honeypot_pixel.png` has no `alt` attribute. The `display:none` styling hides it from assistive tech, so impact is low. `alt=""` would still be correct.
- **Small text:** `.disclaimer { font-size: 8px }` at `max-width: 400px` is below common legibility minimums. `.footer` is 11px.
- **Generic `<title>`:** `The North Face` doesn't match the subject, which affects the web-view tab and accessibility context.
- **Preheader duplicates:** The inline style repeats `font-size` (1px, then 11px) and `color` (#333333, then #999999). The later values win, and the element is `display:none` anyway, so there is no functional impact.

## 4. Personalization & Merge Tokens
No issues found. No unresolved tokens (`%%…%%`, `{{…}}`, `[FIRSTNAME]`) appear in the visible source. The footer and body are truncated, so this covers only the visible portion.

- **Authentication-Results:** Not found, so SPF, DKIM and DMARC are unknown. The From domain `e.thenorthface.com` matches the tracking and image subdomains (`click.e.`, `image.e.`), which is good for alignment.

## 7. Recommendations
1. **Fix the CSS syntax errors:** add `font-family:` to the `table, td` and `h1…h6` rules, add the missing `;` in the `<body>` style, and close the `@media (max-width: 480px)` block.
2. **Fix the table structure:** wrap the inner tables in a valid `<tr><td>` and add `role="presentation"`, `cellpadding="0"`, `cellspacing="0"` and `border="0"` to all layout tables.
3. **Outlook layout:** add an MSO ghost table or fixed `width="600"` so the 600px layout holds in Outlook desktop.
4. **Honeypot image:** set `alt=""`, and verify the honeypot URL is excluded from click reporting.
5. **Headers:** inspect the raw source message for `List-Unsubscribe`, `List-Unsubscribe-Post` and `Authentication-Results`. If the relay is stripping them, fix capture in the audit pipeline so this check stops producing warnings.
6. **Link resolution:** run a redirect-following pass on a sample of the `click.e.thenorthface.com` links to check destinations, status codes and UTMs.
7. **Plain text:** reduce URL density in the text alternative, for example by using shorter links.
8. **Minor:** use a unique `<title>` and raise the mobile disclaimer above 8px.
