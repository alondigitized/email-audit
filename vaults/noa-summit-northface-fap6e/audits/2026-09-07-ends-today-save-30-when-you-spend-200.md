# Ends today: Save 30% when you spend $200+
**Score:** 6/10 · **Type:** Email audit · **2026-09-07**
## Executive summary

- This is day five of the exact same XPLR Pass "Spend $200+" creative, now wearing its "final day" costume. The September 3rd send introduced this mechanic, and it's run essentially unchanged through the 4th, 5th, and 6th — same black hero block, same headline shape, same "*Terms apply." asterisk, same category grid underneath. Today's only move is swapping "Ends tomorrow" for "Ends today," which is the correct urgency escalation for a real deadline but doesn't disguise that a subscriber has now seen this block five days running.
- The good news is the render itself is clean: no broken images, clear hero hierarchy, a product grid that actually shows fall gear (fleece, insulated jackets, backpack, trucker hat, boots), and a legitimate "Already on Sale? Still Included" teal panel that adds a second reason to click. But five consecutive near-identical sends is a cadence problem that no amount of clean execution fixes — this reads like the brand ran out of new creative for the loyalty threshold and is just riding the countdown to the deadline.
- Judgement: solid execution of a stale campaign. The urgency is now credible (today really is the last day, per the history), which should lift open rate over the prior four sends, but repetition fatigue caps the ceiling.

## What's working

- "Ends today" creates real, credible urgency — this is genuinely the terminal day of the promo per the brand history, unlike vaguer "ends soon" framing.
- Product grid is diverse and seasonally relevant: fleece vest, insulated parka, kids' gear, travel backpack, trucker hat, boots — decent breadth for one email.
- "Already on Sale? Still Included" panel is a smart secondary CTA that removes the common "sale exclusions" objection before the shopper even asks.
- XPLR Pass member-exclusive framing is visually consistent (badge, black block) and reinforces loyalty tie-in at both top and bottom of the email.
- No render bugs — text is legible, images load, spacing is even.

## What's weak

- This is the fifth consecutive day of the identical "Spend $200+, Get 30% Off" black-hero creative — zero visual differentiation from the 3rd/4th/5th/6th sends.
- "Member Exclusive" gating with a $200 spend floor is a high bar buried under generic hero copy — no visible mention of how close a shopper might already be to qualifying.
- No product pricing or sale percentage shown on individual grid items — shopper has to click through blind to see if a $200 vest+boots combo even works.
- Fine-print asterisk ("*Terms apply.") is still doing the heavy lifting for exclusions, same complaint as every prior send in this thread.

## Recommendations

- 1. **Break the creative pattern.** Five straight days of the same hero block trains subscribers to skip this email on sight. For the final-day send specifically, swap in a countdown timer or a bolder "LAST CALL" treatment distinct from days 1-4 — differentiation matters most on the day you most need the click.
- 2. **Add a price/qualifying hint to the grid.** Show at least one item's price so shoppers can gut-check the $200 threshold without clicking through.
- 3. **Tighten the subject for true last-day urgency** — "Ends today" is good, but pairing it with a hard time (e.g., "11:59pm ET") would sharpen the deadline.
- 4. Move "Already on Sale? Still Included" higher — it's currently a scroll-deep afterthought, but it removes a real purchase objection and deserves hero-adjacent placement on the last day.

# Technical Email Audit: The North Face — "Ends today: Save 30%..."

**1. Technical Summary**
Standard ESP-templated (Salesforce Marketing Cloud/Cordial-style) responsive HTML email with MSO/Outlook conditional blocks and mobile media queries; automated QA passed 50% of checks with 4 warnings and 0 hard failures.

**2. Link & Tracking Issues**
- Primary CTA and header link route through `click.e.thenorthface.com/?qs=ABB7InYiOjEsImQiOjQ5OTJ9AAsAAAAABJ_l...` — a standard ESP click-tracking redirect.
- A 1x1 tracking pixel (`honeypot_pixel.png`, see below) is wrapped in an `<a>` tag pointing to the same click-tracking redirect, which is unusual — tracking pixels are normally unlinked `<img>` elements, not anchors. This isn't necessarily a bug but is worth noting as non-standard markup.
- QA flagged 37 tracking/click-redirect links skipped from HTTP probing (expected behavior — redirect domains are not resolved to avoid false positives, not a defect).
- No further redirect destinations were provided in the truncated source, so final landing URLs cannot be verified.

**3. Rendering & Accessibility**
- `honeypot_pixel.png` (1x1 tracking pixel) is missing `alt` text. Low-impact since `display:none` and 1x1 dimensions mean screen readers rarely surface it, but best practice is `alt=""` to explicitly mark it decorative.
- Extensive Outlook/MSO conditional comments (`<!--[if gte mso 9]>`, `<!--[if true]>`) and Yahoo/Samsung-specific fixes are present, indicating reasonable cross-client hardening.
- The `<style>` block has a malformed rule: `table, td { 'HelveticaNeue-Medium', 'Helvetica Neue Medium', ... }` — missing the `font-family:` property name, so this rule is dropped by parsers. Same pattern in `h1, h2, h3, h4, h5, h6 { 'HelveticaNeue-Medium', ... }`. Fallback fonts will not apply via these selectors (though `font-family` is separately set inline on `<body>`, so visual impact is likely limited to headings/table text not covered by the body style).
- Preheader text uses long chains of `&nbsp;&zwnj;` padding characters — functional but adds significant hidden markup weight.

**4. Personalization & Merge Tokens**
- No unresolved merge tags (e.g. `%%FIRSTNAME%%`, `{{...}}`, `*|FNAME|*`) visible in the truncated source.
- No issues found.

**5. Compliance (CAN-SPAM, unsubscribe, authentication headers)**
- `List-Unsubscribe` header not found in the message headers — one-click unsubscribe cannot be confirmed at the header level (may be present in the HTML footer, which is beyond the truncated source, but is not enforceable/machine-readable without the header).
- `List-Unsubscribe-Post` (RFC 8058) header not found — even if `List-Unsubscribe` exists, without this header mail clients (Gmail/Yahoo) cannot present true one-click unsubscribe.
- `Authentication-Results` header not found — SPF/DKIM pass/fail status could not be verified via the relay; this is noted as an infrastructure/relay visibility gap rather than a confirmed auth failure.
- Sender uses `reply@e.thenorthface.com`, a dedicated subdomain — consistent with standard ESP sending practice, no evidence of domain spoofing.

**6. Email-to-Site Continuity (UTM params, landing page alignment)**
- All observed links use opaque ESP redirect tokens (`?qs=...`) rather than direct UTM-tagged URLs, so UTM parameter presence/accuracy cannot be verified without following the redirect chain.
- Cannot confirm landing page alignment (e.g., that the 30%/$200+ offer is reflected on the destination page) since only the redirect entry point is visible in the truncated source.

**7. Recommendations**
- Fix the malformed CSS rules (`table, td {...}` and `h1–h6 {...}`) by adding the missing `font-family:` property.
- Add `alt=""` to the tracking pixel image for correct accessibility semantics.
- Confirm `List-Unsubscribe` and `List-Unsubscribe-Post` headers are actually being sent (check upstream of the AgentMail relay, since the relay may simply not be surfacing them) — required for Gmail/Yahoo bulk sender compliance.
- Verify SPF/DKIM/DMARC alignment independently (e.g., via a direct header capture or `mail-tester.com`) since `Authentication-Results` wasn't observable through this relay.
- Follow the redirect chain on the primary CTA to confirm final landing URL includes correct UTM parameters and matches the promoted offer.
