# Get 25% off select gear for Memorial Day.
**Score:** 10/10 · **Type:** Email audit · **2026-05-16**
## Executive summary

- This is the second Memorial Day sale email from The North Face in two days — May 14 sent "Memorial Day Sale: Save 25% on select gear," and today's subject is "Get 25% off select gear for Memorial Day." The offer, creative structure, and four-category grid are functionally identical. For a subscriber who opened the May 14 send, this reads as a straight repeat, not a reminder or an escalation. That cadence problem is the defining weakness of an otherwise solid email.
- Judged in isolation, the execution is tight. Hero offer loads above the fold, the deadline (ENDS 5.25) is prominent, the four category tiles give clear paths to Women's, Men's, Footwear, and Bags & Gear, and the XPLR Pass bar appears both at top and bottom. Visual hierarchy is clear; no render bugs.
- Verdict: competent template work undermined by a lazy deployment decision. If you're going to send twice on the same promotion, you need differentiated creative — a specific bestseller, a "last chance" angle, or segment-level targeting. Without that, this second send trains subscribers to ignore the first email.

## What's working

- Hero offer ("Up to 25% Off Select Gear") and hard deadline (ENDS 5.25) land immediately without scrolling — no ambiguity about what the email is for.
- Four-category grid (Women's, Men's, Footwear, Bags & Gear) gives distinct click paths for different shopper intents without feeling cluttered.
- XPLR Pass loyalty banner runs at both top and bottom, reinforcing member value twice without being intrusive.
- Models appropriately represent both genders in outdoor/activewear context — on-persona.
- Clean layout, zero render bugs, no broken images or text overlap visible.

## What's weak

- This is a near-duplicate of the May 14 send — same offer, same structure, essentially the same subject line. A subscriber who opened two days ago gets no new information.
- "Shop Sale" lands on a general sale page — no hero product, no specific SKU surfaced to anchor the click.
- No social proof anywhere — ratings, review counts, or bestseller callouts would add credibility and specificity.
- Subject drops the deadline entirely ("Memorial Day" implies a deadline but gives no date), even though the hero copy has ENDS 5.25 right there to use.
- Footer navigation shows "Men's | Kids'" with no Women's link — conspicuous given Women's Sale leads the category grid.

## Recommendations

- 1. **Differentiate the creative from May 14** — if you're sending twice, earn the second send. Lead with a single hero product ("The Dryzzle jacket is 25% off — ends Sunday"), or shift to a "last chance" frame, or segment by gender/category. A pixel-for-pixel repeat punishes engaged subscribers.
- 2. **Put the deadline in the subject** — ENDS 5.25 is doing real urgency work inside the email; it should be in the subject line too.
- 3. **Feature one specific product in the hero** — a named jacket, shoe, or pack with a direct PDP link drives higher click intent than a generic sale-page CTA.
- 4. **Add a bestseller or review signal** — even "Top-rated by 2,400+ hikers" on the footwear tile moves the needle.
- 5. **Fix the footer nav** — Women's Sale is a hero category tile but absent from the footer navigation.

### 2. Link & Tracking Issues

**Plain-text part is 78.6% URLs** (5,637 of 7,167 chars per QA). This is well above the ~40% threshold where Spamhaus/Barracuda heuristics begin penalizing. A URL-dense plain-text part with no substantive prose looks machine-generated to filters.

### 3. Rendering & Accessibility

**Broken `font-family` declarations (CSS parse failure):**
```css
/* As written — property name missing, value is a bare string */
table, td { 'HelveticaNeue-Medium', 'Helvetica Neue Medium', ... }
h1, h2, h3, h4, h5, h6 { 'HelveticaNeue-Medium', ... !important; }
```
Both rules are missing the `font-family:` property name. Standards-mode parsers (Gmail web, Apple Mail, most mobile clients) will silently discard these declarations, falling back to the UA default serif or sans-serif. Only the `body` inline style and any inherited declarations will apply.

**Missing semicolon in `body` style attribute:**
```html
<body style="font-family:'HelveticaNeue-Medium', ... Arial, sans-serif margin: 0; padding: 0;">
```
There is no `;` between the `font-family` value and `margin: 0`. Parsers will treat `sans-serif margin: 0` as part of the font-family value and ignore `margin` and `padding` on the body.

**Outer table missing `<tr><td>` wrapper:**
```html
<table bgcolor="#f4f4f4" style="width:100%...">
  <!-- immediately nests another table, no <tr><td> -->
  <table id="backgroundWrapper" ...>
```
Malformed table nesting. Strict renderers (Outlook, some webmail) will attempt to auto-correct, which can produce unexpected column widths or collapse the outer background.

**Unclosed mobile media query block:** The `@media only screen and (max-width: 480px)` block inside `<!--[if false]><!-->` appears to be missing its closing `}` before `</style>`. If the truncation cut this off mid-rule, renderers that evaluate the block will discard all subsequent style rules.

**`align-content` used in email CSS:**
```css
.disclaimer { font-size: 8px; align-content: center !important }
```
`align-content` is a flexbox/grid property with no email-client support. Use `text-align: center` instead.

**Non-standard conditional comment:**
```html
<!--[if false]><!-->
```
The standard idiom for targeting non-MSO clients is `<!--[if !mso]><!-->`. `[if false]` evaluates to false in Outlook's VML parser (so the block is hidden from Outlook as intended), but it is not conventional and may behave unexpectedly in conditional-comment-aware clients.

### 5. Compliance

**`List-Unsubscribe` header absent** (QA: `[WARN]`). Gmail, Yahoo, and Apple Mail use this header to render the native unsubscribe button in the message chrome. Its absence increases the likelihood of "Report Spam" being the user's only visible opt-out, which directly harms sender reputation.

**`List-Unsubscribe-Post` header absent** (QA: `[WARN]`, RFC 8058). Gmail has required one-click unsubscribe (`List-Unsubscribe-Post: List-Unsubscribe=One-Click`) for bulk senders since February 2024. Its absence puts the sender out of compliance with Google's bulk sender policy.

**`Authentication-Results` header not found** (QA: `[WARN]`). SPF, DKIM, and DMARC pass/fail status cannot be confirmed via the AgentMail relay. If DKIM signing is not applied at the ESP level (`e.thenorthface.com`), Gmail and Yahoo may downgrade placement or reject outright.

**CAN-SPAM physical address and unsubscribe mechanism** are not visible in the truncated source but are presumed present in the footer (not auditable from the provided excerpt).

**Preheader/subject date mismatch (technical framing):** Subject references "Memorial Day"; preheader says "End of season savings ends 5.25." If `5.25` refers to May 25, 2026 (Memorial Day), the dates are technically consistent. However if this preheader was reused from a prior campaign with a different end date, it constitutes a misleading material claim under CAN-SPAM §7704(a)(1). Verify the preheader was updated for this send.
