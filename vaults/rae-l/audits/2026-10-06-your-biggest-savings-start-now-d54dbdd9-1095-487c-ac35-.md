# Your biggest savings start now
**Score:** 7/10 · **Type:** Email audit · **2026-10-06**
## Executive summary

- This is a "Big Deals" roundup that follows the 10/05 "Your beauty favorites, 20% off 👏" send. That email had one clear sitewide offer. This one has four separate offers and no headline number. The hero is a large "Big Deals" wordmark with "Time's running out on these must-haves" and a black "Shop now" button, so it promises urgency and gives no deal. The subject, "Your biggest savings start now," has the same problem.
- The body is better. Each module leads with a bold offer: BOGO free Arctic Fox, BOGO 50% Nailboo, 35% off BaBylissPRO flat irons, 40% off Ion hair dryer. Each has product shots and a "Shop now" link. For a hair-color and nails shopper, the Arctic Fox BOGO is the real draw, and it sits first below the hero. The email is clean and readable, but it holds back its best offer until after the hero. It also carries a lot of stacked banners and fine print.
- Overall it's a competent, mid-pack deal roundup. It repeats the "deals, deals, deals" cadence Sally has run since the 09/30 "Last chance" send, and the subject gives no reason to open it now.

## What's working

- The offers are specific and sized by type. "Buy one, get one free" and "35% off" are bold and easy to scan.
- The Arctic Fox BOGO free leads the body, which suits a hair-color shopper.
- Product shots are clean, with brand and product names in a mono label under each.
- The layout is consistent: headline, "Shop now" link, two products. The cream and yellow-green palette sets each module apart.
- The Klarna strip and the icon row (free shipping $40+, 2-hour delivery, pickup) address friction near the bottom.

## What's weak

- The hero shows no offer. "Big Deals" and "Time's running out" are vague, and the real deals only show after scrolling.
- Three banners sit above the hero: Sally Rewards $5 off $25, BOPIS, and 2-hour delivery. They compete with the hero and push it down.
- The deadline is missing from the visible copy. "Time's running out" has no date. The fine print buries the 10/31/2026 expiry.
- The 40% off Ion hair dryer module has no product label under it, unlike the other three. It's also the only module with the image beside the copy, so the rhythm breaks.
- The fine print is long and dense. The $5 reward terms and exclusions read as hedging.

## Recommendations

- 1. Put the best offer in the hero, for example "BOGO free Arctic Fox" or a "Up to 40% off" number. Drop the vague "Big Deals" wordmark.
- 2. Move the rewards, BOPIS and delivery banners below the offers, or cut them to one.
- 3. Add a real deadline to the hero, such as "Ends Sunday."
- 4. Give the hair dryer the same two-product layout and label as the other modules.
- 5. Replace the generic "Shop now" with specific CTAs such as "Shop Arctic Fox BOGO."

## Technical Audit

## 1. Technical Summary
The HTML source is a table-based XHTML 1.0 Transitional template with responsive CSS. QA found third-party pixels with an unresolved `[CACHEBUSTER]` macro and an insecure `http://` pixel. The header-based compliance and authentication checks could not be evaluated because the relay didn't capture those headers. The HTML was truncated, so this review covers only the evidence provided.

## 2. Link & Tracking Issues
- **Unresolved macro:** `https://t.myvisualiq.net/impression_pixel?r=[CACHEBUSTER]&et=i&ago=212&ao=883&aca=-11&si=-11&ci=-11&pi=-11&ad=-11...` contains a literal `[CACHEBUSTER]`. The value was never substituted, so the pixel's cache-busting doesn't work. Mail clients and proxies may cache it and under-count impressions.
- **Placeholder values:** The same pixel has `aca/si/ci/pi/ad=-11`, which look like unpopulated defaults. Attribution for this pixel is probably broken.
- **Insecure pixel:** `http://login.dotomi.com/ucm/UCMController?dtm_com=2&dtm_cid=2990...` uses plaintext HTTP. Clients may block it, and the request exposes the recipient's IP and user agent over an unencrypted channel.
- **Identifier in a pixel path:** `https://pxl.mon-trk.com/987bfe61-.../2321893/003aZ00000rqS8GQAU` appears to embed a Salesforce Contact ID (the `003` prefix). It is an ID, not a clear PII leak, but it is a persistent recipient identifier in a third-party URL.
- **Unverified links:** 58 click-redirect links were skipped, so none were resolved. Link validity and destinations are untested.
- **Pixel stack:** Three separate third-party pixels (Monetate, VisualIQ, Dotomi) add load and are failure points that depend on external hosts.

## 3. Rendering & Accessibility
- **Missing alt attributes:** The QA flagged four images:
  - an image with an empty `src`;
  - `003aZ00000rqS8GQAU`;
  - `impression_pixel`;
  - `UCMController`.

  The last three are tracking pixels and should carry `alt=""` plus `width="1" height="1"`. The empty-`src` image is a broken or placeholder element that can render a broken-image icon in some clients.
- **No `lang` attribute:** `<html xmlns="http://www.w3.org/1999/xhtml" xmlns:v=... xmlns:o=...>` has no `lang`, so screen readers can't pick the correct language profile.
- **Generic title:** `<title>Sally Beauty</title>` doesn't match the subject line. This is minor.
- **XHTML validity:** `<meta name="x-apple-disable-message-reformatting">` is not self-closed under an XHTML 1.0 doctype. This is minor and unlikely to break rendering.
- **Font fallback:** `a{font-family:'Founders Grotesk', Helvetica, sans-serif}` references a font that has no `@font-face` in the visible CSS (only Open Sans is declared). Links fall back to Helvetica.

## 4. Personalization & Merge Tokens
- **Unresolved token:** `[CACHEBUSTER]` in the VisualIQ pixel URL (see Section 2). This is the only merge-token failure confirmed in the visible source.
- **Not evaluable:** The truncated HTML doesn't show whether recipient-name or other personalization fields rendered.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058):** Both are not found. The QA note says the AgentMail relay may not capture them, so this is unconfirmed rather than a confirmed sender defect. Gmail and Yahoo bulk-sender rules require both.
- **`Authentication-Results`:** Not found, so SPF, DKIM and DMARC status is unknown from this data. The sender domain is `em.sallybeauty.com`; verify against the raw message.
- **Footer unsubscribe link and physical address:** These were not in the visible portion of the HTML, so they can't be confirmed or denied.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
Not assessable. The 58 tracking links were skipped and the visible HTML doesn't show final destinations. No UTM parameters are visible, and the links appear to use click-redirect domains, so UTM presence can only be checked after redirect resolution.

## 7. Recommendations
1. Fix the VisualIQ pixel so `[CACHEBUSTER]` is replaced at send time with a random value, and populate the `-11` parameters or drop the pixel.
2. Change the Dotomi pixel to `https://`, or remove it if HTTPS isn't supported.
3. Add `alt=""` and explicit 1x1 dimensions to all tracking pixels. Remove or fix the empty-`src` image.
4. Add `lang="en"` to `<html>`. Optionally self-close the `x-apple-disable-message-reformatting` meta tag.
5. Check the raw `.eml` for `List-Unsubscribe`, `List-Unsubscribe-Post` and `Authentication-Results`. If the relay is stripping them, fix capture in AgentMail ingestion so these checks stop returning warnings.
6. Resolve the click-redirect links with a redirect-following probe, record the final URLs and their UTM parameters, and check that none dead-end.
