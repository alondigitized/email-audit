### 3. Rendering & Accessibility

**`img { white-space: pre; }` (line in `<style>`)** — `white-space: pre` applied globally to all `<img>` elements is non-standard. Images have no text content so this is typically a no-op, but it is unexpected and may interact with certain Outlook rendering paths. Should be removed.

**`'Founders Grotesk'` referenced but never declared** — The rule `a { font-family: 'Founders Grotesk', Helvetica, sans-serif; }` specifies Founders Grotesk as the primary typeface for all anchor elements, but no `@font-face` block for Founders Grotesk exists in the `<style>` section. All clients will silently fall through to Helvetica. If Founders Grotesk is intentional, an `@font-face` src pointing to a hosted `.woff2` must be added. If Helvetica is the intended fallback everywhere, remove the Founders Grotesk reference.

**Open Sans loaded at `v17`** — Google Fonts URLs reference `/opensans/v17/`. Current Open Sans is v29+. Google does serve legacy version paths via redirect, but this adds a latency hop and may eventually break if Google deprecates old version paths. Update URLs to omit the version pin or use the CSS API endpoint (`fonts.googleapis.com/css2?family=Open+Sans`).

**External font CDN calls to `fonts.gstatic.com`** — Gmail (desktop web), Outlook (Win/Mac), and Yahoo strip or block external stylesheets and `@font-face` references. All six `@font-face` declarations are invisible in those clients. Ensure fallback stack (Arial/Helvetica) renders acceptably at all intended sizes — visual QA in Gmail web required.

**`.filter-item:hover` CSS rule** — Hover pseudo-class is supported only in Apple Mail, Thunderbird, and Outlook for Mac. This is acceptable as progressive enhancement, but confirm it is not load-bearing for usability (i.e., the item must be clearly tappable/clickable without hover state).

**`<!---->`  empty comment before `<style>`** — Appears to be a stripped template variable or CMS/ESP artifact. Harmless but indicates a merge/template processing issue worth investigating upstream.

**`-webkit-font-smoothing`, `-moz-osx-font-smoothing`, `text-rendering: optimizeLegibility` on `body`** — These CSS properties are ignored in virtually all email clients (applied to the webmail page body, not the email frame). No harm, but dead code.
