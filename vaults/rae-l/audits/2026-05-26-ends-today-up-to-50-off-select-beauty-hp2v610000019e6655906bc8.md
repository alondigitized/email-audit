# ENDS TODAY‼️Up to 50% off select beauty.
**Score:** 10/10 · **Type:** Email audit · **2026-05-26**
## Executive summary

- This is the third wave of the Sephora Stacking Weekend promotion — the same 50%-off-plus-500-bonus-points mechanic first seen on May 22, extended with a "LAST CHANCE" send earlier today (May 26), and now fired again with a parallel "ENDS TODAY" subject. The creative is functionally identical across all three sends: same Stacking Weekend headline, same dual-offer lockup, same product grid, same editorial sections for rhode and the "NEW COLOR NOW" color story. When you opened the first May 26 send this morning and now get this one, the experience is inbox fatigue in slow motion.
- Inside the email, execution is clean. The "ENDS TODAY" urgency bar sits above the fold in Sephora's signature orange-red, the 50% badge and 500-point circle read instantly at mobile size, and the "Must-Haves" product grid gives subscribers somewhere specific to land. The Beauty Insider section near the footer reinforces member value without feeling tacked-on. If this were the only send today, it would be a tight closing-window mailer.
- The real problem is cadence, not creative. Two promotional sends in one day for the same promotion — both citing urgency — cancel each other out. Subscribers who ignored the first one have already made their decision. Those who planned to act don't need a second push within hours.

## What's working

- **"ENDS TODAY" urgency bar is immediately legible** — orange-red placement above the Sephora logo forces the eye to the deadline before any other copy.
- **Dual-offer lockup (50% + 500 pts) reads cleanly** at mobile size — two visually distinct badges avoid crowding.
- **"Must-Haves" product grid** gives the email a defined shopping destination rather than dumping subscribers on the homepage.
- **Beauty Insider loyalty reinforcement** near the footer adds a retention signal for members who aren't yet in the habit of checking their points balance.
- **No render bugs** — layout is solid, images loaded, no broken gaps or overlapping text visible.

## What's weak

- **Two urgency sends on the same day undercut each other** — "LAST CHANCE" and "ENDS TODAY" hitting the same inbox within hours is textbook list fatigue; the second open rate will crater.
- **"ENDS TODAY‼️" in ALL CAPS with a double-exclamation emoji** pushes into spam-signal territory and reads more desperate than confident.
- **CTAs are generic "SHOP NOW"** across the board — with specific products in the grid, each tile could carry a more useful label (e.g., "Shop Tatcha" or "Grab Fenty").
- **No social proof** — no star ratings, bestseller badges, or "X sold today" signals on any product tile despite this being a closing-window send where proof would reduce hesitation.
- **Subject drops the "Stacking Weekend" brand name** — after two earlier sends trained subscribers to recognize that campaign frame, abandoning it here severs the narrative thread.

## Recommendations

- 1. **Kill the duplicate send — or at minimum, stagger by 6+ hours with meaningfully different creative.** Two urgency emails in one day for identical copy is the single biggest lever here. If the promotional window genuinely ends at midnight, one well-timed "closes at midnight" send at 6–7 PM local is far more effective than two daytime blasts.
- 2. **Reframe the subject to close the Stacking Weekend story** — subscribers have been trained on this campaign name; use it in the final send to create closure rather than generic urgency.
- 3. **Add a time-specific deadline** — "ENDS TODAY" is softer than "Ends at midnight tonight." A specific clock time converts fence-sitters more reliably.
- 4. **Swap "SHOP NOW" for category-level CTAs** — "Shop Skincare Deals" / "Shop Makeup Deals" on the grid tiles reduces the cognitive step from offer to click.
- 5. **Drop one emoji, keep the urgency** — ‼️ can go; the red urgency bar does the same job visually without the spam-signal cost.

- **Subject Alt B:** `Last call: 50% off select beauty ends at midnight`
- **Preheader Alt A:** `Your final chance to stack savings before the deals disappear.`
- **Preheader Alt B:** `Spend $75, earn 500 points — offer closes tonight.`

### 3. Rendering & Accessibility

**[CONFIRMED] `maximum-scale=1` blocks user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on mobile. Fails WCAG 1.4.4 (Resize Text) and is flagged by modern email accessibility linters. Remove `maximum-scale=1`.

**[CONFIRMED] `text-size-adjust: none` applied to body-level elements**
```css
div, a, tr, table, body, span, img, strong, td {
  -webkit-text-size-adjust: none;
  -ms-text-size-adjust: none;
  -moz-text-size-adjust: none;
  text-size-adjust: none;
}
```
Applying this to `body` and block-level elements suppresses OS-level font scaling for low-vision users. Acceptable scoped to `.sup` (its declared purpose); applying it globally is an accessibility defect.

**[CONFIRMED] Duplicate responsive CSS rule blocks**
The `@media (max-width: 480px)` block declares `.show` and `.appear` twice each with identical selectors:
```css
/* First declaration */
*[class=show], .show { display: block !important; width: 100% !important; … }
/* Second declaration — immediately follows */
*[class=show], .show { display: block!important; display: table!important; }
```
Same pattern for `.appear`. The duplicate `display: block` / `display: table` on the second pass is redundant dead weight and increases parse time, though rendering impact is minimal in practice.

**[CONFIRMED] Missing `lang` attribute on `<html>` element**
```html
<html xmlns="..." xmlns:v="..." xmlns:o="...">
```
No `lang="en"` (or locale variant). Screen readers cannot determine language; WCAG 3.1.1 failure.

**[CONFIRMED] `robots` meta value is malformed**
```html
<meta name="robots" content="no index" />
```
`"no index"` (with space) is not a recognized directive — the correct token is `"noindex"`. Email clients ignore this tag, but it indicates a template hygiene issue.
