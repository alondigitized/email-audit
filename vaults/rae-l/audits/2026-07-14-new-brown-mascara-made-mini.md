### 3. Rendering & Accessibility

**Confirmed issues:**

- **Missing `lang` attribute** — `<html>` has no `lang="en"`. Screen readers cannot determine the document language. Fix: `<html lang="en" ...>`.

- **Empty `<title>`** — `<title> </title>` (whitespace only). Some clients surface this as the tab/window title. Should be set to the subject line or brand name.

- **`@import` font loading will silently fail in Gmail and Outlook** — Both:
  ```
  @import url(https://static-forms.klaviyo.com/fonts/api/v1/SguDsz/custom_fonts.css);
  @import url(https://fonts.googleapis.com/css?family=Montserrat&display=swap);
  ```
  are stripped by Gmail (which ignores `<style>` blocks entirely) and blocked by Outlook. The fallback stack `"Helvetica", sans-serif` applies in those clients, which is functional but means the Montserrat brand font never renders for the majority of users. This is a known limitation of email, not a fixable bug without web font service workarounds, but it should be documented.

- **All link hover states are identical to default state** — `a:hover { color:#5f4b3c; text-decoration:none }` provides zero visual feedback on hover. Not a breaking issue but reduces usability on desktop clients that respect hover CSS.

- **Preheader padding uses Unicode filler characters** — The invisible `͏` (U+034F COMBINING GRAPHEME JOINER) characters are a common preheader-stuffing technique, but some spam filters (SpamAssassin) penalize runs of invisible Unicode. Consider using `&zwnj;` (`&#8204;`) or `&nbsp;` instead, which are more broadly accepted.

- **Image `alt` attributes** — Cannot assess from truncated source. All product images must have descriptive `alt` text; hero/banner images should have non-empty `alt` rather than `alt=""`.
