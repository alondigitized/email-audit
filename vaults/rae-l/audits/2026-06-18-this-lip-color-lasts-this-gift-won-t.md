### 3. Rendering & Accessibility

**`<html>` missing `lang` attribute** — screen readers cannot determine language. Should be `<html lang="en" ...>`.

**`<title>` is empty** — `<title> </title>` renders as a blank tab title in browser-based clients (Gmail, Yahoo). Use the subject line or a descriptive string.

**Google Fonts `@import` will silently fail in most desktop clients** — `@import url(https://fonts.googleapis.com/css?family=Montserrat&display=swap)` is blocked by Gmail (strips `<style>` blocks with `@import`), Outlook (ignores web fonts entirely), and Apple Mail on some configurations. The fallback stack `"Montserrat", "Helvetica", sans-serif` in `p, h1, h2, h3` is correct. However, `h4` declares `"Helvetica Neue", Arial` without `Montserrat` — inconsistent fallback chain.

**Klaviyo custom font import also subject to blocking** — `@import url(https://static-forms.klaviyo.com/fonts/api/v1/SguDsz/custom_fonts.css)` carries the same risk. If custom fonts are non-critical, both imports should be moved to a `<link>` tag wrapped in `<!--[if !mso]>` conditional, which survives more clients.

**All link states set to identical non-interactive style:**
```css
a:not([name]) {color:#5f4b3c;text-decoration:none}
a:link, a:visited, a:active, a:hover {color:#5f4b3c;text-decoration:none}
```
Hover state provides zero affordance. Not a blocker, but hover differentiation (underline or slight color shift) improves usability in webmail clients that support it.

**Image alt text** — not visible in truncated source. Confirm all `<img>` tags carry descriptive `alt` attributes; decorative images should use `alt=""`.
