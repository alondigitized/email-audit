## Technical Audit

## 1. Technical Summary
The send has one confirmed deliverability defect, a missing plain-text part (0 chars), and a few accessibility defects in the head and images. Authentication and unsubscribe headers could not be checked because the relay doesn't capture them. The HTML source is truncated, so findings below cover only the visible head and the QA output.

## 2. Link & Tracking Issues
- 12 material links were probed and none were reported broken. 49 were skipped as footer, utility or social links, so those are unverified.
- The unsubscribe link is always probed, but the QA output doesn't give its result. I can't confirm it works.
- The tracking pixel `https://mi.sephora.com/p/up/f6716d0a0f52104e/o.gif?mi_u=4958433775694848&mi_ecmp=20261022_New_at_Sephora_Insider` carries a per-recipient ID (`mi_u`) and a campaign ID (`mi_ecmp`). That is expected for open tracking. It has no alt attribute (see section 3).

## 3. Rendering & Accessibility
- **Missing alt text, confirmed by QA on 3 images:**
  - `https://app.sephora.com/O/AQEAAZcF2gAn…`, which looks like another open-tracking pixel.
  - `https://mi.sephora.com/p/up/.../o.gif`, the tracking pixel above.
  - `https://images.harmony.epsilon.com/ContentHandler/images/.../2021_Navs_Header_06.jpg`, the nav header image. This is a content image, so its missing alt is the one that affects users. When images are blocked or read by a screen reader, the nav labels are lost.
  - The two pixels should carry `alt=""`.
- **Viewport:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1">`. `maximum-scale=1` blocks pinch-zoom, which is an accessibility issue (WCAG 1.4.4).
- **Text scaling:** the CSS sets `-webkit-text-size-adjust: none` and `-ms-text-size-adjust: none` on `div, a, tr, table, body, span, img, strong, td`. This disables user text-size scaling on iOS and Windows.
- **Language:** the visible `<html xmlns=… xmlns:v=… xmlns:o=…>` has no `lang` attribute, so screen readers can't pick a pronunciation profile.
- **Robots meta:** `<meta name="robots" content="no index">` is invalid. The correct value is `noindex`, so parsers may ignore it. The impact is low.
- **Title:** `<title>Sephora</title>` is generic. This is low severity.

## 4. Personalization & Merge Tokens
No issues found. The visible source has no unresolved merge tokens such as `%%…%%`, `{{…}}` or `[FIRSTNAME]`. The truncated body is unchecked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
