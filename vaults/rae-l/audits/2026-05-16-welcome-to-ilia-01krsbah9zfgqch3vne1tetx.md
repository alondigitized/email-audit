# Welcome to ILIA
**Score:** 9/10 · **Type:** Email audit · **2026-05-16**
## Executive summary

- ILIA's welcome email pulls a smart move by dropping a new subscriber directly into a Friends + Family sale rather than delivering a vanilla onboarding letter. The design is clean and on-brand — warm editorial photography, a restrained color palette, and tight product merchandising in the "A Cart Collage" section. The VIP program is woven throughout rather than tacked on as an afterthought, which shows strategic intent.
- The glaring miss is the subject line. "Welcome to ILIA" completely hides a 20% sitewide offer that's the first thing you see on open. Any inbox recipient without brand loyalty has no reason to open; the subject reads like a transactional receipt, not a sales moment. This is fixable in one A/B test.
- The email also has a conversion focus problem: it asks you to "SHOP THE SALE +" and "JOIN FOR FREE +" in the same scroll, splitting commitment. For a welcome send, that's one ask too many. Still, execution quality is high enough that the sales mechanics underneath work hard once you're in.

## What's working

- **Promotional banner leads instantly** — "20% OFF SITEWIDE | 20% OFF FOR VIP" is the first thing the eye hits; no hunting for the offer.
- **VIP program threaded through the whole email** — 2X points + 25% member discount is shown in context, not buried in footer fine print.
- **"A Cart Collage" product block** — specific product names (bronzer/highlighter, barrier cream) with gift-with-purchase framing makes the offer tangible.
- **Social proof credibly placed** — Allure/Bazaar editorial callout in the product block adds third-party validation without feeling like a brag.
- **Clean render, no visual bugs** — no broken images, no layout breakage, consistent editorial aesthetic top to bottom.

## What's weak

- **Subject line "Welcome to ILIA" hides the entire commercial proposition** — a 20% sitewide sale is buried behind a greeting that reads like account confirmation.
- **No sale deadline visible** — "Friends + Family Sale" floats without an end date; urgency is zero once you're past the banner.
- **Two competing CTAs dilute each other** — "SHOP THE SALE +" and "JOIN FOR FREE +" ask for different commitments in the same email; neither wins clearly.
- **No personalization** — no subscriber name, no category signal ("you browsed skincare" / "your first order") — feels broadcast rather than directed.
- **VIP "25% off" vs. banner "20% off" discrepancy** — without clear context, this risks confusion about which offer applies to whom.

## Recommendations

- 1. **Lead the subject with the offer** — "Welcome to ILIA" is the single highest-leverage fix. Test against a subject that names the discount.
- **Subject Alt A:** `You're in — 20% off everything, right now`
- **Subject Alt B:** `Welcome gift: 20% off sitewide`
- **Preheader Alt A:** `Friends + Family Sale is live. Free shipping over $50.`
- **Preheader Alt B:** `Your first order: 20% off + free Allure-rated gift.`
- 2. **Add a deadline to the hero** — even "Sale ends Sunday" printed under the hero CTA turns this from ambient promo into an actionable window.
- 3. **Pick one primary CTA** — demote "JOIN FOR FREE +" to a secondary link below the fold; make "SHOP THE SALE +" the uncontested conversion target for this send.
- 4. **Resolve the 20% vs. 25% messaging** — label clearly: non-member gets 20%, VIP gets 25%. One sentence eliminates the ambiguity.

### 1. Technical Summary

### 2. Link & Tracking Issues

- No UTM parameters confirmed in the visible portion of the source.

---

### 3. Rendering & Accessibility

**`<title>` is blank**
```html
<title> </title>
```
Appears as an empty tab label in browser-based opens (Gmail web, etc.). Should be the email subject line.

**CSS `@import` for fonts — not supported in major clients**
```css
@import url(https://static-forms.klaviyo.com/fonts/api/v1/SguDsz/custom_fonts.css);
@import url(https://fonts.googleapis.com/css?family=Montserrat&display=swap);
```
`@import` inside `<style>` is stripped by Gmail (all versions), Outlook, and Apple Mail on iOS. Montserrat will silently fall back to the declared `"Helvetica", sans-serif` stack, but the custom Klaviyo font (`SguDsz`) will fail entirely in those clients with no declared fallback.

**Conflicting `p` CSS rules**

Two separate `p` rule blocks exist in the same `<style>` tag:
```css
/* Block 1 */
p { display: block; margin: 13px 0 }

/* Block 2 — later in same block */
p { margin-left: 0; margin-right: 0; margin-top: 0; margin-bottom: 0; padding-bottom: 1em }
```
Block 2 overrides Block 1's margins. Block 1 is dead code — the `display: block` is the only surviving declaration. This is likely a Klaviyo template artifact but adds unnecessary weight and confusion.

**Link color accessibility**

All five `<a>` states use `color:#5f4b3c; text-decoration:none`. With no underline and a single color state, links are distinguishable from body text by color only — this fails WCAG 2.1 SC 1.4.1 (Use of Color). No hover underline is applied either; hover CSS is supported in many modern email clients.
