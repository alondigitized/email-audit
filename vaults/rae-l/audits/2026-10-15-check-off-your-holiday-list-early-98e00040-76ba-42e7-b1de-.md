## Technical Audit

## 1. Technical Summary
The email is a table-based XHTML 1.0 Transitional layout with a viewport meta tag and a mobile media query at 499px. The automated QA found no hard failures. The real issues are in third-party tracking pixels (a plain-HTTP pixel, an unresolved `[CACHEBUSTER]` macro, missing alt attributes) and an empty-`src` image. The HTML source was truncated, so the body, footer and link targets could not be fully verified.

## 2. Link & Tracking Issues
- **Unverified links:** 50 tracking links were skipped because they are click-redirect domains, so none were HTTP-probed. Their destinations and status codes are unconfirmed.
- **Unresolved macro:** the pixel `https://t.myvisualiq.net/impression_pixel?r=[CACHEBUSTER]&et=i&ago=212&...` still contains the literal `[CACHEBUSTER]` token. The ESP or ad-server did not substitute it, so the cache-busting value is never filled in. This can cause cached pixel responses and under-counted impressions.
- **Non-HTTPS pixel:** `http://login.dotomi.com/ucm/UCMController?dtm_com=2&dtm_cid=2990&...` uses plain HTTP. Clients that block mixed content or insecure resources may not load it, which would drop that tracking call. The pixel is also a link and tracking hygiene risk.
- **Pixel stack:** the email carries at least three third-party pixels: `pxl.mon-trk.com`, `myvisualiq.net` and `dotomi.com`. Each adds an external request and a separate privacy and deliverability surface.

## 3. Rendering & Accessibility
- **Missing alt attributes:** four images have no alt text:
  - the image with an empty name and empty `src`
  - `https://pxl.mon-trk.com/987bfe61-f108-4c0f-99ff-4b5d2e0c19ef/2324653/003aZ00000rqS8GQAU`
  - the `myvisualiq` impression pixel
  - the `dotomi` UCMController pixel

  These are tracking pixels, so the accessibility impact is limited. Pixels should still carry `alt=""` and ideally `width="1" height="1"` so screen readers skip them.
- **Empty `src`:** the first flagged image has `src: ` (empty) and no alt text. An empty `src` can trigger a broken-image icon or a redundant request to the page URL in some clients. This needs checking in the full source.
- **Font fallback:** `@font-face` rules load Open Sans from `fonts.gstatic.com`. The link style uses `font-family:'Founders Grotesk', Helvetica, sans-serif`, but no `@font-face` for Founders Grotesk appears in the visible source. It falls back to Helvetica, which is acceptable. Gmail and Outlook ignore webfonts regardless.
- **Other markup:** the source includes the `x-apple-disable-message-reformatting` meta (`<meta name="x-apple-disable-message-reformatting">` is not self-closed, which is harmless in this doctype context) and an Outlook VML namespace. No other rendering defects were confirmed.

## 4. Personalization & Merge Tokens
- **Unresolved token:** `[CACHEBUSTER]` in the `myvisualiq` pixel URL (see section 2). This is the only unresolved token in the visible source.
- The rest of the source is truncated, so personalization in the body and footer could not be assessed.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **No confirmed issues.**
- The QA warnings for missing `List-Unsubscribe`, `List-Unsubscribe-Post` (RFC 8058) and `Authentication-Results` headers are most likely artifacts of the AgentMail relay. The QA output itself says the headers "may not be captured", so they are not confirmed defects of the sender. Sender SPF, DKIM and DMARC status is unknown and should not be reported as failing.
- The visible portion of the HTML does not include the footer, so the physical postal address and the in-body unsubscribe link could not be verified.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- Not assessable. All 50 links are on tracking or redirect domains and were not resolved, so UTM parameters and landing pages could not be verified.
- Resolving a sample of redirects to `sallybeauty.com` would settle this.

## 7. Recommendations
1. Fix the `[CACHEBUSTER]` substitution in the `myvisualiq` pixel, or remove the pixel.
2. Serve the `dotomi` UCMController pixel over HTTPS, or confirm that the vendor supports it.
3. Add `alt=""` to all tracking pixels. Give the image with the empty `src` a valid source or remove it.
4. Re-run the audit with a full, untruncated HTML source. Follow the click-redirect chains to check final URLs and UTM parameters.
5. Capture raw headers (`List-Unsubscribe`, `List-Unsubscribe-Post`, `Authentication-Results`) from the original message rather than the relay copy before judging compliance and authentication.
