# Don't leave a good thing behind.
**Score:** 8/10 · **Type:** Email audit · **2026-08-03**
## Executive summary

- This is another entry in Skechers' relentless urgency-email rotation — "SELLING FAST... ADD TO CART BEFORE THEY'RE GONE!" is functionally the same beat as "This style has limited availability!" (audited 6/30, 7/16, 7/29), just wearing a new subject line, "Don't leave a good thing behind." The hero is a single product (Arch Fit Arcade slip-in) sitting in a sea of blank space, followed by a fairly generic "more great options" grid and a real, if soft-pedaled, 2-for-$100 sitewide offer.
- The offer itself is the most useful part of this email, but it's buried below six thumbnails and a wall of navigation links, and — reviewing this on 8/4 — the fine print says it was only "Valid online thru 8/3," meaning the deal has already lapsed by the time anyone reading this today would click through. Combined with the vague, scarcity-flavored subject line that doesn't name a product or number, this reads as filler urgency rather than a real limited-time event.
- Judgement: competent, on-brand, no render bugs — but it's the same recycled "hurry, it's disappearing" template Skechers has now run at least four times in five weeks, and the one dated offer inside it is stale as of open. Mid-pack send, dragged down by cadence fatigue and a now-expired CTA.

## What's working

- Clean, on-brand execution — no overlapping text, no broken images, consistent navy/white Skechers palette throughout.
- The 2-for-$100 banner is a genuinely concrete, scannable offer with a clear "SHOP NOW" link next to it.
- Hero product is named specifically ("Skechers Slip-ins: Arch Fit Arcade") rather than a vague "check this out."
- Secondary grid of six products gives browsers more entry points if the hero doesn't land.
- Utility footer (Afterpay/Klarna, curbside pickup, app download, store finder) is complete and familiar.

## What's weak

- The dated offer ("Valid online thru 8/3") has already expired as of today (8/4) — anyone opening this now hits a dead promo.
- Large, unexplained blank gap between the "ADD TO CART BEFORE THEY'RE GONE!" subhead and the actual shoe image pushes the hero product below the mobile fold.
- Subject line "Don't leave a good thing behind" is vague — no product, no offer, no number — and continues the same synthetic-urgency drumbeat this inbox has seen repeatedly (7/29's "limited availability," 7/25's "cart expires soon," 7/21's "did you forget something").
- "SELLING FAST" scarcity claim isn't tied to any real signal (no stock counter, no "X left"), which reads as templated urgency rather than honest scarcity.
- CTA copy is the generic "SHOP NOW" twice over rather than naming the product or the deal.

## Recommendations

- 1. Kill the dead-by-open date problem: either extend/refresh the offer window dynamically or pull the "Valid thru 8/3" banner from future sends entirely — a stale deadline is worse than no deadline.
- 2. Close the whitespace gap above the hero shoe so the product and price are visible without scrolling on mobile.
- 3. Retire "selling fast" / "limited availability" language for a cycle — this persona has now seen that exact beat four times since June 30; rotate to a benefit-led or new-arrival angle instead.
- 4. Make the CTA product-specific ("Shop Arch Fit Arcade") instead of generic "Shop Now."
- 5. Add a size/fit or rating cue under the hero product to give browsers a reason to click beyond the image.
- **Subject Alt A:** `2 for $100: Arch Fit slip-ins + more`
- **Subject Alt B:** `Your Arch Fit Arcade is almost gone`
- **Preheader Alt A:** `Mix and match select styles — 2 for $100, ends soon.`
- **Preheader Alt B:** `The slip-in you looked at is still here. For now.`

# Technical Email Audit: "Don't leave a good thing behind." (SKECHERS)

## 1. Technical Summary
This is an Attentive-served (`msgs.skechers.com` / `attentivemail.com`) promotional email with a broken unsubscribe link, no plain-text MIME part, and missing RFC 8058 one-click unsubscribe headers — combining to create both a compliance risk and a deliverability risk.

## 2. Link & Tracking Issues
- **Unsubscribe link returns HTTP 400** — QA FAIL. The link (`https://skechers.attentivemail.com/ls/click?upn=u001.LNc6...BFWD_...`) is broken, meaning recipients clicking "Unsubscribe" cannot opt out via that link.
- All links use Attentive's `ls/click?upn=` redirect wrapper, consistent with standard click-tracking; no malformed `href` syntax observed in the sampled markup.
- Open-tracking pixel present: `https://skechers.attentivemail.com/wf/open?upn=...` (expected for an ESP-served campaign).
- QA probing coverage: 12 of 38 material links were actively probed (ranked by click likelihood); 26 lower-priority footer/social/utility links were skipped by design, so link-health beyond the unsubscribe failure is not fully verified.

  - Mixed-content `http://` images in an `https` mail client context risk being blocked or flagged by client image proxies (Gmail/Outlook rewrite via their own CDN, but some strict clients block plain-http assets outright).

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Unsubscribe link is broken (400)** — QA FAIL. This is a functional CAN-SPAM violation risk: the visible unsubscribe mechanism does not resolve.
- **`List-Unsubscribe` header not found** — QA WARN. May be a relay-side capture gap (AgentMail) rather than confirmed absence at the source MTA.
- **`List-Unsubscribe-Post` header not found (RFC 8058)** — QA WARN. Without this, one-click unsubscribe per Gmail/Yahoo 2024 bulk-sender requirements cannot be confirmed as supported.
- **`Authentication-Results` header not found** — QA WARN. SPF/DKIM/DMARC pass/fail status cannot be verified from available headers (relay capture gap noted by QA, not a confirmed auth failure).
- Physical mailing address / CAN-SPAM footer disclosure not visible in the truncated HTML sample — cannot confirm presence or absence.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- All sampled links route through the Attentive `ls/click?upn=...` redirect wrapper; the encoded `upn` token obscures the final destination URL, so UTM parameters and landing-page alignment cannot be directly verified from the HTML source alone.
- No issues found in the directly observable markup (link structure is consistent with standard ESP redirect tracking).

## 7. Recommendations
1. **Fix the unsubscribe link immediately** — it returns HTTP 400. This is the highest-priority issue (compliance + deliverability risk).
2. Add a plain-text MIME alternative — current plain-text part is 0 chars, which hurts spam-filter scoring and violates CAN-SPAM's multipart-message best practice.
3. Confirm `List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) headers are actually being sent at the source MTA; if the relay is simply not capturing them, verify directly with Attentive/AgentMail rather than assuming absence.
4. Switch all 8 `http://image.emails.skechers.com/...` asset URLs to `https://` to avoid mixed-content blocking in strict mail clients.
5. Add descriptive `alt` text to the hero image (`183222_GRY_HERO_LG`) and the second product image (`a6ec5198-...jpg`) for accessibility/screen-reader support.
6. Verify SPF/DKIM/DMARC alignment directly against the sending MTA logs, since `Authentication-Results` wasn't captured by the relay.
