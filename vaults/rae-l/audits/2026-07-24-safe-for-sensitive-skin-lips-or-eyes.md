### 3. Rendering & Accessibility

**`@import` not supported in Gmail (web/Android)**
```css
@import url(https://static-forms.klaviyo.com/fonts/api/v1/SguDsz/custom_fonts.css);
@import url(https://fonts.googleapis.com/css?family=Montserrat&display=swap);
```
Gmail strips `<style>` blocks containing `@import`. The Klaviyo custom font will be absent across all Gmail clients; Montserrat falls back to the declared stack (`"Montserrat", "Helvetica", sans-serif`), which degrades gracefully, but custom font branding is lost for the largest client segment.

**Empty `<title>` element**
```html
<title> </title>
```
Contains only a whitespace character. Benign for rendering, but some spam heuristics and screen readers flag an effectively empty title.

**Universal link state suppression (accessibility risk)**
```css
a:not([name]) { color:#5f4b3c; text-decoration:none }
a:link, a:visited, a:active, a:hover { color:#5f4b3c; text-decoration:none }
```
All five link states — including `:hover` — resolve identically. Links are visually indistinguishable from body text by color and decoration alone. This fails WCAG 1.4.1 if foreground/background contrast between `#5f4b3c` and surrounding text does not differ by ≥3:1.

**Legacy Google Fonts API endpoint**
```css
https://fonts.googleapis.com/css?family=Montserrat&display=swap
```
Uses the deprecated `css` (v1) endpoint rather than `css2`. The v1 API lacks per-weight subsetting and may return fewer supported formats. Minor risk; no breakage, but `css2?family=Montserrat:wght@400;700&display=swap` is the current recommended form.
