### 2. Link & Tracking Issues

### 3. Rendering & Accessibility

**Dark-mode white knockout — confirmed bug.**
The "SPF 40" text inside the Super Serum Skin Tint link has a hardcoded white background:
```html
<span data-color="#FFFFFF" style="background-color: rgb(255, 255, 255);">SPF 40</span>
```
In dark-mode clients (Apple Mail, Outlook for iOS/Android), the surrounding text color inverts to near-white while this inline `background-color` does not, producing white-on-white invisible text. Fix: remove the inline `background-color` from that span; the parent container's background will handle it.

**`@import` font loading stripped by Gmail.**
```html
<!--[if !mso]><!-->
<style>@import url("https://static-forms.klaviyo.com/fonts/api/v1/SguDsz/custom_fonts.css");</style>
<!--<![endif]-->
```
The MSO conditional correctly excludes Outlook, but Gmail (all variants) strips `<style>` blocks entirely, so `@import` never executes there. The fallback stack (`Arial, "Helvetica Neue", Helvetica, sans-serif`) is present on all text spans, so rendering degrades gracefully — but Karla will not load for ~40–50% of typical B2C audiences.

**Inconsistent font-size units.** `<li>` elements declare `font-size: 11pt` on the block, while inner `<span>` elements override with `font-size: 15px`. 11pt ≈ 14.67px — close enough that the override wins cleanly, but the unit mismatch is a Klaviyo editor artifact that could cause drift if someone edits the block-level style without touching the spans.

**`<p>` inside `<li>` throughout.** Not a standards violation, but this structure is generated by the Klaviyo rich-text editor and can render with unexpected spacing in older Outlook versions that apply block-level margins to nested `<p>` tags.
