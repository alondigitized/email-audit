# “It felt like a godsend.” —Este Haim
**Score:** 6/10 · **Type:** Email audit · **2026-06-11**
## Executive summary

- This is the second email in ILIA's HAIM x ILIA arc — the June 9 launch introduced the collaboration (scored 7/10); this send pivots to deepening the Super Serum Skin Tint case with clinical proof, with Este Haim's testimonial as the headline hook. The strategy is reasonable: borrow celebrity credibility to anchor a long-form product education email. Execution is mostly clean, but the email tries to do too much — proof arc, benefit stacking, and then an abrupt "Milk This Gift" cross-sell at the bottom that feels grafted on from a different campaign.
- The clinical proof sections ("the proof is in the clinicals," "barrier-boosting hydration," "made for sensitive skin," "daily stressor defense") read as thorough, but they also dilute the punch of the Este Haim quote. The quote should be the payoff; instead it's buried mid-scroll after a wall of claim modules. A clean beauty audience will appreciate the ingredient integrity, but the structural logic — quote as hook, clinicals as ladder, CTA as close — gets muddled.
- The "Milk This Gift" module at the bottom is the biggest problem. It introduces a second narrative that has no setup, no connective tissue, and undercuts the editorial credibility ILIA has been building all week.

## What's working

- **Subject line as social proof hook.** A first-person celebrity quote in the subject is distinctive and earns the open — far more interesting than the generic "NEW Soft Focus" subjects from earlier in the arc.
- **Clinical proof framework is on-brand.** The "proof is in the clinicals" framing is consistent with ILIA's "Makeup That Makes Your Skin Better" tagline and fits their clean beauty audience.
- **Este Haim quote block is visually strong.** The full-width quote layout with the warm-toned imagery is the best visual moment in the email.
- **Sensitive-skin callout is smart targeting.** "Made for sensitive skin (and all skin)" broadens reach while leading with the specificity that converts the right buyer.
- **Footer benefit bullets are clean.** Safe for sensitive skin, non-comedogenic, fragrance-free, cruelty-free/vegan — these are the purchase triggers for this audience, and listing them plainly works.

## What's weak

- **"Milk This Gift" module is a jarring non sequitur.** There's no copy bridge from the skin tint proof arc into this gift set module — it reads like a scheduling accident, not a deliberate cross-sell.
- **No visible CTA with specific copy until far down the scroll.** The hero has no obvious above-the-fold button; the first clear action is deeply buried.
- **No offer.** This email has zero price reduction, no bundle incentive, no urgency mechanism — it's a pure editorial send, which is fine if it's leading somewhere, but there's no signal that a deal is coming.
- **Benefit modules are repetitive mid-scroll.** Four sequential claim blocks ("clinically proven," "barrier-boosting hydration," "made for sensitive skin," "daily stressor defense") without visual breaks create scroll fatigue.

## Recommendations

- 1. **Restructure: quote at the top, one clinical proof module, then CTA.** The Este Haim pull quote should be the hero — not the fifth scroll stop. Cut three of the four clinical modules; pick the single most differentiating claim (sensitive skin + non-comedogenic is the winner) and let it breathe.
- 2. **Remove or isolate the "Milk This Gift" module.** It belongs in its own send or at minimum needs a one-line bridge ("Looking for a gift? The Skin Tint is inside."). As-is it hurts the email's coherence.
- 3. **Add a primary CTA button above the fold.** The hero section needs a button — "Shop the Skin Tint" or "Try Este's Pick" — before any clinical copy begins.
- 4. **Introduce urgency.** Nothing in this email creates a reason to act now. Even a soft signal ("New in the HAIM collection") would help.

### 3. Rendering & Accessibility

**`<title>` is empty**
```html

```
Several email clients (Yahoo, AOL, some Outlook versions) surface the `<title>` value as a tooltip or fallback subject. An empty title is a missed fallback and may trigger accessibility warnings in screen reader testing.

**External `@import` CSS will be stripped**
```css
@import url(https://static-forms.klaviyo.com/fonts/api/v1/SguDsz/custom_fonts.css);
@import url(https://fonts.googleapis.com/css?family=Montserrat&display=swap);
```
Gmail (web and Android), Outlook (desktop), and Samsung Mail strip `@import` rules entirely. `Montserrat` will silently fall back to `Helvetica`/`sans-serif`. This is expected behavior for email, but the fallback stack must be visually acceptable — confirm it renders acceptably without the webfont.

**Google Fonts v1 API endpoint**
```
https://fonts.googleapis.com/css?family=Montserrat&display=swap
```
The v1 endpoint is deprecated in favor of `css2`. It still resolves, but Google has signaled eventual removal. Low urgency but worth updating to `css2?family=Montserrat:wght@400;700&display=swap`.

**h4 excluded from Montserrat font stack**
```css
h4 { font-family: "Helvetica Neue", Arial; ... }   /* no Montserrat */
p, h1, h2, h3 { font-family: "Montserrat", "Helvetica", sans-serif }
```
`h4` elements will always render in Helvetica Neue regardless of webfont load, while all other text elements attempt Montserrat first. Likely unintentional inconsistency.

**All link states styled identically, including hover**
```css

a:hover { color:#5f4b3c; text-decoration:none }
```
No hover differentiation exists. This removes the interactive affordance for mouse users in webmail clients that support `:hover` (Outlook.com, Gmail web). Not an error per se, but worth flagging as an accessibility concern for WCAG 2.4.4 (link purpose discernibility).
