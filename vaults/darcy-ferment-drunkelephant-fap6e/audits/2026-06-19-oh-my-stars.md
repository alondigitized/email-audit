# Oh, my stars
**Score:** 8/10 · **Type:** Email audit · **2026-06-19**
## Executive summary

- Drunk Elephant closes out a heavy B-Hydra content arc with a full social-proof pivot: three long-form customer reviews anchored by "THANKS FOR ALL THE 5-STAR LOVE!" This is the third B-Hydra email in six days (June 13 ingredient deep-dive, June 15 hydration editorial, now June 19 reviews). As a content rotation strategy that's actually smart — education → benefits → community validation is a logical arc, and the reviews here are substantive. They surface real use-case specifics: arid climate, age 65, acne-prone sensitive combo skin, multi-year loyalty.
- The structural problem is the subject line. "Oh, my stars" is a five-star pun that reads as a mild exclamation and reveals absolutely nothing about the email's content, product, or offer. Any brand could have sent it. For a recipient scanning an inbox on a Thursday morning, that's a miss. The GWP cross-sell ("Spend $149+") at the bottom is an afterthought — it earns its own section and headline ("MAKING IT RAIN") but no visual integration with the reviews story that precedes it.
- Net verdict: the body executes well; the subject line and offer structure let it down.

- Three full, attributed reviews covering distinct skin concerns (dryness/arid climate, line-smoothing, acne-prone combo skin) — far more credible than a single pull-quote
- "WELL DONE, B-HYDRA!" hero headline is confident and brand-voice-consistent — it makes the product the protagonist, not the brand
- Clean visual hierarchy: aquatic hero shot → social proof section → secondary offer; the eye follows naturally
- No render bugs visible; the blue water texture in the hero is on-brand and functional
- Review length is generous enough to feel real, short enough to read on mobile

## What's weak

- "Oh, my stars" tells an inbox scanner nothing — no product, no offer, no category signal
- Third B-Hydra email in six days; cadence fatigue is real, and this one brings no new angle beyond reviews
- The $149 GWP threshold is buried in a disconnected second section with its own headline ("MAKING IT RAIN") — it reads like a separate email appended below
- No urgency anywhere in the email — neither the reviews nor the cross-sell give a reason to act today
- Review attribution is initials only (—C, —Jodi, —Juli) with no skin type labels or verified-buyer signal, which undercuts trust slightly

## Technical Audit — Drunk Elephant "Oh, my stars"

### 1. Technical Summary

Standard XHTML 1.0 Transitional table-layout email with several infrastructure-level concerns: triple-loaded custom fonts create unnecessary HTTP overhead, and invalid CSS comment syntax inside `<style>` blocks can cause silent rendering failures in strict parsers. Core structure is functional but fragile.

---

### 2. Link & Tracking Issues

**Third-party font CDN dependency (db.onlinewebfonts.com)**
All four custom font variants (BrownBold, BrownLight, BrownThin + Brown variants) load from `db.onlinewebfonts.com`. This CDN is not controlled by Drunk Elephant. If it goes down or rate-limits, all branded fonts silently fail across the entire send.

**Triple font-loading redundancy**
Each custom font is requested three separate ways in the same `<head>`:
1. `<link href="https://db.onlinewebfonts.com/c/...">` 
2. `@import url(https://db.onlinewebfonts.com/c/...)` inside `<style>`
3. `@font-face { src: url("https://db.onlinewebfonts.com/t/...") }`

This generates 3x the HTTP requests per font for clients that honor all three. The `<link>` + `@import` duplication alone is redundant — pick one.

**Cannot audit CTAs/product links** — HTML is truncated before body content. UTM parameters on outbound links are unverifiable from this source.

---

### 3. Rendering & Accessibility

**HTML comments inside `<style>` block (invalid CSS)**
```css
<!-- *[class=contenttable] { width:414px !important;} -->
<!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
```
HTML comment delimiters (`<!--` / `-->`) inside a `<style>` tag are syntactically invalid in CSS. These rules are silently ignored by any client that correctly parses CSS, meaning the `contenttable` and `mobile` responsive overrides never apply on mobile. This is a dead-code bug hiding as working code.

**`text-size-adjust` conflict**
`body` sets `-webkit-text-size-adjust:100%` but the wildcard rule immediately overrides it with `-webkit-text-size-adjust:none`. The `none` value (rather than `100%`) actively prevents text scaling on some mobile clients and is the more aggressive/incorrect setting.

**`maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
This locks user zoom on mobile — a WCAG 1.4.4 (Resize Text) failure. Users with low vision cannot pinch-to-zoom.

**Global `line-height: 100%` reset**
`*{line-height: 100%}` applied universally collapses line-height to font-size across every element. For multi-line text this renders lines touching or overlapping. Should be scoped or removed.

**Missing `lang` attribute**
The `<html>` tag has no `lang="en"` attribute. Screen readers cannot determine language; affects pronunciation and WCAG 3.1.1 compliance.

**`<title>` is generic**
`<title>Drunk Elephant</title>` — non-descriptive for screen readers that expose the document title.
