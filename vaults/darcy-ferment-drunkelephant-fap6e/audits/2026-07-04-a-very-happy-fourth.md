# A very happy Fourth!
**Score:** 8/10 · **Type:** Email audit · **2026-07-04**
## Executive summary

- Drunk Elephant's Fourth of July send leads with sentiment over conversion — "BEACH, PLEASE." is a clean, seasonally correct hero, but the email is essentially a long editorial where the best offer (35% off) is buried four product sections below the fold. The top banner delivers free shipping with no minimum, which is a genuinely strong hook, but it gets orphaned: the hero never picks it up, and the scroll asks a lot before paying off.
- The "Because…" copy structure is the most interesting thing here — each product gets a situational reason for existing (dry skin, thirsty lips, full immersion) — but all six CTAs read "SHOP NOW," which flattens any momentum those reasons build. Compare this to the June 21 "Summer to go" send (9/10), where the hero kit image and price created immediate purchase intent. This send prioritizes brand warmth over that kind of clarity.
- The visual design is clean, the layout holds, and the beach/hydration theme is thematically coherent. But for a holiday email competing against a crowded July 4th inbox, this is too soft on the offer and too slow to reward the scroll.

## What's working

- **Free shipping banner lands immediately** — no minimum, top of email, hard to miss.
- **"Because…" editorial structure** gives each product a persuasive reason before the CTA, which is smarter than a flat product grid.
- **Beach + hydration theme is coherent** — B-Hydra, Lippie Balm, SPF bag, and "SKIN GETS THIRSTY, TOO." all reinforce one storyline.
- **"BEACH, PLEASE." hero copy** is punchy and on-brand for DE's tone.
- **Layout renders cleanly** — alternating image/copy pairs, no visible bugs or broken images.

## What's weak

- **35% off is buried below four product modules** — the single hardest working number in this email shouldn't require that much scroll.
- **Subject "A very happy Fourth!" is a greeting card, not a sales hook** — zero product or offer signal, so it relies entirely on brand loyalty to earn the open.
- **Every CTA says "SHOP NOW"** — generic across six touchpoints, missing the chance to convert the specific product copy DE just wrote.
- **No explicit deadline** — the July 4th context implies urgency but nothing in the email says "today only" or "ends tonight."
- **The hero doesn't introduce the 35% offer** — a subscriber who bounces after the hero leaves without knowing the best reason to click.

- 1. **Pull 35% off into the hero.** "BEACH, PLEASE. — 35% off your summer edit + free shipping" turns a mood piece into an offer. The June 24 Reboot Camp send did this right; replicate it here with a beach frame.
- 2. **Make the subject carry an offer signal.** The greeting is warm but the inbox is crowded on July 4th — lead with value.
- 3. **Tie a "today only" deadline to the 35% offer.** Even a simple "through midnight" line converts the holiday context into real urgency.
- 4. **Differentiate the CTAs.** "Shop B-Hydra," "Shop the beach bag," "Shop lip care" — DE wrote six product reasons; let them do the work all the way to the click.
- 5. **Condense the bottom half.** The "SKIN GETS THIRSTY, TOO." hydration module is a third act that dilutes focus. Either fold it into the editorial or drop it.

### 3. Rendering & Accessibility

**Critical — HTML comments inside `<style>` block:**
```css
@media only screen and (max-width: 600px) {
  *[class=hide] { display: none !important;}
  <!-- *[class=contenttable] { width:414px !important;} -->
  <!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
```
HTML comment syntax (`<!-- ... -->`) is invalid inside a CSS `<style>` block. Both rules — `contenttable` width and `mobile` width — are dead code. Any email client that parses CSS strictly will silently drop them, breaking the responsive layout for those two container classes on screens ≤600px.

**Triple font loading (performance):**
BrownBold, BrownLight, and BrownThin are each loaded three times:
1. `<link href="https://db.onlinewebfonts.com/c/...">` in `<head>`
2. `@import url(https://db.onlinewebfonts.com/c/...)` inside `<style>`
3. `@font-face { src: url("https://db.onlinewebfonts.com/t/...") }` also inside `<style>`

This triples HTTP requests for each of the three third-party fonts before the email body renders. Remove the `<link>` tags and `@import` lines; keep only `@font-face`.

**Third-party font CDN dependency:**
BrownBold/Light/Thin load from `db.onlinewebfonts.com`, a third-party CDN with no SLA. BrownRegular correctly loads from `www.drunkelephant.com` (brand-controlled). If `db.onlinewebfonts.com` is unavailable, three of four weights fall back silently — inconsistent with the one weight that is self-hosted.

**`maximum-scale=1` in viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents pinch-to-zoom on iOS. This is an accessibility violation for users with low vision. Change to `initial-scale=1` without `maximum-scale`.

**`-webkit-text-size-adjust:none` (universal selector):**
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```
`none` disables all automatic text scaling in WebKit/Blink clients (Apple Mail, iOS Mail). The standard safe value is `100%`, which prevents unwanted scaling while permitting user-initiated zoom. Already correctly set on `body`; the `*` override contradicts it.
