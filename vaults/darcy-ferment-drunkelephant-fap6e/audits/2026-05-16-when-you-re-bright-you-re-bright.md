# When you’re bright, you’re bright.
**Score:** 7/10 · **Type:** Email audit · **2026-05-16**
## Executive summary

- Drunk Elephant pivots here from the discount drumbeat — the last four emails all led with 15% off — and bets the send on social proof. "WE'RE SEEING STARS." is clever double-meaning work: five stars + skin brightness, tied together by the "Thank you for the 5-star love!" bridge. It's the most brand-coherent creative in this recent run, and the three customer reviews are unusually substantive: specific benefits named, timelines cited, repeat-purchaser signal included.
- The catch is the top banner. "UK, HELLOOOO. THE OFFER ENDS IN..." is a geo-targeted layer that feels grafted onto a different email. For any non-UK recipient it's immediately confusing, and the healthcare worker free-sample offer below it is conditional — if you're not in healthcare, the countdown is counting down toward nothing you can claim. That disconnect front-loads friction before the email's real payload (the reviews) even registers.
- The strategic call to drop the discount here is defensible. Repeated 15% off emails erode price anchoring, and a review-led send reinforces C-Firma's cult status without training customers to wait for a sale. But the execution is two ideas in one email.

## What's working

- **"WE'RE SEEING STARS." headline** — clean pun that earns both the brightness claim and the review payoff below it without feeling forced.
- **Three substantive, differentiated reviews** — "It works fast," "A parent for mature skin," and "It stays fresh" each target a distinct buyer objection (speed, age-appropriateness, oxidation concern). That's unusually well-curated social proof.
- **Photography and visual hierarchy** — the C-Firma product shot is sharp, the model's skin is on-brand aspirational, and the read order (hero → CTA → reviews) flows cleanly.
- **Countdown timer** — adds real urgency even if the offer it's attached to is niche.
- **Cadence break from discount-led messaging** — smart to run a brand-value send after four consecutive % off emails.

## What's weak

- **UK geo-banner on what may be a non-UK send** — "UK, HELLOOOO." is either a mis-targeted segment or a jarring visual for any recipient outside the UK. Either way, wrong first impression.
- **Healthcare worker offer creates exclusion for everyone else** — the countdown drives urgency toward a free sample that the majority of recipients can't claim. That's a bait-and-switch feel even if unintentional.
- **"SHOP NOW" CTA is generic** — after three specific, product-named reviews, the button does nothing with that momentum. No product name, no benefit echo.
- **No offer for the non-HCW, non-UK majority** — the email asks for a click with zero price incentive and no loyalty acknowledgment. Compared to the 15% off emails this replaces, there's no equivalent hook to convert fence-sitters.

## Recommendations

- 1. **Strip or localize the UK/healthcare banner for non-UK segments.** If the offer is UK-only, it should not appear above the fold for everyone else. Use segmentation or swap in a universal urgency banner ("Offer ends soon — shop C-Firma before it sells out").
- 2. **Rename the CTA to echo the reviews.** "Shop C-Firma Day Serum" or "See Why It's 5 Stars" takes the review narrative straight into the click action.
- 3. **Add a lightweight offer for non-HCW recipients** — even a GWP (gift with purchase) or free shipping threshold preserves the no-discount positioning while giving a reason to act now.
- 4. **Lead with the strongest review claim in the subject** — "One week. Clearer skin." is right there in the body copy and would be a more concrete hook than the pun.
- **Subject Alt A:** `"One week. Clearer skin. See why."`
- **Subject Alt B:** `"C-Firma: 5 stars from 60-something skin"`
- **Preheader Alt A:** `"Real results, real reviews — shop the vitamin C serum everyone keeps reordering"`
- **Preheader Alt B:** `"Brighter, firmer, and according to J.P. — the best her skin has ever looked"`

### 3. Rendering & Accessibility

**Critical — Dead CSS rules (HTML comments inside `<style>` block):**

```css
@media only screen and (max-width: 600px) {
  <!-- *[class=contenttable] { width:414px !important;} -->
  <!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
```

`<!-- -->` inside a `<style>` block is not valid CSS comment syntax — it is parsed as invalid tokens. Both `contenttable` and `mobile` width rules are silently ignored in all standards-compliant clients, breaking the responsive layout for those two classes on sub-600px viewports.

**Triple font loading — 6+ redundant HTTP requests per open:**

The same four font families (Brown Bold, Brown-Light, Brown-Thin, BrownRegular) are declared via three mechanisms simultaneously:
- `<link rel="stylesheet">` in `<head>` → `db.onlinewebfonts.com`
- `@import url(...)` inside `<style>` → same `db.onlinewebfonts.com` URLs
- `@font-face` blocks inside `<style>` → split between `db.onlinewebfonts.com` and `www.drunkelephant.com/on/demandware.static/`

The `<link>` and `@import` calls are redundant to the `@font-face` blocks. Remove both `<link>` tags and `@import` statements; keep only `@font-face`. Note: web fonts render only in Apple Mail / iOS Mail — Gmail and Outlook ignore them — so this overhead is paid on the clients that would actually render them.

**Split font CDN — single point of failure per weight:**

`BrownRegular` resolves from `drunkelephant.com` (Demandware CDN); Bold/Light/Thin resolve from `db.onlinewebfonts.com`. An outage on either CDN silently drops 2–4 weights with no cross-CDN fallback.

**Blanket `line-height: 100%` reset:**

```css
*{line-height: 100%}
```

Applied to all elements unconditionally. Multi-line copy in `<p>` and `<td>` elements will collapse to tight single-spacing in clients that honor the cascade, overriding any element-level `line-height` not declared `!important`. This typically manifests as crushed body copy on Windows/Outlook.

**`.sm` hidden with no show counterpart visible:**

```css
.sm{ display:none; }
```

No corresponding `@media` rule to re-show `.sm` elements is present in the provided CSS. If any content is placed in `.sm` elements (common for mobile-only copy or CTAs), it is permanently hidden to all clients. Confirm whether a show rule exists in the unshown portion of the HTML.

**Unusual mobile breakpoint — 418px:**

The 418px breakpoint (targeting legacy iPhone SE) predates the current 390px iPhone 15/16 viewport. If this template has not been updated post-2022, the 418px block may fire on no common device.
