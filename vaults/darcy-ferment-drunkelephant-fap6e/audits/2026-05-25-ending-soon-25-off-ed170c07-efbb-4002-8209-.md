# Ending soon: 25% off
**Score:** 8/10 · **Type:** Email audit · **2026-05-25**
## Executive summary

- This is the closing-bell email of Drunk Elephant's eight-send Friends & Family blitz, and it's the most functionally justified send in the sequence. The countdown timer — showing 0 days, 3 hours, 18 minutes — provides the one thing the May 24 sends ("Now you see it" at 3/10, "Well, hi" at 6/10) completely lacked: real-time urgency that is genuinely true. The creative is still the same "25% OFF SITEWIDE" wordmark from every send since May 21, but "FRIENDS & FAMILY IS WINDING DOWN" alongside a live clock earns the deploy in a way the flat May 24 reruns did not.
- The body structure is the smartest in the sequence: a GWP (full-size F-Balm with $75+ purchase), a bundle section with a $100+ savings hook, and a kits grid with explicit price anchors all give a subscriber a real reason to return and close the cart. That last-call architecture is sound.
- The damage is cadence. Eight emails in five days, and the subject drops all of Drunk Elephant's brand voice for pure utility. "Ending soon: 25% off" could come from literally any skincare brand. For the grand finale, that's a missed shot.

- Countdown timer (0 days, 3 hours, 18 min) is specific, visual, and the most compelling urgency asset in any email this week

- **Subject Alt A:** `"Your cart is waiting. 3 hrs left."`

## 1. Overview

This is the closing-bell email of Drunk Elephant's eight-send Friends & Family blitz, and it's the most functionally justified send in the sequence. The countdown timer — showing 0 days, 3 hours, 18 minutes — provides the one thing the May 24 sends ("Now you see it" at 3/10, "Well, hi" at 6/10) completely lacked: real-time urgency that is genuinely true. ### 3. Rendering & Accessibility

**Critical — Dead responsive CSS rules (HTML comments inside CSS block):**
Inside the `@media only screen and (max-width: 600px)` block, two rules use HTML comment syntax instead of CSS comment syntax:

```css
<!-- *[class=contenttable] { width:414px !important;} -->
<!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
```

HTML comment delimiters (`<!-- -->`) are not valid CSS. These rules will be silently ignored by all CSS parsers, meaning `.contenttable` and `.mobile` elements will not reflow at the 600px breakpoint. This is a confirmed rendering defect on mobile.

**Redundant font loading — 3x requests per font family:**
BrownBold, BrownLight, and BrownThin are each loaded via three separate mechanisms:
1. `<link rel="stylesheet" href="https://db.onlinewebfonts.com/c/...">` (head)
2. `@import url(https://db.onlinewebfonts.com/c/...)` (inline `<style>`)
3. `@font-face` src pointing to `db.onlinewebfonts.com/t/...`

This generates 6–9 redundant HTTP requests per render, adding latency before the email paints. De-duplicate to `@font-face` declarations only.

**Third-party font CDN dependency:**
Brown font variants are served from `db.onlinewebfonts.com`. This service is a community font host with no SLA. Downtime or rate-limiting causes silent fallback to system fonts, affecting layout fidelity. BrownRegular is served from `www.drunkelephant.com/on/demandware.static/...` — a first-party path that is more reliable.

**`maximum-scale=1` in viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from pinching to zoom on mobile. This is an accessibility defect (violates WCAG 1.4.4 Resize Text, Level AA).

**Aggressive global `line-height: 100%`:**
`*{line-height: 100%}` overrides line-height on all elements including buttons and multi-line text, which can compress leading and cause overlapping text in certain clients (notably Samsung Mail and older Android WebView).
