# Still time to save 20%
**Score:** 5/10 · **Type:** Email audit · **2026-06-17**
## Executive summary

- This is the SheerID professional-verification play again — the same 20% educator/first-responder/military/student discount that ran on June 8th. The creative is nearly identical: "IT SERVES YOU RIGHT" headline, same five verification category buttons (A Teacher, A Student, A Medical Professional, A Member of the Military, A First Responder), same three-step process breakdown. The only difference is the subject line has changed from "Grab 20% Off Before It's Gone!" to "Still time to save 20%" — this is an urgency nudge to the non-openers from the June 8 send.
- As a retargeting email, the strategy is sound. Resending to non-openers with a softer subject is standard practice and costs nothing. But the email itself is doing very little creative evolution — it's the same layout, same copy, same hero image. For a subscriber who did open the June 8 version, this lands as a repeat rather than a reminder. The 20% offer is stronger than DE's standard 15%, which is a genuine hook for the eligible audience. For everyone else, though, this email is irrelevant by definition.
- The execution is clean — no render bugs, clear verification flow — but it's a narrow-audience offer served broadly. If SheerID segmentation was done correctly, that's fine. If this went to the full list, it's wasted sends.

## What's working

- **Offer is concrete and elevated:** 20% off (vs. standard 15%) is a meaningful bump that eligible recipients will notice.
- **Five clear verification CTA buttons** make the action path unambiguous — no friction figuring out which category applies to you.
- **Three-step process copy** ("Get verified on SheerID, receive your discount code, keep saving") reduces hesitation about what happens after clicking.
- **Hero image and layout are clean** — no render bugs, text is legible, visual hierarchy from headline → body → buttons holds up.
- **"For a limited time only" urgency** is present in the hero copy, which is appropriate for a retarget.

## What's weak

- **It's a near-identical resend of June 8's email** — a subscriber who opened that one gets déjà vu with nothing new to engage with.
- **"IT SERVES YOU RIGHT" headline is cute but gated** — for ineligible recipients (the majority), the email has zero relevance and no escape hatch offer.
- **No product visual or specific product mention** — there's nothing to show what the 20% would actually buy; it's an abstract discount without anchoring desire.
- **Preheader is weak** — appears to bleed into "view in browser" territory; there's no compelling secondary hook for inbox preview.
- **The three-step copy block is generic** — it reads like onboarding instructions, not persuasion. It doesn't sell the 20% as aspirational.

## Recommendations

- 1. **Add a product carousel below the verification buttons** — show 2–3 hero SKUs (B.Hydra, C-Firma, Protini) with prices and the discounted 20%-off price alongside. Give the offer an object. That's the single change that would lift this email most — right now 20% off "anything" is abstract.
- 2. **Differentiate the resend creatively** — swap the hero image, update the headline to something like "Last chance: 20% off, confirmed for you" to signal this is a time-stamped follow-up, not the same email again.
- 3. **Rewrite the three-step block as benefits** — instead of "receive your discount code," say "unlock 20% off your next B.Hydra, Protini, or any DE product." Name the reward.
- 4. **Add a soft escape for ineligible recipients** — a small footer line: "Not in these categories? Check out our Subscribe to Save 10% program." Recaptures non-qualifiers rather than dead-ending them.
- **Subject Alt A:** `Last chance — 20% off for educators, military & more`
- **Subject Alt B:** `Your 20% off is still waiting (verify before it's gone)`
- **Preheader Alt A:** `B.Hydra, Protini, and everything else — 20% off. Verify in 30 seconds.`
- **Preheader Alt B:** `Teachers, first responders, military: claim your discount before it closes.`

### 3. Rendering & Accessibility

**Critical — invalid CSS in `<style>` block:**

```css
@media only screen and (max-width: 600px) {
  *[class=hide] { display: none !important;}
  <!-- *[class=contenttable] { width:414px !important;} -->
  <!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
```

HTML comment syntax (`<!-- -->`) is illegal inside CSS. Any parser that doesn't silently discard these will expose literal `<!--` text or drop the surrounding rule block entirely. The `contenttable` and `mobile` responsive width overrides may be non-functional.

**Triple font loading — redundant requests:**

Brown Bold, Brown-Light, and Brown-Thin are each loaded three times:
1. `<link>` tag to `db.onlinewebfonts.com`
2. `@import` inside `<style>`
3. `@font-face` declaration (also pointing to `db.onlinewebfonts.com`)

This generates 6–9 redundant HTTP requests per client that supports web fonts in email (Apple Mail, some Outlook versions). It does not affect Gmail/Outlook Windows (which ignore web fonts), but adds load latency where it does work.

**Third-party font CDN dependency:**

`db.onlinewebfonts.com` is a font redistribution service, not a first-party CDN. Availability is not guaranteed by Drunk Elephant's infrastructure. The first-party `BrownRegular` is correctly hosted on `drunkelephant.com/on/demandware.static/...`; Bold, Light, and Thin variants should be migrated to the same host.

**Zoom/accessibility suppression:**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none;}
```

`maximum-scale=1` blocks pinch-to-zoom on iOS. Combined with `text-size-adjust:none`, users with low vision cannot enlarge content. Both should be removed; email clients handle zoom independently.
