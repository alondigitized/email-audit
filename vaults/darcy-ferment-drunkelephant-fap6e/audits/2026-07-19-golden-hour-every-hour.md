### 3. Rendering & Accessibility

**Font triple-loading (confirmed bug):** Brown Bold, Brown-Light, and Brown-Thin are each loaded three separate ways simultaneously:
1. `<link rel="stylesheet">` tags in `<head>`
2. `@import url(...)` inside the `<style>` block
3. `@font-face` declarations in the same `<style>` block

This causes 3× redundant HTTP requests per font family and increases blocking load time. Only `@font-face` is needed; the `<link>` and `@import` entries should be removed.

**HTML comments embedded inside CSS (confirmed invalid markup):**
```css
@media only screen and (max-width: 600px) {
  <!-- *[class=contenttable] { width:414px !important;} -->
  <!-- *[class=mobile] { width:414px !important;} -->
```
`<!-- -->` is HTML comment syntax, not CSS. These rules are silently dropped by conforming CSS parsers. The `contenttable` and `mobile` width overrides on mobile are not applied. If those classes exist in the body, mobile layout for those elements is broken.

**`maximum-scale=1` on viewport meta:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from pinching to zoom. This is an accessibility failure (WCAG 1.4.4 — Resize Text). Should be removed.

**Third-party font CDN dependency:** `db.onlinewebfonts.com` is a third-party service not controlled by the brand. If it goes down or rate-limits, all Brown variants fall back to system fonts mid-campaign. `BrownRegular` loads from `drunkelephant.com`'s own Demandware static host — consistent approach would be to self-host all weights there.

**`-webkit-text-size-adjust: none`** applied globally via `*{}` selector. Using `none` (not `100%`) disables iOS auto-scaling entirely rather than just preventing inflation — can make text unreadably small on older iPhones.
