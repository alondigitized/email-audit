# Drunk classics are 25% off!
**Score:** 9/10 · **Type:** Email audit · **2026-05-23**
## Executive summary

- "Drunk classics are 25% off!" is the fourth Friends & Family email in three days — and the creative team is clearly working to justify each send with a fresh angle rather than just reposting the hero offer. The "classics" framing (Protini, C-Firma, B-Hydra, D-Bronzi as named best-sellers) is the only meaningful differentiator from yesterday's two sends, and it mostly lands. The tiered GWP sections ($100+, $175+) add genuine layered incentive beyond the baseline 25%.
- That said, the cadence math is punishing. A subscriber who opened every email since May 21 has now seen the same 25% off sitewide offer four times. Subject and hero are clean, brand voice is intact, but the law of diminishing returns is real — this send will underperform the May 21 launch on open rate regardless of execution quality.
- The one fixable omission that costs this email disproportionately: no visible sale end date anywhere in the email. Without a deadline, all urgency is decorative. Add three words ("Ends Sunday midnight") and this converts better overnight.

## What's working

- "Drunk classics" framing gives this send its own identity; naming the four hero SKUs (Protini, C-Firma, B-Hydra, D-Bronzi) turns a generic discount email into a curated best-of.
- Visual hierarchy is clean — 25% OFF SITEWIDE lands first, SHOP NOW button is prominent and unambiguous.
- Tiered GWP sections ("Future's Looking Bright" / "Mask Me Anything") create genuine incremental incentive to push carts above $100 and $175 thresholds.
- Brand voice stays sharp end-to-end: "A great time to get Drunk." / "Future's Looking Bright" / "Mask Me Anything" all feel native to DE.
- No render bugs; product images are clean and all four SKUs carry their own individual SHOP link.

## What's weak

- No sale end date visible anywhere in the email — the primary driver of last-chance urgency is completely absent.
- The top banner promotes Subscribe-to-Save 25% off a first subscription order, a competing CTA that dilutes the F&F sitewide message before the hero even loads.
- Fourth consecutive F&F email in three days (two on May 22 alone) — cadence fatigue is real, and this will be the worst-performing of the four by open rate.
- "SHOP NOW" / "SHOP" CTAs are generic; they don't echo "classics," which was the creative bet of this send.
- GWP tier copy ($100+ / $175+) is small and the specific free products are hard to parse at mobile scale.

## Recommendations

- 1. **Add a hard deadline to the hero.** "Sale ends Sunday midnight" or equivalent. This is the single highest-leverage change — it converts undecided subscribers before they archive the email.
- 2. **Remove the Subscribe-to-Save banner or defer it.** It's a separate conversion mechanic that competes with F&F messaging. A cleaner use: send it standalone after the sale closes to re-engage non-purchasers.
- 3. **Sharpen CTA copy.** Change the hero button from "SHOP NOW" to "SHOP CLASSICS" to stay thematically coherent with the subject line. Individual product links could extend to "SHOP PROTINI," etc.
- 4. **Make GWP tiers scannable on mobile.** Bump the threshold amount to headline-weight text or add a "FREE GIFT AT $100+" badge so it reads instantly without leaning in.
- 5. **Make this the last F&F send unless there is a genuine escalation.** A "last chance" send tomorrow with a confirmed end time is acceptable. A fifth creative variation without escalating stakes (extended date, free shipping, added gift tier) will measurably damage list health.

### 1. Technical Summary

Table-based XHTML 1.0 Transitional email with three separate font-loading mechanisms for the same typefaces; the most critical code issue is HTML comment syntax injected directly inside a CSS `@media` block, which silently kills two responsive layout rules.

---

### 2. Link & Tracking Issues

**Truncated source — full link audit not possible.** From what is visible:

- No UTM parameters confirmed on any link in the rendered portion; assessment deferred to full source (see §6).
- Font assets are served from `https://db.onlinewebfonts.com` (third-party CDN) — requests to this domain will appear in recipient mail client logs and could be flagged by corporate security gateways.
- Font assets also served from `https://www.drunkelephant.com/on/demandware.static/…` (Salesforce Commerce Cloud). If the Demandware static versioning timestamp (`v1719565389232`) is stale or the path is invalidated by a platform upgrade, all custom fonts silently fall back to system fonts.

---

### 3. Rendering & Accessibility

**Critical — HTML comments inside CSS block break responsive rules:**

```css
@media only screen and (max-width: 600px) {
  *[class=hide] { display: none !important;}
  <!-- *[class=contenttable] { width:414px !important;} -->
  <!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
```

`<!-- -->` is HTML syntax; inside a `<style>` block it is invalid CSS and is not parsed as a comment by any CSS engine. Both the `.contenttable` and `.mobile` responsive width overrides are silently dropped. Affected classes will not resize at ≤600px viewport widths.

**Triple font loading — duplicate HTTP requests:**

The same three Brown font variants are requested three times each:
1. `<link>` tags in `<head>` (`db.onlinewebfonts.com`)
2. `@import` inside `<style>` (same `db.onlinewebfonts.com` URLs)
3. `@font-face` declarations (also `db.onlinewebfonts.com` + separate `.eot`/`.woff2`/etc. stack)

This fires 6–9 redundant HTTP requests per open, adds latency on first render, and will cause inconsistent font resolution ordering across clients.

**`-webkit-text-size-adjust: none` on universal selector:**

```css
*{-webkit-text-size-adjust:none; -ms-text-size-adjust:none; ...}
```

Using `none` (not `100%`) prevents iOS Mail users from manually zooming text — a WCAG 2.1 §1.4.4 violation. Change to `100%`.

**`line-height: 100%` on universal selector:**

```css
*{line-height: 100%}
```

This blanket override is known to collapse line-height inheritance in Outlook and produce clipped descenders on multi-line text. Should be scoped to specific elements, not `*`.

**`max-height: 1000000px` on universal selector:**

Standard Gmail clipping hack — no issue, intentional.
