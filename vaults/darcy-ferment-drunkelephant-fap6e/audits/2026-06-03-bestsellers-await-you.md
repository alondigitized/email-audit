# Bestsellers await you!
**Score:** 8/10 · **Type:** Email audit · **2026-06-03**
## Executive summary

- After a 14-email Friends & Family blitz ending May 28, the product launch on May 30, and the clean "Hydrated skin" editorial on June 1, Drunk Elephant is clearly in a content-reset mode — and this email fits that strategy. The core concept is genuinely smart: name a skin concern, then map one bestseller to fix it. That structure is far more useful than a generic bestseller roundup.
- The problem is that the subject line buries the lede completely. "Bestsellers await you!" is the blandest possible wrapper around a hook that could have read "Dull? Dry? Uneven? Puffy?" or "Name your skin issue — we'll fix it." The map-a-concern mechanic is only revealed inside the email, after the subscriber has already decided to open based on a generic subject.
- The execution is clean and the editorial tone is sustained well. But the entry point (subject + preheader) underserves a legitimately clever interior.

## What's working

- **Skin concern → product mapping** is genuinely useful editorial — Dull / Dry / Uneven / Puffy is a clear, scannable structure that most subscribers can self-sort into.
- **"SUMMER SKIN, SORTED"** at the foot ties the roundup to the current season credibly and without fake urgency.
- **No discount pressure** — the right call given the F&F blitz only ended six days ago. Feels like earned trust, not laziness.
- **Four specific product callouts** with benefit-level copy (not just product names) give the reader something to act on.
- **Clean render** — no broken images, no layout bugs visible in the screenshot.

## What's weak

- **Subject line wastes the hook.** "Bestsellers await you!" could come from any brand on any Tuesday. The skin-issue mechanic inside is much more compelling and was left out entirely.
- **Top-level SHOP NOW fires before the hook lands.** Placing the CTA above the four skin-concern panels asks for the click before the rationale is given. The CTA should follow the payoff.
- **Preheader appears to lean on formula/packaging updates** — if it reads as product news, it creates a mismatch with what the email is actually about (a skin-concern quiz structure).
- **No individual CTAs visible under each product panel** — or if they exist, they're not prominent enough to register as scannable anchor points.

## Recommendations

- 1. **Rewrite the subject to surface the internal hook.** The "Name an issue" framing is the whole email — it should be the subject too. That's a straightforward swap with zero creative risk.
- 2. **Move the SHOP NOW CTA below the four skin-concern panels.** Let the logic land — problem → solution → action — before asking for the click. The current flow is CTA before payoff.
- 3. **Add a per-panel mini-CTA** (e.g., "Shop B-Goldi →") beneath each concern block so the subscriber can go directly to the product they identified with, not a generic bestsellers page.
- 4. **Preheader should preview the four concerns,** not reference formulas. Something like "Dull / Dry / Uneven / Puffy — your fix is one click away" tells the subscriber exactly what's inside.

- **Preheader Alt A:** `Dull, dry, uneven, puffy — there's a bestseller for each.`

### 3. Rendering & Accessibility

**Issue — HTML comments inside `<style>` block (invalid CSS):**

```css
<!-- *[class=contenttable] { width:414px !important;} -->
<!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
```

HTML comment syntax (`<!-- -->`) inside a `<style>` block is invalid CSS. It is a legacy HTML 3.2 artifact and is parsed correctly by virtually no modern email client. These two ruleset declarations are effectively dead — `.contenttable` and `.mobile` width overrides will not apply on any client that enforces CSS spec. This can break mobile layout for the two affected elements.

**Issue — `maximum-scale=1` in viewport meta:**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

Prevents pinch-to-zoom on mobile. Fails WCAG 1.4.4 (Resize Text, Level AA). Should be removed or set to `maximum-scale=5`.

**Issue — Duplicate font loading (6 redundant HTTP requests):**

BrownBold, BrownLight, and BrownThin are each loaded **twice** — once via `<link rel="stylesheet">` and again via `@import` inside the `<style>` block, pointing to the same `db.onlinewebfonts.com` URLs:

```html
<link href="https://db.onlinewebfonts.com/c/4150d76a852e1c349e0b6fe15f29d9ca?family=Brown+Bold" rel="stylesheet">
```
```css
@import url(https://db.onlinewebfonts.com/c/4150d76a852e1c349e0b6fe15f29d9ca?family=Brown+Bold);
```

That's 6 requests where 3 are required. Most email clients strip `<link>` tags in `<head>`, so the `@import` copies are correct to keep — the `<link>` tags are the redundant ones and should be removed.

**Issue — Third-party font CDN dependency:**

Both `db.onlinewebfonts.com` (BrownBold/Light/Thin) and `www.drunkelephant.com` demandware static (BrownRegular) are loaded at render time. `db.onlinewebfonts.com` is not operated by the brand; an outage or rate limit causes fallback font rendering. Self-hosting all four weights on a brand-controlled CDN is lower risk.

**Cannot verify:** `alt` attributes on images — source is truncated before `<img>` tags. Must confirm all product images carry descriptive `alt` text and decorative images use `alt=""`.
