# Friends, family: 25% off starts now!
**Score:** 8/10 · **Type:** Email audit · **2026-05-21**
## Executive summary

- This is Drunk Elephant's Friends & Family sale email — and it's a noticeable gear-shift from the 15% off drumbeat that's been running since May 11. The jump to 25% sitewide, combined with two threshold spend offers (free Hydra kit at $100+, full-size F-Balm at $75+), makes this feel like an event, not just another discount push. The brand voice is dialed in: the top banner's "WHY ARE YOU STILL READING THIS? GO SHOP!" is exactly the kind of playful irreverence that makes DE's email program distinctive.
- The structure does most of the right things — hero delivers the offer immediately, product tiles show both strike-through and sale prices, and the two bonus gift tiers give high-intent buyers a reason to spend more. The main drag is the hero CTA ("HAPPY SHOPPING") which is too soft for a sale email with this much real urgency behind it.
- Compared to the May 16 "When you're bright, you're bright" send — which deliberately avoided discounting — this one earns the sale framing. The escalation feels real.

## What's working

- **25% off is a concrete, meaningful jump** from the 15% baseline that's been running all month — subscribers who noticed the prior cadence will register the upgrade.
- **Top banner copy** ("WHY ARE YOU STILL READING THIS? GO SHOP!") is punchy and on-brand; it does real work reinforcing urgency before the hero even loads.
- **Two tiered gift-with-purchase offers** ($75+ and $100+) are clearly called out with "FULL SIZE GIFT" badge, giving high-intent buyers a reason to stretch their basket.
- **Product tiles show both original and discounted prices** side-by-side — removes the mental math friction entirely.
- **Visual hierarchy is clean**: the eye flows naturally from hero headline → hero CTA → tier offers → product grid.

## What's weak

- **"HAPPY SHOPPING" CTA is too passive** for a sale email — it doesn't create a sense of scarcity or motion; something like "SHOP 25% OFF NOW" would carry more urgency.
- **No explicit sale end date visible** — "It's go time!" and "before they sell out" are soft urgency signals, but no deadline anchors the FOMO for fence-sitters.
- **The $75+ / $100+ threshold tiers are buried in secondary sections** — they're strong enough to be in the hero block, not below the fold.
- **No social proof anywhere in the email** — a single star-rating line or "bestseller" badge on one tile would help, especially since the May 16 send leaned heavily on 5-star reviews and DE subscribers have already been primed for it.

## Recommendations

- 1. **Replace "HAPPY SHOPPING" with a deadline-anchored CTA** — "SHOP 25% OFF — ENDS SUNDAY" or "CLAIM 25% OFF NOW" turns passive into urgent. This is the single highest-lift change.
- 2. **Surface the $75+ F-Balm offer in or directly below the hero** — it's the more achievable threshold and functions as a purchase trigger for moderate spenders; it's currently competing with the hero copy when it should reinforce it.
- 3. **Add an explicit sale expiry date** — even "offer ends Monday" in small type under the hero CTA would convert holdouts who need a clock, not just vibes.
- 4. **Drop a "bestseller" or star-rating badge on one product tile** — the T.L.C. Babyfacial ($87.75 sale) already has brand recognition; adding "4.8★ · 12k reviews" under it costs nothing and would lift click rate on the highest-ASP item.

### 3. Rendering & Accessibility

**[HIGH] HTML comments inside CSS `@media` block — rules are dead**

```css
@media only screen and (max-width: 600px) {
  *[class=hide] { display: none !important; }
  <!-- *[class=contenttable] { width:414px !important;} -->
  <!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
```

`<!-- ... -->` is not valid CSS comment syntax. Both `.contenttable` and `.mobile` responsive width rules are silently ignored in every client. Any element using those classes renders at its default width on narrow viewports.

**[MEDIUM] Triple font-loading for the same typefaces**

For `BrownBold`, `BrownLight`, and `BrownThin`, the email loads the same font via three stacked mechanisms:

1. `<link href="https://db.onlinewebfonts.com/c/...">` (HTML `<head>`)
2. `@import url(https://db.onlinewebfonts.com/c/...)` (inside `<style>`)
3. `@font-face { src: url("https://db.onlinewebfonts.com/t/...") }` (also inside `<style>`)

This generates 6+ redundant HTTP requests per font family at render time. Most email clients block external CSS/fonts entirely, so all three mechanisms fail in Gmail, Outlook, and Apple Mail unless images are enabled — but the redundancy still inflates page weight and parse time in clients that do execute them (e.g., Apple Mail on iOS).

`BrownRegular` is the only weight loaded cleanly via `@font-face` alone from `drunkelephant.com`'s own CDN — this pattern should be standardized.

**[MEDIUM] `maximum-scale=1` in viewport meta**

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```

Prevents user pinch-zoom on mobile. WCAG 1.4.4 (Resize Text) requires that text can be resized up to 200% without loss of functionality. This also triggers accessibility warnings in some inbox previewers.

**[LOW] Universal `line-height: 100%` override**

```css
*{line-height: 100%}
```

A unitless percentage `line-height` on the universal selector collapses inherited line-height across all elements to 1× the element's own font-size. This is intentional for tightly-controlled table cells but will compress multi-line text blocks and cause clipping on descenders in some clients. Scope this to specific selectors rather than `*`.

**[LOW] `<title>` has no campaign context**

```html
<title>Drunk Elephant</title>
```

Inbox previewers and browser-view renders use the `<title>`. A campaign-specific value (e.g., "Friends & Family 25% Off — Drunk Elephant") is a minor improvement for preview fidelity.
