# Stock up at 25% off!
**Score:** 8/10 · **Type:** Email audit · **2026-05-22**
## Executive summary

- This is a day-two reminder for the same Friends & Family 25% off sitewide sale that launched yesterday ("Friends, family: 25% off starts now!" — 8/10). The creative team earned it: rather than just resending the same email, they layered in two gift-with-purchase tiers ("Future's Looking Bright" at $100+ spend, "Mask Me Anything" at $75+ spend) and a kit grid at 35% off — all of which give the repeat send a reason to exist. The hero is clean, the 25% off message dominates the fold, and the visual hierarchy is exactly right.
- The cracks show in the preheader and the urgency layer. The preheader is being used to pitch Subscribe-to-Save at 10% off — a completely different offer — right above an inbox subject line advertising 25% off. In an inbox that reads subject + preheader together, those two numbers are incoherent. And while "don't wait!" suggests urgency, no deadline is visible anywhere in the email, so it rings hollow.
- Verdict: a solid second-day send, better merchandised than the opener, but undone by a preheader that fights the subject and urgency copy with no backing date.

## What's working

- **25% OFF hero is impossible to miss.** Large, high-contrast type dominates the first fold. A subscriber opens and instantly knows the offer.
- **GWP tiers add real incremental value.** Two spend-threshold unlocks ($75+ for F-Balm, $100+ for Pekee + Bright Trio) give repeat openers a reason to upgrade their cart — not just the same 25% pitch they already saw yesterday.
- **Kit grid at 35% off deepens the deal story.** Pricing is shown on each kit tile; four distinct products give browsers multiple entry points.
- **"This way to the friend zone." hook is on-brand and warm** — fits the F&F sale theme without being cloying.
- **Clean render.** No broken images, no layout drift, fine print is present and legible.

## What's weak

- **Preheader actively undermines the subject.** "Sign up for Subscribe to Save and get 10% off" appears in the inbox preview right after a subject promising 25% off — two different numbers, two different offers, visible simultaneously in the inbox.
- **Zero deadline anywhere in the email.** "Don't wait!" is urgency theater without a clock. Yesterday's send had the same problem; two days in, still no end date.
- **"SHOP NOW" CTAs are generic throughout.** Every section — hero, GWP tiers, kit grid — resolves to the same CTA with no product-specific anchoring.
- **Back-to-back cadence is wearing thin.** This is the seventh Drunk Elephant send in nine days. A 25%-off reminder the day after a 25%-off launch is borderline fatigue territory for any subscriber who opens frequently.

## Recommendations

- 1. **Fix the preheader immediately.** Pull the Subscribe-to-Save pitch out of the preheader slot — it's cannibalizing the 25% off message. Replace it with deadline copy that actually closes the loop the subject opens.
- **Preheader Alt A:** `Sale ends Sunday — 25% off everything, sitewide.`
- **Preheader Alt B:** `Your last chance to stack 25% off + free F-Balm at $75.`
- 2. **Put a hard end date in the hero.** Add "Ends [date]" directly below the 25% OFF headline. Even a vague "this weekend only" outperforms "don't wait!" for click conversion.
- 3. **Sharpen the subject for urgency.** The current subject is fine but doesn't differentiate from yesterday's send.
- **Subject Alt A:** `25% off ends Sunday — kits at 35% too`
- **Subject Alt B:** `Friends & Family: last 48 hours + free F-Balm on $75`
- 4. **Make the GWP tiers the CTA, not just a section header.** "SHOP NOW" beneath "Mask Me Anything" doesn't tell the subscriber what they're shopping for. Change to "Unlock Free F-Balm" — a concrete benefit, not a generic instruction.
- 5. **Differentiate the subject more aggressively from yesterday.** Lead with the kits angle or the GWP tiers, which are actually new today. "35% off kits + 25% everything" gives a subscriber who already saw yesterday's email a reason to open again.

### 3. Rendering & Accessibility

**[HIGH] Invalid HTML comment syntax inside CSS `@media` block**
```css
@media only screen and (max-width: 600px) {
  *[class=hide] { display: none !important;}
  <!-- *[class=contenttable] { width:414px !important;} -->
  <!-- *[class=mobile] { width:414px !important;height: auto !important;} -->
```
`<!-- -->` are HTML comment delimiters, not CSS comment syntax. These two rules are silently dropped by all CSS parsers. Any element with `class="contenttable"` or `class="mobile"` will not resize on screens ≤600px. Fix: change to `/* ... */` or uncomment if intentional removal.

**[MEDIUM] `maximum-scale=1` in viewport meta**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocks user-initiated pinch-zoom on mobile. Fails WCAG 1.4.4 (Resize Text). Remove `maximum-scale=1`.

**[MEDIUM] Triple font-loading for the same assets**
The same `db.onlinewebfonts.com` font URLs are loaded via three separate mechanisms:
1. `<link rel="stylesheet" href="https://db.onlinewebfonts.com/c/...?family=Brown+Bold">` (in `<head>`)
2. `@import url(https://db.onlinewebfonts.com/c/...?family=Brown+Bold)` (inside `<style>`)
3. `@font-face { src: url("https://db.onlinewebfonts.com/t/4150d76a852e1c349e0b6fe15f29d9ca.woff2") }` (also inside `<style>`)

This fires 3 separate HTTP requests per font weight before the email even renders. Gmail strips `<link>` and `@import` tags, so only the `@font-face` blocks survive — making the first two mechanisms dead weight that add parse time in other clients.

**[LOW] `BrownRegular` uses first-party CDN; Bold/Light/Thin use third-party**
`BrownRegular` is served from `drunkelephant.com/on/demandware.static/...` (reliable, first-party). The other three weights load from `db.onlinewebfonts.com`, a font redistribution host with no SLA. Inconsistent reliability; consider self-hosting all weights on `drunkelephant.com`.

**[LOW] Global `* { line-height: 100% }` reset**
Overrides line-height on every element including links and buttons. This is a known cause of clipped descenders and misaligned CTA text in some clients. Should be scoped to layout tables only.

**[INFO] XHTML 1.0 Transitional DOCTYPE**
Standard for email; not a defect, but VML namespace (`xmlns:v`, `xmlns:o`, `xmlns:w`) is only needed if conditional VML is present further in the HTML.
