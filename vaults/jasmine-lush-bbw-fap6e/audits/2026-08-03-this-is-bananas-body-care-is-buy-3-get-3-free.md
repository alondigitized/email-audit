# 🤭 this is bananas - body care is buy 3, get 3 free. 🍌
**Score:** 8/10 · **Type:** Email audit · **2026-08-03**
## Executive summary

- This is the cleanest thing in the recent batch: one hero image does the beauty-shot work, and it's followed immediately by a real, quantified offer — "STARTS TODAY / BUY 3, GET 3 FREE" — with a button right there. No click-to-reveal games like the 8/2 flash-sale email that scored 4/10 for hiding its own price. It's closer in execution quality to the soap and mist sends that scored 9/10 on 8/1 and 7/31.
- The soft spot is sequencing: the subject and hero lead with the "bananas" pun before the deal registers, so there's a beat of confusion before the payoff lands. And the flavor choice (banana, watermelon) feels disconnected from the fall creative this brand was running just days earlier — it reads like an SKU-driven promo rather than a coherent campaign moment.
- Net: a well-executed, single-offer email that undersells its own strongest asset — the number itself — by wrapping it in a pun instead of leading with it.

## What's working

- The offer is stated plainly and once — Buy 3, Get 3 Free — with no reveal gimmick or buried pricing.
- Two SHOP CTAs are each tied to a specific, visible product (banana body wash/cream, watermelon hand spray), not a generic homepage link.
- Real product detail is visible: sizes (16 FL OZ, 2.1 OZ), "kills 99.9% of bacteria," "Dermatologist Approved."
- A "Top Offers" grid gives eight more entry points (Fragrance, Body Care, Candles, Soaps, etc.) if the hero doesn't convert.
- No render bugs — every image loads cleanly, no overlapping text.

## What's weak

- The pun ("Going bananas for Banana") delays the actual offer instead of leading with it.
- No preheader/preview text is visible to reinforce the subject in the inbox — that real estate is empty.
- The flavor drop feels disconnected from this brand's own recent fall push ("fall starts with a spritz," 7/31) — reads like an isolated SKU promo, not a campaign beat.
- No loyalty/rewards-member messaging despite this being a known lever for the brand.
- CTA copy is just "SHOP" / "SHOP NOW" — generic, doesn't name what's being shopped.

## Recommendations

- 1. Lead the hero and subject with the offer itself, not the banana pun — the number is the strongest asset here and it's currently buried under a joke.
- 2. Add a preheader that adds a second concrete detail (end date or category) — right now nothing complements the subject.
- 3. Replace generic "SHOP" buttons with category-specific CTAs ("Shop Body Care," "Shop Hand Soaps").
- 4. Surface the offer end date ("through Aug 7") above the fold instead of only in the footer legal block.
- 5. Add a one-line loyalty/rewards callout near the banner if the recipient is a member.
- **Subject Alt A:** `Buy 3, get 3 free — full-size body care, starts today`
- **Subject Alt B:** `🍌 buy 3 get 3 free is here (body, skin & hair)`
- **Preheader Alt A:** `Full-size favorites, mix & match — ends August 7.`
- **Preheader Alt B:** `Stock up: 3 free when you buy 3, today only through Sunday.`

# Technical Audit — Bath & Body Works Promotional Email

## 1. Technical Summary
SFMC/ExactTarget-generated HTML 4.01 table-based email with MSO conditionals and a mobile breakpoint. Automated QA returned a 57% pass rate, 0 hard issues, 3 warnings — mainly missing alt text, empty-`src` images, and unconfirmed compliance headers via the relay.

## 2. Link & Tracking Issues
- Open-tracking pixel present and correctly placed: `https://click.e2.bathandbodyworks.com/open.aspx?M5JZVUC5G4UENNXKPZFZYV4CIE.70248&d=70248&bmt=0` (1x1, standard SFMC beacon).
- 31 links use the `click.e2.bathandbodyworks.com` redirect domain — consistent with the sending domain (`e2.bathandbodyworks.com`) and image domain (`image.e2.bathandbodyworks.com`); QA skipped HTTP probing of these by design, so true destinations are unverified.
- Two `<img>` tags have an empty `src=""` (QA: "Image missing alt text: : src:"). Empty `src` is a known anti-pattern — some clients issue a spurious request to the current document, wasting a request and polluting logs. Should be populated or removed.
- The Everest Engagement personalization call — `https://bbwus.everestengagement.com/ea/fw0q51vctP/?e=&c=080326_EM_SU_BAU_PROMO_0_NRDM_TBCB3G3_AM_BAL-NTF-OPTD_FULL_V1` — has an empty `e=` parameter (likely an unpopulated subscriber/email ID merge field) and exposes the full internal campaign code directly rather than being wrapped by the click-tracking domain.

## 3. Rendering & Accessibility
- 4 images flagged missing `alt` text, including the primary content image `418d0db7-5a65-43cb-b5c9-9c6c142e4fd2.png` — no description available to screen readers.
- Two images have no `src` at all (see above) — will render broken in most clients.
- `@import url('https://fonts.googleapis.com/css2?family=Source+Sans+Pro...')` is declared twice (once in `<head>`, once in a nested `stylingblock-content-wrapper` block). `@import` is stripped by Outlook, Gmail, and most mobile mail clients, so this rule will silently fail in the majority of inboxes — degrades gracefully to the Arial/Helvetica fallback stack, but the duplicate is dead code.
- MSO conditional comment is internally inconsistent: text reads "helps render code in **120dpi** versions of Outlook" but the block sets `<o:PixelsPerInch>96</o:PixelsPerInch>` (96dpi/100% zoom). Comment also contains a stray `*/` — a leftover CSS-comment artifact pasted into an HTML comment.
- `<meta http-equiv="Content-Type" charset=utf-8">` is declared at the end of `<head>`, after `<title>` and `<style>`, rather than as the first child — not spec-compliant placement, though no non-ASCII content precedes it here so there's no visible impact.
- Table layout (600px fixed width) with `max-width:599px` mobile breakpoint and dedicated mobile padding classes — standard, structurally sound responsive pattern.

## 4. Personalization & Merge Tokens
- No unresolved merge tags (`%%...%%`, `{{...}}`) visible in the rendered HTML — personalization resolved correctly for this send.
- Comments confirm AMPscript-driven branching not visible in output: *"Set APT for NTF campaigns, otherwise respect email-defined APT"* / *"If @NTF_Flag is 'N', @APT should be set in the email; no default fallback here"* — consistent with the `NTF-OPTD` flag found in the campaign code noted in §2.
- Preheader is hardcoded static text ("get juicy with our pick of the patch. 🍉") while a commented-out dynamic preheader slot exists (`data-key="gvhu7dvhmx9"`, `data-label="Preheader"`). The shipped fallback text doesn't correspond to this send's subject (🤭 bananas / buy‑3‑get‑3 body care, 🍌) — indicative of a disabled dynamic content block and a stale/mismatched fallback string carried over from another template.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)

- `List-Unsubscribe-Post` (RFC 8058 one-click): not found (QA WARN), same relay caveat.
- `Authentication-Results` (SPF/DKIM/DMARC): not found (QA WARN) — status unknown, likely a relay-capture artifact per QA notes rather than confirmed misconfiguration.

- The one directly visible destination (Everest Engagement endpoint) uses a proprietary `c=` campaign-code param instead of standard `utm_source`/`utm_medium`/`utm_campaign` — expected for a personalization API call, not a user click-through, so this isn't itself an issue.
- Sending domain, click-tracking domain, and image domain are all consistent `e2.bathandbodyworks.com` subdomains — good alignment, no mismatch signal that would hurt deliverability/trust.
- Cannot confirm that link destinations match the promoted offer since URLs are masked by the tracking layer and weren't resolved.
