## Technical Audit

## 1. Technical Summary
The email has no confirmed hard failures (0 issues, 3 warnings, 57% pass rate). Five images lack `alt` attributes, and several header and tracking checks couldn't be verified because the relay didn't capture the headers and the HTML was truncated.

## 2. Link & Tracking Issues
- **43 tracking links were not probed.** They are on click-redirect domains, e.g. `bbwus.everestengagement.com/ea/...`, so destinations, redirect chains and 404s are unverified. This is a coverage gap, not a confirmed defect.
- **The tracking pixel has no `alt`.** `https://bbwus.everestengagement.com/ea/fw0q51vctP/?e=200511831233&c=110926_EM_FA_BAU_PROMO_0_NRDM_B1G1CDL_AM_BAL_G6M_V1` is an open-tracking pixel. It is not a content image, so this is low severity.
- **The tracking URL carries campaign and recipient identifiers in the query string.** The `e=` parameter is an encoded recipient/event ID. This is normal for ESP tracking, but it means the links are per-recipient.

## 3. Rendering & Accessibility
- **Five images are missing `alt` text.** All are hosted at `image.e2.bathandbodyworks.com/lib/fe9213737561047a72/m/1/`:
  - `4851c40c-9928-4c38-88b8-02583dd793aa.png`
  - `d6327aef-bba4-4c90-8be7-77b3d8306641.png`
  - `00a9ac12-8940-4f37-9570-9b23c6fb7b9c.png`
  - `7b7c94ef-aaa3-42f7-8531-38bf7f901ae6.png`
  - `bbebdf75-1fc0-48a3-96d4-ad8652de93f7.png`

  If these carry offer or CTA content, that content is invisible to screen readers and with images blocked. The `alt` attribute is missing entirely, rather than set to an empty `alt=""` for decorative images.
- **The Google Fonts `@import` can't load Helvetica Neue.** `@import url('https://fonts.googleapis.com/css2?family=Helvetica+Neue&display=swap')` requests a family Google Fonts doesn't serve. `@import` is also ignored by Gmail and many other clients. The `.font-main` fallback stack (Helvetica, Arial, sans-serif) covers this, so the effect is a wasted request.
- **Duplicate charset declarations.** Both `<meta http-equiv="Content-Type" content="text/html; charset=UTF-8"/>` and `<meta charset="utf-8">` are present. This is harmless but redundant.
- **A `<table>` appears directly after the `<meta>` tags with no visible `</head>`/`<body>`.** In the truncated source, content seems to start inside `<head>`. I can't confirm this because of the truncation, so it needs a full-source check.
- **Dark mode is handled.** The email has `color-scheme` meta tags, `prefers-color-scheme` rules and `[data-ogsc]`/`[data-ogsb]` Outlook selectors. No issues found there.
