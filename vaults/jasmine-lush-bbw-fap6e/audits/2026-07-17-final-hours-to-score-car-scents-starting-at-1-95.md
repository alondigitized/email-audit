# 🚨 final hours to score car scents starting at $1.95.
**Score:** 6/10 · **Type:** Email audit · **2026-07-17**
## Executive summary

- This email is nominally a "final hours" closer on car scents — a legitimate, recognizable B&BW category priced at an accessible $1.95 entry point. The hero delivers on the subject line promise: "Your Fall Escape Awaits / Final Hours" with car fragrance product photography and the $1.95/$2.95 price anchors front and center. That part works.
- What doesn't work is everything that follows. Below the car scent hero, this email crams in at least four distinct promotional blocks: hand sanitizers at $1, foaming soaps at $3.50 (a "Starts Today!" — which is today's *other* B&BW email), a Halloween fall candle section ("Cast a Spell on Your Senses"), and a "Summer Sale 75% off" module. Summer Sale and Fall Escape are running side-by-side in the same email in mid-July. The mixed signals aren't just aesthetically cluttered — they actively undermine urgency. If everything is on sale always, "final hours" means nothing.
- This is a solid car-scent closer dragged down by being weaponized as a campaign dump. The subject deserved a tighter send.

## What's working

- The hero is on-brief: "Final Hours" + "Your Fall Escape Awaits" + $1.95 price anchor visible above the fold, directly matching the subject.
- $1.95 entry price is a genuinely low anchor — hard to miss and hard to dismiss for a B&BW subscriber who buys car fresheners.
- The 🚨 emoji in the subject creates urgency without stacking multiple exclamation points — restrained by B&BW standards.
- "Free shipping with any $50 purchase" is visible in the header and reduces friction for anyone already considering a larger basket.
- The "Buy Online, Pickup in Store Today" callout near the footer adds a same-day fulfillment option that reinforces the urgency of "final hours."

## What's weak

- The email contains at least four separate campaigns (car scents, hand sanitizers/soaps, fall candles, Summer Sale) — there is no single clear offer to act on after the hero.
- "Cast a Spell on Your Senses" Halloween imagery running alongside a "Summer Sale 75% off" module in the same email is temporally incoherent — it's mid-July.
- All three "SHOP" CTAs use identical generic copy with no destination differentiation; there's no primary action hierarchy.
- The "Starts Today!" hand soap block directly overlaps with today's separate Clean Hands Event email — subscribers received both, and the messaging cannibalizes itself.
- The "Top Offers" product grid at the bottom renders at very small scale and individual products are barely distinguishable at inbox reading size.

## Recommendations

- 1. **Cut the email to one campaign.** Car scent final hours only — strip the hand soap, candle, and Summer Sale blocks. The subject earned a focused closer; the multi-campaign body squanders it.
- 2. **Make the CTA specific to destination.** "Shop Car Fresheners" not "SHOP" — and link directly to the car care category, not the homepage.
- 3. **Resolve the summer/fall contradiction.** Either run this as a Summer Sale send or a Fall Escape send. Running both in the same scroll is a credibility hit on both.
- 4. **The "Starts Today!" hand soap block belongs in the Clean Hands Event email, not here.** It appeared in a separate send today already — including it here dilutes both.

## Technical Audit — Bath & Body Works Car Scents Promo (2026-07-17)

### 1. Technical Summary

Standard Salesforce Marketing Cloud (ExactTarget) table-based deployment via `e2.bathandbodyworks.com`. Three substantive issues were found: two broken image nodes (empty `src`), missing `List-Unsubscribe` headers as captured, and unstripped template artifacts leaking internal campaign logic in HTML comments.

---

### 2. Link & Tracking Issues

**24 click-tracking links unprobed.** All CTAs route through `click.e2.bathandbodyworks.com` (SFMC redirect domain), which the QA runner correctly skipped. UTM parameter presence on destination URLs cannot be confirmed from this source alone.

**Second tracking domain detected.** An image tag uses `bbwus.everestengagement.com` as a pixel endpoint:
```
src: https://bbwus.everestengagement.com/ea/fw0q51vctP/?e=200511831233&c=071726_EM_SU_BAU_PROMO_0_NRDM_195CAR295HDEE_FH_BAL_G
```
This is a secondary engagement-tracking vendor (Everest/Validity). The QA system flagged it under "Image missing alt text" because it has no `alt=""`. Not a blocking issue, but alt="" should be set explicitly.

**Open pixel is present** at `https://click.e2.bathandbodyworks.com/open.aspx?PJUBG54H44PENL7LQEIIF2E3PA.70246&d=70246&bmt=0` — standard, no issues.

---

### 3. Rendering & Accessibility

**Two images with empty `src` attributes.** The QA output shows:
```
[WARN] Image missing alt text: : src: 
[WARN] Image missing alt text: : src: 
```
Empty `src` on an `<img>` causes some clients to render a broken-image icon and triggers an unnecessary HTTP request to the page's base URL in others. These nodes need either a valid `src` or removal.

**One content image missing `alt` text:**
```
src: https://image.e2.bathandbodyworks.com/lib/fe9213737561047a72/m/1/418d0db7-5a65-43cb-b5c9-9c6c142e4fd2.png
```
No `alt` attribute present. For a promotional content image this blocks accessibility and will render as a broken description in screen readers.

**Everest pixel image missing `alt=""`** (noted above in §2). Tracking pixels should carry an explicit empty alt: `alt=""`.

**Duplicate `@import` for Google Fonts.** Source+Sans+Pro is imported twice — once in `<head>` (weight 400 only) and again inside the body's `<td>` stylingblock (weights 400 and 700). The in-body `<style>` block is the more complete one; the head import is redundant and adds an extra render-blocking request on clients that support web fonts.

**`<style>` block in `<body>`.** The second font import lives inside a `<td>`, outside `<head>`. Most modern clients handle this, but Gmail strips embedded `<style>` from body content in some rendering contexts; the fallback stack (Arial, Helvetica) will apply there regardless.

**Preheader implementation is correct** — hidden div with entropy-pad characters to prevent body bleedthrough into preview text. No rendering concern.

### 4. Personalization & Merge Tokens

**No unrendered merge tokens exposed** (no `%%FIELD%%` or `{{variable}}` literals in visible output). Good.

**Unstripped shell-command artifact appears twice in HTML comments:**
```html
<!-- `date "+ET%m.%y"` -->
```
This is a backtick-wrapped shell expression that was never executed — it survived into the final send as a literal comment. It exposes internal deployment-date tagging convention and indicates a template preprocessing step was skipped or failed for this field. Not subscriber-visible, but leaks operational metadata to anyone viewing source.

**AMPscript logic comments are present** and unstripped:
```html
<!--Adds daily APT set via ampscript. Adds preset APT for emails flagged NTF-->
<!--Set APT for NTF campaigns, otherwise respect email-defined APT-->
<!--If @NTF_Flag is "N", @APT should be set in the email; no default fallback here-->
<!--Set variables to support dynamic template attributes-->
```
These expose internal segmentation variable names (`@NTF_Flag`, `@APT`) and campaign logic. Not harmful in isolation, but constitutes unnecessary information disclosure and should be stripped at send time.

**Content Builder slot commented out** rather than populated:
```html
<!-- <div data-type="slot" data-key="gvhu7dvhmx9" data-label="Preheader"></div> -->
```
The preheader was hardcoded inline instead of using the slot. Functionally equivalent but breaks template modularity — if the slot system is in use elsewhere in this template, this inconsistency creates maintenance risk.

### 5. Compliance

**`List-Unsubscribe` header absent as captured** (QA WARN). This may be an AgentMail relay capture artifact — SFMC routinely injects this header at the MTA level, so it may be present in actual delivery but not in the relay capture. Needs verification against a raw message received in a test inbox (e.g., check headers in Gmail "Show original").

**`List-Unsubscribe-Post` (RFC 8058) absent as captured.** Same caveat as above. Without this header, Gmail and Apple Mail cannot offer one-click unsubscribe in their UI, which is a Google Bulk Sender requirement for senders at Bath & Body Works' volume (>5k/day). Needs the same verification step.

**SPF/DKIM status unknown** — `Authentication-Results` not captured by relay. Given the sender's volume, these are almost certainly configured; confirm via test inbox "Show original."

**Unsubscribe link in body** — the HTML is truncated before the footer, so the mandatory CAN-SPAM unsubscribe link and physical address cannot be confirmed from this source. Assumed present based on SFMC defaults; should be verified in full render.
