# ✍️ ends today: back-to-school essentials.
**Score:** 7/10 · **Type:** Email audit · **2026-07-19**
## Executive summary

- This email has one job-wrecking problem: the subject line promises "back-to-school essentials" and the email body delivers none of it. What opens is The Clean Hands Event ($1/$2 soaps), car candles at $10, and a 75% Summer Sale — legitimate B&BW offers, but zero back-to-school framing anywhere in the visible render. A subscriber who opened expecting dorm-ready hand sanitizers, mini soaps, or a school-kit bundle will scan for two seconds, find nothing that matches, and leave. That's not a small miss — it's the entire email's credibility problem.
- Strip that away and you have a reasonably well-constructed multi-offer digest. The Clean Hands Event hero is clean and price-forward ($1 at the top), the ENDS TODAY car candle section adds urgency, and the 75% Summer Sale star badge is bold. The issue is that three separate event sections compete for the same CTA real estate, and none of them delivers what the subject promised.
- The cadence context makes this worse. This is B&BW's third email pushing the Clean Hands Event (audited July 17 at 8/10, then again July 18 as part of the $5.95 body care cycle). The subject-line pivot to "back-to-school" looks like an attempt to reframe the same content as fresh — and it backfires.

## What's working

- **The Clean Hands Event hero is price-forward and above the fold.** $1 and $2 price anchors are visible immediately without scrolling.
- **"ENDS TODAY!" is visually prominent in the car candle section.** High-contrast dark section with bold all-caps creates real urgency.
- **75% Summer Sale badge is eye-catching.** The starburst graphic stops the scroll and communicates scale.
- **Rewards/loyalty entry point is present in the header.** Members know their account is in play.
- **No render bugs.** Images load, text renders cleanly, no layout breaks.

## What's weak

- **Subject line/body mismatch is a bait-and-switch.** "Back-to-school essentials" appears nowhere in the email render. This is the single largest failure.
- **Three competing hero sections dilute each other.** Clean Hands Event, car candles ENDS TODAY, and 75% Summer Sale all fight for first click — none wins.
- **The 75% Summer Sale is buried third.** That's the most compelling offer in the email and it appears after two full event sections.
- **"SHOP" is the only CTA copy.** No verb+noun specificity — "Shop Hand Soaps," "Shop Car Scents," "Shop the Sale" would each convert better than a generic button.
- **Third Clean Hands Event email in three days.** The July 17 launch (8/10) and July 18 body care send already hit this same event. Fatigue is real.

## Recommendations

- 1. **Fix the subject/body alignment — pick one.** Either rewrite the body to actually feature back-to-school bundles (travel minis, hand soaps for dorm, etc.) or kill the back-to-school subject and lead with the 75% Summer Sale, which is the strongest and most honest hook in this email.
- 2. **Elevate the 75% Summer Sale to hero position.** Move it above the Clean Hands Event. A 75% sale is a stronger opener than a $1 soap — it sets the frame before the specifics.
- 3. **Differentiate the CTA copy per section.** "Shop Hand Soaps" / "Shop Car Scents" / "Shop the Sale" each drive category-specific clicks and reduce cognitive load.
- 4. **Rest the Clean Hands Event.** Three emails in three days on the same event is enough. Let it close and reset.

- **Preheader Alt B:** `Clean Hands Event + Summer Sale both closing tonight.`

### 3. Rendering & Accessibility

**Content rendered before `<body>` opens (structural bug):**
A `<table>` wrapping the preheader block appears in the HTML *after* `</head>` but *before* `<body>`. Browsers will auto-correct this, but Outlook and some legacy clients may drop or duplicate the node:
```html
</head>
<table ... class="stylingblock-content-wrapper"> <!-- ← outside <body> -->
  ...
</table>
<body ...>
```

**Two `<img>` tags with empty `src` (broken image bug):**
```
[WARN] Image missing alt text: : src: (×2)
```
Empty `src` causes a same-page HTTP request in some clients and renders as a broken image. These appear to be unfilled template slots.

**Five images missing `alt` text on non-decorative assets:**
- `6a2a21c2c28dcea9.png` — `mi.bathandbodyworks.com` (likely promo creative)
- `418d0db7-5a65-43cb-b5c9-9c6c142e4fd2.png` — `image.e2.bathandbodyworks.com`
- `bbwus.everestengagement.com/ea/fw0q51vctP/` — Everest tracker image
- Two empty-src images above

Missing `alt` breaks screen readers and displays nothing when images are blocked (common in Outlook by default).

**Duplicate Google Fonts import:** `@import url('https://fonts.googleapis.com/css2?family=Source+Sans+Pro...')` appears twice — once in `<head>` and once inside a `<td>` style block in the body. Redundant and may cause a double render-blocking request in some clients.

**`<style>` block inside `<td>`:** A second `<style>` element is injected mid-body inside a table cell. Technically invalid HTML4 and ignored by some clients (Gmail strips `<style>` in body on non-AMP sends).

---

### 4. Personalization & Merge Tokens

**Unresolved shell command tokens (template rendering failure):**
```html
<!-- `date "+ET%m.%y"` -->
```
This appears *twice* in the rendered HTML. The backtick expression was not evaluated — it should have resolved to something like `ET07.26`. The literal text is visible in view-source and signals a broken build step.

**AMPscript logic exposed in comments:**
```html
<!--Adds daily APT set via ampscript. Adds preset APT for emails flagged NTF-->
<!--Set APT for NTF campaigns, otherwise respect email-defined APT-->
<!--If @NTF_Flag is "N", @APT should be set in the email; no default fallback here-->
```
Internal audience-segmentation variables (`@NTF_Flag`, `@APT`) are leaked in HTML source. Not a security risk, but exposes platform logic to any recipient who views source.

**Commented-out slot tag** — `<!-- <div data-type="slot" data-key="gvhu7dvhmx9" data-label="Preheader"></div> -->` is an inert template artifact left in the send. No functional impact.
