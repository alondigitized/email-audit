## What's working

- **Subject-to-hero alignment is crisp**: "dive in" 🌊 → poolside illustration → "Swim Up to Happy Hour" → Wallflowers refills. The creative chain holds.
- **Price is the first thing you read**: $3.95 badge is prominently placed in the hero, no hunting required.
- **"3 DAYS ONLY" urgency marker** is visible without scrolling — creates clear temporal framing.
- **Secondary offer is cleanly tiered**: "2 for $16" body sprays sit below the hero without fighting for lead position.
- **Render is clean**: no broken images, overlapping text, or missing placeholders visible anywhere.

## What's weak

- **"SHOP" CTA is lazy**: both hero and secondary CTAs say only "SHOP" — no product noun, no verb pull. Compare to the May 23 "clean up with this deal" send which had tighter copy throughout.
- **Cadence fatigue is real**: this is email six in roughly five days; "starts now" urgency is undercut when the subscriber already knows another deal is coming tomorrow.
- **"Swim Up to Happy Hour" is clever, not clear**: the tagline is fun but doesn't immediately signal home fragrance — a first-time opener might think body care or candles are the hero.
- **TOP OFFERS grid is very small**: four tiny thumbnail icons ("Fragrance, Skin Care, Candles, Wallflowers") are hard to parse and dilute focus from the lead offer.

- 1. **Replace "SHOP" with product-specific CTA copy** — "SHOP WALLFLOWERS" or "GRAB $3.95 REFILLS" would connect subject line price promise directly to the click. This is the single highest-lift change.
- 2. **Pin the deadline to a calendar day** — "3 DAYS ONLY" is vague; "Ends Thursday night" gives the subscriber something to act against.
- 3. **Add a product noun to the hero tagline** — something like "Swim Up to Happy Hour — Refills at $3.95" removes ambiguity about what the deal is.
- 4. **Shrink or remove the TOP OFFERS grid** — four tiny tiles below two hero offers splits attention without adding meaningful clickable surface.
- 5. **Consider a rest day** — the May 23–25 sprint was dense; a breather before the next launch would make "starts now" feel fresher.

---

### 3. Rendering & Accessibility

**[Critical] Table element placed before `<body>`** — the preheader slot wrapper `<table class="stylingblock-content-wrapper">` is rendered between `</head>` and `<body>` in the document flow. Most email clients recover via error correction, but it is malformed HTML and can produce phantom whitespace or broken rendering in strict parsers (some older Outlook builds, Lotus Notes).

```html
</head>
<!-- template comments -->
<table ... class="stylingblock-content-wrapper">  ← outside <body>
  <tr><td><!--Set variables...--></td></tr>
</table>
<body ...>
```

**[High] `<meta charset>` declared last in `<head>`** — `<meta http-equiv="Content-Type" content="text/html; charset=utf-8">` appears after `<style>` blocks. Per HTML spec and email client best practices, charset declaration must be the first element in `<head>` to prevent character misinterpretation before the parser reaches it.

**[High] Three images missing alt text** (QA confirmed):
- `418d0db7-5a65-43cb-b5c9-9c6c142e4fd2.png` — `src: https://image.e2.bathandbodyworks.com/lib/fe9213737561047a72/m/1/418d0db7-5a65-43cb-b5c9-9c6c142e4fd2.png`
- Two additional images with **empty `src` attributes** — these will render as broken image icons in clients that don't suppress them, and contribute accessibility failures under WCAG 2.1 §1.1.1.

**Preheader padding block** — the invisible character-stuffing block (`&#847; &zwnj;` repeated ~100×) inside `display:none` is technically correct for preview text clipping, but the volume is unusually high. No functional issue, but it will inflate HTML payload size.

---

### 4. Personalization & Merge Tokens

**[High] AMPscript logic comments leaking into final HTML** — three internal template comments are present verbatim in the sent email:

```html
<!--Adds daily APT set via ampscript. Adds preset APT for emails flagged NTF-->
<!--Set APT for NTF campaigns, otherwise respect email-defined APT-->
<!--If @NTF_Flag is "N", @APT should be set in the email; no default fallback here-->
```

These expose internal variable names (`@NTF_Flag`, `@APT`), campaign segmentation logic, and the absence of a fallback — a minor information disclosure and a sign that template cleanup is incomplete. They should be removed from the production send template.

**Shell timestamp comment** — `<!-- \`date "+ET%m.%y"\` -->` appears twice. This looks like an un-evaluated shell substitution from a build script; it is inert but indicates a broken template stamping step.

No unresolved merge tokens (e.g., `%%variable%%` placeholders) detected in the truncated source.

### 5. Compliance

**[High] `List-Unsubscribe` header absent** — QA: `[WARN] List-Unsubscribe header not found`. RFC 2369 mandates this header for bulk email. Its absence means Gmail, Outlook, and Apple Mail cannot surface the native unsubscribe UI, increasing spam-report risk. Note: QA caveat states this may be a relay capture gap, not a true absence — but it must be confirmed at the MTA level.

**[High] `List-Unsubscribe-Post` header absent** — QA: `[WARN] List-Unsubscribe-Post header not found (RFC 8058)`. Google and Yahoo's 2024 bulk sender requirements mandate one-click unsubscribe. Missing this header is a deliverability compliance violation for high-volume senders.

**[Medium] SPF/DKIM authentication unverifiable** — QA: `Authentication-Results` header not captured via AgentMail relay. Sending domain is `e2.bathandbodyworks.com` (ExactTarget/SFMC subdomain); authentication is expected to pass for a sender of this scale, but it cannot be confirmed from available headers.

**CAN-SPAM physical address** — not visible in the truncated source. Should be confirmed present in the email footer (standard for BBW; likely present in untruncated HTML).
