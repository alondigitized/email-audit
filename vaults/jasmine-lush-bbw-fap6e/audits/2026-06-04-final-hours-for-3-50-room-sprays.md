# final hours ⏱️ for $3.50 room sprays.
**Score:** 8/10 · **Type:** Email audit · **2026-06-04**
## Executive summary

- This is Bath & Body Works' second email of June 4 — the morning send ("🤩 $3.50 room sprays—today only," 9/10) opened the arc; this one is the closing bell. The "FINAL HOURS" red banner and $3.50 price badge execute the urgency above the fold cleanly, and the "Spritz of the Bright Side" summer headline with citrus imagery is solid. That's where the discipline ends.
- Below the hero, a blue "Feels Like a Sweet Time" section pushes a separate product at $14, then a "TOP OFFERS" grid fragments the email into a mini-catalog. Closing-bell emails have one job — convert the people who opened the morning send but didn't click. Splitting that into three competing offers is the same mistake as the May 31 single-wick "last day" send (6/10), which coasted on repetition rather than tightening the close.
- Verdict: the hero executes; the body diffuses. A one-offer version of this email would be meaningfully more effective.

## What's working

- "FINAL HOURS" banner lands before the hero copy — urgency is established at first glance, no scrolling required.
- $3.50 price badge is front-and-center in the hero; lowest-barrier impulse trigger in the B&BW playbook.
- "Spritz of the Bright Side" is punchy summer copy — light, seasonal, fits the citrus visual.
- Clean render throughout — no broken images, no text overlap, no layout bugs.
- 100% Guarantee section at the bottom quietly reduces purchase hesitation for fence-sitters.
- Blue "Feels Like a Sweet Time" section pushes a different product at $14 immediately below the hero — splits focus at exactly the moment the close should be tightening.
- "TOP OFFERS" grid turns the bottom half into a catalog, bleeding off urgency with more SKUs to evaluate.
- "Final hours" is vague — no specific end time (midnight? 11:59 PM ET?) makes the urgency feel soft vs. the "ENDS TODAY!" clarity B&BW used on June 1–3.
- This is the second email today; cadence risk is real. The subscriber who didn't click the morning send was either not interested or distracted — hitting them again with the same offer in a noisier email is not the right reactivation.
- No visible countdown timer or explicit deadline time reinforcement in the hero copy.

## Recommendations

- 1. **Cut the blue secondary section.** One job: room sprays. The $14 offer belongs in tomorrow's arc opener, not competing for scrolling attention here.
- 2. **Pin an explicit deadline to the hero.** "Final hours" → "Ends tonight at midnight." Specific times convert better than vague windows.
- 3. **Rewrite the hero CTA button.** "SHOP" is wasted real estate — "Shop Room Sprays" or "Get $3.50 Sprays" earns the specificity the price badge already sets up.
- 4. **Replace the TOP OFFERS grid with a single scent-count line.** "Choose from 20+ scents — all $3.50" preserves depth without catalog fragmentation.

- **Subject Alt B:** `$3.50 room sprays: your last chance tonight.`

### 1. Technical Summary

The email renders from a Salesforce Marketing Cloud (SFMC) template with standard table-based layout and Outlook conditional comments. Two confirmed template pre-processing failures (unrendered shell commands left in comments) and four accessibility violations were identified; compliance headers are unverifiable through the AgentMail relay.

### 2. Link & Tracking Issues

**25 CTAs unverifiable.** All click-throughs route through `click.e2.bathandbodyworks.com` redirect. UTM parameters on destination URLs cannot be confirmed without resolving the redirect chain. QA skipped all 25.

**Open pixel exposes list/subscriber token in path:**
```
https://click.e2.bathandbodyworks.com/open.aspx?BHK35Y5LYNNEPI7ULDJ4BQN6TM.70247&d=70247&bmt=0
```
The token `BHK35Y5LYNNEPI7ULDJ4BQN6TM` is visible in the URL path as a query string fragment before `&d=`. No immediate exploitability, but it confirms list/subscriber identity in plaintext.

**Secondary tracking pixel via Everest/Zeta Global** — exposes internal campaign naming convention in `src`:
```
https://bbwus.everestengagement.com/ea/fw0q51vctP/?e=200511831233&c=060426_RDMFH_CRS_350CRSEE_NS_BAL_V6
```
The `c=` value (`060426_RDMFH_CRS_350CRSEE_NS_BAL_V6`) encodes the campaign code and date in the pixel request. Also missing `alt` attribute (see §3).

### 3. Rendering & Accessibility

**4 images confirmed missing `alt` text (QA):**

| Image | Issue |
|---|---|
| `418d0db7-5a65-43cb-b5c9-9c6c142e4fd2.png` | Non-decorative product image, no `alt` |
| 2 `<img>` tags with empty `src=""` | Broken references + no `alt` |
| Everest pixel (`bbwus.everestengagement.com`) | Tracking pixel, should have `alt=""` |

**Two `<img src="">` (empty src) tags** will cause some email clients (notably Outlook) to fire a GET request against the email's base URL. These should be removed or the src populated.

**Google Fonts `@import` using deprecated font name:**
```css
@import url('https://fonts.googleapis.com/css2?family=Source+Sans+Pro&display=swap');
```
`Source Sans Pro` was renamed `Source Sans 3` on Google Fonts. The legacy name may redirect or return 404 silently. Fallback (`Arial, Helvetica`) kicks in for all desktop clients anyway (Outlook ignores `@import`), but the stale reference should be updated.

**`<meta charset>` placement** — the `Content-Type` meta tag is declared after the Outlook `<!--[if gte mso 9]>` conditional block rather than as the first element in `<head>`. Minor, but charset should be declared before any conditional rendering.

---

### 4. Personalization & Merge Tokens

**Two unrendered shell date interpolations** — identical, appearing in the `<head>` comment block:
```html
<!-- `date "+ET%m.%y"` -->
```
The backtick shell syntax was not processed by the build pipeline before send. No subscriber data leaked, but this confirms a broken pre-send template step that fired silently.

**AMPscript implementation comments exposed in production HTML:**
```html
<!--Adds daily APT set via ampscript. Adds preset APT for emails flagged NTF-->
<!--Set APT for NTF campaigns, otherwise respect email-defined APT-->
<!--If @NTF_Flag is "N", @APT should be set in the email; no default fallback here-->
```
These leak internal campaign logic: APT variable behavior and NTF (New-To-File) flag handling. Should be stripped at build time.

**Empty SFMC content slot coexists with hardcoded preheader:**
```html
<div data-type="slot" data-key="gvhu7dvhmx9" data-label="Preheader"></div>
```
The slot is unpopulated; the actual preheader is hardcoded in a separate hidden `<div>`. The vestigial slot was not cleaned before send.

### 5. Compliance

| Header | Status | Risk |
|---|---|---|
| `List-Unsubscribe` | Not captured (QA WARN) | Gmail/Apple Mail will not render unsubscribe UI chrome |
| `List-Unsubscribe-Post` (RFC 8058) | Not captured (QA WARN) | One-click unsubscribe absent; required for Google's bulk sender policy (>5K/day) |
| `Authentication-Results` | Not captured (QA WARN) | SPF/DKIM/DMARC alignment for `e2.bathandbodyworks.com` unverifiable via relay |

The `List-Unsubscribe-Post` gap is the highest-risk finding: Google's February 2024 bulk sender requirements mandate RFC 8058 one-click unsubscribe for high-volume senders. Absence can affect inbox placement. It is unclear whether these headers are absent from the send or stripped by the AgentMail relay — that distinction needs to be confirmed at the ESP level.

CAN-SPAM physical address and unsubscribe link were not visible in the truncated source; assumed present in footer — **unverified due to truncation**.
