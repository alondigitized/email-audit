# it's glow time—$10 single wicks start ✨now.✨
**Score:** 9/10 · **Type:** Email audit · **2026-06-01**
## Executive summary

- Bath & Body Works opens a new single-wick arc on June 1, cleanly pivoting off the $12.95 3-wick run that closed out May 28–31. The "STARTS TODAY!" teal banner leads, "Coastal Mood Lighting" headlines the collection, and the "$10" price badge for all single wicks is immediately visible — structurally, this is the same launch playbook they ran on May 28 for the 3-wick arc (which earned a 9/10). The colorful summer candle product shot is seasonally sharp and the message is unambiguous.
- The gap is urgency. May 28 had a closing bell coming — today's email is a pure launch with no visible end date. "STARTS TODAY!" tells you when it began, not when it ends. That's a weaker pull than the clockwork "ENDS TODAY!" banners from the May 28–30 run. The secondary "Now serving: Scents of the Summer" block below the hero also dilutes focus — it's a generic magazine spread that doesn't add to the $10 single-wick argument.
- Overall: a clean, seasonally correct launch email that earns high scores on clarity and offer prominence but leaves urgency and CTA specificity on the table.

## What's working

- "STARTS TODAY!" banner + "$10" price badge read instantly — offer is above the fold and unambiguous.
- "Coastal Mood Lighting" is a credible June 1 seasonal hook that distinguishes this from the May 3-wick and sanitizer arcs.
- Clean arc pivot — new product category (single wick), new price ($10), fresh creative after three rounds of 3-wick sends.
- Multiple colorful candle SKUs in the hero communicate collection depth without clutter.
- "TOP OFFERS / TODAY'S DEALS" category grid extends discovery without stepping on the hero offer.

## What's weak

- No end date anywhere — "STARTS TODAY!" creates a launch moment but zero closing urgency.
- "SHOP" CTA is a dead end — a generic verb with no noun; contrast with "Shop $10 Single Wicks" which would reinforce the offer in the action.
- The "Now serving: Scents of the Summer" secondary module is visually rich but message-generic — it splits the email's focus from a single $10 offer into a broad summer catalog tease.
- Fine print block at the bottom is dense; whether the $10 applies to every single wick or has exclusions is not clarified above the fold.

## Recommendations

- 1. **Add a closing deadline to the banner.** Change "STARTS TODAY!" to "STARTS TODAY · Ends Sunday" (or whatever the real end date is). The May 28 arc built its urgency across three days of escalating closing-bell emails — start that arc with a visible runway.
- 2. **Rewrite the CTA.** "SHOP" → "Shop $10 Single Wicks" or "Get Mine for $10." Specificity in the CTA reinforces the offer at the moment of decision.
- 3. **Remove or compress the "Now serving: Scents of the Summer" module.** If it must stay, make it a slim row below the hero, not a competing full-width section.
- 4. **Surface one hero SKU with a name.** The product grid is colorful but anonymous. Name one candle in the hero ("Oceanside Lemon" or whatever anchors the coastal story) to make the collection feel discoverable rather than generic.

## Technical Audit — Bath & Body Works "$10 Single Wicks" (2026-06-01)

### 1. Technical Summary

The email is a standard Salesforce Marketing Cloud (SFMC) deployment with Movable Ink and Everest engagement tracking. No critical failures, but there are three confirmable markup errors, two accessibility gaps, and compliance headers that could not be verified through the relay.

### 2. Link & Tracking Issues

**Open-pixel present and functional:**
```

```
Rendered as a `width="1" height="1"` `<img>` inside a `display:none` / `mso-hide:all` table — correct pattern.

**Everest engagement pixel:**

Expected for MI personalisation; `mi_u` is subscriber ID. No issue beyond the missing `alt`.

---

### 3. Rendering & Accessibility

**Two tables rendered outside `<body>`** — the preheader spacer table and the open-pixel table both appear between `</head>` and `<body>` in source order:

```html
</head>
<!-- comment -->
<table ...><!-- preheader --></table>
<table ...><!-- open pixel --></table>
<body style="...">
```

Most email clients recover silently via quirks-mode parsing, but strict renderers (some versions of Outlook, Apple Mail with certain security settings) may drop or reorder these elements. This is a template authoring bug.

**Two images with empty `src` attributes** — QA found two `<img>` tags with no `src` value at all. These will render as broken-image placeholders in clients that show them (Gmail mobile, Outlook 365):

```
[WARN] Image missing alt text: : src: (×2)
```
Both also lack `alt` text, so screen readers get nothing.

**Three additional images missing `alt` text:**
| Image | Domain |
|---|---|
| `d3caeb897c1a2826.png` | `mi.bathandbodyworks.com` (Movable Ink) |
| `418d0db7-5a65-43cb-b5c9-9c6c142e4fd2.png` | `image.e2.bathandbodyworks.com` |
| Everest engagement pixel | `bbwus.everestengagement.com` |

Tracking pixels should carry `alt=""` explicitly; content images should carry descriptive alt text for screen readers and image-off rendering.

**`<meta http-equiv="Content-Type">` placement** — declared after `<style>` and MSO conditionals inside `<head>`. Should be the first tag in `<head>` to guarantee charset declaration before any content is parsed. Not a live breakage in tested clients but technically incorrect.

**Legacy DOCTYPE** — `HTML 4.01 Transitional` is standard for email and not a defect.

**Preheader filler block** — the Unicode entity padding (`&#847; &zwnj;` etc.) is present and correctly hidden (`display:none; max-height:0; overflow:hidden`). No issue.

---

### 4. Personalization & Merge Tokens

**Unresolved date macro in HTML comments (×2):**
```html
<!-- `date "+ET%m.%y"` -->
```
Appears twice in source as a literal string. This looks like a shell-style template placeholder that was never evaluated by the build pipeline. It does not affect rendering (it is inside an HTML comment), but suggests the template versioning/date-stamp macro failed to execute before send.

**AMPscript logic comments leaked into delivered source:**
```html
<!--Adds daily APT set via ampscript. Adds preset APT for emails flagged NTF-->
<!--Set APT for NTF campaigns, otherwise respect email-defined APT-->
<!--If @NTF_Flag is "N", @APT should be set in the email; no default fallback here-->
```
These are visible in raw source to any subscriber who views source. They expose internal campaign logic (APT = Audience Preference Token, NTF = New-to-File flag). Not exploitable, but information disclosure that is typically stripped in production builds.

**No unresolved merge token syntax** (`%%variable%%`, `{{variable}}`) visible in the truncated source. Subscriber ID `200511831233` is correctly resolved in tracking URLs.
