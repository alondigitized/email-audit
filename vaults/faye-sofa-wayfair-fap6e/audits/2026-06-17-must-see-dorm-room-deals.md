# 👀 MUST-SEE DORM ROOM DEALS 👀
**Score:** 5/10 · **Type:** Email audit · **2026-06-17**
## Executive summary

- Wayfair is doing the same subject-body mismatch it pulled June 17 with "Area Rugs from our Exclusive Brands" (4/10) — the subject promises a focused "DORM ROOM DEALS" send, but the body delivers the same DEAL WEEK multi-category scatter chassis: bedding, chairs, rugs, storage, bed frames, repeat. The dorm angle is entirely cosmetic. There's no "dorm room" hero header, no dedicated category section, no move-in narrative — just the same grid of 40–50% off tiles that's been running for two weeks.
- The timing makes it worse. June 17 is 6–8 weeks before dorm move-in peaks. Even an actual student subscriber is unlikely to be in shopping mode. For an adult consumer, the prompt is irrelevant from the subject line.
- The email renders cleanly and the discounts are real, but Wayfair continues to reach for a seasonal hook without doing the actual targeting work. At this cadence (six-plus emails in five days), this one reads as noise.

## What's working

- 40% OFF and 35% OFF are visible in the hero without scrolling — the discount is instantly legible.
- Star ratings are present on product tiles in the "picked just for you" grid — passive social proof at no cost.
- No render bugs: the layout holds, images load, the branded header is clean.
- Wayfair Rewards strip appears in the footer — loyalty reinforcement for members who notice it.

## What's weak

- Subject-body mismatch: "DORM ROOM DEALS" appears nowhere in visible body copy or section headers.
- Scatter chassis undercuts the promise — 5+ unrelated product categories with no dorm narrative thread.
- ALL CAPS subject + double 👀 bookends reads as shouting in an already crowded inbox after 6+ recent sends.
- June 17 is too early — dorm shopping peaks late July/August; the hook doesn't land yet.
- No visible urgency mechanism — "MUST-SEE" is empty filler with no deadline, countdown, or stock signal.

## Recommendations

- 1. **Build the actual dorm email.** Add a "Dorm Room Essentials" section header, link to a dorm category page, and limit the grid to items that belong in a 12×12 room. The products are there — the positioning isn't.
- 2. **Put the discount in the subject.** "Up to 50% off" is visible in the body; surface it in the subject line to earn the open.
- 3. **Drop ALL CAPS.** Title case consistently outperforms shouting, especially with a subscriber base that's already seen 6 caps-heavy subject lines this week.
- 4. **Anchor to move-in day.** "Move-in is 7 weeks out — stock up now" is real urgency. "MUST-SEE" is not.

### 3. Rendering & Accessibility

**Gmail strips `<head>` styles entirely.**
All responsive rules (every `@media only screen` block) and the `@font-face` declaration live in `<head><style>`. Gmail's CSS inliner discards these, meaning:
- No mobile breakpoints fire in Gmail (web and Android app), serving all subscribers a desktop-width layout.
- `Sofia` font never loads in Gmail regardless of WOFF availability.

The `mso-font-alt: "Arial"` fallback is correctly set, so Outlook degrades safely. Gmail gets system-default sans-serif — acceptable but unintentional.

**Fixed-height containers will clip dynamic content.**
At `max-width: 480px`:
```css
.ProductRec-name  { height: 48px !important }
.ProductRec-price { height: 40px; vertical-align: top }
.ProductRec-salesCopy { height: 28px; vertical-align: top }
.ProductRec-stars, .ProductRec-shippingCopy { height: 16px }
```
Any product name or price string longer than the fixed height is silently cropped — no `overflow: hidden` paired with `text-overflow: ellipsis` to signal truncation.

**`word-break: break-all` on `.ProductRec-name`.**
This breaks mid-character, not mid-word. A 12-character product name can render as `Desk Or`/`ganizer` across two lines. `word-break: break-word` or `overflow-wrap: break-word` is the correct cross-client value here.

**Custom font loaded over HTTP CDN — no HTTPS enforcement risk.**
`src: url(https://secure.img.wfrcdn.com/st4/stores/common/fonts/sofia/sofia_reg.woff)` — URL is HTTPS, so no mixed-content issue. Font domain is a Wayfair-controlled CDN; not an external dependency risk.
