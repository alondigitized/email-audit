- The email then loses focus. A Keurig "Big Help. Small Price Tags." block comes next, then a "fresh-picked favorites" grid of sconces, tables, chairs and sectionals. ## What's working

- The subject names a specific product and size ("10' X 10' PERGOLAS"), which is a strong segmentation cue.
- The first tile echoes the subject's wording, so the click path is clear.
- The "70% OFF" and "48-hour clearance" banner gives one concrete, time-bound offer.
- Star ratings under the "fresh-picked favorites" products add some social proof.
- The Wayfair header and consistent purple styling make the brand instantly recognizable.

## What's weak

- The pergola tile is tiny and shares the grid with unrelated categories. The "48 HR" graphic dominates instead.
- The large empty white block near the bottom looks like a broken or missing module.
- No prices or discounts appear on any product tile, so "70% OFF" is never tied to a pergola.
- The Keurig block, the refrigerator guide and the general product grid dilute the pergola focus.
- The creative and offer repeat the 2026-10-17 pergola and clearance sends, so the cadence feels stale.

## Recommendations

- 1. Make the hero a pergola hero. Use one large 10' x 10' pergola image with a "from $X, up to 70% off" line and a "Shop 10' x 10' Pergolas" button. Move the generic clearance banner below it.
- 2. Replace the mixed "must-shop steals" grid with four pergola and gazebo products. Each gets a price, a was/now price, and a rating.
- 3. Fix or remove the empty white module. Cut the Keurig and refrigerator blocks from a pergola-triggered send.
- 4. Add the deadline text ("Ends Sunday midnight") next to the hero so the 48-hour urgency attaches to pergolas.
- 5. Change the send cadence or creative. Don't send another pergola email with the same layout the day after the last one.

## Technical Audit

## 1. Technical Summary
The email's markup is a standard responsive table layout with consistent per-link tracking parameters. Its main technical problems are missing alt text on content and star-rating images, 20 plain-`http://` tracking pixels, and one image URL with an invalid percent-escape. The compliance headers could not be verified.

## 2. Link & Tracking Issues
- **Link health is unconfirmed, not broken.** Eight probed links returned HTTP 429 (rate limiting), including `/daily-sales`, `/`, the pergola event page and the app OneLink URL. None returned a 4xx or 5xx error, so I'm not flagging them as defects. Wayfair's servers are throttling the probe.
- **Four links were not probed** because the 70s budget ran out. They are kitchen-sinks, washable-rugs, small-kitchen-appliances and one `wayfair.com/?_emr=…` link. Their status is unknown.
- **The OneLink fallback is not HTTPS.** The app link (`wayfairapp.onelink.me/2420802157`) sets `af_web_dp=http%3A%2F%2Fwww.wayfair.com%2Fthe-wayfair-app`. Users without the app land on an `http://` URL and depend on a redirect to HTTPS.
- **One image URL has an invalid percent-escape.** `0728_Outd%oorClearance_SkinnyHero-VP.jpg` contains `%oo`, which is not valid percent-encoding (it should be `%6F%6F` or a plain `oo`). Depending on how the CDN decodes it, this image may fail to load or return a 404. The filename also starts with `0728`, so it looks like a reused asset. QA reported no HTTP result for it, so this is a risk rather than a confirmed break.
- **The two OneLink URLs for "Get Exclusive Deals on the App" are the same except for `_eml`.** This is expected per-link tokenization. No issue.

## 3. Rendering & Accessibility
- **Content images lack alt text.** The affected images are:
  - `48HR-Clearance_Spring2026_SkinnyHero-VP.png`
  - `wfus_batchheaderrevamp_event_top_3_purple.png`
  - `small_appliances_01_gif.gif`
  - `email-sku-headers_test-09.jpg`
  - `wfus_jt800_batch9_seo_appliances_fridgedimensions_…`
  - `0728_Outd%oorClearance_SkinnyHero-VP.jpg`

  Several of these are the only content inside an `<a>`. QA's link text for them is `[image: <filename>]`, so the link's accessible name is the filename. That affects images-off clients and screen readers.
- **Review-star images have no alt text.** `stars_10.png` and `stars_11.png` appear 8 times in total (under `secure.img.wfrcdn.com/.../review_stars/`). The rating is not available to assistive tech.
- **Tracking pixels have no alt text.** `b.php` is the open pixel at `t.wayfair.com`, and there are 20 `li.wayfair.com/imp?s=1241260xx` pixels. A missing `alt` attribute is the main cost here. Use `alt=""` and `role="presentation"` or `aria-hidden="true"` so they are skipped rather than announced.
- **20 ad-impression pixels use `http://`.** They run from `li.wayfair.com/imp?s=124126000` through `124126019`. Clients that block mixed content will drop them, which under-counts impressions. They also add 20 extra requests.
- **`<html>` has no `lang` attribute.** The source shows `<html xmlns="http://www.w3.org/1999/xhtml">`, which hurts screen-reader pronunciation.
- No other rendering issues are visible. The source includes a mobile media query at 480px and the Gmail `u ~ div` and `u + .Gmail` fixes. The HTML was truncated, so the body table structure and `<title>` were not reviewed.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens (`{{…}}`, `%%…%%`, `[[…]]`) appear in the visible source, subject or QA data. Per-recipient identifiers (`_emr`, `_eml`, `mdlid`) are populated.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Unverified, not confirmed defects.** QA reports `List-Unsubscribe`, `List-Unsubscribe-Post` (RFC 8058) and `Authentication-Results` as not found, and notes the AgentMail relay may strip them. SPF, DKIM and DMARC status is unknown.
- **The body unsubscribe link and physical postal address could not be confirmed** because the HTML was truncated. QA says an unsubscribe link was always included in probing, but no result was reported for it.
- Sender is `editor@members.wayfair.com`, a dedicated sending subdomain. Nothing else is observable.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **No `utm_*` parameters.** Links use a proprietary scheme: `source=graymatter_batch`, `batchid=15`, `varid=7`, `csnid=…`, `sltid`, `refid=MKTEML_121688`, `emlid=101`, `maiid=16440`, `mdlid`. This is consistent across all links, but analytics that expect `utm_source`, `utm_medium` and `utm_campaign` won't attribute these without custom mapping.
- **Landing alignment is good.** The subject ("10' X 10' PERGOLAS") matches the module link `/daily-sales/filters/10%27-x-10%27-pergolas-just-for-you-se71596.html?eid=428543`. `unifiedeventid=428543` matches `eid`.
- **The apostrophe in the pergola URL is encoded** as `%27`, which is correct.
- **`sltid` varies by placement:** 2 for the logo and "Shop Sale", 5 for the hero and 6 for the event tiles. This gives per-slot click attribution.

## 7. Recommendations
1. Add descriptive `alt` text to the content images and the star ratings (for example `alt="4.5 out of 5 stars"`). Set `alt=""` on all 21 tracking and impression pixels.
2. Serve the 20 `li.wayfair.com/imp` pixels over HTTPS.
3. Fix or re-export `0728_Outd%oorClearance_SkinnyHero-VP.jpg` so its URL contains no invalid percent-escape, then confirm it returns 200.
4. Change `af_web_dp` in the OneLink URL to `https://www.wayfair.com/the-wayfair-app`.
5. Add `lang="en"` to `<html>`.
6. Verify the raw `.eml` headers (`List-Unsubscribe`, `List-Unsubscribe-Post`, `Authentication-Results`, DKIM signature) from the original message, not the relay copy.
7. Re-probe the 8 rate-limited and 4 unprobed links with slower pacing. Also re-check the unsubscribe link and footer address in the untruncated HTML.
8. If cross-channel reporting matters, map the `graymatter_batch` parameters to `utm_*` in analytics.
