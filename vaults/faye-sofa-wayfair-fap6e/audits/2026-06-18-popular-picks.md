# Popular Picks
**Score:** 7/10 · **Type:** Email audit · **2026-06-18**
## Executive summary

- "Popular Picks" is the most anonymous subject line Wayfair has sent in this entire stretch — 13 characters, zero offer, zero product category, zero urgency. That's a problem because the email itself is actually one of the more interesting ones in the June batch: it opens with a "LAST CALL" hero on a mint shag rug, delivers a "Popular Picks" product carousel, and then adds a "Sales You 'Almost' Missed" retargeting section that implies browsed-but-not-bought products. That last section is the most sophisticated thing Wayfair has tried in this whole cadence and they buried it under a subject line that reads like a placeholder.
- The body chassis is familiar — multi-category scatter (hammock, TV consoles, bedroom furniture, area rugs, mattresses) with the persistent Wayfair Rewards footer strip — but the "Almost Missed" framing adds a personalization layer missing from every prior send this week. It's not the June 16 "Backyard party?" editorial moment (the 7/10 standout in brand history), but it's a notch above the pure-blast sends.
- The verdict: interesting concept, catastrophically undersold in the envelope. A subscriber scanning their inbox at 7am sees "Popular Picks" from Wayfair and mentally files it next to every other undifferentiated promo they've received. The click potential is there; the open is the casualty.

## What's working

- **"Sales You 'Almost' Missed" section** is the sharpest creative move in this June batch — framing it as a recovery moment rather than another product dump implies behavioral targeting and creates mild FOMO.
- **Hero image lands well** — the mint green shag rug is high-contrast and eye-catching; visual hierarchy from top to first CTA is clean.
- **"LAST CALL" badge** provides the urgency the subject line refuses to deliver; at least it's there once you open.
- **Star ratings visible** in the product grid add credibility at the browse stage.
- **No render bugs** — images load, layout holds, no overlapping elements or lorem ipsum.

## What's weak

- **"Popular Picks" subject is the weakest envelope in this entire June cadence** — no product, no offer, no urgency, nothing to differentiate from the daily blast noise.
- **Same multi-category scatter chassis** (outdoor, living room, bedroom, rugs, mattresses) that's run every day this week; Wayfair has not rotated the structural approach beyond the June 16 editorial pivot.
- **No explicit discount percentage or dollar amount** visible in the hero or Popular Picks section — "LAST CALL" without a stated savings figure reduces urgency to decoration.
- **"Shop All Picks for You" CTA is generic** — "All Picks" points to a catch-all destination rather than a targeted category page, diluting click intent.
- **Wayfair Rewards strip buried in footer** — member pricing or points-on-purchase should be in the hero if they want it to move behavior.

## Recommendations

- 1. **Lead the subject with the "Almost Missed" hook** — that's the most novel idea in the email; put it in the envelope where it can actually drive opens. Something like "You almost bought this" or "Still thinking about these?" would outperform "Popular Picks" by a wide margin.
- 2. **Attach a concrete discount to the hero** — "LAST CALL" floating over a rug with no stated savings is empty urgency. Add "Up to 60% off" or the specific rug price prominently.
- 3. **Split the "Sales You 'Almost' Missed" section into its own dedicated send** — retargeting deserves its own subject line and a tighter body, not a scroll-buried section in a scatter email.
- 4. **Replace "Shop All Picks for You" with a category-specific CTA** ("Shop Rugs," "Shop Outdoor") — any specificity lifts CTR on these multi-product emails.
- 5. **Surface Wayfair Rewards above the fold** if this is a member send — the loyalty strip in the footer goes unseen on mobile.
- **Subject Alt A:** `You almost bought this — still interested?`
- **Subject Alt B:** `Last call: the rug (and 3 others) you saved`
- **Preheader Alt A:** `These picks from your recent browsing are going fast.`
- **Preheader Alt B:** `Up to 60% off items you already loved. Today only.`

### 2. Link & Tracking Issues

**Cannot fully assess** — HTML is truncated before the body links appear. From the visible source:

- No UTM parameters or redirect/tracking URLs are visible in the `<head>` portion, which is expected.
- External resource load: `https://secure.img.wfrcdn.com/st4/stores/common/fonts/sofia/sofia_reg.woff` — this is the only `<link>`-equivalent in the visible fragment. If this CDN is down at render time, no fallback URL is referenced.

---

### 3. Rendering & Accessibility

**Three confirmed issues:**

**a) `@font-face` Sofia with incomplete fallback**
```css
@font-face {
  font-family: "Sofia";
  src: url(https://secure.img.wfrcdn.com/st4/stores/common/fonts/sofia/sofia_reg.woff) format("woff");
  mso-font-alt: "Arial"
}
```
`mso-font-alt` is Outlook-only. No `font-family` stack fallback is declared in the `@font-face` block itself. Gmail, Yahoo, and iOS Mail will silently drop to the client default (typically serif) unless a fallback is set on each text element inline.

**b) Fixed heights on product name/price cells will clip content**
```css
.ProductRec-name { height: 48px !important }
.ProductRec-price { height: 40px; vertical-align: top }
.ProductRec-salesCopy { height: 28px; vertical-align: top }
.ProductRec-stars, .ProductRec-shippingCopy { height: 16px }
```
These are applied at `max-width: 480px`. Any product name longer than ~2 lines at mobile font size will be hard-clipped. `overflow: hidden` is already set on `.ProductRec-name`, confirming intentional clipping — but with `word-break: break-all` (see below), this becomes destructive.

**c) `word-break: break-all` on `.ProductRec-name`**
```css
.ProductRec-name { word-break: break-all; overflow: hidden; display: block; height: 48px !important }
```
`break-all` breaks at any character boundary including mid-word. Combined with the fixed 48px height and `overflow: hidden`, this means the last visible "word" in a product name may be a dangling character fragment. `word-break: break-word` or `overflow-wrap: break-word` would be safer.

**d) Duplicate media query blocks**
The `<style>` block repeats individual `@media only screen and (max-width: 480px)` wrappers for each button variant class (`.u-Button`, `.u-Button--primary`, `.u-Button--transactional`, `.u-Button--alternate`) rather than grouping selectors. Functionally identical, but the generated code pattern suggests a template loop bug — each variant is being output as its own block instead of a single grouped selector. This adds ~300 bytes of unnecessary CSS.
