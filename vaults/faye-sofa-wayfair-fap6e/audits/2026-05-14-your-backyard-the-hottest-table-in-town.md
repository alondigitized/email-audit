# Your backyard = the hottest table in town 😎 🍽️
**Score:** 9/10 · **Type:** Email audit · **2026-05-14**
## Executive summary

- Wayfair lands a well-structured outdoor entertaining send timed perfectly for mid-May. The hero is clean, the promo code (`OUTDOOR10`, $10 off $100+) is surfaced immediately, and the category flow — glassware → kitchen tools → grills → dining sets — has a logical purchasing journey behind it. This is competent category email marketing.
- The subject, however, does almost none of the heavy lifting the body deserves. "Hottest table in town" is a fun phrase but tells you nothing about price, product, or offer — it reads more like a tagline than a reason to open. The email earns its clicks once opened; it doesn't earn the open itself.
- The rug section at the bottom breaks the thematic thread. Someone browsing charcoal grills and dining sets doesn't pivot naturally to decorative mats — it reads like a "fill the template" decision, not an editorial one.

## What's working

- **Promo code in the hero badge** — `OUTDOOR10` with the $10/$100 threshold is front and center; no hunting required.
- **Strong category ladder** — entertaining glassware → outdoor kitchen → grills → dining sets is a coherent path from impulse to considered purchase.
- **Prices in every product tile** — the "$379.99" on grills and equivalent on dining sets let you window-shop without clicking.
- **"Shop Outdoor Dining Essentials" CTA** — verb + specific noun, not the lazy "Explore" or "Discover."
- **Season timing** — mid-May is peak outdoor setup intent; this send is on calendar.

## What's weak

- **No expiration on `OUTDOOR10`** — a promo code with no visible deadline removes all urgency from the offer.
- **Rug section at the bottom** — off-theme for an outdoor dining send; dilutes the editorial focus.
- **No social proof anywhere** — not a single review count, star rating, or "X people bought this" signal across every product tile.
- **Zero personalization** — the copy treats every recipient identically; no "back for summer" hook, no purchase-history nod, nothing member-specific despite coming from `members.wayfair.com`.
- **"Try this in your space" is text-only** — the AR feature is a genuine differentiator but the section shows no visual proof of it working; it's easy to scroll past.

## Recommendations

- 1. **Add a deadline to `OUTDOOR10`** — "Ends Sunday" or "48 hours only" in the hero badge would transform this from a passive discount into an action trigger. Single highest-leverage change.
- 2. **Rewrite the subject to carry the offer** — the body has a real offer; the subject line doesn't mention it. Move the code or the $10 signal into the subject directly.
- 3. **Cut or relocate the rug section** — either drop it from this send or replace it with a "complete the look" outdoor rug tie-in that's framed as dining-adjacent, not a separate category dump.
- 4. **Add star ratings to product tiles** — even "4.7 ★ (2,341)" on the top grill would sharply lift click confidence.
- 5. **Show the AR feature in action** — swap the "Try this in your space" text block for a before/after GIF or lifestyle screenshot of a dining set placed in a real backyard.

### 3. Rendering & Accessibility

**Media query breakpoint at 480px** is below the viewport width of many current flagship phones (e.g., iPhone 15 Pro Max renders at 430pt; many Android flagships exceed 480px). The `u ~ div { min-width: 100vw }` Gmail hack is correct but only compensates for Gmail's specific clipping behavior — it does not substitute for a wider breakpoint.

**`<style>` block in `<head>` only.** Gmail (webmail), Yahoo, and older Android clients strip `<head>` styles. All layout-critical properties (widths, display, padding) must also be present as inline `style=""` attributes. The utility class system (`.u-FullWidth`, `.u-HalfWidth`, etc.) is invisible to those clients unless duplicated inline.

**`.u-MobileHide { display: none !important }`** — suppressing content via media query is unreliable in clients that ignore `<style>` blocks. If hidden content is decorative, acceptable. If it hides functional copy or CTA fallbacks, this is a rendering risk.

**Alt text** — cannot verify from truncated HTML. All `<img>` tags must carry descriptive `alt` attributes; images-off rendering (common in Outlook) will show blank boxes otherwise.

**`@supports (-webkit-touch-callout: none)` block** used to target iOS Safari specifically for `.u-HalfWidthBlock img` — this is a recognized workaround and is correct, but should be tested against iOS 17+ where rendering behavior changed.
