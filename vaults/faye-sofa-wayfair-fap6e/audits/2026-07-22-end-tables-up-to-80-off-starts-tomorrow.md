# END TABLES  🚩 UP TO 80% OFF starts TOMORROW 🚩  
**Score:** 8/10 · **Type:** Email audit · **2026-07-22**
## Executive summary

- Wayfair is doing the same thing it did with "Inside: CORDLESS VACUUMS" on July 20 — the subject promises a specific category (end tables, up to 80% off) and the body delivers something else entirely (a grid of rugs, kitchen mats, and home textiles). The only end-table content is a small hero banner at the top that teases the deal "starts TOMORROW," which means the featured product isn't even available yet. The bulk of the email is a "deals of the day" rug carousel that has nothing to do with why you opened.
- The underlying logic is understandable: use a high-discount category as a subject hook to drive opens, then fill the body with today's live offers. But the execution leaves subscribers who opened for end tables staring at area rugs with no path to the product they came for. This is a trust withdrawal.
- Compared to the July 20 NIGHTSTANDS email (8/10), which actually delivered furniture content and a clear event window, this one squanders the same Black Friday in July scaffolding with a tease-and-fill structure that feels like a mismatch. Wayfair has the creative muscle to execute this better; this send is lazy deployment of a working formula.

## What's working

- **The hero percentage is unmissable.** "80% OFF" rendered in a bold circular badge grabs the eye immediately at the top — the discount signal lands before anything else.
- **"Starts TOMORROW" creates legitimate anticipation.** Unlike the "FREE shipping all day every day" zombie sends from July 18–21, this gives the subscriber a reason to check back — there's an actual upcoming event.
- **"24 HOURS ONLY" in the body creates a secondary urgency layer.** Even if it's for rugs, the time-bound framing keeps the email from feeling static.
- **No render bugs.** Product images load, layout is clean, prices are legible on item tiles.

## What's weak

- **Subject promises end tables; body delivers zero end tables.** The featured product appears only in the tease hero — you can't browse or buy end tables from this email.
- **"Deals of the day" CTA is category-agnostic.** The button doesn't say "Shop End Tables" or even "Shop Black Friday in July" — it dumps the subscriber into a generic deals page.
- **Rug-heavy body is a non sequitur.** Kitchen mats and area rugs following an end-table hook feel like unsold inventory filler, not a curated send.
- **Flag emoji spam in the subject.** 🚩🚩 flanking the subject line reads as a spam pattern in many inbox previews and ages the creative immediately.
- **No direct link to the upcoming end table sale page.** If tomorrow's event is real, give me a "Preview the sale" anchor — a wasted conversion moment.

## Recommendations

- 1. **Put end tables in the body.** If the sale starts tomorrow, show 4–6 end table products at the "starting at $X" price with a "Sale begins 7/23" overlay. Let me see what I'm waiting for. This single change fixes the subject-body contract.
- 2. **Replace the generic CTA.** "Shop End Tables" or "Preview Black Friday in July" beats "deals of the day" every time for a subscriber who opened on a furniture promise.
- 3. **Drop the flag emojis.** The NIGHTSTANDS email used ⚫ to create visual separation cleanly — 🚩 reads as warning/spam in the subject. Swap for a minimal separator or nothing.
- 4. **Add a countdown.** "Sale starts in 18 hours" paired with a preview of the end table assortment would make this a strong anticipation email rather than a filler send.
- **Subject Alt A:** `End Tables: 80% off starts tomorrow — preview the picks`
- **Subject Alt B:** `Black Friday in July preview: End Tables up to 80% off`
- **Preheader Alt A:** `The sale opens at midnight — here's what's going fast.`
- **Preheader Alt B:** `End tables, ottomans, and accent pieces — deals go live July 23.`

---

### 3. Rendering & Accessibility

**Web font — incomplete fallback stack**
```css
@font-face {
  font-family: "Sofia";
  src: url(https://secure.img.wfrcdn.com/.../sofia_reg.woff) format("woff");
  mso-font-alt: "Arial"
}
```
- Only `woff` format declared; no `woff2`. Minor load-time inefficiency where fonts do render.
- `mso-font-alt` covers Outlook, but no CSS `font-family` stack fallback (e.g., `font-family: "Sofia", Arial, sans-serif`) is visible in the truncated source. Gmail, Yahoo, and all webmail clients silently drop `@font-face` — if body text elements aren't specifying a system fallback inline, those clients render the browser default serif.

**Aggressive word-break on product names**
```css
.ProductRec-name { word-break: break-all; }
```
`break-all` splits at any character boundary, including mid-word (e.g., "round" → "rou-nd"). Should be `overflow-wrap: break-word` or `word-break: break-word`.

**Fixed pixel heights on dynamic content**
```css
.ProductRec-price { height: 40px; }
.ProductRec-salesCopy { height: 28px; }
.ProductRec-stars, .ProductRec-shippingCopy { height: 16px; }
```
Fixed heights at the 480px breakpoint will clip content if rendered text exceeds the allocated height — particularly risky for sale copy with longer strings or if font scaling increases on accessibility-configured devices.

**HTML size risk**
The CSS block alone is already very large before the body starts. If the full HTML exceeds **102KB**, Gmail clips the email with a "View entire message" prompt, suppressing the unsubscribe footer and any below-the-fold CTAs. Verify compiled size.
