# More flowers, more wow—on us
**Score:** 8/10 · **Type:** Email audit · **2026-06-16**
## Executive summary

- This is the seventh Double Blooms execution from 1-800-Flowers in 28 days — following May 19, May 27, June 2, June 10, June 13, and June 15. The creative is essentially unchanged: hero arrangement flanked by "DOUBLE" block typography, a $44 anchor price, three sub-hero color variants (yellow, pink, purple), and a "SHOP NOW" button. Versus the June 15 "Beat the heat with free flowers" send, the only meaningful delta is the subject line and a minor headline tweak.
- The render itself is clean — no broken images, clear pricing, a readable 20% off code for best sellers. But the more interesting offer (20% off best sellers, with an explicit code) is buried below three rows of $44 Double Blooms product, which by week four is the staler pitch. The stronger incentive is playing second fiddle to the exhausted one.
- "On us" in the subject implies something is free. Nothing is free. That's the single most damaging decision in this send — it undermines trust at the moment of highest leverage.

## What's working

- $44 price point is visible in the hero and repeated consistently across all three color variants — no price hunting required.
- "SHOP NOW" button renders cleanly in a contrasting green immediately above the fold.
- Three color variants give choice without decision paralysis.
- 20% off code is present and legible below the hero — a genuine secondary incentive.
- "Shop by Category" grid at the bottom is comprehensive and well-organized; useful fallback for a subscriber not ready to buy flowers today.

## What's weak

- "On us" in the subject is misleading — you're paying $44 for the arrangement; nothing is comped. This is bait language.
- Seventh identical Double Blooms creative in 28 days; this template has no new visual, no lifestyle context, no creative variation to earn another open.
- The 20% off best sellers offer — which is a stronger, fresher incentive — is sequenced below three repetitive $44 hero units.
- No urgency signal visible anywhere: no deadline, no countdown, no "ends tonight" language.
- "More wow" is inert filler copy with no informational content.

## Recommendations

- 1. **Lead the hero with the 20% off code, relegate Double Blooms to secondary.** The 2X mechanic is at maximum fatigue; 20% off best sellers is concrete and actionable for in-market subscribers. Flip the hierarchy.
- 2. **Add a deadline.** "Offer ends Sunday" or a 48-hour window transforms a passive browse into a decision. Nothing in this render creates a reason to act today over next week.
- 3. **Retire or meaningfully refresh the Double Blooms creative.** Swap product-only photography for a lifestyle shot — someone receiving the arrangement, a dining table setup, anything with human context — if you're going to run this mechanic an eighth time.
- 4. **Fix "on us."** If nothing is free, don't say "on us." Either make something actually free (a small gift, a card, free delivery) or drop the phrase entirely.

- **Subject Alt B:** `Double the blooms, 20% off this week`
- **Preheader Alt A:** `Use code BLOOMS — plus pick your color: yellow, pink, or purple`
- **Preheader Alt B:** `Best sellers on sale + Double Blooms still going — offer ends Sunday`

### 3. Rendering & Accessibility

**Missing `lang` attribute on `<html>`:**
```html
<html xmlns="..." xmlns:v="..." xmlns:o="...">
```
No `lang="en"` — required for screen readers and client-side accessibility tree construction.

**Mobile breakpoint is 418 px, not the standard 480 px:**
```css
@media only screen and (max-width: 418px)
```
Devices with viewport widths between 419–479 px (e.g., iPhone SE portrait in some browsers) receive no responsive overrides — layout will overflow or collapse unintentionally.

**Redundant duplicate media query:**
```css
@media only screen and (min-width: 768px) { img {max-width:640px} }
@media only screen and (min-width: 640px) { img {max-width:640px} }
```
Both rules set the same declaration. The `768px` rule is dead code — the `640px` rule always fires first and wins on any 640px+ viewport.

**`line-height:100%` global reset:**
```css
* { line-height:100% }
```
Applied universally, this causes text clipping on descenders and oversized fonts in Gmail and Outlook 2019+. Should be scoped to structural containers, not the universal selector.

**`.woff` instead of `.woff2` for Playfair Display 900 weight:**
```css
src:url(https://fonts.gstatic.com/s/playfairdisplay/v22/...btM.woff) format('woff');
```
All other variants load `.woff2`. The weight-900 italic fallback increases payload by ~30% and is inconsistent with sibling declarations.

**`mso-font-alt` missing on all Lato `@font-face` blocks:**
Playfair Display correctly declares `mso-font-alt:'Times New Roman'`. None of the six Lato variants include an `mso-font-alt`, so Outlook will substitute its default font (Calibri or Times) rather than a controlled fallback.

**Alt text on images:** Cannot assess — HTML truncated before `<body>`. This is a required check; images without `alt` attributes fail WCAG 1.1.1 and render as broken icons in image-blocked clients.
