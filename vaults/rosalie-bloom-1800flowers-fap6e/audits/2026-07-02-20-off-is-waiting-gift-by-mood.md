# 20% off is waiting — gift by mood 🎨
**Score:** 7/10 · **Type:** Email audit · **2026-07-02**
## Executive summary

- 1-800-Flowers makes a smart creative pivot here: the last week has been wall-to-wall patriotic red-white-and-blue (June 29 "America is turning 250!" at 8/10, July 1 "Save Up to 25% 🎆" at 8/10), and this send breaks the pattern entirely by reframing flowers as a mood-matching gift system. "Show Your True Colors" is a clever double entendre — it ties colors to emotional intention, which is a genuinely differentiated way to browse. The 20% off discount anchors it with hard value before the creative concept does any heavy lifting.
- The execution is clean: seven color-mood pairings (Vibrant Red, Orange Energy, Sunny Yellow, Green With Gratitude, Blue Skies Ahead, Ultra Lavender, Pretty in Pink) each get their own bouquet photo and a SHOP NOW button, turning one email into seven curated entry points. The visual hierarchy is strong — discount banner → "Show Your True Colors" hero → color grid → category grid → footer. Nothing is fighting for attention.
- The main weakness is timing friction. Subscribers who just saw 25% off for July 4th will immediately clock that this is 20% off — a slight step down in discount depth — with no seasonal rationale. "Gift by mood" is evergreen creative, but landing it the day after July 4th with a lesser discount makes it feel like the holiday sale is ending, not a fresh reason to buy.

## What's working

- **Creative reset is well-executed** — mood/color conceit is genuinely fresh after five days of patriotic creative and breaks inbox fatigue.
- **20% off is prominently displayed** in the top banner with the promo code visible; no hunting required.
- **Seven distinct color-mood sections** multiply click surface area and let different gift occasions self-select without the sender having to name them all.
- **Photography is strong** — each color section has a tight, well-lit arrangement photo that makes the product feel premium.
- **"SHOP BY CATEGORY" footer grid** offers a fallback browsing path for anyone not grabbed by the mood concept.

## What's weak

- **20% vs. yesterday's 25%** — loyal subscribers will notice the step-down in discount depth with no seasonal justification to explain it.
- **No deadline on the 20% off** — every "SHOP NOW" button is evergreen; there's nothing pushing the decision to today.
- **"SHOP NOW" CTA copy is generic across all seven sections** — each color-mood pairing has earned the right to a more specific verb ("Send Red," "Gift Yellow," or even "Shop Vibrant Red").
- **No social proof anywhere** — no star ratings, no "bestseller" badge, no review count; the photography works hard but nothing validates that these specific arrangements are beloved.
- **The mood copy is evocative but occasion-agnostic** — a subscriber trying to solve a specific gifting problem (birthday, sympathy, congrats) doesn't get a hook to their occasion.

## Recommendations

- 1. **Add a hard deadline to the 20% offer** — even "through July 4th weekend" or "ends Sunday" makes this send urgent instead of evergreen. Given yesterday's July 4th discount email, this one needs a reason to exist *today*.
- 2. **Replace "SHOP NOW" with mood-specific CTAs** — "Send Vibrant Red," "Shop Sunny Yellow," etc. Each section already has a name; use it on the button. 15-character CTA improvement that costs zero design work.
- 3. **Drop one color section; add a social proof block** — seven product sections is a lot of scroll depth. Swap one mid-funnel section for a 3-star-review strip or "Over 5M arrangements delivered" trust badge.
- 4. **Tie the color concept to an occasion** — "Feeling grateful? Send Green." or "Their birthday calls for pink." A single parenthetical under each mood name bridges the emotional concept to a real-world trigger.
- 5. **Frame the 20% relative to the July 4th window** — "Last chance at 20% off — the holiday weekend continues" makes the discount feel like an extension, not a retreat.
- **Subject Alt A:** `Show your mood in flowers — 20% off today`
- **Subject Alt B:** `What color are you gifting? 20% off inside`
- **Preheader Alt A:** `Red for passion, yellow for joy, lavender for calm — pick your vibe and save.`
- **Preheader Alt B:** `Seven moods. Seven bouquets. One code: FLOWERPOWER25.`

### 3. Rendering & Accessibility

**`maximum-scale=1` viewport lock — confirmed issue**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents users from pinching to zoom. WCAG 1.4.4 (Resize Text) failure. Remove `maximum-scale=1`.

**Mobile breakpoint targets 418px, not standard 480px — confirmed issue**
```css
@media only screen and (max-width: 418px) { ... }
```
The companion class `.mobile { width:414px !important; }` reveals this is hardcoded to iPhone 6/7/8 physical pixels. Any Android device between 419px–480px receives zero responsive treatment. Standard breakpoint is 480px; the width class should be `100%` rather than a fixed `414px`.

**Redundant `img` max-width media query — confirmed issue**
```css
@media only screen and (min-width: 768px) { img {max-width:640px} }
@media only screen and (min-width: 640px) { img {max-width:640px} }
```
The 768px rule is fully shadowed by the 640px rule — any viewport ≥640px already caps images at 640px, so the 768px block is dead code. Remove it.

**External Google Fonts will not render in most clients — confirmed**
```css
src:url(https://fonts.gstatic.com/s/playfairdisplay/...) format('woff2')
```
Gmail (web + iOS + Android), Outlook (all versions), and Yahoo block or ignore external `@font-face` `src:url()` references. The `mso-font-alt:'Times New Roman'` fallback on Playfair is present on three of five `@font-face` declarations but **missing** on the Playfair Display italic weight-900 variant — that instance will fall back to the client default serif rather than Times New Roman in Outlook.

**`.woff` vs `.woff2` inconsistency — confirmed**
```css
/* weight-900 normal: */
src:url(.../nuFvD-...fsukDT.woff) format('woff');   /* ← .woff */
/* all other weights: */
src:url(...).woff2) format('woff2');                  /* ← .woff2 */
```
The weight-900 upright Playfair loads `.woff` while every other weight loads `.woff2`. `.woff2` is smaller and more widely supported; this is likely a copy-paste error in the template.

**`line-height:100%` global reset — low risk, noted**
```css
* { line-height:100%; }
```
This sets line-height relative to font-size on every element. On elements with large font sizes (headings), `100%` can cause lines to touch or overlap. Not a blocking issue given Outlook's `mso-line-height-rule:exactly` is paired, but worth overriding on text containers explicitly.
