### 3. Rendering & Accessibility

**Confirmed issues:**

**a) `maximum-scale=1` viewport prevents user zoom**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Blocks pinch-to-zoom. Fails WCAG 1.4.4 (Resize Text). Remove `maximum-scale=1`.

**b) Mismatched `@font-face` format for Playfair Display 900 normal**
```css
src:url(https://fonts.gstatic.com/s/playfairdisplay/v22/nuFvD-...ukDT.woff) format('woff');
```
All other `@font-face` declarations use `.woff2`. This entry loads `.woff` only — larger file, slower render. Likely a copy-paste error; should be `.woff2`.

**c) Missing `mso-font-alt` on Playfair Display 900 normal**
The weight-900 normal `@font-face` has no `mso-font-alt:'Times New Roman'` fallback, unlike the other weights. Outlook will substitute its default serif inconsistently.

**d) Redundant `@media` breakpoints**
```css
@media only screen and (min-width: 768px) { img {max-width:640px} }
@media only screen and (min-width: 640px) { img {max-width:640px} }
```
The `768px` rule is fully subsumed by the `640px` rule. Dead code — remove the `768px` block.

**e) `line-height:100%` applied to `*`**
```css
* { line-height:100%; }
```
Aggressive global override. Can collapse line height on multi-line text elements in certain clients. Standard practice is to scope this to `td`, `p`, and specific selectors.

**f) No `role="presentation"` on layout tables** (cannot confirm from truncated HTML — flag for full-source QA)
Layout tables should carry `role="presentation"` for screen reader compatibility.

**g) External Google Fonts blocked by major clients**
`fonts.gstatic.com` URLs are stripped by Gmail (web), Outlook, and Apple Mail's privacy proxy. Fallback fonts (`Times New Roman`) will render instead. This is expected behavior but confirm the fallback renders acceptably.
