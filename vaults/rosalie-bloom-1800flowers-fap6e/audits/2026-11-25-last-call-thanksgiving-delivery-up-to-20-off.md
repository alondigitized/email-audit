# Last Call: Thanksgiving Delivery + Up To 20% OFF
**Score:** 7/10 · **Type:** Email audit · **2026-11-25**
## Executive summary

- This is a clean, seasonal last-call send. The burnt-orange hero, script "Thanksgiving" and sunflower bouquet carry the Thanksgiving feel well. The offer sits in a thin olive bar at the very top ("UP TO 20% OFF* WITH CODE FLOWERSALE"). The hero itself leads with delivery urgency: "Don't wait until the turkey's in the oven. If you need it there tomorrow, order right now!" The single yellow SHOP NOW button is easy to find.
- The body is where it loses steam. "Gifts Delivered Today" shows four products with no prices, no ratings and no individual links I can tell are product-specific. The nine-tile category grid below it (Birthday, Romance, Sympathy and so on) is generic catalog navigation that dilutes the last-call urgency. Compared with 11/24's "Save Up to 20% OFF + Guaranteed Thanksgiving Delivery", this is nearly the same creative one day later, and the subject is a little more urgent.
- Verdict: a competent, on-brand send that's well-timed but unremarkable. The urgency message is right and the execution after the hero is padded. Expect it to do its job, not to stand out.

## What's working

- The hero is warm and seasonal, and the bouquet photo is vivid and appetizing.
- The urgency copy is concrete and conversational ("If you need it there tomorrow, order right now!").
- One yellow SHOP NOW button contrasts strongly with the red hero.
- The code FLOWERSALE is in the top banner, so the offer is visible immediately.
- The four product shots in "Gifts Delivered Today" are on theme (fall bouquets, turkey strawberries) and well-photographed.

## What's weak

- The "Up to 20%" tiers aren't explained. There's no spend threshold, and the asterisk fine print is at the bottom, which feels vague next to the 11/20 send's clear $149/$99/$69 tiers.
- The product tiles have no prices, no names linking to a deal, and no reviews or social proof.
- The nine-tile "Shop by Category" grid, with Sympathy, Romance and Greeting Cards, pulls attention away from the Thanksgiving last-call purpose.
- The code is only in the small top bar, not on the hero or the button, so the discount is easy to miss.
- The footer is cramped, with tiny legal text and a dense wine disclaimer.

## Recommendations

- 1. Put the offer and code in the hero: a "Code FLOWERSALE" pill next to the SHOP NOW button, plus a "Order by [time] for delivery tomorrow" deadline so the urgency has a credible cutoff.
- 2. Cut the category grid to three or four tiles that match the "delivered today" message (Same-Day, Fall, Best Sellers, Gourmet).
- 3. Add prices, a "Same-Day" badge and star ratings to the four product tiles.
- 4. Show the spend tiers (e.g. $149+ = 20%) in the body instead of leaving them behind the asterisk.
- 5. Lead the subject with the deadline, and use the preheader for the code and cutoff.
- **Subject Alt A:** `Order by 2pm for Thanksgiving delivery tomorrow`
- **Subject Alt B:** `Last chance: fresh fall bouquets, 20% off`
- **Preheader Alt A:** `Use code FLOWERSALE on same-day fall bouquets and gourmet gifts.`
- **Preheader Alt B:** `Still time to send Thanksgiving flowers. Save up to 20% today.`

## Technical Audit

## 1. Technical Summary
The HTML is a table-based XHTML 1.0 Transitional layout with dark-mode meta tags and responsive media queries. The visible problems are a tracking pixel stack with missing alt text and plain-HTTP image sources. The compliance and authentication findings can't be confirmed, because the headers weren't captured and the HTML source was truncated.

## 2. Link & Tracking Issues
- **Click-tracking links not probed:** 20 tracking/redirect links were skipped by the QA HTTP probe, so destination validity and redirect chains are unverified.
- **Multiple third-party pixels:** The email loads at least five separate tracking beacons:
  - `http://view.atdmt.com/FLO/view/361227669/direct/01/` (Atlas/Microsoft)
  - `http://pixel.mathtag.com/event/img?mt_id=155437&mt_adid=103507&v1=&v2=&v3=&s1=&s2=&s3=` and `...mt_id=155438...` (MediaMath)
  - `https://bounceexchange.com/tag/em/1622.gif`, which appears twice
  - `https://click.dv.1800flowers.com/o/443d6e8a-...` and `https://mi.1800flowers.com/p/up/ada90b86b2846dd9/o.gif?...` (first-party open pixels)
- **Empty macro parameters:** The mathtag URLs have empty `v1=&v2=&v3=&s1=&s2=&s3=` values. Either the placeholders were never populated or they are unused. Empty query fields add no tracking value.
- **Duplicate beacon:** `bounceexchange.com/tag/em/1622.gif` is included twice, which may double-count events.

## 3. Rendering & Accessibility
- **Missing alt text:** 6 images have no alt attribute, so screen readers may announce the raw URLs. These are tracking pixels, so the fix is `alt=""` (plus `width="1" height="1"` if not already set):
  - `view.atdmt.com/FLO/view/361227669/direct/01/`
  - both `pixel.mathtag.com` pixels
  - both `bounceexchange.com/.../1622.gif` instances
  - `click.dv.1800flowers.com/o/443d6e8a-...`
  - `mi.1800flowers.com/.../o.gif`
- **Insecure image sources:** `http://view.atdmt.com/...` and both `http://pixel.mathtag.com/...` URLs use plain HTTP. Gmail's image proxy typically rewrites these, but other clients may block them or show mixed-content warnings. The affected pixels may then silently fail to fire.
- **Dark-mode declarations:** `color-scheme` and `supported-color-schemes` are declared in both the `<meta>` tags and `:root`. No issue found, but dark-mode rendering wasn't verified from the truncated source.
- **Global `* {line-height:100%}`:** This universal selector may cause unexpected line-height overrides. It is minor and not confirmed to cause a defect.

- **`List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058):** Both are reported as not found. The QA tool notes the AgentMail relay may strip them, so this is **not confirmed** as a sender defect. Verify against the raw message at the origin.
- **Physical address:** The QA check flagged none, but the HTML provided is truncated before the footer. This is **unconfirmed**. Check the full source for the postal address.
- **`Authentication-Results`:** Not present, which is expected via the relay, so SPF/DKIM/DMARC status is unknown. The sending domain `em.1800flowers.com` is a dedicated subdomain, which is consistent with good practice, but alignment can't be verified here.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)

- The 20 click-tracking links were not resolved, so the final landing URLs, UTM parameters and landing page match with the "Thanksgiving Delivery / Up to 20% off" offer are **unverified**.

## 7. Recommendations
1. Add `alt=""` to all six pixel images, and set explicit `width="1" height="1"` and `style="display:block"` as appropriate.
2. Switch `view.atdmt.com` and `pixel.mathtag.com` to HTTPS, or confirm the vendors support it. Otherwise drop the pixels, since legacy Atlas and MediaMath beacons are likely obsolete.
3. Remove the duplicate `bounceexchange.com/tag/em/1622.gif` pixel and the empty `v1`–`s3` parameters from the mathtag URLs.
4. Re-run QA against the full raw message, with the original headers and an untruncated footer. This would confirm the `List-Unsubscribe` and `List-Unsubscribe-Post` headers, the physical address, and SPF/DKIM/DMARC.
