# Don’t Miss It—Double Blooms for Birthdays 🎉
**Score:** 7/10 · **Type:** Email audit · **2026-06-20**
## Executive summary

- This is the eighth Double Blooms execution from 1-800-Flowers in roughly 30 days — following May 19, May 27, June 2, June 10, June 13, June 15, and June 16. The birthday pivot ("More Birthday Magic") is the creative delta here, swapping the generic occasion framing for a specific gifting moment. It's a thin strategic move: the layout, badge system, and product grid are lifted unchanged from the last several sends. For a subscriber who has been receiving these, the inbox fatigue is real before they even open.
- Inside the email, the offer stack is objectively strong — the $20 off + 2X blooms badges appear on four distinct arrangements, and a secondary "20% off best sellers" block with a coupon code gives a second reason to buy. The birthday occasion is reinforced throughout. But the multi-product grid (Carnivore Blooms, Red Roses, orange roses, Vibrant Blooms) creates a browsing experience rather than a decisive one, and the "Shop by Category" tile section underneath makes this feel like a homepage dump more than a curated occasion email.
- Clear verdict: above-average production quality and a solid offer, but the cadence has eroded whatever urgency these sends once carried. The birthday framing is the right instinct — they just need to commit to it harder with a single hero SKU rather than four.

## What's working

- **Occasion focus is the right call.** "More Birthday Magic" gives this iteration a clearer occasion hook than the generic "More flowers, more wow" from June 16.
- **Triple-stacked offer is visible at a glance.** The $20 badge + 2X visual badge + 20% off code section gives three distinct value signals without feeling confusing.
- **Product names are visible.** Carnivore Blooms, Red Roses, Vibrant Blooms are named, which is a step above anonymous arrangement photos.
- **"Join the Celebration" loyalty block.** A tangible membership CTA with an app-download prompt toward the bottom — useful acquisition tool for non-members.

## What's weak

- **The 8th Double Blooms send in 30 days has burned down subscriber goodwill.** The template is unchanged; birthday copy is a thin coat of paint.
- **No single hero SKU.** Four arrangements compete equally — no hierarchy tells you what to actually buy for a birthday.
- **"Don't Miss It" urgency is unearned.** There is no deadline, no expiry date, no inventory signal — the urgency phrase is hollow.
- **"Shop by Category" block undercuts the occasion story.** Dropping a browse grid into a birthday email fragments the experience and makes it feel like a catalogue.
- **No price anchor shown.** The $20 off is visible but the original price is not, making the discount hard to evaluate.

## Recommendations

- 1. **Pick one hero birthday arrangement and name it.** Drop the four-product grid down to a single featured SKU with a price, the discount struck through, and one large CTA. Add "ships by [date]" for birthday gifting confidence.
- 2. **Kill "Don't Miss It" in the subject.** Replace with a real urgency signal — a date, a stock level, or a delivery window — or drop it entirely. Vague FOMO is transparent.
- 3. **Remove the "Shop by Category" tiles.** They dilute the birthday narrative. If category browsing must stay, move it below the fold after the primary CTA.
- 4. **Surface a delivery guarantee.** "Order by [date] for same-day delivery" would convert more birthday buyers than a browse grid.
- 5. **Vary the template.** Seven sends of the same Double Blooms layout before this one means this email is invisible to a significant portion of the list. Even a color palette shift or a video thumbnail would break the visual association.
- **Subject Alt A:** `Birthday flowers, doubled — for $20 off`
- **Subject Alt B:** `Same-day birthday blooms, doubled up`
- **Preheader Alt A:** `Pick one arrangement — we'll double it. Order by tonight for delivery tomorrow.`
- **Preheader Alt B:** `Four birthday arrangements, all 2X blooms, all $20 off. One belongs at their party.`

### 3. Rendering & Accessibility

**`maximum-scale=1` in viewport meta — confirmed issue:**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />
```
Prevents user-initiated pinch-zoom. Fails WCAG 1.4.4 (Resize Text, Level AA). Should be removed or changed to `maximum-scale=5`.

**Lato `@font-face` blocks lack `mso-font-alt` fallback:**
Playfair Display declarations correctly include `mso-font-alt:'Times New Roman'`, but none of the six Lato `@font-face` blocks do:
```css
/* Playfair — has fallback */
mso-font-alt:'Times New Roman';

/* Lato — no fallback declared */
src:url(https://fonts.gstatic.com/s/lato/v17/S6uyw4BMUTPHvxw.woff2) ...
```
Outlook on Windows will ignore the web font; without `mso-font-alt`, it falls back to Outlook's default (Calibri), which may break intended font sizing.

**Playfair Display weight:900 uses `.woff` not `.woff2`:**
```css
/* All other weights */
format('woff2')
/* Weight 900 only */
format('woff') ← older format, larger file
```
Minor but inconsistent. `.woff2` should be used for consistency and compression.

**Redundant media queries — same rule declared twice:**
```css
@media only screen and (min-width: 768px) { img {max-width:640px} }
@media only screen and (min-width: 640px) { img {max-width:640px} }
```
640px range is fully contained within 768px+. The 768px block is dead code. Keep only the 640px breakpoint.

**Mobile breakpoint at 418px is outdated:**
```css
@media only screen and (max-width: 418px) { .mobile {width:414px !important;} }
```
414px targets iPhone 6/7/8 (2016 era). Current small phones (iPhone SE 3rd gen, Android baseline) use 375–390px logical width. Content in the 375–417px range won't receive these mobile overrides.

**`supported-color-schemes` in CSS `:root` is not a valid CSS property:**
```css
:root { color-scheme:light dark; supported-color-schemes:light dark; }
```
`supported-color-schemes` belongs only in the `<meta>` tag (where it is correctly placed). The CSS declaration is silently ignored but adds noise.

**`.appleLinks` override removes affordance on auto-detected links:**
```css
.appleLinks a { color:#000000 !important; text-decoration:none !important; }
```
iOS Mail auto-detects phone numbers and addresses as links. This rule makes them visually identical to surrounding body text, which may confuse users who expect them to be tappable.
