# Gift Luxuriously This Fall ✨ 🎁 💐 🍬 ✨
**Score:** 6/10 · **Type:** Email audit · **2026-10-08**
## Executive summary

- This is a clean, editorial gift guide with a real offer, 20% off with code GLOW20, in a thin banner above the logo. The "Gifts That Say Fall Luxury" script headline gives it a premium feel. The numbered 1–5 layout, with alternating image and text, is easy to scan and makes the email read like a curated list.
- The email doesn't show what any of the five products cost or what the discount is worth on them. The code sits in a thin banner and doesn't appear again. "SHOP LUXE" is a plain underlined text link, not a button. The deadline (10/18) only appears in the fine print at the bottom. The offer is the one thing that would push someone to buy now, and it's the easiest part to miss.
- This follows the pattern of this week's sends: 20% off GLOW20 on 10/1, 25% off GLOW25 on 10/7, and a new theme each day. The creative is better than the 10/6 "Free Vase" email, which promised something it didn't deliver. But the five-emoji subject line and the near-daily cadence make this feel like the same promo in new packaging. It's a solid but unremarkable send.

## What's working

- The 20% off code banner is the first thing you see and is easy to read.
- The big script headline and "HIT LIST" kicker set a luxury tone that fits the premium products.
- The large numerals 1–5 make the layout scannable and give the eye a clear path down the page.
- The callouts "Same-day delivery available" and "Stays preserved for up to one year!" add useful product detail.

- The subject's five-emoji string (✨ 🎁 💐 🍬 ✨) looks spammy and gives no offer, even though 20% off is available.

- 2. Add prices and a "Use GLOW20" line under each product, and turn the "SHOP LUXE" link into a real button.
- 3. Add a visible deadline, such as "Ends 10/18", next to the code in the top banner.

## Technical Audit

## 1. Technical Summary
The visible markup is a standard XHTML 1.0 Transitional table layout with dark-mode meta tags. The automated QA findings are mostly low-severity tracking-pixel hygiene (missing `alt`, `http://` sources) plus compliance and authentication checks that look like relay or truncation artifacts and can't be confirmed from this data. The HTML source was truncated, so the body, footer and link targets could not be inspected.

## 2. Link & Tracking Issues
- **Unverified links:** 29 tracking links were skipped by the HTTP probe because they are click-redirect domains. Their destinations, status codes and redirect chains are unverified.
- **Insecure pixels (http://):**
  - `http://view.atdmt.com/FLO/view/361227669/direct/01/`
  - `http://pixel.mathtag.com/event/img?mt_id=155437&mt_adid=103507&...`
  - `http://pixel.mathtag.com/event/img?mt_id=155438&mt_adid=103507&...`

  Some clients may block these. Open or ad-pixel counts would then be undercounted, and mixed-content warnings are possible in web clients. The `view.atdmt.com` host is a legacy ad-tech domain, and I couldn't check whether it still resolves.
- **Empty macro parameters:** both mathtag pixels send `v1=&v2=&v3=&s1=&s2=&s3=` with no values. These look like unpopulated template variables, so the event data they carry may be empty.
- **Duplicate pixel:** `https://bounceexchange.com/tag/em/1622.gif` appears twice, which could double-count events.
- **Pixel stack:** the email carries at least six third-party or first-party tracking pixels:
  - atdmt
  - two mathtag
  - bounceexchange (twice)
  - `click.dv.1800flowers.com/o/22139cda-...`
  - `mi.1800flowers.com/p/up/ada90b86b2846dd9/o.gif`

  That adds to load and request count and gives more points of failure.

## 3. Rendering & Accessibility
- **Missing `alt` on all eight flagged images.** These are tracking pixels, so `alt=""` would be acceptable. The QA tool flags the attribute as absent entirely, and a missing attribute can make screen readers announce the file name or URL.
- **No `lang` attribute:** `<html xmlns="http://www.w3.org/1999/xhtml" ...>` has none, which affects screen-reader pronunciation.
- **Zoom disabled:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1" />` blocks pinch-zoom. This fails WCAG 1.4.4 and 1.4.10 on some clients.
- **Dark-mode contrast risk:** the email declares `color-scheme: light dark`. It also hardcodes `th {color:#000000 !important}`, `th a {color:#000000 !important}` and `.appleLinks a {color:#000000 !important}`. If a client applies a dark background, black `!important` text would have poor contrast. I couldn't see the body to confirm.
- **Text-resize rule:** `* {-webkit-text-size-adjust:none; -ms-text-size-adjust:none; line-height:100%}` disables text-size adjustment globally. `body` overrides it to `100%`, but the universal selector is redundant and risky.
- **Breakpoint and sizing:** the mobile breakpoint is an unusual `max-width: 418px`. `.mobile` and `.showmobile` use a fixed `width:414px`, which may overflow narrow viewports.
- **Generic `<title>`:** `1800Flowers.com` doesn't describe the email.
- **Hidden-content rules:** `.mobileshow` and `.hide` rely on `display:none`. These may be ignored by some clients (older Gmail, Outlook), but I couldn't check how they're used.

## 4. Personalization & Merge Tokens
No issues found. No unresolved tokens such as `{{...}}`, `%%...%%` or `[FIRSTNAME]` appear in the visible source. The only suspect values are the empty mathtag macros noted in section 2.

## 5. Compliance
These are warnings only and can't be confirmed as failures:
- **List-Unsubscribe and List-Unsubscribe-Post (RFC 8058):** not found. The QA note says the AgentMail relay may strip these headers, so this is inconclusive. Gmail and Yahoo bulk-sender rules require both for senders over 5,000 messages a day.
- **Authentication-Results:** not found, so SPF, DKIM and DMARC status is unknown. The QA note attributes this to the relay.
- **Physical address:** the QA check found none. The HTML was truncated, so the footer was probably not inspected. 1-800-FLOWERS is a large sender, and the address is probably in the footer. This needs the full source to verify.
- **Sender domain:** `em.1800flowers.com` is a dedicated sending subdomain. That is good practice, but alignment is unverified.

## 6. Email-to-Site Continuity
- **UTM parameters:** none are visible in the provided data. The 29 tracked links were not resolved, so landing URLs, UTM tags and destination alignment can't be assessed.
- **Campaign identifier:** `mi_ecmp=261008_EMAIL_18F_PZ_DV_12AMET_PROMO` on the open pixel suggests campaign tracking is done through the vendor's redirect parameters (`mi_cid`, `mi_mid`) rather than UTMs.

## 7. Recommendations
1. Re-run the audit on the full, untruncated HTML and raw headers to settle the compliance, authentication and link-destination warnings.
2. Resolve the click-redirect links (follow redirects, not just a HEAD probe) to check final landing URLs, status codes and UTM or campaign parameters.
3. Upgrade the `http://` pixels (atdmt, mathtag ×2) to HTTPS, or remove them. Confirm `view.atdmt.com` is still live.
4. Populate or remove the empty `v1/v2/v3/s1/s2/s3` mathtag parameters, and de-duplicate the bounceexchange `1622.gif` pixel.
5. Add `alt=""` to all tracking pixels and `lang="en"` to `<html>`.
6. Remove `maximum-scale=1` from the viewport meta tag.
7. Review the `!important` black text overrides (`th`, `.appleLinks a`) against the dark-mode rules, and drop the global `-webkit-text-size-adjust:none` on `*`.
