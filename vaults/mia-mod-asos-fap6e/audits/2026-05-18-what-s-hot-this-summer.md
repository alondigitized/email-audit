# What's hot this summer
**Score:** 7/10 · **Type:** Email audit · **2026-05-18**
## Executive summary

- This is a classic ASOS editorial broadcast — clean photography, multiple product sections, zero offer. The email works hard on aesthetics and delivers on brand feel, but walks away from every conversion opportunity. There's no discount, no deadline, no personalization, nothing that distinguishes this from the last five ASOS sends. The "You look hot" headline is a clever callback to the subject line, and the summer framing is seasonally coherent — but clever copy on top of an empty funnel doesn't drive revenue.
- The split between women's and menswear fragments the message. A send that tries to serve everyone ends up optimized for no one. The Polo Ralph Lauren feature section has real potential — a named brand, a named aesthetic, specific product positioning — but it gets buried mid-scroll behind generic "SHOP NOW" repetition and an oddly parsed headline.
- Bottom line: a competent, visually polished brand email that leaves serious click-through lift on the table by refusing to make a concrete offer or commit to a single audience.

## What's working

- **"You look hot" headline** plays back on the subject line cleanly — small moment of delight for the reader who made the connection.
- **Clean white layout** with strong photography; no render artifacts or broken images visible.
- **Category tile row** (SANDALS, BAGS, SPF ESSENTIALS, SUNGLASSES) provides a useful navigational shortcut for accessory-focused shoppers.
- **Polo Ralph Lauren feature** adds brand specificity and credibility that the rest of the email lacks.
- **Seasonally appropriate** — summer framing in mid-May lands at the right moment in the purchase cycle.

## What's weak

- **No concrete offer anywhere** — no discount, no free shipping, no BOGO. This is a pure editorial send, which makes it easy to file and forget.
- **"IT'S AN IRS LAW SUMMER"** reads as a tax-authority reference to any American recipient; "IRIS LAW" loses its parsing in all-caps typography at this width.
- **"Deal the style"** in the Ralph Lauren section is garbled copy — almost certainly meant to be "Steal the style" with a missing first letter visible in the render.
- **Five identical "SHOP NOW" CTAs** with no differentiation; the eye can't prioritize and the brain doesn't commit.
- **Women's + menswear split** dilutes focus — the email doesn't know who it's talking to by the time it reaches the Adidas sneaker block.

## Recommendations

- 1. **Add a concrete hook to the subject and hero.** Even "Free shipping on all summer orders" or "New summer drops, shipping free today" turns this from content to commerce. That single change touches every downstream metric.
- 2. **Commit to one audience per send.** If the list is segmented by gender, send two emails. If not, lead with the gender that indexes higher on summer AOV — and relegate the other to a footer module.
- 3. **Fix "Deal the style" → "Steal the style"** immediately. A missing letter on a named-brand feature is a QA miss that undermines trust.
- 4. **Make the Iris Law feature the hero, not a mid-scroll module.** Named talent + named brand + specific product = the sharpest story in this email. Bury it at position three and you waste the asset.
- 5. **Replace generic CTAs** with category-specific copy: "Shop Iris Law's Picks," "Shop Beach Dresses," "Shop Men's New In" — verb + noun that tells the reader what they'll land on.

- **Preheader Alt A:** `Beach-ready dresses, bags and sandals — landing now`

### 3. Rendering & Accessibility

**Critical — `<meta>` tags inside `<p>` body tag:**
```html
<p>
  <meta http-equiv="Content-Type" content="text/html; charset=UTF-8">
  <meta charset="utf-8">
  <meta name="viewport" ...>
  ...
</p>
```
Meta elements placed inside `<body>` within a `<p>` wrapper is invalid HTML. Most clients will silently handle it, but strict parsers (some webmail clients, Lotus Notes) may drop or misinterpret these directives. `<meta>` belongs in `<head>`.

**CSS selector bug — `*[class=nomob]` exact-match attribute selector:**
```css
*[class=nomob]  { display: block; }
*[class=nodesktop] { display: none; }
```
The attribute selector `[class=nomob]` only matches elements where the class attribute is exactly and solely `"nomob"`. Any element with multiple classes (e.g. `class="nomob container"`) will not match. This is a known ESP anti-pattern that silently breaks responsive hiding on multi-classed elements.

**`-webkit-text-size-adjust: none` on body:**
```css
body { -webkit-text-size-adjust: none; }
```
Using `none` disables font scaling entirely on iOS Safari. The correct value is `100%`, which prevents automatic resizing while still allowing user-controlled zoom. `none` will suppress both.

**`font-size: 0em` on all table elements:**
```css
table, tr, td, th { font-size: 0em; }
```
Standard gap-collapse technique, but any text content placed directly inside `<td>` without a child `<p>` or `<span>` will be invisible. Requires that all leaf-level content uses explicit font-size overrides.

**Empty preheader div:**
```html
<div style="display:none !important;visibility:hidden;..."></div>
```
The preheader container has no text content. Inbox clients (Gmail, Apple Mail) will fall through to the first visible body text as preview copy. This is either intentional (unusual) or a missing merge token.

**Missing `lang` attribute on `<html>`:**
No `lang="en"` or locale equivalent. Screen readers default to the OS language; assistive tech cannot confirm document language for correct pronunciation rules.

**Duplicate charset declarations:**
```html
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8">
<meta charset="utf-8">
```
Redundant but harmless. Minor bloat.

**SVG font format included in `@font-face`:**
```css
url("FuturaPT-Book.svg") format("svg")
```
SVG fonts are deprecated and unsupported in all modern browsers and email clients. Dead weight in the CSS payload (3 `@font-face` declarations × 5 formats each = 15 format entries, 3 of which are no-ops).
