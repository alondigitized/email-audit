# Want an extra 20% off all Sale?
**Score:** 10/10 · **Type:** Email audit · **2026-07-08**
## Executive summary

- This is ASOS's smartest send in weeks — a gated Premier-member exclusive that tries to break the "sale for everyone" fatigue by making 20% extra feel earned. The hero does exactly what it should: bold code (PREM20), clear deadline (Thursday 11pm), dual gender CTAs, clean visual hierarchy in yellow-green on white. If you have ASOS Premier, this scans as a genuine perk, not another mass-blast.
- The problem is context. This is the second ASOS email to hit the inbox today, following the full-price "New arrivals" editorial from this morning (8/10). A full-price reset followed immediately by a flash-sale exclusive is a mixed signal — the brand doesn't know what it is today. Worse, the "extra off Sale" escalation pattern has appeared three times since June 24 (extra 10%, extra 25%, further reductions on July 6). Premier members who read every email will clock the pattern.
- The single biggest creative flaw: "SIGN UP TO PREMIER NOW" sits directly below copy that reads "Because you've got ASOS Premier." Either this email went to non-members (making the hero copy false) or it's prompting existing members to re-subscribe (just confusing). Either way, the segmentation looks broken.

## What's working

- Code PREM20 is displayed prominently in the hero — no hunting in fine print
- "Ends Thursday, 11pm" is a specific, credible deadline
- Dual CTA (SHOP WOMEN'S / SHOP MEN'S) is gender-inclusive without forcing a choice
- "Because you've got ASOS Premier" elevates the offer above the generic sale emails that dominated June
- Visual scan path is clean: banner → code → deadline → buttons, nothing competes

## What's weak

- Second ASOS email today kills cadence — the morning new-arrivals editorial and this flash-sale exclusive cancel each other out
- "SIGN UP TO PREMIER NOW" CTA directly contradicts the "you've got ASOS Premier" hero copy — audience targeting appears broken
- No single hero product — all CTAs land on category pages, giving browsers no anchor to buy from
- The "SHOP OUR TOP BRANDS" logo strip below the fold adds noise with no connection to the time-limited sale offer
- Subject phrased as a question when a statement would convert harder

## Recommendations

- 1. **Kill the "SIGN UP TO PREMIER NOW" CTA**, or route it to a separate acquisition email entirely. Asking Premier members to sign up in the same scroll as "Because you've got ASOS Premier" looks like a merge-tag error.
- 2. **Lead with one specific hero product at the stacked price** — "This dress: was £45, now £27 with PREM20" drives buyers. Category links drive browsers.
- 3. **Rewrite the subject as a statement**: "Your Premier deal" beats a question and does the segmentation work the current line skips.
- 4. **Don't send two emails the same day** from the same brand without a clear content boundary and at least 4 hours between them.
- 5. **Drop the brand logo strip** — on mobile it's wasted scroll when the offer has a hard deadline to close.

## 3. Rendering & Accessibility

**Confirmed issues:**

- **Duplicate charset declaration** (lines 3–4): Both `<meta http-equiv="Content-Type" content="text/html; charset=UTF-8">` and `<meta charset="utf-8">` are present. Per the HTML spec the `charset` shortform should appear first; the `http-equiv` form is legacy. Harmless in practice but indicates copy-paste template debt.

- **`font-size: 0em` on `table, tr, td, th`**: Ghost-text suppression technique that can cause child elements to inherit 0 font-size in clients that do not reset explicitly. Any `<td>` without an explicit inline `font-size` will render invisible text in affected clients (primarily older Android WebKit).

- **Mobile breakpoint at 460px**: `@media screen and (max-width:460px)` is narrower than the de facto standard of 480px. Devices with viewport widths of 461–480px (some mid-generation Android phones) will receive the desktop layout.

- **`FuturaPT-Heavy` mapped to `font-weight: 600`**: CSS weight 600 is semibold, not heavy (typically 800+). On clients that fall back to the system Futura or Arial, the rendered weight will be lighter than intended. Should be `font-weight: 800` or `900`.

- **SVG font format included**: Both `@font-face` blocks include `.svg` format. SVG fonts were deprecated in 2013 and only relevant for iOS < 4.2. Including them increases `<head>` size without benefit.

- **`-webkit-text-size-adjust: none` on `body`**: Using `none` (rather than `100%`) blocks user-initiated text scaling, which is an accessibility regression for low-vision users. WCAG 1.4.4 (Resize text) applies to email viewable in browsers. Change to `100%`.

- **Conflicting `-ms-text-size-adjust`**: `body` sets `-ms-text-size-adjust: none` while the `*` rule sets `-ms-text-size-adjust: 100%`. The `*` rule wins due to specificity; the `body` declaration is dead code.

- **Animation without `prefers-reduced-motion` guard**: The `@keyframes ticker` animation has no `@media (prefers-reduced-motion: reduce)` override. The `@supports` guard handles client capability but not user accessibility preference.

- **`mso-hide: all` missing on hidden elements**: The `.nodesktop` class uses `display: none; max-height: 0; overflow: hidden` but omits `mso-hide: all`. Outlook ignores CSS `display:none` and will render `.nodesktop` content in desktop Outlook versions.
