# Extra 30% off selected Sale styles
**Score:** 8/10 · **Type:** Email audit · **2026-07-18**
## Executive summary

- This is ASOS running the same play it ran on July 11 — "extra 30% off Sale" stacked on existing sale pricing, a code in the hero, a Monday deadline. The July 11 send scored 9/10 partly because the volume ("1,000s of styles") made the breadth feel significant. This send walks that back with "selected Sale styles," which is a weaker promise with no payoff — you don't learn what's in or out until you click. The creative execution is clean and mistake-free, but the email is doing the mechanical minimum.
- The split CTA (SHOP WOMEN'S / SHOP MEN'S) is a missed personalization moment. ASOS knows what gender I shop for. Forcing that choice in the hero is friction they could have resolved before send. The product grid below ("We Think You'll Love These") skews heavily female — sandals, mini skirt, blouse, wide-leg trousers — which makes the paired men's CTA feel decorative rather than real.
- This is a competent, unambitious email. It will convert sale-hunters who didn't buy on July 11. For everyone else, this is the fourth "extra % off" mechanic in ten days and it reads like it.

## What's working

- **Code + deadline in the hero**: The promo code and "Ends Monday 8am BST" deadline are above the fold, reducing any click-hesitation.
- **Clean render**: No broken images, no layout breakage, no overlapping text. The black hero block is visually strong.
- **Clear, dual CTAs**: "SHOP WOMEN'S" and "SHOP MEN'S" are unambiguous buttons — nothing buried.
- **Product grid reinforces intent**: The "We Think You'll Love These" carousel gives the sale context a product story, not just a discount promise.
- **Subject line is short and scannable**: 34 characters, no spam triggers, reads clean on mobile.

## What's weak

- **"Selected" is a downgrade with no explanation**: July 11 said "1,000s of Sale styles." This says "selected." That qualifier raises the question "selected how?" and gives no answer.
- **Split CTA forces a decision ASOS already knows the answer to**: Personalized CTAs by gender are table stakes at ASOS's scale.
- **No urgency amplification in the subject line**: The Monday deadline lives in the email body but the subject line carries none of it — a wasted slot.
- **Cadence fatigue is real**: This is roughly the fourth "extra % off" email in ten days. The mechanic is losing its signal; it reads as a permanent discount structure, not a limited event.
- **App download section dilutes focus**: Putting a "Download the App" block between the product grid and the footer splits attention right when purchase intent is highest.

## Recommendations

- 1. **Put the deadline in the subject line.** "Extra 30% off — ends Monday" raises stakes without adding characters.
- 2. **Gender-segment the CTA.** ASOS has the data. Send me a single "SHOP WOMEN'S SALE" hero with no men's button, and vice versa. The split CTA is a lazy compromise.
- 3. **Explain "selected."** Either lead with a category anchor ("Extra 30% off 800+ dresses, tops & more") or drop the qualifier and restore the breadth signal. "Selected" is vague downward.
- 4. **Kill or relocate the app block.** It interrupts the purchase funnel at exactly the wrong moment. Move it to the footer or a post-click email.
- 5. **Raise the offer stakes or gate it.** The July 8 Premier-exclusive send (PREM20) was the most defensible version of this mechanic because it felt earned. Running the same promo publicly for the 4th time with no gate erodes the perception that ASOS Premier is worth anything.
- **Subject Alt A:** `Extra 30% off Sale — ends Monday 8am`
- **Subject Alt B:** `Your last chance: extra 30% off Sale styles`
- **Preheader Alt A:** `Dresses, sandals, summer must-haves — all with 30% extra off. Code: EXTRA30.`
- **Preheader Alt B:** `Code EXTRA30 · Hundreds of Sale picks dropping in price — shop before Monday.`

### 3. Rendering & Accessibility

**Issue — Global `font-size: 0em` on table elements:**
```css
table, tr, td, th { font-size: 0em; ... }
```
This ghost-spacing technique requires every content cell to explicitly reset `font-size`. Any `<td>` missing an inline or class-level font-size reset will render invisible text. High Outlook/Lotus Notes risk.

**Issue — CSS table centering won't work in Outlook:**
```css
table { margin: 0 auto; }
```
Outlook (Word rendering engine) ignores `margin: 0 auto` for table centering. Requires `align="center"` attribute on the `<table>` element itself. If outer wrapper tables rely solely on this CSS, layout will be left-aligned in Outlook 2016–2021.

**Issue — No `role="presentation"` visible on layout tables:**
Screen readers will announce layout tables as data tables. Cannot confirm whether `role="presentation"` is applied inline on body tables (source truncated), but it is absent from the CSS defaults.

**Issue — SVG font format included (unnecessary):**
```css
url("...FuturaPT-Book.svg") format("svg")
```
SVG fonts are deprecated, unsupported by all modern browsers and email clients, and add dead weight to the `@font-face` stack. Remove all five SVG `src` entries across both `@font-face` declarations.

**Note — Media query breakpoint is 460px:**
```css
@media screen and (max-width:460px)
```
Industry standard is 600px (some use 480px). Devices between 461px–599px receive desktop layout in a mobile viewport. Common Android mid-range devices fall in this range.

**Positive findings:**
- `<html lang="en">` present
- `<meta name="x-apple-disable-message-reformatting">` present
- `<meta name="format-detection" content="telephone=no, date=no, ...">` present
- `mso-font-alt: Arial` fallback declared on both `@font-face` blocks
- `@supports` guard correctly hides ticker fallback when animation is supported
