# 20% off 1000s of styles
**Score:** 8/10 · **Type:** Email audit · **2026-06-09**
## Executive summary

- ASOS shifts from yesterday's aspirational football-fashion editorial ("Styled for match day," June 8) into a straight discount trigger — a textbook two-step: inspire first, convert second. The creative execution is clean and competent: a four-product grid showing summer-weight women's styles, a clearly coded offer (SASSON), and a deadline (ends Wednesday 11pm BST, which is tomorrow). The offer is real and legible.
- What the email lacks is any reason to act *now* beyond that deadline — and the deadline is buried in small copy beneath the hero rather than front-and-center. The brand gallery (Topshop, adidas, Levi's, New Balance) at the bottom reads as filler that dilutes the primary conversion message, and the app CTA competes without earning its placement.
- Overall this is a functional promo email that will convert existing deal-seekers but leaves open-rate and click-rate points on the table due to the urgency copy placement and the absence of personalization.

## What's working

- **Code + deadline both visible above the first fold** — SASSON and "Ends Wednesday 11pm BST" appear in the hero block, so committed buyers can act immediately without scrolling.
- **Subject line is exceptionally clear and mobile-short** — "20% off 1000s of styles" at 22 characters fits any inbox truncation window without ambiguity.
- **Two-step creative sequence from June 8 is smart** — yesterday's editorial primed the style context; today's discount is the conversion punch.
- **No render bugs** — clean layout, images load, text and buttons are properly spaced.
- **Product grid is coherent** — all four images read as the same brand aesthetic (summer, contemporary women's fashion), no obvious visual inconsistency.

## What's weak

- **Deadline urgency is undersized** — "Ends Wednesday 11pm BST" is styled at roughly the same size as the sub-body copy; it should be the loudest element after the discount figure.
- **Both CTAs say "SHOP NOW"** — identical generic copy for two separate placement positions. The second button after the grid could do real work ("SHOP THE SALE," "GET 20% OFF") and it doesn't.
- **Brand logo rail competes with the conversion goal** — the Topshop/adidas/New Balance strip below the product grid signals that the email lost confidence in its own offer.
- **Preheader is soft and vague** — "Fancy a little treat? We think you'll love these" adds no information value; it doesn't hint at the discount, the code, or the deadline that could move open rate.
- **Back-to-back cadence creates fatigue risk** — June 8 + June 9 sends will trigger aggressive inbox filtering for segment-fatigued subscribers.

## Recommendations

- 1. **Elevate the deadline into the hero headline** — restructure so the eye reads: *20% off → ends tomorrow (Wed 11pm)→ code SASSON → SHOP NOW*. Deadline copy should be at least as large as the code itself.
- 2. **Differentiate the two CTAs** — first button: "SHOP WOMEN'S SALE," second button (after grid): "GET 20% OFF NOW." Verbs tied to the offer outperform bare "SHOP NOW."
- 3. **Rewrite the preheader to contain the deadline** — the inbox is the highest-leverage touchpoint; move the urgency there, not deep in the body.
- 4. **Cut or consolidate the brand rail** — if brand-partner sends (like the Cotton On email on May 31) have their own moment, don't undercut a discount promo with brand discovery content. Swap it for a second curated product row.
- 5. **Add a personalization hook** — even a first-name token in the preheader ("Alon, your 20% code expires tomorrow") would lift open rate materially.

- **Subject Alt B:** `Your 20% off code: SASSON (expires Wed)`
- **Preheader Alt A:** `1000s of summer styles — ends Wednesday 11pm BST`

### 1. Technical Summary

The email has a critical structural defect: `<meta>` and `<title>` elements are embedded inside `<body><p>` with no `<head>` section present. Several CSS declarations are non-functional in email environments. Link, UTM, and compliance sections cannot be fully verified from the truncated source.

### 2. Link & Tracking Issues

**Cannot fully verify** — HTML is truncated before CTA links appear. The following must be confirmed against the full source:
- All `<a href>` values should use redirect/tracking wrappers (e.g., `click.asos.com`) and not raw `asos.com` URLs
- Link-level click tracking tags must be present on every CTA

**Confirmed structural concern**: All `<a>` elements inherit `color: inherit; text-decoration: none` via:
```css
a, span { font-family: inherit; font-weight: inherit; text-decoration: none; color: inherit; }
```
If CTA containers don't explicitly set a contrasting color, links will be visually identical to surrounding text — a functional regression in clients that support embedded CSS (Apple Mail, iOS Mail).

---

### 3. Rendering & Accessibility

**Critical — Malformed document structure**: The email has no `<head>` element. `<meta>` tags, `<title>`, and `<style>` are all placed inside `<body>`. Specifically, `<meta charset>`, `<meta viewport>`, and `<title>` are nested inside a `<p>` element:

```html
<html><body>
  <p>
    <meta http-equiv="Content-Type" content="text/html; charset=UTF-8">
    <meta charset="utf-8">
    <meta name="viewport" ...>
    <title>20% off 1000s of styles</title>
  </p>
```

`<meta>` and `<title>` are not valid children of `<p>`. Most email clients strip `<head>` anyway, but placing these inside a block element can cause charset/viewport parsing to fail in strict parsers (some Android webview-based clients).

**Non-functional CSS**:
- `font-display: swap` inside `@font-face` is not supported by any email client. Dead code.
- `-webkit-font-smoothing: antialiased !important` on `*` is ignored in all email clients.

**Responsive breakpoint**: Media query fires at `max-width: 460px`. Standard email breakpoints are 480px or 600px. Devices 461–480px wide (older Android handsets, some small phones) will receive desktop layout with no responsive adjustments.

**Image accessibility**: `img { display: block; border: none; outline: none; text-decoration: none; }` resets are present but no `alt` attribute enforcement is visible in the CSS. Alt text presence on actual `<img>` tags must be verified in full source.

**`<style>` in `<body>`**: HTML5 permits this but some older webmail clients (Yahoo legacy, AOL) may handle in-body style blocks inconsistently.
