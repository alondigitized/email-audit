### 3. Rendering & Accessibility

**Duplicate `@font-face` for `'Aldine-Light'` with no differentiating descriptor:**
```css
@font-face { font-family: 'Aldine-Light'; src: url('...tt0804m.woff') ... }
@font-face { font-family: 'Aldine-Light'; src: url('...tt0805m.woff') ... }
```
Both declarations share the same `font-family` name with no `font-weight` or `font-style` to differentiate them. CSS cascade rules mean the second declaration (tt0805m) overwrites the first. If these are intended to be different weights/styles, both need explicit descriptors.

**`-webkit-text-size-adjust: none` on `*` conflicts with `100%` on `.body-fix`:**
```css
* { -webkit-text-size-adjust: none; }
.body-fix { -webkit-text-size-adjust: 100%; }
```
The `*` selector applies `none` globally, preventing users from adjusting text size — an accessibility concern. The `100%` value on `.body-fix` is overridden by the more specific `!important`-less `*` rule in most interpretations. Correct approach is `100%` on `body` only.

**CSS hover states are non-functional in email:**
Both `.poll:hover .pollButton` and `.img-hover-zoom:hover img` use hover pseudo-classes, which are not supported in Gmail, Outlook (any version), or Yahoo Mail. These effects silently fail for the majority of recipients. No fallback is defined.

**`section { display: inline !important; }`** — This globally forces any `<section>` element to render inline. If `<section>` tags appear in the body for layout purposes, this will collapse them. Confirm no layout sections exist in the full HTML.
