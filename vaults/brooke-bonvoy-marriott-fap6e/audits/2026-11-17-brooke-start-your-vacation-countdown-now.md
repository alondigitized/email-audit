## Technical Audit

## 1. Technical Summary
The HTML is a well-formed, responsive-capable email with a resolved first-name token, but it has no plain-text part (0 chars). One link is a relative path with no domain, and one image has no alt text. Most of the QA "broken link" failures are 403s from the tracking redirector, which are probably the QA prober being blocked rather than real breakage.

## 2. Link & Tracking Issues
- **Relative, unresolvable link (real defect):** the "MY ACCOUNT" `href` is `/loyalty/myAccount/default.mi?enrollmentSourceCode=INCK&nck=1028103536&ck=12697940&lk=1000301947`. It has no scheme or host, so the probe failed with `unknown url type`. In a mail client this link has no base URL to resolve against and will not work. The wrapped tracker URL (`.../d2afcb0f98f14b0b0000021ef3a0bccf/...`) wraps the relative path, so the redirect target may be malformed. That could not be confirmed because the redirect was not followed.
- **403 on tracked links (likely a probe artifact):** these all return 403 on `email-marriott.com/T/v71000001a1e972b3f3862a50369fea4b34/...`:
  - "find & reserve"
  - "» find & reserve"
  - "Marriott Bonvoy" (two links)
  - "UNSUBSCRIBE"

  Five links on the same click-tracking domain failing identically points to bot or header filtering on the redirector, not five bad destinations. The data can't distinguish the two. The unsubscribe 403 matters most and needs a manual browser check.
- **Duplicate CTAs:** "find & reserve" and "» find & reserve" use different tracking IDs (`...bcd0` and `...bccd`). That is normal for per-placement tracking, not a defect.
- **Very long tokens:** the `__F__=` query strings run to several hundred characters. This is a risk for some clients and scanners that truncate URLs, but no truncation was observed.
- **Coverage gap:** only 12 of 44 links were probed (32 skipped). The skipped links, mostly footer, utility and social, are unverified.
- **Mixed content in font CSS:** `@font-face` for `Aldine-Regular` and `Aldine-Regular-Italic` lists `http://cache.marriott.com/...woff` as a fallback source. Clients that support WOFF2 won't use it, but it is a non-HTTPS resource reference.

## 3. Rendering & Accessibility
- **Missing alt text:** the image `d2afcb0f98f14b0b00004c5a42963aa1` (`https://email-marriott.com/O/v71000001a1e972b3f3862a50369fea4b34/d2afcb0f98f14b0b00004c5a42963aa1`) has no `alt` attribute. Screen readers will announce the filename, and the image will show nothing if blocked.
- **Plain-text part missing:** the text version is 0 characters (`[FAIL]`). This hurts accessibility, text-only clients and spam scoring. It could be a relay artifact (see section 5).
- **Web fonts:** the `@font-face` blocks for Aldine and Swiss list `.otf` with `format('otf')`. The correct format token is `opentype`, so that source is ignored. The `.eot` and `.svg` sources are also obsolete. Fallbacks (`Times New Roman`, `Arial`) are declared, so the impact is low.
- **Outlook handling:** the MSO conditional blocks (`OfficeDocumentSettings`, `gt mso 9` font overrides) and `x-apple-disable-message-reformatting` are present. No rendering defect is evident in the truncated source.
- **Truncation:** the HTML was truncated, so the body markup, button structure and `role="presentation"` usage could not be audited.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe and List-Unsubscribe-Post (RFC 8058):** neither header was found. The QA tool says the AgentMail relay may strip them, so this is unconfirmed. If the headers are truly absent, the email won't meet Gmail and Yahoo bulk-sender one-click unsubscribe requirements.
- **Authentication-Results:** not found, so SPF, DKIM and DMARC status is unknown. The tool attributes this to the relay. Check the raw message headers at the original recipient to confirm.
- **In-body unsubscribe:** an "UNSUBSCRIBE" link is present in the body, but it returned 403 on probe (see section 2), so it should be verified manually.
- **Postal address:** it is not visible in the truncated source, so it was not verified.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **No UTM parameters visible:** attribution runs through the opaque `__dU__` and `__F__` tokens on the redirector rather than UTMs. The final landing URLs could not be seen because every redirect either returned 403 or was not followed.
- **Landing alignment:** it could not be assessed, because no redirect resolved. The "MY ACCOUNT" destination is the only visible path (`/loyalty/myAccount/default.mi`), and it carries `enrollmentSourceCode=INCK`, `nck`, `ck` and `lk` rather than UTMs.

## 7. Recommendations
1. Make the "MY ACCOUNT" `href` absolute (`https://www.marriott.com/loyalty/myAccount/default.mi?...`) and re-test the redirect.
2. Manually check the `UNSUBSCRIBE` tracking link in a real browser. If it also returns 403 there, fix it as a compliance issue.
3. Re-probe the 403 links with a browser-like User-Agent, or allowlist the QA prober, to separate bot blocking from real failures.
4. Add a plain-text MIME part. It should be non-empty, with working URLs for the main CTAs and the unsubscribe link.
5. Add `alt` text to image `d2afcb0f98f14b0b00004c5a42963aa1`, using `alt=""` if it is decorative.
6. Fetch raw headers from a direct inbox, not through the AgentMail relay, to confirm `List-Unsubscribe`, `List-Unsubscribe-Post` and SPF/DKIM/DMARC.
7. Fix the font sources: use `format('opentype')` instead of `format('otf')`, change the `http://` font URLs to HTTPS, and drop the legacy `.eot` and `.svg` sources.
8. Probe the 32 skipped links, or at least spot-check the footer and utility links, to complete link coverage.
