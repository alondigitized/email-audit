### 3. Rendering & Accessibility

**Confirmed issue — invalid `@font-face` format hint:**
```css
src: url('...tt0804m.otf') format('otf'),   /* ❌ invalid */
     url('...tt0805m.otf') format('otf'),   /* ❌ invalid */
```
The correct value is `format('opentype')`. Both `Aldine-Light` and `Aldine-Light-Italic` declarations are affected. Browsers that parse this strictly will skip the OTF source and fall through to WOFF, which is functionally acceptable but represents broken intent.

**Confirmed issue — over-broad `-webkit-text-size-adjust: none`:**
```css
* { -webkit-text-size-adjust: none; }
```
Applied to the `*` selector rather than `body`. `none` (vs. `100%`) suppresses user-initiated text scaling in iOS WebKit, which is an accessibility concern and can affect WCAG 1.4.4 compliance. Standard practice is `body { -webkit-text-size-adjust: 100%; }`.

**No issues found:**
- Outlook DPI fix (`o:PixelsPerInch`) present.
- VML namespace declarations correct.
- `<meta name="x-apple-disable-message-reformatting">` present.
- `format-detection` suppressing auto-linking for phone/date/address/email — correct.
- Responsive breakpoint declared at `max-width: 480px`.
- `img { display: block; }` globally applied — correct.
