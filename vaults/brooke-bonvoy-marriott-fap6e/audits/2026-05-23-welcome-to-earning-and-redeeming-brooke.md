# Welcome to Earning and Redeeming, Brooke
**Score:** 7/10 · **Type:** Email audit · **2026-05-23**
## Executive summary

- This is the third onboarding email from Marriott Bonvoy in six days (May 17 welcome, May 20 app push, May 23 earn/redeem). The pattern is now undeniable: this is a drip-deck, not a marketing campaign. Each slide arrives on its own, asking Brooke to absorb one more concept before she's actually done anything with the program. The email itself is competent — it covers earning, redeeming, the Uber Eats partnership, and account activation in a clean layout — but it never coalesces into a single reason to act today.
- The Uber Eats "Go From Takeout to Check-In" section is the most interesting piece here, a genuinely differentiated earn signal that most people don't associate with hotel loyalty. That should be the hero, not the fourth block. Instead it's buried below two generic "earn everywhere / redeem for the extraordinary" panels that say essentially nothing.
- The "Personalize Your Stay, Brooke" section with the ACTIVATE YOUR ACCOUNT CTA reveals that Brooke still hasn't activated her account six days after joining. That's the real problem to solve — and the email finally names it, but only in the final content block before the footer.

## What's working

- **Personalization lands twice** — subject line and the "Personalize Your Stay, Brooke" section header both use her name, giving the email a more direct feel than the previous two sends.
- **5,000-point redemption floor is a specific, memorable anchor** — "free nights starting at just 5,000 points" gives an otherwise abstract program a concrete floor.
- **Brand logo grid is well-executed** — showing ~30 hotel brand logos at the bottom demonstrates program breadth in a way that's visual and scannable.
- **Uber Eats partnership is a standout differentiator** — earning points on food delivery is a genuine "I didn't know that" moment that makes the program feel useful in daily life.

## What's weak

- **Five competing CTAs with no hierarchy** — LEARN MORE (×2), SEE ALL WAYS TO EARN, SEE ALL WAYS TO REDEEM, and ACTIVATE YOUR ACCOUNT all compete equally; the eye has nowhere to land.
- **ACTIVATE YOUR ACCOUNT is buried fourth** — if Brooke hasn't activated after six days, that's the job of this email. Hiding the activation CTA after three content blocks is burying the lede.
- **No time pressure or offer** — three emails in six days and still no concrete incentive to book a stay, earn bonus points, or activate by a deadline.
- **"Go From Takeout to Check-In" imagery reads as a tablet/food delivery device** — it's small and low-contrast; the Uber Eats hook is stronger in words than in visuals.
- **Cadence fatigue is now a real risk** — a third educational email with no offer lands like unsolicited homework; a less engaged subscriber would have unsubscribed by now.

## Recommendations

- 1. **Collapse the three drip emails into one and anchor on a first-stay incentive** — even 1,000 bonus points on your first booking beats three slides of "here's how the program works." This is the highest-leverage change.
- 2. **Lead with the Uber Eats earn hook in the hero** — it's the most surprising, everyday-relevant benefit. Make it the reason to open, not a footnote.
- 3. **Make ACTIVATE YOUR ACCOUNT the sole primary CTA** — the sequence data shows Brooke hasn't activated. One prominent button above the fold fixes that; the other CTAs can be secondary links.
- 4. **Add a soft deadline to the activation ask** — "Activate by June 1 to be ready for summer travel" is enough to create credible urgency without manufacturing pressure.

- **Subject Alt B:** `Did you know you earn Bonvoy points on Uber Eats?`
- **Preheader Alt A:** `Activate your account and you're closer than you think.`

### 1. Technical Summary

### 2. Link & Tracking Issues

**ESP tracking domain mismatch**
Poll hover image resolves directly to `https://media.4at5.net/email_domains/mar/264715/images/poll_btn_rollover.png` — a bare media asset URL, not a tracked redirect. If this image is ever used as a CTA, clicks would be untracked.

**Sending domain vs. asset domain split**

- Font/asset CDN: `cache.marriott.com`

Three distinct domains in play. DKIM alignment requires the `d=` tag on the DKIM signature to match the `From:` header domain (`email-marriott.com`). If assets from `cache.marriott.com` set cookies, cross-domain attribution breaks in Safari (ITP).

### 3. Rendering & Accessibility

**Invalid CSS font format strings**
Both `@font-face` blocks use `format('otf')` which is not a valid CSS format hint. The correct identifier is `format('opentype')`. Browsers silently skip invalid format hints and fall through to the next `src` entry, so rendering degrades gracefully, but this indicates a copy-paste error in the template baseline.

```css
/* Current (incorrect) */
url('...tt0804m.otf') format('otf'),

/* Correct */
url('...tt0804m.otf') format('opentype'),
```

**SVG font format declared**
All four `@font-face` blocks include an `.svg` source entry. SVG fonts are unsupported in every modern browser and email client since ~2017. Dead weight, harmless but should be removed.

**Aggressive text-size suppression**
```css
* { -webkit-text-size-adjust: none; }
```
The global `none` value prevents OS-level text scaling on iOS/Android. This conflicts with WCAG 1.4.4 (Resize Text). The `<body>` correctly uses `100%`, but the wildcard `none` overrides it for all descendant elements in WebKit. Should be scoped to `body` only and set to `100%`.

**Webkit font-weight override**
```css
@media screen and (-webkit-min-device-pixel-ratio:0) {
  .Aldine-Light-Italic { font-style: normal !important; }
  [class~="x_Aldine-Light-Italic"] { font-style: italic !important; }
}
```
The class-based rule sets `normal`, then immediately the attribute-selector rule sets `italic` for the same visual role. The `x_` prefix is the Outlook.com class name mangling prefix — this dual declaration is intentional but only the attribute selector will fire in Outlook.com (the class gets renamed). No rendering defect, but brittle.

**Mobile breakpoint at 414px only**
A single breakpoint at `max-width: 414px` misses the 414–600px range common on larger phones (iPhone Plus, Android large). Cannot confirm whether a second breakpoint exists in the truncated source.
