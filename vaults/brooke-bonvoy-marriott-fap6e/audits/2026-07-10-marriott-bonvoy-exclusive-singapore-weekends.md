- **Business travel module is a creative non-sequitur**: The "For Trips That Mean Business" section — featuring a workspace photo and "Learn More" button — directly contradicts the weekend leisure angle established above. This dilutes the message.
- **"10% off" is a weak discount hook**: After Marriott's recent 5,000-point bonus (July 3) and 125K-point credit card offers, a 10% room rate discount reads as a step down in perceived value.
- **No personalization visible**: The June 30 and June 15 emails used "Brooke" prominently; this send is completely anonymized, reducing relevance.
- **No deadline/urgency visible**: There's no "Book by [date]" or "Weekend stays through [month]" — the offer floats without a shelf life.
- **Preview text leaks junk**: The topmost line "Enjoy our lowest rates for your Marriott Bonvoy weekends" is serviceable but feels like auto-generated filler rather than a crafted hook.

## Recommendations

- 1. **Cut the business travel module entirely.** This is a weekend leisure pitch. The second block actively confuses the send's purpose and halves the visual real estate available to close the deal.
- 2. **Add a deadline.** "Valid through August 31" or "Weekend stays this summer" turns a passive offer into a reason to book now. The July 3 Richmond email suffered the same absence of urgency.
- 3. **Bring back personalization.** The June 30 and June 15 sends used "Brooke" in the subject and body with clear lift — dropping it here is a regression.
- 4. **Strengthen the discount frame.** 10% off is real money but sounds thin. Translate it: "Save $30–$90 per night" or anchor it against a typical rate to make it land.
- 5. **Sharpen the subject line.** "Marriott Bonvoy Exclusive: Singapore Weekends" is flat — "Exclusive" and "Bonvoy" together read like brand filler. Lead with the concrete benefit.

### 3. Rendering & Accessibility

**Issue A — `viewport` meta: missing hyphen in `initial-scale`**
```html
<meta name="viewport" content="width=device-width, initial scale=1.0">
```
Should be `initial-scale=1.0`. The current value is parsed as an unknown key `initial scale` and the scale directive is silently ignored, causing mobile clients to render at desktop width.

**Issue B — Empty `<title>` tag**
```html
<title></title>
```
An empty title is flagged by several spam filters (SpamAssassin rule `MISSING_SUBJECT_HEADER` variant) and causes screen readers to announce no document name. Should be set to the subject line or a descriptive string.

**Issue C — Deprecated SVG font format included in all `@font-face` blocks**
```css
url('...tt0804m.svg') format('svg')
```
SVG fonts were removed from Safari in 2020 and are unsupported in all major email clients. The `format('svg')` entries are dead weight; they won't cause errors but add unnecessary payload to every font stack.

**Issue D — Invalid `sup` CSS shorthand**
```css
sup {
  vertical-align: text-top .6em;
}
```
`vertical-align` does not accept two space-separated values. This will be ignored by all parsers; the intended behavior (raising superscripts) will not apply. Correct to:
```css
sup { vertical-align: super; font-size: 60%; }
```

**Issue E — Legacy `.ReadMsgBody` / `.ExternalClass` hacks are now no-ops**
These target Hotmail/Windows Live clients that reached end-of-life in 2013. Not a bug, but dead code adding ~0.3 KB.
