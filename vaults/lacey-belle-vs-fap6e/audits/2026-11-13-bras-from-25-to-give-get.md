## Technical Audit

## 1. Technical Summary
The email is a Salesforce Marketing Cloud send (`click.e1.victoriassecret.com`) with valid campaign tagging and no unrendered merge tokens in the visible source. The main problems are malformed document structure, 11 images missing `alt`, 10 insecure `http://` third-party pixels, and a viewport meta tag that blocks zoom. The automated QA reports 57% pass, 0 errors and 3 warnings.

## 2. Link & Tracking Issues
- **Unverified links:** 44 tracking links were skipped as click-redirect domains, so no HTTP status was checked. Landing-page health is unconfirmed.
- **Insecure pixels:** Ten Dotomi (Conversant) cookie-sync pixels load over plain `http://`: `http://ads.dotomi.com/cookieredir/2482/pub1.php` through `pub10.php`. There is also `http://login.dotomi.com/ucm/UCMController?dtm_com=2&dtm_cid=2482...`. Clients that block mixed or insecure content will drop them, so the ad-sync pixels will silently fail.
- **Hashed email in query strings:** `dtm_email_hash=4edea106…c6fe` appears in the JSON-LD URL. The same hash is the parameter name in each `pubN.php?a4edea106…=1` pixel. A `customerID=43cece97…` hash is also in the JSON-LD URL. These are SHA-256 identifiers sent to a third-party ad domain over unencrypted HTTP.
- **Open pixel:** `click.e1.victoriassecret.com/open.aspx?qs=…&d=70265&bmt=0` is a 1x1 image with `alt=""`, which is correct for a pixel.

## 3. Rendering & Accessibility
- **Missing alt text:** 11 images have no `alt`. Ten are the Dotomi tracking pixels, which should carry `alt=""` explicitly. The eleventh is a content image, `https://image.e1.victoriassecret.com/lib/fe92137274640d7b71/m/179/5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png`. Screen readers will announce its filename or URL.
- **Zoom disabled:** `<meta name="viewport" content="… maximum-scale=1, user-scalable=0">` prevents pinch-zoom (WCAG 1.4.4).
- **Invalid document structure:**
  - A `<table>` and a `<script type="application/ld+json">` sit inside `<head>`, before the `<meta>` and `<style>` tags. Parsers will implicitly close `<head>`, so the meta and style tags may end up in `<body>`.
  - The doctype is HTML 4.01 Transitional, while the content uses XHTML-style self-closing tags.
- **Empty title:** `<title style="display: none; …"></title>` is empty and sits inside `<body>`.
- **Layout tables:** Most layout tables lack `role="presentation"`. Only the `stylingblock-content-wrapper` tables have it.
- **CSS defects:**
  - `ReadMsgBody{ width: 100%;}` is missing its leading `.`, so it targets a nonexistent element.
  - `min-width{width:auto!important;}` is not a valid selector.
  - `max-height:auto` is not a valid value.
  - The global `table{max-width:600px!important;}` caps every nested table.
- **JSON-LD:** The `PromotionCard` markup is only honored by Gmail. It is harmless elsewhere.

## 4. Personalization & Merge Tokens
No issues found in the visible source. No literal `%%…%%`, `{{…}}` or `[FIRSTNAME]` tokens appear, and the per-recipient hashes are rendered. The HTML was truncated, so the body was not fully inspected.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe and List-Unsubscribe-Post:** Both were not found. The QA tool attributes this to the AgentMail relay possibly stripping them, so this is **unconfirmed, not a verified defect**. Check the raw message at the sending ESP.
- **Authentication-Results:** Not found, so SPF, DKIM and DMARC status is unknown. The tool attributes this to the relay.
- **Body footer:** The unsubscribe link and physical postal address are not in the truncated source, so they could not be verified.
- **Sending domain:** `e1.victoriassecret.com` is used consistently for the From address, tracking and images.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Tagging scheme:** The email uses ESP/Dotomi parameters, not `utm_*`: `cm_mmc=di-_-111326525-_-VSD_VSL_20261113_VS_6484_FILEBAL`, `d_cellid=111326525` and `mi_ecmp=20261113_VS_6484_FILEBAL`. The campaign ID `20261113_VS_6484_FILEBAL` is consistent across the link and the `dtmc_email_category` parameter.
- **GA attribution:** There are no `utm_source`, `utm_medium` or `utm_campaign` parameters in the visible URL. If the site's analytics depends on UTMs, it needs mapping from `cm_mmc`.
- **Landing alignment:** The URL `https://www.victoriassecret.com/us/vs/bras` matches the subject line's bra offer. It was not fetched, because it sits behind a tracking redirect.

## 7. Recommendations
1. Switch all Dotomi pixels to `https://`, or remove the cookie-sync pixels. Add `alt=""` to each.
2. Add descriptive `alt` text to `5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png`.
3. Remove `maximum-scale=1, user-scalable=0` from the viewport meta tag.
4. Move the `<table>` and JSON-LD `<script>` out of `<head>`, and give the `<title>` real text.
5. Fix the CSS selectors (`.ReadMsgBody`, `min-width`, `max-height:auto`).
6. Add `role="presentation"` to the layout tables.
7. Review sending hashed email and customer IDs in query strings and unencrypted pixel URLs.
8. Confirm `List-Unsubscribe`, `List-Unsubscribe-Post` and SPF/DKIM/DMARC from the original headers, not the relayed copy.
9. Add `utm_*` tags, or confirm that analytics maps `cm_mmc` and `mi_ecmp`.
