### 1. Technical Summary

### 2. Link & Tracking Issues

**Open pixel — empty alt, no `role`**
```html
<img src="https://click.e1.victoriassecret.com/open.aspx?3222YV6HH6DUTEESCPSOGHV2UY.70251..." width="1" height="1" alt="">
```
`alt=""` is correct for a tracking pixel, but the enclosing `<div style="font-size:0; line-height:0;">` provides no `role="presentation"`. Minor — some screen readers will still announce it as an unlabeled image.

**Subscriber and customer IDs hardcoded in JSON-LD**
The `offerPageUrl` and `merchantHomepageUrl` inside the structured data block include individualized parameters:
- `mi_u=200492586522` — SFMC subscriber ID (plaintext)
- `customerID=43cece97e6d8df6be697d752bcdd40b9f91bee03bb8b831603f25685d19b1e2f` — hashed customer identifier
- `dtm_email_hash=4edea106b333e696054ee7efded08d13b357adf450709a7b066a2e459aafc6fe` — hashed email address

These values are embedded in `application/ld+json`, which Gmail parses and indexes for Promotions tab display. Google ingests the entire JSON-LD payload. While the values are hashed, they are recipient-unique identifiers exposed to a third-party indexer in a machine-readable format.

**Source is truncated** — click-through link redirect behavior and any third-party ad trackers in the body cannot be fully assessed.

---

### 3. Rendering & Accessibility

**`<table>` as direct child of `<head>` — invalid HTML**
```html
<head>
  <table ... class="stylingblock-content-wrapper">
    <tr><td ...>
      <script type="application/ld+json">...</script>
    </td></tr>
  </table>
  <meta name="viewport" .../>   <!-- appears after table -->
```
`<table>` is not a permitted child of `<head>`. The SFMC block wrapper renders the structured data script inside a table cell inside the document head. Strict parsers (and Gmail's JSON-LD extractor) may fail to recognize the annotation, nullifying the Promotions tab discount badge entirely.

**`user-scalable=0` and `maximum-scale=1` in viewport**
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=0" />
```
Pinch-to-zoom is blocked on mobile. This fails **WCAG 1.4.4 (Resize Text, Level AA)**. Users with low vision cannot zoom the email content.

**Missing `lang` attribute on `<html>` element**
No `lang="en"` present. Screen readers default to the OS language rather than inferring document language, which affects pronunciation and reading mode.

**`<meta>` tag ordering**
The `Content-Type` and `viewport` metas appear after the table block in `<head>`. The charset declaration (`charset=UTF-8`) should be the very first element inside `<head>` per HTML spec; late placement can cause character-set sniffing in legacy clients.
