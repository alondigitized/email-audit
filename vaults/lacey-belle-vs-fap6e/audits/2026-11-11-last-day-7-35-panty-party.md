## Technical Audit

## 1. Technical Summary
The email uses a table-based layout with Salesforce Marketing Cloud tracking (`click.e1.victoriassecret.com`) and several third-party pixels. The confirmed issues are malformed document structure, a zoom-disabling viewport tag, insecure `http://` pixel requests that carry a hashed email, and a missing alt attribute on one content image. The header-based compliance and authentication checks couldn't be verified, because the relay likely strips those headers.

## 2. Link & Tracking Issues
- **49 tracking links were not probed.** The QA run skipped them as click-redirect domains, so link validity and destination status are unverified.
- **Insecure tracking pixels.** All of these are `http://`, not `https://`:
  - `http://mi.victoriassecret.com/p/up/bc3d99b3ec2e075f/o.gif?mi_u=200492586522&mi_ecmp=20261111_PK_6473_FILEBAL`
  - `http://login.dotomi.com/ucm/UCMController?dtm_com=2&dtm_cid=2482…`
  - `http://ads.dotomi.com/cookieredir/2482/pub1.php` through `pub10.php`
- **Impact of the `http://` pixels.** Clients that block mixed content will drop these pixels, and attribution and cookie-sync (`cookieredir`) will fail silently. The `pub*.php` URLs also put a 64-character hex hash in the query string in cleartext, `a4edea106b33…=1`. It matches the `dtm_email_hash` value (`4edea106b333…`) in the JSON-LD URL, which suggests it is a hashed email address.
- **Ten sequential cookie-sync pixels.** `pub1.php` to `pub10.php` all fire on open. That adds weight and request latency, and it is a privacy surface.
- **Primary open pixel.** `click.e1.victoriassecret.com/open.aspx?...` is correctly formed, 1x1, with `alt=""`.

## 3. Rendering & Accessibility
- **Invalid document structure.**
  - A `<table class="stylingblock-content-wrapper">` containing a `<script>` sits inside `<head>`, before `<meta name="viewport">` and the content-type meta.
  - A `<title>` and `<style>` also appear inside body-level table cells, and the title is empty (`<title style="display: none; …"></title>`).
  - Parsers will hoist or discard these elements inconsistently.
- **Zoom disabled.** `<meta name="viewport" content="… maximum-scale=1, user-scalable=0" />` blocks pinch-zoom, which is a WCAG 1.4.4 failure.
- **Invalid CSS selectors.** `ReadMsgBody{ width: 100%;}` is missing its leading `.`, and `min-width{width:auto!important;}` targets a nonexistent element. Neither rule has any effect.
- **Missing alt text.** `https://image.e1.victoriassecret.com/lib/fe92137274640d7b71/m/179/5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png` is a content image hosted on the brand's image CDN, so this is a real accessibility gap.
- **Missing alt text on tracking pixels.** `o.gif` and `pub1–10.php` have no alt. These are 1x1 pixels, so the impact is low, but `alt=""` would be cleaner.
- **Missing language and roles.** No `lang` attribute appears on `<html>`. Only the "stylingblock" wrapper tables carry `role="presentation"`, and the main layout tables (`class="container"`, `tb_properties`) do not.
- **Legacy doctype.** The doctype is HTML 4.01 Transitional.

## 4. Personalization & Merge Tokens
- No unresolved merge tokens (`%%…%%`, `{{…}}`, `[FirstName]`) are visible in the truncated source.
- Per-recipient identifiers are present as expected: `mi_u=200492586522`, `customerID=43cece97…`, `dtm_email_hash=4edea106…`.
- The source is truncated, so full token coverage couldn't be verified.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **No `List-Unsubscribe` or `List-Unsubscribe-Post` (RFC 8058).** The QA tool reports "may not be captured by AgentMail relay", so this is unconfirmed. Treat it as unverified, not as a sender defect.
- **No `Authentication-Results` header.** SPF, DKIM and DMARC status is unknown. The relay likely strips this header.
- **Footer not inspected.** The truncated source doesn't include the footer, so the in-body unsubscribe link and postal address couldn't be checked.
- **Domain mismatch.** The From domain is `e2.vspink.com`, while the tracking, image and landing domains are `e1.victoriassecret.com` and `victoriassecret.com`. This is typical for ESP setups, but DKIM and DMARC alignment can't be assessed without headers.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Landing URL (from the JSON-LD):** `https://www.victoriassecret.com/us/pink/underwear/underwear-offer?cm_mmc=di-_-111126425-_-VSD_VSL_20261111_PK_6473_FILEBAL&d_cellid=111126425&mi_ecmp=20261111_PK_6473_FILEBAL…`
- **No standard `utm_*` parameters.** Attribution relies on proprietary parameters: `cm_mmc`, `d_cellid`, `mi_ecmp`, `mi_u`. These are consistent with each other (campaign ID `20261111_PK_6473_FILEBAL`) and match the date and brand. This is a consistent scheme, not a defect, but it won't populate standard analytics source and medium dimensions.
- **Landing page unverified.** The page didn't load in the HTTP probe, because 49 links were skipped. Whether the `underwear-offer` page matches the "7/$35" subject line can't be confirmed.
- **PII in the URL.** The URL carries `customerID` and `dtm_email_hash` as query parameters, which exposes persistent identifiers in the URL and in referrers.

## 7. Recommendations
1. Serve all pixels over `https://`: `mi.victoriassecret.com/…/o.gif`, `login.dotomi.com/…`, `ads.dotomi.com/cookieredir/…/pub1–10.php`. Check whether the 10-pixel cookie sync is needed.
2. Remove `maximum-scale=1, user-scalable=0` from the viewport meta tag.
3. Fix the document structure. Move the JSON-LD and wrapper table out of `<head>`, populate or remove the empty `<title>`, and add `lang` to `<html>`.
4. Fix or remove the invalid `ReadMsgBody` and `min-width` CSS rules.
5. Add descriptive alt text to `5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png`, and `alt=""` to the tracking pixels.
6. Add `role="presentation"` to the main layout tables.
7. Verify `List-Unsubscribe`, `List-Unsubscribe-Post`, and SPF/DKIM/DMARC from raw message headers, since the relay strips them. Also confirm the footer unsubscribe link and postal address in the full HTML.
8. Resolve the redirect chains for the key CTA links with a real browser or GET request to confirm landing-page alignment.
9. Consider adding `utm_*` parameters alongside the proprietary ones, and avoid exposing `customerID` and `dtm_email_hash` in landing URLs.
