## Technical Audit

## 1. Technical Summary
The email is a table-based layout with responsive media queries. The source has several hygiene problems: 11 insecure `http://` Dotomi pixels with no alt text, a duplicated open pixel, invalid CSS selectors, and a viewport that blocks zoom. Compliance and authentication headers could not be checked, because the relay did not capture them.

## 2. Link & Tracking Issues
- **Insecure third-party pixels:** 11 images load over `http://`. They are `http://login.dotomi.com/ucm/UCMController?dtm_com=2&dtm_cid=2482...` and `http://ads.dotomi.com/cookieredir/2482/pub1.php` through `pub10.php`. Clients that proxy or block mixed content may drop them, which would break Dotomi/Epsilon cookie-sync and conversion tracking silently.
- **Duplicate open pixel:** `https://click.e1.victoriassecret.com/open.aspx?UWJSU5PIW3CU3AONTW2AJIECJA.70269&d=70269&bmt=0` appears twice. One is in the first `<div style="font-size:0">` and one is a bare `<img>` inside the header block. This can double-count opens.
- **Unverified links:** 48 tracking links on the click redirect domain were skipped from HTTP probing, so I can't confirm their destinations or whether they resolve.

## 3. Rendering & Accessibility
- **Missing alt text:** 12 images have none (the 11 Dotomi pixels above, plus `https://image.e1.victoriassecret.com/lib/fe92137274640d7b71/m/179/5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png`). The pixels are decorative, so `alt=""` would be correct for them. The `.png` is a content-domain image, so it likely needs real alt text, or `alt=""` if it is decorative.
- **Viewport blocks zoom:** `<meta name="viewport" content="..., maximum-scale=1, user-scalable=0">` prevents pinch-zoom, which fails WCAG 1.4.4.
- **Invalid CSS in the first `<style>` block:**
  - `ReadMsgBody{ width: 100%;}` is missing its leading `.`, so the rule never matches. The later `.ReadMsgBody` rule is correct.
  - `min-width{width:auto!important;}` targets a nonexistent `<min-width>` element and does nothing.
- **Invalid markup:**
  - `<title style="display: none; ...">` sits inside `<body>`, and the `<head>` has no `<title>`.
  - The doctype is HTML 4.01 Transitional, and `<html>` has no `lang` attribute.
  - Only some tables set `role="presentation"`. The outer layout tables lack it.
- **Leaked template artifact:** the comment `<!-- `date "+ET%m.%y"` -->` is an unprocessed shell/template expression in production HTML.
- **Empty block:** `<div id="AMPScript">` wraps an empty "Ampscript v0 START/END" block.

## 4. Personalization & Merge Tokens
No unresolved merge tokens appear in the visible source. The AMPScript block is empty and its output is not visible. The source is truncated, so I can't assess the rest of the body.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- `List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) were not found. The QA tool notes the AgentMail relay may strip them, so this is unconfirmed. If they really are missing, that is a gap against Gmail/Yahoo bulk-sender requirements.
- `Authentication-Results` was not found, so SPF/DKIM/DMARC alignment is unknown. The From domain is `e1.victoriassecret.com`.
- The footer (physical address, visible unsubscribe link) is not in the truncated source, so I can't confirm it.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)

- The Dotomi pixels carry `dtmc_email_category=20261015_VS_6327_FILEBAL`, so campaign attribution looks to be handled by the redirect and Dotomi layer. I can't verify the landing page.

2. Add meaningful `alt` to `5bcec3ac-...png`, or `alt=""` if it is decorative.
3. Remove the duplicate open pixel.
4. Remove `maximum-scale=1, user-scalable=0` from the viewport meta.
