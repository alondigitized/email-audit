## Technical Audit

## Technical Audit: "Tuesday Panty Edit: Itsy Shine Strap Thong"

### 1. Technical Summary
The email is a table-based layout with an ESP click-tracking wrapper. The automated QA shows 0 hard failures and 3 warnings (57% pass rate). The real issues are about a dozen third-party `http://` pixels without alt text, three content images without alt text, a viewport meta that blocks zoom, and CSS/class mismatches. The HTML was truncated, so footer, link and UTM checks are incomplete.

### 2. Link & Tracking Issues
- **Duplicate open pixel:** The same URL is embedded twice: `https://click.e1.victoriassecret.com/open.aspx?EFMPC5NILWSULE3K4U7SM5J7SU.70264&d=70264&bmt=0`. One copy is in the wrapper `<div style="font-size:0; line-height:0;">` and the other is a bare `<img>` further down. This can double-count opens and adds a redundant request.
- **Dotomi (Epsilon) cookie-sync pixels over HTTP:** `http://ads.dotomi.com/cookieredir/2482/pub1.php` through `pub10.php`, plus `http://login.dotomi.com/ucm/UCMController?dtm_com=2&dtm_cid=2482…&dtmc_email_category=20261013_VS_6169_FULLFILE`. That is 11 third-party tracking images. They are non-HTTPS and have no `alt`. They add load time and are likely to be blocked by privacy proxies and some clients.
- **Unverified links:** 51 tracking links were skipped by the QA probe (click-redirect domains). Destination status, redirect chains and expiry are unverified.

### 3. Rendering & Accessibility
- **Missing alt on content images** (QA-confirmed):
  - `https://image.e1.victoriassecret.com/lib/fe92137274640d7b71/m/1/3505172c-7ae5-4640-adb1-053932dab3a3.gif`
  - `https://image.e1.victoriassecret.com/lib/fe92137274640d7b71/m/179/5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png`
  - `https://mi.victoriassecret.com/p/rp/a1b54323f61922cc.png?mi_u=…&mi_ecmp=20261013_VS_6169_FULLFILE…`, which is a Movable Ink dynamic image.

  If any of these carry product or offer information, it is lost with images off or in screen readers. The tracking pixels can legitimately use `alt=""`, but they have no `alt` attribute at all.
- **Zoom disabled:** `<meta name="viewport" content="… maximum-scale=1, user-scalable=0">` blocks pinch-zoom on mobile (WCAG 1.4.4).
- **Class mismatch:** The markup uses `class="content_padding"` but the media query defines `.content-padding`. The mobile padding override never applies.
- **Invalid or ineffective CSS:**
  - `ReadMsgBody{…}` is missing its leading `.`, so it targets an element instead of the class.
  - `min-width{width:auto!important;}` is a malformed selector.
  - `max-height:auto` is not a valid value.
- **Structure:** A `<title>` and a second `<style>` block sit inside `<body>`. Many layout tables lack `role="presentation"`. The doctype is HTML 4.01 Transitional. Several clients tolerate all of this, but it is non-standard.
- **Leaked template comment:** `<!-- \`date "+ET%m.%y"\` -->` is a shell-style backtick artifact. It is harmless but shows an unprocessed build step. The `AMPScript` div is empty, with no unresolved script output.

### 4. Personalization & Merge Tokens
No issues found in the visible source: no unresolved `%%…%%`, `{{…}}` or AMPscript tokens. The portion after truncation could not be checked.

### 5. Compliance (CAN-SPAM, unsubscribe, authentication)
- **Headers not captured:** The QA could not find `List-Unsubscribe`, `List-Unsubscribe-Post` (RFC 8058) or `Authentication-Results`. It attributes this to the AgentMail relay, so these are **unverified, not confirmed missing**. Gmail and Yahoo bulk-sender rules require one-click unsubscribe, so check the raw headers at the source.
- **Footer not reviewed:** The physical address and the in-body unsubscribe link fall after the truncation point, so neither could be verified.
- **Sender:** `VictoriasSecret@e1.victoriassecret.com` is aligned with the tracking and image subdomains (`click.e1`, `image.e1`). No mismatch.

### 6. Email-to-Site Continuity
- **UTM parameters unverified:** No UTM parameters are visible in the available source, and the 51 click links were skipped by the probe. Campaign attribution appears to rely on the ESP wrapper and the ID `20261013_VS_6169_FULLFILE`. That ID is passed to Movable Ink (`mi_ecmp`) and Dotomi (`dtmc_email_category`).
- **Landing page alignment:** Not checkable without resolved destinations.

### 7. Recommendations
1. Add descriptive `alt` text to the two `image.e1` assets and the Movable Ink image. Add `alt=""` to the tracking pixels.
2. Remove the duplicate open pixel.
3. Move the Dotomi pixels to HTTPS, or drop them. Ten cookie-sync calls per open is heavy.
4. Remove `maximum-scale=1, user-scalable=0` from the viewport meta.
5. Change `.content-padding` to `.content_padding` (or the reverse) so the mobile rule applies. Fix `.ReadMsgBody` and remove the malformed `min-width{}` and `max-height:auto`.
6. Check the raw message headers for `List-Unsubscribe` and `List-Unsubscribe-Post`, and for SPF, DKIM and DMARC results.
7. Re-run the audit with the full HTML and with click-redirects resolved, to verify the footer, unsubscribe link, UTMs and destinations.
