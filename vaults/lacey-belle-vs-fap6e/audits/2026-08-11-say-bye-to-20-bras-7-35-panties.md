# PINK Friday Exclusives — Technical Email Audit

## 1. Technical Summary
Table-based HTML email using standard ESP media queries and Silverpop/Acoustic-style open tracking; one broken CTA link (400) and no visible unsubscribe/authentication headers were captured in the provided headers/HTML.

## 2. Link & Tracking Issues
- **Broken link (400):** SMS signup CTA ("Lets text. Sign up for SMS...") resolves to `https://vspink.attn.tv/p/LSA/landing-page` and returns HTTP 400. This link is non-functional as sent.
- 61 additional tracking/click-redirect links (`click.e1.victoriassecret.com`, etc.) were skipped by automated HTTP probing per standard practice for redirect-wrapped tracking domains — not independently verified, flagging as unconfirmed rather than pass/fail.
- Open-tracking pixel present twice (identical `open.aspx?YAYHH4GJZ2NULAQFR6YA6ECOXI.70252` beacon fired at both `<body>` start and again inside the nested wrapper table) — redundant but not functionally broken.

## 3. Rendering & Accessibility
- Legacy HTML4 Transitional doctype with Outlook (`mso`) conditional font-fix and standard `ReadMsgBody`/`ExternalClass` resets — appropriate for cross-client compatibility, no issues found there.
- **Missing `alt` text** on multiple tracking/beacon images: `o.gif` (mi.victoriassecret.com), the `dotomi.com` UCMController pixel, and `pub1.php`–`pub10.php` cookie-redirect pixels, plus the content image `5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png`. The 1x1 tracking pixels are low-impact for screen readers, but the content image missing `alt` is a genuine accessibility gap.
- **Mixed content (`http://` not `https://`):** `mi.victoriassecret.com/p/up/.../o.gif`, `login.dotomi.com/ucm/UCMController`, and `ads.dotomi.com/cookieredir/2482/pub1–10.php` are all served over plain HTTP. Most modern mail clients (Gmail, Outlook, Apple Mail) block or proxy non-HTTPS image loads, meaning these tracking/retargeting pixels likely silently fail to fire for a large share of recipients.

## 4. Personalization & Merge Tokens
No AMPscript, merge fields, or personalization tokens are populated in the visible source — the `<div id="AMPScript">` block contains only `<!-- Ampscript v0 START/END -->` comments with no active dynamic content. No issues found; nothing to evaluate for broken token rendering.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe header not found:** Per automated QA, no `List-Unsubscribe` header was captured. Note the caveat in the findings — this may reflect the AgentMail relay not surfacing the header rather than the sender omitting it — but as received, one-click unsubscribe cannot be confirmed.
- **List-Unsubscribe-Post header not found (RFC 8058):** One-click unsubscribe support cannot be confirmed from available data.
- Truncated HTML source does not extend to a footer/unsubscribe link region, so in-body CAN-SPAM elements (physical address, unsubscribe link) could not be verified from the provided excerpt — flagging as unconfirmed rather than fail.
