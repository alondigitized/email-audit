**Score:** 7/10 · **Type:** Email audit · **2026-10-02**

- This is the first Victoria's Secret send I've seen that stacks two real offers in one subject: Buy 2 Bras, Get 1 Free, plus 8/$38 panties. The subject leads with the bra deal but the hero leads with the panties, so the first thing you read in the inbox isn't the first thing you see when you open it.
- The rest is the usual long scroll: party-approved PJs, a Bombshell Shine fragrance launch, a Fashion Show vanity case gift with $100+ purchase, a category grid, a rewards block and a trending row. Only the bra BOGO is new.

- The subject names two concrete offers in 38 characters, which fits a mobile inbox.
- The hero panty stack with the "LIMITED TIME" tag and the big "8/$38" headline is easy to read.
- The XS–XXL size row under the hero is useful product information.

## What's weak

- The subject leads with bras but the hero leads with panties, so the two don't line up.
- The body is very long. PJs, fragrance, the vanity case, a category grid and a trending row all compete with the two offers in the subject.
- 8/$38 panties are repeated from yesterday's send, which makes this feel like the same promo again.

## Technical Audit

## 1. Technical Summary
The email uses a 600px nested-table layout with a double-fired open pixel and about 11 insecure third-party (Dotomi) tracking images. It also disables pinch-zoom in the viewport meta tag, and several images have no alt text. The header and compliance warnings are probably relay artifacts and can't be confirmed from this data. The HTML source was truncated, so the body links and footer weren't inspected.

## 2. Link & Tracking Issues
- **Duplicate open pixel.** The same 1x1 beacon appears twice in the source: once in the top `<div style="font-size:0; line-height:0;">` and again right after the `<!-- `date "+ET%m.%y"` -->` comment. Both use `https://click.e1.victoriassecret.com/open.aspx?NKBBCOC6MYPUDOWY7LT7KVXGMQ.70248&d=70248&bmt=0`. This can double-count opens in some clients.
- **Insecure third-party cookie-sync pixels.** The QA data flags `http://ads.dotomi.com/cookieredir/2482/pub1.php` through `pub10.php`, plus `http://login.dotomi.com/ucm/UCMController?dtm_com=2&dtm_cid=2482…`.
  - All of them load over `http://`, so mixed-content blocking or proxy stripping is likely. Gmail's image proxy and Apple Mail Privacy Protection will also neutralize them.
  - Each one is an extra third-party request on open, and each has no alt attribute.
- **Unverified click links.** The QA run skipped 52 tracking links (click-redirect domain, no HTTP probe), so link validity and destinations are unverified.

## 3. Rendering & Accessibility
- **Zoom disabled.** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=0" />` blocks pinch-zoom. This fails WCAG 1.4.4 (Resize Text) in clients that honor the tag.
- **Missing alt text on non-tracking images.**
  - `https://image.e1.victoriassecret.com/lib/fe92137274640d7b71/m/1/3505172c-7ae5-4640-adb1-053932dab3a3.gif`
  - `https://image.e1.victoriassecret.com/lib/fe92137274640d7b71/m/179/5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png`
  - If either carries content, it's invisible with images off and to screen readers. If it's a spacer, it needs `alt=""` rather than no attribute.
- **Missing alt on a tracking image.** `https://mi.victoriassecret.com/p/rp/a076cc7f15d20566.png?mi_u=…&mi_ecmp=20261002_VS_6245_FULLFILE` has no alt attribute.
- **Invalid CSS in the first `<style>` block.**
  - `ReadMsgBody{ width: 100%;}` is missing the leading `.`, so it matches nothing.
  - `min-width{width:auto!important;}` is an element selector for a non-existent tag.
  - `max-height:auto` is not a valid value.
- **Document structure.**
  - There is no `lang` attribute on `<html>`.
  - A `<title style="display:none…">` with empty content sits inside `<body>`, where it is invalid.
  - Layout tables are inconsistent about `role="presentation"`. Only the `stylingblock-content-wrapper` tables have it.
- **Leftover template artifacts.** The source still contains the `<!-- `date "+ET%m.%y"` -->` comment, an empty `<div id="AMPScript">` and empty "Ampscript v0 START/END" comments. These are harmless but add weight.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens appear in the visible portion of the source. The AMPScript block is empty, and the rest of the source was truncated.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **Missing headers (unverified).** The QA data reports `List-Unsubscribe`, `List-Unsubscribe-Post` (RFC 8058) and `Authentication-Results` as not found. The QA notes say these may be dropped by the AgentMail relay, so absence in the captured message is not evidence the sender omitted them. Check the raw headers at the origin or in a direct-to-Gmail test. If they are genuinely missing, one-click unsubscribe would fail the Gmail/Yahoo bulk-sender requirements.
- **Footer not inspected.** The HTML was truncated before the footer, so the visible unsubscribe link and physical postal address could not be checked.
- **Third-party tracking disclosure.** Ten cookie-sync pixels fire on open with no consent mechanism visible. This is a privacy risk in GDPR/ePrivacy regions, though it can't be fully assessed from this data.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **No UTM parameters in the visible source.** Tracking uses ESP and vendor identifiers instead: `mi_ecmp=20261002_VS_6245_FULLFILE` and `dtmc_email_category=20261002_VS_6245_FULLFILE`. These are consistent with each other.
- **Landing pages unverified.** Whether UTMs are applied on redirect, and whether the pages match the "Buy 2 Bras, Get 1 FREE + 8/$38 Panties" offer, can't be confirmed because all 52 click links were skipped.

## 7. Recommendations
1. Remove the duplicate `open.aspx` beacon so only one fires.
2. Move the Dotomi pixels to `https://`, or drop the 10 `pubN.php` cookie-sync pixels. Add `alt=""` to any that stay.
3. Remove `maximum-scale=1, user-scalable=0` from the viewport meta tag.
4. Add descriptive alt text to `3505172c-…gif` and `5bcec3ac-…png`, or `alt=""` if they are decorative. Add `alt=""` to the `mi.victoriassecret.com` pixel.
5. Fix the invalid CSS (`.ReadMsgBody`, remove `min-width{}`, change `max-height:auto`). Add `lang="en"` to `<html>`, and move or remove the `<title>` inside `<body>`.
6. Confirm `List-Unsubscribe`, `List-Unsubscribe-Post` and SPF/DKIM/DMARC in the raw source headers, not through the relay.
7. Re-run the audit with the full HTML (no truncation). Resolve the 52 redirect links to check landing-page destinations, UTM propagation and the footer unsubscribe/address.
