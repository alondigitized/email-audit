## What's weak

- **Free Lace Tote is buried mid-email** — the single most differentiating offer in this send isn't visible above the fold; subscribers who don't scroll never see it.
- **Subject line ignores the GWP entirely** — "Looking for a Lift? Try NEW Very Sexy Bras" reads as a product launch announcement, not an action-driver; the tote is the reason to click *now*, and it's not in the subject.

- **Cadence note:** This follows immediately on the July 22 "Push-Up Bra That Started It All" send — two consecutive Very Sexy emails risks fatigue even though the creative is distinct.

- 2. **Add a deadline to the GWP** — "Free Lace Tote with any bra purchase, this week only" turns a nice offer into an urgency signal.

## Technical Audit — Victoria's Secret "Very Sexy Bras" (2026-07-23)

### 1. Technical Summary

The email is a standard HTML4 table-based build with functional responsive breakpoints. The primary technical concerns are a cluster of HTTP (non-HTTPS) retargeting pixel calls from Dotomi/Conversant and missing authentication/compliance headers at the relay layer.

---

### 2. Link & Tracking Issues

**18 click-redirect links skipped by probe** — all routed through `click.e1.victoriassecret.com`. This is expected ESP click-tracking behavior; no actionable issue assuming ESP wrapping is confirmed.

**Open pixel uses plain HTTP:**
```
src="https://click.e1.victoriassecret.com/open.aspx?LXDQR3SU6DRELDQMEO3T3U4NXA.70252..."
```
Open pixel itself is HTTPS — fine.

**Dotomi retargeting pixels are HTTP-only (10 instances):**
```
http://login.dotomi.com/ucm/UCMController?...
http://ads.dotomi.com/cookieredir/2482/pub1.php?...
...pub10.php?...
```
These are plain `http://` URLs. Gmail, Outlook, and Apple Mail route all HTTP image requests through their own HTTPS proxies, which will break the cookie-matching mechanism these pixels depend on. The retargeting sync will silently fail for a large portion of recipients. This is a functional defect, not just a warning.

---

### 3. Rendering & Accessibility

**11 images with missing `alt` text confirmed by QA** — all are the Dotomi tracking/retargeting pixels (pub1–pub10 + UCMController). These are intentionally invisible 1x1 pixels, so empty `alt=""` is the correct fix (not descriptive alt text). Currently they have no `alt` attribute at all, which causes some screen readers to read out the full URL.

**One content image missing alt:**
```
src="https://image.e1.victoriassecret.com/lib/fe92137274640d7b71/m/179/5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png"
```
This appears to be a product/creative image (hosted on `image.e1.victoriassecret.com`), not a pixel. Missing alt text here is an accessibility failure for screen reader users.

**DOCTYPE is HTML 4.01 Transitional** — expected for broad email client compatibility; not an issue.

**`<title>` tag placed inside `<body>` in a nested table cell** (`<title style="display: none; max-height: 0px; overflow: hidden;">`). This is a preheader-suppression hack that is technically malformed HTML but is a known ESP pattern. No functional impact expected.

**`<script>` block in `<head>` before `<meta>` tags** — the JSON-LD `PromotionCard` block appears before the `<meta charset>` declaration. Some parsers may misinterpret character encoding for the script content, though in practice this is low risk for ASCII-safe JSON.
