## Technical Audit

## 1. Technical Summary
The email's visible markup has structural HTML problems (a `<table>` and `<title>` outside their valid containers, and a malformed CSS selector). It also embeds 11 plain-HTTP third-party Dotomi pixels that lack alt text, and its URLs carry hashed email identifiers. The truncated source and the relay-stripped headers limit what I could verify for compliance and personalization.

## 2. Link & Tracking Issues
- **Probe coverage:** 51 tracking links were skipped by the HTTP probe because they are on click-redirect domains. Their destinations are unverified.
- **Insecure third-party pixels:** There are 11 `http://` Dotomi (Epsilon) pixels:
  - `http://login.dotomi.com/ucm/UCMController?dtm_com=2&dtm_cid=2482...`
  - `http://ads.dotomi.com/cookieredir/2482/pub1.php` through `pub10.php`
  
  Clients that proxy or block insecure content, such as Gmail's image proxy and Apple Mail with Mail Privacy Protection, will likely drop these. The cookie-sync and retargeting pixels will not fire reliably.
- **Hashed identifier in pixel URLs:** The query string `a4edea106b33...=1` on each `pubN.php` URL is the same value as `dtm_email_hash` in the JSON-LD URL. It is a 64-hex-character hash (SHA-256 length) sent to a third party in cleartext over HTTP.
- **Open pixel:** `https://click.e1.victoriassecret.com/open.aspx?qs=...&d=70269&bmt=0` is a 1x1 image with `alt=""`, which is correct.

## 3. Rendering & Accessibility
- **Invalid document structure:**
  - The `<head>` opens with a `<table class="stylingblock-content-wrapper">` containing a `<script type="application/ld+json">`, before the `<meta>` and `<style>` tags. A table is not valid in `<head>`, and browsers may close `<head>` early at that point.
  - An empty `<title style="display:none...">` sits inside a body `<td>`.
  - Either problem can cause client-dependent parsing of the viewport meta and style blocks.
- **Doctype mismatch:** The doctype is HTML 4.01 Transitional, but the markup uses XHTML-style `<meta ... />` and `role="presentation"`.
- **Malformed CSS:** In the first `<style>` block, `ReadMsgBody{ width: 100%;}` is missing its leading `.`, so it targets a nonexistent element. `min-width{width:auto!important;}` is also an invalid selector. The mobile rule `max-height:auto` is an invalid value.
- **Viewport meta:** `maximum-scale=1, user-scalable=0` blocks pinch-zoom in clients that honor it, which fails WCAG 1.4.4.
- **Missing alt text (QA-confirmed):**
  - `https://image.e1.victoriassecret.com/lib/fe92137274640d7b71/m/179/5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png` has no `alt`. This is the only content image flagged.
  - The 11 Dotomi pixels also lack `alt`.
- **Outlook:** A `mso` conditional block sets `font-size:16px; line-height:1` on `body, table, td`. `line-height:1` can clip multi-line text in Outlook.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens (`%%...%%`, `{{...}}`) appear in the visible source. The tail of the document is truncated, so the footer and body are unchecked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe and List-Unsubscribe-Post (RFC 8058):** QA reports both missing. This is likely an AgentMail relay capture limitation rather than a sender fault, so it is unconfirmed. If the headers are really absent, Gmail and Yahoo bulk-sender rules are not met.
- **Authentication-Results:** Not captured, so SPF, DKIM and DMARC status is unknown. Sending from `e1.victoriassecret.com` could not be verified.
- **Footer unsubscribe link and physical address:** The truncated HTML does not show them, so I could not check them.
- **Privacy:** The JSON-LD block exposes `dtm_email_hash` and `customerID` (both 64-hex hashes) in a URL that schema.org-aware clients can read and surface. Hashed PII in URLs and structured data is a privacy concern, though not a CAN-SPAM violation.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **Landing URL:** The JSON-LD URL is `https://www.victoriassecret.com/us/vs/panties/panties-offer?cm_mmc=di-_-110626515-_-VSD_VSL_20261106_VS_6442_FULFILE-_&d_cellid=110626515&mi_u=200492586522&mi_ecmp=20261106_VS_6442_FULFILE...`. The path matches the panty-offer subject line.
- **Campaign ID:** `20261106_VS_6442_FULFILE` is consistent across the JSON-LD URL and the Dotomi `dtmc_email_category` parameter.
- **No standard UTM parameters:** The URL uses proprietary parameters (`cm_mmc`, `d_cellid`, `mi_ecmp`). Attribution in GA-style tools depends on custom mapping.
- **Destination unchecked:** The click-tracked links were not probed, so I did not confirm they land on the `panties-offer` page or that the 7/$35 offer renders there.

## 7. Recommendations
1. Move the JSON-LD `<table>` and `<script>` out of `<head>` and into `<body>`. Put the `<title>` in `<head>`.
2. Fix the CSS selectors (`.ReadMsgBody`, remove `min-width{}`), and remove `max-height:auto`.
3. Serve all Dotomi pixels over `https://`, or drop them. Add `alt=""` to every pixel image.
4. Add a descriptive `alt` to `5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png`, or `alt=""` if it is decorative.
5. Remove `user-scalable=0` and `maximum-scale=1` from the viewport meta.
6. Stop putting `dtm_email_hash` and `customerID` in URLs and structured data, or confirm they are salted and rotated.
7. For the audit pipeline:
   - Capture raw headers (`List-Unsubscribe`, `List-Unsubscribe-Post`, `Authentication-Results`) from the original message rather than the relay, so these warnings can be resolved.
   - Extend the HTML capture beyond the truncation point so the footer unsubscribe link and address can be checked.
   - Resolve the 51 redirect links with a HEAD or GET follow to verify final landing pages.
