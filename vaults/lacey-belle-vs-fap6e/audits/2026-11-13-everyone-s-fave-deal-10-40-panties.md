## Technical Audit

## 1. Technical Summary
The email is a Salesforce Marketing Cloud send (`click.e1.victoriassecret.com`, `stylingblock-content-wrapper`) with a large third-party tracking footprint. It has several markup defects, plus insecure `http://` pixel calls that pass a hashed email address. The HTML is truncated, so the footer, unsubscribe link and body links could not be checked.

## 2. Link & Tracking Issues
- **53 tracking links were not probed** (QA: "Tracking/click-redirect domains — skipped HTTP probe"). Destination validity is unverified.
- **Insecure tracking calls.** These pixels load over `http://`:
  - `http://mi.victoriassecret.com/p/up/bc3d99b3ec2e075f/o.gif?mi_u=200492586522&mi_ecmp=...`
  - `http://login.dotomi.com/ucm/UCMController?...`
  - `http://ads.dotomi.com/cookieredir/2482/pub1.php` through `pub10.php`
  
  Clients that block mixed content or insecure requests will drop them, which skews open and attribution data.
- **Dotomi cookie-sync pixels.** Ten `pub{1-10}.php` calls each carry `a4edea106b33…afc6fe=1`, the same SHA-256 email hash that appears as `dtm_email_hash` in the page URL. That hash is sent in cleartext over HTTP to third-party ad domains.
- **Customer identifiers in URLs.** The JSON-LD `url` includes `dtm_email_hash`, `mi_u=200492586522` and `customerID=43cece97…`. These are persistent identifiers in a link that is also exposed to schema consumers.

## 3. Rendering & Accessibility
- **Body content inside `<head>`.** A `<table class="stylingblock-content-wrapper">` containing a `<script type="application/ld+json">` block sits before `<meta name="viewport">`, inside `<head>`. This is invalid HTML and parsers may auto-close the head early. The viewport and content-type metas, and possibly the style blocks, can then be mishandled.
- **Schema markup.** The `PromotionCard` JSON-LD is only honored by Gmail, and it is invalid inside `<head>` here.
- **Invalid CSS selectors.**
  - `ReadMsgBody{ width: 100%;}` is missing its leading `.`, so it matches nothing.
  - `min-width{width:auto!important;}` is a type selector for a nonexistent element.
  - `max-height:auto !important` is not a valid value.
- **Stray `<title style="display:none…">` and `<style>` tags** appear inside `<body>` tables. This is non-conformant and may be stripped by some clients.
- **Viewport blocks zoom.** `maximum-scale=1, user-scalable=0` fails WCAG 1.4.4 (resize text).
- **Missing alt text:**
  - `https://image.e1.victoriassecret.com/lib/fe92137274640d7b71/m/179/5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png` is a hosted content image, so this is a real accessibility gap.
  - `o.gif` and the Dotomi `pub1`–`pub10.php` tracking pixels also lack alt. The attribute is absent rather than `alt=""`, which is low impact for 1×1 pixels.
- **Legacy doctype.** The HTML 4.01 Transitional doctype is paired with `role="presentation"` attributes and HTML5-era patterns. This is minor.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens (`%%…%%`, `{{…}}`) appear in the visible portion. The tokens that resolved (`mi_u`, `customerID`, `dtm_email_hash`) are populated. The truncated remainder was not checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe and List-Unsubscribe-Post (RFC 8058) were not found.** QA attributes this to the AgentMail relay possibly not capturing them. It is unconfirmed, not a verified defect.
- **Authentication-Results was not found**, so SPF, DKIM and DMARC status is unknown. QA again attributes this to the relay.
- **Footer not visible.** The unsubscribe link and physical postal address could not be checked because the source is truncated.
- **Sender and link domains differ.** The From domain is `e2.vspink.com`, while the click and open tracking domain is `e1.victoriassecret.com`. This is typical for SFMC, but DKIM/DMARC alignment cannot be confirmed without headers.
- **Open pixel.** `click.e1.victoriassecret.com/open.aspx?...` is correctly formed with `alt=""`, width 1 and height 1.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **No `utm_*` parameters.** The only visible URL (the JSON-LD `url`) uses proprietary parameters: `cm_mmc`, `d_cellid`, `mi_ecmp`, `mi_u`, `dtm_email_hash`. It has no `utm_source`, `utm_medium` or `utm_campaign`, so GA-based attribution relies on the Coremetrics `cm_mmc` parameter.
- **Campaign IDs are consistent.** `20261113_PK_6479_FILEBAL` appears in `cm_mmc` and `mi_ecmp`, and in the Dotomi `dtmc_email_category`.
- **Landing path.** The path `/us/pink/underwear/underwear-offer` is consistent with the "10/$40 Panties" subject. It was not fetched, because it is behind the tracking redirect.

## 7. Recommendations
1. Move the JSON-LD block out of `<head>` tables. Either place it in `<head>` as a bare `<script>` or put it in `<body>` after `<body>` opens. Remove the `<title>` and `<style>` tags from body tables.
2. Serve all pixels over HTTPS (`mi.victoriassecret.com`, `login.dotomi.com`, `ads.dotomi.com`), or drop the `pub1`–`pub10` cookie-sync calls. If they stay, confirm the hashed-email-over-HTTP exposure is intentional.
3. Fix the CSS selectors: `.ReadMsgBody`, remove `min-width{}`, and replace `max-height:auto`.
4. Remove `maximum-scale=1, user-scalable=0` from the viewport meta.
5. Add descriptive `alt` to `5bcec3ac-…png`, and `alt=""` to the tracking pixels.
6. Add `utm_source`, `utm_medium` and `utm_campaign` alongside `cm_mmc` for analytics parity.
7. For this audit pipeline, capture the raw headers (`List-Unsubscribe`, `List-Unsubscribe-Post`, `Authentication-Results`) and the full untruncated HTML. Until then, the compliance and footer checks stay unresolved rather than failed.
