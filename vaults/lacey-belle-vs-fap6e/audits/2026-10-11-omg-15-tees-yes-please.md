## Technical Audit

## 1. Technical Summary
The email's markup has structural problems: a `<table>` and `<script>` sit inside `<head>`, the viewport meta blocks zoom, and several CSS rules are malformed. It also loads 10+ non-HTTPS third-party pixels. The automated QA scored 57% with 3 warnings. The header-based compliance and authentication checks couldn't be confirmed, and the source was truncated, so footer content is unverified.

## 2. Link & Tracking Issues
- **Unverified links:** 47 tracking links were skipped by the HTTP probe because they are click-redirect domains. Their destinations and status codes are unconfirmed.
- **Test identifier in tracking params:** every JSON-LD URL carries `cm_mmc=...VSD_VSL_20261011_PK_6292_FILEBALTEST` and `mi_ecmp=20261011_PK_6292_FILEBALTEST`. The campaign ID looks like a seed/test label. If this was a production send, reporting will be attributed to a test campaign name.
- **Insecure pixels:** 12 images load over `http://`, which risks blocking or mixed-content warnings:
  - `http://mi.victoriassecret.com/p/up/bc3d99b3ec2e075f/o.gif`
  - `http://login.dotomi.com/ucm/UCMController?...`
  - `http://ads.dotomi.com/cookieredir/2482/pub1.php` through `pub10.php`
- **Third-party sync pixels:** `pub1`–`pub10.php` are ten cookie-redirect calls to Dotomi/Epsilon. Each adds a request and a latency/deliverability cost. Each also carries the same email hash in its query string (`a4edea106b33...=1`).
- **Identifiers in URLs:** the JSON-LD URLs expose `dtm_email_hash` and `customerID` (both 64-hex SHA-256 values) as query parameters. Anyone who forwards the email also forwards these identifiers.

## 3. Rendering & Accessibility
- **Invalid `<head>` content:** a `<table class="stylingblock-content-wrapper">` containing the JSON-LD `<script>` sits before `<meta>` and `<style>` inside `<head>`. Parsers will move it into `<body>`, which can produce stray whitespace or layout shifts.
- **JSON-LD limits:** the three `PromotionCard` entries have different `image` values but identical `url` values. Gmail Promotions annotations only render for registered senders, and most other clients strip `<script>`.
- **Zoom blocked:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=0">` disables pinch-zoom, which fails WCAG 1.4.4.
- **Malformed CSS:**
  - `ReadMsgBody{ width: 100%;}` is missing its leading `.`, so it matches nothing.
  - `min-width{width:auto!important;}` is an invalid selector.
  - `max-height:auto !important` is an invalid value.
  - Global `table{max-width:600px!important;}` caps nested tables.
- **Doctype:** HTML 4.01 Transitional is acceptable for email, but it is mixed with `<meta ... />` XHTML-style self-closing tags.
- **Missing alt text:**
  - Content image: `https://image.e1.victoriassecret.com/lib/fe92137274640d7b71/m/179/5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png` has no `alt`. This is the only real accessibility finding in the list.
  - Tracking pixels: `o.gif`, the Dotomi `UCMController` pixel and `pub1`–`pub10.php` also lack `alt`. These are non-visual, so they should carry `alt=""` and be hidden from assistive tech.
  - Open pixel: `open.aspx` correctly has `alt=""`.

## 4. Personalization & Merge Tokens
No issues found in the visible source. There are no unrendered `%%…%%`, `{{…}}` or `[[…]]` tokens. The source is truncated, so the body and footer weren't checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058):** both are not found. The QA note says the AgentMail relay may strip these headers, so this is unconfirmed. Gmail and Yahoo bulk-sender rules require both for senders at this volume.
- **`Authentication-Results`:** not found, so SPF, DKIM and DMARC alignment are unknown. The relay may have removed it.
- **Footer:** the unsubscribe link and physical postal address aren't in the truncated source, so they can't be verified.
- **Domain mismatch:** the From domain is `e2.vspink.com`, but links and images are on `victoriassecret.com`, `e1.victoriassecret.com` and `click.e1.victoriassecret.com`. This is common, but it needs a check that DKIM `d=` and the return-path align.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- The URLs use proprietary params (`cm_mmc`, `d_cellid=101126425`, `mi_u`, `mi_ecmp`) and no `utm_source`, `utm_medium` or `utm_campaign`. This is consistent across the visible links, but it won't populate GA-style reports without mapping.
- The JSON-LD landing path `/us/pink/tops-and-bottoms/offer` matches the "$15 Tees" subject. The live page content wasn't probed because the links were skipped.
- All three PromotionCards point to the same URL, so per-card click attribution isn't possible from the structured data.

## 7. Recommendations
1. Move the JSON-LD block out of `<head>` or wrap it in a valid `<body>` placement. Don't put a `<table>` in `<head>`.
2. Remove `maximum-scale=1` and `user-scalable=0` from the viewport meta.
3. Add descriptive `alt` text to `5bcec3ac-…png`. Add `alt=""` to all tracking pixels.
4. Switch all pixels (`mi.victoriassecret.com`, `login.dotomi.com`, `ads.dotomi.com`) to `https://`, or drop the Dotomi `pub1`–`pub10` syncs.
5. Fix the CSS: `.ReadMsgBody`, remove `min-width{}` and `max-height:auto`.
6. Confirm `FILEBALTEST` is not in production campaign IDs.
7. Re-run QA against raw `.eml` source with full headers (`List-Unsubscribe`, `List-Unsubscribe-Post`, `Authentication-Results`). Also run it on the untruncated HTML, including the footer.
8. Give each PromotionCard a distinct URL if per-card attribution matters.
