## Technical Audit

## 1. Technical Summary
The email's markup is structurally malformed (body content placed inside `<head>`, invalid CSS selectors, zoom disabled). It also loads 10 cleartext `http://` third-party cookie-sync pixels with no alt text. Header-level compliance and authentication checks couldn't be confirmed because the relay didn't capture the headers. The HTML source is also truncated.

## 2. Link & Tracking Issues
- **50 tracking links were not probed.** The QA run skipped the click-redirect domains, so link destinations are unverified. The open pixel is `https://click.e1.victoriassecret.com/open.aspx?qs=…&d=70265&bmt=0`, a 1×1 image with `alt=""`, which is correct.
- **10 non-HTTPS pixels:** `http://ads.dotomi.com/cookieredir/2482/pub1.php` through `pub10.php`, plus `http://login.dotomi.com/ucm/UCMController?dtm_com=2&dtm_cid=2482…`. Clients that block mixed content or proxy images (Gmail, Apple Mail Privacy Protection) can drop these. Cookie syncing in email will not run in most clients.
- **Hashed email in query strings.** `dtm_email_hash=4edea106…c6fe` is in the JSON-LD URL, and the same hash is the parameter name in each `pub*.php` URL. `customerID=43cece97…` is in the JSON-LD URL as well. These are identifiers passed through URLs and third-party requests.

## 3. Rendering & Accessibility
- **Malformed document structure.** A `<table class="stylingblock-content-wrapper">` containing a `<script type="application/ld+json">` sits inside `<head>`, before the `<meta>` and `<style>` tags. This is invalid HTML and parsers will move or drop it. Another `<title style="display: none; …"></title>` sits in the body, and it is empty.
- **Zoom disabled.** `<meta name="viewport" content="… maximum-scale=1, user-scalable=0">` blocks pinch-zoom (WCAG 1.4.4).
- **Invalid CSS selectors** in the first `<style>` block:
  - `ReadMsgBody{…}` has no leading `.`, so it matches an element name rather than the class.
  - `min-width{width:auto!important;}` is not a valid selector.
- **Global `table{max-width:600px!important;}`** applies to every table, including the `width="100%"` wrappers, and will clamp nested layouts.
- **Missing alt text:**
  - `https://image.e1.victoriassecret.com/lib/fe92137274640d7b71/m/179/5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png`
  - All 11 Dotomi pixels. These are invisible tracking images, so `alt=""` would be the correct fix.
- **Outdated doctype.** `HTML 4.01 Transitional` is paired with `role="presentation"` (an ARIA attribute). It's functional but inconsistent.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens (`%%…%%`, `{{…}}`, `[FirstName]`) appear in the visible source. The rest of the body was truncated, so this only covers the visible portion.

## 5. Compliance
- **`List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058) not found.** QA notes the AgentMail relay may strip them, so this is unconfirmed. Without both headers there is no one-click unsubscribe, which Gmail and Yahoo require for bulk senders.
- **`Authentication-Results` missing.** SPF, DKIM and DMARC status is unknown from this capture. The From domain `e1.victoriassecret.com` and the tracking domain `click.e1.victoriassecret.com` share a parent, which is a good sign for alignment, but it is not verified.
- **Footer not visible.** The visible source doesn't include an unsubscribe link or postal address, so CAN-SPAM body requirements can't be assessed.

## 6. Email-to-Site Continuity
- The only destination visible is the JSON-LD URL `https://www.victoriassecret.com/us/vs/bras?cm_mmc=di-_-110526515-_-VSD_VSL_20261105_VS_6441_FULFILE-_&d_cellid=110526515&mi_u=…&mi_ecmp=20261105_VS_6441_FULFILE`.
- **No standard `utm_*` parameters.** Attribution relies on proprietary parameters (`cm_mmc`, `d_cellid`, `mi_ecmp`). This is consistent with a Coremetrics/Epsilon setup but won't populate GA4 campaign dimensions.
- The campaign ID `20261105_VS_6441_FULFILE` is consistent across the URL and the Dotomi `dtmc_email_category`.
- The body CTAs weren't in the truncated source, so landing-page alignment for them is unverified.

## 7. Recommendations
1. Move the JSON-LD `<script>` and its wrapper table out of `<head>`. Put `<meta>` and `<style>` first, and make the body a single valid tree.
2. Remove `maximum-scale=1` and `user-scalable=0` from the viewport meta.
3. Serve all Dotomi pixels over `https://`, or drop the 10 `pub*.php` cookie-sync calls. Add `alt=""` to them and to `5bcec3ac-….png`, with descriptive alt text if that image carries content.
4. Fix the CSS selectors (`.ReadMsgBody`, remove `min-width{}`) and scope the `table{max-width}` rule to the container.
5. Re-run the audit against the raw message. Confirm `List-Unsubscribe`, `List-Unsubscribe-Post: List-Unsubscribe=One-Click`, and SPF/DKIM/DMARC results in the original headers.
6. Review whether the hashed email and `customerID` need to be in URLs and third-party requests. Consider adding `utm_*` parameters alongside the existing tracking.
7. Probe a sample of the 50 skipped tracking links by following the redirect chain to the landing page.
