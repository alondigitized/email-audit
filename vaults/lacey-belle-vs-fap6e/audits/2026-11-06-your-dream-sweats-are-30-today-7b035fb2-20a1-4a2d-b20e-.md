## Technical Audit

## 1. Technical Summary
The email's structure is mostly sound, with markup and CSS defects and an accessibility-hostile viewport meta. The bigger concern is about 10 plain-HTTP third-party cookie-sync pixels, which pass a hashed email address in cleartext. The HTML was truncated and the QA run reported no hard failures (0 issues, 3 warnings), so footer and unsubscribe markup could not be verified.

## 2. Link & Tracking Issues
- **Unverified links:** 58 tracking links on click-redirect domains were skipped by the HTTP probe, so their destinations and status codes are unconfirmed.
- **Plain-HTTP third-party pixels:** `http://ads.dotomi.com/cookieredir/2482/pub1.php` through `pub10.php` and `http://login.dotomi.com/ucm/UCMController?...` are loaded over HTTP.
  - Each `pubN.php` URL carries `a4edea106b333e696054ee7efded08d13b357adf450709a7b066a2e459aafc6fe=1`, which matches the `dtm_email_hash` value in the JSON-LD URLs. That is a hashed email identifier sent unencrypted to an ad network.
  - Clients that block mixed content or proxy images may drop these pixels, so the tracking is also unreliable.
- **Duplicate promotion cards:** Both JSON-LD `PromotionCard` entries use the same `url` (`/us/pink/new-arrivals?...`) with different images. This is probably unintended duplication.

## 3. Rendering & Accessibility
- **Viewport meta:** `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=0">` disables pinch-zoom, which fails WCAG 1.4.4 (Resize Text).
- **Invalid document structure:** A `<table>` and `<script type="application/ld+json">` sit inside `<head>`, before the `<meta>` and `<style>` tags. Parsers will relocate them, and the behavior varies by client. The HTML 4.01 Transitional doctype is also paired with self-closing `<meta ... />` syntax.
- **Broken CSS selectors:**
  - `ReadMsgBody{ width: 100%;}` is missing the leading `.`, so it targets a nonexistent element.
  - `min-width{width:auto!important;}` is not a valid selector.
  - `max-height:auto` is an invalid value.
- **Missing alt text on a content image:** `https://image.e1.victoriassecret.com/lib/fe92137274640d7b71/m/179/5bcec3ac-502d-4d8f-b48c-0a3d20e6e3c2.png` has no alt. This is the only flagged image that is plausibly visible content.
- **Missing alt text on tracking pixels:** The QA flags for `o.gif`, `UCMController`, and `pub1.php` through `pub10.php` are tracking or cookie-sync pixels. These are not user-facing, so I don't count them as real accessibility defects. Add `alt=""` and `width="1" height="1"` for consistency. The `open.aspx` pixel already has `alt=""`.

## 4. Personalization & Merge Tokens
No issues found. The visible source has no unresolved merge tokens such as `%%...%%`, `{{...}}`, or `[FIRST_NAME]`. Per-recipient values (`mi_u`, `dtm_email_hash`, `customerID`) are rendered.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **`List-Unsubscribe` and `List-Unsubscribe-Post` (RFC 8058):** Both are reported absent. QA notes the AgentMail relay may strip them, so this is **unconfirmed**. Verify against the raw message at the origin.
- **`Authentication-Results`:** It is absent, which is expected via the relay. SPF, DKIM and DMARC status is unknown, and no failure is evidenced.
- **Unsubscribe link and postal address:** The truncated source doesn't reach the footer, so I can't assess them.
- **Domain split (observation only):** The From domain is `e2.vspink.com`, while images and clicks use `e1.victoriassecret.com`. This isn't a violation, but confirm DKIM and return-path alignment on the raw headers.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **No UTM parameters:** The visible URLs use proprietary parameters (`cm_mmc`, `d_cellid`, `mi_ecmp`, `mi_u`) and no `utm_*`. This is a vendor convention, so attribution depends on Victoria's Secret's own analytics.
- **Landing page mismatch:** The only destination I can see (the JSON-LD URL) is `https://www.victoriassecret.com/us/pink/new-arrivals`, a generic new-arrivals page. The subject promises "Dream Sweats Are $30 Today". Body links were not visible in the truncated source or probed, so I can't confirm whether they deep-link to a sweats collection.
- **Identifiers in URLs:** `dtm_email_hash` and `customerID` are hashed, but they are persistent per-recipient identifiers in shareable URLs.

## 7. Recommendations
1. Move all `dotomi.com` pixels to HTTPS, or remove the cookie-sync pixels. Stop passing the email hash to third parties over HTTP.
2. Remove `maximum-scale=1, user-scalable=0` from the viewport meta.
3. Move the JSON-LD block and wrapper table into `<body>`, and fix the `.ReadMsgBody` selector. Drop the invalid `min-width{}` rule and the `max-height:auto` declaration.
4. Add descriptive alt text to `5bcec3ac-...png`, and `alt=""` to the tracking pixels.
5. Confirm `List-Unsubscribe` and `List-Unsubscribe-Post` and the SPF, DKIM and DMARC results from the origin raw message, not the relay copy.
6. Deep-link the JSON-LD and CTA URLs to the advertised sweats collection, and add `utm_*` if the site's analytics need them.
7. Re-run the audit on the full, untruncated HTML to check the footer, unsubscribe link, postal address, and the 58 skipped links.
