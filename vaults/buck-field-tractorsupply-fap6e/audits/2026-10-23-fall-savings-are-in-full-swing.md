## Technical Audit

# Technical Audit: Tractor Supply Company, "Fall savings are in full swing 🍂"

## 1. Technical Summary
The email is a table-based, responsive layout with MSO/VML namespaces and a click-tracking redirect on every link. The QA run reports a 19% pass rate, but most failures are read timeouts on `e.ez.tractorsupply.com/click?…` tracker URLs. Those point to probe or redirector behavior, not confirmed dead destinations. One real source defect is the malformed DOCTYPE.

## 2. Link & Tracking Issues
- **7 of 12 probed links failed with "The read operation timed out".** All are on the click-tracking host `https://e.ez.tractorsupply.com/click?…`. The link texts are "Tractor Supply Co.", "2026FW43Hero" (×2) and "Display images to show real-time content" (×4).
- **Not confirmed as broken destinations.** All timed out on the same host, and the probe never reached a final landing page. This pattern fits tracker throttling or bot filtering. It could also be slow redirect resolution. Treat it as "unverified", not "broken".
- **Hero and logo links are unverified.** The "2026FW43Hero" and "Tractor Supply Co." links are the highest-value clicks, and none resolved. Re-probe them with a browser-like UA and a longer timeout.
- **The "Display images to show real-time content" link** has this text on four separate tracked URLs. Each is a distinct tracker token, so these are likely separate dynamic-content blocks. Confirm what each resolves to.
- **The unsubscribe link returned HTTP 403.** The link text is "Update your preferences or unsubscribe", on `https://e.ez.tractorsupply.com/click?ZdJHdbptAEIV5FqTkqrjLEmCJhFpq…`. A 403 to an automated probe is common for preference-center bot protection, but the link was not verified as functional.
- **28 links were skipped.** Coverage is partial by design (footer and social are deprioritized).

## 3. Rendering & Accessibility
- **Malformed DOCTYPE system identifier.** The source has `<!DOCTYPE html PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" "http://www.w3c.org/TR/1999/REC-html401-19991224/loose.dtd">`. The host `w3c.org` is wrong (it should be `w3.org`), and the path is non-standard.
- **DOCTYPE and namespace mismatch.** The HTML 4.01 DOCTYPE is paired with `xmlns="http://www.w3.org/1999/xhtml"` on `<html>`. This is a common ESP-template pattern and is usually harmless, but it is inconsistent.
- **Missing alt text on three tracking images.** All three are tracking pixels, so the accessibility impact is low:
  - `https://mi.tractorsupply.com/p/cp/76ddd2c9608d17c7/o.gif?mi_u=60740592613`
  - `https://eaAnalyticsTSC.everestengagement.com/ea/o8uREqbKQf/?e=60740592613&c=102326_TSC_WKY_FW43TopDealsWeekly`
  - `https://e.ez.tractorsupply.com/open?ZPM1NSwMxEMbxfJacjSSz3bz0ZCmCiCyI4sFLmczOluJqQzJ7sOJ3lwX1_ON5…`
  
  Add `alt=""` to each so screen readers skip them.
- **Invalid CSS casing.** The `<style>` block uses `Margin: 0 auto !important` (capital M). Clients ignore it, and it is harmless.
- **Possible mismatched meta value.** `<meta content="width=device-width, initial-scale=1.0" name="x-apple-disable-message-reformatting">` carries a viewport-style value. The tag only needs to be present, so this has no practical effect.
- The `lang="en"` attribute is present, and the media queries at 639px and 580px are intact.

## 4. Personalization & Merge Tokens
No issues found. No unresolved merge tokens (`%%…%%`, `{{…}}`, `[FIRST_NAME]`) appear in the visible HTML. The source is truncated, so the rest was not checked.

## 5. Compliance (CAN-SPAM, unsubscribe, authentication headers)
- **List-Unsubscribe and List-Unsubscribe-Post (RFC 8058)** were not found. The QA tool itself notes that the AgentMail relay may strip these headers, so absence is not confirmed. Verify against the raw message at the origin or in a non-relayed inbox.
- **Authentication-Results** was not found. SPF, DKIM and DMARC status is unknown for the same relay reason. The From domain is `ez.tractorsupply.com`, so check alignment directly.
- **An unsubscribe link is present**, labeled "Update your preferences or unsubscribe". It returned 403 to the probe (see section 2).
- The physical postal address was not checked, because it is likely in the truncated footer.

## 6. Email-to-Site Continuity (UTM params, landing page alignment)
- **UTM parameters and landing pages are not verifiable.** Every link is wrapped in an opaque encoded redirect (`/click?Z…`), and no probe reached a final URL, so UTM presence and landing-page alignment can't be assessed.
- **Campaign identifier.** The open-tracking pixel exposes `c=102326_TSC_WKY_FW43TopDealsWeekly`, a campaign name that carries no destination information.
- **Subscriber ID in URLs.** The same numeric ID (`60740592613`) appears as `mi_u=` and `e=` in the pixel URLs. This is standard ESP behavior, not a defect.

## 7. Recommendations
1. **Re-probe the timed-out tracker links** (hero, logo, "Display images…") with a longer timeout and a browser-like UA. Follow the redirect chain to the final URL and confirm UTM params and a 200 landing page.
2. **Verify the unsubscribe and preference link manually** in a browser. Treat the 403 as a probe artifact unless it reproduces.
3. **Check the raw message headers** (List-Unsubscribe, List-Unsubscribe-Post, Authentication-Results) outside the relay.
4. **Fix the DOCTYPE** to a valid system identifier. Better, move to `<!DOCTYPE html>` with consistent namespaces.
5. **Add `alt=""` to the three tracking pixels.**
6. **Treat the 19% pass rate as inflated by probe limits.** Only the DOCTYPE and missing-alt items are confirmed source defects.
