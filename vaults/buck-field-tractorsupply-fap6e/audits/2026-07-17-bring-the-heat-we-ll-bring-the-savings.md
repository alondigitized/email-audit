### 2. Link & Tracking Issues

**`no-referrer` meta suppresses HTTP Referer on all clicks**
```html
<meta content="no-referrer" name="referrer">
```
Referrer-policy `no-referrer` strips the `Referer` header from every outbound click. UTM parameters embedded in URLs still pass to GA/analytics, but any attribution system relying on the HTTP referrer header (some legacy or third-party tools) will see `(direct)` instead of the email source. If UTMs are consistently applied throughout the body (unverifiable in truncated source), impact is low — but this is an intentional tradeoff worth confirming against analytics configuration.

---

### 3. Rendering & Accessibility

**`x-apple-disable-message-reformatting` carries wrong `content` value**
```html
<meta content="width=device-width, initial-scale=1.0" name="x-apple-disable-message-reformatting">
```
The `content` attribute here is a copy of the viewport tag and has no meaning for this meta. The correct form is either a bare `<meta name="x-apple-disable-message-reformatting">` or `content=""`. Most Apple Mail versions ignore the content value and honor the tag's presence alone, so functional impact is likely nil — but this is dead code copied in error and should be cleaned up.

**Non-standard capitalized `Margin` property (multiple occurrences)**
```css
Margin: 0 auto !important;
```
CSS property names are case-insensitive per spec and all tested clients handle this, but it signals copy-paste from a non-linting source. No rendering defect, but worth correcting in the template master.
